# 人事服务域与平台管理后台的入口边界

## 1. 知识讨论背景

用户询问组织架构视图的人员添加途径，回答时将员工花名册的路径写为 `管理后台 → 员工管理 → 员工花名册`。用户指出管理后台没有这个菜单，花名册属于人事领域的员工管理应用。根因是跨域套用了平台级入口前缀。

## 2. 候选知识

- **人事服务是独立顶层模块**，不是管理后台的子菜单。`00_领域概述.md` 已写明人事服务是"薪福通帮助中心'人事服务'一级模块"。
- 员工花名册的正确路径是 `人事服务 → 员工管理 → 员工花名册`，而非 `管理后台 → ...`。
- 人事服务域下的所有子模块（组织管理、员工管理、招聘管理、假勤管理、客户管理等）都不应以 `管理后台 →` 作为入口前缀。
- 与管理后台的关系：管理后台是平台级全局入口（承载组织、成员、权限等平台治理能力），人事服务是业务应用级入口（承载 HR 领域的业务能力），二者是**平级顶层入口**，不存在嵌套关系。

## 3. 影响范围

- 变更类型：修正
- 影响业务域：hr_service、organization
- 影响对象：人事服务域下所有子模块的路径描述（员工花名册、合同管理、任职管理、假勤管理、招聘管理、客户管理、组织管理（人事侧）、编制管控、岗位管理、职级管理）
- 建议更新位置：knowledge/raw/business/人事服务/00_领域概述.md（补充入口层级说明）
- 处理建议：修正（将人事服务域下所有 `管理后台 →` 前缀改为 `人事服务 →`）

## 4. 不确定点

- [GAP] "管理后台"的完整菜单树当前未采集入库，无法做全量交叉校验。
