# 权限查询逻辑与交互全景

## 1. 知识讨论背景

用户询问"现在平台的权限查询是什么逻辑和交互"。当前权限查询相关知识分散在 `12_查询与配置路径`、`15_页面载体语义`、`10_能力地图`、`11_任务场景` 四份文件中，缺少一份面向"权限查询到底是什么、怎么用、有哪些缺口"的整合视图。本次回答将分散信息归纳为一份完整交互全景。

## 2. 候选知识

### 2.1 查询定位

权限查询是独立于配置的解释与排障入口，承担"穿透查看用户、角色、权限之间关系"，不承担配置职责。页面类型为 Page，位于 `通用权限管理 -> 权限查询`。

### 2.2 查询维度与可行性

| 维度 | 可行性 | 承载页面 |
|------|--------|----------|
| 按用户查 | 完整 | 权限查询 → 按用户查询结果 → 权限详情 |
| 按角色查 | 部分可行 | 依赖角色管理页，缺少独立查询结果视图 |
| 按应用查 | 完整 | 应用管理 → 应用设置页 |
| 按变更查 | 部分可行 | 分散在权限域与审批域之间，缺少统一变更台账 |
| 按权限/功能点查 | 缺口 | 反向查询"某功能点被谁持有"的承载未核实 |

### 2.3 按用户查询的完整交互链路（主链路）

**步骤一：发起查询**
- 页面：[权限查询] Page
- 交互：左侧查询配置区，下拉切换"按用户"，选择目标用户，点击查询
- 初始态：右侧展示主题插画引导

**步骤二：查看结果汇总**
- 页面：[按用户查询结果] Page
- 交互：按应用粒度聚合展示，含应用名称、分类、终端图标（PC/移动端）、有权限功能数/全部功能数（分子/分母）、操作列
- 能力：支持按应用名称二次检索、分页、点击"权限明细"下钻

**步骤三：查看权限明细**
- 页面：[权限详情] Modal
- 交互：只读弹窗，含权限身份解释（全员默认 / 管理端 / 超管）、电脑端/移动端切换、左侧业务模块导航、右侧功能点与数据权限明细
- 职责：纯解释层，不承载配置

### 2.4 核心设计原则

1. 查询与配置分离：查询页只解释"谁有什么权限、为什么"，不授予或修改
2. 渐进式信息披露：先按应用聚合 → 再按需下钻到功能点和数据范围
3. 分子/分母量化：用"已授权功能数 / 全部功能数"帮助判断权限深度和风险
4. 多端差异可见：电脑端和移动端权限可能存在差异，查询链路明确支持端切换

### 2.5 查询页结构要点

[权限查询] 页采用左右双栏：
- 左侧：多维检索条件配置区（查询维度下拉 + 对象选择器 + 查询按钮）
- 右侧：初始态视觉插画引导

[按用户查询结果] 页：
- 顶部：已查询结果栏（可修改查询条件重新查询）
- 中部：应用级权限概览表格（应用名称、分类、终端、功能统计、权限明细入口）
- 底部：分页

[权限详情] Modal：
- 顶部：权限身份说明文本
- 视图切换：权限类别 Tab + 端切换胶囊
- 主体：左侧一级分类导航 + 右侧模块明细表格堆叠
