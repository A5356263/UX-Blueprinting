# 领域识别与领域卡片读取规则

## 领域范围

UXB 复杂度判断覆盖六大领域：

- 协同办公
- 人事服务
- 薪税代发
- 财务费控
- 平台门户
- 管理后台

## 读取原则

1. 先用通用复杂度判断标准判断。
2. 再识别需求更接近哪个业务域。
3. 如果领域明确，读取对应领域卡片。
4. 如果跨领域，只读取相关多个领域卡片。
5. 如果只是纯前端展示调整，可以不读领域卡片。
6. 判断不准时，读取相关领域卡片辅助提问。

领域卡片读取的目标是补足当前判断依据，不是为了完整性通读更多知识。

不要每次通读全部领域卡片。

## 跨领域读取

如果需求明显跨域，只读取相关卡片，不读全部领域。

例如：

- 入职后自动开通应用入口：读人事服务 + 平台门户 + 管理后台
- 报销审批后自动付款并入账：读协同办公 + 财务费控
- 发薪失败后同步工资单状态：读薪税代发 + 人事服务
- 外部人员进入协作、门户和权限体系：读人事服务 + 平台门户 + 管理后台
- 角色首页如果同时影响入口权限：读平台门户 + 管理后台

## 容易误判的边界类型

以下不是固定触发词，而是常见的高误判边界类型。命中相似语义时，不要只按字面领域直接下结论：

- 涉及“外部人员、外包人员、顾问、供应商人员”等非标准员工身份
  - 先判断是新增展示对象，还是进入员工主数据、组织、权限和流程体系。
- 涉及“不同角色看到不同首页、入口或工作台”
  - 先判断是只改首页展示，还是同时改变应用可见性、身份识别或入口分发规则。
- 涉及“统一待办、统一任务中心、统一任务视图”
  - 先判断是入口聚合，还是统一任务对象、状态和回写链路。

## 可不读领域卡片的场景

以下场景可以不读领域卡片：

- 明确只是视觉调整
- 明确只是字段顺序、提示语、空状态、卡片尺寸
- 已明确不改对象、规则、状态、生效、口径、回写

但回复里仍应说明为什么这是低复杂度，而不是只报结论。
