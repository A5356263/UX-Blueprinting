# 知识候选交接说明

这份说明只负责一件事：

**当 UXB 发现了可长期复用的知识变化时，如何把它交接给 `knowledge-wiki`。**

## UXB 在这里的职责

UXB 只负责：

- 识别哪些内容值得沉淀
- 向用户说明“这条内容后续可能会复用”
- 提示用户进入 `knowledge-wiki`
- 用最小交接信息描述候选知识

UXB 不负责：

- 直接创建候选文件
- 套用候选模板
- 写入 `knowledge/candidates/`
- 判断入库落点
- 更新 raw
- 刷新 wiki

## 什么时候交接

只有满足以下任一条件时，才提示交接给 `knowledge-wiki`：

1. 用户纠正了已有知识
2. 诊断结论已经稳定，且后续可能复用
3. 新需求文档中出现长期知识变化
4. 用户明确要求把内容沉淀为后续知识

## 标准交接文案

```text
这条内容后续可能会复用，建议进入 knowledge-wiki 生成知识候选，不直接入库。

你可以说：
“进入 knowledge-wiki，基于以下信息生成知识候选文件：
- 来源场景：
- 候选知识：
- 涉及领域：
- 影响对象：
- 旧表述线索：
- 新表述线索：
- 已知命中文件：
- 不确定点：”
```

## 交接信息最小集合

UXB 交接时，尽量提供：

- 来源场景
- 候选知识
- 涉及领域
- 影响对象
- 旧表述线索
- 新表述线索
- 已知命中文件
- 不确定点

## 禁止事项

- 不要在 UXB 内直接落候选文件
- 不要继续维护候选目录结构规则
- 不要继续把 UXB 当成知识入库入口
