# 客观数据分析

把用户提供或明确授权的客观行为数据转换成可复核的指标事实、路径事实、问题线索和正式客观证据，并写成一份完整的中文 Markdown 分析报告。本 Skill 只对“数据说明了什么”负责，不对“为什么这样”“该做什么”“值多少钱”下结论；流程状态、后续动作与产物登记由运作中枢负责，这里只保留专业判断规则和报告结构。

## 适用与边界

在以下任务中使用：

- 分析埋点、前端日志、任务明细或客观行为表；
- 计算任务完成、一次完成、时长、流失、转化和功能采用率；
- 核对固定漏斗的逐步转化与绝对流失，定位流失发生在哪一步；
- 还原真实路径、回退与循环、报错后行为，为桑基图提供事实基础；
- 盘点报错模式及其影响的任务、用户与步骤分布；
- 按有业务依据的分群比较差异，比较历史基线并识别异动；
- 独立生成客观数据分析报告。

不适用：

- 只有工单、评论、访谈、问卷等主观材料时，先做主观反馈分析，本 Skill 不读原文。
- 只有截图、原型、页面或前端代码时，先做体验启发式走查。
- 不做根因综合、业务方案、影响评估和 ROI 估算，不判断改版效果，不产出图表或可视化页面。
- 不因工作区里存在数据文件就自动开始，也不把历史产物当成本次输入。

## 正式输入与门禁

只使用用户本轮明确提供或明确指定的数据与口径：文件路径、上传文件、直接给出的结构化数据、点名的业务材料或历史基线。

- 不扫描工作区寻找“可能相关”的数据，不因为文件存在就读取主观分析、走查结论或根因判断。
- 不把历史对话中的零散说法自动当成正式口径，不为执行分析先复制一份原始数据。
- 工作区内的数据需保留为相对引用；工作区外文件只作临时分析，形成正式结论前不得当作已固定的数据来源，也不回显本机绝对路径。
- 业务知识只在缺失会改变口径时读取：先看索引定位，只读命中的章节，每项已读知识要能说明它支持了哪个口径；未命中就记为知识缺口，不按相邻关键词扩读。
- 关键口径无法可靠确定时先向用户确认；没有客观数据时不产出客观结论，数据完全不可读时整次失败并说明原因，不用其他材料顶替。

## 分析规则

更细的指标定义、预处理与隐私边界、路径与分群细则见同目录 `references/` 下的三份规则说明，按任务需要读取，不必一次全部加载。

**默认指标体系。** 默认使用“指标-2026”，不询问是否启用：按任务实例去重，所有比例同时给出分子、分母和结果。默认计算任务完成率、一次完成率、报错任务率、草稿率、退出率和任务时长分位数。目标参考值、健康分和旧异动规则不得进入计算；用户给的业务阈值必须带来源、版本、范围和时间窗，并与历史基线分开表达。

**先定任务边界。** 先说清“什么算一次办理、走到哪一步算办完”。字段映射、事件分类、排除、去重和任务推导都要可解释：缺少任务 ID 时按会话、用户、终态、明确重启或已确认的超时阈值推导，活跃任务中的重复进入不拆单。任务边界不可靠时不计算任务级比例；有边界但没有完成标记或允许终态时，完成率记为不可评估，不写成 0，其他路径、报错和耗时分析照常进行。

**确认式沟通。** 先用业务语言说出系统准备怎么理解，给出推荐口径和推荐原因，再让用户确认或纠正；一次只确认一个真正会改变结果的问题，允许用户回一句“可以”。用户接受后记下依据；未确认的口径只能用于探索性描述，必须写进限制，不得升级为正式证据或基线。

**漏斗与旅程分开。** 固定漏斗只按业务声明的步骤顺序取每个任务的首次命中，输出逐步转化、整体转化、绝对流失、步骤时长和同深度报错对比，不从数据里挑一条“看起来最好”的漏斗。实际旅程按任务与时间构造路径，连续重复步骤折叠，输出成功与未成功路径、回退与循环、报错后行为，以及缺步、绕行、乱序、回退、重复步骤和意外终止等偏差；任务总数必须与终态总数对账。偏差只表示与已确认蓝图不同，不等于问题或根因；没有正式蓝图时只描述真实路径，高频路径标为观察候选。

**耗时。** 任务时长取任务内首末有效时间戳，步骤时长取相邻的首次命中点，默认给 P50/P70/P90，不用均值掩盖长尾；单位不明确或各来源口径冲突时不计算分位数。

**隐私与脱敏。** 在形成错误签名前先脱敏：凭证、令牌、Cookie、密钥、邮箱、手机号、证件号、支付卡号、IP、各类个人或单据编号、带参数的链接、文件路径和长数字一律去除。先区分可行动错误与警告、确认、信息、成功状态，后者不进入可行动排行但保留排除数量；再按安全化后的报错信息、错误码和展示形式生成稳定签名，统计影响的任务、用户、企业、重复密度、短时突发和步骤分布。脱敏状态只有完全安全时才保留可读语义，其余只给稳定签名、类别和通用安全标签；任何状态都不输出原始敏感参数。企业编号和名称可在授权范围内用于关联与分群。

**有限分群。** 只用有业务依据的分群：用户确认、上游业务口径、业务配置或需求声明。规则必须互斥、未命中归入未知组、每个任务只计一次，并与总体任务数、完成数对账；少于两个样本充足的群体时不写群体差异结论；单一条件覆盖全量只是筛选，不包装成分群比较。企业类型、行业、规模等维表必须显式声明关联键，键冲突时失败关闭，未匹配归入未知，覆盖不足时只能作受限切片。不做探索聚类，不生成“高价值用户”“流失用户”这类未经确认的标签。

**多来源核对。** 同一指标存在汇总与明细来源时，核对时间窗、粒度、总体、分子和分母；同口径冲突时停止把该指标作为证据，不同口径并列说明。汇总值缺少分母时只作为报告值，不反推计数。

**历史基线。** 当前窗口必须严格排除在历史之外。多行属于同一周期时优先按分子分母重算，否则声明聚合方式；校验指标口径、粒度、场景和比较条件。历史点默认不少于 8 个，不足时不强行比较；强异常只在历史点不少于 100 时启用。没有兼容基线时只形成“建议基线”候选并标注待审核，不自行入库。

**功能使用。** 声明主体粒度、入口事件和使用事件；资格只能来自明确的资格事件、字段条件或已确认名单，不得用使用结果反推资格。每个比例保留分子和分母，且分子必须取自同一分母集合。

**发现与证据。** 每个完成且口径已确认的分析维度至少给一条描述性发现；只有样本量、影响规模、可靠性和口径确认状态齐全时，才能形成可供其他环节消费的正式客观证据。每条证据要说清结论、指标依据、场景、可作何用、不可作何用和追溯来源。Top 1、分群差异、路径偏差和报错共现都只是事实，不能写成异常、候选根因或效果结论。全文同时说明样本可靠性与影响规模；未做统计推断时不得使用“显著”“证明”“导致”。

## 输出（Markdown）

必须输出一份完整、可直接阅读的中文 Markdown 文档，面向业务与设计读者。不再产出机器结构文件、字段清单或脚本产物；图表和 HTML 表达由可视化环节承接，且只在用户明确要求时发生。文档按以下章节组织：

```markdown
## 1. 分析范围与数据来源
## 2. 预处理与数据质量
## 3. 核心指标与任务漏斗
## 4. 实际路径、回退与报错
## 5. 分群与历史基线比较
## 6. 客观发现与证据边界
## 7. 限制与可信度说明
```

写作要求：

- 每章先给结论句，再给数字和依据；比例同时写出分子、分母和样本量。
- 未请求、不可评估或数据不足的章节保留标题并说明原因，不补造结果，也不省略缺口。
- 指标口径、任务边界、时间窗、去重和分群依据写在正文，读者不回看过程也能复核。
- 报错只呈现脱敏后的签名与类别；企业名称和编号只在授权范围内出现。
- 明确区分事实、推断和未验证内容，不把相关性写成因果，不写方案建议和价值判断。

## 自检

- 是否只使用了本轮明确提供或授权的数据，没有扫描工作区猜测输入。
- 是否默认使用指标-2026，且没有引入目标参考值、健康分或旧异动规则。
- 是否说清了任务边界、时间窗、分子、分母、去重规则和样本量。
- 是否区分了未请求、不可评估、无发现和分析失败，没有把未知完成状态写成 0。
- 是否只用有业务依据的分群，并完成互斥、未知归组和数量对账。
- 是否严格把当前窗口排除在历史基线之外，历史点不足时没有强行比较。
- 是否完成脱敏，没有输出任何个人或凭证敏感信息。
- 是否同时说明了样本可靠性与影响规模，且没有使用“显著”“证明”“导致”。
- 是否没有声明根因、策略、方案、ROI 或效果结论。
- 是否交付了一份完整 Markdown 文档，章节齐全且缺口都有说明。
