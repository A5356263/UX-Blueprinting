# 来源分级定义

Phase 2 的每条策略都必须标注 source_type。以下是 5 级来源分级的完整定义。

## 分级表

| source_type | 含义 | 使用方式 |
|---|---|---|
| `material_explicit` | 材料明确写出的 FR、指定交互、结构调整、优化目标或验收口径 | 可作为较强依据直接呈现 |
| `material_inferred` | 从材料行为、流程、界面信号推断，材料未直接写出 | 可进入主策略，保留推断边界 |
| `kb_pattern` | 与 knowledge 中已有模式对应 | 可作为复用经验来源，用于补充边界和风险 |
| `domain_inference` | 基于领域知识提出，材料未直接写出 | 可进入候选或主策略，必须写成立前提或待确认项 |
| `design_hypothesis` | 设计假设，材料无锚点、无 kb 支撑、无领域共识 | 只能作为需验证方向，不应写成已确认方案 |

## 来源判断要点

### material_explicit vs material_inferred 的边界

`source_type` 看的是策略核心机制本身是否有材料锚点，不是看它回应的问题是否有锚点，也不是看实现条件、能力或依赖是否已确认。

- 材料已明确写出的 FR、指定交互、结构调整、优化目标或验收口径 → `material_explicit`
- 只有材料没有直接给出、但能从行为/流程/界面信号推导出的 → `material_inferred`

实现条件、能力或依赖的不确定性应写入成立前提或待确认项，不参与来源判断。

### domain_inference 的边界

当策略核心机制基于领域知识提出、材料未直接写出时，标 `domain_inference`。必须写成立前提，说明该策略在什么条件下成立、什么条件下需要降级。

不得因"材料未确认实施条件/能力/依赖"而将策略降为 `domain_inference`——这类不安定因素写入成立前提即可。

### design_hypothesis 的边界

证据最弱的一档。当策略核心机制缺少材料锚点、kb 支撑和领域共识时使用。只能作为需验证方向呈现，必须在「前提与降级」中说明验证方式。

## 常见错误

- 把问题有材料锚点等同于策略有材料锚点——来源看策略机制本身
- 把实现条件不确定等同于来源不可靠——不确定写入成立前提，不影响来源判定
- 把 kb_pattern 当作 stronger signal——kb 只提供经验参考，不替代材料裁决
- domain_inference 不写成立前提——这是最常见的遗漏，会让未确认假设伪装成已确认方案
