# 策略方向库

供 Phase 2 辅助校准策略方向的适用条件、落地手段和失败边界。
Phase 1 问题识别和候选方向生成阶段不读此文件——候选方向应由模型基于材料和领域推理独立生成，读此文件只用于校准已有方向，不用于产生新方向。

**使用方式**：根据已识别的问题和设计判断选择匹配的策略方向，参考其适用条件和落地手段辅助策略展开。不替代针对当前项目的设计裁决。

**阅读提醒**：以下 `适用 / 不适用 / 参考落地手段 / 参考指标` 都是启发式判断，不是机械打分规则；应结合当前材料的任务目标、风险和约束综合判断。

## 策略方向

### 降低输入成本
**适用**：用户需要重复填写跨任务相同字段；字段值可从历史记录或当前信息推断；高频操作主要负担是录入本身  
**不适用**：字段每次需主动确认，预填可能引发误操作；合规要求强制手动输入  
**参考落地手段**：智能预填/默认值、渐进式披露（按条件分步展示）、表单分组与分步裁决、草稿保存  
**参考指标**：任务完成率、任务完成时长

### 提升操作可信度
**适用**：操作不可逆或修复成本高（删除、提交后不可修改）；操作会影响他人或下游系统；用户对操作结果有不确定感  
**不适用**：低风险操作频繁触发确认会打断节奏；用户已非常熟悉且结果可预期  
**参考落地手段**：内联字段校验（即时反馈）、操作影响实时预览、二次确认弹窗、成功/失败 toast 反馈  
**参考指标**：折返率、提示信息出现率

### 提升流程透明度
**适用**：流程有多个中间状态，用户需要知道当前在哪个节点；后续步骤有等待或依赖他人；不同角色看到不同数据范围  
**不适用**：简单线性操作用户能自然感知；状态变化频率极低  
**参考落地手段**：状态标签体系、列表筛选结构（按状态过滤）、进度可视化  
**参考指标**：用户提问量、任务节点完成率

### 优化信息层级
**适用**：页面同时承载主任务与低频管理任务，主次不清；信息密度高导致扫读困难；不同角色对同一页面关注点差异明显  
**不适用**：信息量少且结构简单，分层反而增加查找路径；用户需要一次看到全部信息进行对比  
**参考落地手段**：渐进式披露、表单分组/分步判断、列表筛选结构、就近呈现相关信息  
**参考指标**：任务完成时长、AI 清晰度评分

### 保留原位置
**适用**：填写期间用户需要跳出查阅信息再回来；子流程完成后需要回到原位置；列表有筛选状态，操作后需要保留  
**不适用**：任务是一次性短操作无中断风险；保留原位置会导致用户看到过期状态  
**参考落地手段**：草稿保存、状态驱动入口（带着当前状态进入）、就近入口触发  
**参考指标**：任务完成率、折返率

### 降低行动负荷
**适用**：完成主任务需要跨多个页面跳转或步骤明显偏多（如超过 3 步可作为信号）；存在重复触发的低价值确认；高频任务路径过长  
**不适用**：高风险操作需要步骤数建立决策停顿；合规流程要求每步有明确记录；步骤本身承载信息确认价值  
**参考落地手段**：渐进式披露、场景内触发入口、状态驱动入口  
**参考指标**：任务完成时长、任务完成率

### 前置错误拦截
**适用**：规则复杂且分散，用户填写阶段难以主动判断；错误修复成本高（需要重走流程）；提交后集中报错打断完整理解  
**不适用**：字段少且规则简单；实时校验会打断连续输入节奏；约束信息字段旁已充分可见  
**参考落地手段**：内联字段校验、提交前完整性检查（checklist）、预算/规则前置校验、就近呈现约束信息  
**参考指标**：提示信息出现率、任务完成率

### 流程闭环与后续引导
**适用**：任务完成后有明确后续动作；提交结果不在当前视图内需要跳转确认；任务链有上下游依赖需要引导下一步  
**不适用**：任务是终点动作无后续需求；结果已在当前页面充分可见  
**参考落地手段**：状态标签、列表筛选结构、空状态引导、行内结果状态、toast 反馈  
**参考指标**：任务完成率、用户提问量

### 分级引导匹配
**适用**：存在新手用户或低频操作，规则无法通过界面自解释；操作有不可逆风险需提前告知；同一功能面向不同熟悉度的用户群体  
**不适用**：用户已熟悉操作，引导会打断高频操作；规则简单到字段标签和占位文本即可理解  
**参考落地手段**：新手引导（全流程遮罩）→ 帮助文档/外链 → 问号/Tooltip → 前置暗提示/占位文本 → 后置校验（仅用于无法前置的服务端校验）  
**引导侵入度原则**：按用户熟悉度和操作风险从高到低选择  
**参考指标**：任务完成率、用户提问量

### 保持一致性
**适用**：同类操作在不同页面有用户预期，打破一致性会造成困惑；跨场景一致性能显著降低学习成本  
**不适用**：强制一致会导致某场景信息过载；两场景任务目标差异大，强行一致反而造成困惑  
**一般取舍顺序**：通常先保证简洁和场景适配，再考虑一致性；若一致性能明显降低学习成本，也可优先保留一致性  
**参考落地手段**：统一状态标签体系、统一就近呈现相关信息  
**参考指标**：任务完成时长、AI 清晰度评分

## 常用落地手段速查

| 手段 | 适用场景 | 典型错误 |
|---|---|---|
| 智能预填/默认值 | 高频重复字段、可从历史推断 | 预填低准确率时反而引发误操作 |
| 渐进式披露 | 字段多/步骤多，只展示当前需要的 | 把并排比较任务拆成分步 |
| 表单分组 | 字段多但同属一次提交、主题可分 | 把弱依赖字段也拆成独立步骤 |
| 内联校验 | 规则明确可前置的字段 | 在自由文本输入中触发，打断节奏 |
| 二次确认弹窗 | 不可逆或影响他人的高风险动作 | 在低风险高频操作中使用，造成疲劳 |
| 状态标签 | 对象有多个有意义的中间状态 | 状态含义不清，用户不知道下一步 |
| 提交前检查清单 | 多条件前置、离职/结账等流程 | 清单太长、阻断非必要项 |
| 草稿保存 | 长填写流程、有中断风险 | 草稿恢复时状态已过期或不可用 |
| 空状态引导 | 首次使用或搜索无结果时 | 只写"暂无数据"没有后续操作引导 |
| 主动通知推送 | 审批超时、异常状态、状态变更 | 通知频率过高，用户屏蔽 |
| 进度可视化 | 多步骤流程、有等待阶段 | 步骤名称泛化，看不出当前具体状态 |

## 参考指标速查

| 指标 | 说明 | 对应策略方向 |
|---|---|---|
| 任务完成率 | 尝试执行后成功完成的比率 | 降低输入成本、保留原位置、流程闭环 |
| 任务完成时长 | 从起点到终点的耗时 | 降低输入成本、优化信息层级、降低行动负荷 |
| 折返率 | 流程中发生回退/重复操作的比率 | 提升操作可信度、保留原位置 |
| 提示信息出现率 | 阻断式报错/提示出现的频率 | 提升操作可信度、前置错误拦截 |
| 用户提问量 | 客服/机器人收到的用户问题数 | 提升流程透明度、流程闭环 |
| 任务节点完成率 | 特定节点内完成该节点操作的比率 | 提升流程透明度 |
| 满意度得分 | 用户主观评分（NPS/问卷等） | 优化信息层级、提升操作可信度 |
| 功能使用率 | 使用特定功能的用户占有权限用户比率 | 优化信息层级、提升流程透明度 |
