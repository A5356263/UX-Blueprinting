## 1. 组件总览


### 1. 组件总览

数据展示类组件主要用于承载结构化信息、只读信息、层级信息、状态提示和数量提示。不同组件适合不同的信息密度和交互复杂度。

| 组件 | 主要用途 | 典型场景 | 关键能力 |
|---|---|---|---|
| Table 表格 | 展示多行多列结构化数据 | 列表、订单、单据、人员、账单、审批记录 | 排序、筛选、分页、选择、操作、状态展示、图片展示 |
| 表格-表头筛选 | 对表格某一列进行条件筛选 | 表格中按文本、数值、日期、状态、树形选项筛选 | 筛选浮层、重置、确认、搜索、单选、多选、树选择 |
| Descriptions 描述列表 | 展示一个或多个只读字段组合 | 详情页、审批详情、合同信息、付款信息、基础资料 | 左右结构、上下结构、带边框、字段标签与内容对齐 |
| Tree 树形控件 | 展示层级结构数据 | 文件夹、组织架构、分类目录、权限树、级联目录 | 展开、收起、选择、复选、图标、排序、异步加载 |
| Badge 徽标 | 提示数量、状态或未处理信息 | 未读消息、待处理数量、新内容、状态标记、导航提示 | 数字徽标、圆点徽标、状态徽标、描边/非描边、图标叠加 |

## 4. Descriptions 描述列表


### 4. Descriptions 描述列表

#### 4.1 何时使用

Descriptions 用于展示一个或多个只读字段的组合，适合详情页、信息确认页、审批页、合同页、付款页等场景。

适合使用的场景：

- 展示只读字段。
- 展示基础信息、合同信息、付款信息、申请信息。
- 展示字段数量中等，不需要用户直接编辑。
- 展示字段之间有清晰的 label 和 value 关系。
- 需要在详情页中组织字段信息。

不适合使用的场景：

- 数据是多行多列列表，应使用 Table。
- 数据有明显层级展开关系，应使用 Tree。
- 需要展示状态数量或未读提示，应使用 Badge。
- 字段需要高频编辑，应使用 Form 表单，而不是 Descriptions。

#### 4.2 组件结构

Descriptions 支持多种结构：

##### 左右结构

左侧为 label，右侧为内容详情。

适合：

- 字段较短。
- 字段较多，且需要快速扫描。
- 信息密集但仍需保持可读性。

##### 上下结构

上方为 label，下方为内容详情。

适合：

- 内容较长。
- 需要增强字段内容可读性。
- 页面宽度相对充足。

##### 带边框-左右结构

通过边框区分 label 和内容。

适合：

- 信息需要更强区隔。
- 审批、合同、财务等较正式的信息展示。
- 多组字段需要结构化展示。

##### 带边框-上下结构

上方 label，下方内容，并带边框分隔。

适合：

- 字段内容较长。
- 信息需要表格化排版。
- 需要更强的字段组边界。

#### 4.3 尺寸间距规则

##### 基础间距

| 属性 | 规格 |
|------|------|
| 标题距面板顶部 | 4px |
| 标题右侧边距 | 16px |
| 标题与首个表单项垂直间距 | 16px |
| 表单项之间垂直间距 | 16px |
| 多列布局左右两列水平间距 | 24px |
| Label 到输入区域水平间距 | 20px |

##### 带边框结构

| 属性 | 规格 |
|------|------|
| 顶部内边距 | 20px |
| 左右内边距 | 20px |
| 外容器与内部列表间距 | 8px |
| 左右布局 label 固定宽度 | 约 122px |

- 标签宽度不限制最小宽度，尽量不超过 6 个字，最大不超过 128px。
- Label 背景色使用中性色，分割线使用中性边框色。
- 上下分割线不应重合造成视觉过重。

#### 4.4 内容规则

Descriptions 的内容可能包含：

- 普通文本。
- 长文本。
- 数字金额。
- 附件列表。
- 图片或图标。
- 表格嵌套。
- 链接。
- 状态标签。

规则：

- 长文本应允许换行。
- 附件应按列表展示，并提供预览、下载等操作。
- 金额应统一格式。
- 链接应有明显点击样式。
- 内容为空时，应使用统一占位符，如“-”。
- 同一组信息中的 label 与 value 对齐方式应保持一致。

#### 4.5 使用示例

Descriptions 常用于：

- 对公报账单详情。
- 合同信息展示。
- 支付明细。
- 审批详情。
- 付款申请详情。
- 员工薪资详情弹窗。
- 财务单据详情。
- 基础档案详情。

## 5. Tree 树形控件


### 5. Tree 树形控件

#### 5.1 何时使用

Tree 用于展示层级较多的内容，能够清晰表达父子关系、目录结构和组织关系，并支持展开、收起、选择等交互。

适合使用的场景：

- 文件夹目录。
- 分类目录。
- 组织架构。
- 权限树。
- 部门选择。
- 菜单配置。
- 多级数据关系。
- 需要展开和收起节点的层级数据。

不适合使用的场景：

- 数据只是普通列表，无明显层级关系。
- 数据是多列结构化信息，应使用 Table。
- 只展示一组只读字段，应使用 Descriptions。
- 层级过深且无法有效浏览时，应考虑搜索、分层页面或级联选择。

#### 5.2 组件结构

Tree 主要由以下部分组成：

1. 展开/收起控件：用于展开或收起当前节点下的其他节点。
2. 文本：当前节点展示的文本内容。
3. 复选框：支持节点复选。
4. 图标：支持树状结构节点显示图标。
5. 拖拽/排序控件：用于调整节点顺序。
6. 当前节点状态：如正常、悬停、选中、禁用。

#### 5.3 尺寸布局

##### 层级缩进

| 属性 | 规格 |
|------|------|
| 第一级节点左侧缩进 | 8px |
| 子级节点相对父级缩进 | 20px |

##### 元素间距

| 属性 | 规格 |
|------|------|
| 展开图标到文本间距 | 4px |
| 文本到右侧边缘间距 | 32px |
| 单行高度 | 32px |
| 条目之间垂直间距 | 8px |

- 不同层级之间的缩进必须一致。
- 选中背景应覆盖节点文本区域，突出当前项。

#### 5.4 样式状态

Tree 支持以下状态：

| 状态 | 说明 |
|---|---|
| 正常 | 默认展示状态 |
| 悬停 | 鼠标移入节点时的状态 |
| 选中 | 当前节点被选中 |
| 禁用 | 节点不可操作 |
| 展开 | 节点子级已展开 |
| 收起 | 节点子级已隐藏 |
| 复选选中 | 节点复选框被选中 |
| 半选 | 子节点部分选中时，父节点可展示半选状态 |

#### 5.5 控件类型

Tree 可包含不同控件类型：

- 默认树：仅展示展开、收起和文本。
- 带图标树：节点前展示文件夹、文档、分类等图标。
- 排序树：节点前展示拖拽或排序操作控件。
- 单选树：一次只能选中一个节点。
- 复选树：可选择多个节点。
- 异步加载树：点击展开节点后动态加载子数据。

#### 5.6 文本显示规则

Tree 节点文本默认在控件区域内单行显示，超出部分使用省略号，鼠标悬停可显示完整文本。

规则：

- 默认一行展示，超出省略。
- 支持调整为换行显示。
- 换行时折叠箭头、图标、复选框应与第一行文本对齐。
- 文本过长时不应挤压展开箭头或选择控件。
- 多级树文本应保证层级缩进清晰。

#### 5.7 树状层级数

树状层级数支持业务自定义。

推荐规则：

- 一般建议不超过 6 级。
- 如果层级过深，应提供搜索能力。
- 如果层级过深且数据量很大，应考虑异步加载。
- 对权限、组织架构等复杂树，可根据业务需要扩展层级，但必须保证浏览效率。

#### 5.8 异步数据加载

Tree 支持点击展开节点后动态加载子节点。

适合：

- 数据量大。
- 层级深。
- 初始加载全部数据成本高。
- 组织架构、文件目录等动态数据。

规则：

- 展开时应有加载反馈。
- 加载失败应可重试。
- 已加载节点应避免重复请求。
- 异步加载不应改变用户已选状态。

## 6. Badge 徽标


### 6. Badge 徽标

#### 6.1 何时使用

Badge 用来代表用户或事物，支持图片、图标或字符展示，也常用于提示未读数量、待处理数量、新内容、状态点等信息。

适合使用的场景：

- 显示未读消息数量。
- 显示待处理任务数量。
- 显示新功能、新内容。
- 在导航、菜单、Tab、图标、文本旁提示数量或状态。
- 表示一组不同状态的视觉提示。
- 通过颜色表示成功、错误、正常、进行中、警示等状态。

不适合使用的场景：

- 需要展示详细数据，应使用 Table。
- 需要展示字段详情，应使用 Descriptions。
- 需要展示层级结构，应使用 Tree。
- 提示内容非常复杂，不能仅用数量或圆点表达时，应使用更完整的通知或提示组件。

#### 6.2 组件结构

Badge 结构包括：

1. 徽标内容：可以是数字或文本。
2. 徽标色值：支持多种颜色。
3. 徽标类型：圆点、数字气泡、状态点等。
4. 被附着对象：图标、文本、导航项、应用图标等。
5. 边框：可选，用于图标或文案叠加场景。

#### 6.3 徽标类型

##### 数字徽标

用于显示具体数量。

适合：

- 未读数量。
- 待处理数量。
- 新消息数量。
- 审批数量。

规则：

- 显示具体数值，传递“量化”信息。
- 数字较大时可显示为 99+。
- 数字徽标通常用于 icon、文本、导航等元素旁。
- 核心价值是明确提示数量。

##### 圆点徽标

用于提示存在未处理内容，但不强调数量。

适合：

- 有新内容。
- 有未处理事项。
- 弱化数量，只提示存在性。
- 图标或文本左上/右上轻提示。

规则：

- 无具体数值。
- 通过视觉红点提示存在未读或新内容。
- 仅传递“存在性”信息。
- 不应承载复杂含义。

##### 状态徽标

用于展示不同状态。

适合：

- 成功。
- 错误。
- 正常。
- 进行中。
- 警示。

状态颜色建议：

- 绿色：成功、已完成。
- 红色：错误、异常、需要关注。
- 灰色：正常、未开始、不需要处理。
- 蓝色：进行中、处理中。
- 橙色：警示、风险提示。

#### 6.4 尺寸布局与缩紧规则

Badge 支持数字和文本类型，多种颜色状态（成功/错误/正常/进行中/警示），表现为圆点或数字气泡。

##### 红线标识间距

| 场景 | 属性 | 规格 |
|------|------|------|
| 导航锚点/文本 + 徽标 | 徽标距文本右侧 | 8px |
| 导航锚点/文本 + 徽标 | 徽标到容器边缘 | 8px |
| 图标 + 数字徽标 | 徽标距图标顶部/右侧 | 10px |
| 图标 + 数字徽标 | 部分布局下徽标距图标 | 4px |
| 应用图标 + 数字徽标 | 徽标距图标边缘 | 8px 或 4px（按比例） |

- 数字徽标应保持圆角胶囊形态。
- 圆点徽标应保持视觉轻量。
- 徽标过大时应避免遮挡底层图标或文本。

#### 6.5 描边与非描边

Badge 支持描边和非描边两种样式。

##### 带描边

适合：

- 徽标叠加在 icon 或文案上。
- 背景复杂，需要保证徽标清晰可见。
- 徽标与底层元素颜色相近。

##### 不带描边

适合：

- 徽标单独使用。
- 徽标跟在文案前面或后面。
- 背景简单、对比度足够。

#### 6.6 使用场景规则

推荐规则：

1. 数字徽标常用于 icon、文本和导航等元素后，显示具体数值，明确提示未处理或新内容数量。
2. 圆点徽标常用于 icon 或文本左上/右上，仅表示存在新内容或未处理事项。
3. 状态徽标用于表达一组状态的视觉提示，不承载具体数量。
4. 带描边徽标用于叠加场景，不带描边徽标用于普通文本前后场景。

#### 6.7 Badge 示例场景

Badge 常用于：

- 左侧导航菜单未读数量。
- 顶部消息 icon 红点。
- Tab 标签数量提示。
- 应用图标待办数量。
- 单据状态提示。
- 表格状态列。
- 工作台待办入口。
- 系统消息入口。

## 7. 组件选择决策规则


### 7. 组件选择决策规则

#### 7.1 根据数据结构选择

| 数据结构 | 推荐组件 |
|---|---|
| 多行多列结构化数据 | Table |
| 表格中的单列条件筛选 | 表格-表头筛选 |
| 少量或中等数量只读字段 | Descriptions |
| 层级结构、父子关系、目录结构 | Tree |
| 数量提示、状态点、新内容提示 | Badge |

#### 7.2 根据信息密度选择

| 信息密度 | 推荐组件 |
|---|---|
| 高密度、多字段、多行 | Table |
| 中密度、字段详情 | Descriptions |
| 高层级、多节点 | Tree |
| 低密度、提示型信息 | Badge |

#### 7.3 根据交互需求选择

| 交互需求 | 推荐组件 |
|---|---|
| 排序、筛选、分页、批量选择 | Table |
| 对某一列表头字段筛选 | 表格-表头筛选 |
| 展开、收起、父子节点选择 | Tree |
| 查看只读字段详情 | Descriptions |
| 提示未读、待办、状态 | Badge |

#### 7.4 根据业务页面选择

| 页面类型 | 推荐组件 |
|---|---|
| 列表页 | Table |
| 详情页 | Descriptions |
| 目录页 | Tree |
| 工作台、导航、消息入口 | Badge |
| 表格字段筛选 | 表格-表头筛选 |

#### 8.4 Tree 检索关键词

树形控件、层级结构、父子关系、目录、文件夹、组织架构、分类目录、权限树、展开、收起、节点、复选、单选、异步加载、拖拽排序、层级缩进、树选择。

#### 8.5 Badge 检索关键词

徽标、红点、数字徽标、圆点徽标、状态徽标、未读数量、待处理数量、新消息、新内容、状态提示、导航提示、99+、成功、错误、进行中、警示、描边徽标、非描边徽标。

## 9. AI 推荐优先级


### 9. AI 推荐优先级

当用户描述中出现以下需求时，AI 应优先推荐对应组件：

- “多行多列”“列表”“分页”“操作列”“批量选择” → 推荐 Table。
- “筛选某一列”“表头筛选”“点击筛选 icon” → 推荐 表格-表头筛选。
- “详情页”“只读字段”“基础信息”“合同信息”“字段和值” → 推荐 Descriptions。
- “层级”“目录”“组织架构”“父子节点”“展开收起” → 推荐 Tree。
- “未读数量”“红点”“待办数量”“新内容提示”“状态点” → 推荐 Badge。

## 10. 设计校验规则


### 10. 设计校验规则

#### 10.1 Table 校验

- 是否为多行多列结构？
- 是否需要分页或横向滚动？
- 操作列是否过多？
- 重要字段是否可见？
- 表头和内容是否语义一致？
- 空状态是否清晰？
- 图片列是否有统一尺寸？
- 标签是否过多并需要折叠？

#### 10.2 表头筛选校验

- 筛选是否与当前列强相关？
- 浮层宽度是否适合内容？
- 是否需要搜索？
- 是否需要单选、多选或树选择？
- 是否有重置和确定？
- 空状态是否清晰？
- 复杂选择是否应打开选择器弹窗？

#### 10.3 Descriptions 校验

- 是否为只读信息？
- label 和 value 是否对应清晰？
- 标签宽度是否统一？
- 长文本是否可换行？
- 带边框场景是否需要更强区隔？
- 空值是否有统一占位符？

#### 10.4 Tree 校验

- 是否存在真实层级关系？
- 层级是否过深？
- 是否需要搜索或异步加载？
- 节点状态是否清晰？
- 展开、收起、选择控件是否易识别？
- 文本过长是否有省略或换行规则？

#### 10.5 Badge 校验

- 是否只是提示数量或状态？
- 是否需要显示具体数量？
- 是否只需要红点提示存在性？
- 徽标是否遮挡底层元素？
- 是否需要描边保证可见性？
- 状态颜色是否符合语义？

## 12. Tooltip 文字提示


### 12. Tooltip 文字提示

#### 12.1 何时使用

Tooltip 用于提供简单的文字提示气泡。当用户移入某个触发元素时显示提示，移出后消失。Tooltip 不承载复杂文本和复杂操作，主要用于解释、补充、提示和查看被省略内容。

适合使用 Tooltip 的场景：

- 解释 icon 的功能。
- 解释设置项或字段含义。
- 提示按钮点击前的限制条件。
- 表头排序时提示当前排序状态。
- 表格中文本省略后，hover 显示完整内容。
- 对按钮、图标、省略号、表头、可点击区域进行轻量说明。
- 在不打断用户操作的情况下提供即时帮助。

不适合使用 Tooltip 的场景：

- 需要展示复杂内容、表单、操作按钮或多段说明。
- 内容需要用户长期阅读或复制。
- 需要用户主动确认、取消或提交。
- 需要展示结构化信息，如列表、详情、图片或文件。
- 提示内容非常关键，不能只依赖 hover 才能发现。

复杂说明应考虑 Popover、气泡卡片、弹窗、帮助文档或页面内说明。

#### 12.2 组件结构

Tooltip 通常由以下部分组成：

1. 三角箭头：指向触发点，说明提示来源。
2. 文本内容：用于承载简短说明文字。
3. 提示气泡容器：承载背景色、圆角、阴影和内边距。
4. 触发元素：可以是 icon、按钮、表头、省略文本或其他可 hover 区域。

#### 12.3 内容规则

Tooltip 文案应简洁直接，建议只承载短文本。

规则：

- 优先使用一句话说明。
- 避免多段复杂文本。
- 不建议超过 3 行，最多不超过 10 行。
- 若内容超过 10 行，应出现滚动条。
- 若需要展示复杂远胜信息，可改用气泡卡片样式。
- 文案应说明当前元素的含义、限制或状态，不应重复元素本身文案。

#### 12.4 尺寸与样式规则

##### 基础规格

| 属性 | 规格 |
|------|------|
| 字体大小 | 14px |
| 字体颜色 | #132240 85% |
| 宽度 | 自适应 |
| 最大宽度 | 320px（支持换行） |
| 高度 | 随内容延展 |
| 内容建议 | 不超过 3 行 |
| 内容上限 | 最多 10 行，超过滚动条 |
| 最大高度 | 208px |
| 文本区域内边距 | 各 8px |

- 三角箭头默认指向上方居中。
- 深色半透明背景，圆角保持小圆角。

#### 12.5 箭头方向规则

Tooltip 的方向根据触发点位置命名和选择。

常见方向包括：

- 上中。
- 上左。
- 上右。
- 下中。
- 下左。
- 下右。
- 左中。
- 右中。

优先规则：

- 默认优先显示在触发点下中位置。
- 若下方空间不足，可使用上中。
- 若页面右侧空间不足，可使用左侧方向。
- 若页面左侧空间不足，可使用右侧方向。
- 若触发点靠近页面边界，应选择不会溢出页面的方向。
- 三角箭头应准确指向触发元素或触发区域。

#### 12.6 交互规则

Tooltip 的触发方式以 hover 为主。

规则：

- 鼠标移入触发元素时显示。
- 鼠标移出触发元素时消失。
- Tooltip 不应阻断主流程操作。
- Tooltip 不应承载可点击按钮。
- Tooltip 不应替代错误提示或确认弹窗。
- 当用于说明按钮操作条件时，应在用户点击前帮助用户理解限制条件。
- 当用于省略文本时，应 hover 展示完整文本。

#### 12.7 典型业务场景

Tooltip 常用于：

- 展示 icon 功能说明。
- 对设置项进行进一步解释。
- 在用户执行操作按钮旁提示成功条件或限制条件。
- 排序表头展示文字提示，显示当前排序状态。
- 表格中文本省略时，hover 展示全部内容。
- 表头字段解释。
- 导航 icon 功能说明。

## 13. Collapse 折叠面板


### 13. Collapse 折叠面板

#### 13.1 何时使用

Collapse 是可以折叠和展开的内容区域，主要用于对复杂或非必要内容进行分组和隐藏，从而保持页面整洁。

适合使用 Collapse 的场景：

- 页面内容较复杂，需要分组展示。
- 部分内容不是用户当前必须阅读的信息。
- 设置页中存在多个配置分组。
- 表单页中存在多个字段分区。
- 详情页中需要将信息按模块展开或收起。
- 页面空间有限，需要减少默认信息密度。
- 用户需要自主控制是否查看某部分内容。

不适合使用 Collapse 的场景：

- 业务限制要求内容不可展开或不可折叠。
- 当前内容是核心流程信息，默认隐藏会影响理解。
- 内容非常少，没有折叠必要。
- 多个折叠区域嵌套过深，导致用户难以定位。
- 用户必须同时对比多个区域内容时，不宜折叠隐藏。

#### 13.2 组件结构

Collapse 通常包含以下结构：

1. 标题：说明当前折叠区域的内容主题。
2. 折叠按钮：用于点击切换展开或收起状态。
3. 操作按钮：对整体面板或标题进行操作。
4. 面板子内容：展开后显示的内容区域，可包含字段标题、说明文案、表单项、开关等内容。

#### 13.3 样式类型

Collapse 支持多种展示形式。

##### 大号折叠面板：标题灰色底

适合：

- 设置页。
- 表单页。
- 信息密集页。
- 需要突出分组边界的页面。

特点：

- 标题区使用灰色底。
- 标题区域更明显。
- 适合承载较多内容。
- 可支持标题区操作。

##### 大号折叠面板：标题白色底

适合：

- 视觉更轻量的详情页或设置页。
- 希望降低标题背景存在感的页面。
- 内容本身已具备明显分隔时。

特点：

- 标题区为白色底。
- 视觉更轻。
- 面板展开后内容区域仍保持清晰边界。

##### 小号折叠面板

适合：

- 空间受限区域。
- 高密度布局。
- 侧边栏。
- 容器宽度小于 1060px 的场景。
- 桌面配置类页面。

特点：

- 标题字号更小。
- 标题区高度更低。
- 支持收起、展开、禁用等状态。
- 可配合图标、拖拽、删除、开关等操作。

#### 13.4 操作按钮位置规则

Collapse 的操作按钮根据作用对象放置。

规则：

- 拖拽、折叠按钮放在标题左侧。
- 针对标题本身的操作放在标题侧，如编辑标题。
- 针对整个分组的操作放在右侧，如删除、启用开关、链接按钮。
- 操作按钮应与点击热区区分，避免误触。
- 标题区域可点击时，独立操作按钮应保留明确热区。

#### 13.5 尺寸布局规则

##### 大号折叠面板

| 属性 | 规格 |
|------|------|
| 标题文字 | 16px |
| 标题区固定高度 | 48px |
| 面板内边距 | 20px |
| 内容区垂直间距 | 20px |
| 顶部内边距 | 20px |
| 圆角 | 6px |

##### 小号折叠面板

| 属性 | 规格 |
|------|------|
| 标题文字 | 14px |
| 标题区固定高度 | 40px |
| 面板左右内边距 | 12px |
| 圆角 | 6px |

##### 交互规则

- 灰色卡片区域整体可点击展开/收起。
- 若同时存在其他操作（链接按钮、开关），需截断点击热区（互动热区分离）。

#### 13.6 交互规则

Collapse 支持展开、收起和禁用状态。

规则：

- 点击折叠按钮或标题区域可展开/收起。
- 大号折叠面板默认灰色卡片整体可点击展开收起。
- 小号折叠面板默认灰色卡片可点击展开收起。
- 若标题区存在其他操作，则需要划分点击热区。
- 禁用状态下不可展开或收起。
- 展开和收起状态应有明确箭头变化。
- 同组内容较多时，可默认折叠次要内容。

#### 13.7 使用场景

大号折叠面板适合：

- 独立页面。
- 弹窗。
- 容器宽度不小于 1060px。
- 设置页面。
- 表单页面。

小号折叠面板适合：

- 空间受限区域。
- 高密度布局。
- 侧边栏。
- 容器宽度小于 1060px。
- 桌面配置页面。

## 14. Carousel 走马灯


### 14. Carousel 走马灯

#### 14.1 何时使用

Carousel 用于展示一组平级内容。当内容空间不足时，可以用走马灯形式进行收纳和轮播展示。它常用于图片轮播、卡片轮播、首页模块或宣传内容展示。

适合使用 Carousel 的场景：

- 有一组平级内容需要轮播。
- 内容之间同级，不存在主从关系。
- 页面空间不足，需要收纳多项内容。
- 需要展示图片、卡片、公告、宣传图或工作台模块。
- 用户可以通过指示器或切换箭头查看不同内容。

不适合使用 Carousel 的场景：

- 内容之间有明显层级关系，应使用 Tree 或分组结构。
- 内容需要同时比较，不应隐藏在轮播中。
- 内容非常重要，用户必须全部看到。
- 内容很多且需要快速定位，应考虑列表或卡片网格。
- 轮播内容需要复杂操作，容易因切换造成误操作。

#### 14.2 组件结构

Carousel 通常包含：

1. 内容区域：承载当前轮播项，可为图片、卡片或模块内容。
2. 指示器：指示当前停留在哪个内容项，可点击切换。
3. 切换箭头：hover 时显示，点击切换到上一项或下一项。

#### 14.3 元素规则

##### 指示器

指示器用于展示当前轮播位置。

规则：

- 默认状态仅展示指示器。
- 当前项应高亮。
- 指示器可点击切换内容。
- 指示器不宜过多，否则会降低识别效率。
- 指示器通常位于内容区域底部居中。

##### 切换箭头

切换箭头用于手动切换不同内容。

规则：

- 默认不展示或弱展示。
- hover 内容区域时显示。
- 点击左箭头切换上一项。
- 点击右箭头切换下一项。
- 箭头应覆盖在内容区域左右两侧。
- 箭头不应遮挡核心信息。

#### 14.4 样式状态

Carousel 的元素支持不同状态。

指示器状态：

- 正常：未选中状态。
- 悬浮：鼠标移入状态。
- 点击 / 选中：当前轮播项状态。

切换箭头状态：

- 正常：默认状态。
- 悬浮：hover 状态。
- 点击：按下或切换状态。

#### 14.5 走马灯状态

Carousel 有两类典型显示状态：

##### 默认状态

默认状态通常只显示指示器，不显示切换箭头或弱化箭头。

适合：

- 内容数量不多。
- 不希望打扰用户。
- 轮播内容主要用于展示而非强操作。

##### 悬浮状态

悬浮状态展示切换箭头。

适合：

- 用户需要主动切换。
- 当前区域可交互。
- 需要提示用户还有更多内容。

#### 14.6 使用场景

Carousel 常用于：

- 首页图片轮播。
- 首页工作台卡片轮播。
- 公告或宣传内容轮播。
- 侧栏推荐卡片轮播。
- 产品动态、帮助入口、功能推荐。
- 内容空间不足时收纳多张图片或多张卡片。

#### 14.7 设计建议

- 轮播项内容应保持同类。
- 不同轮播项之间信息量应相近。
- 不应将核心操作隐藏在轮播中。
- 不建议轮播项数量过多。
- 自动轮播应避免打断用户阅读。
- 若用户正在 hover 或操作轮播区域，应暂停自动切换。
- 关键内容应提供其他入口，而不是只依赖轮播曝光。

## 15. Empty 空状态


### 15. Empty 空状态

#### 15.1 何时使用

Empty 用于当前没有数据时，对用户进行格式化提示。它也可用于初始化场景，引导用户创建流程或完成下一步操作。

适合使用 Empty 的场景：

- 当前没有数据。
- 搜索结果为空。
- 筛选结果为空。
- 表格中无数据。
- 页面内容为空。
- 抽屉或弹窗中无内容。
- 用户没有权限。
- 系统异常或网络错误。
- 图片加载失败。
- 初始化场景中需要引导新增或创建流程。

不适合使用 Empty 的场景：

- 数据仍在加载，应使用加载状态。
- 数据为空但无需占据视觉区域。
- 空状态会打断用户当前任务。
- 错误信息需要用户立即处理时，应使用错误提示或异常页。
- 权限问题需要明确说明时，不应只展示“暂无内容”。

#### 15.2 组件结构

Empty 通常包含：

1. 示意配图：辅助表达当前空状态含义。
2. 说明文案：描述当前场景内容，建议一行表达。
3. 标题文案：可选，用于更明确说明空状态主题。
4. 辅助文案：可选，用于补充说明或引导。
5. 按钮：可选，用于引导用户新增、刷新、返回、重试等。

#### 15.3 空状态分类

Empty 支持默认尺寸和小尺寸。

##### 默认尺寸空状态

| 属性 | 规格 |
|------|------|
| 图标尺寸 | 80px × 80px |
| 主要提示文字 | 14px，颜色 #132240 65% |
| 图标到文字垂直间距 | 16px |
| 标题与辅助文本垂直间距 | 16px |

适合：页面级空状态、基础表格页、抽屉或弹窗内容区。

##### 小尺寸空状态

| 属性 | 规格 |
|------|------|
| 图标尺寸 | 72px × 72px |
| 主要提示文字 | 12px，颜色 #132240 65% |
| 图标到文字垂直间距 | 12px |
| 标题与辅助文本垂直间距 | 16px |

适合：页面内局部区域、小表格、卡片区域、首页卡片。
- 检索为空。
- 网络出错。

#### 15.4 尺寸布局规则

默认尺寸空状态：

- 图标尺寸约 80px × 80px。
- 主文案字号约 14px。
- 图标与文案间距约 16px。
- 可支持按钮。
- 可支持标题和辅助文案。
- 页面级场景中，缺省图距离页面上下边距比例约为 3:7。
- 表格中使用时，空状态应根据表体高度适配。
- 抽屉中使用时，缺省图距离表体上下边距比例约为 4:6。
- 弹窗中使用时，缺省图距离内容区上下边距比例约为 3:7。

小尺寸空状态：

- 图标尺寸约 72px × 72px。
- 主文案字号约 12px。
- 图标与文案间距约 12px。
- 适合局部区域和小容器。
- 首页卡片中可使用小尺寸空状态，缺省图整体垂直居中，上间距约 16px，下边距约 20px。

#### 15.5 内容组合形式

Empty 可采用以下组合：

- 图标 + 文字。
- 图标 + 文字 + 按钮。
- 图标 + 标题 + 辅助文字 + 按钮。
- 仅文字。
- 小尺寸图标 + 文字。
- 小尺寸图标 + 文字 + 按钮。

设计建议：

- 页面级空状态优先使用默认尺寸。
- 表格高度较小时，可使用小尺寸或仅文字。
- 若需要引导用户创建数据，可增加主按钮。
- 若是异常状态，可增加重试按钮。
- 若是权限问题，应说明原因或提供申请入口。

#### 15.6 样式状态

Empty 支持不同交互状态，主要体现在按钮和可点击区域上。

状态包括：

- 正常。
- 悬停。
- 点击。

规则：

- 空状态本身一般不可交互。
- 若需要交互，应通过按钮承载。
- 按钮可根据场景选择主按钮或默认按钮。
- 文案不应伪装成按钮。
- 引导新增类空状态应优先使用主按钮。

#### 15.7 使用场景规则

##### 页面中使用

页面空状态使用默认尺寸空状态。

规则：

- 缺省图距离页面上下边距比例约为 3:7。
- 空状态整体应居中或处于视觉中心偏上位置。
- 页面没有数据时，应避免只显示空白页。
- 初始化流程可使用“引导新增”类型。

##### 表格中使用

表格空状态根据表格所在场景选择默认尺寸或小尺寸。

基础表格页：

- 使用默认尺寸空状态。
- 空状态根据页面高度适配。
- 缺省图距离表体上下边距比例约为 3:7。

页面内表格：

- 可使用小尺寸空状态。
- 缺省图整体垂直居中。
- 上下建议约 16px 边距。
- 可根据页面需要选择“图标 + 文本”或“仅文本”。

##### 抽屉中使用

抽屉空状态使用默认尺寸空状态。

规则：

- 缺省图距离表体上下边距比例约为 4:6。
- 空状态不应贴近抽屉顶部。
- 抽屉内容区较窄时应避免过长文案。

##### 弹窗中使用

弹窗空状态使用默认尺寸空状态。

规则：

- 缺省图距离内容区上下边距比例约为 3:7。
- 内容区较小时可调整为空状态小尺寸。
- 弹窗底部按钮区不应与空状态混淆。

##### 首页卡片中使用

首页卡片中使用小尺寸空状态。

规则：

- 缺省图整体垂直居中。
- 上间距约 16px。
- 下边距约 20px。
- 文案应尽量简短。

## 16. FilePreview 文件预览


### 16. FilePreview 文件预览

#### 16.1 何时使用

FilePreview 是系统内用于查看图片、Word、PDF 等文件的控件，主要用于表单图片查看、附件文件查看、表格图片查看等场景。

适合使用 FilePreview 的场景：

- 查看图片。
- 查看 Word 文件。
- 查看 PDF 文件。
- 查看表单附件。
- 查看表格图片。
- 查看单据附件。
- 查看合同、发票、凭证、资料等文件。
- 对文件进行下载、分享、删除、旋转、缩放等操作。

不适合使用 FilePreview 的场景：

- 文件不需要预览，只需要下载。
- 文件内容必须编辑而不是查看。
- 文件数量很多且需要批量管理，应使用文件列表或附件管理组件。
- 文件预览会暴露敏感内容且没有权限校验。
- 文件格式不支持在线预览时，应提供下载或错误提示。

#### 16.2 预览入口类型

FilePreview 支持两类典型入口：

##### 点击文件打开弹窗 / 抽屉遮罩

适合：

- 当前页面中临时查看文件。
- 不希望离开当前上下文。
- 表单、表格、详情页中的附件预览。
- 单文件或多文件快速查看。

规则：

- 弹窗或抽屉需要有标题区。
- 默认展示当前文件名称。
- 文件不是多文件时，不展示左右切换 icon。
- 文件是多文件时，可展示左右切换 icon。
- 底部操作区支持页码、下载、分享、删除、旋转、缩放等操作。

##### 点击文件打开新页签

适合：

- 文件较大。
- 用户需要较长时间查看。
- 希望保留独立预览页。
- 用户可能需要在多个文件之间切换浏览器页签。

规则：

- 每打开一个文件，生成一个新页签。
- 浏览器页签标题默认为“文件预览”。
- 内容页标题区展示当前文件名称。
- 若单文件预览，不展示左右切换。
- 支持下载、分享、删除、旋转、缩放等底部操作。
- 进入新页签后，只有关闭新页签才可以关闭文件内容。

#### 16.3 组件结构

FilePreview 通常包含：

1. 标题区：展示当前文件名称，弹窗模式中可包含关闭按钮。
2. 内容区：展示文件内容，可缩放查看。
3. 内容切换区：多文件场景下，显示左右切换按钮。
4. 底部操作区：展示当前文件数量、翻页、下载、分享、删除、旋转、缩放等操作。

#### 16.4 单文件预览规则

单文件预览适合仅查看一个文件。

规则：

- 标题展示当前文件名称。
- 文件数量显示为 1/1。
- 不展示左右切换 icon。
- 支持下载、分享、删除、旋转、缩小、放大等操作。
- 图片或文档内容应在预览区域居中展示。
- 预览背景可使用中性灰，突出文件内容。

#### 16.5 多文件预览规则

多文件预览适合一次查看多个附件或图片。

规则：

- 标题展示当前文件名称。
- 文件数量显示为 N/N。
- 支持左右切换。
- 第一个文件不支持左切。
- 最后一个文件不支持右切。
- 当前文件切换时，标题和页码应同步更新。
- 单文件时不展示左右切换。
- 多文件预览时，不要只展示当前文件而不提供切换入口。

#### 16.6 操作能力

FilePreview 支持以下操作：

- 左旋 90 度。
- 右旋 90 度。
- 缩小。
- 放大。
- 关闭预览。
- 下载。
- 分享。
- 删除。
- 左切。
- 右切。

操作规则：

- 缩小通常只有放大后才可继续缩小。
- 放大可支持连续放大，但不应无限制放大。
- 删除属于高风险操作，应谨慎处理。
- 关闭预览在弹窗模式中关闭弹窗，在新页签模式中需要关闭页签。
- 操作 icon hover 时应展示文字提示。
- 操作按钮应具备正常、悬停、禁用状态。

#### 16.7 弹窗 / 抽屉预览规则

弹窗或抽屉预览用于当前页面内查看文件。

规则：

- 标题区必须存在。
- 关闭按钮必须清晰。
- 内容区域应占据主要空间。
- 预览背景与页面背景应区分。
- 底部操作区固定在底部。
- 多文件切换按钮可放在内容区左右侧。
- 弹窗模式下关闭按钮关闭预览层。
- 不应让预览层遮挡后仍无法退出。

#### 16.8 新页签预览规则

新页签预览用于独立查看文件。

规则：

- 浏览器新页签标题默认为“文件预览”。
- 页面内标题区展示当前文件名称。
- 内容区域支持缩放。
- 单文件时不展示左右切换。
- 多文件时支持切换。
- 底部操作区支持下载、分享、删除、旋转、缩放。
- 关闭文件内容需要关闭新页签。

#### 16.9 使用场景

FilePreview 常用于：

- 表单中图片查看。
- 表格中图片查看。
- 附件文件查看。
- 合同文件预览。
- 发票文件预览。
- 报销凭证预览。
- 单据附件查看。
- Word 或 PDF 查看。
- 图片轮播式预览。

## 19. 补充设计校验规则


### 19. 补充设计校验规则

#### 19.1 Tooltip 校验

- 是否只是短文本提示？
- 是否通过 hover 触发？
- 是否不需要用户操作？
- 文案是否过长？
- 气泡方向是否会溢出页面？
- 是否需要改用气泡卡片或弹窗？
- 是否用于省略文本查看全文？

#### 19.2 Collapse 校验

- 内容是否复杂或非必要？
- 是否适合默认收起？
- 是否会隐藏关键流程信息？
- 标题是否清晰表达内容分组？
- 操作按钮是否与展开热区区分？
- 容器宽度是否决定使用大号或小号折叠面板？

#### 19.3 Carousel 校验

- 内容是否平级？
- 是否真的存在空间不足？
- 是否会隐藏重要内容？
- 是否需要指示器和左右切换？
- 轮播项数量是否过多？
- hover 时是否展示切换箭头？
- 当前项是否清晰可见？

#### 19.4 Empty 校验

- 当前是否真的无数据？
- 是否应展示加载而不是空状态？
- 空状态类型是否符合原因？
- 是否需要按钮引导新增、重试或刷新？
- 页面、表格、抽屉、弹窗是否使用了合适尺寸？
- 文案是否简短明确？
- 权限或错误状态是否表达清楚？

#### 19.5 FilePreview 校验

- 文件是否支持在线预览？
- 是单文件还是多文件？
- 是否需要弹窗、抽屉或新页签？
- 是否需要左右切换？
- 是否需要下载、分享、删除、旋转、缩放？
- 删除操作是否有风险控制？
- 文件名称、页码和当前内容是否同步？
- 单文件时是否隐藏了无意义的切换按钮？

## 21. Popover 气泡卡片


### 21. Popover 气泡卡片

#### 21.1 何时使用

Popover 用于在用户点击或鼠标移入元素时，弹出气泡式卡片浮层。它比 Tooltip 承载能力更强，适合展示较复杂的说明、详情、设置项或图文内容。

适合使用 Popover 的场景：

- 需要展示比 Tooltip 更复杂的说明内容。
- 需要在浮层中展示标题、正文、分割线、链接、图片或简单设置项。
- 需要解释某个字段、按钮、状态或业务规则。
- 需要展示简单详情，如标题 + 多行文本 + 链接。
- 需要展示复杂详情，如步骤说明、字段说明、操作说明。
- 需要展示少量设置项，如开关配置。
- 用户需要短暂停留查看信息，但不需要进入完整页面或弹窗。

不适合使用 Popover 的场景：

- 只需要一句短提示，应使用 Tooltip。
- 需要用户完成复杂表单操作，应使用弹窗、抽屉或页面。
- 内容非常多，需要长时间阅读。
- 需要承载复杂表格、大量图片或多步骤流程。
- 需要强制用户处理或确认，不应使用普通 Popover。

#### 21.2 组件结构

Popover 通常包含：

1. 标题：卡片可配置标题，可选添加 icon。
2. 分割线：有标题时可配置展示分割线，用于区分标题和内容。
3. 三角箭头：指向触发点，支持多个方向。
4. 内容区域：承载文本、富文本、图片、链接、设置项或说明内容。
5. 触发元素：可以是文字、按钮、icon、表头、标签或任意可交互对象。

#### 21.3 内容类型

Popover 可承载以下内容：

- 仅文案，用于补充说明。
- 简单详情，如标题 + 文本 + 链接。
- 富文本内容，如多段说明、重点信息、蓝色链接。
- 图片内容，如预览图、说明图。
- 设置项，如开关、选项配置。
- 步骤说明，如安装步骤、操作步骤、说明流程。

设计建议：

- 简单短文案优先使用 Tooltip。
- 中等复杂说明使用 Popover。
- 强流程、长内容或多表单操作使用弹窗或抽屉。
- 若 Popover 内含图片并且内容超过 3 行，建议考虑更宽的小号弹窗。
- 若内容高度超过 400px，应出现滚动条。

#### 21.4 尺寸布局规则

##### 基础尺寸

| 属性 | 规格 |
|------|------|
| 宽度 | 随内容自适应 |
| 最大宽度 | 424px（同 Web 端对话框组件宽度） |
| 字号 | 14px |
| 行高 | 160% |

##### 红线标识间距

| 属性 | 规格 |
|------|------|
| 卡片内部边距（上/左/右/下） | 20px |
| 按钮之间水平间距 | 8px |
| 多字段场景字段垂直间距 | 16px |

##### 特殊约束

若气泡卡片中容纳图片 + 超过 3 行文本时，建议替换使用 480px 宽度的小号弹窗。

#### 21.5 箭头方向规则

Popover 支持多个箭头方向，箭头方向按气泡相对触发点的位置命名。

常见方向包括：

- 下左、下中、下右。
- 上左、上中、上右。
- 右上、右中、右下。
- 左上、左中、左下。

规则：

- 箭头必须指向触发元素或触发区域。
- 默认优先在触发点上方或下方展示。
- 若当前位置会遮挡内容或超出页面，应切换到更合适方向。
- 页面边缘场景应优先选择不会溢出的方向。
- Popover 与触发元素应保持明确关联。

#### 21.6 交互规则

Popover 可由 hover 或点击触发。

规则：

- hover 触发：适合查看说明、简短设置、轻量详情。
- 点击触发：适合需要用户停留查看、复制、操作简单设置的内容。
- 鼠标移出后，hover 型 Popover 消失。
- 点击型 Popover 应支持点击外部关闭。
- Popover 内如有可交互内容，应避免鼠标移出立即关闭。
- Popover 不应替代强制确认弹窗。
- 若需要阻断用户流程，应使用 Modal 或 Tour 的模态引导。

#### 21.7 使用场景

Popover 常用于：

- 表格字段的复杂说明。
- 页面提示条中的补充说明。
- 发票、账单、金额等字段解释。
- 设置项开关说明。
- 操作入口说明。
- 富文本说明。
- 重要数据口径解释。
- 简单图片说明。

## 22. Image 图片


### 22. Image 图片

#### 22.1 何时使用

Image 用于展示可预览查看的图片。它可以作为缩略图展示，也可以点击查看大图，并支持多图预览、加载状态和加载失败状态。

适合使用 Image 的场景：

- 展示单张图片。
- 展示多张图片。
- 表单图片上传后的预览。
- 表格图片列预览。
- 附件图片查看。
- 用户需要点击缩略图查看大图。
- 图片加载中或加载失败时需要明确反馈。

不适合使用 Image 的场景：

- 图片只是装饰，不需要预览。
- 图片与其他文件类型混合预览，应使用 FilePreview。
- 需要查看 Word、PDF、Excel 等文件，应使用 FilePreview。
- 图片数量很多且需要管理、筛选、排序，应使用图片列表或附件管理。
- 图片内容敏感但没有权限控制。

#### 22.2 组件结构

Image 组件通常包含：

1. 缩略图片：点击后查看大图。
2. 大图预览：展示图片全屏或局部遮罩预览。
3. 遮罩层：图片预览放大层背景。
4. 左右切换 icon：多图预览时用于切换上一张、下一张。
5. 辅助 icon：支持左右旋转、放大、缩小等操作。
6. 关闭 icon：关闭预览大图。

#### 22.3 图片状态

Image 支持以下状态：

- 单图预览：展示单张缩略图。
- 预览 hover：鼠标悬停缩略图时展示预览提示或遮罩。
- 加载中：图片加载时可使用 placeholder 或渐进加载。
- 加载失败：展示图片占位图。
- 多图预览：多张图片缩略图并列展示，点击后支持左右切换。
- 多图放大预览：大图预览中展示左右切换 icon。

#### 22.4 预览规则

单图预览规则：

- 点击缩略图查看大图。
- 单张图片不需要展示左右切换 icon。
- 大图预览中可支持旋转、缩放、关闭。
- 图片加载失败时展示占位图。

多图预览规则：

- 多张图片并列展示缩略图。
- 点击任意图片进入大图预览。
- 大图预览中支持左右切换。
- 第一张图片不支持左切。
- 最后一张图片不支持右切。
- 切换时图片内容与当前索引应同步。
- 若图片加载失败，大图预览中展示占位图。

#### 22.5 尺寸布局规则

Image 的布局规则：

- 图片预览弹层中，图片应位于视觉中心。
- 顶部操作栏与图片之间保持安全距离。
- 图片左右两侧与切换按钮之间保持明确间距。
- 左右切换按钮应位于图片两侧，不能遮挡图片主体。
- 缩略图尺寸应统一。
- 多图缩略图之间间距应一致。
- 表格或表单中的缩略图应保持统一圆角。
- 加载失败占位图尺寸应与图片容器一致。

#### 22.6 操作规则

Image 大图预览支持：

- 左旋 90 度。
- 右旋 90 度。
- 缩小。
- 放大。
- 关闭预览。
- 左切。
- 右切。

规则：

- hover 操作 icon 时应显示文字提示。
- 放大可连续放大，但需要限制最大倍率。
- 缩小通常只有放大后才可继续缩小。
- 关闭预览必须明确可见。
- 多图预览时，第一个文件不支持左切，最后一个文件不支持右切。
- 操作 icon 应具有正常、悬停、禁用状态。

#### 22.7 Image 与 FilePreview 的区别

Image 只负责图片展示和图片预览。

FilePreview 负责更广义的文件预览，包括图片、Word、PDF 等文件，并支持文件标题、页码、下载、分享、删除等更完整的文件操作。

选择建议：

- 仅展示图片缩略图和大图预览 → 使用 Image。
- 需要预览 PDF、Word、附件文件 → 使用 FilePreview。
- 图片属于附件体系，并需要下载、分享、删除、页码等文件操作 → 使用 FilePreview。
- 表单上传图片后只查看图片 → 使用 Image。

## 23. Segmented 分段控制器


### 23. Segmented 分段控制器

#### 23.1 何时使用

Segmented 用于在同一页面或同一视图内快速切换一组平级、关联性强、数量较少的内容或功能。用户切换后仍停留在当前页面，不跳转到新页面；关联区域内容会随选中项变化。

适合使用 Segmented 的场景：

- 同一数据集的多维度展示。
- 同一页面内多个模块内容切换。
- 状态切换，如待办、已办。
- 分类筛选，如全部、已完成、未完成。
- 局部视图切换，如列表视图、卡片视图、图标视图。
- 切换内容较少、关联性强、层级平级。
- 需要比 Tab 更轻量的局部切换。

不适合使用 Segmented 的场景：

- 切换后需要进入新页面。
- 选项数量很多。
- 选项之间不是平级关系。
- 内容层级较复杂，应使用 Tabs 或导航。
- 选项需要多选。
- 分段控制器单独置于页面顶部，脱离标签页组件和内容区。

#### 23.2 组件结构

Segmented 通常包含：

1. 选项：支持文字、图标、文字 + 图标混合。
2. 背景色：通过颜色表达选中和未选中。
3. 选中态：当前选项高亮。
4. 未选中态：其他选项弱化。
5. 禁用态：不可点击的选项。
6. 内容区域：随选中项变化的关联内容区。

#### 23.3 类型

##### 文字型

以文字标签作为选项。

适合：

- 状态切换。
- 分类筛选。
- 简单视图切换。
- 选项含义明确且可用文字表达。

##### 图标型

以图标作为选项。

适合：

- 布局切换。
- 展示模式切换。
- 列表、网格、卡片等视图切换。

##### 组合型

以图标和文字结合为选项。

适合：

- 功能较复杂。
- 需要提升识别效率。
- 单纯图标不足以表达含义的场景。

#### 23.4 状态

Segmented 支持以下状态：

- 选中：当前项被选中。
- 未选中：当前项未被选中。
- 悬停：鼠标移入选项。
- 点击：鼠标按下或点击态。
- 禁用：选项不可点击。

规则：

- 选中项必须清晰高亮。
- 未选中项应保持可识别但弱化。
- 禁用项应明显不可点击。
- hover 和点击态应有反馈。
- 切换后关联内容区应立即更新。

#### 23.5 尺寸布局规则

Segmented 必须水平排列，不支持垂直布局。三种尺寸规格如下：

##### 尺寸规格

| 属性 | 大尺寸（大型导航） | 中尺寸（默认常规） | 小尺寸（紧凑布局） |
|------|------------------|------------------|------------------|
| 高度 | 40px | 32px | 24px |
| 左右内边距 | 16px | 16px | 16px |
| 右侧底边距 | 4px | - | 4px |

- 大尺寸：用于大型导航场景。
- 中尺寸：默认常规场景，大多数页面内容切换。
- 小尺寸：紧凑布局场景。

##### 通用规则

- 选项宽度默认随内容自适应。
- 选项之间应均匀排列。
- 图标与文字之间保持清晰间距。
- 选项数量建议不超过 5 个。
- 若容器较窄且选项不超过 3 个，可使用通栏展示方式。

#### 23.6 场景规则

页面内容切换：

- Segmented 可用于页面内容切换。
- 选项宽度默认根据内容自适应。
- 禁止单独置于页面顶部。
- 必须嵌套在标签页组件内，位于标签页内容区域，即标签页层级的下方。
- 适合在某个页面或模块内切换局部内容。

通栏展示场景：

- 推荐用于紧凑区域。
- 适合局部顶部或区域视图切换。
- 当容器小于等于 400px 且选项不超过 3 个时，可考虑通栏展示。
- 当分段控制器自适应宽度超过容器宽度 75% 时，建议通栏展示。
- 通栏可以避免容器内部留白，提高视觉一致性。

## 24. Tag 标签


### 24. Tag 标签

#### 24.1 何时使用

Tag 用于标记事物的属性、状态、维度或分类。它可以用于详情、表格、筛选、分类、审批状态、业务属性等场景。

适合使用 Tag 的场景：

- 标记业务状态。
- 标记对象属性。
- 标记分类维度。
- 展示可删除筛选条件。
- 展示可点击标签并打开详情。
- 在表格中展示状态、分类或属性。
- 用颜色区分不同状态语义。
- 用圆点、旗帜、邮戳等特殊标签表达特定业务含义。

不适合使用 Tag 的场景：

- 需要提示未读数量，应使用 Badge。
- 需要承载大段说明文本，应使用 Popover 或 Descriptions。
- 需要表达复杂流程状态，应使用步骤条或状态组件。
- 页面上需要强提醒，不应只依赖轻量标签。
- 标签过多导致信息噪音，应折叠或收纳。

#### 24.2 标签类型

##### 基础标签

基础标签用于常规属性、状态或分类展示。

包括：

- 浅底标签：默认标签，彩色文字 + 浅底容器，适合详情、表格等多种场景。
- 深底标签：反白文字 + 深色容器，强调信息或突出展示。
- 带 icon 标签：在文字前增加状态 icon，如信息、成功、警示、错误等。

##### 特殊标签

特殊标签用于更明确的业务场景。

包括：

- 可删除标签：支持删除，常用于筛选、选择、分类等场景。
- 圆点标签：彩色圆点 + 中性文字，常用于表格默认表示状态。
- 旗帜标签：用于与页面中已有默认标签区分，标签需贴附容器右边缘。
- 可点击标签：文字后带图标，标签整体可点击。
- 邮戳标签：彩色邮戳，仅用于需要映射真实场景的情况，如发票场景。
- 运营标签：胶囊渐变标签，由图标 + 文本组成，如推荐、AI、NEW 上新等。

#### 24.3 标签语义颜色

Tag 的颜色应具有明确语义。

常见语义：

- 蓝色：等待状态、进行中、品牌属性、可见范围。
- 绿色：通过、成功、已完成、已认证、已授权。
- 橙色：风险、警示、待办、迟到、早退。
- 红色：失败、高度警示、异常、授权失败、核验失败。
- 灰色：取消、暂停、未启用、未授权、无权限、退票。
- 紫色 / 青色 / 黄色：无功能语义，仅在特定场景使用，如加班、商务卡、外出、出差、预收款、分摊、改签等。

设计要求：

- 页面中无需表任务状态时，标签仅用于多标签分类区分。
- 不要滥用颜色表达过多复杂含义。
- 同一业务状态在不同页面中应保持颜色一致。
- 标签颜色不能只依赖视觉，应有清晰文案。

#### 24.4 尺寸布局规则

##### 基础规格

| 属性 | 规格 |
|------|------|
| 高度 | 约 20px |
| 宽度 | 随文字自适应 |
| 圆角 | 约 4px |
| 文案字号 | 约 12px |
| 图标 | 默认 14px / 状态图标 12px |
| 关闭 icon | 约 8px |
| 标签文字与关闭 icon 间距 | 约 4px |

##### 状态语义

| 颜色 | 语义 | 示例 |
|------|------|------|
| 蓝色 | 等待/进行中/品牌属性 | 审核中、授权中、请假、电子发票 |
| 绿色 | 成功状态 | 已完成、已通过、已启用 |
| 橙色 | 有风险需警示 | 未通过、涉敏、迟到 |
| 红色 | 失败/高危提示 | 冻结、试用结束、旷工、欠薪 |
| 灰色 | 取消/暂停 | 未认证、未启用、无权限 |
| 其他 | 无功能语义，仅场景区分 | 加班、商务卡、分摊 |

##### 组合使用规则

- 标签与文字间距约 8px，标签之间间距约 8px。
- 标签过多时应折叠。
- 表格内标签应避免撑高行高。

#### 24.5 状态规则

可删除标签支持：

- 默认。
- 悬停。
- 点击。

可点击标签支持：

- 默认。
- 悬停。
- 点击。

规则：

- 可点击标签必须有明确 hover 反馈。
- 可删除标签的关闭 icon 必须可识别。
- 点击标签后可打开详情弹窗。
- 标签交互区域应足够清晰，避免误触。
- 不可点击标签不应表现出可点击样式。

#### 24.6 使用场景规则

基础标签：

- 可用于详情页、表格、字段状态、分类展示。
- 适合展示状态、属性和维度。

圆点标签：

- 适合表格中默认状态展示。
- 适合状态信息较轻、无需强视觉容器的场景。

旗帜标签：

- 适合需要与页面默认标签区分的标签。
- 使用时标签需要贴附容器右边缘。

可点击标签：

- 适合点击后查看详情弹窗。
- 标签整体可点击。
- 点击后可展示弹窗详情。

邮戳标签：

- 适合发票、票据等需要映射真实印章或状态标记的场景。
- 不建议在普通业务标签中滥用。

运营标签：

- 适合左侧菜单或运营推荐场景。

## 25. Tour 漫游式引导


### 25. Tour 漫游式引导

#### 25.1 何时使用

Tour 用于分步引导用户了解产品功能。它通过高亮目标元素、展示分层提示信息，降低 B 端用户学习成本，提升功能使用率与操作准确性。

适合使用 Tour 的场景：

- 新用户首次使用功能。
- 核心功能有重大更新。
- 高危操作前需要引导。
- 次要功能入口需要轻量说明。
- 老用户功能更新提示。
- 功能位置发生变化，需要引导用户找到入口。
- 多步骤流程需要逐步说明。

不适合使用 Tour 的场景：

- 普通短说明，应使用 Tooltip。
- 简单字段解释，应使用 Popover。
- 用户已经在高频流程中，不应反复打断。
- 非必要流程使用强制模态引导。
- 一次性展示过多步骤。
- 没有明确目标元素的泛泛说明。

#### 25.2 组件结构

Tour 通常包含：

1. 标题描述：总结描述，常驻显示，可换行，但应简洁。
2. 关闭按钮：非强制引导中展示，点击后结束引导流程。
3. 正文描述：引导文本，可换行。
4. 图片展示：可选，根据说明内容横向撑满，纵向根据场景确定。
5. 行动按钮：点击后完成对应动作，如上一步、下一步、知道了。
6. 分页显示：展示当前气泡卡片在流程中的位置，如 2/3。
7. 指引角：指向触发点或目标区域。

#### 25.3 引导类型

##### 非模态引导

非模态引导弱于强制引导，无遮罩层，不影响核心操作。用户可以自主选择是否了解。

适合：

- 次要功能入口。
- 老用户轻量功能更新。
- 功能位置指引。
- 不影响主流程的说明。

规则：

- 可常规显示。
- 可自动消失，或根据条件判断消失。
- 步骤关联引导通常需要点击关闭。
- 不应阻断核心任务。

##### 模态引导

模态引导强于非模态引导，会用遮罩层隔离非目标区域，强制用户聚焦引导内容。用户必须主动操作才能继续。

适合：

- 新用户首次启动强引导。
- 核心功能重大更新。
- 高危操作前置引导。
- 用户必须操作否则无法使用产品的功能。

规则：

- 必须有明确下一步或关闭操作。
- 不应滥用。
- 应避免在低价值功能上使用。
- 引导步骤不宜过多。
- 被高亮目标必须清晰。

#### 25.4 气泡样式

Tour 气泡支持多种内容样式：

- 常规：标题 + 正文 + 分页 + 上一步 / 下一步。
- 仅一段文案：无需分段显示事项。
- 单一提示：无需多个行动按钮时，可只展示“知道了”。
- 有图片：正文下方包含图片展示。
- 仅描述：无标题和行动按钮，可常驻、自动消失或按条件消失。
- 仅标题：适合非常轻量的说明。

设计建议：

- 常规尺寸建议宽度 288px。
- 中等尺寸可使用 424px。
- 大尺寸可使用 480px。
- 同一组引导中尺寸建议保持一致。
- 常规尺寸文案建议不超过 3 行。
- 若内容较多，使用大尺寸。
- 若信息量非常大，应插入大图或拆分步骤。

#### 25.5 布局尺寸规则

Tour 气泡尺寸：

- 开发不强制设宽，设计师遵循 288、424、480 三个尺寸。
- 常规尺寸：288px。
- 中等尺寸：424px。
- 最大尺寸：480px。
- 同一组引导尺寸建议保持一致。
- 内容较多时优先使用大尺寸，而不是堆叠过长文本。

布局规则：

- 标题与正文应有清晰层级。
- 关闭按钮位于右上角。
- 分页通常在左下角。
- 行动按钮在右下角。
- 图片区域可根据内容横向撑满。
- 按钮最多展示两个，可只展示一个，也可不展示。
- 单卡片引导时可不展示分页。

#### 25.6 触发角与位置规则

Tour 的触发位置可根据实际目标位置选择。

规则：

- 指引角必须指向触发点或目标区域。
- 默认在触发点上方居中。
- 若气泡确认框在当前位置会遮挡内容，可选择其他位置。
- 支持上、下、左、右及组合方向。
- 当目标靠近页面边缘时，应自动选择不会溢出的方向。
- 模态引导中，高亮目标应与气泡位置对应清晰。

#### 25.7 场景规则

新手引导场景：

- 用于用户第一次进入功能时。
- 可高亮关键目标。
- 应控制步骤数，避免过长。
- 每一步应解释一个明确功能点。

功能更新引导：

- 适合老用户。
- 使用非模态引导更合适。
- 文案应说明更新价值，而不是只说位置变化。

高危操作前置引导：

- 可使用模态引导。
- 用户必须主动确认才能继续。
- 仅用于高风险或必须理解的操作。

轻量功能入口说明：

- 使用非模态引导。
- 可常驻、自动消失或根据条件消失。
- 不应干扰主流程。

#### 25.8 AI 检索关键词

Tour、漫游式引导、新手引导、功能引导、分步引导、产品引导、气泡引导、模态引导、非模态引导、高亮目标、下一步、上一步、知道了、引导气泡、功能更新提示、强制引导、操作前置引导。

## 26. 第三组补充组件选择决策规则


### 26. 第三组补充组件选择决策规则

#### 26.1 根据展示目的选择

#### 26.2 与已有组件的边界

- “新手引导”“分步引导”“功能引导”“下一步”“高亮目标” → 推荐 Tour。

## 27. 第三组补充设计校验规则


### 27. 第三组补充设计校验规则

#### 27.1 Popover 校验

- 是否比 Tooltip 承载内容更复杂？
- 是否需要标题、分割线、链接、图片或设置项？
- 内容是否过长，是否应改用弹窗或抽屉？
- 箭头是否准确指向触发点？
- 浮层是否会超出页面边界？
- hover 或点击触发方式是否符合用户任务？
- 是否包含复杂表单，若是应避免使用 Popover？

#### 27.2 Image 校验

- 是否只是图片展示和图片预览？
- 是否需要支持多图切换？
- 单图时是否隐藏左右切换？
- 加载失败是否有占位图？
- 缩略图尺寸是否统一？
- 预览操作是否包含旋转、缩放、关闭？
- 如果需要预览 PDF / Word / 附件，是否应改用 FilePreview？

#### 27.3 Segmented 校验

- 选项是否平级且关联性强？
- 选项数量是否较少，建议不超过 5 个？
- 切换后是否仍停留在当前页面？
- 是否只是局部内容切换，而非页面级导航？
- 选中态是否足够明显？
- 是否错误地单独放在页面顶部？
- 容器较窄时是否考虑通栏展示？

#### 27.4 Tag 校验

- 标签是否用于表达状态、属性、分类或维度？
- 标签颜色是否有明确业务语义？
- 是否误用 Tag 表达未读数量，应改用 Badge？
- 多个标签之间间距是否合理？
- 标签是否过多，是否需要折叠？
- 可点击标签是否有 hover 和点击反馈？
- 可删除标签的关闭 icon 是否清晰？

#### 27.5 Tour 校验

- 是否真的需要分步引导？
- 是否有明确目标元素？
- 是否需要模态引导，还是非模态引导即可？
- 步骤是否过多？
- 每一步是否只讲一个重点？
- 引导气泡是否遮挡关键内容？
- 是否滥用强制引导？
- 上一步、下一步、关闭、分页是否清晰？
