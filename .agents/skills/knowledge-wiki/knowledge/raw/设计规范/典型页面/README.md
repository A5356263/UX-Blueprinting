# 典型页面

## 这是什么

这是典型页面设计规范的二级路由入口，用来解释稳定页面类型的目标、整体结构、核心模块和页面级决策规则。

本 README 承载页面分类契约与任务路由；具体页面事实保留在对应主题文件中。

## 分类契约

### 分类定义

典型页面回答的是：一类稳定页面为完成什么目标，应如何组织整体信息、区域、模块和主要操作。

### 解决的问题

- 当前需求属于哪种页面类型
- 页面整体应采用什么结构和布局
- 页面需要包含哪些核心区域和模块
- 页面级操作、信息密度和内容顺序如何组织
- 页面如何引用组件和场景规则而不复制正文

### 为什么独立成类

- 页面具有高于单个组件的整体目标和信息结构
- 同一页面类型可跨业务领域复用
- 页面结构不应混入组件细节或任务流程文件

### 与相邻分类的关系

- 组件提供页面中的按钮、表格、表单、反馈和头部等局部单元
- 场景模式提供搜索、导入、异步和审批等任务路径
- 补读组件或场景后，页面整体结构和模块关系必须回到本分类确认

### 稳定结论

- 表单页、详情页、表格页和报表页具有不同目标与结构，必须分别成文
- 页面文件只记录页面级事实，不重复维护组件正文
- 页面内部出现任务流程时，通过场景模式补充，不把场景规则复制进页面 README

### 显式缺口

- [GAP] 部分页面资产缺少统一的终端、版本和业务适用范围
- [QUESTION] 表格页与可编辑表格组件的边界仍需结合后续材料持续校验

## 任务触发索引

- 分步表单、上下布局表单或左右布局表单：读 `表单页.md`
- 详情布局、信息分组、锚点、操作记录或底部操作：读 `详情页.md`
- 标准表格页、多栏表格布局或表格状态页面：读 `表格页.md`
- 数据报表、统计指标、图表或钻取分析页面：读 `报表页.md`

## 条件依赖与回主类

- 命中具体控件结构、状态或尺寸时补读组件；命中搜索、导入、异步或审批任务时补读场景模式
- 相邻分类只补充页面实现所需事实；最终页面目标、结构和模块关系必须回到本分类确认

## 维护原则

- README 只承载分类契约和路由，不展开页面正文
- 一个页面文件只承担一个稳定页面类型
- 跨页面复用区域应进入组件，跨页面任务路径应进入场景模式
- 不以“页面模式汇总”重新合并不同页面类型

- 补读组件或场景后必须回到本分类确认页面整体结构与已知缺口
