# 审批管理

## 这是什么

这是审批管理领域的固定文件级路由入口，用来说明本领域承载什么知识、遇到什么问题该优先看哪些语义文件。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应语义文件中。

## 领域契约

### 领域定义

审批管理领域回答的是：平台如何提供通用审批能力，使企业能够配置表单、流程、审批角色和数据联动，并承接各业务域的审批任务。

它覆盖：

- 表单与字段配置。
- 流程节点、分支、动态流程、自动化和子流程。
- 审批角色、管理员权限、数据管理和异常处理。
- 审批任务的发起、处理、转派、交接和查询辅助能力。

### 领域边界

- 审批管理提供通用审批机制，不决定费用、权限、人事或支付业务为何触发审批。
- 下游业务域拥有自己的业务对象、触发条件、审批前后状态和最终业务结果解释权。
- 审批管理只记录通用审批配置、审批任务处理和已证实的跨模块联动能力。

### 跨域依赖

- 系统业务审批可与假勤统计、员工花名册联动。
- 自动化任务可更新花名册、假勤外出记录、低代码平台连接器，或通过 HTTP 请求同步外部系统。
- 权限、人事、费用和企业支付等领域需要审批机制时，先在本域读取命中的通用机制，再回到原业务域确认业务结果。
- 人事服务可消费本域的入职、调动和离职审批机制；费用管理可消费报销单、账单和垫款审批机制；权限管理可消费权限变更审批机制；企业支付可消费供应商准入和付款审批机制。

### 显式缺口

- [GAP] 各业务域接入审批能力的具体对接规范和边界条件未完整采集。
- [QUESTION] 审批管理与 OA 审批的关系和边界是否已完全清晰，仍需持续校验。

## 条件依赖与回主域

- 某项业务为何触发审批、审批前后业务状态如何变化，由对应业务域回答。
- 从权限、人事、费用或企业支付进入本域时，只读取命中的通用机制文件；读完必须回到原业务域确认对象、规则、状态和结果。
- 审批人离职涉及成员生命周期时补读成员管理；本域只承接审批任务转派与流程交接。
