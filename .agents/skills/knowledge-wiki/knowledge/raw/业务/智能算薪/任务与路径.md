| 事务 | 角色 | 目标 |

| 多所得类型与多薪资组算薪 | 薪资专员 | 处理多所得类型、部门调动、兼任、一人多税局等算薪场景 |
| 算薪联动电子工资单与代发 | 薪资专员 | 算薪完成后推送工资单、提交代发或导出网银代发数据 |
| 薪资计算发起审批 | 薪资专员 | 算薪结果提交审批流程 |
| 假期余额结薪 | 薪资管理员 / 考勤管理员 | 将带薪假余额结算为工资 |

## 智能算薪初始化配置

新企业配置使用智能算薪的关键配置步骤，角色为薪资管理员/企业管理员。

```text
维护组织架构与员工花名册
→ 维护员工个税信息
→ 完成人员税局报送
→ 完成权限设置和薪酬设置
→ 配置薪资档案
→ 配置薪资规则（创建薪资组）
→ 进行当月薪资计算
```

- 算薪前六项准备：
  1. 在"员工管理"导入员工花名册，需填写个税字段。
  2. （可选）在"个税服务"完成"扣缴义务人管理"配置及员工报送。
  3. （可选）创建"参保方案"，生成"月结账单"。
  4. 完成"薪酬设置"，配置财务人员数据权限。
  5. 完成"薪资档案"设置，确定薪资构成，并为员工定薪。
  6. 创建"薪资组"，配置薪资规则。
- 组织架构：可单笔新增，也可通过"导入/导出/修改组织"批量维护。
- 员工花名册：算税的前提是花名册信息中已填写个税申报信息并对人员进行了报送；导入花名册前需先在个税服务完成扣缴义务人管理配置（设置税局相关信息），并开启花名册"个税基础信息"字段分组及对应功能权限。
- 人员报送：人员报税状态需为"可报税"。
- 使用智能算薪前必须完善花名册；智能算薪人员基于花名册员工，需在花名册维护员工信息后才能在薪资档案和薪资计算中管理员工薪资信息。
- 操作步骤与详细指引见 `问答与差异.md` 的「智能算薪操作指引」。

## 创建薪资组与配置薪资规则

薪资专员创建薪资组并按步骤配置薪资规则。

```text
基础设置（薪资组名称、税款所属月、社保所属月、考勤所属月、算薪公司、算薪人员、排除算薪人员、计薪周期、计薪月份、发薪日、标准计薪时长）
→ 选择配薪方式（使用模板 / 使用Excel工资表 / 复制已有薪资组规则 / 导入薪资规则）
→ 配置薪资规则（编辑分组、添加工资项、设置个税所得项目、设置各工资项取值规则）
→ 暂存或完成
→ 返回薪资计算页面
```

- 配薪方式说明：
  - 使用模板：可自行设置工资项及配置算薪规则；系统提供基础模板、完整模板、离职补偿金薪资组、年终奖薪资组、一次性伤残补助金薪资组、正算薪资组、反算薪资组。
  - 使用 Excel 工资表：智能识别工资表内容，自动生成简单的薪资规则。
  - 复制已有薪资组规则：使用已有薪资组规则或在其规则上调整。
  - 导入薪资规则：将已导出的薪资组规则文件导入生成薪资组。
- 税款所属期：税款应计算与缴纳的期间设置与薪资所属月一致或比薪资所属月晚一个月。
- 若需从薪酬档案获取数据，需确保在薪酬档案中已添加此字段；若选择手工导入，在薪资计算时需使用 Excel 导入对应数据。
- 后续重新维护工资项或计算规则时通过编辑薪资组进入；公式未完成可暂存，暂存后在待完善中重新进行规则配置。
- 若不同部门或子公司存在不同薪资规则，可创建多个薪资组。
- 操作步骤与详细指引见 `问答与差异.md` 的「智能算薪操作指引 → 7. 薪资组管理」与「1.16 如何设置薪资组」。

## 当期薪资计算

薪资专员核算企业薪资组员工月度工资，在完成员工花名册信息维护和薪资组配置后进行。

```text
点击当期工资（确认计薪月和计薪周期）
→ 核对计薪人员（确认本期需计薪人员）
→ 计算税前薪资（导入浮动数据、同步考勤数据、同步社保数据）
→ 计算税后薪资（同步个税、计算个税、计算实发项）
→ 算薪完成（锁定结果、联动代发、联动电子工资单）
```

- 计薪月份与薪资所属月不符时：计薪月份小于薪资所属月，需创建下月工资表以进入对应月份；计薪月份大于薪资所属月，需删除工资表返回上期工资表。删除工资表将删除当期工资数据，需谨慎操作。
- 核对计薪人员：计薪人员根据薪资组设置算薪人员范围和员工入离职日期自动判断；如需修改可手动添加或删除算薪人员。
- 同步个税前应确保个税服务中人员报送列表的员工信息已经报送成功，报送成功方可算税。
- 算薪结果按钮可锁定或解锁工资表；锁定后可对工资单进行更多操作（发送电子工资单或发送到薪资代发）。
- 已完成算薪的薪资组可在"当期工资"中的"计算税前薪资"页面选择"在线编辑"或"导入修改"完成手动修改算薪结果。
- 当期工资计算结果显示在当期工资中；如需显示在历史工资中，需创建下月工资表，当期工资数据会显示到历史工资中。
- 计薪人员核对与数据有误的异常处理见 `状态与异常.md#异常与排查`。
- 操作步骤与详细指引见 `问答与差异.md` 的「员工当期工资计算指引」。

## 批量算薪

薪资专员对门店或部门对应多个薪资组、薪资规则相似的企业进行多薪资组批量计算（多适用于连锁餐饮、门店类企业）。

```text
进入批量算薪 → 选择计薪月份查询 → 勾选需要批量计算的薪资组
→ 系统自动带出所选薪资组的所有算薪人员
→ 导入浮动数据、同步社保
→ 计算税前工资、个税和税后工资
→ 批量算薪完成 → 一键锁定所有工资表、批量提交审批/代发/电子工资单
```

- 系统会根据对应薪资组的算薪人员范围自动带出所有算薪人员；若中途在花名册中新增或修改人员信息，可通过重新同步人员同步信息；该功能暂不支持手工添加人员。
- 计算过程中若不小心退出计算页面，仍可重新进入批量算薪回到批量计算页面。
- 批量计算进行中无法单独操作单个薪资组的工资计算，建议在任务完成后或终止任务后再进行相关操作；终止任务后，已导入和同步的数据会保留在各自的薪资组中。
- 导入浮动数据模板会包含所选薪资组的所有手工导入项目；若某个工资项只存在于某薪资组规则中，但在模板中给其他薪资组的员工也录入了数据，导入后数据依旧只会对该薪资组员工体现。
- 操作步骤与详细指引见 `问答与差异.md` 的「批量算薪操作指引」。

## 税前工资算税

适用于企业不需要通过薪福通计算应发工资，已经有现成的应发工资，需根据应发工资计算个税以及得出税后实发的场景。计算完成后可通过个税服务板块对个税进行申报缴费，也可同步代发和电子工资单。

```text
维护组织架构 → 维护员工花名册（含个税申报信息） → 完成人员报送
→ 参数设置（权限、审批、算税与社保）
→ 导入工资表（配置算税方式、导入匹配方式、员工校验规则）
→ 配置数据范围（选择sheet页、表头起始行、数据起始行、数据终止行）
→ 同步社保（匹配社保表头 或 从月结账单自动导入）
→ 设置上传信息（薪资所属月、标题、税款所属月、所得项目、税前税后款项）
→ 计算个税 → 查看算税结果
→ 联动审批 / 同步代发 / 提交电子工资单
```

- 算税方式：正算（导入本期收入计算个税得出实发工资）、反算（导入实发工资计算个税得出本期收入）。
- 导入模式：仅算税、增员+算税、增员+更新+算税。
- 员工校验规则：按姓名+证件号校验、按证件号校验；校验规则的选择决定重名与不匹配时的处理方式（详见 `规则与权限.md#导入匹配与校验`）。
- 社保数据来源两种：来源于社保公积金月结账单（需提前生成月结账单，在参数设置开启"社保自动导入"）；来源于工资表导入数据（关闭"社保自动导入"，上传工资表后将系统字段表头和导入的工资表表头匹配）。
- 税前税后款项设置：若应发工资已合计出，可直接将应发工资设置为税前应发项，其他税前工资项默认设置为其他项；若需系统计算，则把加项设置为税前应发项、减项设置为税前应扣项、税后补发给员工的匹配到税后补发项、税后扣除员工实发工资的匹配到税后补扣项、不参与计算的匹配成其他。保存后系统会记住该设置，上传相同模板时默认为此设置。
- 计算个税：由系统自动计算个税和实发工资，结果可在税前工资算税中查看详情。
- 专项附加扣除、个人养老金扣除的数据来源见 `规则与权限.md#个税数据来源`。
- 操作步骤与详细指引见 `问答与差异.md` 的「税前工资算税操作指引」与「通过税前工资算税计算实发工资设置指引」。

### 税前工资算税反向生成花名册

在当前人力行业处理甲方工资表的税前工资算税场景中，传统新增员工流程繁琐，需分别在花名册、个税档案、税局报送等多个页面顺序操作。本功能在创建工资单时自动同步完成员工新增、个税信息登记及税局报送，大幅简化操作。

```text
打开参数开关（"同步处理人员信息及个税报送"）
→ 表头匹配（系统预设字段，匹配规则：只要工资表包含证件号码和姓名即可进入下一步）
→ 业务校验（按证件号码识别新增/更新，新增必须有姓名、证件类型、证件号码和部门）
→ 导入结果（继续导入 / 下载变更信息）
→ 个税信息校验（指定税局或在线编辑，校验税局信息是否完整）
→ 个税信息导入结果（去人员报送 / 下载变更信息）
→ 个税人员报送（数据校验、数据权限校验、异步处理）
→ 回到创建税前工资算税批次的主流程
```

- 功能使用时需升级到新版本花名册；参数未打开时和原有功能无差别。
- 系统预设字段：姓名、员工号、证件类型、证件号码、入职日期、部门、员工类型、岗位、工资卡号、手机号。
- 人员识别：员工证件号码在花名册不存在时识别为"新增"，否则识别为"更新"。
- 人员报送为异步处理；报送时会校验当前操作人在人员报送菜单的数据权限。
- 操作步骤与详细指引见 `问答与差异.md` 的「税前工资算税反向生成花名册」。

### 通过数据采集进行日工资计算

人力资源行业存在较多日结工资的情况（如劳务派遣），日薪工资计算比较简单，可通过数据采集直接计算出薪资结果，算税后发薪。

```text
创建采集表（可引用算薪方式选择"税前工资算税"，采集类型按需选择"不变动""按日变动"或"按月变动"）
→ 配置薪资相关字段
→ 在采集表中维护数据
→ 在税前工资算税同步采集数据
→ 选择数据采集表和日期 → 预览数据 → 确认同步
→ 计算个税
```

- 如开启了审批，需先对采集的数据发起审批，审批通过后才可用于算薪。
- 操作步骤与详细指引见 `问答与差异.md` 的「税前工资算税常见问题与补充操作 → 怎么使用税前工资算税进行日工资计算」。

## 定薪、调薪与定岗定薪

### 定薪与调薪

薪资专员为员工确定或调整固定薪资项（基本工资、岗位工资、固定补贴项等）。

```text
单笔定薪：薪资档案 → 员工操作列"定薪" → 录入基本薪资信息 → 保存生效
批量定薪：薪资档案 → "批量定薪" → 手动导入 → 下载模板 → 填写上传 → 导入
单笔调薪：薪资档案 → 选择员工"调薪" → 录入调整后薪资 → 系统计算调整比例 → 保存提交
批量调薪：薪资档案 → "批量调薪" → 下载模板 → 填写上传 → 导入
```

- 定薪：员工入职后确定薪资；调薪前可多次定薪、允许修改；调薪后不可定薪。
- 调薪：员工涉及转正、晋升时调整薪资；员工要先完成定薪操作后才能进行调薪操作。
- 批量定薪/调薪支持手工导入和按定岗定薪规则生成两种方式。
- 模板类型：仅未定薪人员模板（含所有薪酬档案中还没定薪的人员）；未定薪、已定薪未调薪人员模板（含还没定薪的人员以及已定过薪、还没调薪的人员）。两个模板除自带人员信息外其余内容一致，也可删除自带人员自己录入需要定薪的人员。
- 调薪生效日期必填；如果调薪生效日期设置大于当前日期，则需等到生效日时薪资档案列表页才显示调整后的最新薪资信息。
- 调薪补发：可补发调薪生效日到调薪完成日中间的差额工资，需点击按钮开启，并开通"特殊薪资发放计划"白名单功能。详见调薪补发。
- 导入时若数据填写有误，系统会提示错误，用户可导出错误文件修改后重新上传。
- 操作步骤与详细指引见 `问答与差异.md` 的「定薪、调薪操作指引」。

### 调薪补发

调薪审批流程较长，导致调薪完成日跟实际生效日间隔时间很长，会在调薪完成日所属的计薪月份补发差额工资。例如企业在 7 月才完成员工调薪流程，但实际调薪生效日为 3 月，因此在 7 月发薪时需要计算之前几个月的薪资差额并进行补发。

```text
确认企业已开启"特殊薪资发放计划"
→ 单人调薪补发：调薪时勾选"补发调薪工资"、填写"补发截止日期"
→ 或批量调薪补发：弹窗开启"调薪补发按钮" → 下载模板 → 填写"调薪完成日期" → 上传导入
→ 调薪补发计划查询：通过特殊薪资发放计划选择核算薪资组，查看发放金额和归属计薪月份
→ 薪资组工资项设置：编辑薪资组配置薪资规则，创建薪资项，通过自定义公式获取补发金额
```

- 只有当"调薪生效日期"早于当前日期，才会显示"补发调薪工资"选项。
- 例如企业 3 月 1 日调薪，7 月份发 6 月薪资时需要补 3、4、5、6 月的差额，则"调薪完成日期"需选择 7 月。
- 补发仅支持全额补发，不支持按照明细补发。
- 操作步骤与详细指引见 `问答与差异.md` 的「调薪补发场景指引」。

### 定岗定薪

企业根据员工的岗位等信息自动匹配对应的岗位工资，算薪时直接调用薪资数据进行计算。

```text
创建关联表（输入关联表名称）
→ 创建添加定岗字段（如岗位、职级）作为定岗依据，添加对应薪酬字段（如岗位工资、职级工资、基本工资）作为定薪依据
→ 数据维护（批量导入 或 单笔新增）：给对应的定岗字段维护对应的薪资标准
→ 定岗定薪操作：批量定岗定薪，生成按部门定薪的数据
```

- 定岗定薪可满足的场景包括：通过职级、职称、岗位给员工核定工资标准；按部门统一给花名册员工定薪后逐个微调；按工种定薪；通过级别定好员工的基本工资和岗位工资；入职定岗定薪；薪资档案按岗位定薪调薪；薪酬档案项支持公式计算。
- 操作步骤与详细指引见 `问答与差异.md` 的「员工定岗定薪场景操作指引」。

### 定调薪折算

企业固定的薪资项需要根据转正日期和调薪生效日进行折算，目前系统支持在薪酬档案和薪资组中折算。

- 薪酬档案折算方式包含 4 种：不折算、根据工作日折算、根据工作日含节假日折算、按自然日折算。
- 在薪酬档案定调薪折算：在薪资档案的档案项设置中选择折算方式并保存。
- 在薪资规则设置折算：在配置薪资规则中设置折算规则，规则设置需要使用公式。
- 转正/调薪折算：选择折算表明该工资项对在算薪周期中间转正、调薪的人员需要分段折算薪资；不勾选表明对在算薪周期中间转正、调薪的人员都按调整后的金额计算薪资。
- 操作步骤与详细指引见 `问答与差异.md` 的「定调薪折算场景指引」。

## 数据采集

数据采集用于将算薪需要收集的产量、销售额、绩效、奖金、津贴补助等浮动数据项设计为采集表模板，通过 API 对接、员工移动端提报、部门负责人录入等方式获取数据，自动生成以员工为维度的合计项直接用于薪资计算。

```text
创建基础表（配置字段：产品类型、单价等；字段来源支持手工导入或自定义公式）
→ 基础数据维护（单个新增或批量导入基础数据）
→ 创建数据采集表（配置可引用算薪方式、采集类型、可引用薪资组类型、是否区分员工等）
→ 设置采集表字段（字段名称、字段类型、字段来源规则、是否必填、是否作为唯一标识等）
→ 维护采集表数据（单个新增或批量导入，按月采集需选择薪资所属期）
→ 创建汇总表（配置来源采集表、可引用薪资组类型、汇总类型、是否区分员工等）
→ 生成汇总数据（按月生成需选择薪资所属期）
→ 算薪时引用采集/汇总数据
```

- 适用场景示例：制造业统计员工计件工资（根据计件类型定单价，按计件数量统计）；学校统计教师课时费（按老师级别和课程类型核算课时标准）；零售门店分配奖金依赖各门店和个人的零售额、绩效分数等数据。
- 字段类型有文本、数值、日期、百分比、选项可选，也可设置默认值。
- 编辑时所有信息都可修改，修改后的规则只对之后维护的数据进行校验，以前的数据不会进行校验。
- 导入数据可选择录入新数据（适用于计薪及未录入数据的员工）和修改已有数据（适用于更新、修改已有数据的员工）。
- 采集表类型为"区分员工"时，导入的模板中需生成姓名、员工号或者证件号码、证件类型（参数设置的导入类型为员工号则模板中为员工号，否则为证件类型、证件号码），且必输。
- 开启审批时，采集数据需发起审批，审批通过后才可用于算薪。
- 采集数据支持锁定管理和控制规则（阈值控制）校验，详见 `规则与权限.md#数据采集规则`。
- 操作步骤与详细指引见 `问答与差异.md` 的「数据采集使用场景」。

## 成本分摊

企业人员在同一个算薪周期跟进多个项目（或门店、合同公司等），根据员工在各个项目的工作时长（或比例、金额），将员工的算薪结果按项目维度拆分，分别统计在各个项目的成本。

```text
创建分摊方案（选择数据来源：智能算薪 / 税前工资算税）
→ 配置方案（选择分摊类型、分摊方式，设置数据来源为从花名册获取或手工录入）
→ 数据维护（新增数据或导入修改，维护数值）
→ 生成分摊结果（选择分摊方案、统计方式、分摊维度等，可保存模板）
→ 查看汇总/明细，推送至财务
```

- 分摊类型（支持多选）：按部门、按业务分组、按成本中心、按合同公司、按项目、按门店、按自定义类型。
- 分摊方式：按比例（按分摊比例设置的数据，将算薪结果数据乘以分摊比例并汇总到相关维度）、按工作时长（按时长比例分摊）、按金额（按导入的工资项金额分摊）。
- 录入金额需与算薪工资表数值一致，否则生成分摊结果时会报错金额不一致，无法分摊。
- 生成结果时可保存为模板，下次可直接使用，无需重新选择。
- 操作步骤与详细指引见 `问答与差异.md` 的「创建企业分摊方案」。

## 社保公积金

### 创建参保方案

薪福通内置了 200 个城市的社保方案，可根据企业需求创建参保方案，生成企业月结账单的离线台账，该台账可用于智能算薪和税前工资算税获取社保数据。目前新注册的企业默认使用台账（高阶版）。

```text
单个创建：创建方案 → 创建新方案或复制已有参保方案
→ 填写方案名称、选择参保城市（带出系统参保方案模板）
→ 选择项目（社保+医保+公积金 或 社保+公积金，可编辑自定义项目）
→ 设置增员规则/减员规则
→ 关联人员（按工作地、户口性质或花名册字段自动关联方案）
→ 设置统一基数（开启：各险种统一基数；关闭：设置各险种基数上下限）
→ 设置独立增减员规则、基数类型（单基数/双基数）、个人与企业取整规则
→ 创建
批量创建：参保方案 → 批量导入 → 新增式导入 → 下载模板 → 填写方案信息 → 上传
```

- 项目模板说明：社保医保已分割、参停保需分开操作的省份，可选择社保+医保+公积金的项目模板（社保项目包含养老、失业、工伤，医保分组包含医疗、生育两险）；社保医保暂未分割、参停保仍同步操作的身份，可选择社保+公积金的项目模板（社保项目包含养老、失业、工伤、医疗、生育五险）；企业暂不对员工缴纳公积金则不勾选公积金项目。
- 关联人员后，该分类下有新增人员参保时自动关联参保方案。
- 操作步骤与详细指引见 `问答与差异.md` 的「创建参保方案操作指引」。

### 维护参停保人员

创建完参保方案后，企业初始化配置或员工入职时需要办理参保；员工离职后需要办理停保。

```text
参保：
  单笔参保：参保人员 → 新增员工 → 完善参保信息 → 保存
  批量参保：待参保人员跳转参保 或 批量操作-批量新增
停保：
  单笔停保：参保人员 → 员工操作"停保" → 填写停保信息 → 确定
  批量停保：待停保人数跳转 → 勾选需停保人员 → 批量停保 → 填写停保信息 → 确定
```

- 批量参保两种方式：批量新增（为未参保人员设置不同参保方案不同缴费基数的场景）、统一新增（为未参保人员设置相同参保方案相同缴费基数的场景）。
- 工资申报方式：按人员（每个分组对应的基数一致，如社保工资、公积金工资）、按险种（各险种对应的基数不一致，如养老保险基数、医疗保险基数）。
- 调整右下角每页显示数据量，避免出现分页漏选的情况。
- 企业有离职未停保人员时，参保员工页会展示离职未停保人员数量，可在已离职员工中勾选后进行批量停保；已达退休年龄的员工也可在参保人员提示信息中查看到，操作停保流程与离职待停保人员一致。
- 当薪资组算薪人员范围包括离职员工，且该离职员工在当前计薪周期中，系统会自动添加该部分员工至当月计薪人员中；如不在也可手工添加离职员工至当月计薪人员中参与算薪。如还要算税，需确保算税员工在个税中还是可报税状态（人员状态为正确且报送成功）。
- 操作步骤与详细指引见 `问答与差异.md` 的「维护参停保人员操作指引」。

### 调基补差

社保公积金缴费基数调整（调基）后，对已缴费用与应缴费用之间的差额进行补缴。新基数通常从每年 1 月 1 日开始生效，但到年中（如 7 月）才正式确定执行，需追溯从 1 月 1 日起的所有费用。

```text
台账（基础版）：调整员工基数（单个调整/批量调整） → 导入按月补缴金额
台账（高阶版）：调整员工基数（单个/批量）或调整参保方案基数 → 选择生效月，开启"补缴差额"开关并填写补缴起止月份和账单生成月份 → 保存 → 系统自动生成补差金额 → 补缴管理查看/修改/删除补缴数据 → 生成月结账单（包含补缴部分）
```

- 台账（基础版）：支持调整员工基数后导入按月补缴金额的方式进行调基补差；批量调整支持"使用工资"和"使用基数"两种方式。
- 台账（高阶版）：支持通过调整员工基数自动生成补差金额和通过调整参保方案基数自动生成补差金额两种方式；批量调整支持"按办理项目"和"按险种"两种工资申报方式；按险种分单基数、双基数。
- 补缴差额：员工基数调整需要补缴跟之前月份的基数差额时可开启此开关，生成的补缴数据可以在补缴管理明细界面查看并做修改和删除。
- 举例：员工的社保公积金调基实际从 7 月开始，但调基金额在 9 月才确定，所以从 9 月账单开始操作调基，并补缴 7 月和 8 月的差额。则调整生效月份为 9 月（操作调基的月份），补缴起止月份为 7-8 月，账单生成月份为 9 月。
- 操作步骤与详细指引见 `问答与差异.md` 的「社保公积金调基补差操作指引」。

### 生成月结账单

社保管理生成月结账单的方式有 3 种：生成账单、从局端同步、导入。

```text
生成账单：创建好参保方案和完成员工参停保 → 选择账单月和部门 → 生成对应月份月结账单
从局端同步：从社保服务-查询统计-人员缴费明细页面点击更新明细 → 从局端同步数据生成月结账单（台账高阶版支持）
导入：选择导入方式（智能导入 / 模板导入）→ 选择账单布局样式、账单月份、账单关联项目 → 配置数据范围 → 匹配社保项目 → 校验数据 → 提交 → 预览账单 → 完成
```

- 生成账单：适用于使用系统社保公积金版块创建参保方案，在参保员工界面维护员工的基数生成账单后用于算薪。
- 从局端同步：适用于使用社保服务，从局端同步的员工的缴费明细生成月结账单用于算薪。
- 导入：适用于导入员工的社保公积金明细生成账单用于算薪。
- 智能导入可直接导入从各地社保局网站下载的账单数据；模板导入（目前仅台账基础版支持）支持下载系统提供的模板，或上传自定义项目的模板。
- 如果选择的账单月份已有账单数据，可以选择替换或者合并数据；账单关联项目可以勾选多个险种项目，也可以新增自定义项目。
- 系统会记录用户上次设置的表头起始行和数据起始行、社保项目映射配置，下次导入如果模板没有变动过会自动记忆。
- 操作步骤与详细指引见 `问答与差异.md` 的「生成月结账单操作指引」。

### 社保公积金补缴

对应该缴纳社保公积金的期间内因公司未及时缴纳、个人未及时缴纳、计算错误等原因未能按时足额缴纳的部分进行补缴。

```text
台账（基础版）：补缴管理 → 选择补缴月份 → 下载模板填写员工的补缴数据 → 导入 → 核对明细 → 生成月结账单
台账（高阶版）：补缴管理 → 导入 → 选择账单月份 → 选择补缴方式（输入金额补缴 / 输入补缴起止月份补缴）→ 下载模板填写 → 上传 → 核对明细 → 导入
```

- 补缴月份已生成月结账单时，需删除账单后重新生成（或重新生成账单）；补缴后员工补缴月份的月结账单会包含员工本月的社保公积金金额和补缴金额。
- 模板填写规则：数据导入匹配规则按姓名匹配员工花名册的记录，如果有重名员工则证件号必输且不能重复；红色星标部分为必输项不能删除；模板中的险种是取设置的所有参保方案中的险种合集，可删除不需要的险种但至少保留一个险种；社保所属月是该笔补缴金额社保归属月，如果不输默认跟账单月份一致，格式支持 2023/01 或 2023/1 或 2023-01 或 2023-1。
- 输入补缴起止月份补缴：系统自动根据补缴起止月份中员工关联的参保方案生成社保金额，如果中间某月参保方案存在调基的情况，会自动按调整前后的方案生成社保金额。
- 操作步骤与详细指引见 `问答与差异.md` 的「社保公积金补缴操作指引」。

### 社保公积金台账（高阶版）迁移

基础版可迁移至高阶版。高阶版相比基础版可支持人员管理联动台账参停保，并增加了险种按分类统计合计、调基补差可自动计算补缴差额，并支持从局端同步数据生成月结账单等功能。

```text
迁移前：若已在高阶版创建参保方案，为防止数据冲突，需先删除高阶版中参保人员、参保方案
→ 点击社保公积金-台账（高阶版）-参保人员，勾选所有人员批量删除参保人员
→ 点击参保方案，删除参保方案
→ 点击参保人员 → "一键迁移" → 完成迁移
```

- 操作步骤与详细指引见 `问答与差异.md` 的「社保公积金相关问答 → 5.2 怎么迁移社保公积金台账（高阶版）」。

## 补贴计划

企业确定在某个周期内会给员工发放固定补贴时提前设置的计划，算薪时可直接引用（如高温补贴，每年 6-9 月固定 30 元/月）。

```text
创建补贴计划 → 选择奖金补贴类型 → 设置发放薪资组和发放工资项 → 选择发放员工 → 选择发放模式 → 选择发放周期 → 确认 → 系统自动生成补贴数据明细 → 核对 → 确定 → 展示已生成补贴数据明细
```

- 奖金补贴类型：当前仅可选择系统补贴类型，包含通用/默认、生日补贴、高温补贴。
- 发放薪资组非必填；发放工资项若薪资组不填则显示全部薪资组的工资项，选择某个薪资组则显示该薪资组的工资项；使用补贴计划需提前在薪资规则创建对应工资项。
- 发放模式：每月固定金额（在发放周期内每月发放固定金额）、总包分期等额发放（将金额平均分配至发放周期的月份）。
- 发放周期：可选择连续或者间隔月份。
- 薪资组应用：
  - 创建补贴计划时发放薪资组未选择：企业在核算发放员工所在薪资组时，只要计薪周期在补贴所选的月份范围内，系统会自动获取补贴计划中的金额（核算的薪资组需包含补贴工资项）；若多个薪资组均包含该补贴工资项，则首个计算的薪资组可自动获取金额，其余薪资组无法获取；已被薪资组引用计算的补贴明细会显示引用的薪资组和已发放状态，且无法删除。
  - 创建补贴计划时发放薪资组已选择：仅该薪资组在核算对应补贴月份时可获取补贴金额，其余薪资组无法使用。
  - 重置发放状态：若已发放补贴明细的薪资组删除了该员工的当期工资数据，则补贴计划中的发放薪资组和已发放状态将重置为空薪资组和未发放状态。
- 操作步骤与详细指引见 `问答与差异.md` 的「补贴计划操作指引」。

## 多所得类型与多薪资组算薪

多所得类型算薪分为两种场景：企业同一员工在同一个月有多种不同所得类型的收入；多个员工需要在同一薪资组算薪但涉及到的所得类型不同。

```text
同一人多个所得类型：
  方式一（多个薪资组独立算薪）：第一个薪资组计算正常工资薪金，第二个薪资组计算全年一次性年终奖
  方式二（单个薪资组同一员工计算多个所得项目）：编辑薪资组 → 配置薪资规则 → 设置个税所得项目 → 针对不同工资项设置不同所得项目（如应发工资设为正常工资薪金、年终奖设为全年一次性奖金）→ 系统根据所设置的个税所得项目分别计税
不同人员不同所得类型：计算税后工资-计算个税 → 确认税款所属月 → 选择对应所得项目 → 指定人员并选择对应人员 → 算税成功后重新选择另一个所得项目并按指定人员选择对应人员
```

多薪资组算薪场景包括：员工在月中发生部门调动当月需在新旧部门同时算薪；员工兼任多岗位需分别在对应岗位完成算薪；同一员工当月有多种所得类型的收入需分薪资组核算；员工在多家企业税局报税需多个税局核算薪资。

- 部门调动场景处理：
  - 使用人事异动产生的记录算薪：开启时，如果使用人事异动，根据异动记录产生的历史数据（历史部门、岗位等）用于薪酬计算；关闭时，不管是否使用人事异动，只取花名册当前数据算薪。配置在薪酬设置-参数设置-高级设置中。
  - 通过薪酬档案同步花名册：更换部门后算薪界面还显示原来的部门，需通过薪资档案"同步花名册"。
  - 通过算薪界面"重新同步人员"。
- 兼任部门场景：花名册查询是否已增加兼任部门；同步兼任部门人员需打开"同步兼任部门人员"开关（编辑薪资组-基础设置-算薪人员）。
- 一人多税局算税场景：一个人在薪资组中只能存在一条算税数据，同一人多个税局算税，人员就需要存在于多个薪资组独立算税；算税完成后可通过个税服务-个税管理-个税核算查看对应税局及个税明细。
- 操作步骤与详细指引见 `问答与差异.md` 的「多所得类型算薪场景操作指引」与「多薪资组算薪场景操作指引」。

## 算薪联动电子工资单与代发

### 联动电子工资单

企业管理员核算完薪资后，可以直接把工资表推送到电子工资单界面进行发放，推送分为单批次发送和多批次合并发送两种方式。

```text
单批次发送：当期工资 → 更多操作-提交电子工资单（提交前需先锁定工资表）→ 设置是否全部人员提交（可提交人员和反向选择不提交人员）→ 跳转电子工资单页面 → 设置工资单可见项 → 立即发送或预约发送
多批次合并发送：提交电子工资单 → 选择批次 → 提交 → 跳转电子工资单页面设置
```

- 多批次合并发送电子工资单需满足条件：勾选的所有批次算薪状态必须为"已生成税后工资"；所有批次锁定状态必须为"已锁定"；所有批次薪资所属月必须一致；如果设置了需要审批，所有批次审批状态必须为审批通过。没有满足条件则不能合并发送电子工资单。
- 算薪完成阶段也可以锁定工资表后发送电子工资单。
- 操作步骤与详细指引见 `问答与差异.md` 的「算薪联动电子工资单场景指引」。

### 联动代发

企业管理员核算完薪资后，可以直接把工资表推送到薪资代发界面进行发放，也可以导出数据通过网银发放，推送分为单批次代发和多批次合并代发两种方式。

```text
单批次代发：当期工资 → 更多操作-发起薪资代发（发起前需先锁定工资表）→ 选择按一个批次代发或按部门/业务分组/合同公司拆分多个批次代发 → 提交已勾选员工 → 跳转薪资代发-代发申请-新增代发页面提交代发申请
多批次合并代发：薪资代发 → 选择可提交合并代发的数据 → 确定 → 选择代发方式和员工 → 提交代发申请
导出招行网银代发数据：当期工资 → 更多操作-按格式导出-招行网银代发数据 → 导出后直接上传网银代发
```

- 多批次合并代发需满足条件：勾选的所有批次算薪状态必须为"已生成税后工资"；所有批次锁定状态必须为"已锁定"；所有批次必须为未代发、全部失败、部分失败；所有批次薪资所属月必须一致；如果设置了需要审批，所有批次审批状态必须为审批通过。没有满足条件则不能合并代发。
- 代发将仅提交已勾选的员工；校验成功或失败的工资明细信息都可继续提交到代发经办界面，可在代发经办界面继续修改。
- 多批次合并代发时，如果员工不在选择的部门、业务分组、合同公司，则选择代发员工页面不会展示对应的代发员工；选择代发方式后选择具体的代发员工，可修改代发人员的银行卡号、开户行和开户地；多批次合并代发实发工资会显示一个员工在多个批次的实发工资合计。
- 差额补发：完成薪资计算并联动代发后，若发现部分员工薪资数据存在遗漏，系统支持重新计算薪资，基于已完成的代发金额自动计算差额并联动代发。需要首次代发已经成功，"已发放金额"才会更新数据，系统才会自动计算出差额；差额部分提交到薪资代发版块进行发放。
- 操作步骤与详细指引见 `问答与差异.md` 的「算薪联动代发场景指引」。

## 薪资计算发起审批

当期工资计算完成并锁定当期工资后，如开启算薪审批，需提交审批流程。

```text
工资表单笔发起审批：当期工资 → 发送审批
多笔工资表汇总发起审批：薪资计算 → 提交审批
拆分当期工资表发起审批：当期工资 → 发起审批 → 拆分审批
```

- 如开启了审批，企业可在审批设置界面配置审批流程、节点以及审批的分支条件（审批流配置跳转协同办公-OA 审批）。
- 审批通过后才可以进行后续操作（如提交电子工资单、发送薪资代发）。
- 操作步骤与详细指引见 `问答与差异.md` 的「薪资计算发起审批场景指引」。

## 假期余额结薪

针对有余额概念且为带薪假的假期类型（如年假、调休假），如果假期额度到期仍未使用完，剩余额度可给员工结算为工资。薪福通支持设置带薪假余额结薪；若同一家企业不是所有员工的带薪假期都可以结薪，也支持按照不同使用人员设置结薪方案。

```text
结薪设置：
  假期类型设置：假勤管理-假期类型设置 → "是否带薪"设为"带薪假" → 勾选"假期余额可结薪"
  假期方案设置：设置该假期类型的"余额结薪设置" → 打开"余额结薪"开关 → 选择手工结薪或自动结薪（自动结薪支持按月结薪和按年结薪）
余额结薪：
  手工结薪：假期额度明细 → 筛选员工 → 余额结薪（单笔）或批量结薪 → 选择结薪额度和结薪月份
  离职自动结薪：离职管理确认员工离职触发 → 假期管理收到系统消息后实时自动生成离职员工的额度结薪单
  过期余额定期自动结薪：根据假期方案设置的自动结薪规则定期生成结薪单
  余额结薪记录查询：假期额度明细 → 余额结薪记录 → 按月查询员工额度结薪情况
→ 月考勤统计结薪时长查询 → 智能算薪应用结薪时长计算结薪工资
```

- 勾选"假期余额可结薪"后，会自动在假勤管理-考勤统计-统计项管理"其他"分组的"月考勤汇总"中增加该假期类型的结薪时长字段（如年假结薪（天））；删除假期类型时，系统会自动将该假期类型的结薪时长字段删除。
- "假期余额可结薪"关闭联动假期方案的"余额结薪设置"，若该假期类型下任何一个假期方案打开"余额结薪"，则不允许关闭。
- 结薪方式：
  - 手工结薪：考勤管理员手工操作结薪；可对每一笔额度明细进行操作，支持多次结薪，支持指定结薪月份（即算薪月份）。
  - 离职结薪-自动生成结薪单：员工离职当月，系统自动结算剩余的假期余额到月考勤统计中该假期类型的结薪字段。
  - 过期余额结薪-定期生成结薪单：根据设置的时间，系统自动结算剩余的假期余额到月考勤统计中该假期类型的结薪字段。
- 不能手工结薪的情况：假期方案设置中"假期余额"不可结薪；剩余额度为 0。
- 批量结薪只能选择同一个结薪月份，不支持同一批员工结薪到不同月份，这种情况可分多次操作不同月份的结薪。
- 离职自动结薪前置条件：假期方案设置中离职结薪方式选择"自动生成结薪单"；员工可结薪假期余额不为 0。
- 过期余额定期自动结薪前置条件：假期方案设置中过期余额结薪方式选择"定期生成结薪单"；员工在假期设定范围内过期未休完余额不为 0。
- 按年结薪：每年 12/31 日结薪（如 2023/12/31 结薪范围为 2022/1/1-2022/12/31）；按月结薪：每月 31 日结薪（如 2023/2/28 结薪范围为 2023/2/1-2023/2/28）。按月结薪选择 29、30 或 31 号时，当月若无此日期则在当月最后一天生成结薪单。
- 结薪有误时，可以在余额结薪记录中删除员工的结薪记录，然后重新结薪。
- 按入职日发放的假期、按月发放的假期、调休假支持按月结算和按年结算两种自动结算方式；按年发放+按固定日期发放的假期，仅支持按年结算一种自动结算方式。
- 操作步骤与详细指引见 `问答与差异.md` 的「结薪功能操作指引」。

## 事务依赖与回主域
