# 协同办公

## 这是什么

这是协同办公业务知识库的聚合领域的子域路由入口，用来说明各子域目录分别承载什么知识、遇到什么问题该优先进入哪个子域。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应子域语义文件中。

## 全局入口信号

- 命中：需要查询智能报表，或通讯录、企业公告、公文、信息收集、必应、智能会议室、日程等协同办公工具的业务规则、流程、状态或使用边界。
- 排除：通用审批机制进入审批管理；通用权限治理进入权限管理；成员身份与组织底座事实进入成员管理或组织架构。

## 领域契约

### 领域定义

协同办公领域回答的是：
企业如何通过薪福通平台的智能报表和多个独立办公工具完成日常办公协同与数据可视化。

它覆盖的不是单一办公功能，而是一整套与企业协同办公相关的业务语义，包括：

- 智能报表：报表查阅、订阅推送、预警规则、权限管控
- 通讯录：与人事花名册实时互通，支持组织架构/我的部门/常用联系人三个视图
- 企业公告：文字/图片/附件多种形式，按部门/岗位/员工类型设置查看范围
- 公文：发文拟稿/收文/签报全流程，多级多部门会签审批
- 信息收集：问卷调查 + 补录表单，支持普通模式和下发模式
- 必应：待办创建/列表/协同处理、重复规则和智能提醒
- 智能会议室：楼栋/会议室数字化录入、可视化预约、两级管理
- 日程：创建/订阅/设置，月/周/日视图

### 解决的问题

协同办公领域主要用于解释以下问题：

- 企业员工如何查阅、订阅和接收报表预警
- 报表权限如何分配和管理
- 企业如何通过各独立办公工具完成日常办公（通讯录、公告、公文、会议等）
- 信息收集和日程管理如何运作

### 为什么独立成域

协同办公需要独立沉淀，是因为它同时具备以下特征：

- 是薪福通平台的核心一级模块，覆盖企业日常办公协同的多个工具
- 智能报表依赖智数平台的数据加工，有独立的查阅、订阅、预警和权限体系
- 通讯录、企业公告、公文、信息收集、必应、智能会议室、日程 7 个办公工具各自独立成子域，各有完整的业务功能
- 与权限、审批、成员等多个领域存在交叉依赖

### 与上游领域的关系

- 与权限域交叉：报表权限控制通过权限域统一治理
- 与审批域交叉：OA 审批属于协同办公范畴，但独立维护在审批域
- 与成员域交叉：通讯录与人事花名册数据实时互通

这里描述的是上游依赖事实，不等于具体规则已经由其他领域定义完成。

### 稳定结论

- 协同办公是企业日常办公协同的核心入口
- 其核心价值是为报表查阅与预警、各独立办公工具使用提供稳定输入
- 它可以服务业务分析、产品设计、体验解释和排障分析，但本文件本身不承载下游消费说明

## 条件依赖与回主域

- 先按智能报表或各独立办公工具确定主子域，不因出现“协同”通读所有子域
- 命中报表或工具授权时补读权限管理，命中通讯录身份数据时补读成员管理，命中公文会签等通用审批机制时补读审批管理
- 读完依赖域后必须回到主子域确认协同对象、状态与结果
