# 内网知识源维护

本分支根目录的 `knowledge-import/` 是唯一权威知识正文。内网使用导入后的知识副本。此 Skill 由源分支维护者使用。

## Step 0 · 运行入口与来源门禁

根据用户请求选择维护或提取。只读取用户明确提供或授权的材料、与任务直接相关的现有正文及更新记录。候选经用户明确审阅或治理放行后可作为待核材料，写入正式知识前仍须核对来源和适用范围。

## 维护正文

1. 按 [输入证据适配](references/input-adaptation.md) 判断材料能够证明的内容，区分现状、目标、历史、待确认和冲突。
2. 按对象、动作、条件和结果查找唯一事实落点。检查会受影响的规则、状态、权限、页面、上下游关系和例外。
3. 按 [知识入库与保真规则](references/ingestion.md) 写入已确认内容。确认相同对象、适用范围和条件后再替换旧表述。已知缺口、疑问或冲突分别保留 `[GAP]`、`[QUESTION]`、`[CONFLICT]`。
4. 按 [验证规则](references/validation.md) 对照源材料与改动，再向 [知识更新记录](knowledge-changes.md) 追加实际内容变化。

## 记录实际变化

每条记录写明带时区的时间、动作（新增、修改或删除）、对象与主题、实际变化、可定位到文件和章节或规则的当前落点。替换、删除或移动还须记录原落点与足以唯一辨认旧内容的原句或准确描述。移动可在同一条记录中给出新旧落点。纯格式整理和迁移位置不改变知识含义时无需登记。更新记录在正文目录外维护。

## 按指定范围提取

按用户指定的时间、主题或记录筛选，逐条定位并核对当前权威正文。同一规则多次修改时提取所选范围涉及的当前结果。新增后又删除时说明最终状态。删除项用原落点和原内容定位，供维护者处理。范围或定位不明确时说明缺口，只提取能确定的范围。交付形式由用户当次决定。

## 交付与下一步

维护时说明已改内容、定位、未决项与记录位置。提取时说明实际覆盖范围及需要核对的删除或替换项。
