# 设计规范入库模板

## 这是什么

这里提供设计规范入库时的分类、文件划分、路由和语义验收参考。模板不是正式知识，不进入 `knowledge/wiki/index.md`，也不是必须逐项填满的问卷。

输入是否已经整理完成，只影响实际整理工作量，不改变入库标准。

## 使用入口

- `知识对象划分指南.md`：判断信息属于样式、组件、典型页面还是场景模式，并决定合入、拆分、合并或新建主题。
- `设计规范README.template.md`：新建设计规范领域总路由，或根 README 结构需要补齐时参考。
- `分类README.template.md`：新增分类或补齐分类路由时参考。
- `主题文件.template.md`：新建或重组主题正文时参考。
- `来源语义验收清单.md`：写入前逐章节检查语义是否完整保留。

## 统一入库流程

```text
确认本次输入作为设计规范入库
→ 按样式、组件、典型页面、场景模式归类
→ 检查语义完整性、重复与冲突
→ 检查文件职责、标题和内容颗粒度
→ 同步根 README、分类 README、顶部导航和全局 index
→ 运行机械校验
→ 使用真实问题验证路由
```

## 使用原则

1. 已整理输入检查通过后尽量原样接入；混乱输入可以无损拆分、合并、重排和去重。
2. 原始文件边界不决定正式文件边界；一个主题文件承担一个可独立路由、回答和维护的稳定知识对象。
3. 不得摘要化。条件、数值、状态、例外、结构、步骤、反馈和恢复路径必须保留。
4. 文件名只表达核心对象，不重复上级目录已有的“规范”“组件”或“场景”语义。
5. README 负责契约和路由，主题文件负责唯一规范正文；同一事实不得跨文件复制维护。
6. 模板章节按实际知识增删，不得照抄占位符或为填满模板补造事实。
7. 无法确认的信息使用 `[GAP]`，矛盾信息使用 `[CONFLICT]`，需要决策的信息使用 `[QUESTION]`。

## 跨域提示规则

设计规范中出现可归入设计准则或交互模式的信息时：

- 原始信息继续完整保留在设计规范。
- 在当次聊天窗口列出信息位置、核心内容、判断依据和建议归属。
- 等待用户决定是否另行更新设计准则或交互模式。
- 不自动迁移，不修改设计准则或交互模式。
- 不创建候选文件、未入库记录、映射表或其他持久化状态。

## 禁止事项

- 不把设计规范套入业务知识八类载体。
- 不保留原始材料来源路径、CSV 检索表、问答脚本、Prompt、回答模板或 AI 检索元数据。
- 不按来源目录、文件数量或行数机械拆分主题。
- 不把模板目录加入正式知识索引。
- 不在 README 复制主题正文或维护长文件章节目录。
- 不通过脚本决定知识归属、语义等价、冲突或跨域迁移。
