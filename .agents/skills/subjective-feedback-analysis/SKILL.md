# 主观反馈分析

把散乱的主观材料变成一份可追溯、已脱敏、带使用边界的分析报告：说明样本中的用户表达、主题、情绪、紧急度、体验表现和待验证假设。本技能只描述样本内发生了什么，不把用户表达升级为客观事实、真实发生率、最终根因或效果结论。

## 适用与边界

适用材料：客服工单、用户群聊、客服与运营记录、问卷开放题、访谈摘录、应用商店与社媒评论、内嵌反馈、客户成功记录，以及两个反馈窗口之间的主观比较。

不适用于：

- 埋点、漏斗、真实路径、性能、接口和原始系统日志——这些是客观行为数据，本技能不读取、不分析。
- 现有页面的启发式走查与界面问题诊断。
- 最终根因综合、业务影响与投入产出比、方案效果与归因回检。
- 产品排期、优先级定级和具体解决方案设计。

服务日志只有明确绑定客户原声或客服转述文本时才能进入；内部处理记录只能作为情境背景，不得聚成客户反馈或提升为证据。没有明确文本绑定时，不得把整行记录拼成一条反馈。

保留正向与冲突信号：满意、信任、易用和恢复成功同样要写进报告，不用少量正向反馈抵消高风险阻断，也不只盯负面材料。

## Step 0 · 运行入口与来源门禁

正式输入只有四类：用户在本轮消息中给出的反馈文本、附件、截图、文件或链接；用户明确授权读取的目录与项目材料；用户明确指定的已确认上游结论；已通过治理且与当前问题直接相关的正式上下文。

不得自行扫描工作区寻找“可能有用”的工单、群聊、访谈或历史主题。聊天历史只帮助理解意图，除非用户说“就用上面这些”，否则不能当成正式输入。

材料足够时直接开始分析，先用一句通俗的话说明理解到的范围，再往下做；不要让用户先选模式或先填表。只有会实质改变结果的歧义才发问，一次最多三个：

- 分析对象或时间范围存在多种合理解释。
- 需要读取新增目录、额外数据源或敏感范围。
- 前后比较缺少窗口、干预说明或关键可比口径。
- 业务术语含义无法安全推断。

执行方式只有两个正交判断：材料是用户直接给的，还是用户指定的上游结论；本轮看当前现状，还是对齐两个反馈窗口做比较。两种判断都不改变下文的分析规则。

输入质量先判定再动分析：材料可读、时间窗与去重口径清楚为可用；存在渠道、字段、样本或语义限制为可用但有保留；范围有多种解释为需用户补充；材料不可读、全部无法安全处理或根本没有主观反馈内容为阻断。只有阻断时停下，其余缺口写进限制说明。

## 分析规则

**先脱敏，再分析。** 姓名、手机号、邮箱、证件号、地址、个人账号与用户 ID、合同号、订单号、工单号、支付流水、金额明细、内部人员、群名、带敏感参数的后台链接、验证码与密钥、权限细节和漏洞信息，全部在进入分析前替换为稳定占位符（如 [PERSON_1]、[TICKET_1]、[SECRET_1]），同一实体在同一份报告里用同一占位符。报告里只出现脱敏文本。确实无法安全脱敏的内容不进入报告，只保留风险类型与来源引用，并标注需人工复核。企业编号与企业名称可在授权范围内作为关联与分群依据保留，不按个人隐私字段删除，也不得因此扩大授权范围或对外披露。

**反馈单元与去重。** 拆成最小可理解的反馈单元并保留上下文：工单区分用户原话、客服转述、处理记录和解决状态；群聊按会话线程合并提问、追问、答复和结果确认；访谈保留问题与必要追问；问卷和评论可以一条拆出多个议题，但共享同一来源。去重按稳定优先级：明确的重复标记 → 同一会话线程 → 同一匿名主体、相近时间、高度相似文本 → 复制粘贴传播。必须区分同一用户反复追问、多人独立反馈、同一事件传播和真正的重复记录；主体无法稳定识别时，不声称独立用户数。

**开放编码优先。** 先开放编码，再合并成子主题与主题；主题名描述用户表达的体验现象，不写根因或方案。既有主题只能当锚点，不能压制新主题；相反意见、弱信号和无法归类的条目都要保留。流程阻断、权限或配置、信息展示、能力缺失、效率成本、业务规则逻辑、协作问题这类标签只用于辅助检索与切片，是多标签，不替代开放主题，也不自动产生产品优先级、根因或方案。

**三个维度分开判断。** 情绪（正向、中性、轻度负向、中度负向、强烈负向、未知）、紧急度（高、中、低、未知）、主观严重度（阻断、主要、次要、提示、未知）互不替代。强烈情绪不能证明高普遍性；资金、权限、合规或核心任务阻断即使低频也可以进入高关注，但必须同时给出样本量和置信度。

**只写样本内数字。** 每个主题都给样本内数量与占比，并说明分母和去重口径。不得写成总体发生率、真实影响人数或业务规模。切片只用材料或正式上下文中已有的依据——产品模块、页面、功能、操作节点、渠道、角色、企业群体、生命周期、客户类型、熟练度和显式业务字段；没有依据就写未知，不发明“高价值用户”这类标签。允许受控的单维或最多三维交叉，样本过少时降级并标注风险。

**渠道偏差要写出来。** 工单与客服记录天然偏问题样本，不能代表沉默用户；群聊重复咨询、运营引导和刷屏风险高；社媒与应用商店会被极端情绪、传播和版本事件放大；问卷受题目措辞、招募方式和不回复影响；访谈上下文深但样本小；客户成功与运营记录偏向高价值客户且常含转述。

**置信度三档。** 高：多来源独立出现、去重清楚、引用与主题一致。中：单渠道稳定，或多渠道但仍有缺口。低：样本少、偏差强、重复或转述风险高。主观置信度不得升级为因果置信度。

**页面、流程与旅程只做映射，不做倒推。** 优先用结构化字段和原文里的模块、页面、入口、功能、按钮、步骤、错误提示，其次用用户明确引用的正式上游结论。直接命中为高置信，继承正式映射的适用范围，上下文推断要标为推断并降低置信度。一条反馈可以关联多个页面或功能，不强制单选：页面回答“发生在哪里”，功能回答“正在做什么”，操作节点回答“具体卡在哪一步”。不得从情绪倒推页面。

**报错只写“用户报告”。** 用户、客服或运营转述的报错文案、错误码、超时、失败或权限不足，只能标为转述的报错，并保留原文、位置、前置操作、影响和恢复情况，不得写成已验证 Bug 或系统日志事实。只有日志或监控告警、没有用户反馈的，不属于本技能。

**体验工单只看入口。** 用户要求筛选体验工单时，按视觉动线、交互流程、信息传达、负向体验信号、界面或交互异常、报错与失败反馈六类打入口标签，允许多标签；相关与可能相关进入体验主题频次，其余保留数量和分流原因。未命中不等于没有体验价值，不确定条目不得静默删除。标准里的视线跳转次数、点击与跨系统跳转次数、加载秒数、屏幕尺寸都只是启发式参考，不作硬门槛。

**关注信号不是产品优先级。** 用高关注、中关注、低关注、待复核表达值得优先看的主观信号，综合样本内频次、跨渠道出现、受影响角色、情绪、紧急度、任务关键性、资金/权限/合规信号、绕行方案和置信度。它不是 P0—P3，也不给排期或影响人数。

**前后比较只比样本。** 只有两个反馈窗口都能识别时才做：先对齐渠道范围、去重口径、主题规则版本、用户结构、时间窗长度、业务周期、同期活动与故障、政策与规则变化。状态只用“增加、减少、持平、新出现、本期未观察到、结构性转移、不可比”，并同时给出两个窗口的样本内数量、占比、分母和限制。“本期未观察到”不等于问题已解决，“再次观察到”也不等于正式回归。不得使用有效、无效、已解决、回归、由某原因导致这类效果或归因词。已有正式基线时直接引用，不重新定义。

**问卷 NPS 单独算。** 材料中有 0–10 分 NPS 时，按答卷去重后给出总体、业务板块、企业状态以及板块×企业状态的推荐者、被动者、贬损者比例与样本数；只有拿到邀请数或邀请标记时才计算响应率。NPS 是答卷粒度的主观指标，不与任务或企业粒度直接拼接。

**客观验证请求有条件。** 只有当重要发现确实需要行为、错误、漏斗、路径或规模上的验证时才提出，并写清相关发现、假设、需要的信号、范围、时间窗和原因。提出请求不等于获得读取授权。

**知识候选必须有触发条件。** 只有出现稳定重复问题、多个相近问法、稳定答复、冲突答案、过期风险、临时绕行方案或值得复用的用户困惑时才生成候选，并区分为问答、回答模式和引导素材三类，全部标注需人工复核。“运营复核过”只表示人工整理过，不代表答案正确或仍然有效。普通主题分析不机械生成候选。

**查知识要定向。** 只有业务规则、状态、权限、路径或既有答案会改变判断时，按对象、动作和结果从萃知检索。核对实际来源、适用条件、结果与例外。若明确依赖会改变规则、责任或异常，补查后回到主线；证据不足时记录缺口。

## 正式证据与交接

在报告中分别列出发现、可交接证据、客观验证请求和知识候选。证据应能按编号定位脱敏来源、样本口径、限制与允许用途；代表性原声与样本内比较不得自动升级为正式证据。证据治理按报告中明确列为证据的条目消费。知识候选按审阅流程处理。

## 输出（Markdown）

正式产物为 `spark-output/subjective-feedback-analysis.md`。在正文记录本轮任务、范围或时间窗、输入来源和产物身份。消费上游时读取本轮明确关联的完整 Markdown，核对所属项目或需求、分析范围、来源、可用结论及限制。同一路径的旧产物只有在本轮明确关联时才可采用。需要放行或审核的内容，以报告中可定位的条目及明确授权为准。

必须输出一份 Markdown 分析报告，这是本技能唯一的交付物：不额外维护平行的机器可读结果文件，不附校验脚本产物，也不输出 HTML 或正式图表。报告只复述已经完成的分析，不新增结论；所有引用都是脱敏摘录并注明来源类型；所有数字都是样本内数字并带上分母。正文用自然语言描述关系，在证据和交接表中保留必要的条目编号。

报告章节依次为：

## 1. 结论摘要与样本边界
## 2. 材料范围、去重与隐私处理
## 3. 样本质量与渠道偏差
## 4. 主题聚类：频次、情绪与紧急度
## 5. 关注信号与低频高风险
## 6. 条件切片：页面、流程、分群与前后窗口
## 7. Findings 与代表性脱敏原声
## 8. 客观验证请求、知识候选与限制

各章要点：

- 第 1 章用 3–6 条写出样本内最重要的表达与边界，注明有效反馈总量和时间窗。
- 第 2 章写清纳入与排除、样本单位、去重单位、线程合并规则、渠道与时间窗、脱敏方式，以及无法脱敏内容的处置。
- 第 3 章给输入量、有效量、重复量、排除量、无法解析量、渠道覆盖、字段缺失、线程完整性、分群覆盖、翻译与语义风险。
- 第 4 章每个主题写样本内数量与占比、分母、情绪与紧急度分布、典型表达和置信度。
- 第 5 章单独列低频高风险信号，说明它为什么值得关注，同时保留频次与置信度。
- 第 6 章只在有依据时出现：页面与流程映射要分直接命中与推断，分群切片注明依据，前后比较给两个窗口的可比性说明与样本内变化。
- 第 7 章区分 Findings 与正式证据：Findings 是样本内发现，可以含待验证假设；满足追溯、脱敏、样本边界、置信度和用途限制的才写成正式证据，并写明允许与禁止的用途。
- 第 8 章列客观验证请求、可选知识候选和全部限制；没有内容时写“无”，不要留空节。

前后比较模式下，第 6 章扩展为两个窗口的可比性、主题与情绪变化、再次出现的信号；其他章节保持同一结构，只补充窗口标签。

## 自检

- 输入是否全部来自用户本轮提供、明确授权或明确指定的正式上游？
- 是否先脱敏再分析，报告里没有任何未脱敏原文、个人名、个人账号、工单号或凭证？
- 是否每个主题都给了样本内数量、占比、分母和去重口径，没有写成总体发生率？
- 情绪、紧急度、主观严重度是否分开判断，低频阻断是否同时保留了频次与置信度？
- 渠道偏差、转述风险、翻译与语义风险是否写进限制？
- Findings 与正式证据是否分开，假设有没有被当成证据？
- 报错是否保持“用户报告”口径，没有误标为已验证 Bug 或系统日志？
- 工单分类是否允许多标签，不确定项是否保留而没有静默删除？
- 前后比较是否只用样本内的变化词，没有写出有效、已解决、回归或因果归因？
- 知识候选是否都标注需人工复核，没有直接发布或包装成正式规则？
- 报告章节是否齐全，篇幅是否克制，没有掺入排期、优先级定级、ROI 或影响人数承诺？

## 交付与下一步

正式报告写入并通过自检后，若包含可交接给证据治理的正式证据，在会话交付结尾提示：「可以说『用证据治理核对本次报告的证据，并明确哪些可以给下游使用』。」用户明确选择后再调用 `evidence-govern`。该提示不写入正式报告。

正式报告写入并通过自检后，若有适合且获准展示的结果，在会话交付结尾给一句可选提示。按本轮结果调整说法，例如「用数据可视化整理本次反馈主题，或结合这份报告和客观分析报告做一份总览」。提示仅出现在会话中，用户明确提出后再调用 `data-visualization`。
