# 体验启发式分析

把本轮实际取得或经用户明确提供的界面材料，转成不评分、可定位、可追溯的体验风险观察，并写成一份可读的 Markdown 报告。只描述材料能证明的内容：观察就是观察，风险假设就是风险假设，不把两者混成结论，也不用界面材料推断真实行为、根本原因、方案价值或方案效果。

## 适用与边界

适用：

- 视觉清晰度、信息架构、流程连续性、组件与设计系统一致性、边缘状态、文案可理解性、响应式与触控线索、操作反馈与恢复、基础可访问性线索，以及与明确 Brief 或验收条件的偏离。
- 三类任务：现状发现（看当前可观察的风险）、限定范围检查（只看点名范围）、改版前后风险回检（只比较明确给定的前后材料）。
- 材料形态：截图、原型、流程与蓝图、前端代码、DOM、可访问性树、运行态录制，以及本轮工具真实采集到的界面状态。

不在本 Skill 内完成：

- 埋点、漏斗、日志、真实路径等行为数据判断；工单、评论、访谈等主观反馈分析。
- 跨来源互证、情境评估与证据放行；最终根因结论；具体体验或交互方案。
- 界面评分、优先级排序、批量 UI 巡检、完整 WCAG/ADA/EAA 或法律合规结论。
- 业务价值、受影响规模、投入产出比与方案效果定论。

硬边界：至少要有一种可观察的界面材料。只有业务问题、客观数据或主观反馈、却没有界面材料时，不开展本分析，也不产出报告。

## Step 0 · 运行入口与来源门禁

只使用以下来源：用户本轮提供的截图、原型、链接、文件、代码或结构化材料；用户明确授权读取的目录与项目材料；本轮由工具真实取得并登记的界面材料；用户明确引用的上游材料；判断确实需要时，从萃知检索并可回溯到正式原文的规则。禁止自行扫描工作区寻找“可能相关”的历史材料；链接或工具内容没有真正取得时，不得声称已经检查。

- 来源逐项登记：类型、引用、获取方式（用户提供、工具采集、明确上游）、加载状态（完整、部分、不可读）、本轮确实具备的观察能力、材料限制、敏感程度与披露限制。引用里不保存本机绝对路径、账号凭证或带密钥的链接。
- 裸激活：用户没给材料时，用一句白话索取：“请发我想检查的页面、流程、原型、截图、代码或文件路径，也可以直接说只想检查哪个页面或哪段改版。”
- 补问克制：只有范围会实质改变结论、回检缺少前后材料、读取需要额外授权、或规范冲突无法裁决时才追问，且只问最少必要的问题。
- 知识库按需：纯视觉、可见状态、响应式和可访问性线索默认不查萃知；只有当业务规则、角色权限、预期流程、字段含义、异常机制或设计规范会改变判断时才从萃知定向检索。核对适用范围、触发条件、结果、例外与可定位的正式来源，读到最小充分依据即停。索引与说明只用于定位，不作为规则事实；适用范围或版本无法确认时提出待确认，不自行裁决。

隐私门禁先于分析：

- 来源与结论的隐私状态分别判定：可公开、受限（只能使用脱敏后的结论）、待确认（人工复核前不得扩大用途）、禁止（不得进入证据或可读输出）。
- 来源含个人信息、企业信息、单据号或凭证时，不得把原文、截图或可反推身份的内容自动复制进报告、预览或知识库。
- 结论只有真正去标识化、且无法反推出具体个人、企业、单据或凭证时，才可标为可公开；无法确认时一律按待确认处理并请求人工复核。

## 分析规则

**不评分，不重复计数。** 一个可观察问题只保留一条 Finding；认知负担、可发现性、平台原则、Nielsen 启发式等只作为观察透镜或标签，不得为同一问题另立一条。没有整体评分，没有覆盖率百分比，也没有界面“通过/不通过”的结论。

**十个检查域。** 流程连续性（入口、推进、返回、取消、终态与恢复）；信息架构（导航、分组、层级、命名、任务可达）；组件与设计系统（语义、设计令牌、状态一致性）；视觉层级（主行动可见、扫读与发现）；边缘状态（空、加载、错误、权限、网络、部分成功、极端数据）；文案（标签、按钮、术语、错误与帮助是否可理解、可行动）；响应式（视口、设备、方向、溢出、触控）；反馈与恢复（操作反馈、进度、防重复、确认、撤销）；基础可访问性（可感知、可操作、可理解、语义健壮性线索）；Brief 一致性（与明确 Brief、验收条件的偏离）。每条 Finding 只选一个主分类，其余归为透镜。

**范围与覆盖。** 全量走查覆盖十类；限定检查只覆盖明确点名的范围；差异回检只覆盖前后变化影响到的范围。覆盖状态只用四种说法：已检查且有风险、已检查未发现明显风险、不可评估（写明材料限制）、不在本次范围（写明原因）。“未发现”只代表现有材料下没看到，不代表审计通过。

**按当前页面职责选检查点。** 涉及上下游交接、材料只覆盖局部状态，或页面类型相同但任务职责不同时，读取 [界面证据与场景描述指南](references/interface-evidence-guide.md)。用已确认的角色、任务、页面职责和业务约束确定检查重点，再用直接界面证据核对；缺少会改变判断的情境时按补问规则处理。涉及高密度界面时，按 [视觉清晰度规则](references/platform-accessibility-rules.md#视觉清晰度) 核对关键对象、信号和动作能否关联。

**严重度只表示设计风险。** 阻断：材料直接证明主任务无法继续、没有恢复路径，或明确违反已确认红线；严重：明显影响理解、完成、信任、可达性或关键状态恢复；轻微：不阻断，但影响效率、一致性或清晰度；提示：材料不足、需要进一步验证的观察。严重度不代表发生频率、影响人数、业务价值或实施优先级；未确认的规则风险不得标为阻断。

**观察与假设必须分开。** 每条 Finding 分别写：材料中实际可见、可定位的事实；由该事实提出的体验风险假设；后续设计必须解决的关注点（不是具体方案）。禁止“用户一定……”“必然导致……”“已验证根因”“建议改用某组件”这类表述。

**置信度只表示观察可靠性。** 高：问题可直接观察、位置明确、材料与适用规则一致；中：可观察但材料不完整，或动态状态尚未验证；低：判断依赖上下文、推断或未确认规则。不按材料类型统一封顶：截图可以高置信地证明裁切，却不能证明真实点击或键盘操作。结构或运行材料能提高结构与状态判断的可靠性，但不提高因果置信度。

**规则依据有优先级。** 用户确认的规则、正式上游规则、知识库原始条目、明确的项目规则依次优先，其次才是本轮材料；推断和未知只能形成待确认风险。前四类才能支撑确定性的业务判断。项目正式规范优先于通用启发式；多份规范冲突时，按硬约束、当前项目正式版本、业务域正式规范、公司通用准则、通用启发的顺序评估，同时核对适用产品、端、角色、状态与版本；无法裁决时提出规则冲突待确认，不得判定“违反规范”。

**材料能力决定能说什么。** 截图只支持静态可见判断（布局、层级、文案、遮挡、裁切、可见对比风险、触控目标线索）；原型与流程只支持路径、分支与设计预期；前端代码只支持代码中可证明的结构、语义、状态与设计令牌线索，不等于最终界面；DOM 与可访问性树支持语义、名称与状态线索，不支持视觉层级和真实辅助技术表现；运行材料支持交互后的状态变化、反馈与错误线索，不支持发生率和满意度。源码与运行证据冲突时，用运行证据描述现状，把源码差异留作实现线索。不得声称运行过浏览器、设计工具、自动化审计或辅助技术，除非本轮工具真实执行且结果已经登记。

**视觉与可访问性只到线索层。** 没有真实注意力模型、眼动设备或注意力数据时，不得使用“模拟注意力”“热力图”“眼动”等表述；没有可靠颜色值时不输出精确对比度；只有实际运行键盘、屏幕阅读器或辅助技术测试，才能描述对应表现。固定导航数量、屏数、响应时间、触控尺寸等阈值，只有适用规范明确引用时才能决定严重度，否则只作为人工复核提示。需要完整 WCAG/ADA/EAA 或法律合规结论时，提出可访问性专项复核，本 Skill 不下结论。

**Finding 去重。** 用稳定标识识别同一问题：由产品范围、页面或流程、任务节点、位置、状态、主分类与风险类型构成，不依赖整段自然语言。同一位置、同一风险被多个透镜命中时合并；同一风险出现在不同页面、流程或关键状态时可以分开；无法可靠判断时不强行合并，记录候选关联。

**证据升级是道窄门。** 一条 Finding 要成为可用的启发式证据，必须同时满足：至少一个已实际读取且具备相应观察能力的来源；页面、流程、位置与状态可定位；观察与风险假设已分开；规则依据、置信度、隐私与用途边界明确；不依赖未确认规则形成确定结论；没有阻断性的补证请求。一条 Finding 最多对应一条证据，未通过就写清原因。启发式证据固定是弱证据：不能当作强证据使用，必须人工复核，不能支持因果主张。

**先补证，再谈结论。** 补证事项要写清缺哪类验证、具体需要补什么材料、为什么需要、以及是否阻断证据升级。常见类型：补充界面材料、人工走查复核、业务规则确认、客观行为确认、主观反馈确认、可访问性专项复核、真机或浏览器验证、规则冲突确认、隐私复核。阻断性补证未解决前，不得把该发现升级为证据。

**回检只描述变化。** 改版前后回检必须有明确的前后材料引用和可比范围，只写：哪些风险已消失、哪些仍存在、哪些新增、可比条目的严重度变化、范围是否可比。回检不产生证据，不进入效果验证，不声明方案有效；风险减少不等于方案有效，风险增加也不等于方案失败。

**上游结论只当范围提示。** 行为数据、主观反馈、既有根因或价值结论可以帮助判断该看哪里，但不能支撑 Finding、不能提高置信度，也不能当作风险成立的证据。引用上游材料时，隐私与用途限制原样继承，不得自行放宽。

## 正式证据与交接

在「可升级证据与补证事项」区分已明确晋升的证据、一般风险发现和补证请求。正式证据记录稳定编号、界面材料位置、复现条件、观察边界、置信度与允许用途。证据治理只把已晋升条目作为正式证据消费。

## 输出（Markdown）

正式产物为 `spark-output/experience-heuristic-analysis.md`。在正文记录本轮任务、范围或时间窗、输入来源和产物身份。消费上游时读取本轮明确关联的完整 Markdown，核对所属项目或需求、分析范围、来源、可用结论及限制。同一路径的旧产物只有在本轮明确关联时才可采用。需要放行或审核的内容，以报告中可定位的条目及明确授权为准。

做分析就必须交付一份 Markdown 文档，这是本 Skill 唯一的正式产物；不生成任何机器格式的中间数据文件，也不把受限原文、截图或未脱敏文本写进报告。报告用中文、短段落和列表书写，面向设计与产品读者可读；内部标识与追溯信息只在需要定位时少量出现，不堆砌成参数清单。

报告固定包含以下章节，顺序不变，编号即标题：

```markdown
## 1. 走查范围与材料能力
## 2. 检查覆盖与未覆盖说明
## 3. 体验风险发现（Findings）
## 4. 可升级证据与补证事项
## 5. 改版前后风险变化
## 6. 隐私与使用边界
## 7. 局限与待确认
```

- 第 1 章先用一小段说明本轮有直接证据的关键发现、对任务的影响或风险及其依据，引用对应 Finding 编号，并指出会改变判断的待复核项。只有材料缺口时先说明缺口。随后写清检查对象、材料形态、材料能证明到哪一步和未检查的范围。
- 第 2 章按十个检查域说明覆盖状态，未覆盖或不可评估的必须给出原因。
- 第 3 章逐条展开 Findings：位置与状态、可观察事实、风险假设、设计关注点、主分类、严重度、观察可靠性、规则依据；同一问题只出现一次。
- 第 4 章只写哪些发现可以升级为启发式证据、哪些没有升级及原因、还缺哪类补证、补证是否阻断。
- 第 5 章只在改版前后回检时填写实质内容；非回检时保留章节并写明“本轮不适用”。
- 第 6 章写受限与待确认项、脱敏处理、可披露范围、允许用于哪些用途、禁止用于哪些用途、哪里必须人工复核。
- 第 7 章写材料限制、未裁决的规则冲突、需要人工确认的问题和不可评估项。

报告纪律：章节不得删减；不得出现整体评分、百分比或通过/不通过的结论；报告只能复述分析中已经确认的内容，不得在写作阶段新增结论；受限内容只留“受限，需复核”的提示；同一条 Finding 不在多个章节重复计数。

## 自检

交付前逐项检查，能改的直接改，不能改的降级、阻断证据升级或写成补证事项：

- 输入是否全部来自本轮正式输入，有没有偷偷扫描工作区，或声称看过未实际取得的材料。
- 范围与覆盖是否一致：全量覆盖十类，限定只覆盖点名范围，差异只覆盖变化影响面。
- 来源能力声明是否与实际取得一致，局部状态有没有被当成完整页面，截图、代码、DOM 有没有被当成运行证据使用。
- 每条 Finding 是否单一主分类、已去重、可定位、观察与假设分开，措辞里有没有“一定”“必然”“已验证”。
- 严重度是否只表达设计风险，有没有被写成发生率、影响人数、业务价值或优先级。
- 证据升级的门槛是否逐条满足，未升级的有没有写清原因，升级的是否都标为弱证据、需人工复核、不支持因果。
- 隐私状态是否逐条判定，受限内容是否只在报告里留下受限提示。
- 规则冲突、未确认规则与阻断性补证，是否确实阻止了确定性结论。
- 回检是否只描述变化，有没有写成方案有效的结论。
- 报告章节是否齐全，是否没有新增结论、没有评分或通过/不通过判断，也没有泄露受限原文。

## 交付与下一步

正式报告写入并通过自检后，若包含可交接给证据治理的正式证据，在会话交付结尾提示：「可以说『用证据治理核对本次报告的证据，并明确哪些可以给下游使用』。」用户明确选择后再调用 `evidence-govern`。该提示不写入正式报告。

正式报告写入并通过自检后，若有适合且获准展示的结果，在会话交付结尾给一句可选提示。按本轮结果调整说法，例如「用数据可视化整理本次可展示的体验风险和走查覆盖情况」。提示仅出现在会话中，用户明确提出后再调用 `data-visualization`。
