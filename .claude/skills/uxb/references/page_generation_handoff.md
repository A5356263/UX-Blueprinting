# 页面事实最小提取

只在 `uxb_output.md` 与 `uxb.json` 完成、校验通过且核心定案冻结后执行。本步骤只使用本轮正式需求，不读取 UXB 产物，不重新分析需求。

## 事实白名单

只摘录需求中明确写出的页面生成事实：

- 页面、Tab、区域、模块、弹窗、抽屉及明确层级。
- 字段、选项、操作、按钮、控件类型、入口位置和固定文案。
- 展示条件、角色可见性、默认值、必填、上下限、格式、枚举和校验顺序。
- 会直接改变页面显示或用户下一步的状态、空态、异常反馈、失败恢复和审批结果展示。
- 会改变内容、版本、审批、发布、替换、删除的明确用户动作及确认载体。

禁止写业务背景、价值判断、体验方案、算法机制、后台实现和 UXB 分析结论。不得根据上下文推导原文没有的页面、因果、失败机制或否定结论。

## 事实与路由

每条事实必须有稳定 ID，并能直接指向正式需求中的原句、标题或表格单元。事实 ID 按 `HF-001` 递增。

等级：

- `P0`：页面、Tab、模块、弹窗、抽屉、按钮、字段、状态、权限或文案等页面生成必须核对的事实。
- `P1`：会改变用户任务、旅程步骤、状态流转、风险动作或恢复路径的事实。
- 两者不互斥；同时满足时标为 `P0+P1`，`page-spec` 索引必须包含所有带 `P0` 的事实。

候选消费者只按以下固定映射标注，不判断下游是否遗漏：

- `stories`：明确用户目标、关键动作、可观察结果、角色任务差异或验收条件。
- `journey-analysis`：步骤流转、权限分支、等待、失败、撤销、回退、恢复或风险动作。
- `experience-blueprint`：页面载体、交互入口、关键动作、状态反馈、异常恢复或权限显示差异。
- `page-spec`：全部 `P0` 事实。

## 输出结构

输出到 `spark-output/context/page-generation-handoff.md`，只生成 Markdown，不生成 JSON：

```markdown
# 页面事实补充

- 项目名：{project_name}
- 需求来源：{本轮正式需求名称}

## 0. 消费索引
- stories：{HF ID；没有则写“无”}
- journey-analysis：{HF ID；没有则写“无”}
- experience-blueprint：{HF ID；没有则写“无”}
- page-spec：{全部 P0 的 HF ID；没有则写“无”}

## 1. 事实项

### HF-001
- 等级：{P0｜P1｜P0+P1}
- 类型：{页面载体｜模块结构｜关键动作｜状态反馈｜权限显示｜字段文案}
- 事实：{保持原意的一句话事实}
- 来源：{需求文档名 + 章节、标题或表格位置}
- 候选消费者：{消费者列表}
```

索引只列 ID，不复制事实正文。没有白名单事实时仍输出文件头和四个“无”，不得为了填充而推导。
