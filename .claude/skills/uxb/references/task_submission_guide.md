# 任务摘要说明

这份说明只负责：

**分析总结收敛之后，怎么整理主链路前任务摘要，并进入条件确认。**

## 顺序

当前固定顺序是：

```text
Step 2
→ 分析总结收敛
→ 主链路前任务摘要
→ 条件确认
```

任务摘要不是 `Step 2` 的直接下一步之前的旧式跳板。
它前面必须先有分析总结收敛。

## 什么时候该写任务摘要

满足下面条件后，才整理主链路前任务摘要：

1. `Step 1` 已完成
2. `Step 2` 已完成
3. `Step 2` 后已经停下来交流
4. 已完成分析总结收敛

如果还没到这里，不要提前整理任务摘要。

## 任务摘要结构

默认只保留三段：

1. 判断
2. 建议怎么做
3. 仍需确认

不默认再单列“影响”，避免重复 `Step 2` 的风险分析。

## 用户侧表达

任务摘要必须用用户看得懂的话。

不要说：

- `facts`
- `route_decision`
- `run-routed-main`
- `gate / validate / coverage`

可以说：

- 我先把这次任务收成一句话
- 我建议怎么往下推进
- 还有哪些点最好先确认

## 条件确认

任务摘要后，必须进入条件确认节点。

默认 3 条路径是：

1. 进入正式蓝图任务
2. 先补充需要确认的
3. 探索更多的业务方案

这里默认使用编号选项。

## 启动门槛

只有用户明确选择：

- `1. 进入正式蓝图任务`

才表示正式进入主链路。

确认之前：

1. 不创建正式任务目录
2. 不写正式输入
3. 不写判断单
4. 不运行主链路

## 正式产物与知识库边界

正式任务产物进入：

- `projects/<project-id>/`

不要把正式任务产物自动写进 `knowledge/`。
