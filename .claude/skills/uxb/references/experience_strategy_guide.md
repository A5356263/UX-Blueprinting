## 1. 目的与边界

本文件帮助 UXB 从正式方案和体验证据中形成项目级体验策略。

它不执行任务生命周期扫描，不输出页面方案，也不把每个局部交互问题提升为策略。

策略要解决的是一组任务、角色或阶段共同面对的体验关系，或一个核心任务长期使用方式的改变。

## 2. 策略依据

策略依据来自：

1. 正式主输入中的问题、目标、用户、解决方向、范围和限制。
2. Stories 中的任务、目标、完成结果、设计触点和风险。
3. Journey 中的阶段、触点、痛点、信心低点、转折和流失风险。
4. 实际读取且改变判断的业务知识、设计准则和策略级模式。

正式主输入是业务事实来源。Stories 和 Journey 是体验证据。知识库只校准已有事实下的策略选择。

## 3. 体验矛盾识别

以下主题可用于识别体验矛盾。它们不是固定输出清单；只处理当前输入已有证据的主题。

### 3.1 任务发现与继续

关注用户如何发现能力、开始任务，或在原任务受阻后继续处理。

当稳定入口、情境触发、阻断说明和继续路径共同影响多个任务，或影响一个核心任务的完成方式时，可以形成入口与恢复策略。

### 3.2 学习与心智建立

关注新能力、规则变化或复杂概念如何被首次理解，并在后续使用中减少负担。

当用户需要先理解新的业务方式、模型或责任关系，才可能正确完成后续任务时，可以形成渐进理解、引导或变化感知策略。

### 3.3 信息与规则理解

关注复杂规则、数据关系、来源和影响范围如何转成用户可判断的信息层级。

当同类规则反复影响多个任务，或核心任务需要依赖规则理解才能完成时，可以形成信息架构或业务语言转译策略。

### 3.4 状态、责任与任务连续

关注状态、结果、进度、责任和对象在阶段、角色或系统变化后是否仍可理解。

当交接、等待、返回、异常恢复或跨系统处理会让用户失去上下文时，可以形成状态透明、上下文连续或责任可见策略。

### 3.5 风险、效率与持续使用

关注高风险决定、不可逆影响、高频重复成本和规则变化后的稳定使用方式。

当用户需要在决定前理解影响，或长期重复任务需要统一效率方向时，可以形成风险认知或效率策略。

## 4. 策略层与交互方案层

以下内容属于策略层：

- 建立首次理解到熟练使用的渐进关系。
- 同时提供稳定入口和任务内继续路径。
- 让跨角色流转持续保留对象、进度和责任信息。
- 让高风险决定在行动前获得影响认知。

以下内容属于 Experience Blueprint：

- 入口放在什么页面或区域。
- 使用页面、弹窗、抽屉、步骤条还是其他容器。
- 选择什么控件、字段和按钮。
- 具体信息布局、跳转和最终文案。

单个页面、字段、控件、一次反馈或局部流程的选择不提升为策略。单个核心任务跨越多个体验阶段，或会改变学习、信任、风险认知和长期使用方式时，可以形成策略。

## 5. 策略形成方法

对每个已确认的体验矛盾，依次写清：

1. 矛盾：用户需要什么，当前方案或证据显示什么阻碍。
2. 主张：本项目采用的体验方向。
3. 适用范围：角色、任务或阶段。
4. 预期结果：用户获得的理解、连续性、效率或信心。
5. 方案承接结果：后续交互方案必须实现的体验结果。

策略使用明确动作和结果。以下表述不能单独成立：

- 清晰展示。
- 体验友好。
- 及时反馈。
- 合理引导。

存在真实取舍时，只在内部比较两个方向。取舍会改变项目级体验结果时再比较；比较后形成一个明确策略。

## 6. 设计标准与策略边界

每条策略形成至少一个可观察设计标准。标准描述用户在任务中的可见结果，不虚构数值指标。

示例：

- 用户在跨角色交接后能识别当前对象、状态和下一责任方。
- 首次使用者获得必要解释，熟练使用者可以直接继续任务。
- 用户在高风险动作前能理解影响范围和不可恢复结果。

策略边界说明两类内容：

- 本策略适用的角色、任务或阶段。
- 留给 Experience Blueprint 决定的页面、容器、控件和文案细节。

## 7. 依据与置信度

每条策略记录真实来源及置信度：

- `high`：策略主张由正式主输入直接明确，或已获用户明确确认。
- `medium`：正式主输入与 Stories、Journey 或设计知识共同支持，推导链可追溯且没有冲突。
- `low`：策略主要来自设计推导，正式主输入只提供问题背景。进入正式 Markdown 前需要用户逐条确认。

置信度描述依据强度，不代替用户确认，也不改变正式主输入中的业务事实。

## 8. 通用正反例

正例：

```text
策略主张：建立“首次理解—首次完成—后续熟练使用”的渐进关系。
解决的矛盾：用户需要理解新的任务方式，长期使用又不应持续承受说明负担。
方案承接结果：首次使用获得必要解释，熟练用户可以直接完成任务。
```

反例：

```text
在右侧抽屉顶部放置三步引导和蓝色主按钮。
```

反例指定了容器、布局和控件，属于 Experience Blueprint。
