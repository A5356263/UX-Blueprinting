# 用户侧表达说明

这份说明只负责一件事：

**把 UXB 面向用户时的默认表达固定下来。**

## 总规则

1. 先给结论，再展开
2. 用大白话，不用内部词
3. 每一步都先独立说清楚，再停下来
4. 分叉场景优先用编号选项
5. 不把分析过程写成小蓝图

不要把内部工程词直接扔给用户，例如旧主线里的中间产物名、校验名、模式名或脚本名。

## Step 1 默认结构

`Step 1` 固定是：

**问题定性 + 问题聚焦**

默认展示结构：

```md
## 先做一轮初始判断

这次更像是：[一句话，说清是问题还是方案]

### 先把问题聚焦

### 1. 谁有这个问题？
- [一两句]

### 2. 现在怎么解决？
- [一两句]

### 3. 为什么重要？
- [一两句]

### 4. 什么算成功？
- [一两句]

### 5. 有什么约束？
- [一两句]

### 我的判断

[一两句总判断]

1. [关键要点]
2. [关键要点]
3. [关键要点]
```

输出规则：

1. 一问一两句
2. 没信息就直接写“文档未提及，需要补充”
3. 不搬运文档原文
4. 不先评价文档完整度
5. “我的判断”先收总判断，再拆关键要点

## Step 1 结束引导语

`Step 1` 结束后必须停下来。

```md
你现在可以选：

1. 继续体验问题诊断（推荐，理由一句话）
2. 先纠正我的判断
3. 探索更多的业务方案
```

推荐规则：

- 默认推荐路径 1
- 如果当前方向不一定最合适，或可能有更轻、更顺的方案，推荐路径 3
- 推荐理由写在推荐项后面的括号里，不单独成段

## Step 1 纠正判断时的处理

如果用户选择路径 2：

1. 局部更新，不全量重来
2. 如果纠正导致需求性质完全改变，再全量重来
3. 先说明“你的纠正影响了哪些部分”，再重写受影响内容

## Step 2 默认结构

`Step 2` 固定是：

**本次判断 + 关键体验诊断 + 后续必须解决的问题与策略边界**

默认展示结构：

```md
## 我继续往下看这件事真正卡在哪里

### 本次判断

[一小段大白话，说清这次复杂在哪里、会造成什么体验压力、因此本轮重点分析什么]

### 关键体验诊断

1. [关键角色要完成什么任务，以及任务在哪里断]
2. [为什么这会成为体验问题]
3. [当前最需要解决的断点是什么]

### 后续必须解决的问题与策略边界

1. [后续方案必须解决什么]
2. [哪些方向可以判断，哪些边界不能提前定死]
3. [已明确的业务前提]

### 需要确认

- [只有当不同答案会改变核心判断或策略方向时才出现]
```

要求：

1. 复杂度、需求类型、体验压力维度、5 Why 首先是内部分析工具，不默认逐条展示给用户
2. 并列断点、边界和必须解决的问题优先编号拆开
3. 一个编号只表达一个主要判断
4. 没有必须确认项时，整个“需要确认”区域省略

## Step 2 结束引导语

`Step 2` 结束后也必须停下来。

```md
你现在可以选：

1. 收敛结论，生成需求定案（推荐）
2. 先补充关键前提
3. 探索更多业务方案
```

要求：

1. `Step 2` 后不能直接写正式文档
2. 必须先停下来
3. 默认推荐 1
4. 如果待确认项会影响主方案成立，推荐 2
5. 如果当前方案可能过重、治标不治本或路径不唯一，推荐 3

## 基于补充信息更新判断

当用户在 `Step 2` 中途补充或纠正信息后，不重播完整 `Step 2`，默认只更新变化点：

```md
### 基于补充信息更新判断

你补充的信息是：

- ...
- ...

这会改变以下判断：

1. ...
2. ...

已关闭的 GAP：

- ...

更新后的剩余 GAP：

- ...
```

## 分析结论收敛默认结构

`Step 2` 后的下一步固定是分析总结收敛。

```md
## 分析结论收敛

### 已明确
- ...

### 必须解决
- ...

### 未定项
- ...

### 下一步

你可以直接选下一步：

1. 生成需求定案文档
2. 先补充需要确认的前提
3. 探索更多业务方案
```

要求：

1. “已明确”只写经过分析后可以确定的判断
2. “必须解决”只写阻断主方案的问题
3. “未定项”只写仍待确认、但不一定阻断主方案的问题
4. “下一步”必须给用户可选路径
5. 这一步还不是正式需求定案文档
6. 不直接对用户说内部文件词
7. 不使用“这次任务我先帮你收成一句话”“一句话总结”“一句话结论”这类标题

## 条件确认节点默认结构

分析结论收敛之后，固定进入条件确认节点。

```md
你可以直接选下一步：
1. 生成需求定案文档
2. 先补充需要确认的
3. 探索更多的业务方案
```

补充说明默认写成：

```md
如果你选 1，我就把前面的分析收成正式需求定案文档，并给体验蓝图准备好结构化上下文。
```
