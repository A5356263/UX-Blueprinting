# UXB 用户确认表达

## 1. 目的

UXB 只保留一次设计师主确认。用户侧先看到体验定案草案，确认后才生成正式产物。

## 2. 草案结构

```markdown
# 体验定案草案

## 核心判断

{一段明确结论}

## 体验目标与优先级

- {目标与优先关系}

## 信息与流程方向

- {信息架构方向}
- {流程编排方向}

## 关键解释与反馈策略

- {关键节点解释策略}
- {状态反馈与连续性策略}

## 体验取舍

- {已选方向、未选方向和理由}

## 体验蓝图承接要求

- {蓝图必须落实的策略约束}
```

只展示本次有决策价值的内容。不复制需求基线。

## 3. 确认语

草案后固定输出：

```text
请确认这版体验方向：

1. 确认并生成正式体验定案
2. 调整部分体验判断
```

不得增加“补业务前提”“探索业务方案”等旧路径。

## 4. 用户确认

以下表达可视为明确确认：

- 确认。
- 接受。
- 按这版生成。
- 选择 1。

只要用户同时提出修改，就先吸收修改，不视为确认。

## 5. 用户调整

用户提出调整时：

1. 说明受影响的体验结论。
2. 只更新相关部分。
3. 保持其他已接受结论不变。
4. 重新展示完整草案。
5. 再次等待明确确认。

不重做 PRD Review，不新增业务事实，不把体验调整写回需求基线。

## 6. 业务问题回流

如果用户指出需求基线存在业务错误、规则冲突或未闭环：

- 说明该问题属于需求基线。
- 停止正式 UXB 生成。
- 建议重新执行 PRD Review。
- 不在 UXB 内代替产品关闭问题。

## 7. 表达规则

- 先结论，后理由。
- 使用短句。
- 标题不跳级。
- 并列内容使用无序列表。
- 不输出内部状态名、评分或完整推理过程。
- 不输出页面、组件、布局和最终文案。
