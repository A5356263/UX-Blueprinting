# Knowledge Candidate Guide

当用户纠正知识、确认诊断结论可复用、或要求把某条内容沉淀为后续稳定知识时，用这个 guide。

## 定位

知识候选区是正式知识库之前的缓冲层。

它的作用是：

- 先把值得沉淀的内容整理出来
- 让用户确认内容是不是稳定知识
- 给后续正式入库留痕

它不是：

- 正式 knowledge
- UXB 主链路产物
- `packages/` 的输入
- `projects/<project-id>/` 的正式交付件

## 目录结构

仓库根目录下统一使用：

```text
知识候选区/
├── 知识问答/
├── 诊断咨询/
└── 新需求文档/
```

规则：

1. 根目录没有 `知识候选区/` 时，可以按需创建。
2. 子目录不存在时，可以按需创建。
3. 每条候选知识单独一个 Markdown 文件。
4. 一个文件只记录一条候选知识。

## 文件命名

推荐格式：

```text
YYYY-MM-DD_HHMM_业务域_简短主题.md
```

示例：

```text
2026-05-07_2130_权限管理_权限配置前置企业认证.md
```

如果业务域不明确，可以用：

```text
YYYY-MM-DD_HHMM_待归类_候选主题.md
```

## 候选状态

候选状态只使用下面五种：

- `待确认`
- `已确认待入库`
- `已入库`
- `暂缓`
- `已拒绝`

含义如下：

- `待确认`：AI 认为可能有沉淀价值，但用户还没确认。
- `已确认待入库`：用户确认可以作为稳定知识，等待写入正式 knowledge。
- `已入库`：已写入 `knowledge/raw/**` 或 `knowledge/raw/inbox/**`，并刷新 wiki。
- `暂缓`：先保留，不当成稳定知识。
- `已拒绝`：用户明确不需要沉淀。

## 模板

默认使用：

```text
.codex/skills/uxb/assets/knowledge_candidate.template.md
```

要求：

- 不复制完整聊天原文
- 写成可复用、可判断的语义化知识
- 标清影响范围和不确定点
- 保留用户确认记录和入库处理记录

## 什么时候创建候选

不要过度沉淀。

只有满足下面任一条件时才创建候选文件：

1. 用户明确说“记录 / 记一下 / 更新知识库 / 写入知识库”。
2. 用户纠正了知识，AI 询问是否记录，用户同意。
3. 诊断咨询出现稳定结论，AI 建议沉淀，用户同意。
4. 新需求蓝图完成后，AI 提取候选，用户同意。
5. 用户明确要求把某条内容沉淀为后续可复用知识。

不要因为 AI 自己觉得有价值，就擅自创建大量候选文件。

## 不同场景下怎么触发

### 知识问答

默认不创建候选。

如果用户纠错，先修正当前回答，再自然询问是否记录到知识候选区。

推荐话术：

```text
我先按这个纠正修正当前答案。这条看起来像稳定规则，要不要我先记到知识候选区，状态标成待确认？
```

### 诊断咨询

诊断过程中不要频繁创建候选。

当阶段性结论已经比较稳时，可以轻提示：

```text
这条判断后续可能会复用。需要的话，我可以先记到知识候选区，不直接入库。
```

### 新需求文档

蓝图完成后，如果里面有已确认规则、流程依赖、体验原则可复用，可以提议先提取到 `知识候选区/新需求文档/`。

不要把整份蓝图直接入库。

### 直接知识维护

如果用户直接说“更新知识库”，先整理候选，再让用户确认，不要直接写 `knowledge/`。

## 正式入库规则

知识候选区只是缓冲区。正式入库必须同时满足：

1. 用户确认该候选可以作为稳定知识。
2. 候选内容已经语义化整理，不是聊天原文。
3. 已经给出建议写入位置。
4. 不确定点已处理，或明确保留待确认标记。
5. 入库后运行 knowledge 子系统更新逻辑。

## 建议入库位置

如果业务域明确：

```text
knowledge/raw/business/<domain>/
```

如果更像体验指南：

```text
knowledge/raw/guidelines/
```

如果暂时无法归类：

```text
knowledge/raw/inbox/
```

## 入库后动作

通常执行：

```bash
python knowledge/scripts/update_wiki.py --apply
```

如果只更新单个 raw：

```bash
python knowledge/scripts/update_wiki.py --apply --only <raw-file-path>
```

入库处理结果需要回写到候选文件。

## 不允许行为

不要这样做：

- 不经确认直接写 knowledge
- 把聊天原文整段写进候选文件
- 把候选当正式知识直接引用
- 因为“看起来有价值”就批量造候选
- 把候选区接进 `packages/` 主链路
