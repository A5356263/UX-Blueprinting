# 知识沉淀后置说明

这份说明只负责一件事：

**明确 UXB 不再承担知识候选交接动作，相关沉淀统一后置给 `knowledge-wiki`。**

## UXB 在这里的职责

UXB 只负责：

- 完成需求分析与定案
- 产出正式业务结果
- 让正式产物成为后续知识扫描的输入来源

UXB 不负责：

- 直接创建候选文件
- 套用候选模板
- 写入 `knowledge/candidates/`
- 判断入库落点
- 更新 raw
- 刷新 wiki
- 在交接话术里主动提示“去生成知识候选”

## 当前后置规则

与 `UXB` 相关的知识沉淀不再走“分析结束后立即交接”的旧模式。

改为：

1. `UXB` 正常完成自身分析与定案
2. 正式产物写入 `spark-output/`
3. 当用户明确触发知识沉淀相关任务时，由 `knowledge-wiki` 扫描正式产物
4. `knowledge-wiki` 自己判断是新增、覆盖、重复，还是无需入库

## knowledge-wiki 在这里接管什么

`knowledge-wiki` 接管的是：

- 扫描 `UXB` 正式产物
- 判断是否值得生成知识候选
- 生成候选或给出不入库结论
- 必要时进入正式知识入库或覆盖更新

## 这次没有改变什么

这次只移除了“UXB 主动交接知识候选”的职责。

没有移除 `knowledge-wiki` 原本已经存在的能力，包括：

- 知识问答
- 手动放入材料后的处理
- 手动生成候选
- 正式知识入库
- 覆盖更新

## 禁止事项

- 不要在 UXB 内直接落候选文件
- 不要继续维护候选目录结构规则
- 不要继续把 UXB 当成知识入库入口
- 不要在 UXB 完成时主动追加知识候选提示
