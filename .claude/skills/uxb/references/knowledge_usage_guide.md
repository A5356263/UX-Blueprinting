## 1. 目的与边界

知识用于校准体验策略。它不补全正式业务事实，也不替代正式主输入。

- 正式主输入决定本轮问题、目标、范围和解决方向。
- 业务知识解释已涉及的既有机制、状态、责任、系统边界和领域术语。
- 设计知识帮助选择项目级体验策略。
- 页面、容器、组件和控件模式由 Experience Blueprint 消费。

## 2. 消费顺序

按以下顺序使用知识：

```text
正式主输入与体验证据
→ 已确认的体验矛盾
→ 缺少的业务语境或设计依据
→ 必要知识规则块
→ 体验策略与设计标准
→ 实际使用来源记录
```

没有具体体验矛盾时，不读取设计知识。正式输入已完整解释当前业务语境时，不读取业务知识。

## 3. 正式知识源

只从 `.claude/skills/knowledge-wiki/knowledge/` 读取正式知识。

先通过正式索引和领域路由定位主题，再读取支持当前策略判断的完整规则块。来源名称和路径必须真实。

不把索引、README、目录名、检索词或单句命中直接写成策略依据。

## 4. 业务知识

正式输入不能解释以下内容，且该内容会改变当前策略时，读取对应业务知识：

- 既有机制如何运作。
- 状态在系统中的含义。
- 角色责任和系统交接边界。
- 领域术语和对象关系。
- 当前需求与既有能力的新增、修改、移除或复用关系。

读取当前主题的必要完整规则块。主题涉及相互依赖文件时，读取这些文件；不遍历整个业务域。

正式输入明确新增、修改或移除既有能力时，以正式输入为本轮事实。知识冲突会改变策略时，停止受影响策略并报告冲突。

## 5. 设计知识

根据已确认的体验矛盾读取对应设计准则或策略级模式：

| 体验矛盾 | 优先读取方向 |
|---|---|
| 任务发现、受阻继续 | 可发现性、情境触发、阻断恢复、上下文承接 |
| 新能力理解或规则变化 | 首次认知、渐进引导、变化感知 |
| 复杂规则与信息理解 | 信息架构、渐进披露、认知负担、可解释性 |
| 状态、交接或跨系统连续 | 状态透明、任务连续、责任可见、同步反馈 |
| 高风险或重复成本 | 风险认知、影响预览、操作效率、错误控制 |

未找到直接模式时，使用相关通用设计准则继续。设计知识无法支持业务选择时，不替代正式输入决定业务方向。

## 6. 来源记录与停止

只记录实际改变、限制或校准策略的来源。每项来源需说明：

- 对应策略或设计标准。
- 来源类型和真实名称。
- 对策略选择的作用。

出现以下情况时停止读取：

- 当前策略已能解释对象、边界、责任和体验关系。
- 新知识不再改变策略或设计标准。
- 后续内容转入当前策略之外的业务域或页面细节。

找不到业务知识但正式输入已足够时，继续形成策略。找不到直接设计模式时，使用通用准则，不虚构来源。
