# 业务知识入库模板

## 这是什么

这里存放知识入库模板，只作为 AI 规划和编写 `knowledge/raw/**` 的轻量骨架参考。

这些模板不属于正式知识，不进入 `wiki/index`，不生成 summary，也不直接参与主链路消费。

## 它和 `README.template.md` 的区别

- `README.md`：说明模板目录本身如何使用
- `README.template.md`：用于生成新业务领域的 `knowledge/raw/yewu/<domain-pinyin>/README.md`

不要把本文件内容直接复制到业务领域目录中。

## 使用原则

1. 先判断新材料应并入现有领域，还是需要新建领域。
2. 先读取目标领域 README、相邻领域示例，再参考这里的模板。
3. 先输出入库计划，确认后再落地 raw。
4. 有内容才建文件，不为编号完整批量造文件。
5. 没有对应模板，不代表不能创建该编号文件。
6. 有对应模板，也不代表必须创建该编号文件。
7. 模板只提供结构，不预填具体业务语义。

## 通用编号段

- `00-09`：领域定义层，用于领域概述、范围边界、术语、对象与关系
- `10-19`：业务承载层，用于能力、场景、入口路径、状态流程、页面字段、边界限制
- `20-29`：规则判断层，用于规则、来源、冲突、约束、状态、生效与审计
- `30-39`：体验解释层，用于体验风险、解释策略、体验翻译与文案线索
- `50-59`：FAQ / 外部口径 / 异常排障层，用于常见问题、帮助文档差异、外部口径、异常排障

## 不强制建满

编号体系用于帮助 AI 和维护者判断落点，不代表每个领域都必须拥有全部文件。

如果某个领域信息较少，可以只保留：

- `README.md`
- `00_领域概述.md`
- 少量真正有内容的编号文件

如果信息还不稳定，应优先使用：

- `[GAP]`
- `[CONFLICT]`
- `[QUESTION]`

不要用空文件制造“完整感”。

## 禁止事项

- 不要把模板目录 README 当成业务领域 README
- 不要让模板进入 `knowledge/wiki/index.md`
- 不要为模板生成 summary
- 不要把主链路消费说明写进模板
