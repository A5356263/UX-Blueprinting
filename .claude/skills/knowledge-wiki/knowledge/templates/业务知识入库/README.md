# 业务知识入库模板

## 这是什么

这里保留当前项目业务知识的轻量骨架参考。它们只是本地示例，不是 `knowledge-wiki` 的通用入库标准。

这些模板不属于正式知识，不进入 `wiki/index`，也不直接参与主链路消费。

## 它和 `README.template.md` 的区别

- `README.md`：说明模板目录本身如何使用
- `README.template.md`：只在新知识集合或领域确实需要独立路由时参考

不要把本文件内容直接复制到业务领域目录中。

## 使用原则

1. 先判断知识集合、主域和现有落点，不从模板反推知识结构。
2. 先读取当前本地结构合同、index、命中的必要 README 或大文件导航，再参考这里的本地模板。
3. 先输出一次处理回执，确认后再落地 raw 或候选。
4. 有内容才建文件，不为编号完整批量造文件。
5. 没有对应模板，不代表不能创建该编号文件。
6. 有对应模板，也不代表必须创建该编号文件。
7. 模板只提供结构，不预填具体业务语义。
8. 大文件可继续保留；行数只触发快速导航检查，不自动触发拆分。
9. 单一大文件已有定位、场景路由和快速导航时，不额外建 README。

## 不强制建满

编号体系只用于当前项目中已经采用该约定的业务集合，不代表其他团队、业务集合或领域必须复制。

如果某个领域信息较少，可以只保留：

- `README.md`
- 少量真正有内容的编号文件

如果信息还不稳定，应优先使用：

- `[GAP]`
- `[CONFLICT]`
- `[QUESTION]`

不要用空文件制造“完整感”。

## 禁止事项

- 不要把模板目录 README 当成业务领域 README
- 不要让模板进入 `knowledge/wiki/index.md`
- 不要让模板进入正式消费目录
- 不要把主链路消费说明写进模板
- 不要因文件行数自动拆分
- 不要按目录强制创建 README
- 不要把当前业务编号和文件名当成通用入库标准
