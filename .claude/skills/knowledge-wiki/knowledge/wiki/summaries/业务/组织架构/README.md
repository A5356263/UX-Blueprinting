## 稳定结论
- 阅读顺序遵循四层结构：00（领域总览）→10/11（旧对象归位）→13/14（底座模型）→15（运行流转）
- 维护时优先记录平台组织底座中的稳定对象、关系、状态和迁移语义
- 旧组织能力进入新底座后，按"职能→视图"结构表达，不回到旧菜单语义
- 组织与成员必须分域表达，不把成员生命周期写成组织知识
- 涉及权限与业务消费时，只记录组织域作为上游输入的事实，不代写权限规则或业务规则
