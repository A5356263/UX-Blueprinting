## 定位
交互模式域的总入口路由卡。解决“已经判断清楚问题类型后，这类任务通常该怎么组织、用什么承载方式表达”的问题，作为设计准则之后的第二层读取入口。

## 触发信号
- 需要从上位原则继续落到任务组织方式时
- 需要在多个承载形式之间做体验层面的取舍时
- 需要为复杂页面补足反馈、引导和恢复路径的组织方法时

## 稳定结论
- `设计准则` 负责回答为什么这样判断，`交互模式` 负责回答这类任务通常怎么组织
- 读取顺序通常是先读准则、再读交互模式，不直接从组件形式反推体验目标
- 本域放模式和形式边界，不放业务规则、组件 API 和视觉样式规范
