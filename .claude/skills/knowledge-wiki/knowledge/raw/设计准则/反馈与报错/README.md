# 反馈与报错

## 这是什么

这是反馈与报错设计准则的二级路由入口，用于沉淀可跨业务复用的反馈与报错体验设计知识。

这里关注的是：用户在权限不足、校验失败、状态阻断、网络异常、外部系统失败等场景下，应该在什么位置看到什么形式的反馈，以及文案如何解释原因和下一步。

它不承载正式业务事实正文，也不承载主链路消费说明。

## 编号段

- `00`：反馈与报错体验设计指南（范围、边界、总体原则）
- `01`：反馈形式选择原则（位置、形式、时机）
- `02`：报错与状态文案模板（可复用文案与反例）
- `03`：通用报错场景案例（权限、状态、校验、网络等）
- `04`：人事与薪酬场景案例
- `05`：财税场景案例

## 任务触发索引

- 需要理解反馈与报错的总体原则和边界：读 `00_反馈与报错体验设计指南.md`
- 需要判断反馈位置、形式和时机：读 `01_反馈形式选择原则.md`
- 需要提取可复用文案和反例：读 `02_报错与状态文案模板.md`
- 需要查找通用报错场景（权限、状态、校验、网络等）：读 `03_通用报错场景案例.md`
- 需要人事薪酬语境下的反馈案例：读 `04_人事与薪酬场景案例.md`
- 需要财税语境下的反馈案例：读 `05_财税场景案例.md`

## 边界

- 放体验设计判断依据，不放实现细节
- 放反馈形式和文案原则，不放组件方案或前端规则清单
- 放可复用场景素材，不把业务事实判断替换掉
- 不负责定义报错治理系统、前后端实现方案或成效指标系统

## 维护原则

- README 只做领域内路由，不写正式设计准则正文
- 新增内容优先归入现有编号文件，不回退成单一长文
- 目录内只保留稳定知识，不写讨论过程、导入说明或候选状态
- 不在本目录中沉淀主链路消费地图、蓝图移交说明或下游执行指令
- 做结构替换时不保留兼容层，确认替换后直接移除旧知识位
