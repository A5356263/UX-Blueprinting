# 组织架构

## 这是什么

这是平台组织底座知识库的固定文件级路由入口，用来说明本领域承载什么知识、遇到什么问题该优先看哪些语义文件。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应语义文件中。


## 领域契约

### 领域定义

组织架构领域回答的是：
平台组织底座如何承载多维组织、职能、视图、组织范围生成，以及旧组织能力如何迁移到新底座。

它覆盖的不是单一组织树，而是一整套与平台组织底座相关的业务语义，包括：

- 多维组织：组织数据底座
- 职能：业务场景定义层
- 视图：职能下的维度承载层，一个职能下可建立多个视图
- 组织管辖范围：成员在特定职能/视图上下文中的可访问组织范围
- 多维组织组件：消费组织范围与职能语义的标准化组织控件

### 解决的问题

组织架构领域主要用于解释以下问题：

- 多维组织底座如何汇聚行政组织、法人公司等组织维度
- 职能与视图如何组织平台组织能力
- 组织数据如何参与成员挂载、组织范围生成、业务过滤与组件消费
- 菜单结构重构后，组织模块自身的领域边界是什么
- 旧组织能力如何迁移到新底座

### 为什么独立成域

组织架构需要独立沉淀，是因为它同时具备以下特征：

- 在平台组织重构后，组织域已从"静态企业结构主数据"升级为"平台组织底座"
- 组织底座是平台的基础设施，被成员、权限、业务消费等多个下游依赖
- 多维组织、职能、视图等概念构成一套完整的组织建模体系
- 组织与成员、权限有明确边界：组织负责组织底座，成员负责身份主体，权限负责授权规则

### 不覆盖

- 人事领域的组织管理（编制、岗位、职级、人事组织治理）— 保留在 `knowledge/raw/业务/人事服务/组织管理/`
- 成员加入、停用、退出等成员生命周期知识 — 保留在 `knowledge/raw/业务/成员管理/`
- 具体权限规则、审批规则、原因码合同 — 保留在对应领域

### 与下游领域的关系

- 成员通过挂载关系接入多维组织，但成员模块本身不并入组织域
- 权限域消费成员主体与组织范围结果，但授权规则仍归权限域管理
- 平台组织组件消费组织范围和职能语义

这里描述的是下游依赖事实，组织域作为平台底座为各下游提供组织数据。

### 稳定结论

- 组织架构是平台组织底座的承载域，已完成从"结构主数据"到"平台组织底座"的升级
- 原"组织架构"默认归位到行政职能/组织架构视图，原"法人公司"默认归位到核算职能/法人公司视图
- 其核心价值是为多维组织、职能、视图、组织范围生成和组件消费提供稳定输入
- 它可以服务业务分析、产品设计、体验解释和排障分析，但本文件本身不承载下游消费说明

### 显式缺口

- [QUESTION] 平台组织底座中新旧能力的迁移是否已全部完成，遗留映射是否已完全清晰
- [QUESTION] 组织范围生成的规则是否已完全稳定，与权限域的消费接口是否已明确
## 任务触发索引

- 需要理解组织域边界已经从"结构主数据"升级为"平台组织底座"：读本 README 的“领域契约”
- 需要理解组织、法律实体、成本中心、职能、视图、成员挂载或范围生成：读 `业务对象与术语.md`
- 需要理解初始化、发布、迁移、过滤、业务消费或菜单重构主流程：读 `任务与路径.md`

## 条件依赖与回主域

- 多维组织底座、职能、视图、成员挂载关系和组织范围生成以本域为主；成员生命周期补读成员管理，授权结果补读权限管理，编制、岗位、职级和人事组织治理补读人事服务/组织管理
- 读完依赖域后必须回到本域确认组织对象、视图、范围生成与迁移语义；依赖域不得替代组织底座事实

- 未命中条件依赖时不扩读相邻领域；README 未定位到正式知识时直接记录知识缺口。

## 维护边界

- README 只承载领域契约与领域内路由，不展开具体业务规则正文
- 正式业务事实写入对应语义文件
- 优先记录平台组织底座中的稳定对象、关系、状态和迁移语义
- 组织与成员必须分域表达，不把成员生命周期写成组织知识
- 涉及权限与业务消费时，只记录组织域作为上游输入的事实，不代写权限规则或业务规则
- 不在本目录中沉淀主链路消费地图、蓝图移交说明或下游执行指令
- 做结构替换时不保留兼容层，确认替换后直接移除旧知识位
