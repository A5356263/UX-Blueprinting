## 路由地图

### 文件定位

本文件用于说明权限域内页面之间，以及权限域与外部治理模块之间的主要路由关系。

### 1. 配置链路

- `用户授权 -> 功能授权 -> 数据授权`
- `用户授权 -> 权限详情`
- `角色管理 -> 授权规则`
- `角色管理 -> 功能权限 / 数据权限`
- `权限管理模式 -> 子管理配置页`
- `权限管理模式 -> 双管理员模式配置页`
- `权限管理模式 -> 权限变更审批模式配置页`
- `应用管理 -> 应用设置页`

### 2. 解释链路

- `用户授权 -> 权限详情`
- `权限查询 -> 按用户查询结果`
- `按用户查询结果 -> 权限明细`
- `权限详情 -> 应用管理`

### 3. 外部治理链路

- `权限变更审批模式配置页 -> 审批管理`
- `权限变更审批模式配置页 -> 协同办公审批列表`
- `应用设置页 -> 通用审批`
- `功能授权 -> 应用中心`

### 4. 路由说明

- `用户授权 -> 功能授权 -> 数据授权` 是按人配置的主链路
- `角色管理 -> 授权规则` 是角色模板化授权向自动授权扩展的链路
- `权限管理模式 -> 子管理配置页 / 双管理员模式配置页 / 权限变更审批模式配置页` 是系统级治理链路
- `权限查询 -> 按用户查询结果 -> 权限明细` 是解释与排障链路，不负责配置
- `应用管理 -> 应用设置页` 是应用级入口治理与单应用管理员治理链路

### 5. 当前缺口

## 查询与配置路径

> 权限域必须同时说明查询路径与配置路径；即使现状承载分散，也要显式写出当前承载、边界与缺口。

### 1. 查询路径

#### 1.1 按用户查

- 语义：查询某个用户当前有什么权限、来源是什么、为什么可用或不可用
- 现状承载：
  - `权限查询`：提供按用户的查询入口
  - `按用户查询结果`：按应用聚合展示查询结果
  - `权限详情`：补充只读明细解释
- 可行性：`feasible`

#### 1.2 按角色查

- 语义：查询某个角色拥有哪些成员、拥有哪些权限模板
- 现状承载：
  - `角色管理`：可查看角色成员与角色配置入口
- 可行性：`partial`
- 说明：当前页面事实明确了角色成员与配置入口，但未明确独立的“按角色查询页”

#### 1.3 按应用查

- 语义：查询某个应用当前对谁可见、谁是该应用管理员、该应用关联哪些后台配置入口
- 现状承载：
  - `应用管理`：查看应用级台账、可见范围、状态
  - `应用设置页`：查看单应用入口治理与单应用管理员
- 可行性：`feasible`

#### 1.4 按变更查

- 语义：查询权限增删改是否经过审批、何时生效、谁处理过
- 现状承载：
  - `权限变更审批模式配置页`：提供前往审批管理与审批记录的入口
  - `审批管理 / 协同办公审批列表`：承载审批记录查看
- 可行性：`partial`
- 说明：当前承载分散在权限域与审批域之间，权限域内未见统一变更台账页

#### 1.5 按权限查 / 按功能点查

- 语义：查询某个具体功能点、权限项由哪些人或角色持有
- 现状承载：`[GAP]`
- 可行性：`[GAP]`
- 说明：现有页面事实中只明确了“权限查询”支持按权限维度切换，但未核实对应结果承载页

### 2. 配置路径

#### 2.1 用户配置路径

- 路径：`用户授权 -> 功能授权 -> 数据授权`
- 说明：
  - `用户授权` 负责找人、批量操作、进入配置
  - `功能授权` 负责功能点勾选
  - `数据授权` 负责数据范围配置
  - `权限详情` 负责事后核对与解释

#### 2.2 角色配置路径

- 路径：`角色管理 -> 功能权限 / 数据权限 -> 授权规则`
- 说明：
  - `角色管理` 是角色模板化治理入口
  - 功能权限与数据权限用于构造角色能力包
  - `授权规则` 用于把角色与组织属性、岗位属性绑定

#### 2.3 治理配置路径

- 路径一：`权限管理模式 -> 子管理配置页`
- 路径二：`权限管理模式 -> 双管理员模式配置页`
- 路径三：`权限管理模式 -> 权限变更审批模式配置页 -> 审批管理`
- 说明：
  - 该类路径承载的是系统级治理规则
  - 不属于普通功能授权页的局部配置

#### 2.4 协作配置路径

- 路径：`成员协作权限`
- 说明：
  - 在单页内完成主规则、补充规则、适用应用的配置
  - 该路径管理的是人际可见性，不是后台管理授权

#### 2.5 应用配置路径

- 路径：`应用管理 -> 应用设置页`
- 说明：
  - `应用管理` 负责应用台账、启停、可见范围与状态治理
  - `应用设置页` 负责单应用入口治理、应用管理员治理与外部治理入口串联

### 3. 现状缺口
- [GAP] 按权限查 / 按功能点查现状承载待进一步核实
- [GAP] 按角色查虽有角色管理承载，但独立查询语义与结果视图仍未完全明确
- [GAP] 按变更查当前分散在权限域与审批域之间，权限域内缺少统一变更台账页

## 任务场景

### 文件定位

本文件从“任务场景 -> 页面 / 路径”的角度，说明权限域中的高频任务分别落在哪些页面与链路中。

### 1. 给单个用户开权限

- 任务目标：给指定用户开通应用、功能权限、数据权限
- 主要页面 / 路径：
  - `用户授权`：先检索并定位目标用户
  - `功能授权`：配置功能点
  - `数据授权`：配置数据范围
  - `权限详情`：核对最终结果
- 关键说明：这是按人配置的主路径，适合单体排查与单体治理；授权前通常需要先完成平台注册、加入企业等前置动作；授权对象可包括内部员工与外部人员；数据范围需先选“全部/部分/无”，仅在“部分”下进入条件组配置（组内交集、组间并集）

### 2. 批量给人授权 / 移除

- 任务目标：对一批用户进行批量角色关联、批量授权或批量移除
- 主要页面 / 路径：
  - `用户授权`：通过全局批量操作区发起批量动作
  - `角色/人员选择器`：完成批量对象选择
  - `权限详情`：[GAP] 现有事实只明确了详情查看入口，未说明批量结果核对页
- 关键说明：批量操作属于高风险治理动作，需要同步考虑审计与可回溯性；批量数据授权可通过“一键设置为全部数据权限”或批量设置提升效率

### 3. 查看某人为什么有 / 没有权限

- 任务目标：解释某个用户最终为什么能看、能做、不能做或未生效
- 主要页面 / 路径：
  - `权限查询`：选择按用户查询
  - `按用户查询结果`：查看按应用聚合的结果
  - `权限详情`：查看更细粒度的只读明细
- 关键说明：这是解释与排障链路，不承担配置职责

### 4. 用角色批量分发权限

- 任务目标：通过角色模板为多个人批量分发权限
- 主要页面 / 路径：
  - `角色管理`：创建或选中角色
  - `功能权限`：配置角色功能权限
  - `数据权限`：配置角色功能权限
  - `角色成员管理区`：添加成员到角色
- 关键说明：角色页承担模板化授权职责；如需修改角色授权，应回到角色管理页完成，不能在用户授权页把角色来源权限改成真源；角色数据范围同样遵循“范围类型 + 条件组”模型与最小约束（至少 1 组、组内至少 1 条件）

### 5. 配角色自动授权规则

- 任务目标：让角色随部门、职务、成员组等条件自动授予与回收
- 主要页面 / 路径：
  - `角色管理`：选中目标角色
  - `授权规则`：配置条件组与规则组
- 关键说明：规则组内取交集，规则组之间取并集

### 6. 开启子管理员分权

- 任务目标：给指定人员下放可管理的组织范围与可授权功能上限
- 主要页面 / 路径：
  - `权限管理模式`：启用子管理员模式
  - `子管理配置页`：配置子管理员、人、组织范围、功能上限
- 关键说明：这是配置“权限的权限”，不是直接配置业务权限；子管理员只能在其组织管辖范围内，对其应用管辖范围中的功能进行授权

### 7. 开启双管理员互审

- 任务目标：让高危权限操作进入互审链路
- 主要页面 / 路径：
  - `权限管理模式`：选择双管理员互审模式
  - `双管理员模式配置页`：配置互审搭档与互审范围
- 关键说明：该任务改变的是高危操作的生效机制；关闭双管理员模式本身也需要进入互审审批

### 8. 开启权限变更审批

- 任务目标：把权限变更纳入审批流治理
- 主要页面 / 路径：
  - `权限管理模式`：选择权限变更审批模式
  - `权限变更审批模式配置页`：进入模式说明与路由枢纽
  - `审批管理 / 通用审批`：配置审批流程
- 关键说明：该路径依赖外部审批中台，不在权限域内重复配置流程引擎；仅开启模式不等于审批闭环已经完成，仍需补齐“系统审批 -> 权限管理”的流程设计、发布与授权配置

### 9. 控成员之间可见性

- 任务目标：控制员工与外部协作对象之间的可见性边界
- 主要页面 / 路径：
  - `成员协作权限`：配置主规则、补充规则、适用应用
- 关键说明：这是协作可见性治理，不等于后台管理授权

### 10. 控应用入口与应用管理员

- 任务目标：控制应用在前台是否可见，以及谁能管理该应用后台
- 主要页面 / 路径：
  - `应用管理`：管理应用台账、可见范围、启停状态
  - `应用设置页`：配置单应用入口治理与单应用管理员
  - `功能权限 / 数据权限`：为应用管理员配置具体管理权限
- 关键说明：应用入口治理与后台管理权限治理需要分开理解；前台是否看见应用由应用可见范围决定，是否能使用和操作应用由功能权限决定，两者同时生效
