# 企业设置

## 这是什么

这是企业设置领域的二级路由入口，用来说明本领域承载什么知识、遇到什么问题该优先看哪些语义文件。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应语义文件中。


## 领域契约

### 领域定义

企业设置领域回答的是：
企业如何在薪福通平台中完成展示表达、品牌配置、个性化设置和消息管理。

企业设置为管理后台导航栏上的一级目录。一级目录本身无页面，仅承载以下三个二级目录（均有独立页面）：

- **个性化展示**：企业对外展示的品牌和个性化配置（含企业文化 6 项 + 企业信息展示 2 项）
- **定制方案**：企业功能与配置的定制化方案管理
- **消息设置**：企业消息通知的接收与管理设置

### 解决的问题

企业设置领域主要用于解释以下问题：

- 企业如何进行个性化品牌展示
- 企业如何管理定制化配置方案
- 企业如何设置和管理消息通知
- 企业配置如何影响员工的使用体验

### 为什么独立成域

企业设置需要独立沉淀，是因为它同时具备以下特征：

- 关注的是企业展示表达和配置管理，与企业内部治理（组织、成员、权限）是不同的关注点
- 配置结果直接影响所有员工的使用体验
- 与组织、成员、权限等治理域有明确边界：企业设置管展示和配置，治理域管规则

### 与上游领域的关系

- 个性化展示可能依赖组织架构域的企业基本信息
- 消息设置可能与协同办公域的消息能力存在交叉

这里描述的是上游依赖事实，不等于具体规则已经由其他领域定义完成。

### 稳定结论

- 企业设置是企业展示和配置管理的核心域，当前覆盖个性化展示、定制方案和消息设置三个子模块
- 个性化展示已录入：企业文化（6项配置）+ 企业信息展示（2项配置）
- 定制方案已录入：组装方案选择 + 行业特性选择 + 启用后详情态
- 消息设置已录入：消息渠道设置（4种渠道），业务消息设置和企业内部消息收发待补充

### 显式缺口

- [GAP] 组装方案中完整卡片列表未采集
- [QUESTION] 短信、微信公众号、邮件和 AI 电话语音的默认开关状态待确认
## 任务触发索引

- 需要理解企业设置域的边界与覆盖范围：读本 README 的“领域契约”
- 需要理解企业设置的稳定能力、覆盖范围和配置结果：读 `功能与操作清单.md`
- 需要理解开通条件、配置约束、可见范围或消息生效规则：读 `规则与权限.md`
- 需要理解具体页面、字段、配置项或既有交互规格：读 `页面与字段.md`
- 需要查询维护入口或开通问法：读 `问答与差异.md`

## 条件依赖与回主域

- 企业展示、品牌、定制方案和消息设置以本域为主；只有需要确认企业基本信息来源时补读组织架构，需要确认消息承载能力时补读协同办公
- 读完依赖域后必须回到本域确认企业配置项与展示结果；组织、成员和权限治理规则不在本域推断

## 维护原则

- README 只承载领域契约与领域内路由，不展开具体业务规则正文
- 正式业务事实写入对应语义文件
- 不在本目录中写组织、成员或权限治理规则
- 不在本目录中沉淀主链路消费地图、蓝图移交说明或下游执行指令
- 做结构替换时不保留兼容层，确认替换后直接移除旧知识位
