# 状态与异常

- 最近更新：2026-08-27

## 状态

### 薪资组状态

| 状态 | 含义 |
|------|------|
| 启用 | 薪资组当前处于启用状态，可用于算薪 |
| 停用 | 薪资组当前处于停用状态 |

### 算薪状态

薪资组或工资表中员工的算薪进度状态：

| 状态 | 含义 |
|------|------|
| 未算薪 | 该员工尚未进行薪资计算 |
| 已生成税前工资 | 已计算生成税前工资，尚未计算税后工资 |
| 已生成税后工资 | 已完成税后工资计算 |

### 锁定状态

| 状态 | 含义 |
|------|------|
| 已锁定 | 工资表/算薪结果已锁定，锁定后可对工资单进行更多操作（发送电子工资单或发送到薪资代发） |
| 未锁定 | 工资表/算薪结果尚未锁定 |

- 算薪结果按钮可锁定或解锁工资表。
- 提交电子工资单、发起薪资代发前需先锁定工资表。

### 审批状态

| 状态 | 含义 |
|------|------|
| 未提交 | 尚未提交审批 |
| 审批中 | 审批流程进行中 |
| 已通过 | 审批已通过 |

### 代发状态

| 状态 | 含义 |
|------|------|
| 未提交 | 尚未提交代发 |
| 已代发 | 已提交代发（含代发成功） |

### 工资单状态

| 状态 | 含义 |
|------|------|
| 未提交 | 尚未提交电子工资单 |
| 已提交 | 已提交电子工资单 |

### 算税状态

| 状态 | 含义 |
|------|------|
| 未算税 | 尚未计算个税 |
| 已算税 | 已完成个税计算 |

- 算税方式、代发状态、算税状态在税前工资算税批次中展示。

### 数据采集审批状态

数据录入页面中采集数据的审批状态：

| 状态 | 含义 |
|------|------|
| 待提交 | 采集数据尚未提交审批 |
| 审批中 | 采集数据审批进行中 |
| 已通过 | 采集数据审批已通过 |

- 开启了审批时，采集数据需发起审批，审批通过后才可用于算薪。

### 定调薪状态

薪资档案中员工的定调薪状态：未定薪（员工尚未完成定薪）。

### 补贴计划发放状态

| 状态 | 含义 |
|------|------|
| 未发放 | 补贴明细尚未被薪资组引用发放 |
| 已发放 | 补贴明细已被薪资组引用计算，会显示引用的薪资组和已发放状态，且无法删除 |

- 若已发放补贴明细的薪资组删除了该员工的当期工资数据，则补贴计划中的发放薪资组和已发放状态将重置为空薪资组和未发放状态。

### 计薪状态相关展示

- 薪资计算页面薪资组行展示算薪状态（已生成税后工资/已生成税前工资/未算薪）、薪资组状态（启用/停用）、锁定状态（已锁定/未锁定）。
- 当期工资页面信息行展示：计薪周期、薪资锁定时间、工资单状态（未提交）、审批状态（审批中）。
- 计算薪资步骤 1 统计卡片展示：当期工资表总数、较上月、可算薪人员、已锁定、手工添加人员、应同步算薪人员、异常人员、入职、转正。
- 计算税后薪资页员工算税状态：未算税。

## 异常与排查

### 试用数据与线下计算结果不符

背景：配置好规则，设置好个税以后，企业开始用工资数据试用，却发现与传统计算出来的结果不符。

问题：影响因素较多：引用的字段源数据有误、专项附加扣除同步、社保公积金见角进分、折算等。

排查步骤：
- 步骤一：误差较小（元、角）的时候，优先检查社保公积金取数的条件。
- 步骤二：先检查公式是否有问题，这个最容易出错的。
- 步骤三：个税检查，特别是专项附加扣除。由于同步不及时，可能导致算税不同。

### 税前工资数据有误处理

在计算完税前/税后工资后，发现工资数据有误，需要排查该工资项取值规则，按照实际算薪规则进行调整。

- 查看税前/税后工资数据路径：【智能算薪-算薪管理-薪资计算-当期工资-计算税前工资/计算税后工资】。
- 修改薪资规则路径：【智能算薪-算薪管理-薪资计算-编辑薪资组-配置薪资规则】。

**1. 税前工资计算有误**：调研客户薪资规则，修改薪资规则公式。

**2. 税前工资取数有误**：
- 数据来源为手工导入：修改浮动数据，重新导入数据。
- 数据来源为数据采集：修改数据采集数据，重新计算税前工资（如数据采集开启了审批，需要先审批完成）。
- 在线编辑、导入修改：当月有个别人员薪酬数据发生调整，但薪资规则不发生变化，可计算完税前工资后，通过在线编辑/修改、导入修改方式操作。

### 税后工资数据有误处理

检查个税计算结果，查看员工（累计减除费用、累计专项附加扣除等）数据，核实完毕后重新同步个税。路径：【个税服务-个税管理-个税核算-详情】。

- 累计减除费用不正确：通过花名册查看任职受雇从业日期、入职年度就业情形是否填写无误。如有误修改为正确的信息重新人员报送，如无误可以在个税备注中增加任意备注重新人员报送。路径：【花名册-选中人员-个税申报信息】。
- 累计专项附加扣除不正确：首先更新对应税款所属月的核算数据，如对核算数据存疑，再更新填报数据，核实员工当前专项实时填报情况。

### 核对计薪人员异常处理

**（一）员工信息有误**

核对计薪人员时发现员工基本信息与当前花名册信息不一致，需重新同步花名册信息，按以下两个步骤操作：
- 步骤一：【智能算薪-档案管理-薪资档案】-"同步花名册"。
- 步骤二：【智能算薪-算薪管理-当期工资-计算薪资】-"核对计薪人员-重新同步人员-不变更人员信息仅同步信息"。

**（二）计薪人员数量有误**

核对计薪人员时发现应计薪人员数量有误，有人员缺少或增多的情况，需通过下列 4 个步骤进行排查：
- 步骤一：检查薪资组设置，算薪人员和排除算薪人员设置，是否有勾选对应员工或对应部门等信息。
- 步骤二：排查计薪人员同步异常原因，检查员工花名册信息是否填写完整。
- 步骤三：核对当前计薪周期和员工入离职时间是否一致。例：当前计薪周期为 11月1日-11月30日，员工入职日期为 12 月，或者员工离职日期为 10 月，当前计薪周期会排除这部分员工。
- 步骤四：检查参数设置是否有使用人事异动产生的记录算薪，开启后如果使用人事异动，根据异动记录产生的历史数据（如历史部门、岗位等）用于薪酬计算，关闭后仅获取当前花名册数据算薪。例：当前薪资组计算 A 部门员工，员工已经调动到 B 部门，但计薪人员列表还存在 A 部门员工，需检查是否开启了人事异动开关。

信息检查无误后通过薪资组重新同步算薪人员。重新同步人员的方式：
- 重新同步人员并保留数据：重新获取薪资组的算薪人员，原算薪人员的已导入信息保留，如有新增人员需重新算薪。
- 不变更人员信息仅同步信息：仅同步现有算薪人员的花名册最新信息，如果花名册的信息会影响算薪数据，需重新算薪。
- 重新同步人员且清除数据：清除原算薪人员的所有算薪算税数据，需要重新算薪。

### 确认当期计薪月份异常处理

**（一）计薪月份小于薪资所属月**

当创建当期工资时显示的计薪月份小于企业当前薪资所属月，需通过"创建下月工资表"，创建对应月份工资表。

**（二）计薪月份大于薪资所属月**

当创建当期工资时显示的计薪月份大于企业当前薪资所属月，需通过【更多操作-删除工资表】，返回上期工资表。

- 可通过创建下月工资表或更多操作中的删除工资表功能返回上个月的工资表进行计算，删除将会删除当期工资数据请谨慎操作。

### 花名册修改工号后同步异常

在花名册修改员工工号后，智能算薪中员工工号未改变的处理：
1. 刷新页面。
2. 点击"档案管理-薪资档案-同步花名册"手工同步。
3. 点击"算薪管理-薪资计算-薪资组-当期工资-计算薪资-重新同步"。
4. 重新选择算薪人员进行操作。

### 差额补发

在完成薪资计算并联动代发后，若发现部分员工薪资数据存在遗漏，系统支持在薪资组中重新计算薪资，系统将基于已完成的代发金额自动计算出差额部分，并联动代发，确保薪资补发准确无误。

场景举例：员工A首次算薪的实发工资是 3000 元，并已完成代发，后续企业发现该员工薪资数据存在遗漏，重新录入后计算，实发工资更新为 5000 元。

- 操作路径：在【智能算薪-算薪管理-薪资计算】页面，点击对应薪资组的"当期工资"，右上角点击"更多操作"-"查看代发结果"，可操作"差额补发"。
- 系统会根据最后一次计算的实发金额与已发放金额，自动计算出实发差额。
- 需要首次代发已经成功，"已发放金额"才会更新数据，系统才会自动计算出差额。
- 点击"补发差额"即可将差额部分提交到薪资代发版块进行发放。

### 多薪资组算薪异常排查

**部门调动场景**：
- 使用人事异动产生的记录算薪：开启时，如果使用人事异动，根据异动记录产生的历史数据（历史部门、岗位等）用于薪酬计算；关闭时，不管是否使用人事异动，只取花名册当前数据算薪。配置在【智能算薪-薪酬设置-参数设置-高级设置】。
- 通过薪酬档案同步花名册：更换部门后，算薪界面还显示原来的部门，便需要通过薪酬档案"同步花名册"。
- 通过算薪界面"重新同步人员"。

**兼任部门场景**：花名册查询是否已增加兼任部门，同步兼任部门人员需打开"同步兼任部门人员"的开关（编辑薪资组-基础设置-算薪人员-同步兼职部门人员）。

### 批量算薪中断

- 计算过程中若不小心退出了计算页面，仍可点击"批量算薪"重新回到批量计算页面。
- 在批量计算进行中，无法单独操作单个薪资组的工资计算，建议在任务完成后或终止任务后再进行相关操作。
- 终止任务后，已导入和同步的数据会保留在各自的薪资组中，方便后续继续操作。

### 导入异常处理

- 导入税前工资数据时，数据范围配置好后点击下一步，如果导入的数据有问题，会弹出错误提示界面，点击蓝色字体"导出错误结果文件"；打开下载的表格，表格的最前方列"错误信息"栏会展示错误原因，根据提示信息进行修改后，再用此模板点击"再次导入"。
- 定薪/调薪导入时若数据填写有误，系统会提示错误，用户可导出错误文件修改后重新上传。

## 前置条件

| 流程 | 前置条件 |
|------|---------|
| 使用智能算薪 | 已在员工管理导入员工花名册并填写个税字段；如使用个税需完成扣缴义务人管理配置及员工报送（可选用）；如使用社保需创建参保方案并生成月结账单（可选用）；完成薪酬设置并配置财务人员数据权限；完成薪资档案设置并为员工定薪；创建薪资组并配置薪资规则 |
| 使用智能算薪算薪 | 人员需在花名册维护员工信息；同步个税前个税服务中人员报送列表的员工信息已报送成功 |
| 离职员工算薪算税 | 薪资组算薪人员范围包括该离职员工且该离职员工在当前计薪周期中；算税需确保算税员工在个税中还是可报税状态（人员状态为正确且报送成功） |
| 税前工资算税 | 花名册信息中已填写个税申报信息并对人员进行了报送；人员报税状态为"可报税" |
| 税前工资算税反向生成花名册 | 需升级到新版本花名册；打开"同步处理人员信息及个税报送"开关 |
| 从社保公积金同步社保 | 已生成当月月结账单 |
| 从考勤数据获取工资项 | 企业同时启用薪福通假勤管理模块 |
| 工资项从薪酬档案获取 | 已在薪资档案模块完成对应档案项的定调薪 |
| 工资项从数据采集获取 | 已提前在采集表完成数据录入 |
| 调薪补发 | 已开启"特殊薪资发放计划"白名单功能；调薪生效日期早于当前日期 |
| 提交电子工资单/发起薪资代发 | 工资表已锁定 |
| 多批次合并发送电子工资单 | 所有批次算薪状态为已生成税后工资、锁定状态为已锁定、薪资所属月一致、如设置审批需所有批次审批通过 |
| 多批次合并代发 | 所有批次算薪状态为已生成税后工资、锁定状态为已锁定、批次为未代发/全部失败/部分失败、薪资所属月一致、如设置审批需所有批次审批通过 |
| 生成月结账单 | 已创建好参保方案并完成员工参停保 |
| 社保公积金调基补差（高阶版自动） | 已生成月结账单；开启"补缴差额"开关并填写补缴起止月份和账单生成月份 |
| 假期余额结薪（手工） | 假期方案设置中"假期余额"可结薪；剩余额度不为 0 |
| 离职自动结薪 | 假期方案设置中离职结薪方式选择"自动生成结薪单"；员工可结薪假期余额不为 0 |
| 过期余额定期自动结薪 | 假期方案设置中过期余额结薪方式选择"定期生成结薪单"；员工在假期设定范围内过期未休完余额不为 0 |
| 数据采集用于算薪 | 开启审批时需先对采集数据发起审批，审批通过后才可用于算薪 |
| 差额补发 | 首次代发已成功 |

## 生效方式

| 项目 | 生效方式 |
|------|---------|
| 定薪 | 保存后立即生效；调薪前可多次定薪允许修改，调薪后不可定薪 |
| 调薪 | 生效日期必填；调薪生效日期设置大于当前日期时，需等到生效日时薪资档案列表页才显示调整后的最新薪资信息 |
| 调薪补发 | 在调薪完成日所属的计薪月份补发差额工资 |
| 当期工资显示 | 当期工资计算完结果显示在"当期工资"；需显示在历史工资时点击"创建下月工资表" |
| 采集数据锁定 | 锁定后该日期范围内的数据不能再新增/修改/删除 |
| 补贴计划引用 | 创建补贴计划时发放薪资组未选择时，计薪周期在补贴所选月份范围内且薪资组包含补贴工资项即自动获取金额；多个薪资组均包含该补贴工资项时仅首个计算的薪资组可获取 |
| 社保公积金工资从薪资档案同步 | 在社保公积金-设置-参数配置后生效 |

## [GAP] / [CONFLICT] / [QUESTION]

- [GAP] 台账（高阶版）、参停保信息同步、社保对账等页面相关状态的完整枚举未采集
- [QUESTION] 算薪审批被拒后是否支持重新发起、是否有冷却限制，未在材料中明确
- [QUESTION] 定调薪状态除"未定薪"外的完整取值（如定薪中、已定薪等）未在材料中明确
