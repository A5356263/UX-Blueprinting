# 11_权限规则与可见性策略

补充智能报表域中权限维度的独立性、优先级规则，以及权限驱动的页面与操作可见性策略。

- 来源：docs/discussion/报表/ 知识提取（concepts、relations、topics）
- 来源类型：二次编译知识提取
- 最近更新：2026-05-15

## 1. 权限维度

### 1.1 功能权限与数据权限的独立性

功能权限和数据权限是两个独立的权限维度：

- **功能权限**：决定用户"能不能进入某个页面、能不能执行某项操作"（如查看报表、导出、授权）
- **数据权限**：决定用户"进入后能看到哪些数据范围"（按部门/岗位/人员维度过滤）

两者互不包含，独立判定。用户可能具备查看某报表的功能权限，但因数据权限限制而看到空数据或被过滤后的数据。

### 1.2 权限判定流程

1. 先判定功能权限 → 无权限则不展示入口
2. 有功能权限后再判定数据权限 → 无数据权限则展示空数据 + 原因说明
3. 数据权限的过滤结果不影响功能权限的判定

## 2. 权限优先级规则

### 2.1 角色继承与单报表覆盖

- 用户从所分配的角色中继承权限
- 当存在单张报表级别的权限设置时，以单报表权限为最高优先级进行判定
- 单报表权限可以覆盖（扩大或缩小）角色继承的权限

### 2.2 授权人数限制与引导

- 单次用户授权不超过 20 人
- 超过 20 人时，应引导管理员使用角色授权方式批量管理
- 角色授权单次不超过 20 个角色

## 3. 可见性策略

### 3.1 入口可见性

- 用户无查看权限的报表/功能入口，直接不展示（非置灰）
- 不展示的范围包括：导航菜单项、报表卡片、操作按钮、搜索和收藏结果中的条目

### 3.2 操作可用性

- 用户权限不足时，对应的操作入口不提供（非置灰）
- 例如：无导出权限时不显示"导出"按钮；无授权权限时不显示"授权"入口
- 不同角色的操作可见性差异：

| 角色 | 可见操作 |
|------|---------|
| 普通员工 | 查看、收藏、导出（如有权限）、订阅 |
| 单张报表管理员 | 上述 + 对该报表授权（齿轮图标） |
| 智数报表应用管理员 | 可对其他员工授权 |
| 业务管理员 | 有"权限管理"菜单时可对企业所有报表授权 |
| 超级管理员 | 所有操作 |

## 4. 状态策略

### 4.1 空数据状态

- 有报表权限但无数据权限时：展示空状态页面 + 原因说明文字（如"当前数据范围内无数据"）
- 不应展示为系统错误或异常提示
- 不应让用户误以为是系统故障

### 4.2 加载状态

- 页面加载过程中使用骨架屏（Skeleton），而非空白页面或无限转圈

### 4.3 操作反馈

- 高风险操作（如停用报表、删除授权、修改关键配置）需要二次确认弹窗
- 操作成功后需要明确的成功反馈（Toast 或页面提示）
- 操作失败后需要明确的失败原因说明

### 4.4 权限变更后的即时生效

- 授权、停用/启用等操作完成后即时生效，无需用户刷新页面

## 5. 常见误解

- "有查看权限就一定能看到数据" → 不成立，数据权限可能导致空数据展示
- "权限不足就置灰按钮" → 不符合本系统规则，推荐直接不提供操作入口
- "无数据就是系统出错了" → 应优先用空状态解释原因，而非引导用户报障

## 缺口 / 待确认

- [GAP] 数据维度的组合逻辑未明确（部门/岗位/人员的交集/并集/优先级）
- [GAP] 空数据原因的类型枚举与对应文案规范未建立
- [GAP] "无权限不展示"在导航、搜索结果、收藏列表等跨页面场景的细则未覆盖
- [GAP] 权限变更后的即时生效机制（前端缓存刷新策略）未明确
- [CONFLICT] 角色命名不统一：原始材料中"报表管理员""单报表管理员""报表应用管理员"混用
