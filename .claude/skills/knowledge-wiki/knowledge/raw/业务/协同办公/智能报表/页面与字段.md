## 页面分级与关键页面规则

补充智能报表域的页面优先级划分（P0/P1/P2）、左侧导航结构、关键页面的交互规则与约束，以及智数平台的产品边界。

- 来源：docs/discussion/报表/ 知识提取 + 用户提供的实际导航结构
- 来源类型：二次编译知识提取 + 产品事实补充
- 最近更新：2026-05-15

### 1. 左侧导航结构

报表应用左侧一级导航菜单：

```text
首页
报表中心
模板市场
配置管理
  ├── 权限管理
  ├── 订阅与预警
  └── 报表管理员设置
待验收报表
```

### 2. 页面分级体系

#### 2.1 分级概览

| 级别 | 页面 | 定位 |
|------|------|------|
| P0 | 首页、报表中心、模板市场、报表详情页 | 核心体验页面，面向所有用户 |
| P1 | 配置管理（权限管理、订阅与预警、报表管理员设置） | 管理与配置页面，面向管理员和高级用户 |
| P2 | 待验收报表 | 流程节点页面，面向特定流程参与者 |

#### 2.2 分级原则

- P0：面向所有用户，是产品核心价值的承载页面，优先级最高
- P1：面向管理员和高级用户，支撑权限管控与分发能力
- P2：面向特定流程参与者，频次较低

### 3. 关键页面规则

#### 3.1 首页（P0）

- 面向不同角色展示差异化内容
- 普通员工：展示有权限的报表入口和关键数据摘要
- [GAP] 首页的具体布局和信息展示规则未明确

#### 3.2 报表中心（P0）

- 核心能力：分类浏览、搜索、筛选、查看报表、收藏、切换视图、授权（按角色不同）
- 页面结构：顶部搜索筛选区 + 操作区 + 内容区（左侧分类树、右侧卡片/表格视图）
- 默认分类："我的收藏"和"未分类"置顶，业务分类在下方
- 每个分类默认展示第一行数据，展开可查看全部
- 视图偏好：支持卡片视图和列表视图切换，个人级别记住偏好，首次访问默认卡片视图；仅记住视图类型，不记住筛选条件
- 状态规则：无权限的报表不展示；无数据时展示空状态；加载时使用骨架屏

#### 3.3 模板市场（P0）

- 面向所有用户，浏览和选用可用的报表模板
- 页面结构：搜索筛选区 → 模板卡片列表区 → 分页区（详见 `模板市场页面规则.md`）
- 卡片信息优先级：模板名称 > 业务场景标签 > 模板缩略示意
- 整卡可点击进入模板详情页，卡片内不放置复杂操作入口
- 包含主题报表模板和个性化报表模板
- 模板需已上架且企业有权限才可使用
- 模板引用的数据集模型也需已上架且企业有权限
- 修改报表的前提条件之一：员工需要对"模板市场启用的个性化报表"有授权权限
- [GAP] 模板详情页的具体内容和交互规则未采集

#### 3.4 报表详情页（P0）

- 从报表中心卡片点击进入
- 核心能力：全屏查阅、导出（Excel/PDF/图片，需导出权限）、数据显示（查看可视化背后的数据结构）
- 支持钻取、联动等高级分析场景
- 右上角可发起"卡片预警"创建

#### 3.5 配置管理（P1 容器）

配置管理为一级导航目录，其下包含三个二级页面。

##### 权限管理

- 以单张报表为维度进行权限配置
- 授权对象：用户（最多 20 位员工）、角色（最多 20 个角色）
- 可授权限类型：查看、导出、授权（将该报表授权给他人）
- 数据权限配置前，数据集字段需先在智数平台绑定平台维度
- 高风险操作需要二次确认
- [GAP] 权限项与界面组件的具体映射关系未建立

##### 订阅与预警

- 页面结构：顶部 Tab 切换"订阅任务"和"预警任务"
- 通用列表能力：筛选、切换"我创建的"/"我接收的"
- 权限视图差异：普通员工仅可见"我接收的"；应用管理员可见全部功能

**订阅规则：**
- 当前仅支持邮件订阅
- 创建流程：选择报表 → 选择收件人 → 校验邮箱 → 设置推送时间/频率（日/周/月）
- 系统自动过滤无查看权限的收件人
- 默认读取花名册邮箱（可修改）
- 收件人点击邮件链接可直接跳转查看报表内容
- [GAP] 除邮件外的其他订阅渠道正在完善中

**预警规则：**
- 预设的主题报表暂不支持预警
- 最多添加 5 条预警规则
- 每条规则包含：名称 + 维度条件 + 数值条件
- 多条规则可选触发条件：满足所有 / 满足任一
- 触发时间：更新后通知 或 定时通知（日/周/月）
- 通知渠道：平台内消息、待办、邮件
- 通知标题 ≤ 20 字符，内容 ≤ 2000 字符
- 入口补充：报表详情页右上角"卡片预警"也可发起创建

##### 报表管理员设置

- [GAP] 该页面的具体功能规则未采集

#### 3.6 待验收报表（P2）

- 路径：待验收报表 → 待我验收
- 验收通过：报表直接发布
- 验收拒绝：填写拒绝原因，重新进行报表开发优化
- [GAP] 该页面的具体交互规则未完整采集

### 4. 产品边界：智数平台

制作报表、管理模板和数据加工不在报表应用内，而是跳转至 **企业应用开发中心 → 智数平台**。

#### 4.1 智数平台定位

- 面向内部开发者和产品经理
- 用于调试、开发、上传官方报表模板等

#### 4.2 智数平台目录结构

```text
企业应用开发中心
  ├── 工作台
  ├── 网页应用
  ├── API 平台
  ├── 连接平台
  ├── 低代码平台
  └── 智数平台
        ├── 报表制作
        ├── 报表模板市场
        └── 数据处理
              ├── 数据集
              ├── 维度管理
              ├── 数据加工
              └── 数据集市
```

#### 4.3 与报表应用的关系

- 报表应用的数据来源为智数平台（离线或准实时数据输出）
- 报表应用内"制作报表"入口跳转至智数平台
- 数据权限配置前，数据集字段需在智数平台绑定平台维度

## 模板市场页面规则

补充报表应用中"模板市场"一级菜单下的报表模板卡片列表页的完整交互规格。

- 来源：用户提供的产品事实
- 来源类型：产品交互规格
- 最近更新：2026-05-15

### 1. 页面定位

- 页面名称：报表模板卡片列表页
- 入口：报表应用左侧一级导航 → 模板市场
- 页面性质：P0（面向所有用户，浏览和选用报表模板的核心入口）

### 2. 触发条件

- 用户需要快速浏览、筛选并选择适合当前业务场景的模板
- 用户通过"模板名称"和"业务场景"进行认知和选择

### 3. 页面职责

- 快速建立模板用途认知
- 帮助用户理解模板包含的报表类型与组合结构
- 支持用户在大量模板中快速定位目标
- 降低模板选择成本，而非强调视觉展示

### 4. 页面结构

页面按以下顺序组织：

1. 搜索筛选区
2. 模板卡片列表区
3. 分页区

### 5. 搜索筛选规则

- 搜索区固定于页面顶部
- 支持按模板名称搜索
- 支持按模板类型筛选
- 筛选项优先使用单选或标签筛选，避免复杂表单
- 搜索与筛选应服务于"快速定位"，禁止出现高学习成本筛选结构

### 6. 卡片布局规则

- 模板以卡片网格形式平铺展示
- 卡片需要保持统一高度
- 当数据量超过单屏容量时使用分页，而非无限滚动
- 卡片间距需优先保证浏览节奏一致性
- 禁止瀑布流布局

### 7. 卡片信息优先级

卡片内容按以下优先级组织：

1. 模板名称
2. 业务场景标签
3. 模板缩略示意

#### 7.1 模板名称

- 优先突出业务主题关键词，避免冗长描述
- 保证用户可在快速浏览过程中完成识别
- 标题超过一行时截断，并在悬停时展示完整内容

#### 7.2 业务场景标签

- 用于表达"适用场景"，而非功能堆砌
- [GAP] 标签的完整枚举和分类方式未采集

#### 7.3 模板缩略示意

- 用于辅助理解模板结构，不承担装饰作用
- [GAP] 缩略图的具体呈现形式（示意插图 / 真实截图 / 结构图）未明确

### 8. 交互规则

- 卡片悬停时需提供明确交互反馈
- 点击卡片进入模板详情页
- 整卡可点击，避免仅局部热区可操作
- 主交互行为保持唯一（进入详情），禁止同时存在多个高优先级操作
- 禁止在卡片中展示复杂操作入口

### 9. 视觉约束

- 卡片容器使用弱强调背景区分
- 卡片视觉风格保持信息型而非营销型
- 禁止使用大面积 Banner、插画或强装饰元素
- 圆角、阴影与容器规范保持一致
- 视觉重点应服务于信息识别效率，而非视觉冲击

### 缺口 / 待确认

- [GAP] 模板类型的完整枚举未采集
- [GAP] 业务场景标签的完整枚举和分类方式未采集
- [GAP] 缩略图的具体呈现形式（示意插图 / 真实截图 / 结构图）未明确
- [GAP] 模板详情页的具体内容和交互规则未采集
- [GAP] 分页的具体参数（每页卡片数量、默认排序规则）未明确

## 权限结果的页面呈现参考

本节保留原规则文件中的页面呈现要求，不作为权限或状态规则使用。

### 空数据

- 有报表权限但无数据权限时，页面展示空状态和原因说明文字，例如“当前数据范围内无数据”。
- 不将该结果展示为系统错误或异常提示。

### 加载与操作反馈

- 页面加载过程中使用骨架屏（Skeleton），不使用空白页面或无限转圈。
- 停用报表、删除授权、修改关键配置等高风险操作使用二次确认。
- 操作成功提供成功反馈；操作失败提供失败原因说明。
