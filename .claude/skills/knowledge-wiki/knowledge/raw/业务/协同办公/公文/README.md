# 公文

## 这是什么

这是公文子域的固定文件级路由入口，用来说明本子域承载什么知识、遇到什么问题该优先看哪些语义文件。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应语义文件中。

## 领域契约

### 领域定义

公文领域回答的是：
企业如何通过薪福通平台的公文管理完成从发文办理、公文交换到收文办理的全流程公务文书管控。

公文管理业务由发文办理、公文交换和收文办理三部分构成；发文归档和收文归档均进入公文档案库。

### 解决的问题

公文领域主要用于解释以下问题：

- 企业如何完成公文的发文拟稿、审核、复核、签发、套红用印、分送和归档
- 企业如何完成公文的收文登记、拟办、批示、承办、办理和归档
- 公文如何在发文与收文之间进行交换
- 如何配置公文应用、参数、流程和角色权限
- 如何配置和完成阅知任务
- 如何生成公文稿

### 为什么独立成域

公文需要独立沉淀，是因为它同时具备以下特征：

- 公文管理业务由发文办理、公文交换和收文办理三部分构成，有完整的业务闭环
- 公文涉及多级多部门会签审批，与审批域存在交叉
- 具备强规则性：字号、密级、文种、公文分类、流程配置
- 涉及发文、收文、交换、归档、阅知、公文稿等多类对象和任务

### 与上游领域的关系

- 公文会签机制补读审批管理
- 工具开通或使用授权补读权限管理

这里描述的是上游依赖事实，不等于具体规则已经由其他领域定义完成。

### 稳定结论

- 公文是企业公务文书管理的核心工具
- 其核心价值是为发文办理、公文交换、收文办理提供稳定输入
- 它可以服务业务分析、产品设计、体验解释和排障分析，但本文件本身不承载下游消费说明

### 显式缺口

- [GAP] 公文15种文种的具体名称清单未枚举（密级三级、字号构成、文种数量已采集）
