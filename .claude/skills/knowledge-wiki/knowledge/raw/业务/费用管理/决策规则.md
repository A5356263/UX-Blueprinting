# 20_决策规则

## 规则

- 功能归属判断：
  - 涉及机票、酒店、用车预订时，优先归入差旅服务。
  - 涉及个人报销或员工垫付时，优先归入日常报销。
  - 涉及供应商付款、合同付款或对公支出时，优先归入对公报账或企业支付相关能力。
  - 涉及发票采集、验真、查重时，优先归入发票管理能力。
- 预算判断：费用管理类需求需要显式判断是否涉及预算控制逻辑。
- 移动端判断：报销、发票采集、审批等高频操作需要考虑移动端操作体验。
- 集成判断：涉及商旅平台、ERP、财务系统或 API 导出时，需要单独判断外部集成能力。

## 判断条件

- 如果需求对象是出差申请、商旅预订、差旅报销或企业月结，优先进入 `差旅服务/`。
- 如果需求对象是费用报销、费用申请、发票、分摊、收款账户或支付打款，优先进入 `日常报销/`。
- 如果需求对象是供应商、合同、付款申请或对公付款，优先进入 `企业支付/`，必要时回查费用管理整体规则。
- 如果需求对象是费用类型、预算、支付、核算、表单流程或系统设置，优先进入 `通用配置/`。

## 优先级

1. 先判定业务对象和用户任务。
2. 再判定所属子域。
3. 再判定是否涉及预算、审批、发票、支付、核算或外部集成。
4. 最后判断是否需要跨子域回查。

## 冲突处理

- 当一个需求同时涉及多个子域时，按主任务归属确定主落点，把预算、审批、发票、支付等作为依赖能力处理。
- 当帮助文档口径与产品真源不一致时，不直接裁决，用 `[CONFLICT]` 标记并回查更强来源。

## [GAP] / [CONFLICT] / [QUESTION]

- [QUESTION] 预算控制在差旅服务、日常报销、企业支付、通用配置之间的统一入口和生效优先级仍需继续核对。
