## 这是什么

这是企业支付（对公报账）子域的二级路由入口，用来说明这个目录里各编号段分别承载什么知识、遇到什么问题该优先看哪些文件。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应编号文件中。


## 领域契约

### 领域定义

企业支付（对公报账）领域回答的是：
企业如何通过薪福通平台完成供应商管理、合同管理、付款申请和对公付款的全流程线上管理。

它覆盖的不是单一付款动作，而是一整套与企业对公支付相关的业务语义，包括：

- 4 种业务场景：预付款支付、先票后款、到票核销、分期支付
- 供应商管理：准入/变更审批、档案自动同步
- 合同管理：框架/付款合同、临期提醒
- 发票核验与费用政策管控
- 外币支付与费用在线分摊
- 凭证生成推送智能记账

### 解决的问题

企业支付领域主要用于解释以下问题：

- 企业对公付款有哪几种业务场景
- 供应商如何准入和管理
- 合同如何与付款关联
- 发票如何核验、费用如何分摊
- 外币支付如何处理
- 付款后如何生成凭证

### 为什么独立成域

企业支付需要独立沉淀，是因为它同时具备以下特征：

- 有完整的业务闭环：供应商管理 → 合同管理 → 付款申请 → 对公付款
- 支持 4 种不同的付款业务场景，各有独立的流程逻辑
- 涉及供应商准入审批、合同临期管理、外币支付等复杂场景
- 与招商银行支付系统和智能记账深度集成

### 与上级领域的关系

- 与 OA 审批集成：供应商准入/变更审批、付款审批
- 与招商银行代发/云直联/CBS 集成：支付能力
- 与智能记账集成：凭证自动生成推送
- 与国税局接口对接：发票验真验重
- 与费用管理-通用配置交叉：费用政策、预算方案、支付设置由通用配置定义

这里描述的是上游依赖事实，不等于具体规则已经由其他领域定义完成。

### 稳定结论

- 企业支付是对公报账的核心子域
- 其核心价值是为供应商管理、付款场景、外币支付和凭证生成提供稳定输入
- 它可以服务业务分析、产品设计、体验解释和排障分析，但本文件本身不承载下游消费说明
