# 日常报销

## 这是什么

这是日常报销子域的二级路由入口，用来说明这个目录里各编号段分别承载什么知识、遇到什么问题该优先看哪些文件。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应编号文件中。


## 领域契约

### 领域定义

日常报销领域回答的是：
企业员工如何通过薪福通平台完成日常费用报销的全流程线上操作。

它覆盖的不是单一报销单，而是一整套与日常费用报销相关的业务语义，包括：

- 发票核验：对接国税局接口，查重验真
- 费用政策与预算设置：按部门/项目/成本中心多维度管控，超标预警或禁止提交
- 代发支付：审批后推送代发，一键支付并状态回写
- 凭证生成：推送智能记账
- 数据报表：按部门/人员/费用多维度统计

### 解决的问题

日常报销领域主要用于解释以下问题：

- 员工如何提交日常费用报销
- 发票如何验真验重
- 费用如何按政策和预算管控
- 报销审批后如何支付
- 报销数据如何生成凭证和报表

### 为什么独立成域

日常报销需要独立沉淀，是因为它同时具备以下特征：

- 有完整的业务闭环：提单 → 审批 → 支付 → 记账
- 涉及与国税局接口对接（发票验真验重），有独立的技术集成
- 具备强规则性：费用政策、预算方案、超标管控
- 与代发支付和智能记账深度集成

### 与上级领域的关系

- 与 OA 审批集成：报销单审批流程
- 与国税局接口对接：发票验真验重
- 与招商银行代发集成：报销支付
- 与智能记账集成：凭证自动生成推送
- 与费用管理-通用配置交叉：费用政策、预算方案、表单字段由通用配置定义

这里描述的是上游依赖事实，不等于具体规则已经由其他领域定义完成。

### 稳定结论

- 日常报销是员工费用报销的核心子域
- 其核心价值是为发票核验、费用管控、报销支付和凭证生成提供稳定输入
- 它可以服务业务分析、产品设计、体验解释和排障分析，但本文件本身不承载下游消费说明

## 条件依赖与回主域

- 费用报销、费用申请、借还款、支付与记账闭环以本域为主；只有命中审批机制时补读审批管理，命中共享费用政策、预算、支付或会计配置时补读费用管理/通用配置
