# 假勤管理

## 这是什么

本目录是人事服务下“假勤管理”的正式业务知识入口，覆盖考勤、排班、打卡、外勤、请休假、加班、异常处理及核算发布。README 只定义领域边界和任务路由；业务事实分别放入对应的固定信息类型文件。

## 领域契约

### 领域定义

假勤管理回答：企业如何配置人员适用规则，形成排班与打卡／申请记录，处理异常，按日月核算，按企业配置进行考勤确认与发布，并向智能算薪提供可取用结果。它不以一个统一状态机代替不同班制、规则、审批与发布开关的条件。

### 解决的问题

- 考勤组、司历、班次、地点、移动方案、假期及加班等如何配置并关联到人员。
- 员工或管理员如何打卡、补卡、发起请假／加班／出差／外出申请，以及批量发起和审批有何区别。
- 异常、记录删除、额度初始化、日月核算、确认发布与算薪取数的条件和影响。
- 已确认页面有哪些、哪些详情有证据、哪些仅有信息架构节点而尚待补充。

### 为什么独立成域

假勤有自身的对象、规则与核算闭环；同时依赖组织和花名册，条件性使用 OA 审批、智能费控和智能算薪。跨域依赖不改变假勤记录、适用规则及核算结果由本域解释的归属。

### 与其他领域的条件关系

- 人员资料不全时读员工管理／组织管理；补全资料后返回本域确认考勤组匹配与统计结果。
- 命中申请审批或表单配置时补读审批管理；批次处理与审批通过须分开，随后返回本域查申请和考勤状态。
- 命中费控出差同步或假期结薪公式时补读相应领域；本域仅记录同步条件及算薪取数依赖，不推导其他系统的完整流程。
- 原产品介绍提及钉钉／企业微信单点登录及第三方打卡 API，同步边界和异常机制仍须以专门证据核实。

### 稳定结论与缺口

业务主线为“配置适用规则 → 排班与打卡／申请 → 异常处理 → 日月核算 → 确认和发布 → 算薪取数”。日统计先于月汇总；考勤确认是否启用由企业决定；开启发布时按配置发布后才能供算薪取数。完整权限矩阵、部分状态机、回滚和设备失败处理尚未提供，不以旧产品介绍中的“实时同步”“室内10米”“余额自动结转至薪资”等概述填补。
