# 业务对象与术语

假勤管理的业务主线为“配置适用规则 → 排班与打卡／申请 → 异常处理 → 日月核算 → 确认和发布 → 算薪取数”。并非每家企业都启用全部环节；是否适用取决于班制、规则、权限及开关。本文件定义对象与角色，不代替规则或页面字段。

## 对象及关系

| 对象 | 业务含义 | 关系与边界 |
| --- | --- | --- |
| 员工 | 假勤申请、打卡和统计的人员主体 | 资料来自组织与花名册；一名员工适配一个考勤组，资料缺失应回到花名册核查 |
| 考勤组 | 将人员与司历、班次、打卡及其他适用规则关联 | 所属组织的数据权限与员工适用范围不同；自由工时、固定班制、排班制不能混用规则 |
| 司历、节假日方案 | 定义工作日、应出勤日期和天数 | 司历可关联节假日安排；月份、年度、调休与排班有关 |
| 班次、排班 | 班次定义应出勤时段；排班确定人员在日期上的班次 | 有效打卡、请假时长、弹性和异常依实际班次判断 |
| 上班地点、移动打卡方案 | 地点定义位置或设备；方案选择地点及打卡方式 | 配好地点不代表员工已启用，还需方案和考勤组关联 |
| 考勤机、设备人员、人脸 | 设备采集打卡并关联花名册员工，人脸是验证资料 | 设备人员匹配和人脸下发是不同步骤；设备已有的人脸不自动出现在 App 人脸列表 |
| 打卡、补卡、外勤及拍照记录 | 记录不同渠道的出勤凭据 | 记录来源、是否需要审批、统计效力、删除后果须分别判断 |
| 假期类型、方案、额度 | 类型定义假种，方案定义适用范围和核算/发放规则，额度表示有余额假期的数量 | 无余额类型不应凭空出现额度；额度初始化和方案发放不能重复计算 |
| 业务申请单、批次 | 单据表达请假、加班、外出、出差等申请，批次跟踪多人发起过程 | 批次完成不等于每张单据审批通过；记录删除与业务单据删除不是同一对象 |
| 日考勤统计、月考勤明细、月考勤汇总 | 日统计是月汇总计算基础，月明细用于查看逐日统计项 | 更新月数据须核查日后月的核算顺序 |
| 考勤确认、发布 | 考勤确认可由员工参与；发布开启时决定月结果是否可供算薪取数 | 确认是否启用由企业决定，不能统一视为发布硬门槛 |

## 核心角色与权限边界

| 角色 | 已确认任务 | 不可自动推断 |
| --- | --- | --- |
| 员工 | 打卡、适用范围内申请、录入人脸、按配置参加考勤确认 | 可修改他人记录，或绕过适用规则 |
| 考勤管理员 | 配置规则、人员、排班、设备，管理记录和异常 | 默认拥有全公司或所有门店数据权限 |
| 考勤员／考勤专员 | 核算、核查、发送确认和按配置发布 | 与所有称为“管理员”的角色权限完全相同 |
| 表单管理员 | 配置假勤审批流程 | 任意管理员都有审批配置权；超级管理员默认为表单管理员 |
| 审批人员 | 审批对应申请 | 可直接编辑全部考勤记录 |
| 企业管理员、资料维护人员 | 维护组织、花名册与相关授权 | 自动拥有每个假勤页面的全部操作权 |

完整权限矩阵未提供。适用人群、页面操作权和可见数据范围是三个不同维度；月汇总跨店权限还取决于所属门店或用工门店管理模式。

## 跨应用对象

- 组织与员工管理：假勤使用花名册人员资料。考勤人员页可以提示前往花名册补资料，但确切落点和返回行为未确认。
- OA 审批：出差、外出代理发起进入 OA；请假、加班等单据是否审批通过与批次提交状态分开。
- 智能费控：出差同步取决于配置，补同步历史范围另受限制；费控记录与 OA 单据不是同一删除对象。
- 智能算薪：以符合配置及发布条件的考勤结果取数；假期余额结薪金额公式属于算薪领域，不在本域推导。
- 外部平台：原产品介绍提及钉钉、企业微信的单点登录及第三方打卡信息 API 同步；本批材料未提供两平台分别适用的版本、配置路径、失败处理，不能以概述代替接口契约。
