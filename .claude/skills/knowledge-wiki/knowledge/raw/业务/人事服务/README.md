# 人事服务

## 这是什么

这是人事服务业务知识库的二级路由入口，用来说明各子域目录分别承载什么知识、遇到什么问题该优先进入哪个子域。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应编号文件中。


## 领域契约

### 领域定义

人事服务领域回答的是：
企业如何通过薪福通平台完成人力资源管理中的组织、员工、招聘、考勤、客户等核心人事业务。

它覆盖的不是单一人事功能，而是一整套与人力资源生命周期相关的业务语义，包括：

- 组织架构搭建、编制管控、岗位与职级管理
- 员工在职数据管理和生命周期异动
- 招聘全流程管理与入职衔接
- 排班、打卡、请休假、加班、考勤核算
- 人力资源服务企业的客户全生命周期管理

### 解决的问题

人事服务领域主要用于解释以下问题：

- 企业如何搭建和维护组织架构、编制、岗位与职级
- 员工从入职到离职的全生命周期如何管理
- 招聘流程如何运作、候选人如何衔接入职
- 考勤规则如何配置、考勤数据如何核算
- 人力资源服务企业如何管理客户和项目

### 为什么独立成域

人事服务需要独立沉淀，是因为它同时具备以下特征：

- 是薪福通平台的核心一级模块，覆盖企业人力资源管理的完整能力
- 包含多个独立子域，每个子域有自己完整的业务闭环
- 与审批、权限、成员、账户等多个上游领域存在交叉依赖
- 子域之间也存在业务衔接关系（如招聘→入职→员工管理）

### 与上游领域的关系

- 与权限域交叉：人事服务各模块的权限分配通过权限域统一治理
- 与审批域交叉：人事异动（入职/调动/离职）的审批流程由 OA 审批承接
- 与账户与企业生命周期域交叉：企业开通后的人事初始化流程
- 与成员域交叉：员工身份以成员为前置条件

这里描述的是上游依赖事实，不等于具体规则已经由其他领域定义完成。

### 稳定结论

- 人事服务是薪福通平台人力资源管理的核心入口
- 其内部按帮助中心模块结构拆分为 5 个子域，各自独立维护
- 核心价值是为人力资源管理各场景提供稳定的业务事实输入
- 它可以服务业务分析、产品设计、体验解释和排障分析，但本文件本身不承载下游消费说明

### 显式缺口

- [GAP] 子域知识覆盖度不均匀：组织管理、员工管理、客户管理、招聘管理较完整，考勤管理仅覆盖产品介绍
- [QUESTION] 各子域之间的数据衔接闭环是否已完整沉淀，仍需结合跨域场景持续校验

## 任务触发索引

- 需要理解人事服务整体边界：读本 README 的“领域契约”

## 条件依赖与回主域

- 先按组织管理、员工管理、招聘管理、考勤管理或客户管理确定主子域，不因出现“人事”通读全部子域
- 命中通用审批机制时补读审批管理，命中权限分配时补读权限管理，命中成员身份时补读成员管理；招聘转入职时只读取招聘管理与员工管理的衔接事实
- 读完依赖域后必须回到主子域确认人事对象、状态、流程与结果
