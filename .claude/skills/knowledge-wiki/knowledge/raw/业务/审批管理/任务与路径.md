## 核心事务总览

管理员确定审批表单、可发起人员和审批管理员 → 配置表单字段、流程节点、分支与适用规则 → 员工发起审批或由自动化任务发起后续审批 → 系统按当前流程计算节点处理人 → 审批人、办理人和抄送人按节点职责处理或查看 → 审批流程形成处理结果，并可触发已配置的后续审批或业务数据联动。

本总览只表达已证实的任务交接，不替代下游业务域对审批触发条件、业务状态和最终业务结果的定义。

## 表单与流程配置

### 表单配置任务

管理员可创建系统业务审批、自定义审批或 2.0 自定义审批；表单类型、字段和打印限制读取 [页面与字段](页面与字段.md)。

配置时确定审批名称、所在分组、审批说明、可发起人员和审批管理员，再设计表单控件与条件属性。

### 流程节点设计

| 节点或能力 | 任务交接 |
|---|---|
| 审批人 | 按配置处理同意或拒绝等审批任务；审批人来源、多人方式、字段权限和高级规则读取 [规则与权限](规则与权限.md) |
| 办理人 | 接收办理任务并提交办理结果，不执行同意或拒绝 |
| 抄送人 | 接收被配置为可查看的审批内容，不参与审批结论 |
| 分支节点 | 按条件与优先级进入一条分支；均不满足时进入默认分支 |
| 并行分支 | 多个分支可同时执行，全部完成后进入下一节点 |

### 流程模拟

完成流程节点配置后，可通过以下方式验证流程是否按当前设置计算：

1. 快速模拟：选择发起人和发起部门，查看模拟流程结果。
2. 提单模拟：输入已有表单编号，系统使用对应表单的发起人进行模拟。
3. 单号模拟：通过审批单号进行流程模拟。

### 流程版本与流程模板

- 同一审批表单可保存多个流程版本并切换使用。
- 版本管理可管理已有版本；界面区分“启用中”和“当前设计”。启用中的版本在发布后实际应用，当前设计表示画布中正在变更的内容。
- 当前流程可保存为流程模板，供其他审批表单复用。
- 可使用已保存模板或复制其他表单流程；在当前表单中调整模板不会影响原模板。

## 审批任务执行

### 发起与处理

- 员工可在 PC 端或移动端发起审批，也支持导入或批量发起。
- 提交前可展示审批流和对应人员信息；部分节点需要发起人指定具体审批人员。
- 审批人处理待办任务；管理员开启批量处理后可批量操作审批任务。
- 审批任务可通过薪福通 App、微信公众号或 PC 端待办通知。

### 委托、批量与管理员处理

- 委托审批需要具备 OA 审批委托权限；管理员可为审批人设置委托。
- 批量发起一次只能针对一个审批表单，且需先开启批量审批管控。
- 管理员审批用于处理部分异常审批任务；列表只展示操作人有权限的数据。

### 审批人变更

- 审批中的临时变更通过原审批人转派或管理员数据管理处理。
- 长期变更按审批人来源调整：审批管理员或审批角色通过数据管理变更；组织负责人或审批主管通过组织架构变更；汇报上级、成员组、岗位或职位通过对应成员或花名册信息变更。

## 动态流程与自动化

### 动态流程

开启动态流程后，系统在每个审批节点实时计算并更新审批人员及路径。适用于人员角色或岗位变更，或表单数据随业务变化的场景。

示例：采购审批中，采购金额变化可使后续处理人从行政变为分管领导；该示例只说明系统会根据变化重新计算后续路径，不定义采购金额规则。

### 自动化任务

自动化任务可在审批流程到达任意环节或结束后触发：

1. 发起审批：自动发起新的审批流程，并带入关键信息。
2. 更新业务数据：更新花名册、假勤外出记录或低代码平台连接器；现有能力要求配置员工唯一标识，例如员工号。
3. HTTP 请求：将审批状态或数据通过 API 同步至企业其他系统。

## 子流程与数据管理

### 子流程

- 子流程适用于集团或连锁企业中分子公司、部门共用同一张表单但独立管理流程的场景。
- 主流程管理员新增子流程并配置对应的子流程管理员。
- 子流程管理员仅查看有权限的子流程，并可独立调整子流程配置。
- 主流程引用子流程后，子流程调整会被主流程引用最新配置。
- 员工提交时，系统按主流程和子流程共同计算审批人。

### 数据管理与审批角色

- 数据管理仅管理员可用。
- 当审批人已离职或暂时无法处理待审批单据时，可通过流程转派将流程交给其他审批人，支持批量或单个转派。
- 流程交接可将审批管理员、审批角色或审批人从 A 替换为 B。
- 企业可建立审批角色；同一角色中的成员可分别设置分管部门。不同项目有不同负责人时，可按项目负责人等角色形成差异化审批范围。
