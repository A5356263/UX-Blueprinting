# 项目背景

## 这是什么

这是项目背景知识库的二级路由入口，用来说明这个目录里各编号段分别承载什么知识、遇到什么问题该优先看哪些文件。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应编号文件中。


## 领域契约

### 领域定义

项目背景领域回答的是：
薪福通平台是什么、面向谁、覆盖哪些能力、具备什么优势。

它覆盖的不是单一产品功能，而是一整套与平台定位和产品认知相关的业务语义，包括：

- 产品定位：平台的核心定位与价值主张
- 平台角色与终端：谁在使用平台、通过什么终端
- 产品能力版图：平台覆盖的能力范围
- 产品优势与服务模式：平台的差异化优势和服务方式
- 管理控制台能力概览：管理后台的能力全景

### 解决的问题

项目背景领域主要用于解释以下问题：

- 薪福通是什么、解决什么问题
- 平台的用户角色和终端有哪些
- 平台覆盖哪些业务能力
- 平台相比竞品有什么优势
- 管理控制台提供哪些管理能力

### 为什么独立成域

项目背景需要独立沉淀，是因为它同时具备以下特征：

- 提供平台的全局认知基础，是所有业务域知识的起点
- 产品定位、角色终端、能力版图等信息需要在各业务域之间保持一致
- 对应"认识薪福通"相关知识体系，是新人理解和业务分析的基础输入

### 稳定结论

- 项目背景是平台全局认知的承载域
- 其核心价值是为产品定位、角色终端、能力版图、产品优势和管理后台全景提供稳定输入
- 它可以服务业务分析、产品设计、体验解释和排障分析，但本文件本身不承载下游消费说明

### 显式缺口

- [QUESTION] 产品能力版图是否随产品迭代保持更新，需持续关注
- [QUESTION] 平台角色与终端分类是否已完全覆盖当前产品状态，需持续校验

## 使用边界

- 本域只用于建立产品全局背景、角色终端与能力版图，不替代任何业务域的对象、规则、状态、页面或异常事实
- 需求已能确定业务主域时，不得因需要“了解背景”默认读取本域；只有产品定位或全局能力边界确实影响判断时才按命中章节补读

## 维护原则

- README 只承载领域契约与领域内路由，不展开具体业务规则正文
- 正式业务事实写入对应编号文件
- 不在本目录中写具体后台配置规则和页面实现细节
- 不在本目录中沉淀主链路消费地图、蓝图移交说明或下游执行指令
- 做结构替换时不保留兼容层，确认替换后直接移除旧知识位
