# 成员管理

## 这是什么

这是成员管理领域的二级路由入口，用来说明这个目录里各编号段分别承载什么知识、遇到什么问题该优先看哪些文件。

本 README 承载领域契约与任务路由；具体业务规则仍保留在对应编号文件中。


## 领域契约

### 领域定义

成员管理领域回答的是：
谁是企业成员、成员如何进入和退出企业、成员如何分组、外部人员如何治理。

它覆盖的不是单一成员记录，而是一整套与成员身份和生命周期相关的业务语义，包括：

- 成员加入与邀请：手机号邀请、二维码/链接邀请、快速加入企业
- 成员退出与离职交接：停用、退出流程
- 成员分组：按岗位、职位、法人公司等维度配置规则自动归属
- 外部人员：外部人员管理与转换

### 解决的问题

成员管理领域主要用于解释以下问题：

- 成员如何加入企业（邀请方式、加入路径）
- 成员如何退出企业、离职交接如何处理
- 成员如何分组、分组规则如何配置
- 外部人员如何管理、如何转为内部成员
- 第三方同步（钉钉、企业微信、飞书）如何影响成员数据
- 成员域与组织域、权限域的边界是什么

### 为什么独立成域

成员管理需要独立沉淀，是因为它同时具备以下特征：

- 在平台组织重构后，成员已从组织模块独立出来成为独立模块
- 成员承载的是成员主体与身份关系，不是组织主数据
- 成员可通过挂载关系接入多维组织，但成员模块本身不并入组织域
- 成员是权限主体的核心载体

### 不覆盖

- 组织主数据或平台组织底座建模（保留在 `knowledge/raw/业务/组织架构/`）
- 员工在职数据管理（保留在 `knowledge/raw/业务/人事服务/员工管理/`）

### 与上游领域的关系

- 成员可通过挂载关系接入多维组织，组织域提供组织底座
- 第三方同步（钉钉、企微、飞书）作为成员数据来源
- 成员是权限域的主体输入

这里描述的是上游依赖事实，不等于具体规则已经由其他领域定义完成。

### 稳定结论

- 成员管理是平台成员身份和生命周期管理的核心域
- 在平台组织重构后，成员与组织已实现模块分离，成员独立承载身份主体
- 其核心价值是为成员接入、退出、分组和外部人员治理提供稳定输入
- 它可以服务业务分析、产品设计、体验解释和排障分析，但本文件本身不承载下游消费说明

### 显式缺口

- [QUESTION] 第三方同步（钉钉/企微/飞书）的同步机制和边界条件是否已完全清晰，需持续校验
- [QUESTION] 成员分组规则配置的灵活度和限制是否已完全稳定

## 与组织域的关系

成员是独立模块，不再与组织模块混写。成员承载的是成员主体与身份关系，可通过挂载关系接入多维组织。

## 条件依赖与回主域

- 成员加入、退出、分组和外部人员治理以本域为主；多维组织挂载与范围生成补读组织架构，员工花名册、合同和任职异动补读人事服务/员工管理
- 需求涉及成员作为权限主体时补读权限管理，但授权规则和生效结果归权限域
- 成员退出涉及审批任务转派或流程交接机制时补读审批管理；普通成员退出不因“交接”一词读取完整审批域
- 读完依赖域后必须回到本域确认成员身份、生命周期与分组结果；未命中上述条件时不扩读
