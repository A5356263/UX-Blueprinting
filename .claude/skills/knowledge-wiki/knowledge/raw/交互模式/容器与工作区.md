# 容器与工作区模式库

Phase 1 在候选生成阶段按需读取（用于校准候选空间结构名称、适用边界和失败代价），Phase 2 同样可按需读取（用于展开落地手段）。

**使用方式**：在 UX 最优解写定后、候选生成阶段，用于校准候选容器/工作区方案、识别反例和失败代价。不替代当前项目材料形成固定结论。

**阅读提醒**：以下容器选择条件是启发式信号，不是硬阈值。字段数、条目数、区域数量只用于初筛；最终仍应回到任务复杂度、是否需要保留原页面信息、风险等级和返回原任务的要求判断。

**装配要求**：选中容器或工作区模式后，必须结合当前业务证据写清触发入口、需要保留的上下文、核心区域与操作、成功或失败时的关闭规则、返回位置和相近模式的排除原因；不得只写“使用抽屉”“使用工作台”。

**配套文件**：入口编排见 [入口与导航.md](入口与导航.md)；状态、反馈、异常恢复和回流见 [状态、反馈与恢复.md](状态、反馈与恢复.md)。

## 基础容器

### 独立页面
**激活方式**：路由下钻  
**适用**：字段较多、包含文件上传，或列表/详情/看板等需要完整页面空间；操作完成后通常不需要回到原页面  
**不适用**：操作与当前页面强相关且信息量中等时更可优先比较抽屉；仅需确认无需填写时更可优先比较弹窗

### 弹窗
**激活方式**：弹窗覆盖  
**适用**：需要强制用户响应；确认型（操作不可撤销或影响范围广）；表单较轻；支撑对象维护动作规模较小  
**不适用**：字段明显偏多、信息密度高时更可优先比较抽屉或独立页面；管理条目规模持续扩大时更应比较独立页面  
**注意**：弹窗内可以有内联校验、实时计算、联动下拉等复杂交互，不能以"含复杂交互"为由升级为独立页面

### 抽屉
**激活方式**：侧边滑出  
**适用**：操作与当前页面内容强相关；完成后需要回到当前页面或原位置；表单复杂度中等  
**不适用**：字段和结构明显偏重、包含主从表格或深层编辑时更可优先比较独立页面；无需填写只需确认时更可优先比较弹窗

### 对象选择与回填
**适用**：任务需要从候选对象中浏览、搜索、筛选或选择，并将结果带回当前主任务。
**默认组织**：主任务提供选择入口 → 保留当前主任务 → 打开选择模态弹窗 → 浏览、搜索、筛选、选择候选对象 → 确认选择 → 关闭选择模态弹窗 → 返回主任务 → 回填已选摘要 → 继续提交主任务。
**直接选择**：输入已列出全部候选，且任务不需要搜索、筛选、分类浏览或查看详情时，主任务直接承载选择项。一次可选数量使用正式业务输入。
**复用边界**：已有复用选择器时，沿用其已有承载方式和返回规则。
**不承担**：本模式不决定候选范围、单选多选、业务校验或对象可用性。

### 全屏弹窗
**激活方式**：全屏覆盖  
**适用**：复杂编辑，任务完成后必须回到触发页面；包含多功能区域的复杂工具类编辑器  
**不适用**：任务完成后不需要回到原页面（直接用独立页面）

### Tab 页签
**激活方式**：页签切换  
**适用**：同一模块有少量平级子视图；各子视图内容性质相近，用户需要频繁切换  
**不适用**：子视图过多或性质差异大，导致页签本身成为理解负担

### 嵌入区块
**激活方式**：页内折叠/展开  
**适用**：低频查看的辅助信息或高级配置项；折叠后不影响主流程  
**不适用**：内容是主流程必须填写的字段

### 左右分栏
**激活方式**：分栏并排  
**适用**：用户需要同时查看两份相关内容（列表 + 详情预览）；频繁的主从切换  
**不适用**：屏幕宽度不足（移动端）；两侧内容无强关联

## 工作区模式

适用于需要多区域协作的复杂任务。这些模式属于后置校准知识，初步判断形成后用于比较候选，不直接推出固定布局结论。

### 多区协作工作台
**适用**：用户需要在同一任务中持续对照多个对象/区域/状态；既有主操作区，也有必须同步可见的来源对象/说明区/结果区；切换页面/弹窗会显著打断判断链  
**不适用**：任务本质是单对象短操作；关键信息可以自然分步处理；窄屏或移动端  
**失败代价**：区域过多分散注意力；把低频管理动作并排抬高稀释主线  
**常见误用**：直接等同于固定三栏，而不先判断哪些对象必须并行可见  
**可比较替代**：主从协作工作台、左右并行分区、上下堆叠工作区、独立整页编辑器

### 主从协作工作台
**适用**：用户需要先定位对象，再对选中对象做查看/编辑/核对；主对象集合稳定存在，详情区随选中项变化；经常在多对象间往返或逐条处理  
**不适用**：当前任务不是围绕对象集合逐条处理；对象很少或详情处理很重  
**失败代价**：若对象需要并排比较，单一主从会让比较成本上升  
**常见误用**：把真正需要并列比较的多对象压成单一主从

### 左右并行分区
**适用**：两侧内容都有持续价值且用户需要高频对照；屏幕宽度足够；天然横向分工（如来源对象 + 编辑对象、输入区 + 结果区）  
**不适用**：其中一侧只在少数时刻需要；移动端/窄屏；任务更依赖纵向流程推进  
**失败代价**：若两侧都过重，造成窄列、拥挤和扫读困难

### 上下堆叠工作区
**适用**：主任务按纵向顺序推进；屏幕高度可用于分配多区块；结果/说明/历史信息需同页保留但无需长期左右对照  
**不适用**：用户必须频繁在两区域来回对照（滚动打断判断）；上下区块都很重导致首屏看不到主任务  
**失败代价**：滚动距离过长时，上下关联记忆变差

### 独立整页编辑器
**适用**：主任务是单对象深度编辑，完成后不依赖原页面信息；任务包含较多模块/规则/长链编辑  
**不适用**：编辑判断依赖来源对象/结果预览持续可见；完成后需要立即延续原任务链  
**失败代价**：离开原页面后回忆成本变高；若缺少明确返回路径，用户难以继续原任务链  
**常见误用**：把所有复杂任务都升级成整页，不判断离开原页面的代价

### 保留原页信息的编辑器
**适用**：编辑过程中需要持续回看来源信息/规则/结果预览；完成后通常需要回到触发场景继续处理  
**不适用**：任务已是独立闭环，不需要原页面信息；关键背景信息可以通过少量摘要带入  
**失败代价**：保留的信息不对，用户仍要来回切换；过度保留会压缩编辑区  
**常见误用**：全屏覆盖 ≠ 保留原页信息；把所有辅助信息塞进常驻侧栏

### 任务辅助面板
**适用**：规则说明/历史/次级管理动作与主任务紧密相关但不应常驻；完成辅助动作后应回到主任务  
**不适用**：辅助内容已成为独立高频任务；用户需要长时间并行查看  
**失败代价**：关键内容被错误后置到辅助面板，主路径遗漏重要信息  
**常见误用**：把低频管理动作提升为页面同层主入口

### 结果核对面板
**适用**：任务包含公式/规则/配置/差异分析等即时判断需求；用户在提交前就要知道结果是否通过  
**不适用**：结果只需最终成功反馈，不需要中途核对；当前阶段主要目标是收集输入  
**失败代价**：结果核对被后置，用户在错误路径上走得更远才发现问题

## 取舍提醒（容器与工作区）

**不宜独立页：原页面关键信息必须持续可见**  
当主任务判断依赖来源对象/规则/实时结果持续可见时，切走原页面会让用户失去比较对象和处理进度，折返和记忆成本上升。应考虑：保留原页信息的编辑器、多区协作工作台、左右并行分区、全屏弹窗。

**不宜只扩大编辑区：问题来自多对象协作，不只是空间不足**  
当真实负担来自对象定位/对象关系/结果核对和编辑协同时，扩大编辑区只解决视觉问题，核心摩擦未被解决。应考虑：多区协作工作台、主从协作工作台、结果核对面板、任务辅助面板。
