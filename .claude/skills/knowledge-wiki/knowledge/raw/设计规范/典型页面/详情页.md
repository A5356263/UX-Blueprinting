## Detail Page Assets 详情页设计资产


> 分类：典型页面 / 详情页  
> 适用系统：XFT Design 6.0  
> 适用范围：B 端系统详情页，包括合同详情、报账详情、对账详情、付款详情、申请详情、审批详情、客户详情、员工详情、供应商详情、设备详情等。  
> 资产用途：供页面生成 Skill 检索详情页模式、详情模块、布局规则、列数规则、操作记录规则和底部操作规则。

### 1. 详情页资产总览

详情页用于展示单个业务对象的完整信息。详情页必须帮助用户快速识别当前对象，并理解该对象的基础字段、业务状态、关联明细、审批流程、操作记录和可执行操作。

详情页不是单一模板，而是由以下维度组合生成：

- 布局维度：左右布局、上下布局
- 内容表达维度：基础样式、表格样式
- 字段密度维度：单列、双列、多列
- 承载维度：页面承载、抽屉承载
- 公共增强模块：详情头、锚点、分组标题、审批流、关联表格、操作记录、底部汇总、底部操作

详情页必须至少包含一种核心字段展示模块：

- Description List Module 描述列表模块
- Table-like Detail Grid Module 表格化详情网格模块

详情页不能只有明细表格，而缺少业务对象的基础字段。

#### 核心约束：详情页布局与提单表单保持一致

**详情页的布局（上下/左右）必须与提单时的表单布局一致，不允许变化。**

| 提单表单布局 | 详情页布局 | 说明 |
|------------|-----------|------|
| 左右布局 | 左右布局 | 保持一致，用户在同一视觉框架下对照查看 |
| 上下布局（自定义表单） | 上下布局 | 保持一致，不因从编辑态切换到查看态而改变信息架构 |

此约束的目的：用户在提单时习惯的字段排列方式和阅读动线，在查看详情时不应被改变。从填写到查看应保持信息结构的一致性。

### 2. 页面模式资产

#### 2.1 Split Basic Detail Pattern 左右布局基础样式详情

左右布局基础样式详情适用于以描述列表为主体，同时右侧需要展示审批流、状态流、操作记录或辅助信息的详情页。

适用场景：

- 申请详情
- 审批详情
- 报账详情
- 对账详情
- 采购付款详情
- 基础单据详情
- 需要右侧流程辅助区的详情页

结构顺序：

1. Breadcrumb 面包屑
2. Detail Hero Header 详情头，可选
3. Horizontal Anchor 或 Vertical Anchor 锚点，可选
4. Left Description Sections 左侧描述列表区域
5. Right Approval / Status / Operation Aside 右侧审批流、状态流或操作记录辅助区
6. Footer Summary / Footer Action 底部汇总或底部操作区，可选

必需模块：

- Description List Module

可选模块：

- Detail Hero Header Module
- Horizontal Anchor Module
- Vertical Anchor Module
- Detail Section Title Module
- Approval Flow Module
- Operation Record Module
- Footer Summary Module
- Footer Action Module
- Footer Summary Action Module

布局规则：

左侧是主详情内容区，使用描述列表承载基础字段。右侧是辅助信息区，适合展示审批流、状态流、操作记录、风险提示等。右侧区域不应承载复杂表格、复杂字段网格或主内容模块。

列数规则：

左右布局下，主内容区默认使用双列描述列表。字段值较长、字段说明较多、字段类型为备注、地址、审批意见、原因说明时，应跨整行展示。左右布局中不建议默认使用多列。

校验规则：

- 必须包含描述列表
- 必须展示业务对象名称或业务编号
- 如果出现审批流，必须包含节点、处理人、状态和时间
- 右侧辅助区不能替代主详情区
- 长文本、附件、明细表格必须跨整行

常见错误：

- 不要把右侧栏做成复杂表格
- 不要缺少基础字段
- 不要所有字段无分组堆叠
- 不要把长文本强行塞进双列窄区域

#### 2.2 Stacked Basic Detail Pattern 上下布局基础样式详情

上下布局基础样式详情适用于按顺序阅读多个信息分组的详情页，主体以描述列表为主。

适用场景：

- 合同详情
- 客户详情
- 员工详情
- 供应商详情
- 设备详情
- 项目详情
- 档案详情
- 不需要右侧固定辅助区的详情页

结构顺序：

1. Breadcrumb 面包屑
2. Detail Hero Header 详情头，可选
3. Horizontal Anchor 或 Vertical Anchor 锚点，可选
4. Description Sections 描述信息分组
5. Related Records 关联记录，可选
6. Operation Record 操作记录，可选
7. Footer Summary / Footer Action 底部汇总或底部操作区，可选

必需模块：

- Description List Module

可选模块：

- Detail Hero Header Module
- Horizontal Anchor Module
- Vertical Anchor Module
- Detail Section Title Module
- Related Detail Table Module
- Operation Record Module
- Footer Summary Module
- Footer Action Module

布局规则：

页面内容从上到下排列，每个信息分组可以独立选择单列、双列或多列。上下布局拥有完整横向空间，适合承载更多字段和更宽的明细表格。

列数规则：

上下布局默认使用双列。字段数量少或字段值较长时使用单列。字段值短、页面宽度充足、字段数量较多时可使用多列。多列最多 3 列。不同分组可以使用不同列数。

校验规则：

- 必须包含描述列表
- 必须有清晰分组或明确字段阅读顺序
- 长文本、附件、明细表格必须跨整行
- 多个分组时建议展示分组标题

常见错误：

- 不要大量字段无标题堆叠
- 不要所有分组机械使用同一列数
- 不要将长文本压缩到多列窄区域
- 不要缺少页面对象名称或业务编号

#### 2.3 Split Table-like Detail Pattern 左右布局表格样式详情

左右布局表格样式详情适用于字段较多、字段边界需要强区分，并且右侧存在审批流、状态流或操作记录的单据型详情页。

适用场景：

- 报账单详情
- 对账单详情
- 付款单详情
- 采购单详情
- 审批单详情
- 合同付款详情
- 字段多且需要强边界分隔的流程单据详情

结构顺序：

1. Breadcrumb 面包屑
2. Detail Hero Header 详情头，可选
3. Horizontal Anchor 横向锚点，可选
4. Left Table-like Detail Grid 左侧表格化详情网格
5. Related Detail Tables 关联明细表格，可选
6. Right Approval Flow / Operation Record 右侧审批流或操作记录，可选
7. Footer Summary / Footer Action 底部汇总或操作区，可选

必需模块：

- Table-like Detail Grid Module

可选模块：

- Detail Hero Header Module
- Horizontal Anchor Module
- Approval Flow Module
- Operation Record Module
- Related Detail Table Module
- Footer Summary Module
- Footer Action Module
- Footer Summary Action Module
- Detail Section Title Module

布局规则：

左侧承载表格化详情网格和关联明细表格。右侧承载审批流、状态流、操作记录或风险提示。右侧辅助区域不应承载复杂表格或主详情字段网格。

视觉规则：

- label 和详情信息通过分割线分隔显示
- label 单元格使用浅灰背景
- value 单元格使用白色背景
- 单元格 padding 为上下 8px、左右 12px
- label 背景可使用 `#f3f4f6` 或 `--color-layout-bg-neutral-gray`
- value 背景使用 `--color-container-bg-neutral-bright`
- 分割线使用 `--color-divider-neutral`

列数规则：

左右布局中，表格化详情网格默认不超过双列。字段值较长时使用单列或跨整行。右侧存在审批流时，左侧主内容最多双列。左右布局中不建议使用多列。

校验规则：

- label 和 value 必须清晰分隔
- 长文本、附件、明细表格必须跨整行
- 右侧栏不得放复杂详情网格或大型数据表格
- 必须展示业务对象名称或编号
- 如果包含审批流，审批流必须包含节点、处理人、状态和时间

常见错误：

- 不要在左右布局中强行三列
- 不要把明细表格塞入 value 单元格
- 不要让 label 背景和 value 背景没有区分
- 不要把右侧审批栏做成主内容区

#### 2.4 Stacked Table-like Detail Pattern 上下布局表格样式详情

上下布局表格样式详情适用于页面宽度充足、字段较多、需要规整展示的单据型或审批型详情页。

适用场景：

- 合同付款信息
- 付款条款
- 对账明细
- 费用明细
- 采购明细
- 申请单详情
- 审批单详情
- 字段多且需要规整展示的单据型详情页

结构顺序：

1. Breadcrumb 面包屑
2. Detail Hero Header 详情头，可选
3. Horizontal Anchor 或 Vertical Anchor 锚点，可选
4. Table-like Detail Sections 表格化详情分组
5. Related Detail Tables 关联明细表格，可选
6. Operation Record 操作记录，可选
7. Footer Summary / Footer Action 底部汇总或操作区，可选

必需模块：

- Table-like Detail Grid Module

可选模块：

- Detail Hero Header Module
- Horizontal Anchor Module
- Vertical Anchor Module
- Detail Section Title Module
- Related Detail Table Module
- Operation Record Module
- Footer Summary Module
- Footer Action Module
- Footer Summary Action Module

布局规则：

上下布局拥有完整横向空间，适合展示双列或三列表格化详情网格。每个分组可以根据字段数量和字段长度单独决定列数。关联明细表格必须独占整行。附件、长文本、备注、说明、审批意见等内容必须跨整行。

视觉规则：

- label 和详情信息通过分割线分隔显示
- label 单元格使用浅灰背景
- value 单元格使用白色背景
- 单元格 padding 为上下 8px、左右 12px
- label 背景可使用 `#f3f4f6` 或 `--color-layout-bg-neutral-gray`
- value 背景使用 `--color-container-bg-neutral-bright`
- 分割线使用 `--color-divider-neutral`

列数规则：

默认使用双列。字段较多且字段值短时可使用三列。多列最多 3 列。不同分组可以采用不同列数。长文本、附件、明细表格必须跨整行。

校验规则：

- 多列最多 3 列
- 不同字段类型应决定是否跨列
- 多个分组必须有分组标题
- 明细表格必须独占整行
- label 和 value 必须视觉区分明确

常见错误：

- 不要所有分组机械使用三列
- 不要让长文本在三列中被压缩
- 不要缺少分组结构
- 不要将数据表格误做成 label-value 字段网格

### 3. 公共模块资产

#### 3.1 Detail Hero Header Module 详情头模块

详情头用于突出当前详情对象的身份信息。

适用场景：

当详情对象需要突出名称、状态、申请人、负责人、编号、供应商、金额等核心信息时使用。适合单据、申请、审批、报账、合同、采购、付款、对账等对象。

结构顺序：

1. 图标或视觉元素
2. 对象名称
3. 状态标签
4. 核心元信息
5. 可复制编号或附属信息

规则：

详情头位于页面顶部。可以使用轻背景或背景图突出，但必须保持克制。核心名称优先，附属信息弱化。字段不要超过 5 个。

#### 3.2 Description List Module 描述列表模块

描述列表模块是基础样式详情的核心模块，用于展示业务对象的核心字段。

规则：

页面承载默认双列，抽屉承载默认单列。长文本、附件、明细表格必须跨整行。字段很多时按业务分组展示。

#### 3.3 Table-like Detail Grid Module 表格化详情网格模块

表格化详情网格用于字段较多、字段边界需要强区分的详情页。

规则：

label 和 value 通过分割线分隔，label 使用浅灰背景，value 使用白底。cell padding 为上下 8px、左右 12px。它是字段详情展示方式，不是真正的数据表格。

#### 3.4 Related Detail Table Module 关联明细表格模块

关联明细表格用于展示关联借款、付款条款、对账明细、对账记录、商品明细、费用明细等多行数据。

规则：

关联明细表格必须独占整行。左右布局中应放在左侧主内容区，不放在右侧审批流区域。它是真正的数据表格，不是表格化详情网格。

#### 3.5 Approval Flow Module 审批流模块

审批流用于展示审批节点、审批人、审批状态、审批时间、审批意见和评论。

规则：

左右布局中优先放在右侧辅助区。上下布局中可以放在详情信息之后。审批流必须包含节点名称、处理人、状态和时间。当前节点必须可识别。

#### 3.6 Operation Record Module 操作记录模块

操作记录用于展示详情对象的修改历史、操作日志、变更记录或审计记录。

适用场景：

当业务对象存在修改历史、操作审计、字段变更、状态变更、审批操作、系统操作或人工操作记录时使用。

操作记录有两种展示方式：

第一种是操作信息较多时，使用摘要表格加详情入口。摘要表格展示修改人、修改时间和详情入口。点击详情后展示操作记录详情表格，详情表格包含修改模块、原信息、修改后信息、修改人、修改时间。

第二种是单点操作时，直接单行展示，不强制提供详情入口。单行记录需要完整表达操作对象、操作内容、操作人和操作时间。

规则：

- 操作记录不是必需模块，应根据业务需求展示
- 当存在操作记录时，必须至少展示操作人和操作时间
- 当一条操作记录包含多项变更时，应提供详情入口
- 当一条操作记录只是单点操作时，可以单行展示，不需要详情入口
- 操作详情中必须体现原信息与修改后信息的对比
- 操作记录应按时间倒序或业务指定顺序排列

常见错误：

- 不要每一条单点操作都强制生成详情链接
- 不要把复杂多字段变更压缩成单行展示
- 不要只展示修改后信息而缺少原信息
- 不要缺少操作人或操作时间

#### 3.7 Horizontal Anchor Module 横向锚点模块

横向锚点用于详情页内分组定位，视觉样式可接近 Tabs，但交互不是内容切换。

规则：

点击锚点后应滚动到对应分组，而不是隐藏其他分组内容。锚点名称必须与分组标题一致。

#### 3.8 Vertical Anchor Module 纵向锚点模块

纵向锚点用于分组较多、页面较长、左侧有足够空间的详情页。

规则：

点击后滚动定位到对应分组，滚动时可同步激活当前锚点。不要把纵向锚点做成系统主导航。

#### 3.9 Detail Section Title Module 分组标题模块

分组标题用于区分详情页中的多个信息区域。

规则：

多个分组时建议使用分组标题。标题必须准确描述下方内容。可折叠时必须有明确状态。

#### 3.10 Footer Summary Module 底部汇总信息模块

底部汇总用于展示金额、数量、费用或条目统计。

规则：

可单独展示。汇总信息必须包含标签、值、单位或币种。不要只显示金额数字不显示含义。

#### 3.11 Footer Action Module 底部操作按钮模块

底部操作按钮用于承载详情页页面级操作，例如保存、提交、撤回、打印、取消、关闭、去付款、转交、更多操作。

规则：

当仅展示操作按钮且没有汇总信息时，操作按钮在页面底部居中展示。按钮数量不宜过多。危险操作必须二次确认。

#### 3.12 Footer Summary Action Module 底部汇总与操作组合模块

底部汇总与操作组合用于同时展示汇总信息和页面级操作。

规则：

当底部同时存在汇总信息和操作按钮时，汇总与操作作为一个整体左对齐展示。汇总信息在前，操作按钮在后。

### 4. 列数适配规则

#### 4.1 单列

单列适用于抽屉详情、窄容器、字段值较长、备注说明较多、移动端适配或需要顺序阅读的详情页。

规则：

- 抽屉详情默认单列
- 长文本字段必须单列或跨整行展示
- 附件、图片、凭证、明细表格必须跨整行或独立分组

#### 4.2 双列

双列是页面详情的默认推荐方案，适用于字段数量中等、字段值较短、需要兼顾信息密度和可读性的 B 端详情页。

规则：

- 页面承载的基础详情默认双列
- 页面承载的表格详情默认双列
- 左右布局中主内容区默认最多双列

#### 4.3 多列

多列适用于上下布局、宽屏页面、字段很多且字段值较短的场景。多列通常最多 3 列。

规则：

- 上下布局可使用多列
- 左右布局不默认使用多列
- 多列最多 3 列
- 长文本、附件、明细表格不得放入多列窄格

### 5. 跨列规则

以下内容必须跨整行或独立成组展示：

- 备注
- 说明
- 原因
- 地址
- 审批意见
- 规则描述
- 异常说明
- 附件
- 图片
- 凭证
- 明细表格
- 关联表格
- 操作记录详情表格

### 6. 锚点规则

横向锚点和纵向锚点都是页内定位，不是 Tab 内容切换。

当点击锚点时，应滚动定位到对应详情分组，而不是隐藏其他分组。锚点名称必须与页面分组标题一致。

### 7. 操作记录规则

操作记录是详情页公共模块，不是必需模块。

当操作信息较多，或一条记录包含多个字段变更时，使用“操作记录摘要表格 + 详情入口 + 操作记录详情表格”。

操作记录摘要表格推荐字段：

- 修改人
- 修改时间
- 修改详情

操作记录详情表格推荐字段：

- 修改模块
- 原信息
- 修改后信息
- 修改人
- 修改时间

当操作信息较少，或仅为单点操作、单字段变更、简单状态变更时，可直接单行展示，不强制提供详情入口。

单点操作记录推荐字段：

- 操作模块或操作类型
- 操作内容
- 操作人
- 操作时间

### 8. 底部汇总与操作规则

详情页底部可以展示汇总信息、操作按钮，或者两者同时展示。

当仅展示汇总信息时，汇总信息可单独左对齐展示。

当仅展示操作按钮时，按钮组应在页面底部居中展示。

当汇总信息和操作按钮同时出现时，汇总与按钮应作为一个整体左对齐展示。汇总信息在前，操作按钮在后。

危险操作如撤回、取消、删除、驳回、重置等，必须二次确认，并说明影响范围。

### 9. Token 与视觉规则

详情页遵循 XFT 企业级后台设计系统，整体保持清晰、克制、信息密度高。

页面背景使用 `--color-layout-bg-neutral-gray`。  
主内容表面使用 `--color-container-bg-neutral-bright`。  
主按钮使用 `--color-bg-accent-regular`。  
说明文字使用 `--color-text-neutral-gray30`。  
正文值使用 `--color-text-neutral-gray50`。  
分割线使用 `--color-divider-neutral`。  
状态使用 success、warning、error、info 等语义 token。

表格化详情网格中，label 背景使用 `#f3f4f6` 或 `--color-layout-bg-neutral-gray`，value 背景使用 `--color-container-bg-neutral-bright`。单元格 padding 为上下 8px、左右 12px。
