# 场景模式

## 这是什么

这是场景模式设计规范的二级路由入口，用来解释跨组件任务的触发条件、处理路径、状态反馈、异常与恢复方式。

本 README 承载场景分类契约与任务路由；具体场景规则保留在对应主题文件中。

## 分类契约

### 分类定义

场景模式回答的是：用户为完成一类稳定任务，在什么条件下进入，依次经历哪些步骤，系统如何反馈状态，以及失败后如何恢复。

### 解决的问题

- 当前需求是否属于一个跨组件任务
- 任务从哪里开始、如何推进和结束
- 处理中、成功、失败和中断状态如何反馈
- 大批量、异步或高风险任务如何避免误操作
- 任务需要依赖哪些页面和组件承载

### 为什么独立成类

- 场景跨越多个组件，不能由单个组件规则完整表达
- 场景具有稳定的任务顺序、状态和恢复路径
- 同一场景可以出现在不同业务页面中，不应绑定单个页面

### 与相邻分类的关系

- 组件提供场景中的输入、展示、反馈和操作载体
- 典型页面提供场景所在页面的整体结构
- 补读组件或页面后，任务路径、状态、结果和恢复方式必须回到本分类确认

### 稳定结论

- 每个场景文件只承担一个可独立触发和回答的任务对象
- 全屏、审批流、图片裁剪和拖拽排序分别成文，不建立混合场景文件
- 与已有查询、异步或批量任务相同的来源片段合并到已有主题，不创建重复正文

### 显式缺口

- [GAP] 部分场景材料缺少异常分支、退出条件或恢复路径

## 任务触发索引

- 搜索、筛选、筛选项配置或高级筛选：读 `查询与筛选.md`
- 数据导入、数据导出、字段校验或结果反馈：读 `导入导出.md`
- 大批量文件上传、下载、任务面板或批量进度：读 `批量上传下载.md`
- 后台处理、任务浮窗、任务通知或任务记录：读 `异步任务.md`
- 隐藏导航、最大化内容区域或退出全屏：读 `全屏.md`
- 审批节点、审批状态、转办、驳回或撤回：读 `审批流.md`
- 图片缩放、比例、旋转、镜像或裁剪框：读 `图片裁剪.md`
- 列表、表格、标签或模块顺序调整：读 `拖拽排序.md`
- 查询跨场景通用间距、遮罩、反馈和降噪约束：读 `场景通则.md`

## 条件依赖与回主类

- 命中控件结构、尺寸或状态时补读组件；命中页面整体布局时补读典型页面
- 相邻分类只补充场景承载所需事实；最终触发条件、任务步骤、状态、结果和恢复方式必须回到本分类确认

## 维护原则

- README 只承载分类契约和路由，不展开场景正文
- 一个场景文件只维护一个稳定任务对象
- 已有同对象主题时合并来源片段，不建立近义重复文件
- 不建立“其他场景”“补充场景”等兜底文件
- 来源缺少异常或恢复信息时记录 `[GAP]`，不得自行补造

- 未命中组件或页面依赖时不扩读相邻分类；未定位到场景时记录 `[GAP]`
- 补读组件或页面后必须回到本分类确认任务路径、状态、结果、恢复方式与已知缺口
