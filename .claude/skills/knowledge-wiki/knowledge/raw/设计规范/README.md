# 设计规范

## 这是什么

这是设计规范领域的总路由入口，用来说明本领域承载什么知识、不同设计问题应进入哪个分类，以及什么时候需要补读相邻知识。

本 README 承载领域契约与分类路由；具体设计事实保留在样式、组件、典型页面和场景模式的主题文件中。

## 领域契约

### 领域定义

设计规范领域回答的是：当前产品在视觉样式、组件使用、页面组织和任务场景中，具体规定应该怎么做。

它记录可直接核对和执行的产品标准，包括：

- 视觉尺度与样式取值
- 组件结构、尺寸、状态和交互
- 稳定页面类型的整体结构
- 跨组件任务的步骤、状态、反馈和恢复

### 解决的问题

- 某个样式值、组件或页面结构是否符合当前产品标准
- 相近组件、页面或场景之间如何选择
- 页面应包含哪些区域和核心模块
- 任务如何开始、推进、结束并反馈异常
- 具体设计问题应读取哪个主题文件和章节
- 来源材料存在冲突或缺失时应如何停止和记录

### 为什么独立成域

- 设计规范回答具体标准，不等同于解释“为什么”的设计准则
- 设计规范记录当前产品事实，不等同于抽象一类任务的交互模式
- 规范事实需要可定位、可核对和可维护，不能散落在问答脚本、页面案例或业务文档中
- 样式、组件、页面和场景之间存在稳定依赖，需要统一路由而不是独立成信息孤岛

### 与相邻知识的关系

- 设计准则提供判断依据和价值取舍；设计规范提供当前产品的具体执行标准
- 交互模式提供通用任务组织方法；设计规范提供当前组件、页面和场景的具体规则
- 业务知识提供业务对象、规则、状态和权限；设计规范不定义业务事实
- 当具体规范与设计准则、交互模式或业务事实冲突时，标记 `[CONFLICT]`，不得静默覆盖

### 内部知识层级

- 样式：提供所有设计对象共同依赖的视觉基础
- 组件：提供可跨页面复用的结构与交互单元
- 典型页面：提供稳定页面类型的整体目标与组织方式
- 场景模式：提供跨组件、跨页面任务的步骤、状态和恢复路径

这些分类存在依赖，但不是固定阅读顺序。Agent 应从问题主体直接进入主分类，仅在命中明确依赖时补读相邻分类。

### 稳定结论

- 一个主题文件只承担一个可独立路由、回答和维护的稳定知识对象
- 文件名只表达核心对象，不重复上级目录已经表达的“规范”“组件”或“场景”语义
- README 负责契约和路由，主题文件负责唯一规范正文
- 样式当前统一维护在一个正文文件中；组件、页面和场景按稳定对象建立主题文件
- 原始材料的文件边界不决定正式知识边界

### 显式缺口

- [GAP] 部分旧材料缺少统一的产品版本、终端和适用范围标记
- [GAP] 部分场景缺少完整异常分支、退出条件和恢复路径
- [QUESTION] 设计变量是否需要同步维护机器可读 Token 真源，仍需确认

## 任务触发索引

- 间距、排版、颜色、圆角、投影、图标、分割线或基础布局：读 `样式/README.md`
- 按钮、导航、录入、展示、表格、反馈或页面头部组件：读 `组件/README.md`
- 表单页、详情页、表格页或报表页的整体组织：读 `典型页面/README.md`
- 查询筛选、导入导出、批量文件、异步任务、全屏、审批、裁剪或排序：读 `场景模式/README.md`
- 询问具体规则背后的判断依据或设计取舍：先定位本域具体规范，再补读设计准则
- 询问可跨产品复用的任务组织方法：先定位本域具体场景，再补读交互模式
- 询问业务对象、字段、状态、权限或业务流程：进入对应业务知识 README；设计规范不得替代业务事实

## 条件依赖与回主域

- 组件命中视觉取值时补读样式；页面命中控件细节时补读组件；场景命中页面承载或控件状态时补读典型页面或组件
- 命中设计理由时补读设计准则；命中通用任务组织时补读交互模式；命中业务规则时补读业务知识
- 相邻知识只补充当前判断所需输入；完成补读后必须回到设计规范确认当前产品采用的具体样式、组件、页面或场景标准

## 维护原则

- README 只承载领域契约和路由，不展开主题规则正文
- 正式规范事实写入对应主题文件，同一事实不得跨文件复制维护
- 新增、拆分、合并、重命名或移动主题时，必须同步更新根 README、分类 README、顶部导航和链接校验
- 旧 Skill 的检索脚本、回答模板、AI 提示和 CSV 决策表不得成为正式规范正文
- 输入信息不得摘要化；条件、数值、状态、例外、结构、步骤、反馈和恢复路径必须保留
- 无法确认的内容使用 `[GAP]`，矛盾内容使用 `[CONFLICT]`，不得自行补造

## 停止条件

- 命中任务所需的分类 README，并通过正式知识清单和主题顶部导航读完相关章节后停止
- 未命中条件依赖时不扩读相邻分类或相邻知识；README 未定位到正式主题时记录 `[GAP]`
- 读取相邻分类、设计准则、交互模式或业务知识后，必须回到本领域确认具体标准、适用范围、冲突与已知缺口
