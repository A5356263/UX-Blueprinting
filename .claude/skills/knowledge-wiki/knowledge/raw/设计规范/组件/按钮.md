## 按钮相关组件指南

### 1. 组件定义

按钮用于标记一个可触发的操作命令。用户点击按钮后，会触发相应的业务逻辑。

按钮通常用于页面提交、保存、确认、取消、返回、查询、重置、导出、下载、删除、编辑、打开详情、展开更多操作等交互场景。

按钮设计的核心目标是让用户明确知道：

- 当前有哪些操作可以执行；
- 哪个操作最重要；
- 操作会影响什么对象；
- 操作之间的主次关系是什么；
- 点击后是否会触发关键流程、危险行为或不可逆动作。

### 2. 核心原则

按钮设计应遵循以下原则：

1. 按钮必须服务于用户当前任务，不应堆叠无关操作。
2. 主操作应清晰可见，辅助操作应降低视觉权重。
3. 同一区域内按钮应形成明确的优先级。
4. 按钮数量应控制，避免干扰用户判断。
5. 高风险或不可逆操作必须与普通操作区分。
6. 操作按钮应靠近其作用对象，减少用户理解成本。
7. 相同类型、相同层级、相同场景的按钮样式应保持一致。
8. 按钮布局应符合阅读顺序、业务流程和视觉动线。
9. 按钮不应仅依赖颜色表达含义，需结合文案、位置、上下文共同传达。
10. 禁用、加载、悬停、点击等状态必须可感知。

### 3. 按钮优先级

按钮优先级用于定义操作的重要程度和视觉权重。

#### 3.1 P1 主操作

P1 是页面或模块中最重要的操作，通常是当前流程的主要推进动作。

常见场景：

- 提交
- 确认
- 保存
- 新建
- 下一步
- 完成
- 查询中的核心查询动作

推荐按钮类型：

- 主按钮

使用规则：

- 一个页面或一个核心操作区内，通常只保留一个 P1 主操作。
- P1 应具有最高视觉权重。
- P1 应出现在用户最容易发现的位置。
- P1 应尽量避免与多个同级主按钮并列。

#### 3.2 P2 次操作

P2 是辅助完成主流程的操作，重要性低于主操作，但仍然属于当前任务路径中的有效动作。

常见场景：

- 取消
- 返回
- 重置
- 上一步
- 次要提交
- 辅助配置

推荐按钮类型：

- 次按钮
- 默认按钮
- 幽灵按钮

使用规则：

- P2 可以与 P1 并列出现。
- P2 不应抢占 P1 的视觉焦点。
- P2 通常放在 P1 附近，但视觉权重低于 P1。

#### 3.3 P3 低频操作

P3 是用户可能会使用，但不是当前任务主路径的低频操作。

常见场景：

- 查看详情
- 编辑
- 复制
- 导出
- 下载
- 打开新页面
- 高级筛选
- 更多设置

推荐按钮类型：

- 文字按钮
- 链接按钮
- 图标按钮
- 下拉按钮

使用规则：

- P3 不应使用高视觉权重按钮。
- P3 可以放入更多菜单、下拉按钮或操作列中。
- P3 应避免与 P1、P2 形成视觉竞争。

#### 3.4 P4 风险操作

P4 是危险、不可逆或具有强影响的操作。

常见场景：

- 删除
- 停用
- 作废
- 清空
- 撤销重要动作
- 删除配置
- 终止流程

推荐按钮类型：

- 危险按钮
- 低权重危险文字按钮
- 二次确认弹窗中的危险主按钮

使用规则：

- P4 必须与普通操作明显区分。
- P4 不应默认作为主按钮放置。
- P4 应避免和高频正向操作放在一起。
- P4 通常需要二次确认。
- P4 如果在列表操作列中出现，建议使用低视觉权重形式，如危险文字按钮。
- 如果是批量危险操作，应谨慎使用，并明确告知影响范围。

### 4. 按钮组件构成

按钮由以下元素构成：

1. 按钮容器：承载点击区域、背景色、边框和状态。
2. 按钮文案：表达操作含义。
3. 图标：用于增强识别或表达动作。
4. 下拉箭头：表示还有更多操作。
5. 分裂区域：在分裂按钮中，将主操作与展开操作分开。
6. 加载图标：表示操作正在执行中。

#### 4.1 常规按钮

常规按钮由按钮容器和文字组成，可选配左侧图标或右侧图标。

适用场景：

- 表单提交
- 查询
- 重置
- 保存
- 取消
- 新建
- 页面级操作

#### 4.2 图标按钮

图标按钮以图标作为主要表达方式。

适用场景：

- 工具栏中的紧凑操作
- 表格右上角辅助工具
- 设置
- 刷新
- 打印
- 列配置
- 移动端底部导航或工具按钮

使用规则：

- 图标含义必须清晰。
- 必要时提供 Tooltip 说明。
- 不适合承载关键业务操作。
- 不适合表达复杂含义。
- 不应在无说明的情况下使用生僻图标。

#### 4.3 组合按钮

组合按钮由主按钮和下拉按钮组合而成，通常用于一个主操作附带多个相关扩展操作的场景。

适用场景：

- 主操作 + 更多操作
- 默认操作 + 其他操作
- 新建 + 导入
- 下载 + 下载模板
- 发布 + 定时发布

使用规则：

- 左侧通常承载主操作。
- 右侧通常承载展开菜单。
- 组合按钮应保证主操作明确。
- 不应把不相关的操作强行合并。

### 5. 按钮尺寸、边距与元素间距规范

按钮尺寸分为中号（默认 32px）、大号（40px）、小号（24px）三种规格。以下数值中，文字标注为视觉设计规范，红线标识为盒模型精确间距。

#### 5.1 各尺寸规格数值总览

##### 中号（默认规格，高度 32px，圆角 6px）

| 按钮类型 | 高度 | 圆角 | 左边缘间距 | 右边缘间距 | 元素间间距 | 备注 |
|---------|------|------|-----------|-----------|-----------|------|
| 常规按钮 | 32px | 6px | 16px | 16px | 图文 8px / 图标下拉 8px | 内边距 16px 左右 |
| 文字按钮 | - | - | 8px | 8px | - | **操作列中使用时缩至左右各 4px** |
| 图标按钮 | 32px | - | 8px | 8px | 图标 16px | 正方形布局 |
| 组合按钮 | 32px | - | 16px | 16px | 分割线间距 4px | 文本距左 16px，间隔 4px，箭头距右 16px |
| 链接按钮 | - | - | 0px | 0px | - | 左右无边距 |

##### 大号（强调规格，高度 40px，圆角 6px）

| 按钮类型 | 高度 | 圆角 | 左边缘间距 | 右边缘间距 | 元素间间距 | 备注 |
|---------|------|------|-----------|-----------|-----------|------|
| 常规按钮 | 40px | 6px | 16px | 16px | 图文 8px | 高度提升至 40px |
| 文字按钮 | - | - | 8px | 8px | - | 操作列使用时缩至 4px |
| 图标按钮 | 40px | - | 8px | 8px | 图标 16px | 保持正方形 |
| 组合按钮 | 40px | - | 16px | 16px | 分割线间距 4px | 保持中号比例放大 |
| 链接按钮 | - | - | 0px | 0px | - | 始终无边距 |

##### 小号（紧凑规格，高度 24px，圆角 4px）

| 按钮类型 | 高度 | 圆角 | 左边缘间距 | 右边缘间距 | 元素间间距 | 备注 |
|---------|------|------|-----------|-----------|-----------|------|
| 常规按钮 | 24px | 4px | 8px | 8px | 图文 4px | 圆角降低至 4px 保持视觉协调 |
| 文字按钮 | - | - | 8px | 8px | - | 操作列使用时缩至 4px |
| 图标按钮 | 24px | - | 8px | 8px | 图标 16px | - |
| 组合按钮 | 24px | - | 8px | 8px | 分割线间距 4px | 文本距左 8px，间隔 4px，箭头距右 8px |
| 链接按钮 | - | - | 0px | 0px | - | 始终无边距 |

#### 5.2 尺寸规格决策判定

| 规格 | 高度 | 适用场景 | 视觉权重 |
|------|------|---------|---------|
| **大号** | 40px | 核心入口、表单提交、确认支付等首要业务场景 | 高 |
| **中号** | 32px | 默认规格。常规列表操作、表格工具栏、面板内操作 | 中 |
| **小号** | 24px | 紧凑空间、弹窗内部、移动端卡片内部 | 低 |

#### 5.3 关键规则

- **圆角适配**：中号/大号统一使用 6px，小号因尺寸缩减降低至 4px 以保持视觉协调。
- **文字按钮特殊边距**：常规场景下文字左右边距为 8px（无论大小号），但在表格操作列中使用时，左右边距必须收缩至 4px 以适应列宽。
- **链接按钮**：始终左右无边距（0px）。
- **图标按钮**：始终保持正方形布局，图标大小统一为 16px。
- **组合按钮分割线**：所有尺寸规格下，中间分割线间距统一为 4px。
- 小号按钮不适合作为页面主操作。
- 小号按钮应避免承载复杂文案。
- 小号按钮应保证可点击区域足够。

### 6. 按钮样式类型

#### 6.1 主按钮

主按钮用于页面中最主要的操作。

核心用途：

- 核心路径入口
- 表单提交
- 保存配置
- 确认支付
- 完成任务
- 流程推进

适用场景示例：

- 提交
- 保存
- 确定
- 新建
- 下一步
- 完成

使用限制：

- 单区域内通常只允许一个主按钮。
- 颜色应醒目。
- 不应滥用于多个同级操作。
- 不应承载低频操作。

#### 6.2 次按钮

次按钮用于辅助操作或备选路径。

核心用途：

- 辅助操作
- 备选路径
- 次级流程推进

适用场景示例：

- 取消
- 返回
- 上一步
- 暂存
- 次要确认

使用限制：

- 可以有多个。
- 视觉优先级低于主按钮。
- 应与主按钮形成明显主次关系。

#### 6.3 幽灵按钮

幽灵按钮用于低背景干扰场景，通常带边框、背景较轻。

核心用途：

- 轻量级操作
- 低干扰按钮
- 次要操作

适用场景示例：

- 工具栏中的辅助按钮
- 操作区中的次要入口
- 非主流程按钮

使用限制：

- 页面上允许存在多个幽灵按钮。
- 可与主按钮及其他按钮组合使用。
- 不适合作为最核心操作的唯一入口。

#### 6.4 默认按钮

默认按钮用于中性普通操作。

核心用途：

- 普通操作
- 返回
- 取消
- 重置
- 放弃保存

适用场景示例：

- 取消
- 返回上一页
- 重置表单
- 放弃保存

使用限制：

- 可多个并存。
- 视觉优先级低于主按钮。
- 通常与主按钮并列出现。
- 不应用于强调操作。

#### 6.5 危险按钮

危险按钮用于高危或不可逆操作。

核心用途：

- 高危操作
- 不可逆操作

适用场景示例：

- 删除
- 作废
- 停用
- 清空
- 撤销重要流程

使用限制：

- 必须谨慎使用。
- 通常需要二次确认。
- 不应与正向主按钮混淆。
- 不应成为默认聚焦操作。

#### 6.6 文字按钮

文字按钮用于低干扰、弱视觉权重的操作。

核心用途：

- 表格行内操作
- 卡片内编辑
- 删除
- 取消
- 轻量入口

适用场景示例：

- 编辑
- 删除
- 查看
- 取消
- 复制
- 设置

使用限制：

- 不应用于核心业务操作。
- 可折叠进更多菜单。
- 通常无需背景色。
- 文案应简短明确。

#### 6.7 链接按钮

链接按钮用于页面跳转或打开新页面。

核心用途：

- 页面跳转
- 查看详情
- 打开帮助文档
- 跳转二级页面
- 外部链接

适用场景示例：

- 查看详情
- 前往设置
- 打开帮助
- 跳转到管理页

使用限制：

- 不应用于执行业务动作，如提交、删除、保存。
- 应表达跳转属性。
- 通常用于低频或辅助信息访问。
- 避免和普通文字按钮混淆。

#### 6.8 切换按钮

切换按钮用于状态切换，不执行复杂操作。

核心用途：

- 状态切换
- 开启或关闭
- 启用或禁用
- 收藏或取消收藏

适用场景示例：

- 收藏
- 取消收藏
- 启用
- 禁用
- 开启
- 关闭

使用限制：

- 不应用于触发业务执行动作。
- 状态改变后应立即反馈。
- 需要有明确当前状态。

#### 6.9 图标按钮

图标按钮用于空间受限或工具型入口。

核心用途：

- 工具栏功能入口
- 设置
- 刷新
- 打印
- 移动端底部导航

适用场景示例：

- 刷新
- 设置
- 打印
- 列配置
- 搜索
- 筛选

使用限制：

- 必须配合 Tooltip 或清晰图标。
- 图标需具备通用认知度。
- 不适合作为核心业务操作的唯一入口。

#### 6.10 下拉按钮

下拉按钮用于多操作选择，但默认不直接执行具体动作。

核心用途：

- 多操作入口
- 默认从属操作
- 条件筛选
- 批量操作集合

适用场景示例：

- 导出
- 更多
- 批量操作
- 筛选条件
- 下载选项

使用限制：

- 需明确子选项。
- 不可用于单一操作。
- 若有默认操作，应考虑使用分裂按钮。

#### 6.11 分裂按钮

分裂按钮用于“一个默认操作 + 多个扩展操作”的场景。

核心用途：

- 高频默认操作
- 扩展操作
- 组合操作

适用场景示例：

- 下载 PDF + 下载 Excel
- 导出当前页 + 导出全部
- 新建 + 批量导入

使用限制：

- 默认操作必须是最高频场景。
- 下拉菜单内的操作必须与默认操作相关。
- 不应把无关操作强行合并。

#### 6.12 更多/折叠按钮

更多/折叠按钮用于收纳过多按钮，避免页面拥挤。

核心用途：

- 收纳边缘按钮
- 减少视觉噪音
- 控制按钮数量

适用场景示例：

- 表格上方操作按钮超过 5 个
- 表单底部次要操作过多
- 页面操作项较多

使用限制：

- 不承载具体业务语义。
- 不可收纳主按钮。
- 点击后应展示下拉菜单。

### 7. 按钮状态

按钮状态包括正常、悬停、点击、禁用、加载等。

#### 7.1 正常状态

正常状态表示按钮当前可点击。

#### 7.2 悬停状态

悬停状态用于提示用户该区域可交互。

使用规则：

- 悬停反馈应轻微但可感知。
- 悬停状态不应改变按钮语义。

#### 7.3 点击状态

点击状态用于反馈用户已经触发操作。

使用规则：

- 点击反馈应即时。
- 对于异步操作，应进入加载状态或给出反馈。

#### 7.4 禁用状态

禁用状态表示当前条件不满足，按钮不可点击。

使用规则：

- 禁用按钮应降低视觉权重。
- 需要时提供原因说明。
- 不应让用户误以为系统故障。
- 禁用状态不应触发业务逻辑。

#### 7.5 加载状态

加载状态用于表示操作正在执行。

使用规则：

- 加载中按钮应避免重复点击。
- 加载状态可结合 loading 图标。
- 长耗时操作应提供进一步反馈。

### 8. 按钮数量规则

#### 8.1 按钮个数控制

按钮数量应根据操作层级和区域控制。

规则：

- 单一区域内主按钮通常只保留 1 个。
- 主要按钮组不宜过多。
- 如果按钮数量超过用户可快速识别范围，应折叠到“更多”。
- 表格工具栏中，如果按钮数量过多，应按业务优先级分组或折叠。
- 表格上方按钮超过 5 个时，建议将低频操作折叠。
- 同一区域内不应同时出现多个高视觉权重按钮。

#### 8.2 级别识别

按钮级别应通过颜色、边框、背景、文案和位置共同表达。

规则：

- 主按钮视觉最强。
- 次按钮视觉弱于主按钮。
- 文字按钮和链接按钮视觉权重最低。
- 危险按钮应表达风险，但不应无条件提升为主按钮。
- 图标按钮适合承载工具类低频操作。

#### 8.3 呼吸感与间距

按钮布局需要保留足够的呼吸感。

规则：

- 按钮之间需要稳定间距，**多个按钮左右并列时，间距为 8px**。
- 文字按钮/链接按钮之间间距同为 8px。
- 图标按钮之间间距可收紧至 4px~8px。
- 危险按钮与正向主按钮之间间距建议 ≥16px，防止误操作。
- 按钮与内容之间需要保留足够距离。
- 操作区与内容区应通过间距形成层次。
- 按钮组不应过于拥挤。
- 页面主操作区域和内容区域应视觉分离。

### 9. 按钮布局总则

按钮布局取决于按钮所在区域。

常见区域包括：

- Header 页面头部区域
- Toolbar 操作工具区
- Body 内容区
- Footer 页面底部区域
- 表格操作列
- 弹窗操作区
- 表单操作区
- 卡片操作区

#### 9.1 布局基本原则

1. 越重要的操作越靠右或越靠近用户视线焦点。
2. 与内容强相关的操作应靠近内容。
3. 与页面整体相关的操作应放在 Header 或 Toolbar。
4. 与表格数据相关的操作应放在 Toolbar 或表格操作列。
5. 与单行数据相关的操作应放在行内操作区。
6. 与表单提交相关的操作应放在表单底部或内容结束位置。
7. 低频操作应折叠或弱化。
8. 危险操作不应与主操作紧贴，必要时需要分组隔离。

### 10. Header 页面头部区域按钮位置

Header 区域用于承载页面级操作。按钮位置的基本原则是：放置全局变更类操作，按钮始终在最右边。

#### 10.1 适用操作

Header 适合放置页面级、全局性、流程性操作。

常见操作：

- 新建
- 保存
- 提交
- 发布
- 页面级确认
- 页面级取消
- 返回
- 全局配置
- 主要流程推进

#### 10.2 位置规则

1. Header 中的关键操作应放在右侧。
2. 主按钮通常位于最右侧。
3. 次按钮应放在主按钮左侧。
4. 标题、标签、页签等信息内容通常位于左侧或中部。
5. 如果 Header 中同时有页签和按钮，按钮仍应保持在右侧。
6. 弹窗或抽屉头部如需操作入口，轻量操作可放右上角。
7. Header 不应堆叠过多按钮，低频操作应移动到更多菜单或内容区。

#### 10.3 Header 场景示例

适合：

- 页面标题右侧的“默认按钮 + 主按钮”
- 带页签页面右侧的页面级操作
- 页面头部的“次按钮 + 主要按钮”
- 弹窗头部的轻量链接按钮或关闭按钮

不适合：

- 单行数据操作
- 与表格行强相关的操作
- 大量批量操作
- 复杂筛选操作
- 低频工具操作堆叠

### 11. Toolbar 操作工具区按钮位置

Toolbar 区域主要用于表格和数据区域上方，承载全局操作、批量操作以及对数据视图的实时干预。

#### 11.1 Toolbar 基本原则

Toolbar 位于表格数据的上方，按钮在左右分区展示。

规则：

- 左侧为主操作区，承载业务操作。
- 右侧为次操作区，承载设置类、跳转类、辅助类、工具类操作。
- 中间建议保留 24px 安全间距。
- 按钮区域最大宽度通常不超过 1020px，约等于一个按钮区域加 5 个按钮。
- 当超出小屏幕可展示范围时，按钮必须折叠展示。
- 主按钮始终放在左侧主操作区首位。
- 控钮区不应仅使用文字按钮。
- 图标按钮应靠右，通常作为工具操作。
- 如果工具区仅有 1 个操作，按钮仍保持右对齐；如果不高频，可用图标按钮放右侧，其他按钮放左侧。

#### 11.2 Toolbar 主操作区

主操作区位于左侧，用于用户进入页面后的核心目标操作。

常见操作：

- 新建
- 添加
- 批量新增
- 批量删除
- 批量导入
- 批量启用
- 批量停用
- 提交
- 审核

使用规则：

- 业务主操作放最左。
- 主操作区可以包含主按钮、幽灵按钮、默认按钮。
- 主按钮不应超过一个。
- 批量操作应放在业务主操作之后。
- 操作之间应按优先级排序。

#### 11.3 Toolbar 次操作区

次操作区位于右侧，用于承载非业务主路径操作。

常见操作：

- 显示设置
- 列设置
- 刷新
- 密度设置
- 帮助中心
- 跳转到其他页面
- 高级筛选
- 导出
- 下载

使用规则：

- 设置类、跳转类、辅助类操作放右侧。
- 图标按钮通常放在最右。
- 仅当操作具有明确工具属性时使用图标按钮。
- 不应把业务主操作放到右侧工具区。

#### 11.4 Toolbar 场景规则

##### 常规场景

表格上方常规工具栏：

- 左侧放主操作和业务操作。
- 右侧放工具按钮。
- 表格主体位于 Toolbar 下方。
- 表格操作列中的“详情”等行内操作不属于 Toolbar。

##### 特殊场景：分段选择器

当表格上方存在分段选择器时：

- 分段选择器可位于表格上方。
- 操作区仍按照主操作区和次操作区分区。
- 业务操作应靠左。
- 工具操作应靠右。

##### 特殊场景：按钮过多

当按钮过多导致一行展示不下时：

- 按钮折叠后无法满足一行内显示时，使用换行展示，但应谨慎。
- 主按钮和高频按钮优先展示。
- 低频按钮折叠到更多菜单。
- 图标工具按钮仍可保持右侧。
- 不建议让主操作被挤压到不可见区域。

### 12. Body 内容区按钮位置

Body 区域中的按钮应跟随内容操作，主按钮在左。

#### 12.1 Body 基本原则

Body 区域按钮与内容强相关，操作应靠近作用对象。

规则：

- 按钮应跟随内容。
- 主按钮通常在左侧。
- 次按钮在主按钮右侧。
- 与某组筛选条件相关的按钮应靠近筛选条件。
- 与某个状态反馈相关的按钮应靠近状态反馈。
- 与表格相关的分页、刷新、跳转等可位于表格附近。
- Body 中不应放置页面级全局操作，页面级操作应放 Header 或 Toolbar。

#### 12.2 Body 适用场景

适合：

- 表单内部操作
- 查询与重置
- 高级筛选展开或收起
- 空状态引导操作
- 成功反馈后的继续操作
- 内容块内操作
- 表格底部刷新或分页相关操作

#### 12.3 Body 场景示例

##### 成功反馈区

适合放置：

- 主操作
- 次操作

规则：

- 主按钮在左。
- 次按钮在右。
- 按钮应跟随反馈内容。

##### 查询筛选区

适合放置：

- 查询
- 重置
- 更多筛选
- 收起更多

规则：

- 查询作为主要动作时，可使用主按钮。
- 重置作为辅助动作，应使用次按钮或默认按钮。
- 更多筛选可以使用文字按钮或链接按钮。
- 按钮应靠近筛选条件末尾。

##### 表格内容区

适合放置：

- 表格底部操作
- 分页操作
- 刷新
- 每页条数选择
- 跳页操作

规则：

- 与表格数据相关的操作应靠近表格。
- 不应与 Header 或 Toolbar 的页面级操作混淆。

### 13. Footer 页面底部区域按钮位置

Footer 通常用于流程末端或表单底部操作。

适用场景：

- 表单提交
- 流程确认
- 弹窗底部确认
- 抽屉底部确认
- 页面底部保存

规则：

- 主按钮通常放在操作组内最右或最靠近流程推进方向的位置。
- 次按钮通常放在主按钮左侧。
- 如果按钮跟随内容而非页面级固定底部，可遵循 Body 规则。
- 弹窗底部按钮应保持稳定位置。
- 危险操作不建议与确认按钮紧贴。

### 14. 表格操作列按钮

表格操作列用于单行数据的行内操作。

适用场景：

- 详情
- 编辑
- 删除
- 复制
- 启用
- 停用
- 查看日志
- 更多

规则：

- 行内操作通常使用文字按钮或链接按钮。
- 如果行内操作超过 2-3 个，应折叠为“更多”。
- 高频操作可直接展示。
- 低频操作放入更多菜单。
- 危险操作可放更多菜单中，并使用危险样式。
- 行内不建议使用大面积实体按钮。
- 行内操作应与当前行数据强绑定。

### 15. 弹窗按钮

弹窗按钮用于确认用户在弹窗中的选择。

适用场景：

- 确认
- 取消
- 保存
- 提交
- 删除确认
- 二次确认

规则：

- 主要确认按钮应突出。
- 取消按钮应弱化。
- 危险确认应使用危险按钮。
- 弹窗底部按钮位置应稳定。
- 不建议在弹窗中放置过多按钮。
- 弹窗头部只适合放关闭或轻量链接操作。

### 16. 表单按钮

表单按钮用于提交、保存、重置、取消等表单相关操作。

适用场景：

- 提交
- 保存
- 查询
- 重置
- 取消
- 返回
- 暂存

规则：

- 表单提交可使用主按钮。
- 重置、取消、返回使用次按钮或默认按钮。
- 表单内按钮应跟随表单内容。
- 表单底部按钮应与输入区域保持合适距离。
- 查询表单中，查询按钮优先级高于重置按钮。
- 高级筛选展开收起可使用文字按钮或链接按钮。

### 17. 按钮组合关系

#### 17.1 主按钮与次按钮

推荐组合：

- 主按钮 + 次按钮
- 查询 + 重置
- 保存 + 取消
- 提交 + 返回
- 确认 + 取消

规则：

- 主按钮在优先位置。
- 次按钮辅助主按钮。
- 不应出现两个视觉权重相同的主按钮。

#### 17.2 主按钮与幽灵按钮

适用于业务操作区：

- 新建 + 批量操作
- 主操作 + 高级操作
- 主操作 + 辅助入口

规则：

- 主按钮优先出现。
- 幽灵按钮不应抢占主按钮焦点。

#### 17.3 文字按钮组合

适用于低权重操作：

- 编辑
- 删除
- 查看
- 更多

规则：

- 文字按钮之间应保持间距。
- 低频项应折叠。
- 危险项应视觉区分。

#### 17.4 分裂按钮组合

适用于默认操作与扩展操作：

- 下载 PDF + 其他格式
- 导出当前页 + 导出全部
- 新建 + 导入

规则：

- 默认操作必须高频。
- 扩展操作必须相关。
- 下拉内容不应过多。

### 18. 按钮文案规则

按钮文案应表达明确动作。

推荐：

- 使用动词或动宾结构。
- 文案简短。
- 避免含糊表达。
- 避免使用抽象词。
- 对危险动作明确说明。

示例：

- 查询
- 重置
- 保存
- 提交
- 新建
- 删除
- 导出
- 下载
- 查看详情
- 前往设置
- 更多操作

不推荐：

- 好的
- 操作
- 处理
- 去做
- 继续一下
- 点我
- 执行

### 19. 禁止或谨慎使用规则

1. 不要在同一区域放置多个主按钮。
2. 不要把低频操作设计成主按钮。
3. 不要用链接按钮执行保存、提交、删除等业务动作。
4. 不要让危险操作默认聚焦。
5. 不要把无关操作合并进同一个下拉按钮。
6. 不要在表格行内使用大面积实体按钮。
7. 不要仅用图标表达复杂业务操作。
8. 不要让按钮数量超过用户可快速理解的范围。
9. 不要把页面级操作放到行内操作区。
10. 不要把行级操作放到 Header。
11. 不要在 Toolbar 中只使用文字按钮作为操作区按钮。
12. 不要让主操作被折叠到更多菜单中。
13. 不要在无反馈的情况下执行长耗时操作。
14. 不要让禁用按钮缺少必要说明。
15. 不要让按钮间距过密。

### 21. 勾选按钮与开关按钮使用规则

勾选按钮和开关按钮都可以表达“选择”或“状态变化”，但二者的使用语义不同。设计时应根据操作是否立即生效、是否属于选项选择、是否需要提交确认来判断使用哪一种组件。

#### 21.1 勾选按钮 Checkbox

勾选按钮用于在一组条件、选项或对象中进行选择。它通常表达“是否选中某项”，不一定立即触发业务结果，常常需要用户点击提交、保存、确认等按钮后才生效。

适用场景：

- 多选条件
- 表单配置项
- 列表批量选择
- 同意协议
- 权限勾选
- 偏好设置
- 筛选条件选择
- 表格行选择

使用规则：

- 当用户需要从多个选项中选择一个或多个时，使用勾选按钮。
- 当选择结果需要等待用户点击“保存”“提交”“确定”后才生效时，使用勾选按钮。
- 当选项之间可以同时成立时，使用勾选按钮。
- 当需要支持批量选择时，使用勾选按钮。
- 勾选按钮应与明确的选项文案一起出现。
- 勾选按钮不应单独承担复杂业务说明。
- 勾选状态应清晰表达当前是否被选中。
- 表格中的全选、半选、单选状态需要保持一致的视觉反馈。

#### 21.2 开关按钮 Switch

开关按钮用于表达某个功能、状态或设置的开启与关闭。它通常表示即时生效的状态切换。

适用场景：

- 启用或停用
- 开启或关闭功能
- 打开或关闭通知
- 自动保存开关
- 是否公开
- 是否默认
- 是否允许某项能力
- 状态类配置

使用规则：

- 当操作表示“开/关”状态时，使用开关按钮。
- 当用户切换后需要立即生效时，使用开关按钮。
- 当状态本身比动作更重要时，使用开关按钮。
- 开关按钮应明确表达当前状态。
- 开关切换后应提供即时反馈。
- 如果切换会造成较大影响，应增加确认提示。
- 如果切换不会立即生效，而是需要提交后统一保存，应优先使用勾选按钮。
- 如果切换项较多且属于表单配置，应谨慎使用大量开关，避免页面噪音。

#### 21.3 勾选按钮与开关按钮的区别

勾选按钮偏向“选择”，开关按钮偏向“状态控制”。

| 判断维度 | 勾选按钮 | 开关按钮 |
|---|---|---|
| 核心语义 | 选择某个选项 | 开启或关闭某个状态 |
| 是否即时生效 | 通常不即时生效 | 通常即时生效 |
| 是否需要提交 | 常需要保存或提交 | 通常切换即生效 |
| 适用对象 | 选项、条件、对象 | 功能、状态、权限 |
| 常见场景 | 多选、表单、筛选、批量选择 | 启用、停用、通知、功能开关 |

#### 21.4 选择判断规则

如果用户是在选择多个条件、多个对象或多个配置项，应使用勾选按钮。如果用户是在控制某个功能是否开启，应使用开关按钮。

如果切换后不会立即生效，而是需要点击页面底部或表单底部的“保存”按钮后才生效，则不建议使用开关按钮，应使用勾选按钮或选择控件。

如果开关操作具有风险，例如停用账号、关闭重要能力、影响用户访问权限，则切换前或切换后应提供明确确认反馈。

### 22. 禁用按钮使用规则

禁用按钮用于表达当前操作暂不可用。它的目的不是阻止用户理解操作，而是帮助用户知道该操作存在，但当前条件尚未满足。

#### 22.1 禁用按钮的适用场景

适用场景：

- 必填项未填写
- 表单校验未通过
- 未选择任何数据
- 当前用户没有操作权限
- 当前状态不允许操作
- 数据正在加载
- 操作依赖的前置条件未完成
- 操作暂时不可用
- 系统正在处理中，避免重复提交

使用规则：

- 当按钮对应的操作存在，但当前条件不满足时，可以使用禁用态。
- 禁用按钮应保持可识别，但视觉权重要明显降低。
- 禁用按钮不应响应点击事件。
- 禁用按钮不应被误认为系统故障。
- 禁用按钮应在必要时说明原因。
- 对关键操作的禁用，应通过提示、说明文字或表单校验帮助用户恢复可用状态。
- 长时间禁用的按钮，应让用户知道如何解除禁用。
- 不应在没有任何解释的情况下禁用核心操作。

#### 22.2 禁用按钮的原因说明

禁用态的关键问题是：用户需要知道为什么不能操作，以及如何让按钮变为可用。

推荐说明方式：

- 在按钮附近显示说明文字。
- 鼠标悬停禁用按钮时显示 Tooltip。
- 在表单项下方显示校验错误。
- 在空状态或权限提示中说明不可用原因。
- 在批量操作区域提示“请选择数据后操作”。
- 在权限受限场景提示“暂无权限，请联系管理员”。

常见说明示例：

- 请先填写必填项。
- 请至少选择一条数据。
- 当前状态不支持该操作。
- 暂无权限执行此操作。
- 数据加载中，请稍后操作。
- 保存中，请勿重复提交。
- 请完成上一步后继续。

#### 22.3 禁用按钮与隐藏按钮

禁用和隐藏表达不同含义。禁用表示操作存在，但当前不可用；隐藏表示该操作在当前场景下不应出现。

适合禁用的场景：

- 用户可以通过补充信息让按钮可用。
- 操作是当前流程的一部分。
- 用户需要知道这个功能存在。
- 当前状态暂时不满足条件。
- 操作不可用原因可以被解释。

适合隐藏的场景：

- 用户永远没有该功能权限。
- 当前业务场景完全不支持该操作。
- 展示按钮会造成误解。
- 操作与当前任务无关。
- 功能入口不应暴露给当前角色。

使用规则：

- 如果用户可以通过行动恢复可用，优先禁用。
- 如果用户无法通过行动恢复可用，优先隐藏。
- 如果隐藏会导致用户不知道流程下一步，应保留禁用并说明原因。
- 如果按钮涉及权限控制，应根据产品策略决定隐藏还是禁用。
- 关键流程按钮不建议突然消失，应保持稳定位置并解释不可用原因。

### 23. 禁用态探索与设计判断

禁用态不是单纯的灰色样式，而是一种状态沟通机制。设计禁用态时，需要判断禁用是否必要、是否可理解、是否可恢复、是否影响流程完成。

#### 23.1 禁用态设计目标

禁用态需要同时满足三个目标：

1. 让用户知道操作存在。
2. 让用户知道当前不能操作。
3. 让用户知道如何恢复可操作状态。

如果禁用态只表达“不能点”，但没有说明原因，就会增加用户试错成本。

#### 23.2 禁用态判断问题

设计按钮禁用态时，应先回答以下问题：

- 用户是否需要知道这个操作存在？
- 当前不可用是临时状态还是永久状态？
- 用户是否可以通过补充信息、选择对象或完成前置步骤恢复可用？
- 不可用原因是否清晰？
- 是否需要在禁用按钮旁提供解释？
- 是否应该用错误提示、空状态、权限提示替代禁用？
- 禁用后是否会阻断用户完成任务？
- 是否存在比禁用更好的引导方式？

#### 23.3 不推荐使用禁用态的情况

以下情况应谨慎使用禁用态：

- 用户不知道为什么按钮不可用。
- 用户无法找到恢复可用的方法。
- 禁用按钮是页面中唯一的下一步入口，但没有任何说明。
- 禁用原因来自多个复杂条件，却没有解释。
- 操作与当前场景无关，应该隐藏而不是禁用。
- 用户没有权限且无法申请权限。
- 禁用按钮长期存在且没有可操作路径。
- 禁用只是为了阻止错误，但没有在输入过程中提供校验反馈。

#### 23.4 推荐的替代方案

当禁用态无法清楚传达原因时，可以使用其他方式替代。

替代方案：

- 使用表单实时校验，引导用户修正错误。
- 保持按钮可点击，点击后展示错误原因。
- 在按钮旁展示缺失条件。
- 在空状态中提示需要先创建数据。
- 在权限场景中展示申请权限入口。
- 使用步骤条或引导说明前置条件。
- 对危险或不可逆操作使用二次确认，而不是直接禁用。

#### 23.5 禁用态与错误提示

禁用态适合阻止明显不满足条件的操作，错误提示适合解释用户提交后发现的问题。

使用规则：

- 必填项为空时，可以禁用提交按钮，也可以允许点击后提示缺失项。
- 如果用户容易理解缺失条件，可以使用禁用态。
- 如果缺失条件较多或复杂，建议允许点击并统一展示错误提示。
- 如果表单很长，禁用底部提交按钮但不说明原因，会造成困惑。
- 禁用态应尽量配合输入项校验，而不是单独存在。

### 24. 链接按钮使用规则

链接按钮用于表达跳转、导航、查看详情或打开外部资源。它看起来像链接，但在设计系统中可作为按钮的一种轻量样式。

#### 24.1 链接按钮适用场景

适用场景：

- 查看详情
- 跳转页面
- 打开帮助文档
- 前往设置
- 查看规则
- 打开外部链接
- 查看更多信息
- 表格行内详情入口
- 文本段落中的辅助入口

使用规则：

- 链接按钮主要用于导航和信息查看。
- 链接按钮应表达“前往某处”或“查看某内容”。
- 链接按钮不应用于提交、保存、删除、确认等强业务动作。
- 链接按钮的文案应明确目标。
- 链接按钮可以出现在正文、表格行内、提示信息、空状态中。
- 链接按钮视觉权重较低，不应承载页面唯一主操作。
- 外部跳转应在必要时提示跳转属性。
- 如果链接会打开新页面，应根据产品规范考虑是否提供外链标识或新窗口提示。

#### 24.2 链接按钮与文字按钮区别

链接按钮和文字按钮都属于低视觉权重按钮，但语义不同。

| 判断维度 | 链接按钮 | 文字按钮 |
|---|---|---|
| 核心语义 | 跳转或查看 | 执行轻量操作 |
| 常见动作 | 查看详情、前往设置、打开帮助 | 编辑、删除、复制、取消 |
| 是否改变当前数据 | 通常不直接改变 | 可能改变数据 |
| 常见位置 | 正文、表格行内、提示信息 | 表格行内、卡片操作区 |
| 风险动作 | 不推荐 | 可用于低权重危险操作 |

#### 24.3 链接按钮文案

链接按钮文案应让用户知道点击后会去哪里或看到什么。

推荐文案：

- 查看详情
- 前往设置
- 查看规则
- 打开帮助
- 查看日志
- 查看全部
- 了解更多
- 管理权限
- 配置字段

不推荐文案：

- 点击这里
- 更多
- 去看看
- 操作
- 处理
- 打开
- 查看

使用规则：

- 避免使用含糊文案。
- 避免单独使用“这里”“更多”等无法表达目标的词。
- 如果链接目标是帮助文档，应明确写为“查看帮助”或“查看规则”。
- 如果链接目标是配置页面，应明确写为“前往设置”或“配置权限”。

#### 24.4 链接按钮禁止场景

以下场景不应使用链接按钮：

- 保存
- 提交
- 删除
- 确认
- 支付
- 发布
- 批量操作
- 高风险操作
- 页面主操作
- 弹窗主确认操作

对于会修改数据或提交业务结果的操作，应使用主按钮、次按钮、文字按钮或危险按钮，而不是链接按钮。

### 25. Footer 页面底部区按钮位置

Footer 页面底部区用于承载流程末端、表单末端或页面固定底部的操作。Footer 的按钮位置应稳定，帮助用户在完成内容填写或浏览后快速执行下一步。

#### 25.1 Footer 适用场景

适用场景：

- 表单提交
- 页面保存
- 流程确认
- 下一步
- 上一步
- 取消
- 返回
- 弹窗底部操作
- 抽屉底部操作
- 分步流程底部操作
- 页面固定底部操作栏

使用规则：

- Footer 适合放置与当前页面或当前流程整体相关的操作。
- Footer 不适合放置单个内容块、单行数据或局部组件的操作。
- Footer 按钮应保持稳定位置，不应随内容变化频繁跳动。
- 表单较长时，可使用固定底部操作栏提高操作可达性。
- 如果 Footer 是页面级操作区，应避免承载过多低频操作。
- 如果操作只影响局部内容，应放在内容区附近，而不是 Footer。

#### 25.2 Footer 按钮排列规则

Footer 中按钮排列需要体现流程方向和操作优先级。

常见规则：

- 主按钮放在最重要、最容易触达的位置。
- 次按钮与主按钮相邻，但视觉权重更低。
- 返回、取消、上一步等操作应弱于提交、保存、下一步。
- 危险操作不应与主确认按钮紧贴。
- 多个次要按钮应按流程顺序或业务优先级排列。
- Footer 操作数量不宜过多，低频操作应移到页面内容区或更多菜单。

#### 25.3 Footer 与 Header 的区别

Header 更适合页面进入时就需要看到的全局操作，Footer 更适合用户完成内容阅读或填写后的流程提交操作。

| 判断维度 | Header | Footer |
|---|---|---|
| 位置 | 页面头部 | 页面底部 |
| 操作性质 | 页面级、全局性、入口型 | 流程末端、提交型、确认型 |
| 用户阶段 | 进入页面时 | 完成内容后 |
| 常见动作 | 新建、发布、页面级保存 | 保存、提交、下一步、取消 |
| 适合场景 | 页面标题区、全局操作 | 表单底部、流程底部、弹窗底部 |

#### 25.4 Footer 与 Body 的区别

Body 中的按钮应跟随具体内容，Footer 中的按钮应服务于整体流程。

判断规则：

- 如果操作只影响某个内容块，放在 Body。
- 如果操作影响整个页面或整个表单，放在 Footer。
- 如果用户完成所有内容后才执行操作，放在 Footer。
- 如果用户在阅读某段内容时就需要操作，放在 Body。
- 如果按钮需要始终可见以便提交，使用固定 Footer。
- 如果按钮是局部引导，如空状态按钮，应放在 Body。

#### 25.5 固定 Footer 操作栏

固定 Footer 操作栏适用于长页面、长表单和分步流程。

适用场景：

- 长表单保存
- 多步骤配置
- 页面底部提交
- 审批确认
- 抽屉底部操作
- 需要持续可见的保存入口

使用规则：

- 固定 Footer 应与页面内容区有明确分隔。
- 固定 Footer 不应遮挡内容。
- 页面底部应预留安全距离，避免内容被覆盖。
- 操作按钮不宜过多。
- 主操作应清晰突出。
- 长耗时操作点击后应进入加载状态。
- 禁用主按钮时应说明原因。

#### 25.6 Footer 中的危险操作

Footer 中如需出现危险操作，应谨慎处理。

使用规则：

- 危险操作不应与正向主操作紧贴。
- 危险操作应通过颜色、文案和确认弹窗表达风险。
- 如果危险操作不是当前流程主路径，应移动到页面内容区或更多菜单。
- 如果危险操作影响范围大，应增加二次确认。
- 不应将危险按钮设置为默认聚焦按钮。
