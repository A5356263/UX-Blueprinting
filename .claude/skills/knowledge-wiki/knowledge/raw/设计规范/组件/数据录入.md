## 数据录入部分组件指南


本文档用于设计知识检索 Skill，整理数据录入类组件的使用场景、组件结构、样式状态、布局规范、交互规则和组件选择决策逻辑。

数据录入类组件主要用于用户提交、选择、确认或切换信息。它们通常出现在表单、筛选器、配置页面、详情编辑页、弹窗、抽屉、表格编辑、批量操作和流程配置场景中。

本文档覆盖以下组件：

- Form 表单
- Checkbox 多选
- Cascader 级联选择
- Switch 开关
- DatePicker 日期时间选择器

---

### 1. Form 表单

#### 1.1 组件定位

Form 表单用于承载一组数据录入项，帮助用户填写、编辑、提交结构化信息。表单通常由标签、输入控件、校验提示、辅助说明、操作按钮等元素组成。

Form 是数据录入场景中的基础容器组件。其他数据录入组件，如 Input、Select、Checkbox、Cascader、Switch、DatePicker 等，通常作为表单项嵌入 Form 中使用。

#### 1.2 何时使用

当用户需要提交一组结构化信息时，应使用 Form。

适用场景包括：

- 新建、编辑、查看业务对象
- 配置系统参数
- 提交审批、申请、任务或工单
- 填写用户资料、组织信息、规则配置
- 表格行内编辑或批量录入
- 弹窗、抽屉、页面中的数据编辑区域

不适合使用 Form 的情况：

- 只有一个轻量切换项，优先考虑 Switch
- 只有一个独立选择项，优先考虑 Checkbox、Radio 或 Select
- 主要用于信息展示而非输入，优先使用详情展示组件

#### 1.3 组件结构

Form 表单通常包含以下结构：

- 表单容器：承载整体表单区域
- 表单分组：用于对不同信息模块进行分区
- 标签 Label：说明字段含义
- 必填标识：用于提示该字段必须填写
- 输入控件：承载用户输入或选择
- 占位提示 Placeholder：说明输入内容或选择要求
- 辅助说明：解释字段规则、限制或业务含义
- 校验信息：展示错误、警告或成功状态
- 操作按钮：提交、取消、保存、重置等

#### 1.4 标签 Label 使用规则

Label 是表单项中非常重要的信息组织元素，用于帮助用户理解字段含义。

使用建议：

- Label 文案应准确、简洁、明确
- Label 应避免使用模糊词，例如“信息”“内容”“选项”等
- Label 不宜过长，过长时应优化字段命名或使用辅助说明
- 必填字段需要明确标识
- 同一表单内 Label 的命名方式应保持一致
- Label 与输入控件之间的间距应统一

常见 Label 布局方式：

- 左右布局：Label 位于控件左侧，适合后台系统、信息密集型表单
- 上下布局：Label 位于控件上方，适合宽松页面、移动端、复杂输入项
- 分组布局：多个表单项按业务模块分组展示，适合复杂表单

#### 1.5 尺寸与布局

Form 表单应根据页面复杂度、字段数量和业务流程选择合适布局。信息录入量大、复杂度高时需分组，分组大于 5 项或超 1 屏建议使用锚点定位。

##### 左右结构表单

| 属性 | 规格 |
|------|------|
| 标题距顶部 | 4px |
| 标题右侧边距 | 16px |
| 标题下方到首个表单项 | 16px |
| 表单项行与行垂直间距 | 16px |
| 左右双列控件水平间距 | 24px |
| 标签文本距输入控件 | 20px |
| 卡片/分组之间垂直间距 | 24px |

- Label 宽度应统一，控件左边缘应对齐。
- 必填标识、校验提示、辅助说明需要有固定位置。

##### 上下布局

适合字段说明较长、控件复杂或页面空间较窄的场景。
- Label 与控件之间的垂直间距应保持一致。
- 表单项之间应有清晰分隔。
- 避免在同一区域内混用过多布局方式。

#### 1.6 样式状态

Form 中的表单项常见状态包括：

- 默认状态：字段尚未输入或尚未触发交互
- 聚焦状态：用户正在输入或选择
- 已填写状态：字段已存在有效内容
- 禁用状态：字段不可编辑
- 只读状态：字段不可编辑但可查看
- 错误状态：字段内容不符合校验规则
- 警告状态：字段内容可提交但存在风险提示
- 成功状态：字段通过校验
- 加载状态：字段内容正在异步获取或校验

#### 1.7 校验规则

表单校验应帮助用户尽快发现和修正错误。

推荐规则：

- 必填校验应在提交前明确展示
- 格式校验应在用户输入完成后触发
- 错误信息应说明如何修正，而不仅是提示“错误”
- 同一表单内错误提示位置应统一
- 对复杂字段可增加辅助说明，减少用户犯错
- 不建议过早打断用户输入

错误提示建议：

- 使用明确、可操作的文案
- 避免只说“请输入正确内容”
- 优先指出缺失项或格式要求
- 多字段错误时，应帮助用户定位到具体字段

#### 1.8 使用建议

Form 设计应优先保证信息清晰、输入效率和错误可恢复。

设计建议：

- 字段顺序应符合用户填写流程
- 强相关字段应放在一起
- 非必要字段不应过度暴露
- 长表单建议分组或分步
- 表单底部应提供明确操作按钮
- 主操作按钮应突出，次操作按钮应弱化
- 提交后应提供反馈，例如成功提示、错误定位或保存状态

#### 1.9 AI 检索关键词

Form, 表单, 数据录入, 字段, Label, 必填, 校验, 错误提示, 辅助说明, 表单布局, 左右布局, 上下布局, 表单分组, 提交, 保存, 编辑, 新建, 配置页, 后台系统

#### 1.10 组件选择决策

当用户需要一次性填写或提交多个字段时，优先使用 Form。

如果用户只需要完成单个布尔状态切换，不应使用完整 Form，而应考虑 Switch。

如果用户只需要选择多个离散选项，可在 Form 内使用 Checkbox。

如果用户需要选择层级数据，可在 Form 内使用 Cascader。

如果用户需要选择日期、时间或日期区间，可在 Form 内使用 DatePicker。

### 2. Checkbox 多选

#### 2.1 组件定位

Checkbox 多选用于在一组选项中选择零个、一个或多个选项。它适合表达多个选项之间相互独立、可同时成立的关系。

Checkbox 也可以用于单个确认项，例如同意协议、开启某个附加选项、确认某个条件等。

#### 2.2 何时使用

当用户需要从多个候选项中选择多个值时，应使用 Checkbox。

适用场景：

- 多选筛选条件
- 多个权限项选择
- 多个标签选择
- 多个功能项勾选
- 表单中的附加选项
- 批量选择表格数据
- 勾选协议或确认说明

不适合使用 Checkbox 的情况：

- 只能选择一个选项时，优先使用 Radio 或 Select
- 需要立即切换系统状态时，优先使用 Switch
- 选项数量过多且需要搜索时，可考虑 Select 多选或 Transfer
- 存在明显层级关系时，可考虑 Cascader 或 Tree

#### 2.3 组件结构

Checkbox 通常包含：

- 选择控件：用于表示选中、未选中或半选状态
- 文案字段：说明选项含义
- 辅助文案：补充解释选项内容
- 禁用状态：表示当前选项不可操作
- 选项组：承载多个 Checkbox
- 全选项：用于批量选择一组选项
- 半选状态：表示部分子项被选中

#### 2.4 样式状态

Checkbox 的常见状态包括：

- 默认未选中
- 悬停
- 聚焦
- 选中
- 半选
- 禁用未选中
- 禁用已选中
- 错误状态
- 组合选项状态

#### 2.5 常规样式

Checkbox 可独立出现，也可与文字、说明、图片、标签等组合。

常见组合：

- 纯 Checkbox
- Checkbox + 主文案
- Checkbox + 主文案 + 辅助文案
- Checkbox + 图标或图片
- Checkbox + 标签
- Checkbox + 输入框
- Checkbox + Select
- Checkbox 全选 + 子选项

#### 2.6 场景样式

在表单中使用时，Checkbox 常与字段 Label、说明文字、图片、输入框或下拉选择组合。

适用方式：

- 横向排列：适合选项较少、文案较短的场景
- 纵向排列：适合选项较多、文案较长的场景
- Label 场景布局：适合表单项中展示一组选项
- 卡片式 Checkbox：适合选项需要更多说明或视觉区分的场景

#### 2.7 尺寸与布局

##### 横向排列

| 属性 | 规格 |
|------|------|
| 全选与第一项间距 | 12px |
| 选项之间水平间距 | 24px |
| 行底部边距 | 8px |

适合选项数量少、文案短、横向空间充足的场景。

##### 纵向排列

| 属性 | 规格 |
|------|------|
| 选项之间垂直间距 | 8px |
| 标题与选项块垂直间距 | 8px |
| 卡片/容器内部上下间距 | 16px |

适合选项数量多、文案较长、需逐项阅读的场景。

##### 表格场景

| 属性 | 规格 |
|------|------|
| 标签与选项水平间距 | 8px |
| 选项之间水平间距 | 24px |
| 行间距 | 8px |

#### 2.8 交互规则

Checkbox 的交互应符合用户对“多选”的预期。

交互规则：

- 点击选择控件或文案均可切换选中状态
- 多个选项之间可以同时选中
- 再次点击已选项可取消选中
- 禁用项不可点击
- 全选项可控制子选项全部选中或取消
- 当部分子项选中时，全选项应呈现半选状态
- 半选状态通常不由用户直接选择，而由子项状态计算得出

#### 2.9 使用建议

设计 Checkbox 时应注意：

- 选项文案应短且明确
- 选项之间应相互独立
- 不应使用 Checkbox 表达互斥关系
- 选项较多时应分组或提供搜索
- 必填多选项需要明确校验规则
- 涉及协议确认时，应明确说明用户确认的内容

#### 2.10 AI 检索关键词

Checkbox, 多选, 勾选, 复选框, 全选, 半选, 权限选择, 多选筛选, 标签选择, 表单多选, 勾选协议, 选项组, 横向布局, 纵向布局, 禁用, 选中状态

#### 2.11 组件选择决策

当多个选项可以同时成立时，使用 Checkbox。

当只有两个互斥状态且切换后立即生效时，优先使用 Switch。

当选项之间存在层级关系时，优先使用 Cascader 或 Tree。

当只能从多个选项中选择一个时，不应使用 Checkbox，应使用 Radio 或 Select。

### 3. Cascader 级联选择

#### 3.1 组件定位

Cascader 级联选择用于从一组具有层级关系的数据中逐级选择目标项。它适合表达父子层级、分类路径、行政区域、组织结构、业务分类等数据。

Cascader 的核心价值是将复杂层级数据压缩到一个选择入口中，用户通过逐级展开完成选择。

#### 3.2 何时使用

当用户需要从层级数据中选择一个或多个目标项时，应使用 Cascader。

适用场景：

- 省市区选择
- 公司、部门、团队选择
- 事项分类选择
- 商品类目选择
- 多级业务类型选择
- 树状数据路径选择

不适合使用 Cascader 的情况：

- 数据没有层级关系，优先使用 Select
- 层级过深且需要大范围浏览，优先考虑 Tree
- 选项数量巨大且用户更依赖关键词搜索，需强化搜索能力
- 需要展示复杂节点信息，可能需要 TreeSelect 或自定义面板

#### 3.3 组件结构

Cascader 通常包含：

- 下拉框：用于展示当前选择结果
- 弹出层：承载多级选项面板
- 一级选项列表
- 二级选项列表
- 三级或更多级选项列表
- 选项文本
- 展开箭头：表示该项存在下一级
- 选中状态：表示当前已选择的路径或节点
- 搜索框：用于快速查找层级选项
- 文本省略：用于处理过长选项文案

#### 3.4 尺寸与布局

| 属性 | 规格 |
|------|------|
| 每个区域最小宽度 | 120px |
| 每个区域最大宽度 | 400px |

- 选项文案过长时应使用省略或 Tooltip。
- 面板应尽量避免超出视口。
- 层级列之间应保持清晰分隔。

#### 3.5 样式类型

Cascader 常见类型包括：

- 单选
- 多选
- 单选扩展
- 多选扩展

单选适合选择唯一层级路径。

多选适合选择多个层级节点。

单选扩展适合需要展示更多级别但最终只选择一个节点的场景。

多选扩展适合需要在多级结构中选择多个节点的场景。

#### 3.6 下拉项状态

Cascader 下拉项常见状态包括：

- 正常
- 悬停
- 禁用
- 点击
- 选中
- 半选
- 展开
- 搜索匹配

状态设计建议：

- 悬停状态用于提示可点击
- 选中状态应清晰表达当前选择
- 禁用状态不可点击
- 多选时父节点可根据子项呈现半选状态
- 当前路径应通过背景色或高亮表现

#### 3.7 选择框展示规则

Cascader 的选择结果展示方式应根据选择模式决定。

单选展示：

- 可展示完整路径
- 也可仅展示末级选项
- 当路径较长时应省略中间内容

多选展示：

- 可使用标签展示多个已选项
- 超出展示空间时可折叠为数量提示
- 应支持清除选择
- 应避免过多标签撑高输入框

#### 3.8 搜索交互

Cascader 可提供搜索能力，用于提升层级数据选择效率。

搜索建议：

- 当层级数据较多时建议提供搜索
- 搜索结果应展示完整路径，避免用户误选
- 匹配关键词可高亮
- 搜索后仍应保留层级上下文
- 结果为空时应展示空状态

#### 3.9 选项超长适配

当选项文字过长时，需要处理展示规则。

常见方式：

- 默认单行省略
- 自定义多行展示
- Tooltip 展示完整内容
- 搜索结果中展示完整路径
- 面板宽度适当扩展但不无限拉伸

#### 3.10 触发方式

Cascader 常见触发方式包括：

- 鼠标移入展开
- 鼠标点击展开

选择触发方式时应考虑：

- 鼠标移入适合高效浏览，但容易误触
- 鼠标点击更稳定，适合复杂选择和多选场景
- 多选、长文本、复杂层级建议优先使用点击展开

#### 3.11 使用建议

设计 Cascader 时应注意：

- 层级不宜过深
- 节点文案应短且可区分
- 多选场景应明确父子节点勾选关系
- 搜索结果应显示路径
- 禁用节点应说明原因或避免出现
- 已选结果应可清除
- 超长文本应有统一处理方案

#### 3.12 AI 检索关键词

Cascader, 级联选择, 层级选择, 省市区, 组织架构, 分类选择, 多级选择, 单选级联, 多选级联, 级联下拉, 搜索级联, 路径选择, 父子节点, 半选, 展开, 下拉面板

#### 3.13 组件选择决策

当用户需要从具有父子层级关系的数据中选择目标项时，使用 Cascader。

如果数据没有层级关系，应使用 Select。

如果层级结构复杂、需要浏览整棵树，应使用 Tree 或 TreeSelect。

如果只是选择日期或时间，不应使用 Cascader，应使用 DatePicker。

### 4. Switch 开关

#### 4.1 组件定位

Switch 开关用于在两个互斥状态之间切换，例如开启与关闭、启用与停用。它通常表示一个配置项、功能项或状态项是否生效。

Switch 的核心特征是状态切换通常会立即生效，不需要用户再点击提交按钮。

#### 4.2 何时使用

当用户需要在两个相反状态之间进行切换，且切换结果可以即时生效时，应使用 Switch。

适用场景：

- 开启或关闭功能
- 启用或停用配置
- 是否允许某项能力
- 表格中快速启停状态
- 设置页中的即时配置项
- 权限、通知、自动化规则的开关

不适合使用 Switch 的情况：

- 用户需要提交整个表单后才生效，优先使用 Checkbox 或 Radio
- 状态不是二元关系
- 切换后会产生高风险或不可逆影响，需增加确认
- 需要选择多个值，应使用 Checkbox
- 需要输入具体内容，应使用 Form 或 Input

#### 4.3 组件结构

Switch 通常包含：

- 开关轨道：表示整体开关区域
- 滑块圆点：表示当前状态
- 开启状态：通常使用品牌色或强调色
- 关闭状态：通常使用灰色
- 状态文案：可展示“开启/关闭”“启用/停用”
- 禁用状态：表示不可切换
- 加载状态：表示状态正在更新

#### 4.4 样式状态

Switch 常见状态包括：

- 开启
- 开启悬停
- 开启禁用
- 关闭
- 关闭悬停
- 关闭禁用
- 启用
- 停用
- 加载中

#### 4.5 尺寸

##### 大尺寸

用于基础设置页、配置页面、独立表单项。

| 属性 | 规格 |
|------|------|
| 轨道宽度 | 44px |
| 轨道高度 | 22px |
| 带"开启"文本标签整体宽 | 54px |
| 标签与开关间距 | 6px |
| 开关距右侧边缘 | 4px |

##### 小尺寸

#### 4.6 文案规则

Switch 的文案应表达当前状态，而不是将要执行的动作。

推荐文案：

- 开启 / 关闭
- 启用 / 停用
- 是 / 否
- 显示 / 隐藏

注意事项：

- 同一系统内文案应统一
- 不应混用“开启/停用”等不成对表达
- 文案应避免过长
- 如状态含义不清，应在旁边增加说明

#### 4.7 交互规则

Switch 的交互应简单直接。

交互规则：

- 点击开关可切换状态
- 切换后通常立即生效
- 异步更新时应展示加载或禁用状态
- 更新失败时应回滚并提示原因
- 高风险操作应二次确认
- 禁用状态不可点击
- 表格中的 Switch 应避免误触，可结合确认弹窗

#### 4.8 即时生效与表单提交

Switch 与 Checkbox 的关键区别是是否即时生效。

Switch 适用于即时生效：

- 用户点击后状态立刻改变
- 不依赖表单提交
- 常用于系统设置、表格状态切换、启停功能

Checkbox 适用于表单提交：

- 用户勾选后只是改变表单值
- 需要点击保存或提交后才真正生效
- 常用于表单中的选项确认、协议确认、多选项选择

#### 4.9 使用建议

设计 Switch 时应注意：

- 只用于两个互斥状态
- 状态变化应可预测
- 高风险切换需确认
- 异步切换需反馈加载状态
- 表格中密集使用时应保证可点击区域与误触防护
- 不应将 Switch 用作多选控件

Switch, 开关, 启用, 停用, 开启, 关闭, 即时生效, 状态切换, 二元状态, 设置项, 表格开关, 功能开关, 禁用状态, 加载状态, 配置开关

#### 4.11 组件选择决策

当用户需要在两个互斥状态之间即时切换时，使用 Switch。

如果该选择需要跟随表单一起提交，应使用 Checkbox。

如果存在多个选项可同时选择，应使用 Checkbox。

如果切换动作风险较高，应增加确认弹窗或二次确认机制。

### 5. DatePicker 日期时间选择器

### 6. 数据录入组件选择总规则

#### 6.1 组件选择优先级

当设计数据录入场景时，应先判断用户任务类型：

1. 用户是否需要填写多个字段？
   - 是：使用 Form。
2. 用户是否需要从多个独立选项中选择多个？
   - 是：使用 Checkbox。
3. 用户是否需要从层级数据中选择？
   - 是：使用 Cascader。
4. 用户是否需要切换一个二元状态且即时生效？
   - 是：使用 Switch。
5. 用户是否需要选择日期、时间或时间范围？
   - 是：使用 DatePicker。

#### 6.2 组件之间的关键区别

Form 是容器，用于组织多个输入项。

Checkbox 是多选控件，用于选择多个可并存选项。

Cascader 是层级选择控件，用于选择具有父子结构的数据。

Switch 是即时状态切换控件，用于开启/关闭或启用/停用。

DatePicker 是时间选择控件，用于选择日期、时间或区间。

#### 6.3 易混淆组件决策

##### Checkbox 与 Switch

如果选择结果需要点击“保存”后才生效，使用 Checkbox。

如果点击后立即改变系统状态，使用 Switch。

##### Checkbox 与 Cascader

如果选项之间相互独立，使用 Checkbox。

如果选项之间存在父子层级，使用 Cascader。

##### Cascader 与 Select

如果数据有层级关系，使用 Cascader。

如果数据是扁平枚举，使用 Select。

##### DatePicker 与 Input

如果需要标准日期格式和日历选择，使用 DatePicker。

如果是自由文本或非标准时间描述，使用 Input。

##### Form 与单独控件

如果页面需要提交多个字段，使用 Form。

如果只有一个独立状态或选择，不一定需要完整 Form。

### 9. TreeSelect 树选择

#### 9.1 组件定位

TreeSelect 树选择用于在下拉选择框中承载树形结构数据，帮助用户从具有层级关系的数据中选择一个或多个目标节点。

TreeSelect 可以理解为 Select 与 Tree 的组合。它既具备下拉选择的紧凑入口，又具备树组件的层级展开、折叠、父子节点选择、半选和多选能力。

#### 9.2 何时使用

当 Select 的选择项是树形结构，且用户需要在有限页面空间内完成层级选择时，应使用 TreeSelect。

适用场景包括：

- 组织架构选择
- 部门、团队、人员组选择
- 权限范围选择
- 分类目录选择
- 树形业务对象选择
- 多层级标签选择
- 需要在表单中选择树节点的场景

不适合使用 TreeSelect 的情况：

- 数据没有层级关系，优先使用 Select
- 只是简单的二级或三级路径选择，且用户不需要浏览树结构时，可使用 Cascader
- 需要大面积浏览、拖拽、编辑树结构时，应使用 Tree
- 树节点信息复杂，需要展示多列内容时，应考虑自定义选择面板

#### 9.3 组件结构

TreeSelect 通常包含：

- 选择框：展示当前已选值
- 下拉面板：承载树形节点
- 搜索输入框：用于搜索树节点
- 全选项：用于批量选择节点
- 父节点：包含子节点的层级节点
- 子节点：树中的末级或下级节点
- 展开 / 收起图标：控制节点层级显隐
- Checkbox：多选模式下用于勾选节点
- 选中状态：表示当前节点被选中
- 半选状态：表示部分子节点被选中
- 禁用状态：表示节点不可选择
- 辅助入口：如“文字按钮”等扩展操作入口

#### 9.4 尺寸与布局

##### 层级/行列间距

| 属性 | 规格 |
|------|------|
| 第一级缩进（左侧边距） | 8px |
| 展开/折叠图标距文本 | 4px |
| 一行右侧留白 | 32px |
| 子级菜单向右缩进 | 20px |
| 单行高度 | 32px |
| 行与行垂直间距 | 8px |
| 底部内边距 | 16px |
| 长文本深度第二级缩进 | 20px |
| 分组顶部内边距 | 12px |

- 下拉面板高度应限制，超出后滚动。
- 下拉宽度应能容纳主要节点名称。
- 长文本节点应支持省略或 Tooltip。

#### 9.5 样式状态

TreeSelect 的常见状态包括：

- 默认状态
- 悬停状态
- 聚焦状态
- 展开状态
- 选中状态
- 半选状态
- 禁用状态
- 搜索状态
- 空结果状态
- 加载状态

单选模式中，用户只能选择一个节点。

复选模式中，用户可以选择多个节点，并可能出现父子节点联动关系。

#### 9.6 文本显示规则

TreeSelect 中的节点文案需要处理超长展示问题。

推荐规则：

- 默认在限定宽度内单行省略
- Hover 时可展示完整文本
- 支持 Tooltip 展示完整内容
- 重要层级信息可通过路径辅助说明
- 搜索结果中应尽量展示命中节点及其上下文

当节点名称很长时，不应无限拉宽下拉面板，而应通过省略、Tooltip 或换行策略处理。

#### 9.7 异步数据加载

当树形数据量较大或节点需要动态获取时，TreeSelect 可支持异步加载。

适用场景：

- 组织架构数据量大
- 节点下级数据需要按需请求
- 权限树或分类树过大
- 用户展开节点后才加载子节点

设计建议：

- 展开父节点时加载子节点
- 加载过程中展示 loading 状态
- 加载失败时提供重试或错误提示
- 不应一次性加载过大的完整树，避免性能问题
- 搜索时需明确搜索范围，是本地已加载数据还是全量远程数据

#### 9.8 交互规则

TreeSelect 的交互应兼顾层级浏览和选择效率。

交互规则：

- 点击选择框打开下拉树面板
- 点击展开图标展开或收起子节点
- 单选模式下点击节点后选中该节点
- 多选模式下点击 Checkbox 切换节点选中状态
- 父节点可根据子节点选中情况呈现半选状态
- 禁用节点不可选择
- 搜索输入后应过滤或定位匹配节点
- 点击清除按钮可清空已选值
- 多选结果过多时应折叠展示

#### 9.9 使用建议

设计 TreeSelect 时应注意：

- 树层级不宜过深
- 节点名称应清晰可区分
- 父子节点选择关系应符合业务逻辑
- 多选时应明确父节点与子节点是否联动
- 搜索结果应保留层级上下文
- 大数据量场景建议支持异步加载
- 长文本节点需要统一展示策略
- 不应将复杂树管理任务塞入 TreeSelect

#### 9.10 TreeSelect 与 Cascader 的区别

TreeSelect 更适合用户需要浏览树结构、选择多个树节点、处理半选和父子节点联动的场景。

Cascader 更适合用户按照路径逐级选择，尤其适合省市区、类目路径等从左到右逐级定位的场景。

如果用户关心“树节点本身”和父子勾选关系，优先使用 TreeSelect。

如果用户关心“选择路径”和逐级定位过程，优先使用 Cascader。

#### 9.12 组件选择决策

当用户需要在下拉选择框中选择树形结构数据时，使用 TreeSelect。

如果数据是扁平枚举，使用 Select。

如果数据是路径型层级选择，使用 Cascader。

如果用户需要展开浏览整棵树或管理树结构，使用 Tree。

#### 10.1 组件定位

Upload 上传用于将本地文件、图片、附件或其他资源提交到系统中。它帮助用户完成文件选择、拖拽上传、上传进度查看、上传结果反馈和文件管理。

Upload 通常出现在表单、详情编辑、资料提交、图片上传、附件管理、批量导入等场景中。

#### 10.2 何时使用

当用户需要向系统提交文件或图片时，应使用 Upload。

适用场景包括：

- 上传附件
- 上传图片
- 上传头像或封面
- 上传资质文件
- 上传合同、发票、证明材料
- 批量上传文件
- 拖拽上传
- 表单中的附件字段
- 页面或弹窗中的文件导入

不适合使用 Upload 的情况：

- 用户只需要输入文件链接，应使用 Input
- 用户只需要选择系统已有资源，应使用 Select、资源选择器或文件选择弹窗
- 上传过程涉及复杂裁剪、编辑、标注，应使用专门的图片编辑或文件处理组件

#### 10.3 组件结构

Upload 通常包含：

- 上传按钮：触发文件选择
- 上传区域：用于点击或拖拽上传
- 上传图标：提示可上传文件
- 上传说明：说明文件格式、大小、数量限制
- 文件列表：展示已上传或上传中的文件
- 文件名称：展示文件名
- 文件类型图标：区分图片、文档、压缩包等类型
- 上传进度条：展示上传进度
- 上传状态：上传中、上传成功、上传失败
- 操作按钮：预览、下载、删除、重新上传
- 错误提示：说明上传失败原因
- 图片缩略图：图片类文件上传后的预览

#### 10.4 上传类型

Upload 按**交互模式**分为三种（详细交互规范见 `knowledge/上传文件.md`）：

- **按钮上传**：适合轻量附件上传（多用在表单字段中）
- **照片墙上传**：适合图片类文件，上传后以缩略图网格展示（多用在表单字段中）
- **拖拽上传**：适合批量上传或需要明显上传区域的场景（多用在页面 / 弹窗等容器中）

按**内容类型**区分：

- 图片上传：适合头像、封面、相册、资质图片等需要预览的场景
- 附件上传：适合文档、表格、压缩包等文件型资源
- 多文件上传 / 单文件上传：按文件数量区分

按**承载位置**区分：

- 表单字段中的上传
- 页面 / 弹窗 / 抽屉中的上传

- 多文件列表应支持滚动或折叠。

#### 10.6 样式状态

Upload 常见状态包括：

- 默认状态
- 悬停状态
- 上传中
- 上传成功
- 上传失败
- 禁用状态
- 拖拽悬停状态
- 文件数量达到上限
- 文件格式错误
- 文件大小超限

上传状态应通过视觉反馈明确表达，避免用户不确定文件是否已成功提交。

#### 10.7 文件列表展示

上传后的文件列表用于展示文件结果和后续操作。

常见展示方式：

- 纯文件名列表
- 文件名 + 状态
- 文件名 + 进度条
- 文件名 + 操作图标
- 图片缩略图列表
- 卡片式文件列表
- 错误文件列表

设计建议：

- 上传成功的文件应允许预览、下载或删除
- 上传失败的文件应展示失败原因
- 上传中的文件应展示进度
- 文件名过长应省略并支持完整查看
- 多文件场景应保证列表可扫描

#### 10.8 图片上传规则

图片上传需要更强调预览和格式反馈。

设计建议：

- 图片上传后应展示缩略图
- 图片上传失败应展示失败样式
- 支持预览、删除、重新上传
- 可根据业务支持裁剪或压缩
- 应明确图片格式、尺寸和大小限制
- 多图上传应明确最大数量

#### 10.9 拖拽上传规则

拖拽上传适合需要较高上传效率的场景。

交互规则：

- 用户拖拽文件进入上传区域时，应显示高亮状态
- 松开文件后开始上传
- 上传区域应提示“点击或拖拽文件上传”
- 上传中应展示进度
- 上传失败应允许重试
- 不支持的文件应给出明确提示

#### 10.10 上传校验规则

Upload 应在上传前或上传中进行必要校验。

常见校验包括：

- 文件格式校验
- 文件大小校验
- 文件数量校验
- 文件名称校验
- 图片尺寸校验
- 文件安全校验
- 重复文件校验

错误提示建议：

- 明确指出失败原因
- 说明允许的格式或大小
- 提供重新上传入口
- 不应只提示“上传失败”

#### 10.11 交互规则

Upload 的交互应覆盖上传前、上传中和上传后。

交互规则：

- 点击上传按钮或上传区域打开文件选择器
- 支持拖拽时可拖入文件触发上传
- 上传中展示进度
- 上传成功后展示文件列表
- 上传失败后展示错误状态和原因
- 可删除已上传文件
- 可预览或下载已上传文件
- 达到上传数量上限后应隐藏或禁用上传入口
- 禁用状态下不可上传或删除文件

#### 10.12 使用建议

设计 Upload 时应注意：

- 上传前明确文件要求
- 上传中提供进度反馈
- 上传失败提供可恢复操作
- 上传成功后展示清晰结果
- 图片上传应优先展示缩略图
- 文件上传应展示文件类型和文件名
- 多文件上传应明确数量限制
- 大文件或慢网络场景应避免无反馈等待

#### 10.13 AI 检索关键词

Upload, 上传, 文件上传, 图片上传, 附件上传, 拖拽上传, 上传按钮, 上传区域, 文件列表, 上传进度, 上传失败, 上传成功, 重新上传, 删除文件, 预览文件, 下载文件, 文件格式, 文件大小限制, 多文件上传

#### 10.14 组件选择决策

当用户需要从本地选择文件并提交到系统时，使用 Upload。

如果用户只是输入文件地址，使用 Input。

如果用户选择的是系统已有资源，使用资源选择器或 Select。

如果上传内容需要图片预览，使用图片上传样式。

如果需要批量导入或多文件提交，可使用拖拽上传或文件列表上传。

### 11. Input 输入框

#### 11.1 组件定位

Input 输入框用于接收用户输入的文本、关键词、编号、名称、说明、备注、链接等内容。它是最基础的数据录入组件之一。

Input 适合用于自由文本输入、短文本输入、搜索输入、密码输入、带前后缀内容的输入，以及与其他控件组合形成复合输入。

#### 11.2 何时使用

当用户需要输入文本内容时，应使用 Input。

适用场景包括：

- 输入名称
- 输入标题
- 输入编号
- 输入关键词
- 输入手机号、邮箱、链接等文本
- 输入搜索条件
- 输入备注或说明
- 输入密码
- 输入带单位、前缀或后缀的信息
- 表单中的普通文本字段

不适合使用 Input 的情况：

- 只能输入数字且需要步进控制，优先使用 InputNumber
- 需要选择日期或时间，使用 DatePicker
- 需要从固定选项中选择，使用 Select、Radio 或 Checkbox
- 需要上传文件，使用 Upload
- 需要输入长篇多行文本，使用 TextArea

#### 11.3 组件结构

Input 通常包含：

- 输入框容器
- 输入内容
- Placeholder 占位提示
- 清除按钮
- 前缀 Icon
- 后缀 Icon
- 前置标签
- 后置标签
- 字数统计
- 错误提示
- 帮助说明

#### 11.4 样式状态

Input 的常见状态包括：

- 默认状态
- 输入中状态
- 悬停状态
- 聚焦状态
- 已输入状态
- 禁用状态
- 只读状态
- 错误状态
- 警告状态
- 搜索状态
- 密码可见 / 不可见状态

#### 11.5 普通输入框

普通输入框用于基础文本输入。

适用场景：

- 名称
- 标题
- 编码
- 链接
- 备注的短文本
- 表单中的普通字段

设计建议：

- Placeholder 应说明输入要求
- 输入框宽度应与内容预期匹配
- 必填字段应结合 Form 校验
- 错误提示应说明如何修正
- 禁用状态应清晰不可编辑

#### 11.6 文本域

文本域用于较长的多行文本输入。

适用场景：

- 备注
- 描述
- 说明
- 评论
- 多行内容编辑

设计建议：

- 文本域应提供足够高度
- 可根据需要支持自适应高度
- 字数限制场景应展示字数统计
- 错误提示不应遮挡输入内容
- 不应使用单行 Input 承载长文本

#### 11.7 搜索输入框

搜索输入框用于关键词查询。

适用场景：

- 列表搜索
- 表格筛选
- 下拉面板搜索
- 树节点搜索
- 资源搜索

设计建议：

- 使用搜索 Icon 提示功能
- 支持回车触发搜索
- 支持清空搜索内容
- 搜索结果为空时展示空状态
- 即时搜索时应考虑防抖和加载状态

#### 11.8 密码输入框

密码输入框用于敏感信息输入。

适用场景：

- 登录密码
- 支付密码
- 验证码或密钥
- 账号安全配置

设计建议：

- 默认隐藏输入内容
- 可提供显示 / 隐藏密码按钮
- 错误提示应避免泄露敏感信息
- 可结合强度提示或规则说明
- 不应在普通文本框中输入敏感密码

#### 11.9 前缀与后缀

Input 可通过前缀或后缀增强语义。

常见方式：

- 前缀文字
- 后缀文字
- 前缀 Icon
- 后缀 Icon
- 前置选择器
- 后置单位

适用场景：

- URL 前缀
- 金额单位
- 搜索 Icon
- 用户 Icon
- 固定协议头
- 带单位输入

设计建议：

- 前后缀应与输入内容强相关
- Icon 应具备明确语义
- 不应加入无意义装饰性 Icon
- 前后缀不可影响输入内容识别
- 后缀单位应避免用户误输入重复单位

#### 11.10 标签输入

标签输入用于输入多个离散文本项。

适用场景：

- 标签
- 邮箱收件人
- 关键词组
- 多个编号
- 多个自定义值

设计建议：

- 输入后可生成标签
- 标签应支持删除
- 超出宽度时应换行或折叠
- 应明确分隔方式，如回车、逗号或空格
- 需要固定选项时可考虑 Select 多选

#### 11.12 交互规则

Input 的交互应符合用户输入预期。

交互规则：

- 点击输入框进入聚焦状态
- 输入内容后展示已输入状态
- 可配置清除按钮用于一键清空
- 回车可触发提交或搜索
- 禁用状态不可输入
- 只读状态可复制但不可编辑
- 输入错误时展示错误状态和说明
- 字数限制场景应展示当前字数与最大字数

#### 11.13 使用建议

设计 Input 时应注意：

- Placeholder 不应替代 Label
- Label 说明字段是什么，Placeholder 说明如何填写
- 输入规则复杂时应提供辅助说明
- 校验提示应清晰可操作
- 文本输入应尽量减少格式负担
- 对固定格式内容可使用掩码或格式化
- 不应让用户输入本可以选择的固定枚举值

#### 11.14 AI 检索关键词

Input, 输入框, 文本输入, 单行输入, 文本域, TextArea, 搜索框, 密码输入, 前缀, 后缀, 清除按钮, 字数统计, Placeholder, Label, 表单输入, 标签输入, 搜索输入, 错误校验

#### 11.15 组件选择决策

当用户需要输入自由文本时，使用 Input。

如果输入内容是数字且需要数值控制，使用 InputNumber。

如果输入内容是日期或时间，使用 DatePicker。

如果输入内容来自固定选项，使用 Select、Radio 或 Checkbox。

如果输入内容是文件，使用 Upload。

### 12. InputNumber 数字输入框

#### 12.1 组件定位

InputNumber 数字输入框用于输入和编辑数值内容。它适合金额、数量、比例、小数、整数、排序值、库存、价格、阈值等需要数值校验的场景。

InputNumber 可以提供步进控制、最小值、最大值、精度、小数位、单位、前后缀和格式化展示能力。

#### 12.2 何时使用

当用户需要输入数字，并且系统需要对数字进行格式、范围或精度控制时，应使用 InputNumber。

适用场景包括：

- 输入金额
- 输入数量
- 输入价格
- 输入库存
- 输入比例或百分比
- 输入排序值
- 输入阈值
- 输入重量、长度、面积等带单位数值
- 表格中的数值编辑
- 表单中的数值字段

不适合使用 InputNumber 的情况：

- 输入内容虽然包含数字，但本质是文本标识，例如手机号、身份证号、邮编、银行卡号，应使用 Input
- 需要选择日期或时间，应使用 DatePicker
- 需要从固定数值选项中选择，应使用 Select 或 Radio
- 需要输入复杂公式，应使用专门表达式输入组件

#### 12.3 组件结构

InputNumber 通常包含：

- 数字输入区域
- Placeholder
- 步进按钮
- 前缀文字或符号
- 后缀单位
- 数值格式化展示
- 千分位分隔
- 精度控制
- 最小值限制
- 最大值限制
- 错误提示

#### 12.4 样式状态

InputNumber 的常见状态包括：

- 默认状态
- 输入状态
- 悬停状态
- 聚焦状态
- 禁用状态
- 只读状态
- 错误状态
- 超出范围状态
- 步进按钮可用状态
- 步进按钮禁用状态

#### 12.5 基础数字输入框

基础数字输入框用于普通数值输入。

适用场景：

- 数量
- 排序
- 权重
- 分数
- 阈值
- 库存

设计建议：

- 应限制非数字字符输入
- 应根据业务设置最小值和最大值
- 可支持整数或小数
- 错误状态应说明允许范围
- 不应使用普通 Input 让用户输入需要校验的数值

#### 12.6 带前缀 / 后缀的数字输入框

InputNumber 可通过前缀或后缀表达数值单位和语义。

常见方式：

- 货币符号
- 货币单位
- 百分号
- 件、个、次等数量单位
- kg、m、cm 等计量单位
- 自定义业务单位

设计建议：

- 单位应展示在输入框内部或相邻位置
- 用户不需要手动输入单位
- 单位位置应固定
- 前后缀不应干扰数值编辑
- 同一业务中单位展示方式应统一

#### 12.7 金额输入框

金额输入框是 InputNumber 的典型场景。

适用场景：

- 价格
- 金额
- 费用
- 预算
- 折扣金额
- 交易金额

设计建议：

- 金额可使用千分位分隔
- 小数位应符合币种要求
- 货币符号或货币单位应明确
- 金额输入建议右对齐，便于数字比较
- 金额错误提示应明确范围或格式

#### 12.8 精度与范围控制

InputNumber 应根据业务规则控制数值范围和精度。

常见规则：

- 最小值
- 最大值
- 整数限制
- 小数位限制
- 步进值
- 百分比范围
- 负数限制
- 千分位格式化

设计建议：

- 允许范围应在辅助说明中明确
- 超出范围应展示错误提示
- 步进按钮到达边界时应禁用
- 小数位不应超过业务需要
- 百分比场景通常应限制在合理范围内

#### 12.9 表格中的数字输入

InputNumber 可用于表格单元格内编辑数值。

设计建议：

- 表格内输入框应控制宽度
- 数字内容建议右对齐
- 聚焦时展示完整输入能力
- 悬停或点击时进入编辑态
- 错误状态应在单元格内或附近清晰展示
- 批量编辑时应避免误触

#### 12.10 交互规则

InputNumber 的交互应符合数值编辑预期。

交互规则：

- 点击输入框进入编辑状态
- 可通过键盘输入数字
- 可通过步进按钮增加或减少数值
- 到达最大值或最小值后应限制继续操作
- 输入非法字符时应拦截或校验提示
- 失焦时可格式化展示
- 禁用状态不可编辑
- 错误状态应说明数值要求

#### 12.11 使用建议

设计 InputNumber 时应注意：

- 数字类字段优先使用 InputNumber，而不是普通 Input
- 手机号、证件号、邮编等数字字符串不应使用 InputNumber
- 金额、比例、数量应明确单位
- 范围限制应提前告知用户
- 小数精度应符合业务真实需求
- 表格中使用时要保证右对齐和可编辑反馈
- 不应让用户手动输入单位或分隔符

#### 12.12 AI 检索关键词

#### 12.13 组件选择决策

当用户需要输入可计算的数值时，使用 InputNumber。

如果用户输入的是手机号、身份证号、邮编等数字字符串，应使用 Input。

如果用户需要选择日期或时间，应使用 DatePicker。

如果用户需要从固定数值选项中选择，应使用 Select 或 Radio。

如果用户需要输入金额、数量、比例、库存、价格等字段，优先使用 InputNumber。

### 13. Radio 单选框

#### 13.1 组件定位

Radio 单选框用于在一组选项中选择唯一一个选项。它适合表达互斥关系，即多个选项中只能有一个成立。

Radio 的特点是选项通常直接展示在页面中，用户可以一眼看到所有可选项并快速做出选择。

#### 13.2 何时使用

当用户需要在多个互斥选项中选择一个时，应使用 Radio。

适用场景包括：

- 选项数量较少的单选
- 表单中的互斥选择
- 配置项单选
- 筛选条件单选
- 支付方式、配送方式、类型选择
- 带说明的方案选择
- 卡片式单选
- 图文单选

不适合使用 Radio 的情况：

- 允许选择多个选项，应使用 Checkbox
- 选项数量很多，应使用 Select
- 只有开启和关闭两个状态且即时生效，应使用 Switch
- 选项存在层级关系，应使用 Cascader 或 TreeSelect
- 需要输入自定义内容，应结合 Input 或使用其他输入组件

#### 13.3 组件结构

Radio 通常包含：

- 单选控件
- 选项文案
- 选项辅助说明
- 选项组
- 选中状态
- 禁用状态
- 图文内容
- 卡片容器
- 标签 Label

#### 13.4 样式状态

Radio 的常见状态包括：

- 默认未选中
- 悬停状态
- 聚焦状态
- 选中状态
- 禁用未选中
- 禁用已选中
- 错误状态

Radio Button 或按钮式单选还包括：

- 默认按钮状态
- 悬停按钮状态
- 选中按钮状态
- 禁用按钮状态

#### 13.5 常规样式

Radio 可作为基础圆形控件出现，也可与文字、说明、图片或卡片组合。

常见组合：

- Radio + 主文案
- Radio + 主文案 + 辅助文案
- Radio + 图片
- Radio + 图文卡片
- Radio Button 按钮式单选
- Radio + 输入框
- Radio + 复杂说明区域

#### 13.6 尺寸与布局

Radio 单选样式分为大、中、小三种尺寸，统一圆角 6px。

##### 单选尺寸规格

| 属性 | 大号 (40px) | 中号 (32px) | 小号 (24px) |
|------|-----------|-----------|-----------|
| 文本左右内边距 | 16px | 16px | 12px |
| 勾选图标距右边缘 | 16px | 16px | 12px |

##### 卡片选择/大图选择

| 属性 | 规格 |
|------|------|
| 卡片高度 | 88px |
| 卡片宽度 | 120px |
| 卡片之间水平间距 | 16px |
| 选中边框与未选中卡片间距 | 24px |
| 子项垂直间距 | 8px |

##### 布局规则

- 横向布局：选项少、文案短、需快速比较时使用。
- 纵向布局：选项多、文案长、需逐项阅读时使用。
- 卡片式布局：含图片/说明/复杂信息时使用。

#### 13.7 Radio Button

Radio Button 适合在紧凑区域中表达互斥选项。

适用场景：

- 状态筛选
- 时间维度切换
- 类型切换
- 视图切换
- 选项较短的配置项

设计建议：

- 选项数量不宜过多
- 文案应短
- 选中状态应明确
- 不应与普通按钮混淆
- 不适合承载长说明内容

#### 13.8 图文单选与卡片单选

当选项需要通过图片、图标、描述或示例进行区分时，可使用图文单选或卡片单选。

适用场景：

- 模板选择
- 方案选择
- 入口类型选择
- 样式选择
- 布局选择
- 带示例图的业务选项

设计建议：

- 整张卡片应可点击
- 选中状态应明显
- 图片与文案应对应清晰
- 卡片大小应统一
- 说明文字不宜过长
- 禁用卡片应提供原因或不可用提示

#### 13.9 Radio 与 Input 组合

Radio 可以与 Input 组合，用于“选择某选项后补充输入”的场景。

适用场景：

- 选择“其他”后填写原因
- 选择自定义值
- 选择某类型后填写额外信息
- 单选方案中需要补充参数

设计建议：

- 只有对应 Radio 被选中时，关联 Input 才应可编辑
- 未选中时 Input 可禁用或弱化
- 输入内容应与当前选择项形成明确关系
- 校验规则应只在该选项被选中时触发

#### 13.10 交互规则

Radio 的交互应符合单选预期。

交互规则：

- 同一组选项中只能选择一个
- 点击单选控件或文案均可选中
- 已选中的 Radio 通常不可通过再次点击取消，只能切换到其他选项
- 禁用选项不可点击
- 选项组应有明确 Label
- 错误状态应提示必须选择或选择不合法
- 卡片式 Radio 应支持点击整个卡片选中

#### 13.11 使用建议

设计 Radio 时应注意：

- Radio 用于互斥选择，不应用于多选
- 选项数量较少时使用 Radio，数量多时考虑 Select
- 默认选项应谨慎设置，避免误导用户
- 文案应平行、简洁、可比较
- 选项顺序应符合业务逻辑
- 复杂选项应增加辅助说明
- 卡片式单选应保证选中状态明显
- 不应使用 Radio 表达即时开关状态

#### 13.12 AI 检索关键词

Radio, 单选框, 单选, 互斥选择, 单选组, Radio Button, 按钮式单选, 图文单选, 卡片单选, 方案选择, 类型选择, 配置单选, 表单单选, 横向布局, 纵向布局, Label 布局

#### 13.13 组件选择决策

当用户需要从多个互斥选项中选择一个时，使用 Radio。

如果用户可以选择多个选项，使用 Checkbox。

如果选项数量很多，使用 Select。

如果是二元状态且点击后立即生效，使用 Switch。

如果选项存在层级关系，使用 Cascader 或 TreeSelect。

如果选项需要图文说明或方案对比，可使用卡片式 Radio。

### 14. TimePicker 日期时间选择器 / 时间选择器

#### 14.1 组件定位

TimePicker 用于选择时间、时间范围或带日期的具体时间点。它帮助用户以结构化方式输入时、分、秒等时间信息，避免手动输入造成格式错误。

在组件命名上，当前指南中标题为“日期时间选择器 TimePicker”，但从组件能力看，它主要覆盖时间选择以及日期与时间组合选择。若任务只需要选择日期，应使用 DatePicker；若任务需要选择时分秒或日期时间，应使用 TimePicker 或日期时间类型的 DatePicker。

#### 14.2 何时使用

当用户需要选择具体时间、时分、时分秒、日期时间或日期时间范围时，应使用 TimePicker。

适用场景包括：

- 选择某个具体时间点
- 选择时分
- 选择时分秒
- 选择日期 + 时分
- 选择日期 + 时分秒
- 设置任务执行时间
- 设置预约时间
- 设置开始时间和结束时间
- 配置生效时间、截止时间、提醒时间
- 设置营业时间、排班时间、定时规则

不适合使用 TimePicker 的情况：

- 只需要选择日期，使用 DatePicker
- 只需要选择月份或年份，使用 DatePicker 的月 / 年类型
- 只需要输入普通文本，使用 Input
- 需要选择固定时间段枚举，例如“上午 / 下午 / 晚上”，可使用 Select 或 Radio
- 时间规则非常复杂时，可使用自定义时间配置组件

#### 14.3 组件结构

TimePicker 通常包含：

- 输入框：展示当前选择的时间或日期时间
- 下拉面板：承载时间选择内容
- 时间面板：支持选择时、分、秒
- 日期面板：在日期时间类型中支持选择日期
- 扩展菜单：支持对日期时间选择进行自由扩展
- 清除入口：用于清空当前选择
- 确认按钮：用于确认选择结果
- 当前选中状态：表示用户当前选择的时间值
- 禁用项：表示不可选择的时间值
- 快捷操作：如“此刻”“当前时间”等

#### 14.4 布局尺寸

TimePicker 的布局应保证时间列清晰、可滚动、易选择。

设计建议：

- 时、分、秒应按列展示
- 每列宽度应保持一致
- 当前选中值应高亮展示
- 时间列应支持滚动
- 底部操作区应包含清除和确认入口
- 日期时间组合时，日期面板与时间面板应保持清晰分区
- 面板高度不宜过大，应避免遮挡主要操作区域

#### 14.5 选择类型

TimePicker 常见选择类型包括：

- 时分
- 时分秒
- 年月日时分
- 年月日时分秒

当业务只需要分钟级精度时，应使用“时分”类型。

当业务需要精确记录秒级时间时，才使用“时分秒”类型。

当时间必须绑定具体日期时，应使用“年月日时分”或“年月日时分秒”类型。

#### 14.6 样式状态

TimePicker 的常见状态包括：

- 默认状态
- 悬停状态
- 聚焦状态
- 已选择状态
- 当前时间状态
- 禁用时间状态
- 错误状态
- 清除状态
- 展开状态
- 确认状态

#### 14.7 日期时间组合选择

当用户需要同时选择日期和时间时，应使用日期时间组合面板。

适用场景：

- 预约开始时间
- 活动开始时间
- 任务执行时间
- 定时发布时间
- 生效时间
- 截止时间

设计建议：

- 日期和时间的选择区域应清晰分离
- 用户应先选择日期，再选择时间
- 时间默认值应符合业务预期
- 若需要确认按钮，应避免用户误以为选择后立即生效
- 不需要秒级精度时，不应展示秒列

#### 14.8 交互规则

TimePicker 的交互应降低时间输入错误。

交互规则：

- 点击输入框打开时间选择面板
- 用户通过滚动或点击选择时、分、秒
- 点击清除入口可清空已选时间
- 点击确认按钮写入最终值
- 禁用时间不可选择
- 输入框允许手动输入时，应进行格式校验
- 日期时间类型中，日期和时间都满足规则后才可确认
- 选择范围时，结束时间不应早于开始时间

#### 14.9 使用建议

设计 TimePicker 时应注意：

- 根据业务选择最小必要时间精度
- 不要在只需要时分时展示秒
- 不要在只需要日期时使用 TimePicker
- 高频固定时间可提供快捷项
- 时间格式应统一，例如 HH:mm 或 HH:mm:ss
- 禁用时间应有明确视觉状态
- 错误提示应说明正确格式或可选范围
- 日期时间组合中应避免日期与时间关系不清

#### 14.10 TimePicker 与 DatePicker 的区别

DatePicker 主要用于选择日期、月份、年份、日期区间或日期时间区间。

TimePicker 主要用于选择具体时间、时分秒，或与日期结合选择具体日期时间点。

如果用户任务关注“哪一天”，优先使用 DatePicker。

如果用户任务关注“几点几分”，优先使用 TimePicker。

如果用户任务关注“某一天的几点几分”，使用日期时间组合选择。

TimePicker, 时间选择器, 日期时间选择器, 时分, 时分秒, 年月日时分, 年月日时分秒, 时间面板, 时间下拉, 任务执行时间, 预约时间, 生效时间, 截止时间, 定时规则, 时间格式, 禁用时间, 确认按钮

#### 14.12 组件选择决策

当用户需要选择具体时间、时分秒或日期时间时，使用 TimePicker。

如果用户只需要选择日期、月份、年份或日期区间，使用 DatePicker。

如果用户只需要从固定时间段中选择，例如上午、下午、晚上，使用 Select 或 Radio。

如果用户需要输入自由文本时间说明，使用 Input。

### 15. Select 选择器

#### 15.1 组件定位

Select 选择器用于从预设选项中选择一个或多个值。它适合在有限空间内承载选项列表，并通过下拉面板帮助用户完成选择。

Select 是通用选择类组件，常用于表单、筛选条件、配置项、搜索条件、弹窗、抽屉和表格编辑中。

#### 15.2 何时使用

当用户需要从一组预设选项中选择一个或多个选项时，应使用 Select。

适用场景包括：

- 从枚举值中选择
- 从状态列表中选择
- 从类型列表中选择
- 从人员、角色、标签中选择
- 表单中的下拉选择
- 筛选条件中的下拉选择
- 表格行内选择
- 多选标签选择
- 支持搜索的下拉选择

不适合使用 Select 的情况：

- 选项数量很少且需要直接展示，优先使用 Radio
- 选项允许多选且数量较少、需要全部露出，优先使用 Checkbox
- 选项存在层级路径，使用 Cascader
- 选项是树形结构，使用 TreeSelect
- 需要输入自由文本，使用 Input
- 需要选择日期或时间，使用 DatePicker 或 TimePicker

#### 15.3 组件结构

Select 通常包含：

- 触发框 / 选择框：展示当前选中值
- 输入区域：可用于搜索或输入关键词
- 展开箭头：提示可展开下拉
- 清除 Icon：用于清除当前选项
- 前缀 Icon：辅助表达选项类型或业务语义
- 下拉面板：承载选项列表
- 选项列表：展示可选择项
- 选项文案：展示选项名称
- 选中标记：表示当前已选项
- 多选标签：多选模式下展示已选项
- 空状态：无匹配结果时展示
- 加载状态：远程搜索或异步加载时展示

#### 15.4 样式类型

Select 常见类型包括：

- 默认选择框
- 标签选择框
- 单选 Select
- 多选 Select
- 可搜索 Select
- 可清除 Select
- 远程搜索 Select
- 带 Icon 的 Select
- 分组 Select

默认选择框适合从少量或中等数量选项中选择一个值。

标签选择框适合从多个选项中选择多个值，并用标签展示结果。

可搜索 Select 适合选项较多或用户需要快速定位选项的场景。

远程搜索 Select 适合选项数据量大、需要服务端搜索的场景。

#### 15.5 尺寸与布局

##### 基础尺寸

| 属性 | 规格 |
|------|------|
| 整体高度 | 32px |
| 圆角 | 6px |
| 左右内边距 | 12px |
| 下拉箭头图标距右边缘 | 8px |
| 图标垂直居中距边缘 | 16px |

- 选择框高度应与同类输入组件保持一致。

##### 下拉选项列表

| 属性 | 规格 |
|------|------|
| 选项行高度 | 32px |
| 选项之间间距 | 8px |
| 全选与选项内部对齐间距 | 8px |
| 全选到第一个选项间距 | 12px |

##### 标签选择框（多选）

| 属性 | 规格 |
|------|------|
| 标签之间间距 | 稳定间距 |
| 超出宽度时 | 折叠为数量提示 |
| 标签文本过长 | 省略 |
| 删除标签 | 不影响其他已选项 |

#### 15.7 支持搜索

当选项较多或用户难以快速扫描时，Select 应支持搜索。

搜索规则：

- 输入关键词后过滤或请求选项
- 搜索结果应高亮或明确展示匹配项
- 无结果时展示空状态
- 搜索过程可展示 loading
- 远程搜索应考虑防抖
- 搜索结果应避免丢失必要上下文

#### 15.8 选项超长适配

当 Select 选项文案过长时，应提供统一处理规则。

常见方式：

- 默认单行省略
- Hover 展示完整 Tooltip
- 下拉面板适当加宽
- 选项内容换行展示
- 使用辅助说明承载长内容

设计建议：

- 不应让超长文本撑破布局
- 不应只展示无法区分的截断文本
- 对关键业务选项，应提供完整查看方式
- 下拉面板宽度应与内容和页面空间平衡

#### 15.9 交互规则

Select 的交互应符合下拉选择预期。

交互规则：

- 点击选择框展开下拉面板
- 点击选项后完成选择
- 单选模式下选择后通常关闭下拉
- 多选模式下选择后可继续选择
- 点击清除 Icon 可清空当前选择
- 禁用状态不可展开或选择
- 支持搜索时，输入关键词过滤选项
- 支持键盘操作时，可通过上下键移动焦点，Enter 选择
- 失焦或点击外部时关闭下拉

#### 15.10 使用建议

设计 Select 时应注意：

- 选项文案应简洁、可区分
- 选项数量较多时提供搜索
- 选项过多时考虑远程搜索或分页加载
- 多选结果过多时使用标签折叠
- 默认值应谨慎设置，避免误导用户
- Placeholder 应说明选择要求
- 选项分组可提升扫描效率
- 不应使用 Select 承载复杂层级树数据

#### 15.11 Select 与其他选择组件的区别

Select 适合从扁平预设选项中选择一个或多个值。

Radio 适合少量互斥选项直接展示。

Checkbox 适合少量或中等数量的多选项直接展示。

Cascader 适合路径型层级数据选择。

TreeSelect 适合树形结构数据选择。

Input 适合自由文本输入，而不是固定选项选择。

#### 15.12 AI 检索关键词

Select, 选择器, 下拉选择, 单选下拉, 多选下拉, 标签选择, 可搜索选择器, 远程搜索, 选项列表, 扁平枚举, 状态选择, 类型选择, 角色选择, 标签选择, 清除 Icon, 下拉面板, 超长选项, 标签折叠

#### 15.13 组件选择决策

当用户需要从预设扁平选项中选择一个或多个值时，使用 Select。

如果选项很少且需要直接展示，单选用 Radio，多选用 Checkbox。

如果选项存在层级路径，使用 Cascader。

如果选项是树形结构，使用 TreeSelect。

如果用户需要输入自由文本，使用 Input。

### 16. Sidebar Contents 分栏目录

#### 16.1 组件定位

Sidebar Contents 分栏目录用于在侧边区域展示一组目录、分类、对象列表或导航项，帮助用户在多个内容区域、配置模块或数据对象之间快速切换。

它本质上更偏导航和信息组织组件，不是传统输入控件。但在后台系统、复杂配置页、分类管理、对象选择、数据筛选和分栏编辑场景中，它也可以作为选择入口，辅助用户完成数据录入或内容编辑任务。

#### 16.2 何时使用

当页面内容较多，需要通过侧边目录进行分组定位、对象切换或分类选择时，可以使用 Sidebar Contents。

适用场景包括：

- 复杂表单中的分组导航
- 配置页面中的模块目录
- 分类列表与右侧内容联动
- 左侧对象列表 + 右侧详情编辑
- 数据管理页面中的目录筛选
- 权限配置中的侧边分类
- 多级菜单目录
- 页面锚点定位
- 分栏布局中的内容导航

不适合使用 Sidebar Contents 的情况：

- 只有少量字段或少量内容，不需要侧边目录
- 用户需要选择一个普通枚举值，应使用 Select 或 Radio
- 用户需要选择树形数据节点，应使用 TreeSelect 或 Tree
- 用户需要路径型层级选择，应使用 Cascader
- 移动端或极窄空间中，侧边目录可能占用过多空间

#### 16.3 组件结构

Sidebar Contents 通常包含：

- 侧边容器：承载目录区域
- 目录标题：说明当前目录内容
- 一级目录项：主要分类或模块
- 二级目录项：子分类或子模块
- 展开 / 收起控件：控制多级目录显隐
- 当前选中项：表示当前正在查看或编辑的内容
- 悬停状态：提示目录项可点击
- 操作按钮：如确认、取消、关闭、更多操作
- 搜索框：用于快速查找目录项
- 滚动区域：用于承载较长目录
- 分栏内容区：通常与右侧页面内容联动

#### 16.4 尺寸与布局

Sidebar Contents 的宽度应根据内容层级和页面布局确定。

常见宽度范围：

- 小尺寸：约 200px，适合简单目录或轻量导航
- 中尺寸：约 240px，适合常规后台页面目录
- 大尺寸：约 280px，适合目录层级较多或文案较长的场景

设计建议：

- 侧边目录不应占用过多主内容空间
- 目录项宽度应能容纳主要文案
- 超长目录项应省略或 Tooltip
- 目录较长时应支持独立滚动
- 底部操作区可固定，避免滚动后不可见
- 右侧内容区域应与目录选中项保持联动

#### 16.5 样式状态

Sidebar Contents 的常见状态包括：

- 默认状态
- 悬停状态
- 选中状态
- 禁用状态
- 展开状态
- 收起状态
- 搜索状态
- 空结果状态
- 滚动状态
- 固定底部操作状态

目录项通常需要清晰区分当前选中内容，避免用户不知道右侧内容对应哪个目录项。

#### 16.6 目录层级

Sidebar Contents 可支持一级目录或多级目录。

一级目录适合：

- 内容结构简单
- 模块数量有限
- 用户只需要在同级内容间切换

多级目录适合：

- 内容存在父子分类
- 配置项按模块分层
- 数据对象存在归类关系
- 需要展开或折叠子项

设计建议：

- 层级不宜过深
- 展开层级应通过缩进表达
- 当前选中项应有高亮
- 父级展开状态应清晰
- 目录层级过深时，应考虑 Tree 或 TreeSelect

#### 16.7 搜索与筛选

当目录项较多时，Sidebar Contents 可提供搜索能力。

搜索规则：

- 搜索框通常放在目录顶部
- 输入关键词后过滤目录项
- 搜索结果应保留必要层级上下文
- 无结果时展示空状态
- 搜索关键词应支持清除
- 远程目录搜索应展示加载状态

#### 16.8 底部操作区

部分分栏目录场景中，底部会提供确认、取消或其他操作按钮。

适用场景：

- 弹窗中的目录选择
- 分栏选择器
- 批量配置
- 多模块配置保存
- 需要确认后才应用选择的目录操作

设计建议：

- 底部操作区应固定在侧边栏底部
- 主操作与次操作应区分
- 若点击目录即切换内容，底部按钮应明确作用范围
- 不应让用户误以为目录点击已经完成提交

#### 16.9 交互规则

Sidebar Contents 的交互应保证导航与内容联动清晰。

交互规则：

- 点击目录项切换右侧内容或定位到页面区域
- 点击展开图标展开或收起子目录
- 当前目录项应保持选中高亮
- 鼠标悬停目录项时展示可点击反馈
- 目录过长时支持滚动
- 搜索后展示匹配目录项
- 目录项禁用时不可点击
- 底部操作按钮用于提交、取消或关闭当前选择

#### 16.10 使用建议

设计 Sidebar Contents 时应注意：

- 只有内容分组较多时才使用
- 目录名称应短且可区分
- 当前选中状态必须明显
- 多级目录不宜过深
- 左侧目录与右侧内容应保持稳定映射
- 目录搜索应保留层级上下文
- 在弹窗中使用时应控制高度和滚动区域
- 不应将 Sidebar Contents 当作普通下拉选择器使用

#### 16.11 Sidebar Contents 与相关组件的区别

Sidebar Contents 适合页面级或区域级内容导航，以及左侧目录 + 右侧内容联动。

Select 适合在表单字段中选择扁平选项。

TreeSelect 适合在下拉框中选择树形节点。

Tree 适合展示完整树结构或进行树节点管理。

Cascader 适合路径型层级选择。

Tabs 适合少量同级模块切换。

#### 16.12 AI 检索关键词

Sidebar Contents, 分栏目录, 侧边目录, 侧边导航, 分栏选择, 目录导航, 左侧目录, 右侧内容, 配置目录, 分类导航, 多级目录, 目录搜索, 选中项, 展开收起, 页面锚点, 分组导航, 后台系统导航

#### 16.13 组件选择决策

当页面内容较多，需要通过左侧目录定位、切换或筛选右侧内容时，使用 Sidebar Contents。

如果用户只是在一个字段中选择值，应使用 Select、TreeSelect 或 Cascader。

如果用户需要展示完整树结构并管理节点，应使用 Tree。

如果用户只需要少量同级页面切换，可使用 Tabs。

如果目录项较多，应提供搜索、滚动和明确的选中状态。

## 上传文件 · 场景指南（知识整理）


> 适用场景：表单 / 页面 / 弹窗中「文件上传」交互的设计参考

### 一、何时使用

提供合适的上传模式，帮助用户高效完成数据录入任务。

### 二、组件结构

#### 1. 按钮上传（上传结果：文件名显示 / 缩略图+文件名展示）

- **上传前**：
  - ① 上传 icon：必有，展示在上传按钮内；
  - ② 上传按钮：必有，支持点击选择文件；
  - ③ 描述文案：对上传文件大小 / 格式等的描述信息。
- **上传中**（按钮上传）：
  - 1. 上传文件结果热区背景：必有，根据业务需求展示其宽度；
  - 2. 文件名称：必有，延用上传时名称，展示不下省略，支持 hover 查看详情；
  - 3. 加载动效：文件过大 / 网速慢时上传过程的加载动效；
  - 4. 加载进度条：根据文件上传进度实时变化；
  - 5. 删除 icon：对上传进度中的文件进行删除。
- **上传后**（按钮上传）：
  - 1. 上传成功：必有，文件 icon + 文件名称正常展示；
  - 2. 查看 icon：支持点击查看文件内容；
  - 3. 下载：支持下载已上传文件；
  - 4. 上传失败：失败时必有，文件 icon + 标红文件名称展示；**不支持查看和下载**。

#### 2. 照片墙上传

- **上传前**：
  - ① 照片墙上传背景框：必有；
  - ② 上传按钮：必有，点击添加（`点击添加上传内容`）。
- **上传中**：
  - 加载进度条：必有，原点击上传按钮变为上传加载进度，文案改为「上传中」。
- **上传后**：
  - 1. 上传成功：必有，展示图片缩略图；
  - 2. 上传成功 hover：必有，hover 时支持点击查看大图、下载和删除；
  - 3. 上传失败：图片失败缩略图、标红展示、展示图片名称（最多两行，展示不下省略）；
  - 4. 上传失败 hover：必有，hover 时支持删除；
  - 5. 图片上传：必有，图片缩略图 + 图片名称。

#### 3. 拖拽上传

- **上传前**：
  - 1. 背景框：必有，支持点击或把文件拖拽进入；
  - 2. 文件 icon：必有；
  - 3. 文案：必有，可自定义添加辅助文案；
  - 默认文案：`点击或拖拽到此区域上传`。
- **上传中**：拖拽 + 按钮结果反馈（1 / 2）：选用；
- **上传后**：上传结果为文件列表或缩略图列表。

### 三、页面框架结构

#### 1. 按钮上传（多用在表单字段中）

```
[①上传icon ②上传按钮] ③描述文案（文件大小/格式说明）
  上传中：②上传按钮（加载动效/进度条） + 文件名称 xxx.png（可删除）
  上传后：[上传按钮] + 文件项：文件icon + 文件名称 [查看icon][下载][删除]
  上传失败：文件icon + 标红文件名称（不支持查看和下载）
```

#### 2. 图片墙上传（多用在表单字段中）

```
[①背景框 + ②上传按钮（+）]     → 点击添加上传内容
  上传中：背景框内加载进度条（文案「上传中」）
  上传后：图片缩略图网格（可 hover 查看大图/下载/删除）
         失败项：失败缩略图 + 标红图片名称（hover 可删除）
```

#### 3. 拖拽上传（多用在页面/弹窗等容器中）

```
┌────────────────────────────────┐
│ ①背景框 + ②文件icon + ③文案     │
│ 点击或拖拽到此区域上传            │
│ （这里是描述文案）               │
└────────────────────────────────┘
  上传后（文件列表）：文件名称.mp4 / 图片名称.png / 未知类型文件 …
  上传后（缩略图列表）：图片缩略图网格
```

### 四、样式状态

#### 1. 按钮点击上传【多用在表单字段中】

- 状态：`常规` / `带描述文案` / `上传中` / `上传失败` / `有上传结果-文件列表`。

#### 2. 图片墙上传【多用在表单字段中】

- 通过图片缩略模式选择上传图片/文件，上传的图片在页面中呈缩略图显示；
- 当仅图片时可不展示文件名称；当为文件时需要展示文件名称；
- 可以 hover 缩略图进行查看、下载、删除交互；
- 状态：`仅图片墙上传` / `图片墙样式上传所有文件样式`（常规 / 上传中 / 上传失败 / 有上传结果-文件列表）。

#### 3. 拖拽上传【多用在页面/弹窗等容器中】

- 用户拖拽文件到指定区域即可完成上传，也支持点击上传；
- 上传结果支持两种形态：`文件列表` / `缩略图列表`。

### 五、支持的文件类型（缩略图 icon）

视频（FileVideo）、音频（FileRadio）、未知类型文件（FileUnknown）、压缩文件（FileZip）、Word 文件（FileWord）、PDF 文件（FilePdf）、PPT 文件（FilePpt）、OneNote 文件（FileOnenote）、Text 文件（FileText）、Axure 文件（FileAxure）、Excel 文件（FileExcel）。

### 六、关键交互要点（速记）

1. **三种上传模式**：按钮上传（表单字段）、图片墙上传（图片/文件）、拖拽上传（页面/弹窗容器）；
2. **上传前**：icon + 按钮 + 描述文案（大小/格式约束）三要素必有；
3. **上传中**：加载动效 + 进度条 + 文件名（可删除）；
4. **上传后**：成功项支持查看 / 下载；失败项标红展示且不支持查看、下载；
5. **照片墙**：hover 缩略图提供查看大图、下载、删除；失败缩略图 hover 可删除；
6. **文件名称规则**：延用上传时名称，过长省略，hover 查看详情（照片墙最多两行省略）。

## 上传文件 (Upload Files)


- **【上传文件 (Upload Files)】**
  - **设计策略**：入口分为按钮上传（列表/平铺展示）和拖拽上传两种。对文件大小、格式、数量进行前置校验。
  - **组件结构**：
    - 文件列表模式：显示文件名、大小、状态（上传中、成功、失败），支持删除与重试。
    - 图片墙/相册模式：带遮罩预览、支持查看大图和删除。
    - 拖拽区域：允许将文件拖入指定区域，并在拖入时高亮。
