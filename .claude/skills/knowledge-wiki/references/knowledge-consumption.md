# 知识问答规则

用于查询当前正式知识库中已有的业务规则、字段、状态、页面路径、菜单、权限、流程边界、设计准则和交互模式。

## 一、问题定界

- 每次问答包括追问都必须按当前问题重新判断事实闭环。可以继承当前会话中已经实际读取且范围明确的正式事实；不得因上轮已经回答而省略本次必要事实，也不得用未经核验的对话记忆替代正式知识。
- 读取前必须确认：询问对象、询问关系、适用范围、需要回答到什么深度，以及是否要求封闭全集。
- 事实身份与事实边界遵守 `SKILL.md` 的统一事实边界；二者任一不同，不得判定为重复或冲突。
- 结论必须由直接承担当前问题事实责任的正式章节支撑；不得按问题关键词固定映射文件。
- 问题来自 FAQ、操作指引或外部资料，不改变证据责任。询问角色、任务、规则、状态、结果、边界或上下游依赖时，必须先读取对应正式责任文件；不得直接以问答块作为结论真源。

## 二、最短关联消费

1. 先读 `knowledge/wiki/index.md`，按需求信号选择直接回答问题的知识类型、业务集合或主域。
2. 按 index 指向进入必要的业务集合 README 或领域 README；学习其实际文件路由，只读明确命中的下一层或正式文件，不得把维护侧的八类名称写死为消费选择表。
3. 文件内容较大且问题只命中局部主题时，必须先看顶部场景路由或快速导航，再读取完整命中章节；只有问题覆盖文件大部分主题时才允许全文读取。`页面与字段.md` 默认只读命中页面章节；问答与差异默认只在操作指引、排障、帮助、收费协议、外部动态、历史或差异查证问题中读取命中问题块。
4. 按第三部分的完整性门禁确定关联消费范围；仅有关键词相近或业务相邻，不构成读取理由。
5. 只有主域路由中的条件依赖被当前问题实际触发时，才进入依赖域并读取命中内容；随后必须回到主域完成结论闭环。
6. 路由未定位到正式知识时直接说明缺口，不遍历 `raw/` 补救，不补造结论。

问答与差异不属于需求分析、规则确认或事务闭环的默认读物。只有正式知识出现明确冲突、缺口或需要追溯来源，或用户直接询问其承担的辅助内容时，才按需补读；补读也不能替代正式责任文件。

路由层数不固定；业务领域和独立子域 README 负责边界与文件选择，不要求 README 重复维护章节目录。

## 三、回答双门禁

按 `SKILL.md` 的问答双门禁执行以下检查。

### 3.1 完整性门禁

- 必须覆盖直接回答当前问题的事实，以及缺失后会改变答案正确性、完整性或适用性的条件、例外、状态、结果、权限、异常和审计事实。
- 命中局部知识后不得立即停止；但未被当前问题触发的相邻知识不得为追求“全面”而扩入答案。
- “几种”“有哪些”“全部”等封闭枚举，必须命中承担当前问题直接事实责任的完整正式清单，并确认其范围覆盖当前问题。
- 直接问题已经讲清、必要关联事实已经闭环，且继续读取不会改变结论时，必须停止。

### 3.2 证据一致性门禁

- 每条准备输出的结论都必须由正式知识支持相同的对象、关系、适用范围、条件、例外和表达强度；任一项不一致，必须删除该结论、限定到证据范围，或明确标记未知。
- 合成多个正式事实时，必须区分直接结论、场景专属约束和跨场景通用约束；不得把通用规则错误挂到单个项目，不得把场景规则复制到所有项目。
- 不得把局部场景提升为全局规则，不得把“可配置、开启后、支持”改写为固定前提，不得互换不同角色或业务主体。
- 流程图、典型路径、示例、FAQ 和页面局部默认只能证明其中项目存在；只有明确声明集合完整且适用范围一致时，才能证明全集。
- 实际读到多个可计数表达时：事实身份不同则分别保留；事实身份或事实边界无法确认则标记 `[QUESTION]`；事实身份、事实边界和直接事实责任相同但集合不同则标记 `[CONFLICT]`，不得凭更新时间猜测。

### 3.3 未通过时

- 无法证明完整全集时，必须说明只能确认局部或无法确认总数；不得把局部事实表述为全集，也不得为此遍历整个 `raw/`。
- `[GAP]`、`[QUESTION]` 或 `[CONFLICT]` 影响结论时，只说明必要边界，不得用推断补齐。
- 双门禁只作内部检查，不向用户展示读取过程、检查项或门禁状态。

## 当前稳定设计知识

- 设计准则：从 index 直接进入单一原则集，先看场景路由，只读命中章节。
- 交互模式：从 index 进入交互模式 README，先读全局地图，再读命中的完整模式块，最后回看交互链是否闭合。

这两种结构是当前项目的高概率稳定默认，不将其推广为所有知识类型的固定模板。

## 输出要求

- 说明当前知识库如何定义。
- 说明该定义能支撑什么结论。
- 只输出业务答案，不复述内部拆解和读取过程。

## 边界

需求是否合理、方案如何设计、体验如何诊断、流程如何优化和功能是否应该实现不属于知识问答，应转回 UXB。
