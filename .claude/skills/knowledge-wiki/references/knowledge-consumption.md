# 知识问答规则

用于查询当前正式知识库中已有的业务规则、字段、状态、页面路径、菜单、权限、流程边界、设计准则和交互模式。

## 最短读取顺序

1. 先读 `knowledge/wiki/index.md`，按需求信号选择直接回答问题的知识类型、业务集合或主域。
2. 按 index 指向进入必要的业务集合 README 或领域 README。
3. 学习 README 的实际文件路由，只读明确命中的下一层或正式文件；不得把维护侧的八类名称写死为消费选择表。
4. 文件内容较大且需求只命中局部主题时，必须先看顶部场景路由或快速导航，再读取完整命中章节；只有需求覆盖文件大部分主题时才允许全文读取。`页面与字段.md` 默认只读命中页面章节，FAQ 默认只读命中问题块。
5. 只有主域路由中的条件依赖被实际需求触发时，才进入依赖域并读取命中内容。
6. 读完依赖域后回到主域，补齐对象、规则、状态、结果、异常、审计与缺口闭环。
7. 达到最小充分证据后停止。路由未定位到正式知识时直接说明缺口，不遍历 raw 补救，不补造结论。

路由层数不固定；业务领域和独立子域 README 负责边界与文件选择，不要求 README 重复维护章节目录。

## 内部停止条件

- 命中局部知识后不得停止；问题涉及的主体、动作、条件、例外、结果及已触发依赖均有正式依据后再输出。
- 回答前确认询问对象、询问关系、适用范围，以及是否要求封闭全集。
- 事实身份由对象、关系和适用范围共同确定；三项不同，不得判定为重复或冲突。
- 结论必须由直接承担当前问题事实责任的正式章节支撑，不得按问题关键词固定映射文件。
- 流程图、典型路径、示例、FAQ 和页面局部默认只能证明其中项目存在；只有明确声明集合完整且适用范围一致时，才能证明全集。
- “几种”“有哪些”“全部”等封闭枚举，只有命中完整正式清单、范围覆盖当前问题，且已读内容不存在同一事实身份与事实责任的冲突时，才能停止。
- 无法证明全集时，必须说明只能确认局部或无法确认总数；不得把局部事实表述为全集，也不得为此遍历整个 `raw/`。
- 实际读到多个可计数表达时：事实身份不同则分别保留；事实身份无法确认则标记 `[QUESTION]`；事实身份和直接事实责任相同但集合不同则标记 `[CONFLICT]`，不得凭更新时间猜测。
- 以上只作内部检查，不向用户展示读取过程、检查项或闭环状态；证据不足影响正确性时，只说明必要边界。

## 当前稳定设计知识

- 设计准则：从 index 直接进入单一原则集，先看场景路由，只读命中章节。
- 交互模式：从 index 进入交互模式 README，先读全局地图，再读命中的完整模式块，最后回看交互链是否闭合。

这两种结构是当前项目的高概率稳定默认，不将其推广为所有知识类型的固定模板。

## 输出要求

- 说明当前知识库如何定义。
- 说明该定义能支撑什么结论。
- 只输出业务答案，不复述内部拆解和读取过程。
- `[GAP]`、`[QUESTION]` 或 `[CONFLICT]` 会影响结论时，用最少文字说明边界；不得用推断补齐。

## 边界

需求是否合理、方案如何设计、体验如何诊断、流程如何优化和功能是否应该实现不属于知识问答，应转回 UXB。
