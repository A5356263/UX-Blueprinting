# 领域划分指南

## 适用条件

仅在以下任一条件成立时使用本指南：

- 用户提供的材料没有明确产品、业务集合、应用、领域或子域分类。
- 用户明确说明现有目录只是临时整理。
- 用户明确要求重新梳理领域。

用户已明确分类时，直接保留用户分类，不执行 Agent 重新划分。

## 分类优先级

必须按以下顺序判断，不得调换：

1. 用户明确指定的产品、业务集合、应用、领域或子域。
2. 用户明确说明为正式结构的现有产品目录或应用结构。
3. 当前知识库已经确认的领域契约。
4. 根据业务对象、用户任务、规则、状态生命周期和维护责任推导。
5. 无法稳定判断时进入候选。

普通文件夹、下载目录、材料包目录和上传顺序只作为线索，不视为用户明确分类。

## 层级定义

- 业务集合：稳定产品线、产品套件、业务系统或一级业务分类。
- 领域或子域：独立应用、功能模块、稳定业务能力或具有独立结果责任的业务单元。
- 信息类型：领域内部知识回答的问题性质，不是领域层级。
- 领域专属主题：具体对象、功能或页面主题；只能作为固定类型文件内章节，不得派生自定义文件类型。

## 新领域成立条件

提议新领域或子域时，必须同时写清：

- 它回答的稳定业务问题。
- 它拥有的核心对象、规则、状态或最终结果。
- 它与相邻领域的负责和不负责范围。
- 它对应的独立应用、功能模块或持续维护责任。
- 它不能归入已有领域的原因。

标题不同、页面不同、文件较多、文档较长或关键词不同，均不能单独成立新领域。

## 主域与依赖域

- 拥有当前对象最终状态和结果解释权的领域是主域。
- 依赖域只提供会改变主域规则、状态、责任、生效、异常或审计的输入。
- 同一事实只保留一个主归属；其他领域通过条件依赖路由补读。
- 读取依赖域后必须回到主域确认最终结果。

## 用户分类冲突

用户分类与现有知识库冲突时：

1. 保留用户原分类与原始材料。
2. 标记重叠、冲突和影响。
3. 给出建议归属与依据。
4. 未经用户确认不得移动、合并、覆盖或删除正式知识。

## 停止条件

出现以下任一情况时停止正式入库并进入候选：

- 无法确定主域及最终结果所有权。
- 两个领域都声称拥有同一事实且没有裁决依据。
- 新领域边界无法写清。
- 用户明确分类与现有结构冲突但尚未确认处理方式。
- 只能依据文件名、目录位置或单个关键词推断领域。
