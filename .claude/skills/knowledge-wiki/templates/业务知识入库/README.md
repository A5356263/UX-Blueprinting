# 业务知识入库模板

## 这是什么

这里定义正式业务知识的固定信息类型及轻量骨架。模板是入库参考，不是正式知识，也不是机械填空表。

这些模板不属于正式知识，不进入 `wiki/index`，也不直接参与主链路消费。

## 使用入口

- `领域划分指南.md`：仅在材料缺少用户明确分类，或用户明确要求重新梳理领域时读取。
- `信息类型目录.md`：确定主域后必须读取，用于选择八类固定载体、合入章节或进入候选。
- `领域README.template.md`：新建业务领域，或已通过四项门禁的物理子域时使用，作为固定文件级路由入口。
- `功能与操作清单.template.md`：材料包含多个可独立检索的功能或操作记录时参考。
- 其余 `*.template.md`：确认存在对应事实后参考；不得为了凑齐类型创建空文件。

不要把本文件内容直接复制到业务领域目录中。

## 使用原则

1. 先判断知识集合、主域和现有落点，再在八类固定载体中选择唯一真源。
2. 先读取当前本地结构合同、index、命中的必要 README 或大文件导航，再参考这里的本地模板。
3. 先输出一次处理回执，确认后再落地 raw 或候选。
4. 有内容才建文件，不为形式完整批量造文件。
5. 八类文件名固定；同一领域或通过四项门禁的物理子域内，同一类型只允许一个文件。
6. 现有七类正文文件无法无损容纳时，必须先进入候选；只有同时满足 `信息类型目录.md` 的七项门槛并获得用户明确确认，才允许建立第九类。
7. 模板只提供结构，不预填具体业务语义。
8. 大文件可继续保留；行数只触发快速导航检查，不自动触发拆分。
9. README 只路由到文件；长文件用顶部快速导航定位章节。
10. 模板用于帮助 Agent 参考、复制并按材料组织知识；正式文件必须按实际事实、领域语义和消费目标增删章节与字段，不得照抄占位符、不适用结构或模板说明。
11. 模板中的推荐骨架表达该类知识的默认组织方式，不等同于每个领域、每个章节或每个记录的强制字段清单；信息不足时显式保留 `[GAP]`，不得为填满模板而推测。

## 固定文件名

- `领域README.template.md`
- `业务对象与术语.template.md`
- `功能与操作清单.template.md`
- `任务与路径.template.md`
- `规则与权限.template.md`
- `状态与异常.template.md`
- `页面与字段.template.md`
- `问答与差异.template.md`

## 不强制建满

如果某个领域信息较少，可以只保留：

- `README.md`
- 少量真正有内容的固定类型文件

如果信息还不稳定，应优先使用：

- `[GAP]`
- `[CONFLICT]`
- `[QUESTION]`

不要用空文件制造“完整感”。

## 禁止事项

- 不要把模板目录 README 当成业务领域 README
- 不要让模板进入 `knowledge/wiki/index.md`
- 不要让模板进入正式消费目录
- 不要把主链路消费说明写进模板
- 不要因文件行数自动拆分
- 不要把模板当作固定问卷，逐项填入无事实依据或无消费价值的内容
- 不要把模板注释、占位符和使用说明复制到正式知识
- 不要按模块、功能、来源文件或一次性主题重复创建同类型文件
- 不要把用户分类、菜单、应用或已有文件夹直接转换成物理子域；未通过四项门禁时必须作为父域文件章节
- 不要自行发明第九类文件
