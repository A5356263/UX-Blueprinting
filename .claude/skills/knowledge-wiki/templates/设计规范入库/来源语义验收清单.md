# 设计规范来源语义验收清单

## 使用方式

写入前按输入的自然章节、表格、结构图或明确步骤逐项核对。清单只用于当次验收，不要求生成长期台账或正式映射文件。

每个来源单元必须得到一种明确结果：

- 无损写入或无损合并
- 确认完全重复并保留唯一正文
- 保留 `[CONFLICT]`
- 标记 `[GAP]` 或 `[QUESTION]`
- 明确不属于设计规范

## 语义完整性

- [ ] 主体、对象和动作未被互换。
- [ ] 适用范围、前置条件和触发条件已保留。
- [ ] 明确数值、尺寸、数量、时间和阈值已保留。
- [ ] “必须、不得、可以、建议、开启后、支持”等表达强度未改变。
- [ ] 类型、优先级、状态和状态变化已保留。
- [ ] 操作步骤、顺序、分支和退出条件已保留。
- [ ] 成功结果、失败反馈、异常处理和恢复路径已保留。
- [ ] 例外、限制、禁止事项和适用终端已保留。
- [ ] 表格、结构关系和必要示例没有被概述替代。
- [ ] 不清晰或缺失的信息使用显式标记，没有推测补全。

## 结构与唯一责任

- [ ] 信息已进入样式、组件、典型页面或场景模式中的唯一主分类。
- [ ] 已有主题可以清晰承载时没有重复建文件。
- [ ] 新主题具有独立路由、回答和维护价值。
- [ ] 文件名和标题表达具体对象，没有重复上级目录语义。
- [ ] 根 README、分类 README 和主题顶部导航已按实际变化同步。
- [ ] 同一事实没有跨文件复制维护。

## 跨域提示

- [ ] 可归入设计准则或交互模式的信息仍完整保留在设计规范。
- [ ] 相关建议只在聊天窗口列出信息位置、核心内容、判断依据和建议归属。
- [ ] 没有修改设计准则或交互模式。
- [ ] 没有创建候选文件、未入库记录、映射表或其他持久化状态。

## 发布判断

任一会改变规范含义的检查项未通过时，不得发布对应修改。应修正文档、保留冲突或请求用户确认，不得以“整体已整理”替代逐单元验收。
