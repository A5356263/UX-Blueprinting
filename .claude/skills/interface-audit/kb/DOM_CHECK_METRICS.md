# DOM/A11Y 证据采集指标

本文档只用于帮助从 DOM、Accessibility Tree、runtime 和 computed style 中采集证据，不直接决定扣几分。扣分必须回到 `ASSESSMENT_CRITERIA.md` 的表格法：问题单元个数 × 档位单题分。

## 使用原则

- 先找到证据路径，再判断它对应哪个检查元素。
- DOM 指标只能证明“是否存在、是否可见、是否有状态、是否有关系”，不能单独证明真实点击率、完成率或用户满意度。
- 视觉判断需要截图、bbox 或 computed style；没有这些证据时，不评价颜色、遮挡、密度或层级。
- 指标异常只形成“一个或多个问题”的证据，不携带固定扣分值。
- 指标异常必须落到 `ASSESSMENT_CRITERIA.md` 中的 `criterion_id`，并写清 `expected` 与 `actual`；不能只写“看起来不清晰”。

## 通用证据字段

| 证据 | 可证明内容 |
| --- | --- |
| `role` / 标签名 | 控件语义、导航/表格/表单结构 |
| 可见文本 | 标题、标签、按钮、提示、错误文案 |
| `aria-*` | 可访问状态、错误状态、禁用状态、当前步骤 |
| `disabled` / `readonly` | 可操作与不可操作 |
| `href` / `type` / `form` | 链接、提交、输入关系 |
| `bbox` / viewport | 首屏可见性、遮挡、距离、密度 |
| computed style | 颜色、字号、间距、透明度、z-index |
| runtime event | 点击后状态变化、loading、toast、错误、成功反馈 |

## 元素证据点

### 1. 看得见

优先采集：

- 是否有 `<nav>`、面包屑、当前选中菜单或页面标题。
- 关键入口、筛选条件、对象范围是否在首屏或主区域可见。
- 核心信息与任务对象是否位于同一区域或相邻区域。
- 表格/列表/看板是否有明确标题、分组或状态标签。

可形成问题的证据：关键入口不可见、当前范围不清、导航与业务路径不匹配、核心信息被次要区域挤压。

### 2. 看得懂产品/功能

优先采集：

- `<h1>`、主要模块标题、说明文字。
- 按钮/链接是否表达“动作 + 对象/结果”。
- 页面是否说明业务对象、服务能力或预期结果。

可形成问题的证据：页面只展示对象不说明能力、标题过泛、操作结果不可见、能力只来自任务上下文而非界面。

### 3. 每句话都理解

优先采集：

- 按钮、标签、表头、空状态、错误提示、帮助说明。
- 专业术语、缩写、中英文混杂、同义词混用。
- 术语旁是否有 tooltip、说明、链接或示例。

可形成问题的证据：术语无解释、同一对象多种叫法、按钮文案泛化、错误/空状态只描述失败不说下一步。

### 4. 看得快

优先采集：

- 首屏平级模块数量、标题层级、表格列数、状态标签。
- 字号、颜色、粗细、位置是否形成主次。
- 核心操作和相关内容的距离。

可形成问题的证据：主次不清、平级信息过多、表格字段无优先级、核心状态或下一步被淹没。

### 5. 可操作/不可操作可感知

优先采集：

- `<button>`、`<a>`、`role="button"`、`disabled`、`aria-disabled`。
- 禁用控件是否有 `title`、tooltip、相邻说明或权限提示。
- 可点控件和普通文本的样式差异。

可形成问题的证据：看起来可点但不可点、禁用无原因、权限限制点击后才暴露、链接和按钮语义混乱。

### 6. 知道怎么操作

优先采集：

- 步骤条、当前步骤、进度、面包屑、状态标签。
- 必填字段、前置条件、依赖规则、默认值和示例。
- 下一步 CTA 是否存在且靠近任务对象。

可形成问题的证据：当前状态不明、下一步不明、必填/规则不可见、用户必须试错才能推进。

### 7. 操作时立即有感知

优先采集：

- `:hover`、`:active`、选中态、输入态、提交态。
- 点击后 runtime 是否出现 loading、toast、inline message、状态变更。
- 反馈位置是否靠近触发控件或操作对象。

可形成问题的证据：点击后无变化、反馈不在可见区域、状态变化远离触发点、用户无法判断操作是否被接收。

### 8. 操作顺畅

优先采集：

- 流程是否可返回、取消、中断、继续。
- 是否出现多层弹窗、重复确认、重复输入、非必要跳转。
- 表单输入在返回或错误后是否保留。

可形成问题的证据：流程绕路、反复确认、用户信息丢失、不能返回或取消、结束状态不清。

### 9. 即时反馈与等待进度

优先采集：

- loading、skeleton、progress、队列、预计时间、后台任务通知。
- 提交或加载时相关按钮是否禁用，是否防止重复提交。
- 长任务完成后是否有通知或结果入口。

可形成问题的证据：长等待无进度、重复提交可发生、后台完成无通知、局部/全局 loading 混乱。

### 10. 报错清晰有帮助

优先采集：

- 字段级错误、全局错误、toast、弹窗错误。
- 错误是否说明位置、原因、修正方式、示例或重试入口。
- `aria-invalid`、错误关联关系和用户输入保留情况。

可形成问题的证据：只说失败、没有字段定位、没有修正建议、错误后丢失输入、无重试或帮助入口。

### 11. 可撤销/可纠错

优先采集：

- 撤销、编辑、重试、取消、返回修正入口。
- 删除、支付、审批、提交等高风险操作的确认和结果预览。
- 成功页、记录、凭证、审计信息或恢复时效说明。

可形成问题的证据：不可逆操作无确认、无撤销/编辑/重试、成功后无结果记录、恢复入口隐藏或时效不明。

## 记录格式建议

```json
{
  "element_id": "operation_guidance",
  "criterion_id": "E6-02",
  "unit_scope": "component:btn_submit",
  "state_scope": "default",
  "evidence": ["dsl.pages[0].components[3]", "dsl.interactions[0]"],
  "expected": "下一步 CTA 应靠近当前任务对象，并说明动作结果。",
  "actual": "按钮远离当前任务对象，文案只有“提交”。",
  "evidence_test": "组件距离和文案均不能证明用户可理解下一步。",
  "problem_count": 1
}
```

把上述 `problem_count` 汇总到对应元素的 `deductions[]`，再按档位计算 `points`。
