# IA 提取操作规则

本文件定义体验蓝图 §1 页面结构的提取过程。提取在六步推导和 §2-§9 正文全部完成后执行，从已完成的交互设计中读取承载对象和路径信息，投影为站点树和主导航。

本文件只管提取操作，不涉及交互设计规则或业务判断规则。

## 1. 扫描源

从两个章节读取信息：

**主扫描源：§7 页面 / 弹窗 / 抽屉设计。** 每个 `###` 小标题对应一个承载对象。从标题和"进入条件"字段判断承载类型：

- 标题含"页面"且无"父级承载页"标注 → 独立页面
- 标题含"父级承载页" → 入口节点（菜单、下拉菜单等导航容器）
- 标题含"抽屉" → 抽屉
- 标题含"弹窗"或"窗口" → 弹窗或反馈窗口
- 标题含"复用引用"且标注"本期未修改" → 系统级组件

**辅助扫描源：§3 交互流程总览。** 用于确认页面之间的跳转关系和入口层级，补全 §7 中未显式体现的导航结构。

**示例：** 某项目 §7 包含 8 个承载对象（7-1 到 7-8），扫描结果为：

| 编号 | 标题关键词 | 判定类型 |
| --- | --- | --- |
| 7-1 | 权限管理模式选择页（父级承载页） | 入口节点 |
| 7-2 | 自助申请权限模式配置页 | 独立页面 |
| 7-3 | 个人中心下拉菜单（父级承载页） | 入口节点 |
| 7-4 | 我的权限页面 | 独立页面 |
| 7-5 | 申请权限抽屉 | 抽屉 |
| 7-6 | 申请记录页面 | 独立页面 |
| 7-7 | 申请详情抽屉 | 抽屉 |
| 7-8 | 权限阻断反馈窗口（复用引用） | 系统级组件 |

## 2. 分类规则

每种承载类型在 IA 中的归入方式：

**独立页面** → 进入站点树，同时参与主导航筛选。

**抽屉** → 作为子节点挂在触发页面下，`surface_type` 标注为 `"drawer"`。触发页面从 §7 的"进入条件"字段读取——进入条件中提到的页面名称即为父节点。多个进入条件时挂在主要触发页面下，其余触发点作为注释说明。

**弹窗** → 作为子节点挂在触发页面下，`surface_type` 标注为 `"modal"`。挂载方式同抽屉。

**入口节点（父级承载页）** → 进入站点树，作为其下属独立页面的容器。`surface_type` 标注为 `"page"`。是否进入主导航取决于它是否是用户主动进入的导航入口（如侧边栏菜单项）。

**系统级组件（复用引用且本期未修改）** → 进入站点树，`surface_type` 标注为 `"system"`，作为子节点挂在触发它的页面下，不展开细节。

**access 字段推导：**

- 进入条件要求登录且适用角色无限制 → `"authenticated"`
- 进入条件要求特定角色（如超级管理员、审批人）→ `"role-restricted"`
- 进入条件不要求登录 → `"public"`
- 进入条件未明确说明时 → 从适用角色字段推导；仍无法判断时写 `"unknown"`

## 3. 主导航生成

主导航是用户在产品侧边栏或顶部导航栏中看到的入口列表。

**筛选范围：** 从站点树中筛选有独立路由、用户主动进入的独立页面。入口节点（如菜单容器）作为导航入口时，其下属页面列入 children。

**每项字段：**

- `label`：中文名称，与 §7 承载对象标题一致
- `route`：kebab-case 英文路由，按路由命名规则生成
- `icon_hint`：lucide-react 或 ant-icons 图标名称，作为设计师参考
- `access`：按分类规则推导
- `children`：子导航项数组，无子项时写 `[]`

**数量控制：** 3-7 项。超过 7 项时，把低频项收入"更多"或二级菜单。

**排序：** 按核心任务频率排序，最高频的任务入口靠前。

**排除项：** 抽屉、弹窗、系统级组件不进入主导航。

## 4. 站点树生成

站点树是完整的页面层级结构图，包含全部承载对象及其父子关系。

**格式要求：**

- 缩进树形结构，每个节点一行
- 节点格式：`label — route [access]`
- 抽屉和弹窗追加 `(drawer)` 或 `(modal)` 标注
- 系统级组件追加 `(system)` 标注
- route 为空的节点写 `—`
- 根节点为产品或功能域名称

**示例：**

```
权限管理
├── 权限管理模式选择 — /permission-mode [role-restricted]
├── 自助申请权限模式配置 — /self-service-config [role-restricted]
├── 个人中心菜单 — (page) [authenticated]
│   └── 我的权限 — /my-permissions [authenticated]
│       ├── 申请权限 (drawer)
│       └── 申请详情 (drawer)
├── 申请记录 — /application-records [authenticated]
└── 权限阻断反馈窗口 (system) [authenticated]
```

**路由命名规则：**

- kebab-case，全英文
- 资源型：`/items/[id]/edit`
- 操作型：`/new`、`/settings`
- 列表型：`/items`
- 详情型：`/items/[id]`
- 优先用名词，用 `/board` 而非 `/view-board`
- 抽屉和弹窗通常无独立路由，route 写 null

**路由来源：** 从 §7 承载对象的进入条件和页面标题推导。进入条件中提到的现有页面路由沿用；新增页面按命名规则生成。

**层级确定：** 从 §7 的进入条件和 §3 的路径描述推导父子关系。入口节点（父级承载页）的下属页面作为 children；抽屉和弹窗挂在触发页面下作为 children。
