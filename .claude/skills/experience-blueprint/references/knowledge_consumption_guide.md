# 知识消费细则

> **知识消费入口**：本文档中涉及的知识读取（`summary`、`raw` 等），统一通过 `knowledge-wiki` 完成，不依赖固定目录别名或文件路径。

这份文件只放”怎么做”的细则，不放”必须执行”这类硬门槛。硬规则、降级规则和自检硬门槛统一留在 `SKILL.md`。

## 1. Summary / Raw 判断规则

固定协议只有一条：

```text
先命中知识
→ 先读 summary
→ 再读该 summary 对应的 raw
→ 再进入体验推导
```

`summary` 只负责路由，不负责承载深度信息。

## 1.1 Summary 发现规则

当前 `knowledge-wiki` 的 `summary` 层通过固定目录结构发现，不通过 `summary*.md` 这类命名猜测发现。

固定规则：

1. `summary` 层位于 `knowledge-wiki/knowledge/wiki/summaries/...`
2. `wiki/summaries/.../README.md` 是 `summary` 层的路由说明
3. `raw/.../README.md` 是 `raw` 层入口说明，不可替代 `summary`
4. 读取编号知识时，优先按“同领域、同编号”的方式从 `summary` 对应到 `raw`

例如：

```text
先命中 yewu/shenpi-guanli
→ 先读 wiki/summaries/yewu/shenpi-guanli/README.md
→ 再读 wiki/summaries/yewu/shenpi-guanli/10_shenpi-guanli.md
→ 再读 raw/yewu/shenpi-guanli/10_shenpi-guanli.md
```

禁止：

- 不得用 `summary*.md` 之类的猜测式搜索来判断 `summary` 是否存在
- 不得因为没搜到 `summary*.md` 就回退成“直接广读 raw”
- 不得把 `raw/.../README.md` 当作 `summary` 层替代品

### 1.1 Summary 的职责

summary 只用来做三件事：

- 帮助确认命中了哪个知识域
- 帮助确认下一步该读哪份 raw
- 帮助快速判断这份 raw 和当前体验设计的关系

在当前知识结构下，`README.md` 也要分层理解：

- `wiki/summaries/.../README.md`：帮助命中领域与编号段
- `raw/.../README.md`：帮助理解 raw 层入口说明与边界

不允许把 summary 当作可以停留的深度信息层。

### 1.2 Raw 的职责

raw 才是正式知识消费对象。体验蓝图阶段需要从 raw 中提取：

- 规则边界
- 状态分支
- 异常处理细节
- 体验策略所需的时序、角色、治理和来源信息

### 1.3 常见必读场景

- 审批管理：审批超时、转派、交接、催办、审批人缺失
- 治理模式：关闭能力后的影响、回收策略、与其他治理模式的共存
- 权限来源：来源解释、来源追溯、状态变化后的展示口径
- 状态模型：中间态、终态、回退态、异常态

## 2. 体验相关性判断法

判断一份知识是否与当前体验设计相关，优先看它是否影响以下任一方面：

- 某个角色的操作路径
- 某个页面的信息结构
- 某个状态的反馈策略
- 某个异常或阻断的处理方式
- 某个治理动作的风险提示、确认链路或结果说明
- 某个来源标签、解释文案或追溯能力

如果都不影响，可以记录为“扫描后判断不相关”，不进入该条知识的消费链路；一旦判断为相关，就必须继续读取对应 raw。

## 3. 体验策略提取法

从 raw 中提取的不是“原文摘要”，而是“这条知识对体验设计意味着什么”。

推荐转换模板：

1. 先写知识中的关键规则 / 事实
2. 再写它转成了什么体验策略
3. 最后写它落到正文的哪个章节 / 节点 / 页面

推荐句式：

- 关键规则：`……`
- 体验策略：`因此在体验蓝图中，需要……`
- 落点：`对应正文 §X / 节点 X-X / 页面 PX`

## 4. 附录记录格式

### 4.1 设计准则消费

建议字段：

- 使用依据
- 转换结果
- 落点
- 是否新增补充

“是否新增补充”用于区分：

- 直接承接 UXB 已选条目
- 体验阶段新增补充条目

### 4.2 业务知识消费

建议字段：

- 知识来源
- 关键规则 / 事实
- 转换成的体验策略
- 落点
- raw 读取情况

`raw 读取情况` 推荐写法：

- `已读 raw`

### 4.3 知识缺口

当 summary / raw 都不能支撑当前设计时，记入知识缺口。建议字段：

- 缺口主题
- 当前缺什么
- 影响哪个章节 / 节点
- 建议确认方

## 5. 孤儿判断反查清单

### 5.1 从 UXB §0 回看

- 每条关键判断是否在体验蓝图 `§0` 或正文中被承接
- 如果正文用了推荐方案推进，是否在 `§8` 明确标注

### 5.2 从规则边界回看

- UXB 的状态边界，是否进入 `§7`
- UXB 的异常边界，是否进入 `§5`
- UXB 的治理操作边界，是否进入 `§3 / §4 / §6`

### 5.3 从附录消费表回看

- 每条“设计准则消费”是否指向了真实章节
- 每条“业务知识消费”是否指向了真实章节 / 节点 / 页面
- 是否存在“有来源、无落点”的孤儿条目

### 5.4 从正文反查来源

- 正文里所有明显依赖外部规则的关键设计，是否在附录里能反查到来源
- 是否存在“有落点、无来源”的设计结论

## 6. 示例

### 6.1 Summary 命中后继续读 Raw

- 知识来源：审批管理 summary
- 判断：summary 只负责把体验蓝图路由到审批管理 raw
- 处理：读取 raw，提取超时、催办、转派、审批人失效等细节
- 落点：`§5 审批超时`、`§5 审批人不存在`、审批人相关页面或状态说明

### 6.2 UXB 未读，但体验阶段必须补读

- 知识来源：审批管理 raw
- 上游状态：UXB 未读
- 体验阶段判断：审批人操作链路、异常反馈、结果通知强依赖该知识
- 处理：补读 raw，在附录中明确标记为“体验阶段新增补充”
