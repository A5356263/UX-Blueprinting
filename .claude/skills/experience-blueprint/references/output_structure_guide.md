# 体验蓝图输出写作指南

这份指南只负责一件事：

**把 `experience_blueprint.md` 的写法固定下来。**

## 写作红线

1. 不重新裁决需求是否成立
2. 不绕过 UXB 自行判断能力形态
3. 不省略 UXB 明确强调的配置态、关闭态、回退态
4. 不用空泛表述替代具体页面结构和文案
5. 不在 `§6` 之外使用 ASCII 框图
6. 旅程图按角色独立绘制，阶段用目标命名，不混入 UI 操作词汇
7. 次交互流程保持步骤结构，不退化为概述
8. 状态文案使用统一口径表
9. 正文不暴露内部执行术语
10. 异常与阻断流程是正式内容，不是附录

## 失败条件

1. 缺少旅程图、主流程或异常流程
2. 把设计参考写成自动路由或内部判断说明
3. 页面文案是元指令而不是用户可见文本
4. 依赖未装配知识或自行脑补 guideline
5. 只展开单一路径主流程，异常与阻断明显薄弱
6. 在 `§6` 之外使用 ASCII 框图
7. 通过体验蓝图重新判断需求是否成立或能力形态
8. 页面设计停留在功能罗列，没有结构和反馈落点
9. 旅程图从 HTML 预览层反推
10. 状态模块是长段流程复述而非统一口径表

## 合格标准

1. 读完后能清晰知道谁在什么场景下做什么、系统如何响应
2. 主流程、次流程、异常与页面承接清晰
3. 旅程图按角色独立存在，阶段划分清晰
4. 状态模块为统一口径表，而非长段流程复述
5. 正文不暴露内部执行术语
6. `§5` 不是附录，且至少说明触发条件、系统反馈、用户下一步
7. `§6` 能体现结构化空间、信息层级和异常状态下的结构变化
8. ASCII 框图只出现在 `§6`
9. 明确承接 UXB 中提出的边界、风险和保护策略

## 各章节写法

### `§0` 本次关键设计判断

- 用一句话说明本次体验方案准备怎么处理
- 再写主要影响、建议方案、不建议方案、关键待确认

### `§1` 旅程图

- 一个角色一张旅程图
- 阶段名称用目标命名
- 每阶段写用户目标、关键触点、用户信心、痛点
- 补上阶段间过渡

### `§2` 交互流程总览

- 展示分角色交互流程
- 单列异常流程重点
- 关键节点可与 `§3` 建立编号对应

### `§3` 主交互流程

- 每个节点必须写用户动作、系统反馈、前置解释、建议文案、下一步
- 节点是完整任务，不是单次点击

### `§4` 次交互流程

- 保持步骤结构
- 可用节点标题或步骤块分段

### `§5` 异常与阻断流程

- 每个异常写发生时机、触发条件、判断依据、反馈形式、系统反馈、用户下一步
- 如果需要补救路径，也要写清楚

### `§6` 页面 / 弹窗 / 抽屉设计

- 写页面目标、进入条件、页面结构、状态反馈区、异常结构变化、具体文案、按钮、成功反馈、失败反馈
- 页面结构部分可使用 ASCII 框图

### `§7` 状态与反馈文案

- 用统一状态口径表
- 不重复完整流程说明

### `§8` 待确认问题

- 每条写问题标题、影响、建议确认方
- 若上游主方案未闭合，明确标注“基于推荐方案推进”

### `§9` 附录：设计指南消费说明

- 记录设计准则如何转成体验策略
- 记录业务知识如何影响设计判断
- 记录知识缺口及影响模块
- 命中知识后，先读 summary，再读对应 raw；不要把 summary 当最终停留层
