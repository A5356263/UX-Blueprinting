# 输入适配

写入前先给输入材料分类，只提取可复用、可沉淀的知识。

## 知识候选区文件

知识候选区文件是入库线索卡，不是正式知识正文。

处理规则：

- `知识讨论背景` 用于理解来源，不直接写入 raw。
- `候选知识` 是主要可入库内容。
- `影响范围` 用于确定扫描种子和更新方向，不代表完整更新范围。
- `不确定点` 只允许转写为 `[GAP] / [QUESTION] / [CONFLICT]`，不得改成确定事实。
- 不要把候选文件整篇搬入 `knowledge/raw/**`。

## 产品介绍

提取产品定位、目标用户、核心能力、支持场景、模块关系和稳定价值点。
丢掉空泛营销语、重复宣传文案和没有依据的表述。
通常合并到 `00_领域概述.md`、`10_能力说明.md`、`README.md` 或邻近主题文件。

## 操作指引

保留操作路径、前置条件、步骤、权限、校验规则、状态变化、错误处理、注意事项和限制。
路径能原样保留时尽量原样保留，例如：

```text
【员工管理】员工管理设置-基础设置
```

合并到对应功能 raw 文件。

## FAQ / 问答材料

FAQ 默认放到：

```text
50_常见问题.md
```

只有在内容过大时才拆分，例如：

```text
51_导入导出常见问题.md
52_权限与可见性常见问题.md
53_异常报错常见问题.md
```

不要新建 `FAQ.md`、`faq.md`、`问答汇总.md` 这类随意文件名。
FAQ 不能只留问题标题，答案内容也要保留。

推荐结构：

```md
## 如何设置工号生成规则？
### 问题

如何设置工号生成规则？

### 答案

进入【员工管理】员工管理设置-基础设置-工号设置，开启自动生成工号后，可按前缀、序号、后缀等规则生成员工号。

### 操作路径

【员工管理】员工管理设置-基础设置-工号设置

### 注意事项

- 若员工未匹配任何工号规则，员工号可能为空。
- 若序号生成至最大值，会报错提示。
```

## 截图分析

只提取稳定产品事实：页面名、可见模块、字段、入口、按钮、状态、提示文案、权限规则和可见性规则。
不要把 OCR 过程、视觉猜测、临时分析笔记和工具日志写进正式知识。
不确定时用 `[QUESTION]`。

## 视频分析

只提取稳定流程和产品规则：角色、操作路径、页面切换、系统反馈、异常处理和限制。
除非作为证据需要，否则不要保留时间戳、视频处理日志、口头填充语或工具失败细节。

## 帮助中心采集结果

正式知识可以吸收文章正文、明确规则、流程、字段、依赖关系和 FAQ 答案。
不要把 `_collection` 日志、覆盖率报告、浏览器步骤、失败 URL 列表或抓取过程笔记抄成正式知识。

## 会议纪要 / 讨论记录

只入库已确认、可复用的结论。
未确认内容用 `[QUESTION]`，来源冲突用 `[CONFLICT]`，缺信息用 `[GAP]`。
不要把临时争论过程直接当成正式事实。

## 需求草稿

拆开看可复用业务事实、临时任务要求、方案想法和假设。
只有可长期复用的事实进 `knowledge/`。
任务特有要求应留在项目产物，不要进永久知识层。

## 合并与新建规则

优先合并，避免扩散。
当新材料只是补充已有主题时，优先合并到现有 raw 文件。

只有满足这些条件才新建 raw 文件：

- 现有文件没有合适落点
- 内容足够稳定
- 内容量足够独立成文
- 文件符合当前目录结构
- 能用中文命名且与本地风格一致

不要只为了让编号看起来完整就新建文件。

如果信息已存在且完整，就跳过。
如果信息冲突，就保留并标记 `[CONFLICT]`。
如果信息缺失，就标记 `[GAP]`。
如果归属或有效性不清，就标记 `[QUESTION]`。
不要静默补造事实。
