# Detail Page Blueprint（详情页蓝图）

由 agent 基于 Intent Model 手工构造。结构决策必须基于业务对象特点，不得依赖"默认模板"。构造前必须按以下规则决策布局和列数。

## 1. 布局决策（左右 vs 上下）

核心问题：**页面是否有需要在右侧固定的辅助信息？**

| 条件 | 布局 | CSS | 参考 |
|------|------|-----|------|
| ApprovalDetailPage（含审批流） | **左右**（`1fr 375px`） | `layout.detail-side.basic` | 飞书审批模式 |
| DetailPage 含审批流/状态流/操作记录需右侧固定 | **左右** | `layout.detail-side.basic` | `field-columns.csv` Split 模式 |
| DetailPage 无右侧辅助信息需求 | **上下** | 无需 layout 资产 | `field-columns.csv` Stacked 模式 |

### 决策逻辑

```
含审批流？ → 是 → 左右布局（审批流固定右侧 375px）
      ↓否
含操作记录/状态流需右侧固定？ → 是 → 左右布局
      ↓否
      → 上下布局
```

注意：
- 审批流宽度固定 375px（禁止事项第 12 条），使用 `layout.detail-side.basic`
- 操作记录使用新规范（禁止 `.op-log-list` / `.op-log-item` flex 布局，禁止事项第 13 条）
- 右侧栏不承载复杂详情网格

## 2. 详情页模式选择

详情页有四种模式，由 `data/content-assets/field-columns.csv` 定义：

| 模式 | 布局 | 详情样式 | 适用场景 |
|------|------|---------|---------|
| Split Basic | 左右 | 描述列表 | 字段详情 + 右侧审批流/操作记录 |
| Stacked Basic | 上下 | 描述列表 | 纯字段详情，无辅助信息 |
| Split Table-like | 左右 | 表格化网格 | 单据型 + 右侧审批流 |
| Stacked Table-like | 上下 | 表格化网格 | 字段多、规整展示、无辅助信息 |

选择逻辑：先决定布局（左右/上下），再根据业务对象特点决定详情样式（描述列表 vs 表格化网格）。

## 3. 列数决策

生成详情页前必须查阅 **`data/content-assets/column-selection.csv`**（7 条规则）。核心规则摘要：

| 条件 | 列数 | 对应规则 |
|------|------|---------|
| 页面承载、字段中等（默认） | **双列** | Rule 2 |
| 表格样式详情、字段多且值短 | **2-4 列**（不支持单列） | Rule 3a |
| 左右布局 | **最多双列** | Rule 6 |
| 长文本（备注/说明/原因/地址/审批意见） | **跨整行** | Rule 4 |
| 附件/明细表格 | **跨整行** | Rule 5 |
| 抽屉/窄容器 | **单列** | Rule 1 |
| 上下布局+宽屏 | **双列或多列** | Rule 7 |

## 4. 自检

完成 Blueprint 后逐项确认：

1. 布局选择有明确理由（基于辅助信息需求，不是"默认左右"）
2. 列数选择引用 `column-selection.csv` 的具体规则编号
3. 长文本字段标记为跨整行
4. 明细表格独占整行，不塞进 value 单元格
5. 右侧栏内容明确（审批流/操作记录/状态流），不空洞
