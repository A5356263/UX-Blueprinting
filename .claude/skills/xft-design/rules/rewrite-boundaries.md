# 改写边界总规则

## 1. 两类内容

页面生成时，内容分为两类：

### 需求变量（允许 AI 改写）

- 页面是否整页生成还是局部生成
- 页面包含哪些区域
- 每个区域包含多少字段、模块、动作
- 字段数量、字段名称、文案内容
- 默认区 / 展开区字段分配
- 模块是否显示、区域局部裁剪
- 页面内区域组合顺序
- 与当前需求直接相关的局部结构增删
- 对 layouts：内容区区域数量、区域顺序裁剪、轻量增删（不改变页面主线类型）

### 实现常量（不允许 AI 自由改写）

- 控件尺寸档位（button 默认档位、input/select/datepicker 高度 padding）
- label 宽度求法、控件宽度区间与适配机制
- 字段纵向对齐机制、动作区默认落位机制
- `data-collapse-*`、`data-overlay-*`、`data-tab-*` 等 runtime data-* 契约接法
- token 使用方式
- 已验证的 placeholder / hover / focus / disabled / error 状态样式
- 已验证的按钮、输入框、选择器默认视觉实现
- modal / drawer / tabs 等组件的基础结构和状态行为
- 对 layouts：页面主线类型本身、内容区主骨架的职责性质

## 2. 基线来源

控件实现基线来自：

- `references/components/ant/*/summary.md`（快速判定尺寸档位、间距、状态层级）
- `references/components/ant/*/component.html`（继承真实 HTML/CSS 写法）
- `runtime/`（继承真实交互契约）
- `design-systems/`（继承 token 与视觉边界）

## 3. 允许突破冻结的条件

仅在以下情况允许突破默认冻结：

- 当前需求与稳定实现直接冲突
- 当前资产无法承载用户明确要求的结构
- 当前资产存在真实错误，导致结构、样式或轻交互失效

即便如此：
- 优先做最小改动
- 不得顺手重写整块实现
- 改动后仍需保持与 runtime/、design-systems/ 一致

## 4. 最小改动原则

当必须修改稳定实现时：

- 只改与当前需求直接冲突的部分
- 不顺手改相邻默认样式
- 不顺手重排整块结构
- 不顺手替换已成立的适配机制

如果问题本质是"默认实现本身不稳"，优先回修 references 资产，而不是继续往规则里补说明。

## 5. 区域块与控件基线的关系

references/blocks/ 的区域块可改，区域块内部的控件实现必须继续继承控件基线。

区域块可改，控件基线不可漂。

## 6. 改写边界标记

资产代码中的 `<!-- EDITABLE -->` 和 `<!-- FROZEN -->` 注释标记是改写边界的物理标记。

- `<!-- EDITABLE -->` 区域内的代码允许按说明范围改写。
- `<!-- FROZEN -->` 区域内的代码默认不修改。
- 标记与本文件的文字规则冲突时，以本文件规则为准（标记是快速参照，规则是最终仲裁）。

## 7. 失败信号

若生成结果出现以下情况，优先判断为"未继承控件基线"，而不是优先补提示词：

- placeholder 颜色不对
- 默认按钮尺寸漂移
- 输入框高度漂移
- 交互按钮存在但 runtime 不生效
- hover / focus / disabled 状态缺失

## 8. 与其他目录的职责分工

- rules/：触发条件、职责边界、不可破坏的结构关系、条件分支、失败回退
- references/：稳定默认实现、内容区布局骨架资源、可改写的区域资产
- runtime/：已支持的真实轻交互契约
- design-systems/：token 与视觉边界
