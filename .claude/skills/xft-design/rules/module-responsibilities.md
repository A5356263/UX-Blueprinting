# 模块职责规则

## Header

负责：

- 页面标题
- 页面身份信息
- 影响整个页面的顶层动作

不负责：

- 长表单主体
- 表格主内容
- 行级操作

## Filter

负责：

- 查询条件
- 收窄条件
- 查询 / 重置动作
- 必要时的高级筛选展开区

不负责：

- 批量操作
- 结果统计主体
- 表格工具按钮

额外规则：

- 每个字段项保持 `label + control` 两段语义关系
- 动作组与字段区同属一个筛选模块，不插入任一字段项内部
- 默认动作顺序保持为 `重置 -> 查询 -> 展开/收起`
- 若字段较少，可不使用展开区
- 若当前区域本质是普通表单、搜索框组或工具栏，则不套用 Filter 规则

## Action

负责：

- 结果集相关的页面级操作
- 与当前数据区直接相关的切换与辅助工具
- 批量操作与结果集上下文动作

不负责：

- 查询字段主体
- 单记录详情内容
- 最终表单提交动作

额外规则：

- 默认采用左侧业务操作、右侧辅助工具的两区关系
- 主按钮位于左侧业务操作区最前
- 图标型工具操作位于整个区域最右
- 若操作较少，可不做复杂分组
- 若动作过多，优先保留主操作与高频操作，低频操作折叠
- 若当前区域主任务是查询输入，则不套用 Action 规则

## Primary Content

负责：

- 页面主信息载体
- 表格、列表、详情主体、表单主体

不负责：

- 纯装饰填充内容

## Detail Section

负责：

- 单对象摘要与详情阅读
- 元数据、说明信息、过程信息分组
- 结果说明与过程信息的单对象组织

不负责：

- 结果列表主体
- 大量录入控件

额外规则：

- 摘要与详情分组可并存，但必须围绕同一对象
- 详情信息较少时，可合并为单区块
- 详情信息较多时，可拆为多个 section
- 若当前区域核心是字段录入，不套用 Detail 规则

## Footer Actions

负责：

- 保存、提交、确认、取消、关闭

不负责：

- 机械重复顶部全部动作

## Modal Task

负责：

- 在覆盖层内完成确认、补录、选择或查看
- 保持 `header + body + footer actions` 的基本结构

不负责：

- 需要完整页面承载的长流程
- 多个无关主任务的混合

额外规则：

- 标题、主体、底部动作必须服务同一覆盖层任务
- 底部动作不得漂移进主体内容内部
