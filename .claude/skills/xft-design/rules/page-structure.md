# 页面结构总规则

## 页面壳选择

- `Rule ID`：`PAGE_STRUCTURE.SHELL`

When:
- 生成产品内业务页面

Must:
- 默认使用 `admin-side-shell`
- 明确为消息、待办等无持续侧边导航的独立页面时，使用 `admin-top-shell`

Must Not:
- 不因需求未描述 Sider（侧边栏）而主动去除 Sider

Fallback:
- 无法确认时使用 `admin-side-shell`
- 需要保持现有父页面结构时，继承父页面已有 Shell（页面壳）

## 区域落位规则

本章节用于定义页面组织方式确定后，内容应落在哪类区域。

### Header 区域

Must:
- 承载页面标题
- 承载页面身份信息
- 在需要时承载简短上下文说明
- 仅在确实影响整个页面时承载顶层操作

Must Not:
- 不要承载长表单内容
- 不要承载表格主体

### Filter 区域

Must:
- 承载查询条件
- 承载轻量收窄条件
- 承载筛选重置与提交动作

Must Not:
- 不要承载行级操作
- 不要承载仅面向详情解释的说明

### Action 区域

Must:
- 承载与主工作集直接相关的页面级动作

Must Not:
- 除非是为了布局压缩，否则不要只放筛选动作

### Primary Content 区域

Must:
- 承载页面主信息载体
- 承载表格主体、表单主体、摘要主体或详情块

Must Not:
- 不要塞入削弱主任务的装饰性填充内容

### Footer Actions 区域

Must:
- 承载确认、取消、保存、提交、关闭或最终阶段动作

Must Not:
- 除非流程确有要求，否则不要机械重复顶部所有动作

## 列表管理页

- `Page Type ID`：`PAGE_TYPE.LIST`

When:
- 主任务是浏览、筛选、比对、批量处理或审核多条记录
- 页面主内容是表格、列表、卡片列表或结果集

Must:
- 页面组织方式为 `header -> filter -> action area -> primary data area -> supporting actions or pagination`

Must Not:
- 若主任务是新建、编辑、提交或配置，不归入列表页
- 若主任务是查看单条记录细节，不归入列表页
- 若主任务发生在覆盖层内，优先判断是否属于弹窗页
- 不要把单条记录详情内容混入主列表流程

Fallback:
- 若筛选很轻，可在视觉上合并筛选区与操作区，但两者职责仍需区分
- 无法确认是否属于列表页时，不强行套用列表页主线

## 表单页

- `Page Type ID`：`PAGE_TYPE.FORM`

When:
- 主任务是创建、编辑、提交、配置或补录信息
- 页面主内容由字段输入、字段分组、确认动作构成

Must:
- 页面组织方式为 `header -> form sections -> footer actions`

Must Not:
- 若页面核心是结果浏览与筛选，不归入表单页
- 若页面核心是单条记录静态查看，不归入表单页
- 若表单承载在覆盖层中，优先判断是否属于弹窗页
- 除非需求明确要求，否则不要把破坏性动作或最终动作放在未完成的主表单内容之前

Fallback:
- 若表单很短，可将多个 section 收束成一个表单承载面
- 无法确认是否属于表单页时，不强行套用表单页主线

## 详情页

- `Page Type ID`：`PAGE_TYPE.DETAIL`

When:
- 主任务是查看单条记录、状态、结果或配置详情
- 页面核心内容是摘要、详情分组、元数据或过程信息

Must:
- 页面组织方式为 `header -> summary -> detail sections -> footer or secondary actions`

Must Not:
- 若主任务是录入与提交，不归入详情页
- 若主任务是批量浏览与筛选，不归入详情页
- 若详情只是在弹窗内短暂展示，优先判断是否属于弹窗页
- 不要让次级统计信息挤占主记录摘要位置

Fallback:
- 若摘要信息极少，可并入第一个详情 section
- 无法确认是否属于详情页时，不强行套用详情页主线

## 弹窗页

- `Page Type ID`：`PAGE_TYPE.MODAL`

When:
- 主任务发生在覆盖层（Modal / Drawer）内
- 页面需要在不离开当前上下文的前提下完成确认、补录、选择或查看

Must:
- 页面组织方式为 `modal header -> modal body -> footer actions`

Must Not:
- 若任务需要完整页面承载主流程，不归入弹窗页
- 若交互复杂到需要独立页面导航，不归入弹窗页

Fallback:
- 无法确认是否应使用弹窗页时，优先回到整页主线判断

## 冲突优先级

当布局规则或组织规则彼此冲突时，使用以下优先级：

1. 保住任务清晰度
2. 保住可读层级
3. 保住对齐一致性
4. 保住稳定间距节奏
5. 最后才保紧凑度

回退规则：

- 如果一行放不下下一个完整块，就整块换行
- 如果对齐与密度冲突，优先保对齐
- 如果装饰平衡与任务清晰冲突，优先保任务清晰
- 如果一个区域承载过多内容，应先拆职责，再缩一切内容
- 如果复杂交互无法在 HTML 预览范围内真实表达，应退化为清晰的预览表达，而不是伪造完整行为
