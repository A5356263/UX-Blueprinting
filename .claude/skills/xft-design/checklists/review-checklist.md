# Review Checklist

## 1. 需求还原

- [ ] `Design Spec` 中要求生成的页面或区域对象都已覆盖。
- [ ] 关键业务状态与动作没有因为资产边界而被省略或篡改。
- [ ] 没有为了套资产而擅自扩页、缩页或改写业务语义。
- [ ] 占位内容只出现在需求未提供的位置，没有伪造业务数据。

## 2. 资产边界

- [ ] 页面代码未直接 `import antd`。
- [ ] 先用 `shell`，再用 `composition`，最后才下探 `primitive`。
- [ ] 没有为常用结构临时写出第二套重复 JSX。
- [ ] 自定义补充区域没有绕过 token 规则。
- [ ] 使用的正式资产都能在 registry 中找到。

## 3. 页面结构

- [ ] 页面只存在一条清晰主线，没有把多个同层主任务并列堆放。
- [ ] 页面组织符合对应页型的结构主线，没有区域先后错位。
- [ ] Header、Filter、Action、Primary Content、Detail 等职责没有混写。
- [ ] 稳定资产优先被复用，没有重写同职能第二套结构。

## 4. 模块检查

### FilterBar

- [ ] 当前区域明确承担筛选结果集职责，而不是普通表单或工具栏。
- [ ] 字段与动作属于同一筛选系统，没有混入批量操作或结果统计。
- [ ] 字段保持 `label + control` 基本语义。
- [ ] 动作组与字段组同层，没有把动作塞进字段内部。
- [ ] 优先使用正式 `filter-bar` composition。

### ActionBar

- [ ] 当前区域明确承担结果集相关页面级操作，而不是查询主体。
- [ ] 保持左侧业务动作、右侧辅助工具的基本关系或等价变体。
- [ ] 主按钮不超过一个，且位于左侧动作区前部。
- [ ] 没有把详情动作、页头动作或最终提交流程误塞进操作区。
- [ ] 优先使用正式 `action-bar` composition。

### DetailSection

- [ ] 当前区域明确承担单对象阅读，而不是列表或录入主线。
- [ ] 摘要、字段、说明、过程信息围绕同一对象展开。
- [ ] 信息少时保持单区块，信息多时拆 section 但仍保留单一主线。
- [ ] 没有把批量操作、筛选区或大量录入控件混入详情区。
- [ ] 优先使用正式 `detail-section` composition。

## 5. 视觉与 Token

- [ ] 没有硬编码颜色、间距、圆角、阴影。
- [ ] 颜色、字号、圆角、阴影、间距优先继承 `design-systems/`。
- [ ] 同页主按钮、次按钮、输入控件、标题层级保持统一档位。
- [ ] 同一窗口内只有一个主视觉主按钮。
- [ ] 需要视觉边界的区域由 `Panel` 或等价 Surface 承载。
- [ ] Surface 间距与内部节奏没有脱离 token 配方。
- [ ] 没有造出 token 体系外第二套主色、灰色或状态色。

## 6. 最终一致性

- [ ] 页面结构来自页型规则，而不是整段 HTML 参考复制。
- [ ] 输出结果主要由正式 React 资产层承接。
- [ ] 没有因为局部补充而破坏主链路一致性。
