# FILTER_BAR Checklist

## P0 必须通过

- 输出区域是否确实承担“筛选结果集”的职责，而不是页面级操作区、结果统计区或批量操作区。
- 是否只包含查询条件、重置、查询、展开/收起，不再出现“全部”“待处理”或其他快速筛选能力。
- 每个字段项是否保持 `label + control` 两段结构，没有拆分到不同容器。
- 动作组是否与基础字段区同层，没有插入任一字段项内部。
- 高级筛选展开后是否进入独立扩展区，没有与基础字段混写。
- 展开/收起交互是否能够由 `runtime/basic-interactions.js` 的 `data-collapse-toggle` 契约承接。
- 是否没有使用 `runtime/` 之外的新交互系统。
- 展开 / 收起是否只依赖一个真实状态源，不存在两个 toggle 各自维护状态。
- 收起后基础动作区 `重置 -> 查询 -> 展开/收起` 是否仍然存在且可见。
- 展开后动作区是否位于整个筛选区最右下角，而不是停留在上方或漂到中间。

## P1 应该通过

- 同组字段的 `label` 宽度是否一致，并以最长 `label` 为固定宽度基线。
- 同组字段的控件宽度是否一致，纵向是否对齐，没有一列长一列短。
- 默认桌面布局是否按 `180px-400px` 控件宽度区间自适应决定当前行字段数，而不是写死成固定三列。
- 单个控件是否没有被压缩到明显低于 `180px`，也没有被拉宽到明显超过 `400px`。
- 动作顺序是否保持为 `重置 -> 查询 -> 展开/收起`。
- 间距、字号、颜色、圆角和阴影是否优先使用 `design-systems/` token，而不是裸样式值。
- 视觉节奏是否符合桌面端表单默认值，没有出现明显过密或过散。
- 高级筛选区默认是否保持视觉连续，没有额外分割线或独立卡片壳。

## P2 可选优化

- 高级字段数量很少时，是否可以直接默认展开并省略展开控件。
- 结构与视觉都成立的前提下，字段块和动作组是否进一步保持了更稳定的扫描节奏。
