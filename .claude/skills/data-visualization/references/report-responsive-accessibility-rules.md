# 报告、响应式与无障碍规则

## 1. 默认交付

正式 HTML 默认：

- 离线、自包含；
- 不引用 CDN、远程字体或外部脚本；
- 不包含令牌、绝对本机路径或未授权内部定位信息；
- 直接在现代浏览器打开；
- 图表数据与来源可审计。

Objective 专用报告可以组织 Objective 固定章节。通用图表页只组织图表、数据表、关系、来源和限制，不生成新的分析叙事。两者必须通过同一个正式发布入口生成；同一 Run 与 Purpose 不得先后写出两份内容不同的正式 HTML。

## 2. 页面结构

三类正式报告共享以下视觉底线，但不强制章节同构：

- 使用有限的主色、强调色和状态色，不能让每个模块形成自己的色彩系统；
- 通过标题层级、留白、卡片和结论提示建立阅读顺序，不用内部状态码充当视觉标题；
- 核心指标和主要结论优先，技术追溯和长明细采用渐进披露；
- 表格使用清晰表头、行分隔和横向滚动，不能依赖缩小字体塞入全部列；
- 阴影、渐变和动效只用于层级与交互反馈，不能承载业务含义。

通用图表页建议顺序：

1. 标题、来源运行和表达范围
2. 数据质量与重要限制
3. 图表或关系图
4. 每图对应的可访问数据表
5. 来源契约与人工复核项

Dashboard 仅组织已有指标与视图，不决定应该分析什么。

Objective 报告按业务问题组织：

1. 本次分析了什么：范围、时间、任务口径、来源和数据质量；
2. 整体表现如何：只展示通过门禁的正式核心指标；
3. 任务在哪里停止、流转或重复：结果分布、固定漏斗和主要流向；
4. 哪些报错与待复核消息模式影响较大：结论、影响任务和重复密度；
5. 哪些业务分群存在样本内差异：样本、覆盖、可靠性和差异；
6. 哪些内容仍需验证：限制、不可评估原因和允许的下游交接；
7. 技术附录：Run、精确来源和口径追溯。

每节采用“已有结论 → 图表或表格 → 口径与限制”。内部 ID、状态码、摘要和来源路径默认进入技术附录。

指标模块为 `not_evaluable` 时，不显示从冲突来源中选取的单一 KPI；改为说明冲突范围和需要对齐的口径。未请求模块不渲染。

试点报告只作为表达验收样例，不作为数值、公式、根因、优化方案或优先级的事实源。

## 3. 响应式

- 宽表和关系图允许横向滚动。
- 多列指标卡在窄屏自动降为两列或单列。
- 移动端减少同时展示的标签，完整信息放表格或详情。
- 不对复杂桌面图做不可读的等比缩放。
- 触控区域、字体和行距保持可读。
- 路径图应默认突出上游已声明的主要真实路径；低占比连线可以视觉降噪，
  但不得删除其可访问数据或改变数值。
- 大型关系图画布应按节点数量自适应高度，完整流向表允许折叠展示。
- 图表与关系表在窄屏可横向滚动；打印模式解除滚动裁剪，确保表格可完整输出。

## 4. 无障碍

- 页面使用语义化标题层级。
- 图表提供 `role=img`、明确的 `aria-label` 和文字摘要。
- 所有数值图提供数据表替代。
- 每张关系图在 SVG 后提供可独立阅读的节点表和边表。节点表包含标签、类型、状态和来源；边表包含起点、终点、关系类型、权重、权重单位、状态、来源和限制。
- 关系图 `aria-label` 说明节点数、边数、关系类型以及权重是否具备可比较规模。
- 只有权重为有限数值且权重单位存在时，线宽才可表达规模；否则使用固定虚线，并显示“未提供可比较规模”。
- 状态不只靠颜色；同时使用文字、线型或图形。
- 保持足够对比度和键盘可阅读顺序。
- 动画不是理解内容的必要条件，默认不自动播放。
- 页面提供跳到正文的键盘入口，并为可交互控件提供明确 `focus-visible`。
- 动态路径详情使用 live region；系统请求减少动画时关闭非必要过渡。
- 打印模式保留正文和数据，移除无意义的交互控件与装饰阴影。

## 5. 敏感信息

- 继承上游敏感级别、脱敏状态和允许展示范围。
- 用户 ID、企业 ID、工单原文和原始报错不默认作为大面积标签。
- 可以用聚合值、匿名编号或摘要时执行最小披露。
- 上游明确允许原文展示时，保留其授权或规则引用。
- 无法判断是否可展示时阻断正式发布，写入人工复核请求。
