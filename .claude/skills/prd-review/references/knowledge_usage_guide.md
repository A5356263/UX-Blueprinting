# PRD Review 知识消费规则

## 1. 正式知识来源和权威边界

正式消费根目录：

- `.claude/skills/knowledge-wiki/knowledge/`

各类内容的作用：

- `wiki/index.md`：只负责选择知识类型、业务集合或主领域。
- 业务集合 README、领域 README：只负责边界、文件路由、条件依赖和停止条件。
- `raw/业务/**`：正式业务事实来源。
- `wiki/questions.md`：显式知识缺口入口，不能作为确定事实。
- `candidates/**`：非正式候选，不得进入需求基线。
- `templates/**`：知识维护模板，不进入消费路径。
- 项目外 FAQ、历史问答或讨论材料：只能作为检索线索，除非已经进入正式 raw。

PRD Review 只消费业务知识。不要读取设计准则和交互模式完成业务审查。

## 2. 消费目标

知识消费用于：

- 确认当前系统事实。
- 识别本次新增、修改、移除或沿用的对象。
- 发现受影响的角色、权限、规则、状态、异常、数据和依赖。
- 验证 PRD 对当前能力的描述是否准确。
- 发现 PRD 漏写的变化影响。

知识不能用于：

- 否定产品明确提出的目标变化。
- 替产品决定新规则。
- 生成体验策略。
- 生成页面或交互方案。

## 3. 问题定界

读取知识前，先从 PRD 确认：

- 业务对象。
- 关键动作。
- 当前状态与目标状态关系。
- 角色和适用范围。
- 预期业务结果。
- 已明确的外部依赖。

不得只根据需求标题、页面名或单个关键词确定领域。

## 4. 主领域定位

按以下顺序执行：

```text
读取 wiki/index.md
→ 根据业务对象、动作和结果选择主领域
→ 进入主领域 README
→ 学习实际文件路由
→ 读取承担当前事实责任的 raw 文件
→ 按顶部导航读取命中章节
```

规则：

- index 和 README 不是业务事实。
- 不得把关键词固定映射成唯一文件。
- 不得猜测不存在的目录或文件。
- 不得遍历 `raw/` 或逐文件试读。
- 路由没有命中正式知识时，记录知识缺口。

## 5. 依赖领域触发条件

只有以下条件同时成立时，进入依赖领域：

1. 主领域 README 或正式原文明示依赖。
2. 当前需求实际触发该依赖。
3. 依赖事实会改变对象、角色、权限、规则、状态、异常、结果或审计结论。

读取依赖领域后，必须回到主领域完成闭环。

不得因为业务相邻、关键词相似或“可能有关”无限扩读。

## 6. 正式原文读取规则

- 长文档先读顶部适用范围和快速导航。
- 只读完整命中章节，不读孤立句子。
- FAQ 或问答文件只读命中问题块及其必要上下文。
- 页面与字段类文件只读命中页面或对象章节。
- 命中局部知识后，不得在必要关联事实尚未闭环时停止。
- 未被当前需求触发的相邻知识不得扩入。

每项用于审查的知识必须能说明：

- 支撑哪个当前事实。
- 适用哪个对象和角色。
- 适用范围、条件和例外是什么。
- 会影响哪个审查结论。

## 7. 知识覆盖模型

按当前需求实际触发范围覆盖：

```text
业务对象
→ 角色
→ 动作
→ 权限
→ 状态
→ 规则
→ 异常
→ 业务结果
→ 依赖系统
→ 数据与审计
```

“覆盖全部相关知识”不是通读整个领域，而是所有会改变本次闭环结论的相关事实都得到核验。

## 8. 覆盖记录

Agent 在内部维护：

| 覆盖节点 | PRD 目标描述 | 当前正式事实 | 关系 | 审查结果 |
|---|---|---|---|---|
| 对象、角色、动作等 | PRD 原文位置 | raw 文件与章节 | 沿用、新增、修改、移除、无法确定 | 已闭环、阻断、不适用 |

覆盖记录只用于内部检查和来源追溯，不作为用户产物。

## 9. 当前事实与目标状态关系

### 沿用

PRD 声称沿用当前能力时：

- 目标描述必须与正式当前事实一致。
- 不一致且未说明变化时，形成阻断。

### 新增

检查：

- 新能力与当前对象和规则如何关联。
- 是否产生新角色、权限、状态或依赖。
- 当前能力是否需要同步调整。

### 修改

检查：

- 修改前后的目标差异。
- 适用范围和生效条件。
- 旧规则如何处理。
- 历史数据和下游影响。

### 移除

检查：

- 被移除能力的替代或终止结果。
- 历史数据处理。
- 仍依赖该能力的角色和下游。
- 权限、状态、接口和审计如何收口。

正式知识不同于目标状态，不等于冲突。只有变化关系和影响无法闭环时才阻断。

## 10. 反向检索

对关键动作执行反向检索，补充正常路径容易遗漏的限制。

触发条件：

- 动作不可逆。
- 动作受权限控制。
- 动作改变关键状态。
- 动作影响下游。
- 正向知识不能证明完整结果。

围绕当前动作，在已经命中的正式文件和明确依赖中定位：

- 禁止或不支持。
- 不可撤回或不可恢复。
- 已关联或已被使用。
- 权限限制。
- 状态限制。
- 重复与并发。
- 外部失败和部分成功。

反向检索仍须遵守正式路由。不得为搜索这些词遍历整个 raw。

## 11. 证据一致性

每条知识结论必须与原文保持相同的：

- 对象。
- 关系。
- 角色。
- 适用范围。
- 条件。
- 例外。
- 表达强度。

禁止：

- 把局部场景提升为全局规则。
- 把“可配置”“开启后”“支持”改写为固定前提。
- 互换不同角色或业务主体。
- 把示例、典型路径或局部 FAQ 当作完整清单。
- 根据文件更新时间自行选择冲突一方。

封闭枚举只有在命中承担当前问题直接事实责任的完整正式清单时才能成立。

## 12. 知识缺口与显式问题

出现以下情况时记录知识缺口：

- index 或 README 无法定位正式事实。
- 正式原文缺少当前能力说明。
- `[GAP]`、`[QUESTION]` 或 `[CONFLICT]` 影响本次审查。
- 正式事实的对象、范围或条件无法与 PRD 对齐。

处理方式：

- 影响业务闭环：形成阻断问题。
- 不影响本次业务闭环：不纳入问题单。
- 不得遍历 raw 补救。
- 不得用 Agent 常识补齐。

## 13. 停止条件

同时满足以下条件才停止知识读取：

1. 核心对象和关系已覆盖。
2. 关键角色、动作和权限已覆盖。
3. 核心状态和规则已覆盖。
4. 会改变业务结果的异常已覆盖。
5. 被触发的系统、数据和审计依赖已覆盖。
6. 当前事实与目标状态的变化关系已明确。
7. 所有影响闭环的知识缺口都已进入阻断判断。
8. 继续读取不会改变审查结论。

## 14. 失败与阻断处理

- 正式知识无法访问：说明缺失位置；影响闭环时阻断。
- 路由存在但目标文件不存在：记录知识缺口；不得猜测替代文件。
- 正式文件存在冲突：保留双方来源；影响目标判断时阻断。
- 非正式材料与正式知识不同：不能覆盖正式知识，只能触发核验。
- PRD 明确改变当前规则：按目标状态审查，不把差异本身当作阻断。

## 15. 禁止事项

- 不读取设计准则或交互模式完成 PRD 审查。
- 不固定费控、人事或其他领域的绝对路由。
- 不设置领域优先级。
- 不限制最多读取几个相关领域。
- 不计算知识覆盖率或可信度分数。
- 不自动判断知识时效。
- 不把行业惯例、竞品或 Agent 经验当作知识。
- 不向用户展示知识路由、覆盖矩阵或完整推理过程。
- 不使用脚本判断知识是否适用、是否冲突或是否足够。
