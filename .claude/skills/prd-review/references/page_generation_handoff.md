# 页面事实最小提取

## 1. 文档目的与职责边界

只从冻结需求基线提取 Page Spec 可直接消费的页面事实。

它是需求事实的后置投影，不是体验分析，也不是页面设计。

## 2. 基线冻结后的执行条件

- `spark-output/requirements_baseline.md` 已生成。
- 基线状态为 `formal`。
- PRD Review 门禁已通过。

存在阻断问题时不得执行。

## 3. 唯一输入

- `spark-output/requirements_baseline.md`

不得读取原始 PRD、问题单、产品聊天回复或 UXB 补充页面事实。

## 4. 页面事实白名单

只提取基线已明确写出的以下事实：

- 页面、页签、区域、模块、弹窗、抽屉及其层级关系。
- 字段、选项、操作、按钮及已明确的控件类型。
- 页面入口和固定业务文案。
- 展示条件、角色可见范围和业务权限。
- 默认值、必填、最小值、最大值、格式、枚举和校验顺序。
- 页面状态、空状态、错误状态和恢复结果。
- 审批或任务结果对页面内容和下一步的影响。
- 会改变内容、版本、审批、发布、替换或删除结果的动作事实。
- 已明确的确认要求及其承载位置。

只提取可直接映射到页面规格的确定事实。

## 5. 禁止提取内容

- 需求背景和业务价值。
- 体验目标和体验策略。
- 信息架构建议。
- 交互流程建议。
- 页面布局、视觉样式和组件方案。
- Agent 推断的页面、字段、按钮、提示或状态。
- 后端算法、接口实现和数据库方案。
- 不会影响页面表达的内部业务规则。
- UXB 结论。
- 下一步推荐。

无法直接证明为页面事实时，不提取。

## 6. 稳定事实编号与基线来源

- 使用 `HF-001`、`HF-002` 顺序编号。
- 编号在当前产物内唯一。
- 按基线章节顺序提取。
- 每条事实必须指向需求基线章节和稳定编号；没有稳定编号时指向具体条目。
- 不用原始 PRD 位置代替基线来源。

## 7. 输出路径与 Markdown 结构

- `spark-output/context/page-generation-handoff.md`

固定结构：

```markdown
# 页面事实交接

- 项目：{项目名}
- 来源：spark-output/requirements_baseline.md
- 事实数量：{数量}

## 页面事实

### HF-001
- 类型：{页面结构｜内容与操作｜条件与权限｜校验｜状态与结果}
- 事实：{基线中已确认的页面事实}
- 基线来源：{§章节 / 稳定编号}
```

没有某类事实时，不输出空分类标题。

## 8. 零事实处理

- 仍生成交接文件。
- `事实数量` 写 `0`。
- `页面事实` 下写“本次需求基线未包含可直接投影的页面事实。”

## 9. 失败处理

生成失败只影响 Page Spec 交接，不影响需求基线、UXB 或 Experience Blueprint。

失败时：

- 不修改已冻结的需求基线。
- 不从其他来源补事实。
- 向用户说明失败位置。
- 下游 UXB 和 Experience Blueprint 仍可使用需求基线。

## 10. Agent 语义验收

- 每条事实都能在需求基线中定位。
- 没有推断新页面事实。
- 没有体验策略或交互方案。
- 没有遗漏基线中明确且可供 Page Spec 消费的事实。
- 数量与条目数一致。
