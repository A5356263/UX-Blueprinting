# 页面事实最小提取

## 1. 文档目的与职责边界

只从冻结需求基线提取 Page Spec 可直接消费的页面事实。

它是需求事实的后置投影，不是需求摘要、体验分析或页面设计。

“最小”指一条 HF 只表达一个可直接消费的事实；“完整”指所有命中页面事实白名单的基线事实均须投影。不得只摘录代表性事实。

## 2. 基线冻结后的执行条件

- `spark-output/requirements_baseline.md` 已生成。
- 基线状态为 `formal`。
- PRD Review 门禁已通过。

存在阻断问题时不得执行。

## 3. 唯一输入

- `spark-output/requirements_baseline.md`

不得读取原始 PRD、问题单、产品聊天回复或 UXB 补充页面事实。

## 4. 页面事实白名单

只提取基线已明确写出的以下事实：

- 页面、页签、区域、模块、弹窗、抽屉及其层级关系。
- 字段、选项、操作、按钮及已明确的控件类型。
- 页面入口和固定业务文案。
- 展示条件、角色可见范围和业务权限。
- 默认值、必填、最小值、最大值、格式、枚举和校验顺序。
- 页面状态、空状态、错误状态和恢复结果。
- 审批或任务结果对页面内容和下一步的影响。
- 会改变内容、版本、审批、发布、替换或删除结果的动作事实。
- 已明确的确认要求及其承载位置。

只提取可直接映射到页面规格的确定事实。

### 4.1 基线章节扫描矩阵

按以下顺序逐节扫描正式需求基线。每条基线事实命中白名单即生成 HF；不得因该事实属于次要角色、次要流程或下游可能已消费而跳过。

| 基线章节 | 必须检查的页面事实 |
|---|---|
| §2 这次会新增或变更什么 | 新增或变更的记录、配置项、权限对象，以及已明确的对象关系。 |
| §3 谁能做什么 | 角色可见性、操作权限、不可操作条件和作用范围。 |
| §4 每件事怎么完成 | 已明确入口、业务动作、字段、固定文案、任务结果和下一步页面影响。 |
| §5 要遵守什么规则 | 会改变页面可见、可操作、校验、选项范围或确认要求的规则。 |
| §6 会出现哪些状态 | 会改变页面内容、操作可用性、状态展示或下一步的状态事实。 |
| §7 遇到特殊情况怎么办 | 会改变页面提示、禁用、错误结果、恢复动作或后续任务的异常事实。 |
| §8 会影响哪些记录和系统 | 审批承接、任务结果回写、记录字段、审计信息等会直接影响页面表达的事实。 |
| §9 这次明确不做什么 | 会造成页面不可用、不可选、不可提交或不可展示的已确认限制。 |
| §10 体验定案 | 不提取；本节由体验蓝图消费，不属于页面事实。 |
| §11 做成后应该看到什么结果 | 仅核验是否存在前文未投影的页面结果事实；不得把验收描述重复生成 HF。 |

## 5. 禁止提取内容

- 需求背景和业务价值。
- 体验目标和体验策略。
- 信息架构建议。
- 交互流程建议。
- 页面布局、视觉样式和组件方案。
- Agent 推断的页面、字段、按钮、提示或状态。
- 后端算法、接口实现和数据库方案。
- 不会影响页面表达的内部业务规则。
- UXB 结论。
- 下一步推荐。

无法直接证明为页面事实时，不提取。

## 6. 提取与去重规则

1. 按 §2 至 §9、§11 的顺序逐节扫描；跳过 §10 体验定案。
2. 同一事实跨章节重复出现时，只生成一条 HF，`基线来源`指向该事实的完整主落点。
3. 一个基线条目含多个可独立消费的事实时，拆为多条 HF。
4. 只有属于同一对象、同一条件和同一页面结果的事实可以合并为一条 HF。
5. 页面承载位置、字段、Tab、模块层级、控件类型仅在基线明确时输出；未明确时不得推导。
6. 不得通过读取 UXB、Experience Blueprint 或 Page Spec 判断某项事实是否已被承接，也不得以“下游可能已消费”为由跳过。

### 6.1 内部候选事实对账

生成前，按 §2 至 §9、§11 建立内部候选事实清单。每项命中白名单的原子事实必须记录：基线来源、白名单类别，以及对应 HF-ID；不命中时记录明确原因。

生成后按候选事实清单回查。任一命中事实没有 HF-ID 时，返回提取步骤补充；不得宣布完成。该清单只用于 Agent 语义验收，不写入交接文件，不生成额外产物。

## 7. 稳定事实编号与基线来源

- 使用 `HF-001`、`HF-002` 顺序编号。
- 编号在当前产物内唯一。
- 按基线章节顺序提取。
- 每条事实必须指向需求基线章节和稳定编号；没有稳定编号时指向具体条目。
- 不用原始 PRD 位置代替基线来源。

## 8. 输出路径与 Markdown 结构

- `spark-output/context/page-generation-handoff.md`

固定结构：

```markdown
# 页面事实交接

- 项目：{项目名}
- 来源：spark-output/requirements_baseline.md
- 事实数量：{数量}

## 页面事实

### HF-001
- 类型：{页面结构｜内容与操作｜条件与权限｜校验｜状态与结果}
- 事实：{基线中已确认的页面事实}
- 基线来源：{§章节 / 稳定编号}
```

没有某类事实时，不输出空分类标题。

## 9. 零事实处理

- 仍生成交接文件。
- `事实数量` 写 `0`。
- `页面事实` 下写“本次需求基线未包含可直接投影的页面事实。”

## 10. 失败处理

生成失败只影响 Page Spec 交接，不影响需求基线、UXB 或 Experience Blueprint。

失败时：

- 不修改已冻结的需求基线。
- 不从其他来源补事实。
- 向用户说明失败位置。
- 下游 UXB 和 Experience Blueprint 仍可使用需求基线。

## 11. Agent 语义验收

生成前完成以下逐条检查：

1. 完成 §6.1 的内部候选事实对账。
2. 为每条命中白名单的事实检查一个 HF-ID；不命中时有明确原因。
3. 检查每个 HF 的事实、类型和基线来源均可回指。
4. 检查 `事实数量` 等于实际 HF 条目数。
5. 检查没有输出体验策略、交互方案、页面推断、原始 PRD 新事实或 UXB 结论。

脚本只能检查文件存在、编号连续和数量一致。事实是否命中白名单、是否遗漏和是否越界，只能由 Agent 进行语义验收。
