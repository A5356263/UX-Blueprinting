# Wiki 页面规格

## 目标

为 `knowledge/wiki/` 下的 Markdown 页面提供统一的写作合同，保证：

- 人可读
- LLM 可稳定消费
- 可增量维护
- 可显式记录缺口与冲突

## 页面类型

当前定义 5 类页面：

### 1. Entity Page

用于描述相对稳定的对象。

适用对象示例：

- 页面
- 角色
- 应用
- 治理模式
- 组织对象

### 2. Concept Page

用于描述抽象概念、规则边界和定义。

适用对象示例：

- 功能权限
- 数据权限
- 应用可见性
- 协作可见性
- 查询职责

### 3. Topic Page

用于描述跨多个对象的综合性专题。

适用对象示例：

- 页面承载语义
- 治理模式对比
- 权限查询路径
- 体验转译要求

### 4. Relation Page

用于描述两个或多个对象之间的关系、边界和映射。

适用对象示例：

- 应用可见性 vs 功能权限
- 查询页与配置页边界
- 页面与任务场景映射

### 5. Index Page

用于提供领域入口和导航，不承担核心知识真源。

## 文件路径建议

- `knowledge/wiki/entities/<slug>.md`
- `knowledge/wiki/concepts/<slug>.md`
- `knowledge/wiki/topics/<slug>.md`
- `knowledge/wiki/relations/<slug>.md`
- `knowledge/wiki/indices/<slug>.md`

建议文件名使用稳定 ASCII slug，页面标题使用中文业务名。

## 通用页面合同

所有 Wiki 页面都建议包含以下栏目：

### 0. 文件定位

说明该页的角色、适用范围和不处理内容。

### 1. 结论

给出当前最稳定、最应优先消费的结论。

### 2. 适用范围与边界

明确：

- 本页覆盖什么
- 本页不覆盖什么
- 与哪些相邻页面存在边界

### 3. 主体内容

按页面类型填充核心知识。

### 4. 关键关系

明确本页与其他页面或对象的依赖、映射、上下游关系。

### 5. 证据与来源

列出支撑结论的原始来源、任务产物或已有知识页。

### 6. 关联页面

列出建议联读页面。

### 7. 缺口与冲突

显式记录不确定性。

### 8. 变更记录

记录关键改动和原因。

## 类型化补充要求

### Entity Page 必填内容

- 对象名称
- 对象类型
- 对象职责
- 关键状态
- 上下游关系
- 常见混淆点

### Concept Page 必填内容

- 概念定义
- 判定规则
- 非目标说明
- 常见误解
- 与相近概念的区分

### Topic Page 必填内容

- 专题目标
- 结构分解
- 关键结论
- 适用场景
- 非适用场景

### Relation Page 必填内容

- 关系双方
- 关系类型
- 联系点
- 差异点
- 选择条件

### Index Page 必填内容

- 入口说明
- 导航结构
- 推荐阅读顺序

## 标记规范

允许在正文中显式使用以下标记：

- `[GAP]`：信息缺口，尚未确认
- `[CONFLICT]`：不同来源存在冲突
- `[ASSUMPTION]`：暂时假设，后续需核实
- `[DEPRECATED]`：旧结论，不建议继续引用

要求：

- `[GAP]` 必须尽量指出缺的是哪一类信息
- `[CONFLICT]` 必须指出冲突双方或冲突来源
- `[ASSUMPTION]` 不得伪装成最终结论

## 引用规则

建议优先引用三类来源：

1. 原始资料
- 任务输入
- 会议纪要
- 页面材料
- 外部文档快照

2. 仓库知识
- `knowledge/business/`
- `knowledge/guidelines/`

3. 任务产物
- `facts.md`
- `business_blueprint.md`
- `experience_blueprint.md`

当页面结论来自推导而非原文直述时，应明确说明“根据哪些来源归纳得出”。

## 维护原则

- 稳定结论前置
- 证据后置
- 缺口显式保留
- 冲突不强行抹平
- 优先增量修改，不做无意义重写

## 与主链路的边界

Wiki 页面不是最终交付件。

它承担的是：

- 长期知识沉淀
- 跨任务复用
- 领域概念统一
- 任务上下文压缩

它不承担的是：

- 替代 `facts.md`
- 替代业务蓝图
- 替代体验蓝图
- 替代视觉设计稿
