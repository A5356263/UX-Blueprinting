# 体验蓝图消费设计指南知识优化方案

> 适用项目：UX-Blueprinting  
> 适用分支语境：`origin/研发版模式`  
> 目标问题：`experience_blueprint.md` 生成时必须结合设计指南知识，但当前链路未实际消费 `Design Guidelines`。  
> 基本原则：不新增重型机器语义，不把体验蓝图重新拉回编号化 / trace 化，不用硬编码规则替代模型判断。

---

## 1. 背景

当前项目的主链路是：

```text
task_card.md
→ task_card_resolved.json
→ context_manifest.json
→ facts.md
→ business_blueprint.md
→ experience_blueprint.md
→ check_status.json / check_report.md
```

体验蓝图阶段的定位是：基于 `facts.md` 和 `business_blueprint.md`，用 UX 设计师语言生成可评审的体验方案，包括角色、流程、页面、弹窗、抽屉、状态、异常与文案。

在这个阶段，设计指南不是可选项。体验蓝图需要根据具体业务场景，按需查阅设计指南，避免只输出业务流程说明，而缺少体验策略和交互质量支撑。

---

## 2. 当前问题

### 2.1 现象

本次 `projects/employee-self-permission` 测试中，`task_card.md` 已包含：

```md
## Design Guidelines

- knowledge/wiki/summaries/guidelines/README.md
```

但运行后的 `task_card_resolved.json`、`context_manifest.json`、`knowledge_usage_report.json` 中，体验阶段没有实际消费设计指南。

典型表现是：

```json
"experience": {
  "guideline_refs_used": [],
  "guideline_raw_refs_used": [],
  "guideline_selection_reason": []
}
```

这说明体验蓝图生成时只消费了权限业务知识，没有消费设计指南知识。

### 2.2 根因

根因不是 `task_card.md` 没写指南入口，而是解析和装配链路没有保留这一节。

当前 `task_card_resolve` 的引用解析只覆盖：

```text
Knowledge
Wiki
Templates
Checks
```

没有把：

```text
Design Guidelines
```

纳入可解析引用，因此这部分信息在 `task_card.md → task_card_resolved.json` 的转译过程中被丢失。

随后 `knowledge_consumption/planner.py` 只有在已解析出的 refs 中发现 `/guidelines/`，才会把它放入 experience 阶段的 `guideline_refs`。因为前一步已经丢失，所以后续自然为空。

---

## 3. 优化目标

本次优化要达成以下目标：

1. `task_card.md` 可以只声明设计指南入口，不要求人工精准列出所有具体指南。
2. `task_card_resolved.json` 不能丢失 `Design Guidelines` 信息。
3. `experience_blueprint.md` 生成前，模型根据 `business_blueprint.md` 中的方案承接要求、主要风险、页面/流程/状态/异常场景，自行选择需要查阅的设计指南。
4. 设计指南的实际消费记录写入现有 `knowledge_usage_report.json`。
5. 不新增复杂硬编码脚本，不做大量 if-else 场景映射。
6. 不把体验蓝图产物改回机器编号、trace 表、承接矩阵。

---

## 4. 设计原则

### 4.1 task_card 只做入口声明，不做精准指南选择

`task_card.md` 只需要表达：

```md
## Design Guidelines

- knowledge/wiki/summaries/guidelines/README.md
```

它的含义是：

```text
本任务的 experience 阶段必须允许并优先使用设计指南。
具体读哪些指南，由 experience 生成时根据业务蓝图和体验场景判断。
```

不要求在 task_card 阶段提前判断：

- 状态反馈指南
- 异常反馈指南
- 表单文案指南
- 承载容器指南
- 列表空状态指南
- 信息架构指南

因为仅凭需求背景很难精准判断全部体验策略需要的指南，过早枚举反而容易漏。

### 4.2 体验阶段负责动态选择指南

真正的选择动作发生在 experience 生成前。

选择依据包括：

- `business_blueprint.md` 的「方案承接要求」
- `business_blueprint.md` 的「主要风险与保护策略」
- 体验蓝图即将涉及的角色
- 体验蓝图即将涉及的流程
- 页面、弹窗、抽屉、表单、列表、状态、异常、阻断等场景

选择方式应该是模型根据上下文理解后自然判断，而不是脚本硬编码。

### 4.3 只记录消费，不污染产物

`knowledge_usage_report.json` 用于记录设计指南消费情况：

```json
"guideline_refs_used": [],
"guideline_raw_refs_used": [],
"guideline_selection_reason": []
```

这些字段可以继续使用，但不应该要求 `experience_blueprint.md` 里出现机器化引用、编号或 trace。

体验蓝图仍然保持自然语言产物：

```text
谁做什么、系统怎么回应、页面上写什么文案、失败时怎么处理。
```

---

## 5. 目标链路

优化后的链路应为：

```text
task_card.md
  声明 Design Guidelines 入口
        ↓
task_card_resolved.json
  无损保留 guideline_refs
        ↓
context_manifest.json
  experience 阶段携带 guideline 入口
        ↓
experience 生成前
  根据 business_blueprint 的风险、承接要求、页面/流程场景，选择具体指南
        ↓
experience_blueprint.md
  自然语言吸收设计指南，不输出机器引用
        ↓
knowledge_usage_report.json
  记录实际消费的 guideline summary / raw / selection reason
```

---

## 6. 具体改造点

### 6.1 `task_card_resolve/core.py`

增加对 `## Design Guidelines` 的解析。

建议新增字段：

```json
{
  "guideline_refs": [
    "knowledge/wiki/summaries/guidelines/README.md"
  ]
}
```

同时建议保留以下信息，避免未来继续出现有损转译：

```json
{
  "raw_sections": {
    "Design Guidelines": [
      "knowledge/wiki/summaries/guidelines/README.md"
    ]
  },
  "unparsed_sections": []
}
```

要求：

- `task_card.md` 中出现的正式章节，不应无声丢失。
- 未识别章节应进入 `unparsed_sections`，用于检查。
- `Design Guidelines` 不应混入业务 knowledge refs，而应作为 experience 阶段可用的指南入口。

### 6.2 `context_assemble/core.py`

在组装上下文时，将 `guideline_refs` 注入 experience 阶段。

建议在 `knowledge_consumption_plan.experience` 中稳定出现：

```json
{
  "guideline_entry_refs": [
    "knowledge/wiki/summaries/guidelines/README.md"
  ],
  "guideline_refs": [],
  "raw_refs_from_source_refs": []
}
```

说明：

- `guideline_entry_refs` 表示 task_card 声明的指南入口。
- `guideline_refs` 表示实际选中的具体指南 summary。
- 如果暂时不做实际自动选择，也至少不能丢失入口。

### 6.3 `knowledge_consumption/planner.py`

不要只从 `knowledge_refs` / `wiki_refs` 里筛 `/guidelines/`。

应支持：

```text
resolved.guideline_refs
```

作为 experience 阶段的设计指南入口。

选择逻辑不建议硬编码为大段脚本，只需要保证：

- 指南入口被装配进上下文；
- experience 生成提示中要求模型根据 business 自行选择；
- 选择结果能写入 `knowledge_usage_report.json`。

### 6.4 `specs/10_experience_blueprint_contract.md`

保留并强化当前规则：

```text
生成前先读 business_blueprint.md 的「方案承接要求」和「主要风险与保护策略」，根据内容判断需要查阅哪些设计指南。
```

但表述上要避免变成硬编码规则。建议改为：

```text
体验阶段必须在生成前判断当前体验方案涉及哪些设计问题，并从 task_card 的 Design Guidelines 入口中选择相关指南。选择依据包括：状态反馈、异常阻断、弹窗/抽屉承载、表单填写、列表记录、空状态、信息架构、认知负担、可访问性等。
```

### 6.5 `knowledge_usage_report.json`

继续使用现有字段，但要补齐内容：

```json
"experience": {
  "guideline_refs_used": [
    "knowledge/wiki/summaries/guidelines/xxx.md"
  ],
  "guideline_raw_refs_used": [
    "knowledge/raw/guidelines/xxx.md"
  ],
  "guideline_selection_reason": [
    {
      "guideline": "knowledge/wiki/summaries/guidelines/xxx.md",
      "reason": "business_blueprint 中存在关闭模式阻断、审批失败、申请状态反馈等场景，需要参考异常与状态反馈指南"
    }
  ]
}
```

如果 summary 信息足够，可以不读取 raw；如果 summary 不足以指导设计，再回查 raw。

---

## 7. 不做什么

本次优化明确不做以下事情：

1. 不把所有设计指南一次性塞进上下文。
2. 不在 task_card 阶段要求人工列出所有具体指南。
3. 不做大段硬编码场景映射。
4. 不要求 `experience_blueprint.md` 输出 guideline ID、trace 表、承接矩阵。
5. 不新增独立的“设计指南选择阶段”作为主链路阶段。
6. 不改变 `facts → business → experience` 的主结构。

---

## 8. 验收标准

### 8.1 基础验收

给定 task_card：

```md
## Design Guidelines

- knowledge/wiki/summaries/guidelines/README.md
```

运行 assemble 后，应满足：

```text
task_card_resolved.json 中存在 guideline_refs
context_manifest.json 中 experience 阶段能看到 guideline 入口
knowledge_usage_report.json 中 experience 不再丢失指南入口
```

### 8.2 体验生成验收

生成 `experience_blueprint.md` 后，应满足：

```text
knowledge_usage_report.json 中 guideline_refs_used 不为空，或明确记录没有选中具体指南的原因。
```

如果业务蓝图中存在以下内容，则通常应能选中相关指南：

- 状态变化 / 状态反馈
- 异常 / 阻断 / 失败
- 弹窗 / 抽屉
- 表单 / 填写 / 提交
- 列表 / 记录 / 空状态
- 信息架构 / 认知负担 / 可访问性

### 8.3 产物质量验收

`experience_blueprint.md` 应体现设计指南带来的体验质量提升，但不能出现机器化表达。

合格表现：

```text
阻断提示有原因、有下一步；
审批详情页能帮助审批人判断；
表单提交前解释关键风险；
状态文案具体可展示；
异常流程有用户可执行的下一步。
```

不合格表现：

```text
只写“需要提示用户”；
只写“页面文案要解释状态”；
直接暴露 guideline_refs；
出现 EXP-xx / TR-xx / source_path 等内部标记。
```

---

## 9. 推荐实施顺序

1. 修改 `task_card_resolve/core.py`，保留 `Design Guidelines`。
2. 修改 `task_card_resolved.json` 的结构输出，增加 `guideline_refs`。
3. 修改 `context_assemble/core.py`，将 guideline 入口注入 experience。
4. 修改 `knowledge_consumption/planner.py`，支持从 `resolved.guideline_refs` 获取指南入口。
5. 强化 `specs/10_experience_blueprint_contract.md` 中的指南选择规则。
6. 确认 `knowledge_usage_report.json` 记录实际指南消费。
7. 用 `projects/employee-self-permission` 重跑验证。

---

## 10. 最终结论

本问题的本质不是体验蓝图不需要设计指南，而是 `task_card.md → task_card_resolved.json → context_manifest.json` 的链路中，`Design Guidelines` 被有损解析丢掉了。

正确优化方向是：

```text
task_card 只声明指南入口；
resolved 无损保留入口；
experience 根据 business 和体验场景自然选择指南；
usage_report 记录实际消费；
体验蓝图保持人话，不回退到编号和机器 trace。
```
