# 预览层页面结构关系渲染规范

## 1. 文档目的

本规范用于约束 preview 层如何把正式体验蓝图中的页面结构关系更真实地还原出来。

本规范的前提是：

- preview 不是主驱动层
- preview 不新增业务语义
- preview 只消费正式蓝图与预览中间模型

## 2. 当前现状问题

### 2.1 中间模型问题

当前 `packages/experience_preview/build_preview_model.py` 会从 `区块布局示意` 中提取代码块，并把每一行转成：

- `label`
- `block_type`
- `summary`

但不会识别：

- left / right
- main / side
- header + footer
- top / bottom
- split layout

因此结构关系在中间模型阶段就被压平了。

### 2.2 渲染器问题

当前 `packages/experience_preview/render_html.py` 中 `_render_sketch_blocks()` 只是把 `sketch_blocks[]` 逐个渲染成顺序 block，因此：

- 左右关系会退化为上下堆叠
- 主从关系不会被表达
- Header / Footer 只是普通区块
- Step / Side / Menu 关系不会被真实还原

## 3. 预览层目标

preview 要做到的不是“画得更精细”，而是：

**把正式蓝图中已经存在的页面结构关系，用最小但稳定的方式还原为更接近真实页面的草图。**

## 4. 不做什么

preview 不做：

- 不回写蓝图
- 不补业务语义
- 不从 RAW 直接读结构语义
- 不自行猜测结构变化
- 不生成高保真页面
- 不进入响应式 / 栅格 / 像素层

## 5. 合同层需要补充的内容

### 5.1 `specs/14_experience_preview_contract.md`

需要补充：

- `page_views[].sketch_blocks[]` 不再只是线性块列表
- 必须支持最小结构关系字段

建议新增字段：

- `layout_kind`
- `zone`
- `position_hint`
- `children[]`

或等价字段，但目标一致。

## 6. 推荐最小中间模型

建议把 `sketch_blocks[]` 最小升级为：

```text
sketch_block
- block_id
- label
- summary
- zone
- layout_kind
- position_hint
- children[]
```

### 6.1 `zone` 建议值

- header
- intro
- filter
- action
- menu
- tab
- step
- main
- side
- footer
- alert
- info

### 6.2 `layout_kind` 建议值

- stack
- split_lr
- main_side
- footer_actions
- header_with_actions
- single

### 6.3 `position_hint` 建议值

- top
- left
- right
- center
- bottom
- inline

## 7. 解析规则

### 7.1 输入来源

预览层只解析正式蓝图中的 `区块布局示意`。

### 7.2 解析目标

从 ASCII / 文本图中识别：

- 单列堆叠
- 左右并列
- 主区 + 辅区
- 顶部头部 + 右侧动作
- 底部动作区

### 7.3 解析原则

#### 能识别则结构化

若能从文字判断：

- `Left`
- `Right`
- `Main`
- `Side`
- `Footer`
- `Header`

则必须转成结构关系。

#### 不能识别则降级

若无法稳定识别，再退回普通 `stack`。

#### 不得伪造

不能为了好看强行脑补不存在的 left/right 关系。

## 8. 渲染规则

### 8.1 页面级布局

每个页面草图应至少支持：

1. 顶部 Header
2. 左右双栏
3. 主区 + Side 区
4. Footer 动作区
5. Step / Tab 与 Main 的上下组合

### 8.2 视觉表现原则

渲染只需做到：

- 一眼能看出结构关系
- left / right 明显可见
- header / footer 与主体分层明显
- 抽屉与弹窗有基本形态差异

不需要：

- 真组件皮肤
- 真操作态
- 精确宽度

## 9. 与正式蓝图的边界

preview 只负责把蓝图里已有的结构表达得更像结构，不负责把蓝图里没有的结构补出来。

因此：

- 蓝图没写 left/right，preview 不得强造 left/right
- 蓝图没写结构变化，preview 不得擅自做页面重排

## 10. 目标文件清单

建议至少更新：

- `specs/14_experience_preview_contract.md`
- `packages/experience_preview/build_preview_model.py`
- `packages/experience_preview/render_html.py`
- `docs/runbook/experience_preview_flow.md`

## 11. 验收标准

1. 页面草图不再默认全部顺序堆叠
2. left / right / main / side / footer 能被还原
3. 无法识别时能安全降级为 stack
4. preview 不新增业务语义
5. preview 结果与正式蓝图表达一致
