# 体验蓝图预览层集成与地址输出合同

## 1. 文档目的

本文档用于定义体验蓝图预览层在工程集成中的硬性执行约束，重点回答以下问题：

- 预览层在何时触发。
- 预览层与主链路之间的边界是什么。
- 预览层完成后，Code Agent 必须如何在聊天窗口输出本地预览地址。
- 预览层失败时，不得对主链路造成何种影响。

本文档属于实现约束文档，不承担业务说明职责。

---

## 2. 定位定义

### 2.1 功能定位

体验蓝图预览层是正式体验蓝图的只读派生扩展层。

其职责是：

- 读取正式体验蓝图。
- 生成本地浏览器可访问的预览页面。
- 向使用者交付明确可打开的本地预览地址。

### 2.2 非主链路定位

体验蓝图预览层不属于主链路正式产物，不参与主链路正式校验，不改变主链路阶段定义。

### 2.3 核心边界

预览层必须同时满足以下边界：

- 不回写正式体验蓝图。
- 不修改主链路已有产物。
- 不新增业务结论。
- 不作为主链路成功与否的判定条件。
- 不进入正式 Gate / Validate。

---

## 3. 触发合同

### 3.1 触发时机

预览层的标准触发时机为：

**主链路任务完成后，再执行预览层生成。**

这里的“主链路任务完成”指主链路约定的正式产物已经生成完成，且主链路已结束当前轮次的正式输出。

### 3.2 禁止提前触发

以下情况不得触发预览层：

- 正式体验蓝图尚未生成完成。
- 主链路仍处于事实收集、推导、校验、归档等正式处理中。
- 当前正式蓝图仍在被主链路写入或覆盖。

### 3.3 允许的触发方式

允许以下触发方式：

- 主链路末尾显式串接预览生成步骤。
- 主链路完成后由独立后处理步骤触发。
- Code Agent 在确认主链路完成后主动执行预览生成。

无论使用哪种触发方式，都必须满足“先主链路完成，后预览层执行”。

---

## 4. 输入与输出合同

### 4.1 输入合同

预览层的标准输入为正式体验蓝图文档。

若工程中存在中间结构，也只能作为技术中间层使用，不得取代正式体验蓝图作为事实源。

### 4.2 输出合同

预览层的标准输出为：

- 本地浏览器可访问的预览页面或预览站点。
- 聊天窗口中可直接点击或复制访问的本地预览地址。

### 4.3 禁止的输出替代

以下内容不得替代本地预览地址交付：

- 仅输出本地文件路径。
- 仅输出目录路径。
- 仅输出“已启动服务”之类的模糊提示。
- 仅输出截图或静态图片而不给出地址。

---

## 5. 地址输出合同

### 5.1 地址输出要求

在预览层生成完成后，Code Agent 必须在聊天窗口明确输出本地预览地址。

### 5.2 地址格式要求

本地预览地址应满足以下要求：

- 必须为完整 URL。
- 必须包含协议头，例如 `http://`。
- 必须包含本地地址与端口，例如 `127.0.0.1` 与端口号。
- 推荐格式为：`http://127.0.0.1:<port>`。

### 5.3 输出展示要求

聊天窗口中的地址输出必须满足以下要求：

- 单独成行展示。
- 文本中明确说明这是“本地预览地址”。
- 不得把地址埋在大段说明中导致难以发现。
- 若存在多个入口，应明确说明默认入口地址。

### 5.4 最低输出模板

推荐最低输出模板如下：

```text
本地预览地址：
http://127.0.0.1:<port>
```

如存在首页路由，也可写为：

```text
本地预览地址：
http://127.0.0.1:<port>/
```

---

## 6. 失败与降级合同

### 6.1 失败隔离要求

若预览层生成失败，不得影响主链路正式产物的保留、归档、交付或成功判定。

### 6.2 失败反馈要求

若预览层失败，Code Agent 必须在聊天窗口明确说明：

- 主链路正式产物是否已完成。
- 失败发生在预览层，而不是主链路正式阶段。
- 当前失败原因。
- 是否已生成部分可访问内容。

### 6.3 禁止的失败表述

不得使用以下模糊表述：

- “整体失败”。
- “任务失败”。
- “无法完成主流程”。

若主链路已完成，则必须明确写明：

**主链路已完成，失败仅发生在预览层。**

---

## 7. 集成行为限制

### 7.1 不得进入正式校验

预览层不得进入主链路正式 Gate / Validate，不得把预览渲染结果作为正式蓝图合格性的硬门槛。

### 7.2 不得改变正式文件合同

预览层不得要求主链路正式体验蓝图为了预览而改变其正式文件命名、正式归档路径或正式阶段顺序。

### 7.3 允许的轻量配合

允许主链路为了提升预览稳定性，补充以下轻量配合项：

- 稳定章节标题。
- 稳定表头命名。
- 稳定页面、流程、状态等标识写法。

但这些配合项不得改变主链路的业务含义。

---

## 8. 验收要点

预览层集成完成后，至少应满足以下验收项：

- 主链路正式产物仍可独立存在。
- 预览层在主链路完成后才触发。
- 预览层失败不会导致主链路被判失败。
- 聊天窗口中明确给出本地预览地址。
- 地址为完整可访问 URL，而非文件路径。
- 预览层仍保持只读派生扩展层定位。

---

## 9. 结论性定义

为避免后续理解偏差，统一使用以下定义：

**体验蓝图预览层，是正式体验蓝图的只读派生扩展层，不属于主链路正式产物，不参与主链路校验，仅用于本地浏览器可视化阅读；在主链路任务完成后执行，并由 Code Agent 在聊天窗口明确交付本地预览地址。**
