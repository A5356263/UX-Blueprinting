# 体验蓝图预览层总方案文档（通用版）

## 1. 文档目的

本文档用于定义“体验蓝图预览层”的通用方案。

该预览层用于在主链路生成正式体验蓝图文档后，将其转换为更适合人阅读的本地浏览器预览形态。预览层不改变正式蓝图的业务语义，不替代正式蓝图，也不承担主链路中的业务判断职责。

本方案适用于任意体验蓝图，只要其内容至少覆盖页面、流程、状态、文案、风险、规则、原则或追踪关系中的主要部分，即可生成通用预览。

---

## 2. 方案定位

### 2.1 方案性质

预览层属于以下性质：

- 正式体验蓝图的派生阅读层。
- 面向人阅读的可视化说明层。
- 主链路完成后的后处理展示层。
- 本地浏览器预览层。

### 2.2 明确不是

预览层不是以下内容：

- 原型系统。
- 高保真设计稿。
- 低保真原型工具。
- 新的正式业务产物。
- 主链路的校验对象。
- 替代体验蓝图的唯一交付形式。

---

## 3. 方案目标

预览层的核心目标如下：

1. 将正式体验蓝图转换为更适合人阅读的浏览器预览页面。
2. 用简单流程图表达整体体验流程与阻断关系。
3. 用单页面线框草图表达页面骨架与信息层级。
4. 在每张页面草图下挂出该页面对应的全部说明信息。
5. 在主链路任务完成后，向使用者提供本地预览地址。

---

## 4. 核心原则

### 4.1 正式蓝图唯一事实源原则

正式体验蓝图文档是唯一事实源。预览层只读消费正式蓝图，不回写正式蓝图，不新增正式结论。

### 4.2 不增语义原则

预览层不得新增页面、流程、状态、规则、风险、阻断、原则或结论。若某信息在正式蓝图中不存在，则预览层只能显示缺失，不得自行补造。

### 4.3 人读优先原则

预览层的目标是降低阅读成本，而不是追求设计感、视觉精度或交互复杂度。

### 4.4 固定结构原则

无论具体蓝图内容如何，预览层都应使用统一结构输出，避免每个项目都变成一套不同的阅读方式。

### 4.5 主链路隔离原则

预览层是主链路完成后的后处理层。它不得改变主链路中的阶段定义、产物合同、归档逻辑、校验逻辑或业务语义。

### 4.6 地址可交付原则

预览层不仅要生成页面，还必须对外提供可访问入口。在主链路任务完成后，Code Agent 必须在聊天窗口明确给出本地预览地址，便于直接打开查看。

---

## 5. 输入范围

### 5.1 输入对象

输入对象为整份正式体验蓝图文档，而不是只读取个别章节。

### 5.2 输入要求

蓝图可以是任意业务域，但为了生成稳定预览，建议至少具备以下一种或多种结构：

- 信息架构或入口关系。
- 任务流或流程说明。
- 页面 / 窗口清单。
- 页面目标与关键动作。
- 区块布局示意或页面骨架说明。
- 状态、反馈、文案、风险、规则、原则、追踪映射等结构化说明。

### 5.3 缺失容忍

若某些章节缺失，预览层允许降级渲染，但必须遵守以下约束：

- 可以缺少部分页面专属状态。
- 可以缺少部分页面专属文案。
- 可以缺少页面级草图来源。
- 不可以因缺失信息而新增业务语义。

---

## 6. 输出范围

### 6.1 输出内容

预览层输出为一套本地浏览器可访问的前端预览页面，建议至少包含：

- 总入口页。
- 全局流程总览页。
- 页面预览卡集合页，或单页内的页面卡列表。

### 6.2 输出形态

预览层只表达两类一级视图：

#### 视图一：全局流程总览

用于展示主链路中的主要节点、路径、阻断与回退关系。

#### 视图二：页面预览卡

每个页面、抽屉、弹窗、子页面或其它承载单元，均对应一张预览卡。

每张预览卡固定包含：

1. 页面摘要。
2. 线框草图。
3. 关键理解。
4. 状态。
5. 文案。
6. 风险与阻断。
7. 原则与追踪。
8. 开放问题 / 缺口。

---

## 7. 页面表达方式

### 7.1 页面排序原则

页面不按文档章节顺序排，而按阅读顺序排。

排序优先级如下：

1. 先主流程，后补充页面。
2. 父页面在前，附属浮层在后。
3. 主要阅读页在前，解释性页在后。
4. 若无法判断，则按页面清单顺序保底。

### 7.2 页面分组原则

若蓝图中存在不同角色域、业务域或阶段域，可按域分组展示，但不强制。

### 7.3 页面承载类型

预览层至少支持以下承载类型：

- 页面。
- 抽屉。
- 弹窗。
- 子页面。
- 流程节点说明页。

---

## 8. 草图表达方式

### 8.1 草图定义

预览中的草图只用于表达页面骨架、区块关系与信息层级，不用于表达真实视觉设计。

### 8.2 草图表现要求

草图必须满足以下要求：

- 只使用块级示意。
- 允许使用短标签标识区块语义。
- 不渲染真实组件。
- 不渲染真实交互状态。
- 不使用真实业务数据。
- 不追求视觉高保真。

### 8.3 草图块数量建议

单页建议控制在 5 至 8 个区块。若超过该范围，应优先进行语义合并，避免草图再次文档化。

---

## 9. 流程图表达方式

### 9.1 流程图类型

采用简单流程图或页面流程图，不采用重型业务流程建模语法。

### 9.2 流程图节点字段

每个节点只展示以下最小信息：

- 节点名称。
- 节点类型。
- 一句任务目标。

### 9.3 连线规则

- 实线表示主成功路径。
- 虚线表示阻断、失败或回退路径。
- 连线标签可标识规则编号、异常编号或关键判断。

### 9.4 流程图边界

流程图不表达页面内部细节，不表达组件层内容，不承担页面级注释职责。

---

## 10. 页面下挂信息范围

每张页面预览卡下应尽可能挂出与该页面相关的一切信息，但必须按固定分类展示，不得直接复制整段原文。

固定分类如下：

1. 页面摘要。
2. 关键理解。
3. 状态。
4. 文案。
5. 风险。
6. 阻断。
7. 原则。
8. 追踪映射。
9. 开放问题。
10. 缺口。

若某分类无内容，应显示为空或明确写明“无直接项”，不得静默省略。

---

## 11. 主链路集成要求

### 11.1 集成时机

预览层应在正式体验蓝图产出完成后执行。

### 11.2 集成方式

预览层应作为主链路完成后的附加步骤存在，而不是嵌入体验蓝图推导逻辑本身。

### 11.3 输出要求

主链路结束后，至少应完成以下动作：

1. 读取正式体验蓝图。
2. 生成预览中间结构。
3. 生成前端预览页面。
4. 启动本地预览服务或以本地端口暴露预览入口。
5. 在 Code Agent 聊天窗口明确输出本地预览地址。

### 11.4 地址输出要求

Code Agent 在聊天窗口输出本地预览地址时，至少应包含：

- 预览已生成的说明。
- 可访问的本地地址。
- 地址用途说明。

推荐输出形式如下：

```text
体验蓝图预览已生成。
本地预览地址：http://127.0.0.1:<port>
可在浏览器中直接打开查看全局流程图与页面预览卡。
```

若系统使用 `localhost` 或其他本地回环地址，也允许输出等价形式，但必须是可点击或可复制访问的明确地址。

---

## 12. 非目标

本方案明确不承担以下职责：

- 不进入正式 Gate / Validate。
- 不替代正式蓝图。
- 不要求业务侧改写主链路提示词。
- 不要求生成新的业务事实。
- 不要求加入交互模拟。
- 不要求引入设计系统。
- 不要求支持多人协同编辑。

---

## 13. 交付建议

建议将本方案拆分为以下文档共同使用：

1. 总方案文档。
2. 规则层文档。
3. 执行清单。
4. 实现用字段映射表。

其中前三者用于定义整体目标、约束与执行边界；字段映射表用于指导 Code Agent 将正式蓝图中的章节和字段稳定映射为预览结构。
