# 体验蓝图预览规范文档阅读顺序说明

## 1. 文档目的

本文档只用于说明体验蓝图预览规范文档的推荐阅读顺序。

本文档不承担方案定义、规则定义、实现定义或执行定义职责。

---

## 2. 核心文档范围

当前体验蓝图预览规范的核心文档共四份：

1. 《体验蓝图预览总方案（通用版）》
2. 《体验蓝图预览规则层（通用版）》
3. 《体验蓝图预览执行清单（通用版）》
4. 《体验蓝图预览实现用字段映射表（通用版）》

这四份文档构成预览层的核心规范集合。

---

## 3. 推荐阅读顺序

### 第一步：先读总方案文档

先阅读《体验蓝图预览总方案（通用版）》。

阅读目的：

- 明确预览层是什么。
- 明确预览层不是什么。
- 明确其与正式体验蓝图、主链路之间的边界。
- 明确整体输出目标与结构。

### 第二步：再读规则层文档

再阅读《体验蓝图预览规则层（通用版）》。

阅读目的：

- 明确从正式蓝图中读取哪些信息。
- 明确这些信息如何归属到流程、页面或全局说明区。
- 明确缺失时如何降级，而不新增业务语义。

### 第三步：再读执行清单文档

再阅读《体验蓝图预览执行清单（通用版）》。

阅读目的：

- 明确落地实施分阶段步骤。
- 明确每一阶段需要完成什么。
- 明确工程执行时的检查项。

### 第四步：最后读字段映射表文档

最后阅读《体验蓝图预览实现用字段映射表（通用版）》。

阅读目的：

- 明确正式蓝图内容如何映射为中间结构。
- 明确中间结构如何映射为前端预览视图。
- 明确字段缺失、页面挂载、全局挂载等实现细则。

---

## 4. 为什么采用这个顺序

采用该顺序的原因如下：

- 先理解整体定位，再理解规则，避免一开始陷入实现细节。
- 先理解规则，再看执行步骤，避免执行动作与规则脱节。
- 最后再看字段映射，避免在未理解整体边界前过早进入实现细节。

简言之，该顺序遵循：

**先看是什么，再看怎么约束，再看怎么做，最后看怎么落字段。**

---

## 5. 补充文档说明

除上述四份核心文档外，还存在一份补充性集成文档：

《体验蓝图预览层集成与地址输出合同》

该文档不纳入“四份核心文档阅读顺序”之内，但在涉及以下事项时必须同步阅读：

- 主链路末尾如何接入预览层。
- 预览层何时触发。
- Code Agent 如何在聊天窗口输出本地预览地址。
- 预览层失败时如何与主链路隔离。

---

## 6. 最低阅读要求

不同角色的最低阅读要求如下：

### 方案审阅者

至少阅读：

- 总方案文档
- 规则层文档

### 实现者 / Code Agent

至少阅读：

- 总方案文档
- 规则层文档
- 执行清单文档
- 字段映射表文档
- 集成与地址输出合同

### 验收者

至少阅读：

- 总方案文档
- 执行清单文档
- 集成与地址输出合同

---

## 7. 结论

若仅需要一个明确的推荐顺序，请按以下顺序阅读四份核心文档：

1. 总方案文档
2. 规则层文档
3. 执行清单文档
4. 字段映射表文档

涉及工程接入与地址交付时，再补充阅读《体验蓝图预览层集成与地址输出合同》。
