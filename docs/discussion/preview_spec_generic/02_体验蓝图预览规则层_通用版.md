# 体验蓝图预览层规则层文档（通用版）

## 1. 文档目的

本文档定义体验蓝图预览层的规则系统。

规则层的职责是回答以下问题：

- 从正式蓝图中读什么。
- 如何将蓝图内容归属到流程或页面。
- 如何将原始文本投影为稳定的预览结构。
- 如何在信息缺失时做降级，而不新增语义。

规则层不负责业务推导，不负责新增页面，不负责修改正式蓝图。

---

## 2. 规则总原则

### 2.1 唯一事实源原则

正式体验蓝图是唯一事实源。预览层不得自造事实。

### 2.2 显式映射原则

每一类预览内容都必须能回溯到蓝图中的明确来源。

### 2.3 最小投影原则

预览层只提取支持阅读所需的信息，不全文复写正式蓝图。

### 2.4 固定结构原则

预览层中的流程视图、页面视图、字段顺序、信息分区名称都必须稳定一致。

### 2.5 缺失显式化原则

当某类信息在正式蓝图中缺失时，预览层必须明确显示缺失，而不是静默忽略。

---

## 3. 章节到预览的映射规则

### 3.1 通用映射表

| 蓝图内容类型 | 预览用途 | 映射目标 |
| --- | --- | --- |
| 信息架构、入口关系、节点关系 | 提供路径与关系基础 | 全局流程图、页面摘要 |
| 任务流、流程步骤、判断、阻断 | 提供流程结构 | 全局流程图、单流程视图 |
| 页面 / 窗口清单 | 提供页面元信息 | 页面摘要 |
| 页面目标、首屏重点、关键动作 | 提供页面理解信息 | 关键理解区 |
| 区块布局、页面骨架说明 | 提供页面结构来源 | 线框草图区 |
| 状态与反馈信息 | 提供状态说明 | 状态区 |
| 文案合同、提示语义说明 | 提供文案解释 | 文案区 |
| 风险、疑惑点、保护策略 | 提供页面级风险解释 | 风险与阻断区 |
| 原则、判断依据、追踪映射 | 提供溯源关系 | 原则与追踪区 |
| 开放问题、缺口 | 提供未完成项 | 开放问题 / 缺口区 |

### 3.2 允许的输入形式

规则层不强依赖章节标题完全一致，但要求能识别语义等价内容。例如：

- “任务流蓝图”与“主流程说明”可视为同类输入。
- “页面 / 窗口清单”与“页面列表”可视为同类输入。
- “风险、疑惑点与保护策略”与“风险说明”可视为同类输入。

---

## 4. 页面归属规则

### 4.1 强绑定规则

当某信息明确引用页面标识、页面名称或页面对象时，必须直接归属到对应页面。

适用信息包括但不限于：

- 页面清单中的页面项。
- 页面目标与关键动作。
- 区块布局示意。
- 页面级风险。
- 页面级原则命中。
- 页面级追踪映射。

### 4.2 弱绑定规则

当某信息未明确引用页面，但其语义明显服务于某一页面时，可采用弱绑定。

弱绑定必须同时满足以下条件：

1. 该信息对某一页面具有直接解释作用。
2. 不会同时对多个页面构成等强度解释。

若无法满足以上两个条件，则禁止弱绑定。

### 4.3 全局挂载规则

以下内容应放入全局说明区，而不是强行归属页面：

- 同时作用于多页面的通用说明。
- 无法判断页面归属的规则或风险。
- 仅属于流程级别而非页面级别的信息。

---

## 5. 流程归属规则

### 5.1 流程节点来源

流程节点优先来源于正式蓝图中的：

- 页面或节点清单。
- 任务流步骤。
- 信息架构中的入口与承载关系。

### 5.2 流程节点构成

每个流程节点固定包含：

- 节点名称。
- 节点类型。
- 一句任务目标。

### 5.3 流程关系来源

节点之间的关系优先来源于：

- 明确的步骤顺序。
- 成功结果与失败结果。
- 阻断条件与回退路径。

### 5.4 流程图最小化规则

流程图只保留主路径、阻断、回退与关键判断，不展开页面内部细节。

---

## 6. 页面排序规则

### 6.1 排序目标

排序服务于阅读体验，而不是忠实复刻原文章节顺序。

### 6.2 排序优先级

页面排序按以下优先级决定：

1. 主流程顺序优先。
2. 父页面优先于附属浮层。
3. 主要阅读页优先于解释性浮层。
4. 若仍无法判断，则按页面清单原始顺序保底。

### 6.3 分组规则

若蓝图存在多角色、多业务域或多阶段域，可按域分组，但页面内部固定结构不得变化。

---

## 7. 草图生成规则

### 7.1 草图目标

草图用于表达页面结构、区块顺序、层级关系和主要信息容器。

### 7.2 草图来源优先级

页面草图生成时，推荐按以下优先级取材：

1. 区块布局示意。
2. 页面目标与关键理解中的结构描述。
3. 信息优先级说明。
4. 页面基础元信息。

### 7.3 草图块规则

每个草图块必须具备明确区块语义，不允许无来源拆块。

允许的块类型可抽象为：

- Header
- Intro
- Summary
- Step
- Main Area
- Form Area
- Constraint Note
- Detail Area
- List Area
- Actions
- Footer Actions

### 7.4 草图标签规则

块标签必须简短，优先使用正式蓝图中已有的区块语义，不允许在块内放长段落文本。

### 7.5 草图数量规则

单页块数量建议控制在 5 至 8 个；若超过该数量，应优先进行合并抽象。

### 7.6 承载类型规则

- 页面：按纵向主结构绘制。
- 抽屉：绘制右侧抽屉轮廓。
- 弹窗：绘制居中容器轮廓。
- 子页面：按页面绘制，但标注其承载身份。

---

## 8. 页面信息区固定结构规则

每张页面预览卡必须使用固定的信息区顺序：

1. 页面摘要。
2. 线框草图。
3. 关键理解。
4. 状态。
5. 文案。
6. 风险与阻断。
7. 原则与追踪。
8. 开放问题 / 缺口。

禁止因页面差异而改变以上顺序。

---

## 9. 状态映射规则

### 9.1 状态来源

状态区信息只能来自正式蓝图中的状态、反馈、结果、异常说明等相关内容。

### 9.2 状态字段

每个状态项建议至少包含：

- 状态名称。
- 触发条件。
- 页面反馈。
- 下游结果。

### 9.3 状态缺失处理

若某页面没有专属状态项，可显示“本页无直接专属状态项”，但不得凭经验补写。

---

## 10. 文案映射规则

### 10.1 文案来源

文案区信息只能来自正式蓝图中的文案合同、提示说明、语义目标或页面说明。

### 10.2 文案字段

每个文案项建议至少包含：

- 文案标识或标题。
- 场景。
- 语义目标。
- 必含信息。
- 禁止写法。

### 10.3 文案缺失处理

若某页面没有专属文案项，可显示为空，但不得伪造文案建议。

---

## 11. 风险与阻断映射规则

### 11.1 风险来源

风险区优先来自风险说明、异常说明、失败路径、限制条件与保护策略。

### 11.2 阻断来源

阻断区优先来自规则、异常条件、不可提交条件、失败条件与治理限制。

### 11.3 展示要求

风险与阻断可以在同一区中展示，但必须区分：

- 为什么用户会误解。
- 为什么系统会阻断。
- 系统给出的保护策略或处理方向。

---

## 12. 原则与追踪映射规则

### 12.1 原则来源

原则区只能来自正式蓝图中明确写出的原则、命中原因、适用位置或判断依据。

### 12.2 追踪来源

追踪区只能来自正式蓝图中的追踪映射、规则承接、判断承接或事实引用。

### 12.3 组合展示要求

原则与追踪可以放在同一区块中，但必须能明确看出：

- 本页命中了哪些原则。
- 本页承接了哪些规则、判断、事实或异常。

---

## 13. 缺失与降级规则

### 13.1 缺失声明

当蓝图缺失某项输入时，预览层必须显式声明缺失。

### 13.2 降级优先级

推荐降级顺序如下：

1. 缺页面草图来源时，使用页面目标与关键信息抽象草图。
2. 缺专属状态时，显示无专属状态项。
3. 缺专属文案时，显示无专属文案项。
4. 缺页面归属时，将信息提升为全局说明。

### 13.3 禁止事项

禁止通过经验性补全新增页面、状态、规则、风险或原则。

---

## 14. 本地预览地址输出规则

### 14.1 执行时机

在主链路完成、预览页面生成且本地预览服务可访问后执行。

### 14.2 输出对象

输出对象是 Code Agent 聊天窗口中的最终说明。

### 14.3 输出要求

必须明确输出：

- 预览已生成。
- 本地预览地址。
- 地址用途说明。

### 14.4 禁止输出方式

禁止只说“已生成，可本地查看”而不提供地址。

禁止只说“已启动服务”而不提供端口。

禁止只给文件路径而不给浏览器可访问地址。

---

## 15. 规则层适用对象

本规则层文档主要供以下对象使用：

- Code Agent。
- 预览生成脚本实现者。
- 主链路集成实现者。
- 预览验收人员。
