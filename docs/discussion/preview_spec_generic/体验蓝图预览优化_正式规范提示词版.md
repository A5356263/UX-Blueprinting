# 体验蓝图预览优化正式规范（提示词版）

## 1. 使用目的
本文件用于直接提供给 AI / Code Agent，指导其对 `projects/real-self-apply-v1/runtime/preview/index.html` 进行第二轮界面优化。

本次优化只处理预览层的**信息组织、流程图表达、页面卡布局与视觉收敛**，不改正式体验蓝图语义，不新增业务结论，不进入主链路正式产物。

---

## 2. 输入对象
- 目标文件：`projects/real-self-apply-v1/runtime/preview/index.html`
- 参考数据：`projects/real-self-apply-v1/runtime/preview/preview_model.json`
- 可联动样式：`projects/real-self-apply-v1/runtime/preview/assets/style.css`

---

## 3. 总体目标
将当前预览页从“文档网页化”继续收敛为“适合体验设计师阅读的预览页”。

重点目标：
1. 流程图更紧凑、更易扫读。
2. 流程级阻断、依赖、前提尽量融入流程节点，不再拆成冗余独立模块。
3. 页面预览卡改为一行一个，形成左主右辅的阅读结构。
4. 顶部 `Experience Blueprint` 区块缩小，降低纵向占用。
5. 删除或弱化纯内部编号、重复信息、纯调试型冗余展示。

---

## 4. 强制优化要求

### 4.1 流程图区域
1. 流程节点卡片必须更小、更紧凑。
2. 流程节点标题字号固定为 **14px**。
3. 流程节点说明文字建议 **12px**。
4. 流程节点辅助标签、编号建议 **11px**。
5. 节点内边距、节点间距、整段纵向留白必须整体缩小，目标是同屏可看到更多节点。
6. `IA-01`、`IA-04`、`IA-05` 这类标识属于**信息架构节点编号 / 内部结构编号**，不是主阅读内容：
   - 默认弱化显示；
   - 不得比节点标题更显眼；
   - 可作为副标、角标或悬浮信息；
   - 若节点名已可理解，可不作为主文案展示。
7. 不再单独保留“流程级阻断”大模块。
8. 流程级阻断必须尽量融合进流程图，改为**中间判断节点**：
   - 判断成立：进入下一节点；
   - 判断不成立：用回退线或阻断线返回原节点 / 上一步 / 当前页；
   - 连线需带简短标签，例如“满足 / 不满足”“通过 / 阻断”。
9. 当前“全局依赖 / 前提”不再单独作为大面板优先展示。
10. 链路依赖应尽量融入对应节点说明中，放在节点标题下方，作为简短依赖描述，例如：
   - `依赖：TF-01 已完成`
   - `前提：模式已开启`
11. 流程图仍需保留“按角色分泳道、按链路分组”的结构，不得退回成单一总线。

### 4.2 全局模块处理
1. 当前“全局区块”模块不再保留为独立大面板。
2. 全局信息必须拆分并融入更合适的位置：
   - 全局原则：可放到顶部紧凑说明区，使用小标签 / 小列表；
   - 全局开放问题与全局缺口：合并为一个更小的“全局待确认”区块；
   - 全局依赖 / 前提：优先融入流程节点，不再单独大块展示。
3. 若某类全局信息为空，则该子模块不渲染。
4. 不允许出现“为展示而展示”的兜底大区块。

### 4.3 页面预览卡
1. 页面预览卡必须改为**一行只展示一个**。
2. 每个页面卡改为**左右双栏结构**：
   - 左侧：页面基础信息、页面摘要、线框草图、来源说明；
   - 右侧：关键理解、状态、文案、风险与阻断、原则、设计模式与追踪、开放问题 / 缺口。
3. 右侧信息区应是信息密集区，但每个模块必须紧凑、可快速扫读。
4. 左侧是主阅读区，右侧是辅助判断区，不允许主次颠倒。
5. 不得重复展示同一语义：
   - 标题与正文不能重复；
   - 页面名与页面摘要不能重复表达同一句话；
   - 角色、入口、退出等元信息去重后再展示。
6. `来源说明` 默认折叠即可，不应抢占主阅读空间。
7. 若某页面某一类信息为空，优先不渲染该模块；只有确有必要时才显示“无直接项”。

### 4.4 顶部说明区（Hero）
1. `Experience Blueprint` 顶部区块整体缩小。
2. 主标题、说明文字、meta 信息全部降级为更紧凑的阅读层级。
3. 目标是：顶部说明区只承担“预览定位 + 来源 + 版本”作用，不占用过多纵向空间。
4. 不得让顶部说明区比实际内容区更抢眼。
5. 调试信息不得默认大面积展开。

---

## 5. 展示结构要求
优化后页面建议阅读顺序如下：

1. 紧凑顶部说明区
2. 全局流程总览
3. 全局待确认（仅在存在全局开放问题 / 缺口时显示）
4. 页面预览卡列表（一行一个）
5. 调试信息（默认折叠，弱化展示）

禁止继续保留以下当前结构：
- 独立“流程级阻断”大面板
- 独立“全局依赖 / 前提”大面板
- 独立“全局区块”大面板

---

## 6. 视觉收敛要求
1. 整体视觉目标是：更紧凑、更清楚、更像信息预览页，而不是宣传页。
2. 流程图、页面卡、顶部区块都要减少纵向留白。
3. 字号层级应明显区分：
   - 主标题
   - 页面标题 / 流程节点标题
   - 模块标题
   - 正文
   - 辅助编号 / 标签
4. 不使用夸张大标题、大空白、大段说明文。
5. 不新增高保真视觉风格，不引入复杂交互。

---

## 7. 禁止事项
1. 不修改正式体验蓝图原文。
2. 不新增业务语义。
3. 不把内部编号当作主文案。
4. 不继续增加新的独立大模块。
5. 不把调试信息作为默认阅读内容。
6. 不为“完整”而保留明显冗余区块。

---

## 8. 输出要求
AI / Code Agent 完成优化后，必须：

1. 修改预览页相关实现文件；
2. 保持预览层仍为只读派生层；
3. 输出可访问的本地预览地址；
4. 在聊天窗口中用简洁中文说明：
   - 改了哪些模块；
   - 删除或融合了哪些冗余区块；
   - 还有哪些未处理项。

---

## 9. 可直接给 AI 的执行指令
请基于本规范，优化 `projects/real-self-apply-v1/runtime/preview/index.html` 及其相关样式与渲染逻辑。严格遵守以下原则：

- 保留预览层“只读派生、不改正式蓝图”的边界；
- 优先压缩流程图与顶部说明区；
- 将流程级阻断、全局依赖 / 前提尽量并入流程图节点；
- 删除独立“全局区块”模块，并将其拆分融入合适位置；
- 页面预览卡改为一行一个、左主右辅布局；
- 删除重复文案、弱化内部编号、隐藏无必要的空模块；
- 最终给出本地预览地址供浏览器查看。
