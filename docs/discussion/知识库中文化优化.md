# 知识库中文化优化

## 任务概述

将 `knowledge/` 知识库子系统中所有业务命名从英文全部改为中文，消除英中双层命名体系，同时清除 `packages/` 主链路中历史遗留的 domain 硬编码脚手架。

## 执行阶段

### 第一轮：raw/business 改名（已完成但有遗漏）

将 `knowledge/raw/business/` 下 14 个业务域目录及 121 个文件改为中文命名，保留编号前缀（`00_`、`10_` 等）。

**遗留问题**：只改了 raw 侧，未同步改 wiki summaries 侧，造成两层命名体系：
- raw：`权限管理/`
- wiki summary：`permission/`

同一业务域需要在两套命名间跳转，且 wiki summary 的 `source_path`/`source_refs` 指向中文 raw 路径，但自身目录和文件仍是英文。

## AI 犯的错误

### 错误 1：狭隘思考，只分析被问到的范围

用户最初询问 `knowledge/raw/business` 改中文名是否有问题。AI 只分析这一个目录的改名影响，没有主动考虑镜像结构的 `knowledge/wiki/summaries/business/`。导致第一轮完成后出现双层命名。

**根因**：回答问题只聚焦窄范围，没有退一步看全局。

### 错误 2：发现风险后过度设计

当用户指出 wiki summary 也需要改名时，AI 第一反应是新增映射层（`DOMAIN_EN_TO_CN`），用英文 key 映射中文目录名。这违背了自己之前确认的原则——「代码只做字符串匹配，名称对齐即可」。

**根因**：发现代码中用目录名做字典键的风险后，下意识想保护现有代码逻辑，忘了自己之前的结论。

### 错误 3：再次犯同样的映射层错误

在写第二轮计划时，又引入了映射层方案。用户再次纠正后才去掉。

**根因**：没有从第一次纠错中吸取教训。

### 错误 4：git mv 操作产生嵌套目录

在 Step 3 执行 wiki summary 目录改名时，由于 Round 1 的 Python 修复脚本曾在中国目录下生成了残留文件，导致 `git mv` 将英文目录嵌套进了已存在的中文目录中（如 `安全管理/security_management/`）。自检时只检查了顶层目录是否消失，没有深入检查每个中文目录内部。

**修复**：删除了 14 个嵌套英文目录。

### 错误 5：计划未覆盖全部受影响的脚本

在列 knowledge/scripts/ 需要修改的脚本时，遗漏了 `lint_wiki.py`、`refresh_overview.py`、`refresh_questions.py`、`update_wiki.py`。这四个脚本同样有 `"manifests" not in p.parts` 过滤条件。

**修复**：在执行过程中发现并补充修改。

### 错误 6：计划未覆盖 knowledge_loader.py 的 _classify_ref

`packages/generation/reasoning/knowledge_loader.py` 中的 `_classify_ref` 函数检查 `"guideline" in lowered` 来对 guideline 文件分类。guidelines 目录改名后，路径变成 `/设计准则/`，这个检查会失效。最初计划中将 `knowledge_loader.py` 列入「不改」范围。

**修复**：在执行过程中发现并补充修改。

### 错误 7：Python 参数顺序错误

清除 `core.py` 中 `domain` 默认值时，将 `domain: str` 放在 `task_name: str = "Demo Task"` 之后，导致 Python 语法错误（必填参数不能跟在可选参数后面）。

**修复**：调整参数顺序，`domain` 放在 `task_name` 前面。

## 不改的区域（已确认保留）

- `page_id` 字段——稳定标识符，不随路径变化而手动修改
- `packages/` 中 `stage == "business"` 等阶段标识符——不是目录名，不需要改
- `templates/task_card.template.md`——`{{DOMAIN}}` 占位符不变
- 代码中变量名/函数名（如 `guideline_refs`、`_is_guideline_summary`）——不是路径，不需要改
- `knowledge/raw/inbox/`、`knowledge/scripts/`、`knowledge/outputs/` 等顶层目录——不是业务命名，不需要改
- `raw/`、`wiki/`、`summaries/` 等协议路径段——基础设施目录名，不需要改
