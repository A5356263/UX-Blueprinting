# 实施任务清单

## 1. 使用说明

本文件直接给 Code Agent 执行。

执行原则：

- 只改动必要文件
- 优先增强现有骨架
- 不新增无必要目录和机制
- 每项任务都要有明确验收结果

---

## 2. 任务 A：补正式主链路入口

### 目标

新增统一主链路命令，替代分散手工执行。

### 要改动的内容

- 在 `packages/__main__.py` 新增：
  - `run-main`

### 命令建议

```bash
python -m packages run-main <project-id>
```

### 逻辑要求

按以下顺序执行：

1. `assemble`
2. `generate-facts`
3. `gate-facts`
4. `generate-business`
5. `gate-business`
6. `generate-experience`
7. `gate-experience`
8. `validate`
9. `coverage`
10. `archive`
11. `preview`

### 验收标准

- 一条命令能跑完整链路
- 任一 gate 失败时，后续正式步骤停止
- `preview` 作为后置自动步骤执行

---

## 3. 任务 B：补三段正式生成能力

### 目标

让主链路具备正式“生成”步骤，不再只有装配和检查。

### 要改动的内容

新增能力入口：

- `generate-facts`
- `generate-business`
- `generate-experience`

### 逻辑要求

- 输入来源必须来自当前项目
- 输出必须落到当前项目 `workspace/`
- 每次生成后都要更新 provenance
- 不得从其他项目复制正式产物进入当前项目

### 验收标准

- 新项目可从 `requirement.md` 出发走完整链路
- 三份正式产物由当前项目生成
- 不再依赖复制旧项目正式产物

---

## 4. 任务 C：补产物来源约束

### 目标

阻止跨项目复制正式产物伪装为“当前项目生成”。

### 要改动的内容

新增：

```text
projects/<project-id>/runtime/provenance.json
```

并在以下步骤加入检查：

- `gate-facts`
- `gate-business`
- `gate-experience`
- `validate`

### 必须检查的字段

- `project_id`
- `generation_mode`
- `producer`
- `source_hash`
- `command_chain`
- `copied_from_project_id`

### 放行规则

- `generation_mode == generated` 才默认放行
- `copied` 默认失败
- 缺 provenance 默认失败

### 验收标准

- 复制旧项目正式产物时，系统能稳定拦截
- 当前项目正式产物可追溯

---

## 5. 任务 D：修正 preview 自动化与输入优先级

### 目标

让 `preview` 成为主链路完成后的自动后置动作，并修正输入读取顺序。

### 要改动的内容

- 修正 `packages/experience_preview/` 中的读取优先级
- 在 `run-main` 中自动触发 `preview`

### 正确顺序

1. 先读 `exports/final/experience_blueprint.md`
2. 不存在时再读 `workspace/experience_blueprint.md`

### 失败处理

- `preview` 失败只记录 preview 状态
- 不改写主链路成功状态

### 验收标准

- 主链路完成后自动生成本地预览
- `preview` 默认使用 final 版本
- `preview` 失败不影响正式交付状态

---

## 6. 任务 E：样例迁移与样例校验

### 目标

让样例独立治理，不污染真实项目。

### 要改动的内容

新增目录建议：

```text
examples/benchmarks/positive/
examples/benchmarks/negative/
```

迁移对象：

- `projects/real-self-apply-v1`
- `projects/demo-smoke-v1`

过渡期若不迁移，至少要：

- 标记只读
- 排除默认项目扫描
- 禁止被当作正式复用源

### 新增命令建议

```bash
python -m packages sample-check
```

### 检查项

正例检查：

- `status == passed`
- `blocker_count == 0`
- `warning_count == 0`

反例检查：

- `status == failed` 或命中特定 blocker
- repair loop 可生成修复计划

### 验收标准

- 样例校验能独立执行
- 样例不参与普通项目逻辑
- 样例不再作为复制来源

---

## 7. 任务 F：收口现有项目边界

### 目标

避免当前仓库在过渡期出现“真实项目”和“样例项目”混用。

### 要改动的内容

- 给现有样例补充标识文件，如：
  - `sample_meta.json`
  - 或在 `meta.json` 中增加 `project_role`

### 建议字段

- `project_role`: `real_project | benchmark_positive | benchmark_negative`
- `read_only`: `true | false`
- `excluded_from_default_scan`: `true | false`

### 验收标准

- 执行中枢能识别样例与真实项目
- 默认流程不会误扫样例目录

---

## 8. 实施优先级

### P0：必须先做

1. 任务 A：补 `run-main`
2. 任务 B：补 `generate-*`
3. 任务 C：补 provenance
4. 任务 D：修 preview 自动化与输入优先级

### P1：紧接着做

5. 任务 F：补项目角色标识
6. 任务 E：补 `sample-check`

### P2：整理期做

7. 把样例从 `projects/` 迁移到 `examples/benchmarks/`

---

## 9. 最终验收清单

以下条件全部满足，才算本轮改造完成：

- 新项目可以从输入独立跑完整链路
- 系统能阻止复制旧项目正式产物
- `preview` 自动后置执行
- `preview` 优先读取 `final`
- 样例不再污染真实项目目录
- 样例只用于回归校验
- Code Agent 不再需要靠临时判断决定是否复制旧产物

## 10. 一句话执行要求

先补正式生成，再补来源约束，再把 preview 自动后置，最后把样例独立治理。
