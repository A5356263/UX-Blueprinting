# 仓库优化总方案

## 1. 文档目标

在不破坏现有执行中枢、规则法典、知识库分层的前提下，补齐当前主链路的关键缺口，使仓库满足以下目标：

- 新任务必须能从头到尾独立执行
- 正式产物必须具备来源可追溯性
- 体验蓝图预览必须在主链路完成后自动生成
- 样例只作为基线校验，不污染真实项目目录
- Code Agent 能按固定入口执行，不靠临时判断

## 2. 当前判断

### 2.1 已成立的骨架

当前仓库的主骨架是成立的：

- `specs/`：正式规则真源
- `packages/`：执行中枢与固定命令入口
- `knowledge/`：知识真源与 wiki 编译层
- `memory/`：长期经验沉淀层
- `templates/`：固定模板
- `projects/`：任务项目目录

### 2.2 当前关键缺口

当前需要正式补齐的不是规则数量，而是执行闭环中的四个缺口：

1. 主链路只有“装配 + 检查”，没有正式“生成”步骤
2. 没有“产物来源约束”，无法阻止跨项目复制正式产物
3. `preview` 已实现，但没有由执行中枢在主链路完成后自动触发
4. 样例缺少独立治理边界，容易和真实项目混在一起

## 3. 正式决策

### 3.1 项目目录治理

正式决策：

- `projects/` 只保留真实项目
- 正反样例迁移到独立样例目录
- 建议新增：`examples/benchmarks/`

过渡期允许：

- 暂时保留 `projects/real-self-apply-v1`
- 暂时保留 `projects/demo-smoke-v1`

但必须同时满足：

- 明确标记为只读样例
- 不参与日常任务扫描
- 不作为正式产物复用来源

### 3.2 主链路定位

正式决策：

主链路不再只承担“装配 + 检查”，而应补齐为完整执行链：

`bootstrap -> assemble -> generate-facts -> gate-facts -> generate-business -> gate-business -> generate-experience -> gate-experience -> validate -> coverage -> archive`

说明：

- `generate-*` 是新增正式能力
- 执行中枢负责调度、落盘、状态控制
- 业务判断与体验推导仍由 Agent 完成
- 规则真源仍然只来自 `specs/`

### 3.3 产物来源约束

正式决策：

新增正式产物来源约束，禁止将“复制来的旧项目正式产物”伪装成“当前项目重新生成结果”。

最低要求：

- 每次生成正式产物时，必须写入 `runtime/provenance.json`
- `gate / validate` 必须校验来源状态
- 只要判定为复制、搬运、非本项目生成，默认失败

### 3.4 Preview 定位

正式决策：

- `preview` 不属于主链路正式产物
- `preview` 不参与 gate / validate / coverage
- `preview` 是主链路完成后的自动派生层
- `preview` 由执行中枢自动触发
- `preview` 失败不能回写为主链路失败

### 3.5 Preview 输入优先级

正式决策：

1. 优先读取 `exports/final/experience_blueprint.md`
2. 若归档版不存在，降级读取 `workspace/experience_blueprint.md`

原因：

- `final` 是稳定定稿版本
- `workspace` 是工作区版本，只能作为降级输入

### 3.6 样例治理

正式决策：

- 样例保留，但不作为规则真源
- 样例用于回归校验，不用于生成正式项目产物
- 样例校验不做全文对比
- 样例校验只比关键结果：
  - `status`
  - `blocker_count`
  - `warning_count`
  - 指定缺陷是否被暴露
  - 指定结构是否存在
  - `preview` 是否可生成

## 4. 推荐文档结构

本轮优化规范只保留 3 份正式文件：

1. `00_仓库优化总方案.md`
   - 说明目标、问题、正式决策、阅读顺序

2. `01_执行中枢与主链路优化规范.md`
   - 规定目录治理、主链路、preview、来源约束、样例校验的正式执行方式

3. `02_实施任务清单.md`
   - 直接给 Code Agent 执行
   - 逐项说明改什么、落哪里、验收标准是什么

这样即可，不再继续拆更多文档。

## 5. 阅读顺序

建议阅读顺序：

1. 本文件
2. `01_执行中枢与主链路优化规范.md`
3. `02_实施任务清单.md`

## 6. 一句话结论

本轮不是重做架构，而是在现有骨架上补齐四件事：

- 补正式生成
- 补来源约束
- 让 preview 自动后置执行
- 把样例从真实项目治理里分离出去
