# 执行中枢与主链路优化规范

## 1. 适用范围

本规范用于约束以下能力的正式改造：

- 项目目录治理
- 主链路执行
- 正式产物来源约束
- 体验蓝图预览自动执行
- 样例回归校验

本规范不替代现有 `specs/`，而是在现有规则法典之上补齐执行约束。

## 2. 目录治理规范

### 2.1 正式目录职责

- `specs/`：规则真源
- `packages/`：执行入口与固定能力
- `knowledge/`：知识真源
- `memory/`：长期经验沉淀
- `templates/`：模板
- `projects/`：真实任务项目
- `examples/benchmarks/`：正反样例

### 2.2 真实项目约束

`projects/` 下只允许放真实任务项目。

真实项目的最小结构保持不变：

- `source/`
- `workspace/`
- `runtime/`
- `exports/`

### 2.3 样例目录约束

新增：

- `examples/benchmarks/positive/`
- `examples/benchmarks/negative/`

要求：

- 样例目录默认只读
- 样例不得作为新项目正式产物复制来源
- 样例不得参与日常任务项目扫描
- 样例仅供 `sample-check` 使用

### 2.4 过渡期要求

在样例尚未迁出前：

- `projects/real-self-apply-v1` 视为正例
- `projects/demo-smoke-v1` 视为反例

但执行中枢必须：

- 对这两个项目加只读标记
- 在默认项目枚举中排除它们
- 禁止把它们当作正式产物复用源

## 3. 主链路规范

### 3.1 当前问题

当前主链路只覆盖：

- `bootstrap`
- `assemble`
- `gate-*`
- `validate`
- `coverage`
- `archive`
- `preview`

缺失正式“生成”步骤。

### 3.2 新的正式主链路

执行中枢应新增统一入口，建议命令：

```bash
python -m packages run-main <project-id>
```

正式顺序：

```text
bootstrap
-> assemble
-> generate-facts
-> gate-facts
-> generate-business
-> gate-business
-> generate-experience
-> gate-experience
-> validate
-> coverage
-> archive
-> preview
```

### 3.3 生成步骤职责

新增能力：

- `generate-facts`
- `generate-business`
- `generate-experience`

职责边界：

- 执行中枢负责调度、输入输出、状态写入
- Agent 负责内容生成
- `specs/` 继续作为唯一规则真源
- 不允许把生成逻辑偷偷塞进 `gate` 或 `coverage`

## 4. 产物来源约束规范

### 4.1 目标

保证“当前项目正式产物”必须能证明是当前项目独立生成，而不是复制旧项目结果。

### 4.2 必须新增的运行时文件

新增：

```text
projects/<project-id>/runtime/provenance.json
```

最小字段：

- `project_id`
- `generation_mode`
- `producer`
- `source_hash`
- `task_card_hash`
- `generated_at`
- `parent_project_id`
- `copied_from_project_id`
- `command_chain`

### 4.3 generation_mode 约束

允许值建议：

- `generated`
- `imported_reference`
- `copied`
- `manual_patch`

正式放行条件：

- 主链路正式产物默认只允许 `generated`
- `copied` 默认失败
- `imported_reference` 默认失败
- `manual_patch` 必须带修复说明和重跑记录

### 4.4 门禁要求

以下检查应进入 `gate / validate`：

- 当前正式产物是否存在 provenance 记录
- `project_id` 是否匹配当前项目
- `generation_mode` 是否允许放行
- 是否存在跨项目正式产物复制痕迹
- 当前 `command_chain` 是否覆盖正式主链路要求

## 5. Preview 自动执行规范

### 5.1 定位

`preview` 是体验蓝图完成后的只读派生层，不属于主链路正式产物。

### 5.2 自动执行要求

执行中枢应在以下条件满足后自动执行 `preview`：

- `archive` 完成
- `exports/final/experience_blueprint.md` 已存在
- 主链路状态为可交付

建议形式：

- `run-main` 默认自动执行 `preview`
- 允许通过显式参数关闭，如 `--skip-preview`

### 5.3 失败隔离

若 `preview` 失败，必须满足：

- 主链路正式产物保持成功状态
- 失败只记录在 preview 运行状态中
- 不得把 preview 失败写成主链路失败

### 5.4 输入优先级

正式顺序：

1. `exports/final/experience_blueprint.md`
2. `workspace/experience_blueprint.md`

不得反向读取。

### 5.5 输出要求

`preview` 最小输出保持：

- `runtime/preview/index.html`
- `runtime/preview/assets/style.css`
- `runtime/preview/preview_model.json`
- `runtime/preview/preview_runtime.json`
- `runtime/preview/preview_build_log.md`

## 6. 样例校验规范

### 6.1 新增能力

建议新增：

```bash
python -m packages sample-check
```

### 6.2 样例校验目标

样例校验只验证系统能力是否稳定，不验证全文是否逐字一致。

### 6.3 正例校验项

正例至少检查：

- `check_status.json.status == passed`
- `blocker_count == 0`
- `warning_count == 0`
- 三份正式文档存在
- `preview` 可生成
- provenance 合法

### 6.4 反例校验项

反例至少检查：

- `status == failed` 或存在指定 blocker
- 指定缺陷类型被暴露
- repair loop 能生成修复计划
- 反例不会被误放行

### 6.5 禁止事项

样例校验禁止：

- 比较全文文案
- 把样例输出当成新项目模板正文
- 用样例正式产物覆盖新项目正式产物

## 7. Code Agent 执行边界

Code Agent 在本规范下必须遵守：

- 不得跨项目复制正式产物
- 不得跳过 `generate-*`
- 不得把 `preview` 写成正式主链路产物
- 不得把样例目录当普通项目目录处理
- 不得把 `workspace` 版本优先于 `final` 版本提供给 `preview`

## 8. 最小落地结论

本规范要求最终形成 5 个新增或调整点：

1. 新增 `run-main`
2. 新增 `generate-facts`
3. 新增 `generate-business`
4. 新增 `generate-experience`
5. 新增 provenance 校验
6. 调整 `preview` 为 archive 后自动执行
7. 修正 `preview` 输入优先级
8. 新增 `sample-check`
