# discussion

## 重要说明

`docs/discussion/` 是讨论区与历史推演区，不是主链路规则目录。

- 这里的内容默认不参与主链路执行
- 这里的内容默认不作为现行规则真源
- 这里只有在被明确迁移到正式目录后，才算进入主链路

主链路当前应以这些目录为准：

- `specs/`
- `templates/`
- `packages/`
- `docs/runbook/`
- 当前任务对应的 `projects/<project-id>/source/`、`workspace/`、`runtime/`

## 这个目录的作用

本目录用于存放仍在演进中的讨论稿、方案草案、取舍记录与结构探索。

适合放在这里的内容：

- 还没有收敛成正式规则的优化讨论
- 需要保留版本演进轨迹的方案草稿
- 用来解释“为什么这样定”的推导过程
- 暂时不应直接进入主链路的实验性想法

不适合放在这里的内容：

- 已经收敛完成的正式规范
- 需要被执行链直接消费的现行规则
- 应被 `gate / validate / runbook / templates` 直接依赖的内容

## 与主链路的关系

- `docs/discussion/`：讨论过程、推导轨迹、历史版本
- 正式目录：稳定规则、执行入口、校验口径、当前模板

讨论稿本身通常不会直接影响主链路运行，但会带来认知噪音风险：

- 人工全仓搜索时可能搜到旧结论
- AI 检索仓库时可能把讨论稿误当现行规则
- 后续改逻辑时可能混淆“历史推演”与“当前标准”

因此本目录的使用约束是：

- 保留可以
- 引用到主链路不可以
- 需要生效时，必须显式迁移到正式目录

## 迁移原则

当讨论已经收敛、并准备进入主链路时：

1. 把稳定结论迁移到正式目录
2. 由正式目录承接后续执行与校验
3. 讨论稿继续保留为历史背景，不直接充当规则真源

## 目录组织方式

建议按主题建子目录，并使用 `v0.x` 维护讨论演进。

```text
docs/discussion/
  <topic-slug>/
    v0.1.md
    v0.2.md
```

## 模板

可直接使用：

- `docs/discussion/_template/discussion.template.md`
