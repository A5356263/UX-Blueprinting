# discussion

本目录用于存放仍在演进中的讨论稿、想法草案、方案取舍与结构探索。

它解决的是：

- 某个主题还没定稿，但值得持续记录
- 同一主题会经历 `v0.1`、`v0.2`、`v0.3` 之类的演进
- 需要保留“为什么这么定”的讨论过程

它不解决的是：

- 已经收敛完成的正式规范
- 稳定业务知识与稳定设计原则
- 临时闲聊式讨论

## 什么时候需要放进来

适合放入本目录的情况：

- 讨论已经超过一次，后续还会继续演进
- 需要比较多个方案、记录取舍
- 后续大概率会沉淀进 `docs/sdd/`
- 主题本身会影响目录结构、流程、规格或知识组织方式

不一定要放入本目录的情况：

- 只是一次性口头确认
- 结论已经很清楚，直接落到 `docs/sdd/` 更合适
- 只是零散想法，还不值得形成文档

## 目录组织方式

每个主题单独一个文件夹。

建议结构：

```text
docs/discussion/
  <topic-slug>/
    v0.1.md
    v0.2.md
```

示例：

```text
docs/discussion/
  wiki-sync/
    v0.1.md
    v0.2.md
  guidelines-refactor/
    v0.1.md
```

## 版本演进规则

- 讨论阶段使用 `v0.x`
- 当同一主题出现明显新增结论、取舍变化、目录变化时再升一个版本
- 不要求每次聊天都写一版文档

## 与 SDD 的关系

- `docs/discussion/`：讨论过程与演进轨迹
- `docs/sdd/`：已经确认的规格与正式规范

当讨论完成后：

1. 把稳定结论整理进入 `docs/sdd/`
2. 讨论稿保留，不删除
3. 在最后一版讨论稿中标注迁移目标
