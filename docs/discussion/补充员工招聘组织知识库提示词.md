# 任务：补充员工管理、招聘管理、组织管理知识

## 背景

我会上传 3 个文件：

```text
员工管理.md
招聘管理.md
组织管理.md
```

当前知识库中已经存在这三个模块，不需要从零新增模块。请先检查现有知识库，再按“已有则跳过、缺失则补充”的原则补齐。

当前正式知识入口：

```text
knowledge/wiki/index.md
```

当前已有模块：

```text

knowledge/wiki/summaries/业务/人事服务/招聘管理/
knowledge/wiki/summaries/业务/人事服务/组织管理/
```

## 目标

把上传的 3 个文件补充到现有知识库中，形成可被主链路消费的业务知识。

要求：

1. 不重复新增已有模块。
2. 不整份粗暴放入一个大文件。
3. 已有知识若已覆盖，则跳过。
4. 上传文件中新增、缺失、细化的内容，补充到对应 raw 文件。
5. 问答类内容统一沉淀到 `50_常见问题.md` 或对应 FAQ 文件。
6. 更新后运行知识库维护脚本，生成 / 更新 summary 和 index。

## 处理原则

### 1. raw 是真源

新增或补充知识优先写入：

```text
knowledge/raw/业务/人事服务/员工管理/
knowledge/raw/业务/人事服务/招聘管理/
knowledge/raw/业务/人事服务/组织管理/
```

不要直接手工改最终 summary 作为唯一来源。

### 2. summary 是 AI 消费入口

raw 更新后，通过脚本生成 / 更新：

```text
knowledge/wiki/summaries/业务/人事服务/员工管理/
knowledge/wiki/summaries/业务/人事服务/招聘管理/
knowledge/wiki/summaries/业务/人事服务/组织管理/
```

summary 顶部元数据必须保持完整：

```md
- page_type: summary
- source_group: business
- domain: 对应业务域
- source_refs:
```

### 3. 问答类知识归入 FAQ

上传文件中大量“常见问题 / 问答 / 为什么 / 如何 / 怎么处理”内容，不要新造编号体系。

优先放入：

```text
50_常见问题.md
```

如 FAQ 内容过多，可在同模块下新增：

```text
51_导入导出常见问题.md
52_权限与可见性常见问题.md
53_异常报错常见问题.md
```

没有必要时，不要拆太细。

## 去重要求

补充前先对比现有 raw 和 summary。

判断规则：

```text
如果现有知识已经完整覆盖，只保留现有内容，不重复写。
如果现有知识只有标题、占位、简略说明，则用上传文件补充。
如果上传文件提供了更具体的路径、规则、异常、FAQ 答案，则补充。
如果上传文件内容与现有知识冲突，不要直接覆盖，标记 [CONFLICT]。
如果上传文件内容无法确认是否仍有效，标记 [QUESTION]。
```

## FAQ 写法要求

问答类内容保持原问答语义，但要结构化整理。

推荐格式：

```md
## 如何设置工号生成规则？

### 问题

如何设置工号生成规则？

### 答案

进入【员工管理-员工管理设置-基础设置-工号设置】，开启自动生成工号后，可按前缀、序号、后缀等规则生成员工号。

### 操作路径

【员工管理-员工管理设置-基础设置-工号设置】

### 注意事项

- 若员工未匹配任何工号规则，员工号可能为空。
- 若序号生成至最大值，会报错提示。
```

不要只保留问题标题。
