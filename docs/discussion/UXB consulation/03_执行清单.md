# 前置咨询层执行清单

## 一、文档目标
本文档用于把前置咨询层的落地工作拆成可执行清单，便于后续逐项实现、验证与收敛。

## 二、第一阶段：补齐入口判断能力
### 任务一：增加入口状态定义
需要明确四类状态：

1. 修改项目本身
2. 咨询环继续
3. 新任务正式提交
4. 已有项目继续

### 任务二：增加入口判断顺序
固定判断顺序，避免误判。

### 任务三：增加歧义处理逻辑
当系统无法稳定判断时，先让聊天窗口做一次简洁确认，而不是直接进入执行。

## 三、第二阶段：补齐咨询环能力
### 任务四：定义咨询环状态
建议至少包含：

1. 当前问题摘要
2. 已确认事实
3. 当前判断
4. 阻断缺口
5. 非阻断缺口
6. 建议执行层级
7. 是否已可执行

### 任务五：增加先回答再追问逻辑
系统应优先：

1. 回答问题
2. 纠正用户可能的错误认知
3. 再判断是否要追问

### 任务六：增加缺口分类
明确区分阻断缺口与非阻断缺口。

## 四、第三阶段：补齐可执行阈值能力
### 任务七：增加分阶段阈值判断
至少区分：

1. 可执行到事实阶段
2. 可执行到业务阶段
3. 可执行到体验阶段
4. 可执行完整主链路

### 任务八：增加阈值命中后的提示逻辑
当达到阈值时，聊天窗口要给出简洁提示，而不是直接自动执行。

## 五、第四阶段：补齐正式提交动作
### 任务九：增加正式提交适配器
当用户确认执行后，系统应能把当前咨询结果整理成正式输入材料。

### 任务十：支持按阶段提交
不能默认一律跑完整主链路。
应允许：

1. 只到事实阶段
2. 到业务阶段
3. 到体验阶段
4. 完整执行

## 六、第五阶段：补齐已有项目继续能力
### 任务十一：识别已有项目继续
当用户是在补充、修复、重跑已有任务时，应沿用原项目。

### 任务十二：避免重复创建新任务
系统要避免把已有项目继续误判成新任务正式提交。

## 七、聊天提示清单
### 已可执行提示
建议至少准备以下几类提示：

1. 已可执行到事实阶段
2. 已可执行到业务阶段
3. 已可执行到体验阶段
4. 已可执行完整主链路

### 暂不可执行提示
建议至少准备以下几类提示：

1. 仍有阻断缺口
2. 继续咨询即可
3. 当前先给判断，再补关键条件

## 八、验证清单
### 判断正确性验证
需要验证：

1. 是否能正确识别修改项目本身
2. 是否能正确识别咨询环继续
3. 是否能正确识别新任务正式提交
4. 是否能正确识别已有项目继续

### 咨询行为验证
需要验证：

1. 是否优先回答而不是优先追问
2. 是否能指出用户理解错误
3. 是否能区分阻断缺口与非阻断缺口
4. 是否能在恰当时机提示可执行

### 提交行为验证
需要验证：

1. 未确认前不会误创建正式任务
2. 确认后能正确进入正式执行
3. 可按阶段执行而不是默认跑满全链路
4. 已有项目继续不会误新建任务

## 九、建议实施顺序
建议按以下顺序推进：

1. 先做入口判断
2. 再做咨询环状态
3. 再做阈值判断
4. 再做正式提交
5. 最后做已有项目继续与测试补强

## 十、交付建议
本阶段建议至少形成以下交付物：

1. 总方案文档
2. 规则层文档
3. 执行清单文档
4. 聊天提示模板文档
5. 测试样例文档
