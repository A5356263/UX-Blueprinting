# 前置咨询层接入总方案

## 一、文档目的
本文档用于定义在现有 UX-Blueprinting 项目之外，增加一层前置咨询能力的整体方案。

本方案的目标不是重建一套新的正式主链路，也不是把当前执行中枢改造成重型对话控制器，而是在不破坏现有正式执行结构的前提下，增加一层更适合咨询、澄清、问题判断与提交控制的轻量前置层。

## 二、当前问题
当前项目已经具备以下能力：

1. 可以直接修改项目本身。
2. 可以直接进入正式主链路执行。
3. 可以围绕项目工作区开展正式产物生成、检查、修复与重跑。

但当前还缺一层明确的前置判断能力，主要表现为：

1. 无法稳定判断用户当前是在修改项目本身，还是在发起业务任务。
2. 无法稳定承接“先咨询、后执行”的使用方式。
3. 用户输入一句问题时，容易被直接推进到完整主链路。
4. 聊天窗口缺少一套清晰的“何时继续咨询、何时提示可执行、何时正式提交”的规则。

## 三、目标方案
本次新增一层前置能力，放在正式执行之前。

该层只负责三件事：

1. 判断当前输入属于哪一类入口。
2. 在咨询场景下，基于已有业务知识先回答、再纠错、再判断缺口。
3. 在达到可执行阈值后，提示用户是否进入正式执行链路。

## 四、整体分层
建议把系统分为三层：

### 1. 入口判断层
负责判断当前输入是：

- 修改项目本身
- 咨询环继续
- 新任务正式提交
- 已有项目继续

### 2. 咨询环
当用户尚未正式进入项目执行时，先停留在这一层。

这一层的职责是：

- 先基于现有知识给出回答
- 指出用户认知中的可能错误
- 判断阻断缺口与非阻断缺口
- 评估是否达到可执行阈值
- 在恰当时机提示可进入正式执行

### 3. 正式执行层
只有当用户确认正式执行后，才进入当前项目既有主链路。

正式执行层继续沿用现有结构，不单独重建。

## 五、关键边界
### 1. 咨询环不是正式产物层
咨询环中的回复、判断、纠错与摘要，不能替代正式文档产物。

### 2. 正式主链路仍然只有一条
正式项目、正式任务、正式产物，仍然以已有项目工作区为唯一真相层。

### 3. 咨询环不负责替代执行中枢
咨询环只负责前置判断与提交准备，不负责接管正式执行流程。

### 4. 进入正式执行必须显式确认
即使系统判断已经达到可执行阈值，也不应自动进入正式执行，而是先提示用户确认。

## 六、建议的交互方式
### 情况一：用户在改项目本身
直接走项目修改路径，不进入咨询环，不创建正式任务。

### 情况二：用户在咨询一个问题
先进入咨询环。

咨询环优先做的是：

1. 回答问题。
2. 判断用户理解是否有误。
3. 使用当前知识做出业务判断。
4. 判断现在能否进入正式执行。

### 情况三：用户已明确要执行正式任务
若当前信息已经达到可执行阈值，则提示用户开始正式执行。

### 情况四：用户在继续一个已有项目
沿用已有项目，不新建正式任务。

## 七、正式提交时机
当满足以下条件时，可提示进入正式执行：

1. 任务目标已基本明确。
2. 当前阶段目标已清楚。
3. 阻断缺口已降到可执行范围。
4. 当前输入足以生成正式输入材料。

此时聊天窗口只提示“已可执行”，不直接自动落盘。

## 八、提交后的动作
一旦用户确认执行，系统再进入正式执行层，完成：

1. 创建或续用项目。
2. 写入正式输入材料。
3. 按选定阶段进入执行。
4. 将后续检查、修复、重跑纳入正式工作区。

## 九、非目标
本方案不做以下事情：

1. 不把咨询环做成第二套正式文档驱动系统。
2. 不让聊天窗口替代正式产物。
3. 不把当前执行中枢改造成重型问答代理。
4. 不让咨询阶段直接修改正式产物文件。

## 十、建议产出物拆分
为避免一个文档过载，建议至少拆为三份：

1. 总方案
2. 规则层
3. 执行清单

如果后续继续细化，还可拆出：

4. 聊天提示语规范
5. 咨询环状态字段说明
6. 入口判断测试样例集
