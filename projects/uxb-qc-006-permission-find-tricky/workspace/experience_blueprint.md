# 体验蓝图：功能权限设置页面内查找（刁钻混淆版）

> 输入来源：facts.md + business_note.md + 已装配设计准则（可用性/认知/信息架构/反馈与报错）

## 0. 本次关键设计判断

本次**只做页面内查找**（Ctrl+F体验），不做筛选。核心区分：
- **查找**：高亮匹配文字+焦点跳转。不改变数据展示范围——所有权限项始终可见。
- **筛选**：改变数据展示范围（只看已勾选/只显示命中项）。本次不做，拆出去。

为什么不能两者都做：需求文档自己承认（风险8.1）——如果同时支持查找和筛选，"用户可能不清楚当前看到的是全部权限中的定位结果，还是过滤后的权限集合"。这是用户认知层面的根本性冲突——在同一个页面上同时提供"定位"和"过滤"两种模式会让用户困惑。

## 1. 交互流程总览

管理员在功能权限设置页面 → 查找输入框输入关键词 → 实时高亮所有命中文字 → 焦点跳到第一个命中项 → ↑↓切换命中项 → 折叠节点自动展开 → 清空关键词恢复。

## 2. 主交互流程

### 2.1 查找入口（仅查找，不混合筛选）
- 输入框常驻顶部，placeholder"查找权限项或功能点"——使用"查找"而非"搜索"，明确语义
- 输入后实时高亮，不等待回车
- 命中计数"第1/8个"+↑↓按钮

### 2.2 命中高亮
- 所有匹配文字黄色高亮。当前焦点命中项深色标记。
- 折叠节点内命中：自动展开该节点和所有父级节点。
- **不隐藏未命中项**——所有权限项始终可见。应用U-01状态可见。

### 2.3 焦点跳转+切换
- 自动跳到第一个命中项。↑↓/Enter切换。循环。

### 2.4 清空恢复
- 高亮消失。折叠节点保持展开——应用U-03用户可控。

## 3. 次交互流程

### 3.1 折叠节点展开
- 命中时自动展开。清空后保持展开。

### 3.2 编辑状态保护
- 查找期间已修改的勾选状态不受影响。查找不触发保存/回滚。

## 4. 异常与阻断流程

### 4.1 无命中
- 提示"未找到匹配内容"。不改变页面状态。

### 4.2 大量命中（>50个）
- 提示"匹配结果较多（N个），请输入更完整的关键词"——应用C-04渐进式披露。

### 4.3 仅1个命中
- 正常跳转定位。↑↓按钮置灰。

### 4.4 用户误以为查找就是筛选
- 显式说明：所有权限项仍然可见，查找只是帮你定位——输入框旁加tooltip"查找不改变权限范围"。

### 4.5 业务方要求加入"只看已勾选"
- 升级信号——回到UXB重新判断。不在本次experience中设计。

### 4.6 查找期间修改权限勾选
- 用户点击勾选框，正常修改。查找输入框不清空，高亮不消失——查找不阻断正常权限编辑。

| 是否同时做查找和只看已勾选？ | 不。只做查找。 |

## 附录：设计指南消费说明

- **U-02（真实世界惯例）** → 交互形态接近Ctrl+F。placeholder用"查找"而非"搜索"——明确语义。
- **U-01（状态可见）** → 所有权限项始终可见。高亮+焦点标记明确当前位置。
- **U-03（用户可控）** → 清空后折叠节点保持展开。查找不影响编辑状态。
- **C-03（减少认知负荷）** → 查找=定位（不改变范围）。tooltip说明"查找不改变权限范围"——防止用户混淆查找和筛选。
- **IA-01（信息气味）** → 高亮让用户一眼看到匹配了什么。不隐藏未命中项——用户可以看到"还有什么没匹配"。
- **反馈原则** → 无命中提示简洁明了。大量命中提示引导缩小范围。
