# 背景与约束

## 项目背景

- 领域：权限管理 > 子管理员模式
- 关联领域：安全管理（操作记录）、成员管理（成员加入与认证状态）
- 客户场景：集团型企业大量子管理员配置，功能权限趋同但组织范围各异

## 关键业务约束

1. 复制入口仅在「子管理员模式」列表操作列
2. 复制来源必须是已有子管理员
3. 复制信息至少选择一项（可授权组织 / 可授权功能）
4. 复制对象至少选择一名用户，最多 200 名
5. 复制对象必须满足加入状态（已加入）和认证状态（已认证）
6. 已有子管理员接收复制时采用「叠加」逻辑，不覆盖原有配置
7. 普通用户接收复制后成为子管理员
8. 复制成功必须生成操作记录
9. 双管理员互审模式下，复制完成时需生成审批（整次操作一条审批，非按人审批）
10. 校验顺序：复制信息勾选 → 复制对象选择 → 加入状态 → 认证状态

## 分析总结收敛

### 复杂度判断：中等复杂度 — 既有能力扩展

- 底层业务骨架不变：不改变权限对象关系、状态机、生效机制、数据口径、外部回写
- 新增能力：批量复制操作、新的权限来源路径（复制来源）
- 显著改变权限管理员的配置任务路径

### 已确认判断

1. 核心体验风险在「复制」语义与「叠加」行为的不一致——对已有子管理员是叠加而非覆盖，需在确认前明示
2. 批量校验需采用全量预检模式，不合格人员一次性展示，避免逐个拦截
3. 复制作为新权限来源，需纳入权限查询页面的来源解释（"复制自 XXX"）
4. 操作记录需增加批次关联，同一次复制的多条记录可追溯
5. 双管理员互审是一次操作级别审批，非按人审批
6. 复制结果反馈不能仅靠 toast，需提供可核对的结果

### 风险与 GAP

- [GAP] 批量校验策略未定：全量预检后统一报 vs 逐个顺序拦截
- [GAP] 双管理员互审驳回后回滚策略未定：整体回滚 vs 整体保留
- [GAP] 复制内容（可授权组织/可授权功能）之间的依赖关系未说明
- [GAP] 部分复制失败场景的处理方式未定（如 200 人中 5 人不合格）
