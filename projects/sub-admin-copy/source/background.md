# Background

## 业务背景

### 子管理员模式

子管理员模式是权限域的核心治理能力之一，允许超级管理员将权限管理能力下放给指定人员。子管理员的权限边界由两部分构成：

- **组织管辖范围**：子管理员可以管理哪些组织范围内的用户
- **应用管辖范围（可授权功能）**：子管理员可以对哪些功能进行授权操作

子管理员只能在其组织管辖范围内，对其应用管辖范围中的功能进行授权。这是一种"权限的权限"配置，不是直接配置业务权限。

### 当前痛点

集团型客户（如广西交投 200+ 子管理员）在配置子管理员时，大量子管理员的「可授权功能」完全相同，仅「可授权组织」不同。当前需要逐个手动勾选相同功能权限，纯人工操作，效率低、易出错。

### 相关治理模式

**子管理员模式**与**双管理员互审模式**不可同时开启，但复制操作可能在两种模式下触发不同的生效链路：

- 子管理员模式（无互审）：复制直接生效
- 双管理员互审模式：复制进入审批链路，审批通过后生效

### 双管理员互审规则（来自知识库）

- 双管理员模式下，变更需双方审批后生效
- 关闭双管理员模式本身也需要另一位管理员审批通过后方可关闭
- 治理状态模型：`draft → pending → approved → effective`（或被 `rejected` / `revoked` 终止）

## 已确认的关键决策

与产品确认后的决策：

1. **双管理员互审时机**：开启互审时，复制需审批，审批通过后生效；审批拒绝后复制结果失效，不产生权限变更
2. **部分失败策略**：跳过校验失败的用户，继续处理成功用户；需展示跳过用户清单及原因
3. **去重逻辑**：叠加时自动去重，重复配置项不产生实际变更
4. **加入状态术语**：统一为"已加入企业"
