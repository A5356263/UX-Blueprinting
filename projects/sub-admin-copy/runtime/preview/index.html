轻量业务蓝图

0. 本次关键业务判断

判断：

这次不是底层权限模型重构，而是在既有「按人直授」体系上新增一条批量复用的效率通道。适合按轻量业务蓝图承接——不改决策链骨架，但需要把复制后的来源追溯、叠加策略和审批联动三个关键点收成可执行的业务定案。

主要影响：

  1. 复制操作在来源模型里引入了一条新的权限获取子路径，后续按人查权限时必须能追溯到「从哪个子管理员复制而来」
  2. 叠加不覆盖策略意味着复制后的结果不等于来源配置的镜像，已有子管理员复制后会出现「原有 + 新增」的混合权限集
  3. 双管理员互审如果审批前置且阻塞生效，复制的用户心智会从「即时操作」变成「异步等待」

建议方案：

  • 复制所得权限在来源追溯时标注为「直授（复制来源：子管理员 XXX）」，不新增独立来源枚举
  • 已有子管理员叠加时，重复权限默认去重（静默），仅新增不重复的权限项
  • 双管理员互审审批默认在复制完成后触发（事后审计），不阻塞复制生效；如产品要求审批前置，需整体调整交互流程

本阶段先定清：

  • 复制后的权限来源追溯标签格式
  • 叠加时重复权限的去重策略
  • 双管理员互审的审批时机与生效关系

需要重新判断的信号：

  1. 如果双管理员互审被要求审批前置且阻塞生效——整个交互从同步变异步，需升级为完整业务蓝图
  2. 如果复制来源需要支持「只复制部分组织或部分功能」——需在复制弹窗增加二级选择，功能范围扩展

1. 一句话结论

可以做。在子管理员列表增加「复制」操作，将已配置子管理员的权限信息批量复制给其他用户。建议按「即时复制 + 事后审计」的默认路径推进，双管理员互审视情况补充审批规则。核心要守住的是：复制后的权限必须能追溯到来源、叠加结果必须对用户可解释。

2. 关键业务规则

  • 前提条件： 复制操作的前提是存在至少一个已配置的子管理员作为来源；复制目标必须满足加入状态（已启用）和认证状态（已认证）；这些校验在弹窗确认时按顺序执行，任一失败即阻断
  • 复制内容范围： 复制来源当前拥有的全部可授权组织和全部可授权功能。用户通过勾选控制要复制哪类内容（组织/功能），但不能只复制来源的部分组织或部分功能——这是「复制完整配置」而非「选择性复制」
  • 叠加与去重： 已有子管理员接收复制时，不覆盖原有配置。重复的权限项（同一功能权限、同一组织范围）自动去重，只追加净新增项。去重结果在操作记录中体现为「新增 X 项，已有 Y 项未重复添加」
  • 来源追溯： 复制所得权限在按人查权限时，来源标注为「管理员授予（复制自：XXX/手机号）」，与超管直接授予的权限在来源标签上区分，但同属「直授」大类
  • 操作记录： 按复制内容分别生成两条记录——「复制-可授权组织」和「复制-可授权功能」。记录中明确标注来源子管理员、目标用户列表、本次新增项数。目标超过 5 人时，列表中折叠展示为「XXX 等 N 人」，点击展开完整列表
  • 双管理员互审： 默认审批在复制完成后触发，作为事后审计记录，不阻塞权限生效。如后续产品要求前置审批，需重新评估交互方案并触发升级信号

3. 边界与风险

不能放开的限制：

  • 复制入口只在子管理员模式，不能在成员管理、角色管理等其他入口出现——避免 RISK-001（入口选择困难）
  • 复制目标必须通过加入状态和认证状态两层校验，不能绕过——这是成为子管理员的硬门槛
  • 复制操作不改变子管理员的组织范围 × 应用范围隔离模型——复制后目标用户的授权仍受其自身组织边界约束

最主要的风险：

  1. 来源追溯断裂。 如果复制所得权限在查询时无法区分来源，排障和审计场景就失去了 TR-005 的闭环能力。保护策略：操作记录中持久化复制来源信息，并在权限查询结果中展示来源标签
  2. 叠加结果不可解释。 已有子管理员复制后，权限集变成「原有 + 新增」的混合体，如果界面不区分展示，用户无法判断哪些是这次复制加进去的。保护策略：复制结果在 toast 之外提供简要的结果摘要（新增 X 项，已有 Y 项），操作记录中保留完整明细
  3. 批量操作误配放大。 200 人批量复制，如果来源配置有误，影响面会迅速扩大。保护策略：确认前展示复制预览（来源、复制内容、目标人数），给用户最后一次核对机会

4. 体验承接要求

角色：

  • 权限管理员 / 超级管理员：复制操作的发起者，需要清晰的流程引导和结果反馈
  • 复制目标用户：被动接收权限，不参与交互，但需在权限查询时能看到新的权限来源说明

流程：

  • 必须闭环的主流程：列表点击复制 → 弹窗选择复制内容 → 选择目标用户 → 确认校验 → 执行复制 → 结果反馈
  • 流程中间不能有静默跳转或状态丢失，弹窗关闭后应有二次确认

进度与结果状态：

  • 复制操作是同步执行（无互审时），结果即时反馈：成功/部分成功/失败
  • 若有互审且审批前置（升级场景），需展示「已提交审批，通过后生效」的中间态

异常：

  • 必须处理的异常：复制信息未选、复制对象为空、目标加入状态不符、目标认证状态不符、全部目标校验失败
  • 部分目标校验失败时，建议「列出失败项 + 允许移除后继续」，而非全量阻断——这更符合批量操作的心智

反馈：

  • 成功：toast「复制成功」+ 简要结果摘要（「已将 XXX 的可授权组织/功能复制给 N 人」）
  • 校验失败：在弹窗内标注失败用户及原因，不关闭弹窗，允许用户调整后重试
  • 部分成功（如有）：需明确告知成功 N 人、失败 M 人及失败原因

文案：

  • 弹窗标题：「复制子管理员权限」
  • 复制信息说明：需解释清楚「复制的是来源当前拥有的全部可授权组织/可授权功能」
  • 叠加说明：对已有子管理员，需在界面上说明「不会覆盖其已有权限，仅追加新权限」
  • 报错文案沿用需求文档第 7 节的指定文案，不自行改写

5. 升级信号

  • 出现以下变化时，应停止当前轻量执行并请求 UXB 重新判断：
  • 双管理员互审被要求审批前置且阻塞复制生效——交互从同步变异步，需完整业务蓝图
  • 复制来源需要支持选择「部分组织」或「部分功能」——功能范围显著扩展
  • 复制目标需要支持跨企业或跨管理域——超出当前子管理员隔离模型
  • 复制操作需要支持定时生效或条件触发——引入新的生效机制

6. 待确认问题

影响方案完整性的问题（建议优先确认）

  • 双管理员互审的审批时机： 审批在复制前还是后？如果前置且阻塞生效，当前「即时复制」方案需要整体调整。建议确认方：产品
  • 校验失败的处理策略： 全部阻断还是跳过失败项继续？当前建议采用「列出失败项 + 允许移除后继续」。建议确认方：产品
  • 加入状态口径统一： 「已启用」和「已加入」到底用哪个？影响校验文案。建议确认方：产品

影响局部策略的问题

  • 复制目标权限上限处理： 达到上限时如何处理？需确认是否存在上限规则。建议确认方：产品 + 研发
  • 是否支持只复制部分组织或功能： 当前按完整配置处理，如后续需要选择性复制需升级。建议确认方：产品
  • 埋点统计需求： 是否需要在复制入口、成功、失败等节点埋点？建议确认方：产品 + 数据

体验蓝图

0. 本次关键设计判断

判断：

这次体验方案的核心不是多做页面，而是把「复制」这个看似简单的操作中的异常分支、语义张力和结果可解释性处理好。重点在弹窗内的校验反馈、复制结果摘要和来源追溯标签三个体验落点上。

主要影响：

  1. 弹窗是唯一的交互载体，复制信息选择、目标选择、校验、确认、结果反馈全部在这个弹窗内完成——弹窗的信息架构和状态切换是体验成败的关键

2.「复制」操作名和「叠加不覆盖」行为之间存在语义差——如果不前置解释，已有子管理员的管理者会困惑为什么复制后的结果和来源不一样

  1. 批量复制 200 人的校验失败反馈决定了操作效率的上限——如果因 1 人失败而全量阻断，体验会很差

建议方案：

  • 复制弹窗采用单页表单结构，不做步骤条——选择复制内容和选择目标之间没有强依赖，不需要分步
  • 校验失败时标注失败用户及原因，允许移除后继续，不全部阻断
  • 已有子管理员在复制对象中时，前置展示「已是子管理员，将叠加权限」的标签说明

不建议方案：

  • 不把复制弹窗拆成步骤条——两步之间无强依赖，分步反而降低效率
  • 不在弹窗内展示复制来源的完整权限明细——信息过载，应该用摘要替代
  • 不把双管理员互审的审批状态放在复制弹窗内处理——审批是复制后的独立流程

关键待确认：

  1. 校验失败是全部阻断还是跳过失败项继续——直接影响弹窗内的校验反馈交互和结果展示结构
  2. 双管理员互审的审批时机——如果审批前置且阻塞生效，复制结果反馈需要从「复制成功」改为「已提交审批」

1. 旅程图

权限管理员
查看子管理员列表→识别需要复制的来源子管理员→发起复制→选择复制内容→选择目标用户→确认并校验→查看复制结果→确认操作记录可查

旅程缺口

  • 缺少复制失败后的重试入口——当前方案中操作记录只记录成功结果，失败情况没有统一聚合视图
  • 缺少复制来源权限的预览——用户在发起复制前无法快速确认来源子管理员当前拥有哪些权限，只能凭记忆操作

2. 交互流程总览

权限管理员
子管理员列表→节点 3.1：发起复制→节点 3.2：配置复制信息→节点 3.3：选择复制目标→节点 3.4：确认并校验→节点 3.5：查看复制结果
系统
接收复制请求→顺序校验→执行复制→生成操作记录→（如有互审）生成审批

异常流程重点：

  • 复制信息未勾选——弹窗内阻断，提示「请选择复制信息」
  • 复制对象为空——弹窗内阻断，提示「请选择至少一名复制对象」
  • 目标加入状态或认证状态不符——弹窗内标注失败用户及原因，允许移除后重试
  • 员工选择弹窗数据加载失败——弹窗内提示加载失败，提供重试入口
  • 全部目标校验失败——弹窗内展示失败列表，确认按钮不可用

3. 主交互流程

节点 3.1：在子管理员列表发起复制

用户动作：

权限管理员在子管理员模式列表中，找到目标来源子管理员，点击其操作列的「复制」按钮。

系统反馈：

打开「复制子管理员权限」弹窗，弹窗内默认全选「可授权组织」和「可授权功能」，复制对象为空。

需要前置解释的信息：

「复制」会将该子管理员当前拥有的全部可授权组织/可授权功能复制给目标用户。如果只想复制其中一部分，当前版本不支持——建议在弹窗顶部用一句轻提示说明。

建议文案：

弹窗顶部提示：「将【来源子管理员姓名/手机号】当前的全部可授权组织和可授权功能复制给其他用户」

下一步：

用户在弹窗内继续配置（节点 3.2）。

节点 3.2：配置复制信息

用户动作：

用户在「复制信息」区域勾选或取消勾选「可授权组织」和「可授权功能」。至少保留一项。

系统反馈：

两个复选框默认选中。用户取消全部勾选时，复选框为未选中状态，不主动报错（等到确认时才校验）。

需要前置解释的信息：

如果只勾选「可授权组织」，则仅复制组织范围，不改变目标的功能权限。反之亦然。这个区分应该通过复选框标签旁的简短说明传达。

建议文案：

  • 复选框标签：「可授权组织」/「可授权功能」
  • 辅助说明（标签旁）：「复制来源拥有的全部可授权组织」「复制来源拥有的全部可授权功能」

下一步：

用户继续选择复制目标（节点 3.3）。

节点 3.3：选择复制目标

用户动作：

用户点击复制对象选择器，打开「选择员工」弹窗。在弹窗中搜索、筛选并勾选目标用户，确认后回填至复制对象输入框。用户可再次编辑（增删目标）。

系统反馈：

  • 选择器提示语：「最多可以复制给 200 名用户」
  • 选择员工弹窗仅展示加入状态为「已启用」且认证状态为「已认证」的员工
  • 已选用户展示在输入框中，每个用户以标签形式呈现，支持逐个删除
  • 如果用户选择了已有子管理员，标签上增加「已是子管理员」标记，hover 时展示 tooltip：「复制后将在此基础上叠加新权限，不会覆盖已有配置」

需要前置解释的信息：

  • 已有子管理员的叠加逻辑——这是和「复制」字面义最大的差异点，必须在目标选择阶段就让用户感知
  • 最多 200 人的限制

建议文案：

  • 选择器 placeholder：「请选择复制对象」
  • 已有子管理员标签 tooltip：「该用户已是子管理员，复制后将在其现有权限基础上叠加，不会覆盖」
  • 超限提示：「最多可选择 200 名用户」

下一步：

用户确认配置，点击「确认」按钮（节点 3.4）。

节点 3.4：确认并校验

用户动作：

用户点击弹窗底部的「确认」按钮。

系统反馈：

按顺序执行四层校验：
1. 复制信息未勾选 → 弹窗内提示「请选择复制信息」，焦点回到复制信息区，不关闭弹窗
2. 复制对象为空 → 弹窗内提示「请选择至少一名复制对象」，焦点回到选择器，不关闭弹窗
3. 目标加入状态不符 → 弹窗内提示「XXX、XXX 加入状态不是已加入，不能成为子管理员」，在目标列表中标注失败用户，不关闭弹窗
4. 目标认证状态不符 → 弹窗内提示「XXX、XXX 未完成实名认证，不能成为子管理员」，在目标列表中标注失败用户，不关闭弹窗
校验全部通过后，展示确认前摘要（复制来源、复制内容、目标人数），用户再次确认后执行复制。

需要前置解释的信息：

校验失败的用户不会影响其他合格用户的复制——这是当前建议策略，若产品决定全量阻断，交互需调整。

建议文案：

  • 确认前摘要标题：「确认复制」
  • 摘要内容：「将【来源姓名】的“可授权组织”和“可授权功能”复制给 N 名用户」
  • 确认按钮：「确认复制」
  • 取消按钮：「取消」

下一步：

确认后执行复制，进入结果反馈（节点 3.5）。

节点 3.5：查看复制结果

用户动作：

用户查看复制结果反馈。

系统反馈：

  • 全部成功：弹窗关闭，toast「复制成功」，下方显示简要摘要「已将【来源姓名】的可授权组织和可授权功能复制给 N 人」
  • 如有互审且审批后置：toast 后追加「已生成审批记录」
  • 操作记录同步生成，可在操作记录页面查看

建议文案：

  • Toast：「复制成功」
  • Toast 副文：「已将【来源姓名】的可授权组织/功能复制给 N 人」

下一步：

用户返回子管理员列表，可看到新子管理员出现在列表中（如有新增）。

4. 次交互流程

节点 4.1：在选择员工弹窗中筛选目标

用户动作：

在选择员工弹窗中，通过搜索框输入姓名或手机号筛选员工，勾选目标用户。

系统反馈：

搜索结果实时刷新，仅展示符合条件的员工（已启用 + 已认证）。已选用户以勾选状态标记。底部展示已选计数。

下一步：

点击弹窗底部「确认」按钮，回填至复制对象输入框。

节点 4.2：编辑已选复制对象

用户动作：

在复制对象输入框中，点击某个用户标签的删除按钮移除该用户；或再次点击选择器打开员工弹窗追加用户。

系统反馈：

标签实时更新。已有子管理员的标签始终保持「已是子管理员」标记。移除或追加后计数更新。

下一步：

继续编辑或点击「确认」提交。

节点 4.3：在操作记录中查看复制记录

用户动作：

权限管理员在操作记录页面，按「子管理员模式」功能筛选，找到复制操作记录。

系统反馈：

按复制内容分别展示两条记录：「复制-可授权组织」和「复制-可授权功能」。每条记录展示操作者、来源子管理员、目标用户列表（超过 5 人时折叠为「XXX 等 N 人」，点击展开）。记录中标注本次新增项数。

建议文案：

  • 操作：「复制-可授权组织」/「复制-可授权功能」
  • 操作内容：「将子管理员【XXX/手机号】可授权组织复制给【XXX/手机号】等 N 人（新增 X 项）」

下一步：

点击展开查看完整目标列表。

5. 异常与阻断流程

异常 1：复制信息未勾选

发生时机： 用户点击「确认」按钮时
触发条件： 复制信息的两个复选框均未勾选
判断依据： 需求文档第 7 节，校验规则第一条
反馈形式： 弹窗内顶部提示
系统反馈： 「请选择复制信息」
用户下一步： 至少勾选一项后重新点击确认

异常 2：复制对象为空

发生时机： 用户点击「确认」按钮时
触发条件： 复制对象选择器为空
判断依据： 需求文档第 7 节，校验规则第二条
反馈形式： 弹窗内选择器下方提示
系统反馈： 「请选择至少一名复制对象」
用户下一步： 至少选择一名用户后重新点击确认

异常 3：目标加入状态不符

发生时机： 用户点击「确认」按钮时
触发条件： 部分或全部目标的加入状态不是「已启用」
判断依据： 需求文档第 7 节，校验规则第三条
反馈形式： 弹窗内目标列表中标注，并在列表上方展示汇总提示
系统反馈： 「XXX、XXX 加入状态不是已加入，不能成为子管理员」；失败用户在列表中高亮标注
用户下一步： 移除失败用户后重新点击确认，或关闭弹窗放弃本次操作

异常 4：目标认证状态不符

发生时机： 用户点击「确认」按钮时
触发条件： 部分或全部目标未完成实名认证
判断依据： 需求文档第 7 节，校验规则第四条
反馈形式： 弹窗内目标列表中标注，并在列表上方展示汇总提示
系统反馈： 「XXX、XXX 未完成实名认证，不能成为子管理员」；失败用户在列表中高亮标注
用户下一步： 移除失败用户后重新点击确认，或关闭弹窗放弃本次操作

异常 5：员工选择弹窗数据加载失败

发生时机： 打开员工选择弹窗时
触发条件： 员工数据接口异常或超时
判断依据： 来自体验风险模式 RISK-005（跨模块散落），员工选择器依赖独立的员工数据服务
反馈形式： 员工选择弹窗内空状态
系统反馈： 「员工数据加载失败，请重试」；提供「重试」按钮
用户下一步： 点击重试或关闭弹窗稍后再试

异常 6：全部目标校验失败

发生时机： 用户点击「确认」按钮后
触发条件： 所有复制目标均不满足加入状态或认证状态要求
判断依据： 来自体验风险模式 RISK-007（批量操作安全风险）
反馈形式： 弹窗内展示失败列表，「确认」按钮置灰不可用
系统反馈： 「所有选中用户均不满足成为子管理员的条件，无法复制」
用户下一步： 关闭弹窗，重新选择符合条件的用户

异常 7：复制来源在操作过程中被删除或变更

发生时机： 用户在弹窗中配置时，来源子管理员被其他管理员删除或权限被修改
触发条件： 并发操作导致来源数据变化
判断依据： 来自业务常识——弹窗期间数据可能变化
反馈形式： 弹窗关闭 + toast 提示
系统反馈： 「复制来源已发生变化，请重新发起复制」
用户下一步： 回到列表刷新后重新操作

6. 页面 / 弹窗 / 抽屉设计

复制弹窗：「复制子管理员权限」

页面目标： 让权限管理员在单一弹窗内完成从选择复制内容、选择目标用户、校验到确认的全流程。

进入条件： 在子管理员模式列表中点击某个子管理员操作列的「复制」。

页面结构：

+---------------------------------------------------------+
| 复制子管理员权限 [X] |
+---------------------------------------------------------+
| 提示：将【来源姓名/手机号】当前的全部可授权组织和 |
| 可授权功能复制给其他用户 |
+---------------------------------------------------------+
| 复制信息 |
| [x] 可授权组织 复制来源拥有的全部可授权组织 |
| [x] 可授权功能 复制来源拥有的全部可授权功能 |
+---------------------------------------------------------+
| 复制对象 |
| [用户标签A ×] [用户标签B(已是子管理员) ×] [用户标签C ×] |
| [点击选择复制对象] 最多可以复制给 200 名用户 |
| |
| [校验失败提示区：标注失败用户及原因] |
+---------------------------------------------------------+
| [取消] [确认复制] |
+---------------------------------------------------------+

状态反馈区： 校验失败提示位于复制对象选择器下方，列出失败用户名和原因。

异常状态下的结构变化：

  • 校验失败时：失败用户在标签区高亮显示（红色边框），标签下方出现失败原因说明。确认按钮保持可用（若有合格用户）或置灰（若全部失败）。
  • 员工选择弹窗加载失败时：弹窗内展示空状态图文和「重试」按钮。

具体文案：

  • 弹窗标题：「复制子管理员权限」
  • 提示文案：「将【XXX/手机号】当前的全部可授权组织和可授权功能复制给其他用户」
  • 确认按钮：「确认复制」
  • 取消按钮：「取消」

按钮： 主要按钮「确认复制」在右侧，次要按钮「取消」在左侧。

成功反馈： 弹窗关闭，toast 「复制成功」+ 副文「已将【XXX】的可授权组织/功能复制给 N 人」。

失败反馈： 弹窗不关闭，校验失败用户在标签区高亮标注，上方展示汇总提示。

员工选择弹窗：「选择员工」

页面目标： 让权限管理员从符合条件的员工中筛选并选择复制目标。

进入条件： 在复制弹窗中点击复制对象选择器。

页面结构：

+---------------------------------------------------------+
| 选择员工 [X] |
+---------------------------------------------------------+
| [搜索框：输入姓名或手机号搜索] |
+---------------------------------------------------------+
| 组织架构树 | 员工列表 |
| [组织A] | [x] 员工A 138****0000 |
| [部门1] | [x] 员工B 139****0000 |
| [部门2] | [ ] 员工C 137****0000 |
| [组织B] | [ ] 员工D 136****0000 |
+---------------------------------------------------------+
| 已选 N 人 [确认] [取消] |
+---------------------------------------------------------+

状态反馈区： 底部已选计数实时更新。

异常状态下的结构变化：

  • 数据加载失败时：员工列表区展示空状态「员工数据加载失败，请重试」和「重试」按钮。组织架构树保持可用（若已加载成功）。
  • 搜索无结果时：员工列表区展示空状态「未找到匹配的员工」。

具体文案：

  • 弹窗标题：「选择员工」
  • 搜索框 placeholder：「输入姓名或手机号搜索」
  • 空状态-无结果：「未找到匹配的员工」
  • 空状态-加载失败：「员工数据加载失败，请重试」
  • 确认按钮：「确认」
  • 取消按钮：「取消」

按钮： 「确认」为主按钮，「取消」为次按钮。底部实时展示已选计数。

原有页面：子管理员模式列表

页面目标： 在原列表中增加复制入口，不改变列表的原有结构和功能。

进入条件： 权限管理员进入子管理员模式页面。

页面结构变化： 在每条子管理员记录的操作列最左侧增加「复制」操作项。

具体文案： 操作项文案：「复制」

按钮： 「复制」为操作列中的文字链接或图标按钮，与「编辑」「删除」等已有操作项保持风格一致。

状态含义适用对象用户可操作统一反馈口径
待配置复制弹窗已打开，等待用户填写权限管理员勾选复制内容、选择目标弹窗就绪，提示来源信息
校验失败复制信息或目标不满足条件权限管理员修正配置后重试「请选择复制信息」/「请选择至少一名复制对象」/「XXX 不满足条件，不能成为子管理员」
全部校验失败所有目标均不满足条件权限管理员关闭弹窗，重新选择「所有选中用户均不满足成为子管理员的条件，无法复制」
确认中校验通过，用户已点击确认系统等待系统执行确认按钮 loading 态
复制成功复制已执行，权限已生效权限管理员 / 目标用户关闭弹窗，查看列表或操作记录「复制成功」+ 摘要
审批中复制已完成，互审批正在流转权限管理员查看审批进度「已生成审批记录」（若审批后置）
来源已变化复制来源在操作中被删除或修改权限管理员关闭弹窗，回到列表刷新「复制来源已发生变化，请重新发起复制」

8. 待确认问题

影响交互方案的关键问题

  1. 校验失败是全部阻断还是跳过失败项继续？

影响：决定弹窗内校验失败的交互模式——如果全阻断，只需展示失败列表 + 禁用确认按钮；如果跳过继续，需要展示「N 人将跳过」+ 确认后部分成功的结果摘要。
建议确认方：产品

  1. 双管理员互审的审批在复制前还是后生效？

影响：决定复制结果反馈的文案和时机——后置则 toast「复制成功」即可；前置则需展示「已提交审批，通过后生效」的中间态，且需考虑审批拒绝后的回滚交互。
建议确认方：产品

  1. 「加入状态」口径最终用「已启用」还是「已加入」？

影响：校验失败提示文案和员工筛选条件的一致性。
建议确认方：产品

影响细节策略的问题

  1. 操作记录中多复制对象时是否需要折叠展示？

影响：当前建议超过 5 人折叠为「XXX 等 N 人」，需确认折叠阈值和展开交互。
建议确认方：产品

  1. 是否需要埋点统计复制入口点击、成功率和复制对象人数？

影响：如需要，需在弹窗确认按钮、成功 toast、失败节点等关键位置预留埋点。
建议确认方：产品 + 数据

  1. 复制结果是否需要展示成功明细（每人复制了哪些权限）？

影响：如果需要在弹窗内或 toast 后展示详细结果，需设计结果明细的展示结构。
建议确认方：产品 + 设计

使用依据转换结果落点
流程模式选择原则——单页长表单优于步骤条复制弹窗采用单页表单 + 分区结构，不分步节点 3.2-3.4，复制弹窗页面结构

反馈与报错——字段级问题贴近字段提示校验失败提示紧贴复制对象选择器下方，不弹独立错误弹窗节点 3.4，异常 1-4
