## 1. 知识定位

这是一份权限域的对象模型卡，用来回答“权限判断链里最小要素有哪些对象、每类对象最低需要哪些属性”。

它适合做模型建模、字段设计和规则解释前的对象对齐。

## 2. 任务触发线索

当任务需要定义权限判断输入、梳理最小数据结构，或把页面事实抽象成主体/资源/动作/范围/来源/状态等对象时，应优先读取本文件。

设计蓝图或排查字段缺口时也会触发阅读。

## 3. 覆盖内容

本文件覆盖权限判断中的基础业务对象，重点包括：

- `subject`：权限结果的承受者或操作者，最小属性含 `subject_id`、`subject_type`、`org_scope`、`role_refs[]`
- `resource`：被访问、查看、配置或操作的对象，最小属性含 `resource_id`、`resource_type`、`parent_resource_id`、`app_id`
- `action`：主体对资源执行的动作，最小属性含 `action_code`、`action_name`、`action_level`
- `scope`：权限最终作用的数据边界，最小属性含 `scope_type`、`scope_expression`、`scope_result`
- `source`：参与解释权限结果的授予来源，最小属性含 `source_enum`、`source_ref`、`source_priority`
- `modifier`：影响生效、责任边界和操作范围的治理修饰因子，最小属性含 `modifier_type`、`modifier_state`、`modifier_ref`
- `state`：权限变更或治理流程当前状态，最小属性含 `state_code`、`effective_flag`、`actor_responsibility`

## 4. 可直接使用的稳定结论

- 权限判断至少涉及主体、资源、动作、范围、来源、修饰因子、状态七类对象。
- `scope`、`source`、`modifier`、`state` 不是附属备注，而是解释权限结果不可缺的结构对象。
- 修饰因子负责影响是否生效、谁能改、谁能继续操作，不等于授予来源本身。
- 状态对象必须能表达当前状态、是否已生效和责任人，否则无法支撑治理解释。
- 业务对象模型是后续决策链、原因码、审计合同的共同底座。
