## 2. facts 摘要

- > 本文基于 `projects/sub-admin-copy/source/requirement.md` 和 `projects/sub-admin-copy/source/background.md` 提炼。原始需求来自 `input/子管理员权限复制/子管理员支持复制_需求文档.md`。
- 当前状态：超级管理员在「子管理员模式」中逐个配置子管理员的可授权组织与可授权功能。子管理员的权限边界由组织管辖范围和应用管辖范围两条线共同决定。
- 痛点：集团型客户（如广西交投 200+ 子管理员）中，大量子管理员的可授权功能完全一致，仅可授权组织不同。目前必须逐个子管理员手动勾选相同功能权限，实施成本高、配置效率低。
- 方案方向：在子管理员列表的操作列新增「复制」能力，允许管理员将某个已配置完成的子管理员的权限信息（可授权组织、可授权功能），批量复制给其他用户。复制对象原本不是子管理员的，复制后成为子管理员；原本已是子管理员的，在原有配置基础上叠加并自动去重。
- 核心涉及角色：
- 权限管理员 / 超级管理员：发起复制操作
- 被复制子管理员：作为权限信息来源
- 复制对象用户：作为权限信息接收方
- **复制入口**：在「子管理员模式」列表的操作列最左侧增加「复制」操作项。仅子管理员行展示该入口，普通用户行不展示。
- **复制弹窗**：点击「复制」后打开弹窗，弹窗分为「复制信息」和「复制对象」两个区域。弹窗样式与现有「添加子管理员」弹窗一致。
- **复制信息选择**：包含「可授权组织」和「可授权功能」两个选项。打开弹窗时默认全部勾选。至少选择一项，支持多选。这是复制的内容范围控制。
- **复制对象选择**：通过用户选择器选择复制目标用户。提示语为"最多可以复制给 200 名用户"。支持多选，最多 200 名。已选用户展示在输入框中，支持再次编辑。点击选择器后打开「选择员工」弹窗。

## 3. business 核心判断与承接要求

### 5. 推荐业务方案
- 权限管理员 / 超级管理员：唯一可发起复制操作的角色。选择复制来源、复制内容、复制对象，确认提交。在互审模式下同时是审批发起人。
- 被复制子管理员：提供权限快照的来源。仅作为信息源，不参与操作流程。
- 复制对象用户：接收权限的目标。可能是普通用户（复制后成为子管理员），也可能是已有子管理员（复制后权限叠加）。在互审模式下不感知审批过程。
- 第一步：管理员在子管理员列表定位到目标来源子管理员，点击操作列的"复制"。
- 第二步：弹窗打开。「复制信息」区域默认勾选可授权组织和可授权功能两项。管理员可取消其中一项，但必须保留至少一项。
- 第三步：管理员通过「复制对象」选择器选择目标用户。选择器点击后打开"选择员工"弹窗（复用添加子管理员的员工选择弹窗），仅展示已加入企业且已认证的员工。支持多选，最多 200 名。已选用户展示在输入框中，支持删除和重新选择。
- 第四步：管理员点击「确认」。系统按顺序执行四项校验：
- 复制信息未勾选 → 阻断，提示"请选择复制信息"
- 复制对象为空 → 阻断，提示"请选择至少一名复制对象"
- 部分用户加入状态不合规 → 不阻断，跳过这些用户
- 部分用户未认证 → 不阻断，跳过这些用户
- 第五步：校验通过的用户执行复制。无互审模式直接生效，有互审模式进入审批。结果反馈给管理员：

### 6. 必须守住的规则和边界
- 不能放开的限制：
- 复制入口仅出现在子管理员行上。普通用户行、非子管理员模式页面不展示。
- 复制信息至少选择一项，不能空提交。
- 复制对象最少 1 名、最多 200 名。
- 未加入企业或未认证的用户自动跳过，且跳过用户必须在结果中显式列出，不能静默忽略。
- 叠加时原配置不覆盖、重复项自动去重。
- 必须审批的场景：
- 系统开启双管理员互审模式时，复制必须走审批链路。审批通过后生效，审批拒绝后作废。不可绕过审批直接生效。
- 必须二次确认的操作：
- 当前方案暂不强制二次确认弹窗。但建议在确认按钮点击后，如果复制对象数量较大（如超过 50 人），走互审模式天然提供了一层审核。无互审模式下的批量复制需产品确认是否额外增加二次确认。
- 必须前置说明的信息：
- 选择器提示语"最多可以复制给 200 名用户"需要始终可见。

### 7. 主要风险与保护策略
- 风险一：批量误操作。管理员可能选错来源或选错目标，一次性将错误权限复制给多达 200 人。
- 真实问题类型：流程设计问题——批量操作缺乏确认关卡。
- 影响：权限错误扩散面大，修正需要逐人回退。
- 缓解：互审模式下审批人可审核复制来源与目标清单，形成第二道关卡。无互审模式下，操作记录可追溯，支持事后审计和回退定位。建议在确认前展示复制来源名称和复制对象数量，让管理员在点击确认前有最后确认机会。
- 风险二：部分成功场景的信息不对称。200 人中 10 人校验失败，管理员如果不仔细看明细，可能遗漏处理失败用户。
- 真实问题类型：反馈形式问题——部分成功的反馈如果不够突出，容易被忽略。
- 影响：被跳过的用户长期未获得应有的子管理员权限，管理员事后需要单独处理，体验差。
- 缓解：弹窗内清晰区分成功区和跳过区。跳过区列出每名用户及具体原因。如果所有用户都跳过，弹窗不关闭，强制管理员关注。
- 风险三：互审审批时效。审批流程中，复制结果处于待生效状态。如果审批人长期不处理，管理员的配置诉求被搁置。
- 真实问题类型：流程设计问题——审批没有超时或催办机制。
- 影响：企业急需配置子管理员权限时被审批卡住。
- 缓解：审批系统层面的催办和超时机制不在本需求范围内，但业务方案需要明确审批记录的可见性——发起人和审批人都能在操作记录/审批记录中查看复制申请的状态。

### 8. 方案承接要求
- 必须覆盖的角色：
- 权限管理员 / 超级管理员（发起复制，是主要操作者，experience 阶段需要覆盖其从列表到弹窗到结果的完整操作路径）
- 被复制子管理员（在列表中作为来源被识别，experience 阶段需要说明如何区分来源行和普通行）
- 复制对象用户（在选择器中被筛选和选择，experience 阶段需要覆盖选择、展示、删除、校验跳过等交互）
- 必须闭环的主流程：
- 子管理员列表（定位来源、点击复制入口）→ 复制弹窗（配置复制信息、选择复制对象）→ 校验（按顺序执行，阻断或跳过）→ 结果反馈（全成功/部分成功/全失败三种分支）→ 操作记录/审批（生效后记录，互审模式进入审批）
- 必须处理的异常：
- 复制信息为空 → 阻断提交 + 提示"请选择复制信息"（experience 需设计阻断态）
- 复制对象为空 → 阻断提交 + 提示"请选择至少一名复制对象"（experience 需设计阻断态）
- 复制对象加入状态不合规 → 跳过 + 提示"XXX、XXX 加入状态不是已加入，不能成为子管理员"（experience 需设计跳过用户清单和原因展示）
- 复制对象未认证 → 跳过 + 提示"XXX、XXX 未完成实名认证，不能成为子管理员"
- 部分成功 → 弹窗展示成功/失败明细（experience 需设计双区展示）

### 9. 待确认问题
- 1. 复制来源权限范围——全量复制还是支持管理员选择来源的部分组织/功能？当前按全量复制设计，如果确认改为部分选择，弹窗需增加组织/功能子选择器，属于中等改动。
- 2. 复制对象权限上限——如果已有子管理员接近或达到系统权限数量上限，叠加时超限如何处理？需产品明确上限规则本身以及超限时的行为（阻断还是截断）。
- 3. 操作记录多对象折叠——当复制对象数量较多时，操作记录中用户列表是否折叠展示？影响操作记录页面的信息密度设计。
- 4. 埋点需求——是否需要埋点统计复制入口点击、复制成功/失败次数、复制对象人数分布等？如需埋点，experience 阶段可配合标注埋点事件。
- 5. 复制对象数量超过 50 人时是否需要二次确认——无互审模式下缺乏审批关卡，批量误操作风险较高。建议由产品确认是否增加二次确认弹窗。
