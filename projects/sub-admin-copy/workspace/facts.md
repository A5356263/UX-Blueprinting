# Facts

> 本文基于 `projects/sub-admin-copy/source/requirement.md` 和 `projects/sub-admin-copy/source/background.md` 提炼。原始需求来自 `input/子管理员权限复制/子管理员支持复制_需求文档.md`。

## 任务概述

当前状态：超级管理员在「子管理员模式」中逐个配置子管理员的可授权组织与可授权功能。子管理员的权限边界由组织管辖范围和应用管辖范围两条线共同决定。

痛点：集团型客户（如广西交投 200+ 子管理员）中，大量子管理员的可授权功能完全一致，仅可授权组织不同。目前必须逐个子管理员手动勾选相同功能权限，实施成本高、配置效率低。

方案方向：在子管理员列表的操作列新增「复制」能力，允许管理员将某个已配置完成的子管理员的权限信息（可授权组织、可授权功能），批量复制给其他用户。复制对象原本不是子管理员的，复制后成为子管理员；原本已是子管理员的，在原有配置基础上叠加并自动去重。

核心涉及角色：
- 权限管理员 / 超级管理员：发起复制操作
- 被复制子管理员：作为权限信息来源
- 复制对象用户：作为权限信息接收方

## 功能范围

**复制入口**：在「子管理员模式」列表的操作列最左侧增加「复制」操作项。仅子管理员行展示该入口，普通用户行不展示。

**复制弹窗**：点击「复制」后打开弹窗，弹窗分为「复制信息」和「复制对象」两个区域。弹窗样式与现有「添加子管理员」弹窗一致。

**复制信息选择**：包含「可授权组织」和「可授权功能」两个选项。打开弹窗时默认全部勾选。至少选择一项，支持多选。这是复制的内容范围控制。

**复制对象选择**：通过用户选择器选择复制目标用户。提示语为"最多可以复制给 200 名用户"。支持多选，最多 200 名。已选用户展示在输入框中，支持再次编辑。点击选择器后打开「选择员工」弹窗。

**选择员工弹窗**：样式与「添加子管理员」弹窗一致。仅展示加入状态为「已加入企业」且认证状态为「已认证」的员工。不满足条件的员工不出现。

**复制校验**：点击确认按钮时按顺序执行四项校验。校验一：复制信息是否已勾选，未勾选阻断并提示"请选择复制信息"。校验二：复制对象是否已选择，未选择阻断并提示"请选择至少一名复制对象"。校验三：复制对象的加入状态是否均为已加入企业，不满足的用户被跳过并提示具体用户名及原因。校验四：复制对象的认证状态是否均为已认证，不满足的用户被跳过并提示具体用户名及原因。

校验三和校验四不阻断整体操作，仅跳过不满足条件的用户，满足条件的用户继续复制。校验一和校验二阻断操作，用户修正后重新提交。

**复制结果反馈**：全部成功时 toast 提示已成功复制给 N 名用户。部分成功时弹窗内展示成功/失败明细，包含跳过用户及原因。全部失败时弹窗内展示失败用户及原因，弹窗不关闭。

**操作记录**：复制成功后生成操作记录。文案格式为"将子管理员【XXX/手机号】可授权组织复制给【XXX/手机号】..."和"将子管理员【XXX/手机号】可授权功能复制给【XXX/手机号】..."。可授权组织和可授权功能分别生成记录，每条记录包含功能、操作、操作对象、操作内容字段。

**双管理员互审**：系统开启双管理员互审模式时，复制操作触发审批，审批通过后复制结果方可生效。审批通过前，复制结果暂不生效。审批拒绝后，复制结果失效，不产生权限变更。复制可授权组织和可授权功能合并生成一条审批。审批记录包含复制来源、复制对象清单、复制内容。

## 关键业务规则

**复制信息必须至少选一项**：可授权组织和可授权功能至少勾选一个。这是弹窗内部校验的第一道，未勾选时直接阻断提交。

**复制对象数量限制**：至少选择 1 名、最多选择 200 名用户。选择器内仅展示已加入企业且已认证的员工。

**校验顺序固定**：复制信息校验 → 复制对象校验 → 加入状态校验 → 认证状态校验。前两项不通过阻断整个操作，后两项不通过仅跳过特定用户。

**新用户成为子管理员**：复制对象原本不是子管理员时，复制成功后该用户成为子管理员，获得被复制的可授权组织或可授权功能。

**已有子管理员叠加**：复制对象原本已是子管理员时，在原有配置基础上叠加被复制的可授权组织或可授权功能。不覆盖原有配置。

**自动去重**：叠加时，如果复制对象已有的配置项与被复制内容重复，自动去重不产生重复项。去重以配置项为单位，不是以整体权限为单位。

**双管理员互审生效链路**：开启互审模式时，复制进入审批流程。审批通过后复制结果才生效。审批拒绝后，复制结果作废且不可自动恢复。关闭互审模式时，复制直接生效。

**操作记录生成**：复制成功（指权限实际生效）后，为可授权组织和可授权功能分别生成一条操作记录。如果只复制了其中一项，则只生成对应的一条记录。

## 状态流转

**复制操作的状态流转（无互审模式）**：
- 用户点击「复制」→ 弹窗打开，复制信息和复制对象处于初始状态
- 用户选择复制信息、选择复制对象 → 弹窗内配置完成
- 用户点击「确认」→ 系统按顺序执行四项校验
- 全部校验通过 → 复制生效，toast 提示成功，弹窗关闭
- 部分校验不通过 → 跳过失败用户，成功用户复制生效，弹窗展示明细
- 全部校验不通过（仅校验三和四场景）→ 弹窗展示失败明细，不关闭

**复制操作的状态流转（双管理员互审模式）**：
- 用户点击「复制」→ 弹窗打开，配置过程同上
- 用户点击「确认」→ 系统按顺序执行校验
- 校验通过的用户 → 复制进入 `pending`（待审批），暂不生效
- 审批通过 → 复制进入 `effective`（已生效），生成操作记录
- 审批拒绝 → 复制进入 `rejected`（已拒绝），结果作废

**复制对象的状态流转**：
- 原本不是子管理员 → 复制生效后成为子管理员
- 原本已是子管理员 → 复制生效后权限范围扩大（叠加），角色不变

## 异常与边界

**校验一触发**：复制信息未勾选任何选项。管理员点击确认时触发阻断。系统反馈"请选择复制信息"。管理员在弹窗内修正后重新提交即可。

**校验二触发**：复制对象为空。管理员点击确认时触发阻断。系统反馈"请选择至少一名复制对象"。管理员需选择至少一名用户后重新提交。

**校验三触发**：部分复制对象的加入状态不是"已加入企业"。被跳过用户会单独列出。系统反馈"XXX、XXX 加入状态不是已加入，不能成为子管理员"。如果所有复制对象都未加入，则全部失败，弹窗不关闭。

**校验四触发**：部分复制对象未完成实名认证。被跳过用户单独列出。系统反馈"XXX、XXX 未完成实名认证，不能成为子管理员"。如果所有复制对象都未认证，则全部失败，弹窗不关闭。

**部分成功场景**：一部分复制对象通过全部校验、一部分被跳过。成功部分立即生效（无互审模式）或进入审批（互审模式）。弹窗内展示成功用户清单、跳过用户清单及跳过原因。操作记录仅对实际生效的复制操作生成。

**复制对象数量超限**：选择超过 200 名用户时，选择器应阻止超出。需求文档只说明"最多 200 名"，但未明确超出时选择器的具体限制方式。[GAP]

**复制对象权限上限**：如果复制对象已达到子管理员可配置的权限上限，叠加复制内容时如何处理，需求文档未明确上限规则和超限处理方式。[GAP]

**双管理员互审未开启但后续开启**：发起复制时互审未开启（复制直接生效），但复制结果生效后互审被开启。此场景下已完成复制的用户不受影响，因为复制结果已经生效。

**被复制来源子管理员被删除或修改**：复制操作是快照式复制还是引用式复制。需求文档未明确。当前默认理解为快照式——复制以来源子管理员当前的权限配置为快照，复制完成后来源的变化不影响已复制的结果。但需产品确认。[GAP]

**网络异常或系统异常**：校验通过后、写入权限数据时发生系统异常。需求文档未描述异常恢复策略。[GAP]

## 依赖与前置条件

**子管理员模式已开启**：复制入口仅出现在子管理员模式开启后的子管理员列表中。如果系统未开启子管理员模式，此功能不可达。

**被复制来源存在**：复制来源必须是已被配置为子管理员的用户。无法对非子管理员执行复制。

**员工数据**：复制对象的数据来自员工花名册，依赖员工管理模块提供加入状态和认证状态。

**双管理员互审配置**：如果系统开启了双管理员互审模式，复制依赖审批中台完成审批流程的配置和发布。审批链路本身的流程设计不在权限域范围内。

**操作记录模块**：复制成功后的操作记录写入依赖操作记录模块的能力。

**权限管理模式页面**：复制入口位于权限管理模式下的子管理员列表页面，依赖现有页面结构和交互框架。

## 开放问题与缺口

1. `[GAP]` 复制来源的权限范围——复制时是复制来源子管理员的完整可授权组织和可授权功能，还是允许管理员在复制时只选择部分组织或部分功能？如果允许部分复制，弹窗需增加组织/功能选择器，影响弹窗结构。

2. `[GAP]` 复制对象权限上限——如果复制对象已接近或达到子管理员权限数量上限，叠加时超限如何处理，需求文档未定义上限规则本身。

3. `[GAP]` 操作记录中多对象的折叠展示——当复制对象数量较多（如 200 人），操作记录中逐个列出所有用户名会导致记录过长。

4. `[GAP]` 埋点需求——是否需要统计复制入口点击、复制成功、复制失败、复制对象人数等数据。

5. `[GAP]` 复制快照还是引用——复制后来源子管理员的权限被修改，已复制的结果是否受影响。默认按快照理解。

6. `[GAP]` 系统异常恢复——校验通过后写入权限数据时发生系统异常，已写入数据是否回滚、未写入数据是否重试。
