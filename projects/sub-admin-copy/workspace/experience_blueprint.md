# 体验蓝图

## 0. 本次关键设计判断

**判断：**

本次体验方案的核心是把「批量操作的不可见性」和「复制语义的认知偏差」这两个风险消化在一个弹窗内——通过全量预检结果区、叠加行为前置说明、以及结构化的执行结果反馈，让权限管理员在提交前就清楚后果、提交后能核对结果。

**主要影响：**

1. 复制弹窗需要承载比普通配置弹窗更多的信息层级——配置区、预检结果区、执行结果区三者要在同一个弹窗内自然流转
2. 「叠加不覆盖」的语义必须在确认前明示，不能让用户带着「复制就是一模一样」的心智提交后才发现问题
3. 操作记录需要在追溯体验上可还原「谁从谁那里复制了什么给哪些人」，不能只是两条孤立记录

**建议方案：**

- 复制弹窗采用单页三段式：配置区（复制信息 + 复制对象）→ 结果区（预检失败清单 或 执行成功汇总）→ 底部确认/关闭按钮。结果区根据当前阶段动态展现
- 已有子管理员在被选为复制对象时，在对象列表中以标签「已有管理范围」标记，并在确认按钮上方固定展示叠加行为说明
- 执行成功后结果区展示汇总数据（共 N 人，新成为子管理员 M 人，叠加权限 K 人），同时 toast 轻提示「复制成功」

**不建议方案：**

- 不做分步向导——复制配置项少、步骤短，分步反而增加操作成本
- 不把预检失败做成 toast 逐个弹——会激怒批量操作用户

**关键待确认：**

1. 复制弹窗是新建弹窗还是复用「添加子管理员」弹窗的容器样式——影响开发成本评估
2. 员工选择器当前是否已支持 200 人选人上限和已选数量展示——若不支持，需要选择器能力先行补齐

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- 权限管理员：识别需复制的子管理员 → 打开复制弹窗 → 确认复制内容 → 选择复制对象 → 提交并等待预检 → 查看预检结果（失败则修正后重试）→ 确认执行复制 → 查看执行结果 → 关闭弹窗 → 在操作记录中可追溯
- 复制对象用户（普通用户）：收到子管理员身份 → 确认新权限生效
- 复制对象用户（已有子管理员）：原有权限不变 → 新增权限叠加生效
- 审批人（双管理员互审模式下）：收到审批 → 判断是否通过 → 驳回时权限整体回滚

### 旅程缺口

- 复制对象用户端缺少权限变更通知机制——当前未定义是否需要通知、通知形式和内容
- 审批驳回后是否通知发起人——当前未定义

## 2. 交互流程总览

**分角色交互流程：**

- 权限管理员：子管理员列表页 → 点击某子管理员操作列的「复制」→ 复制弹窗（配置态）→ 勾选复制内容 → 选择复制对象 → 点击「确认」→ 系统全量预检 → 预检失败：弹窗内结果区展示不合格清单 → 修正对象后重新提交 → 预检通过：弹窗内结果区展示执行成功汇总 → 关闭弹窗回到列表
- 系统：接收复制请求 → 按顺序全量预检（复制信息 → 对象选择 → 加入状态 → 认证状态）→ 全部通过后执行复制 → 生成操作记录（带批次 ID）→ 如开启双管理员互审则生成审批

**异常流程重点：**

- 复制来源子管理员在弹窗打开期间被删除：弹窗顶部 banner 提示，确认按钮置灰
- 所有复制对象均不满足加入/认证条件：结果区展示完整不合格清单
- 双管理员互审审批驳回：已复制权限整体回滚，操作记录中可查回滚标记
- 执行过程中系统异常：toast 提示失败，弹窗保持打开、已选内容保留

## 3. 主交互流程

**节点 3.1：进入复制弹窗**

用户动作：
在子管理员列表页，点击某子管理员操作列最左侧的「复制」按钮。

系统反馈：
打开「复制」弹窗，弹窗标题为「复制子管理员权限」。复制信息区默认全选「可授权组织」和「可授权功能」。复制来源子管理员的姓名/手机号在弹窗顶部信息区固定展示。

需要前置解释的信息：
复制来源子管理员的姓名和手机号，放在弹窗顶部，让用户随时知道自己从谁那里复制。

建议文案：
- 弹窗标题：「复制子管理员权限」
- 来源信息：「复制来源：XXX / 138XXXX8888」

下一步：
用户配置复制内容和选择复制对象。

---

**节点 3.2：选择复制内容**

用户动作：
在复制信息区勾选或取消勾选「可授权组织」「可授权功能」。两项默认全选，至少保留一项。

系统反馈：
取消勾选到仅剩一项时，该项 checkbox 置灰不可取消（保证至少选一项）。两项全选时为正常可操作态。

需要前置解释的信息：
两项的含义：可授权组织 = 该子管理员能管理哪些组织范围；可授权功能 = 该子管理员能操作哪些功能。

建议文案：
- 区域标题：「选择复制内容」
- 选项文案：「可授权组织」「可授权功能」
- 底部提示：「至少选择一项」

下一步：
用户点击「选择复制对象」入口，打开员工选择器。

---

**节点 3.3：选择复制对象**

用户动作：
点击「选择复制对象」按钮，打开员工选择器弹窗（复用「添加子管理员」的选择员工组件）。搜索/筛选后勾选目标用户，确认后返回复制弹窗，已选用户以列表形式展示在复制对象区。

系统反馈：
选择器内已选计数器展示「已选 N/200 人」。达到 200 人时选择器内 checkbox 全部置灰不可继续添加。返回复制弹窗后，复制对象区列表展示已选用户。

已有子管理员在列表中以标签「已有管理范围」标记，并在列表下方固定展示说明文案。

需要前置解释的信息：
- 最多可选 200 人
- 已有子管理员的用户会被标记，复制后不覆盖其原有权限

建议文案：
- 区域标题：「选择复制对象」
- 选择入口按钮：「选择员工」
- 空态提示：「请选择至少一名复制对象」
- 已有子管理员标记：「已有管理范围」
- 叠加说明（列表下方常驻）：「复制对象中标记为「已有管理范围」的用户，复制后将在其原有权限基础上增加所选内容，不会覆盖已有配置」

下一步：
用户点击「确认」按钮，触发全量预检。

---

**节点 3.4：全量预检与结果反馈**

用户动作：
点击弹窗底部「确认」按钮。

系统反馈：
按钮进入 loading 态。系统按顺序全量校验：
1. 复制信息是否至少勾选一项
2. 复制对象是否至少选择一人
3. 逐个检查复制对象的加入状态
4. 逐个检查复制对象的认证状态

校验结果分两种：

**预检失败**：弹窗内容区切换为结果区，展示不合格清单。清单按失败原因分组——「以下成员加入状态不符合」「以下成员未完成实名认证」。每组列出成员姓名和手机号。确认按钮恢复可用。用户可点击成员旁的「移除」将其从复制对象中移除，或关闭弹窗放弃。

**预检通过**：弹窗内容区切换为执行中 loading 态，执行完成后展示成功汇总。

需要前置解释的信息：
- 预检为什么失败——每个失败成员旁边标注具体原因

建议文案：
- 确认按钮 loading：「校验中…」
- 预检失败区标题：「以下 N 名成员不满足条件，请处理后重新提交」
- 加入状态分组标题：「加入状态不符合（未加入/未启用）」
- 认证状态分组标题：「未完成实名认证」
- 成员行操作：「移除」
- 汇总行：「移除全部不合格成员」
- 全部合格通过后 loading：「复制中…」
- 执行成功汇总：
  ```
  复制完成
  共复制给 N 名成员
  其中 M 人新成为子管理员
  K 人已叠加权限
  ```
  （若有双管理员互审）附加：「已生成审批，审批通过后权限生效」

下一步：
预检失败：用户移除不合格成员后重新点击确认。
预检通过 + 执行成功：用户查看汇总后点击「关闭」返回列表。

## 4. 次交互流程

### 节点 4.1：查看操作记录

用户动作：
在管理后台「安全管理 > 操作记录」中，按操作模块筛选「子管理员模式」，找到复制操作对应的记录。

系统反馈：
操作记录列表展示复制操作。一次复制操作对应两条记录（复制-可授权组织、复制-可授权功能），两条记录共享同一批次 ID。点击查看详情可看到完整复制来源和复制对象名单。

建议文案：
- 操作类型：「复制-可授权组织」「复制-可授权功能」
- 操作内容：「将子管理员【XXX/手机号】可授权组织复制给【YYY/手机号】【ZZZ/手机号】…」
- 批次关联：详情中展示「批次 ID：XXXXX」

下一步：
用户可继续查看详情或返回列表。

### 节点 4.2：双管理员互审审批跟进

用户动作：
权限管理员在审批管理中查看复制操作触发的审批单状态。

系统反馈：
审批单展示：发起人、复制来源、复制对象列表、复制内容、提交时间。审批通过后复制权限正式生效。审批驳回后已复制权限自动回滚，操作记录中对应记录增加「已回滚」标记。

建议文案：
- 审批通过后：「审批已通过，权限已生效」
- 审批驳回后：「审批已驳回，权限已收回」

下一步：
审批通过：权限生效，无需额外操作。
审批驳回：发起人可重新发起复制。

## 5. 异常与阻断流程

**异常 5.1：复制来源子管理员在弹窗期间被删除**

发生时机：复制弹窗打开期间。
触发条件：其他管理员并发删除了复制来源子管理员。
判断依据：business_blueprint_lite 边界与风险中的并发保护策略。
反馈形式：弹窗顶部 banner。
系统反馈：「复制来源子管理员已被删除，无法继续复制。请关闭弹窗后重新选择。」
用户下一步：关闭弹窗，返回列表重新选择来源。

**异常 5.2：复制信息未勾选**

发生时机：点击确认按钮时。
触发条件：用户取消勾选了所有复制信息项。
判断依据：facts 规则 3.1，校验顺序第一位。
反馈形式：inline 提示。
系统反馈：复制信息区域下方红色文字：「请至少选择一项复制内容」。
用户下一步：勾选后重新提交。

**异常 5.3：复制对象未选择**

发生时机：点击确认按钮时。
触发条件：复制对象区为空。
判断依据：facts 规则 3.2，校验顺序第二位。
反馈形式：inline 提示。
系统反馈：复制对象区域下方红色文字：「请选择至少一名复制对象」。
用户下一步：点击选择员工并选择后重新提交。

**异常 5.4：部分复制对象不满足加入状态**

发生时机：点击确认后预检阶段。
触发条件：复制对象中有用户的加入状态不为「已加入」。
判断依据：facts 规则 3.3，校验顺序第三位。
反馈形式：弹窗结果区（替换配置区）。
系统反馈：在结果区「加入状态不符合」分组下展示不合格成员名单，格式：「XXX / 138XXXX8888 — 未加入」。
用户下一步：点击不合格成员旁的「移除」将其移出复制对象，或点击「移除全部不合格成员」批量移除，修正后重新提交。

**异常 5.5：部分复制对象不满足认证状态**

发生时机：点击确认后预检阶段。
触发条件：复制对象中有用户未完成实名认证。
判断依据：facts 规则 3.4，校验顺序第四位。
反馈形式：弹窗结果区（替换配置区）。
系统反馈：在结果区「未完成实名认证」分组下展示不合格成员名单，格式：「XXX / 138XXXX8888 — 未认证」。
用户下一步：同上，移除不合格成员后重新提交。

**异常 5.6：全部复制对象均不合格**

发生时机：点击确认后预检阶段。
触发条件：所有复制对象都不满足加入状态或认证状态。
判断依据：business_blueprint_lite 边界与风险。
反馈形式：弹窗结果区。
系统反馈：结果区展示完整不合格清单，底部提示「所有复制对象均不满足条件，请重新选择」。
用户下一步：移除全部不合格成员，重新选择复制对象，或关闭弹窗。

**异常 5.7：复制对象超过 200 人**

发生时机：在员工选择器中选择时。
触发条件：已选人数达到 200 人上限后继续尝试勾选。
判断依据：facts 约束，上限 200 名。
反馈形式：选择器内反馈。
系统反馈：达到 200 人时选择器内 checkbox 全部置灰，选择器底部提示「已达到 200 人上限」。
用户下一步：确认当前选择或移除部分成员后重新选择。

**异常 5.8：系统执行失败**

发生时机：预检通过后执行复制时。
触发条件：系统异常导致复制无法完成。
判断依据：business_blueprint_lite 边界与风险中的事务化处理策略。
反馈形式：toast。
系统反馈：toast 提示「复制失败，请重试」。弹窗保持打开，配置内容不丢失。
用户下一步：重试或关闭弹窗稍后再试。

**异常 5.9：双管理员互审审批驳回**

发生时机：复制完成后审批人被驳回时。
触发条件：审批人驳回审批单。
判断依据：business_blueprint_lite 边界与风险策略——驳回后整体回滚。
反馈形式：操作记录状态变更 + 发起人通知（如有通知机制）。
系统反馈：操作记录中对应记录标记「已回滚」。被复制的权限自动收回。
用户下一步：发起人可查看驳回原因后重新发起复制。

## 6. 页面 / 弹窗 / 抽屉设计

### 复制弹窗

页面目标：让权限管理员快速将一个已有子管理员的权限信息批量复制给一个或多个用户。

进入条件：在子管理员列表页操作列点击某子管理员的「复制」按钮。

页面结构：

```
+--------------------------------------------------+
| 顶部信息区                                       |
| 「复制来源：XXX / 138XXXX8888」                  |
+--------------------------------------------------+
| 复制信息区                                       |
| ☑ 可授权组织  ☑ 可授权功能                       |
| 提示：至少选择一项                                |
+--------------------------------------------------+
| 复制对象区                                       |
| [选择员工]      已选 N/200 人                     |
|                                                   |
| 已选用户列表：                                    |
| · YYY / 139XXXX9999                              |
| · ZZZ / 137XXXX8888  [已有管理范围]               |
|                                                   |
| 提示：标记为「已有管理范围」的用户，复制后将      |
| 在其原有权限基础上增加所选内容，不会覆盖已有配置   |
+--------------------------------------------------+
| 结果区（按需展示，替换上方内容区）                |
| 预检失败：不合格清单 + 移除操作                   |
| 执行成功：汇总数据                                |
+--------------------------------------------------+
| 底部区                                           |
| [取消]                              [确认]       |
+--------------------------------------------------+
```

状态反馈区：结果区在预检失败或执行成功时动态展示，替换配置区。预检失败时展示分组的不合格清单。执行成功时展示汇总数据和下一步提示。

异常状态下的结构变化：
- 来源子管理员被删除：顶部信息区变为红色 banner「复制来源子管理员已被删除，无法继续复制」，确认按钮置灰，内容区不变但所有操作不可用
- 复制信息仅剩一项：该项 checkbox 置灰不可取消，底部提示不变
- 复制对象为空：复制对象区展示空态「请选择至少一名复制对象」

具体文案：
- 弹窗标题：「复制子管理员权限」
- 取消按钮：「取消」
- 确认按钮：「确认」

成功反馈：
- 结果区汇总 + toast「复制成功」

失败反馈：
- 预检失败：结果区展示不合格清单
- 系统失败：toast「复制失败，请重试」

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 配置中 | 弹窗已打开，等待用户配置 | 权限管理员 | 勾选复制内容、选择复制对象 | 弹窗正常展示 |
| 校验中 | 点击确认后正在全量预检 | 权限管理员 | 等待（按钮 loading） | 确认按钮显示「校验中…」 |
| 预检未通过 | 部分复制对象不满足加入或认证条件 | 权限管理员 | 移除不合格成员后重新提交，或取消 | 「以下 N 名成员不满足条件，请处理后重新提交」 |
| 执行中 | 预检通过，正在执行复制 | 权限管理员 | 等待 | 「复制中…」 |
| 复制成功 | 复制已完成，权限已生效（或待审批通过后生效） | 权限管理员 | 关闭弹窗 | toast「复制成功」；结果区展示汇总 |
| 互审待审批 | 复制完成但需审批通过后权限才生效 | 权限管理员 + 审批人 | 关闭弹窗，等待审批 | 「已生成审批，审批通过后权限生效」 |
| 审批已驳回 | 审批被驳回，权限已收回 | 权限管理员 | 重新发起复制 | 操作记录中标记「已回滚」 |
| 来源已失效 | 复制来源子管理员在弹窗打开期间被删除 | 权限管理员 | 关闭弹窗 | 「复制来源子管理员已被删除，无法继续复制」 |

## 8. 待确认问题

1. **加入状态统一口径**

   影响：校验失败时的提示文案（「未加入」还是「未启用」），以及操作记录中引用该状态时的表述。
   建议确认方：产品。

2. **双管理员互审驳回后是否需要通知发起人**

   影响：是否需要「权限被收回」的主动通知机制、通知渠道和文案。
   建议确认方：产品。

3. **操作记录「详情」字段是否需要展开复制对象完整名单**

   影响：详情页的信息结构设计。当前标注为「无」，但批量操作场景下展开名单对审计追溯有意义。
   建议确认方：产品 / 安全合规。

4. **员工选择器当前是否支持 200 人上限和已选数量展示**

   影响：如需选择器能力先行补齐，会影响复制弹窗的开发排期。
   建议确认方：技术 / 产品。

5. **复制内容（可授权组织 / 可授权功能）独立勾选时是否允许只复制其中一项**

   影响：如果只复制组织不复制功能，子管理员有管理范围但无操作权限，实际不可用——是否需要在 UI 上提示这种组合的风险。
   建议确认方：产品。

6. **复制对象是否包含复制来源本人**

   影响：选择器是否需要过滤掉来源子管理员自己。
   建议确认方：产品。
