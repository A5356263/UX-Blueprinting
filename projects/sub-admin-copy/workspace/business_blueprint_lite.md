# 轻量业务蓝图

## 0. 本次关键业务判断

**判断：**

本次是既有能力扩展——在子管理员管理能力上新增批量复制操作，不改变底层权限对象、状态机和生效机制，适合按轻量业务蓝图承接。

**主要影响：**

1. 复制引入新的权限来源路径（复制来源），权限查询页面的来源解释模型需要扩展
2. 「叠加」语义是复制能力对已有子管理员的默认行为，需要明确与「覆盖」「去重」的边界
3. 批量操作（最多 200 人）的校验和结果反馈模式，会直接影响体验主方案的结构

**建议方案：**

- 复制对已有子管理员采用「叠加不覆盖」策略：新增的归新增，已有的保持不变，重复功能跳过不重复记录
- 批量校验采用全量预检：一次性校验所有复制对象的加入状态和认证状态，不合格的统一列出，不逐个拦截
- 操作记录以批次 ID 关联同一次复制的多条记录

**本阶段先定清：**

- 「叠加」的准确定义：对已有子管理员，复制来的功能/组织如在原有配置中已存在，跳过不重复记录；不存在的直接新增
- 批量校验的执行模式：全量预检，所有不合格对象一次性返回，修正后重新提交
- 操作记录的批次关联方式：同一复制操作生成的操作记录共享一个批次 ID

**需要重新判断的信号：**

1. 复制需求从「叠加」变成可选的「覆盖 / 叠加」双模式
2. 复制来源从「单个子管理员」扩展为「多个子管理员」
3. 复制对象从「用户」扩展为「角色」或「部门」
4. 双管理员互审模式从「整次操作一条审批」变成「按人审批」

## 1. 一句话结论

可以做。建议以「叠加不覆盖、全量预检、批次关联」三项策略作为本次复制能力的业务基线。当前最关键判断是：复制不应该改变权限系统已有的来源透明性和审计可追溯性，新增路径的同时必须补齐解释和留痕。

## 2. 关键业务规则

**前提条件：**

- 子管理员模式已启用
- 复制来源子管理员存在且未被删除
- 复制对象已存在于企业中

**不适用场景：**

- 复制来源子管理员已被删除或禁用
- 企业未开启子管理员模式
- 所有复制对象均不满足加入状态或认证状态

**核心规则：**

1. 复制信息（可授权组织 / 可授权功能）至少选一项，默认全选
2. 复制对象 1~200 名，通过员工选择器指定
3. 校验顺序：复制信息勾选 → 复制对象选择 → 加入状态 → 认证状态
4. 加入状态口径定为「已加入」（产品需统一当前材料中「已加入」与「已启用」的表述差异）
5. 普通用户：复制后成为子管理员，按复制信息设置可授权功能和组织
6. 已有子管理员：复制后不覆盖原有配置，新增功能/组织直接叠加，已有功能/组织跳过不重复记录
7. 双管理员互审开启时：复制完成后生成一条整次操作审批
8. 复制成功：生成操作记录，可授权组织和可授权功能各一条，共享同一批次 ID
9. 全量预检失败：一次性返回所有不合格对象及原因，用户修正后重新提交

## 3. 边界与风险

**不能放开的限制：**

- 复制入口仅出现在子管理员模式列表，不扩展到其他权限管理页面
- 复制对象必须满足加入状态和认证状态，不允许跳过校验
- 最多 200 名复制对象，不允许突破上限
- 复制来源只能是单个已有子管理员，不支持多来源合并

**最关键的风险与保护策略：**

| 风险 | 保护策略 |
| --- | --- |
| 复制操作未覆盖并发场景（来源子管理员被并发删除） | 确认时对来源子管理员做存在性校验，不存在则阻断并提示 |
| 双管理员互审驳回后权限悬空 | 驳回后整体回滚，已复制的权限自动收回，操作记录中增加回滚标记 |
| 批量操作中部分人因系统故障未执行成功 | 全量预检通过后，执行阶段采用事务化处理：全部成功或全部失败，不出现部分成功 |
| 复制对象超限导致选择器体验崩坏 | 选择器在达到 200 人上限时置灰不可继续添加，并在选择器底部显示「已选 N/200 人」 |

## 4. 体验承接要求

**角色：**

- 权限管理员 / 超级管理员（操作方）
- 子管理员（复制来源，只读展示）
- 复制对象用户（目标，接收权限）

**流程：**

- 子管理员列表 → 点击「复制」→ 打开复制弹窗 → 确认复制信息（默认全选）→ 选择复制对象 → 点击确认 → 全量预检 → 通过则执行复制 → 展示结果 → 关闭弹窗
- 预检不通过：一次性展示不合格对象清单 → 用户可移除不合格对象或取消 → 修正后重新提交

**进度与结果状态：**

- 弹窗待配置态：复制信息默认全选，复制对象为空，确认按钮可用
- 预检中态：点击确认后校验阶段，按钮 loading
- 预检失败态：不合格对象清单展示，确认按钮恢复可用
- 执行成功态：结果反馈区域展示成功概况（共复制 N 人，其中 M 人成为子管理员，K 人叠加权限）
- 双管理员互审等待态：结果反馈区域提示「已生成审批，审批通过后生效」

**异常：**

- 复制来源子管理员不存在：弹窗内顶部 banner 提示，确认按钮置灰
- 复制对象全部不合格：结果反馈区域展示完整不合格清单
- 复制对象部分不合格：仅展示不合格清单，合格的正常执行
- 双管理员互审驳回：原复制的权限自动收回，操作记录中可查回滚记录
- 系统执行失败：toast 提示「复制失败，请重试」，弹窗保持打开、已选内容保留

**反馈：**

- 预检失败用弹窗内结果区域展示，不做额外弹窗叠加
- 执行成功用弹窗内结果区域展示概况 + toast「复制成功」作为辅助通知
- 双管理员互审模式下，弹窗内明确告知「已生成审批，审批通过后权限生效」
- 操作记录中每条记录均携带批次 ID

**文案：**

- 复制信息区域标题：「选择复制内容」
- 复制对象区域标题：「选择复制对象」
- 已有子管理员提示文案：「复制对象中已有子管理员，复制后将在其原有权限基础上增加所选内容，不会覆盖已有配置」
- 预检失败汇总：「以下 N 名成员不满足条件，请处理后重新提交」
- 执行成功汇总：「已成功复制给 N 名成员（其中 M 人新成为子管理员，K 人已叠加权限）」

## 5. 升级信号

- 出现以下变化时，应停止当前轻量执行并请求 UXB 重新判断：
- 复制需要支持「覆盖模式」（替换原有权限而非叠加）
- 复制对象类型从「用户」扩展到「角色」或「组织节点」
- 双管理员互审从操作级审批变为按人审批
- 需要支持复制后的「撤销」或「回滚」独立操作（超出审批驳回回滚范围）
- 复制能力需要与角色模板、自动授权规则产生联动

## 6. 待确认问题

- 「加入状态」口径是「已加入」还是「已启用」，需产品统一并确认校验文案
- 双管理员互审驳回后回滚策略——建议整体回滚，需产品确认
- 操作记录的「详情」字段当前标注为「无」，是否需要在详情中展开复制对象完整名单
- 员工选择器复用「添加子管理员」弹窗的选择器，需确认该组件是否已支持 200 人上限和数量展示
