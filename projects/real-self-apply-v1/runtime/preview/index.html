关键理解

  • 主任务是完成路径、范围和审批流配置并启用；次任务是回顾当前模式说明、查看帮助与退出编辑。
  • 当前模式还是未开启/已开启；启用后会发生什么；如果企业已开启互斥模式会被拦截。
  • 角色/应用范围的定义、后续新增是否自动加入、预设审批流的默认含义。
  • 路径一旦确定会改变员工申请语义；关闭模式时若有在途流程会失败。
  • 选择申请路径 | 进入页面后即可操作 | 单选切换并刷新第二步范围区域 | 决定后续申请语义
  • 选择角色范围 / 应用范围 | 选择路径后可操作 | 打开 P-02 / P-03 或更新“全部范围”状态 | 形成员工可申请范围
  • 修改审批流程 | 第三步可点击 | 打开审批流子页面 | 回写审批流配置
  • 点击启用 / 确认编辑 | 必填配置完成后可点击 | 先校验互斥规则，再给结果反馈 | 成功进入已开启态；失败则阻断并解释
  • 互斥规则与关闭拦截原因：用户把治理限制误判为系统故障
  • 申请路径差异（角色 vs 功能权限）：申请语义混乱，审批难以判断
  • 可申请范围与“后续新增自动加入”策略：员工提交超范围申请，反复失败
  • 帮助文档与了解更多入口：培训成本无法转移到自助解释

状态与反馈

  • 模式未开启触发：企业未启用自助申请权限模式结果：可进入 P-01 配置页
  • 模式设置中触发：进入 P-01 但尚未点击启用结果：可继续启用或返回
  • 模式已开启触发：启用成功结果：员工入口可见
  • 启用失败（互斥拦截）触发：命中 R-01 / EX-01结果：返回配置页继续调整

文案

  • 模式宣传态目标：解释模式价值与结果示例：“员工可自助申请权限，审批通过后系统自动分配权限。”
  • 启用失败目标：解释互斥规则，不让用户误判系统故障示例：“企业已开启「双管理员互审模式」，不能同时开启此模式。”

风险与阻断

  • 选择申请路径进入页面后即可操作。保护策略：在切换时解释角色申请与功能权限申请差异
  • 选择角色范围 / 应用范围选择路径后可操作。保护策略：对“后续新增自动加入”做前置解释
  • 修改审批流程第三步可点击。保护策略：返回时不刷新页面，保持上下文
  • 点击启用 / 确认编辑必填配置完成后可点击。保护策略：必须展示冲突模式名称和处理方向
  • 把互斥规则误解成系统故障用户只看到失败，不知道是治理规则冲突。保护策略：启用失败时显式展示冲突模式名称和处理方向
  • 启用失败（互斥拦截）触发 命中 R-01 / EX-01。影响：返回配置页继续调整

  • 可申请范围与“后续新增自动加入”策略：员工提交超范围申请，反复失败

状态与反馈

  • 模式已开启触发：启用成功结果：员工入口可见
  • 申请审批中触发：员工提交申请后结果：等待审批结果
  • 申请已拒绝 / 未生效触发：审批拒绝或撤回结果：可回到 P-05 重新申请

文案

  • 申请提交成功目标：解释提交成功但尚未生效示例：“申请已提交，待审批通过后生效。”
  • 范围外不可申请目标：解释为什么当前对象不能申请示例：“当前角色不在企业允许的申请范围内，请联系超级管理员调整范围。”

风险与阻断

  • 选择申请类型打开抽屉后可操作。保护策略：清晰区分“申请角色”和“申请功能权限”
  • 选择申请对象并填写原因申请类型选定后可操作。保护策略：对不可申请对象即时阻断并解释
  • 提交申请必填项完成后可点击。保护策略：明确提示“提交后进入审批，不代表已生效”
  • 把提交成功误解成权限已生效“提交”与“生效”时间点被混淆。保护策略：成功反馈固定带出“待审批后生效”
  • 把范围外限制误解成权限异常用户不知道是范围限制还是系统问题。保护策略：在对象选择前展示允许范围，并对范围外对象即时解释
  • 申请已拒绝 / 未生效触发 审批拒绝或撤回。影响：可回到 P-05 重新申请

原则、模式与追踪

  • 承载模式:抽屉
  • TR-03 角色申请要先给可申请范围，再允许提交
  • TR-04 功能权限申请需要说明默认数据权限语义和范围边界

待确认项

  • OQ-03：功能权限申请是否需要额外解释“默认申请所有数据权限”，仍待规则最终确认。
