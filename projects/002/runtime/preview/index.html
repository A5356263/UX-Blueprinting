Business Blueprint

1. 一句话结论

需求成立，值得做。建议将"自助申请权限"作为独立功能模块建设，包含管理端配置、员工端查看和申请、审批端处理三条角色链路。核心风险点在互斥模式校验、在途流程阻断、以及审批规则细则缺口。

2. 需求是否成立

成立。中大型企业中超管集中管理权限的负担真实存在。员工多、流动大，每次变动都要超管操作。支持自助申请和查看能将工作分散到员工端，同时审批链路保留管控。用户调研 10 人中 6 人认为有价值，竞品金蝶已有类似功能。但小企业培训成本高是推广层面的约束——功能适用场景偏向中大型、组织相对稳定的企业。

3. 值不值得做

收益：降低超管集中授权工作量，提升分配效率；员工可自助查看权限减少沟通成本；审批保留管控不失控。成本：开发需新增管理端配置、员工端查看和申请、审批流程对接、申请记录；培训成本可通过页面引导降低。综合判断收益大于成本。

4. 应该做成什么能力形态

推荐独立功能模块。理由：需求包含三角色完整闭环（管理员配置 → 员工申请 → 审批人审批），有独立状态机和互斥规则，对象和流程复杂度足够支撑独立模块。如果嵌入现有流程，互斥校验、范围配置、审批流程会混入现有界面增加认知负担。

备选路径：扩展现有权限管理（在现有流程中增加"允许员工申请"选项，边界易模糊，不推荐）。

5. 推荐业务方案

角色与职责：

  • 超管：开启和配置自助申请权限模式，选择申请方式、配置可申请范围、配置审批流程，可关闭和编辑
  • 员工：查看自己权限（功能权限/数据权限/角色），提交权限申请，查看申请记录，撤销审批中的申请
  • 审批人（预设为组织负责人）：收到待办，同意或拒绝申请

主流程闭环：
1. 超管进入权限管理模式 → 校验互斥 → 配置三步（申请方式/范围/审批）→ 开启 → 模式生效
2. 员工进入个人中心 → 我的权限 → 申请权限 → 填写内容 → 提交 → 审批流程
3. 审批人收到待办 → 同意/拒绝 → 系统自动分配权限
4. 员工查看申请记录跟踪状态

6. 必须守住的规则和边界

  • 与双管理员互审模式、权限变更审批模式互斥，启用和开启时均需校验
  • 关闭模式时存在在途审批流程则阻断关闭
  • 员工只能申请配置范围内的角色或应用，已停用角色不可申请
  • 审批不可绕过，即使超管开启了模式
  • 资金用户、子管理员权限、实名要求等特殊校验在提交时生效
  • 服务人员不展示"我的权限"入口
  • 仅审批中可撤销，已通过/已拒绝/已撤销不可操作

7. 主要风险与保护策略

  • 互斥模式冲突：启用前清晰提示冲突原因，超管知情决策
  • 在途流程阻断关闭：明确告知在途流程数量和涉及审批人，帮助推动处理
  • 申请超出授权范围：前端只展示可申请内容，提交时后端再次校验
  • 培训成本导致使用率低：页面足够直观降低学习门槛，提供帮助文档入口
  • 审批规则不明确 [GAP]：对接审批引擎前需确认多级审批、会签、超时处理规则

8. 方案承接要求

必须覆盖的角色：超管（配置端）、员工（申请端和查看端）、审批人（审批端）

必须闭环的主流程：超管配置（校验→三步设置→开启→已开启状态）、员工申请（查看权限→申请→提交→等待结果）、审批人处理（收到待办→同意/拒绝）

必须处理的异常：互斥模式冲突阻断、在途流程关闭阻断、提交校验失败、空状态

必须解释的状态：模式未启用/设置中/已开启/编辑中，申请审批中/已通过/已拒绝/已撤销，关闭失败

必须保护的风险：互斥冲突、在途阻断、范围约束、特殊身份校验

设计建议：设置页采用步骤式引导降低认知负担，申请抽屉前置说明权限分配规则，空状态引导去申请权限

9. 待确认问题

  • 审批流程具体规则未明确（多级审批、会签、超时处理）
  • 敏感角色和敏感组织是否需要排除
  • 埋点口径和事件清单未提供
  • 操作记录字段和展示方式未明确
  • OA 审批"可发起人去掉"和"默认复核人员风险"含义待确认
  • 帮助文档内容需产品侧补充
  • 权限组件第 2-18 条规则需要文档支持

Experience Blueprint

1. 交互流程总览

本次体验围绕三类用户展开：

超管 / 权限管理员：在权限管理模式中开启并配置"自助申请权限模式"，决定员工能申请什么类型的权限、能申请哪些角色或应用、由谁审批。

员工：在个人中心查看自己当前拥有的权限，在需要时提交权限申请，跟踪申请进度。

审批人：收到审批待办后，同意或拒绝员工的权限申请。

主流程分为三条：

  • 超管配置流程：进入权限管理模式 → 点击立即启用 → 选择申请方式 → 配置可申请范围 → 配置审批流程 → 开启成功
  • 员工申请流程：进入个人中心 → 我的权限 → 申请权限 → 填写申请内容 → 提交申请 → 查看申请记录
  • 审批人审批流程：收到待办 → 同意或拒绝

异常流程重点关注：

  • 互斥模式已开启时不能启用自助申请权限模式
  • 关闭模式时存在在途审批流程，关闭失败
  • 员工提交申请时校验不通过
  • 申请记录的各种状态反馈（审批中、已通过、已拒绝、已撤销）

2. 主交互流程

流程 A：超管开启自助申请权限模式

节点 A1：进入权限管理模式页

用户动作超管进入管理后台的权限管理模式页面，了解"自助申请权限模式"的作用。
系统反馈页面展示说明——员工可自助查询和申请权限，审批通过后系统自动分配权限。
前置解释开启后员工会看到"我的权限"入口；权限申请通过后系统自动分配无需超管手动操作；该模式不能与"双管理员互审模式"和"权限变更审批模式"同时开启。
页面文案`员工可自助申请权限，工作流审批通过后，系统将自动分配权限。`
按钮`立即启用`（主按钮）、`了解更多`（链接按钮，跳转帮助文档）
下一步超管点击"立即启用"。

节点 A2：点击"立即启用"— 互斥校验

用户动作超管点击"立即启用"。
系统反馈校验企业是否已开启互斥模式。未开启时进入设置页（模式此时仍未启用）。已开启时阻断。
异常提示`企业已开启「双管理员互审模式」，不能同时开启此模式。`
下一步通过则进入设置页，阻断则需先关闭互斥模式后重试。

节点 A3：设置页 — 选择申请方式

用户动作超管在设置页第一步选择员工可申请的权限类型。

两个互斥选项："申请角色"和"申请功能权限"。默认选中"申请角色"。
前置解释选择"申请角色"适合主要通过角色授权的企业，申请通过后自动关联角色；选择"申请功能权限"适合主要按应用和功能直接授权的企业，申请通过后自动获得功能权限。此选择决定后续员工申请页面的内容类型。
选项说明```
申请角色：申请通过后，员工将自动关联上申请角色。适合企业主要通过角色授权的场景。
申请功能权限：申请通过后，员工将自动获得对应功能权限。适合企业主要按应用和功能直接授权的场景。
```
下一步进入第二步。

两个互斥选项："申请角色"和"申请功能权限"。默认选中"申请角色"。

节点 A4：设置页 — 配置可申请范围

用户动作根据第一步选择，配置角色范围或应用范围。

选"申请角色"：设置角色范围（全部角色/部分角色），选择"部分角色"时打开弹窗，支持搜索、分页，展示角色名称/说明/状态。设置项"后续新增角色自动加入"默认勾选。

选"申请功能权限"：设置应用范围（全部应用/部分应用），选择"部分应用"时打开弹窗，支持搜索、分页，展示应用名称/终端/启用状态。设置项"后续新增应用自动加入"默认勾选。
前置解释员工只能申请这里配置的范围；已启用和已停用的均在可选范围；新增的自动加入可减少后续维护。
页面文案`请选择允许员工自助申请的角色。未包含在范围内的角色，员工无法提交申请。`
下一步进入第三步。

选"申请角色"：设置角色范围（全部角色/部分角色），选择"部分角色"时打开弹窗，支持搜索、分页，展示角色名称/说明/状态。设置项"后续新增角色自动加入"默认勾选。

选"申请功能权限"：设置应用范围（全部应用/部分应用），选择"部分应用"时打开弹窗，支持搜索、分页，展示应用名称/终端/启用状态。设置项"后续新增应用自动加入"默认勾选。

节点 A5：设置页 — 配置审批流程

用户动作查看或修改审批流程。
系统反馈默认预设审批人为员工所在组织的组织负责人。
前置解释员工提交后进入审批流程，审批通过后系统才分配权限。可点击"修改审批流程"调整。
页面文案`系统已预设「员工申请权限」时的审批流程，默认审批人为员工所在组织的组织负责人。如需调整，可点击修改审批流程。`
下一步点击底部"开启"。

主要操作：修改审批流程（打开子页面）

节点 A6：点击"开启"

用户动作完成配置后点击"开启"。
系统反馈再次校验互斥模式。通过后 toast 提示成功，页面刷新为已开启状态，个人中心增加"我的权限"入口。
成功文案`自助申请权限模式已开启。`
按钮`关闭模式`、`编辑`、`帮助文档`

已开启状态提示：此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。

流程 B：员工查看权限

节点 B1：进入个人中心

用户动作员工进入个人中心。
系统反馈已开启模式的企业用户在"我的企业"下方展示"我的权限"入口。未开启不展示，服务人员不展示。

节点 B2：进入"我的权限"

用户动作员工点击"我的权限"。
系统反馈进入独立页面，包含三个 tab：功能权限（默认选中）、数据权限、角色。

空状态文案：您没有功能权限。 / 您没有数据权限。 / 您没有关联的角色。

流程 C：员工申请权限

节点 C1：点击"申请权限"

用户动作员工点击"申请权限"。
系统反馈打开"申请权限"抽屉。展示申请人（默认当前用户不可编辑）、申请原因（必填，最多 500 字，提示"请填写申请原因"）、申请内容区（根据管理端配置展示角色或功能权限）、提交按钮。

节点 C2：填写申请内容

用户动作选择要申请的权限或角色，填写申请原因。
前置解释员工只能选择配置范围内的内容；申请功能权限时默认申请全部数据权限。

功能权限提示：`提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。`

功能权限提示：提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。

节点 C3：提交申请

用户动作点击"提交"。
系统反馈校验权限后发起审批流程。

成功反馈：`申请已提交，请等待审批。`
失败反馈`当前申请内容不满足授权条件，请调整申请内容后重新提交。`
下一步进入申请记录查看进度。

成功反馈：申请已提交，请等待审批。

节点 C4：查看申请记录

用户动作进入申请记录页。
系统反馈筛选项（申请日期、审批状态：已通过/已拒绝/审批中/已撤销），列表（申请时间、申请原因、申请内容、审批状态、操作）。审批中可撤销，其他状态不可操作。

流程 D：超管编辑已开启模式

点击"编辑"→ 页面进入可编辑状态 → 隐藏"关闭模式"和"编辑"，底部展示"取消编辑"和"确认编辑"→ 确认后 toast 编辑成功。

流程 E：超管关闭模式

点击"关闭模式"→ 二次确认弹窗（标题"关闭模式"，正文"关闭模式后，员工将无法自助查询和申请权限，请确认是否关闭自助申请模式？"，按钮"不关闭"/"确认关闭"）→ 校验在途流程 → 通过则 toast 关闭「自助申请权限模式」成功，不通过则弹窗"关闭失败"。

流程 F：员工查看申请详情

申请记录中点击"查看详情"（仅申请功能权限时出现）→ 静态详情抽屉展示当时提交的权限范围和申请原因。

流程 G：员工撤销申请

审批中状态的申请点击"撤销"→ 状态变更为"已撤销"，撤销按钮消失。

前置解释员工只能申请这里配置的范围；已启用和已停用的均在可选范围；新增的自动加入可减少后续维护。
页面文案`请选择允许员工自助申请的角色。未包含在范围内的角色，员工无法提交申请。`
下一步进入第三步。

选"申请角色"：设置角色范围（全部角色/部分角色），选择"部分角色"时打开弹窗，支持搜索、分页，展示角色名称/说明/状态。设置项"后续新增角色自动加入"默认勾选。

选"申请功能权限"：设置应用范围（全部应用/部分应用），选择"部分应用"时打开弹窗，支持搜索、分页，展示应用名称/终端/启用状态。设置项"后续新增应用自动加入"默认勾选。

节点 A5：设置页 — 配置审批流程

用户动作查看或修改审批流程。
系统反馈默认预设审批人为员工所在组织的组织负责人。
前置解释员工提交后进入审批流程，审批通过后系统才分配权限。可点击"修改审批流程"调整。
页面文案`系统已预设「员工申请权限」时的审批流程，默认审批人为员工所在组织的组织负责人。如需调整，可点击修改审批流程。`
下一步点击底部"开启"。

主要操作：修改审批流程（打开子页面）

节点 A6：点击"开启"

用户动作完成配置后点击"开启"。
系统反馈再次校验互斥模式。通过后 toast 提示成功，页面刷新为已开启状态，个人中心增加"我的权限"入口。
成功文案`自助申请权限模式已开启。`
按钮`关闭模式`、`编辑`、`帮助文档`

已开启状态提示：此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。

流程 B：员工查看权限

节点 B1：进入个人中心

用户动作员工进入个人中心。
系统反馈已开启模式的企业用户在"我的企业"下方展示"我的权限"入口。未开启不展示，服务人员不展示。

节点 B2：进入"我的权限"

用户动作员工点击"我的权限"。
系统反馈进入独立页面，包含三个 tab：功能权限（默认选中）、数据权限、角色。

空状态文案：您没有功能权限。 / 您没有数据权限。 / 您没有关联的角色。

流程 C：员工申请权限

节点 C1：点击"申请权限"

用户动作员工点击"申请权限"。
系统反馈打开"申请权限"抽屉。展示申请人（默认当前用户不可编辑）、申请原因（必填，最多 500 字，提示"请填写申请原因"）、申请内容区（根据管理端配置展示角色或功能权限）、提交按钮。

节点 C2：填写申请内容

用户动作选择要申请的权限或角色，填写申请原因。
前置解释员工只能选择配置范围内的内容；申请功能权限时默认申请全部数据权限。

功能权限提示：`提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。`

功能权限提示：提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。

节点 C3：提交申请

用户动作点击"提交"。
系统反馈校验权限后发起审批流程。

成功反馈：`申请已提交，请等待审批。`
失败反馈`当前申请内容不满足授权条件，请调整申请内容后重新提交。`
下一步进入申请记录查看进度。

成功反馈：申请已提交，请等待审批。

节点 C4：查看申请记录

用户动作进入申请记录页。
系统反馈筛选项（申请日期、审批状态：已通过/已拒绝/审批中/已撤销），列表（申请时间、申请原因、申请内容、审批状态、操作）。审批中可撤销，其他状态不可操作。

流程 D：超管编辑已开启模式

点击"编辑"→ 页面进入可编辑状态 → 隐藏"关闭模式"和"编辑"，底部展示"取消编辑"和"确认编辑"→ 确认后 toast 编辑成功。

流程 E：超管关闭模式

点击"关闭模式"→ 二次确认弹窗（标题"关闭模式"，正文"关闭模式后，员工将无法自助查询和申请权限，请确认是否关闭自助申请模式？"，按钮"不关闭"/"确认关闭"）→ 校验在途流程 → 通过则 toast 关闭「自助申请权限模式」成功，不通过则弹窗"关闭失败"。

流程 F：员工查看申请详情

申请记录中点击"查看详情"（仅申请功能权限时出现）→ 静态详情抽屉展示当时提交的权限范围和申请原因。

流程 G：员工撤销申请

审批中状态的申请点击"撤销"→ 状态变更为"已撤销"，撤销按钮消失。

4. 异常与阻断流程

### 异常 1：互斥模式已开启

发生时机：超管点击"立即启用"或"开启"时。触发条件：企业已开启"双管理员互审模式"或"权限变更审批模式"。系统反馈：企业已开启「双管理员互审模式」，不能同时开启此模式。用户下一步：先关闭互斥模式再重试。

### 异常 2：关闭模式时存在在途审批

发生时机：超管确认关闭模式。触发条件：存在未完成的申请审批流程。弹窗标题"关闭失败"，正文当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。按钮"知道了"。用户下一步：等待审批完成后再关闭。

### 异常 3：提交申请时校验不通过

发生时机：员工点击"提交"。触发条件：资金用户校验、子管理员模式权限校验、实名要求校验、特殊身份默认权限校验不通过。系统反馈：当前申请内容不满足授权条件，请调整申请内容后重新提交。用户下一步：调整申请内容重新提交，无法自行处理则联系管理员。

5. 页面 / 弹窗 / 抽屉设计

□页面：自助申请权限模式介绍页

页面目标：让超管了解该模式并决定是否启用。结构：模式说明区 + 互斥规则提示 + 操作区。文案：员工可自助申请权限，工作流审批通过后，系统将自动分配权限。按钮：立即启用（主）、了解更多（次）。

□页面：自助申请权限模式设置页

页面目标：三步式引导超管完成配置。结构：选择申请方式 → 配置范围 → 配置审批流程 → 底部操作区。按钮：取消、开启（主）、修改审批流程（链接）。成功反馈：自助申请权限模式已开启。失败反馈：企业已开启「双管理员互审模式」，不能同时开启此模式。

□页面：已开启状态页

页面目标：确认模式状态，支持关闭或编辑。提示语：此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。按钮：关闭模式、编辑、帮助文档。

▣弹窗：关闭模式二次确认

标题：关闭模式。正文：关闭模式后，员工将无法自助查询和申请权限，请确认是否关闭自助申请模式？按钮：不关闭 / 确认关闭。

▣弹窗：关闭失败提示

标题：关闭失败。正文：当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。按钮：知道了。

　抽屉：申请权限

页面目标：让员工提交权限申请。结构：申请人（默认当前用户不可编辑）+ 申请原因（必填，500 字上限）+ 申请内容区 + 操作区。按钮：提交（主）、取消。成功反馈：申请已提交，请等待审批。失败反馈：当前申请内容不满足授权条件，请调整后重新提交。

□页面：我的权限

页面目标：展示员工当前权限和角色。结构：三个 tab（功能权限/数据权限/角色，默认功能权限）+ 申请权限入口 + 申请记录入口。空状态：您没有功能权限。 / 您没有数据权限。 / 您没有关联的角色。

□页面：申请记录

页面目标：查看申请进度。结构：筛选区（申请日期、审批状态）+ 列表区 + 分页。审批状态：审批中、已通过、已拒绝、已撤销。操作规则：仅审批中可撤销。

6. 状态与反馈文案

  • 模式未启用：尚未开启，超管可点击"立即启用"进入设置
  • 设置中：已进入设置页但未开启，员工端暂不可见
  • 已开启：`此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。`
  • 审批中：`申请已提交，请等待审批。`员工可撤销
  • 已通过：`申请已通过，权限已生效。`
  • 已拒绝：`申请已拒绝。你可以查看拒绝原因后重新提交申请。`
  • 已撤销：员工主动撤销，不可恢复，需重新提交
  • 关闭失败：`当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。`
