## Pattern 1：三步式配置页的写法

**来源**：`experience_blueprint.md` 流程 A 节点 A3-A5

**适用场景**：管理端有多步配置流程（步与步之间有先后依赖）

**片段**：

```
第一步选择决定第二步内容——选"申请角色"则第二步配角色范围，
选"申请功能权限"则第二步配应用范围。每一步前置解释当前选择
会怎样影响后续。

页面结构：三步标题 + 当前步骤高亮 + 底部"上一步/下一步"导航。
```

**为什么可复用**：多步配置是管理端超高频模式。这个片段提炼的不是具体文案，而是"步骤依赖关系需要前置解释"这个设计原则。

## Pattern 2：空状态文案模板

**来源**：`experience_blueprint.md` 节点 B2

**适用场景**：任何有 tab 切换的数据展示页，tab 下无数据时

**片段**：

```
每个 tab 的空状态文案与 tab 名对应：
- "功能权限" tab 无数据 → "您没有功能权限。"
- "数据权限" tab 无数据 → "您没有数据权限。"
- "角色" tab 无数据 → "您没有关联的角色。"

格式："您没有{tab对应的对象类别}。"
```

**为什么可复用**：空状态文案是通用模式。"您没有XXX"的句式可以直接套用到任何对象类型。

## Pattern 3：阻断型弹窗的写法

**来源**：`experience_blueprint.md` 异常 2

**适用场景**：操作被阻断时，需要告知用户原因但不提供绕过方式

**片段**：

```
弹窗结构：
- 标题：操作结果（如"关闭失败"），不是操作名称
- 正文：阻断原因 + 谁需要做什么才能解除阻断
- 按钮：仅"知道了"，不给绕过入口

文案示例：
"当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。"

关键原则：阻断原因 + 解除条件 + 单一确认按钮（不给绕过）。
```

**为什么可复用**：阻断弹窗是通用错误处理模式。标题/正文/按钮三层结构的写法可直接复用。

## Pattern 4：抽屉型申请表单的写法

**来源**：`experience_blueprint.md` 流程 C 节点 C1-C3

**适用场景**：用户从列表/详情页发起一个轻量操作（申请/提交/编辑），不需要整页跳转

**片段**：

```
抽屉结构：
- 顶部：申请人信息（只读，默认当前用户）
- 中部：操作内容区（根据管理端配置动态展示）
- 底部：操作按钮 + 关键说明

关键说明放在按钮上方，不是顶部：
"提交申请后，默认申请功能的所有数据权限。如需部分数据权限，
请联系企业管理员授权。"

成功反馈（简洁，告知下一步）：
"申请已提交，请等待审批。"

失败反馈（说明原因 + 引导下一步）：
"当前申请内容不满足授权条件，请调整后重新提交。"
```

**为什么可复用**：抽屉型操作是高频模式。关键说明放按钮上方、成功反馈简洁+告知下一步、失败反馈引导修正——这些结构可跨场景复用。
