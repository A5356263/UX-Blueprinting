# Experience Blueprint

## 0. 本次关键设计判断

- **建议方案**：管理端复用现有"权限管理模式"页面的选择框架，新增"员工自助申请模式"选项，进入独立的配置流程（范围 → 审批 → 确认开启）。员工端以"我的权限"为统一入口，查看权限、申请权限、申请记录在同一入口内通过 tab 切换。审批端复用现有审批中台的通知和列表承载，不新建独立的审批工具。
- **不建议方案**：为员工端单独设计一套"权限商店"式的浏览和加购体验。这会让权限申请看起来像电商选购，淡化审批的严肃性，也与管理员"控制范围"的意图不一致——员工看到的是被限定的可选范围，不是自由浏览的全量目录。
- **核心理由**：这个功能的核心体验矛盾是"员工想要权限"和"管理员需要控制"之间的张力。体验方案需要在员工操作顺畅和管控边界清晰之间取得平衡——员工申请路径要短、要看得懂，但安全边界（范围限制、审批卡点、操作记录）也必须被用户感知，不能为了流畅而隐藏控制点。
- **必须确认**：员工端入口最终放在工作台的哪个位置；审批超时阈值是否支持管理员自定义。

## 1. 交互流程总览

本次体验围绕以下角色展开：

- **超级管理员 / 权限管理员**：在管理端进入"权限管理模式"页 → 选择"员工自助申请模式" → 配置可申请范围和审批流 → 开启模式 → 后续可查看状态、修改配置或关闭模式。
- **员工**：在员工端进入"我的权限"入口 → 查看已有权限 → 需要时点击"申请权限" → 从开放范围中选择 → 填写原因 → 提交 → 在"申请记录"tab 追踪状态。
- **审批人**：通过审批通知或审批列表收到待审批申请 → 查看申请详情 → 同意或拒绝 → 同意后系统自动授权。

主流程：

- **管理员开启自助申请模式**：权限管理模式页 → 选择模式 → 配置可申请范围 → 配置审批流 → 确认开启
- **员工查看权限**：进入我的权限 → 查看权限列表（含来源） → 按需进入申请
- **员工申请权限**：我的权限页 → 点击申请权限 → 选择目标 → 填写原因 → 提交 → 看到提交成功
- **审批人处理申请**：审批通知 → 查看详情 → 同意或拒绝 → 结果通知员工
- **管理员关闭模式**：权限管理模式页 → 关闭模式 → 处理进行中申请 → 确认关闭

次流程：

- 管理员修改已生效的配置
- 员工撤销审批中的申请
- 审批人查看申请历史

异常流程重点关注：

- 管理员配置不完整时不允许开启
- 审批流配置无效时拒绝保存
- 员工申请已有权限或重复申请时被拦截
- 审批超时后自动升级到管理员
- 管理员强制关闭模式时审批中申请被批量拒绝
- 员工尝试访问他人数据时被数据层拦截

## 2. 主交互流程

### 管理员侧

**节点 A1：进入权限管理模式页**

用户动作：超管或权限管理员在管理端导航中进入"权限管理"模块，点击"权限管理模式"。

系统反馈：页面展示当前启用的治理模式（如有），以及所有可选模式的列表。每个模式以卡片形式展示，包含模式名称、一句话简介和当前状态标记（"当前启用"或"未启用"）。"员工自助申请模式"作为新增选项出现在列表中。

本节点需要前置解释：模式之间互斥——一次只能启用一种。切换模式前需要先关闭当前模式。这些信息应在页面顶部以说明文字呈现。

建议页面文案：
- 页面标题：权限管理模式
- 页面说明：选择一种权限治理方式。一次只能启用一种模式，切换前需先关闭当前模式。
- 新模式卡片标题：员工自助申请模式
- 新模式卡片简介：允许员工查看自己的权限，并在管理员设定的范围内自助申请权限，审批通过后自动授权。
- 当前未开启任何模式时，页面状态文案：当前未启用权限治理模式。选择一个模式开始配置。

下一步：管理员点击"员工自助申请模式"卡片进入配置流程。

**节点 A2：配置可申请范围**

用户动作：管理员进入模式配置的第一步——"设置可申请范围"。页面左侧展示可被申请的角色和功能权限列表（来自系统已有定义），右侧展示已选中的项目。管理员勾选希望开放给员工申请的角色和功能权限。

系统反馈：列表中的高危权限项（如删除企业、修改安全设置、管理管理员等）带有红色标记和"高危"标签，默认不勾选。管理员将鼠标悬停在标记上时，显示说明"此权限涉及企业安全，不建议开放给员工申请"。管理员勾选或取消勾选时，右侧已选区域实时更新。页面底部显示已选项目数量。

本节点需要前置解释：管理员需要被告知——"未被您勾选的权限和角色，员工将无法看到和申请。请根据企业实际需求选择，避免将高风险权限纳入可申请范围。"

建议页面文案：
- 步骤标题：设置可申请范围
- 左侧列标题：可用权限与角色
- 右侧列标题：已开放申请（共 N 项）
- 高危标记 hover 说明：此操作涉及企业安全，不建议开放给员工申请
- 未勾选任何项时右侧空状态：尚未选择任何权限或角色。请在左侧勾选希望开放给员工的申请项。
- 底部说明：员工只能申请您在此处添加的权限和角色。后续可随时调整。
- 下一步按钮：继续设置审批流程

下一步：管理员点击"继续设置审批流程"进入审批配置。

**节点 A3：配置审批流程**

用户动作：管理员进入配置第二步——"设置审批流程"。选择审批人类型，或对接审批中台配置完整的审批规则。

系统反馈：页面以单选或下拉形式展示审批人类型选项，包括：直属上级、组织负责人、指定人员、自定义审批流（跳转审批中台配置）。每个选项下方有一句话说明该类型的含义。如选择"指定人员"，展开人员选择器；如选择"自定义审批流"，提供跳转审批中台的链接。管理员确认后，系统校验审批规则有效性——如果审批人不存在或链路不完整，页面顶部出现红色提示条，并标注具体的无效项，阻止进入下一步。

本节点需要前置解释：管理员需要知道"审批人将收到员工的权限申请通知。如果审批人岗位变更或离职，请及时更新审批流程配置，避免申请卡死。"

建议页面文案：
- 步骤标题：设置审批流程
- 选项一：直属上级——由申请人的直属上级审批
- 选项二：组织负责人——由申请人所在组织的负责人审批
- 选项三：指定人员——由您指定的具体人员审批
- 选项四：自定义审批流——跳转到审批管理配置详细的审批规则
- 校验失败提示（红色提示条）：审批规则配置不完整——[具体无效项]。请修改后再继续。
- 跳转审批中台链接文字：前往审批管理配置
- 底部说明：审批规则生效后，所有员工提交的权限申请都将按此规则流转。审批人变更时请及时更新配置。
- 返回按钮：上一步
- 下一步按钮：确认并开启

下一步：管理员点击"确认并开启"进入确认页。

**节点 A4：确认并开启模式**

用户动作：管理员在确认页查看已配置的范围摘要和审批规则摘要，确认无误后点击"开启自助申请模式"。

系统反馈：页面展示本次配置的完整摘要——可申请范围（列出已选的权限和角色名称，最多展示 10 条，超过则显示"等共 N 项"）、审批规则（显示审批人类型和具体审批人姓名或规则描述）。管理员点击开启按钮后，如果系统检测到当前已有其他治理模式启用，弹出二次确认弹窗，说明当前模式将被关闭及影响范围。管理员在弹窗中确认后，系统执行切换：关闭旧模式，启用新模式，记录操作日志。开启成功后，页面跳转回模式状态页，显示"员工自助申请模式"标记为"当前启用"，并展示配置摘要和"修改配置"入口。页面顶部出现绿色提示条"自助申请模式已开启，员工现在可以查看权限并发起申请。"

本节点需要前置解释：管理员在开启前需要确认——"开启后，员工将立即可以在员工端看到'我的权限'入口并发起申请。您可以在开启后随时修改配置或关闭模式。"

建议页面文案：
- 确认页标题：确认配置并开启
- 范围摘要标签：可申请范围（共 N 项）
- 审批摘要标签：审批规则
- 开启按钮：开启自助申请模式
- 二次确认弹窗标题：确认切换治理模式
- 弹窗正文：当前已启用"[当前模式名称]"。切换后将关闭该模式。如有进行中的流程，切换操作不影响已提交的审批。确认切换吗？
- 弹窗确认按钮：确认切换
- 弹窗取消按钮：取消
- 开启成功提示条：自助申请模式已开启。员工现在可以查看权限并发起申请。
- 模式状态页操作按钮：修改配置 / 关闭模式

下一步：管理员可查看模式状态、修改配置或关闭模式。员工端同步生效。

### 员工侧

**节点 B1：进入我的权限页**

用户动作：员工在员工端导航或工作台点击"我的权限"入口。

系统反馈：页面加载后展示员工当前拥有的权限列表。权限按应用分组，每个应用下列出该应用内的权限项，每条权限显示名称和来源（如"通过 销售专员 角色获得""管理员直授""自助申请"）。权限来源用不同颜色标签区分。页面顶部显示权限总数概览。如果员工没有任何权限，页面展示空状态说明。

本节点需要前置解释：员工首次进入时需要理解——"这里展示的是您当前拥有的权限。如果缺少需要的权限，可以点击'申请权限'提交申请。"

建议页面文案：
- 页面标题：我的权限
- 权限总数概览文案：共 N 项权限，覆盖 M 个应用
- 权限来源标签：通过 [角色名] 获得 / 管理员直授 / 自助申请
- 空状态标题：暂无权限记录
- 空状态说明：您当前没有分配任何权限。如需使用相关功能，请联系管理员或申请权限。
- 申请权限按钮：申请权限
- Tab 切换：我的权限 | 申请记录

下一步：员工在权限列表中找到目标权限或发现缺失后，点击"申请权限"按钮。

**节点 B2：申请权限——选择目标**

用户动作：员工点击"申请权限"后，进入申请表单。第一步是选择申请目标——从管理员配置的可申请范围中选择权限或角色。

系统反馈：页面展示可申请范围列表，按权限类型（角色 / 功能权限）分两组展示。每组显示可选项的名称和简要说明。如果管理员配置的范围为空（没有任何可选权限），页面展示空状态。员工点击某个权限或角色后，该项高亮选中，底部"继续"按钮激活。如果员工已有某项权限，该项在列表中置灰并标注"已有"。

本节点需要前置解释：员工需要被告知——"以下为企业开放的权限申请范围。请选择您需要的权限或角色。灰色项表示您已拥有。"

建议页面文案：
- 步骤提示：第 1 步，共 2 步——选择权限
- 分类标签：角色 / 功能权限
- 已有权限标记：已有
- 范围为空时的空状态：当前企业未开放任何可申请的权限或角色。如有需要，请联系管理员。
- 继续按钮：继续填写申请原因

下一步：员工选中目标后点击"继续"，进入填写申请原因。

**节点 B3：申请权限——填写原因并提交**

用户动作：员工在第二步中填写申请原因，然后提交申请。

系统反馈：页面展示员工上一步选择的权限或角色（只读展示，可返回修改）。下方为申请原因输入框（必填），placeholder 为"请说明申请这项权限的原因，帮助审批人了解您的需求"。员工填写后点击"提交申请"。提交时系统做两层校验：（1）如果该权限员工已有，阻止提交并提示"您已拥有此权限，无需再次申请"；（2）如果同权限已有审批中的申请，阻止提交并提示"该权限已有审批中的申请，请等待审批结果"。校验通过后，提交成功，页面跳转到"申请记录"tab，系统在页面顶部展示绿色提示条，同时申请单进入审批流。

本节点需要前置解释：提交前让员工知道——"提交后需经审批，审批通过后权限将自动生效。您可以在'申请记录'中查看进度。"

建议页面文案：
- 步骤提示：第 2 步，共 2 步——填写原因
- 已选权限展示标签：申请权限：销售报表查看权限
- 修改选择链接：修改
- 申请原因输入框标签：申请原因
- 输入框 placeholder：请说明申请这项权限的原因，帮助审批人了解您的需求
- 校验提示一：您已拥有此权限，无需再次申请。
- 校验提示二：该权限已有审批中的申请，请等待审批结果。您可在"申请记录"中查看进度。
- 提交按钮：提交申请
- 返回按钮：上一步
- 提交成功提示条：申请已提交，审批通过后权限将自动生效。您可在"申请记录"中查看进度。

下一步：员工跳转到"申请记录"tab 查看刚提交的申请状态。

**节点 B4：查看申请记录**

用户动作：员工在"我的权限"页切换至"申请记录"tab，查看自己的历史申请列表。

系统反馈：页面以列表形式展示员工提交的所有申请，按提交时间倒序排列。每条申请显示：申请的权限/角色名称、提交时间、当前状态（审批中/已通过/已拒绝/已撤销）、审批人姓名和处理时间（如已有结果）。审批中的申请右侧显示"撤销"操作按钮。已通过或已拒绝的申请可点击进入详情。列表为空时展示空状态。

本节点需要前置解释：无需额外前置解释——列表状态标签已自解释。

建议页面文案：
- Tab 名称：申请记录（共 N 条）
- 状态标签：审批中 / 已通过 / 已拒绝 / 已撤销
- 撤销按钮：撤销申请
- 空状态标题：暂无申请记录
- 空状态说明：您还没有提交过权限申请。需要申请权限时，请在"我的权限"中点击"申请权限"。
- 撤销确认弹窗标题：确认撤销申请
- 弹窗正文：撤销后，该申请将不再进入审批流程。确认撤销吗？
- 弹窗确认按钮：确认撤销
- 弹窗取消按钮：暂不撤销
- 撤销成功提示：申请已撤销

下一步：员工可从申请记录返回"我的权限"tab，或在审批通过后查看已生效的权限。

### 审批人侧

**节点 C1：收到审批通知并查看详情**

用户动作：审批人收到审批通知（可在审批中台的通知列表或消息推送中查看），点击进入申请详情页。

系统反馈：详情页展示申请的完整信息——申请人姓名和部门、申请的权限或角色名称、申请原因原文、提交时间。页面布局以上下结构组织：顶部为申请人信息和申请时间，中部为申请内容（以卡片形式突出展示），底部为操作区（"同意"主按钮和"拒绝"次按钮）。如果申请对应的员工已离职，页面顶部以提示条展示"该员工已离职，此申请自动关闭"，操作按钮隐藏。

本节点需要前置解释：审批人需要清楚——"同意后权限将自动授予申请人。请确认申请内容合理后再操作。"

建议页面文案：
- 页面标题：权限申请详情
- 申请人信息区：申请人：[姓名] | 部门：[部门名称]
- 提交时间：提交于 [日期]
- 申请内容卡片标题：申请内容
- 申请原因标签：申请原因
- 申请原因无内容时的占位：申请人未填写原因
- 员工已离职提示：该员工已离职，此申请已自动关闭。
- 同意按钮：同意授权
- 拒绝按钮：拒绝
- 拒绝确认弹窗标题：确认拒绝
- 弹窗正文：拒绝后，该员工权限不会变更。是否填写拒绝原因？（选填）
- 拒绝原因 placeholder：请说明拒绝原因（选填），将通知申请人
- 弹窗确认按钮：确认拒绝
- 操作成功提示：操作成功。已通知申请人。

下一步：审批人返回审批列表继续处理其他申请。

## 3. 次交互流程

**管理员修改配置**

管理员在模式状态页点击"修改配置"后，进入与首次配置相同的两步流程，但页面展示的是当前已生效的配置值。修改后点击"保存修改"，系统提示"配置已更新。已提交的审批中申请不受影响，新配置仅对后续新申请生效。"修改审批流时，系统校验新审批人有效性，规则与首次配置一致。

**员工撤销审批中的申请**

员工在申请记录中找到审批中的申请，点击"撤销申请"。系统弹出二次确认弹窗。员工确认后，申请状态变为"已撤销"，审批人侧该申请同步关闭。撤销成功后页面显示绿色提示条"申请已撤销"，该条申请从审批人的待处理列表中移除。

**审批人查看申请历史**

审批人可在审批中台的"已处理"列表中查看自己处理过的权限申请记录，包含同意和拒绝的历史。每条记录显示申请人、申请内容、处理结果和处理时间。

## 4. 异常与阻断流程

**异常 1：管理员未完成配置就尝试开启**

- 发生时机：管理员在范围配置或审批配置步骤中，未完成必填项就点击"确认并开启"。
- 触发条件：可申请范围未勾选任何权限；或审批规则未设置或无效。
- 判断依据：business 中"配置不完整时不允许开启"的规则。
- 反馈形式：页面顶部出现红色提示条，具体列出未完成的配置项。开启按钮置灰不可点击。
- 系统反馈："请完成以下配置后再开启：① 可申请范围——至少选择一项权限或角色；② 审批流程——需设置有效的审批规则。"
- 用户下一步：管理员返回对应步骤完成配置。

**异常 2：审批流配置无效**

- 发生时机：管理员在审批配置步骤中，设置的审批人不存在或链路不完整。
- 触发条件：选定的审批人账号已注销；自定义审批流缺少必要节点。
- 判断依据：business 中"审批规则无效则拒绝保存"的规则。
- 反馈形式：页面顶部红色提示条，标注具体的无效项。保存/下一步按钮置灰。
- 系统反馈："审批规则存在问题：审批人 [姓名] 已离职或账号已注销，请更换。"
- 用户下一步：管理员修改审批人设置或重新配置审批流。

**异常 3：员工申请已有权限**

- 发生时机：员工在申请表单中选择目标并点击"提交申请"时。
- 触发条件：系统检测到该员工已拥有所申请的权限。
- 判断依据：business 中"不能对同一权限重复提交申请"的防重规则。
- 反馈形式：提交按钮上方出现红色文字提示，阻止提交。
- 系统反馈："您已拥有此权限，无需再次申请。"
- 用户下一步：员工关闭申请表单，返回"我的权限"页确认已有权限。

**异常 4：员工重复申请同权限**

- 发生时机：员工在申请表单中选择目标并点击"提交申请"时。
- 触发条件：系统检测到该员工已有同权限且状态为"审批中"的申请。
- 判断依据：business 中"不能对同一权限重复提交申请"的防重规则。
- 反馈形式：提交按钮上方出现红色文字提示，阻止提交。提示中包含"查看申请"链接。
- 系统反馈："该权限已有审批中的申请，请等待审批结果。[查看申请]"
- 用户下一步：员工点击"查看申请"跳转到对应的申请详情。

**异常 5：审批超时自动升级**

- 发生时机：员工提交申请后，审批人在约 7 个工作日内未处理。
- 触发条件：申请状态为"审批中"且超过超时阈值。
- 判断依据：business 中"审批超时后系统自动升级到管理员处理"的兜底策略。
- 反馈形式：超时当天，系统向审批人发送提醒通知；同时向管理员发送升级通知。申请单上显示"已升级处理"标签。
- 系统反馈（审批人侧）："您有超时未处理的权限申请，系统已升级给管理员处理。"
- 系统反馈（管理员侧）："以下申请因审批超时已升级，请及时处理：[申请列表]。"
- 系统反馈（员工侧）：申请状态更新为"审批中（已升级至管理员处理）"。
- 用户下一步：管理员在审批中台处理升级的申请。

**异常 6：管理员关闭模式时存在审批中申请**

- 发生时机：管理员在模式状态页点击"关闭模式"。
- 触发条件：系统检测到当前存在状态为"审批中"的申请。
- 判断依据：business 中"关闭模式时系统检查进行中申请，默认推荐等待自然完成"的规则。
- 反馈形式：弹出选择弹窗，列出两个选项及各自的说明。
- 系统反馈（弹窗标题）：关闭模式前需要处理中的申请
- 弹窗正文："当前有 N 条权限申请正在审批中。请选择处理方式。"
- 选项一（推荐）：等待全部申请审批完成后自动关闭——当前申请正常流转，全部完成后模式自动关闭。员工在此期间不能提交新申请。
- 选项二：立即关闭并批量拒绝——所有审批中的申请将被拒绝，模式立即关闭。此操作不可撤回，需填写原因。
- 选项二被选中时出现的文本输入框：关闭原因（必填）
- 选项二确认按钮：确认关闭并拒绝
- 选项一确认按钮：确认，等待完成后自动关闭
- 关闭成功后提示条（等待模式）：模式将在所有审批中申请处理完毕后自动关闭。当前员工无法提交新申请。
- 关闭成功后提示条（强制关闭）：模式已关闭。N 条审批中的申请已被拒绝，相关员工已收到通知。

**异常 7：员工越权访问他人数据**

- 发生时机：员工通过 URL 尝试访问他人的权限详情或申请记录。
- 触发条件：当前登录员工与被访问数据的所有者不匹配。
- 判断依据：business 中"员工只能查看自己的权限和申请记录"的数据隔离规则。
- 反馈形式：页面不展示数据，以空状态或错误页呈现。
- 系统反馈："无权查看此内容。"
- 用户下一步：员工返回自己的权限页。

**异常 8：模式已关闭时员工尝试申请**

- 发生时机：员工在模式关闭后进入"我的权限"页，点击"申请权限"按钮。
- 触发条件：自助申请模式状态为"已关闭"。
- 判断依据：business 中"关闭后申请权限入口关闭或置灰"的规则。
- 反馈形式："申请权限"按钮置灰不可点击，鼠标悬停时显示说明。
- 系统反馈（按钮 hover 提示）："企业当前未开启自助申请权限，如需权限请联系管理员。"
- 页面顶部提示条："自助申请权限功能暂未开放。您可以查看已有权限，如需新权限请联系管理员。"

## 6. 状态与反馈文案

**模式状态**

- **已关闭**：含义——自助申请模式未启用，员工无法申请权限。页面反馈——模式卡片显示"未启用"标签，员工端"申请权限"入口置灰。
- **配置中**：含义——管理员已开始配置但尚未完成所有步骤。页面反馈——模式卡片显示"配置中"标签，配置页显示进度和缺失项。此状态对员工不可见（员工仍视为关闭状态）。
- **已开启**：含义——模式正常运行，员工可查看权限并发起申请。页面反馈——模式卡片显示"当前启用"标签和配置摘要，员工端"申请权限"入口可用。
- **关闭中（等待审批完成）**：含义——管理员已触发关闭但选择等待审批中申请处理完。页面反馈——模式卡片显示"关闭中"标签，员工端可查看已提交申请但不可提交新申请，提示"自助申请功能即将关闭，暂不支持提交新申请。"

**申请单状态**

- **审批中**：含义——申请已提交，等待审批人处理。员工可撤销。页面反馈——申请记录中显示"审批中"标签（蓝色），可看到"撤销申请"按钮。
- **已通过**：含义——审批人同意，权限已自动授予。页面反馈——申请记录中显示"已通过"标签（绿色），对应权限出现在"我的权限"列表中，来源标记为"自助申请"。
- **已拒绝**：含义——审批人拒绝，权限不变。页面反馈——申请记录中显示"已拒绝"标签（灰色），可点击查看拒绝原因（如有）。
- **已撤销**：含义——员工主动撤回了申请。页面反馈——申请记录中显示"已撤销"标签（灰色）。
- **已关闭**：含义——因管理员关闭模式或其他系统原因，申请被关闭。页面反馈——申请记录中显示"已关闭"标签（灰色），附关闭原因。

**权限来源标记**

- **通过 [角色名] 获得**：含义——权限来自角色关联。页面反馈——蓝色标签。
- **管理员直授**：含义——管理员在用户授权页直接授予。页面反馈——灰色标签。
- **自助申请**：含义——员工通过自助申请流程获得。页面反馈——绿色标签。

## 7. 待确认问题

**1. [QUESTION] 员工端"我的权限"入口最终放在工作台的哪个位置？**

影响导航层级和信息架构。当前方案假设为独立的一级入口，如果放在二级或作为工作台卡片，入口设计需要调整。建议由产品侧确认导航方案。

**2. [QUESTION] 审批超时阈值是否支持管理员自定义？**

当前方案使用约 7 个工作日作为默认值。如果支持管理员自定义，审批配置页需要增加一个阈值的设置项。如果不支持，阈值需要产品侧给出最终值。

**3. [QUESTION] 是否需要在"我的权限"页展示权限的生效时间和到期时间（如有）？**

当前方案按业务蓝图建议展示了权限来源，但未涉及时效信息。如果权限体系中存在时效性（如临时授权到期），需要在权限列表和申请记录中补充展示。建议确认权限体系是否支持临时授权。

**4. [QUESTION] 员工提交申请后，审批前是否需要系统自动做一次合规检查（如敏感权限申请自动转人工二次确认）？**

当前方案假设审批人做唯一合规判断。如果需要系统先行拦截或标记，申请提交流程需要增加一个校验环节。建议由安全或合规团队确认。

## 附录：依据与追踪

本文档的体验方案基于以下业务依据和设计原则。

**反馈形式选择**：优先在操作前说明限制而非操作后弹窗（如模式关闭时"申请权限"按钮置灰 + hover 说明、高危权限标记在配置阶段展示）；字段级问题贴近字段提示（如申请原因必填校验）；轻量可恢复用 toast（如提交成功、撤销成功）；复杂阻断用弹窗并说明原因和下一步（如关闭模式时的二选一弹窗）。以上选择参考了"反馈形式选择原则——能在操作前说明的限制不要等失败后再解释"和"字段问题优先在字段附近说明"的设计原则。

**权限安全边界的体验化**：business 中的三条安全规则在体验方案中的对应——越权申请通过"范围外权限不可见"实现（申请表单只展示管理员已开放的范围）；重复申请通过提交前校验 + 红色提示阻断实现；数据隔离通过"无权查看此内容"的空状态页实现而非前端隐藏。

**状态解释的可见性设计**：申请单状态（审批中/已通过/已拒绝/已撤销/已关闭）以颜色标签区分，含义自解释；权限来源（角色/直授/自助申请）以颜色标签在"我的权限"列表中展示，帮助员工理解"为什么有这项权限"。

**异常兜底的用户通知**：审批超时升级不仅触发系统流转，同时通知审批人（提醒）、管理员（升级通知）、员工（申请状态更新），确保三方都清楚当前进度和下一步责任人。这对应 business 中"审批超时后系统自动升级到管理员处理"的兜底策略。

**文案的用户化转译**：所有提示和报错文案使用业务语言而非技术词——"该权限不在可申请范围内"而非"scope validation failed"；"您已拥有此权限"而非"duplicate grant detected"；"审批人已离职或账号已注销"而非"approver entity not found"。

**业务承接覆盖**：experience 阶段已承接 business 方案承接要求中的所有必选项——三类角色的全部主流程、全部异常处理、全部状态解释、全部风险保护措施，以及五条设计建议。
