# 可用性、交互控制与效率原则

## U 系列：通用可用性启发式

### U-01 系统状态可见

- 来源：Nielsen 启发式
- 定义：系统应持续告知用户当前状态与进展。
- 触发：异步、审批/延迟生效、加载、后台任务、冲突覆盖。
- 推导输出：状态/进度/结果必须可见；用户能判断“现在/下一步/何时生效”。
- 文档落点：状态与反馈｜流程｜可解释性
- 自检问句：用户是否需要刷新/猜测系统在做什么？
- 反模式：操作后无反馈、只给“成功/失败”不解释。
- 取舍提示：信息可见≠信息堆叠，需分层呈现。

### U-02 贴近现实世界

- 来源：Nielsen
- 定义：用用户熟悉的概念与语言解释系统。
- 触发：领域术语多、规则抽象、管理员配置。
- 推导输出：用业务语义表达规则与对象；避免内部字段直出。
- 文档落点：术语与概念｜规则
- 自检问句：用户是否必须理解系统内部结构才能操作？
- 反模式：术语混用、名词不可理解。
- 取舍提示：必要专业术语要给出定义与示例。

### U-03 用户控制与自由

- 来源：Nielsen
- 定义：支持撤销、回退、退出，避免“被困住”。
- 触发：长流程、批量、高风险配置、误操作成本高。
- 推导输出：关键动作可撤销/可回滚；提供退出与恢复入口。
- 文档落点：流程｜风险与防护
- 自检问句：做错一步是否只能重来？
- 反模式：强制不可退、不可撤销。
- 取舍提示：不可撤销时必须加强确认与审计。

### U-04 一致性与标准

- 来源：Nielsen
- 定义：同概念同命名同规则；遵循平台与行业惯例。
- 触发：多模块、多端、多入口。
- 推导输出：术语/状态/反馈/规则表达统一；避免同义不同名。
- 文档落点：命名规范｜状态与反馈｜规则
- 自检问句：同一概念是否在不同位置叫不同名字？
- 反模式：状态名、按钮文案、概念模型漂移。
- 取舍提示：少数例外必须显式标注“为什么不同”。

### U-05 错误预防

- 来源：Nielsen
- 定义：优先通过约束与提示降低错误发生。
- 触发：高风险操作、权限/资金/删除、复杂配置。
- 推导输出：执行前暴露影响范围与冲突原因；阻止明显错误路径。
- 文档落点：校验规则｜风险与防护
- 自检问句：是否把用户推向错误再报错？
- 反模式：先允许执行、事后再泛化报错。
- 取舍提示：过度约束会降低效率，需匹配角色与风险等级。

### U-06 识别优于回忆

- 来源：Nielsen
- 定义：让用户“看见就能用”，减少记忆负担。
- 触发：跨页配置、多条件、多来源叠加。
- 推导输出：关键选择/来源/结果外显；提供摘要与上下文线索。
- 文档落点：信息结构｜可解释性
- 自检问句：用户是否要记住上一步做了什么？
- 反模式：隐藏关键信息、依赖用户记忆。
- 取舍提示：外显信息需可扫读，避免长段解释。

### U-07 灵活与效率

- 来源：Nielsen / Shneiderman
- 定义：兼顾新手保底与熟练用户提速。
- 触发：管理员高频任务、重复配置、批量处理。
- 推导输出：默认值/批量/快捷入口；但不破坏可控与安全。
- 文档落点：流程｜效率策略
- 自检问句：熟练用户是否被迫走新手路径？
- 反模式：只能逐条处理、重复劳动。
- 取舍提示：效率提升要配套审计与回滚。

### U-08 极简与聚焦

- 来源：Nielsen
- 定义：减少无关信息，突出任务与决策点。
- 触发：信息密度高、配置页/表格页。
- 推导输出：主次分层；低频/高级内容延后呈现。
- 文档落点：信息结构｜可读性
- 自检问句：是否“全是重点”导致没有重点？
- 反模式：一屏堆满规则与字段。
- 取舍提示：极简不等于缺信息，关键是分层。

### U-09 可行动的错误恢复

- 来源：Nielsen
- 定义：错误要可理解、可定位、可行动。
- 触发：校验失败、冲突覆盖、权限不足。
- 推导输出：原因+影响+修复路径；提供下一步建议。
- 文档落点：错误与恢复｜规则
- 自检问句：用户看完错误是否仍不知道怎么办？
- 反模式：只给错误码/“未知错误”。
- 取舍提示：避免暴露敏感内部信息，但要给可行动指引。

### U-10 就地帮助与文档

- 来源：Nielsen
- 定义：复杂系统需要可就地获取的解释。
- 触发：首次使用、规则系统、管理员工具。
- 推导输出：关键决策点提供解释入口；帮助可检索、可复制。
- 文档落点：帮助与指引｜术语
- 自检问句：用户是否只能找人问？
- 反模式：把帮助全放到外部大文档。
- 取舍提示：帮助应短、贴近当前决策点。

## ISO 系列：ISO 9241-110 交互原则

### ISO-01 适合任务

- 来源：ISO 9241-110
- 定义：交互应高效支持任务完成。
- 触发：流程冗长、重复输入、频繁切换。
- 推导输出：减少非必要步骤；结构顺序匹配任务顺序。
- 文档落点：流程｜信息结构
- 自检问句：是否存在“为系统而做”的步骤？
- 反模式：为了配置而配置、必须走完全部字段。
- 取舍提示：一致性与效率可能冲突，优先保任务完成。

### ISO-02 自描述

- 来源：ISO 9241-110
- 定义：用户在任意点都能理解“这里是什么/能做什么/下一步”。
- 触发：复杂配置页、规则编辑、空状态。
- 推导输出：关键对象/范围/状态语义清晰；结果可解释。
- 文档落点：信息结构｜状态与反馈
- 自检问句：是否需要培训才能理解当前页面？
- 反模式：只有内部术语、缺上下文。
- 取舍提示：自描述依赖一致术语与可读性。

### ISO-03 可控性

- 来源：ISO 9241-110
- 定义：用户能控制节奏与顺序。
- 触发：自动跳转、强制流程、批量执行。
- 推导输出：支持暂停/返回/调整；避免不可预期的自动行为。
- 文档落点：流程｜风险与防护
- 自检问句：系统是否“替用户做决定”且不可改？
- 反模式：强制提交、不可返回。
- 取舍提示：对高风险动作可提高控制成本以换安全。

### ISO-04 符合预期

- 来源：ISO 9241-110
- 定义：与用户既有经验一致（平台/行业/产品内部一致）。
- 触发：多端一致、迁移旧系统、管理员工具。
- 推导输出：不随意发明新概念/新入口；例外需解释。
- 文档落点：命名规范｜信息结构
- 自检问句：是否出现“只有老用户才懂”的私有规则？
- 反模式：同类功能在不同端逻辑不同。
- 取舍提示：创新要有强收益且可渐进引入。

### ISO-05 容错

- 来源：ISO 9241-110
- 定义：允许犯错且不造成严重后果。
- 触发：权限/配置/批量/高影响变更。
- 推导输出：预览影响、可回滚、失败可恢复。
- 文档落点：风险与防护｜审计
- 自检问句：误操作是否会造成不可逆后果？
- 反模式：一次点击永久生效。
- 取舍提示：容错会增加系统复杂度，需分风险等级。

### ISO-06 适合学习

- 来源：ISO 9241-110
- 定义：系统帮助用户逐步掌握。
- 触发：首次使用、复杂模块、角色交接。
- 推导输出：渐进披露、示例、就地解释、可逆操作。
- 文档落点：帮助与指引｜流程
- 自检问句：新手能否在无培训下完成核心任务？
- 反模式：上来就要求理解全部概念。
- 取舍提示：学习性与效率需双通道策略。

### ISO-07 可个性化

- 来源：ISO 9241-110
- 定义：允许不同用户以不同方式完成任务。
- 触发：岗位差异大、新手/专家差异大。
- 推导输出：偏好/视图可配置，但不破坏一致性与审计。
- 文档落点：效率策略｜可配置项
- 自检问句：是否只有一种路径，且对某类角色很不友好？
- 反模式：强制统一流程忽略岗位差异。
- 取舍提示：个性化需要边界与回退机制。

## I 系列：交互效率与操作学

### I-01 指向效率（Fitts）

- 来源：交互定律
- 定义：目标越大/越近，操作越快越不易错。
- 触发：主操作、高频操作、移动端触控。
- 推导输出：高频目标更易触达；危险操作避免“太易触达”。
- 文档落点：操作原则｜风险与防护
- 自检问句：高频操作是否需要精细点击？
- 反模式：高频按钮很小、危险按钮离主操作太近。
- 取舍提示：易触达与防误触需平衡（隔离危险操作）。

### I-02 约束与防呆（Constraints）

- 来源：交互原则
- 定义：用约束减少错误路径与不确定性。
- 触发：输入、范围选择、条件组合。
- 推导输出：不可选即不可操作且原因可解释；避免先错后罚。
- 文档落点：校验规则｜可解释性
- 自检问句：用户是否经常走到“不可用”的死路？
- 反模式：把错误留到最后一次性爆发。
- 取舍提示：约束要配说明，避免“系统莫名其妙不让选”。

### I-03 新手/专家双通道

- 来源：可用性原则组合
- 定义：新手保底，专家提速。
- 触发：管理员高频配置、重复任务。
- 推导输出：保留安全主路径；提供批量/快捷但可审计可回滚。
- 文档落点：流程｜效率策略
- 自检问句：专家是否只能重复低效步骤？
- 反模式：只有一种路径，且对一类用户极其低效。
- 取舍提示：快捷能力必须有边界与风险控制。
