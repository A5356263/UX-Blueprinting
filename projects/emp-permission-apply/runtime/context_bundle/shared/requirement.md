# Requirement

- Project ID: emp-permission-apply
- Task Name: 员工自助申请权限
- Domain: 权限管理

## 原始需求

来源：`input/自助权限申请/需求文档_员工自助申请权限.md`

### 需求背景

目前企业员工权限由管理员或超管集中处理。中大型企业中员工多、流动频繁，新增/变更/核对工作量大。部分企业超管可能是老板本人，沟通成本高、时效不稳定。希望通过支持员工自助查看和申请权限，把部分申请工作从管理员侧分散到员工侧，同时保留管理员对范围和审批流程的控制。

### 目标

新增"员工自助申请权限"能力，使员工可以：
- 查看自己当前拥有的权限
- 主动申请所需权限
- 审批通过后自动获得权限
- 查看申请记录和审批状态

管理员可以控制：
- 是否允许自助申请
- 可申请范围
- 审批流程
- 关闭该能力

### 核心场景

1. 管理员配置自助申请权限（开启、设范围、设审批流程）
2. 员工查看自己的权限
3. 员工申请权限（提交申请、说明原因）
4. 审批人处理申请（同意/拒绝，通过后自动授权）
5. 管理员关闭自助申请能力（不影响审批中的申请）

### 初步业务规则

- 仅最高权限管理员可开启/关闭
- 开启前需设置可申请范围和审批方式
- 可申请范围可按角色或功能权限配置（待定）
- 管理员可后续调整配置
- 员工端和审批端规则待补充

### 已知风险

- 培训成本（员工端学习）
- 权限安全风险（范围过宽）
- 审批流程风险（审批人不存在、链路错误）
- 模式互斥风险（与已有权限治理模式冲突）

### 竞品参考

金蝶有相近功能，支持用户查看权限并通过申请单申请角色或组织数据权限，审批通过后自动授权。
