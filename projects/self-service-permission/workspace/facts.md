# Facts

## 任务概述

本次需求新增"员工自助申请权限"能力，解决中大型企业中权限分配高度依赖管理员的痛点。员工可以主动查看自己已有权限、发起权限申请，审批通过后系统自动授权。同时管理员保留对开关、可申请范围和审批流程的完全控制。

涉及角色：
- 超级管理员 / 权限管理员：配置自助申请开关、可申请范围、审批方式
- 员工：查看自己权限、发起权限申请、查看申请记录
- 审批人：处理权限申请，同意或拒绝

主要场景：
- 管理员开启并配置自助申请能力
- 员工查看自己已有权限
- 员工发现缺权限后发起申请
- 审批人收到申请并审批
- 审批通过后系统自动授权
- 管理员关闭自助申请能力

## 功能范围

### 管理端配置
- 做什么：管理员开启/关闭员工自助申请权限能力，配置可申请范围和审批方式
- 谁使用：超级管理员、权限管理员
- 优先级：P0

### 员工查看已有权限
- 做什么：员工查看自己当前拥有的所有权限（功能权限、数据权限、角色），按应用分类展示，显示权限来源和生效时间
- 谁使用：全体员工
- 优先级：P0

### 员工发起权限申请
- 做什么：员工浏览可申请的权限范围，选择要申请的权限（一期仅角色），填写申请原因并提交
- 谁使用：全体员工
- 优先级：P0

### 审批人处理申请
- 做什么：审批人查看申请内容（申请人、申请权限、申请原因、申请人现有权限），同意或拒绝并填写审批意见
- 谁使用：审批人（默认直属组织负责人）
- 优先级：P0

### 员工查看申请记录
- 做什么：员工查看自己提交的申请历史和当前状态（待审批/已通过/已拒绝/已撤销），审批通过前可撤销
- 谁使用：全体员工
- 优先级：P1

### 操作记录与审计
- 做什么：记录能力开启/关闭、申请提交、审批操作等关键动作
- 谁使用：系统
- 优先级：P1

### 管理员查看申请统计
- 做什么：基础计数——申请总数、通过数、拒绝数、审批中数量
- 谁使用：超级管理员、权限管理员
- 优先级：P2

## 关键业务规则

1. 自助申请是权限获取通道，不是治理模式，必须与现有三种治理模式（子管理员模式、双管理员互审、权限变更审批模式）兼容共存
2. 只有具备最高权限的管理员可以开启或关闭自助申请能力
3. 开启前必须设置可申请范围和审批方式
4. 一期仅开放角色申请，二期再开放单功能权限申请
5. 管理员可标记特定角色/权限为"不可申请"，系统默认排除超级管理员角色、子管理员角色和管理端专用角色
6. 申请必须经过审批才能生效，不得直接授权
7. 审批人默认优先级：申请人直属组织负责人 → 权限管理员 → 超级管理员；管理员可自定义审批流程
8. 提交申请前必须校验审批人存在，不存在则阻断提交并提示
9. 申请权限时不支持自选数据权限范围，申请角色时继承角色默认数据范围
10. 审批通过后系统自动完成授权，权限即时生效
11. 管理员关闭能力后，已通过申请的权限保留；审批中的申请允许走完但禁止新提交
12. 关闭前向管理员展示当前审批中的申请数量
13. 服务人员不开放此能力
14. 所有关键操作记入审计日志

## 状态流转

申请单状态：`draft`（可编辑） → `pending`（审批中） → `approved`（已通过） → `effective`（已生效）
                                                              → `rejected`（已拒绝，流程结束）
                       `pending` 状态可被员工主动撤销 → `revoked`（已撤销）

- `draft → pending`：员工提交申请
- `pending → approved`：审批人同意
- `pending → rejected`：审批人拒绝
- `approved → effective`：系统自动授权完成
- `pending → revoked`：员工主动撤销

## 异常与边界

1. **审批人不存在**
   - 场景：员工提交申请时，默认审批人（组织负责人）未设置
   - 触发条件：提交申请前系统校验审批链
   - 系统反馈：阻断提交，提示"审批流程未就绪，请联系管理员"
   - 用户处理：联系管理员配置审批人

2. **审批超时**
   - 场景：审批人长时间未处理
   - 触发条件：超过配置的超时天数
   - 系统反馈：自动升级到上一级审批人或超级管理员
   - [GAP] 超时天数是否由管理员配置，以及默认天数待定

3. **审批人离职/变更**
   - 场景：审批流程中审批人离职或岗位变更
   - 触发条件：审批中台的标准转交机制触发
   - 系统反馈：按审批中台规则自动转交
   - [GAP] 具体的转交规则取决于审批中台实现

4. **管理员关闭能力**
   - 场景：管理员决定关闭自助申请能力
   - 触发条件：管理员执行关闭操作
   - 系统反馈：展示当前审批中的申请数量，确认后禁止新提交，已有申请允许走完
   - 已授权限不回收

5. **与治理模式交互**
   - 场景：企业同时开启某治理模式和自助申请能力
   - [QUESTION] 双管理员互审模式下，自助申请是否也需要双人审批？当前倾向为自助申请的审批链路独立于治理模式的审批修饰

6. **范围配置冲突**
   - 场景：管理员配置的可申请范围中包含后续被标记为"不可申请"的角色
   - 系统反馈：标记为不可申请的角色自动从可申请范围中移除
   - [GAP] 如果某角色已被员工申请且审批中，此时管理员标记为不可申请，处理方式待定

## 依赖与前置条件

- 审批中台（OA审批）：承接权限申请的审批流程设计、发布与运行
- 组织管理：提供直属组织负责人作为默认审批人
- 权限管理现有体系：来源模型扩展（新增 SELF_SERVICE 类型）、角色管理（可申请范围引用角色清单）
- 成员管理：确认申请人身份和在职状态
- 工作台：承载员工端入口卡片

- [GAP] 审批超时天数是否可由管理员配置及默认值
