# Experience Blueprint

## 0. 本次关键设计判断

**判断：**

三端各自独立页面承接：管理端一个集中配置页，员工端两个页面（权限查看+申请记录），审批端复用审批中台待办。设计重点在降低员工申请门槛和管理员配置理解成本。

**主要影响：**

1. 管理端需要新增"自助申请配置"页面，集中承载开关、范围选择、审批方式三类配置
2. 员工端需要两个新增页面：「我的权限」和「我的申请」，以及一个申请发起入口
3. 审批端复用审批中台现有待办列表和审批详情，不需要新增页面

**建议方案：**

- 管理端：独立配置页，开关在最顶部，范围和审批设置分组展示，保存前校验完整性
- 员工端：「我的权限」作为常驻查询页，申请入口在工作台卡片和权限页内两处露出
- 审批端：复用审批中台标准待办，在审批详情中增加"查看申请人现有权限"入口

**不建议方案：**

- 不支持把申请入口做成弹窗——申请需要浏览可申请范围、查看权限说明、填写原因，弹窗承载能力不足
- 不支持把配置分散到角色管理页——管理员的治理心智是"我要控制能不能自己申请"，不是"我要去改每个角色"

**关键待确认：**

1. 审批表单的最终形态（审批中台自定义表单 vs 权限模块固定表单）会影响审批详情页的设计
2. 员工端入口在权限拦截场景下的触发方式（自动弹出 vs 提示引导）

## 1. 旅程图

- **管理员**：发现权限分配压力大 → 进入自助申请配置页 → 开启能力并设置范围和审批方式 → 保存生效 → 后续查看统计数据判断是否调整配置 → 不再需要时关闭能力
- **员工**：使用系统时发现缺少某功能 → 进入「我的权限」查看当前已有权限 → 在可申请列表中找到目标角色 → 查看角色说明 → 填写原因提交申请 → 等待审批 → 收到审批通过通知 → 确认权限已生效
- **审批人**：收到待办通知 → 查看申请内容（谁申请了什么角色、什么原因）→ 查看申请人现有权限辅助判断 → 决定同意或拒绝 → 填写审批意见 → 提交

### 旅程缺口

- 员工首次使用时不知道"可以自己申请权限"这个能力存在，需要入口引导和场景触达
- 审批人拒绝后员工的下一步不明确——是否允许修改后重新提交、是否需要引导联系管理员

## 2. 交互流程总览

**管理端流程：**
管理员进入「通用权限管理 → 自助申请配置」→ 查看当前配置状态 → 点击编辑 → 开启/关闭能力 → 设置可申请角色范围 → 设置审批方式 → 保存前完整性校验 → 保存成功 → 返回查看态

**员工端流程：**
员工从工作台卡片或「我的权限」进入 → 查看自己已有权限概览 → 点击"申请权限" → 浏览可申请的角色列表 → 点击某个角色查看详情（角色包含的权限项）→ 点击"申请此角色" → 填写申请原因 → 提交 → 校验通过 → 看到提交成功提示和申请状态 → 在「我的申请」中跟踪进度 → 审批通过前可撤销

**审批端流程：**
审批人从待办列表进入审批详情 → 查看申请人信息、申请角色、申请原因 → 可选查看申请人现有权限 → 填写审批意见 → 点击同意或拒绝 → 确认提交 → 结果通知员工

**异常流程重点：**

- 审批人不存在：提交时阻断，提示"审批流程未就绪，请联系管理员"。不进入 pending 状态
- 审批超时：超时后自动升级到上级审批人或超级管理员，通知原审批人和申请人
- 管理员关闭能力：关闭前弹窗展示"N 条审批中的申请将允许走完，不允许提交新申请"，确认后执行
- 申请被拒：员工收到拒绝通知和原因，可重新提交新申请
- 能力未开启：员工端入口隐藏，通过其他入口直接访问时显示"该能力暂未开放"

## 3. 主交互流程

**节点 1：管理员开启并配置自助申请**

用户动作：
管理员进入「自助申请配置」页面，看到当前能力的开关状态。如果是首次进入，开关默认关闭，页面展示能力说明。管理员点击"开启"开关。

系统反馈：
开关切换为开启态，页面展开可申请角色范围和审批方式两个配置区。如果管理员直接保存而不配置范围，系统提示"请至少选择一个可申请角色"。

需要前置解释的信息：
- 开启后员工可在工作台和「我的权限」中看到申请入口
- 可申请范围控制员工能看到和申请哪些角色
- 审批方式决定申请提交后由谁审批

建议文案：
- 页面标题：「自助申请配置」
- 能力说明：「开启后，员工可以查看自己的权限并发起权限申请，审批通过后自动授权」
- 开关标签：「允许员工自助申请权限」

**节点 2：员工发起权限申请**

用户动作：
员工从工作台"申请权限"卡片或「我的权限 → 申请权限」进入可申请角色列表。列表展示角色名称、角色简介、角色包含的权限项数量。员工点击某个角色进入详情，确认后点击"申请此角色"，进入申请表单。员工在申请原因中说明为什么需要这个权限，点击提交。

系统反馈：
提交前系统校验审批人存在。校验通过后展示"申请已提交"成功提示，告知预计审批人。如果校验失败，阻断提交并展示"审批流程未就绪，请联系管理员"。

需要前置解释的信息：
- 申请提交后将由直属组织负责人审批
- 审批通过后权限自动生效
- 审批通过前可以撤销申请

建议文案：
- 列表标题：「可申请的权限」
- 空状态：「暂无可申请的权限，请联系管理员」
- 申请原因标签：「申请原因（选填）」
- 提交按钮：「提交申请」
- 成功提示：「申请已提交，请等待审批」

**节点 3：审批人处理申请**

用户动作：
审批人在审批中台待办列表中看到权限申请事项，点击进入详情。详情展示申请人姓名、所属组织、申请的角色、角色包含的权限项、申请原因。审批人可点击"查看申请人现有权限"辅助判断，然后填写审批意见，点击同意或拒绝。

系统反馈：
同意后系统自动完成授权，通知员工"你的权限申请已通过，权限已生效"。拒绝后通知员工"你的权限申请未通过"，展示拒绝原因。

需要前置解释的信息：
- 同意后权限即时生效
- 拒绝后员工可重新提交申请
- 审批操作不可撤回

建议文案：
- 审批详情标题：「权限申请审批」
- 同意按钮：「同意」
- 拒绝按钮：「拒绝」
- 审批意见标签（拒绝时）：「拒绝原因（必填）」
- 查看现有权限链接：「查看申请人现有权限」

## 4. 次交互流程

**撤销申请（员工）：**
员工在「我的申请」列表中找到审批中的申请 → 点击"撤销" → 确认弹窗"撤销后需重新提交申请" → 确认 → 申请状态变为"已撤销" → 通知审批人申请已撤销

**查看申请记录（员工）：**
员工进入「我的申请」→ 列表按时间倒序展示所有申请 → 每条显示申请角色、提交时间、当前状态 → 支持按状态筛选（全部/审批中/已通过/已拒绝/已撤销）→ 点击某条进入详情

**查看已有权限（员工）：**
员工进入「我的权限」→ 按应用分类展示当前拥有的所有权限 → 每条显示权限名称、来源（管理员授予/角色继承/自助申请）、生效时间 → 支持搜索

**管理员调整配置：**
管理员进入配置页 → 点击编辑 → 修改可申请范围（增删角色）或审批方式 → 保存 → 已有申请不受影响，新申请按新配置执行

**管理员关闭能力：**
管理员在配置页点击关闭开关 → 弹窗展示"N 条审批中的申请"→ 确认关闭 → 员工端入口隐藏 → 审批中的申请仍可正常走完 → 已授权限保留

**管理员查看统计：**
配置页底部展示基础统计：总申请数、通过数、拒绝数、当前审批中数量

## 5. 异常与阻断流程

**异常 1：审批人不存在**

- 发生时机：员工提交申请时
- 触发条件：系统校验默认审批链路，发现直属组织负责人未设置，且无备用审批人
- 判断依据：facts.md 关键业务规则第 8 条
- 反馈形式：提交按钮处内联提示
- 系统反馈：「审批流程未就绪，请联系管理员配置审批人后再提交」
- 用户下一步：联系管理员

**异常 2：审批超时**

- 发生时机：申请处于审批中状态超过配置天数
- 触发条件：超时天数阈值（具体值待产品确认）
- 判断依据：facts.md 异常与边界第 2 条
- 反馈形式：系统自动操作 + 消息通知
- 系统反馈：自动将申请转交至上一级审批人或超级管理员，通知原审批人"申请已超时转交"和申请人"审批人已变更"
- 用户下一步：新审批人处理申请

**异常 3：能力被关闭时员工尝试提交**

- 发生时机：员工在提交申请时能力刚好被关闭
- 触发条件：管理员在员工填写申请期间关闭了能力
- 反馈形式：提交时弹窗阻断
- 系统反馈：「该能力已由管理员关闭，暂时无法提交申请」
- 用户下一步：返回，申请草稿不保留

**异常 4：申请的角色被标记为不可申请**

- 发生时机：员工查看可申请列表时
- 触发条件：管理员在后台将某角色标记为不可申请
- 反馈形式：角色直接从可申请列表中消失，已在申请中的不受影响
- [GAP] 如果角色已在审批中时被标记为不可申请，处理方式待定

**异常 5：审批人离职或变更**

- 发生时机：申请处于审批中时审批人离职
- 触发条件：审批中台检测到审批人岗位变更或离职
- 判断依据：facts.md 异常与边界第 3 条
- 反馈形式：审批中台自动转交
- 系统反馈：按审批中台标准转交规则处理，通知申请人审批人已变更
- [GAP] 具体转交规则取决于审批中台实现

## 6. 页面 / 弹窗 / 抽屉设计

**页面：自助申请配置（管理端）**

- 页面目标：管理员在一个页面内完成自助申请能力的开启、范围和审批配置
- 页面结构：
  - 顶部：页面标题 + 能力说明
  - 区域一：开关区，开启/关闭能力，附带能力简介和影响说明
  - 区域二：可申请角色范围，多选列表（从角色清单中选择），默认排除管理类角色，支持搜索
  - 区域三：审批方式，默认"直属组织负责人"，可选择"自定义审批流程"跳转审批中台
  - 区域四：基础统计（申请总数、通过数、拒绝数、审批中）
  - 底部：编辑/保存/取消按钮
- 具体文案：
  - 标题：「自助申请配置」
  - 开关标签：「允许员工自助申请权限」
  - 范围标签：「可申请的角色范围」
  - 范围空状态：「暂未选择任何角色，员工将无法看到可申请的权限」
  - 审批方式标签：「审批方式」
  - 默认审批文案：「员工提交申请后，由直属组织负责人审批。如负责人不存在，依次由权限管理员、超级管理员审批」
- 按钮：「编辑」（查看态）/「保存」（编辑态）/「取消」
- 成功反馈：「配置已保存」
- 失败反馈：「保存失败，请重试」

**页面：我的权限（员工端）**

- 页面目标：员工查看自己当前拥有的所有权限，了解权限来源和生效时间
- 页面结构：
  - 顶部：页面标题 + 申请入口按钮
  - 搜索区：按应用名称或权限名称搜索
  - 列表区：按应用分组展示，每组下列出该应用下的权限项，每条显示权限名称、来源类型、生效时间
- 具体文案：
  - 标题：「我的权限」
  - 申请入口按钮：「申请权限」
  - 来源文案：「管理员授予」「角色继承」「自助申请」
  - 空状态：「暂未拥有任何权限」
- 按钮：「申请权限」（主按钮）
- 失败反馈：数据加载失败时显示「加载失败，请重试」

**页面：申请权限（员工端）**

- 页面目标：员工浏览可申请的角色，选择目标角色并发起申请
- 页面结构：
  - 顶部：返回按钮 + 页面标题
  - 搜索区：按角色名称搜索
  - 列表区：角色卡片列表，每张卡片展示角色名称、角色简介、包含的权限项数量
  - 点击角色进入详情：展示角色包含的完整权限项列表
  - 详情底部：「申请此角色」按钮
  - 点击后进入申请表单：申请原因输入框 + 提交按钮
- 具体文案：
  - 标题：「申请权限」
  - 角色卡片：角色名称 + 简介 + "包含 N 项权限"
  - 申请原因标签：「申请原因（选填）」
  - 提交按钮：「提交申请」
  - 成功提示：「申请已提交，预计由 [审批人姓名] 审批」
- 按钮：「提交申请」（主按钮）/「返回」
- 空状态：「暂无可申请的权限，如需其他权限请联系管理员」

**页面：我的申请（员工端）**

- 页面目标：员工查看申请记录和当前状态，跟踪审批进度
- 页面结构：
  - 顶部：返回按钮 + 页面标题
  - 筛选区：状态筛选（全部/审批中/已通过/已拒绝/已撤销）
  - 列表区：按时间倒序展示申请记录，每条显示申请角色、提交时间、当前状态标签、操作入口
- 具体文案：
  - 标题：「我的申请」
  - 状态标签：「审批中」「已通过」「已拒绝」「已撤销」
  - 撤销确认弹窗：「撤销后需重新提交申请，确认撤销？」
- 按钮：审批中的申请显示「撤销」（文字按钮）
- 空状态：「暂无申请记录」

**审批详情（审批端，复用审批中台）**

- 页面目标：审批人全面了解申请内容并做出审批决定
- 页面结构（在审批中台标准审批详情基础上增加）：
  - 申请人信息：姓名、所属组织
  - 申请内容：申请的角色名称、角色包含的权限项列表
  - 申请原因
  - 「查看申请人现有权限」链接（可选）
  - 审批意见输入框
  - 同意/拒绝按钮
- 具体文案：
  - 审批意见标签（拒绝时）：「拒绝原因（必填）」
  - 现有权限链接：「查看申请人现有权限」
- 按钮：「同意」（主按钮）/「拒绝」
- 同意成功反馈：「操作成功，权限已自动授权」
- 拒绝成功反馈：「操作成功」

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 审批中 | 申请已提交，等待审批人处理 | 员工 | 撤销申请 | 审批中，预计由 [审批人] 审批 |
| 已通过 | 审批人同意，权限已生效 | 员工、审批人 | 查看权限 | 申请已通过，权限已生效 |
| 已拒绝 | 审批人拒绝，权限未授予 | 员工、审批人 | 重新申请 | 申请未通过 |
| 已撤销 | 员工主动撤销，申请已终止 | 员工 | 重新申请 | 申请已撤销 |
| 已关闭 | 管理员关闭能力后审批中的申请自然走完 | 员工 | 查看结果 | 申请已完成 |

| 操作 | 成功反馈 | 失败反馈 |
|---|---|---|
| 提交申请 | 申请已提交，预计由 [审批人] 审批 | 提交失败，请重试 |
| 撤销申请 | 申请已撤销 | 撤销失败，请重试 |
| 同意申请 | 操作成功，权限已自动授权 | 操作失败，请重试 |
| 拒绝申请 | 操作成功 | 操作失败，请重试 |
| 开启能力 | 已开启，员工可在工作台和「我的权限」中申请 | 开启失败，请重试 |
| 关闭能力 | 已关闭，N 条审批中的申请将允许走完 | 关闭失败，请重试 |
| 保存配置 | 配置已保存 | 保存失败，请重试 |

## 8. 待确认问题

1. **审批表单最终形态**

   影响：如果是审批中台自定义表单，审批详情页由审批中台控制，权限模块只能增加附属信息；如果是权限模块内置固定表单，可以完全控制审批详情页的信息结构和交互。
   建议确认方：产品 + 技术

2. **员工端入口在权限拦截场景的触发方式**

   影响：决定员工首次接触能力的场景。如果是自动弹出引导，需要设计拦截弹窗的内容和跳转逻辑；如果是静态提示，只需要在拦截页面增加引导文案。
   建议确认方：产品 + 设计

3. **审批超时天数的默认值**

   影响：决定超时提示文案中是否写死天数，以及配置页是否需要暴露超时天数设置。
   建议确认方：产品

4. **移动端适配范围**

   影响：员工端申请和查看是否需要移动端适配。当前需求未明确跨端范围，但员工群体有移动端使用场景。
   建议确认方：产品

## 附录：设计指南消费说明

### 1. 设计指南消费

| 使用依据 | 转换结果 | 落点 |
|---|---|---|
| 治理设计准则：高危操作需二次确认 | 关闭能力前弹窗确认，展示审批中申请数量 | 管理端关闭流程 |
| 流程模式设计准则：流程闭环需明确每步的入口和出口 | 每个节点标注了"下一步"，流程不会断在中间 | 主交互流程 |
| 反馈与报错设计指南：阻断需说明原因和下一步 | 审批人缺失阻断时明确告知"联系管理员"+ 原因 | 异常流程 1 |

### 2. 业务知识消费

| 业务知识 | 关键规则 | 转换成的体验策略 | 落点 |
