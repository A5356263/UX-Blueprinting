# Experience Blueprint

## 0. 本次关键设计判断

**判断：**

这次体验方案的核心处理方式是"让超管控得住、让员工看得懂、让审批人判得清"。自助申请不是把权限配置页搬给员工，而是为员工裁剪出一条简化的申请路径，把复杂的权限模型和条件组计算留在管理员侧。

**主要影响：**

1. 三角色各有独立的任务路径和页面入口，不能混成同一个界面的不同状态
2. 模式互斥、校验失败、审批人缺失等阻断场景是体验设计的正式内容，不是异常附录
3. 申请方式的二选一（角色/功能权限）决定了员工侧申请页面的信息结构完全不同，需要两套申请表单设计

**建议方案：**

- 超管配置采用分步式引导（三步线性流程），每步有清晰的当前状态和可修改入口
- 员工申请采用抽屉承载，不做全页跳转，保持"我的权限"作为锚点页面
- 审批人处理申请时，申请内容区采用只读卡片展示，不暴露可编辑控件
- 所有阻断和异常都给出明确的"为什么不行"和"怎么办"

**不建议方案：**

- 不建议把申请表单做成完整权限配置页的翻版（会让员工面对条件组、AND/OR 等概念）
- 不建议把模式配置做成单页长表单（三步配置信息密度高，长表单会让超管遗漏关键设置）

**关键待确认：**

1. 审批人兜底路由的具体交互——转给超管时是否需要超管确认接受？还是自动分配？
2. 撤销后重新提交是否需要冷却期或限制次数？

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

```md
- 超管：识别权限分配效率痛点 → 进入权限管理模式 → 了解自助申请模式 → 三步配置（选方式→选范围→设审批） → 启用模式 → 日常查看运行状态 → 需要时关闭或编辑
- 员工：进入个人中心 → 发现"我的权限"入口 → 浏览已有权限 → 发现缺少某权限 → 点击申请 → 填写原因并选择 → 提交成功 → 等待通知 → 收到结果（通过则权限生效/拒绝则知道原因）
- 审批人：收到待办通知 → 查看申请内容和原因 → 判断是否合理 → 同意/拒绝 → 确认操作完成
```

### 旅程缺口

- 缺少超管查看自助申请统计数据或运行概览的入口 [GAP]
- 缺少员工发现"缺少什么权限"的引导——员工可能不知道自己缺什么权限，只能靠记忆或询问 [GAP]
- 缺少审批人处理申请时的上下文信息——审批人可能需要知道申请人的组织、岗位、现有权限等信息来辅助判断 [GAP]

## 2. 交互流程总览

**分角色交互流程：**

- 超管：权限管理模式页 → 自助申请模式宣传页 → 节点 2.1 三步配置 → 已启用态（只读查看）→ 节点 2.2 关闭/编辑
- 员工：个人中心 → 节点 2.3 我的权限（三个tab）→ 节点 2.4 申请权限（抽屉）→ 节点 2.5 申请记录（筛选+列表）
- 审批人：待办列表 → 节点 2.6 审批处理（查看申请→同意/拒绝）

**异常流程重点：**

- 超管启用时被模式互斥阻断（异常 A）
- 超管关闭时被在途流程阻断（异常 B）
- 员工提交申请时被校验规则阻断（异常 C）
- 审批人不存在导致申请无法流转（异常 D）
- 可申请范围为空（异常 E）

## 3. 主交互流程

```text
节点 2.1：超管三步配置自助申请模式

**用户动作：**

超管在自助申请模式宣传页点击"立即启用"（先校验互斥模式），进入设置页面。设置页面分三步线性推进：

第一步：选择申请方式。两个单选："申请角色"（默认选中）或"申请功能权限"。切换选项时下方提示文案相应变化。选好后自动展开第二步。

第二步：设置范围。根据第一步的选择展示不同的设置界面。
- 选角色：展示角色范围设置——全部角色/部分角色。选部分角色时弹出角色选择弹窗，支持搜索、分页，展示角色名称、角色说明、角色状态。底部有开关"后续新增角色自动加入员工可申请的范围"（默认开启）。
- 选功能权限：展示应用范围设置——全部应用/部分应用。选部分应用时弹出应用选择弹窗，支持搜索、分页，展示应用名称、应用终端、启用状态。底部有开关"后续新添加的应用自动加入员工可申请的范围"（默认开启）。

第三步：设置审批流程。展示预设审批流程说明——"审批人默认为员工所在组织的组织负责人"。提供"修改审批流程"按钮，点击跳转到表单编辑子页面。

**系统反馈：**

- 每步之间有明确的分步指示器，显示当前在第几步
- 选择"部分"时，弹窗中勾选的角色/应用实时统计在弹窗底部
- 设置完成回到页面时，选择的部分角色/应用以标签形式展示（超限时折叠为"+N"）
- 点击"启用"时再次校验互斥模式，通过则 toast "开启成功"并刷新为已启用页面
- 被互斥模式阻断时弹窗提示具体冲突

**需要前置解释的信息：**

- 申请角色的提示："申请通过后，员工将自动关联上申请角色。如果启用常用角色进行授权，建议采用此方式。"
- 申请功能权限的提示："申请通过后，员工将自动获得功能权限。如果企业常用用户直接授权的方式，建议采用此方式。"
- 审批流程说明："系统已预设了「员工申请权限」的审批流程，预设审批人为员工所在组织的组织负责人。如需调整，可点击修改审批流程。"

**建议文案：**

- 第一步标题："选择员工申请权限的方式"
- 第二步标题（角色）："设置角色范围"
- 第二步标题（应用）："设置应用范围"
- 第三步标题："设置审批流程"
- 第三步提示文案："系统已预设了「员工申请权限」的审批流程，预设审批人为员工所在组织的组织负责人。如需调整，可点击修改审批流程"
- 启用按钮："启用"
- 取消按钮："取消"

**下一步：**

启用成功后，页面刷新为已启用状态，个人中心同步出现"我的权限"入口。
```

```text
节点 2.3：员工查看我的权限

**用户动作：**

员工进入个人中心，在"我的企业"下方看到"我的权限"入口，点击进入独立页面。页面默认选中"功能权限"tab，展示员工有权限的应用列表和对应的功能权限。切换到"数据权限"tab 查看数据权限范围，切换到"角色"tab 查看关联的角色。

**系统反馈：**

- 功能权限 tab：按应用分组展示功能权限列表，每个应用下列出其对应的功能权限
- 数据权限 tab：展示数据权限的组织范围和条件组（已翻译为可读文本，不暴露 AND/OR 符号）
- 角色 tab：展示角色名称和角色说明
- 任一 tab 无数据时：展示占位图和提示语"您没有功能权限"/"您没有数据权限"/"您没有关联的角色"

**需要前置解释的信息：**

- 页面右上角或顶部应有"申请权限"按钮入口
- 权限来源可选择性展示（待确认：是否展示来源标签如"管理员授予"/"角色继承"/"自助申请"）

**下一步：**

发现缺少权限时，点击"申请权限"进入申请抽屉。或者切换到"申请记录"查看历史申请。
```

```text
节点 2.4：员工申请权限

**用户动作：**

员工在"我的权限"页面点击"申请权限"，从右侧弹出抽屉。申请人姓名默认带出且不可编辑。在申请原因文本框中填写原因（必填，最多 500 字）。

根据管理员配置的申请方式，抽屉下方展示不同的选择区域：
- 申请角色：展示可申请角色列表（表格形式），每行一个角色，包含勾选框、角色名称、角色说明。角色范围仅包含管理员设置的"角色范围"中已启用的角色。
- 申请功能权限：展示可申请应用的功能权限树，与现有功能权限设置组件一致但范围只限管理员设置的"应用范围"。顶部提示"提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。"

点击提交后，系统进行校验，通过则提交成功，失败则展示阻断提示。

**系统反馈：**

- 申请原因为空时提交按钮置灰或有字段校验提示
- 提交成功：toast "申请已提交"，抽屉关闭，"申请记录"中新增一条"审批中"记录
- 校验失败：具体提示哪项校验未通过，以及如何补救

**建议文案：**

- 申请人标签："申请人"
- 申请原因 placeholder："请填写申请原因"
- 申请角色下方无角色时："暂无可申请的角色"
- 申请功能权限顶部提示："提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。"
- 提交按钮："提交申请"

**下一步：**

提交成功后回到"我的权限"页面，可在"申请记录"中跟踪审批状态。
```

```text
节点 2.6：审批人处理申请

**用户动作：**

审批人在待办列表中看到"员工申请权限"的待办事项。点击进入申请详情页，展示申请人的姓名、申请时间、申请原因、申请内容（角色名称列表或功能权限详情）。审批人查看后点击"同意"或"拒绝"。

拒绝时可填写拒绝原因（建议但不强制）。

**系统反馈：**

- 同意：toast "已同意"，系统自动完成权限分配，员工收到通知
- 拒绝：toast "已拒绝"，员工收到通知，通知中附带拒绝原因（如有填写）

**需要前置解释的信息：**

- 申请内容区展示为只读卡片，不可编辑
- 如果申请的是功能权限，"查看详情"展开功能权限列表
- 审批人可能需要看到申请人的组织、岗位等上下文信息来辅助判断 [GAP：当前材料未明确审批人可见的上下文范围]

**建议文案：**

- 同意按钮："同意"
- 拒绝按钮："拒绝"
- 拒绝原因 placeholder："请填写拒绝原因（选填）"
```

## 4. 次交互流程

**超管编辑已启用的模式：**

已启用页面默认只读，展示当前配置摘要和"关闭模式""编辑"两个按钮。点击"编辑"进入编辑态——按钮区变为"取消编辑""确认编辑"，页面恢复为可编辑的三步设置。点击"确认编辑"校验后 toast "编辑成功"，页面回到只读态。点击"取消编辑"回到只读态且不保存。

**超管关闭模式：**

点击"关闭模式"弹出二次确认弹窗——标题"关闭模式"，文案"关闭模式后，员工将无法自助查询和申请权限，请确认是否关闭自助申请模式？"，按钮"不关闭""确认关闭"。确认关闭时校验在途流程——如有在途流程，提示当前数量并确认（UXB 建议改为允许关闭但提示，而非阻断）。关闭成功 toast "关闭「自助申请权限模式」成功"。

**员工撤销申请：**

申请记录列表中，审批中状态的行展示"撤销"按钮。点击撤销，该申请单状态变为"已撤销"。撤销后该条记录保留在列表中，但不再支持重新操作（撤销按钮消失）。[GAP：撤销后能否对同一权限重新提交申请]

**员工查看申请详情：**

申请记录中申请内容列——如申请的是角色则直接展示角色名称，如申请的是功能权限则展示"查看详情"链接。点击"查看详情"打开静态抽屉，展示提交申请时的表单内容（只读快照）。

## 5. 异常与阻断流程

```text
异常 A：超管启用时被模式互斥阻断

**发生时机：** 超管在宣传页点击"立即启用"或设置页点击"启用"时
**触发条件：** 企业已开启双管理员互审模式或权限变更审批模式
**判断依据：** business_blueprint_lite 确认两个模式互斥为合理设计
**反馈形式：** 弹窗阻断
**系统反馈：** "企业已开启「双管理员互审模式」，不能同时开启此模式。如需开启自助申请模式，请先关闭双管理员互审模式。"
**用户下一步：** 点击"知道了"关闭弹窗，前往对应模式页面关闭互斥模式后再回来启用
```

```text
异常 B：超管关闭时被在途流程阻断

**发生时机：** 超管在关闭确认弹窗中点击"确认关闭"后
**触发条件：** 当前存在审批中的申请单
**判断依据：** business_blueprint_lite 建议改为提示而非阻断
**反馈形式：** 弹窗提示
**系统反馈：** 当前设计为阻断弹窗："当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。"UXB 建议改为提示+确认："当前有 X 条申请正在审批中，关闭模式后这些申请将继续走完审批流程，但员工将无法提交新申请。确认关闭？"
**用户下一步：** 确认关闭或取消
```

```text
异常 C：员工提交申请时被校验规则阻断

**发生时机：** 员工点击"提交申请"后
**触发条件：** 触发资金用户校验、子管理员模式校验、特殊身份校验或实名要求校验中的任一规则
**判断依据：** 需求文档列出的四项校验规则
**反馈形式：** 弹窗或字段级提示（取决于校验类型）
**系统反馈：** 针对每项校验给出具体原因。如资金用户校验："您不是资金用户，不能申请「代发付款」相关权限。"[GAP：其余三项校验的具体文案未在材料中说明]
**用户下一步：** 根据提示调整申请内容或放弃申请
```

```text
异常 D：审批人不存在

**发生时机：** 员工提交申请后，系统尝试路由申请给组织负责人时
**触发条件：** 员工所在组织无负责人，或负责人已离职/停用
**判断依据：** business_blueprint_lite 确认此为关键风险
**反馈形式：** 提交时提示员工 + 管理端提示超管
**系统反馈：** 员工侧：提交时给出提示"当前无法确定您的审批人，请联系企业管理员处理"。超管侧：在自助申请模式页面展示警告"部分员工的审批人已失效，建议检查组织负责人设置"。[GAP：审批人兜底路由的具体交互——是自动转给超管还是让管理员手动指定——待确认]
**用户下一步：** 员工联系管理员，管理员去组织架构中设置组织负责人
```

```text
异常 E：可申请范围为空

**发生时机：** 员工点击"申请权限"打开抽屉时
**触发条件：** 管理员设置的可申请范围中没有已启用的角色或应用
**判断依据：** 需求文档中的范围控制规则
**反馈形式：** 抽屉内空状态
**系统反馈：** "暂无可申请的权限，请联系企业管理员。"
**用户下一步：** 关闭抽屉，联系管理员
```

```text
异常 F：申请时被审批人拒绝

**发生时机：** 审批人点击"拒绝"后
**触发条件：** 审批人认为申请不合理
**判断依据：** 业务规则定义
**反馈形式：** 通知 + 申请记录状态更新
**系统反馈：** 员工收到通知"您的权限申请已被拒绝"（附带拒绝原因），申请记录状态更新为"已拒绝"
**用户下一步：** 查看拒绝原因，视情况重新提交或联系审批人沟通 [GAP：拒绝后能否对同一权限重新提交申请]
```

## 6. 页面 / 弹窗 / 抽屉设计

```text
页面：自助申请模式设置页（管理端）

**页面目标：** 让超管完成自助申请模式的三步配置并启用
**进入条件：** 从权限管理模式选择"自助申请权限模式"，且通过互斥模式校验
**页面结构：**
- 顶部：分步指示器（第一步·申请方式 → 第二步·设置范围 → 第三步·审批流程）
- 中间：当前步骤的设置内容区
- 底部：取消 + 启用按钮

**状态反馈区：**
- 分步指示器高亮当前步骤，已完成步骤可点击回看
- 选择"部分角色/部分应用"时，已选数量实时显示在选择器旁

**异常状态下的结构变化：**
- 启用被阻断时弹出阻断弹窗，页面不变
- 已启用态：整个页面变为只读，分步指示器隐藏，改为展示当前配置摘要卡片

**具体文案：**
- 页面标题："自助申请权限模式"
- 模式说明："员工可自助申请权限，工作流审批通过后，系统将自动分配权限"
- 了解更多链接："了解更多"（跳转帮助文档）

**按钮：**
- 未启用态：取消（次要按钮）+ 启用（主要按钮）
- 已启用态：关闭模式（次要按钮）+ 编辑（主要按钮）
```

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 未启用 | 自助申请模式未开启 | 超管 | 进入设置、启用 | "自助申请权限模式未开启" |
| 配置中 | 正在三步设置中但未最终启用 | 超管 | 完成配置、取消 | 分步指示器显示进度 |

## 8. 待确认问题

1. **审批人兜底路由的具体交互**

   影响：当组织负责人不存在时，申请如何流转——是自动转给超管、还是让管理员手动指定兜底审批人、还是阻断员工提交。直接影响员工申请提交的体验和超管的感知方式。
   建议确认方：产品

2. **撤销后能否对同一权限重新提交申请**

   影响：如果可以无限制重新提交，审批人可能被反复打扰；如果完全禁止，员工可能因操作失误而无法获得需要的权限。需要明确是否设冷却期或次数限制。
   建议确认方：产品

3. **我的权限页面是否展示权限来源**

   影响：员工看到一条权限时是否需要知道"这是管理员直接给我的"还是"我自己申请获得的"。影响信息架构的简洁度 vs 透明度。
   建议确认方：产品 + 设计

4. **审批人可见的上下文信息范围**

   影响：审批人在决定是否同意时，除了申请内容本身，是否需要看到申请人所在组织、岗位、已有权限等信息。影响审批详情页的信息密度。
   建议确认方：产品

5. **拒绝后是否强制填写原因**

   影响：如果拒绝原因选填，员工可能收到空白拒绝而不知道如何改进。如果强制填写，可能增加审批摩擦。建议拒绝原因为选填但界面引导填写。
   建议确认方：产品 + 设计
