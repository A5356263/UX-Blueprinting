# Background

- Project ID: self-service-permission
- Task Name: 员工自助申请权限
- Domain: 权限管理

## 1. 领域背景

本次需求属于权限管理领域。权限管理是一个规则密集、状态敏感、可审计的业务领域，核心价值是为权限判断、来源解释、冲突定位和治理追踪提供稳定输入。

## 2. 当前权限体系概况

### 2.1 权限来源模型

当前权限来源包括：
- ACL_DIRECT：个人直授，来自用户授权页
- RBAC_ROLE：角色授予，来自角色管理
- APP_VISIBILITY：应用可见性，来自应用管理/应用设置
- COLLAB_VISIBILITY：协作可见性，来自成员协作权限

治理修饰层（GOVERNANCE_MODE）影响是否生效、谁能改、何时生效，但不改变授予事实来源。

### 2.2 决策链路

权限结果判断顺序：可见性门槛(L0) → 功能权限(L1) → 数据权限(L2) → 治理与生效(L3)

最终表达式：final_effective_rule = VisibilityGate AND FunctionGrant AND DataScope AND GovernanceState

### 2.3 治理状态模型

当前治理触发点：双管理员模式、权限变更审批模式、子管理员范围隔离、成员停用/删除/离职

标准状态：draft → pending → approved/rejected → effective → revoked

子管理员模式与双管理员模式不可同时开启。

### 2.4 业务对象

权限判断至少涉及七类对象：主体(subject)、资源(resource)、动作(action)、范围(scope)、来源(source)、修饰因子(modifier)、状态(state)。

## 3. 本次需求在体系中的位置

本次新增"自助申请"作为一种新的权限来源路径，在来源模型中对应新增 SELF_SERVICE_APPLICATION 来源类型。该来源路径下的权限经过审批后自动生效，属于治理状态模型的完整链路。

## 4. 能力承载现状

当前权限域主要能力承载页面：
- 用户直授：用户授权、功能授权、数据授权、权限详情
- 角色授权：角色管理、授权规则
- 全局治理：权限管理模式、子管理配置页、双管理员模式配置页、权限变更审批模式配置页
- 查询排障：权限查询、按用户查询结果

本次新增能力需要确定承载页面归属，可能在全局治理下新增配置页，同时在员工侧新增申请入口。

## 5. 已知风险

- 多来源叠加导致来源不透明
- 覆盖规则导致结果违背直觉
- 治理模式导致生效不确定
- 新增来源类型可能增加权限溯源的复杂度
- 审批中台闭环未完成会导致结构性断链
