## 任务概述

本次需求是在现有权限体系中新增一条"员工自助申请权限"的授权链路。当前权限只能由管理员或超级管理员直接授予，员工没有主动查看和申请权限的渠道。中大型企业中人员流动频繁，权限申请依赖线下沟通，授权时效不稳定，管理员侧处理压力大。

目标是让员工可以查看自己的权限、主动申请所需角色（通过审批后自动获得权限）、查看申请记录。管理员可以控制是否开启自助申请、员工可以申请的角色范围（白名单）、审批流程，以及关闭该能力时如何处理在途申请。

涉及三个角色：超级管理员 / 权限管理员（配置方）、员工（申请方）、审批人（审批方）。

核心场景：
1. 管理员配置自助申请模式（开启、设白名单、设审批）
2. 员工查看自己的权限
3. 员工申请权限角色
4. 审批人处理申请
5. 管理员关闭自助申请能力

## 功能范围

### 管理端：自助申请配置

管理员可以在权限管理中找到"自助申请权限"的配置入口，开启后需要设置：
- **可申请角色白名单**：哪些角色员工可以申请。不在白名单中的角色不可见。超级管理员角色和子管理员角色不在白名单候选范围内。
- **审批配置**：选择审批流程或默认审批人。默认审批人为员工所在组织的直接组织负责人。
- **数据权限预设**：每个角色已绑定的数据权限范围在申请通过后自动授予，不需要员工选择和配置。
- **关闭自助申请**：关闭时不回收已授予权限，默认继续走完已在审批中的申请。

使用方：超级管理员 / 权限管理员
优先级：P0

### 员工端：我的权限

员工在个人工作台或个人中心可以查看自己当前拥有的权限概览：
- 功能权限列表（按应用聚合）
- 角色信息
- 每条权限标记来源（管理员授予 / 角色继承 / 自助申请）
- 如果缺少权限，提供"申请权限"的入口

同时在权限不足的页面（如空状态、操作被禁），提供场景化的"申请权限"快捷入口。

使用方：员工
优先级：P0

### 员工端：申请权限

员工提交权限申请的流程：
1. 从可申请角色白名单中选择需要的角色
2. 填写申请原因
3. 提交后，系统自动流转给审批人
4. 申请通过后，系统自动为该员工授予角色及其关联的功能权限和数据权限
5. 员工可以查看申请记录和当前审批状态

申请状态流转：草稿（可选） → 审批中 → 已通过 / 已拒绝 → 已撤销（可选）

使用方：员工
优先级：P0

### 审批端：审批处理

审批人收到审批通知后：
- 查看申请内容：申请人、申请角色、申请原因
- 决定：同意（自动授权）或 拒绝（填写拒绝原因）
- 审批人默认为员工所在组织的直接组织负责人
- 组织负责人不存在/离职时：转给审批主管
- 超时未处理：超时后自动转给上级或将申请标记为异常，通知管理员处理

使用方：审批人（默认组织负责人/审批主管）
优先级：P0

## 关键业务规则

### R-001 白名单控制
员工只能申请管理员白名单中的角色。不在白名单中的角色员工不可见。超级管理员角色和子管理员角色不在白名单候选范围内。

### R-002 数据权限预设
数据权限不开放员工自选。每个角色绑定的数据权限范围由管理员预设，申请通过后自动随角色授予。

### R-003 审批前置
所有权限申请必须经过审批才能生效。没有绕过审批的路径。

### R-004 自动授权
审批通过后，系统自动为员工授予角色及其关联的功能权限和数据权限，新权限来源标记为 SELF_SERVICE_APPLICATION。

### R-005 关闭不回收
管理员关闭自助申请能力时，不回收员工已经通过申请获得的权限。如需回收，管理员应走权限回收流程。

### R-006 关闭时在途保护
管理员关闭自助申请能力时，默认继续走完已在审批中的申请，不影响在途审批。

### R-007 审批人分级兜底
直接组织负责人为默认审批人。组织负责人不存在时，转审批主管处理。均不可用时，申请标记为异常，通知管理员人工处理。

### R-008 与双管理员互审互斥
自助申请模式与双管理员互审模式建议互斥。启用自助申请时，双管理员互审模式不应同时开启。

### R-009 来源标识
通过自助申请获得的权限必须在权限详情中标记来源标识，与管理员直接授予和角色继承的权限区分。

## 状态流转

### 自助申请生命周期

```
[管理员配置开启] → 员工可见申请入口
    ↓
员工提交申请 → 状态：审批中
    ↓
审批人处理 → 通过 → 状态：已通过 → 系统自动授权 → 权限生效
              → 拒绝 → 状态：已拒绝 → 通知申请人（含拒绝原因）
```

可选状态：审批人处理前可撤销 → 已撤销

### 自助申请模式生命周期

```
[管理员开启] → 配置白名单和审批规则 → 模式：已启用
    ↓
管理员关闭 → 回收配置入口 → 模式：已关闭
    ↓
    ├─ 影响入口：员工端不再显示申请入口
    ├─ 不影响已获权限：已通过申请的权限保留
    └─ 不影响在途：审批中的申请继续完成
```

## 异常与边界

### 场景1：可申请角色白名单为空
- 发生场景：管理员开启了自助申请但没有配置任何可申请角色
- 系统反馈：员工端申请入口可见，但选择角色时展示空状态，提示"暂无可申请的角色，请联系管理员配置"
- 管理员侧应有提示：开启前至少添加一个可申请角色

### 场景2：审批人不存在或离职
- 触发条件：员工提交申请后，系统发现默认审批人（组织负责人）不存在或已离职
- 系统行为：自动转给审批主管；审批主管也不存在时，申请标记为异常
- 用户如何处理：管理员在后台看到异常申请，人工指定审批人或手动处理

### 场景3：审批超时未处理
- 触发条件：审批人在规定时间内未处理申请
- 系统行为：发送提醒通知；超时后自动转给上级审批人
- 用户如何处理：无上级或上级也不处理的，标记异常转管理员人工处理

### 场景4：关闭能力时存在在途申请
- 触发条件：管理员关闭自助申请模式
- 系统行为：默认继续完成在途审批，新申请入口关闭
- 管理员可见提示：当前存在 X 笔在途申请，关闭后将继续完成

### 场景5：员工申请已拥有的角色
- 触发条件：员工申请了一个已拥有的角色
- 系统行为：提示"您已拥有该角色"，阻止重复申请
- 边界：如果角色已拥有的权限中数据权限范围发生过变更，不影响已有权限

### 场景6：服务人员申请
- 边界：第一期不开放服务人员使用该能力。服务人员不显示申请入口。
- 若误操作进入申请流程：提示"当前暂不支持自助申请权限"

## 依赖与前置条件

### 已有权限体系依赖
- 权限域已有的角色管理、功能授权、数据授权页
- 已有的权限来源模型（新增 SELF_SERVICE_APPLICATION）
- 已有的决策链契约（L0 可见性 → L1 功能权限 → L2 数据权限 → L3 治理）
- 已有的权限详情页需要扩展来源标识

### 审批系统依赖
- 需要接入审批中台的审批流、审批通知、审批处理能力
- 需要审批中台支持审批人不存在/离职的异常兜底
- 需要审批中台支持超时提醒和自动转派

### 组织架构依赖
- 审批人默认为员工直接组织负责人
- 依赖组织架构中"组织负责人"字段的正确性
- 审批主管回退依赖组织维度中"审批主管"的配置数据

## 开放问题与缺口

- [GAP] 审批中台与权限域的具体对接方式（审批流是在审批中台配置还是在权限域配置）暂不确定，待审批中台对接阶段确认
- [GAP] 员工端"我的权限"页面的具体入口位置和交互层级未最终确定，待体验蓝图阶段细化
- [GAP] 申请记录页是否需要单独的页面还是在"我的权限"中共用入口未确定
- [QUESTION] 审批通知渠道（站内信、邮件、企微/钉钉等）未明确
