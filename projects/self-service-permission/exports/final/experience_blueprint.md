# Experience Blueprint：员工自助申请权限

> 承接自：facts.md（任务概述、功能范围、状态流转、异常与边界）、business_blueprint.md（推荐方案、风险、承接要求）

## 0. 本次关键设计判断

**判断：**

本次体验方案围绕三条角色链路展开——管理员配置、员工申请、审批人处理。核心设计原则是：入口场景化、申请简单化、状态可视、异常兜底。

**主要影响：**

1. 管理员配置端：在权限管理模式中新增"自助申请权限"模式选项，与现有子管理员模式、双管理员互审模式、权限变更审批模式并列
2. 员工端：新增"我的权限"页面（个人工作台/个人中心），新增"申请权限"流程，权限不足页面增加场景化入口
3. 审批端：复用审批中台，审批通知包含申请详情和申请人

**建议方案：**

- 管理端配置采用 Page 承载（与现有治理模式 Tab 结构一致）
- 员工端"我的权限"用 Page，"申请权限"用 Drawer（不脱离员工上下文）
- 审批处理复用审批中台的能力，不单独建页
- 权限来源标签：在权限详情中区分"管理员授予"、"角色：XX"、"自助申请"

**不建议方案：**

- 把员工端的"我的权限"做成弹窗/Modal：权限信息密度高，需要列表和详情查阅，Modal 空间不够
- 在权限域内单独建审批页：审批中台已有成熟能力，复用即可

**关键待确认：**

- "我的权限"入口是在个人工作台还是个人中心，取决于整体导航层级设计

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

```md
- 管理员：在权限管理中发现没有自助申请配置入口 → 开启模式并配置白名单和审批 → 确认配置生效
- 员工：打开系统发现没有需要的权限 → 找到申请入口 → 选择角色并提交 → 等待审批并通过后获得权限
- 审批人：收到审批通知 → 查看申请详情 → 同意/拒绝 → 确认处理完成
```

### 旅程缺口

- 缺少员工端入口的具体菜单位置依据，影响起点判断
- 缺少审批通知渠道（站内信/邮件/企微）的确认，影响通知流程表达

## 2. 交互流程总览

**分角色交互流程：**

- 管理员：进入权限管理模式 → 选择自助申请权限模式 → 节点 3.1 配置白名单和审批规则 → 确认启用
- 员工：发现权限不足或主动查看权限 → 进入我的权限页 → 节点 3.3 提交权限申请 → 等待审批 → 查看申请结果
- 审批人：收到通知 → 节点 3.6 处理申请 → 同意或拒绝 → 结果通知申请人

**异常流程重点：**

- 审批人不存在或离职时的申请流转
- 审批超时未处理时的提醒和转派
- 模式关闭时存在在途申请的处理
- 员工重复申请已拥有角色的拦截

## 3. 主交互流程

```text
节点 3.1：管理员开启自助申请权限模式

**用户动作：**

管理员在权限管理模式列表中找到"自助申请权限"模式卡片，点击启用。

**系统反馈：**

如果管理员未配置白名单和审批规则，弹出提示"开启前请先配置可申请角色和审批规则"并引导到配置页。如果已配置，直接启用。

**需要前置解释的信息：**

- 开启后员工将看到申请入口
- 员工只能申请白名单中的角色
- 关闭后已获得的权限不回收
- 建议与双管理员互审模式互斥

**建议文案：**

- 卡片标题："自助申请权限"
- 卡片描述："开启后，员工可以主动申请所需权限，通过审批后自动获得授权。管理员可控制可申请范围和审批流程。"
- 提示文案："开启前请先配置可申请角色白名单和审批规则"

**下一步：**

进入自助申请权限配置页
```

```text
节点 3.2：管理员配置白名单和审批规则

**用户动作：**

在配置页中：
1. 从已有角色列表中添加可申请角色（超级管理员角色和子管理员角色不可选）
2. 选择审批方式：默认组织负责人 / 自定义审批流
3. 确认保存

**系统反馈：**

- 保存成功时提示"配置已保存"
- 白名单为空时保存按钮不可用，提示"至少添加一个可申请角色"
- 审批方式未选择时提示"请选择审批方式"

**需要前置解释的信息：**

- 超级管理员和子管理员角色不可加入白名单
- 数据权限不开放员工自选，随角色自动授予
- 组织负责人不存在时将转审批主管处理

**建议文案：**

- 页面标题："自助申请权限配置"
- 白名单区标题："可申请角色"
- 白名单区提示："选择员工可以自助申请的角色。不在白名单中的角色员工不可见。"
- 审批区标题："审批规则"
- 审批区选项："默认组织负责人" / "自定义审批流"

**下一步：**

保存后退回权限管理模式列表
```

```text
节点 3.3：员工发起权限申请

**用户动作：**

员工在"我的权限"页面或权限不足的快捷入口进入申请表单，选择需要的角色（白名单中可见的角色），填写申请原因（必填），点击提交。

**系统反馈：**

- 提交成功时提示"申请已提交，请等待审批"
- 如果员工已拥有该角色，提示"您已拥有该角色"并阻止提交
- 如果白名单为空（异常状态），提示"暂无可申请的角色，请联系管理员"

**需要前置解释的信息：**

- 只能申请列表中可见的角色（管理员已开放的）
- 审批通过后才能获得权限
- 申请原因请如实填写，方便审批人判断

**建议文案：**

- 页面标题："申请权限"
- 角色选择器标签："选择角色"
- 申请原因标签："申请原因"
- 提交按钮："提交申请"
- 取消按钮："取消"
- 成功提示："申请已提交，请等待审批"
- 重复提示："您已拥有该角色权限"

**下一步：**

提交后跳转到申请记录页或我的权限页
```

```text
节点 3.4：审批人收到审批通知

**用户动作：**

审批人通过审批中台/通知入口查看待审批的权限申请。
- 看到申请人信息、申请角色、申请原因、申请时间
- 审核申请内容是否合理

**系统反馈：**

- 审批中台队列中出现新的待审批项
- 发送通知给审批人（站内信，以及企微/钉钉/邮件等外部渠道待确认）

**需要前置解释的信息：**

- 审批人默认为员工直接组织负责人
- 审批人需要基于申请角色和原因判断是否合理

**建议文案：**

- 审批队列标题："权限申请审批"
- 申请详情标题："申请详情"
- 申请人字段："申请人：{姓名}"
- 申请角色字段："申请角色：{角色名称}"
- 申请原因字段："申请原因：{原因}"
- 申请时间字段："申请时间：{时间}"

**下一步：**

审批人决定同意或拒绝
```

```text
节点 3.5：审批人处理申请（同意）

**用户动作：**

审批人点击"同意"，系统自动完成授权。

**系统反馈：**

- 为该员工自动授予角色及角色关联的功能权限和数据权限
- 申请状态更新为"已通过"
- 通知申请人"您的权限申请已通过"
- 通知中可包含"查看我的权限"快捷链接

**需要前置解释的信息：**

- 同意后权限即时生效
- 授权来源标记为"自助申请"

**建议文案：**

- 按钮文案："同意"
- 成功提示："已同意，权限已自动授予"
- 申请入通知："您申请的角色 {角色名称} 已通过审批，权限已生效"

**下一步：**

审批人继续处理其他申请或回到审批列表
```

```text
节点 3.6：审批人处理申请（拒绝）

**用户动作：**

审批人点击"拒绝"，填写拒绝原因（必填）。

**系统反馈：**

- 申请状态更新为"已拒绝"
- 通知申请人"您的权限申请未通过"
- 说明拒绝原因

**需要前置解释的信息：**

- 拒绝后员工可以重新申请或联系审批人了解更多信息

**建议文案：**

- 按钮文案："拒绝"
- 拒绝原因标签："拒绝原因"
- 拒绝原因占位提示："请说明拒绝的具体原因..."
- 拒绝按钮确认文案："确定拒绝"
- 申请人通知："您申请的角色 {角色名称} 未通过审批。原因：{拒绝原因}"

**下一步：**

员工查看拒绝原因后，可重新申请或放弃
```

## 4. 次交互流程

```text
节点 4.1：管理员关闭自助申请权限模式

**用户动作：**

管理员在权限管理模式中对该模式执行关闭操作。

**系统反馈：**

如果存在在途申请，弹出确认弹窗提示：
- "当前有 X 笔申请正在审批中。关闭后，新申请入口将关闭，已有在途申请将继续走完审批流程。"
- 按钮："确认关闭" / "取消"
如果无在途申请，直接关闭。

关闭后：
- 员工端申请入口不再显示
- 已通过申请获得的权限不受影响
- 管理员配置的白名单和审批规则保留但不生效

**建议文案：**

- 有在途申请时的确认文案："关闭自助申请权限后，员工将无法提交新的权限申请。已有 {X} 笔在途申请将继续完成审批，已获得的权限不受影响。"

**下一步：**

关闭后退出到权限管理模式列表
```

```text
节点 4.2：员工查看申请记录

**用户动作：**

员工在"我的权限"页面或申请记录页面查看历史申请。

**系统反馈：**

展示申请列表，每条包含：
- 申请角色、申请时间、当前状态（审批中 / 已通过 / 已拒绝）
- 已通过的：显示"已生效"，展示获得的具体权限
- 已拒绝的：显示"未通过"，展示拒绝原因
- 可点击查看详情

**需要前置解释的信息：**

- 审批中的申请预计审批人是谁
- 已拒绝的申请可重新提交

**建议文案：**

- 页面标题："申请记录"
- 状态标签色：审批中（蓝色）、已通过（绿色）、已拒绝（红色）
```

```text
节点 4.3：员工在权限不足页面触发快捷申请

**用户动作：**

员工在某个页面或功能点遇到权限不足的提示，页面上显示"申请权限"按钮，点击后直接进入申请流程。

**系统反馈：**

自动带入上下文：如果可识别到缺少的是某个角色的权限，在申请表单中默认选中该角色（如果该角色在白名单中）。

**建议文案：**

- 权限不足提示："您暂无该功能的操作权限。"
- 快捷按钮："申请权限"

**下一步：**

进入申请表单
```

## 5. 异常与阻断流程

```text
异常 5.1：白名单为空

**发生时机：** 管理员开启模式但未添加可申请角色
**触发条件：** 管理员开启模式时白名单为空
**判断依据：** facts.md R-001
**反馈形式：** 提示弹窗 + 配置页面按钮禁用
**系统反馈：** "请先添加至少一个可申请角色"
**用户下一步：** 前往白名单配置，添加角色

员工端同时展示空状态："暂无可申请的角色，请联系管理员配置"
```

```text
异常 5.2：审批人不存在或离职

**发生时机：** 员工提交申请后寻找审批人时
**触发条件：** 默认组织负责人不存在、已离职或岗位为空
**判断依据：** facts.md R-007
**反馈形式：** 系统自动流转
**系统反馈：** 自动转给审批主管；审批主管也不存在时，申请标记为异常并通知管理员
**用户下一步：** 管理员收到异常通知后，手动指定审批人或处理申请
```

```text
异常 5.3：审批超时

**发生时机：** 审批人在规定时间内未处理
**触发条件：** 超过预设的审批超时时间
**判断依据：** facts.md 异常与边界
**反馈形式：** 系统自动处理
**系统反馈：** 发送超时提醒给当前审批人；超时后自动转派给上级审批人
**用户下一步：** 无有效上级时标记异常，由管理员处理
```

```text
异常 5.4：关闭模式时存在在途申请

**发生时机：** 管理员关闭模式
**触发条件：** 模式关闭时存在审批中的申请
**判断依据：** facts.md R-006
**反馈形式：** 确认弹窗
**系统反馈：** 弹窗提示在途数量，确认后继续审批
**用户下一步：** 管理员确认关闭，或取消操作
```

```text
异常 5.5：员工重复申请

**发生时机：** 员工提交申请时
**触发条件：** 员工已拥有该角色
**判断依据：** facts.md 异常与边界
**反馈形式：** 表单字段提示
**系统反馈：** 提示"您已拥有该角色权限"
**用户下一步：** 员工取消操作或选择其他角色
```

```text
异常 5.6：服务人员访问

**发生时机：** 服务人员尝试进入申请入口
**触发条件：** 当前用户身份为服务人员
**判断依据：** facts.md 异常与边界
**反馈形式：** 页面提示
**系统反馈：** "暂不支持自助申请权限"
**用户下一步：** 联系管理员
```

## 6. 页面 / 弹窗 / 抽屉设计

```text

- 页面标题："自助申请权限配置"
- 模式开关标签："启用自助申请权限"
- 白名单区标题："可申请角色"
- 审批规则标题："审批方式"

- 返回按钮："返回"

**按钮：** 保存（主要）、返回（次要）
```

```text
- 来源标签："来源：管理员授予" / "来源：角色：HR专员" / "来源：自助申请"

**按钮：** 申请权限（主要）
```

```text
页面：申请记录（员工端）

**页面目标：** 员工查看历史申请记录和当前状态
**页面结构：**
- 申请列表：按时间倒序排列
- 每条记录展示：角色名称、申请时间、状态标签（审批中/已通过/已拒绝）

**具体文案：**
- 页面标题："申请记录"
- 状态标签：审批中（蓝色标签）、已通过（绿色标签）、已拒绝（红色标签）
- 空状态："暂无申请记录"
- 拒绝原因前缀："原因：{原因}"

**按钮：** 无（只读页）
**成功反馈：** 无
**失败反馈：** 无
```

## 7. 状态与反馈文案

```md
| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 审批中 | 申请已提交，等待审批人处理 | 员工 | 可查看，不可撤销 | "申请已提交，正在等待审批" |
| 已通过 | 审批通过，权限已生效 | 员工 | 可查看权限详情 | "申请已通过，权限已生效" |
| 已拒绝 | 审批不通过 | 员工 | 可查看拒绝原因 | "申请未通过：{拒绝原因}" |
| 模式已开启 | 自助申请能力可用 | 管理员 | 可配置白名单和审批规则 | "自助申请权限已开启" |
| 模式已关闭 | 自助申请能力关闭 | 管理员 | 可重新开启 | "自助申请权限已关闭" |
| 权限不足 | 员工无权操作某个功能 | 员工 | 可申请权限 | "您暂无该功能的操作权限" |
```

## 8. 待确认问题

1. **员工端入口位置**

   影响："我的权限"放在个人工作台还是个人中心，影响页面层级和导航结构。个人工作台入口访问更直接，个人中心更符合信息组织习惯。
   建议确认方：产品 / 设计

2. **审批通知渠道**

   影响：审批人通过什么渠道收到通知（站内信、邮件、企微/钉钉等），影响体验方案中的通知流程设计。
   建议确认方：产品

3. **审批中台对接方式**

   影响：审批流配置界面是在权限域内嵌还是在审批中台完成，影响管理端配置页的交互复杂度。
   建议确认方：产品 / 技术
