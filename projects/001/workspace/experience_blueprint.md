# Experience Blueprint

## 1. 交互流程总览

本次体验围绕三类用户展开：

**超管 / 权限管理员**：在权限管理模式中开启并配置"自助申请权限模式"，决定员工能申请什么类型的权限、能申请哪些角色或应用、由谁审批。

**员工**：在个人中心查看自己当前拥有的权限，在需要时提交权限申请，跟踪申请进度。

**审批人**：收到审批待办后，同意或拒绝员工的权限申请。

主流程分为三条：

- 超管配置流程：进入权限管理模式 → 点击立即启用 → 选择申请方式 → 配置可申请范围 → 配置审批流程 → 开启成功
- 员工申请流程：进入个人中心 → 我的权限 → 申请权限 → 填写申请内容 → 提交申请 → 查看申请记录
- 审批人审批流程：收到待办 → 同意或拒绝

异常流程重点关注：
- 互斥模式已开启时不能启用自助申请权限模式
- 关闭模式时存在在途审批流程，关闭失败
- 员工提交申请时校验不通过
- 申请记录的各种状态反馈（审批中、已通过、已拒绝、已撤销）

## 2. 主交互流程

### 流程 A：超管开启自助申请权限模式

#### 节点 A1：进入权限管理模式页

用户动作：
超管进入管理后台的权限管理模式页面，了解"自助申请权限模式"的作用和影响。

系统反馈：
页面展示该模式的说明：员工可以自助查询和申请权限，审批通过后系统自动分配权限。

本节点需要前置解释：
- 开启后，员工会在个人中心看到"我的权限"入口
- 权限申请通过后，系统会自动分配权限，无需超管手动操作
- 该模式不能与"双管理员互审模式"和"权限变更审批模式"同时开启

建议页面文案：
```
员工可自助申请权限，工作流审批通过后，系统将自动分配权限。
```

按钮：
- 立即启用
- 了解更多（跳转帮助文档）

下一步：
超管点击"立即启用"。

---

#### 节点 A2：点击"立即启用"— 互斥校验

用户动作：
超管点击"立即启用"。

系统反馈：
系统校验企业是否已开启"双管理员互审模式"或"权限变更审批模式"。

正常结果：
未开启互斥模式时，进入自助申请权限模式设置页（模式此时仍未启用）。

异常结果：
如果企业已开启任一互斥模式，阻断启用。

异常提示文案：
```
企业已开启「双管理员互审模式」，不能同时开启此模式。
```

用户下一步：
如果是异常情况，超管需要先关闭互斥模式，再返回此处重新启用。

---

#### 节点 A3：设置页 — 选择申请方式

用户动作：
超管在设置页的第一步，选择员工后续可以申请什么类型的权限。

页面提供两个互斥选项：
- 申请角色
- 申请功能权限

默认选中"申请角色"。

本节点需要前置解释：
- 选择"申请角色"后，员工申请通过会自动关联角色。适合主要通过角色授权的企业。
- 选择"申请功能权限"后，员工申请通过会自动获得对应功能权限。适合主要按应用和功能直接授权的企业。
- 这个选择会决定员工申请页面展示的内容类型，以及第二步配置的内容。

选项说明文案：
```
申请角色：申请通过后，员工将自动关联上申请角色。适合企业主要通过角色授权的场景。
申请功能权限：申请通过后，员工将自动获得对应功能权限。适合企业主要按应用和功能直接授权的场景。
```

下一步：
超管做出选择后，进入第二步。

---

#### 节点 A4：设置页 — 配置可申请范围

用户动作：
超管配置员工可以申请的角色范围或应用范围。

如果选择了"申请角色"：
进入"设置角色范围"。选项：全部角色、部分角色。默认"全部角色"。选择"部分角色"时打开角色选择弹窗，支持搜索角色、分页展示、显示角色名称/说明/状态。设置项："后续新增角色自动加入员工可申请的范围"（默认勾选）。

如果选择了"申请功能权限"：
进入"设置应用范围"。选项：全部应用、部分应用。默认"全部应用"。选择"部分应用"时打开应用选择弹窗，支持搜索应用、分页展示、显示应用名称/终端/启用状态。设置项："后续新增应用自动加入员工可申请的范围"（默认勾选）。

本节点需要前置解释：
- 员工只能申请这里配置过的角色或应用
- 已启用和已停用的角色/应用都在可选范围内
- 如果勾选了自动加入，后续新增的角色/应用会自动进入可申请范围
- 敏感角色和敏感组织不应进入可申请范围 [GAP：需求中尚未明确敏感角色清单]

页面文案：
```
请选择允许员工自助申请的角色。未包含在范围内的角色，员工无法提交申请。
```
或
```
请选择允许员工自助申请权限的应用。未包含在范围内的应用，员工无法提交申请。
```

下一步：
超管完成范围配置后，进入第三步。

---

#### 节点 A5：设置页 — 配置审批流程

用户动作：
超管查看或修改员工申请权限时的审批流程。

系统反馈：
系统默认预设审批人为员工所在组织的组织负责人。

本节点需要前置解释：
- 员工提交申请后，会进入审批流程
- 审批通过后，系统才会自动分配权限
- 如需调整审批人，可以点击"修改审批流程"跳转到表单编辑页

页面文案：
```
系统已预设「员工申请权限」时的审批流程，默认审批人为员工所在组织的组织负责人。如需调整，可点击修改审批流程。
```

主要操作：
- 修改审批流程（打开子页面）

下一步：
超管完成审批流程配置后，点击底部"开启"。

---

#### 节点 A6：点击"开启"

用户动作：
超管完成三项配置后，点击"开启"。

系统反馈：
系统再次校验互斥模式（双管理员互审模式、权限变更审批模式）。

成功结果：
- toast 提示：`自助申请权限模式已开启。`
- 页面刷新为"已开启"状态
- 展示提示语和操作按钮
- 个人中心增加"我的权限"入口
- 员工可以开始提交权限申请

已开启状态页面文案：
```
此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。
```

按钮：
- 关闭模式
- 编辑
- 帮助文档

异常结果：
如果互斥模式已开启，阻断并提示冲突。

---

### 流程 B：员工查看权限

#### 节点 B1：进入个人中心

用户动作：
员工进入个人中心。

系统反馈：
如果企业已开启自助申请权限模式，在"我的企业"下方展示"我的权限"入口。

展示规则：
- 已开启模式的企业用户：展示"我的权限"
- 未开启模式的企业用户：不展示
- 服务人员账号：不展示

---

#### 节点 B2：进入"我的权限"

用户动作：
员工点击"我的权限"。

系统反馈：
进入"我的权限"独立页面。页面包含三个 tab：
- 功能权限（默认选中）
- 数据权限
- 角色

每个 tab 展示对应的权限数据。如果某个 tab 下没有数据，展示空状态。

空状态文案：
- 功能权限 tab 无数据：`您没有功能权限。`
- 数据权限 tab 无数据：`您没有数据权限。`
- 角色 tab 无数据：`您没有关联的角色。`

页面同时提供"申请权限"入口和申请记录入口。

---

### 流程 C：员工申请权限

#### 节点 C1：点击"申请权限"

用户动作：
员工点击"申请权限"按钮。

系统反馈：
打开"申请权限"抽屉。

抽屉内容：
- 申请人：默认当前用户名称，不可编辑
- 申请原因：必填字段，提示词"请填写申请原因"，最多 500 字
- 申请内容区：根据管理端配置展示"申请功能权限"或"申请角色"
- 提交按钮

---

#### 节点 C2：填写申请内容

用户动作：
员工选择要申请的功能权限或角色，并填写申请原因。

如果管理端配置为"申请角色"：
展示角色列表（仅已启用且在管理端配置范围内的角色），列表字段为勾选项、角色名称、角色说明。

如果管理端配置为"申请功能权限"：
展示功能权限设置组件，应用范围仅限管理端配置的应用。

本节点需要前置解释：
- 员工只能选择管理端配置范围内的内容，看不到未开放申请的角色或应用
- 申请功能权限时，默认申请该功能的所有数据权限。如果只需要部分数据权限，需要联系管理员单独授权

申请功能权限提示文案：
```
提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。
```

---

#### 节点 C3：提交申请

用户动作：
员工填写完申请内容后，点击"提交"。

系统反馈：
系统发起审批流程，并进行提交校验。校验内容包括：资金用户校验、子管理员模式权限校验、特殊身份默认权限校验、实名要求校验。

成功反馈：
```
申请已提交，请等待审批。
```

校验失败反馈：
```
当前申请内容不满足授权条件，请调整申请内容后重新提交。
```

下一步：
员工可以回到申请记录查看审批进度。

---

#### 节点 C4：查看申请记录

用户动作：
员工进入申请记录页面。

系统反馈：
页面提供筛选区和申请记录列表。

筛选条件：
- 申请日期
- 审批状态（已通过、已拒绝、审批中、已撤销）

列表字段：
- 申请时间（年月日 时分秒）
- 申请原因
- 申请内容：申请角色时展示角色名称，申请功能权限时展示"查看详情"链接（点击打开静态详情抽屉）
- 审批状态：已通过、已拒绝、审批中、已撤销

操作规则：
- 审批中：可点击"撤销"
- 其他状态：撤销按钮不可用

## 3. 次交互流程

### 流程 D：超管编辑已开启模式

用户动作：
超管在已开启状态页点击"编辑"。

系统反馈：
页面进入可编辑状态。"关闭模式"和"编辑"按钮隐藏，底部出现"取消编辑"和"确认编辑"按钮。

确认编辑后 toast 提示：
```
编辑成功。
```

取消编辑后回到已开启状态。

### 流程 E：超管关闭模式

用户动作：
超管点击"关闭模式"。

系统反馈：
打开二次确认弹窗。

弹窗标题：`关闭模式`

弹窗正文：
```
关闭模式后，员工将无法自助查询和申请权限，请确认是否关闭自助申请模式？
```

按钮：不关闭 / 确认关闭

点击"确认关闭"后，系统校验是否存在在途审批流程。如果有，关闭失败，弹窗提示：
```
当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。
```

关闭成功 toast：
```
关闭「自助申请权限模式」成功。
```

### 流程 F：员工查看申请详情

用户动作：
员工在申请记录中点击"查看详情"（仅申请功能权限时出现）。

系统反馈：
打开静态详情抽屉，展示当时提交的申请内容——包括申请的权限范围和申请原因。

### 流程 G：员工撤销申请

用户动作：
员工在审批中的申请记录上点击"撤销"。

系统反馈：
申请单状态变更为"已撤销"，撤销按钮消失。

## 4. 异常与阻断流程

### 异常 1：互斥模式已开启，不能启用

发生时机：超管点击"立即启用"或"开启"时。

触发条件：企业已开启"双管理员互审模式"或"权限变更审批模式"。

系统反馈：
```
企业已开启「双管理员互审模式」，不能同时开启此模式。
```

用户下一步：超管需要先关闭互斥模式，再重新尝试启用自助申请权限模式。

---

### 异常 2：关闭模式时存在在途审批

发生时机：超管点击"关闭模式"并确认关闭。

触发条件：当前存在申请流程未完成审批。

弹窗反馈：
标题：`关闭失败`
正文：`当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。`
按钮：`知道了`

用户下一步：等待审批人处理完在途流程后，再次尝试关闭模式。

---

### 异常 3：提交申请时校验不通过

发生时机：员工点击"提交"时。

触发条件：
- 非资金用户申请"代发付款"
- 子管理员申请子管理员模式权限
- 不满足实名要求
- 特殊身份默认权限冲突

系统反馈：
```
当前申请内容不满足授权条件，请调整申请内容后重新提交。
```

用户下一步：员工根据提示调整申请内容，重新提交。如果涉及无法自行处理的问题（如实名要求），需要联系管理员。

---

### 异常 4：申请记录为空

发生时机：员工进入申请记录页，但从未提交过申请。

系统反馈：展示空状态提示和占位图。

建议文案：
```
暂无申请记录。如需申请权限，请点击"申请权限"。
```

## 5. 页面 / 弹窗 / 抽屉设计

### 页面：自助申请权限模式介绍页

页面目标：让超管了解该模式的作用、效果和限制条件，决定是否启用。

页面结构：
- 模式说明区：功能简介 + 使用效果说明
- 互斥规则提示：不能与其他两个模式同时开启
- 操作区

具体文案：
正文：`员工可自助申请权限，工作流审批通过后，系统将自动分配权限。`

按钮：
- `立即启用`（主按钮）
- `了解更多`（次按钮，跳转帮助文档）

---

### 页面：自助申请权限模式设置页

页面目标：让超管完成申请方式、可申请范围、审批流程三项配置。

页面结构（三步式）：
- 第一步：选择员工申请权限的方式（申请角色 / 申请功能权限）
- 第二步：设置角色范围 或 设置应用范围（取决于第一步选择）
- 第三步：设置审批流程
- 底部操作区：取消、开启

具体文案：
第一步标题：`选择员工申请权限的方式`
第二步角色范围标题：`设置角色范围`
第二步应用范围标题：`设置应用范围`
第三步标题：`设置审批流程`

第二步提示：`请选择允许员工自助申请的角色。` / `请选择允许员工自助申请权限的应用。`

第三步提示：`系统已预设「员工申请权限」时的审批流程，预设审批人为员工所在组织的组织负责人。如需调整，可点击修改审批流程。`

按钮：
- `取消`（次按钮）
- `开启`（主按钮）
- `修改审批流程`（链接按钮）

成功反馈：`自助申请权限模式已开启。`
失败反馈：`企业已开启「双管理员互审模式」，不能同时开启此模式。`

---

### 页面：已开启状态页

页面目标：让超管确认模式已开启，了解当前状态，并支持关闭或编辑。

页面结构：
- 已开启提示语
- 当前配置内容摘要
- 操作区

具体文案：
提示语：`此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。`

按钮：
- `关闭模式`（次按钮）
- `编辑`（次按钮）
- `帮助文档`（链接按钮）

---

### 弹窗：关闭模式二次确认

触发条件：超管点击"关闭模式"。

弹窗结构：
- 标题：`关闭模式`
- 正文说明
- 两个按钮

具体文案：
正文：`关闭模式后，员工将无法自助查询和申请权限，请确认是否关闭自助申请模式？`
按钮：`不关闭` / `确认关闭`

---

### 弹窗：关闭失败提示

触发条件：确认关闭时检测到在途审批流程。

具体文案：
标题：`关闭失败`
正文：`当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。`
按钮：`知道了`

---

### 抽屉：申请权限

页面目标：让员工提交权限申请。

页面结构：
- 申请人：默认当前用户，不可编辑
- 申请原因：必填文本域，500 字上限
- 申请内容区（功能权限或角色）
- 操作区

具体文案：
申请人标签：`申请人`
申请原因提示：`请填写申请原因`
功能权限提示：`提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。`

按钮：
- `提交`（主按钮）
- `取消`（次按钮）

成功反馈：`申请已提交，请等待审批。`
失败反馈：`当前申请内容不满足授权条件，请调整后重新提交。`

### 页面：我的权限

页面目标：让员工查看自己当前拥有的权限和角色。

页面结构：
- 三个 tab：功能权限、数据权限、角色
- 默认选中"功能权限"tab
- "申请权限"入口
- 申请记录入口

空状态文案：
- 功能权限：`您没有功能权限。`
- 数据权限：`您没有数据权限。`
- 角色：`您没有关联的角色。`

### 页面：申请记录

页面目标：让员工查看申请进度和结果。

页面结构：
- 筛选区：申请日期、审批状态
- 列表区：申请时间、申请原因、申请内容、审批状态、操作
- 分页

审批状态选项：`审批中`、`已通过`、`已拒绝`、`已撤销`

操作规则：审批中状态展示"撤销"按钮，其他状态不展示。

## 6. 状态与反馈文案

### 状态：模式未启用

含义：企业还没有开启自助申请权限模式。

用户可做：超管可以进入权限管理模式，点击"立即启用"。

页面反馈：员工端不展示"我的权限"和"申请权限"入口。超管端展示介绍页。

---

### 状态：设置中

含义：超管已进入设置页，但还没有点击"开启"，模式尚未生效。

用户可做：超管继续配置申请方式、范围和审批流程。

页面反馈：员工端暂时看不到任何变化。超管端展示设置页。

---

### 状态：已开启

含义：自助申请权限模式已生效。

用户可做：
- 超管：可以编辑配置、关闭模式
- 员工：可以在个人中心查看和申请权限
- 审批人：可以收到并处理审批待办

页面反馈：
```
此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。
```

---

### 状态：审批中

含义：员工已提交申请，审批人还未处理。

用户可做：员工可以查看申请记录；在审批中状态可以撤销申请。

页面反馈：
```
申请已提交，请等待审批。
```

---

### 状态：已通过

含义：审批人已同意申请，系统已自动分配权限。

用户可做：员工可以查看已获得的权限。无需其他操作。

页面反馈：
```
申请已通过，权限已生效。
```

---

### 状态：已拒绝

含义：审批人拒绝了申请。

用户可做：员工可以查看拒绝原因，调整后重新提交申请。

页面反馈：
```
申请已拒绝。你可以查看拒绝原因后重新提交申请。
```

---

### 状态：已撤销

含义：员工在审批中主动撤销了申请。

用户可做：撤销后不可恢复。如需申请，需要重新提交。

页面反馈：申请记录中状态展示为"已撤销"，撤销按钮消失。

---

### 状态：关闭失败

含义：超管尝试关闭模式时，存在在途审批流程。

用户可做：等待审批人处理完在途流程后再次关闭。

页面反馈：
```
当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。
```

## 7. 待确认问题

- 审批流程的具体规则未明确（是否支持多级审批、会签、超时处理等），会影响审批端的交互设计和状态定义
- 敏感角色和敏感组织清单未提供，如需在可申请范围中排除，需要对应配置界面
- 埋点具体口径未提供，当前体验方案暂不涉及埋点交互
- 操作记录的展示方式和字段未明确，当前体验方案暂不涉及
- 帮助文档内容需要产品侧补充，当前暂用"了解更多"和"帮助文档"占位链接
- OA 审批中"可发起人去掉"和"默认复核人员风险"两个备注的含义和处理方式需要确认
