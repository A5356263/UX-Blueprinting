# Facts

> 输入来源：projects/permission-dimension-query/source/requirement.md、projects/permission-dimension-query/source/background.md

## 1. 核心需求事实

- [FACT] 用户主体：权限管理员（日常核对，最高频使用者）、超级管理员（全局审计与异常排查）、审计/安全管理人员（高风险权限分布检查）
- [FACT] 当前场景：管理员需要核对"某个人有哪些权限""某个角色包含什么权限""某项权限被哪些人拥有""某个表单或报表被谁持有"时，必须在权限管理、应用管理、审批管理、报表管理、OA 表单等多个功能域的设置页面之间来回切换、逐项查找
- [FACT] 当前卡点：各域的权限结构和颗粒度不同，没有统一的查询入口。按用户查虽有独立入口，但按角色查仅部分可行（依赖角色管理页），按权限反查存在明确缺口 `[GAP]`，OA 表单和报表维度的统一查询尚未建立
- [FACT] 当前处理方式：管理员在各域设置页面内各自查看权限列表，手动拼凑一个人的完整权限画像，效率低且容易遗漏
- [FACT] 不解决的后果：权限核对和审计依赖管理员个人经验而非系统工具，异常授权、过度授权、敏感权限扩散难以及时发现，对高安全诉求企业构成合规风险
- [CONFIRMED] 用户目标：在统一入口中，从用户、角色、权限、OA 表单、报表五个维度查询权限归属关系，每条权限能追溯到来源和生效状态
- [CONFIRMED] 已明确约束：查询页负责解释不负责配置；查询入口本身需要受控，普通用户不应查看全员权限分布；不同业务域的权限颗粒度不同，结果不宜强行套用同一字段结构；不支持导出、模糊搜索、权限验证模式；敏感权限查询不需要二次确认

## 2. 功能范围

> 以下为需求涉及的五个查询维度，均为新增功能。是否全部纳入本期由 business 阶段定案，按分析收敛建议分期建设。

### 2.1 用户维度查询

- 使用角色：权限管理员（受限范围）、超级管理员（全局范围）、审计/安全人员（按需开放 `[GAP]`）
- 操作目标：查询指定用户拥有的全部权限
- 输入：用户名
- 输出：该用户的所有权限清单，按权限类型分组展示，每条标注来源和生效状态
- 结果：管理员能一次性看到指定用户的完整权限画像，覆盖功能权限和数据权限
- [CONFIRMED] 一期纳入，高优先级

### 2.2 角色维度查询

- 使用角色：权限管理员、超级管理员
- 操作目标：查询指定角色包含的全部权限
- 输入：角色名
- 输出：该角色包含的所有权限清单，覆盖功能权限、数据权限及其他细分权限
- 结果：管理员能判断角色配置是否合理、是否包含高风险权限
- [GAP] 如果角色被多个用户使用，是否在查询结果中展示影响范围
- [CONFIRMED] 一期纳入，高优先级

### 2.3 权限维度查询

- 使用角色：权限管理员、超级管理员
- 操作目标：反查拥有某项指定权限的用户列表
- 输入：权限项名称或标识
- 输出：拥有该权限的用户列表，可核对敏感权限的授权范围
- 结果：管理员能确认某项权限的影响范围，用于安全排查
- [GAP] 需求文档内部优先级不一致（截图标注为高优先级，汇总表标注为中优先级）
- [GAP] 是否只查直接拥有者，还是包含通过角色、组织等间接获得权限的用户
- [CONFIRMED] 一期后半段或二期纳入，待间接授权口径确认

### 2.4 OA 表单维度查询

- 使用角色：权限管理员、超级管理员
- 操作目标：查询拥有某个指定表单权限的用户列表
- 输入：表单名称或标识
- 输出：拥有该表单权限的用户列表
- 结果：管理员能明确哪些人可以查看、处理或管理指定表单
- [GAP] 表单权限、字段权限、表单管理权限、数据权限是否全部纳入查询范围
- [GAP] 数据权限按表单数据属性隔离时，查询结果是否展示具体数据范围
- [CONFIRMED] 二期纳入

### 2.5 报表维度查询

- 使用角色：权限管理员、超级管理员
- 操作目标：查询拥有某个指定报表权限的用户列表
- 输入：报表名称或标识
- 输出：拥有该报表权限的用户列表
- 结果：管理员能明确哪些人可以查看、操作或管理指定报表
- [GAP] 报表权限、报表管理权限、操作权限、数据权限是否全部纳入查询范围
- [GAP] 数据权限按单张报表数据属性隔离时，是否展示具体数据范围
- [CONFIRMED] 二期纳入

## 3. 关键业务规则

> 本次为查询类能力，本身不新增独立业务规则。以下为查询能力必须遵守的已有规则承接和边界约束。

### 3.1 查询入口访问控制

- 触发条件：管理员访问查询入口或提交查询请求
- 处理结果：校验管理员身份和查询范围——第一层校验入口可见性（菜单是否展示），第二层校验查询范围（能否查询该对象）
- 不满足时：入口不可见时不展示菜单项；查询范围不足时阻断查询并提示原因
- 关联约束：依赖已有管理员角色体系；具体哪些角色能访问查询能力尚未定义 `[GAP]`；管理范围按组织架构还是角色分组定义尚未确认 `[GAP]`

### 3.2 查询结果来源展示

- 触发条件：查询结果中包含任意权限条目
- 处理结果：每条权限必须标注来源类型（直接授权 / 角色授权 / 应用可见性 / 协作可见性），展示生效状态（已生效 / 未生效 / 已暂停）
- 不满足时：如果来源追溯链路不完整或无法确定来源，应明确标注"来源未知"而非伪造一个来源
- 关联约束：基于知识库已有来源模型（ACL_DIRECT / RBAC_ROLE / APP_VISIBILITY / COLLAB_VISIBILITY）和治理修饰因子（GOVERNANCE_MODE）；来源展示粒度（只标类型还是展示完整链路）尚未确认 `[GAP]`

### 3.3 查询与配置职责分离

- 触发条件：管理员在查询结果中发现权限问题需要调整
- 处理结果：查询页不提供直接修改权限的能力。如果需要调整，管理员需回到对应配置页（用户授权、角色管理等）操作
- 不满足时：不提供配置入口时，管理员需要记住查询结果再导航到配置页，流程可能断裂
- 关联约束：查询结果是否提供跳转到权限调整页面的入口尚未确认 `[GAP]`

### 3.4 跨域权限颗粒度差异

- 触发条件：查询结果中包含来自不同域的权限条目
- 处理结果：管理类功能权限按"应用 > 菜单 > 操作"展示，OA 表单权限按"表单 > 字段"展示，报表权限按"报表 > 操作/数据"展示，不强行统一字段结构
- 不满足时：如强行套用同一字段模板，不同域的权限语义会丢失，管理员会误读
- 关联约束：知识库对象模型（主体/资源/动作/范围/来源/修饰因子/状态）作为各域权限的统一解释框架，但各域的"资源"和"动作"具体取值可以不同

## 4. 状态流转

本次为查询类能力，不涉及独立业务状态流转。查询结果中涉及的权限生效状态（已生效 / 未生效 / 已暂停）来自已有权限域状态模型，查询能力只反映这些状态，不改变它们。

查询页自身的交互状态流转（未查询 → 查询中 → 有结果/空结果/查询失败）属于页面交互状态，由 experience 阶段设计。

## 5. 异常与边界

| 异常 / 边界 | 触发条件 | 系统处理 | 用户是否有补救路径 | 备注 |
| --- | --- | --- | --- | --- |
| 查询权限不足 | 管理员尝试查询超出自身管理范围的用户或角色 | 阻断查询，告知权限不足及原因 | 是，联系具有更广查询权限的管理员 | 具体阻断方式（弹窗/内嵌提示）由 experience 设计 `[GAP]` |
| 查询对象不存在 | 输入的用户名或角色名在系统中不存在 | 提示未找到该对象 | 是，检查输入或确认对象是否已删除/离职 | |
| 查询结果为空 | 查询合法但该对象当前无任何已生效权限 | 展示空结果状态，与查询失败明确区分 | 是，可前往用户授权页为该对象分配权限 | |
| 查询服务异常 | 网络超时、服务异常、数据源不可用 | 展示错误状态，提供重试入口 | 是，重试或等待后重试 | |
| 跨域数据口径不一致 | 不同域的权限数据存在口径差异，导致同一对象在不同维度下的查询结果看起来矛盾 | 查询结果中标注数据来源域和查询口径说明 `[GAP]` | 是（通过阅读口径说明理解差异） | 需求文档未描述该场景 `[GAP]` |
| 大批量结果 | 查询对象（如超级管理员角色）包含大量权限或关联大量用户 | 结果按权限类型分组折叠，默认只展开第一组 `[GAP]` | 是，手动展开/折叠分组 | 分页、折叠的具体策略由 experience 阶段细化 `[GAP]` |

## 6. 依赖与前置条件

- [CONFIRMED] 外部系统依赖：依赖已有权限管理体系各域的权限数据（用户授权、角色管理、应用管理、审批管理、报表管理、OA 表单）；依赖组织底座中的成员数据、组织视图、岗位数据作为权限归属判断的上游输入
- [CONFIRMED] 已有能力边界：按用户查已有独立入口，是最完整的解释链路；按角色查依赖角色管理页，独立查询语义未完全明确；按权限查/按功能点查是明确缺口；查询页负责解释不负责配置的边界已明确
- [CONFIRMED] 必须复用的底座能力：权限域对象模型（主体/资源/动作/范围/来源/修饰因子/状态）、来源模型（ACL_DIRECT / RBAC_ROLE / APP_VISIBILITY / COLLAB_VISIBILITY）、治理修饰因子（GOVERNANCE_MODE）、已有管理员角色体系
- [CONFIRMED] 不允许新增的概念 / 能力：不允许新增独立的权限来源类型；不允许在查询页嵌入权限修改能力；不允许绕过已有管理员角色体系做访问控制
