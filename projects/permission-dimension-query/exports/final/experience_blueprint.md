# 体验蓝图

> 输入来源：projects/permission-dimension-query/workspace/business_blueprint.md

## 0. 本次关键设计判断

**判断：**

本次体验方案的核心策略是"单一入口 + 维度切换 + 来源渐进披露 + 访问控制前置阻断"。不是做五个查询页面，而是在一个查询中心里让管理员用统一的心智模型完成跨维度查询，同时用渐进披露解决来源信息密度和认知负担的平衡问题。

**主要影响：**

1. 五个维度的查询入口需要在同一个页面内通过维度切换承载，不能拆成五个独立页面
2. 来源追溯是体验核心差异点——既要让管理员看到权限从哪来，又不能被过多信息淹没
3. 访问控制必须在操作前就体现限制（匹配建议过滤、查询范围说明），而不是等提交后再弹窗告知"你没权限"

**建议方案：**

- 单一查询入口 + Tab 维度切换 + 统一结果卡片模型
- 来源采用"标签 + 点击展开"的渐进披露，默认展示获得方式类型，点击展开完整链路
- 访问被拒时在操作前通过匹配范围过滤和前置说明控制预期，提交后被阻断时告知原因和申诉路径
- 查询结果按权限类型分组折叠，默认展开第一组

**不建议方案：**

- 五个维度各自独立页面（违背统一查询的核心目标，延续查询分裂的已知风险）
- 来源链路全部平铺在结果列表（信息密度过高，管理员反而会忽略来源信息）

**关键待确认：**

1. 查询结果是否提供跳转至权限调整页面的入口——直接影响结果卡片是否需要"去调整"按钮
2. 一期具体维度范围——当前方案按用户+角色设计交互，如果权限维度在一期内纳入需补充反查维度的交互

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- 权限管理员：发现权限归属不明确 → 进入统一查询中心 → 选择查询维度 → 输入并确认查询对象 → 查看查询结果（含来源标注） → 展开某条权限的来源详情 → 按需前往配置页调整 → 切换维度继续查询或结束
- 超级管理员：接到全局审计任务 → 进入统一查询中心 → 跨范围查询任意用户或角色 → 查看结果 → 发现异常授权或过度授权 → 追踪完整来源链路 → 形成审计结论或通知责任人调整
- 审计/安全人员：收到审计或安全排查要求 → 进入查询中心 → 在授权范围内查询 → 核对权限分布情况 → 形成审计报告

### 旅程缺口

- 审计/安全人员的查询入口是否默认可见，还是需要单独申请开通——影响审计角色的起点是否成立
- 查询结果到配置页的跳转路径是否成立——影响"按需前往配置页调整"节点是否保留

## 2. 交互流程总览

**分角色交互流程：**

- 权限管理员：在导航中看到"权限查询"入口 → 节点 3.1 进入统一查询中心 → 节点 3.2 选择查询维度并输入查询对象 → 节点 3.3 查看查询结果 → 节点 3.4 展开来源详情 → 节点 4.1 切换维度继续查询 → 或节点 4.2 跳转至配置页调整 → 结束
- 超级管理员：在导航中看到"权限查询"入口 → 节点 3.1 进入统一查询中心 → 节点 3.2 选择查询维度并输入查询对象 → 节点 3.3 查看查询结果 → 节点 3.4 展开来源详情 → 必要时查询更多对象 → 结束
- 审计/安全人员：在导航中看到"权限查询"入口（或通过授权开通后可见） → 节点 3.1 进入统一查询中心 → 节点 3.2 在授权范围内查询 → 节点 3.3 查看查询结果 → 结束

**异常流程重点：**

- 查询权限不足：管理员在输入阶段被匹配建议过滤拦截，或提交后被阻断并告知申诉路径
- 查询对象不存在：输入无匹配结果或提交后提示对象不存在
- 查询结果为空：合法查询但对象无任何权限，区分于查询失败
- 查询服务异常：网络超时或系统异常，提供重试入口
- 大批量结果：结果按类型分组折叠，默认只展开第一组

## 3. 主交互流程

### 节点 3.1：进入统一查询中心

**用户动作：**

管理员在权限管理导航中点击"权限查询"，进入统一查询中心。

**系统反馈：**

页面加载，展示查询维度选择区和查询输入区。默认选中"按用户查"。页面标题区显示功能名称和简短说明。如果管理员因访问控制看不到某些维度，对应 Tab 不显示。

**需要前置解释的信息：**

管理员需要知道这个页面能查什么、不能查什么——当前查询的是"谁有什么权限"和"某个角色包含什么权限"，不包含导出和批量对比能力。搜索范围受管理员自身权限限制，只能搜索自己管理范围内的用户和角色。

**建议文案：**

- 页面标题：权限查询
- 页面说明：从用户或角色维度查看权限归属关系，查询结果仅用于核对和审计，不提供直接修改权限的能力
- 维度 Tab 标签：按用户查 / 按角色查

**下一步：**

管理员选择维度后进入输入环节（节点 3.2）。

### 节点 3.2：选择查询维度并输入查询对象

**用户动作：**

管理员确认当前选中的查询维度（默认"按用户查"），在搜索框中输入用户名或角色名。输入过程中系统提供匹配建议。

**系统反馈：**

- 正常结果：输入框下方出现匹配建议列表，每项显示名称和简要标识（用户显示所属部门，角色显示成员数量预览）。搜索范围受管理员自身权限限制——超出管理范围的用户/角色不出现在匹配建议中。
- 异常结果：若输入内容无匹配结果，建议列表为空，输入框下方提示"未找到匹配的用户，请检查输入是否正确，或确认该用户是否在你的管理范围内"。
- 如果管理员通过精确输入绕过了建议列表（输入了完整用户名但该用户不在管理范围内），提交后返回阻断提示。

**需要前置解释的信息：**

匹配建议只展示管理员有权查看的用户和角色。如果管理员不确定某人是否在管理范围内，输入看看能否匹配到就能知道。

**建议文案：**

- 用户维度输入框占位符：输入用户名搜索
- 角色维度输入框占位符：输入角色名搜索
- 匹配建议-用户附属信息：所属部门 · 在职
- 匹配建议-角色附属信息：成员 128 人
- 无匹配提示（用户维度）：未找到匹配的用户，请检查输入是否正确，或确认该用户是否在你的管理范围内
- 无匹配提示（角色维度）：未找到匹配的角色，请检查输入是否正确

**下一步：**

管理员从匹配建议中选中目标，进入查询等待和结果展示（节点 3.3）。

### 节点 3.3：查看查询结果

**用户动作：**

管理员选中查询对象后，系统开始查询。加载过程中管理员等待。

**系统反馈：**

- 正常结果（有数据）：查询完成后展示结果页。结果按权限类型分组——功能权限、数据权限——每组默认折叠，组标题显示该组权限数量。第一组默认展开。展开后以卡片列表展示，每条卡片包含：权限名称、权限描述（如有）、获得方式标签、生效状态标签。
- 正常结果（无数据）：展示空结果状态，明确说明该对象当前没有任何权限，与查询失败区分。提供前往用户授权页的按钮（如适用）。
- 异常结果（查询失败）：展示错误状态，提供重试入口。使用页面内嵌状态而非弹窗，因为查询失败导致整个结果区域不可用。

**需要前置解释的信息：**

结果中每条权限会标注是通过什么方式获得的（如"直接授予""通过角色 XX 获得""应用可见范围""协作可见范围"），这是理解权限从哪来的关键信息。同一条权限可能有多个获得方式，展示时合并标注。如果权限因为管理规则被暂停或尚未生效，会在状态标签中体现。

权限按类型分组展示——不同域的权限描述方式不同，这是正常的。管理功能权限会展示到菜单和操作级别，表单权限展示到表单和字段级别。

**建议文案：**

- 结果页标题："张三"的权限清单
- 结果页副标题：共 23 条权限 · 来自 3 种获得方式
- 分组标题示例：功能权限（15）、数据权限（6）
- 卡片-权限名称示例：删除员工档案
- 卡片-获得方式标签：直接授予 / 通过角色"华东区管理员"获得 / 应用可见范围 / 协作可见范围
- 卡片-生效状态标签：已生效 / 未生效（审批中）/ 已暂停（管理规则限制）
- 空结果标题：该用户当前没有任何权限
- 空结果说明：该用户尚未被分配权限，或所有权限已被收回、暂停或尚未生效
- 空结果按钮：前往用户授权
- 错误状态标题：查询失败
- 错误状态说明：服务暂时不可用，请稍后重试。如持续失败，请联系技术支持
- 错误状态按钮：重新查询
- 加载中状态：正在查询...

**下一步：**

管理员查看结果后，可以展开具体权限的获得方式详情（节点 3.4），或切换维度继续查询（节点 4.1），或跳转至配置页（节点 4.2）。

### 节点 3.4：展开来源详情

**用户动作：**

管理员点击某条权限的获得方式标签，展开来源详情。

**系统反馈：**

来源详情在卡片内内嵌展开，不跳转页面也不弹出浮层。展开后显示：获得方式类型、来源对象名称（如具体角色名）、如果可以追溯到授权人则展示授权人姓名和授权时间（待确认）。如果同一条权限有多个获得方式，全部列出并说明最终结果取并集。

**需要前置解释的信息：**

如果权限来自角色，这里展示具体的角色名称。如需调整权限，应去对应的角色管理页面操作，而不是在这里直接改。如果权限来源涉及系统默认规则或自动授权规则，也会在此说明。

**建议文案：**

- 来源详情标题：权限获得方式
- 来源条目示例：通过角色"华东区管理员"获得 · 由李四配置 · 2024-01-15
- 来源条目示例 2：直接授予 · 由王五配置 · 2024-03-20
- 多来源说明：该权限有 2 种获得方式，最终结果取并集
- 跳转入口（如 business 确认支持）：前往角色管理页调整 →
- 关闭方式：再次点击来源标签收起

**下一步：**

管理员查看完来源详情后收起展开区，回到结果列表。可以继续查看其他权限的来源，或进行下一步操作。

## 4. 次交互流程

### 节点 4.1：切换查询维度

**用户动作：**

管理员在当前结果页切换到另一个维度的 Tab（如从"按用户查"切换到"按角色查"）。

**系统反馈：**

清空当前查询输入和结果，回到输入状态。输入框占位符随维度变化。不保留上一次的查询结果，避免误以为不同维度的结果可以直接对比。

**下一步：**

回到节点 3.2（输入查询对象）。

### 节点 4.2：从查询结果跳转至权限配置页

> 前提：business 中"查询结果是否提供跳转入口"为待确认。本节点按"提供跳转"的前提设计。如确认为不提供，则移除此节点。

**用户动作：**

管理员在结果页点击某条权限旁的"去调整"入口，或点击来源展开区底部的跳转入口。

**系统反馈：**

新标签页打开对应的权限配置页面（如用户授权页、角色管理页），定位到对应条目。查询页保留当前状态，管理员可以配置完成后再切回来对照。

**建议文案：**

- 跳转按钮：去调整
- 来源展开区跳转入口：前往角色管理页调整

**下一步：**

管理员在新标签页完成配置后，可切回查询页继续查看。

### 节点 4.3：展开 / 折叠结果分组

**用户动作：**

管理员点击结果分组标题，切换该组的展开/折叠状态。

**系统反馈：**

点击折叠时，组内卡片收起，组标题保留权限数量。点击展开时，组内卡片展开。

**下一步：**

继续查看当前分组内容，或切换其他分组。

## 5. 异常与阻断流程

### 异常 E1：查询权限不足

**发生时机：** 管理员提交查询请求时。

**触发条件：** 管理员尝试查询超出自身管理范围的用户或角色。例如，权限管理员只能查自己部门内的人，但输入了其他部门的员工或超级管理员的完整用户名。

**判断依据：** 基于 business "访问控制是硬约束"规则——查询入口的访问控制必须做两层：入口可见性 + 查询范围限制。

**反馈形式：** 页面内嵌提示，显示在输入框下方。不使用弹窗——因为管理员不是操作失误，而是查询了不在范围内的对象，内嵌提示更轻量也更贴近操作位置。

**系统反馈：** 无法查询该用户的权限，该用户不在你的管理范围内。如需查询，请联系具有更广查询权限的管理员。

**用户下一步：** 管理员可以联系超级管理员申请扩大查询范围，或输入其他用户重试。

### 异常 E2：查询对象不存在

**发生时机：** 管理员提交查询请求时。

**触发条件：** 输入的用户名或角色名在系统中完全不存在。在匹配建议阶段已体现为无匹配结果，但如果管理员通过精确输入绕过了建议列表，提交后会命中此异常。

**判断依据：** 基于 facts 异常与边界中"查询对象不存在"场景。

**反馈形式：** 输入框下方内嵌提示。

**系统反馈：** 未找到名为"XXX"的用户，请检查输入是否正确。

**用户下一步：** 修改输入内容重试，或联系管理员确认该用户是否已离职/已删除。

### 异常 E3：查询结果为空

**发生时机：** 查询成功执行但该对象确实没有任何权限。

**触发条件：** 查询对象存在且管理员有权查看，但该对象当前没有任何已生效的权限。可能是因为该用户尚未被分配权限，或所有权限已被收回、暂停或尚未生效。

**判断依据：** 基于 business "查询结果必须区分'无权限'和'查询失败'"规则。

**反馈形式：** 结果区域展示空状态页，配说明文字和操作建议。使用页面内嵌状态而非 toast，因为"没有结果"是当前查询的正常结局，不是系统错误。

**系统反馈：**

- 标题：该用户当前没有任何权限
- 说明：该用户尚未被分配权限，或所有权限已被收回、暂停或尚未生效
- 操作按钮：前往用户授权（打开用户授权页）

**用户下一步：** 如确认该用户应该有权限，可前往用户授权页为其分配权限。

### 异常 E4：查询服务异常

**发生时机：** 查询提交后，服务端返回错误。

**触发条件：** 网络超时、服务异常、数据源不可用等。

**判断依据：** 通用系统异常处理。

**反馈形式：** 结果区域展示错误状态，配重试按钮。使用页面内嵌状态而非 toast，因为查询失败导致整个结果区域不可用，需要明确的重新操作入口。

**系统反馈：**

- 标题：查询失败
- 说明：服务暂时不可用，请稍后重试。如持续失败，请联系技术支持
- 操作按钮：重新查询

**用户下一步：** 点击重试，或等待后重新查询。

### 异常 E5：大批量结果

**发生时机：** 查询已执行，但返回结果数据量过大。

**触发条件：** 查询对象包含大量权限（如超级管理员角色包含数百条权限）或关联大量用户。

**判断依据：** 基于 business "大批量结果导致页面不可用"风险。

**反馈形式：** 结果按权限类型分组折叠展示，默认只展开第一组，其余组折叠。组标题显示该组权限数量，让管理员快速判断规模。如果单组内条目仍然过多（如超过 30 条），组内提供筛选或搜索能力。

**系统反馈：** 结果摘要中显示总数，分组标题显示组内数量，折叠组用数量暗示规模。不需要额外的"结果过多"提示——分组折叠本身就是应对策略。

**用户下一步：** 管理员根据需要展开关注的分组，或在组内筛选定位。

## 6. 页面 / 弹窗 / 抽屉设计

### 页面：统一查询中心（权限查询）

**页面目标：**

为管理员提供一站式权限查询入口，支持从用户和角色维度查看权限归属关系。管理员在此完成"输入对象 → 查看结果 → 理解来源"的完整核对任务。

**进入条件：**

- 管理员已登录，且拥有查询能力访问权限
- 入口在权限管理导航中可见（访问控制第一层——入口可见性）
- 普通用户和无查询权限的管理员看不到此入口

**页面结构：**

```
+----------------------------------------------------+
| 页面标题区：标题"权限查询" / 说明文字                 |
+----------------------------------------------------+
| 维度切换区：Tab"按用户查" | "按角色查"                  |
+----------------------------------------------------+
```

**状态反馈区：**

- 结果摘要栏：查询成功后有结果时展示
- 空结果状态区：查询成功但无结果时替换结果区内容
- 错误状态区：查询失败时替换结果区内容
- 输入框下方提示区：权限不足和对象不存在时展示内嵌提示
- 加载状态：查询执行中在结果区展示加载动画

**异常状态下的结构变化：**

- 权限不足：不改变页面结构，在输入框下方增加内嵌阻断提示
- 对象不存在：不改变页面结构，在输入框下方增加内嵌提示
- 查询结果为空：结果摘要栏和分组列表替换为空状态页
- 查询失败：结果摘要栏和分组列表替换为错误状态页

**具体文案：**

- 页面标题：权限查询
- 页面说明：从用户或角色维度查看权限归属关系，查询结果仅用于核对和审计
- Tab 标签：按用户查、按角色查
- 搜索框占位符（用户维度）：输入用户名搜索
- 搜索框占位符（角色维度）：输入角色名搜索
- 结果摘要："{对象名}"的权限清单 · 共 {N} 条权限 · 来自 {M} 种获得方式
- 分组标题：功能权限（{N}）、数据权限（{N}）
- 获得方式标签：直接授予、通过角色"{角色名}"获得、应用可见范围、协作可见范围
- 生效状态标签：已生效、未生效、已暂停
- 来源展开-角色来源：通过角色"{角色名}"获得 · 由 {授权人} 配置 · {日期}
- 来源展开-直接授予：直接授予 · 由 {授权人} 配置 · {日期}
- 多来源说明：该权限有 {N} 种获得方式，最终结果取并集
- 空结果标题：该用户当前没有任何权限
- 空结果说明：该用户尚未被分配权限，或所有权限已被收回、暂停或尚未生效
- 空结果按钮：前往用户授权
- 错误标题：查询失败
- 错误说明：服务暂时不可用，请稍后重试。如持续失败，请联系技术支持
- 错误按钮：重新查询
- 权限不足提示：无法查询该用户的权限，该用户不在你的管理范围内。如需查询，请联系具有更广查询权限的管理员
- 对象不存在提示：未找到名为"{输入}"的{用户/角色}，请检查输入是否正确

**按钮：**

- 主按钮：重新查询（错误态）、前往用户授权（空结果态）
- 文本按钮/链接：获得方式标签（可点击展开/收起来源详情）

**成功反馈：**

- 查询完成后平滑过渡到结果区，不需要额外的成功 toast 或提示

**失败反馈：**

- 查询失败 → 结果区展示错误状态页
- 权限不足 → 输入框下方内嵌提示
- 对象不存在 → 输入框下方内嵌提示

## 8. 待确认问题

1. **查询结果是否提供跳转至权限调整页面的入口？**

   影响：决定结果卡片上是否需要"去调整"按钮，以及来源展开区底部是否需要跳转入口。当前体验方案按"提供跳转"设计（节点 4.2），如确认不提供则需移除此节点和相关入口。
   建议确认方：产品

2. **权限来源展示粒度？**

   影响：当前方案按"默认展示获得方式标签 + 点击展开链路详情"设计。如果确认只展示获得方式类型不展示链路详情，则节点 3.4 的展开交互需改为不可点击的标签。如果确认展示完整链路，需重新评估信息密度问题。
   建议确认方：产品、设计

3. **一期维度范围？**

   影响：当前方案按用户维度和角色维度设计交互。如果权限维度在一期内纳入，需补充反查维度的查询输入方式（按权限项搜索）和结果展示差异（展示用户列表而非权限列表）。
   建议确认方：产品

4. **访问控制的"管理范围"定义？**

   影响：当前方案中权限管理员的查询范围按"组织架构范围"假设，匹配建议过滤基于此。如果管理范围按角色分组或其他维度定义，匹配建议的过滤逻辑和阻断规则需要调整。
   建议确认方：产品

5. **审计/安全人员的查询入口是否默认可见？**

   影响：当前按审计人员入口可能需单独开通的前提设计（旅程图中标注了"或通过授权开通后可见"）。如果默认可见，需在页面入口的访问控制中纳入审计角色。
   建议确认方：产品、安全

6. **查询结果是否保留查询历史？**

   影响：当前方案不设查询历史功能。如果管理员需要回顾之前的查询结果，是否在本地保留最近查询记录（不涉及服务端日志）？这影响结果区的辅助功能设计。
   建议确认方：产品、设计

7. **大批量结果的具体分页和折叠参数？**

   影响：当前方案采用分组折叠 + 组内筛选策略，但具体触发折叠的数量阈值（如单组超过多少条触发折叠）、是否提供"全部展开"按钮等细节待定。建议 experience 阶段先做保守设计，后续根据实际数据量调整。
   建议确认方：设计、技术
