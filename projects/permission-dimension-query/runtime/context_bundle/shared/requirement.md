# Requirement

- Project ID: permission-dimension-query
- Task Name: 权限维度统一查询
- Domain: 业务/权限管理

## 要解决什么

当前权限分散在多个功能域（权限管理、应用管理、审批管理、报表管理、OA 表单），管理员缺少统一的跨域权限查询入口，需要在不同设置页面之间切换、逐项核对，查找效率低，不利于权限审计和风险排查。

## 核心需求

补齐统一的权限查询能力，支持管理员从以下五个维度查看权限归属关系：

1. **用户维度** — 查询一个用户的全部权限
2. **角色维度** — 查询一个角色的全部权限
3. **权限维度** — 反查拥有某项权限的用户列表
4. **OA 表单维度** — 查询拥有某个表单权限的用户列表
5. **报表维度** — 查询拥有某个报表权限的用户列表

## 用户与角色

- **权限管理员**：负责查看、核对、调整员工或角色的权限配置，是主要使用者
- **超级管理员**：用于全局权限审计、异常权限排查和权限治理
- **审计/安全管理人员**：核对人员权限、角色权限和高风险权限分布

## 权限类型范围

查询需覆盖以下权限类型，不同域权限颗粒度不同：

- **管理类功能权限**：应用权限、菜单权限、页面权限、操作权限、数据权限
- **员工类功能权限**：个人功能（档案、工资单、报销等）、协同功能（通讯录、日程、审批等）
- **报表权限**：操作权限、报表权限、报表管理权限、数据权限
- **OA 表单权限**：表单权限、字段权限、表单管理权限、数据权限

## 已知事实

- 查询能力应服务于权限核对、权限审计和权限调整场景，不应绕过现有权限管理体系
- 查询结果需要准确表达权限来源，避免管理员误判
- 查询权限本身需要受控，不应让普通用户查看全员权限分布
- 知识库已有成熟的对象模型（主体/资源/动作/范围/来源/修饰因子/状态）和来源模型（ACL_DIRECT / RBAC_ROLE / APP_VISIBILITY / COLLAB_VISIBILITY）可直接复用
- 知识库已明确：查询页负责解释，不负责配置
- 不支持导出、模糊搜索、权限验证模式
- 敏感权限查询不需要二次确认

## 已知风险

- 不同功能域的权限结构不同，查询口径不清晰容易导致结果不准确
- 同一权限可能来自角色、组织、岗位、直接授权等多个来源，需展示清楚
- 数据权限可能按组织范围、页面数据属性、表单数据属性、报表数据属性等多维度隔离，展示方式需谨慎设计
- 权限查询本身属于敏感能力，开放范围过大可能暴露企业权限结构

## 不确定点（不阻塞先做，后续再补）

- 间接授权（通过角色、组织拿到的权限）是否纳入查询结果
- 权限来源展示到什么粒度（来源类型还是完整来源链路）
- 查询结果是否支持直接跳转到权限调整页面
- 表单字段权限、报表数据权限是否纳入本期查询
- 查询操作是否需要记录日志
- 五个维度的查询是否共用同一查询模型
- 哪些管理员有权限使用该查询能力
