# 缺口清单

> 本文件汇总权限维度统一查询任务中所有尚未确认的问题及其影响范围。
> 来源：facts.md、business_blueprint.md、experience_blueprint.md 中的 [GAP] 和待确认问题。

## Blockers

- none

## Warnings

- 间接授权（通过角色、组织、岗位获得的权限）是否纳入查询结果尚未确认，影响查询结果的数据量和来源展示逻辑
- 查询入口的访问控制范围（管理范围按组织架构还是角色分组）尚未定义，影响匹配建议过滤逻辑和阻断规则
- 权限维度查询的最终优先级需求文档内部矛盾，影响分期决策
- 查询结果是否提供跳转到权限调整页面的入口待确认，影响结果卡片操作入口设计
- 权限来源展示粒度（类型 vs 完整链路）待确认，影响信息密度和交互设计
- 查询操作是否需要记录日志待确认，影响安全审计边界
- 审计/安全人员的查询入口开通方式待确认，影响角色起点路径
- 表单字段权限、报表数据权限是否纳入本期查询待确认，影响二期数据源范围
- 五个维度的查询是否共用同一查询模型待确认，影响查询结果结构统一程度
- 数据权限的具体展示方式待确认，影响数据权限条目的展示字段和解释方式
- 大批量结果的具体分页/折叠参数待定

## 待补信息

- 权限维度查询的最终优先级——需产品确认（需求文档内部存在截图标注高优先级、汇总表中优先级的矛盾）
- 间接授权的纳入范围——建议一期先纳入角色授权，组织授权和岗位授权等数据源就绪后扩展
- 查询入口的访问控制范围定义——建议一期以组织架构范围作为权限管理员的查询边界
- 一期和二期的具体分界——建议一期=用户维度+角色维度，权限维度在间接授权口径确认后纳入
- 查询结果跳转配置页入口——建议提供，因查询的终点往往是"发现问题需要调整"
- 权限来源展示粒度——建议默认展示获得方式标签 + 点击展开链路详情（渐进披露）
- 查询操作日志——建议至少记录"谁在什么时间查了什么对象"
- 审计/安全人员入口——建议按需开通，不在默认可见范围
- 大批量结果策略——建议分组折叠 + 组内筛选，默认只展开第一组，具体阈值参数后续根据实际数据量调整
