# 轻量业务蓝图

## 0. 路线说明

**判断：**

本次是既有能力的查询维度扩展，不改权限底层对象、规则、状态机和生效机制，属于中等复杂度——需要先做轻量业务判断，再进入具体体验方案。

**主要影响：**

1. 不影响谁能看、谁能做：查询能力本身不改变授权模型，不引入新的授权入口
2. 不影响适用范围和数据范围：查询结果展示的权限范围来自已有授权数据，不新增或修改范围口径
3. 不影响审批、处理人和责任边界：查询链路纯读，不触发任何写操作
4. 不影响流程进度和生效时点：查询结果如实反映当前权限状态，不会因查询行为改变生效
5. 不影响涉及对象与关系边界：主体、资源、动作、范围、来源、状态等权限对象关系不变

**建议方案：**

- 在现有"按用户查询"链路基础上统一三个查询维度的入口
- 按角色查和按权限查作为新增查询视角，复用相同的结果展示框架
- 查询结果必须区分功能权限和数据权限，并标注权限来源

**需要重新判断的信号：**

1. 如果查询结果需要触发权限变更操作（如从查询结果直接修改授权），则需重新评估是否变为配置+查询混合链路
2. 如果新增的查询维度需要聚合跨系统的外部权限数据，则需重新评估数据口径和外部回写风险

## 1. 一句话结论

可以做，建议按三个维度的统一查询入口建设。核心理由：权限数据已经存在，不需要改造底层授权模型，最大的工程工作在于读侧的数据聚合和查询结果的信息结构设计。

## 2. 关键业务规则

- 查询和配置职责严格分离：查询页是解释入口，不是配置入口，查询结果中不提供授权/撤销操作
- 功能权限和数据权限分开展示：即使同一查询对象，两组权限应在视觉和信息层面有明确区分
- 权限来源必须可追溯：每条权限结果必须显示其来源（用户直授/角色授予），且需标注来源优先级
- 可见性先于功能权限：如果应用对主体不可见，即使功能权限存在也不可达，查询结果需加以说明
- 治理状态作为生效说明：已授予但未生效的权限不能混入"已生效"的统计数字
- 数据范围按"全部/部分/无"三种类型展示，部分范围不展开内部计算模型但需保留展开入口

## 3. 边界与风险

**必须守住的边界：**
- 查询页不得提供授权、撤销、变更等配置操作
- 查询结果不得因为不同维度的查询而产生不同的权限结论——同一主体同一资源的结果必须一致
- 角色页的配置职责不得被查询页替代——查询页不承担模板化授权或批量分发

**关键风险：**
- 多入口导致选择困难：管理员面对三个查询入口，不知道当前该选哪个维度
- 多来源导致解释不透明：一条权限可能有多个来源，如果展示不清会导致管理误判
- 跨域数据缺口导致查询不全：部分权限类型可能不在当前数据模型的查询范围内，造成"看起来没权限实际上有"的误判

**保护策略：**
- 三个查询维度共用一个查询页面框架，通过切换维度标签而非多个独立入口降低认知负担
- 结果中统一以来源标签+来源详情展开作为解释手段
- 在查询结果页标注数据覆盖范围，明确告知哪些权限类型在本次查询范围内 [GAP：具体权限类型覆盖清单需确认]

## 4. 体验承接要求

**角色：**
- 权限管理员：核心用户，注重查询效率和信息完整性，需要快速找到目标人员的权限清单
- 超级管理员：高频使用按权限反查，注重全局覆盖能力和异常标记
- 审计人员：注重完整性和可追溯性，需要清晰的权限来源说明和结果导出

**流程：**
- 必须闭环的主流程：选择查询维度 → 输入/选择查询对象 → 查看查询结果 → 展开权限详情（含来源和生效说明）
- 三条查询维度的主流程结构一致，维度的切换不能让用户感到"换了一套体验"

**进度与结果状态：**
- 查询加载态：聚合多域权限数据时可能有等待，需反馈查询进度
- 查询有结果：分功能权限和数据权限两组展示，默认折叠、展开查看
- 查询无结果：区分"对象不存在"和"确实无权限"两种情况
- 权限详情态：展开单条权限后显示来源列表、生效状态和数据范围

**异常：**
- 输入无匹配：提示未找到对象，建议检查拼写或切换到模糊搜索
- 查询超时：权限聚合数据量大时可能超时，提供缩小范围的建议
- 部分权限类型不可查：在页面顶部用说明文案告知当前查询覆盖范围
- 权限已授予但未生效：用状态标签标记，同时给出原因（待审批/已失效等）

**反馈：**
- 查询结果为空时，不能只显示空白列表——要用明确文案告知"没有"以及可能的原因
- 权限来源展示时，多来源情况用分组列表而非平铺文字
- 高危权限或敏感数据权限在列表中应有视觉强调

**文案：**
- 查询入口文案：按人员 / 按角色 / 按权限（简洁维度标签）
- 空结果文案：该人员当前无任何权限（而非"未查询到结果"）
- 加载文案：正在查询权限数据...（而非"Loading"）
- 来源说明：来自角色"XX管理员" / 来自用户直授（带优先级排序）

## 5. 升级信号

- 如果后续要求从查询结果中直接发起授权变更或权限回收，需升级为完整业务蓝图并重新评估配置+查询混合链路的权限边界
- 如果查询需要接入外部系统（如第三方应用的权限数据），需升级判断并补数据口径分析
- 如果要求查询结果支持批量导出、定时生成审计报告等增强能力，需评估是否触及治理和审计契约变化

## 6. 待确认问题

- 按权限反查时，是否需要区分"直接授予"和"通过角色间接获取"，还是合并展示
- 查询结果是否需要支持筛选和排序（按权限类型、来源、生效状态）
- 是否需要权限对比功能（两人权限差异对比、角色权限差异对比）
