Experience Blueprint

0. 本次关键设计判断

判断：

本次核心不是多做页面，而是把三个查询维度、五种权限类型、三种角色视角统一收进一个信息清晰、切换自然的结果页里。体验设计的重点在信息组织和异常反馈，不在流程复杂度。

主要影响：

  1. 查询结果的信息密度高，需要分块策略让管理员不迷失——权限类型分组、获取来源标注、应用归属区分
  2. 三种角色看到的内容范围不同，但页面结构应保持一致，只通过数据范围差异来体现角色边界
  3. 空结果、权限颗粒度不一致、跨应用来源差异等异常状态需要逐一设计反馈方式

建议方案：

  • 统一查询页结构：顶部维度切换 + 搜索区 + 结果区，三个维度共用同一个页面框架，减少学习成本
  • 权限结果按五大类型分组折叠展示，每组标注数量，管理员可按需展开
  • 审计人员界面增加"只读模式"的视觉标识（页面顶部 banner），全流程不出现任何编辑入口

不建议方案：

  • 不建议三个查询维度做三个独立页面——会增加切换成本，且不利于管理员建立统一的查询心智模型
  • 不建议把所有权限类型平铺在一页不做折叠——信息密度过高，管理员需要大量滚动才能定位目标

需要确认：

  1. 按权限反查结果按人员列表直展（角色作为附属字段），是否可接受？
  2. 查询范围受角色限制时，是否需要在页面上告知当前查看范围（如"当前仅可查看所辖部门：技术部"）？
  3. 无结果时是否需要主动提示"可能原因"，还是只显示"暂无数据"即可？

1. 交互流程总览

涉及角色：

  • 权限管理员：进入统一查询页 → 选择维度 → 输入条件 → 查看所辖范围内的查询结果
  • 超级管理员：进入统一查询页 → 选择维度 → 输入条件 → 查看全组织范围内的查询结果
  • 审计人员：进入统一查询页 → 选择维度 → 输入条件 → 查看全组织范围内的查询结果（仅读，页面有只读标识）

主流程：

  1. 管理员从导航进入"权限查询"页
  2. 页面顶部展示三个查询维度标签：按人员查询、按角色查询、按权限查询
  3. 当前维度下的搜索区提供对应的搜索或选择能力
  4. 输入条件后触发查询，结果区按权限类型分组展示
  5. 管理员可在结果区切换维度、修改条件重新查询，无需回到首页

异常流程重点：

  • 查询无结果：区分"该对象确实无权限"和"查询条件无法匹配"，给出不同的空状态说明
  • 搜索无匹配：输入过程中搜索建议为空时，提示"未找到匹配结果"
  • 数据加载失败：网络或服务异常时，结果区展示错误状态并提供重试入口

2. 主交互流程

节点 1：按人员查询

用户动作：

管理员在"按人员查询"标签下，在搜索框中输入人员姓名或工号，系统提供实时搜索建议。选中一个人员后，自动触发查询。或者先选人员，再点击"查询"按钮。

系统反馈：

查询结果区域展示该人员的权限清单，按五大类型分组：

  • 功能权限（菜单、页面、操作权限等）
  • 数据权限（数据可见范围）
  • 表单权限（表单查看、编辑权限）
  • 字段权限（字段级别可见与可编辑）
  • 报表权限（报表查看权限）

每组可折叠，组标题右侧标注该组的权限数量。每组展开后，以列表形式展示权限项，每项包含：权限名称、所属应用/模块、获取方式（直接授权 / 角色继承）、生效状态。

如果该人员在某个权限类型下没有任何权限，该组仍显示但标注"无"。

需要前置解释的信息：

  • 获取方式为"角色继承"时，权限项旁显示角色名称，帮助管理员理解权限来源
  • 如果该人员的权限涉及多个角色来源，在结果顶部汇总展示角色标签

建议文案：

  • 搜索框占位符："输入姓名或工号搜索"
  • 结果区标题："{姓名} 的权限清单"
  • 角色汇总区："{姓名} 拥有以下 {N} 个角色：{角色A}、{角色B}"
  • 分组标题示例："功能权限（12 项）"
  • 空权限组标注："该类型下暂无权限"
  • 获取方式标注："直接授权""通过 {角色名} 继承"

下一步：

管理员可以切换查询维度继续查其他人，或修改搜索条件查另一个人。

节点 2：按角色查询

用户动作：

管理员在"按角色查询"标签下，搜索或选择系统中已有的角色。选中角色后触发查询。

系统反馈：

查询结果区首先展示角色基本信息——角色名称、角色描述、当前拥有该角色的人员数量。如果有超过一定数量的人员（如超过 20 人），提供"查看人员列表"的展开入口。

下方按五大权限类型分组展示该角色包含的权限项。每项权限展示：权限名称、所属应用/模块。角色权限不区分"获取方式"（因为所有权限的来源都是该角色本身）。

需要前置解释的信息：

  • 如果该角色下某些权限类型为空，在组旁标注"无"，并显示说明"该角色未配置此类权限"
  • "拥有该角色的人员"数量为实时数据，点击可查看人员列表（按人员查询的快捷入口）

建议文案：

  • 搜索框占位符："输入角色名称搜索"
  • 角色信息区："{角色名}""{角色描述}""当前 {N} 人拥有此角色"
  • 人员列表入口："查看全部人员 →"
  • 分组示例："功能权限（8 项）"
  • 空权限组标注："该角色未配置此类权限"

下一步：

管理员可以点击"查看全部人员"进入按人员查询视角，或切换查询维度。

节点 3：按权限反查

用户动作：

管理员在"按权限查询"标签下，搜索或浏览具体权限项。搜索时可输入权限名称或功能点名称。系统列出匹配的权限候选项，管理员选中一项后触发查询。

系统反馈：

查询结果区首先展示该权限的基本信息：权限名称、权限类型、所属应用/模块。

下方展示拥有该权限的人员列表。列表每行包含：人员姓名、所属部门、获取方式（直接授权 / 通过某角色继承）、生效状态。列表支持按部门筛选、按获取方式筛选。

如果拥有该权限的人员数量较大，列表分页展示。

需要前置解释的信息：

  • 同一人员可能通过多个途径获得同一权限（如既被直接授权又属于有该权限的角色），此时以直接授权为准展示，但仍标注"同时通过角色 {角色名} 拥有"
  • 如果权限项本身属于某个角色的一部分，结果顶部可标注"此权限包含在以下 {N} 个角色中：{角色A}、{角色B}"

建议文案：

  • 搜索框占位符："输入权限名称或功能点搜索"
  • 结果区标题："拥有「{权限名称}」的人员"
  • 权限来源汇总："此权限包含在 {N} 个角色中：{角色A}、{角色B}"
  • 列表表头：人员姓名、所属部门、获取方式、生效状态
  • 筛选器："按部门筛选""按获取方式筛选"

下一步：

管理员可以点击某个人员姓名跳转到该人员的完整权限清单（按人员查询视角），或继续反查其他权限。

3. 次交互流程

查询维度切换

管理员在任一维度下的结果页，点击顶部标签即可切换到另一维度。切换时，如果当前搜索条件在新的维度下仍然有意义（如按人员查时选中的"张三"，切换到按权限查时清空），自动清空条件并展示新维度的初始搜索区。切换过程无页面跳转，保持在同一个页面内。

权限类型分组展开/折叠

查询结果中各权限类型分组默认全部折叠，管理员按需展开。展开操作不影响其他分组。提供"全部展开"和"全部折叠"快捷操作。

搜索建议

在搜索框中输入时，系统实时提供匹配建议（最多 10 条）。建议列表展示匹配项的名称和简要描述（如人员的部门、角色的描述、权限的所属应用）。管理员可直接点击建议项触发查询，无需完整输入后手动点击查询。

4. 异常与阻断流程

异常 1：查询无结果——人员无权限

发生时机： 管理员选中一个人员后触发查询。
触发条件： 该人员在系统中未分配任何权限。
判断依据： 来自 facts.md 中的"查询无结果"异常描述，以及 business_blueprint_lite.md 中的空结果处理规则。
反馈形式： 页面空状态（结果区展示空状态插图 + 说明文字）。
系统反馈： "该人员暂无任何权限。如需分配权限，请前往「角色管理」或「人员授权」页面操作。"
用户下一步： 管理员可切换查询另一个人，或根据提示前往授权页面（权限管理员和超级管理员可见此入口，审计人员不可见）。

异常 2：查询无结果——角色无权限项

发生时机： 管理员选中一个角色后触发查询。
触发条件： 该角色下未配置任何权限项。
判断依据： 来自 business_blueprint_lite.md 中的待确认问题：角色下无权限项的空结果需与角色不存在的错误提示区分处理。
反馈形式： 页面空状态。
系统反馈： "该角色下暂无权限项。请检查角色配置或联系超级管理员。如该角色已不再使用，建议在「角色管理」中停用或删除。"
用户下一步： 管理员可切换查询另一个角色，或前往角色管理页面检查配置。

异常 3：查询无结果——权限无人拥有

发生时机： 管理员选中一项权限后触发反查。
触发条件： 该权限项在系统中未被授予任何人员或角色。
判断依据： 来自 business_blueprint_lite.md 中的按权限反查边界。
反馈形式： 页面空状态。
系统反馈： "当前无人员拥有此权限。该权限可能仅配置在未启用的角色中，或尚未分配给任何人员。建议前往「角色管理」检查权限配置。"
用户下一步： 管理员可切换反查另一项权限，或前往角色管理页面。

异常 4：搜索无匹配

发生时机： 在搜索框中输入内容，但系统找不到匹配的人员、角色或权限。
触发条件： 输入内容与系统中已有数据不匹配，或超出当前角色的查看范围。
判断依据： 来自 信息架构 IA-01（信息气味）原则：搜索结果应提供可预测的线索。
反馈形式： 搜索建议下拉框中显示"未找到匹配结果"。
系统反馈： 如果可能超出查看范围，追加说明"部分结果可能因查看范围限制未显示"（仅权限管理员可见此提示，因为只有权限管理员有范围限制）。
用户下一步： 修改搜索关键词，或确认搜索对象是否在管辖范围内。

异常 5：数据加载失败

发生时机： 触发查询后，服务端返回错误或网络超时。
触发条件： 网络异常、服务繁忙、权限数据源查询超时。
判断依据： 来自 反馈与报错体验设计指南中的系统异常类反馈规则。
反馈形式： 结果区展示错误状态，提供重试按钮。不弹窗（因为不是高风险阻断，可通过重试恢复）。
系统反馈： "查询失败，请稍后重试。如多次失败，请联系技术支持。"
用户下一步： 点击"重试"按钮重新查询。

异常 6：权限颗粒度不一致

发生时机： 查询结果中，某应用在"操作权限"下无明细，但存在"菜单权限"。
触发条件： 该应用的权限配置只到菜单级，未细化到操作级。
判断依据： 来自 facts.md 中的权限颗粒度差异异常描述。
反馈形式： 在分组内的权限列表底部，显示一行轻量说明文字。不阻断用户，不弹窗。
系统反馈： "该应用仅配置到菜单级权限，无更细粒度的操作权限。"
用户下一步： 无需额外操作。这是正常状态，不是数据缺失。

5. 页面 / 弹窗 / 抽屉设计

页面：权限查询主页

页面目标： 让管理员通过统一的查询界面，从人员、角色、权限三个维度快速查看权限归属关系。

页面结构（从上到下）：

  1. 页面标题区： "权限查询"，下方一行副标题："查看人员、角色和权限之间的归属关系"。审计人员身份时，标题区右侧显示蓝色标签"只读模式"。
  1. 查询维度标签栏： 三个标签——"按人员查询""按角色查询""按权限查询"。当前选中标签高亮，其余为次级样式。切换标签后下方搜索区和结果区联动更新。
  1. 搜索区： 根据当前维度展示不同的搜索框：
  • 按人员查询：搜索框 + 搜索建议下拉（展示人员姓名、工号、所属部门）
  • 按角色查询：搜索框 + 搜索建议下拉（展示角色名称、角色描述）
  • 按权限查询：搜索框 + 搜索建议下拉（展示权限名称、所属应用）
  • 搜索框右侧有"查询"按钮（可选，选中建议项后自动触发也可）
  1. 结果区：
  • 结果标题行：展示查询对象名称和关键汇总信息
  • 权限类型分组：五个可折叠的分组卡片，每张卡片标题为权限类型名称 + 数量
  • 展开后的权限列表：列表形式，每行一项权限
  • 角色范围提示（仅权限管理员可见）：在结果区顶部以轻量 banner 展示当前查看范围

具体文案：

  • 页面标题："权限查询"
  • 页面副标题："查看人员、角色和权限之间的归属关系"
  • 审计只读标签："只读模式"
  • 按人员搜索框占位："输入姓名或工号搜索"
  • 按角色搜索框占位："输入角色名称搜索"
  • 按权限搜索框占位："输入权限名称或功能点搜索"
  • 权限类型分组标题："功能权限""数据权限""表单权限""字段权限""报表权限"

按钮：

  • "查询"按钮（主要，搜索框右侧）
  • "全部展开""全部折叠"文字按钮（结果区右上角）
  • "重试"按钮（仅在加载失败时出现）

成功反馈： 查询完成后，结果区直接展示权限清单，无需额外 toast。

失败反馈： 加载失败时，结果区展示错误状态，含"重试"按钮。

抽屉：角色下人员明细

页面目标： 展示拥有某个角色的全部人员。

页面结构： 以抽屉或展开区域形式呈现人员列表，每行含人员姓名、所属部门。点击某人员可跳转到该人员的权限清单（切换到按人员查询维度）。

具体文案：

  • 抽屉标题："拥有「{角色名}」的人员（共 {N} 人）"
  • 列表表头：人员姓名、所属部门

6. 状态与反馈文案

  • 状态：查询结果加载中

含义： 系统正在查询权限数据。
用户可做： 等待，不可进行新的查询操作（查询按钮置灰或显示加载动画）。
页面反馈： 结果区展示加载动画 + "正在查询…"

  • 状态：查询结果已展示

含义： 查询完成，结果正常展示。
用户可做： 展开/折叠权限分组，切换查询维度，修改条件重新查询。
页面反馈： 结果区正常展示权限清单。无额外提示。

  • 状态：查询无结果（人员无权限）

含义： 查询完成但该人员未分配任何权限。
用户可做： 切换查询另一个人，或前往授权页面（权限管理员和超级管理员可见，审计人员不可见）。
页面反馈： 结果区展示空状态插图 + 说明文字："该人员暂无任何权限。如需分配权限，请前往「角色管理」或「人员授权」页面操作。"

  • 状态：查询无结果（角色无权限项）

含义： 查询完成但该角色下未配置任何权限项。
用户可做： 切换查询另一个角色，或前往角色管理页面检查配置。
页面反馈： 结果区展示空状态插图 + 说明文字："该角色下暂无权限项。请检查角色配置或联系超级管理员。"

  • 状态：查询无结果（权限无人拥有）

含义： 查询完成但该权限未被授予任何人员。
用户可做： 切换反查另一项权限，或前往角色管理页面。
页面反馈： 结果区展示空状态插图 + 说明文字："当前无人员拥有此权限。建议前往「角色管理」检查权限配置。"

  • 状态：查询失败（网络或服务异常）

含义： 查询过程中发生网络或服务异常，未能获取结果。
用户可做： 点击"重试"按钮重新查询。
页面反馈： 结果区展示错误图标 + "查询失败，请稍后重试。如多次失败，请联系技术支持。" + 重试按钮。

  • 状态：审计人员只读标识

含义： 当前登录用户为审计人员，仅可查看权限信息，不可进行任何配置修改。
用户可做： 正常使用全部查询功能，但界面中不出现任何配置入口链接或跳转提示。
页面反馈： 页面标题区右侧展示蓝色标签"只读模式"。

  • 状态：权限管理员范围提示

含义： 当前登录用户为权限管理员，查询范围受管辖范围限制，不能查看管辖范围外的数据。
用户可做： 在其管辖范围内正常查询。如需扩展范围，联系超级管理员调整管辖设置。
页面反馈： 结果区顶部展示轻量 banner："当前仅可查看所辖范围：{部门名称}"。

7. 待确认问题

  • 按权限反查结果按人员列表直展（角色作为附属字段），是否可接受？→ 影响体验蓝图节点 3 的结果区设计

已使用的设计参考与追踪

信息架构 IA-01 信息气味（Information Scent）

  • 来源：knowledge/wiki/summaries/设计准则/信息架构.md
  • 消费位置：节点 1/2/3 的搜索建议设计、维度标签命名、结果区标题文案
  • 转换方式：每个维度标签直接表达查询方向（"按人员""按角色""按权限"），搜索结果建议提供关联线索（姓名+部门、角色名+描述、权限名+所属应用），让管理员在点击前能预判结果内容
  • 对应页面元素：维度标签栏、搜索建议下拉、结果区标题行

信息架构 IA-02 分块（Chunking）

  • 来源：knowledge/wiki/summaries/设计准则/信息架构.md
  • 消费位置：节点 1/2/3 的结果区分组设计、权限类型分组卡片
  • 转换方式：五种权限类型按业务语义分组（功能权限、数据权限、表单权限、字段权限、报表权限），每组有独立标题+数量标注，组间边界清晰。不按数据表结构或应用分组，不把所有权限项平铺
  • 对应页面元素：结果区的五个权限类型折叠卡片、全部展开/折叠操作

反馈与报错体验设计指南（反馈形式选择原则）

  • 来源：knowledge/wiki/summaries/设计准则/反馈与报错/00_反馈与报错体验设计指南.md
  • 消费位置：异常 1-6 的反馈形式选择、状态文案设计
  • 转换方式：
  • 空结果（人员无权限/角色无权限项/权限无人拥有）→ 页面空状态（含原因和下一步），不用 toast（页面内容无法展示的场景）
  • 加载失败 → 结果区错误状态+重试按钮，不用弹窗（可恢复的轻量失败，不阻断用户）
  • 搜索无匹配 → 搜索建议下拉内提示，不用 banner（属于即时输入反馈）
  • 权限颗粒度差异 → 行内轻量说明，不阻断不弹窗（属于信息提示，不是错误）
  • 对应页面元素：空状态插图+文案、错误状态+重试按钮、搜索建议无结果提示、行内说明文字

反馈与报错体验设计指南（文案规则）

  • 来源：同上
  • 消费位置：所有异常状态和反馈的文案
  • 转换方式：每条反馈文案说明"为什么不能继续"和"下一步怎么办"，不使用技术词、错误码、接口名等内部信息。例如"查询失败"而非"API 500 error"
  • 对应页面元素：空状态说明文字、错误状态文案、异常说明文字

业务知识追踪

以下体验设计决策直接承接了 business_blueprint_lite.md 和 facts.md 中的判断：

  • 三种角色查看范围差异 → 页面设计中的"只读模式"标签（审计人员）和"管辖范围 banner"（权限管理员）；超级管理员无特殊标识因为其范围是全组织默认
  • 权限来源区分（直接授权 vs 角色继承）→ 查询结果列表中每项权限标注获取方式，按权限反查结果以人员列表直展、角色作为附属字段
  • 五种权限类型分组 → 结果区按五大类型折叠分组，顺序固定，不因应用不同而变动
  • 按角色查询"部分可行"（知识库标记）→ 本次独立定义按角色查询的结果结构和人员列表展开方式，不依赖现有角色管理页的展示逻辑
  • 按权限反查"明确缺口"（知识库标记）→ 重点设计反查流程，包含权限搜索建议、人员列表、来源标注和筛选能力
