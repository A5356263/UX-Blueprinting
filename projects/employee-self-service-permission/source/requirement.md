# 员工自助申请权限 — 正式需求输入

## 需求背景

目前企业员工的权限分配主要由权限管理员或超级管理员集中处理。在中大型企业中，员工数量多、人员流动频繁，权限新增、变更、核对的工作量较大。部分企业的超级管理员可能是老板本人，业务人员或经办人员需要权限时，需要私下找老板或管理员处理，沟通成本高，授权时效不稳定。

希望通过支持员工自助查看和申请权限，把部分权限申请工作从管理员侧分散到员工侧，同时保留管理员对申请范围和审批流程的控制。

## 目标

本次新增"员工自助申请权限"能力，使员工可以：

- 查看自己当前拥有的权限
- 主动申请所需权限（角色和功能权限）
- 通过审批后自动获得权限
- 查看自己的申请记录和审批状态

同时，管理员可以控制：

- 是否允许员工自助申请权限
- 员工可以申请哪些权限范围
- 申请提交后走什么审批流程
- 是否关闭或调整该能力

## 用户与角色

1. **超级管理员 / 权限管理员**：负责配置是否开启自助申请，控制可申请范围和审批规则
2. **员工**：查看自己的权限，发现缺少权限时主动发起申请
3. **审批人**：处理员工提交的权限申请，决定是否同意授权

## 核心场景

1. 管理员配置自助申请：开启模式 → 设置可申请范围 → 设置审批流程
2. 员工查看自己的权限：查看已有功能权限、数据权限、角色
3. 员工申请权限：选择角色或功能权限 → 填写申请原因 → 提交申请
4. 审批人处理申请：查看申请内容和原因 → 同意或拒绝 → 审批通过后自动授权
5. 管理员关闭自助申请：关闭能力，处理在途申请

## 功能范围

| 功能 | 说明 |
| --- | --- |
| 自助申请权限模式 | 管理员开启或关闭员工自助申请权限的能力 |
| 我的权限 | 员工查看自己已有权限的入口和页面 |
| 申请权限 | 员工发起权限申请的入口和表单 |
| 审批对接 | 员工提交申请后进入审批流程 |
| 申请记录 | 员工查看历史申请和审批状态 |
| 操作记录 | 记录模式开启、关闭、申请、审批等关键操作 |
| 数据埋点 | 统计功能使用情况和转化情况 |

## 已确认的关键业务约束

1. 自助申请权限模式与已有权限治理模式**互斥**，不能同时开启
2. 员工可申请**角色和功能权限**，两种都支持
3. 默认审批人为**组织负责人**，支持选择其他审批人
4. 需要**敏感排除机制**：按用户身份限制可申请范围，特定身份不可申请特定权限
5. 管理员关闭能力后，**已授权权限继续生效**
6. 管理员关闭能力时，需处理**审批中的申请**
7. 员工只能看到与自己相关的权限和申请记录
8. 审批通过后，系统自动完成授权
9. 服务人员暂不开放该能力

## 初步业务规则

### 管理端

- 只有具备最高权限的管理员可以开启或关闭自助申请权限能力
- 开启前需要设置可申请范围和审批方式
- 可申请范围按角色和功能权限配置，受敏感排除机制约束
- 管理员可后续调整配置
- 管理员关闭能力时，需要检查是否存在未完成的申请

### 员工端

- 员工可以查看自己的权限
- 员工可以提交权限申请（选择角色或功能权限），并填写申请原因
- 员工可以查看申请状态
- 审批中的申请是否支持撤销，需要设计判断

### 审批端

- 审批人需要看到申请人、申请原因和申请内容
- 审批同意后，系统自动授权
- 审批拒绝后，员工权限不变
- 审批人缺失或审批流程异常时，需要有兜底处理

## 已知风险

1. **培训成本**：开放申请能力给员工可能增加培训和支持成本
2. **权限安全风险**：可申请范围设置过宽可能导致员工申请到不合适的权限
3. **审批流程风险**：审批人缺失、不合适或链路配置错误可能导致申请无法流转
4. **模式互斥风险**：新增模式后可能与已有模式产生冲突

## 不明确事项（待业务判断阶段进一步确认）

1. 哪些角色或权限不能被员工申请？（敏感排除的具体规则）
2. 是否需要支持上传附件？
3. 员工申请权限时是否可以选择数据权限范围？
4. 审批人不存在或审批流程异常时如何处理？
5. 审批中的申请是否可以撤销？
6. 管理员关闭能力时，正在审批中的申请如何处理？
7. 员工端入口应该放在哪里？
8. 是否需要给员工展示权限来源？
9. 是否需要给管理员提供申请统计或使用情况？
10. 服务人员是否完全不支持该能力？
