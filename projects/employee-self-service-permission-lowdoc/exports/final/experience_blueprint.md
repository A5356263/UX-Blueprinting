## 0. 本次关键设计判断

**判断：**

这次需求的体验方案需要围绕三个角色的独立任务路径展开，同时保证状态信息在三个视角下的一致性。不是简单的「加一个申请按钮」，而是需要定义员工的发现→申请→追踪闭环、审批人的处理决策链路、管理员的配置与监控视图。

**主要影响：**

1. 员工端的核心体验是「从已有权限中发现缺口 → 理解能申请什么 → 完成申请 → 追踪结果」，每个环节的信息透明度和操作确定性直接影响使用意愿
2. 审批端的体验重心是快速判断「这个申请是否合理」，需要在一屏内呈现申请人、申请项、申请原因和风险提示
3. 管理端的配置体验决定这个能力能不能安全落地——默认不可申请的配置策略意味着初始配置工作量，需要设计好批量操作和引导

**建议方案：**

- 员工端：在「我的权限」页面内集成申请入口，权限列表标注来源，可申请范围以分类列表呈现，申请流程不超过两步（选权限→填原因→确认提交）
- 审批端：在审批中台的待办列表中承接权限申请类型，申请详情页呈现四段信息（申请人、申请内容、申请原因、系统校验结果），同意/拒绝操作带二次确认
- 管理端：分三步配置向导（开启能力→设置范围→设置审批），支持批量标记可申请角色/权限，提供统计看板

**不建议方案：**

- 不建议把申请入口做成独立一级导航，会让员工困惑与「我的权限」「角色管理」的关系
- 不建议在申请表单中让员工自定义数据权限范围，第一期复杂度太高且安全风险大
- 不建议关闭能力时静默处理审批中的申请，每一条被关闭的申请都应该有明确的通知

**关键待确认：**

1. 审批通过后权限是即时生效还是延迟生效，影响员工端「已通过」状态页的下一步指引
2. 员工端「我的权限」页面的现有 IA 位置（在工作台还是个人中心），影响申请入口的嵌入方式

> 更多待确认问题详见「8. 待确认问题」。

## 1. 旅程图

```md
- 员工：察觉缺少权限 → 进入「我的权限」查看已有权限 → 发现缺口 → 点击申请 → 浏览可申请范围 → 选择目标角色/权限 → 填写申请原因 → 提交 → 收到提交成功反馈 → 在申请记录中追踪状态 → 审批通过后收到通知 → 在「我的权限」中确认新权限已生效
- 审批人：收到待审批通知 → 进入审批待办列表 → 点击查看申请详情 → 审查申请人/申请项/原因 → 参考系统校验提示 → 决定同意或拒绝 → 填写意见 → 确认操作 → 收到操作成功反馈
- 超管：进入权限管理后台 → 找到自助申请配置入口 → 开启能力 → 配置可申请范围（逐项或批量标记）→ 选择审批人策略 → 确认配置 → 后续可查看统计看板和操作日志 → 必要时关闭能力
```

### 旅程缺口

- 缺少「申请表单」与「我的权限」页面的具体 IA 关系依据，影响申请入口的起点表达
- 缺少审批结果通知的渠道和格式规则，影响审批通过/拒绝后的员工侧反馈设计
- 缺少员工端首页或工作台的结构信息，影响是否有必要在工作台增加申请状态卡片

## 2. 交互流程总览

```text
**分角色交互流程：**

- 员工：进入我的权限 → 查看权限列表（标注来源）→ 节点 3.1 发起权限申请 → 选择申请项 → 填写原因 → 提交确认 → 查看申请记录 → 追踪状态 → 节点 3.2 撤销申请
- 审批人：收到待办通知 → 进入审批列表 → 节点 3.3 查看申请详情并审批 → 同意 / 拒绝 → 确认操作
- 超管：进入管理后台 → 权限管理 → 自助申请配置 → 节点 3.4 开启并配置能力 → 设置可申请范围 → 设置审批策略 → 查看统计看板

**异常流程重点：**

- 异常 5.1：审批人不存在或无效时自动向上查找并兜底
- 异常 5.2：管理员关闭能力时审批中的申请批量终止
- 异常 5.3：员工尝试申请已有权限或不在范围内的权限
- 异常 5.4：审批流程未配置完成时管理员尝试开启能力
```

## 3. 主交互流程

### 节点 3.1：员工发起权限申请

**用户动作：**

员工在「我的权限」页面发现缺少某个权限，点击页面内的「申请权限」按钮，进入申请流程。

**系统反馈：**

- 展示可申请的角色和权限列表（分类组织：推荐申请 / 全部可申请）
- 每个申请项显示名称、简介、以及该权限能做什么
- 员工已拥有的权限自动过滤不展示，避免重复申请
- 如果可申请范围为空的（管理员未配置或全部被已有权限覆盖），展示空状态并引导联系管理员

**需要前置解释的信息：**

- 说明「申请需要审批通过后才能生效」
- 说明「审批人可能是你的直属负责人」
- 可申请范围外但员工需要的权限，提示联系管理员

**建议文案：**

- 页面标题：「申请权限」
- 引导语：「选择你需要申请的角色或权限，提交后由审批人处理，通过后自动生效。」
- 空状态：「暂无可申请的权限。如果你需要特定权限，请联系管理员。」
- 搜索框占位：「搜索角色或权限名称」

**下一步：**

员工选择目标申请项后进入填写申请原因步骤。

### 节点 3.2：员工填写申请原因并提交

**用户动作：**

员工在选择了要申请的角色或权限后，进入确认页面，填写申请原因，检查申请内容无误后提交。

**系统反馈：**

- 展示申请摘要：申请项名称、类型（角色/功能权限）、简介
- 申请原因输入框（必填），提示「请说明为什么需要这个权限，帮助审批人更快做出判断」
- 提交按钮点击后展示处理中状态
- 成功后展示确认页面：申请已提交、预计审批人、申请单编号
- 失败时展示具体原因（如网络错误、申请项已被移除可申请范围等）

**需要前置解释的信息：**

- 提交后在审批通过前可以撤销
- 审批处理时间取决于审批人

**建议文案：**

- 页面标题：「确认申请」
- 申请原因标签：「申请原因」
- 申请原因占位：「例如：需要查看本部门考勤数据以完成月度汇总」
- 提交按钮：「提交申请」
- 成功反馈：「申请已提交。审批人：张经理。我们会通过消息通知你审批结果。」
- 查看申请记录链接：「查看我的申请记录」

**下一步：**

员工可以返回「我的权限」页面，或在申请记录中追踪状态。

### 节点 3.3：审批人查看申请详情并审批

**用户动作：**

审批人在审批待办列表中看到一条权限申请，点击进入详情页。审查申请人的身份、申请内容、申请原因，参考系统给出的校验提示，决定同意或拒绝。

**系统反馈：**

申请详情页呈四段信息结构：
1. **申请人信息**：姓名、部门、岗位
2. **申请内容**：申请的角色或权限名称、类型、说明
3. **申请原因**：员工填写的申请原因原文
4. **系统校验提示**：
   - 该申请项是否仍在可申请范围内（如已被管理员移除则提示）
   - 申请人当前是否已通过其他途径获得该权限（如已获得则提示重复）
   - 该申请项的风险等级（如申请的是敏感权限则标记提示）

操作区：
- 「同意」按钮（主按钮）+ 审批意见输入框（选填）
- 「拒绝」按钮（次要按钮）+ 拒绝原因输入框（必填）
- 两个操作都带二次确认弹窗

**需要前置解释的信息：**

- 同意后权限将自动生效（或告知生效时间）
- 拒绝后员工可以重新提交申请

**建议文案：**

- 同意确认弹窗标题：「确认同意」
- 弹窗内容：「同意后，系统将自动为 [员工姓名] 授予 [角色/权限名称]。」
- 拒绝确认弹窗标题：「确认拒绝」
- 弹窗内容：「拒绝后，[员工姓名] 可以重新提交申请。请填写拒绝原因。」
- 成功反馈：「处理完成。已同意 [员工姓名] 的权限申请。」

**下一步：**

审批人返回待办列表继续处理其他申请。

### 节点 3.4：超管开启并配置自助申请能力

**用户动作：**

超管或权限管理员进入管理后台的权限管理区域，找到「自助申请配置」入口，按三步引导完成配置。

**系统反馈：**

三步配置向导：

**第一步：开启能力**
- 能力开关控件（默认关闭）
- 开启前展示前置条件检查：审批流程是否已配置、是否至少有一个可配置的角色或权限
- 如前置条件不满足，展示具体缺失项并引导完成

**第二步：设置可申请范围**
- 左侧：所有角色和权限的列表（分类组织、支持搜索和筛选）
- 右侧：已标记为「可申请」的汇总区
- 每项有「允许自助申请」开关，默认关闭
- 支持批量勾选和批量标记
- 超管和管理员类角色标记为「不可申请」且锁定不可修改
- 展示每项被标记为可申请后的影响范围（多少人可见、已有人数）

**第三步：设置审批策略**
- 选择审批人策略（直属负责人/指定人员/自定义流程）
- 如选择指定人员，展示人员选择器
- 如选择自定义流程，展示已有审批流程列表
- 可对不同角色/权限设置例外审批人（可选、高级设置）
- 完成配置后展示配置摘要，确认后正式开启

**需要前置解释的信息：**

- 开启后员工端立即可见申请入口
- 可申请范围后续可以修改
- 审批策略后续可以调整

**建议文案：**

- 页面标题：「员工自助申请权限」
- 能力开关标签：「开启员工自助申请权限」
- 开关说明：「开启后，员工可以在自己的权限页面中发起权限申请。」
- 前置条件不满足提示：「在开启前，需要先完成以下配置：1. 设置至少一项可申请的角色或权限；2. 完成审批流程配置。」
- 范围配置引导：「选择哪些角色和权限允许员工自助申请。未标记的将不会在员工端展示。」
- 审批策略引导：「设置员工提交申请后的审批处理方式。」
- 配置完成确认：「确认开启后，员工将可以在"我的权限"中看到申请入口。配置可随时修改。」

**下一步：**

管理员可以随时返回该页面修改配置或查看统计看板。

## 4. 次交互流程

### 员工查看申请记录

员工进入「我的申请」或申请记录列表，按时间倒序查看所有申请单。每条显示申请项名称、提交时间、当前状态（颜色标签区分：审批中-蓝、已通过-绿、已拒绝-红、已撤销-灰、已关闭-灰）。支持筛选按状态。点击进入详情页查看完整信息和审批意见。

### 员工撤销申请

在申请详情页（状态为审批中时），展示「撤销申请」按钮。点击后弹出二次确认：「撤销后你需要重新提交才能继续申请。确定撤销吗？」。确认后申请单状态变为已撤销，并通知审批人该申请已被撤销。

### 员工查看权限来源

在「我的权限」页面，每条权限标记来源标签：「角色继承」「管理员授予」「自助申请」。点击来源标签可查看详情（如角色名、授予时间、申请单编号）。帮助员工理解权限从何而来。

### 审批人查看已处理记录

审批人可以查看自己已处理（同意或拒绝）的申请记录列表，支持按状态和日期筛选。点击可查看处理详情。

### 管理员修改配置

管理员在能力已开启状态下可以修改可申请范围（新增或移除可申请项）和审批策略。修改即时生效。移除可申请项时，不影响已提交的申请。修改审批策略时，只影响后续提交的申请。

### 管理员查看统计看板

管理员在自助申请配置页面查看统计看板：
- 总申请量（可按日期范围筛选）
- 通过率、拒绝率、撤销率
- 平均审批处理时长
- 热门申请项排行
- 审批人处理量排行

## 5. 异常与阻断流程

### 异常 5.1：审批人不存在或无效

**发生时机：** 员工提交申请后，系统查找审批人时
**触发条件：** 员工没有直属组织负责人，或直属负责人账号已停用/离职
**判断依据：** facts.md「审批人异常」、business_blueprint.md「审批链路断链」风险
**反馈形式：** 对申请人透明（不暴露审批路由细节），对超管发送告警通知
**系统反馈：** 系统自动向上查找组织上级直到找到有效审批人。如果遍历到根节点仍无结果，申请自动转给超管。同时给超管发送告警：「员工 [姓名] 提交的权限申请因无法找到有效审批人，已自动转交给你处理。」
**用户下一步：** 超管在审批待办中看到该申请并处理，或手动转交给合适的审批人

### 异常 5.2：管理员关闭能力

**发生时机：** 管理员关闭自助申请能力开关时
**触发条件：** 管理员点击关闭开关并确认
**判断依据：** facts.md「能力关闭影响」、business_blueprint.md「能力关闭时的数据一致性」风险
**反馈形式：** 弹窗提示关闭影响范围，确认后批量处理审批中的申请，通知相关人
**系统反馈：**
- 关闭前弹窗：「关闭后，员工将无法发起新的权限申请。当前有 [N] 条审批中的申请，这些申请将被终止并通知相关人。已通过申请获得的权限不受影响。确定关闭吗？」
- 关闭后：所有审批中的申请批量标记为「已关闭」，申请人和审批人收到通知：「员工自助申请权限已由管理员关闭，你的申请 [申请单编号] 已被终止。」
**用户下一步：** 员工无法再发起新申请；审批人待办列表中相关项被清除

### 异常 5.3：员工尝试重复申请或越界申请

**发生时机：** 员工在可申请范围列表中浏览或尝试提交时
**触发条件：**
- 员工已通过任何途径拥有该权限（重复申请）
- 申请项已被管理员从可申请范围中移除但员工页面未刷新（越界申请）
**判断依据：** facts.md「重复申请」和「权限范围越界」、business_blueprint.md「可申请范围规则」
**反馈形式：**
- 列表中：已有权限标记「已拥有」，不可点击
- 提交时：弹窗提示冲突
**系统反馈：**
- 重复申请提示：「你已拥有该权限（来源：[来源说明]），无需重复申请。」
- 越界申请提示：「该权限暂不支持自助申请。如需获取，请联系管理员。」
**用户下一步：** 选择其他可申请的权限，或联系管理员

### 异常 5.4：未完成前置配置就尝试开启能力

**发生时机：** 管理员尝试开启能力开关时
**触发条件：** 可申请范围为空，或审批流程未配置完成
**判断依据：** business_blueprint.md「能力管控规则」
**反馈形式：** 开关附近的内联提示，阻止开启
**系统反馈：** 开关旁展示前置条件检查结果，红色标记未完成项：「在开启前，请先完成：1. 设置可申请范围（当前为空）；2. 确认审批流程已配置。」
**用户下一步：** 按照提示先完成缺失的配置

### 异常 5.5：申请提交后申请项被移除可申请范围

**发生时机：** 员工已提交申请但尚未审批，管理员移除了该申请项的可申请标记
**触发条件：** 管理员在配置中取消某角色/权限的「允许自助申请」
**判断依据：** business_blueprint.md「可申请范围规则——移除的可申请项不影响已提交的申请」
**反馈形式：** 审批详情页展示提示
**系统反馈：** 审批人在审批详情页中看到提示：「注意：该权限已被管理员从可申请范围中移除，但申请仍然有效，你可以正常处理。」这样审批人可以在知情的情况下决定是否同意。
**用户下一步：** 审批人参考提示做出判断

页面 / 弹窗 / 抽屉：员工端 — 我的权限

**页面目标：** 让员工一目了然地看到自己拥有的所有权限及其来源，并可以从此页面发起权限申请。

**页面结构：** 顶部为页面标题「我的权限」和「申请权限」按钮（仅在能力开启时展示）。筛选区按来源（全部/角色继承/管理员授予/自助申请）和类型（角色/功能权限）筛选，配合搜索框。列表区每条显示权限名称、类型标签、来源标签（颜色区分）、获取时间。点击某条权限可展开查看详情。空状态展示引导文案。

**具体文案：** 页面标题「我的权限」，申请按钮「申请权限」，来源标签「角色继承」「管理员授予」「自助申请」，空状态「暂无权限记录」。

**按钮：** 主按钮「申请权限」，列表项点击进入详情。

**成功反馈：** 无需提交操作，查看类页面无成功反馈。

**失败反馈：** 加载失败时展示「加载失败，请重试」并允许手动刷新。

页面 / 弹窗 / 抽屉：员工端 — 申请权限（选择申请项）

**页面目标：** 让员工浏览可申请的角色和权限，选择要申请的目标。

**页面结构：** 顶部返回按钮和页面标题「申请权限」，引导语一行说明。搜索框下方为分类标签（推荐申请/角色/功能权限）。列表区每项显示名称、简介、类型标签，已拥有的标记为「已拥有」且不可点击。空状态引导联系管理员。点击某项进入确认申请页面。

**具体文案：** 标题「申请权限」，引导语「选择你需要申请的角色或权限，提交后由审批人处理，通过后自动生效。」，已拥有标签「已拥有」，空状态「暂无可申请的权限。如需特定权限，请联系管理员。」

**按钮：** 列表项为主操作区，返回按钮为次要操作。

**成功反馈：** 无需提交操作。

**失败反馈：** 加载失败时展示空状态并允许重试。

页面 / 弹窗 / 抽屉：员工端 — 确认申请

**页面目标：** 展示申请摘要，收集申请原因，完成提交。

**页面结构：** 顶部返回按钮和页面标题「确认申请」。申请摘要卡片展示申请项名称、类型、简介。申请原因为多行文本输入框（必填）配合字数统计。提示信息区说明审批人和生效方式。底部固定提交按钮。

**具体文案：** 标题「确认申请」，申请原因标签「申请原因」（必填），占位文本「请说明为什么需要这个权限，帮助审批人更快做出判断。例如：需要查看本部门考勤数据以完成月度汇总。」，提示「提交后将由审批人处理，通过后自动生效。审批处理完成前你可以撤销申请。」

**按钮：** 主按钮「提交申请」，返回按钮为次要操作。

**成功反馈：** 提交成功后展示确认页：「申请已提交。审批人：张经理。我们会通过消息通知你审批结果。」并提供「查看我的申请记录」链接。

**失败反馈：** 提交失败时展示错误原因，如申请项已不在可申请范围或网络错误，提供重试按钮。

页面 / 弹窗 / 抽屉：员工端 — 申请记录

**页面目标：** 让员工查看所有申请记录和当前状态。

**页面结构：** 顶部返回按钮和页面标题「我的申请」。筛选区按状态筛选（全部/审批中/已通过/已拒绝/已撤销）。列表区每条以卡片形式展示申请项名称、提交时间、当前状态（颜色标签区分）、审批人。点击进入申请详情页。空状态展示引导。

**具体文案：** 标题「我的申请」，状态标签：审批中（蓝色）、已通过（绿色）、已拒绝（红色）、已撤销（灰色）、已关闭（灰色），空状态「暂无申请记录」。

**按钮：** 列表项点击查看详情。

**成功反馈：** 查看类页面无需提交反馈。

**失败反馈：** 加载失败时展示空状态并允许重试。

页面 / 弹窗 / 抽屉：员工端 — 申请详情

**页面目标：** 展示单条申请的完整信息和审批结果。

**页面结构：** 顶部返回按钮和页面标题。状态横幅展示当前状态大标签和状态说明。申请内容区展示申请项名称、类型、简介、申请时间。申请原因区展示员工填写的原文。审批结果区（如有）展示审批人姓名、审批意见、处理时间。底部操作区：审批中状态展示「撤销申请」按钮，已拒绝状态展示「重新申请」按钮。

**具体文案：** 审批中横幅「审批中 — 预计审批人：[姓名]。审批处理完成前你可以撤销申请。」，已通过横幅「已通过 — 权限已生效。可在"我的权限"中查看。」，已拒绝横幅「已拒绝 — [拒绝原因]。你可以修改后重新申请。」

**按钮：** 次要按钮「撤销申请」（审批中状态），主按钮「重新申请」（已拒绝状态）。

**成功反馈：** 撤销成功后展示提示「申请已撤销」并更新页面状态。

**失败反馈：** 操作失败时展示错误原因并提供重试。

页面 / 弹窗 / 抽屉：审批端 — 申请审批详情

**页面目标：** 让审批人在一屏内完成对一条权限申请的审查和决策。

**页面结构：** 顶部返回按钮和页面标题。四段信息结构：申请人信息卡片（姓名、部门、岗位）、申请内容卡片（申请项名称、类型、说明）、申请原因卡片（员工填写的原文）、系统校验提示区（黄色提示条展示异常标记，如「该权限已被管理员从可申请范围中移除」或「申请人当前已通过其他途径拥有该权限」）。底部固定操作区。

**具体文案：** 系统校验提示如「注意：该权限已被管理员从可申请范围中移除，但申请仍然有效，你可以正常处理。」

**按钮：** 主按钮「同意」，次要按钮「拒绝」。

**成功反馈：** 同意后展示弹窗「确认同意 — 同意后系统将自动为 [姓名] 授予 [权限名称]。审批意见（选填）」，确认后反馈「处理完成。已同意 [姓名] 的权限申请。」

**失败反馈：** 拒绝时弹出「确认拒绝 — 请填写拒绝原因，员工可以看到并据此调整后重新申请。拒绝原因（必填）」，操作失败时展示错误原因。

页面 / 弹窗 / 抽屉：管理端 — 自助申请配置

**页面目标：** 让管理员在一个页面内完成能力开关、范围配置和审批策略设置。

**页面结构：** 顶部导航面包屑和页面标题「员工自助申请权限」。三个标签页分区：标签一「能力设置」包含开关控件和前置条件检查清单；标签二「可申请范围」为双栏布局（左侧全部角色/权限列表支持搜索筛选批量勾选，右侧已标记可申请的汇总区）；标签三「审批策略」包含审批人策略选择和例外设置入口。底部保存或修改配置按钮。

**具体文案：** 页面标题「员工自助申请权限」，能力开关「开启员工自助申请权限」配合说明「开启后，员工可以在自己的权限页面中发起权限申请。」，前置条件不满足提示「在开启前，需要先完成：1. 设置至少一项可申请的角色或权限；2. 完成审批流程配置。」，标签名「能力设置」「可申请范围」「审批策略」。

**按钮：** 主按钮「保存配置」（能力未开启时）或「修改配置」（能力已开启时），次要按钮「取消」。

**成功反馈：** 保存成功后提示「配置已保存」并更新页面状态。

**失败反馈：** 保存失败时展示错误原因并提供重试。

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 审批中 | 申请已提交，等待审批人处理 | 员工 | 查看详情、撤销申请 | 「申请审批中，预计审批人：[姓名]」 |
| 已通过 | 审批人已同意，权限已生效 | 员工 | 查看权限、查看申请详情 | 「申请已通过，权限已生效」 |
| 已拒绝 | 审批人已拒绝，附有拒绝原因 | 员工 | 查看拒绝原因、重新申请 | 「申请未通过：[拒绝原因]」 |
| 已撤销 | 员工主动撤销，未产生授权 | 员工、审批人 | 查看详情、重新申请 | 「申请已撤销」 |
| 已关闭 | 管理员关闭能力导致批量终止 | 员工、审批人 | 查看详情 | 「申请已终止：管理员已关闭自助申请能力」 |
| 待审批 | 新申请到达，需要审批人处理 | 审批人 | 查看详情、同意/拒绝 | 「[姓名] 申请 [权限名称]」 |
| 已处理 | 审批人已完成处理 | 审批人 | 查看详情 | 「已处理：[同意/拒绝]」 |

## 8. 待确认问题

1. **审批通过后权限是即时生效还是延迟生效？**

   影响：决定员工端「已通过」状态页的下一步指引（「权限已生效，可在我的权限中查看」还是「权限将于 [时间] 生效」），以及是否需要增加「生效中」的中间状态。
   建议确认方：产品、技术

2. **员工端「我的权限」页面当前在 IA 中的位置？**

   影响：决定申请入口的嵌入方式和导航层级。如果在个人中心，申请入口应在该页面内部；如果在设置子菜单，需要考虑提升可见性。
   建议确认方：产品、设计

3. **是否需要在员工工作台增加申请状态卡片？**

   影响：用于提醒员工「你有 1 条申请审批中」「你的申请已通过」，增加状态可见性但不增加干扰。
   建议确认方：产品、设计

4. **审批意见和拒绝原因的字数上限？**

   影响：输入框的 UI 设计和字数统计展示，以及审批详情页的信息承载。
   建议确认方：产品

5. **统计看板是否需要支持导出？**

   影响：管理端统计看板的功能范围。如果需要导出，需增加导出按钮和格式选择。
   建议确认方：产品
