# 体验蓝图

## 0. 本次关键设计判断

**判断：**

本次体验方案的核心思路是「一个工作台、三种视角、统一结果」，用一个权限查询工作台承接按人、按角色、按权限三个查询维度，结果按权限域分类展示，三类角色共享同一套页面结构但看到不同数据范围。

**主要影响：**

1. 信息架构是最大挑战——不同域的权限含义和颗粒度不同，结果页面需要在「分类清晰」和「统一表达」之间找到平衡
2. 三类角色的查询权限控制会直接影响页面入口和结果范围，但不影响页面结构和交互模式
3. 审计场景的导出需求是硬约束，导出按钮需要作为结果页的一级操作而非隐藏入口

**建议方案：**

- 查询入口设为独立的一级页面（`Page`），不作为现有页面的子 tab，因为三类角色都需要直接访问
- 查询维度用顶部 tab 切换（按人查 / 按角色查 / 按权限查），保持页面结构简洁
- 查询结果按权限域分区展示，每个区的标题说明该域权限的含义和颗粒度
- 导出按钮常驻结果区右上角，导出范围为当前查询条件下的全部结果

**不建议方案：**

- 不建议把三个查询维度拆成三个独立页面——会增加导航负担，且三个维度的结果展示逻辑高度相似
- 不建议把查询结果强行合并为一张平铺列表——不同域的权限含义不同，平铺会造成概念混淆

**关键待确认：**

1. 查询入口在管理后台导航中的具体位置——是与「角色管理」「权限管理模式」平级，还是作为「权限管理」下的子页面
2. 是否需要支持「权限验证」模式（输入人和权限项，直接返回有/没有），还是只做清单式查询

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- 权限管理员：发现权限核对需求 → 进入权限查询工作台 → 选择查询维度（按人/按角色/按权限）→ 指定查询目标 → 查看分类权限清单 → 定位异常或核对项 → 导出结果或跳转配置页
- 超级管理员：发起权限审计 → 进入权限查询工作台 → 选择按权限反查 → 指定高风险权限项 → 查看权限归属分布 → 标记异常归属 → 导出审计底稿
- 审计人员：收到审计任务 → 进入权限查询工作台 → 选择查询维度 → 输入查询条件 → 核对权限范围与合规要求 → 导出结果留档

### 旅程缺口

- 缺少查询入口在导航中具体位置的确认依据，影响「进入权限查询工作台」节点的起点表达
- 缺少审计人员是否可以使用导出之外的留痕和报告能力的信息，影响审计角色路径终点的完整性

## 2. 交互流程总览

**分角色交互流程：**

- 权限管理员：进入查询工作台 → 节点 3.1 选择查询维度 → 节点 3.2 指定查询目标 → 节点 3.3 查看结果与筛选 → 核对权限归属 → （可选）跳转配置页修正 → 节点 3.4 导出结果
- 超级管理员：进入查询工作台 → 选择按权限反查 → 指定高风险权限项 → 查看全局归属列表 → 逐项核对异常归属 → 导出审计底稿
- 审计人员：进入查询工作台 → 选择查询维度 → 输入查询条件 → 查看分类权限清单 → 核对合规性 → 导出留档

**异常流程重点：**

- 查询目标超出管辖范围时，阻断并提示「你只能查看管辖范围内的权限数据」
- 某个权限域数据不可用时，该域结果区降级展示，标注不可用原因，其他域正常展示
- 查询无结果时，展示明确空状态并区分「无权限记录」和「查询条件无匹配」
- 导出数据量过大时，异步生成文件并通过通知告知下载入口

> 不要在本节使用 ASCII 框图、字符边框图或终端布局图。

## 3. 主交互流程

### 节点 3.1：进入权限查询工作台

**用户动作：**

权限管理员、超级管理员或审计人员从管理后台导航进入「权限查询」页面。

**系统反馈：**

加载查询工作台，展示三个查询维度入口（按人查 / 按角色查 / 按权限查），默认停留在「按人查」tab。页面顶部显示当前用户的查询权限范围说明（如「你正在查看管辖范围内的权限数据」或「你正在查看全局权限数据」）。

**需要前置解释的信息：**

- 按人查：输入人员姓名或账号，查看该人员拥有的全部权限
- 按角色查：选择角色，查看该角色包含的全部权限项
- 按权限查：选择权限项，查看拥有该权限的全部人员或角色
- 查询是只读操作，不会修改任何权限配置

**建议文案：**

- 页面标题：「权限查询」
- 按人查 tab：「按人员查询」
- 按角色查 tab：「按角色查询」
- 按权限查 tab：「按权限反查」
- 权限范围提示（管辖）：「你正在查看管辖范围内的权限数据」
- 权限范围提示（全局）：「你正在查看全局权限数据」

**下一步：**

用户选择查询维度后进入节点 3.2。

### 节点 3.2：指定查询目标

**用户动作：**

在当前 tab 下输入查询目标——按人查时搜索并选择人员，按角色查时搜索并选择角色，按权限查时搜索并选择权限项。

**系统反馈：**

- 搜索框支持模糊搜索，输入时实时展示匹配结果的下拉列表
- 选择目标后，搜索框锁定为已选对象名称，旁边显示「查询」按钮
- 如果查询目标超出当前用户的管辖范围，搜索时不展示该目标，并提示「部分结果未显示，超出你的管辖范围」

**需要前置解释的信息：**

- 按人查时，搜索范围为当前用户管辖范围内的人员
- 按角色查时，搜索范围为系统中已定义的角色
- 按权限查时，搜索范围为各功能域中已定义的权限项（功能权限、数据权限等）

**建议文案：**

- 按人查搜索框 placeholder：「搜索人员姓名或账号」
- 按角色查搜索框 placeholder：「搜索角色名称」
- 按权限查搜索框 placeholder：「搜索权限项名称」
- 范围外提示：「部分结果未显示，超出你的管辖范围」

**下一步：**

用户点击「查询」后进入节点 3.3。

### 节点 3.3：查看查询结果

**用户动作：**

查看查询返回的权限清单。结果按权限域分类展示（如功能权限、数据权限、字段权限、报表权限），每个分类区可展开或折叠。用户可对结果进行筛选和排序。

**系统反馈：**

- 结果按权限域分区展示，每个区标题后标注该区包含的权限项数量
- 每个权限项展示：权限名称、权限类型、来源（直接授予/角色继承）、生效范围、生效状态
- 按人查时额外展示：该权限的来源角色（如有）
- 按角色查时额外展示：拥有该角色的成员数量
- 按权限查时额外展示：权限拥有者列表（人员名称和授予方式）
- 支持按权限类型、来源、生效状态筛选
- 结果区右上角常驻「导出」按钮
- 如果某个权限域数据不可用，该区展示降级提示：「[域名称] 暂不支持查询」，不影响其他域的展示

**需要前置解释的信息：**

- 不同域的权限颗粒度不同，分类展示是为了避免概念混淆
- 「来源」字段用于区分权限是直接授予还是通过角色继承
- 如果某个域标注了「暂不支持查询」，说明该域的数据源当前不可用，不是权限缺失

**建议文案：**

- 分类区标题示例：「功能权限（12 项）」
- 降级提示：「数据权限域暂不支持查询，不影响其他域的查询结果」
- 导出按钮：「导出结果」
- 空结果：「未查到相关权限记录」
- 筛选无匹配：「当前筛选条件下无匹配结果」

**下一步：**

用户可导出结果（节点 3.4），或跳转到具体权限的配置页进行修正。

### 节点 3.4：导出查询结果

**用户动作：**

点击结果区右上角的「导出」按钮，将当前查询结果导出为文件。

**系统反馈：**

- 如果结果数据量在阈值内（如 5000 条以内），直接触发浏览器下载，导出为 Excel 文件
- 如果结果数据量超过阈值，提示「数据量较大，将在后台生成文件，完成后通过通知告知你」，文件生成后以通知形式提供下载入口
- 导出的内容与当前查询条件和筛选条件一致

**需要前置解释的信息：**

- 导出的是当前查询和筛选条件下的全部结果，不是当前分页的可见数据
- 导出的文件包含查询条件和导出时间，便于审计留档

**建议文案：**

- 下载按钮：「导出 Excel」
- 异步生成提示：「数据量较大，文件生成后将通过通知告知你」
- 完成通知：「权限查询结果已生成，点击下载」

**下一步：**

导出完成后回到结果页，用户可继续查询其他目标。

## 4. 次交互流程

### 节点 4.1：筛选与搜索查询结果

**用户动作：**

在结果页使用筛选条件缩小查看范围。

**系统反馈：**

筛选条件包括：权限类型（功能权限/数据权限/字段权限/报表权限）、来源（直接授予/角色继承）、生效状态（已生效/未生效）。选择筛选条件后结果即时更新。如果筛选后无匹配结果，展示「当前筛选条件下无匹配结果」。

**下一步：**

清除筛选条件即可恢复完整结果。

### 节点 4.2：从查询结果跳转到权限配置

**用户动作：**

在查询结果中发现权限异常（如缺少应有权限或多出不应有权限），点击权限项旁的「配置」入口跳转到对应配置页。

**系统反馈：**

点击后新开 tab 跳转到对应的权限配置页面（如角色管理、功能授权页等）。配置完成后回到查询结果页，可重新点击查询获取最新数据。

**需要前置解释的信息：**

- 查询页不提供直接修改权限的能力，所有修改操作需跳转到对应的配置页
- 跳转为新开 tab，不覆盖查询结果

**建议文案：**

- 跳转入口：「配置」

**下一步：**

在配置页完成操作后，回到查询页重新查询可获取最新结果。

### 节点 4.3：按权限验证模式

**用户动作：**

在查询工作台切换到「权限验证」模式，同时输入人员和权限项，验证该人员是否拥有该权限。

**系统反馈：**

展示简单的是/否结果——有权限时显示「[人员] 拥有 [权限项] 权限」，并列出权限来源；没有权限时显示「[人员] 不拥有 [权限项] 权限」。结果区不展示权限清单，只回答验证问题。

**需要前置解释的信息：**

此模式用于快速单点验证（如「张三能不能看薪资报表」），不是清单式查询的替代。

**建议文案：**

- 结果肯定：「张三拥有『薪资报表查看』权限，来源：薪酬管理员角色」
- 结果否定：「张三不拥有『薪资报表查看』权限」

**下一步：**

用户可继续验证其他权限项。

## 5. 异常与阻断流程

### 异常 A：查询权限不足

**发生时机：** 用户尝试搜索超出管辖范围的人员时。
**触发条件：** 当前用户是权限管理员，且输入的查询目标不在其管辖范围内。
**判断依据：** business_note 中明确的查询权限两层控制规则——权限管理员只能查管辖范围。
**反馈形式：** 搜索下拉列表过滤 + 内联提示。
**系统反馈：** 搜索框中不展示超出管辖范围的人员。搜索结果区顶部显示：「你只能查看管辖范围内的权限数据」。
**用户下一步：** 输入管辖范围内的查询目标，或联系超级管理员开通更大范围的查询权限。

### 异常 B：查询无结果

**发生时机：** 按任意维度查询，但被查询对象没有任何权限记录时。
**触发条件：** 被查询对象在系统中的权限记录为空。
**判断依据：** facts 中明确的空状态需与查询失败区分。
**反馈形式：** 空状态插图和文案。
**系统反馈：** 「未查到相关权限记录」——区分于「查询失败」或「数据不可用」。如果被查询对象是人员，建议文案可补充：「[人员] 当前没有任何权限，如需授予权限请前往角色管理或功能授权页」。
**用户下一步：** 更换查询目标，或前往配置页进行授权。

### 异常 C：部分域数据不可用（降级）

**发生时机：** 查询结果返回时，某个权限域的数据源无响应。
**触发条件：** 某个功能域的权限查询接口超时或不可用。
**判断依据：** background 中已确认的数据源实时穿透+降级策略。
**反馈形式：** 该域的结果区展示降级状态条。
**系统反馈：** 该域分区标题旁标注「暂不支持查询」，分区内展示说明：「[域名称] 数据暂不可用，不影响其他域的查询结果。如持续出现此问题，请联系技术支持。」其他域的结果正常展示。
**用户下一步：** 查看其他可用域的结果，稍后重新查询。

### 异常 D：导出数据量超限

**发生时机：** 用户点击导出，查询结果数据量超过直接下载阈值。
**触发条件：** 当前查询结果总数超过 5000 条。
**判断依据：** facts 中标记的大数据量性能边界 [GAP]。
**反馈形式：** 弹窗确认。
**系统反馈：** 「当前结果共 [N] 条，数据量较大。文件将在后台生成，完成后通过通知告知你。」用户确认后关闭弹窗，导出任务在后台执行。
**用户下一步：** 等待通知，或缩小查询范围后重新导出。

### 异常 E：跨域数据不一致提示

**发生时机：** 查询结果中，同一个权限在不同域的记录存在冲突。
**触发条件：** 角色管理中记录了某权限，但该权限域本身的数据中无此记录（或反之）。
**判断依据：** facts 中标记的跨域不一致 [GAP]，business_note 建议标记不一致但不阻断查询。
**反馈形式：** 在受影响的权限项旁标记警告图标。
**系统反馈：** 权限项旁显示警告图标，hover 展示：「此权限记录与其他域的数据存在不一致，建议核对后处理」。
**用户下一步：** 点击跳转到对应配置页核对和修正。

## 6. 页面 / 弹窗 / 抽屉设计

### 页面：权限查询工作台

**页面目标：** 让管理员从按人、按角色、按权限三个维度查询权限归属关系，查看分类权限清单，支持导出留档。

**进入条件：** 用户具有权限管理员、超级管理员或审计人员角色，通过管理后台导航进入。

**页面结构：**

```
+--------------------------------------------------+
| 顶部信息区：页面标题「权限查询」                    |
| 权限范围说明：「你正在查看管辖范围内的权限数据」      |
+--------------------------------------------------+
| 查询维度切换： [按人员查询] [按角色查询] [按权限反查] |
+--------------------------------------------------+
| 查询目标区：搜索框 + 已选目标 + [查询] 按钮          |
+--------------------------------------------------+
| 结果工具栏：结果摘要 「共 X 项权限，Y 个域」         |
| 筛选：[权限类型▾] [来源▾] [状态▾]    [导出 Excel] |
+--------------------------------------------------+
| 结果区 — 功能权限（N 项）                    [展开] |
|  权限名称    | 类型    | 来源      | 生效范围 | …  |
|  ...                                            |
+--------------------------------------------------+
| 结果区 — 数据权限（N 项）         [暂不支持查询]    |
|  该域数据暂不可用，不影响其他域的查询结果            |
+--------------------------------------------------+
| 结果区 — 字段权限（M 项）                    [展开] |
|  ...                                            |
+--------------------------------------------------+
| 底部区：最后查询时间 + 数据来源说明                  |
+--------------------------------------------------+
```

**状态反馈区：** 页面顶部权限范围提示。结果工具栏中的结果摘要和筛选。每个域分区内的状态条（正常/降级/空）。异常标记（跨域不一致警告图标）。

**异常状态下的结构变化：**
- 查询无结果时，结果区替换为空状态插图 + 文案，保留查询目标和维度切换
- 部分域降级时，该域分区折叠为降级状态条，其他域正常展开
- 查询权限不足时，搜索框过滤掉不可查的目标，并在下拉列表中展示提示

**具体文案：**
- 页面标题：「权限查询」
- 权限范围提示（管辖）：「你正在查看管辖范围内的权限数据」
- 权限范围提示（全局）：「你正在查看全局权限数据」
- 结果摘要：「共 28 项权限，分布 3 个权限域」
- 导出按钮：「导出 Excel」

**按钮：**
- 主要按钮：「查询」（搜索框旁）
- 次要按钮：「导出 Excel」（结果工具栏右侧）
- 文字按钮：「配置」（权限项旁，跳转到配置页）

**成功反馈：** 查询完成后，结果区从加载态平滑过渡到结果展示，顶部更新结果摘要。

**失败反馈：** 查询接口异常时，结果区展示：「查询失败，请稍后重试。[重试]」。

### 弹窗：导出确认

**页面目标：** 当导出数据量较大时，告知用户异步生成方式和后续通知路径。

**进入条件：** 用户点击导出，且结果数据量超过 5000 条。

**具体文案：**
- 标题：「导出权限查询结果」
- 正文：「当前结果共 12,380 条，数据量较大。文件将在后台生成，完成后通过通知告知你。」
- 确认按钮：「我知道了」

**按钮：** 「我知道了」（关闭弹窗）。

### 弹窗：权限详情速览

**页面目标：** 在结果列表中点击某个权限项时，弹出速览面板展示该权限的详细信息。

**进入条件：** 用户在查询结果列表中点击某个权限项名称。

**具体文案：**
- 面板标题：权限项名称（如「薪资报表查看」）
- 详情区：权限类型、所属域、权限描述、生效条件
- 来源区：授予方式（直接授予/角色继承）、来源角色名称（如有）、授予时间

**按钮：** 「前往配置」（跳转到对应配置页）。

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 查询成功有结果 | 查询返回了有效的权限数据 | 所有角色 | 查看、筛选、导出、跳转配置 | 「共 X 项权限，分布 Y 个权限域」 |
| 查询无结果 | 被查询对象在系统中无任何权限记录 | 所有角色 | 更换查询目标、前往配置页授权 | 「未查到相关权限记录」 |
| 筛选无匹配 | 当前筛选条件下没有符合的结果 | 所有角色 | 调整或清除筛选条件 | 「当前筛选条件下无匹配结果」 |
| 部分域降级 | 某个权限域的数据源暂不可用 | 所有角色 | 查看其他域的结果、稍后重试 | 「[域名称] 暂不支持查询，不影响其他域的查询结果」 |
| 查询权限不足 | 查询目标超出当前用户的管辖范围 | 权限管理员 | 更换管辖范围内的目标、联系超管 | 「你只能查看管辖范围内的权限数据」 |
| 查询失败 | 查询接口异常或超时 | 所有角色 | 重试 | 「查询失败，请稍后重试」 |
| 导出成功 | 文件已生成并开始下载 | 所有角色 | — | 「文件下载已开始」 |
| 导出异步处理中 | 数据量较大，后台生成中 | 所有角色 | 等待通知 | 「文件生成后将通过通知告知你」 |
| 跨域数据不一致 | 同一权限在不同域的记录存在冲突 | 所有角色 | 跳转配置页核对 | 「此权限记录可能存在不一致，建议核对」 |

## 8. 待确认问题

1. **查询入口在导航中的具体位置**

   影响：决定用户从哪个导航路径进入查询工作台，影响三类角色的可发现性和操作习惯。
   建议确认方：产品

2. **是否需要「权限验证」模式（输入人+权限项，直接返回有/没有）**

   影响：如果确认需要，查询工作台需要增加第四种交互模式；如果不需要，主流程只保留三种清单式查询维度。
   建议确认方：产品

3. **各功能域权限数据源的查询接口可用性现状**

   影响：决定哪些域可以有完整的查询结果、哪些域需要长期展示降级状态。如果大部分域都没有可用接口，查询工作台的实际价值会大打折扣。
   建议确认方：技术

4. **导出数据量阈值和格式**

   影响：决定同步下载和异步生成的切换时机、文件格式（Excel/CSV），以及是否需要支持筛选条件导出。
   建议确认方：产品 + 技术

5. **查询结果中是否需要展示已失效或已过期权限**

   影响：决定结果列表的信息范围。如果只展示当前生效的权限，需要明确定义「生效中」的判定逻辑；如果展示全部历史权限，需要增加状态筛选和说明。
   建议确认方：产品

6. **是否需要保存常用查询条件（查询历史或快捷入口）**

   影响：影响查询工作台是否需要「查询历史」或「保存查询条件」的辅助功能。
   建议确认方：产品

7. **不同域的权限分类体系是否需要统一命名**

   影响：不同域的权限类型名称可能存在不一致（如「功能权限」在某些域叫「操作权限」），查询结果中直接使用原始域名称还是统一为标准化分类名称。
   建议确认方：产品 + 设计
