# 体验蓝图

## 0. 本次关键设计判断

**判断：**

本次重点不在多造页面，而是用最少的页面承载按人查和按角色查两个核心维度的查询体验，同时把查询结果的可解释性（来源、状态、范围）和子管理员的可见边界约束做透，让管理员查得到、看得懂、敢用。

**主要影响：**

1. 信息架构上查询与配置分离——查询入口独立于各配置页，形成新的导航节点，但查询结果页通过「去配置」与配置页保持衔接
2. 三个角色在同一套页面上的体验差异——超管全量、权限管理员受范围约束、审计人员侧重导出而非配置跳转
3. 按人查和按角色查使用不同的结果组织逻辑，不能共用同一套列表模板

**建议方案：**

- 新建权限查询入口（导航层独立），内部按 Tab 或二级入口区分「按人查询」和「按角色查询」
- 按人查的结果以人员为维度纵向展开，展示完整权限清单；按角色查的结果以角色为维度展开权限模板
- 查询结果中每条权限旁边标注来源标签（直授/角色继承/协作可见），可展开查看完整来源路径
- 子管理员进入查询页时，页面顶部常驻管理范围提示；查到空结果时分场景给出不同空状态文案
- 审计人员使用与管理员相同的查询页，但结果操作区以导出为主，不突出配置跳转

**不建议方案：**

- 不做一个「统一查询」页面把所有维度混在同一视图——按人查和按角色查的信息组织逻辑不同，强行合一体验会变差
- 不在查询结果中直接放置编辑/删除/授权的操作按钮——防止误操作，保持查询页为纯解释层
- 不把按权限反查纳入本期页面设计——数据链路未确认，做了也是残缺体验

**关键待确认：**

1. 查询入口在导航中的具体位置和层级——是独立一级导航还是挂在权限管理下的二级入口
2. 按角色查询的结果视图是否需要不同于角色管理页的信息维度（如展示每个权限被多少人员持有）

更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- 权限管理员：发现需要核对某人权限 → 进入权限查询 → 选择按人查询 → 输入人员 → 查看权限清单 → 发现异常权限 → 点击来源标签展开来源路径 → 点击「去配置」跳转到角色管理或应用管理调整 → 返回查询页确认调整结果
- 超级管理员：收到审计需求 → 进入权限查询 → 选择按人查询 → 输入人员 → 查看完整权限清单 → 导出权限报告 → 提交审计
- 审计/安全人员：需要排查高风险权限分布 → 进入权限查询 → 选择按角色查询 → 选择高风险角色 → 查看该角色下权限和持有人情况 → 导出结果用于审计留档

### 旅程缺口

- 缺少从组织架构或人员列表直接跳转到权限查询的快捷入口——管理员通常先在人员列表发现异常，再去找查询工具，中间断流
- 缺少导出报告的格式预览和内容确认环节——审计人员导出前无法预览导出内容，可能出现导出后再发现内容缺失

## 2. 交互流程总览

**分角色交互流程：**

- 权限管理员：进入权限查询 → 选择查询维度（按人/按角色）→ 输入查询条件 → 查看结果列表 → 筛选或搜索缩小范围 → 展开单条权限的来源详情 → 跳转配置页进行修改 → 确认修改生效
- 超级管理员：进入权限查询 → 选择查询维度 → 输入查询条件 → 查看全量结果 → 筛选高风险权限 → 导出权限清单 → 归档或提交审计
- 审计/安全人员：进入权限查询 → 选择查询维度 → 输入查询条件 → 查看结果 → 导出权限报告（带水印和时间戳）→ 归档

**异常流程重点：**

- 子管理员查询超出管理范围的人员时，系统不返回该人员的权限数据，提示范围受限
- 查询超时时提示缩小范围重试，不静默失败
- 查询结果中某条数据的来源信息不完整时，在该条目旁标注数据质量问题
- 导出文件生成失败时明确提示并允许重试

## 3. 主交互流程

### 节点 3.1：进入权限查询

**用户动作：**

管理员从导航菜单进入权限查询模块。

**系统反馈：**

展示查询首页，包含两个查询维度入口（按人查询 / 按角色查询）、使用说明摘要。子管理员页面顶部常驻提示：「当前管理范围：XXX 部门及下属部门」。

**需要前置解释的信息：**

- 这里是查询权限归属关系的地方，不做权限配置
- 按人查询：查看某个人员拥有的所有权限
- 按角色查询：查看某个角色包含的所有权限
- 按权限反查暂未开放

**建议文案：**

- 页面标题：「权限查询」
- 子管理员范围提示：「当前查询范围受您的管理权限限制，仅展示您管理范围内的权限数据」
- 按人查询入口文案：「按人员查询 —— 查看某个成员拥有的完整权限」
- 按角色查询入口文案：「按角色查询 —— 查看某个角色下包含的权限集合」

**下一步：**

选择按人查询或按角色查询进入对应查询页面。

### 节点 3.2：按人查询 —— 输入查询条件

**用户动作：**

在按人查询页面，通过搜索框输入人员姓名、账号，或从组织架构中选择人员。

**系统反馈：**

- 搜索框支持模糊搜索，输入时实时展示匹配的人员列表
- 选择人员后，下方显示该人员的基本信息（姓名、部门、岗位）作为确认
- 提供「查询」按钮发起查询

**需要前置解释的信息：**

- 支持按姓名或账号搜索
- 子管理员只能搜索其管理范围内的人员
- 查询结果包含该人员通过直接授予、角色继承和协作可见性获得的所有权限

**建议文案：**

- 搜索框占位文案：「输入姓名或账号搜索」
- 选择人员后确认文案：「即将查询 XXX（部门：XXX · 岗位：XXX）的权限清单」
- 查询按钮：「查询」

**下一步：**

点击「查询」，进入结果展示。

### 节点 3.3：按人查询 —— 查看结果

**用户动作：**

查看该人员的权限清单，通过筛选和搜索缩小范围，展开感兴趣的单条权限查看详情。

**系统反馈：**

- 结果区域顶部显示结果摘要：「共找到 X 条权限记录」
- 每条权限以卡片或行形式展示：权限名称、资源类型、动作、来源标签、生效状态
- 来源标签区分三种颜色或图标：直接授予、角色继承（显示具体角色名）、协作可见
- 点击单条权限可展开完整来源路径、数据范围说明、生效条件
- 支持按资源类型、来源、状态筛选
- 支持关键词搜索当前结果
- 每条结果旁提供「去配置」文字按钮

**需要前置解释的信息：**

- 同一权限如果通过多条路径获得，会分开展示、分别标注来源
- 来源标签解释：直接授予 = 管理员直接给这个人加的；角色继承 = 通过某个角色获得的；协作可见 = 通过协作关系可以看到的
- 子管理员的查询结果受管理范围限制，可能不完整

**建议文案：**

- 结果摘要：「共找到 12 条权限记录，其中直接授予 3 条，角色继承 8 条，协作可见 1 条」
- 来源标签：「直接授予」「通过角色「XXX」继承」「通过协作关系可见」
- 展开后来源路径说明：「来源路径：角色「华东区管理员」→ 应用「考勤管理」→ 功能权限「考勤数据导出」」
- 生效状态：「已生效」「待生效（2026-06-15 起效）」「已失效（2026-05-31 到期）」
- 数据范围：「数据范围：华东区（上海、杭州、南京）」
- 「去配置」按钮文案：「去配置」
- 导出按钮：「导出权限清单」

**下一步：**

- 点击「去配置」跳转到对应配置页
- 点击「导出」生成权限清单文件
- 返回修改查询条件

### 节点 3.4：从查询结果跳转配置并返回

**用户动作：**

在查询结果中点击某条权限的「去配置」，跳转到对应的配置页面（角色管理/应用管理/数据设置等）进行修改，修改完成后回到查询页确认。

**系统反馈：**

- 点击「去配置」后在新标签页打开对应配置页
- 配置页加载完成后，自动定位到相关配置区域
- 用户完成修改后回到查询页，可点击「重新查询」刷新结果

**需要前置解释的信息：**

- 配置操作不在查询页内完成，这是为了防止误操作
- 修改后需要回到查询页重新查询才能看到最新结果

**建议文案：**

- 跳转过渡提示：「正在打开角色管理页面...」
- 返回后的刷新提示：「修改已完成？点击重新查询查看最新权限结果」
- 重新查询按钮：「重新查询」

**下一步：**

返回查询页，点击「重新查询」确认修改生效。

## 4. 次交互流程

### 节点 4.1：按角色查询 —— 输入查询条件

**用户动作：**

在按角色查询页面，从角色列表中选择一个角色。

**系统反馈：**

展示角色搜索框或角色列表，支持搜索和浏览。选择角色后显示角色基本信息（角色名称、角色描述、关联人员数量）。

**建议文案：**

- 搜索框占位文案：「搜索角色名称」
- 选择角色后确认文案：「即将查询角色「XXX」（已关联 XX 名人员）的权限清单」

**下一步：**

点击「查询」查看该角色下的权限集合。

### 节点 4.2：按角色查询 —— 查看结果

**用户动作：**

查看该角色包含的权限集合。

**系统反馈：**

- 结果摘要显示权限总数和分类分布
- 权限列表按资源类型分组展示（应用权限、菜单权限、操作权限、数据权限等）
- 每条权限展示权限名称、资源类型、动作
- 可展开查看该权限当前被授予了多少人员
- 提供「查看持有人」入口（如有）

**建议文案：**

- 结果摘要：「角色「华东区管理员」包含 25 条权限，覆盖 3 个应用、12 个菜单、8 个操作、2 个数据范围」
- 「查看持有人」按钮：「查看持有该权限的人员」

**下一步：**

- 点击某条权限查看持有人
- 切换到按人查询进一步了解具体人员

### 节点 4.3：导出权限清单

**用户动作：**

在查询结果页点击「导出」，系统弹出导出确认弹窗。

**系统反馈：**

- 弹窗显示导出内容摘要：导出范围、记录数量、导出格式、包含字段
- 用户确认后，系统生成文件并提供下载
- 文件带水印（导出时间、导出人）和生成时间戳

**建议文案：**

- 弹窗标题：「确认导出权限清单」
- 弹窗内容：「本次导出包含当前查询范围内的全部 X 条权限记录。导出文件为 Excel 格式，包含权限名称、资源类型、来源、生效状态、数据范围等字段。」
- 水印提示：「导出文件包含导出人和导出时间水印」
- 确认按钮：「确认导出」
- 取消按钮：「取消」
- 导出成功反馈：「权限清单已生成，点击下载」
- 导出失败反馈：「导出失败，请重试」

**下一步：**

下载文件，或关闭弹窗继续查看。

### 节点 4.4：查询结果筛选与搜索

**用户动作：**

在查询结果页使用筛选器或搜索框缩小结果范围。

**系统反馈：**

- 筛选器按资源类型、来源、生效状态分类，选择后即时过滤结果
- 搜索框支持对当前结果的关键词搜索，即时过滤
- 结果数量随筛选实时更新

**建议文案：**

- 筛选器标签：「全部类型」「应用权限」「菜单权限」「操作权限」「数据权限」
- 来源筛选：「全部来源」「直接授予」「角色继承」「协作可见」
- 状态筛选：「全部状态」「已生效」「待生效」「已失效」
- 搜索占位文案：「在当前结果中搜索」

**下一步：**

筛选后查看过滤结果，或清除筛选恢复完整列表。

## 5. 异常与阻断流程

### 异常 5.1：子管理员查询范围受限

**发生时机：** 子管理员搜索或选择超出管理范围的人员时

**触发条件：** 被查询人员不在子管理员的「组织范围 × 应用范围」交叉边界内

**判断依据：** 业务蓝图中「子管理员可见范围约束」规则——查询时应用组织范围 × 应用范围交叉过滤

**反馈形式：** 搜索下拉列表中不展示超出范围的人员；若已选择人员后点击查询，返回空结果态的页面提示

**系统反馈：** 搜索时超出范围的人员不在匹配列表中显示；查询时若人员超出范围，结果区域展示空状态提示

**用户下一步：** 缩小查询范围到自身管理范围内，或联系超级管理员申请扩大管理范围

**建议文案：**
- 搜索无匹配：「未找到匹配的人员。请确认搜索范围是否在您的管理权限内」
- 空结果态（范围受限）：「未找到 XXX 的权限记录。当前结果受您的管理范围限制，可能未展示全部权限数据。如需扩大查询范围，请联系超级管理员」

### 异常 5.2：查询结果中来源数据不完整

**发生时机：** 查看某条权限的来源详情时

**触发条件：** 该权限的来源路径中某个环节数据缺失（如角色已删除但权限残留、数据同步延迟等）

**判断依据：** 业务蓝图中「查询结果必须可解释」规则——不可以隐藏数据不完整的条目，但必须标注

**反馈形式：** 在该权限条目旁显示警告图标和文字说明

**系统反馈：** 权限条目正常展示，但来源标签旁带警告标记，展开后可看到不完整的具体说明

**用户下一步：** 根据不完整提示判断是否需要进一步排查，或联系技术人员确认

**建议文案：**
- 条目警告标注：「部分来源信息不完整」
- 展开后详情：「该权限的来源路径中「角色名称」信息已不可用（角色可能已被删除），当前仅展示可用信息。建议联系技术人员确认此权限的实际归属」
- 数据恢复建议：「如需完整数据，请联系超级管理员或技术人员核查」

### 异常 5.3：查询超时

**发生时机：** 点击查询后，系统在规定时间内未返回结果

**触发条件：** 数据量过大、系统负载高、或权限计算链路耗时过长

**判断依据：** 业务蓝图中「查询超时保护策略」——提示缩小范围重试，不自动缩小范围

**反馈形式：** 页面中央展示加载超时提示，包含「缩小范围重试」按钮

**系统反馈：** 不静默失败，不自动降级查询范围，明确告知用户超时并提供操作指引

**用户下一步：** 缩小查询范围（如增加筛选条件、选择更小组织范围），或等待系统负载降低后重试

**建议文案：**
- 超时提示标题：「查询超时」
- 提示说明：「当前查询数据量较大，暂时未能完成。建议尝试缩小查询范围后重试。」
- 操作按钮：「缩小范围后重试」
- 替代建议：「如多次超时，建议联系技术人员检查系统状态」

### 异常 5.4：导出文件生成失败

**发生时机：** 在查询结果页点击「确认导出」后

**触发条件：** 导出数据量过大、文件生成服务异常、或格式转换失败

**判断依据：** 业务蓝图导出保护策略——导出失败需明确提示并允许重试

**反馈形式：** 弹窗或 toast 提示导出失败

**系统反馈：** 不静默失败，告知用户导出失败并提供重试入口

**用户下一步：** 点击重试，或缩小导出范围后重试

**建议文案：**
- 失败提示：「导出未能完成，请重试」
- 重试按钮：「重新导出」
- 缩小范围建议：「如多次失败，建议缩小查询范围后重新导出」

### 异常 5.5：无查询页访问权限

**发生时机：** 非授权角色尝试进入权限查询模块

**触发条件：** 当前登录用户不在允许使用权限查询的角色范围内

**判断依据：** 业务蓝图中「查询能力是只读层」规则——仍需要授权才能访问

**反馈形式：** 页面拦截提示，不展示任何查询界面

**系统反馈：** 展示无权限页面，告知用户无权访问并提供申请入口

**用户下一步：** 向超级管理员申请权限查询的访问授权

**建议文案：**
- 页面标题：「暂无访问权限」

## 8. 待确认问题

1. **查询入口在导航中的具体位置**

   影响：决定用户从哪些页面可以进入权限查询，以及查询能力在信息架构中的可见性和可发现性。如果挂在权限管理二级入口下，发现成本会高于独立一级入口。
   建议确认方：产品 / 设计

2. **按角色查询是否复用角色管理页**

   影响：如果按角色查询与角色管理页高度重叠，体验上需要明确差异化定位。建议按角色查询聚焦「该角色下的完整权限展开视图 + 每项权限的持有人统计」，与角色管理页的配置视角互补。
   建议确认方：产品

3. **子管理员管理范围的精确计算规则**

   影响：决定查询结果的过滤逻辑和空结果提示是否准确。当前业务蓝图中描述为「组织范围 × 应用范围」交叉约束，但具体计算是否包含子部门、是否包含兼岗部门等细节未定。
   建议确认方：技术 / 产品

4. **查询结果中「数据范围」字段的展示格式**

   影响：当前不同权限类型的数据范围格式不统一（组织树路径、标签、自定义表达式），在查询结果中如何统一展示直接影响用户理解成本。
   建议确认方：技术 / 设计

5. **导出文件的字段完整性和格式规范**

   影响：审计人员对导出文件有合规要求（如必须包含查询时间、导出人、数据完整性声明），如果当前不清楚具体合规要求，导出功能可能不满足审计需要。
   建议确认方：产品 / 业务

6. **按权限反查功能的预计上线时间**

   影响：如果按权限反查在近期上线，查询首页的设计需要预留入口位置；如果长期不可用，「筹备中」的占位方式可能需要调整。
   建议确认方：产品

## 附录：设计指南消费说明

### 1. 设计指南消费

| 使用依据 | 转换结果 | 落点 |
|---|---|---|
| 信息架构与可发现性原则：入口命名必须提供可预测线索 | 查询首页两个维度卡片同时展示名称和描述，让管理员在选择前就知道每个维度的用途 | 查询首页（页面 6.1） |
| 信息架构与可发现性原则：信息分块按任务语义而非数据结构分组 | 按角色查询结果按应用权限、菜单权限、操作权限等任务语义分组，而非按底层数据表分组 | 按角色查询页（页面 6.3） |
| 流程模式选择原则：字段多不等于流程多 | 查询场景不拆成步骤条流程，保持单页查询+结果展示的简洁结构 | 按人查询页（页面 6.2） |
| 认知/可读性原则：控制信息密度，线索太多会变成噪音 | 每条查询结果摘要只展示权限名称、资源类型、来源标签、状态四项，详细来源路径和范围需点击展开 | 查询结果列表（页面 6.2、6.3） |

### 2. 业务知识消费

| 业务知识 | 关键规则 / 事实 | 转换成的体验策略 | 落点 |
|---|---|---|---|
| 查询与配置路径：查询页是解释层，配置页是治理层 | 查询和配置职责不能混写 | 查询结果只展示和解释，不提供编辑入口；每条结果旁设「去配置」文字链接跳转 | 按人查询结果列表、异常流程 |
| 业务对象模型：权限判断至少涉及主体、资源、动作、范围、来源、修饰因子、状态 | scope、source、modifier、state 是查询结果不可缺的结构字段 | 查询结果契约中每条权限必须展示来源标签、生效状态、数据范围；来源分直授/角色/协作三种 | 查询结果列表、展开详情面板 |
| 角色边界：子管理员受组织范围×应用范围约束 | 可见边界与可操作边界不同 | 子管理员查询时过滤结果、空结果区分「真无权限」和「范围受限」 | 查询首页、空结果态、异常流程 5.1 |
| 体验风险模式：多来源、覆盖规则是权限体验最高风险点 | 不解释来源就无法追责 | 每条权限展开后展示完整来源路径，多来源分开展示不合并 | 展开详情面板、异常流程 5.2 |
| 对象关系：协作可见性不应被并入授权模型 | 协作可见与正式授权必须分开标注 | 来源标签独立区分为三种类型，协作可见用独立标签和颜色区分 | 结果列表、来源标签设计 |

| 缺失信息 | 影响模块 | 建议补充方向 |
