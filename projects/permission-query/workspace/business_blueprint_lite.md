# 轻量业务蓝图

## 0. 路线说明

**判断：**

这次是既有能力扩展，不改底层的授权模型、角色关系、业务规则或状态机。当前需要的是先收敛查询路径和业务边界，再落到体验承接上，不适合做完整业务蓝图。

**主要影响：**

1. 查询路径收敛：需要明确"按人查、按角色查、按权限项查"三条查询路径各自的数据来源和聚合逻辑，但不需要重新定义权限对象
2. 结果可解释性：查询结果必须回答"为什么有、为什么没有、来自哪里"，这直接影响管理员是否敢基于查询结果做后续操作
3. 查询与配置的边界：查询只负责解释和排障，不能模糊成配置入口

**建议方案：**

- 三条查询路径各自独立承载，共用同一套权限数据源，但信息架构不强行统一
- 先做按人查（当前可行路径最成熟），再补按角色查和按权限项查
- 查询结果统一标注来源、优先级和生效状态

**需要重新判断的信号：**

1. 如果后续决定查询结果中嵌入"一键修改"或"快速授权"等配置操作，需要回到完整业务蓝图
2. 如果按权限项反查需要跨系统（如报表权限查报表系统），需要重新评估复杂度

## 1. 一句话结论

可以做，而且当前权限数据基础已经具备。核心不是"能不能查"，而是"怎么让管理员查得明白、查完敢动手"。关键判断：查询结果不标注来源和覆盖规则，就等于没查。

## 2. 关键业务规则

1. 每条查询结果必须标注权限来源（直授 / 角色继承 / 应用可见性 / 协作规则），不允许只列权限清单不标来源
2. 当同一权限存在多个来源时，必须显式展示最终生效结果和覆盖原因（如：应用不可见覆盖了个人已持有的功能权限）
3. 查询结果中不提供编辑、删除、新增等配置入口，查询页与配置页之间通过导航串联，不在同一页面混用
4. 查询结果按"应用 → 权限类型（功能权限 / 数据权限 / 表单权限 / 字段权限 / 报表权限）"两级聚合
5. 按角色查时，结果分两个维度：该角色包含的权限清单 + 持有该角色的人员列表
6. 按权限项反查时，结果展示持有者列表及各自的获得方式
7. 查询能力本身可能受权限控制（待确认），如果子管理员只能查管辖范围，查询结果需要做数据过滤
8. 现有三种治理模式（子管理员、双管理员互审、权限变更审批）不影响查询结果的展示逻辑，查询只读不干预治理

## 3. 边界与风险

**不能放开的限制：**

- 查询页不能变成配置页——如果管理员在查询结果中看到问题，需要跳转到对应配置页去修改，不能原地编辑
- 查询结果不能伪造数据完整性——如果某项权限类型的数据查询链路还未打通（如报表权限），必须在对应区域明确标注"暂不支持"，不能假装数据完整
- 按权限项反查不支持模糊搜索——权限项必须从权限树中选择或精确搜索，避免歧义

**最关键的风险：**

- RISK-002 权限来源不透明：管理员看到结果但不知道怎么来的 → 不敢改，查询价值归零
- RISK-003 覆盖规则违背直觉：管理员看到用户有权限但实际不能用 → 误以为系统异常
- RISK-005 查询分裂：管理员在查询页查不到想查的信息，又回到各个设置页翻找 → 查询页形同虚设

**对应保护策略：**

- 每条结果必须标注来源 + 优先级 + 生效状态，不可省略
- 覆盖规则在结果中显式说明（如"该权限因应用不可见而当前不生效"）
- 查询维度不贪多——本次聚焦需求文档明确的三个维度（按人、按角色、按权限项），不强行纳入按应用查和按变更查

## 4. 体验承接要求

**角色：**

- 权限管理员：高频使用按人查和按角色查，需要快速定位 + 完整详情
- 超级管理员：偏重审计视角，需要按权限项反查 + 全局视图
- 审计 / 安全人员：偏重定期核对，需要清晰的权限分布快照和导出能力

**流程：**

- 按人查：选择人员 → 查看按应用聚合的权限清单 → 点击单条查看详情（来源链路、授权时间、操作人）
- 按角色查：选择角色 → 查看权限清单 / 查看人员列表（双 tab）
- 按权限项反查：搜索或浏览权限树选择权限项 → 查看持有者列表 → 点击人员跳转到按人查详情
- 三条路径之间支持互相跳转（如：按人查结果中点击某个角色 → 跳转按角色查）

**进度与结果状态：**

- 查询结果中的权限状态标注：已生效 / 未生效 / 生效中（如有定时生效机制）
- 查询操作本身无状态流转，但结果需要反映权限的当前状态
- 如果权限处于变更审批中，查询结果需要区分"当前已生效的权限"和"审批中待生效的权限"

**异常：**

- 查无结果：必须给出可能原因（该用户未加入企业 / 该用户未被分配任何权限 / 该权限项当前无人持有 / 搜索条件过于严格等）
- 权限来源冲突：显式标注覆盖规则和最终生效结果
- 数据缺失：对查询链路未打通的权限类型，标注"暂不支持查询"而非静默为空
- 无查询权限：如果当前操作者没有查询权限，给出明确提示和申请路径

**反馈：**

- 查询结果加载中：按应用维度渐进展示，避免全局 loading
- 大量结果：支持按应用折叠/展开，默认全部折叠
- 高危权限项（如导出、删除、批量操作）：在结果中做视觉强调，方便审计人员快速定位

**文案：**

- 权限来源的文案需要统一且直观：如"直授（张三，2025-03-15）"、"角色继承（财务主管角色）"、"应用可见性覆盖（应用不可见，当前不生效）"
- 空状态文案区分场景："该用户暂未分配任何权限" vs "该权限项当前无人持有" vs "暂不支持此类权限查询"
- 覆盖规则说明用大白话："该权限来自角色授权，但因应用整体不可见，当前不生效。如需生效，请先调整应用可见范围。"

## 5. 升级信号

出现以下变化时，应停止当前轻量执行并请求 UXB 重新判断：

1. 需求方要求在查询结果中直接编辑、新增或删除权限（查询页变成配置页）
2. 按权限项反查需要跨系统聚合（如接入报表系统、审批系统的权限数据）
3. 查询维度超出当前三个维度（按人、按角色、按权限项），新增按变更查、按应用查等维度且需要统一数据模型
4. 查询结果需要支持实时权限计算而非查询已有数据快照
