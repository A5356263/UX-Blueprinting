# Facts

> 输入来源：`source/requirement.md`、`source/background.md`

## 任务概述

本次需求补齐权限统一查询能力，支持管理员从"按人"、"按角色"、"按权限项"三个维度查询权限归属关系。当前系统权限数据分散在用户授权、角色管理、应用管理等多个页面，管理员需要来回切换逐项核对，缺少统一的查询视角，不利于权限审计和风险排查。

涉及角色（来源：`source/requirement.md` 第3节）：
- 权限管理员：负责查看、核对、调整权限配置，是主要使用者
- 超级管理员：用于全局权限审计、异常排查和权限治理
- 审计 / 安全管理人员：核对人员权限、角色权限和高风险权限分布

主要场景（来源：`source/requirement.md` 第4节）：
- 权限核对：管理员在离职交接、入职授权后核对权限配置是否准确
- 权限审计：审计人员定期审查权限分布，识别异常授权
- 安全排查：在高风险事件后快速定位特定权限的持有人
- 日常排障：管理员解释用户"为什么有/没有某项权限"

## 功能范围

### 按人查询权限
- 做什么：输入或选择用户，查看该用户当前拥有的所有权限，按应用聚合展示，每项权限标注来源（直授/角色继承/应用可见性/协作规则）和生效状态
- 谁使用：权限管理员、超级管理员、审计人员
- 优先级：P0

### 按角色查询权限
- 做什么：选择角色，查看该角色包含的权限清单以及持有该角色的人员列表
- 谁使用：权限管理员、超级管理员
- 优先级：P0

### 按权限项反查
- 做什么：选择某项权限（功能点），反查哪些人员或角色持有该权限，标注获得方式
- 谁使用：权限管理员、超级管理员、审计人员
- 优先级：P0

### 查询结果下钻
- 做什么：点击单条权限结果，展开详情面板，展示完整来源链路、授权时间、操作人、审批记录
- 谁使用：权限管理员、超级管理员
- 优先级：P1

## 关键业务规则

（来源：`source/background.md` 中"关键业务对象"和"已知体验风险"）

1. 查询结果中的每条权限必须标注来源类型（直授、角色继承、应用可见性、协作规则），不然管理员不敢动手改（对应 RISK-002）
2. 当同一权限存在多个来源时，必须显式展示最终生效结果和覆盖原因（对应 RISK-003）
3. 查询只负责解释和排障，不承担配置职责——查询结果中不提供编辑或修改入口
4. 查询能力复用现有权限数据，不对底层授权对象、角色关系、业务规则做任何修改
5. 应用可见性不等于功能权限，功能权限不等于数据权限——查询结果需要区分这些概念边界
6. 协作可见性与管理授权是两套独立模型，查询结果中需要区分展示

## 状态流转

本次查询能力不引入新的业务状态。权限本身的生效/未生效状态、变更审批中的状态沿用现有模型，查询结果中如实反映即可。

（来源：`source/background.md` 中"当前查询能力现状"——查询是对现有数据的只读视图，不产生状态变更）

## 异常与边界

1. 查无结果时：不能只显示"无结果"，需解释可能原因（用户未加入企业、未分配任何权限、权限未生效等）
2. 权限来源冲突时：显式标注覆盖规则和最终生效结果
3. 跨域数据缺失时：如果某项权限类型（如报表权限）的查询链路还未打通，在对应区域标注状态，不伪造成完整数据
4. 查询入口位于权限管理模块内，不与应用管理、角色管理中的已有查询功能冲突
5. 按权限项反查的权限项粒度待确认 [GAP]：是最低到菜单/页面级别，还是一直下钻到按钮/操作级别
6. 查询结果是否支持导出 [GAP]：审计场景通常需要导出做留档，但需求文档未明确

## 依赖与前置条件

- 依赖现有权限数据模型（主体、资源、动作、范围、来源、修饰因子），查询结果的数据来源均来自现有授权体系
- 依赖现有权限查询入口（来源：`source/background.md` 中"当前查询能力现状"）：
  - 按用户查：已有「权限查询」入口和「按用户查询结果」页，可行性为 feasible
  - 按角色查：角色管理页可查看角色成员，但缺少独立查询页，可行性为 partial
  - 按权限项查：缺少按功能点反查持有者的独立承载页，现状为 GAP
- 依赖组织底座中的成员主体信息作为查询的"人"维度输入
- 查询能力不依赖审批中台或外部系统

## 开放问题与缺口

1. [GAP] 查询结果是否需要支持导出？影响结果页的信息层级设计和交互（来源：需求文档未提及）
2. [GAP] 查询权限本身是否有权限控制？子管理员是否只能查管辖范围内的权限数据，还是全企业？影响查询结果的数据范围过滤逻辑（来源：需求文档未提及）
3. [GAP] 按权限项反查时，权限项的最低粒度是什么？菜单/页面级还是按钮/操作级？直接影响结果页的信息承载量（来源：需求文档未提及）
4. [GAP] 按变更查的路径当前分散在权限域和审批域之间，本次是否需要一并收敛？需求文档未提及变更查询，但背景文档指出该路径当前为 partial 状态
5. [GAP] 按应用查的路径已有可行承载（应用管理页），本次需求文档未将其设为查询维度，是否需要纳入统一查询入口？
