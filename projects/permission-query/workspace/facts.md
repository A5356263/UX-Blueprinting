# Facts：结构化需求交接

## 1. 核心需求事实

- [FACT] 用户主体：权限管理员（日常核对）、超级管理员（全局审计与异常排查）、审计/安全管理人员（合规检查）
- [FACT] 当前场景：权限核对、离职交接、权限审计、安全排查、风险治理
- [FACT] 当前卡点：权限分散在应用、菜单、页面、操作、数据、表单、字段、报表等多个功能域中，每个域有独立的配置入口，管理员需要跨页面拼凑信息来还原一个人的完整权限画像
- [FACT] 当前处理方式：在不同设置页面之间切换，逐项核对，手动拼接权限归属关系
- [FACT] 不解决的后果：权限核对效率持续低下；离职交接容易遗漏权限回收；安全审计无法快速定位高风险权限分布；企业合规风险累积
- [CONFIRMED] 用户目标：从按人、按角色、按权限三个维度快速查看权限归属关系，查到的是完整、可解释、可追溯的结果
- [CONFIRMED] 已明确约束：权限颗粒度不统一（功能权限、数据权限、表单权限、字段权限、报表权限等共存）；权限来源多样（直接授予、角色继承、协作可见性）；现有底层数据路径按人查最完整、按角色查部分可行、按权限反查待核实

## 2. 功能范围

### 2.1 按人查询权限

- 使用角色：权限管理员、超级管理员、审计/安全人员
- 操作目标：输入一个人员，查看其拥有的完整权限清单
- 输入：人员标识（姓名/账号/部门筛选）
- 输出：该人员的权限列表，每条包含权限名称、资源类型、动作、数据范围、来源（直授/角色继承/协作可见）、生效状态
- 结果：管理员获得该人员的完整权限画像，可进一步跳转到对应配置页或导出

### 2.2 按角色查询权限

- 使用角色：权限管理员、超级管理员
- 操作目标：输入一个角色，查看该角色包含的权限集合
- 输入：角色标识
- 输出：该角色下挂载的权限清单，每条包含权限名称、资源类型、动作
- 结果：管理员获得该角色的权限模板视图
- [GAP] 独立查询语义与结果视图是否已定义

### 2.3 按权限反查人员

- 使用角色：超级管理员、审计/安全人员
- 操作目标：输入一项具体权限或功能点，反查拥有该权限的所有人员
- 输入：权限/功能点标识
- 输出：拥有该权限的人员列表，每人附带来源和生效状态
- 结果：管理员获得高风险权限的持有人分布
- [GAP] 底层数据路径是否支持此维度反查待核实

### 2.4 按变更查询权限台账（独立能力建议）

- 使用角色：超级管理员、审计/安全人员
- 操作目标：查看权限变更历史记录
- 输入：时间范围、人员或角色筛选
- 输出：权限变更记录列表，包含变更时间、变更内容、变更人、变更原因
- 结果：审计人员获得可追溯的权限变更台账
- [GAP] 当前权限域缺少统一变更台账页，变更分散在权限域与审批域之间

## 3. 关键业务规则

### 3.1 查询结果最小契约

- 触发条件：任意维度的权限查询
- 处理结果：每条查询结果必须包含权限名称、资源类型、动作、数据范围、来源（直授/角色继承/协作可见）、生效状态、范围边界
- 不满足时：查询结果不可信，管理员无法基于结果做下一步判断或操作
- 关联约束：来源字段必须区分「直接授予」「角色继承」「协作可见」三种路径，协作可见性不得与正式授权结果混写

### 3.2 查询角色可见边界

- 触发条件：不同管理角色发起查询
- 处理结果：超级管理员看到全量结果；子管理员受「组织范围 × 应用范围」双重约束，仅可查询其管理范围内的权限数据
- 不满足时：子管理员可能看到越权信息，或查到空结果不知是「无权限」还是「无权查看」
- 关联约束：子管理员查到空结果时，需明确提示「当前结果受您的管理范围限制」，与「该人员确实无此权限」区分

### 3.3 查询与配置职责分离

- 触发条件：用户在查询结果页想要修改权限
- 处理结果：查询页是解释层，不做直接编辑；每条结果旁提供「去配置」入口，跳转到对应配置页面
- 不满足时：查询页上直接编辑容易误操作；完全没有跳转则导致查完即断流
- 关联约束：信息架构上查询入口和配置入口应各自独立导航，不混在同一页面内

### 3.4 多来源权限叠加解释

- 触发条件：同一人员通过多条路径获得同一权限
- 处理结果：查询结果中展开显示每条来源路径，不合并为单一结论
- 不满足时：管理员无法判断该权限是正常授予还是异常获得；审计场景下无法追溯
- 关联约束：个人直授与角色授予可叠加展示，协作可见性独立标注

## 4. 状态流转

| 状态 | 触发条件 | 下一状态 | 用户可见反馈 | 备注 |
| --- | --- | --- | --- | --- |
| 查询发起 | 管理员输入查询条件并提交 | 查询中 | 加载态，显示查询进度提示 | |
| 查询中 | 系统检索权限数据 | 有结果 / 无结果 / 部分结果 | 过渡态，不超过合理响应时间 | |
| 有结果 | 检索到匹配的权限记录 | 结果展示 | 按维度组织的权限列表，每条带来源、状态、范围 | |
| 无结果（真） | 该人员确实无权限 | 空结果展示 | 提示「未查询到该人员的权限记录」 | |
| 无结果（范围受限） | 子管理员查询超出管理范围的人员 | 空结果展示 | 提示「当前结果受您的管理范围限制，可能未展示全部权限」 | 与真无结果区分 |
| 结果→配置跳转 | 用户点击某条结果的「去配置」入口 | 对应配置页 | 跳转到角色管理/应用管理/数据设置等对应配置页 | |
| 结果导出 | 用户发起导出 | 导出文件 | 生成可下载的权限清单文件 | 审计场景关键路径 |

## 5. 异常与边界

| 异常 / 边界 | 触发条件 | 系统处理 | 用户是否有补救路径 | 备注 |
| --- | --- | --- | --- | --- |
| 按权限反查数据链路不完整 | 用户尝试按权限反查 | [GAP] 当前是否阻断查询待确认 | [GAP] 是否需要降级提示或建议替代维度 | 知识库标注为 GAP |
| 按角色查独立语义不完整 | 用户尝试按角色查 | [GAP] 当前结果是否能完整呈现角色权限模板 | 可回退到角色管理页查看 | 角色管理页已有承载 |
| 多来源权限冲突 | 同一人员角色A授予某权限、角色B限制该权限 | 展开显示所有来源路径，标注冲突状态 | 用户可跳转到对应角色或权限配置页处理 | |
| 查询结果过多 | 超大规模企业查询返回数千条记录 | 分页加载，支持筛选和搜索 | 可增加筛选条件缩小范围或导出全量 | |
| 查询超时 | 数据量大或系统负载高导致查询超时 | 提示查询超时，建议缩小范围 | 可缩小查询范围后重试 | |
| 无权限访问查询页 | 非授权角色试图进入查询页 | 提示无权限，拒绝进入 | 需向管理员申请权限 | |

## 6. 依赖与前置条件

- [CONFIRMED] 外部系统依赖：权限数据来源于现有权限配置系统（角色管理、应用管理、数据设置、协作设置等）；组织架构底座提供人员与部门关系；审批域提供权限变更审批记录
- [CONFIRMED] 已有能力边界：按人查询链路最完整；按角色管理页已有承载但独立查询语义不完整；按权限反查链路待核实；按变更查缺少统一台账
- [CONFIRMED] 必须复用的底座能力：现有权限判断引擎的决策链（可见性→功能权限→数据范围→治理修饰）；现有组织范围计算逻辑（用于子管理员可见边界约束）；现有角色管理与授权配置的页面入口
- [CONFIRMED] 不允许新增的概念 / 能力：不得在查询页引入独立的权限授予或回收操作；不得新建与现有权限引擎不一致的判断逻辑；不得绕过现有角色边界直接暴露全量数据给子管理员

## 7. GAP / 待确认

| GAP | 为什么缺 | 影响 business 还是 experience | 不确认的风险 |
| --- | --- | --- | --- |
| 按权限/功能点反查的底层数据路径是否已闭环 | 知识库标注为 GAP，当前产品未确认该链路状态 | 同时影响 business 和 experience：决定该维度能否进入本期范围 | 若强行上线但链路不通，结果残缺，用户看不出也不会被告知 |
| 按角色独立查询的语义和结果视图是否已定义 | 角色管理页承载了配置功能，但独立查询语义未明确 | 主要影响 experience：决定按角色查询的页面设计和结果组织方式 | 做出来的按角色查询与角色管理页功能重叠，价值不清晰 |
| 子管理员在查询场景下的可见范围规则是否已明确 | 角色边界卡定义了子管理员的组织范围×应用范围约束，但查询场景的具体规则未被确认 | 同时影响 business 和 experience：决定查询结果的过滤逻辑和空结果提示策略 | 子管理员可能看到越权数据或对空结果产生误解 |
| 审计人员需要的是实时在线查询还是导出+历史快照 | 需求文档未区分审计场景与日常管理场景 | 同时影响 business 和 experience：决定是否需要独立的审计报告能力 | 用实时查询满足审计需求可能无法满足合规对历史快照和不可篡改记录的要求 |
| 查询结果与变更台账的关系 | 按变更查当前分散在权限域与审批域之间 | 主要影响 business：决定变更台账是否纳入本次范围 | 若混入本次查询范围，会拉大需求跨度，且变更台账需要独立的审批域数据支持 |
