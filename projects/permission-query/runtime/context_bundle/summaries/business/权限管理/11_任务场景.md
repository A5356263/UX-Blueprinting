## 1. 知识定位

这是一份权限域的任务场景卡，用来回答“高频权限任务分别走哪些页面与链路、每条链路的关键目标和说明是什么”。

它是从任务到路径的映射卡，比能力地图更贴近实际操作场景。

## 2. 任务触发线索

当任务要解决“给谁开权限、为什么有/没有权限、角色怎么批量分发、治理模式怎么开启、应用入口怎么控”等具体业务问题时，应优先读取本文件。

它也适合做任务流设计和排障入口判断。

## 3. 覆盖内容

本文件覆盖权限域的高频任务场景，重点包括：

- 给单个用户开权限：`用户授权 -> 功能授权 -> 数据授权 -> 权限详情`
- 批量给人授权/移除：以 `用户授权` 的批量操作为主入口
- 查看某人为什么有/没有权限：`权限查询 -> 按用户查询结果 -> 权限详情`
- 用角色批量分发权限：`角色管理 -> 功能权限/数据权限 -> 角色成员管理`
- 配角色自动授权规则：`角色管理 -> 授权规则`
- 开启子管理员分权：`权限管理模式 -> 子管理配置页`
- 开启双管理员互审：`权限管理模式 -> 双管理员模式配置页`
- 开启权限变更审批：`权限管理模式 -> 权限变更审批模式配置页 -> 审批管理`
- 控成员之间可见性：`成员协作权限`
- 控应用入口与应用管理员：`应用管理 -> 应用设置页`
- 当前缺口：批量授权后的统一结果核对页尚未明确

## 4. 可直接使用的稳定结论

- 权限域的高频任务天然分成授权、解释、角色模板化、治理模式、协作可见性和应用治理几类链路。
- 单人授权主链路是“用户授权 -> 功能授权 -> 数据授权”，而不是单页完成全部配置。
- 角色链路承担的是模板化分发与自动授权，不应与按人排障链路混写。
- 权限查询链路承担解释职责，不承担配置职责。
- 治理模式的开启本质上是在改变生效机制与责任边界，而不是直接授予业务权限。
