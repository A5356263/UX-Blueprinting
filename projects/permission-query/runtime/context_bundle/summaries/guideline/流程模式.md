# 流程模式选择原则

- source_path: knowledge/raw/设计准则/流程模式.md
- domain: 设计准则
- summary_role: light_route_card
- updated_at: 2026-05-28

## 定位
解决"长表单、复杂配置页该用步骤条（Wizard）还是单页表单"的流程模式选择判断问题。面向 B 端专家用户的高频录入/编辑型任务，提供从流程效率、任务依赖和风险控制角度提炼出的流程模式决策依据，防止出现"字段多就加步骤条"的默认错误。

## 触发信号
- 面对字段多/表单长的 B 端录入或编辑任务，需要决定使用步骤条还是单页表单时
- 评估已有步骤条是否真正满足"强依赖/不可逆/高风险"门禁条件时
- 设计资料可分批收集、二次修改频繁的长表单交互时

## 稳定结论
- B 端专家场景的长表单默认不用步骤条——不以字段多/表单长/看起来复杂作为步骤条理由
- 步骤条仅用于"真实分步流程"：后续强依赖前一步结果、分阶段校验/提交、一次性不可逆、低频高风险——四者至少满足其一
- 字段多不等于流程多：先判断任务依赖关系再决定是否分步，不要按字段数量做决定
- 单页长表单配合锚点导航是步骤条的推荐替代方案，提供全局视角与随机存取，支持跳填和暂存/草稿策略
- 单页模式必须控制信息密度并保证分块清晰、定位便捷
