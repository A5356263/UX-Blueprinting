# Experience Blueprint

## 0. 本次关键设计判断

**判断：**

本次体验方案的核心思路是：在现有权限查询页内统一接入三个查询维度，通过维度切换而非页面跳转来区分查询模式，查询结果按权限类型分层展开，优先呈现摘要再支持逐层下钻。

**主要影响：**

1. 现有权限查询页需要从单一维度扩展为三维切换入口，页面信息架构需要重新设计
2. 查询结果页从当前仅支持按用户结果，扩展为支持三种维度的结果呈现，不同维度的结果结构和信息层级不同
3. 角色化可见边界的截断提示需要在查询发起和结果呈现两个环节都显式表达

**建议方案：**

- 权限查询页作为统一入口，顶部用维度切换组件区分"按用户 / 按角色 / 按功能权限"三个模式
- 按功能权限维度下用标签页切换"应用/菜单"和"功能点"两个子层级
- 结果页采用渐进式信息披露：先按应用聚合展示摘要，再按按权限类型分组，最后支持点击查看详情
- 子管理员进入查询页时，页面顶部固定展示管理范围提示条

**不建议方案：**

- 不建议为三个维度分别设计完全不同的结果页——维护成本高且用户心智模型割裂
- 不建议在查询结果中内嵌权限修改能力——会模糊查询和配置的职责边界

**关键待确认：**

1. 按角色查的查询维度入口是否与按用户查、按功能权限反查放在同一层级
2. 查询结果中五类权限的默认展开/折叠策略

## 1. 旅程图

```md
- 权限管理员（日常核对）：
  进入权限查询页 → 选择查询维度 → 指定查询对象 → 查看结果概览（按应用聚合）→ 展开查看权限明细 → 确认核对结果
  如发现异常 → 点击跳转至用户授权页或角色管理页 → 完成配置修改

- 超级管理员（安全审计）：
  进入权限查询页 → 切换至按功能权限反查 → 选择目标功能点 → 查看持有人列表 → 点击某个持有人查看完整权限 → 导出审计记录
  如发现高风险权限分布 → 发起权限治理流程

- 审计人员（合规检查）：
  进入权限查询页 → 按人查或按角色查 → 逐个核查权限归属 → 导出权限清单 → 归档审计记录
  如查询范围受限 → 申请扩大查询权限 → 重新查询

- 子管理员（日常管理）：
  进入权限查询页 → 页面提示当前管理范围 → 在范围内查询 → 查看结果（截断范围外数据）→ 如需扩大范围 → 联系超管
```

### 旅程缺口

- 从查询结果跳转到配置页后，缺少返回查询页并保留上次查询条件的回退路径
- 权限变更后缺少自动刷新查询结果的通知机制
- 批量查询场景（如一次查多个人员的权限）目前不在本次范围内

## 2. 交互流程总览

**分角色交互流程：**

- 权限管理员：选择维度 → 指定对象 → 发起查询 → 查看结果概览 → 可选展开权限类型 → 可选查看详情弹窗 → 可选跳转配置 → 可选导出
- 超级管理员：选择按功能权限反查 → 选择子层级 → 指定目标 → 查看持有人 → 可选导出审计记录
- 审计人员：选择维度 → 指定对象 → 查询 → 逐项核对 → 导出清单
- 子管理员：进入查询页（看到范围提示）→ 在范围内查询 → 查看截断结果 → 如需超范围 → 提示联系超管

**异常流程重点：**

- 查询对象超出管理范围：阻断查询，提示管理边界
- 查询结果为空：区分"无权限记录"和"超出管理范围"
- 存在待生效的权限变更：结果中标注待生效状态
- 查询超时：提示缩小范围或稍后重试
- 导出敏感数据：二次确认弹窗

## 3. 主交互流程

### 节点 3.1：选择查询维度

**用户动作：**

管理员进入权限查询页，在页面顶部的维度切换区选择本次查询维度（按用户 / 按角色 / 按功能权限）。

**系统反馈：**

选中维度高亮激活，页面中部的查询条件区域根据所选维度动态切换内容：
- 按用户：展示人员选择器
- 按角色：展示角色选择器
- 按功能权限：展示子层级切换（应用/菜单 / 功能点）+ 对应的选择器

**需要前置解释的信息：**

- 每个维度旁边附带简短说明：按用户 = "查看某个人的全部权限"，按角色 = "查看某个角色包含的权限"，按功能权限 = "反查某权限被谁持有"
- 子管理员进入页面时，顶部固定展示管理范围提示条："当前查询范围受限于您的管理边界：[组织范围] × [应用范围]。如需扩大范围，请联系超级管理员。"

**建议文案：**

- 维度标签："按用户查"、"按角色查"、"按功能权限反查"
- 管理范围提示："你当前的查询范围受限于管理边界，查询结果不包含范围外的数据"

**下一步：**

指定查询对象后，点击"查询"按钮进入结果页。

### 节点 3.2：按用户查询结果

**用户动作：**

管理员在查询页选择"按用户查"，选择目标人员，点击查询。

**系统反馈：**

进入按用户查询结果页。页面顶部保留查询条件栏（可切换维度、修改查询对象、重新查询）。主体区域按应用聚合展示该用户的权限概况：每个应用一行，展示应用名称、已授权功能数/总功能数、数据权限范围摘要。点击某个应用行展开该应用下的权限明细，按权限类型分组（功能权限 → 数据权限 → 表单权限 → 字段权限 → 报表权限）。每条权限标注来源（"直接授予"或"通过XX角色获得"）和生效状态（"已生效"或"待生效"）。右上角提供"导出"按钮。

**需要前置解释的信息：**

- 分子/分母的含义说明：已授权功能数/该应用总功能数，用于快速判断权限覆盖深度
- 权限来源说明：直接授予的权限与通过角色获得的权限用不同标签区分
- 待生效标注：如果存在审批中的权限变更，在受影响的应用行标注"存在待生效变更"

**建议文案：**

- 结果标题："{人员姓名} 的权限详情"
- 空结果："该人员当前无单独配置的权限记录。如存在全员默认权限，请查看全员默认权限说明。"
- 待生效提示："该应用下有 {N} 项权限变更正在审批中，当前展示为审批前的生效状态。查看审批进度 →"

**下一步：**

点击应用行展开权限明细；点击"权限明细"按钮打开权限详情弹窗（只读）；点击"导出"按钮导出权限清单；发现异常后可点击应用行旁的"去配置"跳转到用户授权页。

### 节点 3.3：按角色查询结果

**用户动作：**

管理员切换至"按角色查"，选择目标角色，点击查询。

**系统反馈：**

进入按角色查询结果页。页面顶部保留查询条件栏。角色基本信息区展示角色名称、成员数量、创建时间。主体区域按应用聚合展示该角色承载的全部权限，结构同按用户查询结果。差异点：结果中不标注权限来源（因为全部来自该角色），但需展示"自动授权规则"摘要（如果该角色配置了自动授权规则）。

**需要前置解释的信息：**

- 角色是模板化授权中介，这里展示的是角色的能力包定义，不等于每个成员的实际权限
- 如果角色配置了自动授权规则，需要说明"满足规则的人员会自动获得此角色的全部权限"

**建议文案：**

- 结果标题："{角色名称} 的权限详情"
- 成员入口："该角色当前有 {N} 位成员。查看成员列表 →"（点击跳转角色管理页）
- 空结果："该角色尚未配置功能权限。去配置 →"（跳转角色管理页的功能权限设置）

**下一步：**

展开权限明细；查看角色成员列表；跳转角色管理页配置权限。

### 节点 3.4：按功能权限反查结果

**用户动作：**

管理员切换至"按功能权限反查"，选择子层级（应用/菜单或功能点），指定目标，点击查询。

**系统反馈：**

进入反查结果页。页面顶部保留查询条件栏。如果选择"应用/菜单"层级，结果以列表展示持有该页面权限的全部人员和角色，区分"直接授予"和"通过角色持有"两类。如果选择"功能点"层级，结果以列表展示持有该具体操作点的全部人员和角色。每个持有人行展示姓名、所属组织、持有来源、生效状态。支持按"仅看人员"或"仅看角色"过滤。

**需要前置解释的信息：**

- "应用/菜单"层级和"功能点"层级的区别：按菜单反查展示的范围更广（含该菜单下所有功能点的持有人汇总），按功能点反查更精准
- 如果查询目标存在层级关系（如应用 → 菜单 → 功能点），结果中需要展示当前层级和可切换的提示

**建议文案：**

- 结果标题（应用/菜单）："持有'{页面名称}'权限的人员和角色"
- 结果标题（功能点）："持有'{功能点名称}'权限的人员和角色"
- 来源标签："通过 {角色名称} 持有"
- 空结果："未找到持有该权限的人员或角色。请检查权限名称是否正确，或尝试按上级菜单维度查询。"

**下一步：**

点击人员姓名查看该人员的完整权限；点击角色名称跳转角色管理页；导出持有人清单。

## 4. 次交互流程

### 节点 4.1：导出查询结果

管理员在任一查询结果页点击"导出"按钮。系统弹出二次确认弹窗："你即将导出当前查询结果，包含 {N} 条权限记录。权限数据属于敏感信息，请妥善保管导出文件。" 如果结果超过500条，弹窗追加提示："当前结果量较大，建议先通过筛选条件缩小范围后再导出。" 用户确认后，系统生成文件并下载。

### 节点 4.2：从查询结果跳转配置

管理员在查询结果中发现权限异常（如缺漏、多余或不符），点击应用行或权限行旁的"去配置"按钮。系统跳转到对应的配置页面（用户授权页或角色管理页），并在跳转时携带查询对象的上下文信息。配置完成后，管理员可点击返回按钮回到查询结果页，系统保留上次的查询条件，管理员可重新查询验证修改结果。

### 节点 4.3：查看权限详情弹窗

管理员在查询结果中点击"权限详情"按钮，打开只读的权限详情弹窗。弹窗展示该用户或角色在该应用下的完整权限明细：按业务模块组织的功能点矩阵和对应的数据权限范围。弹窗内支持端切换（电脑端/移动端）和导出。不提供任何修改入口。

### 节点 4.4：查询条件重置与重新查询

管理员在结果页修改查询对象或切换维度后，点击"查询"按钮重新发起查询。系统清除旧结果，加载新结果。如果管理员切换了查询维度（如从按用户切到按角色），查询条件区同步切换，但保留上一次的查询对象作为建议值（如果适用）。

## 5. 异常与阻断流程

### 异常 5.1：查询对象超出管理范围

**发生时机：** 子管理员在选择查询对象时选择了一个不在其管理范围内的人员或角色
**触发条件：** 选择的查询对象不属于当前管理员的组织管辖范围 × 应用管辖范围
**判断依据：** 来自 business_blueprint.md 第6节"必须守住的规则和边界"
**反馈形式：** 人员选择器内提示 + 查询发起前页面状态提示
**系统反馈：** "该人员不在你的管理范围内，无法查询其权限信息。如需查询，请联系超级管理员扩大你的管理范围。"
**用户下一步：** 重新选择查询对象，或联系超管

### 异常 5.2：查询结果为空

**发生时机：** 查询完成后返回空结果
**触发条件：** 查询对象确实没有任何单独配置的权限记录
**判断依据：** 来自 facts.md《异常与边界》
**反馈形式：** 空状态页面
**系统反馈：** "该人员当前无单独配置的权限记录。" + 补充说明："如存在全员默认权限，请参考全员默认权限说明。" + 链接："查看全员默认权限 →"
**用户下一步：** 如果确认需要为该人员配置权限，点击"去配置"跳转到用户授权页

### 异常 5.3：存在待生效的权限变更

**发生时机：** 查询结果中部分权限处于审批中、尚未生效
**触发条件：** 查询对象的权限变更已提交审批但未完成
**判断依据：** 来自 facts.md《异常与边界》和 business_blueprint.md 第7节风险四
**反馈形式：** 结果页顶部信息提示条 + 受影响行标注
**系统反馈：** "该人员的 {N} 项权限变更正在审批中。以下展示的是当前生效的权限状态，审批通过后会自动更新。" + 链接："查看审批进度 →"
**用户下一步：** 等待审批完成，或前往审批页查看进度

### 异常 5.4：查询超时

**发生时机：** 在超大型企业中进行全局反查时查询响应超时
**触发条件：** 查询涉及的数据量过大，后端查询超时
**判断依据：** 来自 business_blueprint.md 第7节风险三
**反馈形式：** 查询失败提示
**系统反馈：** "查询超时，可能因为当前数据量较大。建议缩小查询范围（如先选择具体应用再查询）后重试。"
**用户下一步：** 通过筛选条件缩小查询范围后重试

### 异常 5.5：导出敏感数据确认

**发生时机：** 管理员点击"导出"按钮
**触发条件：** 任何导出操作
**判断依据：** 来自 business_blueprint.md 第6节"必须二次确认的操作"
**反馈形式：** 二次确认弹窗
**系统反馈：** "你即将导出当前查询结果，包含 {N} 条权限记录。权限数据属于敏感信息，请妥善保管导出文件。确定导出？"
**用户下一步：** 确认导出或取消

### 异常 5.6：子管理员结果被截断

**发生时机：** 子管理员查看查询结果时，部分数据被管理边界截断
**触发条件：** 查询结果中包含子管理员范围外的权限关系
**判断依据：** 来自 business_blueprint.md 第6节和第7节风险二
**反馈形式：** 结果页顶部固定提示条 + 截断位置标记
**系统反馈：** "部分结果因超出你的管理范围而未展示。如需查看完整数据，请联系超级管理员。"
**用户下一步：** 在现有结果中继续核对，或联系超管扩大范围

## 6. 页面 / 弹窗 / 抽屉设计

### 页面 6.1：权限查询页（统一入口）

**页面目标：** 提供三个查询维度的统一进入入口，帮助管理员选择合适的查询方式并指定查询对象

**进入条件：** 管理员（任何具有权限查询菜单权限的角色）从通用权限管理菜单进入

**页面结构：**
- 顶部标题区："权限查询"
- 维度切换区：三个选项卡——"按用户查"、"按角色查"、"按功能权限反查"
- 查询条件区：根据当前维度动态展示对应的选择器
  - 按用户：人员搜索选择器 + 查询按钮
  - 按角色：角色搜索选择器 + 查询按钮
  - 按功能权限：子层级标签页（"应用/菜单" / "功能点"）+ 对应选择器 + 查询按钮
- 引导说明区：右侧展示当前维度的使用场景说明和示例
- 子管理员专属：页面顶部管理范围提示条（固定展示）

**状态反馈区：** 页面顶部（管理范围提示条）、查询条件区下方（校验提示）

**异常状态下的结构变化：**
- 子管理员选择超出范围的对象时：选择器下方展示红色提示文字，查询按钮保持可点击但发起后返回阻断提示
- 功能点标签体系不完善时：功能点选择器降级为关键词搜索输入框

**具体文案：**
- 页面标题："权限查询"
- 维度标签："按用户查"、"按角色查"、"按功能权限反查"
- 查询按钮："查询"
- 引导说明（按用户）："查看某个成员当前拥有哪些权限，以及每条权限的来源"
- 引导说明（按角色）："查看某个角色包含哪些成员，以及该角色承载的全部权限"
- 引导说明（按功能权限）："反查某个页面或某个功能点被哪些人员和角色持有"

**按钮：** 主按钮"查询"，无次要按钮

**成功反馈：** 点击查询后跳转到对应的查询结果页

**失败反馈：** "查询对象不在管理范围内"、"查询对象不存在"、"请先选择查询对象"

### 页面 6.2：按用户查询结果页

**页面目标：** 按应用聚合展示某个用户的完整权限覆盖情况，支持按应用过滤和逐层下钻

**进入条件：** 从权限查询页按用户维度发起查询

**页面结构：**
- 顶部查询条件栏：保留维度切换 + 人员选择器 + 查询按钮（可修改查询对象重新查询）
- 结果标题区："{姓名} 的权限详情" + 导出按钮
- 应用搜索过滤栏：输入框"搜索应用名称"
- 权限概览列表：按应用分组的卡片式或表格式列表
  - 每个应用行：应用名称、应用分类、已授权功能数/总功能数、终端图标、数据权限摘要、操作按钮
  - 展开后的权限明细：按权限类型分组的折叠区（功能权限 → 数据权限 → 表单权限 → 字段权限 → 报表权限）
  - 每条权限：权限名称、来源标签、生效状态
- 分页区：底部页码

**状态反馈区：** 顶部信息提示条（待生效变更提示）、结果标题区下方（结果统计）

**异常状态下的结构变化：**
- 空结果：展示空状态插画 + 说明文字 + "去配置"按钮
- 超管理范围：展示阻断页，不进入结果
- 查询超时：展示错误提示 + "缩小范围"建议

**具体文案：**
- 结果统计："共 {N} 个应用，{M} 项权限"
- 应用行操作："查看详情"、"去配置"
- 权限类型分组："功能权限（{N}项）"、"数据权限"、"表单权限"、"字段权限"、"报表权限"
- 来源标签："直接授予"、"通过 {角色名} 获得"
- 生效状态："已生效"、"待生效"

**按钮：** "导出"（主要）、"去配置"（文字链接）、"查看详情"（文字链接）

**成功反馈：** 结果列表正常加载

**失败反馈：** "查询失败，请重试"、"查询超时，建议缩小范围"

### 页面 6.3：按角色查询结果页

**页面目标：** 展示角色基本信息及其承载的全部权限模板，帮助管理员核对角色的能力包定义

**进入条件：** 从权限查询页按角色维度发起查询

**页面结构：**
- 顶部查询条件栏：同按用户结果页
- 角色基本信息区：角色名称、描述、成员数量（可点击跳转）、授权规则摘要
- 权限概览列表：结构同按用户结果页
- 分页区

**状态反馈区：** 同按用户结果页

**异常状态下的结构变化：** 同按用户结果页。角色已停用时在基本信息区标注"该角色已停用"。

**具体文案：**
- 成员入口："该角色当前有 {N} 位成员。查看成员列表 →"
- 已停用标注："该角色已停用，以下为停用前的权限配置记录"

**按钮：** "导出"、"查看成员"、"去配置"、"查看详情"

### 页面 6.4：按功能权限反查结果页

**页面目标：** 展示某个权限项被哪些人员和角色持有，支持按持有人类型过滤

**进入条件：** 从权限查询页按功能权限维度发起查询

**页面结构：**
- 顶部查询条件栏：保留维度切换 + 子层级切换 + 目标选择器 + 查询按钮
- 结果标题区："持有'{权限名称}'权限的人员和角色"
- 过滤标签栏："全部"、"仅人员"、"仅角色"
- 持有人列表：
  - 人员行：姓名、所属组织、持有来源（直接授予/通过XX角色）、生效状态
  - 角色行：角色名称、成员数量、操作
- 分页区

**状态反馈区：** 同其他结果页

**异常状态下的结构变化：** 空结果时提示检查权限名称或切换到上级菜单维度查询

**具体文案：**
- 过滤标签："全部（{N}）"、"人员（{M}）"、"角色（{K}）"
- 来源标签："直接持有"、"通过 {角色名} 持有"
- 空结果："未找到持有该权限的人员或角色。建议：检查权限名称是否正确，或尝试按上级菜单维度查询。"

**按钮：** "导出"、"查看人员详情"、"查看角色详情"

### 弹窗 6.5：权限详情弹窗

**页面目标：** 以只读方式展示某个用户或角色在特定应用下的完整权限明细

**进入条件：** 在任一查询结果页点击"查看详情"

**页面结构：**
- 弹窗标题："权限明细 - {应用名称}"
- 端切换区：电脑端/移动端标签
- 主体区域：左侧业务模块导航 + 右侧权限矩阵（功能点 × 数据权限）
- 来源说明区：标注每条权限的授予来源
- 底部操作栏："导出"按钮 + "关闭"按钮

**状态反馈区：** 权限矩阵中各功能点的勾选状态和权限来源标签

**异常状态下的结构变化：**
- 无数据权限时：数据权限列显示"无数据权限限制"或"全部数据权限"
- 存在待生效变更时：受影响行右侧标注"待生效"

**具体文案：**
- 弹窗标题："权限明细 - {应用名称}"
- 端切换："电脑端"、"移动端"

**按钮：** "导出"（次要）、"关闭"（主要）

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 已生效 | 权限当前有效，用户可使用 | 所有权限记录 | 无（只读） | 无额外标注 |
| 待生效 | 权限变更已提交审批但尚未生效 | 有审批中的权限变更的记录 | 查看审批进度 | "待生效"标签 + 跳转审批链接 |
| 已停用 | 角色或应用已停用，权限不再生效 | 已停用角色/应用的权限记录 | 无（历史记录） | "已停用"标签 + 停用时间 |
| 管理范围截断 | 子管理员查询结果被管理边界截断 | 子管理员的查询结果 | 联系超管扩大范围 | 页面顶部固定提示条 |
| 空结果-无记录 | 查询对象无单独配置的权限 | 查询结果页 | 去配置或查看默认权限 | 空状态页面 + 配置引导 |
| 空结果-超范围 | 查询对象不在管理范围内 | 查询发起时 | 重新选择或联系超管 | 阻断提示文字 |

## 8. 待确认问题

1. **按角色查询的入口是否与按用户查并列**

   影响：如果按角色查询入口放在角色管理页内作为内嵌功能，权限查询页就只需要两个维度，信息架构更简单；如果三个维度都在权限查询页内并列，入口更统一但页面复杂度更高。
   建议确认方：产品

2. **查询结果中五类权限的默认展开/折叠策略**

   影响：如果默认全部展开，信息量大但管理员可能感到信息过载；如果默认只展开功能权限摘要，需要确保管理员能发现其他四类权限的存在。
   建议确认方：设计和产品

3. **权限详情弹窗中端切换的数据可用性**

   影响：如果移动端权限数据与电脑端差异较大，弹窗内端切换时需要明确标注差异。当前知识库记录多端权限确实可能存在差异。
   建议确认方：研发

4. **导出的文件格式和内容范围**

   影响：影响导出功能的具体设计和合规审核流程。
   建议确认方：产品和安全

5. **功能点标签体系是否足以支撑按功能点反查**

   影响：如果功能点没有统一标签和搜索入口，该子层级可能无法在首期交付，需要先只支持应用/菜单维度。
   建议确认方：研发和产品
