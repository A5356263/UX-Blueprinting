# 子管理员支持复制

## 需求背景

集团型企业使用子管理员模式下放权限管理能力。部分客户子管理员数量较多（如广西交投 200+），这些子管理员的「可授权功能」通常一致，但「可授权组织」不同。当前配置需逐个子管理员单独勾选相同功能权限，实施工作量大、配置效率低。

## 目标

新增「复制」能力，使权限管理员可以：

- 复制某个子管理员的可授权组织
- 复制某个子管理员的可授权功能
- 批量复制给多个用户（最多 200 名）
- 将普通用户快速设置为子管理员
- 对已有子管理员叠加授权范围
- 记录复制操作，满足审计和追溯要求

## 用户与角色

| 角色 | 说明 |
| --- | --- |
| 权限管理员/超级管理员 | 负责维护子管理员及其可授权范围，可执行复制操作 |
| 子管理员（复制来源） | 提供可授权组织或可授权功能配置 |
| 复制对象用户 | 接收复制过来的权限，可能原本不是子管理员，也可能已经是 |

## 核心场景

1. **批量配置子管理员权限**：管理员复用已配置好的子管理员权限，避免重复勾选
2. **普通用户成为子管理员**：复制对象原本不是子管理员时，复制成功后成为子管理员
3. **已有子管理员叠加权限**：复制对象已经是子管理员时，在其原有配置基础上叠加

## 功能范围

- 复制入口：子管理员模式列表操作列新增「复制」
- 复制弹窗：包含复制信息（可授权组织、可授权功能）和复制对象（用户选择器）
- 选择员工弹窗：样式与添加子管理员弹窗一致，仅展示已启用且已认证的员工
- 校验：按顺序校验复制信息、复制对象、加入状态、认证状态
- 复制结果：成功 toast 提示，生成操作记录
- 双管理员互审：若开启则生成审批

## 复制规则

1. 复制对象原本不是子管理员 → 成为子管理员，设置对应权限
2. 复制对象原本已是子管理员 → 叠加不覆盖

## 关键业务约束

1. 复制入口仅出现在子管理员模式中
2. 复制来源必须是已有子管理员
3. 复制信息至少选一项
4. 复制对象至少选一名，最多 200 名
5. 复制对象必须满足加入状态和认证状态要求
6. 叠加不覆盖原有权限
7. 普通用户接收复制后成为子管理员
8. 复制成功必须生成操作记录
9. 开启双管理员互审模式时需按互审规则生成审批

## 不明确事项

1. 加入状态最终统一为"已启用"还是"已加入"？
2. 复制来源是否允许只复制部分组织或功能？
3. 部分用户校验失败时，全部阻断还是跳过失败用户？
4. 复制给已有子管理员时，重复组织或功能是否自动去重？
5. 复制对象达到权限上限时如何处理？
6. 复制成功后是否在弹窗内展示结果明细？
7. 双管理员互审模式下，审批通过前权限是否生效？
8. 审批拒绝后是否需要回滚复制结果？
9. 操作记录中复制对象过多时是否需要折叠展示？
10. 是否需要埋点统计？
