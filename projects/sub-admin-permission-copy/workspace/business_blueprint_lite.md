# 轻量业务蓝图

## 0. 路线说明

**判断：**

这次是既有能力扩展，适合轻量业务承接。核心业务对象不变，主要压力在新增操作路径、异常分支和双管理员互审的待确认规则上。

**主要影响：**

1. 新增复制入口和弹窗流程，但不改变子管理员底层权限模型
2. 新增叠加规则（已有子管理员叠加不覆盖）和身份转换规则（普通用户转子管理员）
3. 双管理员互审模式下的审批规则未定，可能影响复制生效时序和回滚策略

**建议方案：**

- 按轻量业务判断输出关键规则和体验承接要求
- 双管理员互审部分作为待确认问题独立标注，不在本次方案中展开完整审批流程
- 复制来源权限粒度、部分校验失败策略、去重和上限处理等 [GAP] 项，在未确认前采用最保守策略（全部复制、全部阻断、不去重）作为默认假设

**需要升级时机：**

1. 双管理员互审审批规则确认后，涉及复制前审批、拒绝回滚等完整审批链路
2. 需求扩展到跨模块权限复制（如从子管理员复制到角色模板）
3. 引入复制来源部分选择、差异化复制等复杂策略

## 1. 一句话结论

可以做。在现有子管理员管理能力上新增复制操作，核心是解决批量配置的效率问题。建议先守住「复制来源完整配置、校验全部通过才执行、已有子管理员叠加不覆盖」三条底线，双管理员互审相关规则待确认后再补充。

## 2. 关键业务规则

**复制来源必须是已有子管理员。** 不能从非子管理员用户复制权限。复制入口只在子管理员模式中出现。

**复制信息至少选一项，复制对象至少选一名。** 打开弹窗时默认全选复制信息（可授权组织 + 可授权功能），用户可取消但至少保留一项。复制对象通过员工选择器选择，上限 200 名。

**复制对象必须满足准入条件。** 加入状态为已启用、认证状态为已认证，两项不满足的用户不能成为复制目标。员工选择器中只展示满足条件的员工。

**已有子管理员叠加不覆盖。** 如果复制对象已经是子管理员，复制后在其原有可授权功能和组织基础上叠加，不覆盖已有配置。普通用户接收复制后直接成为子管理员。

**复制成功必须生成操作记录。** 可授权组织和可授权功能分别生成一条操作记录，记录来源子管理员和所有复制对象。

**校验顺序固定。** 先校验复制信息是否勾选 → 再校验复制对象是否选择 → 再逐个校验加入状态 → 再逐个校验认证状态。任一环节不通过即阻断，不进入后续校验。

## 3. 边界与风险

**不能放开的限制：**
- 复制入口不能出现在子管理员模式之外的页面
- 复制来源只能是已有子管理员，不能是任意用户
- 复制对象上限 200 名，不能超出
- 复制对象必须满足加入状态和认证状态要求，不能绕过

**最关键的风险：**

1. 双管理员互审审批规则缺失 [GAP]。若审批通过前权限已生效，审批拒绝后需要回滚，回滚逻辑和影响面较大。建议在审批规则确认前，先按"复制即生效 + 审批作为事后审计"处理，避免引入复杂的暂存状态。

2. 部分校验失败的处理策略缺失 [GAP]。若采用全部阻断，200 名中 1 人不通过则全部失败，体验较差。建议默认采用全部阻断，先保证数据一致性，后续可迭代为跳过失败用户。

3. 重复权限叠加可能产生冗余数据。已有子管理员被多次复制相同组织或功能时，是否去重会影响权限数据的整洁度。建议默认不去重（叠加语义），由后端在权限计算时去重。

4. 复制对象权限上限未定义。如果某个用户的可授权范围存在上限，复制可能超出。建议先不在本版本处理上限逻辑，超出时由业务方人工调整。

## 4. 体验承接要求

**角色：**
- 权限管理员/超级管理员：复制操作的发起者和决策者
- 子管理员（复制来源）：被复制的源对象，不参与交互
- 复制对象用户：接收权限的目标，不感知复制过程，复制结果体现在其子管理员权限中

**流程：**
- 主流程必须闭环：入口（列表操作列）→ 弹窗（选择复制信息和复制对象）→ 校验（四级顺序校验）→ 结果（成功 toast）
- 如果开启双管理员互审，审批环节需要独立承接，不能在复制弹窗中混入审批逻辑 [GAP]
- 操作记录需在复制成功后即时生成，用户可从操作记录入口查看

**进度与结果状态：**
- 复制只有两个终态：成功（toast 提示）或失败（具体校验报错）
- 不存在"部分成功"的中间状态（基于全部阻断策略的默认假设）
- 双管理员互审场景下，如果确认审批前置，需增加"审批中"中间状态 [GAP]

**异常：**
- 复制信息未勾选 → 阻断，提示"请选择复制信息"
- 复制对象未选择 → 阻断，提示"请选择至少一名复制对象"
- 部分用户加入状态不符 → 阻断，提示具体用户名和"加入状态不是已加入"
- 部分用户认证状态不符 → 阻断，提示具体用户名和"未完成实名认证"
- 每个阻断都需要让用户清楚知道"哪里不对"和"怎么修正"

**反馈：**
- 成功反馈用 toast，文案为"复制成功"，简洁明确
- 失败反馈在弹窗内展示，不关闭弹窗，让用户可直接修正
- 操作记录在后台生成，不需要在弹窗内展示结果明细（除非后续确认需要）

**文案：**
- 复制入口按钮："复制"
- 弹窗标题："复制"
- 复制信息区域：标签"复制信息"，选项"可授权组织""可授权功能"，默认全选
- 复制对象区域：标签"复制对象"，提示"最多可以复制给 200 名用户"
- 确认按钮："确认"
- 校验报错：按需求文档中的报错文案执行

## 5. 升级信号

出现以下任一情况时，应升级到完整业务蓝图：

1. 双管理员互审审批规则确认，涉及审批前置、审批中暂存状态、拒绝回滚等完整审批链
2. 复制来源支持部分选择（只复制某几个组织或功能），引入差异化复制策略
3. 引入复制后编辑能力（复制预览 → 调整 → 确认）
4. 跨能力复制（如子管理员权限复制为角色模板、跨企业复制）
5. 引入定时复制、批量导入复制对象等高级操作

## 6. 待确认问题

1. 加入状态口径统一为"已启用"还是"已加入"？影响筛选和报错文案
2. 复制来源是否允许只复制部分组织或功能？影响弹窗交互的复杂度
3. 部分用户校验失败时全部阻断还是跳过失败用户？影响异常反馈的设计
4. 已有子管理员重复权限是否自动去重？影响数据策略，建议后端处理
5. 双管理员互审的完整规则（何时生成审批、审批通过前权限状态、拒绝后是否回滚）？影响方案完整度，建议作为独立需求跟进
