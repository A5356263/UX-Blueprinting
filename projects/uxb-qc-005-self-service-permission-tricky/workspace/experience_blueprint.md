# 体验蓝图：员工自助申请权限（刁钻版）

> 输入来源：facts.md + business_blueprint.md + 已装配设计准则（可用性/流程模式/信息架构/认知/反馈与报错）

## 0. 本次关键设计判断

本次体验设计的特殊之处：business明确了3条安全红线（拒绝先授权后审批/拒绝默认全部可申请/拒绝自动通过），experience需要将这些立场转化为用户可见的规则和反馈。核心原则：
- 员工端：**不展示"临时生效"状态**——只有审批通过后才显示"已生效"（承接business立场1）
- 管理端：**不允许空白可申请范围**——开启能力时强制校验（承接business立场2）
- 审批端：**审批人缺失时不自动通过**——展示兜底说明（承接business立场3）

## 1. 交互流程总览

管理员开启能力（强制配置白名单+审批人）→ 员工查看权限 → 发现缺失 → 在白名单内选择可申请权限 → 提交申请 → 审批人处理 → 通过后授权生效 → 员工收到通知。

## 2. 主交互流程

### 2.1 管理端开启能力（强制白名单配置）

管理端4步开启流程——但第2步有强制校验：
- Step 1：了解能力简介
- Step 2：**配置可申请范围（白名单模式）**——默认空，必须至少选1项才能进入下一步。**不提供"全部可申请"选项。** 顶部提示："选择员工可以申请的具体权限范围。建议从非敏感角色和常用功能权限开始。"
- Step 3：配置审批流程——默认组织负责人。**不提供"自动通过"选项。**
- Step 4：确认开启——校验可申请范围非空+审批人配置有效

### 2.2 员工端申请（仅展示白名单内权限）

- "申请权限"按钮：**仅在可申请范围非空时可用**——如果管理员未配置任何白名单，按钮置灰，hover提示"当前无可申请的权限，请联系管理员"
- 申请表单中仅展示白名单内的权限——**不展示全部权限列表**
- 提交后Toast"申请已提交，请等待审批"——**不展示"权限已临时生效"**

### 2.3 员工查看申请状态

**不展示"临时生效"状态。** 状态仅4种：审批中/已通过（权限已生效）/已拒绝/已撤销。

### 2.4 审批端

审批人缺失时：不自动通过。系统提示"审批人不可用，已自动转给超级管理员处理"，同时通知超管。

## 3. 次交互流程

### 3.1 管理端调整白名单配置
- 进入管理页 → 点击调整配置 → 修改白名单范围 → 保存。"可申请范围"始终以白名单形式展示——不提供"全部可申请"开关。
- [GAP] 调整白名单后，已提交未审批的申请是否受影响待确认。

### 3.2 管理端查看统计与操作记录
- 统计卡片展示申请数/通过率/处理时长。
- 操作记录列表展示每次开启/关闭/调整配置/申请/审批/授权操作。

### 3.3 员工撤销申请
- 审批中的申请支持撤销，需二次确认。[GAP] 建议支持。

## 4. 异常与阻断流程

### 4.1 可申请范围为空（白名单未配置）
- 管理端：开启能力时校验——白名单为空时「确认开启」置灰，提示"请至少配置一项可申请范围。不提供'全部可申请'选项是为了保护权限安全。"
- 员工端：「申请权限」按钮置灰，hover提示"当前无可申请的权限，请联系管理员"。

### 4.2 审批人不存在或已离职
- 系统自动将申请转给超级管理员。——**不自动通过。**
- 员工端状态"审批中（审批人变更中）"。
- 超管收到通知"审批人[姓名]不可用，权限申请已自动转给你处理"。

### 4.3 审批超时未处理
- 向审批人发提醒 → 超时自动升级给超管。
- 员工端展示"已等待X天"，提供「催办」按钮。

### 4.4 管理员关闭能力
- 确认弹窗说明关闭影响：不接受新申请；审批中申请继续走完流程。[GAP] 已授权权限是否保留待确认。
- 向有审批中申请的员工发通知。

### 4.5 频繁申请风控
- 24h内超5次申请 → 提示"你今天已提交多次申请，请确认确实需要这些权限后再提交"——但仍允许提交。

### 4.6 模式互斥冲突
- 开启能力时检测到互斥模式 → 阻断弹窗说明原因。

### 4.7 员工尝试申请管理员权限
- 管理员权限不在白名单可选项中出现——员工看不到所以无法申请。

## 5. 页面 / 弹窗 / 抽屉设计

### 5.1 管理端：开启能力第2步（白名单配置）
```
┌──────────────────────────────────────────┐
│ 配置员工可申请的权限范围（白名单模式）       │
│ ──────────────────────────────────────── │

│ 请选择员工可以申请的具体权限范围。           │
│                                          │
│ 按角色：[☐ 普通员工 ☑ 部门助理 ☐ 项目成员]  │
│ 按功能权限：[☑ 员工管理-查看 ...]           │
│                                          │
│ 已选 5 项                        [下一步]  │
└──────────────────────────────────────────┘
```

### 5.2 员工端：申请权限页
- 仅展示白名单内的可申请权限——**不展示全部权限列表。**
- 不在白名单内的权限不出现——员工不知道就无法申请。

### 5.3 员工端：我的申请页
- 状态标签：审批中（黄色）/ 已通过+已生效（绿色）/ 已拒绝（红色）/ 已撤销（灰色）。
- **不展示"临时生效"标签。**

### 5.4 审批端：审批详情页
- 完整展示申请人、内容、原因、附件。同意/拒绝按钮。

### 5.5 管理端：关闭能力确认弹窗
- 说明关闭影响。复选框确认。

## 6. 状态与反馈文案

| 场景 | 文案 |
|------|------|
| 白名单为空时开启 | 请至少配置一项可申请范围。不提供"全部可申请"选项是为了保护权限安全。 |
| 白名单为空时员工申请 | 当前无可申请的权限，请联系管理员 |
| 审批人缺失（员工端） | 审批中（审批人变更中）——原审批人不可用，已自动转给管理员 |
| 审批人缺失（超管端通知） | 审批人[姓名]不可用，权限申请已自动转给你处理 |
| 频繁申请 | 你今天已提交多次申请，请确认确实需要这些权限后再提交 |
| 模式互斥冲突 | 当前已有[XX模式]运行，与员工自助申请权限模式互斥 |
| 提交成功 | 申请已提交，请等待审批 |
| 审批通过 | 你申请的[权限名称]已审批通过，权限已生效 |

## 7. 待确认问题

| 问题 | 当前处理 |
|------|----------|
| 关闭后已授权权限是否保留 | [GAP] 建议保留，需产品确认 |
| 关闭时审批中申请处理 | [GAP] 建议继续走完流程 |
| 模式互斥关系 | [GAP] 需确认互斥范围和共存条件 |
| 敏感权限是否允许自助申请 | 方案中不允许——不在白名单中出现 |
| 服务人员是否开放 | 方案中不开放 |
| 员工能否申请管理员权限 | 方案中不能——不在白名单中出现 |
| 审批人默认是谁 | 建议组织负责人 |
| 是否多级审批 | 建议支持 |

## 附录：设计指南消费说明

- **BFM-02** → 管理端开启能力4步流程，第2步强制校验白名单非空
- **U-01** → 不展示"临时生效"状态——只有审批通过后的"已生效"
- **反馈原则1.2** → 白名单为空时置灰按钮+说明原因；冲突弹窗前置说明
- **反馈原则1.3** → 审批人缺失时明确告知转交谁，而非静默通过
- **C-01（Hick's Law）** → 白名单模式减少员工的选择数量——只展示可申请的而非全部权限
- **C-04（渐进式披露）** → 不在白名单的权限完全不展示——员工不需要知道"有什么不能申请"
