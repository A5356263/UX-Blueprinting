# 体验蓝图：子管理员支持复制

> 输入来源：business_blueprint.md + facts.md + 已装配设计准则（可用性、流程模式、反馈与报错）

## 0. 本次关键设计判断

本次体验设计的核心是在复制弹窗内完成全部交互——不是多页面流程，而是一个弹窗承载"选择内容+选择对象+校验反馈"。基于 BFM-02（分步引导）：复制弹窗分为"复制信息"和"复制对象"两个区域而非两个步骤——因为两个区域的信息密度都不高，可以在一个弹窗内完成。4步校验采用顺序阻断模式——应用反馈原则1.2（操作前说明）：在点击确认前先校验，遇到第一个失败立即阻断并提示。

## 1. 交互流程总览

管理员在子管理员模式列表→找到目标子管理员→点击操作列"复制"→弹窗打开（复制信息默认全选+选择复制对象）→点击确认→顺序校验→校验通过→复制执行→toast"复制成功"+弹窗关闭+列表刷新+操作记录生成→（如开启互审→触发审批[GAP]）

## 2. 主交互流程

### 2.1 复制入口
- 子管理员模式列表，操作列最左侧新增"复制"
- 操作列顺序：复制 | 编辑 | 删除 | ...

### 2.2 复制弹窗

弹窗标题"复制子管理员权限"。分为两个区域：

**复制信息区**：
- 标题"复制信息（必选至少一项）"
- 复选框：☑ 可授权组织 / ☑ 可授权功能
- 默认全选——应用C-05（默认效应）：管理员通常两者都复制
- 取消所有勾选时，「确认」按钮置灰+提示"请选择复制信息"

**复制对象区**：
- 标题"复制对象"
- 提示文字"最多可以复制给200名用户"
- 已选用户以标签展示（可✕移除）
- "选择员工"按钮打开选择员工弹窗
- 总人数超过200时阻断："最多可以复制给200名用户"

### 2.3 选择员工弹窗
- 复用添加子管理员弹窗样式（U-04 一致性标准）
- 仅展示：加入状态=已启用、认证状态=已认证的员工
- 支持搜索和多选
- 底部展示已选人数

### 2.4 校验顺序（不可跳转）

点击确认后按顺序校验，遇到失败立即阻断：

1. 复制信息未勾选 → 弹窗内提示："请选择复制信息"，「确认」按钮不关闭弹窗
2. 复制对象未选择 → 弹窗内提示："请选择至少一名复制对象"
3. 加入状态不符 → 弹窗内提示："张三、李四 加入状态不是已加入，不能成为子管理员"（展示具体用户名）
4. 认证状态不符 → 弹窗内提示："王五 未完成实名认证，不能成为子管理员"

这4步校验不跳转页面，所有提示在弹窗内展示——应用 U-01（状态可见）

### 2.5 复制成功
- Toast："复制成功"
- 弹窗关闭，列表刷新
- 生成操作记录

## 3. 次交互流程

### 3.1 编辑已选对象
- 复制对象输入框中已选用户展示为标签（姓名+✕）
- 点击✕移除单个用户
- 点击"选择员工"继续添加

### 3.2 操作记录查看
- 记录文案："将子管理员【张三/138xxxx】可授权组织复制给【李四/139xxxx】【王五/137xxxx】"
- [GAP] 超过3人折叠："将子管理员【张三/138xxxx】可授权组织复制给【李四/139xxxx】等50人"

## 4. 异常与阻断流程

### 4.1 超过200人
- 用户在选择员工弹窗中已选200人后继续添加
- 系统阻断："最多可以复制给200名用户"
- 用户需先移除部分已选用户才能继续添加

### 4.2 部分用户校验失败
- 用户点击确认，系统按顺序校验
- [GAP] 策略待确认：当前方案采用全部阻断——任一用户校验失败，复制不执行，弹窗不关闭，提示失败用户名单
- 用户可移除失败用户后重试

### 4.3 双管理员互审触发
- 系统检测到双管理员互审模式已开启
- 复制成功后弹出提示："复制操作需要审批，已提交审批申请" [GAP: 文案取决于审批时机确认]
- [GAP] 审批通过前权限是否暂不生效——待确认

### 4.4 复制来源子管理员被删除
- 用户打开复制弹窗期间，复制来源子管理员被其他管理员删除
- 点击确认时系统检测到来源不存在→提示"复制来源的子管理员已被删除，请关闭弹窗后重新选择"

## 附录：设计指南消费说明

- **BFM-02（分步引导）** → 复制弹窗分为"复制信息"和"复制对象"两个区域，视觉上区分但同在一个弹窗内
- **U-04（一致性标准）** → 选择员工弹窗复用添加子管理员弹窗样式
- **U-01（状态可见）** → 校验失败在弹窗内直接展示具体失败用户名，不关闭弹窗
- **C-05（默认效应）** → 复制信息默认全选，减少管理员操作
- **反馈原则1.2（操作前说明）** → 复制信息未选时确认按钮置灰+提示，不让用户点了确认才发现
- **反馈原则1.3（说明原因+下一步）** → 校验失败文案包含"谁失败了"（具体用户名）和"为什么不能"（状态不符原因）
