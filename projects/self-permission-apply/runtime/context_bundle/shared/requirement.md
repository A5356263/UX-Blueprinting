# 原始需求

来源：`input/自助权限申请/需求文档_员工自助申请权限.md`

## 需求背景

目前企业员工的权限分配主要由权限管理员或超级管理员集中处理。中大型企业中，员工数量多、人员流动频繁，权限新增、变更、核对的工作量较大。部分企业的超级管理员可能是老板本人，员工需要权限时需私下找管理员，沟通成本高、授权时效不稳定。

## 目标

新增"员工自助申请权限"能力，使员工可以：
- 查看自己当前拥有的权限
- 主动申请所需权限
- 通过审批后自动获得权限
- 查看申请记录和审批状态

管理员可以控制：
- 是否允许员工自助申请
- 员工可以申请哪些权限范围
- 申请提交后走什么审批流程
- 是否关闭或调整该能力

## 核心场景

1. 管理员配置自助申请权限：开启模式、限制可申请范围、设置审批流程
2. 员工查看自己的权限
3. 员工申请权限
4. 审批人处理申请，审批通过后系统自动授权
5. 管理员关闭自助申请能力

## 初步业务规则

- 只有最高权限管理员可以开启或关闭
- 开启前需设置可申请范围和审批方式
- 可申请范围按角色或功能权限配置
- 管理员可后续调整配置

## 已知风险

- 培训成本：小企业或人员流动性大的企业，培训和支持成本可能上升
- 权限安全风险：申请范围设置过宽可能导致权限失控
- 审批流程风险：审批人缺失或链路配置错误导致申请无法流转
- 模式互斥风险：与已有权限治理模式可能冲突

## 竞品参考

金蝶支持用户查看自己的权限，并通过申请单申请角色或组织数据权限，审批通过后系统自动授权。

## 价值判断

对员工数量多、权限变更频繁、超管处理压力大的企业有价值。初步价值指标：推动至少 3 家客户使用。
