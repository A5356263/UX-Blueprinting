# Background

## 正式任务分析收敛总结

### 1. 核心需求事实

- 企业员工当前依赖管理员（甚至老板）手动分配权限，沟通成本高、时效不稳定
- 目标是通过员工自助申请 + 审批后自动授权，把部分权限分配工作从管理员侧分散到员工侧
- 员工可以查看自己已有的权限、申请所需权限、查看申请进度

### 2. 需求涉及能力范围 / 候选功能单元

- 权限来源模型扩展：新增"员工自助申请"作为新的来源类型
- 权限生效机制扩展：从"配置即生效"变为"审批后自动授权"
- 申请审批全生命周期管理：申请中 → 审批中 → 已通过 / 已拒绝 / 已撤销
- 管理端配置：开关控制、可申请范围设置（按角色 / 功能权限）、审批人指定
- 员工端自助页面：查看已有权限、提交申请、查看申请进度
- 审批端处理：查看申请内容、审批通过 / 拒绝、通过后自动授权

### 3. 关键业务规则（已确认）

- 可申请范围限定为角色和功能权限（不包含数据范围）
- 审批人由管理员在开启配置时指定，未指定时默认路由到超管
- 不与双管理员模式互斥，两者可共存
- 关闭能力时：关新不关旧，已审批中的申请正常走完
- 新来源类型需在来源模型中明确定义优先级和覆盖规则

### 4. 状态流转

申请生命周期：申请中 → 审批中 → 已通过 / 已拒绝 / 已撤销
权限生效状态：新增"待审批生效"中间态（仅在自助申请场景下存在）

### 5. 异常与边界

- 审批人不存在或无法处理时：需要兜底机制（默认路由到超管）
- 审批链路配置错误：申请无法流转，需在配置阶段校验
- 审批通过但授权失败：需要重试或人工介入机制
- 关闭能力时在途申请处理：关新不关旧

### 6. 依赖与前置条件

- 依赖审批中台或固定审批人机制
- 依赖现有权限判断链路（L0-L3）的扩展能力
- 审批通过后的自动授权动作需与现有授权机制对接

### 7. GAP / 待确认

- 员工申请时是按角色申请（一次性获得角色下所有功能权限），还是按功能权限点逐个申请
- 是否需要与审批中台打通，还是固定审批人模式作为长期方案
- 新来源类型在来源模型中的具体优先级和覆盖规则待判
