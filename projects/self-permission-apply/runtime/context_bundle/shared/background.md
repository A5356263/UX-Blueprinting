# 正式任务分析收敛总结

## 1. 核心需求事实
- 权限管理域新增「自助申请权限模式」，员工可自行申请权限，经审批后系统自动分配
- 核心矛盾：当前权限分配中"发起、审核、执行"三个角色合一在管理员身上
- 自助申请模式将发起权分散到员工，审核权保持在业务主管侧，执行权交给系统
- 该模式与双管理员互审模式、权限变更审批模式互斥，不可同时开启

## 2. 需求涉及能力范围
- 权限管理模式新增一项（与子管理员模式、双管理员互审、权限变更审批平级）
- 个人中心新增「我的权限」入口与页面
- 「申请权限」抽屉表单（含功能权限设置组件复用）
- 审批流程对接（默认审批人为组织负责人）
- 申请记录查询与撤销
- 数据埋点和操作记录

## 3. 关键业务规则 / 待定规则

### 已确认规则
- 可申请角色/应用范围由超管预先划定（全部或部分）
- 申请方式有2个选项：申请角色、申请功能权限（单选）
- 审批人默认组织负责人，可修改
- 功能权限申请时，数据权限默认全量
- 关闭模式时需校验是否有在途流程

### 推理结论（基于权限域知识）
- 自助申请审批通过的权限，来源模型建议新增 `APPLICATION_APPROVAL` 来源类型
- 来源优先级复用现有决策链（L0可见性→L1功能权限→L2数据权限→L3治理生效）
- 申请审批通过后的自动分配与既有授权结果统一进入 `final_effective_rule` 计算

### 待定规则（GAP）
- 审批人不可用时（离职、出差、不在岗）的兜底方式待定
- 功能权限对应的数据权限是否允许超管配置为"部分数据权限"待定

## 4. 状态流转
- 申请单状态：审批中 → 已通过 / 已拒绝 / 已撤销
- 自助申请模式状态：未开启 → 设置中 → 已启用 / 已关闭
- 关闭失败状态：有在途流程时关闭失败

## 5. 异常与边界
- 资金用户校验：为非资金用户授予代发付款时阻断
- 子管理员模式校验：子管理员不能授予子管理员模式权限
- 服务人员无此功能入口
- 未开启此模式的企业不展示「我的权限」
- 关闭模式时在途流程需先完成
- 开启互审模式下不能启用此模式

## 6. 依赖与前置条件
- 流程引擎对接（审批流配置）
- 与现有治理模式的互斥逻辑
- 来源模型扩展

## 7. GAP / 待确认
| 待确认项 | 类型 | 优先级 |
|:---|:---|:---|
| 审批人不可用的兜底策略 | 业务决策 | 高 |
| 数据权限全量是否允许超管覆盖 | 产品决策 | 中 |
| 降低培训成本的具体策略 | 体验策略 | 中 |
