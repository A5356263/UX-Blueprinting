# 体验蓝图

> 基于 business_blueprint.md 的判断和 facts.md 的事实整理。承接业务方案中的角色、流程、规则、风险和待确认项。

## 0. 本次关键设计判断

**判断：**

体验方案围绕"三角色、三入口、一闭环"展开。三角色是管理员（配置方）、员工（申请方）、审批人（审批方）；三入口是管理后台的配置入口、员工端的权限查看与申请入口、审批人的待审批入口；一闭环是从配置到申请再到审批授权的完整链路。

**主要影响：**

1. 员工侧的入口嵌在现有权限查询页面中，不单独开辟新菜单——员工在查询结果中发现缺失后直接发起申请
2. 审批人的操作入口放在审批待办中，不单独为权限申请设计独立审批页面——复用现有审批中台的待办能力
3. 管理端的配置入口放在"权限管理模式"区域，与双管理员、权限变更审批等模式同级——保持权限管理结构的统一

**建议方案：**

- 员工端：在权限查询结果页增加"申请权限"入口；在空状态页增加"去申请"引导；在工作台增加"我的申请"卡片查看申请进度
- 审批端：通过审批中台待办接收权限申请，审批表单展示申请详情和原因
- 管理端：在权限管理模式中增加"员工自助申请"配置区，包含开关、可申请范围、审批规则

**不建议方案：**

- 不建议为权限申请单独开发独立的审批页面——与现有审批中台打通，减少重复建设
- 不建议员工端入口做成独立菜单——权限申请不是高频操作，独立菜单成本高且容易空置

**关键待确认：**

1. 审批中台的可用性：如果审批中台尚未完成闭环，审批流程需要先走简化模式（如指定单个审批人）
2. 员工端入口的具体位置：权限查询页面在员工端的访问路径需要确认

## 1. 旅程图

- **管理员**：发现问题（权限管理效率低）→ 开启自助申请 ← 遇到阻断（必须先配置范围和审批规则）→ 完成配置 → 持续监控使用情况
- **员工**：发现自己缺少某功能入口 → 前往权限查询页面确认 ← 发现确实没有该权限 → 点击"申请权限" → 选择所需权限 → 填写申请原因 → 提交申请 ← 等待审批 → 收到审批通过通知 → 使用新权限 / 收到驳回通知 → 了解原因
- **审批人**：收到审批待办通知 → 进入审批页面 → 查看申请详情和原因 → 判断是否同意 → 通过（系统自动授权）/ 驳回（填写驳回原因）

### 旅程缺口

- 员工发现"缺少某功能"到"前往权限查询页面"之间的路径不明确——员工如何感知到自己的权限缺失？是访问功能时被拦截、向管理员询问后被告知、还是自己主动检查？
- 审批人收到通知的方式不明确——是审批中台推送、消息通知、还是邮件？这将影响审批时效预期
- 员工"查看申请进度"的入口不明确——是在工作台、权限查询页面、还是独立的"我的申请"列表？

## 2. 交互流程总览

**管理员配置流程：**
进入权限管理 → 进入权限管理模式 → 选择"员工自助申请"配置区 → 开启功能开关 ← 遇到阻断（必须先配置可申请范围和审批规则）→ 配置可申请范围（选择角色/功能权限）→ 配置审批方式（选择审批人规则）→ 保存 → 配置生效

**员工申请流程：**
发现权限缺失 → 进入权限查询页面 → 查看已有权限列表 ← 确认需要申请 → 点击"申请权限" → 选择申请类型（角色/功能权限）→ 选择具体权限项 → 填写申请原因 → 提交申请 → 收到"提交成功"反馈 → 可在"我的申请"中查看进度

**审批人处理流程：**
收到待办通知 → 进入审批页面 → 查看申请人信息 → 查看申请权限详情 → 查看申请原因 → 决定通过或驳回 → 如通过，填写审批意见 → 确认提交 → 系统自动执行授权 → 通知申请人和管理员

**异常流程重点：**
- 员工申请的权限不在可申请范围内
- 审批人不存在或离职
- 管理员在有人正在申请时关闭能力
- 审批通过后自动授权失败

## 3. 主交互流程

### 节点 3.1：管理员开启自助申请权限

**用户动作：**
管理员进入权限管理 → 权限管理模式 → 看到"员工自助申请权限"配置区 → 点击开关尝试开启

**系统反馈：**
开关开启时，系统弹出提示："开启前需要先设置可申请范围和审批规则。是否立即配置？"提供"去配置"和"暂不开启"两个选项。

**需要前置解释的信息：**
- 开启后，员工可以在指定范围内提交权限申请
- 所有申请都需要经过审批才能生效
- 可通过关闭功能随时停止接收新申请

**建议文案：**
- 开关文案："员工自助申请权限"
- 开关说明："开启后，员工可在指定范围内申请权限，申请需经审批后生效"
- 提示弹窗："开启前需要先配置可申请范围和审批规则。是否立即配置？"

**下一步：**
点击"去配置"进入可申请范围配置页；或点击"暂不开启"返回

### 节点 3.2：管理员配置可申请范围

**用户动作：**
选择配置方式（按角色 / 按功能权限）→ 从列表中勾选允许员工申请的项目 → 保存

**系统反馈：**
保存时校验配置是否有效（至少选择一项），通过后显示"配置已保存"。
如果之前已开启功能，配置更新后即时生效。

**需要前置解释的信息：**
- 只有被勾选的角色或功能权限，员工才能在申请时看到和选择
- 超出此范围的权限，员工端不可见也不可申请
- 后续可以随时调整范围配置

**建议文案：**
- 页面标题："配置可申请范围"
- 说明文字："选择允许员工自助申请的角色或功能权限。超出范围的权限员工不可见也不可申请。"
- 保存按钮："保存配置"

**下一步：**
保存后提示"是否继续配置审批规则？"引导进入审批规则配置

### 节点 3.3：管理员配置审批规则

**用户动作：**
选择审批方式（组织负责人审批 / 指定审批人 / 自定义审批流程）→ 如选择"指定审批人"，选择具体管理员 → 保存

**系统反馈：**
保存时校验审批人是否有效（如果指定审批人，需确认审批人账号正常），通过后显示"审批规则已配置"。

**需要前置解释的信息：**
- 审批人负责审核每一笔权限申请
- 如果审批人不存在（离职/变更），申请将无法流转
- 可以选择多种审批方式

**建议文案：**
- 页面标题："配置审批规则"
- 说明文字："设置审批人处理员工的权限申请。"
- 审批方式选项：
  - "组织负责人审批（员工所属组织的负责人逐级审批）"
  - "指定管理员审批（选择一位或多位管理员审批）"
  - "自定义审批流程（在审批中台配置完整审批链）"

**下一步：**
保存后返回配置总览，开关保持开启状态

### 节点 3.4：员工查看已有权限

**用户动作：**
员工进入权限查询页面 → 查看自己当前拥有的角色和功能权限列表

**系统反馈：**
展示权限列表，包含权限名称、类型（角色/功能权限）、来源（直接授予/角色授予）、状态（已生效/待生效）。
如果企业未开启自助申请权限，不显示"申请权限"入口。

**需要前置解释的信息：**
- 权限来源可以帮助员工理解"我为什么有这个权限"
- "已生效"和"未生效"的区别需要明确

**建议文案：**
- 页面标题："我的权限"
- 列表列：权限名称、类型、来源、状态、有效期（如适用）
- 空状态提示："你当前没有权限。如需使用，请联系管理员或申请权限。"

**下一步：**
如发现缺少权限，点击"申请权限"进入申请流程

### 节点 3.5：员工提交权限申请

**用户动作：**
点击"申请权限"→ 选择申请类型（角色/功能权限）→ 从可申请列表中选择具体权限 → 填写申请原因 → 提交

**系统反馈：**
- 可申请列表只显示管理员已配置开放范围内的权限
- 提交前展示申请摘要（申请内容、申请原因、预期审批人），要求确认
- 提交成功后，显示"申请已提交"，状态变为"待审批"
- 如果申请权限已在可申请范围外，提交时阻断并提示

**需要前置解释的信息：**
- 申请需要经过审批，不是提交即生效
- 审批通过后系统会自动授权，无需再次联系管理员
- 可以随时查看申请进度

**建议文案：**
- 页面标题："申请权限"
- 申请类型选择："申请角色" / "申请功能权限"
- 申请原因输入框占位文字："请说明为什么需要此权限（限200字）"
- 提交按钮："提交申请"
- 提交成功提示："申请已提交，请等待审批人处理"
- 提交成功下一步按钮："查看申请进度"

**下一步：**
提交成功后可前往"我的申请"查看进度

### 节点 3.6：审批人处理权限申请

**用户动作：**
审批人从待办列表进入 → 查看申请详情（申请人、申请内容、申请原因、当前权限概况）→ 决定通过或驳回 → 如通过点击"同意"，如驳回填写驳回原因 → 确认提交

**系统反馈：**
- 通过后显示"已同意，系统将自动完成授权"，系统执行自动授权
- 驳回后显示"已驳回，已通知申请人"
- 自动授权成功后，通知申请人和管理员
- 自动授权失败时，通知审批人和管理员人工处理

**需要前置解释的信息：**
- 审批通过后，系统会自动完成授权，无需审批人额外操作
- 自动授权可能因系统异常失败，需要人工跟进

**建议文案：**
- 页面标题："权限申请审批"
- 基本信息区：申请人、申请时间、申请内容
- 申请原因区：展示员工填写的申请原因
- 审批按钮："同意"（主要按钮）、"驳回"（次要按钮）
- 驳回原因输入框占位文字："请说明驳回原因"
- 同意后提示："已同意，系统将自动完成授权"
- 驳回后提示："已驳回，已通知申请人"

**下一步：**
审批完成后返回待办列表

### 节点 3.7：管理员关闭自助申请能力

**用户动作：**
管理员在配置页面点击开关尝试关闭

**系统反馈：**
关闭前系统自动检测是否存在进行中的申请：
- 如无进行中申请：直接关闭，提示"已关闭，员工将无法提交新申请"
- 如有进行中申请：弹出提示，告知数量，询问处理方式。"当前有 N 个进行中的申请。关闭后，这些申请将如何处理？"提供选项："允许进行中的申请继续完成" / "全部终止"

**需要前置解释的信息：**
- 关闭后，员工不能提交新申请
- 已通过申请获得的权限是否保留取决于配置策略
- 进行中的申请需要明确处理方式

**建议文案：**
- 操作前提示："关闭后将停止接收新的权限申请。请确认处理方式。"
- 如有进行中申请，提示："当前有 N 个申请正在审批中。"
- 处理方式选项：
  - "允许进行中的申请继续完成（推荐）"
  - "全部终止，已通过的权限不受影响"
- 关闭确认按钮："确认关闭"
- 关闭后提示："已关闭。进行中的申请已按所选方式处理。"

**下一步：**
系统按选定的处理方式处理进行中申请，配置状态更新为"已关闭"

## 4. 次交互流程

### 4.1 员工查看申请进度

员工在"我的申请"页面查看所有已提交的申请及相关状态。
列表展示：申请时间、申请内容、当前状态（待审批/已通过/已驳回）、审批人、审批时间。
已通过的申请可查看授权结果。
已驳回的申请可查看驳回原因，部分情况下可重新提交。

### 4.2 员工撤销申请

提交后、审批人处理前，员工可以撤销申请。
撤销后申请状态变为"已撤销"，通知审批人该申请已撤销。
审批人已开始处理的申请不可撤销。

### 4.3 管理员调整配置

管理员可以随时调整可申请范围和审批规则。
调整范围时，不影响已提交的申请（以提交时的范围为准）。
调整审批规则时，已提交的申请仍按原审批人规则流转，新申请按新规则流转。

### 4.4 管理员查看申请统计

管理员可以查看自助申请的统计数据：申请总数、通过率、平均审批时长、热门申请权限排行等。
帮助管理员了解自助申请的使用情况和效果。

## 5. 异常与阻断流程

### 异常 5.1：申请的权限不在可申请范围内

**发生时机：** 员工提交申请时
**触发条件：** 员工选择或填写的权限不在管理员配置的可申请范围内
**判断依据：** facts.md 关键业务规则"可见范围 ≠ 可申请范围"
**反馈形式：** 字段提示
**系统反馈：** "所选权限不在可申请范围内，请联系管理员确认"
**用户下一步：** 联系管理员了解该权限是否可以开放申请

### 异常 5.2：审批人不存在

**发生时机：** 申请提交后，系统尝试分配审批人时
**触发条件：** 配置的审批人已离职、账号停用或不存在
**判断依据：** facts.md 异常与边界"审批人不存在"
**反馈形式：** 提交成功但系统提示 + 管理员通知
**系统反馈：** 申请仍提交成功，状态显示"待分配审批人"。通知管理员重新配置审批人或指定临时审批人。
**用户下一步：** 等待管理员处理；员工可联系管理员提醒

### 异常 5.3：审批通过后自动授权失败

**发生时机：** 审批人点击"同意"后，系统执行自动授权时
**触发条件：** 系统内部错误、权限数据异常或授权接口超时
**判断依据：** facts.md 异常与边界
**反馈形式：** 审批人端弹窗 + 管理员通知
**系统反馈：** 审批人看到"审批已通过，但自动授权异常，需人工处理"。通知管理员人工执行授权。
**用户下一步：** 审批人可标记"已通知管理员"；管理员在后台手动完成授权

### 异常 5.4：管理员关闭能力时存在进行中申请

**发生时机：** 管理员关闭自助申请开关时
**触发条件：** 存在状态为"待审批"的申请
**判断依据：** facts.md 状态流转"能力开关状态"
**反馈形式：** 弹窗确认
**系统反馈：** 弹窗提示"当前有 N 个进行中的申请，请选择处理方式"
**用户下一步：** 选择"允许继续完成"或"全部终止"，或取消关闭操作

### 异常 5.5：关闭后员工尝试提交新申请

**发生时机：** 员工点击提交申请时
**触发条件：** 管理员已关闭自助申请能力
**判断依据：** facts.md 功能范围"管理员开启/关闭自助申请权限"
**反馈形式：** 页面阻断 + 提示
**系统反馈：** "当前未开放自助申请权限，请联系管理员"
**用户下一步：** 联系管理员了解情况

### 异常 5.6：申请重复（员工已拥有该权限）

**发生时机：** 员工选择要申请的权限时
**触发条件：** 员工选择的权限当前已拥有且已生效
**判断依据：** facts.md 关键业务规则
**反馈形式：** 字段提示
**系统反馈：** "你已拥有该权限，无需重复申请"
**用户下一步：** 确认权限是否确实可用；如不可用可能涉及权限生效异常，建议联系管理员

## 6. 页面 / 弹窗 / 抽屉设计

### 页面 6.1：权限管理模式配置页（管理端）

**页面目标：** 集中管理权限治理模式，包括自助申请权限的开启和配置
**进入条件：** 管理员进入权限管理 → 权限管理模式
**页面结构：**
- 模式列表区：展示各治理模式（双管理员、权限变更审批、员工自助申请等）及其状态（已开启/已关闭）
- 配置区：选中某模式后，右侧或下方展示详细配置

```
+------------------------------------------------------+
| 权限管理模式                                          |
+------------------------------------------------------+
| [模式卡片] 双管理员模式               状态：已开启    |
| [模式卡片] 权限变更审批模式           状态：已关闭    |
| [模式卡片] 员工自助申请权限           状态：已开启 →  |
+------------------------------------------------------+
| 下方配置区（选中"员工自助申请"时展示）：              |
|  开关：[开启]                                          |
|  可申请范围：[已配置 3 个角色] → 去配置               |
|  审批规则：[组织负责人审批] → 去配置                  |
```

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|------|------|----------|-----------|-------------|
| 待审批 | 申请已提交，等待审批人处理 | 员工、审批人 | 员工可撤销 | "等待审批人处理" |
| 审批通过 | 审批人已同意，正在执行授权 | 员工、审批人 | 无（等待系统处理） | "审批已通过，正在授权" |
| 已授权 | 权限已成功授予并使用户生效 | 员工 | 可使用新权限 | "申请已通过，权限已生效" |
| 已驳回 | 审批人不同意本次申请 | 员工 | 可查看驳回原因 | "申请未通过" |
| 已撤销 | 员工在审批前取消了申请 | 员工、审批人 | 可重新申请 | "申请已撤销" |
| 待分配审批人 | 申请已提交，但审批人配置异常 | 管理员、员工 | 管理员需重新配置 | "等待分配审批人" |
| 授权失败 | 审批已通过，但自动授权异常 | 管理员、审批人 | 管理员需人工处理 | "审批通过，但授权异常，需人工处理" |
| 已关闭（能力状态） | 管理员已关闭自助申请能力 | 管理员、员工 | 管理员可重新开启 | "自助申请已关闭，员工不可提交新申请" |

## 8. 待确认问题

1. **员工端入口的具体位置**

   影响：决定员工从哪里进入权限查询页面和申请流程。如果入口太深，员工找不到申请功能，转化率低。
   建议确认方：产品 / 设计

2. **审批中台是否已可用**

   影响：如果审批中台尚未完成闭环，第一期需要走简化审批模式（如直接指定审批人），不依赖完整审批链配置。
   建议确认方：技术 / 产品

3. **通知方式**

   影响：审批人如何收到待审批通知（审批中台推送/消息/邮件）？员工如何收到审批结果通知？影响待办页面的设计和通知渠道的选择。
   建议确认方：产品 / 技术

4. **敏感权限列表的维护方式**

   影响：如果需要敏感权限排除机制，管理端需要增加敏感权限配置界面。如果第一期不做，需要明确第一期以"管理员手动控制可申请范围"作为安全边界。
   建议确认方：安全 / 产品

5. **超时自动处理的策略**

   影响：审批人长时间不处理时，是否需要超时机制？超时后自动驳回还是自动转交？如果第一期不做，需要明确预期。
   建议确认方：产品 / 业务
