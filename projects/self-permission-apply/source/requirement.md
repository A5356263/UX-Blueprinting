# Requirement

- Project ID: self-permission-apply
- Task Name: 员工自助申请权限
- Domain: 管理后台
- Source: input/自助权限申请/需求文档_员工自助申请权限.md

## 需求概述

当前企业员工的权限分配完全由管理员或超管集中处理。在中大型企业中，员工多、流动快，权限新增和变更工作量大，沟通成本高，授权时效不稳定。部分企业超管即为老板本人，员工需私下找人处理权限。

本次希望新增"员工自助申请权限"能力，让员工可以查看自己的权限、主动发起申请、通过审批后自动获得权限。同时管理员保留对申请范围、审批流程和开关的完整控制。

## 核心目标

1. 员工可查看自己当前拥有的权限
2. 员工可主动申请所需权限
3. 通过审批后系统自动完成授权
4. 员工可查看自己的申请记录和审批状态
5. 管理员可控制是否开启、可申请范围、审批流程、关闭策略

## 分析结论：问题本质

这不是一个加功能的需求。它的本质是在现有权限治理体系中，为"员工发起 → 审批关卡 → 自动生效"这条路径补齐来源解释、治理状态、审批链路和查询闭环。

## 已确认的范围决策

### 首期范围
- 按角色申请（员工选择角色，不直接选择功能权限）
- 不支持员工自选数据权限范围（数据范围由角色已配置的范围决定）
- 服务人员明确不开放此能力
- 可申请范围按角色勾选配置，敏感角色默认排除

### 权限来源归属
- 自助申请审批通过后，权限来源归入 `ACL_DIRECT`（直授）
- 通过治理修饰因子标记"自助申请审批获得"，不在来源枚举层新增分类

### 治理模式关系
- 自助申请作为现有"权限变更审批模式"的员工侧触发端
- 复用现有治理状态机：draft → pending → approved → effective → revoked
- 与子管理员模式可共存
- 与双管理员模式不互斥，但配置页需标注高风险警告
- 与任何现有模式不互斥（R-009 互斥仅限子管理 + 双管理）

### 审批链路
- 复用 OA 审批中台完整能力
- 默认审批人：组织架构负责人（直接上级）
- 无负责人时回退到权限管理员
- 支持管理员自定义审批流程
- 超时不自动通过（权限审批属安全敏感操作）

### 员工端入口
- 双路径：无权限提示页嵌入申请入口 + 工作台"我的权限"独立入口
- "我的权限"展示每项权限来源（管理员授予 / 来自角色 / 自助申请 / 协作可见）
- 已有权限不可重复申请
- 审批中不可重复提交
- pending 状态可撤销

### 关闭策略
- 已生效权限保留（撤回属高危批量操作，应管理员主动治理）
- 审批中申请全部终止，状态标为 revoked，双方通知
- 草稿归档不可恢复
- 员工端申请入口隐藏，已有记录仍可查看

### 审计与统计
- 操作日志接入安全管理 → 操作记录模块
- 统计数据接入 OA 审批 → 智能分析面板

## 15项不明确事项推理结论

| # | 事项 | 结论 |
|---|------|------|
| 1 | 与现有治理模式是否互斥 | 不互斥，可叠加但需显式定义关系 |
| 2 | 申请角色还是功能权限 | 首期仅角色 |
| 3 | 哪些不可申请 | 含高危操作的角色、涉及资金的角色、超管角色默认排除 |
| 4 | 是否需要敏感角色排除 | 需要，用勾选排除，不另建分类 |
| 5 | 是否需要上传附件 | OA审批已支持附件控件，首期做管理员可配置项 |
| 6 | 是否可选数据权限范围 | 首期不支持 |
| 7 | 审批人默认是谁 | 组织架构负责人，无则回退权限管理员，支持自定义 |
| 8 | 审批人不存在如何处理 | 提交时校验+复用OA审批中台转派机制 |
| 9 | 审批中是否可撤销 | draft/pending允许，审批人已查看后是否可撤作为配置项 |
| 10 | 关闭后已获权限是否保留 | 保留 |
| 11 | 关闭时审批中的如何处理 | 终止通知，状态标为revoked |
| 12 | 员工端入口放哪 | 无权限提示页嵌入 + 工作台"我的权限"双路径 |
| 13 | 是否展示权限来源 | 是，每项权限标注来源 |
| 14 | 是否需要申请统计 | 是，接入OA审批智能分析面板 |
| 15 | 服务人员是否支持 | 不开放 |
