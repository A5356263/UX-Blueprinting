# 背景资料

## 问题定性

需求文档预设了"员工自助申请权限"方案方向，经分析确认方案方向合理。核心判断依据：
- 现有所有权限获取路径（管理员直授、角色批量分发、角色自动授权规则）的发起人和维护人都是管理员
- 自动授权规则只能处理可预测场景（按部门、职务、成员组匹配），无法覆盖跨部门协作、临时项目、特殊报表等"管理员预料不到但员工自己知道缺什么"的场景
- 自助申请与现有能力是互补关系，不是替代关系

## 前置判断结论

### 需求类型
复杂业务需求——同时改变权限来源模型、治理模式规则、员工在权限体系中的角色。

### 复杂度判断
高复杂度。依据：
- 改变业务对象关系：新增"申请单"对象 + 员工→角色→权限的关联链路
- 改变业务规则：新增权限获取路径、可申请范围管控规则
- 改变状态机：申请单生命周期（草稿→审批中→已通过/已拒绝/已撤销→已生效）
- 改变生效机制：权限通过审批后自动生效
- 跨域链路：权限体系 + 审批体系 + 管理配置 + 员工端体验

### 主要压力点
1. 权限来源模型扩展
2. 治理模式共存规则
3. 关闭能力的语义定义
4. 员工端权限认知基础构建
5. 审批链路承接

- 现有任务场景中，员工始终是被动接收方，无主动发起路径

## 策略约束

1. 以角色为申请单位，初期不做功能和数据权限范围自选
2. 不自建审批引擎，复用审批管理已有能力
3. 敏感角色不可申请（超管角色、含删除/批量操作/财务数据等高危功能点的角色）
4. 关闭不回收已授权限，审批中申请统一退回
5. 服务人员当前不支持
6. 一期不做附件上传、数据范围选择、统计看板，但需预留埋点
