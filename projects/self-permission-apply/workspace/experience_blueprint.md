# 体验蓝图

> 本体验蓝图基于 `workspace/business_blueprint.md` 的业务判断展开，将业务方案转译为角色路径、页面承接、状态反馈和异常处理。不重新判断需求是否成立或能力形态。

## 0. 本次关键设计判断

**判断：**

本次体验方案的重点不是新增很多页面，而是把三条角色路径（管理员配置 → 员工申请 → 审批处理 → 自动授权）无缝接入现有权限体系和审批体系，同时把异常反馈和关闭兜底说清楚。

**主要影响：**

1. 管理员侧：现有权限管理模式页需要扩展一个新开关和配套设置区，角色管理页每个角色多一个开关，信息密度增加
2. 员工侧：需要构建三个全新的页面——我的权限（查看已有权限及来源）、申请权限（选择角色并提交）、我的申请（追踪状态）。这是本次体验承接压力最大的部分
3. 审批侧：复用现有审批待办，但需要让审批人看懂权限申请和普通申请的区别，核心是展示角色包含的具体权限

**建议方案：**

- 员工端三个页面作为工作台或个人信息区的子页面，从「我的权限」入口进入
- 管理员配置内嵌在已有权限管理模式页和角色管理页中，不新增独立配置页
- 所有异常反馈以页面内提示为主，弹窗为辅，避免打断用户操作流
- 关闭能力的确认使用弹窗，醒目告知三种后果

**不建议方案：**

- 不建议在员工首页直接放申请入口——员工不是在每次打开系统时都需要申请权限，首页入口会造成干扰
- 不建议为每个异常场景设计独立弹窗——大多数异常用页面内提示即可，弹窗只用于关闭确认和撤销确认

**关键待确认：**

1. 员工端的「我的权限」入口放在工作台哪个位置——这决定了入口的发现率和首页信息架构调整

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- **员工**：发现缺少权限 → 查看自己已有权限和来源 → 浏览可申请角色 → 选择角色并填写原因 → 提交申请 → 等待审批 → 查看审批结果 → 确认权限已生效
- **管理员**：评估是否开放自助申请 → 检查审批流程是否就绪 → 开启能力 → 标记可申请角色 → 绑定审批流程 → 后续观察申请数据 → 必要时关闭能力
- **审批人**：收到待办 → 查看申请人信息和申请角色 → 查看角色包含的权限详情 → 判断是否同意 → 同意或拒绝 → 确认处理完成

### 旅程缺口

- 缺少员工端入口位置的明确依据，影响「发现缺少权限」这个起点的具体承载方式
- 缺少消息通知渠道的明确规则，影响「等待审批」和「查看审批结果」两个节点的通知承接
- 缺少管理员「后续观察申请数据」的看板或统计页面依据

## 2. 交互流程总览

**分角色交互流程：**

- **管理员**：进入权限管理模式页 → 开启「员工自助申请权限」→ 校验审批流程是否可用 → 进入角色管理页 → 逐个标记可申请角色（系统拦截敏感角色）→ 返回设置区绑定审批流程 → 能力生效 → 后续可在设置区调整配置或关闭能力
- **员工**：进入「我的权限」→ 查看已有权限及来源 → 发现缺口 → 进入「申请权限」→ 浏览可申请角色列表 → 选中角色查看权限详情 → 填写申请原因 → 提交申请 → 申请进入「我的申请」列表 → 等待审批结果 → 查看结果（已通过：确认权限生效 / 已拒绝：查看原因，可重新申请）
- **审批人**：收到审批待办 → 查看申请详情（申请人、角色、权限说明、原因）→ 同意（自动授权完成）或拒绝（流程结束）→ 确认处理结果

**异常流程重点：**

- 可申请角色列表为空（无已标记角色或员工已拥有全部）
- 提交申请时审批流程不可用
- 审批人不存在时的兜底流转
- 管理员关闭能力时审批中申请被退回
- 员工撤销审批中的申请
- 敏感角色被尝试标记为可申请
- 审批通过时员工已通过其他途径拥有同一角色

## 3. 主交互流程

### 节点 3.1：管理员开启自助申请能力

**用户动作：**

管理员进入权限管理模式页，在现有治理模式列表中找到「员工自助申请权限」开关，点击开启。

**系统反馈：**

系统检查两项前置条件：（1）是否已有可用的审批流程；（2）是否已有至少一个角色被标记为可申请。若审批流程不可用，提示「尚未配置审批流程，请先在审批管理中创建审批流程」。若无可申请角色，仅做轻提示「开启后需在角色管理中标记可申请角色」，不阻断开启操作。两项条件均满足时，能力即刻生效。

**需要前置解释的信息：**

开启前，页面需说明该能力的含义：「开启后，员工可以在「我的权限」中查看自己的权限并发起权限申请。申请需经过审批，审批通过后系统自动授权。」

**建议文案：**

- 开关标签：「员工自助申请权限」
- 开关说明：「允许员工自助查看权限并发起角色申请，审批通过后自动授权」
- 前置校验提示（无审批流程时）：「尚未配置审批流程，请先在审批管理中创建审批流程后再开启」

**下一步：**

进入角色管理页标记可申请角色，或进入设置区绑定审批流程。

### 节点 3.2：管理员标记可申请角色

**用户动作：**

管理员进入角色管理页，在角色列表中看到每个角色行新增的「允许员工申请」开关。逐个开启需要开放的角色。

**系统反馈：**

开启角色开关时，系统校验该角色是否在敏感角色排除名单中。若命中排除名单，开关不可操作，旁边显示提示文案。成功开启的角色即刻出现在员工可申请列表中。

**需要前置解释的信息：**

角色列表需展示每个角色的权限概要（包含的功能权限数量或关键功能权限名称），帮助管理员判断是否适合开放。

**建议文案：**

- 开关标签：「允许员工申请」
- 开关说明：「开启后，员工可在「申请权限」中看到此角色并发起申请」
- 敏感角色提示：「此角色包含敏感权限，不可设为员工可申请」
- 空态提示（所有角色均未标记时）：「尚未标记任何可申请角色，员工端将无可申请内容」

**下一步：**

返回权限管理模式页的设置区，绑定审批流程。

### 节点 3.3：员工查看已有权限

**用户动作：**

员工进入「我的权限」页面。

**系统反馈：**

页面展示员工当前拥有的所有权限，按角色维度组织。每个角色卡片显示：角色名称、角色简要说明、权限来源标签（角色自带 / 管理员直授 / 自助申请）、获得时间。页面顶部有「申请权限」入口按钮。

**需要前置解释的信息：**

页面需说明「权限来源」的含义，帮助员工理解为什么有这些权限、哪些是系统默认给的、哪些是自己申请的。

**建议文案：**

- 页面标题：「我的权限」
- 页面说明：「以下是你当前拥有的角色和权限。如需更多权限，可点击「申请权限」发起申请」
- 来源标签文案：「角色自带」「管理员分配」「自助申请」
- 空态（员工无任何权限时）：「暂未拥有任何权限。如需权限，请联系管理员或点击「申请权限」」

**下一步：**

员工识别缺口后，点击「申请权限」进入角色选择页。

### 节点 3.4：员工发起权限申请

**用户动作：**

员工在「申请权限」页面浏览可申请角色列表。每个角色卡片显示角色名称、角色权限说明、包含的功能权限数量。点击某个角色可展开查看具体权限列表。选中角色后，进入申请表单页，填写申请原因，点击提交。

**系统反馈：**

提交成功后，申请单生成，状态为「审批中」。页面跳转到「我的申请」列表，新申请出现在列表顶部。同时系统向审批人发送待办通知。

**需要前置解释的信息：**

角色卡片需展示角色包含的具体权限，帮助员工判断是否确实需要这个角色。申请原因字段需提示填写建议。

**建议文案：**

- 页面标题：「申请权限」
- 页面说明：「以下角色可供申请。选择一个角色并填写申请原因，提交后将由审批人审核」
- 角色权限展开提示：「包含 XX 项功能权限：权限A、权限B、权限C」
- 申请原因标签：「申请原因」
- 申请原因提示：「请简要说明为什么需要此权限，以便审批人了解你的使用场景」
- 提交按钮：「提交申请」
- 提交成功提示：「申请已提交，请等待审批」
- 空态（无可申请角色时）：「当前暂无可申请的角色。如你需要更多权限，请联系管理员」

**下一步：**

等待审批结果，可在「我的申请」中追踪状态。

### 节点 3.5：审批人处理权限申请

**用户动作：**

审批人在审批待办列表中看到权限申请。点击进入申请详情，查看申请人姓名、所在部门、申请角色名称、角色包含的权限列表、申请原因。判断后点击「同意」或「拒绝」。拒绝时需填写拒绝原因。

**系统反馈：**

同意：系统自动将角色授予申请人，权限即刻生效。申请单状态变为「已通过」。系统向员工发送通知。拒绝：申请单状态变为「已拒绝」。系统向员工发送通知（含拒绝原因）。

**需要前置解释的信息：**

申请详情页需展示角色包含的具体权限，帮助审批人判断授权的合理性。

**建议文案：**

- 详情页标题：「权限申请 - [申请人姓名]」
- 信息区标签：「申请人」「所属部门」「申请角色」「申请时间」
- 角色权限区标题：「申请角色包含以下权限」
- 申请原因区标题：「申请原因」
- 同意按钮：「同意授权」
- 拒绝按钮：「拒绝」
- 拒绝原因输入提示：「请填写拒绝原因（将告知申请人）」
- 同意成功提示：「已同意，权限已自动授予申请人」
- 拒绝成功提示：「已拒绝」

**下一步：**

审批人返回待办列表继续处理其他事项。系统自动完成授权或通知。

### 节点 3.6：员工查看申请结果

**用户动作：**

员工在「我的申请」列表中看到申请状态更新。点击已通过的申请查看详情。

**系统反馈：**

已通过：申请详情展示审批人、审批时间、授权完成状态。员工可点击「查看我的权限」跳转到权限页面确认新权限已生效。已拒绝：申请详情展示审批人、拒绝时间、拒绝原因。员工可点击「重新申请」发起新的申请。

**建议文案：**

- 已通过状态标签：「已通过」
- 已通过详情提示：「你的申请已通过审批，角色 [角色名称] 已授予你的账号」
- 已拒绝状态标签：「已拒绝」
- 已拒绝详情提示：「你的申请未被通过。拒绝原因：[原因]」
- 重新申请按钮：「重新申请」

**下一步：**

已通过：确认权限已生效，正常使用。已拒绝：根据拒绝原因决定是否重新申请。

### 节点 3.7：管理员关闭自助申请能力

**用户动作：**

管理员进入权限管理模式页，在「员工自助申请权限」开关处点击关闭。

**系统反馈：**

系统弹出确认弹窗，明确告知关闭后的三种后果：（1）员工端不再显示申请入口；（2）当前所有审批中的申请将被退回；（3）已通过申请获得的权限保留，不受影响。管理员确认后，能力关闭。所有审批中的申请自动退回，申请单状态变为「已退回」，员工收到通知。

**建议文案：**

- 弹窗标题：「确认关闭员工自助申请权限」
- 弹窗正文：「关闭后：员工端将不再显示申请入口；当前所有审批中的申请将被退回；已通过申请获得的权限将保留，不受影响。确认关闭？」
- 确认按钮：「确认关闭」
- 取消按钮：「暂不关闭」
- 关闭成功提示：「员工自助申请权限已关闭」
- 退回通知（给员工）：「自助申请权限能力已由管理员关闭，你的申请 [角色名称] 已被退回」

**下一步：**

管理员可在任意时间重新开启能力。已退回的申请不可恢复，员工需在能力重新开启后重新提交。

## 4. 次交互流程

### 节点 4.1：员工撤销审批中的申请

**用户动作：** 员工在「我的申请」列表中找到状态为「审批中」的申请，点击「撤销申请」。

**系统反馈：** 弹出确认弹窗「撤销后不可恢复，确认撤销？」。确认后，申请单状态变为「已撤销」，审批人待办中移除该申请。审批人收到撤销通知。

**建议文案：**
- 撤销按钮：「撤销申请」
- 确认弹窗标题：「确认撤销申请」
- 确认弹窗正文：「撤销后该申请将失效。如需此权限，可重新提交申请」
- 确认按钮：「确认撤销」
- 撤销成功提示：「申请已撤销」

**下一步：** 员工可重新发起申请。

### 节点 4.2：管理员调整可申请角色配置

**用户动作：** 管理员在角色管理页中，将之前标记为可申请的角色改为不可申请（关闭开关）。

**系统反馈：** 系统提示「关闭后，该角色将不在员工可申请列表中显示。已通过申请获得该角色的员工不受影响」。确认后，该角色从员工可申请列表中移除。

**建议文案：**
- 关闭提示：「关闭后，该角色将不再出现在员工可申请列表中。已通过申请获得此角色的员工不受影响」

**下一步：** 配置即刻生效。

### 节点 4.3：管理员更换绑定的审批流程

**用户动作：** 管理员在自助申请设置区，更换绑定的审批流程。

**系统反馈：** 系统提示「更换审批流程后，新提交的申请将使用新流程。当前已在审批中的申请仍按原流程处理」。确认后，新流程生效。

**下一步：** 新提交的申请走新流程。

### 节点 4.4：员工重新申请被拒绝的角色

**用户动作：** 员工在「我的申请」中找到状态为「已拒绝」的申请，点击「重新申请」。

**系统反馈：** 系统跳转到申请表单页，预填上次申请的角色和原因。员工可修改申请原因后重新提交。生成新的申请单，进入审批流程。

**下一步：** 新申请进入审批流程。

## 5. 异常与阻断流程

### 异常 5.1：可申请角色列表为空

**发生时机：** 员工进入「申请权限」页面时

**触发条件：** 管理员尚未标记任何角色为可申请，或员工已通过其他途径拥有全部可申请角色

**判断依据：** business_blueprint.md §6「不能放开的限制」中规定员工只能申请自己尚未拥有的角色

**反馈形式：** 页面空状态

**系统反馈：** 「当前暂无可申请的角色。如你需要更多权限，请联系管理员」

**用户下一步：** 联系管理员确认配置，或检查自己是否已拥有所需权限

### 异常 5.2：提交申请时审批流程不可用

**发生时机：** 员工点击提交申请时

**触发条件：** 管理员开启了自助申请能力但审批流程已被删除或停用

**判断依据：** business_blueprint.md §6「审批必须存在」规则

**反馈形式：** 页面内提示，提交按钮置灰

**系统反馈：** 「审批流程暂不可用，请联系管理员」

**用户下一步：** 联系管理员。不可提交申请

### 异常 5.3：审批人不存在

**发生时机：** 审批流转时

**触发条件：** 员工直属上级字段为空，且部门负责人字段为空

**判断依据：** business_blueprint.md §5 中的审批兜底规则

**反馈形式：** 系统自动流转，对员工和审批人均不可见

**系统反馈：** 系统自动将申请兜底到超级管理员

**用户下一步：** 无需用户操作

### 异常 5.4：管理员关闭能力时审批中申请被退回

**发生时机：** 管理员确认关闭自助申请能力时

**触发条件：** 存在状态为「审批中」的申请

**判断依据：** business_blueprint.md §6「必须二次确认的操作」

**反馈形式：** 对管理员为关闭确认弹窗（含三种后果说明）；对员工为「我的申请」中状态更新为「已退回」；对审批人为待办消失

**系统反馈（员工端）：** 「自助申请权限能力已由管理员关闭，你的申请 [角色名称] 已被退回」

**用户下一步（员工）：** 等待能力重新开启后重新提交申请。不可恢复已退回的申请

### 异常 5.5：管理员尝试标记敏感角色为可申请

**发生时机：** 管理员在角色管理页中尝试开启敏感角色的「允许员工申请」开关

**触发条件：** 该角色在系统预置的敏感角色排除名单中

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 审批中 | 申请已提交，等待审批人处理 | 员工、审批人 | 员工可撤销；审批人可同意/拒绝 | 「等待审批中」 |
| 已通过 | 审批人同意，权限已自动授予 | 员工、审批人、管理员 | 员工可查看权限是否生效 | 「已通过，权限已生效」 |
| 已拒绝 | 审批人拒绝，流程结束 | 员工、审批人 | 员工可查看拒绝原因，可重新申请 | 「未通过」 |
| 已撤销 | 员工主动撤回审批中的申请 | 员工、审批人 | 不可恢复 | 「已撤销」 |
| 已退回 | 管理员关闭能力，审批中申请被系统退回 | 员工、管理员 | 不可恢复，需重新提交 | 「能力已关闭，申请已退回」 |
| 已开启 | 自助申请能力已启用 | 管理员、员工 | 管理员可关闭或调整配置；员工可发起申请 | 「员工自助申请权限已开启」 |
| 已关闭 | 自助申请能力已停用 | 管理员、员工 | 管理员可重新开启 | 「员工自助申请权限已关闭」 |

### 权限来源标签

| 来源 | 含义 | 适用对象 | 统一反馈口径 |
|---|---|---|---|
| 角色自带 | 权限来自员工所属角色的默认配置 | 员工 | 「角色自带」 |
| 管理员分配 | 权限由管理员直接授予 | 员工、管理员 | 「管理员分配」 |
| 自助申请 | 权限通过员工自助申请并经审批获得 | 员工、管理员 | 「自助申请」 |

## 8. 待确认问题

1. **员工端入口位置**

   影响：决定「我的权限」入口的发现率、首页信息架构和导航层级。放在工作台曝光高但需要调整首页布局，放在个人信息区入口低调但发现率可能偏低。
   建议确认方：产品 + 设计

2. **消息通知渠道和文案**

   影响：申请提交后、审批结果、关闭退回等关键节点通过什么渠道通知（系统消息 / 推送 / 短信）、通知内容如何表达。
   建议确认方：产品 + 设计

3. **申请原因是否必填、字数上限**

   影响：影响申请表单的交互约束和错误提示设计。当前方案按必填处理，但未确认字数上限。
   建议确认方：产品

4. **审批通过时员工已拥有同一角色的处理**

   影响：影响审批人的操作反馈（静默跳过还是提示确认）。当前方案建议静默跳过并提示，但需最终确认。
   建议确认方：产品 + 技术

5. **员工离职或停用时审批中申请的处理**

   影响：影响申请单状态机的终态设计和权限回收时机。当前未定义。
   建议确认方：产品

6. **移动端是否支持发起申请和查看状态**

   影响：决定是否需要多端适配、移动端页面结构是否需要单独设计。
   建议确认方：产品

7. **敏感角色排除名单的具体确认**

   影响：决定角色管理页中哪些角色开关不可操作、提示文案的具体表达。需要在开发前由产品和安全方确认名单。
   建议确认方：产品 + 安全
