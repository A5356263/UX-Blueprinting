# 体验蓝图：员工自助申请权限

## 0. 本次关键设计判断

**判断：**

这次体验方案的核心不是设计一个漂亮的申请表单，而是让三类角色（管理员、审批人、员工）各自清楚自己的职责边界，并且在每个关键节点都能获得明确的系统反馈。管理端要能控得住，员工端要能看得懂，审批端要能处理得完。

**主要影响：**

1. 管理员配置页需要同时承载开关、范围选择、审批人指定三项职责，信息密度较高
2. 员工端需要建立三条信息线：我有什么、我能申请什么、我的申请到哪了
3. 审批人的处理体验容易被忽略——审批人可能不常登录系统，需要通知触达

**建议方案：**

- 管理端采用独立配置页，"开关+范围+审批人"三步完成配置
- 员工端在权限查询结果页嵌入申请入口，降低认知切换成本
- 审批人通过待办或通知进入审批页，审批通过后系统静默完成授权

**不建议方案：**

- 不建议把管理员配置页做成弹窗或侧边栏——配置项较多，独立页面更清晰
- 不建议员工端独立做一个"权限申请中心"——与现有"我的权限"查询入口聚合更自然

**关键待确认：**

1. 员工申请时按角色还是按功能权限点——直接影响申请页面的交互形式

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- 超级管理员：识别需要开放自助申请 → 开启配置（设范围、定审批人）→ 确认能力上线
- 员工：发现缺少权限 → 查看已有权限确认确实没有 → 在可申请范围内选择 → 填写理由提交 → 等待审批 → 收到结果通知
- 审批人：收到待审批通知 → 查看申请内容 → 判断并决定（通过/拒绝）→ 确认处理完成

### 旅程缺口

- 员工"发现缺少权限"的触发场景不明确——是主动查看还是使用受阻后才知道需要申请
- 缺少"审批人超时未处理"的升级机制定义
- 缺少"授权失败"后员工和审批人如何获知结果的通知规则

## 2. 交互流程总览

**分角色交互流程：**

- 超级管理员：进入管理后台配置页 → 开启自助申请开关 → 选择可申请范围（角色/功能权限）→ 指定审批人 → 保存生效
- 员工：进入权限查询页面 → 查看已有权限 → 切换到"可申请权限"列表 → 选择需要的权限 → 填写申请原因 → 提交申请 → 在申请记录中查看进度 → 收到结果通知
- 审批人：收到待审批通知消息 → 进入审批列表 → 查看申请详情 → 通过或拒绝 → 确认处理结果

**异常流程重点：**

- 管理员开启时未指定审批人 → 系统提示并阻止开启
- 员工提交的申请审批人不复存在（已离职/已变更）→ 申请卡住，需要兜底
- 审批通过后自动授权失败 → 授权状态异常，管理员介入
- 管理员关闭能力时存在在途申请 → 二次确认后继续关闭

## 3. 主交互流程

### 节点 3.1：管理员开启自助申请配置

**用户动作：**

进入权限管理 → 找到"自助申请配置"入口 → 开启开关

**系统反馈：**

进入配置页，展示配置表单：可申请范围选择区（树形多选：按角色分类/按功能权限分类）+ 审批人指定区（人员选择器）

**需要前置解释的信息：**

- 开启后员工将在工作台看到"权限申请"入口
- 可申请范围建议按最小必要原则配置
- 未指定审批人时无法开启

**建议文案：**

"开启后，员工可以按配置范围申请权限，审批通过后系统自动授权。"
"可申请范围决定员工能申请哪些权限，建议按最小必要原则配置。"

**下一步：**

配置完成后保存 → 系统提示"自助申请已开启" → 能力上线

### 节点 3.2：员工提交权限申请

**用户动作：**

进入"我的权限"页面 → 查看已有权限 → 切换到"可申请权限"列表 → 浏览或搜索可申请的权限 → 选择目标权限 → 填写申请原因 → 点击提交

**系统反馈：**

提交成功 → 状态变为"审批中" → 进入申请记录列表

**需要前置解释的信息：**

- 可申请范围由管理员配置，不在范围内的权限无法申请
- 审批通过后才能获得权限，审批人由管理员指定
- 建议填写真实的申请原因，有助于审批人判断

**建议文案：**

申请按钮："提交申请"
提交成功："申请已提交，等待审批人处理"
列表空态："当前没有可申请的权限，如需其他权限请联系管理员"

**下一步：**

等待审批 → 在申请记录中查看进度

### 节点 3.3：审批人处理申请

**用户动作：**

收到待审批通知 → 进入审批列表（或直接通过通知进入申请详情）→ 查看申请内容和原因 → 点击"通过"或"拒绝" → 如拒绝需填写原因

**系统反馈：**

- 通过：系统自动执行授权 → 授权成功后更新状态为"已通过" → 通知员工
- 拒绝：状态更新为"已拒绝" + 拒绝原因 → 通知员工

**需要前置解释的信息：**

- 审批通过后系统自动完成授权，不需要审批人手动配置
- 如果授权失败，审批人会收到异常通知

**建议文案：**

审批页标题："权限申请审批"
通过按钮："同意授权"
拒绝按钮："拒绝"
拒绝原因提示："请说明拒绝原因，申请人将收到反馈"

**下一步：**

处理完成后返回审批列表

### 节点 3.4：管理员关闭自助申请

**用户动作：**

进入自助申请配置页 → 关闭开关

**系统反馈：**

检测是否存在在途申请 → 如有：弹出二次确认弹窗"当前有 X 笔审批中的申请，关闭后新申请将无法提交，已在审批中的申请将继续完成。确认关闭？" → 确认后能力下线

**需要前置解释的信息：**

- 关闭后员工端不再显示申请入口
- 已在审批中的申请不受影响

**建议文案：**

"关闭后，员工将无法提交新的权限申请。已在审批中的申请将继续正常处理。"
二次确认弹窗标题："确认关闭自助申请？"

**下一步：**

能力下线 → 员工端入口消失

## 4. 次交互流程

### 节点 4.1：员工查看已有权限

**用户动作：** 进入"我的权限"页面 → 查看按应用或角色聚合的权限清单
**系统反馈：** 展示当前已生效的权限列表，包含来源说明（管理员授予/角色分配/自助申请获得）
**下一步：** 如需更多权限，切换到申请入口

### 节点 4.2：员工撤销申请

**用户动作：** 在申请记录中找到审批中的申请 → 点击"撤销申请"
**系统反馈：** 确认后状态更新为"已撤销" → 通知审批人
**前置条件：** 仅限状态为"审批中"的申请
**建议文案：** 撤销确认："确定撤销该申请？撤销后审批人将收到取消通知。"

### 节点 4.3：员工查看申请记录

**用户动作：** 进入申请记录列表 → 按状态筛选或搜索 → 点击查看详情
**系统反馈：** 展示申请内容、当前状态、审批意见（如有）、处理时间线
**下一步：** 被拒绝后可重新申请或联系管理员

## 5. 异常与阻断流程

### 异常 5.1：审批人缺失

**发生时机：** 管理员开启配置时 / 申请流转时
**触发条件：** 管理员未指定审批人；或指定的审批人已离职/不可用
**判断依据：** business 规则——审批人由管理员配置时指定
**反馈形式：** 配置阶段——字段提示；运行时——申请卡住
**系统反馈：** 配置时提示"请至少指定一位审批人"并阻止开启；运行时系统标记"审批人不可用"并通知超管
**用户下一步：** 管理员重新指定审批人

### 异常 5.2：审批通过但授权失败

**发生时机：** 审批人点击"通过"后
**触发条件：** 自动授权接口异常或权限冲突
**判断依据：** business 风险策略
**反馈形式：** 系统异常通知
**系统反馈：** 授权失败 → 申请状态标记为"已通过（授权异常）" → 通知管理员和审批人
**用户下一步：** 管理员手动介入或等待系统重试

### 异常 5.3：员工申请超出可申请范围

**发生时机：** 员工提交申请时
**触发条件：** 员工选择的权限不在管理员配置的可申请范围内
**判断依据：** business 规则——可申请范围由管理员预设
**反馈形式：** 提交时拦截提示
**系统反馈：** "该权限不在可申请范围内，如需申请请联系管理员"
**用户下一步：** 联系管理员或选择范围内的其他权限

### 异常 5.4：关闭能力时存在在途申请

**发生时机：** 管理员关闭自助申请能力时
**触发条件：** 存在状态为"审批中"的申请
**判断依据：** business 规则——关闭时关新不关旧
**反馈形式：** 二次确认弹窗
**系统反馈：** 弹窗列出在途申请数量，确认后方可关闭
**用户下一步：** 确认关闭（在途继续处理）或取消操作

## 6. 页面 / 弹窗 / 抽屉设计

### 页面 6.1：管理员自助申请配置页

**页面目标：** 超级管理员在此开启/关闭自助申请，配置可申请范围和审批人
**进入条件：** 权限管理模块下的独立配置入口
**页面结构：**
```
+--------------------------------------------------+
| 标题：自助申请配置                                 |
| 说明：开启后员工可按配置范围申请权限               |
+--------------------------------------------------+
| 开关区：启用/停用                                  |
+--------------------------------------------------+
| 可申请范围区：                                     |
| [按角色] 树形选择列表，多选                       |
| 或 [按功能权限] 树形选择列表，多选                |
+--------------------------------------------------+
| 审批人区：人员选择器，多选                        |
| 提示：未指定审批人时无法开启                      |
+--------------------------------------------------+
| 保存按钮                                           |
+--------------------------------------------------+
```
**状态反馈区：** 开关下方显示当前状态提示（已开启/已关闭）
**异常状态下的结构变化：** 关闭状态下范围区和审批人区可编辑但置灰提示
**字段说明：** "可申请范围"下方提示"建议按最小必要原则配置"
**按钮：** 主要按钮"保存"，次要按钮"取消"
**成功反馈：** "配置已保存"
**失败反馈：** "保存失败，请重试"

### 页面 6.2：员工端"我的权限"页面

**页面目标：** 员工查看已有权限和可申请权限
**进入条件：** 工作台或应用中进入"我的权限"入口
**页面结构：**
```
+--------------------------------------------------+
| 标题：我的权限                                     |
| 标签切换：[已有权限] [可申请权限] [申请记录]       |
+--------------------------------------------------+
| 按应用或角色聚合的权限列表                         |
| 每项展示：权限名称、来源说明、生效状态             |
+--------------------------------------------------+
```
**状态反馈区：** 各权限项标注来源（管理员授予/角色/自助申请）
**异常状态下的结构变化：** 无可申请权限时展示空态
**按钮：** 无主要操作按钮，切换到"可申请权限"标签后出现"提交申请"按钮

### 页面 6.3：员工端申请权限表单（弹窗或页面）

**页面目标：** 员工在可申请范围内选择权限并提交
**进入条件：** 在"可申请权限"标签页点击申请
**页面结构：**
```
+--------------------------------------------------+
| 标题：申请权限                                     |
+--------------------------------------------------+
| 可申请的权限列表（多选，勾选框）                  |
| 搜索/筛选                                         |
+--------------------------------------------------+
| 申请原因：多行文本输入框                          |
| 提示：请说明申请用途，有助于审批人判断            |
+--------------------------------------------------+
| 提交按钮  |  取消                                  |
+--------------------------------------------------+
```
**状态反馈区：** 提交后显示成功提示
**按钮：** 主要按钮"提交申请"，次要按钮"取消"
**成功反馈：** "申请已提交，请等待审批人处理"
**失败反馈：** "提交失败，请重试"

### 页面 6.4：审批人端审批详情页

**页面目标：** 审批人查看申请内容并做出决定
**进入条件：** 从待办列表或通知消息进入
**页面结构：**
```
+--------------------------------------------------+
| 标题：权限申请审批                                 |
+--------------------------------------------------+
| 申请人信息：姓名/部门                             |
| 申请权限：权限清单                                |
| 申请原因：用户填写的申请理由                     |
+--------------------------------------------------+
| 处理区：                                           |
| [同意授权]  [拒绝]                                |
+--------------------------------------------------+
```
**状态反馈区：** 底部显示当前审批状态和操作记录
**异常状态下的结构变化：** 点击拒绝时出现原因输入框
**按钮：** 主要按钮"同意授权"，次要按钮"拒绝"
**成功反馈：** "已处理完成"
**失败反馈：** "处理失败，请重试"

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|------|------|---------|-----------|------------|
| 待提交 | 员工正在填写申请，尚未提交 | 员工 | 编辑/取消 | "请完善申请信息" |
| 审批中 | 申请已提交，等待审批人处理 | 员工、审批人 | 员工可撤销；审批人可处理 | "等待审批人处理" |
| 已通过 | 审批人同意，系统已自动授权 | 员工、审批人 | 查看权限 | "申请已通过，权限已生效" |
| 已拒绝 | 审批人拒绝 | 员工、审批人 | 查看拒绝原因 | "申请未通过" + 拒绝原因 |
| 已撤销 | 员工主动取消申请 | 员工、审批人 | 查看 | "申请已撤销" |
| 已通过（授权异常） | 审批人同意但系统授权失败 | 管理员、审批人 | 管理员介入处理 | "审批已通过，但授权异常，请联系管理员" |
| 权限已获得 | 该权限已生效 | 员工 | 使用权限 | "已有此权限" |
| 权限待审批 | 该权限已申请但尚未生效 | 员工 | 查看进度 | "已申请，等待审批" |

## 8. 待确认问题

1. **员工申请时按角色申请还是按功能权限点申请**

   影响：两种方式导致申请页面交互完全不同。按角色申请只需选择角色→提交；按功能权限点申请需要提供可搜索的权限列表+多选。同时也影响管理端的范围配置交互。
   建议确认方：产品 / 设计

2. **"我的权限"页面的入口位置**

   影响：员工从哪里进入"我的权限"页面——工作台、应用内、个人中心？这决定了是否需要在现有导航中新增入口或扩展现有入口。
   建议确认方：产品 / 设计

3. **审批人通知方式**

   影响：审批人如何收到待审批通知——应用内消息、短信、邮件、企业微信/钉钉？不通知到位可能导致申请长期无人处理。
   建议确认方：产品 / 技术

4. **员工端是否需要移动端适配**

   影响：如果员工主要通过移动端操作，申请页面的交互和布局需要单独设计。
   建议确认方：产品 / 设计
