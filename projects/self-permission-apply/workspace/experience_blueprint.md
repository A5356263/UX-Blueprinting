# 体验蓝图

## 0. 本次关键设计判断

**判断：**

自助申请权限本质上是把权限分配从"管理员统一管控"变成"规则制定+业务判断+系统执行"三层分工。体验方案要同时服务好三个角色：超管要能精准划定开放边界而不被配置项淹没，员工要能在不培训的情况下独立完成申请，审批人要能快速判断申请是否合理。

**主要影响：**

1. 最复杂的体验设计不在员工端，而在管理端的范围配置——超管需要理解"申请角色"和"申请功能权限"的差异，并做出适合企业的选择
2. 员工端最大的体验风险不是操作路径长，而是"不知道能申请什么"和"提交后不知道卡在哪"
3. 审批人的决策信息充分度直接决定审批效率——只看到"某某申请了角色A"是不够的

**建议方案：**

- 管理端配置用步骤引导（三步）降低超管认知负担，每一步伴随明确的说明文案
- 员工端申请前展示完整的可申请清单，审批中展示流转进度，驳回时展示原因
- 审批人侧与OA审批流程一致，不做独立审批页

**不建议方案：**

- 不要把"申请角色"和"申请功能权限"做成员工端的主动选择——这个选择应该在管理端配置时定死，员工端只面对单一入口
- 不要把审批功能独立实现在权限模块内——应复用流程引擎

**关键待确认：**

1. 审批人不可用时的兜底策略（影响审批流程的完整性）
2. 功能权限申请时数据权限默认全量是否允许超管覆盖（影响员工端申请表单的字段配置）

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

```md
- 超级管理员：发现现有权限管理效率瓶颈 → 开启自助申请模式 → 配置申请方式和范围 → 设置审批流程 → 确认启用 → 监控运行状态
- 员工：收到通知或自行发现可申请权限 → 查看个人权限清单 → 了解可申请范围 → 选择需要申请的角色或功能 → 填写申请原因并提交 → 等待审批 → 收到审批结果 → 查看权限已生效
- 审批人（组织负责人）：收到审批待办 → 查看申请详情（申请人、申请原因、申请内容） → 判断是否同意 → 审批通过/驳回 → 确认结果已通知
```

### 旅程缺口

- 员工怎么知道"现在可以申请权限了"？是主动通知还是被动发现，文档未明确
- 审批人侧是否需要在OA审批之外补充额外的权限上下文信息，文档未说明

## 2. 交互流程总览

**分角色交互流程：**

- 超级管理员：权限管理模式入口 → 选择自助申请模式 → 阅读模式说明和风险提示 → 点击立即启用 → 配置申请方式（角色/功能权限） → 配置范围（全部/部分） → 配置审批流程 → 点击启用 → 校验互斥模式 → 启用成功/失败 → 运行中查看状态 → 关闭或编辑
- 员工：个人中心 → 我的权限入口 → 查看已有权限（功能权限/数据权限/角色） → 切换到申请权限 → 查看可申请清单 → 勾选所需内容 → 填写申请原因 → 提交 → 进入申请记录查看进度 → 收到审批结果通知
- 审批人：收到待办 → 查看申请详情 → 审批通过/驳回 → 填写审批意见（驳回必填） → 确认

**异常流程重点：**

- 互斥模式阻断（启用时校验失败）
- 在途流程阻碍关闭（关闭模式时）
- 员工特殊身份校验失败（资金用户/子管理员）
- 审批人不可用导致申请卡在审批中
- 关闭模式时在途流程拦截

## 3. 主交互流程

```text
节点 3.1：超管开启自助申请权限模式

**用户动作：**

超管进入权限管理模式 → 看到"自助申请权限模式"卡片（含说明文案） → 点击"立即启用"

**系统反馈：**

校验"双管理员互审模式"和"权限变更审批模式"是否已开启。
- 未开启：进入设置页面，此时模式仍为未开启状态
- 已开启任一模式：弹出提示"企业已开启「双管理员互审模式」，不能同时开启此模式"，阻断进入设置

**需要前置解释的信息：**

三种权限管理模式的区别和互斥关系，帮助超管理解为什么不能同时开启

**建议文案：**

模式卡片说明："员工可自助申请权限，工作流审批通过后，系统将自动分配权限"
阻断提示："企业已开启「XXX模式」，不能同时开启此模式"

**下一步：**

设置页面（通过校验时）/ 继续使用现有模式（被阻断时）
```

```text
节点 3.2：超管配置申请范围和审批流程

**用户动作：**

第一步选择申请方式（申请角色/申请功能权限），第二步设置范围（全部/部分），第三步查看或修改审批流程 → 点击"启用"

**系统反馈：**

- 第一步选中"申请角色"→第二步展示角色范围配置；选中"申请功能权限"→第二步展示应用范围配置
- 选择"部分范围"时打开选择弹窗（支持搜索、分页、多选）
- 审批流程默认展示组织负责人，可点击修改跳转至表单编辑
- 点击"启用"前再次校验互斥模式

**需要前置解释的信息：**

- 两种申请方式的差异：角色方式适合已启用角色管理的企业，功能权限方式适合直接按应用授权的企业
- 选择全部角色时实际只包括已启用角色
- "后续新增角色自动加入"的默认含义

**建议文案：**

申请角色下方提示："1. 申请通过后，员工将自动关联上申请角色 2. 如果企业常用角色进行授权，建议采用此方式"
申请功能权限下方提示："1. 申请通过后，员工将自动授权功能权限 2. 如果企业常用用户直接授权的方式，建议采用此方式"
审批流程说明："系统已预设了员工申请权限时的审批流程，预设审批人为员工所在组织的组织负责人"

**下一步：**

启用成功 → toast提示 + 页面刷新为已开启状态 / 启用失败 → 阻断提示
```

```text
节点 3.3：员工申请权限

**用户动作：**

在个人中心点击"申请权限" → 抽屉打开申请表单 → 查看可申请清单 → 勾选需要的内容 → 填写申请原因 → 点击提交

**系统反馈：**

- 抽屉默认显示当前员工可申请的内容（由超管配置的范围决定）
- 选择内容后，校验特殊身份（资金用户/子管理员模式）
- 提交成功：创建申请单，状态为"审批中"，出发审批流程
- 校验失败：阻断提交，提示具体原因

**需要前置解释的信息：**

- "我能申请什么"——可申请清单比员工想象的可能窄，需要清晰展示
- "申请角色"时员工获得的是完整的角色权限；"申请功能权限"时默认获得该功能的所有数据权限
- 功能权限申请时的提示："提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。"

**建议文案：**

申请原因placeholder："请填写申请原因"
提交按钮文案："提交申请"
资金用户校验失败："您当前身份不支持申请代发付款权限"
子管理员校验失败："子管理员不能授予子管理员模式权限"

**下一步：**

提交成功 → 跳转至申请记录页面 / 留在当前页面
```

```text
节点 3.4：审批人审批

**用户动作：**

收到待办通知 → 查看申请详情（申请人、申请原因、申请内容） → 同意或驳回

**系统反馈：**

- 审批通过：系统自动分配权限，申请单状态变更为"已通过"，通知员工
- 审批驳回：申请单状态变更为"已拒绝"，通知员工（含驳回原因）

**需要前置解释的信息：**

- 申请详情中展示申请人的当前权限摘要，帮助审批人判断"是否已经有过类似权限"
- 审批人可以看到申请人的组织信息，以便确认该员工是否属于自己管辖

**建议文案：**

审批详情页标题："权限申请审批"
审批通过确认文案："确认后，系统将自动为申请人分配所选权限"
驳回提示（必填）："请填写驳回原因"

**下一步：**

审批完成 → 返回待办列表
```

## 4. 次交互流程

```text
### 节点 4.1：员工查看我的权限

**用户动作：** 在个人中心点击"我的权限" → 在功能权限、数据权限、角色三个tab间切换查看
**系统反馈：** 默认显示功能权限tab，有数据时展示应用和功能权限列表；无数据时展示空状态提示和占位图
**建议文案：** 空状态提示"您没有功能权限"/"您没有数据权限"/"您没有关联的角色"
**下一步：** 切换tab / 点击"申请权限"去申请新权限
```

```text
### 节点 4.2：员工撤销申请

**用户动作：** 在申请记录中找到审批中的申请单 → 点击"撤销" → 确认撤销
**系统反馈：** 撤销后申请单状态变更为"已撤销"，审批人侧待办自动关闭
**下一步：** 员工可重新提交申请
```

```text
### 节点 4.3：超管编辑已启用的模式

**用户动作：** 在已开启状态页面点击"编辑" → 页面变更为可编辑状态 → 修改配置 → 点击"确认编辑"
**系统反馈：** 编辑时关闭模式和编辑按钮隐藏，底部显示"取消编辑"和"确认编辑"按钮；编辑成功后toast提示"编辑成功"
**下一步：** 页面恢复为已开启状态，配置生效
```

```text
### 节点 4.4：超管查看操作记录

**用户动作：** 在操作记录入口查看权限变更记录
**系统反馈：** 展示自助申请相关的操作日志（开启、关闭、编辑、审批结果等）
**下一步：** 用于审计和排障
```

## 5. 异常与阻断流程

```text
异常 5.1：互斥模式阻断启用

**发生时机：** 超管点击"立即启用"或"启用"时
**触发条件：** 企业已开启"双管理员互审模式"或"权限变更审批模式"
**判断依据：** facts.md 关键业务规则 3.1
**反馈形式：** 弹窗提示
**建议文案：** "企业已开启「双管理员互审模式」，不能同时开启此模式"
**用户下一步：** 如需继续，可先关闭已开启的互斥模式后再尝试
```

```text
异常 5.2：在途流程阻塞关闭模式

**发生时机：** 超管点击"关闭模式"并确认关闭后
**触发条件：** 存在此模式的未完成审批的申请单
**判断依据：** facts.md 状态流转表
**反馈形式：** 弹窗提示
**建议文案：** 弹窗标题"关闭失败"；内容"当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式"
**用户下一步：** 等待审批完成或联系审批人加速处理
```

```text
异常 5.3：资金用户/子管理员校验失败

**发生时机：** 员工提交申请时
**触发条件：** 为非资金用户授予代发付款权限，或子管理员授予子管理员模式权限
**判断依据：** facts.md 关键业务规则 3.6
**反馈形式：** 提交时表单校验提示
**建议文案：** "您当前身份不支持申请代发付款权限" / "子管理员不能授予子管理员模式权限"
**用户下一步：** 更换申请内容或联系企业管理员
```

```text
异常 5.4：申请内容超出可申请范围

**发生时机：** 员工在申请权限表单中选择申请内容时
**触发条件：** 员工尝试申请超出超管配置的可申请范围
**判断依据：** business_blueprint_lite 规则边界说明
**反馈形式：** 前置范围控制——员工不可见不可选不允许的内容
**用户下一步：** 无可操作项，只能在允许范围内申请
```

```text
异常 5.5：审批人不可用导致申请卡住

**发生时机：** 审批人长期未处理
**触发条件：** 组织负责人离职、出差、不在岗
**判断依据：** facts.md GAP表
**反馈形式：** 申请记录中显示"审批中"状态，无进展
**用户下一步：** [GAP] 当前无自动补救路径；体验建议在申请记录中提供"联系管理员"的入口或提示
```

```text
异常 5.6：未开启模式的企业员工无入口

**发生时机：** 员工访问个人中心
**触发条件：** 企业未开启自助申请权限模式
**判断依据：** facts.md 异常与边界表
**反馈形式：** 不展示"我的权限"入口
**用户下一步：** 无可操作项
```

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|:---|:---|:---|:---|:---|
| 审批中 | 申请已提交，等待审批人处理 | 员工 | 查看、撤销 | "您的权限申请已提交，等待XX审批" |
| 已通过 | 审批人同意，系统已自动分配权限 | 员工 | 查看已生效权限 | "权限申请已通过，您已获得申请的权限" |
| 已拒绝 | 审批人驳回了申请 | 员工 | 查看驳回原因、重新申请 | "权限申请未通过，原因：[驳回原因]" |
| 已撤销 | 申请人在审批过程中主动撤销 | 员工 | 重新提交申请 | "您已撤销此权限申请" |
| 自助模式：已启用 | 模式已开启，员工可自助申请 | 超管 | 编辑、关闭 | "此模式已开启，员工可以自助查询和申请个人权限" |
| 自助模式：未启用 | 模式未开启 | 超管 | 立即启用 | "员工可自助申请权限，工作流审批通过后自动分配" |
| 关闭失败（有在途流程） | 存在未完成的申请单 | 超管 | 等审批完成再关闭 | "当前有申请流程未完成审批" |

## 8. 待确认问题

1. **审批人不可用的兜底策略**

   影响：当组织负责人离职、出差或不在岗时，申请单卡在"审批中"状态，员工无法获得权限，且当前无自动补救路径。体验上需要在申请记录中预留告知和引导位。
   建议确认方：产品 / 业务

2. **功能权限的数据权限是否允许超管改为部分数据权限**

   影响：当前设计是"默认全量数据权限"，但对数据敏感型企业可能权限过于宽泛。如果允许超管配置为部分，管理端的配置表单和员工端的申请说明文案都需要调整。
   建议确认方：产品 / 设计

3. **审批人侧展示的信息丰富度**

   影响：审批人看到的申请详情是否包含申请人的当前权限摘要、组织归属等上下文信息，直接影响审批效率。目前默认展示申请人、原因、内容三个字段，补充信息需要确认。
   建议确认方：产品 / 设计

4. **员工如何知道"现在可以申请权限了"**

   影响：如果员工不知道企业已开启此模式，"我的权限"入口可能会被忽略。是否需要首次开启时的全员通知，文档未说明。
   建议确认方：产品 / 运营

## 附录：设计指南消费说明

### 1. 设计指南消费

体验蓝图参考了权限管理域的以下设计原则：

- **可解释性优先原则（TR-001）**：员工的每条申请记录和审批结果都应能回答"为什么有/为什么没有/来自哪里/谁审批的"。在"申请记录"页、"我的权限"页和审批通知中均体现了状态解释和原因展示。
- **概念不增殖原则（TR-003）**：未新增独立权限数据类型，未新增审批引擎，审批复用已存在流程引擎，权限分配复用现有决策链。
- **查询闭环原则（TR-005）**：通过"我的权限"提供按人查权限的闭环，通过"申请记录"提供按变更查状态的闭环。
- **安全第一原则（TR-006）**：关闭模式时的在途流程拦截、互斥模式校验、资金用户/子管理员校验均体现了安全保护策略。

### 2. 业务知识消费

| 业务知识 | 关键规则/事实 | 转换成的体验策略 | 落点 |
