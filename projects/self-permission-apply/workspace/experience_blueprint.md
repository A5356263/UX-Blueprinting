# 体验蓝图

> 本蓝图承接 business_blueprint.md 和 facts.md，用 UX 设计师的语言描述谁做什么、系统如何反馈、页面如何承接、异常如何处理。

## 0. 本次关键设计判断

**判断：**

体验方案的核心思路是「三端独立路由 + 共用审批中台 + 统一权限来源展示」。管理端专注配置和监控，员工端专注查看和发起，审批端复用审批中台能力，所有端在权限来源展示上保持一致。

**主要影响：**

1. 员工需要在「我的权限」页面看到一个全新的内容区——不只是现有权限列表，还包括「可以申请什么」和「申请记录」
2. 管理端需要新增一个独立的配置模块，包含能力开关、角色选择、审批规则、统计面板
3. 审批端需要在不增加认知负担的前提下区分「员工申请」和「管理员变更」两种审批类型

**建议方案：**

- 员工端以「我的权限」为统一入口，承载查看权限、申请权限、查看申请记录三个任务
- 管理端以「自助申请权限配置」为独立入口，放在权限管理后台的治理相关区域
- 审批端复用审批中台列表页，通过类型标签区分来源
- 所有权限展示页面统一使用「管理员分配」「自助申请」两种来源说明

**不建议方案：**

- 不给员工单独做一个「权限申请中心」——会让员工在「我的权限」和一个独立入口之间来回切换
- 不给管理员把配置项分散在多个已有页面里——集中在一个配置页维护成本最低
- 不在审批中台里给自助申请做一套独立的审批页面——复用现有审批详情，只加必要字段

**关键待确认：**

暂无影响核心体验判断的关键待确认。

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- 员工：发现缺少权限 → 打开「我的权限」查看已有权限 → 点击申请 → 选择角色 → 填写原因 → 提交申请 → 等待审批通知 → 查看申请状态 → 权限生效后看到来源标注
- 审批人：收到审批通知 → 打开审批列表 → 看到待审批的权限申请 → 查看申请详情和角色说明 → 决定同意或拒绝 → 填写审批意见 → 结果通知申请人
- 管理员：进入配置页 → 首次使用看到引导 → 勾选可申请角色 → 设置审批规则 → 开启能力 → 后续查看统计和调整配置 → 需要时关闭或调整

### 旅程缺口

- 缺少结果通知的具体规则（审批通过/拒绝后通过什么渠道通知员工）→ 建议复用现有审批中台的通知机制
- 缺少员工首次发现「我的权限」入口的引导 → 建议在能力开启后通过工作台横幅或消息提醒告知员工新入口

## 2. 交互流程总览

**分角色交互流程：**

- 管理员：进入权限管理后台 → 找到「自助申请权限」配置入口 → 节点 3.1 首次开启配置 → 节点 3.2 日常查看和调整 → 节点 3.3 关闭能力（需要时）
- 员工：进入「我的权限」 → 查看已有权限和来源 → 节点 3.4 发现缺权限并申请 → 节点 3.5 查看申请记录 → 节点 3.7 撤销申请
- 审批人：进入审批列表 → 节点 3.6 查看并处理权限申请

**异常流程重点：**

- 员工无直属上级 → 提交时提示并自动转交
- 重复申请 → 提交时阻止
- 可申请角色被移除 → 在途申请不受影响，草稿提示失效
- 能力被关闭 → 员工端入口变为不可用
- 审批人失效 → 管理员收到提醒

## 3. 主交互流程

### 节点 3.1：管理员首次开启自助申请权限

**用户动作：**

管理员在权限管理后台点击「自助申请权限」，进入配置页。由于能力尚未开启，页面展示的是引导状态。

**系统反馈：**

页面显示能力说明：「开启后，员工可以在工作台看到『我的权限』入口，自助查看已有权限并发起权限申请。所有申请必须经过审批，审批通过后系统自动授权。」

页面底部有「开启自助申请权限」按钮，但按钮当前为禁用状态。按钮上方有一句话提示：「请先完成以下配置后再开启：至少选择一个可申请角色、设置审批方式。」

**需要前置解释的信息：**

- 这个能力是什么，开启后会发生什么变化
- 员工会看到什么，管理员的职责是什么
- 哪些角色适合开放申请，哪些不适合

**建议文案：**

- 页面标题：「自助申请权限」
- 引导文字：「让员工自助查看已有权限并申请所需角色，审批通过后自动授权。您随时可以关闭或调整。」
- 配置步骤提示：「第 1 步：选择可申请角色」「第 2 步：设置审批方式」「第 3 步：开启」

**下一步：**

管理员完成配置后，按钮变为可用，点击后能力正式开启。系统提示「员工自助申请权限已开启，员工将在工作台看到『我的权限』入口」。

### 节点 3.2：管理员日常查看和调整配置

**用户动作：**

管理员再次进入「自助申请权限」配置页，能力已处于开启状态。页面顶部显示当前状态和能力开启时间。

**系统反馈：**

配置页分为三个区域：
- 可申请角色管理区：当前已开放的角色列表，每个角色显示名称、简介、是否敏感、被申请次数。支持勾选新增或取消已有，支持编辑简介，支持标记/取消敏感角色。
- 审批规则区：显示当前审批方式（直属上级 / 指定审批人），支持修改。
- 统计概览区：显示累计申请次数、通过率、当前在途申请数。

下方有「关闭自助申请权限」按钮。

**建议文案：**

- 能力状态区：「已开启，共开放 X 个角色可申请」「开启于 202X 年 X 月 X 日」
- 角色管理区标题：「可申请角色」
- 敏感角色标记说明：「标记为敏感的角色在员工端展示但不可申请」

**下一步：**

管理员修改后即时保存生效。可以留在配置页或退出。

### 节点 3.3：管理员关闭能力

**用户动作：**

管理员在配置页点击「关闭自助申请权限」。

**系统反馈：**

弹出确认弹窗，展示关闭影响：

「关闭后：
- 员工无法提交新的权限申请
- 已提交但审批中的申请不受影响，继续走完审批流程
- 已通过申请获得的权限不会被回收，保留在员工账号中

如需回收已通过自助申请获得的权限，关闭后可手动执行批量回收。」

按钮：「确认关闭」和「取消」。

管理员确认后，能力关闭，配置页回到引导状态。已有配置被保留（下次开启时不需要重新配置）。

**需要前置解释的信息：**

关闭不等于回收——这是两个独立操作，需要在交互上区分清楚。

**建议文案：**

- 确认弹窗标题：「关闭自助申请权限？」
- 主要说明：上述关闭影响信息
- 确认按钮：「确认关闭」
- 关闭后状态文案：「自助申请权限已关闭」
- 回收操作入口出现在关闭后的页面：「回收自助申请权限」

### 节点 3.4：员工发现缺权限并发起申请

**用户动作：**

员工在工作台进入「我的权限」页面，看到自己已有的权限列表。发现自己缺少某个角色权限，点击「申请权限」按钮。

**系统反馈：**

进入角色选择页。展示可申请的角色列表。每个角色卡片显示：
- 角色名称和简介
- 如果员工已拥有该角色，卡片右上角标注「已拥有」且不可点击
- 如果是敏感角色，卡片上标注「需联系管理员分配」且不可点击
- 如果员工已有审批中的该角色申请，标注「审批中」且不可点击

员工点击可选的角色卡片，进入申请表单。表单包含：
- 申请角色名称（已选定，不可修改）
- 角色权限说明（展示该角色能做什么，帮助员工确认是否选对了角色）
- 申请原因输入框（必填）
- 审批人信息（显示谁将审批这条申请）

点击「提交申请」后，系统确认提交成功。页面跳转到「我的申请」列表，新申请显示为「审批中」。

**需要前置解释的信息：**

- 员工在提交前需要看到审批人是谁，管理预期
- 角色权限说明帮助员工判断是否选对了角色

**建议文案：**

- 我的权限页面标题：「我的权限」
- 已拥有权限区域标题：「当前权限」
- 申请入口按钮：「申请权限」
- 角色选择页标题：「申请权限」
- 角色卡片介绍区域：角色名称 + 一句话简介
- 敏感角色标注文案：「需联系管理员分配」
- 申请表单标题：「申请角色」
- 原因输入框占位符：「请说明申请该角色的原因，审批人将根据此信息做出判断」
- 审批人信息展示：「审批人：XX（您的直属上级）」
- 提交按钮：「提交申请」
- 提交成功反馈：「申请已提交，请等待审批人处理」

**下一步：**

员工可以返回「我的权限」或在「我的申请」中跟踪状态。

### 节点 3.5：员工查看申请记录

**用户动作：**

员工在「我的权限」页面切换到「我的申请」标签页。

**系统反馈：**

展示申请记录列表，每条显示：
- 申请角色名称
- 当前状态（审批中 / 已通过 / 已拒绝 / 已撤销）
- 提交时间
- 如果是审批中状态，右侧显示「撤销申请」按钮

点击某条申请进入详情，展示：
- 申请角色名称
- 角色权限说明
- 申请原因
- 提交时间
- 审批人
- 审批状态时间线：提交 → 审批中 → 通过/拒绝（含审批人姓名、审批时间、审批意见）
- 如果状态为审批中，底部显示「撤销申请」按钮

**建议文案：**

- 列表页标签：「我的权限」「我的申请」
- 状态文案：审批中、已通过、已拒绝、已撤销
- 空状态：「暂无申请记录」
- 撤销确认弹窗：「撤销后将无法恢复，如需该权限请重新申请。」

**下一步：**

审批中的申请可撤销。已完成的申请作为记录保留。

### 节点 3.6：审批人处理权限申请

**用户动作：**

审批人在审批中台的审批列表里看到一条类型为「权限申请」的待审批项。

**系统反馈：**

审批列表里，每条权限申请显示类型标签「权限申请」，与「管理员变更」等其他审批类型区分。点击进入审批详情，展示：

- 申请人信息（姓名、部门）
- 申请角色名称和权限说明
- 申请原因
- 提交时间
- 审批操作区：「同意」和「拒绝」按钮
- 如果点拒绝，展开拒绝原因输入框（选填）

审批人点击「同意」后，系统完成授权，提示「已同意并完成授权」。点击「拒绝」后，流程结束，提示「已拒绝」。

**需要前置解释的信息：**

审批人看到申请角色的权限说明，帮助做出知情判断。这是体验上区别于其他审批类型的关键差异——申请的不只是一个名称，而是一组具体的权限。

**建议文案：**

- 审批类型标签：「权限申请」
- 审批详情标题：「权限申请 - [角色名称]」
- 申请人信息区：「申请由 [姓名] 提交 [时间]」「所属部门：[部门]」
- 角色说明区：「该角色包含以下权限：...」
- 同意后反馈：「已同意并完成授权」
- 拒绝后反馈：「已拒绝该申请」

**下一步：**

审批完成后，员工会收到审批结果通知（复用审批中台的通知能力）。

### 节点 3.7：员工撤销申请

**用户动作：**

员工在「我的申请」列表或详情页中点击「撤销申请」。

**系统反馈：**

弹出确认弹窗：「撤销后将无法恢复，如需该权限请重新提交申请。」员工确认后，申请状态变为「已撤销」。列表页和详情页同步更新。

**建议文案：**

- 弹窗标题：「撤销申请？」
- 弹窗正文：「撤销后将无法恢复，如需该权限请重新提交申请。」
- 确认按钮：「确认撤销」
- 撤销后列表状态：「已撤销」

**下一步：**

员工可以重新提交对同一角色的申请。

## 4. 次交互流程

### 节点 4.1：管理员调整可申请角色

**用户动作：** 管理员在配置页的角色管理区勾选或取消角色。
**系统反馈：** 勾选即时生效。取消时，如果该角色有审批中的申请，系统提示「有 X 条审批中的申请涉及该角色，取消后不影响在途申请，但员工无法再提交对该角色的新申请」。
**下一步：** 管理员确认后操作生效。

### 节点 4.2：管理员标记/取消敏感角色

**用户动作：** 管理员在角色管理区对某个已开放的角色点击「标记为敏感」。
**系统反馈：** 角色敏感标记即时生效。员工端该角色卡片标注「需联系管理员分配」且不可点击。管理员可以随时取消标记。
**下一步：** 标记后角色仍在可申请列表中，只是员工端不可申请。

### 节点 4.3：管理员批量回收权限

**用户动作：** 管理员在关闭能力后的页面点击「回收自助申请权限」。
**系统反馈：** 弹出确认弹窗，展示将从多少位员工身上回收通过自助申请获得的权限。管理员确认后，系统执行批量回收。
**建议文案：** 弹窗标题：「回收自助申请权限？」正文：「将从 X 位员工身上回收通过自助申请获得的所有权限，此操作不可撤销。」
**下一步：** 管理员确认后执行。回收完成后展示结果摘要。

### 节点 4.4：员工查看权限详情

**用户动作：** 员工在「我的权限」列表中点击某条权限。
**系统反馈：** 展示权限详情，包括：权限名称、权限来源（管理员分配 / 自助申请）、获得时间、如果是自助申请来源则显示对应的申请记录链接。
**下一步：** 员工可以关闭详情或点击链接跳转到对应的申请记录。

### 节点 4.5：审批人查看已处理的申请

**用户动作：** 审批人在审批中台的已处理列表里查看之前处理过的权限申请。
**系统反馈：** 已处理的申请保留在审批记录中，显示审批结果和审批时间。审批人可以重新查看详情但不能修改结果。
**下一步：** 仅供查看。

## 5. 异常与阻断流程

### 异常 5.1：员工无直属上级

**发生时机：** 员工点击提交申请时
**触发条件：** 系统检测到员工的直属上级字段为空
**判断依据：** facts.md「审批人不存在或已失效」异常边界；business_blueprint.md 第 7 节风险 2
**反馈形式：** 在提交确认步骤中展示提示信息而非直接报错
**系统反馈：** 「未找到您的直属上级，申请将自动转给权限管理员 XX 处理。确认提交？」员工确认后正常提交，审批人变更为权限管理员。
**用户下一步：** 员工确认并提交，或取消返回

### 异常 5.2：重复申请同一角色

**发生时机：** 员工在角色选择页点击某个角色时
**触发条件：** 员工已经拥有该角色，或已经有一个该角色审批中的申请
**判断依据：** facts.md「重复申请同一角色」异常边界
**反馈形式：** 角色卡片置灰 + 状态标注
**系统反馈：** 如果已拥有，卡片标注「已拥有」且不可点击。如果审批中，卡片标注「审批中 - 查看申请」且点击后跳转到申请详情而非新申请表单。
**用户下一步：** 无需操作，或查看已有申请状态

### 异常 5.3：能力已关闭时员工尝试申请

**发生时机：** 员工打开「我的权限」页面时
**触发条件：** 管理员已关闭自助申请能力
**判断依据：** facts.md「能力关闭时的边界处理」异常边界；business_blueprint.md 第 6 节
**反馈形式：** 页面状态变更
**系统反馈：** 「我的权限」页面仍可正常查看已有权限，但「申请权限」按钮变为不可用状态，hover 提示「自助申请权限功能暂时关闭，如需申请权限请联系管理员」。
**用户下一步：** 联系管理员

### 异常 5.4：可申请角色在员工填写期间被移除

**发生时机：** 员工正在填写申请表单时
**触发条件：** 管理员将该角色从可申请范围中移除
**判断依据：** facts.md「可申请角色被管理员移除」异常边界
**反馈形式：** 提交时校验提示
**系统反馈：** 员工点击提交时，如果角色已被移除，系统阻止提交并提示「该角色已不可申请，请返回选择其他角色」。
**用户下一步：** 返回角色选择页重新选择

### 异常 5.5：审批人账号失效

**发生时机：** 审批过程中
**触发条件：** 审批人账号被停用或标记为离职
**判断依据：** facts.md「审批人不存在或已失效」异常边界
**反馈形式：** 管理员端消息提醒
**系统反馈：** 系统检测到审批人账号异常后，向权限管理员发送提醒：「XX 的审批人 YY 账号已失效，请手动转交审批任务。」管理员可以在配置页或审批列表中将该申请转给其他审批人。员工端看到的状态不变（仍为审批中）。
**用户下一步：** 管理员手动转交审批。员工等待。审批人的处理入口变为不可用。

### 异常 5.6：员工离职或转岗

**发生时机：** 员工在审批期间或权限生效后发生离职或转岗
**触发条件：** 员工的组织状态变更
**判断依据：** business_blueprint.md 第 9 节待确认问题 3
**反馈形式：** 待确认
**系统反馈：** [GAP] 当前未明确：员工离职时自助申请获得的权限是否需要特殊回收处理。按设计预期，应与管理员分配的权限遵循相同的回收规则。
**用户下一步：** 待产品确认

## 8. 待确认问题

1. **员工端「我的权限」在工作台的具体入口位置？**

   影响：影响员工发现路径和首次使用引导方式。建议放在工作台个人区或顶部导航的个人菜单下，与「个人信息」「账号设置」等入口并列。
   建议确认方：产品 + 设计

2. **审批结果通知通过什么渠道触达员工？**

   影响：影响审批完成后的员工感知方式。建议复用现有审批中台的通知机制（站内消息 + 推送），不独立建设通知通道。
   建议确认方：产品 + 技术

3. **审批人同意申请时需要填写审批意见吗？**

   影响：影响审批详情页的操作区设计。当前方案为选填，建议保持选填——多数情况下「同意」本身就是足够的信息。
   建议确认方：产品

4. **员工申请时需要展示审批人是谁吗？**

   影响：影响申请表单的信息展示。当前方案为展示，帮助员工管理预期（知道在等谁审批）。
   建议确认方：产品

5. **管理端统计面板需要展示哪些维度的数据？**

   影响：影响配置页的统计区设计。当前方案为最基础的三项（累计申请数、通过率、在途数）。如需更细粒度（按角色统计、按时间趋势），需在体验方案中扩展。
   建议确认方：产品 + 运营

6. **员工离职时自助申请获得的权限是否需要特殊回收处理？**

   影响：影响权限回收的体验设计。当前方案认为应与管理员分配的权限遵循相同回收规则，但需产品明确。
   建议确认方：产品 + 安全

### 2. 知识缺口

| 缺失信息 | 影响模块 | 建议补充方向 |
