# 体验蓝图

> 承接 business_blueprint.md 的业务判断，结合 facts.md 的事实梳理和权限管理域/审批管理域知识，输出自助申请权限的体验方案。

## 0. 本次关键设计判断

**判断：**

自助申请权限的体验方案需要覆盖三个角色（管理员配置、员工申请、审批人处理）的完整链路，重点在配置态、申请态和审批态之间的状态衔接和异常处理。信息架构上，管理后台的配置入口放在已有"权限管理模式"内，员工端基于现有入口扩展，审批端复用已有 OA 审批能力。

**主要影响：**

1. 管理后台配置页面新增"自助申请模式"开关和配置区——与现有权限管理模式同级，需处理互斥提示和前置配置校验
2. 员工端新增权限查看和权限申请两个页面——入口位置建议放在工作台或个人中心
3. 审批端复用现有 OA 审批能力——审批人通过已有审批入口处理权限申请

**建议方案：**

- 配置入口融合：在"权限管理模式"配置页新增"自助申请模式"卡片，与双管理员模式、权限变更审批模式同级展示
- 员工端双页设计：权限列表页（展示已有权限）+ 申请页（选择权限→填写原因→提交→查看状态）
- 审批端无缝接入：权限申请作为一类新的审批表单进入 OA 审批流程，审批人不需要学习新入口
- 状态透明化：员工可随时查看申请状态（审批中/已通过/已拒绝）和审批意见

**不建议方案：**

- 不建议为自助申请做独立的审批模块——应复用已有 OA 审批能力，避免审批入口分散
- 不建议在员工端展示所有可申请的权限（不做"权限超市"）——只展示员工已有权限，申请时通过搜索或分类选择
- 不建议在 MVP 阶段支持数据权限范围的申请——数据权限的条件组模型复杂度高，体验上很难做好

**关键待确认：**

1. 员工端入口位置选用工作台还是个人中心
2. 员工申请时是否支持批量选择多个权限
3. 申请过程中是否支持草稿保存

## 1. 旅程图

### 管理员旅程：开启并配置自助申请模式

```
发现 → 进入权限管理模式 → 看到"自助申请模式"卡片（默认关闭）
评估 → 判断是否需要开启、设置哪些范围
配置 → 开启开关 → 系统校验 → 配置可申请范围和审批流程
激活 → 模式激活，员工端出现申请入口
监控 → 后续可在配置页调整范围、关闭模式
```

### 员工旅程：发现缺少权限并申请

```
感知 → 在日常工作中发现缺少某项功能权限
查询 → 进入"我的权限"页，确认确实没有该权限
选择 → 点击"申请权限" → 搜索/浏览可申请的权限 → 勾选
说明 → 填写申请原因 → 提交
等待 → 状态变为"审批中"，可查看进度
结果 → 通过则自动获得权限，拒绝则查看原因
```

### 审批人旅程：处理权限申请

```
接收 → 收到 OA 审批待办通知
查看 → 打开审批单，查看申请人、申请权限和原因
判断 → 业务判断是否应该同意
处理 → 同意（自动授权）或拒绝（填写原因）
完成 → 员工端状态同步更新
```

## 2. 交互流程总览

### 三角色总览

```
┌─ 管理后台 ─────────────────────────────┐
│ 权限管理模式 → 自助申请模式卡片          │
│ ├─ 开启/关闭开关                       │
│ ├─ 可申请范围配置（角色/功能权限）       │
│ ├─ 敏感权限排除                        │
│ └─ 审批流程配置（默认/自定义）          │
└────────────────────────────────────────┘

         ↓ 开启后，员工端出现入口

┌─ 员工端 ───────────────────────────────┐
│ 我的权限                                │
│ ├─ 已有权限列表 + 来源标记              │
│ ├─ 申请权限（选择→填原因→提交）          │
│ └─ 申请记录列表 + 详情                  │
└────────────────────────────────────────┘
         ↓ 提交后，生成审批单

┌─ 审批端（OA 审批）─────────────────────┐
│ 待办审批列表 → 权限申请审批单           │
│ ├─ 同意 → 自动授权                    │
│ └─ 拒绝 → 填写原因                    │
└────────────────────────────────────────┘
```

### 配置与审批流关联

管理员配置审批流程时有两种选择：

1. **默认审批流**：使用组织架构负责人作为审批人。系统自动根据申请人所属组织查找其直接上级，如果未配置则向上查找，均无结果时阻止提交并提示。
2. **自定义审批流**：跳转 OA 审批流程设计器，管理员可配置审批节点、抄送人、超时策略等。自定义审批流与默认审批流互斥，二选一。

## 3. 主交互流程

### 3.1 管理员配置流程

```
管理员进入权限管理模式
  → 看到"自助申请模式"卡片（默认关闭）
  → 点击开启开关
    → 系统校验：是否已配置可申请范围？
      → 未配置 → 提示"请先设置可申请范围" → 跳转配置区
      → 已配置 → 继续
    → 系统校验：是否已配置审批流程？
      → 未配置 → 提示"请先设置审批流程" → 跳转配置区
      → 已配置 → 继续
    → 系统校验：是否存在模式冲突？
      → 有冲突 → 提示冲突详情 → 提供处理建议
      → 无冲突 → 开启成功
  → 模式激活，员工端出现申请入口
```

### 3.2 员工申请流程

```
员工进入"我的权限"页
  → 查看已有权限列表
  → 发现缺少所需权限
  → 点击"申请权限"
  → 选择要申请的权限类型（角色/功能权限）
  → 搜索或浏览可申请列表
  → 勾选所需权限
  → 点击"下一步"进入填写原因
  → 填写申请原因（必填）
  → 可选上传附件
  → 点击"提交"
  → 系统校验：是否还有效（模式未关闭、权限仍在可申请范围）
    → 无效 → 提示原因，阻止提交
    → 有效 → 提交成功
  → 展示提交成功状态，告知审批人信息
  → 引导：查看申请记录 / 返回权限列表
```

### 3.3 审批人处理流程

```
审批人收到审批通知（OA 审批待办）
  → 点击审批单
  → 查看申请详情（申请人、申请权限、原因）
  → 选择处理方式：
    → 同意 → 系统自动完成授权
    → 拒绝（必填拒绝原因）
  → 处理完成
  → 员工端状态同步更新
```

## 4. 次交互流程

### 4.1 管理员关闭自助申请模式

```
管理员在配置页关闭开关
  → 系统检测当前进行中的申请数量
  → 有进行中的申请：
    → 展示二次确认弹窗
    → 弹窗内容："当前有 N 个申请正在审批中。关闭后员工将无法提交新申请，但进行中的申请仍会继续处理。"
    → 操作：确认关闭 / 取消
  → 无进行中的申请：
    → 直接关闭
  → 关闭后：
    → 员工端申请入口消失
    → 已有权限不受影响
    → 已提交的申请可继续查看状态
```

### 4.2 员工查看权限来源

```
员工在"我的权限"页查看权限项
  → 权限项旁展示来源标记
  → 标记风格：
    - "管理员授予"（默认样式）
    - "角色授予"（默认样式）
    - "自助申请"（新增样式，可附带申请时间）
  → 点击来源标记可查看详情（自助申请：查看当时的申请记录）
```

### 4.3 审批人为空时的系统行为

```
员工提交申请
  → 系统查询组织架构负责人
  → 负责人不存在：
    → 系统自动向上查找更高层负责人
    → 仍找不到：
      → 阻止提交
      → 提示"当前无可用审批人，请联系管理员配置审批流程"
  → 管理员配置了自定义审批流：
    → 按自定义流程执行
```

### 4.4 员工撤销申请（待确认）

```
员工查看申请详情
  → 状态为"审批中"且审批人尚未处理
  → 点击"撤销申请"（待产品确认是否支持）
  → 二次确认："确定要撤销该申请吗？"
  → 确认 → 申请状态变更为"已撤销"，通知审批人
  → 取消 → 不做任何变更
```

## 5. 异常与阻断流程

### E1：自助申请模式未开启

**场景**：员工尝试进入申请入口，但管理员未开启自助申请模式

**处理**：
- 员工端不显示申请入口
- 如果通过 URL 直接访问，提示"该功能未启用，请联系管理员"

### E2：可申请范围为空

**场景**：管理员开启模式但未配置可申请范围，或配置的范围为空

**处理**：
- 开启时校验：未配置范围不能开启
- 员工端：申请页展示"当前没有可申请的权限"
- 引导：联系管理员配置

### E3：模式冲突阻止配置

**场景**：管理员尝试同时开启自助申请模式和双管理员模式

**处理**：
- 检测到冲突时，展示提示："自助申请模式与双管理员模式存在冲突，不能同时开启"
- 提供建议："请关闭双管理员模式后再开启自助申请模式"
- 提供快捷操作：关闭双管理员模式

### E4：关闭模式时存在进行中的申请

**场景**：管理员关闭自助申请模式时存在进行中的申请

**处理**：
- 二次确认弹窗
- 展示申请数量
- 说明"进行中的申请将继续处理"
- 管理员确认后才关闭

### E5：提交时模式已关闭

**场景**：员工填写申请过程中（或提交瞬间），管理员关闭了自助申请模式

**处理**：
- 提交时校验模式状态
- 已关闭 → 阻止提交，提示"自助申请功能已关闭"
- 已填写的内容保留在草稿中（建议）

### E6：审批人无法处理申请

**场景**：审批人离职、转岗或无审批权限

**处理**：
- 审批人不可用时，申请流转至审批流程配置的下一个可用审批人
- 没有可用审批人时，申请进入"异常"状态
- 管理员可在后台重新指派审批人或调整审批流程

### E7：敏感权限拦截

**场景**：权限已被管理员配置为敏感权限或从可申请范围中移除

**处理**：
- 已从可申请列表移除的权限在申请页不可见
- 提交时再次校验全部已选权限的有效性
- 无效权限标记为"不可用"并提示原因

### E8：权限自动授权失败

**场景**：审批通过后，系统自动授权时发生异常

**处理**：
- 审批状态显示为"已通过，授权中"
- 系统重试授权操作
- 超过重试次数后标记为"授权异常"，通知管理员手动处理

## 6. 页面 / 弹窗 / 抽屉设计

### 6.1 管理后台：权限管理模式页

**位置**：管理后台 → 权限管理 → 权限管理模式

在现有模式列表基础上新增"自助申请模式"卡片。卡片内容包含：

- **模式名称**：自助申请权限
- **模式说明**：开启后，员工可以主动申请所需权限，经审批后自动获得
- **状态标签**：已开启 / 未开启
- **操作区**：开启/关闭开关
- **配置入口**：开启后显示"去配置"链接
- **互斥提示**：如果存在与其他模式的冲突，在卡片上展示警告

### 6.2 管理后台：自助申请模式配置抽屉

**触发**：点击"去配置"或点击开关时（配置未完成时）

**标题**：自助申请权限配置

**配置项**：

1. **可申请角色**：多选搜索框，展示所有角色列表。选中后展示为标签。支持清空全部。
2. **可申请功能权限**：树形选择器，按应用分组。展开到功能权限级别。支持搜索。
3. **敏感权限排除**：可选配置。默认带建议值（超管角色、全局配置权限、财务/税务权限）。可自定义增删。
4. **审批流程配置**：单选组，默认审批人（组织架构负责人）/ 自定义审批流程。选择自定义时跳转 OA 审批流程设计器。
5. **底部操作**：保存配置 / 取消

### 6.3 员工端：我的权限页

**位置**：员工端个人中心或工作台

**信息层级**：

- **权限概览区**：展示已拥有的角色标签（如"财务专员""项目管理员"），以及功能权限按应用分组展示
- **申请记录区**：最近 5 条申请记录，每条展示申请时间、权限名称、状态标签（审批中/已通过/已拒绝）
- **操作入口**："申请权限"按钮（主按钮），"查看全部记录"链接

**权限项展示**：
- 权限名称 + 所属应用
- 权限来源标记（管理员授予 / 角色授予 / 自助申请）
  - "自助申请"来源标记可点击，查看当时的申请详情
- 权限状态（仅审批中的权限需要展示"待生效"状态）

### 6.4 员工端：申请权限页

**布局**：三步式步骤条（选择权限 → 填写原因 → 提交结果）

**第一步：选择权限**：
- 顶部分类切换：角色 / 功能权限
- 搜索框
- 权限列表（仅展示可申请的权限，每项带复选框）
  - 权限项信息：权限名称 + 权限说明 + 所属应用
  - 点击权限项可查看详情浮层
- 已选数量浮标

**第二步：填写原因**：
- 已选权限摘要（只读标签列表，可上一步修改）
- 申请原因（必填，textarea，10-500 字，带字数统计）
- 附件上传（可选，待产品确认）
- 预计审批人信息（只读展示）

**第三步：提交结果**：
- 成功状态：图标 + "申请已提交" + 审批人信息 + 预计处理时间参考
- 出口：查看申请记录 / 返回权限列表
- 失败状态：图标 + 失败原因 + 建议操作

### 6.5 员工端：申请详情页

**信息展示**：
- 申请编号（有则展示）
- 申请权限列表
- 申请原因
- 附件（如果有）
- 申请时间
- 状态时间线（审批中 / 已通过 / 已拒绝 + 时间）
- 审批人信息 + 审批意见（如果已处理）
- 操作区：仅审批中状态可"撤销申请"（待确认）

### 6.6 审批端：权限申请审批单

**复用 OA 审批标准表单**：

- 审批标题：[申请人] 申请权限
- 表单内容：申请权限、申请原因、附件、申请人信息
- 审批操作：同意 / 拒绝（拒绝时必填原因）
- 与其他审批单的区分：建议在审批列表中增加标签或图标识别

### 6.7 弹窗/抽屉设计

**关闭确认弹窗**（管理员关闭模式时有进行中的申请）：
- 标题：确认关闭"自助申请权限"
- 内容：当前有 N 个申请正在审批中。关闭后员工将无法提交新申请，但进行中的申请仍会继续处理。已授予的权限不受影响。
- 按钮：确认关闭 / 取消

**模式冲突提示弹窗**（检测到与双管理员模式冲突）：
- 标题：模式冲突
- 内容："自助申请权限"模式与"双管理员"模式存在冲突，不能同时开启。请先关闭双管理员模式后再开启。
- 按钮：查看双管理员模式配置 / 取消

**提交成功反馈**（员工提交申请后）：
- 内联反馈，非弹窗
- 状态页设计，不阻断后续操作

## 7. 状态与反馈文案

### 7.1 申请状态定义

| 状态 | 含义 | 员工端展示 | 通知方式 |
|------|------|-----------|---------|
| 审批中 | 已提交，等待审批 | "审批中 · 预计审批人：XXX" | 提交成功即时反馈 |
| 已通过 | 审批同意，授权中 | "审批通过，正在完成授权" | OA 审批通知 |
| 已生效 | 授权完成 | "已生效" + 生效时间 | 自动同步 |
| 已拒绝 | 审批拒绝 | "已拒绝" + 拒绝原因 | OA 审批通知 + 原因 |
| 已撤销 | 员工主动撤回 | "已撤销" | 通知原审批人 |

### 7.2 关键反馈文案

**提交成功**：
- 标题：申请已提交
- 说明：你的权限申请已进入审批流程，请耐心等待
- 审批人：[姓名]
- 动作：查看申请记录 / 返回权限列表

**提交失败**：
- E1（模式未开启）："该功能未启用，请联系管理员"
- E2（范围为空）："当前没有可申请的权限，请联系管理员配置"
- E5（关闭后提交）："自助申请功能已关闭，无法提交新的申请"
- E7（权限不可申请）："所选权限当前不可申请，请刷新后重试"
- 通用失败："提交失败，请稍后重试。如持续失败请联系管理员"

**审批通过通知**：
- 标题：权限申请已通过
- 内容：你申请的 [权限名称] 已通过审批，现在可以使用了
- 动作：查看我的权限

**审批拒绝通知**：
- 标题：权限申请未通过
- 内容：你申请的 [权限名称] 未通过审批
- 原因：[审批人填写的原因]
- 动作：查看详情

### 7.3 空状态文案

- 无权限记录："你当前还没有权限，如有需要可以申请权限"
- 无可申请权限："当前没有可申请的权限，如有疑问请联系管理员"
- 无申请记录："你还没有提交过权限申请"
- 搜索无结果："未找到匹配的权限，请尝试其他关键词"

## 8. 待确认问题

1. **员工端入口位置**

   影响：决定导航结构和页面层级。建议选项：工作台快捷入口、个人中心"我的权限"入口、独立"权限申请"模块入口。

   建议确认方：产品 / 设计

2. **批量申请支持**

   影响：决定申请表单是单选还是多选。支持多选可减少操作次数但增加审批复杂度。建议 MVP 阶段支持多选同一类型权限。

   建议确认方：产品

3. **申请撤销功能**

   影响：决定是否需要撤销状态和撤销交互。员工在审批人处理前主动撤回的场景是否常见。

   建议确认方：产品

4. **草稿保存功能**

   影响：决定是否需要在申请页提供草稿能力。填写较长申请原因时是否有草稿防止内容丢失的需求。

   建议确认方：产品

5. **附件上传支持**

   影响：决定申请表单是否包含附件字段。如支持，需定义文件类型（图片/文档/压缩包）、大小限制、数量限制。

   建议确认方：产品

6. **审批端是否需要区分"权限申请"审批单**

   影响：决定 OA 审批列表中权限申请审批单的展示样式。建议使用标签/图标区分"权限申请"和普通审批，帮助审批人快速识别。

   建议确认方：产品 / 设计
