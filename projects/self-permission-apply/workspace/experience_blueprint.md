# 体验蓝图

## 0. 本次关键设计判断

**判断：**

这次体验方案的重点不是多做页面，而是把三件事做透——超管配置时每一步都知道自己在选什么、员工申请时零培训就能走完、审批状态和权限来源在任何时候都看得见。

**主要影响：**

1. 超管的三步配置页有真实的步骤依赖——第一步选"申请角色还是申请功能权限"直接决定了第二步的内容，这是一个典型的步骤条场景
2. 员工侧"我的权限"承担的是解释职责，不是配置职责——它的设计重点应该是信息分层和来源标注，而不是操作密度
3. 三条角色路径（超管配置→员工申请→审批人审批）在审批结果回写的那一刻交汇——这个交汇点在体验上最容易断裂，需要重点设计状态反馈和通知

**建议方案：**

- 超管配置使用步骤条，三步依次完成，每步校验通过才可进入下一步
- 员工申请做成抽屉形式，保持轻量——不需要跳转到独立页面，降低认知负担
- 权限来源在"我的权限"页面通过标签分组展示，让员工一眼看出"这个权限从哪来的"
- 审批状态变化通过通知和申请记录页双通道同步，员工不需要猜"为什么还没生效"

**不建议方案：**

- 把超管配置做成单页长表单——三步之间有强依赖（申请方式决定后续范围设置内容），单页表单无法表达这种依赖关系，且容易让超管在不理解全局的情况下随机填写
- 把员工申请做成独立全屏页面——申请是一个轻量操作，抽屉足够承载，全屏页面反而增加退出和回看的成本

**关键待确认：**

1. 移动端"我的权限"和"申请权限"的适配范围——如果移动端需要支持，信息架构需要重新评估
2. 审批通知的具体渠道和文案策略——影响员工感知"权限生效"的时效

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- 超管：发现权限分配工作量大 → 了解自助申请模式 → 进入配置页三步设置 → 启用模式 → 确认员工端入口已出现 → 后续观察申请数据并调整范围
- 员工：想使用某个功能但没有权限 → 进入"我的权限"查看当前已有权限 → 发现缺少目标权限 → 打开"申请权限"抽屉 → 填写原因并选择目标 → 提交申请 → 等待审批 → 收到审批结果通知 → 权限生效后在"我的权限"中确认
- 审批人：收到待办通知 → 查看申请内容（谁申请了什么、申请原因）→ 同意或拒绝 → 确认审批结果已通知申请人

### 旅程缺口

- 缺少超管发现"自助申请模式"的引导路径——超管如何从权限管理模式页注意到这个新选项
- 缺少员工首次使用时的引导——员工如何知道"我的权限"入口在哪、能做什么
- 缺少审批人在移动端的审批体验细节——OA审批支持移动端，但申请内容的展示适配需确认

## 2. 交互流程总览

**分角色交互流程：**

- 超管：权限管理模式页 → 查看模式说明（节点 3.1）→ 三步配置向导（节点 3.2）→ 启用确认 → 查看已启用状态页（节点 4.1）→ 后续编辑或关闭
- 员工：个人中心入口 → 我的权限页（节点 3.3）→ 发现缺少某权限 → 申请权限抽屉（节点 3.4）→ 填写申请 → 提交成功反馈 → 申请记录页追踪状态（节点 3.5）→ 收到审批结果通知 → 回到我的权限页确认
- 审批人：收到OA待办 → 查看申请详情 → 同意或拒绝（节点 3.6）→ 填写审批意见 → 提交 → 审批完成

**异常流程重点：**

- 超管启用时被互斥模式阻断
- 超管关闭时被在途流程阻断（当前无强制关闭通道）
- 员工申请时被特殊身份校验拒绝
- 审批人长时间未处理导致审批超时
- 员工在审批中撤销申请
- 审批流程未配置导致申请无法提交

## 3. 主交互流程

### 节点 3.1：超管了解自助申请模式

**用户动作：**

超管进入管理后台的权限管理模式页，看到三种可选模式的说明。点击"自助申请权限模式"区域，看到模式简介和"立即启用"按钮。

**系统反馈：**

展示模式说明卡片，包含：模式名称、一句话描述（"员工可自助申请权限，工作流审批通过后，系统将自动分配权限"）、适用场景、与其他模式的区别提示。底部展示"了解更多"链接（跳转帮助文档）和"立即启用"按钮。

**需要前置解释的信息：**

- 这个模式和另外两种模式（双管理员互审、权限变更审批）是互斥的，只能选一个
- 启用后员工端会出现"我的权限"入口
- 启用前需要完成三步设置

**建议文案：**

- 模式标题："自助申请权限模式"
- 说明文案："员工可自助申请权限，工作流审批通过后，系统将自动分配权限"
- 了解更多链接："了解更多"
- 主按钮："立即启用"

**下一步：**

点击"立即启用"→ 系统校验互斥模式 → 通过后进入三步配置向导（节点 3.2）

### 节点 3.2：超管三步配置向导

**用户动作：**

超管依次完成三步设置，并在最后一步点击"启用"。

**系统反馈：**

三步向导使用步骤条展示进度，每一步完成后可进入下一步，上一步可返回修改。

**第一步：选择申请方式**

- 两个互斥选项：申请角色、申请功能权限
- 默认选中"申请角色"
- 每个选项下方有提示文案说明适用场景：
  - 申请角色："申请通过后，员工将自动关联上申请角色。如果启用常用角色进行授权，建议采用此方式"
  - 申请功能权限："申请通过后，员工将自动授权功能权限。如果企业常用用户直接授权的方式，建议采用此方式"
- 选择后点击"下一步"进入第二步，第二步内容随第一步选择而变化

**第二步：设置范围**

如果第一步选了"申请角色"，展示角色范围设置；如果选了"申请功能权限"，展示应用范围设置。

- 选项：全部/部分，默认"全部"
- 选择"部分"时弹出选择器（角色选择器或应用选择器），支持搜索、分页
- 选择完成后展示所选内容摘要，限制最多展示个数
- 附带设置项：后续新增自动加入可申请范围，默认勾选
- 点击"下一步"进入第三步

**第三步：设置审批流程**

- 展示预设审批流程说明："系统已预设了「员工申请权限」时的审批流程，预设审批人为员工所在组织的组织负责人。如需调整，可点击修改审批流程"
- "修改审批流程"按钮打开表单编辑子页面
- 点击"返回"回到设置页，页面不刷新

**底部操作区：**

- "取消"——返回上一页（模式宣传页）
- "启用"——校验互斥模式 → 通过后启用成功

**需要前置解释的信息：**

- 第一步的选择不可逆——启用后如需切换申请方式，需关闭模式重新配置
- 第二步的"全部"意味着所有角色/应用都开放申请，范围较大
- 第三步的审批流程如未正确配置，员工申请的审批将无法正常流转

**建议文案：**

- 第一步标题："选择员工申请权限的方式"
- 第二步标题（角色）："设置角色范围"
- 第二步标题（应用）："设置应用范围"
- 第二步提示语（角色）："请选择允许员工自助申请的角色"
- 第二步提示语（应用）："请选择允许员工自助申请权限的应用"
- 设置项文案："后续新增角色自动加入员工可申请的范围"
- 第三步标题："设置审批流程"
- 主按钮："启用"

**下一步：**

点击"启用"→ 校验通过 → toast提示"开启成功"→ 页面刷新为已启用状态（节点 4.1）

### 节点 3.3：员工查看我的权限

**用户动作：**

员工进入个人中心，点击"我的权限"入口，查看自己当前拥有的权限。

**系统反馈：**

进入"我的权限"独立页面，默认展示"功能权限"tab。页面包含三个tab：功能权限、数据权限、角色。

- 功能权限tab：展示用户有权限的应用及对应功能权限列表，包括全员应用和管理类应用。每条权限标注来源标签（管理员授予/角色关联/申请获得）
- 数据权限tab：展示用户拥有的数据权限范围
- 角色tab：展示用户关联的所有角色，标注角色来源（管理员分配/申请获得）
- 空状态：如果某个tab下没有数据，展示占位图和提示语——"您没有功能权限""您没有数据权限""您没有关联的角色"

**需要前置解释的信息：**

- "我的权限"是只读查询页，不能在这里修改权限
- 权限来源标签帮助理解"这个权限是怎么来的"

**建议文案：**

- 页面标题："我的权限"
- Tab名称："功能权限""数据权限""角色"
- 空状态文案："您没有功能权限""您没有数据权限""您没有关联的角色"
- 来源标签："管理员授予""角色关联""申请获得"

**下一步：**

如果员工发现缺少需要的权限 → 点击页面内的"申请权限"按钮 → 进入申请权限抽屉（节点 3.4）

### 节点 3.4：员工申请权限

**用户动作：**

员工点击"申请权限"，在抽屉中填写申请并提交。

**系统反馈：**

打开"申请权限"右侧抽屉。

- 申请人：自动带出当前用户名称，不可编辑
- 申请原因：必填文本输入框，提示词"请填写申请原因"，限制最多500字
- 申请内容区：
  - 如果超管设置了"申请角色"模式：展示角色列表表格（勾选项、角色名称、角色说明），仅展示已启用且在超管预设范围内的角色
  - 如果超管设置了"申请功能权限"模式：展示功能权限设置组件，应用范围仅包括超管预设范围。顶部提示语："提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。"
- 底部：提交按钮

提交后：
- 校验特殊身份（资金用户、子管理员等），不通过则报错并阻止提交
- 校验通过后提交成功，抽屉关闭，跳转至申请记录页

**需要前置解释的信息：**

- 申请提交后需要审批人审批，不会立即生效
- 审批通过后权限自动分配，无需再找管理员
- 如果申请的功能权限需要部分数据权限，仍需联系管理员单独授权

**建议文案：**

- 抽屉标题："申请权限"
- 申请原因提示词："请填写申请原因"
- 功能权限模式提示语："提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。"
- 提交按钮："提交申请"
- 提交成功toast："申请已提交，请等待审批"

**下一步：**

提交成功 → 抽屉关闭 → 跳转申请记录页（节点 3.5）查看申请状态

### 节点 3.5：员工追踪申请记录

**用户动作：**

员工在申请记录页查看历史申请的状态，或撤销审批中的申请。

**系统反馈：**

申请记录页包含筛选区和列表区。

筛选区：
- 申请日期：日期范围选择器
- 审批状态：下拉选项（全部/已通过/已拒绝/审批中/已撤销）

列表区：
- 申请时间：年月日 时分秒
- 申请原因：提交时填写的申请原因
- 申请内容：角色名称，或"查看详情"超链接（点击打开详情抽屉，展示申请提交时的内容快照）
- 审批状态：已通过/已拒绝/审批中/已撤销（不同状态使用不同颜色标签）
- 操作："撤销"按钮，仅审批中状态可点击，其他状态置灰

分页展示。

**需要前置解释的信息：**

- 只有审批中的申请可以撤销
- 已通过的申请如需取消权限，需联系管理员
- 已拒绝的申请可以重新提交

**建议文案：**

- 页面标题："申请记录"
- 筛选项标签："申请日期""审批状态"
- 状态标签："已通过""已拒绝""审批中""已撤销"
- 操作按钮："撤销"（审批中）/ 置灰不可点击（其他状态）
- 撤销确认弹窗标题："撤销申请"
- 撤销确认弹窗文案："确认撤销此申请吗？撤销后需重新提交。"
- 撤销成功toast："申请已撤销"

**下一步：**

- 审批通过 → 回到"我的权限"（节点 3.3）确认新权限
- 审批拒绝 → 可重新提交申请
- 撤销申请 → 可重新提交申请

### 节点 3.6：审批人处理审批

**用户动作：**

审批人在OA审批中心收到待办，查看申请内容后决定同意或拒绝。

**系统反馈：**

复用OA审批的待办处理流程。

审批人看到的申请信息：
- 申请人姓名
- 申请时间
- 申请原因
- 申请内容（角色名称或功能权限详情）
- 审批操作：同意/拒绝
- 审批意见输入框

同意后：系统自动分配权限，通知申请人"权限生效"
拒绝后：权限不分配，通知申请人"权限不生效"

**需要前置解释的信息：**

- 审批人需要理解自己审批的是什么权限——申请内容应使用业务语言，不暴露技术术语
- 审批通过意味着系统会自动分配权限，审批人不需要额外操作

**建议文案：**

- 审批标题："员工申请权限 - [申请人姓名]"
- 同意按钮："同意"
- 拒绝按钮："拒绝"
- 审批意见提示："请填写审批意见（选填）"
- 同意后通知文案："您的权限申请已通过审批，权限已生效"
- 拒绝后通知文案："您的权限申请未通过审批"

**下一步：**

审批完成后 → 待办从审批人的待办列表中消失 → 申请人收到通知

## 4. 次交互流程

### 节点 4.1：超管查看已启用状态页

**用户动作：** 超管在模式启用后进入此页面，查看当前配置摘要，或进行编辑/关闭操作。

**系统反馈：**

页面顶部展示提示语："此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。"右侧有"帮助文档"链接。

页面主体展示当前配置摘要（不可编辑态）：
- 申请方式：申请角色 / 申请功能权限
- 角色/应用范围：已选范围的摘要
- 审批流程：预设审批人为组织负责人（如有修改则展示修改后配置）

底部两个按钮："关闭模式""编辑"。

**下一步：** 点击"编辑"→ 进入编辑态（节点 4.2）；点击"关闭模式"→ 进入关闭确认流程（节点 4.3）

### 节点 4.2：超管编辑已启用模式

**用户动作：** 超管点击"编辑"，修改模式配置。

**系统反馈：**

页面从不可编辑态切换为可编辑态。"关闭模式"和"编辑"按钮隐藏，底部出现"取消编辑"和"确认编辑"按钮。三步设置恢复为可编辑状态，超管可修改任意步骤的配置。

点击"确认编辑"→ toast提示"编辑成功"→ 页面回到已启用不可编辑态。
点击"取消编辑"→ 修改不保存 → 页面回到已启用不可编辑态。

**下一步：** 编辑完成后回到已启用状态页（节点 4.1）

### 节点 4.3：超管关闭模式

**用户动作：** 超管在已启用状态页点击"关闭模式"，在二次确认弹窗中确认关闭。

**系统反馈：**

弹出二次确认弹窗：
- 标题："关闭模式"
- 文案："关闭模式后，员工将无法自助查询和申请权限，请确认是否关闭自助申请模式？"
- 按钮："不关闭""确认关闭"

点击"确认关闭"后：
- 校验是否存在审批中的在途申请
- 如有在途流程 → 弹出"关闭失败"弹窗，标题"关闭失败"，文案"当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式"，按钮"知道了"
- 如无在途流程 → 关闭成功，toast提示"关闭「自助申请权限模式」成功"

**关闭成功后对各角色的影响：**

- 超管：回到权限管理模式选择页，自助申请模式卡片显示"未启用"
- 员工：个人中心"我的权限"入口消失；如在关闭前已通过申请获得的权限，权限本身不回收，仅入口隐藏（权限仍可通过管理员在"用户授权"页查看和管理）
- 审批人：已有的在途申请已被关闭前校验清空，不会出现悬空待办

**建议文案：**

- 弹窗标题："关闭模式"
- 弹窗文案："关闭模式后，员工将无法自助查询和申请权限，请确认是否关闭自助申请模式？"

## 5. 异常与阻断流程

### 异常 5.1：互斥模式冲突

**发生时机：** 超管点击"立即启用"或"启用"按钮时
**触发条件：** 企业已开启双管理员互审模式或权限变更审批模式
**判断依据：** business 业务规则——三种治理模式互斥
**反馈形式：** 弹窗阻断
**系统反馈：** 弹窗标题"无法启用"，文案"企业已开启「双管理员互审模式」，不能同时开启此模式"，按钮"知道了"
**用户下一步：** 如需启用自助申请模式，需先关闭冲突模式；或放弃启用

### 异常 5.2：在途流程阻断关闭

**发生时机：** 超管点击"确认关闭"后
**触发条件：** 存在审批中的在途申请单
**判断依据：** business 业务规则——在途流程未完成时不能正常关闭
**反馈形式：** 弹窗阻断
**系统反馈：** 弹窗标题"关闭失败"，文案"当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式"，按钮"知道了"
**用户下一步：** [GAP] 当前无强制关闭通道，超管只能等待所有审批完成。需确认是否增加"强制关闭"选项——强制关闭后自动撤销所有在途申请并通知相关人员，此操作需记录审计日志

### 异常 5.3：特殊身份校验失败

**发生时机：** 员工点击"提交申请"按钮时
**触发条件：** 申请内容触发特殊身份校验规则——非资金用户申请代发付款权限、子管理员申请子管理员模式权限、不满足实名要求等
**判断依据：** business 业务规则——复用现有权限校验体系（资金用户校验、子管理员模式权限校验、特殊身份默认权限、实名要求）
**反馈形式：** 提交失败，在触发校验的权限项旁显示错误提示，或在提交按钮上方统一展示错误摘要
**系统反馈：** 根据校验类型给出具体报错，例如：
- 资金用户校验不通过："您不是资金用户，无法申请「代发付款」权限。如需此权限，请联系企业管理员。"
- 子管理员模式校验不通过："子管理员无法申请「子管理员模式」权限。"
- 实名要求不满足："申请此权限需完成实名认证，请先前往「账号安全」完成实名认证后再申请。"
**用户下一步：** 移除不满足条件的权限项后重新提交；或按提示完成前置条件（如实名认证）后再申请；或联系管理员了解替代路径

### 异常 5.4：审批超时

**发生时机：** 审批人超过预设时间未处理待办时
**触发条件：** 审批待办超过OA审批中设置的超时时间阈值
**判断依据：** business 风险保护——审批超时处理与OA审批的超时机制对接；审批管理知识——超时处理支持4种策略（超时提醒→超时转派→超时通过→超时拒绝）
**反馈形式：**
- 对审批人：超时提醒通知（OA审批现有机制），告知"您有一条权限申请待审批已超时，请尽快处理"
- 对申请人：申请记录中状态保持"审批中"，不额外通知（避免给申请人制造焦虑）；超时后系统根据预设策略自动处理（转派/通过/拒绝），处理结果产生后正常通知申请人
**用户可见规则：** 审批超时后的处理策略应在超管配置审批流程时可见——"审批超时处理"设置项说明不同的处理策略及后果
**用户下一步：** 如审批被超时转派，新审批人收到待办继续处理；如超时通过/拒绝，申请人收到对应通知

### 异常 5.5：审批流程缺失或审批人不可用

**发生时机：** 超管启用模式时、或员工提交申请时
**触发条件：**
- 启用时：审批流程未预设完成（审批表单未创建或未发布）
- 提交时：预设的审批人（组织负责人）已离职或不存在
**判断依据：** business 前置配置——审批流程必须预设完成并可用；business 必须处理的异常——"审批流程缺失或审批人不可用时的兜底处理"
**反馈形式：**
- 启用时：点击"启用"按钮后校验审批流程是否可用。如不可用，弹窗阻断，标题"无法启用"，文案"审批流程尚未配置完成，请先完成审批流程设置后再启用"，按钮"去设置"（跳转审批流程设置页）和"取消"
- 提交时：如审批人不存在或不可用，提交失败，toast提示"审批流程异常，请联系企业管理员处理"，同时建议超管在模式已启用状态下持续监控审批流程的健康状态
**用户下一步：**
- 超管：前往OA审批完成流程配置或更新审批人设置
- 员工：等待管理员修复后重新提交

### 异常 5.6：员工重复申请已有权限

**发生时机：** 员工提交权限申请时
**触发条件：** 员工已拥有目标角色或功能权限
**判断依据：** business 风险保护——避免重复申请
**反馈形式：** 提交前前端校验提示
**系统反馈：** 如检测到员工已拥有所申请的全部权限，在提交前弹出提示"您已拥有所申请的权限，无需重复申请"
**用户下一步：** 前往"我的权限"页面确认已有权限；如仍需要申请（例如权限来源不同），可继续提交

| 已撤销 | 员工主动撤销了申请 | 员工 | 可重新提交申请 | "申请已撤销" |

### 权限来源标签

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 管理员授予 | 由超管或管理员直接授予的权限 | 员工 | 联系管理员修改 | "管理员授予" |
| 角色关联 | 通过角色关联获得的权限 | 员工 | 联系管理员修改角色 | "角色关联" |
| 申请获得 | 通过自助申请审批获得的权限 | 员工 | 联系管理员回收权限 | "申请获得" |

## 8. 待确认问题

1. **移动端适配范围**

   影响：OA审批天然支持移动端审批，但员工端的"我的权限""申请权限""申请记录"是否需要移动端适配，直接影响页面的信息架构设计（移动端tab切换方式、抽屉替代方案等）。
   建议确认方：产品

2. **审批通知渠道与文案策略**

   影响：员工如何及时知道审批结果——仅应用内通知，还是同时通过微信公众号/短信推送。不同渠道的文案长度和信息密度要求不同。
   建议确认方：产品 / 运营

3. **超管强制关闭通道**

   影响：已在business中列为GAP，直接影响关闭模式的交互设计——是否需要增加"强制关闭"按钮及对应的二次确认和审计日志。
   建议确认方：产品 / 安全

4. **首次使用引导方式**

   影响：调研中已指出培训成本风险。超管首次进入设置页、员工首次看到"我的权限"入口时，是否需要新手引导（如功能提示、步骤引导）。
   建议确认方：产品 / 设计

5. **"我的权限"中权限来源的展示颗粒度**

   影响：是按每条功能权限标注来源，还是按应用/角色层级标注来源——影响页面信息密度和可读性。
   建议确认方：设计 / 产品

6. **帮助文档链接就位时间**

   影响：多处"了解更多"和"帮助文档"链接标注为"待补充"。如果上线时帮助文档仍然缺失，需在页面临时隐藏链接还是保留但标注"即将上线"。
   建议确认方：运营 / 产品
