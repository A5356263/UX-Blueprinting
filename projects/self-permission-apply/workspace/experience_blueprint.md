# 体验蓝图

## 0. 本次关键设计判断

**判断：**

这次体验设计的核心不是"做一个好看的申请表单"，而是让三个角色在一条全新的权限获取路径上，每个关键节点都能看到自己需要的信息、做出有依据的判断。重点投入在"解释性设计"——让员工知道能申请什么、为什么有/没有权限、申请走到哪了；让审批人能判断该不该批；让管理员敢开、会配、能关。

**主要影响：**

1. 员工侧需要两个入口（缺权限时的自然触达 + 主动查看的固定入口），不能只放一个菜单项
2. 审批侧需要嵌入"申请人已有权限概览"，这是审批人判断申请合理性的关键信息
3. 管理员侧的配置体验决定这个能力会不会被用起来——如果配置门槛太高，管理员不配或配错，能力形同虚设

**建议方案：**

- 员工端"我的权限"作为信息聚合页，权限来源标注为最核心的解释字段
- 无权限提示页嵌入申请入口，从"发现问题"到"发起解决"一步直达
- 审批详情在标准审批信息基础上增加"申请人已有权限概览"模块
- 管理员首次开启时走配置向导（选角色 → 设审批 → 预览效果），降低认知门槛
- 关闭能力和批量终止操作必须有确认步骤和受影响数量展示

**不建议方案：**

- 不在工作台直接放一个孤立的"申请权限"按钮（缺少上下文时员工不知道能申请什么、该不该申请）
- 不把权限来源混在一起展示而不做区分（会导致排障不可持续）

**关键待确认：**

1. 无权限提示页当前是否存在？如果不存在，需要新增页面承载，影响入口方案
2. 审批人在移动端审批时是否需要查看申请人已有权限概览？影响移动端审批详情的信息结构

更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- 普通员工：发现缺权限（无权限提示页）→ 浏览可申请角色 → 选择角色并填写原因 → 提交申请 → 等待审批（可查看进度）→ 审批通过后权限生效 → 在"我的权限"中查看新权限
- 普通员工（主动查看场景）：进入"我的权限" → 查看已有权限及其来源 → 发现可申请角色 → 发起申请 → 同上后续流程
- 审批人：收到审批待办 → 查看申请人信息、申请内容、已有权限 → 判断是否合理 → 同意（自动授权）或拒绝（填写原因）
- 超级管理员：进入权限管理模式 → 开启自助申请 → 配置向导引导勾选可申请角色 → 配置审批流程 → 发布 → 查看统计数据

### 旅程缺口

- 无权限提示页的当前存在形态和承载页面未确认，影响员工端入口起点的设计依据
- 审批人在移动端的审批详情是否完整支持"已有权限概览"展示，影响移动端体验方案

## 2. 交互流程总览

**分角色交互流程：**

- 普通员工（申请路径）：遇到无权限页面 → 点击"申请权限" → 节点 3.1 浏览可申请角色列表 → 节点 3.2 选择角色并填写申请 → 提交确认 → 查看申请记录 → 收到审批结果通知 → 在"我的权限"中看到新权限
- 普通员工（查看路径）：进入"我的权限" → 查看已有权限列表（含来源标注）→ 查看可申请角色 → 节点 3.1 发起申请
- 审批人：收到待办通知 → 进入审批详情 → 节点 3.3 查看申请人信息与已有权限 → 同意或拒绝 → 确认操作
- 超级管理员：进入权限管理模式 → 开启自助申请开关 → 节点 4.1 配置向导（勾选可申请角色）→ 节点 4.2 配置审批流程 → 发布 → 节点 4.3 查看统计数据

**异常流程重点：**

- 提交申请时审批人不存在 → 阻止提交，引导联系管理员
- 审批通过后自动授权失败 → 管理员介入，告知员工处理中
- 审批进行中管理员关闭能力 → 批量终止所有审批中申请并通知
- 审批通过后应用不可见导致权限不可达 → 在权限详情中显式解释原因
- 可申请角色在审批中被删除 → 自动终止申请并通知

## 3. 主交互流程

### 节点 3.1：员工浏览可申请角色并选择

**用户动作：**

员工从无权限提示页或"我的权限"页进入可申请角色列表，浏览有哪些角色可以申请，选择一个目标角色。

**系统反馈：**

展示可申请角色列表，每项显示角色名称、角色简要说明。员工已有权限的角色标注"已拥有"且不可点击申请。员工已有审批中申请的角色标注"审批中"且不可重复提交。不在管理员开放范围内的角色不展示。

**需要前置解释的信息：**

- 这里展示的是管理员开放申请的角色，不是你一定能看到的所有角色
- 申请审批通过后，权限会自动生效，不需要再找管理员手动开通
- 如果找不到你需要的角色，请联系管理员确认是否已开放申请

**建议文案：**

- 页面标题："申请权限"
- 列表空态："当前没有可申请的角色。如果认为需要某个权限，请联系管理员。"
- 已有权限标注："已拥有——你已通过其他方式获得此权限"
- 审批中标注："审批中——你已有此角色的待审批申请"

**下一步：**

选择一个可申请的角色，进入节点 3.2 填写申请。

### 节点 3.2：员工填写并提交申请

**用户动作：**

在角色详情/申请页查看角色说明，填写申请原因，点击提交。

**系统反馈：**

提交前校验审批链路完整性。如果审批人不存在，阻止提交并给出明确提示。提交成功后，展示提交成功反馈，告知预计审批人和审批路径。同时发送通知给审批人。

**需要前置解释的信息：**

- 提交后需要等待审批人处理，审批通过后权限自动生效
- 审批期间你可以在"我的申请"中查看进度
- 如果需要加急处理，可以直接联系审批人

**建议文案：**

- 页面标题：显示所选角色名称
- 角色说明区：展示角色包含的主要权限范围
- 申请原因输入框占位："请简要说明为什么需要此权限，帮助审批人了解你的使用场景"
- 提交按钮："提交申请"
- 提交成功反馈："申请已提交。审批人：[审批人姓名]。你可以在"我的申请"中查看审批进度。"
- 审批人不存在阻断："当前审批流程尚未配置完整，无法提交申请。请联系管理员完成审批流程配置。"

**下一步：**

提交后跳转到申请记录列表，可查看刚刚提交的申请状态。

### 节点 3.3：审批人查看并处理权限申请

**用户动作：**

从待办列表进入审批详情页，查看申请人信息、申请角色、申请原因、申请人已有权限概览，判断该申请是否合理，选择同意或拒绝。

**系统反馈：**

审批详情展示完整申请信息和申请人已有权限概览。同意后，系统自动完成授权并通知申请人权限已生效。拒绝时弹出拒绝原因输入框（必填），提交后通知申请人。

**需要前置解释的信息：**

- 申请人已有权限列表帮助你判断是否需要额外授权
- 同意后权限会自动生效，无需手动配置
- 超时未处理不会自动通过（权限审批为安全敏感操作）

**建议文案：**

- 审批详情-申请人已有权限模块标题："申请人当前已有权限"
- 若无已有权限："该员工当前无任何权限"
- 同意按钮："同意授权"
- 拒绝按钮："拒绝"
- 拒绝原因输入框占位："请填写拒绝原因，申请人将看到此说明"
- 同意后反馈："已同意，权限已自动生效并通知申请人"
- 拒绝后反馈："已拒绝，申请人将收到通知和拒绝原因"

**下一步：**

审批完成后返回待办列表。如有下一节点审批人，系统自动流转。

## 4. 次交互流程

### 节点 4.1：管理员首次开启自助申请——配置可申请角色

**用户动作：** 在权限管理模式页开启自助申请开关后，进入配置向导第一步，从角色列表中勾选需要开放申请的角色。

**系统反馈：** 展示完整角色列表（含不可勾选的高敏感角色，标注"此角色不支持自助申请"）。默认排除：含高危批量操作的角色、涉及资金操作的角色、超管角色。勾选后实时显示已选数量。敏感角色旁有风险等级标注作为辅助判断。

**建议文案：** 向导标题："配置可申请角色——选择员工可以自助申请的角色范围"。高敏感角色标注："此角色因涉及敏感操作，不支持员工自助申请"。空选择态提示："至少需要选择一个角色，否则员工端将看不到任何可申请内容"。

**下一步：** 点击"下一步"进入审批流程配置。

### 节点 4.2：管理员配置审批流程

**用户动作：** 在向导第二步中设置审批流程，选择审批人类型或跳转至 OA 审批中台进行详细流程设计。

**系统反馈：** 默认展示推荐配置（审批人 = 组织架构负责人）。提供"使用推荐配置"快速完成和"自定义审批流程"跳转 OA 审批中台两个选项。选择自定义时，新标签页打开 OA 审批中台。

**建议文案：** 向导标题："配置审批流程——设置员工提交申请后的审批规则"。推荐配置说明："默认由申请人的组织架构负责人审批。如果员工没有组织负责人，审批将转给权限管理员。"。

**下一步：** 点击"下一步"进入预览确认。

### 节点 4.3：管理员预览并发布

**用户动作：** 在向导最后一步预览配置效果，确认无误后点击发布。

**系统反馈：** 展示配置摘要（已选角色数量、审批方式、预估影响范围）。发布成功后，自助申请能力正式生效，员工端入口出现。如果此时有双管理员模式开启，展示高风险警告："你同时开启了双管理员模式，员工的每一条权限申请都需要两位管理员审批通过才能生效，审批周期会变长。"

**建议文案：** 发布成功反馈："自助申请权限能力已开启。员工可以在工作台查看和申请权限。如需调整配置，可随时在此页面修改。"

**下一步：** 返回权限管理模式页，可查看运行状态和统计数据。

### 节点 4.4：管理员关闭自助申请能力

**用户动作：** 在权限管理模式页关闭自助申请开关。

**系统反馈：** 弹出确认弹窗，展示受影响数据（"当前有 N 条审批中的申请将被终止"）。确认后执行：已生效权限保留，所有 pending 申请终止并通知双方，draft 归档，员工端入口隐藏。关闭操作写入审计日志。

**建议文案：** 确认弹窗标题："确认关闭员工自助申请权限？"。弹窗正文："关闭后：已生效的权限不受影响；当前 N 条审批中的申请将被终止，申请人和审批人都会收到通知；员工端将不再显示申请入口。此操作不可撤销，但你可以随时重新开启。"

**下一步：** 关闭完成后，可在审计日志中查看操作记录。

### 节点 4.5：员工查看申请记录与撤销申请

**用户动作：** 进入"我的申请"列表，查看历史申请和当前状态。对 pending 状态的申请，可选择撤销。

**系统反馈：** 列表展示每条申请的角色、提交时间、当前状态、审批人。撤销操作需二次确认。撤销后状态标为 revoked，审批人收到撤回通知。

**建议文案：** 列表标题："我的申请"。撤销确认弹窗："确定撤销此申请？撤销后审批人将收到通知。如果之后仍需要此权限，可以重新提交申请。"

**下一步：** 撤销后可重新申请同一角色。

### 节点 4.6：员工在"我的权限"中查看权限详情

**用户动作：** 在"我的权限"页面点击某项权限，查看详细信息。

**系统反馈：** 展示权限详情：权限名称、来源（管理员授予 / 来自 XX 角色 / 自助申请 / 协作可见）、获取时间、数据权限范围。对于自助申请获得的权限，额外展示原申请记录链接。对于已生效但因应用不可见导致不可达的权限，显式展示原因说明。

**建议文案：** 权限来源-自助申请标注："通过自助申请审批获得（查看申请记录）"。应用不可见说明："你已获得此权限，但因对应应用当前对你不可见，暂时无法使用。如需使用，请联系管理员调整应用可见范围。"

**下一步：** 可从详情返回列表。

## 5. 异常与阻断流程

### 异常 A：提交申请时审批人不存在

**发生时机：** 员工点击"提交申请"时
**触发条件：** 审批链路中任一节点无有效审批人（组织负责人未设置、审批人已离职等）
**判断依据：** business_blueprint_lite 关键规则中的"审批人不存在处理"规则
**反馈形式：** 页面阻断提示
**系统反馈：** "当前审批流程尚未配置完整，无法提交申请。请联系管理员完成审批流程配置。"
**用户下一步：** 联系管理员。管理员需在 OA 审批中台补完审批人配置，或更换审批方式。

### 异常 B：审批通过后自动授权失败

**发生时机：** 审批人点击同意后，系统尝试自动授权时
**触发条件：** 目标角色已被删除、权限系统不可用、数据一致性问题等
**判断依据：** business_blueprint_lite 关键规则中的自动授权失败处理
**反馈形式：** 审批人侧弹窗提示异常；员工侧通知"授权处理中"
**系统反馈（审批人）：** "授权操作未能自动完成，已通知管理员处理。申请状态将保持为"已通过待生效"。"
**系统反馈（员工）：** "你的权限申请已通过审批，系统正在处理授权，请稍候。"
**用户下一步：** 管理员需在用户授权页手动完成授权，或将申请关联的角色重新配置后重试。

### 异常 C：审批进行中管理员关闭自助申请能力

**发生时机：** 管理员在权限管理模式页点击关闭时
**触发条件：** 存在 pending 状态的申请
**判断依据：** business_blueprint_lite 边界与风险中的"关闭能力时的批量终止操作"
**反馈形式：** 管理员侧弹窗确认，展示受影响数量。执行后通知所有受影响员工和审批人
**系统反馈（管理员确认弹窗）：** "当前有 N 条审批中的申请将被终止。关闭后已生效权限不受影响。"
**系统反馈（员工通知）：** "管理员已关闭自助申请权限能力，你提交的 [角色名称] 申请已被终止。如仍需要此权限，请联系管理员。"
**用户下一步：** 员工需等待能力重新开启后重新申请，或直接联系管理员。

### 异常 D：审批通过但应用不可见导致权限不可达

**发生时机：** 员工在"我的权限"中看到已生效权限，但实际无法使用对应应用
**触发条件：** 应用可见范围未覆盖该员工（对应 RISK-003）
**判断依据：** 决策链契约 L0 可见性门槛；business_blueprint_lite 风险项"覆盖规则导致反直觉结果"
**反馈形式：** 权限详情页显式说明
**系统反馈：** "你已获得 XX 角色的功能权限（通过自助申请审批获得），但该角色对应的应用当前对你不可见，暂时无法使用。如需使用，请联系管理员调整应用可见范围。"
**用户下一步：** 联系管理员调整应用可见范围。管理员可在应用管理中调整。

### 异常 E：可申请角色在审批中被删除

**发生时机：** 员工申请提交后、审批完成前
**触发条件：** 管理员在角色管理中删除了员工正在申请的角色
**判断依据：** facts 异常与边界表
**反馈形式：** 申请自动终止，通知申请人和审批人
**系统反馈（员工）：** "你申请的角色 [角色名称] 已被管理员移除，申请已自动终止。请查看其他可申请角色或联系管理员。"
**系统反馈（审批人）：** "[员工姓名] 申请的 [角色名称] 权限申请已因角色被删除而自动终止。"
**用户下一步：** 员工可选择其他角色申请或联系管理员。

### 异常 F：审批超时

**发生时机：** 审批人在配置的超时时间内未处理
**触发条件：** 超时时间到达
**判断依据：** OA 审批中台超时处理能力；business_blueprint_lite 明确"不自动通过"
**反馈形式：** 按 OA 审批中台已有超时规则（超时提醒 → 超时转派），不做超时自动通过
**系统反馈（审批人）：** "你有一条待审批的权限申请已超时，请尽快处理。"（按 OA 审批超时提醒规则）
**用户下一步：** 审批人仍可手动处理；员工可通过 OA 审批催办功能提醒审批人。

## 6. 页面 / 弹窗 / 抽屉设计

### 页面 6.1：员工端——我的权限

**页面目标：** 让员工集中查看自己当前拥有的所有权限，了解每项权限的来源，并发现可申请的角色。

**进入条件：** 管理员已开启自助申请能力；员工从工作台"我的权限"入口进入。

**页面结构：**

```
+-------------------------------------------------------+
| 顶部信息区：页面标题"我的权限"                           |
| 说明文字："以下是你的当前权限。如需更多权限，可查看      |
|           可申请角色并发起申请。"                       |
+-------------------------------------------------------+
| Tab 切换区：[已有权限] [可申请角色] [我的申请]           |
+-------------------------------------------------------+
| 已有权限列表（默认 Tab）：                              |
| - 每项权限显示：权限名称 | 来源标注 | 获取时间           |
| - 来源标注区分：管理员授予 / 来自 XX 角色 /              |
|   自助申请 / 协作可见                                  |
| - 权限可点击进入详情                                    |
| - 空态："你当前没有任何权限。如有疑问，请联系管理员。"    |
+-------------------------------------------------------+
| 可申请角色列表（切换 Tab）：                             |
| - 每项显示：角色名称 | 简要说明 | 状态                  |
| - 状态：可申请 / 已拥有 / 审批中                        |
| - 已拥有和审批中不可点击                                 |
| - 空态："当前没有可申请的角色。如果认为需要某个权限，     |
|         请联系管理员。"                                 |
+-------------------------------------------------------+
| 我的申请列表（切换 Tab）：                               |
| - 每项显示：角色名称 | 提交时间 | 状态 | 审批人          |
| - 状态：审批中 / 已通过 / 已拒绝 / 已撤销                |
| - pending 状态可点击进入详情并撤销                        |
| - 空态："你还没有提交过权限申请。"                       |
+-------------------------------------------------------+
```

**状态反馈区：** 列表即为状态反馈主体。操作反馈（撤销成功等）使用 toast。

**异常状态下的结构变化：**
- 管理员未开启能力时：页面不展示，入口隐藏
- 数据加载失败时：展示加载失败提示和重试按钮
- 权限数据为空时：展示空态引导

**具体文案：**
- 页面标题："我的权限"
- 已有权限 Tab："已有权限"
- 可申请角色 Tab："可申请角色"
- 我的申请 Tab："我的申请"
- Tab 区上方说明："以下是你的当前权限。如需更多权限，可查看可申请角色并发起申请。"

**按钮：**
- 可申请角色列表中的角色项：主操作按钮为"申请"（仅在"可申请"状态下显示）
- 我的申请列表中 pending 项：次操作按钮为"撤销申请"

**成功反馈：** 撤销申请后 toast："申请已撤销。审批人将收到通知。"

**失败反馈：** 操作失败时 toast："操作未能完成，请稍后重试。"

### 页面 6.2：员工端——申请角色（提交页）

**页面目标：** 让员工了解所选角色的权限范围，填写申请原因，提交申请。

**进入条件：** 员工在可申请角色列表中选择一个角色进入。

**页面结构：**

```
+-------------------------------------------------------+
| 顶部区：返回按钮 + 页面标题（所选角色名称）               |
+-------------------------------------------------------+
| 角色说明区：                                            |
| - 角色名称                                              |
| - 角色包含的主要权限范围说明                             |
| - 提示："审批通过后，此角色的权限将自动生效"              |
+-------------------------------------------------------+
| 申请表单区：                                            |
| - 申请原因（必填，多行文本）：                           |
|   "请简要说明为什么需要此权限，帮助审批人了解你的         |
|    使用场景"                                            |
| - [可选] 附件上传（如管理员已配置）                      |
+-------------------------------------------------------+
| 提交按钮："提交申请"                                    |
+-------------------------------------------------------+
```

**状态反馈区：** 表单内校验提示。提交后跳转到申请记录列表并 toast 提示。

**异常状态下的结构变化：**
- 审批链路不完整时：提交按钮替换为阻断提示，不可点击
- 角色已被删除时：展示"该角色已不可用"并禁用提交

**具体文案：**
- 角色权限范围说明区标题："此角色包含以下权限"
- 申请原因占位文字："请简要说明为什么需要此权限，帮助审批人了解你的使用场景"
- 提交按钮："提交申请"

**按钮：**
- 主按钮："提交申请"
- 次按钮：返回（左上角）

**成功反馈：** toast："申请已提交。审批人：[审批人姓名]。你可以在"我的申请"中查看审批进度。"

**失败反馈：** 阻断提示（审批人不完整时）："当前审批流程尚未配置完整，无法提交申请。请联系管理员完成审批流程配置。"

### 页面 6.3：审批人端——权限申请审批详情

**页面目标：** 让审批人全面了解申请内容，做出有依据的审批决定。

**进入条件：** 审批人从待办列表进入。复用 OA 审批中台的审批详情页框架。

**页面结构：**

```
+-------------------------------------------------------+
| 申请人信息区：                                          |
| - 申请人姓名、部门、职务                                |
+-------------------------------------------------------+
| 申请内容区：                                            |
| - 申请角色名称                                          |
| - 角色包含的主要权限说明                                |
| - 申请原因                                              |
| - 申请时间                                              |
| - [可选] 附件预览                                       |
+-------------------------------------------------------+
| 申请人已有权限概览区（本次新增模块）：                    |
| - 标题："申请人当前已有权限"                             |
| - 权限列表（简要，可展开）                               |
| - 空态："该员工当前无任何权限"                           |
+-------------------------------------------------------+
| 审批操作区：                                            |
| - [同意授权] [拒绝]                                     |
| - 拒绝时弹出拒绝原因输入（必填）                         |
+-------------------------------------------------------+
```

**状态反馈区：** 审批操作后展示结果反馈。

**异常状态下的结构变化：**
- 申请已被撤销或终止时：展示"此申请已失效"并禁用审批操作
- 角色已被删除时：展示"所申请的角色已被删除"并禁用审批操作

**具体文案：**
- 已有权限模块标题："申请人当前已有权限"
- 已有权限空态："该员工当前无任何权限"
- 同意按钮："同意授权"
- 拒绝按钮："拒绝"
- 拒绝原因占位："请填写拒绝原因，申请人将看到此说明"

**按钮：**
- 主按钮："同意授权"
- 次按钮："拒绝"（危险操作样式）

**成功反馈：** 同意后："已同意，权限已自动生效并通知申请人。"；拒绝后："已拒绝，申请人将收到通知和拒绝原因。"

**失败反馈：** 自动授权失败时："授权操作未能自动完成，已通知管理员处理。"

### 页面 6.4：管理员端——自助申请配置页

**页面目标：** 让管理员在权限管理模式下完成自助申请能力的开启、配置和关闭。

**进入条件：** 超管或权限管理员从权限管理模式页进入。

**页面结构：**

```
+-------------------------------------------------------+
| 顶部区：页面标题"员工自助申请权限"                       |
| 总开关："启用员工自助申请权限" [开关]                    |
+-------------------------------------------------------+
| 配置区（能力开启后展示）：                                |

| - 审批流程：[查看/修改] → 打开审批配置或跳转 OA 审批中台  |

+-------------------------------------------------------+
| 运行状态区（能力开启后展示）：                            |
| - 累计申请数 / 审批通过率 / 平均审批耗时                 |
| - 高频申请角色排行                                       |
```

**状态反馈区：** 开关状态和统计数据即为实时反馈。配置变更后 toast 提示已保存。

**异常状态下的结构变化：**
- 双管理员模式同时开启时：在页面顶部展示高风险警告横幅
- 审批中台不可用时：审批流程配置入口展示"暂不可用"状态

**具体文案：**
- 页面标题："员工自助申请权限"
- 总开关标签："启用员工自助申请权限"

**按钮：**
- 主按钮：总开关
- 配置区操作：查看/修改（链接或按钮）

**成功反馈：** 配置保存 toast："配置已保存"。能力开启 toast："员工自助申请权限能力已开启"。能力关闭 toast："能力已关闭，N 条审批中的申请已终止。"

**失败反馈：** 操作失败时 toast，引导重试或联系技术支持。

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 草稿 | 员工已创建申请但未提交 | 员工 | 编辑、提交、删除 | "草稿——你还未提交此申请" |
| 审批中 | 申请已提交，等待审批人处理 | 员工、审批人 | 员工：查看进度、撤销；审批人：同意、拒绝 | 员工侧："审批中——[审批人姓名]正在处理"；审批人侧："待处理——[员工姓名]申请[角色名称]" |
| 已通过 | 审批人已同意，权限尚未生效 | 员工、审批人 | 查看详情 | "已通过——系统正在处理授权" |
| 已生效 | 权限已自动授予完成 | 员工 | 查看权限、使用权限 | "已生效——权限已可用" |
| 已拒绝 | 审批人拒绝了申请 | 员工、审批人 | 员工：查看拒绝原因、重新申请 | "已拒绝——查看拒绝原因" |
| 已撤销 | 员工主动撤销或管理员关闭能力终止 | 员工、审批人 | 查看详情 | "已撤销——[撤销原因]" |
| 异常 | 自动授权失败等异常情况 | 员工、管理员 | 员工：联系管理员；管理员：手动处理 | 员工侧："处理中——系统正在处理你的授权，请稍候"

## 8. 待确认问题

1. **无权限提示页的当前存在形态**

   影响：员工端"发现缺权限→发起申请"的自然触达路径依赖此页面的存在和结构。如果不存在，需要新增页面；如果存在但结构不兼容，需要改造。
   建议确认方：产品 / 设计

2. **审批人移动端已有权限概览展示**

   影响：审批人在移动端审批时能否看到"申请人已有权限概览"模块，影响审批详情的信息架构和移动端适配策略。如果移动端空间不足，可能需要折叠或分层展示。
   建议确认方：设计 / 技术

3. **敏感角色的判定标准**

   影响：管理员首次开启自助申请时，哪些角色默认排除在可申请范围外。如果产品侧不定义标准，管理员需要自行判断，配置门槛上升。
   建议确认方：产品 / 业务

4. **申请时附件上传是否纳入首期**

   影响：申请表单的字段数量和信息结构。OA 审批中台已支持附件控件，首期建议做管理员可配置项（默认关闭），但需确认技术实现和测试范围。
   建议确认方：产品 / 技术

5. **审批人已查看但未处理时是否允许员工撤销**

   影响：员工端"我的申请"列表中 pending 状态申请的撤销按钮可用条件。如果允许任意撤销，审批人体验受影响；如果完全不允许，员工灵活性受限。
   建议确认方：产品

6. **自助申请与双管理员模式叠加时的前端警告强度**

   影响：管理员配置页的高风险警告是横幅提示还是弹窗阻断。如果仅是横幅，管理员可能忽略；如果是弹窗，可能过于强势。
   建议确认方：产品 / 设计
