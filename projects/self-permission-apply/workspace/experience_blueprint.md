# 体验蓝图：员工自助申请权限

## 0. 本次关键设计判断

本次体验设计的核心挑战不是"把申请入口做好看"，而是在三个认知水平截然不同的角色（员工、审批人、管理员）之间建立一套一致且可解释的权限请求体验。关键设计判断如下：

1. **员工侧必须做权限概念翻译**。员工不理解"直授""来源""治理修饰因子"等内部模型。展示给员工的权限信息必须以业务语言组织（如"人事管理权限：可查看和编辑员工信息"），而不是罗列功能权限点。
2. **可解释性是体验的核心质量指标**。员工最常遇到的体验崩塌不是"提交不了申请"，而是"申请通过了但还是看不到某些功能"。必须在权限展示和申请记录中提供跨来源的叠加解释。
3. **审批人的认知负担要尽量降低**。审批人可能不是权限专家，只是被指定审批某类申请的业务负责人。审批界面必须说清"申请了什么、申请后会给申请人带来什么影响"，而不是只展示权限名称列表。
4. **关闭态的体验必须预埋**。能力关闭不只是"隐藏入口"，还需要妥善处理进行中的申请、已生效的权限和员工端的查看入口。

**关键待确认：** 审批超时的处理策略（自动退回还是转交）会影响员工和审批人两端的等待体验，建议在体验方案定案前确认。更多待确认问题详见 ## 8. 待确认问题。

## 1. 旅程图

- **管理员：** 开启能力 → 配置权限模板 → 配置审批流 → 日常调整模板 → 关闭能力
- **员工（首次使用）：** 查看当前权限 → 发现缺少权限 → 浏览可申请列表 → 选择模板 → 填写申请原因 → 提交 → 等待审批 → 查看申请记录
- **员工（收到通过结果）：** 查看申请记录 → 看到审批通过 → 验证权限已生效
- **员工（收到拒绝结果）：** 查看申请记录 → 看到审批拒绝 → 查看拒绝原因 → 可选修改后重新申请
- **审批人：** 收到审批待办 → 查看申请详情 → 判断是否合理 → 通过（自动授权）或 拒绝（填写原因）

## 2. 交互流程总览

**分角色交互流程：**

- **管理员：** 进入管理后台权限管理模块 → 找到"自助申请"设置 → 开启开关 → 创建权限模板（命名+选择功能权限+可选数据范围） → 关联审批流程 → 保存生效 → 员工端可见可申请
- **员工：** 进入个人中心或权限管理入口 → 查看"我的权限" → 切换到"申请权限" → 浏览权限模板列表 → 点击申请 → 阅读模板说明并勾选 → 填写申请原因 → 提交 → 跳转至"我的申请"记录页
- **审批人：** 在审批待办中看到新任务 → 点击查看详情 → 查看申请人、申请模板、原因说明 → 点击通过（系统自动授权，申请状态更新为已通过） → 或点击拒绝（填写拒绝原因，申请状态更新为已拒绝）
- **系统：** 审批通过时，自动调用权限写入接口，为申请人添加功能/数据权限，写入操作日志，通知申请人

**异常流程重点：**
- 审批超时：系统在超时后按预设策略处理（待定），员工端可看到"审批超时"状态并可催办
- 申请部分通过：审批人逐项审批，支持仅通过部分模板
- 自动授权失败：系统记录错误并告警，审批人或管理员可重新触发授权
- 能力关闭时：员工端申请入口隐藏，但"我的申请记录"可查看

## 3. 主交互流程

### 流程一：管理员开启并配置自助申请

**管理员进入设置入口**
- 用户动作：在权限管理模块中点击"自助申请设置"或类似入口
- 系统反馈：展示自助申请能力的总开关和配置区
- 建议文案："开启后，员工可以在权限管理模块中查看自己当前的权限，并申请预设范围内的权限。"
- 下一步：开启配置

**配置权限模板**
- 用户动作：点击"创建权限模板"，输入模板名称（如"人事管理权限包"），选择要包含的功能权限点（或选择已有角色映射），可选设置数据范围
- 系统反馈：展示已创建的模板列表，支持编辑和删除
- 需要前置解释的信息：模板说明应提示管理员"员工将看到模板名称和说明，不会看到具体的功能权限点列"

**关联审批流程**
- 用户动作：选择审批流程（新建审批流或选择已有审批流），设置是否遵循现有治理规则
- 系统反馈：展示审批流概览

**开启能力**
- 用户动作：打开"允许员工自助申请"开关
- 系统反馈：确认提示，保存配置，员工端入口生效
- 下一步：管理员可继续调整模板或查看申请记录

### 流程二：员工申请权限

**查看当前权限**
- 用户动作：在个人中心或权限管理入口点击"我的权限"
- 系统反馈：展示聚合后的权限列表，按业务域分组（如"人事管理""财务管理"），每个分组下展示能力摘要
- 建议文案摘要式展示："你拥有以下权限：人事管理权限（查看、编辑员工信息），财务管理权限（查看报销单）"
- 下一步：如果发现缺少权限，点击"申请权限"

**申请权限**
- 用户动作：在"可申请权限"列表中浏览权限模板，点击目标模板后的"申请"
- 系统反馈：展示申请表单，包含权限模板名称、模板说明（展开可查看详细包含的权限点）、申请原因输入框
- 建议文案：模板说明为"申请后将获得：员工管理-查看、员工管理-编辑、组织架构-查看"
- 用户动作：填写申请原因（如"我需要查看和编辑员工信息来完成薪酬核算工作"），点击提交
- 系统反馈：提交成功后跳转至"我的申请"记录页，显示新申请为"审批中"状态
- 需要前置解释的信息：提交前提示"审批通过后系统自动为你授权，请耐心等待"

**查看申请记录**
- 用户动作：在"我的申请"页面查看申请列表
- 系统反馈：展示提交时间、权限模板名称、当前状态（审批中/已通过/已拒绝）、审批人（如有）
- 下一步：点击单条申请查看详情

### 流程三：审批人处理申请

**接收待办**
- 用户动作：审批人在审批待办列表中看到新的权限申请任务
- 系统反馈：待办列表中展示申请摘要（申请人、申请内容、申请时间）

**查看申请详情**
- 用户动作：点击进入审批详情页
- 系统反馈：展示申请人信息、申请权限模板名称及详细说明（包含哪些功能权限）、申请原因、申请时间
- 建议文案：审批说明中展示"申请通过后，申请人将获得以下权限：员工管理-查看、员工管理-编辑"

**审批决策**
- 通过：用户点击"通过"，系统弹出确认
- 系统反馈：确认后系统自动调用权限写入接口，成功后申请状态更新为"已通过"，通知申请人
- 拒绝：用户点击"拒绝"，系统弹出拒绝原因输入框，提示"请填写拒绝原因，以便员工了解为什么不通过"
- 系统反馈：拒绝后申请状态更新为"已拒绝"，通知申请人并附带拒绝原因

## 4. 次交互流程

### 流程四：管理员关闭能力

**关闭入口**
- 用户动作：在自助申请设置页关闭"允许员工自助申请"开关
- 系统反馈：弹窗确认，提示"关闭后员工端将不再显示申请入口，已提交的进行中申请将正常处理完成。"
- 用户动作：确认关闭
- 系统反馈：能力关闭，员工端入口隐藏
- 下一步：如果需要强制中止进行中申请，管理员可手动点击"中止进行中申请"并确认

### 流程五：员工验证已生效的权限

- 用户动作：在"我的申请"中看到"已通过"状态后，点击"查看我的权限"
- 系统反馈：展示当前聚合后的完整权限列表，新增的权限应清晰标注
- 建议文案：权限列表中新获得的权限应带有"新"标记或在列表中有明确变更说明
- 下一步：如果发现仍有功能不可用，可查看不可用的原因解释

## 5. 异常与阻断流程

### 异常一：审批超时

- 触发条件：审批人在设定时间（如 72 小时）内未处理申请
- 系统反馈：待定，取决于超时策略（自动退回后通知员工"申请因超时已退回"；或转交上级审批人）
- 员工可见反馈：员工在"我的申请"中看到"审批超时"状态标记，可点击"催办"按钮通知审批人
- 用户补救路径：员工可重新提交申请，或联系管理员更换审批人

### 异常二：审批拒绝

- 触发条件：审批人点击拒绝并填写原因
- 系统反馈：申请状态更新为"已拒绝"，通知员工
- 员工可见反馈：在"我的申请"详情中看到拒绝原因
- 用户补救路径：员工可根据拒绝原因调整后重新申请，或联系管理员说明情况

### 异常三：申请部分通过

- 触发条件：申请包含多个权限模板，审批人只通过部分
- 系统反馈：通过的模板自动授权，拒绝的模板标记为已拒绝
- 员工可见反馈：在"我的申请"详情中分项展示"已通过/已拒绝"
- 用户补救路径：员工可重新申请被拒绝的模板，或联系审批人

### 异常四：自动授权失败

- 触发条件：审批人点击通过后，系统调用权限写入接口返回错误
- 系统反馈：申请状态置为"授权失败"，记录错误日志，通知管理员
- 员工可见反馈：员工看到"授权失败，请联系管理员"
- 用户补救路径：管理员可在后台手动重新触发授权，或联系工程排查

### 异常五：员工重复申请

- 触发条件：员工申请的权限模板内容与其已拥有的权限完全重叠
- 系统反馈：提交前校验并提示"你已拥有该权限模板中的全部权限"
- 用户补救路径：无需补救，员工可直接查看已有权限

### 异常六：能力关闭时管理员强制中止

- 触发条件：管理员在关闭能力时选择强制中止进行中申请
- 系统反馈：系统批量拒绝所有进行中申请，记录操作日志
- 员工可见反馈：员工在"我的申请"中看到已关闭，并显示"该申请已被管理员关闭"
- 用户补救路径：联系管理员了解原因

## 6. 页面 / 弹窗 / 抽屉设计

### 6.1 员工：我的权限页

**页面结构：**
```
┌────────────────────────────────────┐
│  我的权限                   申请权限 │  ← 导航区 + 操作入口
├────────────────────────────────────┤
│  ┌──────────────────────────────┐  │
│  │ 人事管理权限（已生效）         │  │  ← 权限卡片区（按业务域分组）
│  │ 可查看员工信息、编辑员工信息   │  │
│  │ 来源：管理员分配         2026-01 │  │
│  └──────────────────────────────┘  │
│  ┌──────────────────────────────┐  │
│  │ 财务管理权限（已生效）         │  │
│  │ 可查看报销单、提交报销申请    │  │
│  │ 来源：自助申请         2026-06 │  │  ← 区分来源说明
│  └──────────────────────────────┘  │
│  ┌──────────────────────────────┐  │
│  │ 考勤管理权限（申请中）         │  │  ← 申请中的权限占位
│  │ 申请于 2026-06-14 提交       │  │
│  └──────────────────────────────┘  │
├────────────────────────────────────┤
│  无法使用某功能？查看权限说明      │  ← 可解释性入口
└────────────────────────────────────┘
```

- **信息区：** 权限卡片按业务域分组，每张卡片展示权限名称、能力摘要、来源说明和生效时间
- **状态区：** 申请中的权限以占位卡片展示，引导员工查看申请记录
- **操作区：** "申请权限"入口、"无法使用某功能？查看权限说明"入口
- **异常状态：** 空权限状态展示"你当前还没有权限，点击申请权限开始"

- **信息区：** 申请人信息、申请内容、申请原因、审批后效果说明
- **操作区：** 通过和拒绝按钮
- **异常状态：** 审批通过后但自动授权失败时，审批人可重新触发授权

## 7. 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
| --- | --- | --- | --- | --- |
| 审批中 | 申请已提交，等待审批人处理 | 员工 | 查看详情、催办 | "你的申请已提交，正在等待审批人处理" |
| 审批通过 | 审批人已同意，权限正在配置 | 员工 | 查看权限 | "审批已通过，权限正在为你配置" |
| 已生效 | 权限已成功授予 | 员工 | 查看权限、查看变更记录 | "权限已生效，你现在可以使用了" |
| 已拒绝 | 审批人不同意该申请 | 员工 | 查看原因、重新申请 | "申请未通过，原因：（审批人填写的原因）" |
| 授权失败 | 审批通过但系统自动授权出错 | 员工、管理员 | 员工联系管理员，管理员重新授权 | "系统授权失败，请联系管理员处理" |
| 审批超时 | 审批人未在规定时间内处理 | 员工 | 催办 | "审批已超时，你可以催办审批人" |
| 已关闭 | 管理员关闭了该申请或能力已关闭 | 员工 | 查看详情 | "该申请已被管理员关闭"（或"该功能已关闭"） |
| 待处理 | 审批人收到新的审批任务 | 审批人 | 查看详情、审批 | "（申请人）申请了（权限模板），请尽快处理" |

## 8. 待确认问题

### 审批超时阈值与处理策略
- **影响：** 直接影响员工等待时长和审批人的处理压力。如果超时后自动退回，员工需重新提交；如果自动转交，需定义转交规则
- **建议确认方：** 产品策略

### 催办功能的行为定义
- **影响：** 催办是通知审批人还是升级到管理员？催办频率是否限制？
- **建议确认方：** 产品

### 权限模板创建时的体验细节
- **影响：** 管理员创建模板时，是以勾选功能权限点的方式还是以引用角色的方式？两种方式影响管理员的操作复杂度
- **建议确认方：** 产品 / 设计

### 关闭能力时"强制中止"交互
- **影响：** 强制中止后是否需要单独通知每个申请人？是否有操作记录？
- **建议确认方：** 产品 / 法务合规

### 员工"无法使用某功能"的解释入口
- **影响：** 是全局入口还是针对具体功能的上下文入口？点击后展示什么信息？
- **建议确认方：** 设计

## 附录：设计指南消费说明

### 已使用的设计原则

设计准则中的治理原则对本方案的影响：
- 系统行为必须可解释：权限模板说明申请前展开、审批后效果在审批页展示、已生效权限标注来源——每条操作都提供了"为什么"的解释
- 默认授权范围应收敛：可申请范围由管理员预配置，模板创建时默认最小权限，扩大需管理员确认
- 关键变更可追溯：所有权限申请和授权记录保留操作日志

### 已消费的业务知识

权限管理领域的业务知识用于确认以下方案判断：
- 权限落点采用已有的个人直授通道，不创建新来源类型
- 权限决策链（可见性→功能→数据→治理）保持不变
- 员工侧需要标注权限来源并做概念翻译，避免认知混淆
