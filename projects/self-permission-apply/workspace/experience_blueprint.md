# 体验蓝图

> 本文基于 [facts.md](./facts.md) 和 [business_blueprint.md](./business_blueprint.md) 的业务判断，转译为角色路径、交互流程、页面承接、状态反馈和异常处理方案。
> 正文已将所有业务术语转译为体验语言，不暴露内部执行术语。

## 0. 本次关键设计判断

**判断：**

本次体验方案的重点不是多做页面，而是把三个角色的差异化路径、状态变化时的反馈、以及异常阻断后的补救路径讲清楚。

**主要影响：**

1. 管理员的配置体验直接影响安全——配置错误（范围过宽、忘排除敏感角色）会导致越权，所以配置页需要引导和校验，不能只是"几个开关"
2. 员工从"被动等管理员给权限"变为"主动申请"，这是一个心智转变，需要清晰的路径引导和状态说明
3. 审批人的决策信息要充分——只看到"谁申请了什么角色"不够，还需要看到这个人当前已有权限，帮他判断"该不该给"

**建议方案：**

- 管理员配置页做成"向导式"——先检查互斥、再设范围、再设排除、再配审批，分步引导
- 员工端入口放工作台，定位为"我的权限"，同时承载查看和申请两个核心任务
- 审批详情页整合申请人已有权限信息和申请角色详情，降低审批人的判断成本

**不建议方案：**

- 不建议把员工申请入口藏在管理后台深处——这会让员工找不到入口，重新走线下找管理员的老路
- 不建议在审批详情页只展示申请内容不展示申请人已有权限——缺少参照信息，审批人无法判断"这个人缺不缺这个角色"

**关键待确认：**

1. 员工端入口是放工作台还是全局导航，影响员工的发现路径和日常使用频率
2. 审批详情页是否需要展示申请人所在部门和岗位，影响审批人判断的信息充分度

> 更多待确认问题详见 `## 8. 待确认问题`。

## 1. 旅程图

- 管理员：识别权限分配压力 → 进入权限管理模式配置 → 检查是否与其他模式冲突 → 设置可申请角色范围 → 排除敏感角色 → 配置审批人来源和超时策略 → 确认开启 → 后续查看申请统计 → 必要时关闭并处理审批中申请
- 员工：进入"我的权限" → 查看当前已有权限及来源 → 发现缺少某角色 → 发起权限申请 → 选择可申请的角色 → 填写申请原因 → 提交后等待审批 → 查看申请状态 → 收到审批结果 → 审批通过后确认权限已生效
- 审批人：收到待办通知 → 打开审批详情 → 查看申请人的基本信息和已有权限 → 查看申请角色包含的具体能力 → 判断是否同意 → 同意则系统自动授权 → 拒绝则填写原因 → 提交审批结果

### 旅程缺口

- 审批通过后员工如何收到通知（站内消息 / 审批通知 / 短信），当前未明确
- 员工被拒绝后是否可以从申请记录页直接重新发起申请，还是需要回到申请入口重新操作
- 管理员关闭能力后，员工的申请记录入口是否仍存在、是否可见、页面如何展示

## 2. 交互流程总览

**分角色交互流程：**

- 管理员：检查治理模式冲突（节点 3.1）→ 配置可申请范围和敏感排除（节点 3.2）→ 配置审批规则（节点 3.3）→ 确认并开启 → 查看申请统计 → 关闭时确认收尾方式（节点 4.1）
- 员工：进入"我的权限"查看已有权限（节点 3.4）→ 发起权限申请（节点 3.5）→ 查看申请记录和状态（节点 4.2）→ 审批通过后确认权限已生效 → 或在待审批状态下撤销申请（节点 4.3）
- 审批人：在审批待办中查看申请详情（节点 3.6）→ 判断并做出审批决定（节点 3.7）→ 结果通知申请人

**异常流程重点：**

- 管理员开启时检测到治理模式互斥 → 阻断并提示解决方案
- 审批人不存在 → 向上查找，最终找不到时进入"待分配审批人"状态并通知超管
- 员工尝试申请被排除的敏感角色 → 该角色在列表中不可见
- 管理员关闭时存在审批中的申请 → 强制要求选择收尾方式
- 审批超时无人处理 → 按超时策略处理（提醒后转派超管）

## 3. 主交互流程

### 节点 3.1：管理员检查治理模式冲突

**用户动作：**

管理员在"权限管理模式"配置页中，看到当前已开启的模式（如"权限变更审批模式"），然后选择"员工自助申请"模式。

**系统反馈：**

如果当前已开启"权限变更审批模式"，系统直接阻断，弹出提示告知两个模式不能同时开启。弹窗中说明为什么互斥（两者都涉及"权限变更需要审批"，同时开启会导致审批链路混乱），并引导管理员先关闭当前模式再开启新模式。

如果当前开启了"双管理员模式"，系统不阻断但给出提醒：自助申请的审批链路将与双管理员互审各自独立运行，请确认审批规则配置。

如果当前没有任何互斥模式，直接进入配置步骤。

**需要前置解释的信息：**

- 为什么自助申请和权限变更审批不能同时开启
- 关闭当前模式的影响范围（如有审批中的数据如何处理）

**建议文案：**

- 提示标题：不能同时开启"权限变更审批"和"员工自助申请"
- 提示正文：这两个模式都涉及"权限变更需要审批"，同时开启会让管理员和审批人难以区分审批类型和管理标准。如需开启员工自助申请，请先关闭权限变更审批模式。
- 按钮：去关闭权限变更审批 / 取消

**下一步：**

关闭冲突模式后，进入配置可申请范围（节点 3.2）。

### 节点 3.2：管理员配置可申请范围和敏感排除

**用户动作：**

管理员在配置页中看到系统已有的角色列表，勾选允许员工申请的角色。同时在敏感排除区看到系统建议排除的角色（超管角色、含权限管理配置能力的角色），可以选择接受建议或调整。

**系统反馈：**

角色列表展示每个角色的名称和简要说明。已被标记为敏感排除的角色默认不勾选并带有警告标记。

如果管理员将系统建议排除的高危角色加入可申请范围，系统给出二次确认提醒："该角色包含核心管理权限，开放申请可能带来安全风险，确认开放？"

如果管理员没有选择任何角色就尝试进入下一步，系统阻断并提示"请至少选择一个可申请的角色"。

**需要前置解释的信息：**

- 什么是敏感角色，为什么需要排除
- 每个可选角色的简要说明（包含哪些主要能力）

**建议文案：**

- 区域标题：选择可申请的角色
- 敏感排除区标题：不可申请的角色（系统建议）
- 敏感排除说明：以下角色包含核心管理权限，建议不开放员工自助申请。您可以根据企业实际情况调整。
- 高危角色确认弹窗：该角色包含权限管理配置能力，开放申请后员工可能通过审批获得管理权限。确认将此角色加入可申请范围吗？
- 按钮：确认开放 / 取消

**下一步：**

配置审批人来源和超时策略（节点 3.3）。

### 节点 3.3：管理员配置审批规则

**用户动作：**

管理员选择审批人来源类型（直属负责人 / 指定角色成员 / 指定成员组等），设置超时时长和处理方式。

**系统反馈：**

审批人来源展示为下拉选择或单选组。选择"直属负责人"时，系统自动展示审批链路预览：员工 → 直属上级 → 上级的上级（降级链路）。选择其他来源时展示对应的审批人预览。

超时策略展示超时时长输入和四选一处理方式（提醒 / 转派 / 通过 / 拒绝）。设置完成后，下方展示审批流程的简要预览图，帮助管理员确认配置无误。

**需要前置解释的信息：**

- 每种审批人来源的含义和适用场景
- 审批人不存在时系统会怎么处理（向上查找降级链路）
- 超时时长建议值（如 3 个工作日）

**建议文案：**

- 审批人来源标签：审批人
- 默认选项说明：直属负责人（推荐）—— 申请人的直属上级作为审批人，上级不存在时自动向上查找
- 超时策略标签：审批超时处理
- 超时说明：审批人在设置时长内未处理，系统将自动提醒。超过最长等待时间后，将自动转派给超级管理员处理。
- 预览标题：审批流程预览

**下一步：**

确认配置并开启自助申请。

### 节点 3.4：员工查看自己的权限

**用户动作：**

员工从工作台点击"我的权限"入口，进入权限查看页面。

**系统反馈：**

页面展示员工当前拥有的所有权限列表。每条权限展示：权限名称（角色名或功能权限名）、来源说明（如"通过角色「销售专员」获得"或"由管理员直接授予"或"通过自助申请获得"）、生效时间。

如果当前没有任何权限，展示空状态：说明简洁的解释和引导，引导按钮指向"申请权限"入口。

**需要前置解释的信息：**

- 权限来源的含义（角色分配 vs 直授 vs 自助申请）
- 为什么要展示权限来源

**建议文案：**

- 页面标题：我的权限
- 页面说明：以下是你当前拥有的所有权限。如果发现缺少某个权限，可以发起[权限申请]。
- 空状态标题：暂无权限
- 空状态说明：你当前没有任何功能权限。如果你需要访问某些功能，可以申请权限，或联系管理员。
- 空状态按钮：申请权限
- 来源说明示例：通过角色「销售专员」获得 · 2025-03-01 生效 / 通过自助申请获得 · 2025-06-15 生效 / 由管理员直接授予 · 2025-01-10 生效

**下一步：**

点击"申请权限"进入申请流程（节点 3.5），或点击某条权限查看详情。

### 节点 3.5：员工发起权限申请

**用户动作：**

员工在"我的权限"页面点击"申请权限"，进入申请表单。表单中展示可申请的角色列表（已自动过滤不可申请的敏感角色），员工选择一个角色，填写申请原因，提交申请。

**系统反馈：**

角色列表展示每个角色的名称和简要说明（包含哪些主要能力）。员工选中角色后，下方展开申请原因输入框。

提交按钮点击后，系统校验申请原因不为空。提交成功则显示成功反馈，申请单进入"待审批"状态。同时系统通知对应审批人。

提交失败时（如网络异常或系统错误），显示失败提示并保留已填写的内容。

**需要前置解释的信息：**

- 每个可选角色包含哪些能力
- 申请提交后需要审批才能生效
- 审批期间可以撤销申请

**建议文案：**

- 页面标题：申请权限
- 表单说明：选择你需要申请的角色并说明原因，提交后将由审批人处理。审批通过后权限会自动生效。
- 角色选择区标签：选择角色
- 申请原因标签：申请原因
- 申请原因占位文字：请说明为什么需要这个权限，例如工作需要访问某个功能模块
- 提交按钮：提交申请
- 成功反馈：申请已提交，请等待审批人处理。你可以在"申请记录"中查看进度。
- 失败反馈：提交失败，请稍后重试。如多次失败，请联系管理员。

**下一步：**

提交后跳转到申请记录页（节点 4.2）查看申请状态。

### 节点 3.6：审批人查看申请详情

**用户动作：**

审批人在审批待办列表中点击某条权限申请，进入审批详情页。

**系统反馈：**

审批详情页分为三个信息区：申请人信息区（姓名、部门、岗位）、申请内容区（申请的角色名称、角色包含的具体权限列表）、申请人已有权限区（申请人当前已拥有的所有权限列表，帮助审批人判断是否需要这个角色）。

如果申请人已有的权限中已经包含了申请角色的部分或全部能力，系统在已有权限区用视觉区分标记出来，提示审批人"此人已有部分该角色的能力"。

**需要前置解释的信息：**

- 申请人已有的权限可能来自多种来源（角色分配、管理员直授、其他自助申请）
- 如果不同意申请，需要填写拒绝原因

**建议文案：**

- 页面标题：权限申请审批
- 申请人信息标签：申请人、部门、岗位、申请时间
- 申请内容区标题：申请内容
- 角色能力说明：该角色包含以下权限
- 已有权限区标题：申请人当前已有权限
- 已有权限提示：申请人已拥有该角色的部分权限（如有重叠）

**下一步：**

做出审批决定——同意或拒绝（节点 3.7）。

### 节点 3.7：审批人做出审批决定

**用户动作：**

审批人查看完申请详情后，选择"同意"或"拒绝"，填写审批意见，提交审批结果。

**系统反馈：**

同意：系统自动调用授权接口，将角色授予申请人。授权成功后申请单状态变为"已生效"，通知申请人"你的权限申请已通过，权限已生效"。

拒绝：申请单状态变为"已拒绝"，通知申请人"你的权限申请未通过"，附带审批人填写的拒绝原因。

如果自动授权失败（如系统异常），显示"授权失败"提示，申请单不改变状态，审批人可重试。

**需要前置解释的信息：**

- 同意后系统会自动授权，不需要手动操作
- 拒绝时需要填写原因，帮助申请人理解

**建议文案：**

- 同意按钮：同意申请
- 拒绝按钮：拒绝申请
- 审批意见标签：审批意见（选填）
- 拒绝原因标签：拒绝原因（必填）
- 拒绝原因占位文字：请说明拒绝原因，申请人可以看到
- 同意后成功反馈：已同意，权限已自动授予申请人
- 同意后通知申请人：你的"销售专员"角色权限申请已通过审批，权限已生效。
- 拒绝后通知申请人：你的"销售专员"角色权限申请未通过审批。拒绝原因：[审批人填写的拒绝原因]。你可以重新提交申请。

**下一步：**

审批完成后返回审批待办列表。

## 4. 次交互流程

### 节点 4.1：管理员关闭自助申请并处理审批中申请

**用户动作：**

管理员在配置页中点击"关闭自助申请"。如果当前存在审批中的申请，系统弹出确认窗口，展示审批中申请的清单和处理选项。

**系统反馈：**

确认窗口展示：当前审批中的申请数量、每条申请的摘要（申请人、申请角色、提交时间）、两个处理选项（全部拒绝 / 转为管理员手动处理）。

管理员选择处理方式并确认后，系统执行收尾操作。关闭后员工端入口隐藏，员工已有的申请记录保留，来源标记更新为"自助申请（已关闭）"。

**建议文案：**

- 确认窗口标题：关闭前请处理审批中的申请
- 确认窗口说明：当前有 X 条权限申请仍在审批中。关闭自助申请前，需要先处理这些申请。
- 选项一：全部拒绝 —— 拒绝所有审批中的申请，申请人会收到拒绝通知
- 选项二：转为管理员手动处理 —— 审批中的申请将转为待办，由管理员手动决定是否授权
- 确认按钮：确认关闭
- 取消按钮：暂不关闭

**下一步：**

关闭后返回配置页，展示关闭状态。员工端入口同步隐藏。

### 节点 4.2：员工查看申请记录

**用户动作：**

员工在"我的权限"页面点击"申请记录"标签或入口，查看自己提交过的所有申请。

**系统反馈：**

申请记录列表展示每条申请的基本信息：申请的角色名称、提交时间、当前状态（待审批 / 已通过 / 已生效 / 已拒绝 / 已撤销）。支持按状态筛选。点击某条记录进入详情页，展示完整的申请信息、审批进度、审批人意见。

**建议文案：**

- 页面标题：申请记录
- 状态筛选标签：全部 / 待审批 / 已通过 / 已拒绝 / 已撤销
- 记录卡片信息：申请角色、提交时间、当前状态
- 详情页-审批进度：提交申请 → 待审批 → 已通过 → 已生效

**下一步：**

从详情页可以查看审批结果，被拒绝的申请可以从这里重新发起。

### 节点 4.3：员工撤销申请

**用户动作：**

员工在申请记录详情页中，对状态为"待审批"的申请，点击"撤销申请"。

**系统反馈：**

弹出二次确认窗口："撤销后该申请将不再被审批，如需申请请重新提交"。确认后，申请单状态变为"已撤销"，审批人待办中该申请消失。撤销记录保留在申请记录中。

如果申请状态已变更为"已通过"或"已拒绝"（在员工点击撤销前审批人已处理），撤销按钮不可用，显示当前状态。

**建议文案：**

- 撤销确认标题：确认撤销申请
- 撤销确认说明：撤销后该申请将不再被审批。如仍需该权限，请重新提交申请。
- 确认按钮：确认撤销
- 取消按钮：暂不撤销
- 撤销成功反馈：申请已撤销

**下一步：**

撤销后返回申请记录列表。

## 5. 异常与阻断流程

### 异常 X1：审批人不存在或审批链路异常

**发生时机：** 员工提交申请后，系统自动分配审批人时。

**触发条件：** 管理员配置的审批人来源找不到对应的人——直属上级不存在、指定角色下无成员、或整个查找链路为空。

**判断依据：** business_blueprint.md 风险二"审批流程断裂"的保护策略。

**反馈形式：** 对员工：申请提交后状态展示为"待分配审批人"，并给出说明。对超管：站内消息或待办通知"有权限申请缺少审批人，请处理"。

**系统反馈：**
- 员工侧：申请已提交，当前正在为您分配审批人。如有疑问请联系管理员。
- 超管侧：以下权限申请缺少审批人，请手动分配或处理：申请人 [姓名]、申请角色 [角色名]、提交时间 [时间]。

**用户下一步：** 员工等待超管分配审批人；超管进入申请详情手动分配审批人或自行审批。

### 异常 X2：审批超时无人处理

**发生时机：** 申请进入"待审批"状态后，审批人在设定时长内未处理。

**触发条件：** 审批时间超过管理员配置的超时时长。

**判断依据：** facts.md 异常与边界"审批超时" + business_blueprint.md 风险二保护策略。

**反馈形式：** 对审批人：超时前发送催办通知。对超管：超时后发送转派通知。

**系统反馈：**
- 催办通知（超时前）：你有一条权限申请已等待 X 天，请尽快处理。申请人：[姓名]，申请角色：[角色名]。
- 转派通知（超时后）：权限申请已超时未处理，已自动转派给您。申请人：[姓名]，申请角色：[角色名]。请尽快处理。

**用户下一步：** 审批人在催办后尽快处理；超管在转派后接手审批。

### 异常 X3：管理员开启时检测到治理模式互斥

**发生时机：** 管理员在配置页中尝试开启"员工自助申请"时。

**触发条件：** 当前已开启"权限变更审批模式"。

**判断依据：** business_blueprint.md 风险三"模式互斥冲突"的保护策略。

**反馈形式：** 弹窗阻断，不允许直接开启。

**系统反馈：**
- 弹窗标题：不能同时开启两个审批模式
- 弹窗正文："员工自助申请"和"权限变更审批"都涉及"权限变更需要审批"，同时开启会导致两条审批链路交叉，管理员和审批人难以区分管理标准。如需开启员工自助申请，请先关闭"权限变更审批"模式。
- 按钮：去关闭权限变更审批 / 取消

**用户下一步：** 点击"去关闭"跳转关闭权限变更审批模式，或取消保持当前状态。

### 异常 X4：员工尝试申请被排除的敏感角色

**发生时机：** 员工进入申请表单，查看可申请角色列表时。

**触发条件：** 管理员已将某些角色标记为"不可申请"（敏感排除）。

**判断依据：** business_blueprint.md 风险一"权限安全风险"的保护策略。

**反馈形式：** 入口过滤——被排除的角色在角色列表中直接不可见。

**系统反馈：** 列表只展示可申请的角色，被排除的角色不出现在列表的任何位置。申请人无法通过搜索或直接输入找到这些角色。

**用户下一步：** 从可申请角色中选择；如需申请被排除的角色，需联系管理员通过手动授权路径处理。

### 异常 X5：自动授权失败

**发生时机：** 审批人点击"同意"后，系统尝试自动授权时。

**触发条件：** 授权接口调用失败（如系统异常、权限数据冲突等）。

**判断依据：** business_blueprint.md 推荐方案中"审批通过后自动授权"的实现约束。

**反馈形式：** 对审批人：弹窗提示授权失败。申请单状态不变更。

**系统反馈：**
- 弹窗标题：授权失败
- 弹窗正文：权限授予过程中出现异常，申请单状态未变更。请稍后重试，如多次失败请联系技术支持。
- 按钮：重试 / 稍后处理

**用户下一步：** 审批人点击重试；如持续失败，提交技术支持处理。此时申请单仍处于"待审批"状态，不会丢失。

### 异常 X6：管理员关闭时存在审批中的申请

**发生时机：** 管理员在配置页中点击"关闭自助申请"时。

**触发条件：** 当前存在状态为"待审批"的申请。

**判断依据：** business_blueprint.md 风险四"关闭能力后的数据悬空"的保护策略。

**反馈形式：** 弹窗阻断，强制要求选择收尾方式后才允许关闭。

**系统反馈：**
- 弹窗标题：关闭前请处理审批中的申请
- 弹窗正文：当前有 [X] 条权限申请仍在审批中。关闭自助申请前，请选择处理方式。
- 选项一及说明：全部拒绝 —— 拒绝所有审批中的申请，申请人会收到拒绝通知。
- 选项二及说明：转为管理员手动处理 —— 审批中的申请将转为您的手动待办，由您逐一决定是否授权。
- 确认按钮：确认关闭（选择处理方式后才可点击）
- 取消按钮：暂不关闭

**用户下一步：** 选择处理方式后确认关闭；或取消返回。

### 异常 X7：员工离职或转岗时的申请处理 [GAP]

**发生时机：** 员工离职或转岗时，存在该员工发起的待审批申请或已生效的申请获得权限。

**触发条件：** 成员管理系统触发离职或转岗操作。

**判断依据：** facts.md 开放问题与缺口中的 [GAP] 项。

**反馈形式：** [GAP] 离职时权限回收的具体时机、通知方式和申请记录保留策略待确认。

**系统反馈：** [GAP] 建议离职时自助申请获得的权限随账号停用一并回收，通知形式待定。

**用户下一步：** [GAP] 待产品确认回收策略后设计。

## 8. 待确认问题

1. **员工端入口是放工作台还是全局导航？**

   影响：决定员工的发现路径。工作台入口适合高频使用但依赖管理员配置工作台卡片；全局导航入口稳定但可能与现有导航结构冲突。入口位置还影响权限中心的定位——是独立的服务中心还是工作台的一个卡片。
   建议确认方：产品 + 设计

2. **审批详情页是否需要展示申请人部门和岗位？**

   影响：审批人的判断信息充分度。如果不展示部门和岗位，审批人可能需要额外确认申请人的身份和业务范围。建议展示，但需要确认字段口径。
   建议确认方：产品

3. **审批通过和拒绝后，员工通过什么方式收到通知？**

   影响：员工是否及时知道申请结果。站内消息 + 审批通知是默认方案，是否需要短信需要评估成本和场景。
   建议确认方：产品

4. **被拒绝的申请，员工从什么入口重新提交？**

   影响：决定"申请记录详情页"是否需要"重新申请"按钮，还是让员工回到申请入口从头填。建议支持从拒绝记录直接重新发起。
   建议确认方：设计

5. **关闭能力后，员工的申请记录页是否还可见？**

   影响：决定关闭后员工端的信息架构。建议保留查看但隐藏申请入口，来源标记如实展示"自助申请（已关闭）"。
   建议确认方：产品

6. **员工离职时权限回收的通知方式？**

   影响：影响离职流程的完整性和员工的知情权。如果自动回收不通知，员工可能困惑为什么权限消失了。
   建议确认方：产品

7. **管理端统计数据的更新频率？**

   影响：管理员看数据时的预期。实时更新可以反映最新状态但可能增加系统压力，定时更新（如每小时）需要明确标注数据截止时间。
   建议确认方：技术 + 产品
