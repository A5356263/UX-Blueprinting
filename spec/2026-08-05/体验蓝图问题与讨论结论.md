# 体验蓝图问题与讨论结论

## 1. 讨论背景

当前主链路以正式需求材料为业务事实来源，由 Experience Blueprint 输出完整交互方案。UXB 后续仅作为可选增强，不再作为主链路必经阶段。

近期测试暴露的问题不在于蓝图缺少页面、流程或异常输出能力，而在于部分体验判断没有稳定覆盖：

- 用户任务被固定理解为从模块入口主动开始。
- 用户在执行原任务时遇到可处理限制后，蓝图可能只写阻断，不提供后续任务入口或处理引导。
- 蓝图对成熟外部能力的引用可能写成未被证实的具体操作能力。
- 正式蓝图仍保留“待确认问题”，使已定案的交互方案混入未关闭信息。
- 知识消费已有基础机制，但“何时读取、何时停止”不够明确，存在遗漏必要知识或扩大阅读范围的风险。

## 2. 已确认结论

### 2.1 蓝图可以做的体验决定

蓝图可以确定：

- 信息应在何时解释。
- 任务从哪里进入，以及受阻后如何继续。
- 是否需要在当前任务中提供后续处理任务的入口或引导。
- 已被系统确认的上下文如何在任务间保留。
- 用户处理后应回到原任务、重新发起还是查看处理状态。
- 成熟能力的复用入口、输入、输出和返回关系。

蓝图不能假定：

- 未被业务材料证明的系统能力。
- 未被证明存在的页面、配置项、审批节点、字段、校验或自动处理。
- 跨系统自动预填、自动回流、数据清理或状态变化。

### 2.2 任务入口不只来自模块入口

一个任务可以通过以下方式开始：

- 用户主动进入模块或页面。
- 用户在执行原任务时，因为可处理限制而被动触发后续任务。
- 用户看到状态、结果或提醒后，继续处理后续任务。

可处理限制包括但不限于：权限不足、前置条件不满足、必要数据或关联对象缺失、当前状态不允许操作、依赖流程未完成、对象失效或变更、规则冲突、适用范围不符、外部系统暂不可用、同步延迟或处理失败。

不是所有限制都需要跳转：

- 当前处可以修正的，保留在当前任务中处理。
- 已存在后续处理任务且可进入的，提供明确转接。
- 没有可处理路径的，明确说明限制结果和责任边界。

### 2.3 正式蓝图不保留待确认问题

- 缺少会改变业务事实、主流程、状态语义、权限、字段规则或承载方案的信息时，停止正式蓝图生成，并返回上游澄清。
- 属于信息层级、入口、解释时机、反馈或任务编排的体验取舍，由蓝图直接定案。
- 成熟外部基座未在本期修改时，作为复用引用写明输入、动作、输出和返回位置，不展开页面，不提问。

### 2.4 知识消费保持最小必要

不重构知识消费机制，不要求全面读取业务知识。

- 业务知识只用于确认当前方案依赖的既有入口、父级承载页、成熟基座边界、状态语义和返回关系。
- 设计准则和交互模式用于支持当前已识别的具体设计决定。
- 证据已足以支撑当前决定后停止阅读。
- 未形成具体设计问题时，不为覆盖率而读取或引用知识。

### 2.5 UXB 不整体迁入蓝图

本次不迁入 UXB 的任务底表、体验压力分级、候选准入、方向比较、覆盖复核、确认机制、产物结构或知识记录机制。

仅吸收“任务可在处理中被动触发”的通用入口视角，并嵌入蓝图既有的流程总览、节点展开和异常处理机制。

### 2.6 文档阅读体验

流程节点保留现有信息结构，字段标签使用加粗形式，便于设计师和后续 Agent 扫读：

- **用户动作：**
- **系统响应：**
- **用户需要知道：**
- **下一步：**

该格式用于流程和异常节点，不强制套用到页面结构章节。

## 3. 任务交互影响预判讨论结论

### 3.1 触发背景

最新测试显示，蓝图已读取“按角色 / 按功能权限”的范围规则，也已识别员工申请任务，但在员工流程中将两种对象类型压缩成“从候选列表选择权限”，遗漏了各自的选择与提交路径，并自行补写了“单选”。

同时，任务内触发规则位于任务路径组装之后。模型容易先按模块主动入口完成主路径，再将任务中受阻的入口降为异常说明，未形成实际可执行的转接路径。

### 3.2 已确认的处理原则

1. 不重写 Experience Blueprint 的主推理链，不改变现有流程、页面、状态、父级承载页和 Context 投影规则。
2. 在任务路径组装前，加入一次仅供内部使用的“任务交互影响预判”。该预判不生成新的正式章节、JSON 字段、清单或矩阵。
3. 预判对每个已识别任务记录：主动入口、输入已证明的任务内受阻入口、会改变交互的规则分支、复用能力的交接关系。
4. 已确认的规则分支只要改变用户操作对象、候选来源、可见信息、提交内容或处理结果，就必须分别进入流程和对应承载面。只改变说明文案的规则保留在对应说明或反馈中。
5. 任务内触发只在输入材料或已读取业务知识证明原任务存在限制、且当前处理或后续任务存在时进入蓝图。蓝图据此确定解释、入口、已知上下文和处理后去向。
6. 复用分为三层：当前方案承载入口与结果；复用能力承担其内部处理；组件复用承担选择、检索等内部交互。当前页面可以提供进入复用能力的入口，但具体能力、输入、输出和返回关系必须有证据。
7. `§8` 保留设计依据说明，但“知识缺口”改为“设计依据与适用边界”。体验决定写明决定、依据和落点；会影响业务能力是否存在的事实缺失，按既有停止规则返回上游。

### 3.3 本次范围

本次只调整蓝图的内部推导顺序、任务分支落点和 `§8` 的表达边界。知识消费机制、Context Schema、校验脚本、UXB、PRD Review、共享工作流和下游 Skill 不在本次范围。
