# 内网知识与 Skill 适配 V0 实施文档

输出时间：2026-11-13 14:57:18 +08:00

## 1. 背景

`only-x-cp` 用于内网 Agent 平台。平台已向 Agent 提供知识检索能力，但当前 16 个正式 Skill 中仍有本地知识库维护 Skill；部分下游规则同时出现平台名称、本地索引、README、raw 和文件路由。知识正文也包含本地导航与跨文件业务关联，直接按目录搬运可能造成噪声、遗漏或关联断裂。

## 2. 目标

- 形成一套可整体导入内网平台知识库的文件，保留已确认的业务和设计知识、必要关联及明确标记的缺口和冲突；不纳入未经确认的候选事实、本地维护和导航指令。
- `.agents/skills/` 不再包含 `knowledge-wiki`；其余 15 个 Skill 保留各自必要的任务知识消费判断，不依赖旧知识 Skill、具体平台名称或本地知识文件路径。
- 以逐单元对照记录、Skill 引用检查和本地验证证明整理范围及规则保真。平台实际导入、切片和召回效果须在内网验证，不能凭本地检查宣称通过。
- 不执行内网上传，不更改与本任务无关的分析流程、专业结论、状态交接或输出格式，不提交或推送。

## 3. 修改范围

| 位置 | 处理目的 |
| --- | --- |
| `.agents/skills/knowledge-wiki/knowledge/raw/` | 作为本次知识盘点和内容对照的来源；先完成导入文件和核对，再移除所属 Skill。 |
| `.agents/skills/knowledge-wiki/` 的其他内容 | 判断是否含正文独有的已确认知识；候选、模板、索引、维护规则和脚本按用户边界处理，不作为运行 Skill。 |
| `.agents/skills/` 其余 15 个 Skill 的主文件、引用参考及受影响模板 | 保留各自必要消费判断，清除具体平台名、旧知识 Skill、索引和路径依赖。 |
| 项目内受影响的引用、清单和测试 | 仅修改实际指向被移除 Skill 或旧消费路径的活跃引用及相关检查。 |
| `knowledge-import/` | 本次拟创建的独立导入文件目录，与正式 Skill 分离；最终仅存可导入的知识文件。 |
| `spec/2026-11-13/` | 保存讨论结论、实施文档与后续逐项对照及验收记录；不与知识导入文件混放。 |

不改项目根目录备份知识、用户输入和历史产物；不在本次任务中重写业务规则或设计推理内核，不改变与知识消费无关的 Skill 流转。

## 4. 实施策略

本任务交付知识导入文件及内网 Skill 适配结果。平台提供检索和知识维护；Skill 负责任务判断。唯一正式消费源为内网知识库中经导入并确认的知识；导入文件是本次迁移交付物，不定义为与平台并行维护的第二个正式运行知识库。实际导入尚未发生前，不能声称内网已有新正式版本。

规则位置：业务和设计知识事实放导入文件；与具体任务有关的何时查询、查询什么、适用判断和失败处理放相应 Skill；知识整理对照与本次验收证据放 `spec/2026-11-13/`。各 Skill 不指定平台或工具名称、知识切片实现、本地目录和索引。

先完成逐文件盘点与知识保全，再建立导入文件，核对后改造各 Skill，最后清理活跃引用并移除 `knowledge-wiki`。任何删除以完整对照、可恢复的 Git 基线和无遗漏证据为前提；若发现无法确认的正式性、来源或知识关联，不以猜测替代，记录阻断并停止受影响项。

## 5. 详细修改

### 5.1 知识盘点与分类

1. 遍历当前 `knowledge-wiki` 下所有知识正文、README、索引、候选、模板和维护文件，建立文件及知识单元清单，记录源路径、标题、内容类别、目标位置、处理动作和判断依据。知识之外的用户输入不自动扫描。
2. 已确认的业务事实、规则、字段、状态、页面结构、操作、流转、设计准则、设计规范与模式保留，维持对象、角色、适用范围、条件、结果、例外、否定和表达强度。
3. `[GAP]`、`[QUESTION]` 保留为缺口或问题，不写成确定结论；`[CONFLICT]` 保留已取得且互相矛盾的陈述及来源，不自行裁决。未经确认的候选事实不进入正式导入文件。
4. 对每个 README、索引、文档导航和模板按段落判断：只服务本地定位或维护的内容不导入；独有且已确认的事实、范围、分类定义或规则先迁入适当正文；未确认描述不当作事实。不得仅凭文件名整文件删除或保留。
5. 相同或相似内容逐项比较适用范围、条件和例外，确认完全等价后才合并；冲突保留两方来源并标记，不以文件时间或猜测决定胜负。

### 5.2 导入文件与关联

- 将通过筛选的知识整理到 `knowledge-import/`，按实际业务领域和设计知识类型划分可导入 Markdown 文件。命名、标题和必要上下文应足以识别对象及适用范围；不把一个领域全部压成单段摘要。
- 将依赖本地路径的链接或“见某文件”改成表达实际对象、规则关系和需要补充查询的语义；对涉及审批、状态、例外和上下游结果的关联，逐条对照原文。仅有导航作用的链接移除；无法确认关联时记录缺口，不虚构关联。
- 不为迎合假定的切片长度机械拆分规则或重复整套正文；保留完整规则单元，避免条件、否定、例外与结论分离造成语义失真。平台的实际切片策略、关系抽取和来源能力未在本次验证，不能假设这些能力一定存在。
- 导入文件不得包含 Skill 的执行流程、平台维护命令、索引更新要求、未确认候选或本地绝对路径。确属知识内容的历史来源、问题和冲突按事实与状态保留。

### 5.3 逐 Skill 内化知识消费

对剩余 15 个 Skill 分别检查主文件、按需引用的 reference 和会随 Skill 分发的模板。建立清单，记录是否需要查询知识、何时查询、需要什么事实、适用判断、来源和冲突/缺口处理；无需查询的 Skill 维持其原职责，不强加知识步骤。

PRD Review 保留业务事实与目标状态、继承和闭环判断；UXB 保留业务机制与策略级设计依据；Page Spec 保留既有承载、页面关系及设计依据；其余 Skill 按自身任务保留必要消费判断。原有专业规则不能仅压成摘要，尤其保留触发条件、适用范围、限制、例外和阻断条件。

删除将平台写成“萃知”的工具指向；删除要求先读 `knowledge-wiki`、index、README、`knowledge/raw/**` 或本地路径的消费动作。把需要补足的上下文表达为按事实和关联继续检索，而不是假定 Agent 可以打开特定文件。来源可定位、规则完整性及不把摘要当事实的原则继续保留。

### 5.4 移除旧 Skill 与清理

知识与消费规则完成逐项对照后，检查所有活跃 Skill、模板、脚本和项目引用。先处理实际引用，再移除 `.agents/skills/knowledge-wiki/`；不得把维护、入库或审核流程移植成新的运行 Skill。移除前核对原有未提交变更及恢复方式；不得清理任务无关文件。

## 6. 执行顺序

| 步骤 | 进入条件与允许范围 | 完成证据与停止条件 |
| --- | --- | --- |
| A 盘点 | 核对当前分支、Git 状态和知识来源；只读盘点。 | 输出逐文件/单元清单及正式性、关联、缺口和冲突；来源不明或无法判断的单元标记待确认。 |
| B 整理知识 | A 已识别源内容；只创建导入文件及对照记录。 | 逐单元核对对象、范围、条件、例外和处理动作；不完整时不移除源 Skill。 |
| C 适配 Skill | B 已确定知识边界；修改 15 个 Skill 的实际相关入口和引用。 | 逐 Skill 检查消费触发、依据和缺口，确认非知识任务职责不变；语义有争议时停止该项。 |
| D 清理与移除 | B、C 对照通过且确认可恢复；处理旧引用并移除 `knowledge-wiki`。 | 无活跃运行依赖指向已移除目录；有未处理调用或独有知识时停止移除。 |
| E 验收 | 所有修改完成。 | 按第 9、10 节记录本地证据；内网导入与检索未实际执行时明确标记待验证。 |

## 7. 红线

- 禁止删减核心业务或设计规则的适用对象、条件、否定、结果和例外；不得把动态业务数据误写成固定页面定义。
- 未确认候选不入正式知识；缺口和冲突保持原有不确定状态，不自动裁决或生成新事实。
- 不把目录、导航、维护流程当业务知识，也不因移除目录而丢失其独有事实或真实依赖。
- 不扩大任何 Skill 的职责或权限，不把上游结论自动升级为规则、根因或方案事实。
- 不修改其他分支、用户已有产物或平台数据；不访问内网、不上传、不提交或推送。

## 8. 注意事项

- 以执行时当前分支文件为准，盘点时同时核对已跟踪和未跟踪内容；不覆盖用户改动。
- 平台指南是组织知识的参考，实际解析、引用、关联、版本及权限能力以目标部署实际结果为准，不把文档描述写成已实测事实。
- 导入文件与对照表分离；对照表记录源与目标、处理原因及缺口，不能随知识正文被当作正式业务规则。
- 用户曾要求具体修改前确认；本实施文档只定义执行步骤，不自行视作执行或发布授权。

## 9. 验收方式

| 检查 | 方法与预期 | 证据及边界 |
| --- | --- | --- |
| 知识完整与筛选 | 逐源文件、逐规则单元对照目标；核对 README 独有事实、候选排除、GAP/QUESTION/CONFLICT 状态、重复及跨文件依赖。 | 在同日期新增实施记录和对照清单，记录源、目标、差异及未决项；本地对照不证明检索召回。 |
| Skill 消费 | 对 15 个 Skill 和被引用参考逐项核对查询触发、专业用途、条件例外及缺口；搜索旧平台名、`knowledge-wiki`、index、raw 和绝对路径，逐条判断活跃性。 | 记录检查结果和实际例外；关键词零命中不单独证明语义正确。 |
| 内容语义 | 使用现有知识中的实际例子，检查角色、状态、权限、条件、例外和下游结果；包括提交与审批、冲突和资料不足场景。 | 给出原文与整理后位置；不得用假设的示例冒充实际验证。 |
| 运行与引用 | 核对被移除 Skill 的活跃引用、剩余 Skill 链接及任务相关测试；执行适当静态检查和现有测试。 | 记录命令、结果和未运行原因；保留用户文件与既有运行路径。 |
| 内网能力 | 在用户可操作的内网环境导入并检查事实、关联、来源、完整条件和异常检索。 | 当前环境不执行上传；未取得平台结果前标记待验证，不声称通过。 |

## 10. 验收标准

- 导入文件可逐项追溯来源；已确认知识及实际关联无遗漏、条件和例外无失真，缺口与冲突未被写成确定事实，未确认候选未混入。
- `knowledge-wiki` 已从正式 Skill 移除；其余 15 个 Skill 的知识消费职责已逐项核对，无活跃旧平台名、知识库 Skill、index、raw 或固定本地知识路径要求。
- 未变更无关专业判断、状态交接和用户已有产物；受影响测试及静态检查结果已如实记录。
- 实施、验证和发布状态分别记录。内网导入和检索未验证时不得标记整项验收通过；提交、推送和平台上传依各自授权执行。
