# 内网知识与 Skill 适配 V1 实施记录

## 源分支改造

- 分支为 `only-x-cp`。业务和设计知识正文迁至根目录 `knowledge-import/`。迁移对照表记录 145 份源文与目标文件，其中 34 份原 README 将领域定义、范围、关系和缺口迁入领域范围文档。
- 旧知识副本及索引、状态页、维护脚本、旧消费与导航规则已从工作树清理。待核候选留在维护侧。导入目录只包含 Markdown 正文。
- `knowledge-wiki` 负责源分支正文维护。更新记录在该 Skill 目录内，只有实际内容变化才登记。此次位置和组织迁移未登记为业务或设计规则更新。
- 业务 Skill 按任务检索，使用本 Skill 的条件、证据与冲突判断。发布说明明确业务 Skill 与导入正文的交付范围。

### 隔离样例走查

使用独立临时目录里的合成更新记录和规则正文，人工按现行 Skill 指令逐条执行。以下是走查产出的结果。样例未写入正式知识或更新记录，知识召回内容由本地构造。

| 实际输入 | 走查结果 |
| --- | --- |
| 筛选 11 月 10 日至 11 日、主题“批量请假 R01”；同文件另有“批次结果 R02” | R01 的两条修改归并为一条，沿旧位置“状态与异常.md / 提交条件”定位到“规则与权限.md / 批量提交”。取到现行原文“校验通过的人员可以继续提交。批次完成仅表示申请已创建，每张申请仍按各自审批流程处理。” R02 未纳入。 |
| 筛选 11 月 12 日删除 R03、位置不全的修改 R04 | R03 返回旧位置“状态与异常.md / 重试限制”和旧句“失败人员只能重试一次。”，状态为已删除。R04 同文件存在多个章节且缺少规则标识，无法定位，列为待补。 |
| 召回完整的管理员批量请假规则 | PRD 审查可以依据正式来源校验“通过校验即可提交”和“仍需逐单审批”；页面规格可以区分校验、批次完成与单据审批，不能据此补造审批状态枚举。 |
| 只召回“批次完成后可在列表查看” | 该片段支持列表可查。按“管理员批量请假、提交条件、单据审批状态”补查，仍缺时将会影响流程或页面状态的规则列为待确认。 |
| 同版本同范围的两个正式来源分别写“每张仍需审批”和“随提交直接通过” | 保留《假勤规则》“批量提交”和《假勤规则补充》“批次结果”两个出处。PRD 阻断审批闭环，页面规格停止受影响的状态设计，UXB 停止依赖审批机制的策略取舍。 |

报告交接走查以两个同名 `requirements_baseline.md` 为输入。一个由本轮明确传入并对应当前需求，另一个来自旧需求。按 Page Spec 入口规则，只绑定本轮文件。配套 Handoff 身份不符时，记录未完成覆盖核对并用完整基线自检。仅有旧报告时，缺少本轮有效基线，应请求提供。本项为本地指令走查，内网还需验证宿主实际如何传入文件及身份信息。

### 整目录打包验收

从业务 Skill 源目录清理了 69 份已废弃的旧 JSON 脚本、格式说明、样例、测试与旅程演示文件。15 个业务 Skill 各自完整压缩，在临时目录解包后通过文件清单、Skill 结构及包内 Markdown 引用检查。脱离项目目录运行旅程渲染与校验，HTML 成功生成，解析 7 条埋点事件。客观分析计算模块导入及分位数样例通过，主观反馈预处理的脱敏样例通过。
