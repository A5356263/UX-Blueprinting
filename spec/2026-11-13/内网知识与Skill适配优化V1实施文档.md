# 内网知识与 Skill 适配 V1 实施文档

输出时间：2026-11-13 15:37:34 +08:00

## 1. 背景

`only-x-cp` 是持续产出内网版本的源分支。内网平台已向 Agent 提供知识工具。当前分支有 16 个 Skill，`knowledge-wiki` 仍按本地 Wiki 维护知识，部分业务 Skill 仍指定平台名称或按旧目录和索引查找知识。内网运行还涉及报告传递、脚本执行和归档存储。

## 2. 目标

- 以本分支维护的业务和设计知识正文为唯一权威源，形成可整体导入的文件。内网知识库消费导入后的副本。
- 保留 `knowledge-wiki` 作为源分支维护 Skill，负责整理、核对和更新知识，并记录实际内容变化。
- 业务 Skill 各自定义查询时机、范围、适用判断和缺口处理。平台提供检索能力。
- Agent 能按用户指定的时间、主题或更新条目精确提取知识范围。交付形式由用户当次指定。
- 分别记录仓库验收与内网部署验收结果，明确每个 Skill 可用的功能范围。

## 3. 修改范围

| 位置 | 修改内容 |
| --- | --- |
| `.agents/skills/knowledge-wiki/` | 改写维护入口及必要参考。盘点原知识、关联和独有事实，清理退出维护流程的索引、导航和脚本引用。 |
| 根目录 `knowledge-import/` | 沿用 V0 拟定位置，作为唯一的权威知识正文目录。该目录中的知识文件可以整体交付导入，更新直接写回这里。 |
| `.agents/skills/knowledge-wiki/knowledge-changes.md` | 拟作为源分支的轻量更新记录，供维护和指定范围提取时读取。 |
| 其余 15 个 Skill | 核对主文件、引用参考和随包模板。仅修改知识消费及受影响的旧引用。 |
| 本日期 `spec/` 目录 | 保存源与目标对照、验收证据及内网运行限制。 |

原有任务门禁、报告格式、跨 Skill 的授权与选路继续按各 Skill 的规定执行。平台上线和知识导入由内网操作人员执行。V1 规定实施范围和验收条件。

## 4. 实施策略

先盘点源知识及依赖，把确认有效的知识迁入唯一正文目录。随后改写维护 Skill 和各业务 Skill 的消费规则，再清理失效的运行引用。发给内网日常 Agent 的内容包括业务 Skill 及各自必需的随包资源，知识正文单独导入知识库。`knowledge-wiki` 留在源分支供维护者使用。

知识变更以正文为准。更新记录帮助 Agent 找到已发生的变化，并定位替换或删除前的内容。平台侧覆盖、删除和召回能力须在部署环境实测。

## 5. 详细修改

### 5.1 整理权威知识正文

- 逐单元盘点现有正文、README、索引、模板及候选。记录源位置、目标位置和处理理由。保留确认的业务事实、规则、页面与字段、设计准则和模式，以及影响理解的实际关联。
- 核对对象、角色、条件、状态、结果、否定、例外和表达强度。README 若含独有且已确认的知识，将该内容完整迁入正文。仅服务本地定位或维护的内容退出导入范围。
- 保留 `[GAP]`、`[QUESTION]`、`[CONFLICT]` 的缺口、疑问或冲突语义。冲突保留能追溯的双方陈述。未经确认的候选事实排除出正式正文。
- 将本地跳转改写为可理解的业务关联。例如同时保留批量提交与逐单审批的关系，使读者能区分提交完成和审批通过。确认完全等价后才合并重复内容。

### 5.2 改写知识维护和更新记录

维护者通过 `knowledge-wiki` 核对新材料、修改正文并登记实际变更。每条记录至少包含以下信息。

| 记录项 | 定位要求 |
| --- | --- |
| 时间、动作与主题 | 写明实际更新时间，标明新增、修改或删除，使用可辨认的知识对象名称。 |
| 内容变化与当前落点 | 写明真正变化的规则或事实。新增和修改给出文件、章节或规则名称，足以区别同文件中的其他条目。移动或重命名时保留旧落点与新落点。 |
| 替换或删除前的线索 | 给出旧落点及能唯一辨认旧知识的原句或准确描述。删除整段时明确其范围。 |

仅格式整理且知识内容未变化时无需登记。记录留在维护 Skill 一侧，导入范围仅为权威知识正文。采用 Markdown 记录即可，人工按需发起提取。

Agent 收到提取请求时，按用户指定的时间、主题或记录筛选，核对对应当前正文。相同规则多次修改时找到该范围涉及的当前结果。新增后又删除时说明其最终状态。删除项利用原位置和旧内容定位，供内网操作人员处理。时间或定位不足时指出具体缺口，并仅整理能确定的范围。用户当次决定交付形式。

### 5.3 内化各业务 Skill 的知识消费

逐项核对 15 个 Skill。对确实需要知识的 Skill，在自身指令或随包参考写清触发条件、查询对象、证据范围、来源核对和冲突处理。PRD 审查保留业务闭环、继承和目标状态判断，UXB 保留策略层判断，Page Spec 保留页面承载与交互依据。仅消费获准上游结论的 Skill 继续按其原有门禁运行。

清除写死的平台名、旧 Wiki 入口、索引和固定本地知识路径。需要补查时按缺少的对象、条件、例外和关联发起检索。影响结论的知识缺口进入该 Skill 原有的待确认或阻断流程。

### 5.4 核对内网运行依赖

- 确认平台可读取主文件和随包参考或资源。检查必需引用能否从实际部署位置打开。
- 核对本轮 Markdown 产物可由用户或宿主明确传递给下游。沿用报告身份、项目、范围、来源及授权检查。平台未提供共享路径时，验证显式传入文件的路径可用。
- `journey-metrics` 的 Python 渲染以实际执行及结果可取为验收证据。
- `evidence-archive` 的长期归档以持久存储、权限、获准写入和跨任务精确读回为验收证据。

## 6. 执行顺序

| 步骤 | 进入条件与允许范围 | 完成证据及停止条件 |
| --- | --- | --- |
| A 盘点 | 核对分支与工作区，读取知识及引用 | 建立逐单元对照。无法确定来源或关联的内容进入缺口清单。 |
| B 迁移正文 | 盘点完成，建立权威正文目录 | 对照确认规则保真及独有事实已迁移。存在遗漏时保留相应源材料。 |
| C 改写维护与消费 | 正文位置确定，修改维护 Skill 和业务消费规则 | 记录可定位新增、修改和删除，逐 Skill 核对专业门禁及旧引用。 |
| D 本地验收 | 实施完成，检查随包资源、知识与变更提取 | 记录实际样例及结果，列明仍须在内网验证的功能。 |
| E 内网验收 | 内网人员具备测试环境及部署材料 | 按第 9 节验证。能力缺失时将对应场景标为受限或待验。 |

## 7. 红线

- 只有实际变化才写入更新记录。知识正文、变更记录与内网消费副本各自沿用第 4 节规定的职责。
- 保留正式知识的表达强度、适用范围、条件和例外。缺口、冲突和候选不得升级为确定事实。
- 知识查询的调整不得绕过报告身份、证据放行、人工授权和原有任务门禁。
- 旧内容消失须有内网侧处理和核验依据。增量中没有某条知识，不构成删除成功的证据。

## 8. 注意事项

执行时以当前分支文件为基线，清理旧文件前核对未提交内容、独有知识和活跃调用。平台指南用于理解知识组织，具体解析、替换和删除以目标部署验证为准。实施结果、验收结果及发布授权分别记录。

## 9. 验收方式

| 检查项 | 样例与通过条件 |
| --- | --- |
| 知识保真 | 按源与目标逐单元对照。抽查有独有事实的 README、跨文件状态关系、例外和冲突。正文可追溯，知识关系与原文一致。 |
| 变更记录和提取 | 使用隔离样例覆盖同文件只改一条、多次修改同一条、移动章节和删除。按指定时间或主题提取，仅包含对应知识范围。删除后仍能识别旧内容及原位置。记录不足时明确缺口。 |
| 业务 Skill 适配 | 检查 15 个 Skill 的活跃引用。使用规则完整、仅召回片段、规则冲突三种输入验证适用判断及补查行为。 |
| 平台交接 | 实际传入一份本轮指定的 Markdown，同时提供同名旧报告样例。下游只接受身份与授权相符的输入，缺失或不符时阻断。 |
| 脚本与归档 | 在目标环境执行旅程渲染并取得产物。归档覆盖授权、重复、失败及跨任务精确读回。 |

本地检查与平台验收分别保存证据。平台的结果未取得时，对应场景标为待验。

## 10. 验收标准

- 本分支存在一份可整体交付的权威知识正文。知识单元、关联和缺口经对照保留。
- `knowledge-wiki` 可以维护源正文并记录实际变化。Agent 可按指定范围定位变化，记录不混入知识导入文件。
- 日常业务 Skill 无活跃的指定知识库品牌、旧 Wiki 路由或固定本地知识路径依赖。原有专业与授权门禁继续生效。
- 内网实测通过的场景才标记可用。报告交接、脚本渲染和账本存储分别验收。
