# 正式需求基线减负优化 V0

- 输出时间：2026-11-24 14:19:24 +08:00

## 目标

减少基线的重复出处和验收排版。新旧基线的独立 Page Spec 盲测已生成两份规格，本次核对的关键业务事实均有落点。

## 输出改动

1. 三个分支同步修改 prd-review 输出规范。取消 §0 标题，将项目名、formal 状态及输入标识放在标题下。保留实际使用的 PRD、审核记录及相关材料的短出处。
2. 取消 §12 汇总。PRD 小节、知识文件与规则编号、产品回复编号放在对应结论旁，可回查具体事实。
3. 保留 §1 至 §11 原编号。§10 按现行规则按需输出。§11 每个 AC 单独一行，写清对应事实、前提、动作与可观察结果，保留验收覆盖。
4. only-plugin 的正式基线登记同时识别新格式。新版按原编号顺序验证，接受无体验定案时省略 §10。原登记格式继续可读、可提交，审核记录登记规则照旧。

## 执行和验收

1. 逐分支修改输出规范，核对 Page Spec 仍从完整基线读取，页面事实交接仍检查 formal 和 §11。
2. 修改插件登记校验，用实际基线样本验证新版、旧版、缺失状态和缺失或错序的业务章节。
3. 检查三个工作树的差异。现有项目基线、对比样本、审核语义和下游生成规则作为验收对照。

## 验证结果

Windows 本地直接运行插件登记校验。新版有无 §10、旧版正式基线、审核记录及 Page Spec 均通过。缺少 formal、业务章节缺失或错序、重复 §10、混用新版与旧章节均被拒绝。三个工作树通过 git diff --check，现有正式基线及页面事实交接的文件哈希一致。Harness 宿主登记与内网运行未在本轮执行。
