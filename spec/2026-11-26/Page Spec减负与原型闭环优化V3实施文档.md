## 本次实施范围

将已确认的 V2 规格减负范围和 §10 读取修正同步到 only-uxb、only-plugin、only-x-cp 各自的 Page Spec 源码。依据为 V2 隔离测试和 V3 对照中已验证的 §10 行为。V3 的临时证据自检、草稿落盘流程及进度机制暂缓，保留现有检查阶段。

## 规则

- 正式基线始终全文读取。§10 存在时承接其中的体验定案和待定问题，缺省时继续。
- 静态父页以默认 ASCII 保留已确认的导航、区域、字段及本期入口。本期有新增触发或回流时写入任务。只有会改变当前任务进入、操作或结果的承载缺口才触发原有门禁。
- 本期新增、变更或任务闭环需要的内容写全。保留入口、状态与条件、字段选项默认值、动作、可见响应及恢复。只有真实结构有差异且需要图示时才加条件线框。
- 生成范围使用「生成」与「不生成」。已确定复用或范围外对象只在「不生成」登记原因或去向。当前任务仍写全必要交接、可见结果及返回关系。同步 Page Spec 的推导说明、输出模板和现有自检。现有 Edge 说明识别新的生成范围，也可消费已有旧规格。

## 分支与验收

- only-uxb 保留本地正式产物路径与预览交接。only-x-cp 保留内网资料检索、正式输入与交付方式。
- only-plugin 核对工作台的任务绑定、Skill 注册、Markdown 校验、产物登记及 npm 随包清单。仅在既有程序无法接受本次 Markdown 结构时修改对应逻辑。
- 验收三分支正式入口、两种生成范围、静态父页、现有自检与各分支宿主边界的一致性。测试插件登记对有和无 §10 的合法基线、新版 Page Spec 均可正常处理，以及必要主章节缺失时仍拒绝。使用 npm pack 预演检查随包文件。
