## 2. PRD Review：写清事实并在冻结前核对

改动入口为 [PRD Review SKILL.md](/E:/AI设计/体验蓝图构建思路/.agents/skills/prd-review/SKILL.md) 的正式基线步骤及 [输出规范](/E:/AI设计/体验蓝图构建思路/.agents/skills/prd-review/references/output_structure_guide.md) 的任务表达与自检。复用现有来源门禁、内部事实表及自检，在首次生成基线和产品回复后更新基线两条路径执行同一检查；零阻断、无问题单的直出路径也执行。

### 写入与归属

只保留本轮有效来源已确认、且会影响页面展示、操作、规则或可观察结果的事实。PRD、正式知识、现有系统结构和产品回复沿用现行来源及冲突优先级。辅助原型按已确认的证据身份使用，示意或候选内容不能升级为需求事实。按现有章节分配唯一完整落点，引用适用的源位置或已有 FN、BR 等编号。

- **§2 变更清单**：对象及新增、修改、移除关系。
- **§3 角色权限**：谁能看、做什么及作用范围。
- **§4 任务**：「从哪里进入」承接已确认入口、位置和触发载体；「怎么完成」承接已确认的页面或模块归属、Tab 名称和层级、字段、操作、固定文案、动作与打开或关闭关系；「完成后发生什么」承接结果、反馈和返回。顺序、控件类型及位置仅按有效来源写明的精度记录。将现有「不指定页面、组件或交互载体」收窄为禁止自行设计，明确该限制不排斥保留来源已确认的事实。
- **§5 规则**：条件性显示或禁用、默认值、选项范围、必填、数量、格式、枚举、校验次序。
- **§6 状态、§7 异常**：状态触发、可见变化、后续动作；失败条件、阻断、准确提示、恢复方式及结果。
- **§8 记录与系统、§9 范围**：实际记录的数据、系统承接及结果回写；明确的排除和限制。展示字段归 §4，实际保存的字段归 §8。
- **§10 体验定案、§11 验收**：沿用原有职责及 §10 的按需输出；§11 只引用既有事实，发现独有事实时回到责任章节处理。

### 冻结前检查

从已绑定的有效原始来源按事实类别建立内部对照项，覆盖主要、次要和异常路径，以及列表、表格、原文引号中明示的细节。对照基线草稿确认每项的对象、成员、条件、精确值和结果齐全。缺项或错位时修正对应章节再复查；产品明确变更的旧结论不列为遗漏。发现未决冲突或关键事实缺失时回到原审核门禁，未通过前不冻结、不写 `formal`。不得通过猜默认项、补齐枚举或引入无关原型让检查通过。

## 3. Page Spec：用基线清单替换外置文件核对

改动 [Page Spec SKILL.md](/E:/AI设计/体验蓝图构建思路/.agents/skills/page-spec/SKILL.md) 的执行顺序、基线入口、Step 3 和输出自检条目。保留现有完整覆盖标准及页面设计推导顺序，按以下方式替换交接操作：

1. **绑定完整基线后、设计推导前**，逐节读取 §2–§9，用 §11 反查遗漏。直接从上游记录「可独立核对的事实、所属实体或条件、基线出处」。同一事实去重，并列 Tab 或字段逐个可核对；条件、动作和结果保持关联。§10 按现行方式单独吸收，不能因它不在清单就跳过。旧版合法基线按既有来源规则读取，清单按有效内容提取，不按新版标题硬截断。
2. **首次写盘前**，沿用现行逐事实标准检查草稿。每条确认有结构、字段、操作、状态或文案等可执行落点，并反查草稿是否擅自补了默认值、扩了权限、闭合了未声明的枚举，或把条件放错对象。名称出现、只写在流程、出现在待确认区均不能代替已确认事实的正式落点。补齐后复查受影响的实体、关系和反馈。已确认事实未覆盖时不得宣称完整交付；真实来源冲突按原门禁处理。
3. **写盘后**，同一清单并入已有正文自检，核对实际写入内容及引用，避免写盘时重新组织造成遗漏。每次绑定新的需求或基线版本均重新提取，旧清单不得跨轮沿用。用户明确指定原始材料的直达模式沿用现有入口及门禁，本轮不将它改造为正式基线路径。

## 4. 执行顺序、依赖和回退

1. **实施前盘点。** 核对当前分支和工作树。对仓库内外置文件名、参考规则名、HF 检查提示逐一查生产者、消费者、交接配置、进度预览、登记与发布引用。当前 `only-uxb` 已定位到两份 Skill 及 [旧提取参考](/E:/AI设计/体验蓝图构建思路/.agents/skills/prd-review/references/page_generation_handoff.md)。遇到其他活动消费者时，先查明合同与迁移范围；未闭环前不得关闭生产。
2. **先迁移事实规则，再成套切换。** 从旧参考保全适用范围和逐事实粒度，将写入与查漏放进第 2、3 节规定的现有步骤。验证 Page Spec 在无交接文件的隔离目录能从基线闭环，再将生产、读取及相关提示一起退出。活动引用归零后，才可退役旧提取参考。保留历史 Spec 和已有产物。用本轮明确绑定的旧样本验证迁移时，若旧交接含基线没有的结论，按原有效来源核实，需要保留时由 PRD Review 修正基线；新运行不读取旧交接来补事实。
3. **联动检查。** 进度预览命令与固定下一步交接继续按原 Skill 执行。PRD 审核问题的业务门禁、正式格式、知识来源优先级、Page Spec 页面设计判断、实体范围和产物合同沿用现行规则。本分支通过后再另行决定跨分支迁移。已知 `only-plugin` 的 `shared-workflow/skill-graph.json` 仍有写盘后补漏说明，`only-x-cp` 允许宿主传入交接文件；两处各自排查，不能照搬本分支的停用动作。
4. **回退触发。** 任一活动消费者依赖外置文件、既有基线无法通过原入口、或已确认事实覆盖下降时，停止切换。恢复成套的旧生产、旧消费及规则引用，保留失败样本定位。修复后重新跑相关检查；不以永久双写掩盖退化。

## 5. 验收与证据

已有四类合成需求 A/B 两组各覆盖 62/62 项。两组都曾把已知状态扩大成完整枚举。独立盲测查到预埋的 3 处遗漏或错误，4 个正确对照无误报。上述结果支持本次方向，但未验证生产环境、同一 Agent 自检效果或端到端成本。

正式实施验收按下列顺序执行并记录实际证据：

- **两段闭环**：至少覆盖不同业务形态的展示、配置、跨角色结果及异常。先从本轮原始输入跑新 PRD Review，再用实际冻结产物跑新 Page Spec。每例先独立定下事实和允许的表达差异，再逐项定位两份输出。新增事实应有来源，已确认事实遗漏或反转均不通过；未知默认值和未声明枚举仍不能被补全。使用此前多业务用例和一份未用于调规则的原始输入样本。旧 A/B 已知的枚举越界作为反例复查。
- **同一 Agent 自检**：分别通过两条正式路径，让同一运行先形成自己的草稿，在检查前从外部对隔离工作副本注入漏字段、漏实体成员或默认值反转。校验时须读回该候选草稿，执行者只知道要核对，不知道预埋点。要求逐个指出事实、上游出处和目标位置，正确对照无误报，并验证修正后的实际正文。若只能靠另一个 Agent 找出问题，不能将日常自检判定为通过。
- **运行边界**：覆盖零阻断直出、产品回复后冻结及未关闭阻断停止；无交接文件时正常生成，同需求陈旧交接与另一需求交接存在时也不扰动当前基线；旧版合法基线、§10 有和无、Page Spec 直达材料模式的关键入口均按原有行为通过。
- **产物与成本**：原有正式产物仍按本分支入口被识别，预览和下游交接可运行，不出现旧交接读取报错或新增清单。对改动执行差异及引用检查。若比较耗时或 token，记录相同输入和对应阶段的实际数据；无法取得则标为未验证。单次短样本的核对时间不能证明整个流程变快。

只有上述适用项通过才完成切换。实施后在本节追加实际样本、逐项结果、发现的偏差和未验证环境。
