# 页面事实交接减负优化 V1 实施文档

- 输出时间：2026-11-25 09:56:19 +08:00
- 范围：`only-uxb`、`only-plugin`、`only-x-cp` 的 PRD Review → 正式需求基线 → Page Spec。
- 状态：三个分支已修改，本地验收见第 6 节；实际宿主验收待验证。V0 保留为历史记录。

## 1. 目标与范围

新运行停止生成、要求传入和读取独立的 `page-generation-handoff.md`。已确认的页面事实在正式基线中写一次。PRD Review 复用现有冻结前自检核对原始来源，Page Spec 在设计前提取内部清单，交付前逐项确认落点。内部清单只用于本次运行，无需另存文件或引入公开 HF 编号。

仅变更页面事实的保留与交接。知识覆盖、业务闭环、候选问题回查、阻断与回复关闭、Page Spec 设计判断和实体覆盖标准沿用现有规则。各分支原有产物名称、章节、状态、登记、预览、宿主输入和固定下一步交接维持现行合同。资料未确认时继续按原审核门禁处理。

## 2. 三分支共用规则

### 2.1 PRD Review 写入与冻结前检查

在各分支的 `.agents/skills/prd-review/SKILL.md` 和 `references/output_structure_guide.md` 对齐总规则、§4 任务表达、禁止输出项及自检。输出规范负责详细写入规则，Skill 入口引用该规范。三分支总规则采用以下已通过隔离 A/B 的原句：

> PRD Review 保留正式来源已确认、会影响操作或验收的页面事实，包括选项、字段、默认值、交互条件和固定文案。未经确认的控件选型、页面排版、交互方案和文案，由 Page Spec 在设计阶段确定。原型中的示意内容不能作为已确认要求。

- 已确认三个选项及多选，保留选项名称、数量和多选；未指定控件类型时留给 Page Spec。只有明确成为需求约束的行为或控件语义才保留，例如「点击后打开弹窗，取消保留原选择」。
- 已确认的按钮名称、提示语和文案变量按来源精度保留。若来源只要求成功反馈，保留反馈要求。未确认的默认项、顺序或完整枚举不得从示例推导。
- 充分保留多条件和多对象的归属。单独能遗漏的成员各可核对；同一触发、条件和结果仍组成完整事实。

基线沿用现有章节，各事实在职责章节完整写一次，可用既有编号或可定位来源短引：

- §2 写对象变更与关系，§3 写角色可见和可操作范围。
- §4 在所属任务内写入口、载体、字段、Tab、操作、确认和返回。正常反馈按所属动作或结果落位，页面展示字段也在所属任务承载。
- §5 写显示条件、选项范围、默认值、必填、数量、格式和校验次序。§6 写状态及可见变化，§7 写异常、提示、阻断和恢复。
- §8 写实际记录的数据、系统承接和回写。§9 写明确排除。§10 沿用已确认体验约束、待定案及按需输出规则。§11 沿用可观察验收，引用既有事实。
- 无需新增「页面事实」章节或额外二级标题。实际保存字段与页面展示字段按各自职责表达。

在现有基线自检里，复用本轮已经读取的有效来源和内部事实表。**对同一处事实一次检查漏项、错位、值或条件变动、凭空补写。** 至少检查所属对象、并列成员、条件、精确值和可观察结果。来源已明确但基线遗漏，回对应章节补齐；冲突或关键事实未定，走原门禁。产品已明确覆盖的旧结论不列为漏项。零阻断直出和产品回复后冻结共用这一步。复核针对有问题的事实，无需为页面细节增加一次独立全文扫描。

### 2.2 Page Spec 内部清单与两次核对

修改各分支 `.agents/skills/page-spec/SKILL.md` 的执行顺序、正式基线入口、HF 核对段及自检。保留各自来源绑定和正式知识消费方式。

1. 绑定并完整读取本轮正式基线后、设计推导前，以页面、Tab、模块、弹窗、字段、动作或状态等实际对象提取「事实、所属条件、基线出处」。查 §2–§9，用 §11 反查有无遗漏；§10 按现行方式单独承接。兼容现行规则接受的基线，不以新版标题截断旧版有效内容。清单只由当前绑定基线建立，新版本基线重新提取。
2. 首次正式输出或登记前，逐项定位草稿中的结构、字段、动作、状态、反馈或文案。沿用现有完整覆盖标准，实体名称、入口或流程提及不能代替完整规格。对照清单也反查新增内容是否扩大了权限、枚举、默认值或改换归属。确定的漏项和错项先修正，复查受影响实体和流程，再提交。
3. 将同一清单并入现有输出自检，核对实际落盘或最终提交的正文。有读回能力时复核已交付正文；宿主仅接收返回内容时在返回前核对最终完整正文。发现偏差时走该分支现有修改或重新登记流程。用户明确指定原始材料直达 Page Spec 时，维持该输入模式及其门禁。

## 3. 分支改动及校验边界

### only-uxb · 本地 Markdown

- PRD Review 移除 `PAGE_FACT_PROJECTION`、冻结后投影步骤与旧参考入口；保留基线、问题单和进度预览。
- Page Spec 使用本轮已绑定的 `spark-output/requirements_baseline.md`，以内部清单替换文件查找、身份判断、HF 编号和缺文件提示；保留 `spark-output/page_spec.md`。
- 验收本地目录没有 HF 时链路正常。有旧 HF 或跨需求 HF 时，仍按本轮基线输出，已存在的历史文件不得被新流程覆盖或清理。

### only-plugin · DSH 工作台

- PRD Review 已无活跃的单独 HF 生产步骤。只对齐 §2.1 的事实写入及自检，保留工作台交接路径。
- Page Spec 使用工作台绑定的正式基线，替换残留的 HF 和写盘后按 HF 追加的说法。完整性检查在第一次调用 `submit_design_artifact` 前完成。继续提交最终完整 Markdown，不向 `spark-output/` 根目录写入替代品。
- 同步更新 `shared-workflow/skill-graph.json` 中 Page Spec 关于 `page-generation-handoff.md` 和写盘后追加的旧说明。保持工作流的正式依赖和下一步配置。
- `runtime/artifacts.js` 检查现有 Markdown 标题、章节与 `formal` 等约束，没有 HF 门禁。保留原校验、产物类型、任务绑定、文件名和登记流程。在现有登记入口回归审核记录、正式基线和 Page Spec，并证明现行非法格式仍被拒绝。若新内容触发校验，先修正 Skill 输出以符合现行合同。
- 核查打包清单能带入新 Skill 和工作流说明，且无退役参考。用只读打包预检或隔离打包产物核验，不用默认会提升版本的打包入口改变版本。工作台集成验证与打包文件清单分别记录。

### only-x-cp · 内网宿主 Markdown

- PRD Review 移除投影步骤、状态标记和旧参考入口。Page Spec 移除从用户、宿主及本地默认路径读取 HF 的规则。
- 保留宿主或用户明确传入同源基线的现有路径及 `requirements_baseline.md` → `page_spec.md` 合同。宿主只传基线时应能完成。即使宿主同时传了旧 HF，也不能把它当成业务来源或缺失基线的替代品。
- 核对内网交付目录和宿主调用说明是否仍要求 HF。实际宿主需验证实际传入、读取、产出或登记全链；本地验证只证明包内规则与 Markdown 接口。如宿主仍把 HF 设为必传，先补齐接口迁移或暂停该分支切换。

三个分支的 `.agents/skills/prd-review/references/page_generation_handoff.md` 在活动引用归零后退役。仓库已知历史 Spec、正式产物和用户输入均保留。历史单独交接如包含基线未有信息，只在用户明确绑定的迁移样本中查有效来源，确认后通过正式基线路径补齐。

## 4. 实施顺序与恢复

1. 三条分支在对应工作树分别核对干净度、活动引用、真正规范和宿主契约。保留已有工作区改动，禁止跨分支复制整份 Skill。发现额外的活动生产方或消费者，先核实其输入输出和迁移条件。
2. 各分支先把保留规则并入现行基线自检，再接入 Page Spec 内部清单。无 HF 的隔离样本通过后，生产、读取、提示和引用在本分支同批退出。删除旧参考前复查调用、图说明、包清单、预览和交付材料。
3. 运行第 5 节公共及分支验收，逐支记录结果。三个分支均通过适用项，才报告三分支迁移完成。宿主验证不可用时，明确区分已验证的本地改动和未验证的运行环境。
4. 出现旧活动消费者仍依赖 HF、原有登记或宿主交接失败、明确事实丢失或被改错时，停止该分支切换。在隔离工作树以同批变更为单位恢复该分支原生产与消费；`only-plugin` 恢复其实际原有规则。保留样本和证据，修复后重跑相关边界，避免留下半套迁移或永久双写。

## 5. 验收标准

**共同验收**

- 从不同业务原始输入实际生成基线，再用该基线生成 Page Spec。用预先确定的事实逐项检查，两段均须保留已确认的成员、字段、默认值、权限和条件。覆盖明确的交互结果、仅供参考的原型、可用与停用但枚举未声明完整等不同证据边界。未声明内容不能被补全。
- 两段链路分别试验同一 Agent 起草后自检。由外部在隔离候选稿故意移除一处已确认字段，另造漏 Tab 或默认值反转。Agent 在正常检查点读回本段候选稿，只知道执行核对，不知道预埋点。验收要求定位上游出处及受影响的正文，保留正确对照，修正后复核最终输出。该试验只用于验收，不为正式 Skill 新增外部审查器、写盘流程或持久新清单。
- 覆盖首次零阻断直出、有效产品回复后冻结、仍有阻断时停止。覆盖 §10 有和无、各分支当前接受的旧版基线、用户明确指定原始材料直达。新链路不创建或要求 HF，也不被陈旧或其他任务的 HF 影响。现有正式输出格式、预览和下游入口继续通过。
- 对三分支差异和活动引用做终检。按第 3 节分别核对本地预览、工作台登记与打包、内网宿主输入输出。每个测试记录输入、来源落点、产物、通过或失败以及无法验证项。耗时和 token 仅按有可比证据的阶段报告。

**已有证据**

- **总规则措辞 A/B**。两个合成业务用例，两组独立上下文，需求、辅助原型和参考规范相同。候选组只替换 §2.1 所引总规则。已确认事实完整保留由现行规则的 12/22 项提高至候选规则的 22/22 项，两组均有 0/10 项原型示意误作要求。四份基线均为正式状态。现行组漏掉了部分已确认的 Tab 结构、弹窗行为和固定文案，候选组保留了这些细节。两组都把批次展示字段写进 §8，说明本次单行试验还没有验证 §4 与 §8 的职责归属，实施后按共同验收检查。 [总规则 A/B 报告及基线](/E:/AI设计/体验蓝图构建思路/spark-output/prd-rule-wording-ab/results.md)
- **交接替换 A/B 与防漏盲测**。四个合成业务样本的文件交接与内部清单 A/B 都覆盖了 62/62 项。两种路径均出现过把已知状态扩成完整枚举的问题。独立盲测找到了 3/3 处预埋的遗漏或错误，4 项正确对照未误报。

上述证据支持进入实施。章节归属、同一 Agent 自检、三分支真实入口、宿主行为和净成本仍待实施后验证。切换完成仍以本节及各分支适用验收为准。
