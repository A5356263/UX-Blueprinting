## 1. 知识定位

这是一份权限域的页面路由关系卡，用来回答“权限域内部页面之间如何跳转，以及它与审批、应用等外部模块之间有哪些关键路由关系”。

它比能力地图更强调页面之间的链路连接。

## 2. 任务触发线索

当任务需要梳理权限页之间的上下游跳转、配置链路与解释链路的连接方式，或需要说明权限域如何跨到审批与应用模块时，应优先读取本文件。

## 3. 覆盖内容

本文件覆盖权限域的主要路由链路，重点包括：

- 配置链路：
  - `用户授权 -> 功能授权 -> 数据授权`
  - `用户授权 -> 权限详情`
  - `角色管理 -> 授权规则`
  - `角色管理 -> 功能权限 / 数据权限`
  - `权限管理模式 -> 子管理配置页 / 双管理员模式配置页 / 权限变更审批模式配置页`
  - `应用管理 -> 应用设置页`
- 解释链路：
  - `用户授权 -> 权限详情`
  - `权限查询 -> 按用户查询结果 -> 权限明细`
  - `权限详情 -> 应用管理`
- 外部治理链路：
  - 权限变更审批配置页通往审批管理、协同办公审批列表
  - 应用设置页与通用审批产生外部连接
  - 功能授权可引向应用中心
- 路由说明：
  - 按人配置是主链路
  - 角色管理到授权规则是模板化授权扩展链路
  - 查询链路负责解释，不负责配置
  - 权限管理模式链路承担系统级治理

## 4. 可直接使用的稳定结论

- 权限域内部同时存在配置链路、解释链路和外部治理链路三种主要路由类型。
- `用户授权 -> 功能授权 -> 数据授权` 是按人授权的稳定主链路。
- `权限查询 -> 按用户查询结果 -> 权限明细` 是解释与排障链路，不应误写成配置链路。
- 权限变更审批、通用审批和应用设置页说明权限域天然需要跨模块协作，而不是完全封闭在本域内。
- 页面路由关系本身就是权限语义的一部分，因为它决定用户如何进入、解释和完成治理动作。
