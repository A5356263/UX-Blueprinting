# 功能权限

## 0. 文件定位

- 页面类型：Concept Page
- 概念名称：功能权限
- 适用范围：权限域中的菜单、页面、操作点、终端维度授权语义
- 不处理内容：数据范围口径、应用入口是否可见、审批流程实现细节

## 1. 结论

- 功能权限回答的是“主体能在某个系统里做什么”，而不是“能看到哪些数据”或“能否看到应用入口”
- 在当前仓库语义中，功能权限通常以菜单、页面、按钮、操作点的方式被配置，并且可细化到导出、排序、核验详情等原子动作
- 功能权限是数据权限的上游前提之一；没有对应功能权限时，数据范围通常没有独立配置意义
- 功能权限既可按人直授，也可通过角色模板化分发，还可被单应用管理员治理链路复用

## 2. 适用范围与边界

- 定义边界：覆盖“页面/功能/操作点是否可执行”的授权结果
- 非目标：不覆盖“数据能看到多少”“应用图标是否出现”“成员之间是否互相可见”
- 常见误解：
  - 把功能权限和数据权限混成一个笼统的“权限配置”
  - 把应用可见性当成后台功能操作权
  - 把查询页中的权限结果展示误当成配置动作

## 3. 主体内容

### 3.1 概念定义

- 功能权限是对业务能力操作面的授权
- 它控制的不是抽象“有权限/没权限”，而是主体是否可以访问某些菜单、进入某些页面、触发某些按钮或执行某些原子操作
- 在当前权限域中，功能权限同时带有终端维度差异，电脑端与移动端可分别查看或配置

### 3.2 判定规则

- 功能权限通常先于数据权限被表达
- 当页面或功能点存在实名、应用开通等前置条件时，功能权限的最终可用性会受到这些条件约束
- 功能权限可存在父子级联、全选、半选、未选等结构化状态
- 功能权限的配置入口可出现在：
  - `用户授权 -> 功能授权`
  - `角色管理 -> 功能权限`
  - `应用设置页 -> 用户授权区 -> 功能权限`

### 3.3 与相近概念的区分

- 与数据权限的区分：
  - 功能权限决定能不能操作
  - 数据权限决定能操作或查看哪些数据范围
- 与应用可见性的区分：
  - 应用可见性决定入口是否出现在工作台
  - 功能权限决定进入后能使用哪些后台能力
- 与协作可见性的区分：
  - 协作可见性控制成员之间信息能否互见
  - 功能权限控制系统功能能否执行

## 4. 关键关系

- 上位概念：权限域、授权结果、终端差异
- 下游对象：`功能授权`、`角色管理`、`应用设置页`
- 常见组合关系：
  - 功能权限 + 数据权限
  - 功能权限 + 应用开通前置条件
  - 功能权限 + 角色模板

## 7. 缺口与冲突

- [GAP] 当前仓库中 `数据授权` 页的页面事实尚未补齐，因此“功能权限决定哪些数据配置分支会出现”的完整合同还未完全落稳
- [GAP] 按权限查 / 按功能点查的结果承载页尚未核实，暂不能完整反推功能权限查询语义
- [CONFLICT] 暂未发现直接冲突，但后续若出现“入口可见即视为有功能权限”的说法，应视为与当前定义冲突
