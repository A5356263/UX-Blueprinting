# 单应用管理员治理

## 0. 文件定位

- 页面类型：Concept Page
- 概念名称：单应用管理员治理
- 适用范围：应用设置页中对单个应用后台管理者的授权、范围和跨模块串联语义
- 不处理内容：应用市场接入、应用研发流程、工作台整体信息架构

## 1. 结论

- 单应用管理员治理回答的是“谁能管理某一个应用的后台能力，以及管理入口如何和应用入口治理解耦”
- 在当前权限域中，它主要由 `应用设置页` 承载，且与“前台入口可见性”同页共存
- 单应用管理员治理不等于应用可见性；能看见应用入口的普通员工，不等于能管理该应用后台
- 单应用管理员治理通常会复用功能权限、数据权限和外部审批配置入口

## 2. 适用范围与边界

- 定义边界：覆盖单一应用内的管理员授权、后台功能/数据权限配置、与审批等模块的串联
- 非目标：不覆盖企业级应用台账总览，不覆盖普通员工前台访问路径，不覆盖全局治理模式本身
- 常见误解：
  - 把应用设置页里的全部内容都理解为入口可见性
  - 认为能配置应用可见范围的人自动拥有后台管理权
  - 认为单应用管理员治理与通用权限管理是两套完全无关的体系

## 3. 主体内容

### 3.1 概念定义

- 单应用管理员治理是对“某个应用后台由谁管理、管理到什么粒度”的治理模型
- 它通常发生在 `应用管理 -> 应用设置页` 的单应用下钻场景中
- 这类治理同时需要回答：
  - 谁能管理该应用
  - 能管理哪些后台功能
  - 能管理哪些数据范围
  - 还要串联哪些外部治理入口

### 3.2 判定规则

- 单应用管理员治理的主承载路径为：
  - `应用管理 -> 应用设置页`
- 在 `应用设置页` 内，通常存在两套并列但不能混淆的语义：
  - 入口治理：可见范围 / 禁用范围 / 子功能启停
  - 管理员治理：对人员配置功能权限 / 数据权限
- 该路径可继续引流到 `通用审批` 等外部治理能力

### 3.3 与相近概念的区分

- 与应用可见性的区分：
  - 应用可见性决定普通使用者是否看到入口
  - 单应用管理员治理决定后台管理者是否有权操作该应用
- 与全局治理模式的区分：
  - 单应用管理员治理是应用粒度
  - 治理模式体系是系统粒度
- 与角色模板化授权的区分：
  - 角色模板化授权强调跨人群复用
  - 单应用管理员治理强调单应用内的治理闭环

## 4. 关键关系

- 上位概念：应用可见性、功能权限、数据权限、跨模块串联
- 下游对象：`应用管理`、`应用设置页`
- 常见组合关系：
  - 单应用管理员治理 + 入口治理
  - 单应用管理员治理 + 通用审批
  - 单应用管理员治理 + 终端差异
