# 角色模板化授权

## 0. 文件定位

- 页面类型：Concept Page
- 概念名称：角色模板化授权
- 适用范围：权限域中通过角色定义能力包、批量分发权限、绑定自动授权规则的语义
- 不处理内容：单次临时直授、审批引擎实现、具体视觉交互布局

## 1. 结论

- 角色模板化授权回答的是“如何把一组稳定权限打包成可复用模板，再分发给多人”
- 在当前权限域中，角色不是最终结果本身，而是承接功能权限、数据权限与成员绑定的中介层
- 角色模板化授权既能降低重复配置成本，也能与授权规则组合，形成随组织属性自动授予与回收的机制
- 角色页承担的是模板化授权职责，不能被误写成单人排障页

## 2. 适用范围与边界

- 定义边界：覆盖角色创建、角色成员管理、角色功能权限、角色数据权限、角色授权规则
- 非目标：不覆盖应用入口可见性，不覆盖成员协作可见性，不覆盖查询排障本身
- 常见误解：
  - 把角色当作最终权限来源的全部解释
  - 把角色管理当作单人授权入口
  - 把授权规则和角色模板分离成两套完全无关机制

## 3. 主体内容

### 3.1 概念定义

- 角色模板化授权是把一组职责相近的权限打包成稳定模板，再把成员绑定到该模板上
- 模板本身可包含功能权限与数据权限，并可叠加自动授权规则
- 这种方式适合处理多人共岗、组织规模大、人员变动频繁的场景

### 3.2 判定规则

- 角色模板化授权的典型路径为：
  - `角色管理 -> 功能权限 / 数据权限`
  - `角色管理 -> 授权规则`
- 标准认知顺序应是：
  - 先定义角色职责
  - 再配置功能权限
  - 再配置数据权限
  - 再决定是否增加自动授权规则
- 当成员属性满足规则时，角色可自动授予；不再满足时可自动回收

### 3.3 与相近概念的区分

- 与按人直授的区分：
  - 直授解决单体快速治理
  - 角色模板化授权解决多人复用与长期维护
- 与应用可见性的区分：
  - 角色模板不等于应用入口一定可见
  - 应用入口可见性仍需由应用治理链路控制
- 与查询页的区分：
  - 角色管理负责构造模板和分发
  - 查询页负责解释最终结果

## 4. 关键关系

- 上位概念：功能权限、数据权限、自动授权、模板化治理
- 下游对象：`角色管理`、`授权规则`
- 常见组合关系：
  - 角色模板化授权 + 成员批量分发
  - 角色模板化授权 + 自动授权规则
  - 角色模板化授权 + 查询结果解释
