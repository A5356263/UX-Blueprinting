# 反馈与报错

本目录用于沉淀可跨业务复用的反馈与报错体验设计知识。

这里关注的是：用户在权限不足、校验失败、状态阻断、网络异常、外部系统失败等场景下，应该在什么位置看到什么形式的反馈，以及文案如何解释原因和下一步。

这里不负责定义报错治理系统、前后端实现方案或成效指标系统。

## 当前结构

- `04_人事与薪酬场景案例.md`

## 阅读方式

1. 先读 `00_反馈与报错体验设计指南.md`，理解范围、边界和总体原则。
2. 再读 `01_反馈形式选择原则.md`，判断反馈位置、反馈形式和反馈时机。
3. 再读 `02_报错与状态文案模板.md`，提取可复用文案和反例。
4. 再读 `03_通用报错场景案例.md`，查找权限、状态、校验、网络等通用场景。
5. 需要人事薪酬语境时读 `04_人事与薪酬场景案例.md`。
6. 需要财税语境时读 `05_财税场景案例.md`。

## 边界

- 放体验设计判断依据，不放实现细节。
- 放反馈形式和文案原则，不放组件方案或前端规则清单。
- 放可复用场景素材，不把业务事实判断替换掉。

## 维护原则

- 新增内容优先归入现有编号文件，不回退成单一长文。
- 目录内只保留稳定知识，不写讨论过程、导入说明或候选状态。
- 调整 raw 后，同步使用 `knowledge/scripts/update_wiki.py` 刷新 wiki summaries 与索引。
