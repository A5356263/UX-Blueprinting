1. 定位

本目录用于存放跨业务、跨产品复用的通用设计原则（方法论/认知/可用性/无障碍等）。
用于支持 S3 在产出设计文档时进行体验推导与自检。

本库只包含：

原则与方法论（可用性、认知负担、信息架构、可读性、视觉层级、无障碍、治理与信任等）

原则如何转译为“体验要求/风险点/检查问句”（原则层表达）

本库不包含：

任何业务逻辑、业务流程、产品功能规则（这些属于 Business Knowledge / 产品规范）

UI 组件方案、页面布局、视觉规范、工程实现细节

2. 目录结构

index.md：本说明文件（定位、结构、使用方式、维护规则）

trigger_index.md：触发索引（场景/风险 → 推荐原则 ID；含自动维护的“未映射原则”提示区）

guidelines.md：原则正文合并文件（按标题分段维护）

3. 使用方式（原则库怎么被用）

S3 根据当前任务识别“场景/风险类型”

在 trigger_index.md 中找到对应场景，获取推荐原则 ID

到 guidelines.md 中按标题/原则 ID 查对应原则内容，用于推导设计要求与自检

注意：S3 输出时“如何标记引用了哪些原则/如何在模板里呈现引用”，属于 S3 Agent Prompt 的职责，不在本知识库里定义。

4. ID 命名约定（用于索引与引用）

建议使用统一前缀，便于检索与裁剪：

U- 可用性原则（如 Nielsen）

ISO- ISO 9241-110 交互原则

C- 认知/决策/负担

IA- 信息架构/可发现性

V- 视觉层级/格式塔

R- 可读性/文案/术语一致

G- 治理/信任/可解释性/可追溯/安全

A11Y- 无障碍/包容性

Q- 质量评估框架

L- 交互定律与偏差（可选扩展）

5. 裁剪原则（避免注入过多）

按场景裁剪：只使用与当前场景匹配的原则（以 trigger_index.md 为入口）

按风险优先：高风险/不可逆/权限与安全相关场景优先使用治理与可解释性原则

按任务类型裁剪：表单/列表/搜索/配置/批量/流程/多角色等只拿对应原则

6. 维护规则

新增/调整原则：应同步更新 trigger_index.md 主表映射；系统会自动维护“未映射原则”提示区并回填 guidelines.md 的触发索引嵌入段

保持“原则层”纯净：发现混入业务规则/产品特例/实现细节应移出本库

避免重复：相近原则合并，保留一个主条目，其他用补充说明即可
