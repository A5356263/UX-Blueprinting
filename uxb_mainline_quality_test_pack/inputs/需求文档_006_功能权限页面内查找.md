# 刁钻测试需求文档：功能权限设置支持页面内查找 / 筛选（混淆版）

> 用途：验证 AI 是否能识别“查找”和“筛选”的本质区别，避免因为需求发生在权限页面就过度消费权限业务知识。

---

## 1. 需求背景

当前功能权限设置页面权限项非常多：

- 末级菜单 1100+
- 操作功能点 1200+
- 页面滚动约 35 屏

权限管理员配置或核对权限时，经常需要找某个功能点、菜单、已勾选权限项。现在只能滚动查找，效率低，也容易漏看。

希望增加一个“搜索 / 筛选 / 页面内查找”的能力，帮助管理员快速找到目标权限项。

---

## 2. 目标

本次希望：

1. 输入关键词后快速定位到命中的权限项。
2. 命中文字高亮。
3. 支持多个命中项之间切换。
4. 无命中时提示无结果。
5. 希望也能快速查看“已勾选权限”。
6. 查找过程中不能影响已勾选但未保存的权限。
7. 不希望用户误以为权限范围被系统自动改变。

---

## 3. 用户与角色

### 3.1 权限管理员

为员工、管理员或角色配置功能权限时，需要快速查找目标权限项。

### 3.2 实施 / 运营人员

协助客户核对权限配置，需要快速定位已授权或需要调整的权限项。

### 3.3 被授权对象

可能是员工、角色、子管理员或其他授权主体。具体支持范围未确认。

---

## 4. 核心场景

### 4.1 查找某个权限项

管理员知道权限名称或关键词，希望快速定位。

### 4.2 核对已勾选权限

管理员想快速看到当前对象已勾选了哪些权限。

### 4.3 纠正权限配置

管理员通过关键词找到权限项，并调整勾选状态。

### 4.4 大量权限场景减少滚动

权限项非常多时，管理员希望减少逐屏查找。

---

## 5. 功能范围

| 功能 | 初步说明 |
|---|---|
| 查找入口 | 在功能权限设置区域提供输入框 |
| 关键词匹配 | 匹配权限名称、菜单名称、操作点名称 |
| 命中高亮 | 匹配文字高亮 |
| 自动定位 | 输入后定位到第一个命中项 |
| 命中切换 | 支持上一个 / 下一个命中项 |
| 无命中提示 | 提示“未找到匹配内容” |
| 已勾选查看 | 希望支持只看已勾选权限 |
| 清空恢复 | 清空关键词后恢复页面 |
| 数据埋点 | 统计查找使用次数和命中情况 |

---

## 6. 初步交互规则

### 6.1 查找入口

1. 查找输入框建议放在功能权限设置区域顶部。
2. 输入关键词后实时查找，不需要点击按钮。
3. 可以支持 Ctrl + F 唤起。
4. 输入框是否常驻未确认。
5. 需要显示命中数量，例如“1/28”。

### 6.2 查找与筛选的混合诉求

业务方当前有几种说法：

- 说法 A：这是页面内查找，不能改变页面数据范围，所有权限项仍然展示，只做高亮和定位。
- 说法 B：管理员其实想快速看已勾选权限，所以最好能只显示已勾选项。
- 说法 C：输入关键词后最好只显示命中项，否则页面还是太长。
- 说法 D：不能让用户误以为没有显示的权限被取消，所以不应该隐藏未命中项。

当前未确定最终采用“查找”还是“筛选”，业务方暂时都叫“搜索”。

### 6.3 高亮规则

1. 页面中所有匹配关键词的文字都需要高亮。
2. 当前命中项需要比其他命中项更明显。
3. 关键词清空后，高亮消失。
4. 命中项如果在折叠节点内，需要让用户看得到。
5. 是否自动展开折叠节点未确认。
6. 如果自动展开，清空关键词后是否恢复原折叠状态未确认。

### 6.4 定位规则

1. 输入关键词后自动定位到第一个命中项。
2. 支持上一个 / 下一个命中切换。
3. 切换时页面跟随滚动。
4. 如果命中项很多，切换可能有性能问题。
5. 如果关键词只有一个字，可能命中非常多，需要考虑是否限制。

### 6.5 已勾选查看规则

1. 有业务方希望增加“只看已勾选”。
2. 也有人认为“只看已勾选”属于筛选，不属于页面内查找。
3. 如果只看已勾选，需要明确未勾选项是否暂时隐藏。
4. 如果隐藏未勾选项，编辑时是否还能继续勾选新权限未确认。
5. 如果只看已勾选后取消某项勾选，该项是否立刻从列表消失未确认。
6. 如果只看已勾选和关键词查找同时存在，优先级未确认。

### 6.6 编辑状态保护

1. 查找或筛选过程中，不应自动保存权限。
2. 查找或筛选过程中，不应丢失未保存的勾选状态。
3. 清空关键词后，用户之前的勾选状态应保持。
4. 如果切换“只看已勾选”，未保存的变更是否参与判断未确认。
5. 如果当前已经勾选但未保存，是否算“已勾选”未确认。

---

## 7. 可能存在的误导性诉求

以下说法来自不同人，未统一：

1. 输入关键词后只显示命中的权限，其他都隐藏。
2. 不能隐藏任何权限，否则管理员会以为权限没了。
3. 最好做成筛选已勾选权限，方便核对。
4. 不是筛选，只是类似浏览器 Ctrl + F 的页面查找。
5. 查找时如果命中折叠节点，就自动展开。
6. 展开后清空关键词应该恢复原来的折叠状态。
7. 展开后清空关键词不要恢复，否则用户刚看到的位置又没了。
8. 查找操作不需要记录操作日志。
9. 搜索权限是安全相关行为，最好也记录。
10. 查找只是前端交互，不应该进入权限审计。

---

## 8. 已知风险

### 8.1 查找和筛选混淆

如果同时支持查找和只看已勾选，用户可能不清楚当前看到的是“全部权限中的定位结果”，还是“过滤后的权限集合”。

### 8.2 权限误解风险

如果隐藏未命中项或未勾选项，用户可能误以为这些权限被取消或不存在。

### 8.3 编辑状态风险

用户在查找 / 筛选过程中勾选或取消权限时，系统必须保证未保存状态不丢失。

### 8.4 折叠节点风险

命中项在折叠节点内时，如果不展开，用户看不到；如果自动展开，又可能改变用户原来的浏览状态。

### 8.5 性能风险

权限项数量较多，大量高亮、自动展开和滚动定位可能造成页面卡顿。

### 8.6 适用范围风险

当前来自功能权限设置页面，但是否扩展到数据权限、角色权限、子管理员权限、组织权限未确认。

---

## 9. 初步文案

- 输入框 placeholder：搜索权限名称
- 无命中：未找到匹配内容
- 命中计数：第 1 / 28 个
- 大量命中：匹配结果较多，请输入更完整的关键词
- 只看已勾选：仅展示已勾选权限
- 清空：清除搜索

## 10. 不明确事项

请结合业务知识和体验判断，区分哪些是查找、哪些是筛选、哪些不应混在本次做：

1. 本次到底是页面内查找，还是筛选已勾选权限？
2. 是否应同时支持关键词查找和只看已勾选？
3. 如果支持只看已勾选，它是否属于本次范围？
4. 查找是否改变页面展示范围？
5. 筛选是否改变页面展示范围？
6. 隐藏未命中项是否会造成权限误解？
7. 查找是否需要记录操作日志？
8. 只看已勾选是否需要记录操作日志？
9. 未保存勾选状态是否参与“已勾选”判断？
10. 折叠节点命中后是否自动展开？
11. 清空关键词后是否恢复折叠状态？
12. 大量命中时是否限制关键词长度？
13. 是否支持拼音、大小写、模糊匹配？
14. 是否支持操作功能点名称匹配？
15. 是否扩展到数据权限或其他权限配置页？
16. 查找入口是常驻还是快捷键唤起？
