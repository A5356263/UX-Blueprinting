## 3. Story 详情

### ST01. 复制已有子管理员的配置给新子管理员

- **Persona**：超级管理员
- **场景**：在子管理配置页，已有至少一个配置完成的子管理员，需要将相同配置授予另一个用户
- **目标**：避免重复勾选相同的功能权限
- **优先级**：P0
- **来源依据**：上游 recommended_direction 核心操作；confirmed_facts：复制完整配置、粘贴后可微调

**用户要完成什么**

作为超级管理员，我想选择一个已有子管理员作为来源，将其完整配置（功能上限 + 组织范围）复制给另一个用户，从而无需重新逐项勾选相同的功能权限。

**完成标准**

- 超管可以从已有子管理员列表中选择一个来源
- 超管可以指定一个目标用户
- 复制操作将来源的完整配置（功能上限 + 组织范围）应用到目标用户
- 复制为一次性快照，来源后续变更不影响已复制的目标
- 复制完成后超管可以立即进入微调（尤其是组织范围修改）
- 目标用户原有配置被覆盖前有明确的提示和确认

**设计触点**

- 涉及页面 / 场景：子管理配置页（列表 + 详情/编辑视图）
- 涉及组件类型：选择器（人员选择器）、操作触发按钮、覆盖确认弹窗、操作结果反馈提示
- 涉及状态：复制前（来源配置正常/来源配置异常）、复制中（处理中）、复制完成（成功/失败/部分失败）
- 涉及交互模式：选择 → 确认 → 执行 → 结果反馈 → 可选进入微调

**风险或待验证点**

- 目标用户已经是子管理员时，配置覆盖策略需要产品明确（全量覆盖 / 合并 / 提示保留）→ 上游 open_gap
- 复制操作是否需要审批 → 上游 open_gap
- 假设：子管理配置页现有数据模型支持配置复制写入（working_assumption）

### ST02. 一次复制到多个目标用户

- **Persona**：超级管理员
- **场景**：集团客户新上线，需要一次创建 200+ 子管理员，已配置好一个基准子管理员
- **目标**：消除逐个操作的低效，实现一次配置多次扩散
- **优先级**：P1
- **来源依据**：上游 target_scenarios "首次批量创建子管理员"；working_assumption：覆盖批量创建

**用户要完成什么**

作为超级管理员，我想从一个已配置的子管理员出发，一次性将配置复制给多个目标用户，从而在超大批量场景（如 200+）下快速完成子管理员体系搭建。

**完成标准**

- 超管可以在复制流程中选择多个目标用户（而非仅单个）
- 系统展示所有待创建子管理员的复制结果，包括成功、失败和原因
- 部分目标用户复制失败时，不阻塞整体流程
- 批量复制后，每个目标子管理员均可独立进入微调

**设计触点**

- 涉及页面 / 场景：子管理配置页、批量操作区
- 涉及组件类型：批量人员选择器、批量操作进度条、批量结果汇总面板
- 涉及状态：批量复制准备中、批量执行中、批量完成（全部成功 / 部分成功 / 全部失败）
- 涉及交互模式：选择来源 → 批量选择目标 → 确认 → 批量执行 → 结果汇总 → 逐人微调入口

**风险或待验证点**

- 200+ 批量操作的后端性能和事务处理策略
- 批量失败时的重试和局部回滚机制
- 假设：批量复制场景足够高频，值得在 P1 引入（working_assumption）

### ST03. 在列表中识别子管理员的配置来源

- **Persona**：超级管理员
- **场景**：子管理员数量较多时（如 200+），快速了解整体配置状况，识别配置一致性和差异
- **目标**：提升配置的可管理性和可审计性
- **优先级**：P1
- **来源依据**：上游 OP4 "配置差异可视化"；experience_focus "配置差异可视化"

**用户要完成什么**

作为超级管理员，我想在子管理员列表层快速看到每个子管理员的配置概览，包括其功能上限来源和组织范围，从而在维护和审计时快速定位异常或确认一致性。

**完成标准**

- 子管理员列表展示每个子管理员的关键配置摘要（功能上限概览 + 组织范围摘要）
- 列表层提供标记或提示，表明哪些子管理员通过复制方式创建
- 超管可以通过筛选或排序快速找出配置相同的子管理员群体

**设计触点**

- 涉及页面 / 场景：子管理配置页（列表视图）
- 涉及组件类型：列表行扩展信息、配置摘要标签、筛选器/排序器、配置来源标记
- 涉及状态：列表加载态、空态（无可展示的子管理员）、正常展示态
- 涉及交互模式：列表内信息展开/收起、筛选条件切换、排序切换

**风险或待验证点**

- 配置摘要信息的详细程度需要平衡信息密度和可读性
- 如果子管理员配置项较多，列表层展示效果可能受限
- 该 Story 属于体验增强，不应阻塞 ST01 的交付
