# 用户故事：子管理员权限复制能力

## 1. 来源与方向

- **来源**：`problem-framing`（问题框定）
- **项目名**：子管理员权限复制能力
- **方向**：权限复制工具——从源子管理员复制完整权限（全部子应用的菜单权限 + 数据权限）到一或多个目标子管理员，复制后目标可逐项检查和修改
- **主角色**：企业超管（主管理员）
- **约束**：不改变权限模型结构、不跨企业复制、不新增角色/模板抽象层、本轮不做批量差异编辑 UI
- **下游承接要求**：选择源和目标的方式、复制后微调的交互形态、权限项搜索和筛选、数据权限复制细节、操作记录与审计

## 3. Story 详情

### S1. 选择源子管理员并查看权限全景

- **Persona**：企业超管
- **场景**：企业规模大，已存在多个子管理员，职责分布在各业务线
- **目标**：快速定位权限配置最接近需求的现有子管理员，确认其权限结构
- **优先级**：P0
- **来源依据**：方向 A（权限复制工具）的必需前置步骤；`handoff_requirements` 第 1 项

**Story 主体**

作为企业超管，我想从子管理员列表中选出一个作为复制源，并查看其在全部子应用下的菜单权限和数据权限的全景概览，从而确认这是合适的复制来源。

**完成标准**

- 超管可以从子管理员列表中选择一个作为源
- 选中后可以看到该子管理员在全部子应用下的权限总览
- 总览应区分菜单权限和数据权限两类
- 支持在总览中按子应用名称搜索/筛选特定权限项
- 源选择后可以取消重新选择

**设计触点**

- 涉及页面 / 场景：子管理员列表页、权限全景预览面板（侧边栏或弹窗）
- 涉及组件类型：列表选择、树形权限展示、搜索/筛选输入
- 涉及状态：空态（无可选子管理员）、加载态（权限数据加载中）
- 涉及交互模式：单选、搜索筛选

**风险或待验证点**

- 权限项过多时全景预览的加载性能
- 超管是否真的需要看全部权限再确认，还是凭名字就够了

### S2. 选择多目标子管理员并执行复制

- **Persona**：企业超管
- **场景**：已确定源，需要将权限批量复制给多个职责相近的子管理员
- **目标**：一次操作完成多个目标的权限复制，避免逐一重复操作
- **优先级**：P0
- **来源依据**：问题框定 §7 推荐方向；客户核心诉求"一个源复制给多个目标"

**Story 主体**

作为企业超管，我已在复制流程中确认了源，接下来我想从子管理员列表中勾选一个或多个目标，一键执行复制，从而将源的全部权限批量赋予这些目标。

**完成标准**

- 支持批量选择多个目标子管理员
- 执行前清晰展示：源是谁、目标有哪些、将被复制的权限范围
- 点击执行后系统完成复制，不因目标数量多而阻塞操作
- 复制过程中有进度反馈
- 复制完成后提示成功/失败结果

**设计触点**

- 涉及页面 / 场景：复制操作页（选择目标步骤）
- 涉及组件类型：用户多选列表、已选项展示区（标签或列表）、操作确认按钮、进度条
- 涉及状态：空态（无目标可选）、加载态（复制执行中）、成功态、部分失败态
- 涉及交互模式：多选、批量操作确认

**风险或待验证点**

- 目标数量非常多时（如 50+）的交互流畅度
- 部分目标复制失败时的处理策略

---

### S3. 处理目标已有权限的冲突

- **Persona**：企业超管
- **场景**：目标子管理员已配有一些权限，复制时需要考虑合并方式
- **目标**：按预期策略处理已有权限，避免意外覆盖或重复
- **优先级**：P1
- **来源依据**：问题框定 §9 待确认问题第 1 项；体验侧关注点第 2 项

**Story 主体**

作为企业超管，当选择的某个目标子管理员已经拥有部分权限时，我想在复制前选择冲突处理方式——是直接覆盖、追加保留还是逐项确认，从而避免复制操作导致意外的权限变更。

**完成标准**

- 复制前检测目标是否已有权限
- 有冲突时提供至少两种策略选择（如"追加，冲突时提示"和"完全覆盖"）
- 用户可以针对本次操作统一选择策略
- 用户也可以逐项查看冲突详情后个别决定
- 选定策略后一次性执行

**设计触点**

- 涉及页面 / 场景：复制操作页（冲突处理步骤）
- 涉及组件类型：策略选择控件（单选/下拉）、冲突列表（差异对比）
- 涉及状态：无冲突态（可跳过）、有冲突态、逐项确认态
- 涉及交互模式：策略选择、逐项确认

**风险或待验证点**

- 默认策略偏好需与客户确认（当前推荐"追加，冲突时提示"）
- 逐项确认在冲突项较多时的操作效率

---

### S4. 核查复制结果并追溯变更

- **Persona**：企业超管
- **场景**：复制执行完成后，需要确认结果是否正确
- **目标**：直观了解每个目标的变更摘要，必要时查看详细变更记录
- **优先级**：P1
- **来源依据**：体验侧关注点第 3 项（复制后的可检查性）；`handoff_requirements` 第 5 项

**Story 主体**

作为企业超管，在权限复制执行完成后，我想看到一份变更摘要，清晰展示每个目标子管理员哪些权限被新增、哪些被覆盖、哪些保持不变，从而确认复制结果符合预期，必要时可追溯审计。

**完成标准**

- 复制完成后展示变更摘要页
- 摘要按目标子管理员分组，区分新增/覆盖/不变的权限项
- 支持展开查看单个目标的完整权限前后对比（差异视图）
- 复制操作记入操作日志，可追溯操作人、时间、源和目标
- 摘要页支持关闭后再次从操作日志中查阅

**设计触点**

- 涉及页面 / 场景：复制结果摘要页（弹窗或独立页）、操作日志列表
- 涉及组件类型：变更摘要卡片、差异对比视图（左右或行内对比）、操作日志条目
- 涉及状态：变更结果为空（无实际变更）、有差异态
- 涉及交互模式：展开/收起、对比查看

**风险或待验证点**

- 差异对比对大量权限项时的性能和可读性
- 操作日志的保留时长和查询效率

---

### S5. 在目标子管理员上微调权限

- **Persona**：企业超管
- **场景**：复制完成后，某些目标子管理员的职责与源存在细微差异，需要局部调整
- **目标**：在复制基础上快速定位差异项并修改，无需重新从零配置
- **优先级**：P0
- **来源依据**：客户明确要求"复制后只需微调"；`handoff_requirements` 第 2 项

**Story 主体**

作为企业超管，复制权限到目标子管理员后，我想进入每个目标的权限编辑页，快速定位到需要调整的权限项（菜单权限或数据权限）并进行修改，从而完成与源的任务差异适配。

**完成标准**

- 复制后可以从结果摘要直接进入单个目标的权限编辑
- 也可从子管理员列表页进入编辑
- 编辑页保留复制后的完整权限配置作为起点
- 修改后保存生效，不影响其他目标子管理员
- 编辑页支持搜索和筛选权限项

**设计触点**

- 涉及页面 / 场景：子管理员权限编辑页、复制结果摘要页→编辑的跳转链路
- 涉及组件类型：权限树/列表编辑、搜索/筛选输入、保存按钮
- 涉及状态：编辑中态、保存成功态、保存失败态（如并发冲突）
- 涉及交互模式：进入编辑、搜索筛选、保存退出

**风险或待验证点**

- 微调"是逐目标独立编辑还是支持批量差异编辑"需确认（当前假设为逐目标独立编辑，符合方向 A 边界）
- 多人同时编辑同一子管理员权限时的并发冲突

## 4. 不进入 Story 的内容

- **权限模板**（方向 B）：不做为故事拆解，问题框定已明确本轮不做
- **批量差异编辑 UI**（方向 C）：不做为故事拆解
- **跨企业权限复制**：不在本轮范围内
- **权限冲突自动修复**：仅提示，不由系统自动处理
- **子管理员通知**：复制后是否通知目标子管理员，待确认后补充

## 5. 待确认问题

1. **已有权限的默认冲突策略**：推荐"追加，冲突时提示"，需与客户确认
2. **微调的操作形态**：当前假设为逐目标独立编辑（方向 A 内），需确认客户是否接受
3. **差异对比的优先级**：S4 的差异对比视图是基础要求，但"复制前先预览差异"是否必要需确认
4. **操作通知**：复制后是否需要通知子管理员本人？还是仅超管可见即可？
