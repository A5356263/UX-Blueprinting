# 页面生成规格：员工自助权限申请

---

## 1. 页面摘要

- **产品领域**：企业权限管理 — 员工自助权限申请
- **页面类型**：Page（我的权限、申请记录、自助申请配置、申请记录总览、审批详情）、Drawer（申请权限）、Modal（提交确认、通过确认、拒绝原因、关闭确认）
- **用户角色**：员工、审批人、超管/权限管理员
- **核心任务**：员工从可申请范围中选择权限并提交申请；审批人审查申请内容并做出决策；管理员配置可申请范围和审批流程后开启能力

---

## 2. 生成范围

### 生成

| 实体 | 类型 | 说明 |
|---|---|---|
| 我的权限 | Page | 员工端顶级页面，查看已有权限+申请入口 |
| 申请权限 | Drawer | 员工从可申请范围中选择权限并提交申请 |
| 申请记录 | Page | 员工查看历史申请和状态详情 |

| 申请记录总览 | Page | 管理端查看运行状态和申请记录 |
| 审批详情 | Page | 审批人审查申请内容并做出决策 |

### 只引用不生成

## 3. 页面实体关系

```
权限管理模式 Page（已有）
  └─ 点击"员工自助申请权限"卡片
      └─ P4 自助申请配置 Page
            ├─ 配置范围、审批、开启/关闭
            └─ 点击"查看申请记录总览"
                └─ P5 申请记录总览 Page

工作台/导航（已有）
  └─ 点击"我的权限"
      └─ P1 我的权限 Page
            ├─ 点击 [申请权限]
            │   └─ P2 申请权限 Drawer
            │         └─ 点击 [提交申请]
            │             └─ 提交确认 Modal
            ├─ 点击某条权限 → 展开权限详情（已有能力）
            └─ 点击"查看申请记录"
                └─ P3 申请记录 Page
                      ├─ 点击某条记录 → 状态详情 Drawer
                      ├─ 点击 [重新提交] → P2 Drawer（预填上次内容）
                      └─ 点击 [催办] → Toast

待办列表（已有）
  └─ 点击某条权限申请
      └─ P6 审批详情 Page
            ├─ 点击 [通过] → 通过确认 Modal
            └─ 点击 [拒绝] → 拒绝原因 Modal
```

## 6. P2：申请权限

### 抽屉目标

让员工从可申请范围中选择权限，填写申请原因，提交申请。

### 区域结构

```
+---------------------------------------------------------------------------------+
| 【 A. 抽屉标题区 】                                                              |
| Text: 申请权限                                                        [关闭 X]    |
+---------------------------------------------------------------------------------+
| 【 B. 引导提示区 】                                                              |
| Icon: info  Text: 以下为当前可申请的权限范围。选择需要的权限并填写申请原因后提交，        |
|                  将进入审批流程。                                                 |
+---------------------------------------------------------------------------------+
| 【 C. 可申请权限列表区 】                                                        |
|                                                                                   |
| CheckboxGroup（按角色聚合，每项可展开）：                                            |
|                                                                                   |
| [v] {角色名}                                            Tag: 包含 {N} 项功能权限   |
|     └ 可进行：{能力列举}                                                           |
|                                                                                   |
| [ ] {角色名}                                            Tag: 包含 {N} 项功能权限   |
|     └ 可进行：{能力列举}                                                           |
|                                                                                   |
| [ ] {角色名}  Tag: 已拥有                                                          |
|     └ 你已拥有此权限，无需重复申请 · 置灰不可选                                      |
|                                                                                   |
| [ ] {角色名}  Tag: 审批中                                                          |
|     └ 你已有该权限的审批中申请 · 置灰不可选                                          |
+---------------------------------------------------------------------------------+
| 【 D. 申请原因区 】                                                              |
| Label: 申请原因 *                                                                 |
| Textarea placeholder: 请说明申请原因，如：因XX项目需要，需使用XX功能进行XX操作         |
| Text: 已输入 {N} 字，至少需要 {M} 字                                              |
|                                                                                   |
| InlineError（条件展示）：                                                           |
| 申请原因至少需要 {M} 字，帮助审批人了解你的使用场景。                                   |
+---------------------------------------------------------------------------------+
| 【 E. 底部操作区 】                                                              |
|                                  [按钮: 取消]  [主按钮: 提交申请]                   |
+---------------------------------------------------------------------------------+
```

### 区域说明

- **A**：标题 + 关闭按钮
- **B**：引导说明文本，告知员工提交后进入审批流程
- **C**：可申请权限列表，CheckboxGroup 多选。每项为角色名+包含功能权限数+能力摘要。已拥有或审批中的权限项置灰+标签说明
- **D**：申请原因必填区。Textarea + 字数计数 + InlineError（条件展示）
- **E**：[取消] 和 [提交申请]。未选任何权限时 [提交申请] 置灰

### 校验阻断态变化

- 未选择任何权限 → [提交申请] 置灰，hover: "请至少选择一项权限"
- 申请原因不足 {M} 字 → D 区下方展示 InlineError，Drawer 不关闭
- 所选权限超出当前可申请范围 → C 区顶部展示 Banner："可申请范围已更新，部分权限可能不再可申请。请重新选择。"
- 所选权限已有审批中或已生效申请 → 对应权限行 InlineError："你已有该权限的有效申请，无需重复提交"

### 提交确认 Modal

```
+---------------------------------------------------------------------------------+
| 【 标题区 】                                                                      |
| Text: 确认提交申请                                                  [关闭 X]      |
+---------------------------------------------------------------------------------+
| 【 正文区 】                                                                      |
| Text: 你正在申请 {N} 项权限，将提交至 {审批人姓名} 审批，预计 {X} 小时内处理。        |
| Text: 提交后无需联系管理员或审批人，审批结果将通过消息通知你。                        |
+---------------------------------------------------------------------------------+
| 【 操作区 】                                                                      |
|                              [按钮: 取消]  [主按钮: 确认提交]                       |
+---------------------------------------------------------------------------------+
```

## 8. P4：自助申请配置

### 页面目标

让管理员配置可申请范围、绑定审批流程、开启或关闭自助申请能力。

### 页面结构

- 页面标题区
  - Text：员工自助申请权限

- 能力说明与流程图区
  - FlowDiagram：员工发现权限缺口 → 选择权限并提交申请 → 审批人审查决策 → 通过后自动授权
  - Checklist：
    - Checkbox [只读]：□ 已配置可申请范围
    - Checkbox [只读]：□ 已绑定审批流程
    - Checkbox [只读]：□ 当前无互斥的治理模式

- 状态与开关区
  - Tag：{运行中/已关闭}
  - Text：开启时间：{时间}（运行中时可见）
  - Link [文本链接]：查看申请记录总览（运行中时可见）
  - Switch：已开启/已关闭
  - Text：关闭后将隐藏员工端申请入口，在途申请将继续走完。

- 配置区 1：可申请范围
  - Text：选择员工可以申请的权限范围（按角色）：
  - CheckboxGroup：
    - [v] {角色名} · 包含 {N} 项功能权限 · 适用于 {场景描述}
    - [ ] {角色名} · 包含 {N} 项功能权限 · 适用于 {场景描述}
  - Text：已选 {N} 个角色

- 配置区 2：审批流程
  - Text：选择员工提交申请后的审批流程：
  - Select：{审批流程名称}（下拉选择已有审批流程）

  - Text：当前选择：{流程名称} · 审批人：{审批人链条描述}

- 配置区 3：配置摘要
  - Text：可申请范围：{角色列表}（共 {N} 个角色，涵盖 {M} 项功能权限）
  - Text：审批流程：{流程名称}
  - Banner（条件展示）：
    - Icon：info
    - Text：当前有 {N} 项在途申请，配置变更不会影响已提交的申请。

  - Text 正文：当前有 {N} 项在途申请涉及 {M} 名员工。关闭后，已提交的申请将继续走完审批流程，但不再接受新的申请。
  - Text：关闭后历史申请记录保留可查，可随时重新开启。
  - Button [取消]
  - Button [主按钮]：确认关闭

- 治理模式冲突 Modal（开启校验失败时弹出）
  - Text 标题：无法开启
  - Text 正文：当前已开启 {模式名}，与员工自助申请互斥。请先关闭 {模式名} 后再开启。

## 11. 主交互流程

### MP1：员工提交权限申请

**节点 1-1：进入我的权限页**
- 动作：从工作台/导航进入
- 反馈：加载权限列表（按应用分组，标注来源和状态）
- 空状态：展示引导去申请

**节点 1-2：选择权限并填写申请**
- 动作：点击 [申请权限] → 打开 P2 Drawer
- 动作：勾选权限项（CheckboxGroup 多选）
- 动作：在 Textarea 输入申请原因
- 反馈：字数计数实时更新；已拥有/审批中的权限置灰不可选
- 校验不通过：未选→按钮置灰；原因不足→InlineError

**节点 1-3：确认提交**
- 动作：点击 [提交申请] → 弹出提交确认 Modal
- 动作：确认 Modal 中的摘要 → 点击 [确认提交]
- 反馈：Drawer 关闭 → Toast "申请已提交，预计 {X} 小时内处理。请在申请记录中查看进度。"
- 下一步：回到我的权限页或点击 Toast 进入申请记录

### MP2：审批人处理申请

**节点 2-1：进入审批详情**
- 动作：从待办列表/消息通知点击申请 → 打开 P6
- 反馈：加载申请人信息、权限差异对比、申请原因

**节点 2-2：通过申请**
- 动作：点击 [通过] → 弹出通过确认 Modal
- 动作：确认 → 点击 [确认通过]
- 反馈：Toast "已通过 {员工姓名} 的权限申请，系统正在自动授权。"
- 下一步：返回待办列表

**节点 2-3：拒绝申请**
- 动作：点击 [拒绝] → 弹出拒绝原因 Modal
- 动作：选择结构化原因 →（可选）填写补充说明 → 点击 [确认拒绝]
- 反馈：Toast "已拒绝 {员工姓名} 的权限申请，结果已通知申请人。"
- 下一步：返回待办列表

### MP3：管理员开启自助申请

**节点 3-1：进入配置页**
- 动作：权限管理模式 → 点击"员工自助申请权限"卡片 [去配置] → 打开 P4
- 反馈：加载流程说明、检查清单、当前状态

**节点 3-2：配置**
- 动作：勾选可申请角色（CheckboxGroup）→ 选择审批流程（Select）→ 查看摘要
- 反馈：摘要区实时汇总

**节点 3-3：开启**
- 动作：点击 [开启自助申请]
- 校验通过：Switch 切换为开启 → Toast "员工自助申请权限已开启"
- 校验失败（未配置）：对应区 InlineError
- 校验失败（模式冲突）：弹出冲突 Modal

## 14. 异常恢复

### EP1：提交时校验失败
- 恢复路径：原路恢复，已填信息不丢失。修正后重新点击提交即可。范围变更导致已选权限被移除时需重新选择。

### EP2：审批超时
- 员工侧恢复：点击 [催办] 触发提醒，等待审批人处理
- 审批人侧恢复：在待办列表中优先处理超时申请
- 管理员侧恢复：在 P5 查看积压，必要时手动转交

### EP3：审批人不存在或不可达
- 管理员侧恢复：在 P5 告警区点击 [处理] → 进入审批管理重新分配审批人 → 在途申请自动恢复流转
- 员工侧：无需用户操作，状态保持"审批中"等待管理员处理

### EP4：管理员关闭能力时存在在途申请
- 员工侧恢复：已提交的在途申请继续走完审批流程，不受影响。新申请入口隐藏
- 管理员侧恢复：关闭后不可提交新申请，在途申请在 P5 仍可追踪。随时可重新开启

### EP5：自动授权失败
- 管理员侧恢复：在 P5 告警区查看失败详情 → 进入用户授权页手动完成授权
- 员工侧：状态显示"已通过·授权处理中"→ 稍后验证。系统自动重试成功则无需介入

### EP6：可申请范围变更影响在途申请
- 恢复路径：在途申请按提交时的范围判断，不受影响。管理员在变更时看到提示确认即可
