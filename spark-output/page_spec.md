# 页面生成规格：企业数字化产品权限自助申请

---

## 1. 页面摘要

- **产品领域**：企业权限管理 — 员工自助权限申请
- **页面类型**：Page（权限申请列表页、我的申请页、我的权限页、审批待办列表页）、Drawer（权限申请 Drawer、审批详情 Drawer）、Modal（权限/角色详情 Modal）
- **用户角色**：员工（申请人）、上级组织负责人（审批人）、权限管理员
- **核心任务**：员工查看可申请目录 → 选择权限/角色 → 提交申请 → 追踪进度 → 获得权限或被拒绝

## 4. 权限申请 Page（承载页面）

### 4.1 页面目标

让员工浏览可申请的功能权限和角色，定位自己需要的项并发起申请。

### 4.2 页面结构

```
+----------------------------------------------------------------------+
|  权限申请                                                             |
|  查看和申请你需要的功能权限与角色                                       |
+----------------------------------------------------------------------+
|  【搜索栏】                                                           |
|  [搜索角色或权限名称...]                    [标签: 全部] [标签: 功能权限] [标签: 角色] |
+----------------------------------------------------------------------+
|  【推荐区 - 可选】                                                    |
|  你可能需要：{角色A}  |  {权限B}  |  {角色C}                          |
+----------------------------------------------------------------------+
|  【内容区 - 默认展示"全部"聚合视图】                                    |
|                                                                      |
|  ┌─ 角色卡片 ─────────────────────────────────────────────────────┐  |
|  │ {角色名称}                    [可申请] [已拥有]                    │  |
|  │ {角色描述}                                                       │  |
|  │ 包含 {N} 项功能权限   成员 {M} 人                                 │  |
|  │ [查看详情]                              [申请此角色]               │  |
|  └────────────────────────────────────────────────────────────────┘  |
|                                                                      |
|  ┌─ 功能权限卡片 ───────────────────────────────────────────────────┐  |
|  │ {权限名称}                                      所属应用：{应用名} │  |
|  │ {权限作用描述}                                                   │  |
|  │ 适用端：电脑端 + 移动端                                          │  |
|  │ [查看详情]                              [申请此权限]               │  |
|  └────────────────────────────────────────────────────────────────┘  |
|                                                                      |
|  ··· (更多卡片)                                                      |
+----------------------------------------------------------------------+
|  【浮动操作栏 - 选中项 >= 1 时显示】                                  |
|  已选 {N} 项    [查看已选]    [去申请]                                |
+----------------------------------------------------------------------+
```

### 4.3 区域说明

- 标题区：Text（页面标题"权限申请"）、Text（副标题）
- 搜索栏：Input（搜索角色或权限名称）、Tabs（全部 / 功能权限 / 角色）
- 推荐区（可选）：Text（"你可能需要"引导）、Link（跳转至推荐项）
- 内容区 — 角色卡片：Text（角色名称）、Tag（可申请 / 已拥有）、Text（角色描述）、Text（功能权限数量+成员数）、Button（查看详情）、Button（申请此角色）
- 内容区 — 功能权限卡片：Text（权限名称）、Text（所属应用）、Text（权限作用描述）、Text（适用端）、Button（查看详情）、Button（申请此权限）
- 浮动操作栏：Text（"已选{N}项"）、Button（查看已选）、Button（去申请）

### 4.4 提取备注

- 结构来自体验蓝图 §6 P1
- 知识库中"用户授权 Page"的检索+列表+操作栏模式已参考
- 角色列表全量展示，可申请角色用 Tag 标识；功能权限仅展示管理员标记为可申请的项
- 推荐区为可选模块，不在 MVP 必需的范围内

### 4.5 关键操作

| 操作 | 触发 | 结果 |
|------|------|------|
| 查看详情 | 点击角色/权限名称 | 打开 E6 详情 Modal |
| 申请角色/权限 | 点击 [申请此角色] 或 [申请此权限] | 打开 E2 申请 Drawer |
| 勾选 + 去申请 | 勾选项后点击浮动栏 [去申请] | 打开 E2 申请 Drawer |
| 搜索 | 输入关键词 | 过滤卡片列表 |
| 切换 Tab | 点击 [全部 / 功能权限 / 角色] | 切换内容区展示 |

|  │ [查看详情]                                                         │  |

|  ┌─ 待办卡片（超时标记）──────────────────────────────────────────────┐  |
|  │ {申请人姓名} 申请了 加入角色A                      2小时前   [超时] │  |

### 5.3 区域说明

- Tab 区：Tabs（待处理 / 已处理）

### 5.4 提取备注

## 6. 权限申请 Drawer

### 6.1 抽屉目标

汇总已选权限/角色，填写申请理由并提交。

### 6.2 区域结构

```
+----------------------------------------------------------------------+
|  提交权限申请                                                  [X]    |
+----------------------------------------------------------------------+
|  ┌─ 已选内容 ───────────────────────────────────────────────────────┐  |
|  │  角色（{N}项）                                                     │  |
|  │  {角色名} [移除]                                                  │  |
|  │  ···                                                              │  |
|  │  功能权限（{M}项）                                                 │  |
|  │  {权限名} - {所属应用} [移除]                                      │  |
|  │  ···                                                              │  |
|  └──────────────────────────────────────────────────────────────────┘  |
|                                                                      |
|  ┌─ 申请理由 ───────────────────────────────────────────────────────┐  |
|  │  [Textarea]                                                       │  |
|  │   请说明你需要在什么业务场景中使用该权限...                          │  |
|  │                                                                   │  |
|  │  还可输入 {N} 字                                                  │  |
|  │  — 例：我在XX业务中需要XX权限来做XX —                              │  |
|  └──────────────────────────────────────────────────────────────────┘  |
|                                                                      |
|  [检测到重复项时插入提醒 Banner]                                       |
|  "以下权限你已拥有，可移除后提交：[权限A] [权限B] [一键移除]"           |
+----------------------------------------------------------------------+
|  [取消] [提交申请]                                                    |
+----------------------------------------------------------------------+
```

### 6.3 区域说明

- 标题区：Text（"提交权限申请"）、Button（关闭 [X]）
- 已选内容区：Text（角色/功能权限分组标题）、Text（{角色名}/{权限名}）、Button（[移除]）
- 申请理由区：Textarea（理由输入）、Text（字数提示）、Text（示例模板）
- 重复项提醒区（条件展示）：Text（提醒文案）、Button（[一键移除]）
- 底部操作栏：Button（[取消]）、Button（[提交申请]）

### 6.4 校验阻断态变化

| 条件 | 变化 |
|------|------|
| 理由为空 | [提交申请] 置灰；理由区下方 InlineError"请填写申请理由" |
| 检测到重复项 | 已选区和底部操作栏之间插入提醒 Banner |
| 提交中 | [提交申请] 变为 [提交中...] 并禁用 |
| 网络异常提交失败 | InlineError"提交失败，请检查网络后重试" |

### 6.5 不合规确认区结构

```
[检测到已拥有权限时插入：]
+----------------------------------------------------------------------+
|  [i] 以下权限你已拥有，可移除后提交：{权限A} {权限B}                   |
|  [一键移除]                                                           |
+----------------------------------------------------------------------+
```

- 结构来自体验蓝图 §6 P3 + §3 节点 3

| 切换 Tab | 点击 Tab | 按状态过滤申请记录 |

## 12. 主交互流程

### 12.1 员工自助申请主路径

**入口发现 → 权限申请 Page → 申请 Drawer → 提交成功 → 我的申请 Page**

#### 节点 1：发现入口

| 子节点 | 用户动作 | 系统反馈 | 下一步 |
|--------|----------|----------|--------|
| 权限拦截引导 | 在业务功能入口被拦截 | Banner"你当前没有{权限名}的权限" + [去申请权限] 按钮 | 点击 [去申请权限] → 进入 E0 |
| 工作台入口 | 进入工作台，点击"权限申请" | 展示入口名和副标题 | 点击入口 → 进入 E0 |

## 15. 异常恢复

| 异常 | 发生时机 | 反馈形式 | 用户下一步 | 恢复路径 |
|------|----------|----------|------------|----------|
| 入口不可见 | 员工不知自助申请功能 | 权限拦截提示中嵌入 [去申请] | 点击进入目录 | 原路恢复，无信息丢失；关掉提示后可通过工作台入口再次进入 |
| 审批人不存在/已离职 | 提交后匹配审批人 | Toast + 通知管理员 | 联系管理员 | 管理员修复组织关系后系统自动重新匹配，恢复审批流程，无信息丢失 |
| 审批超时 | 提交后超时未处理 | 员工端 [催促审批] + 审批端超时标记 | 员工可催办 | 审批人操作后恢复正常流程 |
| 自动授权失败 | 审批通过后授权执行 | 通知双方 + 失败原因 | 申请人联系管理员；审批人协助排查 | 管理员排查修复后后台选择"重新执行授权"，无信息丢失 |
| 批量授权部分失败 | 逐项授权部分失败 | 通知"N项成功，M项失败" | 对失败项单独重新申请 | 失败项可单独重新提交，不需重复申请已成功的项 |
| 重复申请 | 提交前检测 | 提醒 Banner + [一键移除] | 移除重复项后提交 | 无阻断，用户可选择移除或不处理 |
| 敏感权限错误展示 | 浏览目录时 | 不可见或灰色禁用态 | 联系管理员 | 不可操作，无需恢复 |

## 19. 不参与本次生成的待确认项

| 待确认项 | 影响 |
|----------|------|
| 审批流引擎是否提供"审批人已查看"事件回调 | 若不可用，E3 时间线中"审批人已查看"节点无法实现 |
| 审批流引擎是否支持超时自动提醒 | 若不可用，审批超时机制依赖前端轮询实现 |
| 现有授权服务是否提供可触发的执行接口 | 若不可用，自动授权需改为半自动（通知管理员执行） |
| 组织域中"上级负责人"关系是否已定义完整 | 若未定义，审批人匹配机制需另寻方案 |
| 权限管理域是否有"敏感等级"标记 | 若无，敏感权限排除逻辑需基于白名单或手动配置 |
| 员工端入口位置（工作台/导航/全局） | 影响 E0 的入口设计和引导策略 |
| 当前管理后台中"通用权限管理"菜单路径是否已更新 | 影响 E1/P5 后台页面路径命名 |
