## §0 本次关键设计判断

### 判断 1：复制流程使用单页布局而非步骤条

- **主要影响**：源选择 → 目标选择 → 策略配置 → 执行确认的全流程页面结构
- **建议方案**：采用单页多区块布局，顶部固定操作引导（源/目标/策略），底部固定操作栏。用户可以在各区块之间自由跳转修改，不限制线性推进。源确认后目标区块激活，目标确认后策略区块激活，但已完成的区块仍可返回修改。
- **不建议方案**：使用步骤条（Steps）分 3-4 步引导用户逐步推进。理由：B 端专家场景默认非步骤化（BFM-01），超管操作权限时需要对全局有掌控感，步骤条会中断"全局查看 → 局部调整"的心流。
- **关键待确认**：如果目标选择数量极大（50+），单页内信息密度是否可控。如超出单页承载能力，可考虑目标选择使用抽屉展开。

### 判断 2：冲突策略默认使用"追加，冲突时提示"

- **主要影响**：复制执行阶段的合并逻辑和提示交互
- **建议方案**：系统检测目标已有权限后，默认选中"追加已有权限，遇冲突时逐项提示"策略。用户可切换为"完全覆盖目标已有权限"，但不提供"跳过全部冲突"的静默模式（违反 TR-006 安全优先）。
- **不建议方案**：默认"完全覆盖"或"跳过全部"。前者风险过高，后者会导致用户以为复制了但其实被跳过。
- **关键待确认**：客户是否接受"追加+提示"作为默认策略。

### 判断 3：复制结果摘要使用独立页面而非弹窗

- **主要影响**：复制完成后的结果展示形态
- **建议方案**：复制完成后跳转到独立的"复制结果"页面，按目标子管理员分组展示变更摘要。该页面支持刷新（重新获取最新状态）、支持从操作日志中回访。弹窗方式风险在于用户关闭后无法再次查看，而独立页面可以承载更复杂的差异对比结构。
- **不建议方案**：使用 Modal 弹窗展示结果摘要。弹窗空间有限，难以展示多目标的差异对比，且关闭即丢失。
- **关键待确认**：差异对比视图的深度（仅展示变更项 or 展示全部权限的前后对比）。

### 判断 4：微调入口从结果摘要直通权限编辑页，不新增独立编辑界面

- **主要影响**：复制后的微调操作链路
- **建议方案**：复制结果页中每个目标卡片提供"编辑权限"按钮，点击直接跳转到该子管理员的现有权限编辑页（沿用现有功能授权/数据授权路径），编辑页保留复制后的完整配置作为起点，并高亮"与源的差异项"。
- **不建议方案**：在复制流程内新增一套独立的微调编辑界面。理由：增加维护成本，且用户需要学习两套编辑界面。
- **关键待确认**：现有权限编辑页是否能承载复制后的配置起点（即需要后端支持将复制结果作为初始值带入编辑页）。

## §2 交互流程总览

### 主路径：从源复制权限到多目标

整个流程在"用户授权"页的批量操作区发起，在一个单页内完成全部操作。

```
用户授权 Page
  → 选中源子管理员
  → 打开 权限全景预览 Drawer（确认源）
  → 点击 [复制权限]
  → 进入 权限复制 Page（单页多区块）
      ├─ 区块1：源信息（只读展示）
      ├─ 区块2：目标选择
      ├─ 区块3：冲突策略
      └─ 区块4：执行确认
  → 点击 [执行复制]
  → 校验通过
  → 跳转 复制结果 Page
  → 按需进入各目标权限编辑 Page 微调
```

### 分支路径

- 源权限预览空态 → 提示"该子管理员暂无权限，无法作为复制源"，阻止进入复制流程
- 无符合条件的目标 → 提示当前无符合条件的子管理员，引导创建新子管理员
- 冲突策略选择"逐项确认" → 展开冲突列表，逐项勾选
- 复制执行中用户取消 → 中断复制，未完成的目标回滚
- 部分目标复制失败 → 结果页中显示失败项，提供"重试"入口
- 微调时并发冲突 → 保存时提示"该管理员权限已被其他管理员修改，请刷新后重试"

## §3 主交互流程

### 节点 1：选择源子管理员

**用户动作**

在"用户授权"页的列表中选中一个子管理员，点击"复制权限"按钮（或右键菜单/批量操作区）。如果尚未选择源，按钮置灰。

**系统反馈**

- 点击"复制权限"后，打开权限全景预览 Drawer，展示该子管理员在全部子应用下的菜单权限和数据权限总览，按子应用分组，默认收起细节只显示概览数量（如"库存管理应用：菜单权限 5 项、数据权限 2 项"）。
- Drawer 底部按钮："确认使用此源"和"取消"。

**需要前置解释的信息**

权限全景仅作为确认源的依据，确认后不会立即执行任何变更。

**建议文案**

- Drawer 标题："权限全景预览 - {子管理员姓名}"
- 确认按钮："确认使用此源"
- 取消按钮："取消"

**下一步**

- 用户确认源 → Drawer 关闭 → 进入"权限复制"单页
- 用户取消 → Drawer 关闭 → 停留在用户授权页

---

### 节点 2：配置目标与策略

**用户动作**

在"权限复制"页中，源信息区块已自动填充（只读展示来源姓名和权限项数）。用户进入目标选择区块，按部门/角色/地区搜索筛选目标子管理员，从结果列表中勾选。

**系统反馈**

- 目标列表每行展示：子管理员姓名、部门/角色标签、现有权限状态（"已有 {N} 项权限"、"无权限"、"与源有 {N} 项差异"标签）。
- 顶部提供全选和按组选（按部门/角色分组）批量操作控件。
- 已选目标展示在列表上方的标签区，支持逐一移除。
- 列表按"与源差异项数量"降序排列（差异越大的越靠前）。

**需要前置解释的信息**

选择目标后会自动检测这些目标是否已有权限。已有权限的目标会影响下一步的策略选择。

**建议文案**

- 区块标题："选择目标子管理员"
- 搜索占位："按姓名、部门或角色搜索"
- 已选计数："已选择 {N} 个目标"
- 空结果提示："未找到符合条件的子管理员"

**下一步**

用户勾选完成 → 系统自动扫描各目标的已有权限 → 展开冲突策略区块。

---

### 节点 3：确认并执行复制

**用户动作**

冲突策略区块展示检测结果：哪些目标已有权限、哪些无权限。用户选择策略（"追加，冲突时提示"或"完全覆盖"）。查看底部的执行摘要确认面板，确认源、目标数量和策略后，点击"执行复制"。

**系统反馈**

- 无权限冲突的目标：显示绿色标记"无冲突，可正常复制"
- 有冲突的目标：显示冲突项数（如"2 项权限冲突"）
- 选择策略后，执行摘要面板实时更新显示预计操作概览
- 点击执行后，按钮变为加载态并显示进度百分比
- 执行中可取消（显示"正在复制（{当前}/{总数}），点击取消将回滚已处理项"）

**需要前置解释的信息**

- "追加，冲突时提示"的含义：目标已有的权限保留，源有的但目标没有的权限会被新增。当源和目标对同一权限项配置不同时，弹窗让用户逐项决定。
- "完全覆盖"的含义：目标现有权限将被源的权限完全替换，目标已有但源没有的权限会被移除。

**建议文案**

- 策略区块标题："冲突处理策略"
- 策略选项 1："追加已有权限，遇冲突时逐项提示（推荐）"
- 策略选项 2："完全覆盖目标现有权限"
- 执行摘要标题："操作确认"
- 执行按钮："执行复制"
- 执行中提示："正在复制（{当前}/{总数}）"
- 取消确认："取消后已处理的部分将回滚，确定取消？"

**下一步**

执行完成 → 自动跳转到复制结果页。

## §4 次交互流程

### 次流程 1：逐项确认冲突项

- **触发条件**：用户选择了"追加，冲突时提示"策略，且存在冲突项
- **用户动作**：点击"查看冲突详情"，在展开的冲突列表中逐项选择"保留目标原有"或"使用源的配置"
- **系统反馈**：冲突列表按子应用分组，每行展示：权限名称、目标当前值、源的值。每行提供两个操作按钮。
- **建议文案**：冲突列表标题："冲突权限项（{总数} 项）"；项操作："保留目标" / "使用源配置"
- **下一步**：所有冲突项处理完毕后，回到执行确认面板

### 次流程 2：查看复制结果与日志追溯

- **触发条件**：复制执行完成，跳转到复制结果页
- **用户动作**：浏览按目标分组的变更摘要卡片，展开查看差异对比
- **系统反馈**：每个目标一张卡片，包含：目标姓名、变更项总数（新增 {N} 项/覆盖 {N} 项/无变更）。点击"查看详情"展开该目标的完整权限前后对比，按子应用分组，变更项高亮标记。
- **建议文案**：页面标题 "权限复制结果"；变更标签 "新增" / "已覆盖" / "无变更"
- **下一步**：用户可点击目标卡片上的"编辑权限"进入微调，或关闭页面回到用户授权页

### 次流程 3：从结果页回滚单项变更

- **触发条件**：在复制结果页中发现某项权限变更不符合预期
- **用户动作**：在差异对比视图中找到该权限项，点击"撤销此变更"按钮
- **系统反馈**：系统将该权限回复到复制前的状态，并更新变更摘要数据
- **建议文案**：撤销按钮 "撤销此变更"；撤销确认 "确定撤销此项权限变更？"；撤销成功 toast "已撤销"
- **下一步**：撤销后该目标的变更计数更新；如需更多调整，点击"编辑权限"进入全面编辑

## §5 异常与阻断流程

### 异常 1：选择的源子管理员无任何权限

- **发生时机**：点击源子管理员的"复制权限"按钮后，Drawer 加载权限数据时
- **触发条件**：源子管理员在全部子应用下既没有菜单权限也没有数据权限
- **判断依据**：后端返回权限列表为空
- **反馈形式**：Drawer 内容区显示空状态提示
- **系统反馈**：Drawer 内容区展示空状态插图和文案，底部"确认使用此源"按钮置灰
- **用户下一步**：关闭 Drawer，重新选择其他源子管理员
- **恢复路径**：原路返回，无信息丢失

### 异常 2：所有目标均无权限变更

- **发生时机**：复制执行完成，跳转到结果页时
- **触发条件**：源的权限与所有目标的现有权限完全一致，无任何新增或覆盖
- **判断依据**：后端返回变更项计数均为零
- **反馈形式**：结果页展示空变更状态
- **系统反馈**：页面展示"所有目标已具有相同权限，无需变更"的提示
- **用户下一步**：确认后关闭页面
- **恢复路径**：无信息丢失，不做任何实际变更

### 异常 3：执行复制操作超时

- **发生时机**：点击"执行复制"后，后台处理时间超过预期
- **触发条件**：权限项多 + 目标数量多，后端处理超过 30 秒
- **判断依据**：前端超时检测或后端返回超时状态
- **反馈形式**：进度条停留在当前进度，Toast 提示
- **系统反馈**：Toast："复制操作处理时间较长，已进入后台处理，完成后可在操作日志中查看结果"
- **用户下一步**：关闭当前页面，后续从操作日志查看结果
- **恢复路径**：操作进入异步处理，用户可离开页面。完成后通过操作日志追溯结果。中间状态不做回滚，以最终后端结果为准。

### 异常 4：部分目标复制失败

- **发生时机**：执行复制过程中，部分目标处理失败
- **触发条件**：网络波动、权限校验不通过、子管理员范围变更等
- **判断依据**：后端返回结果中包含失败项及原因码
- **反馈形式**：结果页中失败目标卡片展示错误状态
- **系统反馈**：失败卡片展示为红色边框，显示失败原因（如"子管理员管辖范围不匹配"），同时提供"重试"按钮
- **用户下一步**：点击"重试"重新执行失败项的复制；或跳过失败项，只处理成功项
- **恢复路径**：已成功的项不做回滚，仅重新处理失败项

### 异常 5：微调时发生并发冲突

- **发生时机**：在权限编辑页保存微调结果时
- **触发条件**：同一子管理员的权限在同一时间被其他管理员修改
- **判断依据**：后端返回并发冲突标记
- **反馈形式**：保存失败，弹窗提示
- **系统反馈**：弹窗"该管理员的权限已被其他管理员修改，请刷新后重试。刷新后将展示最新配置。"
- **用户下一步**：关闭弹窗，刷新页面查看最新配置，重新进行微调
- **恢复路径**：刷新页面后重新编辑，需重新定位需要调整的权限项。不丢失业务意图，但丢失当前编辑界面的未保存更改。

### 异常 6：执行复制时权限模型变更

- **发生时机**：用户配置好复制参数后，在点击执行前源或目标的权限状态已变化
- **触发条件**：其他管理员在用户配置过程中修改了源或目标的权限
- **判断依据**：点击执行时后端校验发现数据版本与进入页面时不匹配
- **反馈形式**：执行按钮点击后失败，弹窗提示
- **系统反馈**：弹窗"权限数据已更新，请刷新后重新确认复制参数"
- **用户下一步**：关闭弹窗，刷新页面重新选择源和目标
- **恢复路径**：完全返回起点重新配置。无部分写入风险，因为执行被前置校验拦截。

## §6 页面 / 弹窗 / 抽屉设计

### 页面 1：用户授权页（现有页面，增加复制入口）

- **页面目标**：展示子管理员列表，提供复制权限的操作入口
- **进入条件**：超管进入"权限管理 > 用户授权"
- **页面结构**：

```
┌──────────────────────────────────────────────┐
│  权限管理  >  用户授权                          │
```
