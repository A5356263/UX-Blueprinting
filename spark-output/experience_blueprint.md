# 体验蓝图：员工自助申请权限

---

## §0 本次关键设计判断

### 判断 1：员工端权限目录按"业务场景"而非"权限技术标签"组织

**主要影响**：影响员工端的权限浏览页、申请表单页的顶层信息架构，以及"可申请范围"配置页的配置维度。

**建议方案**：将权限目录按"应用 → 功能场景"两层组织，用业务语言描述权限（如"创建订单"而非"功能权限-订单管理-新增"）。每个权限项附带简短业务说明和典型场景示例。

**不建议方案**：不直接把管理后台的权限树（按功能点/菜单级联结构）搬到员工端，也不按技术角色名（如"HR管理员""财务专员"）列权限——前者员工看不懂，后者粒度太粗容易授权过量。

**关键待确认**：可申请范围配置是按角色粒度、功能权限粒度还是混合模式——这决定目录的底层数据来源。

### 判断 2：申请流程采用"单页表单 + 上下文确认"而非步骤条

**主要影响**：影响申请表单页面的布局和交互模式。

**建议方案**：权限选择 + 申请原因合并在一个 Drawer 中完成。权限选择用搜索+分类筛选定位，选中后确认区实时展示已选权限摘要。原因输入提供模板示例。提交前做一次性校验。

**不建议方案**：不加步骤条——步骤条适用于"强依赖/不可逆/高风险/真实分步"场景，权限申请是一条"选→填→提交"的简单链路，拆成多步反而增加操作成本。

**关键待确认**：所选权限是否需要在提交前预览完整的权限效果（如数据范围预览）。

### 判断 3：异常反馈位采用"前置说明 + 实时校验 + 后置引导"三层策略

**主要影响**：影响申请表单的校验策略、审批状态的反馈方式、被拒后的引导设计。

**建议方案**：可申请范围限制前置到目录展示层（不在白名单的不展示），申请原因做实时字数校验，审批完成后引导员工验证权限。被拒时展示具体原因并附"重新申请"入口。

**不建议方案**：不把权限限制放在提交后才报错——能前置展示的限制不应等失败后再解释。不把被拒原因放在一个需要主动点开的详情里。

**关键待确认**：审批人缺失的超时兜底策略（自动转派/通知管理员）。

## §1 旅程消费摘要

以下从 journey-analysis 产出的员工旅程中提取三类信息，驱动后续章节的体验设计决策。

### 信心最低点

| 来源阶段 | 信心度 | 驱动设计落点 |
|----------|--------|-------------|
| 发现权限缺口 → 探索可申请范围（转折点） | 中 | 驱动 §5 权限不可见异常设计——员工在"找不到要申请的权限"时提供搜索和分类引导 |
| 等待审批处理 | 中 | 驱动 §5 审批超时 / 审批人缺失异常设计——审批周期过长是最大流失点 |
| 获取授权结果（被拒分支） | 中 | 驱动 §5 被拒后引导设计——被拒后缺少明确后续路径 |

### 关键转折

| 来源阶段 | 转折条件 | 驱动设计落点 |
|----------|----------|-------------|
| 发现权限缺口 → 探索可申请范围 | 员工确认自己缺少权限，决定通过自助渠道解决 | 驱动 §3 节点 1 的"权限不足时快捷入口"设计——在业务功能没有权限提示时直接提供"去申请"链接 |
| 探索可申请范围 → 发起权限申请 | 员工在可申请目录中找到匹配的权限选项 | 驱动 §3 节点 2 的"权限选择器"设计——选中后在提交前有即时确认反馈 |
| 等待审批处理 → 获取授权结果 | 审批人做出同意或拒绝的决定 | 驱动 §3 节点 5 的结果引导设计——通过后引导验证，被拒后引导重新申请 |

### 流失风险

| 来源阶段 | 流失风险描述 | 驱动设计落点 |
|----------|-------------|-------------|
| 发现权限缺口 | 员工可能直接放弃、转向线下找管理员 | 驱动 §6 P1 页面结构中的"权限不足入口"——在业务功能页提供上下文快捷入口 |
| 探索可申请范围 | 目录太复杂或难以理解，员工放弃自助 | 驱动 §6 P2 目录设计中的搜索和分类筛选——降低认知负荷 |
| 发起权限申请 | 表单填写成本高导致放弃提交 | 驱动 §6 P2 表单设计中的原因模板——降低输入门槛 |
| 等待审批处理 | 审批等待过长，员工转线下 | 驱动 §6 P2 进度追踪、驱动 §5 审批超时兜底 |

## §2 交互流程总览

### 2.1 流程路径清单

本次设计包含以下交互路径：

**主路径（员工视角）：**
1. 我的权限页 → 申请权限 Drawer → 提交 → 申请记录页（审批中状态）
2. 业务功能页（权限不足提示）→ 快捷入口 → 权限申请 Drawer（预筛选）

**管理员配置路径：**
3. 自助申请配置页 → 配置可申请范围 → 配置审批流程 → 开启能力
4. 自助申请配置页 → 关闭能力 → 确认弹窗 → 关闭完成

**审批处理路径：**
5. 审批通知 → 审批处理 Drawer → 查看申请 → 同意/拒绝 → 自动授权

**次路径（员工视角）：**
6. 申请记录页 → 查看详情 → 催办/撤回
7. 申请被拒通知 → 查看原因 → 重新申请

### 2.2 主路径详细流程

#### 主路径 1：员工提交权限申请

```
我的权限 Page
→ [Tab 切换到"可申请权限"] 或 点击 [申请权限]
→ 打开 权限申请 Drawer
→ 浏览/搜索权限目录
→ 勾选目标权限项
→ 查看已选权限摘要
→ 输入申请原因
→ 点击 [提交申请]
→ 系统校验（范围校验 + 原因校验）
→ 校验通过
→ Drawer 关闭
→ Toast：申请已提交
→ 我的权限页 → 申请记录列表新增一条"审批中"记录
```

分支：
- 未勾选权限 → [提交申请] 置灰，提示"请先选择需要申请的权限"
- 申请原因为空 → 提交后 Drawer 不关闭，原因输入框下方显示 InlineError："请说明申请原因"
- 申请原因超出字数 → 实时字数提示变红，提交时拦截
- 所选权限已通过其他方式拥有 → 提交前提示"你已拥有以下权限：{权限名}，确认仍要申请？"

#### 主路径 3：审批人处理申请

```
审批人收到通知（站内/消息）
→ 进入 审批处理 Drawer（或审批中台处理页）
→ 查看申请详情（申请权限、原因、申请人信息）
→ 选择 [同意] 或 [拒绝]
→ 如拒绝，填写拒绝原因（必填）
→ 提交审批决定
→ Toast：处理成功
→ 系统执行自动授权（通过时）
→ 员工收到结果通知
```

分支：
- 审批人同意 → 系统自动执行授权 → 授权成功 → 状态变更为"已授权"
- 审批人同意 → 系统自动执行授权 → 授权失败 → 状态变更为"授权异常"，通知管理员人工处理
- 审批人拒绝 → 必填拒绝原因 → 状态变更为"已拒绝"，通知员工

## §3 主交互流程

### 节点 1：进入权限申请入口

| 字段 | 内容 |
|------|------|
| **用户动作** | 员工通过以下任一方式进入权限申请入口：① 在工作台或全局导航中找到"我的权限"入口 ② 在业务功能页遇到权限不足提示时点击"去申请权限"快捷入口 |
| **系统反馈** | ① 方式进入 → 打开"我的权限"页面，默认展示员工当前已拥有的权限列表 ② 方式进入 → 打开"我的权限"页面并自动切换到"可申请权限"Tab |
| **需要前置解释的信息** | 页面需说明这里展示的是"你能申请的东西"，不是"你有的东西" |
| **建议文案** | 页面顶部提示："你可以在此查看已拥有的权限，或申请新的权限。申请后需审批人通过方可生效。" |
| **下一步** | 员工查看可申请目录，选择需要申请的权限 |

### 节点 2：浏览与选择权限

| 字段 | 内容 |
|------|------|
| **用户动作** | ① 按应用分类浏览可申请权限目录 ② 使用搜索框按关键词查找权限 ③ 勾选一个或多个需要申请的权限项 |
| **系统反馈** | ① 权限目录默认以"应用 → 功能场景"分层展示，每个权限项包含名称、简短说明和勾选框 ② 搜索时实时过滤匹配的权限项 ③ 已选权限在底部的"已选 {N} 项"区域实时更新 |
| **需要前置解释的信息** | 每个权限项的说明是业务语言（如"创建订单：允许新建销售订单，包括录入客户信息、商品明细和金额"），而非技术权限名 |
| **建议文案** | 权限项展示格式：`[ ] {功能场景名} — {一句话说明}`；已选区域显示："已选择 {数量} 项权限 [查看详情] [清空]" |
| **下一步** | 点击 [提交申请] 或继续填写申请原因（可选顺序） |

### 节点 3：填写申请原因

| 字段 | 内容 |
|------|------|
| **用户动作** | ① 在申请原因输入框中填写说明 ② 可点击"查看示例"查看原因模板 |
| **系统反馈** | ① 输入框下方实时显示字数（如：0/200） ② 字数超过 180 时颜色变黄提示接近上限 ③ 超过 200 字时阻止提交并提示 |
| **需要前置解释的信息** | 申请原因帮助审批人判断是否合理，建议说明"为什么需要这个权限"和"用于什么场景" |
| **建议文案** | 输入框 placeholder："请说明你需要该权限的原因（如：负责每月员工考勤统计，需查看全员的考勤数据）"；示例浮层展示："因岗位调整，接手 XX 工作，需要 XX 权限" |
| **下一步** | 点击 [提交申请] |

### 节点 4：提交申请

| 字段 | 内容 |
|------|------|
| **用户动作** | ① 点击 [提交申请] 按钮 ② 系统执行校验 ③ 校验通过后 Drawer 关闭 |
| **系统反馈** | ① 校验中：按钮显示"提交中…"加载态 ② 校验通过：Drawer 关闭，Toast 提示"申请已提交" ③ 系统自动创建申请记录，状态为"审批中" |
| **需要前置解释的信息** | 提交前在已选摘要区展示本次申请的完整内容，供员工最后确认 |
| **建议文案** | Toast："申请已提交，审批结果将通过消息通知你。" |
| **下一步** | 员工可关闭页面等待通知，或切换到申请记录页查看进度 |

### 节点 5：查看审批进度

| 字段 | 内容 |
|------|------|
| **用户动作** | ① 进入"我的权限"→"申请记录"列表 ② 查看各条申请的状态 ③ 如已审批 → 查看结果详情 |
| **系统反馈** | ① 列表按时间倒序展示，每条申请显示：权限名称、提交时间、当前状态、操作入口 ② 状态标签清晰区分：审批中/已通过/已拒绝/已撤回/已关闭 ③ 审批通过 → 点击"验证权限"回到业务功能确认 ④ 审批拒绝 → 显示拒绝原因和"重新申请"入口 |
| **需要前置解释的信息** | 审批中状态可附带预计处理时间或审批人信息 |
| **建议文案** | 状态列文案示例：审批中 — "等待 {审批人姓名} 审批中"；已拒绝 — "因 '{原因}' 被拒绝，如有需要可重新申请" |
| **下一步** | 通过后验证权限/被拒后重新申请/等待中催办 |

## §4 次交互流程

### 流程 1：管理员开启自助申请能力

| 字段 | 内容 |
|------|------|
| **触发条件** | 超管进入自助申请配置页，首次启用 |
| **用户动作** | ① 打开"权限管理模式"或独立配置入口 ② 切换到"自助申请权限"模式卡片 ③ 点击 [立即启用] |
| **系统反馈** | 如未配置可申请范围和审批流程 → 阻止开启，Toast 提示"请先完成以下配置：① 设置可申请范围 ② 设置审批流程"，并跳转到配置区 |
| **需要前置解释的信息** | 开启前必须完成两项配置，否则员工端看不到申请入口 |
| **建议文案** | 引导提示："开启前请先完成可申请范围和审批流程的配置，以确保员工可以正常使用。" |
| **下一步** | 进入可申请范围和审批流程配置 |

### 流程 2：管理员配置可申请范围

| 字段 | 内容 |
|------|------|
| **触发条件** | 超管在自助申请配置页点击"配置可申请范围" |
| **用户动作** | ① 选择配置维度（按功能权限/按角色/混合） ② 从权限树或角色列表中勾选允许员工申请的项目 ③ 点击 [保存] |
| **系统反馈** | 保存后实时生效，员工端可申请目录仅展示已选范围内的权限项 |
| **下一步** | 继续配置审批流程或开启能力 |

### 流程 3：管理员关闭自助申请能力

| 字段 | 内容 |
|------|------|
| **触发条件** | 超管点击关闭开关 |
| **用户动作** | ① 点击关闭开关 ② 系统弹出确认弹窗 ③ 弹窗提示当前进行中的申请数量 ④ 超管确认关闭 |
| **系统反馈** | ① 关闭后"申请权限"入口从员工端隐藏 ② 进行中的申请继续在"申请记录"中可见可追踪 ③ 新的申请请求被拒，提示"当前管理员已关闭自助申请权限功能" |
| **需要前置解释的信息** | 关闭是"停止新申请"而非"系统下线"，已有申请不受影响 |
| **建议文案** | 确认弹窗："关闭后，员工将无法提交新的权限申请。当前 {N} 条进行中的申请将继续正常流转，不受影响。确定要关闭吗？" |
| **下一步** | 确认关闭 → 能力关闭完成；取消 → 保持开启 |

### 流程 4：员工撤回申请

| 字段 | 内容 |
|------|------|
| **触发条件** | 员工在申请记录页查看"审批中"的申请，点击 [撤回] |
| **用户动作** | ① 点击 [撤回] ② 确认弹窗提示撤回后不可恢复 ③ 确认撤回 |
| **系统反馈** | ① 申请状态变更为"已撤回" ② 通知审批人该申请已撤回 ③ 员工可在记录中查看已撤回的申请 |
| **需要前置解释的信息** | 撤回仅限"审批中"状态，已完成的申请（通过/拒绝）不可撤回 |
| **建议文案** | 确认弹窗："撤回后该申请将终止，审批人将收到撤回通知。确定要撤回吗？" |
| **下一步** | 员工可重新提交新的申请 |

### 流程 5：员工重新申请（被拒后）

| 字段 | 内容 |
|------|------|
| **触发条件** | 员工在申请记录页查看"已拒绝"的申请，点击 [重新申请] |
| **用户动作** | ① 点击 [重新申请] ② 系统打开申请 Drawer，预填充上次申请的权限项 ③ 员工可修改申请原因 ④ 提交 |
| **系统反馈** | 按新申请处理，创建新的申请记录，原申请记录保留作为历史 |
| **需要前置解释的信息** | 重新申请是新建一条申请，不是覆盖原申请 |
| **建议文案** | Drawer 中展示上次被拒原因："上次申请因'{原因}'被拒绝，建议参考该原因调整申请内容。" |
| **下一步** | 重新提交后进入审批流程 |

## §5 异常与阻断流程

### 异常 1：审批人缺失

| 字段 | 内容 |
|------|------|
| **发生时机** | 员工提交申请后，系统尝试分配审批人时 |
| **触发条件** | 审批流程配置中无有效审批人（审批人离职、角色无人、流程配置不完整） |
| **判断依据** | 系统检测不到当前申请对应的审批人节点 |
| **反馈形式** | 申请状态显示"派发异常"，同时通知管理员 |
| **系统反馈** | 申请停留在"已提交"状态不前进，给管理员发送通知："有权限申请因审批人配置异常无法处理" |
| **用户下一步** | 系统通知管理员修复审批配置；员工可查看状态为"派发异常"的申请记录，暂不可催办 |
| **恢复路径** | 管理员修复审批配置（添加有效审批人）后，系统自动将申请派发到对应审批人，申请进入"审批中"状态，原路恢复，无信息丢失 |

### 异常 2：审批超时未处理

| 字段 | 内容 |
|------|------|
| **发生时机** | 申请进入"审批中"状态后 |
| **触发条件** | 审批人超过设定的处理时限仍未操作 |
| **判断依据** | 系统计时器检测到超时（超时时限由管理员配置） |
| **反馈形式** | 超时提醒通知发送给审批人；员工端提供催办入口 |
| **系统反馈** | 按超时策略执行：① 仅提醒 → 系统发送催办通知 ② 超时转派 → 转派给其他审批人 ③ 超时通过 → 自动通过 ④ 超时拒绝 → 自动拒绝 |
| **用户下一步** | 策略①②：员工可点击 [催办]，系统再次通知审批人；策略③④：系统自动处理，员工收到结果通知 |
| **恢复路径** | 策略①中审批人处理后恢复，无信息丢失；策略②中转派的新审批人处理后恢复；策略③④为自动终态 |

### 异常 3：权限授权失败

| 字段 | 内容 |
|------|------|
| **发生时机** | 审批人通过后，系统执行自动授权时 |
| **触发条件** | 系统授权接口异常、权限冲突、关联数据不完整等 |
| **判断依据** | 授权服务返回错误码 |
| **反馈形式** | 审批人页面显示"授权中"→"授权异常"；通知管理员 |
| **系统反馈** | 申请状态变更为"授权异常"，通知管理员人工处理；记录失败原因和操作日志 |
| **用户下一步** | 员工看到状态为"授权异常"，引导联系管理员；管理员在后台查看失败原因并人工干预 |
| **恢复路径** | 管理员在后台重新执行授权或手动配置权限后，将状态更新为"已授权"，员工收到结果通知 |

### 异常 4：关闭能力时进行中申请

| 字段 | 内容 |
|------|------|
| **发生时机** | 管理员关闭自助申请能力时 |
| **触发条件** | 管理员执行关闭操作 |
| **判断依据** | 系统检测到关闭指令 |
| **反馈形式** | 关闭前弹窗提示进行中申请数量；关闭后新申请被拒时提示原因 |
| **系统反馈** | 已有申请继续流转，员工可在"申请记录"中继续查看进度；新提交的申请被拒并提示"管理员已关闭自助申请权限功能" |
| **用户下一步** | 进行中的申请无需额外操作；需要新权限的员工联系管理员线下处理 |
| **恢复路径** | 进行中的申请正常完成不受影响；如管理员重新开启能力，员工可继续使用 |

### 异常 5：申请超出可申请范围

| 字段 | 内容 |
|------|------|
| **发生时机** | 员工提交申请前或提交时 |
| **触发条件** | 员工选择的权限不在管理员配置的可申请白名单内 |
| **判断依据** | 系统校验权限是否在可申请范围内（前置：目录本身已过滤，此异常理论上不会发生。但作为安全兜底保留后端校验） |
| **反馈形式** | 提交时后端拦截，Toast 提示"所选权限不在可申请范围内" |
| **系统反馈** | 阻止提交，请求不发送到审批流程 |
| **用户下一步** | 查看可申请目录，选择在范围内的权限 |
| **恢复路径** | 原路返回，已选择的权限和原因保留不丢失 |

### 异常 6：员工申请已拥有的权限

| 字段 | 内容 |
|------|------|
| **发生时机** | 员工提交前校验 |
| **触发条件** | 员工选择的权限已通过其他来源（管理员授权/角色自动授权）拥有 |
| **判断依据** | 系统检测到该权限已在生效状态 |
| **反馈形式** | 提交时提示"你已拥有以下权限：{权限名}"，确认是否仍要提交 |
| **系统反馈** | 不阻断提交，但提示员工确认 |
| **用户下一步** | 如确认需要（如权限即将过期、需要书面申请记录），仍可提交；否则取消申请 |
| **恢复路径** | 取消则返回表单，已填内容保留；确认则正常提交 |
