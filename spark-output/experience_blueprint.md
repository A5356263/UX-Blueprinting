# 体验蓝图：员工自助申请权限

## §0 本次关键设计判断

| 判断 | 主要影响 | 建议方案 | 不建议方案 | 关键待确认 |
|------|---------|---------|-----------|-----------|
| 管理员配置流程采用分步引导（三步），每步聚焦一个决策，减少配置遗漏 | 管理端配置页的结构和交互方式 | 三步式页面：第一步选申请方式，第二步设范围，第三步配审批流程；每步独立的"上一步/下一步"导航 | 一张长表单把所有配置项堆在一起（增加理解成本和操作失误） | 三步是否都放在一个页面区域还是三个独立页面 |
| 员工申请权限使用抽屉承载，保留个人中心的上下文 | 申请权限的承载形式和交互流程 | 点击"申请权限"从右侧滑出抽屉，包含选择内容、填写原因、提交，不离开当前页面 | 跳转到独立申请页（员工需要在申请页和我的权限页之间来回切换） | 抽屉宽度能否承载角色/功能权限的选择内容量 |
| 审批页面展示申请角色/权限的简要说明，弥补审批人决策依据不足 | 审批页面的信息密度 | 在审批详情中增加申请角色/权限的"包含哪些功能"摘要说明，帮助审批人快速判断 | 增加申请人权限画像（涉及跨页数据查询，复杂度高，可作为二期增强） | 是否值得为了审批决策引入权限摘要的数据查询 |
| 状态可见性采用"列表状态标签+详情页状态说明"双层表达 | 申请记录列表和详情页的状态展示方式 | 列表行用标签表达审批状态（审批中/已通过/已拒绝/已撤销），详情页展示完整时间线和审批人信息 | 只在详情页展示状态（员工需要逐条点开才能了解进展） | 详情页是否展示审批人姓名和联系方式 |

## §2 交互流程总览

### 主路径

**路径 P1：员工申请角色/功能权限**
```
个人中心
→ 点击"我的权限"
→ 我的权限页（查看已有权限，确定要申请的内容）
→ 点击"申请权限"
→ 打开申请权限 Drawer
→ 选择要申请的角色/功能权限（单选勾选）
→ 填写申请原因
→ 点击"提交申请"
→ 后端校验（资金用户、子管理员模式、实名）
→ 校验通过 → Drawer 关闭 → Toast "提交成功" → 申请记录新增一条"审批中"
→ 等待审批结果

分支：
- 未选择申请内容 → [提交] 置灰，不可提交
- 申请原因为空 → [提交] 置灰，不可提交
- 后端校验失败 → Drawer 不关闭，展示具体错误提示
```

**路径 P2：审批人审批权限申请**
```
OA 审批待办列表
→ 点击权限申请条目
→ 审批详情页
→ 查看申请人信息、申请内容（角色名/权限说明）、申请原因
→ 选择"同意"或"否决"
→ 如否决，填写否决原因
→ 确认提交
→ 同意 → 系统自动分配 → 通知申请人
→ 否决 → 流程终止 → 通知申请人
```

**路径 P3：超管配置自助申请模式**
```
权限管理模式页
→ 找到"自助申请权限模式"入口
→ 点击"立即启用"
→ 校验互斥模式（双管理员互审、权限变更审批）
→ 通过 → 进入三步设置页
→ 第一步：选择申请方式（角色/功能权限）
→ 第二步：设置范围（全部/部分）
→ 第三步：设置审批流程
→ 点击"启用"
→ 再次校验互斥 → 通过 → Toast "开启成功" → 员工端出现"我的权限"入口
→ 页面刷新为已开启状态

分支：
- 互斥校验失败 → 阻止进入设置页，提示具体冲突模式
```

### 次路径

**路径 S1：员工查看申请记录并撤销**
```
我的权限页 → 切换至"申请记录" → 查看列表 → 点击"撤销" → 二次确认 → 撤销成功
```

**路径 S2：员工被拒绝后重新申请**
```
申请记录列表 → 找到"已拒绝"记录 → 查看拒绝原因 → 点击"重新申请" → 复用历史信息 → 修改后提交
```

**路径 S3：超管编辑已启用模式**
```
模式已开启页 → 点击"编辑" → 页面变为可编辑态 → 修改配置 → 点击"确认编辑" → Toast "编辑成功"
```

**路径 S4：超管关闭模式**
```
模式已开启页 → 点击"关闭模式" → 二次确认弹窗 → 确认关闭 → 校验在途流程 → 通过 → 关闭成功
分支：
- 存在在途流程 → 关闭失败弹窗 → 提示联系审批人完成审批
```

## §3 主交互流程

### §3.1 超管开启并配置自助申请模式

#### 节点 N1：进入权限管理模式

| 字段 | 内容 |
|------|------|
| 用户动作 | 进入"权限管理模式"页，查看各模式卡片 |
| 系统反馈 | 展示子管理员模式、双管理员互审模式、权限变更审批模式、自助申请权限模式四个卡片 |
| 需要前置解释的信息 | 自助申请权限模式的说明文案："员工可自助申请权限，工作流审批通过后，系统将自动分配权限" |
| 建议文案 | 模式卡片标题："自助申请权限模式"；说明文案："员工可自助申请权限，工作流审批通过后，系统将自动分配权限"；链接："了解更多"（跳转帮助文档） |
| 下一步 | 点击"立即启用"按钮 |

#### 节点 N2：互斥校验

| 字段 | 内容 |
|------|------|
| 用户动作 | 点击"立即启用" |
| 系统反馈 | 校验双管理员互审模式和权限变更审批模式是否已开启 |
| 需要前置解释的信息 | — |
| 建议文案 | 校验通过：进入设置页；校验失败：弹窗提示"企业已开启「双管理员互审模式」，不能同时开启此模式"（根据实际冲突模式显示） |
| 下一步 | 校验失败：关闭弹窗，可先去关闭冲突模式 |

#### 节点 N3：三步设置

**第一步：选择申请方式**

| 字段 | 内容 |
|------|------|
| 用户动作 | 在"申请角色"和"申请功能权限"之间单选，默认选中"申请角色" |
| 系统反馈 | 选中项高亮，下方展示对应的提示文案 |
| 需要前置解释的信息 | 两种方式的适用场景差异，帮助管理员根据企业管理方式选择 |
| 建议文案 | 申请角色下方："1. 申请通过后，员工将自动关联上申请角色 2. 如果启用常用角色进行授权，建议采用此方式"；申请功能权限下方："1. 申请通过后，员工将自动授权功能权限 2. 如果企业常用用户直接授权的方式，建议采用此方式" |
| 下一步 | 点击"下一步"进入第二步 |

**第二步：设置范围**

| 字段 | 内容 |
|------|------|
| 用户动作 | 如果第一步选了"申请角色"：选择角色范围（全部角色/部分角色），默认"全部角色"；如果选"部分角色"，弹窗中选择具体角色；如果第一步选了"申请功能权限"：选择应用范围（全部应用/部分应用），默认"全部应用" |
| 系统反馈 | 选择"全部"时直接展示摘要；选择"部分"时弹窗选择，选择后展示已选项 |
| 需要前置解释的信息 | 范围决定了员工能看到和申请的内容边界 |
| 建议文案 | 提示语："请选择允许员工自助申请的角色/应用"；设置项："后续新增角色/应用自动加入员工可申请的范围"（默认选中） |
| 下一步 | 点击"下一步"进入第三步 |

**第三步：设置审批流程**

| 字段 | 内容 |
|------|------|
| 用户动作 | 查看预设审批流程（组织负责人），如需修改点击"修改审批流程" |
| 系统反馈 | 点击"修改审批流程"进入表单编辑子页面；点击返回回到设置页，页面不刷新 |
| 需要前置解释的信息 | 预设审批人为员工所在组织的组织负责人；修改后所有申请都走自定义流程 |
| 建议文案 | 提示文案："系统已预设了「员工申请权限」时的审批流程，预设审批人为员工所在组织的组织负责人。如需调整，可点击修改审批流程" |
| 下一步 | 点击"启用" |

#### 节点 N4：启用

| 字段 | 内容 |
|------|------|
| 用户动作 | 点击"启用" |
| 系统反馈 | 再次校验互斥模式；校验通过后启用成功 |
| 需要前置解释的信息 | — |
| 建议文案 | 成功 Toast："开启成功"；已开启页提示语："此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。帮助文档" |
| 下一步 | 员工端"个人中心"出现"我的权限"入口 |

### §3.2 员工申请权限

#### 节点 N5：进入我的权限

| 字段 | 内容 |
|------|------|
| 用户动作 | 进入个人中心，点击"我的权限"入口（位于"我的企业"下方） |
| 系统反馈 | 打开我的权限页，默认展示功能权限 tab |
| 需要前置解释的信息 | — |
| 建议文案 | — |
| 下一步 | 查看已有权限，或点击"申请权限" |

#### 节点 N6：申请权限

| 字段 | 内容 |
|------|------|
| 用户动作 | 点击"申请权限"按钮 |
| 系统反馈 | 从右侧滑出申请权限 Drawer |
| 需要前置解释的信息 | 根据管理员配置的模式不同，Drawer 中展示角色列表或功能权限列表；如果是角色模式，员工勾选的是角色；如果是功能权限模式，员工勾选的是应用下的功能权限 |
| 建议文案 | 功能权限模式提示语："提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。" |
| 下一步 | 选择要申请的内容 |

#### 节点 N7：填写并提交

| 字段 | 内容 |
|------|------|
| 用户动作 | ① 申请人（默认当前用户，不可编辑）② 从列表中选择要申请的角色/功能权限 ③ 填写申请原因（必填，最多500字）④ 点击"提交申请" |
| 系统反馈 | 提交时执行后端校验（资金用户、子管理员模式、实名要求、特殊身份默认权限） |
| 需要前置解释的信息 | 申请原因建议写清需要使用该权限处理的业务场景 |
| 建议文案 | 申请原因 placeholder："请填写申请原因" |
| 下一步 | 校验通过 → Drawer 关闭 → Toast "提交成功" → 申请记录新增"审批中"记录 |

### §3.3 审批人审批权限申请

#### 节点 N8：审查并决策

| 字段 | 内容 |
|------|------|
| 用户动作 | ① 在 OA 审批待办列表中找到权限申请 ② 打开详情 ③ 查看申请人、申请内容、申请原因 ④ 选择"同意"或"否决" |
| 系统反馈 | 展示申请详情，包括申请人姓名、申请的角色名（含权限说明摘要）/功能权限、"查看详情"链接、申请原因全文 |
| 需要前置解释的信息 | 申请的权限包含哪些具体功能，帮助审批人判断是否合理 |
| 建议文案 | 权限说明摘要格式：角色名/功能权限名 + "包含{主要功能清单}等{N}项功能权限" |
| 下一步 | 同意 → 系统自动分配 → 通知申请人；否决 → 填写否决原因 → 流程终止 → 通知申请人 |

## §4 次交互流程

### §4.1 员工查看申请记录并撤销

| 字段 | 内容 |
|------|------|
| 触发条件 | 员工提交申请后，想查看申请进度或撤销申请 |
| 用户动作 | ① 进入"我的权限"页 ② 切换到"申请记录"tab ③ 查看列表（按日期、状态筛选）④ 找到审批中的记录 ⑤ 点击"撤销" |
| 系统反馈 | 点击"撤销"后弹出二次确认 → 确认后状态变为"已撤销" |
| 需要前置解释的信息 | 撤销后如需重新申请需再次提交完整信息 |
| 建议文案 | 二次确认文案："确定撤销该申请？撤销后如需重新申请，需要重新提交申请信息。" |
| 下一步 | 撤销成功后回到列表，状态刷新为"已撤销"；可重新发起申请 |

### §4.2 超管编辑已启用的配置

| 字段 | 内容 |
|------|------|
| 触发条件 | 模式已启用后，超管需要调整申请方式、范围或审批流程 |
| 用户动作 | ① 在已开启状态页点击"编辑" ② 页面变为可编辑态，按钮变为"取消编辑"和"确认编辑" ③ 修改配置 ④ 点击"确认编辑" |
| 系统反馈 | 编辑态恢复三步设置内容，修改后点击确认 → Toast "编辑成功" |
| 需要前置解释的信息 | 修改配置后，已在途的申请仍按原配置流转 |
| 建议文案 | 编辑区提示："修改配置后，已在审批中的申请仍按原设置流转。" |
| 下一步 | 回到查看态 |

### §4.3 超管关闭模式

| 字段 | 内容 |
|------|------|
| 触发条件 | 超管决定不再使用自助申请权限模式 |
| 用户动作 | ① 在已开启状态页点击"关闭模式" ② 弹出二次确认弹窗 ③ 点击"确认关闭" |
| 系统反馈 | 校验是否存在在途流程 → 有则关闭失败并弹窗提示 → 无则关闭成功 → Toast 提示 |
| 需要前置解释的信息 | 关闭后员工将无法自助查询和申请权限，已有权限不受影响 |
| 建议文案 | 二次确认文案："关闭模式后，员工将无法自助查询和申请权限，请确认是否关闭自助申请模式？"；关闭失败文案："当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式" |
| 下一步 | 关闭成功 → 员工端"我的权限"入口消失 → 员工无法再发起新申请；关闭失败 → 联系审批人或等待在途流程完成 |

### §4.4 员工被拒绝后重新申请

| 字段 | 内容 |
|------|------|
| 触发条件 | 审批人否决了员工的权限申请 |
| 用户动作 | ① 收到拒绝通知 ② 进入申请记录列表 ③ 查看被拒绝的申请 ④ 查看拒绝原因 ⑤ 点击"重新申请" |
| 系统反馈 | 打开申请权限 Drawer，预填上次的申请内容和申请原因，员工可修改后重新提交 |
| 需要前置解释的信息 | 根据拒绝原因调整申请内容或补充申请原因 |
| 建议文案 | — |
| 下一步 | 修改后重新提交，进入审批流程 |

## §5 异常与阻断流程

### §5.1 审批人长时间未处理

| 字段 | 内容 |
|------|------|
| 发生时机 | 员工提交申请后，审批人在合理时间内未处理 |
| 触发条件 | 申请单在"审批中"状态超过预设时长（如 3 个工作日），或超过管理员配置的时限 |
| 判断依据 | 系统记录申请提交时间和当前时间，对比超时阈值 |
| 反馈形式 | 系统通知 + 申请记录列表状态列增加"超时待处理"辅助标识 |
| 系统反馈 | 向审批人发送催办通知（内容参考建议文案）；向申请人发送提醒通知（"您的申请已提交 X 天，审批人尚未处理"） |
| 用户下一步 | 员工：查看催办进展，或联系审批人线下沟通；审批人：收到催办后尽快处理 |
| 恢复路径 | 审批人处理完成后自动恢复，员工无额外操作 |

### §5.2 自动分配权限失败

| 字段 | 内容 |
|------|------|
| 发生时机 | 审批人同意后，系统执行自动分配时 |
| 触发条件 | 系统自动分配权限时发生异常（如角色已停用、关联数据异常、系统内部错误） |
| 判断依据 | 后端分配任务执行结果 |
| 反馈形式 | 系统通知 + 审批单状态标注异常 |
| 系统反馈 | 向申请人发送通知（"您的申请已审批通过，但权限自动分配遇到问题，请稍后重试或联系管理员"）；向审批人或管理员发送通知（"审批通过的权限分配失败，需要人工介入处理"） |
| 用户下一步 | 员工：稍后重试或联系超管；超管/审批人：查看失败原因，手动分配或修正问题后重新触发 |
| 恢复路径 | 超管修复问题→重新触发分配→权限生效；如果无法修复，联系技术支持 |

### §5.3 提交时后端校验失败

| 字段 | 内容 |
|------|------|
| 发生时机 | 员工填写完申请内容后点击"提交" |
| 触发条件 | 资金用户校验不通过、子管理员模式权限校验失败、实名要求不满足、特殊身份默认权限冲突 |
| 判断依据 | 后端校验结果 |
| 反馈形式 | Drawer 不关闭，在页面顶部或对应位置显示具体错误提示 |
| 系统反馈 | 阻止提交，展示具体失败原因（优于"提交失败"的泛化提示） |
| 用户下一步 | 根据提示调整（如先完成实名认证）或联系管理员 |
| 恢复路径 | 修正问题后重新点击"提交"，不丢失已填写的申请内容 |

### §5.4 审批人否决后反馈

| 字段 | 内容 |
|------|------|
| 发生时机 | 审批人点击"否决"并提交后 |
| 触发条件 | 审批人否决了权限申请 |
| 判断依据 | 审批人选择"否决"并提交 |
| 反馈形式 | 通知申请人 + 申请记录状态更新为"已拒绝" |
| 系统反馈 | 向申请人发送通知（含否决原因）；申请记录状态更新 |
| 用户下一步 | 查看拒绝原因 → 调整后重新申请，或联系审批人了解详情 |
| 恢复路径 | 被拒后如需重新申请，可通过"重新申请"入口复用历史信息提交（见 §4.4） |

### §5.5 关闭模式时存在在途流程

| 字段 | 内容 |
|------|------|
| 发生时机 | 超管确认关闭自助申请模式时 |
| 触发条件 | 当前存在未完成的审批流程 |
| 判断依据 | 系统查询在途申请单 |
| 反馈形式 | 关闭失败弹窗，展示提示文案 |
| 系统反馈 | 关闭失败，弹窗提示有在途流程需要先完成 |
| 用户下一步 | 联系审批人尽快处理，或在在途流程全部完成后重新尝试关闭 |
| 恢复路径 | 所有在途流程处理完毕（通过/否决/撤销）后，超管可正常关闭模式 |
