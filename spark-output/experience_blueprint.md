# 员工自助申请权限 — 体验蓝图

## §0 本次关键设计判断

**判断**：体验设计的核心是把"管理员集中授权"的单通道扩展为"管理员授权 + 员工自助申请"的双通道，同时保证员工侧低认知门槛、审批人侧判断信息充分、管理员侧配置可控。

**主要影响**：员工端需要在现有权限体系中新增两条申请路径（角色/功能），且两条路径的信息结构、申请粒度、审批判断依据不同。管理端需新增双维度范围配置能力，且配置结果直接影响员工端展示。

**建议方案**：员工端以"我的权限"为前置页，从此页进入申请流程。申请入口按角色和功能分两个 Tab 承载。管理端用单页 Tab 切换承载角色范围和功能范围配置。审批端复用审批中台待办列表，在审批详情中扩展"申请人当前权限"和"申请后能力变化"两个信息区。关闭能力时用弹窗展示在途申请清单并强制选择处理策略。

**不建议方案**：角色申请和功能申请合并为统一表单（两条路径的申请粒度不同，合并反而增加认知负担）；关闭能力时不做在途确认直接关闭；在员工端展示管理员未配置的"系统全部权限"。

**关键待确认**：GAP-01（审批人来源规则）影响审批路由体验；GAP-02（与治理模式关系）影响配置页逻辑分支；GAP-03（关闭时在途处理策略）影响关闭流程体验。以上三项层级一问题基于推荐方案推进，详见 §8。

## §1 旅程图

### 角色一：员工（申请人）

**路径总览**：发现入口 → 了解当前权限 → 发现缺口 → 选择申请方式 → 提交申请 → 等待结果 → 获得权限

**阶段 1：发现入口**
- 目标：在工作台或权限相关页面找到"我的权限"和"申请权限"入口
- 关键触点：工作台导航 / 权限管理模块内嵌入口
- 信心：中（入口是否可见取决于能力是否开启）
- 痛点：如果入口藏得深，员工根本不知道有这个能力

**关键转折**：能力已开启 + 员工知道自己需要什么权限 → 进入下一阶段

**阶段 2：了解当前权限**
- 目标：看清自己已经有什么权限，来源分别是什么
- 关键触点：我的权限页面（按应用/功能聚合展示，含来源标注）
- 信心：高（能清晰看到全貌）
- 痛点：权限信息量可能较大，来源标注不清晰时员工难以判断"我缺什么"

**关键转折**：员工确认自己缺少某项权限 → 产生申请动机

**阶段 3：选择申请方式**
- 目标：在可申请的角色和功能权限之间，找到自己需要的并理解区别
- 关键触点：申请权限页（角色 Tab / 功能权限 Tab）
- 信心：中（取决于可申请范围的清晰程度和角色/功能说明是否完整）
- 痛点：员工可能分不清"申请角色"和"申请功能权限"的区别——角色是打包授权，功能权限是单点授权

**关键转折**：员工理解了申请选项并做出选择 → 进入申请表单

**阶段 4：提交申请**
- 目标：填写申请原因并提交，理解接下来会发生什么
- 关键触点：申请表单（申请原因 + 提交确认）
- 信心：中高（如果能预览审批流程会更高）
- 痛点：不知道审批人是谁、审批要多久、提交后还能不能撤回

**关键转折**：提交成功 → 进入等待状态

**阶段 5：等待结果**
- 目标：知道申请走到哪了、大概要等多久
- 关键触点：申请记录页（申请状态、审批进度）
- 信心：中（如果审批超时没有自动提醒会焦虑）
- 痛点：审批卡住时不知道是审批人没看还是故意不处理

**关键转折**：审批完成 → 收到结果通知

**阶段 6：获得权限（或被拒）**
- 目标：知道审批结果、权限何时可用、被拒后怎么办
- 关键触点：审批结果通知 + 我的权限页更新
- 信心：通过时高，被拒时低
- 痛点：被拒后不清楚原因、不知道能不能再申请

### 角色二：审批人

**路径总览**：收到待办 → 查看申请内容 → 判断合理性 → 同意/拒绝 → 确认结果

**阶段 1：收到待办**
- 目标：在待办列表中识别出这是"权限申请"类型的审批
- 关键触点：审批中心待办列表
- 信心：高（如果列表摘要信息足够判断优先级）
- 痛点：待办太多时，权限申请可能被淹没

**关键转折**：点开待办 → 进入审批详情

**阶段 2：查看申请内容**
- 目标：全面理解申请人是谁、申请了什么、为什么申请、通过后会怎样
- 关键触点：审批详情页（申请人信息 + 当前权限 + 申请内容 + 申请原因 + 通过后能力变化）
- 信心：取决于信息是否充分
- 痛点：如果只看到"张三申请角色A"而看不到张三现在有什么、角色A能做什么，判断就会变成盲批

**关键转折**：信息充分 → 做出判断

**阶段 3：做出决定**
- 目标：在理解申请合理性的基础上，同意或拒绝
- 关键触点：审批操作区（同意/拒绝按钮 + 审批意见）
- 信心：信息充分时高
- 痛点：如果审批人担心"同意后出事谁负责"，会倾向于拒绝或拖延

**关键转折**：做出决定 → 系统自动处理结果

**阶段 4：确认结果**
- 目标：确认操作已生效，申请人已获通知
- 关键触点：审批结果反馈 + 待办列表更新
- 信心：高
- 痛点：同意后如果自动授权失败但没有明显提示，审批人不知道出了问题

---

### 角色三：权限管理员

**路径总览**：了解能力 → 规划范围 → 配置角色范围 → 配置功能范围 → 配置审批规则 → 开启能力 → 监控运行 → 按需调整

**阶段 1：了解能力**
- 目标：理解自助申请是什么、能控制什么、有什么风险
- 关键触点：权限管理后台中的自助申请配置入口
- 信心：取决于配置页是否有清晰的引导说明
- 痛点：如果配置页没有任何解释，管理员可能不敢操作

**关键转折**：理解能力后 → 决定配置

**阶段 2：配置可申请范围（角色）**
- 目标：从角色列表中选出哪些角色允许员工自助申请
- 关键触点：角色范围配置区
- 信心：高（勾选操作本身简单）
- 痛点：角色数量多时，逐个勾选效率低；不知道某个角色选了之后意味着什么

**关键转折**：角色范围配置完成 → 切换到功能维度

**阶段 3：配置可申请范围（功能权限）**
- 目标：从功能权限树中选出哪些功能权限允许员工自助申请
- 关键触点：功能权限范围配置区（应用 → 功能 → 权限级别）
- 信心：中（三级结构比角色选择复杂）
- 痛点：功能权限层级深、数量多，配置容易遗漏或误选

**关键转折**：两个维度都配置完成 → 配置审批规则

**阶段 4：配置审批规则**
- 目标：指定审批人来源，确保每个申请都能找到正确的审批人
- 关键触点：审批规则配置区
- 信心：中（取决于审批人来源的配置复杂度）
- 痛点：如果审批人来源配置不当（如选了不存在的审批人），员工提交时会直接报错

**关键转折**：所有配置完成 → 开启能力

**阶段 5：监控与调整**
- 目标：查看当前运行状态、申请量、是否有异常
- 关键触点：申请记录列表（管理员视角）、能力状态面板
- 信心：中高
- 痛点：缺乏申请量趋势和异常汇总视图

---

### 角色四：超级管理员

**路径总览**：评估开启 → 开启能力 → 日常关注 → 决定关闭 → 处理在途申请 → 确认关闭

**阶段 1：开启能力**
- 目标：确认配置已完成，安全开启自助申请
- 关键触点：自助申请开关（开启确认）
- 信心：取决于前置检查是否充分
- 痛点：开关打开前没有检查清单（范围是否已配、审批规则是否已设），开了之后员工看到空列表

**关键转折**：能力开启 → 进入运行

**阶段 2：关闭能力**
- 目标：安全关闭，处理好进行中的申请
- 关键触点：关闭确认弹窗（在途申请清单 + 处理策略选择）
- 信心：取决于在途申请的数量和状态分布
- 痛点：如果在途申请很多，关闭变成负担；不知道选哪种处理策略更合适

**关键转折**：确认关闭 → 能力下线

## §2 交互流程总览

### 分角色流程

**员工路径**：
我的权限（查看） → 申请权限（选择角色或功能） → 填写原因并提交 → 申请记录（追踪状态） → 收到结果通知

**审批人路径**：
审批中心待办（收到权限申请） → 审批详情（查看申请人信息+当前权限+申请内容+原因） → 同意/拒绝 → 结果确认

**管理员路径**：
权限管理后台 → 自助申请配置（角色范围 / 功能范围 / 审批规则） → 开启能力 → 申请记录监控

**超管路径**：
权限管理模式页 → 自助申请开关（开启/关闭） → 关闭时处理在途申请 → 确认

### 异常流程重点

- 审批人不存在：提交时阻断，引导员工联系管理员
- 自动授权失败：审批通过但授权异常，通知管理员人工处理
- 能力关闭时有在途申请：强制超管选择处理策略后才允许关闭
- 可申请范围为空：员工端展示空状态引导
- 重复申请：已拥有的权限在可申请列表中置灰不可选

## §3 主交互流程

### 流程一：员工查看我的权限（F1）

**节点 1-1：进入"我的权限"**
- 用户动作：在工作台或权限相关入口点击"我的权限"
- 系统反馈：加载并展示权限清单
- 需要前置解释的信息：页面仅展示当前用户已生效的权限，不含审批中的申请
- 建议文案：页面标题"我的权限"，副标题"以下是你当前拥有的所有权限"
- 下一步：查看权限详情，或点击"申请权限"进入申请流程

**节点 1-2：浏览权限清单**
- 用户动作：按应用分组浏览权限列表，查看每条权限的来源标注
- 系统反馈：每条权限展示：应用名称、权限内容（角色名/功能权限名）、来源标注（管理员授予/角色授权/自助申请）、授予时间
- 需要前置解释的信息：来源标注帮助员工理解"这个权限是怎么来的"
- 建议文案：来源标签——"管理员授予""角色授权""自助申请"
- 下一步：发现缺少某权限时，点击"申请权限"按钮

**节点 1-3：查看权限来源详情**
- 用户动作：点击某条权限的来源标签
- 系统反馈：展示该权限的完整来源信息——授予人/角色/申请单号、授予时间、审批记录（如有）
- 建议文案："此权限来自自助申请（申请单号：XXX），由 XXX 审批通过，于 YYYY-MM-DD 生效"
- 下一步：返回权限清单

---

### 流程二：员工申请角色权限（F2）

**节点 2-1：进入申请页并选择"申请角色"**
- 用户动作：在"我的权限"页点击"申请权限"，默认进入"申请角色"Tab
- 系统反馈：展示可申请的角色列表，每项含角色名称、角色说明、包含的功能权限概要
- 需要前置解释的信息：角色是打包授权——申请一个角色会同时获得该角色下的所有功能权限
- 建议文案：Tab 标签"申请角色 | 申请功能权限"；角色列表空状态："当前暂无可申请的角色，如需帮助请联系管理员"
- 下一步：点击某个角色，进入申请详情

**节点 2-2：查看角色详情并决定申请**
- 用户动作：点击角色卡片，展开查看角色包含的功能权限清单
- 系统反馈：展示角色名称、角色描述、包含的功能权限列表、审批流程预览（可选）
- 需要前置解释的信息：让员工在申请前充分了解这个角色能做什么
- 建议文案：按钮"申请此角色"（已拥有的角色显示"已拥有"并置灰）
- 下一步：点击"申请此角色"

**节点 2-3：填写申请原因并提交**
- 用户动作：在申请表单中填写申请原因，点击提交
- 系统反馈：校验申请原因是否填写，提交成功后展示成功提示并跳转到申请记录页
- 需要前置解释的信息：申请提交后将由审批人审核，审批结果会通过通知告知
- 建议文案：表单字段"申请原因"（占位："请简要说明为什么需要此角色，以便审批人了解情况"）；提交成功 Toast："申请已提交，请等待审批人处理"
- 下一步：跳转到"我的申请记录"页

---

### 流程三：员工申请功能权限（F3）

**节点 3-1：切换到"申请功能权限"Tab**
- 用户动作：在申请页点击"申请功能权限"Tab
- 系统反馈：展示可申请的功能权限列表，按应用分组，每项含功能名称、权限级别、说明
- 需要前置解释的信息：功能权限是单点授权——只授予某一具体功能的操作权限，不包含其他功能
- 建议文案：功能列表分组标题为应用名称；空状态："当前暂无可申请的功能权限，如需帮助请联系管理员"
- 下一步：点击某个功能权限

**节点 3-2：查看功能权限详情并决定申请**
- 用户动作：点击功能权限项查看详情
- 系统反馈：展示功能名称、所属应用、权限说明、审批流程预览（可选）
- 建议文案：按钮"申请此权限"（已拥有的显示"已拥有"并置灰）
- 下一步：点击"申请此权限"

**节点 3-3：填写申请原因并提交**
- 用户动作：填写申请原因，点击提交
- 系统反馈：同角色申请——校验→提交成功→跳转申请记录
- 建议文案：同节点 2-3
- 下一步：跳转到"我的申请记录"

---

### 流程四：审批人处理权限申请（F7）

**节点 4-1：在待办列表中发现权限申请**
- 用户动作：在审批中心待办列表看到一条权限申请待办
- 系统反馈：待办摘要展示：申请人姓名、申请类型（角色/功能）、申请内容名称、提交时间
- 需要前置解释的信息：待办列表需要能区分"权限申请"和其他类型的审批
- 建议文案：待办类型标识"权限申请"
- 下一步：点击进入审批详情

**节点 4-2：查看审批详情**
- 用户动作：浏览审批详情中的各项信息
- 系统反馈：展示以下信息区——
  - 申请人信息区：姓名、部门、岗位
  - 当前权限区：申请人当前拥有的相关权限清单
  - 申请内容区：申请的角色/功能权限名称及其说明
  - 通过后变化区：通过后将新增的权限能力
  - 申请原因区：申请人填写的申请原因
  - 审批历史区：如有前置审批节点，展示历史审批记录
- 需要前置解释的信息："通过后变化区"帮助审批人快速理解审批后果
- 建议文案：信息区分组标题——"申请人信息""当前权限""申请内容""通过后将获得的能力""申请原因"
- 下一步：做出审批决定

**节点 4-3：同意申请**
- 用户动作：填写审批意见（如设置为必填），点击"同意"
- 系统反馈：二次确认（如需要）。确认后系统自动完成授权，展示成功反馈。权限来源标注为"自助申请"。
- 建议文案：同意确认弹窗——"确认同意该申请？通过后系统将自动为申请人授予对应权限。"；成功反馈——"已同意，权限已自动授予申请人"
- 下一步：返回待办列表，该待办已清除

**节点 4-4：拒绝申请**
- 用户动作：填写拒绝原因（必填），点击"拒绝"
- 系统反馈：二次确认。确认后申请状态变更为"已拒绝"，通知申请人。
- 建议文案：拒绝原因占位——"请说明拒绝原因，以便申请人了解"；成功反馈——"已拒绝该申请，申请人将收到通知"
- 下一步：返回待办列表

---

### 流程五：管理员配置可申请范围 — 角色维度（F5）

**节点 5-1：进入角色范围配置**
- 用户动作：在权限管理后台进入"自助申请配置"，选择"可申请角色"Tab
- 系统反馈：展示系统中所有角色列表，每项含：角色名称、角色描述、当前是否可申请（勾选状态）、已申请人数（可选）
- 需要前置解释的信息：勾选的角色将出现在员工的"申请角色"列表中。取消勾选不影响已通过申请的已有授权。
- 建议文案：Tab 标签"可申请角色 | 可申请功能权限 | 审批规则"；页面说明——"配置员工可以在自助申请中看到的角色范围"
- 下一步：勾选或取消勾选角色

**节点 5-2：调整角色选择**
- 用户动作：勾选需要开放的角色，取消不需要的角色
- 系统反馈：即时保存（或统一保存按钮）。取消勾选后，新申请中不再出现该角色，但已有的申请不受影响。
- 建议文案：保存成功 Toast——"可申请角色范围已更新"
- 下一步：切换到功能权限 Tab

### 流程六：管理员配置可申请范围 — 功能权限维度（F5）

**节点 6-1：进入功能权限范围配置**
- 用户动作：在"可申请功能权限"Tab 查看功能权限树
- 系统反馈：展示应用→功能→权限级别的三层树结构，每级可勾选
- 需要前置解释的信息：功能权限按三级结构组织，勾选父级不自动勾选子级
- 建议文案：空状态——"暂未配置可申请的功能权限，员工端将显示为空"
- 下一步：在树中勾选需要开放的功能权限

**节点 6-2：调整功能权限选择**
- 用户动作：展开应用→展开功能→勾选权限级别
- 系统反馈：支持按应用批量展开/收起。勾选即时保存。
- 建议文案：保存成功 Toast——"可申请功能权限范围已更新"
- 下一步：切换到审批规则 Tab

### 流程七：管理员配置审批规则（F6）

**节点 7-1：选择审批人来源类型**
- 用户动作：在审批规则 Tab 选择审批人来源类型
- 系统反馈：展示可选的审批人来源——直属上级、指定角色、指定成员组、审批角色（与现有审批中台审批人来源对齐）
- 需要前置解释的信息：审批人来源决定每个申请提交后由谁审批。如果选定的审批人不存在或不可用，员工提交时会被阻断。
- 建议文案：审批人来源说明——"选择'直属上级'时，系统将自动取申请人的直属上级作为审批人。如果申请人没有明确的直属上级，申请将无法提交。"
- 下一步：根据选择的来源类型，展示对应的选项（如选"指定角色"则展示角色列表）

**节点 7-2：配置具体审批人并保存**
- 用户动作：根据选择的来源类型，补充具体配置（如选择具体角色/成员组）
- 系统反馈：保存成功
- 建议文案：保存成功 Toast——"审批规则已更新"
- 下一步：预览验证或直接开启能力

### 流程八：超管开启/关闭能力（F8）

**节点 8-1：开启自助申请能力**
- 用户动作：在权限管理模式页找到"员工自助申请权限"开关，点击开启
- 系统反馈：开启前检查——可申请范围是否已配置、审批规则是否已配置。如有未配置项，提示先完成配置。全部就绪后确认开启。
- 建议文案：前置检查提示——"尚未配置可申请范围，员工将看到空列表。建议先完成配置再开启。"；确认开启——"确认开启员工自助申请权限？开启后员工可在工作台看到申请入口。"
- 下一步：能力开启，员工端入口出现

**节点 8-2：关闭自助申请能力（有在途申请）**
- 用户动作：点击关闭开关
- 系统反馈：系统检查在途申请（待审批+审批中），如有在途申请，弹窗展示在途申请清单和处理选项
- 建议文案：弹窗标题"关闭前处理在途申请"；清单——"当前有 X 条待审批申请、Y 条审批中申请"；处理选项——"全部自动拒绝 / 等待当前批次处理完毕后自动关闭 / 管理员逐单处理"
- 下一步：超管选择处理方式并确认关闭

**节点 8-3：关闭自助申请能力（无在途申请）**
- 用户动作：点击关闭开关
- 系统反馈：二次确认弹窗
- 建议文案："确认关闭员工自助申请权限？关闭后员工端将不再显示申请入口，已通过的权限不受影响。"
- 下一步：确认关闭，能力下线

## §4 次交互流程

### 次流程一：员工查看申请记录（F4）

- 触发条件：员工从"我的权限"页或通知进入"我的申请记录"
- 用户动作：浏览申请列表（按提交时间倒序），按状态筛选（全部/待审批/已通过/已拒绝）
- 系统反馈：每条申请展示——申请类型图标、申请内容名称、提交时间、当前状态、审批人姓名
- 建议文案：状态标签——"待审批""已通过""已拒绝""已撤销"；空状态——"暂无申请记录"
- 下一步：点击某条申请查看详情

### 次流程二：员工查看申请详情

- 触发条件：在申请记录列表点击某条申请
- 用户动作：查看申请的完整信息和审批进度
- 系统反馈：展示——申请内容、申请原因、提交时间、审批人、审批意见、审批时间、当前状态
- 需要前置解释的信息：已拒绝的申请展示拒绝原因，帮助员工理解下一步怎么办
- 建议文案：已拒绝状态下方——"此申请已被拒绝。如需重新申请，请联系管理员确认。"
- 下一步：返回列表

### 次流程三：员工撤销待审批申请

- 触发条件：员工在申请详情页看到"待审批"状态的申请，点击"撤销申请"
- 用户动作：确认撤销
- 系统反馈：二次确认弹窗，确认后申请状态变更为"已撤销"，审批人待办消除
- 建议文案：确认弹窗——"确认撤销此申请？撤销后审批人将不再收到此待办。"；成功——"申请已撤销"
- 下一步：返回申请记录列表

### 次流程四：管理员查看全量申请记录

- 触发条件：管理员在自助申请配置页点击"查看申请记录"
- 用户动作：查看所有员工的申请记录，支持按状态、时间、申请人筛选
- 系统反馈：列表展示——申请人姓名、申请类型、申请内容、提交时间、当前状态、审批人
- 下一步：点击某条查看详情，或对异常申请进行人工处理

### 次流程五：审批人查看已处理申请

- 触发条件：审批人在审批中心"已处理"列表查看
- 用户动作：回顾自己处理过的权限申请
- 系统反馈：展示已处理的申请列表，标注处理结果（同意/拒绝）和处理时间
- 下一步：点击查看详情回顾

## §5 异常与阻断流程

### 异常一：审批人不存在

- 发生时机：员工点击"提交申请"时
- 触发条件：管理员配置的审批人来源规则未匹配到有效审批人（如选了"直属上级"但员工没有明确的直属上级）
- 判断依据：系统按审批规则计算审批人，返回空结果
- 反馈形式：提交按钮处置灰 + 页面顶部 Banner 提示
- 系统反馈：阻止提交
- 用户下一步：提示"当前无法提交申请，因审批人信息不完整。请联系管理员完善审批规则。"员工联系管理员

### 异常二：自动授权失败

- 发生时机：审批人点击"同意"后
- 触发条件：系统尝试自动授予权限时发生异常（如权限接口不可用、权限冲突）
- 判断依据：授权接口返回失败
- 反馈形式：审批人端——弹窗提示；管理员端——通知
- 系统反馈：审批人看到"授权遇到异常，已通知管理员处理"。申请状态标记为"授权异常"。管理员收到通知。
- 用户下一步：审批人可继续处理其他待办；管理员在权限管理后台排查原因并人工补授权

### 异常三：能力关闭时有在途申请（基于推荐方案推进）

- 发生时机：超管点击关闭开关
- 触发条件：系统中存在状态为"待审批"或"审批中"的申请
- 判断依据：系统查询在途申请数量 > 0
- 反馈形式：弹窗
- 系统反馈：弹窗展示在途申请数量和状态分布，提供三种处理策略供选择——
  - 全部自动拒绝：所有在途申请自动拒绝，通知申请人
  - 等待处理完毕：关闭入口但允许当前批次走完审批流程，全部处理完后自动关闭
  - 逐单处理：由管理员在申请记录中逐单决定
- 用户下一步：超管选择处理策略并确认关闭

### 异常四：可申请范围为空

- 发生时机：员工进入申请页
- 触发条件：管理员开启了能力，但未配置任何可申请角色或功能权限
- 判断依据：可申请角色列表和可申请功能权限列表均为空
- 反馈形式：空状态（页面占位）
- 系统反馈：展示空状态插图 + 提示文案
- 用户下一步：提示"当前暂无可申请的权限，如需帮助请联系管理员。"员工联系管理员

### 异常五：重复申请已拥有的权限

- 发生时机：员工在可申请列表中看到自己已拥有的权限
- 触发条件：员工通过其他途径已拥有该角色或功能权限
- 判断依据：对比员工当前权限与可申请范围
- 反馈形式：列表项置灰 + "已拥有"标签
- 系统反馈：该项不可点击、不可勾选
- 用户下一步：员工看到"已拥有"标签，理解无需重复申请

### 异常六：审批通过时权限已存在

- 发生时机：审批人同意申请后，系统自动授权时
- 触发条件：审批期间员工通过其他途径获得了同一权限
- 判断依据：授权前再次校验权限是否已存在
- 反馈形式：审批人端——Toast 提示；申请记录更新
- 系统反馈：不重复授权，申请记录标记为"已覆盖"，备注"审批通过时该权限已通过其他途径获得"
- 用户下一步：审批人收到 Toast "该权限已存在，无需重复授权"；员工在申请记录中看到覆盖说明

### 异常七：审批超时（基于推荐方案推进）

- 发生时机：申请提交后超过设定时限
- 触发条件：审批人在设定时间内未处理（如 72 小时）
- 判断依据：超过管理员配置的超时时限
- 反馈形式：审批人端——催办通知；员工端——申请记录状态更新
- 系统反馈：按管理员配置的超时策略处理——超时提醒（通知审批人）/ 超时转派（转给其他审批人）/ 超时通过/拒绝
- 用户下一步：员工看到申请状态更新；审批人收到催办

## §7 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|------|------|----------|-----------|-------------|
| 草稿 | 员工已创建但未提交的申请 | 员工 | 编辑、提交、删除 | "草稿" |
| 待审批 | 申请已提交，等待审批人处理 | 员工、审批人、管理员 | 员工：查看、撤销；审批人：同意/拒绝；管理员：查看 | 员工侧："等待审批中"；审批人侧：待办列表中展示 |
| 已通过 | 审批人同意，授权已完成 | 员工、审批人、管理员 | 查看 | "申请已通过，权限已生效" |
| 已生效 | 权限已实际生效 | 员工、管理员 | 查看；管理员：可撤销 | 权限详情中标注"自助申请·已生效" |
| 已拒绝 | 审批人拒绝了申请 | 员工、审批人、管理员 | 查看；[GAP] 是否允许重新申请 | "申请未通过"，附带拒绝原因 |
| 已撤销 | 员工主动撤销了待审批的申请 | 员工、管理员 | 查看 | "已撤销" |
| 已覆盖 | 审批通过时权限已通过其他途径存在 | 员工、审批人、管理员 | 查看 | "该权限已通过其他途径获得，无需重复授权" |
| 授权异常 | 审批通过但自动授权失败 | 员工、管理员 | 管理员：人工补授权或排查 | 员工侧："审批已通过，权限生效中"；管理员侧："授权异常，需人工处理" |
