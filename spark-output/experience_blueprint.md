# 体验蓝图：财富专区 — 资产配置面客版

## §0 本次关键设计判断

### 判断一：资产配置页面采用"总览 + 焦点头屏 + 次要模块延后"的信息分层策略

**判断**：六个信息模块（时点资产、持仓表现、投资分布、期限分布、诊断、推荐）不应在同一层级平铺。应该把"客户当前最关心的"放在首屏可见区（时点资产 + 持仓表现摘要），次要分析模块（分布、诊断）放在中段，行动模块（推荐 + 下载）放在末尾，形成"看到什么→分析什么→做什么"的阅读流。

**主要影响**：影响整个页面的模块排序、首屏信息密度、展开折叠策略。

**建议方案**：首屏上方展示核心总览卡片（时点资产 + 诊断状态摘要），中间是可折叠的分析模块区（持仓表现、投资分布、期限分布），底部是推荐产品区和操作区。分析模块默认只展示摘要卡片，点击展开详情。

**不建议方案**：不建议把所有模块都以同等尺寸铺满首屏，会加剧信息过载。

**关键待确认**：三类诊断结果是否需要按严重程度排序，将影响诊断模块在页面中的展现位置和视觉权重。

### 判断二：诊断结果与推荐产品之间用"问题→建议→产品"的关联卡片组建立因果链

**判断**：当前诊断出三类问题后，客户不知道"那么我该怎么做"。应该让每个诊断结果关联一个对应的建议方向和一组推荐产品，用视觉卡片组把"因为你有这个问题→建议你调整到这个方向→以下是对应的产品"串起来。

**主要影响**：影响诊断模块和推荐模块的布局关系，以及两者之间的交互联动。

**建议方案**：取消诊断模块和推荐模块的物理隔离，改为在页面底部用"诊断 × 推荐"联合卡片区承载。每张卡片包含：问题标签 → 建议方向 → 对应的推荐产品列表 → 购买按钮。

**不建议方案**：不建议在诊断模块只展示问题文字，让客户自己翻到推荐区找对应产品。

**关键待确认**：诊断结果是否显式关联推荐产品，取决于企业财富+的推荐策略是否按诊断输入生成。

### 判断三：采用模块级加载 + 独立降级，避免全屏 loading 阻塞

**判断**：六个信息模块的数据来源都是企业财富+接口，但各模块之间没有强依赖关系，可以独立加载。应该让每个模块自己负责自己的加载态和降级态，避免一个模块接口超时导致整个页面白屏。

**主要影响**：影响页面加载策略、骨架屏设计、降级展示方式。

**建议方案**：页面框架先渲染（账号选择器+模块骨架），各模块按"优先级队列"依次加载——总览卡片（高优）→ 持仓表现（中优）→ 诊断+推荐（中优）→ 分布模块（低优）。加载失败时模块级降级，不影响其他模块正常展示。

**不建议方案**：不建议用一个全屏 loading spinner 等待所有接口返回，也不建议用一个全屏 error 页面代替模块级异常。

**关键待确认**：各模块接口的实际调用方式（独立接口 vs 统一大接口）将影响模块级加载策略的实现方式。

## §1 旅程消费摘要

> 基于上游 UXB 结论推导，未经深度旅程分析。

推导的企业客户旅程包含以下关键阶段：

| 阶段 | 客户目标 | 信心状态 | 关键转折 | 流失风险 |
| --- | --- | --- | --- | --- |
| 进入页面 | 找到资产配置入口，了解自己能看什么 | 中——不清楚入口名是否匹配预期 | 明确入口命名→客户判断值不值得进入 | 入口名模糊时客户可能不点击 |
| 查看总览 | 快速了解自己的资产总额和基本状况 | 高——希望一眼看到核心信息 | 时点资产和诊断摘要首屏可见→判断是否需要深入分析 | 首屏信息太杂乱时离开 |
| 分析持仓表现 | 了解这段时间赚了多少、为什么波动 | 中——数据多时感到压力 | 时间区间筛选器让客户自主控制范围→降低信息压力 | 图表太多看不懂时跳过 |
| 了解诊断问题 | 知道自己持仓有什么风险 | 低——担心看到不好的结果，但也想了解风险 | 诊断结果明确告诉客户"有什么问题"→但若没有解决建议会困惑 | 只有问题没有建议时失去信心 |
| 获取产品推荐 | 找到适合当前情况的产品 | 中——希望推荐与诊断问题匹配 | 推荐产品与诊断问题关联→客户感到"对症" | 推荐与诊断无关时离开 |
| 执行购买 | 完成产品购买 | 高——决策链路已经走通 | 直接从推荐页跳转购买→缩短决策到行动 | 购买流程中断时放弃 |

**在本蓝图中的落点：**
- 信心最低点（诊断阶段）→ §5 异常流程中强化诊断模块的降级和恢复策略
- 关键转折（诊断→推荐）→ §3 主交互流程中设计"诊断×推荐"联合卡片组
- 流失风险（进入页面/分析阶段）→ §6 页面设计中强调首屏信息结构和模块加载优先级

## §2 交互流程总览

### 主路径

**企业客户查看资产配置 → 获取建议 → 执行购买或下载**

资产配置页面
→ 查看时点资产总览（首屏可见）
→ 选择/切换银行账号
→ 查看持仓表现（图表 + 关键指标）
→ 筛选时间区间（默认为近一月）
→ 查看投资分布 / 期限分布 Tab
→ 查看持仓诊断结果
→ 查看关联产品推荐
→ 执行操作：

  - 点击"购买" → 跳转购买页
  - 勾选多个产品 → 跳转购物车
  - 点击产品名称 → 跳转产品详情页
  - 点击下载 → 选择格式弹窗 → 下载文件

### 分支路径

**分支一：切换银行账号**
资产配置页面 → 点击账号选择器 → 选择目标账号 → 页面数据刷新

**分支二：筛选时间区间**
资产配置页面 → 点击时间区间选择器 → 选择自定义起止日期（不超过近两年） → 持仓表现模块数据更新

**分支三：下载建议书**
资产配置页面 → 点击右下角下载悬浮按钮 → 弹出格式选择（PDF / PNG）
→ 选择格式 → 生成文件 → 下载

**分支四：无持仓数据**
资产配置页面 → 判断无持仓 → 展示空状态 → 点击"去购买" → 跳转产品列表页

## §3 主交互流程

### 节点一：进入资产配置页面

**用户动作**
从财富专区菜单或持仓列表入口进入资产配置页面。

**系统反馈**
- 页面框架渲染：顶部银行账号选择器 + 各模块骨架加载占位
- 按优先级发起数据请求：总览数据（高优）→ 持仓表现（中优）→ 诊断+推荐（中优）→ 分布（低优）
- 各模块独立进入加载状态

**需要前置解释的信息**
- 页面标题统一为"资产配置建议书"
- 如从持仓列表进入，自动选中该账号；如从菜单进入，默认选中"全部账号"

**建议文案**
页面标题：资产配置建议书
账号选择器默认文案：全部账号

**状态变化**
页面状态从"加载中"转为"加载完成"（或各模块独立转换）

**下一步**
客户查看总览信息，或切换银行账号

---

### 节点二：查看总览信息

**用户动作**
浏览页面顶部的总览卡片区，了解时点资产和诊断状态摘要。

**系统反馈**
- 展示时点资产总额（自动按范围换算单位）
- 展示诊断状态摘要（如有未读诊断，显示"N项待关注"标签）

**需要前置解释的信息**
- 时点资产是截至最新时间的持仓市值总额
- 诊断状态摘要只展示"有问题/没问题"的简化信号，详情在下方诊断区

**建议文案**
时点资产标签：时点资产（{日期}）
诊断摘要：{N} 项持仓待关注 / 持仓状态良好

**下一步**
客户决定是否深入查看持仓表现或直接看诊断结果。

---

### 节点三：查看持仓表现

**用户动作**
在持仓表现模块查看图表数据和关键指标。

**系统反馈**
- 展示自定义时间区间筛选器（默认近一月）
- 展示 4 个 KPI 卡片：持仓金额、较期初、区间收益、区间年化收益率
- 展示购买/赎回统计：购买笔数、购买金额、赎回笔数、赎回金额
- 展示持仓变动趋势图和收益金额趋势图（折线图）
- 展示产品收益排行列表（按持仓收益降序）

**需要前置解释的信息**
- 较期初：当前余额相比区间开始时的增长率，期初为0时展示"-"
- 区间年化收益率：按固定公式计算，净值精度有限，仅供参考

**建议文案**
- 较期初：{增长率}（期初为0时显示"-"）
- 年化收益率尾部注释：数据由管理机构提供的最新净值测算，仅供参考

**下一步**
客户继续查看投资分布和期限分布，或跳过直接看诊断。

---

### 节点四：查看投资分布与期限分布

**用户动作**
在分布模块浏览 Tab 内容（投资分布 / 期限分布）。

**系统反馈**
- Tab 默认选中"投资分布"
- 投资分布展示：各业务类型（理财、公募基金、资管计划、信托计划）的持仓金额、占比、饼图
- 期限分布展示：按产品期限汇总的持仓金额、占比
- 理财行展示年化收益率及其排名

**需要前置解释的信息**
- 投资分布只看各类资产"占了多少"，不看表现
- 期限分布只看产品"什么时候到期"，不看收益
- 其他业务（公募基金等）仅做汇总展示，不做详细分析

**下一步**
客户查看持仓诊断结果。

---

### 节点五：查看诊断结果与推荐产品（核心关键转折点）

**用户动作**
浏览页面中段的"诊断 × 推荐"联合卡片区。

**系统反馈**
- 按诊断类型展示关联卡片组
- 每张卡片结构：

```
┌─ [诊断标签] ─────────────────────┐
│ 问题描述：活钱管理占比 X%，偏高    │
│ 建议方向：建议调整为 Y% 以下        │
│ ┌─ 推荐产品 ──────────────────┐  │
│ │ 产品A  收益率 N%  推荐理由...│  │
│ │ 产品B  收益率 N%  推荐理由...│  │
│ │ [购买] [购买]              │  │
│ └──────────────────────────────┘  │
└───────────────────────────────────┘
```

- 如无诊断问题，整个诊断推荐区不展示
- 如无推荐产品，仅展示诊断卡片，不展示推荐产品子区

**需要前置解释的信息**
- 每条诊断对应一组建议方向
- 推荐产品基于当前诊断结果生成，与客户的实际持仓和风险匹配

**建议文案**
- 诊断标签：持仓集中度过高 / 产品即将到期 / 持仓时间过长
- 建议方向：建议增配{产品类型}，降低活钱管理占比 / 建议关注到期产品续期 / 建议评估是否继续持有
- 推荐理由前缀：基于您的持仓情况推荐

**下一步**
客户选择购买产品、查看产品详情、批量勾选购买、或下载建议书。

---

### 节点六：购买产品

**用户动作**
点击推荐产品卡片中的"购买"按钮。

**系统反馈**
- 跳转至产品购买页（复用现有购买流程）
- 页面级跳转，非弹窗

**下一步**
在购买页完成交易。

---

### 节点七：批量勾选购买

**用户动作**
在推荐产品卡片区勾选多个产品，点击"批量购买"。

**系统反馈**
- 跳转至购物车页面（复用现有购物车流程）
- 已勾选产品预填入购物车

**下一步**
在购物车完成批量结算。

## §4 次交互流程

### 流程一：切换银行账号

**触发条件**
客户需要查看其他银行账号的资产配置情况。

**用户动作**
点击顶部账号选择器 → 从下拉列表中选择目标账号（或选择"全部账号"）。

**系统反馈**
- 以新账号重新请求所有模块数据
- 各模块重新进入加载状态（独立加载）
- 数据更新后各模块依次刷新

**需要前置解释的信息**
- "全部账号"将汇总名下所有账号的持仓数据
- 切换账号后，之前的阅读位置和筛选条件将重置

**建议文案**
- 账号选择器标签：银行账号
- 选项默认为：全部账号 {总资产额}

**下一步**
客户浏览新账号的配置信息。

---

### 流程二：筛选持仓表现时间区间

**触发条件**
客户需要查看特定时间段内的持仓表现。

**用户动作**
点击持仓表现区域上方的区间筛选器 → 从预设选项中选择（近一月/近三月/近半年/近一年/自定义）→ 如选自定义，选择起止日期。

**系统反馈**
- 时间区间筛选器更新为所选区间
- 持仓表现模块（KPI + 图表 + 排行）全部刷新
- 其他模块不受影响

**需要前置解释的信息**
- 支持近两年的数据范围
- 自定义区间的最小粒度为天

**建议文案**
- 筛选器标签：时间区间
- 默认值：近一个月
- 自定义弹窗标题：选择时间区间

**下一步**
客户查看更新后的持仓表现数据。

---

### 流程三：下载建议书

**触发条件**
客户需要保存或分享当前资产配置建议书。

**用户动作**
点击页面右下角的悬浮下载按钮。

**系统反馈**
- 弹出下载格式选择弹窗
- 格式选项：PDF 格式 / PNG 图片
- 客户选择格式 → 系统开始生成文件 → 文件生成后触发下载
- 文件命名：资产配置建议书{YYYYMMDDHHmmss}

**需要前置解释的信息**
- 下载文件将包含所有内容（分页和 Tab 全部平铺展示）
- 下载时间取决于数据量和网络状态

**建议文案**
- 格式选择弹窗标题：选择下载格式
- PDF 选项描述：适合打印和分享
- PNG 选项描述：适合快速截图查看
- 生成中提示：正在生成文件，请稍候...

**下一步**
客户在本地查看已下载的文件。

---

### 流程四：无持仓数据

**触发条件**
客户名下账号无持仓记录。

**用户动作**
进入资产配置页面。

**系统反馈**
- 判断无持仓数据
- 展示空状态页面：图标 + "暂无持仓数据" + "购买理财产品，开启投资之旅" + 【去购买】按钮

**下一步**
点击"去购买"跳转产品列表页。

## §5 异常与阻断流程

### 异常一：企业财富+接口超时

**发生时机**
任一模块发起数据请求时。

**触发条件**
接口响应时间超过 5 秒。

**判断依据**
前端超时设置（5秒）。

**反馈形式**
模块级降级——该模块保留骨架占位，不阻断其他模块。

**系统反馈**
- 自动重试 3 次，间隔 1 秒
- 3 次均失败后，该模块展示空状态卡片 + "数据加载中，请稍后重试"

**用户下一步**
客户无需操作，继续浏览其他已加载的模块。稍后可手动刷新页面重试。

**恢复路径**
接口恢复后，客户可通过下拉刷新或重新进入页面触发重新请求。此前已填写的筛选条件（时间区间、账号选择）保留。

---

### 异常二：企业财富+服务无响应

**发生时机**
核心数据接口（时点资产 + 持仓表现）同时不可用。

**触发条件**
多个关键接口连续超时或返回错误，且降级重试全部失败。

**判断依据**
前端综合判断——超过半数核心接口同时失败。

**反馈形式**
页面级阻断——不展示空数据拼凑页面，直接展示"系统繁忙"阻断页。

**系统反馈**
- 展示全屏阻断页：图标 + "系统繁忙，请稍后再试"
- 不展示各模块的碎片化空状态
- 记录异常日志并触发告警通知

**用户下一步**
等待 1-2 分钟后重新进入页面。如持续不可用，联系客服。

**恢复路径**
原路返回无信息丢失。重新进入时恢复为全新加载流程。

---

### 异常三：部分模块数据缺失

**发生时机**
个别模块接口返回异常，其他模块正常。

**触发条件**
某个模块（如投资分布）接口报错或返回空数据，但其他接口正常。

**判断依据**
按模块独立判断。

**反馈形式**
模块级展示——失败模块展示空状态卡片，其他模块正常展示。

**系统反馈**
- 失败模块展示：图标 + "暂无{模块名}数据"
- 正常模块正常展示数据
- 不展示 toast 或全屏提示

**用户下一步**
客户可使用其他正常模块。缺失模块的数据将由系统后台异步补全，下次进入时更新。

**恢复路径**
系统后台异步重试补全数据，客户下次进入页面时自动获取更新。客户也可通过切换账号再切回的方式手动触发刷新。

---

### 异常四：文件生成失败

**发生时机**
客户点击下载后，文件生成过程中。

**触发条件**
企业财富+文件生成接口异常。

**反馈形式**
弹窗提示——文件生成弹窗内显示错误信息。

**系统反馈**
- 弹窗提示："文件生成失败，请稍后重试"
- toast 不关闭弹窗，客户可再次尝试

**用户下一步**
点击弹窗中的"重试"按钮重新生成。如持续失败，稍后重试。

**恢复路径**
原路恢复，无信息丢失。重试时重新发起文件生成请求。

---

### 异常五：网络中断（下载过程中）

**发生时机**
文件已经开始下载，下载中途中断。

**触发条件**
下载过程中网络断开。

**反馈形式**
系统通知或页面 toast。

**系统反馈**
- 浏览器下载管理中显示"下载失败"
- 页面 toast："网络异常，下载已中断"

**用户下一步**
网络恢复后重新点击下载按钮。如需断点续传需浏览器支持。

**恢复路径**
原路恢复，无信息丢失。客户回到页面重新发起下载。

---

### 异常六：批量购买部分失败

**发生时机**
客户在购物车中对批量选择的产品执行购买，部分产品因额度不足或已售罄未能成功购买。

**触发条件**
批量购买结算时，部分产品购买成功、部分失败。

**判断依据**
后端逐笔返回购买结果。

**反馈形式**
购物车结算结果页——混合展示成功/失败条目。

**系统反馈**
- 显示购买结果汇总：成功 N 笔、失败 M 笔
- 成功产品展示"购买成功"状态
- 失败产品展示失败原因（额度不足/已售罄/已下架）+ 移除按钮
- 整体提示："部分产品未成功购买，请查看明细"

**用户下一步**
客户可将失败产品移除后重新选择替代产品，或仅保留成功购买的产品。

**恢复路径**
客户在结果页操作后返回购物车或产品推荐区重新选择，已成功购买的产品不受影响。

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
