## §0 本次关键设计判断

### 判断一：Skill 广场按"内容分发市场"而非"管理后台列表"定位

- **判断**：Skill 广场面向两类角色——客户经理（发现可用 Skill）和产品经理（管理自己发布的 Skill）——"共享广场"Tab 按内容分发市场设计，"我发布的"Tab 按管理后台列表设计，两类有明显差异。
- **主要影响**：影响 Skill 广场的页面结构、卡片信息密度、筛选排序策略。
- **建议方案**："共享广场"Tab 强化发现效率：卡片增加场景标签行、热门标记、简短效果指标；排序支持订阅量、最近更新和新上架。"我发布的"Tab 强化管理效率：列表视图（非卡片），增加共享状态、订阅数、编辑/删除操作列。
- **不建议方案**：两 Tab 共用同一套卡片布局和操作入口，导致消费者看到管理按钮、管理者看不到数据。
- **关键待确认**：共享广场是否需要额外的业务场景分类维度。

### 判断二：分行级订阅用"分行级订阅 + 二次确认 + 分行内通知"兜住操作风险

- **判断**：取消订阅影响全分行，不能做成单次点击即时生效的开关切换。
- **主要影响**：影响订阅开关交互、取消确认弹窗内容和通知策略。
- **建议方案**：点击"已订阅"开关 → 弹出确认弹窗，说明"取消后全分行 {N} 人都无法使用此 Skill" → 确认后 Toast 提示已取消 → 分行内其他用户下次进入广场时以轻量 Banner 提示"本分行已取消订阅 {Skill名称}"。
- **不建议方案**：开关点击即时取消，无二次确认；或不做分行内其他人感知。
- **关键待确认**：分行级取消是否还需要分行管理员审批确认（UXB §9 层级一）。

### 判断三：审核流程采用"进度条前置 + 不通过精确定位"解决黑盒问题

- **判断**：审核等待期是生产者旅程的信心最低点，关键在于让提交者知道"审到哪了"和"不通过时具体哪里有问题"。
- **主要影响**：影响 Skill 详情页的状态展示区域、审核不通过后的交互流程。
- **建议方案**：在"我发布的 Skill"列表和详情页顶部展示审核状态进度（待检测 → 检测中 → 已完成）；审核不通过时在详情页提示区高亮具体问题内容，右侧给出修改指引。
- **不建议方案**：只给 Toast "审核不通过"或"内容不合规"；或审核成功后才通知。
- **关键待确认**：审核预期时长（UXB §9 层级二）。

### 判断四：消费者"发现"通过分行通知 + 场景分类 + 联想排序优化三层递进解决

- **判断**：客户经理不知道自己分行订阅了哪些 Skill，这是消费端核心断点，不能只靠"他自己去广场逛"解决。
- **主要影响**：影响分行订阅成功后的通知机制、Skill 广场的分类维度和智能联想的排序策略。
- **建议方案**：分行新订阅 Skill → 以企业内部消息/公告通知全员（含 Skill 名称、一句话功能描述和入口链接）；广场引入"业务场景"分类标签（如客户营销、风险提示、产品查询等），卡片突出显示场景标签；智能联想排序优先个人近期使用过的 Skill，再按订阅量排序。
- **不建议方案**：不做任何通知，完全依赖客户经理主动浏览广场；或不处理联想排序，随 Skill 增长后匹配质量持续下降。
- **关键待确认**：业务场景分类的维度由谁定义（总行统一 vs 分行自定义）。

## §1 旅程消费摘要

### 信心最低点 → 驱动异常流程设计优先级

| 角色 | 阶段 | 信心 | 异常设计优先级 | 本蓝图落点 |
|------|------|------|--------------|-----------|
| 分行产品经理 | 提交与等待审核 | 中 | 高 — 审核流程不透明是核心断点 | §5 审核不通过、§6 Skill 详情页审核状态区 |
| 客户经理 | 发现可用 Skill | 中 | 高 — 不知道分行订了什么，发现成本高 | §5 智能联想无匹配、§4 分行通知机制 |
| 分行产品经理 | 运营与查看效果 | 中 | 中 — 数据不足不影响主流程但影响长期留存 | §5 同步失败、§6 数据区 |
| 分行产品经理 | 迭代优化 | 中 | 中 — 优化后重新审核再次进入等待期 | §5 优化后重新审核 |

### 关键转折 → 驱动交互流程的前置说明

| 角色 | 转折点 | 触发条件 | 需要说明的信息 | 本蓝图落点 |
|------|--------|----------|---------------|-----------|
| 分行产品经理 | 从提交阶段进入运营阶段 | 审核通过 | Skill 已正式上架，但沙盒同步有短暂延迟（秒级），稍后即可在财富小助中使用 | §3 创建提交流程 |
| 客户经理 | 从发现阶段进入选择阶段 | 知道有 Skill 可用 | 分行订阅的 Skill 是什么、适合什么场景 | §4 分行通知机制 |
| 客户经理 | 从选择阶段进入结果阶段 | 找到目标 Skill 并执行 | 当前 Skill 的功能说明和预期输出 | §3 智能联想调用流程 |

### 流失风险 → 驱动页面引导策略

| 角色 | 高风险阶段 | 流失情形 | 页面引导策略 | 本蓝图落点 |
|------|-----------|---------|-------------|-----------|
| 分行产品经理 | 创建与编写 | 不熟悉提示词模板 | 首次使用提供模板折叠和示例预览 | §6 Skill 编辑页面 |
| 分行产品经理 | 提交与等待审核 | 反复不通过 | 不通过时精确标注问题区域 | §5 审核不通过、§6 详情页 |
| 客户经理 | 发现可用 Skill | 找不到合适 Skill | 分行订阅通知 + 场景分类 + 热门推荐 | §4 分行通知、§6 Skill 广场 |
| 客户经理 | 选择与调用 | 列表太长找不到 | 个性化排序 + 最近使用分组 | §3 智能联想 |

## §2 交互流程总览

### 主路径 1：分行产品经理创建并发布 Skill

Skill 广场（共享广场 Tab）→ 点击「发布技能」→ 选择创建方式弹窗 → 选择「手动创建」或「上传文件」→ 进入 Skill 编辑页面 → 填写/修改内容 → 点击「保存」→ 前端校验 → 提交成功 → Toast "创建成功，等待审核" → 跳转至 Skill 详情页 → 展示审核进度 → 审核通过 → 状态更新为"已发布"

分支：
- 上传文件格式错误 → 弹窗提示，不进入编辑页
- 必填字段未填 → [保存] 置灰，字段下方 Inline 提示
- 审核不通过 → 详情页顶部展示不通过原因，可编辑后重新提交

### 主路径 2：客户经理通过智能联想调用 Skill

财富小助输入框 → 输入「/」→ 触发联想下拉列表 → 继续输入关键字缩小范围 → 浏览列表 → 键盘选择或点击 → 回车确认 → 输入框填充「/Skill名称」→ 发送消息 → 跳过意图识别 → 加载提示词 → 执行 AI 交互 → 展示结果

分支：
- 输入「/」后无可用 Skill → 联想列表为空，下方展示"暂无可用 Skill"说明
- 执行超时 → 输入框上方提示"AI 处理超时，请稍后重试"

### 主路径 3：分行级订阅/取消订阅

Skill 广场 → 点击 Skill 卡片的订阅开关（未订阅状态时点「订阅」）→ Toast "订阅成功，本分行所有用户均可使用" → 开关变为「已订阅」

Skill 广场 → 点击 Skill 卡片的订阅开关（已订阅状态时点「已订阅」）→ 弹出确认弹窗，说明影响范围 → 点击「确认取消」→ Toast "已取消订阅，本分行所有用户将无法使用" → 开关变为「订阅」

分支：
- 分行已订阅时再次点击「订阅」→ 提示"该 Skill 已在本分行订阅"
- 取消确认弹窗中选择「再想想」→ 弹窗关闭，开关保持「已订阅」

### 次路径 1：编辑 Skill

「我发布的 Skill」Tab → 点击 Skill 卡片/行 → 进入详情页 → 点击「编辑」→ 进入 Skill 编辑页面 → 修改内容 → 点击「保存」→ 提交审核 → 进入审核流程

### 次路径 2：删除 Skill

Skill 详情页 → 点击「删除」→ 弹出二次确认弹窗（如有订阅，提示被多少分行订阅）→ 确认删除 → 从广场移除，解除所有订阅关系

### 次路径 3：查看版本记录与恢复

Skill 详情页 → 切换至「版本记录」Tab → 浏览版本列表 → 点击「查看详情」→ 查看历史版本内容 → 点击「恢复此版本」→ 弹出二次确认弹框 → 确认后进入编辑页并载入历史版本内容

## §3 主交互流程

### 3.1 创建 Skill（分行产品经理 / 总行产品经理）

**前置说明：**
- 仅产品经理和开发人员角色可见「发布技能」按钮
- 总行用户默认开启共享，分行用户默认关闭共享（UXB §5 确定规则）

**节点一：发起创建**

| 要素 | 内容 |
|------|------|
| 用户动作 | 在 Skill 广场右上角点击「发布技能」按钮 |
| 系统反馈 | 弹出创建方式选择弹窗，两个选项：「手动创建」「上传文件」 |
| 建议文案 | 弹窗标题：「创建 Skill」；选项下方分别说明「按模板填写提示词内容」和「上传 .md 格式文件自动解析」 |
| 下一步 | 选择创建方式后进入编辑页或文件上传 |

**节点二：填写 Skill 内容**

| 要素 | 内容 |
|------|------|
| 用户动作 | 手动模式下填写 名称（必填，50字内）、描述（必填，200字内）、提示词内容（必填，文本域）；上传模式下选择 .md 文件后系统自动解析填充 |
| 系统反馈 | 名称/描述/提示词内容均有字数实时计数器；提示词内容文本域支持 Markdown 语法；共享开关默认按用户角色设置默认值 |
| 建议文案 | 名称上方：「为 Skill 起一个简洁的名称，用户将在联想列表中看到」；描述上方：「一句话描述这个 Skill 的功能」；共享开关旁：「开启后全行用户可见」 |
| 下一步 | 填写完成后点击「保存」 |

**节点三：提交审核**

| 要素 | 内容 |
|------|------|
| 用户动作 | 点击「保存」按钮 |
| 系统反馈 | 前端校验必填字段和字数限制 → 校验通过 → 保存成功 → Toast "创建成功，等待审核" → 页面跳转至 Skill 详情页 → 详情页顶部展示审核进度（待检测 → 检测中 → 已完成） |
| 建议文案 | Toast：「创建成功，正在提交审核」；审核进度区标题：「审核进度」（审核通过后变为「审核已通过」） |
| 需要前置解释的信息 | 审核通过后有秒级同步延迟，需在文案中说明"审核通过后稍等片刻即可在财富小助中使用" |
| 下一步 | 等待审核结果 |

### 3.2 智能联想调用 Skill（客户经理）

**前置说明：**
- 联想列表仅展示当前用户所在分行可用的 Skill（本分行创建 + 本分行订阅的）
- 联想触发条件：输入框中输入「/」且光标在开头或紧接在空格后

**节点一：触发联想**

| 要素 | 内容 |
|------|------|
| 用户动作 | 在财富小助输入框输入「/」 |
| 系统反馈 | 弹出下拉联想列表，按以下优先级排序：个人常用 Skill → 本分行热门 Skill（按订阅量降序）→ 其余可用 Skill；最多 10 条 |
| 建议文案 | 列表为空时显示：「暂无可用 Skill，请联系分行产品经理订阅」 |
| 下一步 | 继续输入关键字或直接选择 |

**节点二：选择并执行**

| 要素 | 内容 |
|------|------|
| 用户动作 | 键盘上下键移动选择，或鼠标点击；回车确认 |
| 系统反馈 | 输入框自动填充「/Skill名称」；用户可继续编辑问题后发送；系统识别 Skill 调用意图后跳过意图识别，直接加载提示词并执行 AI 交互 |
| 建议文案 | 列表项展示格式：「Skill名称」+ 一行简短描述；匹配关键字高亮 |
| 下一步 | 展示 AI 返回结果 |

### 3.3 分行级订阅（客户经理 / 所有用户）

**前置说明：**
- 所有企业财富+用户均可订阅（UXB §5 确定规则）
- 订阅主体为分行级，不是个人级

**节点一：发起订阅**

| 要素 | 内容 |
|------|------|
| 用户动作 | 在 Skill 广场点击卡片上的「订阅」开关（灰色状态） |
| 系统反馈 | Toast "订阅成功" → 开关切换为红色「已订阅」→ 订阅分行数 +1 |
| 建议文案 | Toast：「已订阅，本分行所有用户均可用」 |
| 下一步 | 分行内其他用户进入广场时将看到「已订阅」状态 |

**节点二：取消订阅（高风险动作）**

| 要素 | 内容 |
|------|------|
| 用户动作 | 点击卡片上的「已订阅」开关（红色状态） |
| 系统反馈 | 弹出确认弹窗 → 用户确认后 → Toast "已取消" → 开关切换为灰色「订阅」→ 订阅分行数 -1 → 本分行所有用户将不可用 |
| 建议文案 | 弹窗标题：「取消订阅」；弹窗正文：「本分行共 {N} 人，取消后所有人均无法使用此 Skill。确定取消吗？」；按钮：「确认取消」（次按钮）、「再想想」（主按钮） |
| 需要前置解释的信息 | 取消订阅影响全分行，建议在弹窗中强调影响范围 |
| 下一步 | 取消后可在任何时间重新订阅 |

## §4 次交互流程

### 4.1 分行订阅新 Skill 通知

**触发条件**：分行任一用户成功订阅 Skill

**系统反馈**：以企业内部消息/公告形式通知全分行用户

**建议文案**：
消息标题：「新 Skill 上架：{Skill名称}」
消息正文：「{发布者} 已为分行订阅了 {Skill名称}，可快速 {一句话功能描述}。打开财富小助输入「/」即可使用。」
消息底部：「去看看」链接 → 跳转至 Skill 详情页

**下一步**：客户经理可立即在财富小助中使用该 Skill

### 4.2 编辑 Skill

**触发条件**：Skill 所属分行用户在详情页点击「编辑」

**用户动作**：
- 进入 Skill 编辑页面（与创建共用同一页面结构和表单）
- 修改 Skill 名称、描述或提示词内容
- 点击「保存」提交修改

**系统反馈**：
- 保存成功 → Toast "更新成功，正在提交审核" → Skill 进入待审核状态
- 审核通过 → 新版本生效 → 已订阅用户自动使用最新版本
- 生成新的版本号（v1.0 → v1.1 → v1.2...）

**需要前置解释的信息**：
- 编辑后需重新审核，审核期间旧版本继续可用，不影响已订阅用户

**下一步**：等待审核

### 4.3 删除 Skill

**触发条件**：创建者或管理员在详情页点击「删除」

**系统反馈**：
- 弹出二次确认弹窗
- 如 Skill 已被其他分行订阅，弹窗中提示：「该 Skill 已被 {N} 家分行订阅，删除后将解除所有订阅关系」
- 确认删除 → Toast "删除成功" → 从广场移除 → 所有订阅关系解除 → 沙盒缓存删除
- 取消删除 → 弹窗关闭

**建议文案**：
弹窗标题：「删除 Skill」
弹窗正文：「删除后不可恢复。{如有订阅，追加说明影响范围}」
按钮：「确认删除」（红色次按钮）、「取消」（主按钮）

**下一步**：删除操作不可逆，无返回路径。

### 4.4 恢复历史版本

**触发条件**：用户在版本记录 Tab 中点击「恢复此版本」

**系统反馈**：
- 弹出二次确认弹框：「确认恢复至 {版本号} 版本？当前内容将被覆盖。」
- 确认 → 进入编辑页，载入历史版本内容覆盖当前编辑区域
- 用户可继续修改后重新保存提交

**下一步**：进入编辑流程（§3.1 节点二）

## §5 异常与阻断流程

### 5.1 审核不通过

| 要素 | 内容 |
|------|------|
| 发生时机 | Skill 提交审核后 |
| 触发条件 | 内容含敏感词 / 注入攻击 / 格式不符 / 超长 |
| 判断依据 | 系统自动检测 + 人工兜底 |
| 反馈形式 | Skill 详情页顶部出现不通过提示区；消息通知发送给创建者 |
| 系统反馈 | 详情页顶部 Banner 展示：「审核不通过」，下方列出具体原因（如"第 3 段包含敏感词「XXX」"） |
| 用户下一步 | 点击「去修改」→ 进入编辑页，问题区域自动滚动定位并高亮 → 修改后重新提交（重新进入审核流程） |
| 恢复路径 | 编辑页已填内容保留，只调整问题区域→保存后重新进入等待队列。中途离开不丢失已修改内容。 |

### 5.2 取消订阅影响全分行

| 要素 | 内容 |
|------|------|
| 发生时机 | 用户点击「已订阅」开关 |
| 触发条件 | 用户确认取消订阅 |
| 判断依据 | 当前分行是否已订阅此 Skill |
| 反馈形式 | 二次确认弹窗 |
| 系统反馈 | 弹窗提示影响范围（分行总人数），只有用户确认后才执行取消 |
| 用户下一步 | 确认取消 → 立即生效，全分行不可用；选择「再想想」→ 回到原状态 |
| 恢复路径 | 原路返回，无信息丢失。用户可随时重新订阅此 Skill。 |

### 5.3 沙盒增量同步失败

| 要素 | 内容 |
|------|------|
| 发生时机 | Skill 创建/编辑/删除/订阅后 |
| 触发条件 | MQ 消费失败或沙盒异常 |
| 判断依据 | 后端检测同步状态 |
| 反馈形式 | 仅后台告警，不向用户展示同步状态（需求文档已明确"同步状态不对外展示"） |
| 系统反馈 | 系统自动重试 3 次（间隔 1min/5min/30min），仍失败则告警运维 |
| 用户下一步 | 用户操作已成功（Skill 数据已保存），无需处理。如沙盒中暂时不可用，用户可稍后重试。 |
| 恢复路径 | 运维介入恢复，或等待每周全量同步自动修复。用户操作不受影响。 |

### 5.4 上传文件异常

| 要素 | 内容 |
|------|------|
| 发生时机 | 选择文件后、解析前 |
| 触发条件 | 格式非 .md / 文件超过 1MB / 编码非 UTF-8 |
| 判断依据 | 前端上传前校验 |
| 反馈形式 | 弹窗或文件上传区 Inline 提示 |
| 系统反馈 | 格式错误：「仅支持 .md 格式的 Markdown 文件」；超限：「文件大小不能超过 1MB」；编码错误：「文件编码需为 UTF-8」 |
| 用户下一步 | 更换文件后重新上传 |
| 恢复路径 | 上传区重置，无信息丢失 |

### 5.5 智能联想无匹配

| 要素 | 内容 |
|------|------|
| 发生时机 | 用户在财富小助输入「/」或「/关键字」后 |
| 触发条件 | 当前用户所在分行没有可用的匹配 Skill |
| 判断依据 | 后端查询可用 Skill 列表为空 |
| 反馈形式 | 联想下拉列表展示空状态提示 |
| 系统反馈 | 列表下方显示：「暂无可用 Skill，请联系分行产品经理订阅」 |
| 用户下一步 | 可联系分行产品经理建议创建或订阅相关 Skill |
| 恢复路径 | 原路退出（点击输入框外部或按 Esc），继续使用财富小助普通会话 |

### 5.6 Skill 执行异常

| 要素 | 内容 |
|------|------|
| 发生时机 | 用户在财富小助中选择 Skill 后 |
| 触发条件 | Skill 加载超时 / AI 处理超时 / Skill 内容异常 |
| 判断依据 | 系统检测执行状态 |
| 反馈形式 | 输入框上方提示区 |
| 系统反馈 | 加载超时：「Skill 加载超时，请稍后重试」；处理超时：「AI 处理超时，请稍后重试」；内容异常：「当前 Skill 内容异常，请联系发布者」 |
| 用户下一步 | 根据提示选择重试或切换其他 Skill |
| 恢复路径 | 当前输入保留在输入框中，用户可删除 Skill 调用后继续普通会话。 |

### 5.7 删除已订阅的 Skill

| 要素 | 内容 |
|------|------|
| 发生时机 | 创建者或管理员在详情页点击「删除」 |
| 触发条件 | 该 Skill 已被其他分行订阅 |
| 判断依据 | 后端查询订阅分行数 > 0 |
| 反馈形式 | 二次确认弹窗，追加影响说明 |
| 系统反馈 | 弹窗在原有确认内容基础上追加：「该 Skill 已被 {N} 家分行订阅，删除后将解除所有订阅关系」 |
| 用户下一步 | 确认删除 → 立即移除，不可恢复；取消 → 回到原页 |
| 恢复路径 | 删除不可逆。如需重新上架，必须重新创建并提交审核。 |

## §8 待确认问题

### 层级一：影响主方案是否成立的问题

1. **分行级取消订阅是否需要审批保护**
   - 问题：当前方案为二次确认弹窗。如果业务方认为取消订阅影响过大（全分行不可用），是否需要升级为"需分行管理员审批"才能取消？
   - 影响：影响 §3.3 取消订阅流程和 §6 订阅交互设计
   - 建议确认方：业务方
   - 当前状态：基于推荐方案推进（二次确认弹窗）

### 层级二：影响局部体验设计的问题

1. **Skill 业务场景分类维度**
   - 问题：谁定义分类维度（总行统一还是分行自定义）？MVP 阶段是否需要引入？
   - 影响：影响 §6 Skill 广场的筛选区设计
   - 建议确认方：业务方 + 交互设计

2. **审核时效预期**
   - 问题：自动审核的目标完成时间是多少？超过多久需通知创建者？
   - 影响：影响 §3 审核进度展示策略和 §5 审核异常处理
   - 建议确认方：运营

3. **同步延迟的文案表达**
   - 问题：沙盒同步有秒级延迟，文案如何表达才能既准确又不让用户困惑？
   - 影响：影响 §3 创建成功后的提示文案
   - 建议确认方：交互设计

4. **「我发布的」Tab 名称**
   - 问题：该 Tab 展示所属分行所有 Skill 非个人创建，Tab 名称是否需要调整？
   - 影响：影响 §6 Skill 广场的 Tab 命名
   - 建议确认方：交互设计

5. **优化报告中的「一键替换」**
   - 问题：替换后是否重新触发审核？是否需要告知用户「替换后需重新审核」？
   - 影响：影响 §4 编辑流程和 §6 优化报告弹窗
   - 建议确认方：交互设计

### 交互模式消费

| 模式 | 选择原因 | 排除模式 | 体验落点 |
|------|---------|---------|---------|
| 独立页面（Skill 广场） | 需要完整页面空间展示卡片列表、搜索筛选和 Tab 切换；操作后不需要回到原页面 | 抽屉（范围不够） | §6.1 |
| 弹窗（创建方式选择） | 表单较轻，仅需两个选项供用户选择 | 独立页面（太重） | §6.2 |
| 独立页面（编辑页） | 表单字段较多（含长文本编辑和模板），需完整页面空间 | 抽屉、弹窗（信息密度太高） | §6.3 |
| Tab 页签（详情页） | 三个子视图（评分/详情/版本）内容性质相近，用户需要频繁切换 | 独立分页（切换成本高） | §6.4 |
| 弹窗（二次确认） | 高风险确认型操作，需要强制用户响应 | 抽屉、Toast（强度不够） | §3.3 取消确认、§4.3 删除确认 |

- 上述缺口不影响当前设计；交互决策基于设计准则和上游 UXB 结论
