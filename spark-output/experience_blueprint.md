# 财富小助 Skill 广场｜体验蓝图

## §0 本次关键设计判断

### 判断

用“归属、共享、分行开通、个人使用、运行版本”五个独立状态解释 Skill，列表和详情都展示当前用户真正需要判断的状态，不再用一个“订阅/已订阅”开关包办全部含义。

### 主要影响

这一决策会贯穿 Skill 广场、我的 Skill、Skill 详情、版本记录和财富小助联想。创建者看到管理状态，普通用户看到本分行是否开通及本人是否使用，总行管理者额外看到管理身份。

### 建议方案

- 分行首次订阅使用明确的组织级确认，确认前写清“将为本分行所有用户开通”。
- 个人取消改称“停用我的使用”，结果只影响本人；恢复入口使用“恢复使用”。
- 创建、编辑和还原成功后先反馈“已保存，正在准备使用”，运行就绪后再显示“可在财富小助使用”。
- 版本页把内容、评分和生效状态绑定到同一版本；还原生成新版本，不覆盖历史。
- 复制前说明副本归属与不继承范围，复制后直接进入新副本编辑页。

### 不建议方案

- 不使用二态订阅开关，因为无法表达“本分行已开通，但我个人已停用”。
- 不在字段错误、轻量保存结果上使用阻断弹窗；仅分行订阅、取消共享、还原和删除等高影响动作需要确认。
- 不把“保存成功”直接写成“已生效”，避免管理端与财富小助版本不一致。
- 不向普通用户展示消息队列、缓存、同步任务等技术状态。

### 关键待确认

取消共享对既有外部分行订阅的影响尚未定。本蓝图按推荐方案推进：取消共享后从广场下架并停止新增订阅，既有订阅分行继续可用；删除才终止全部使用关系。

## §1 旅程消费摘要

当前没有与“财富小助Skill广场”同项目的用户故事或旅程分析产物。本节基于 UXB 正式结论推导，未经深度旅程分析。

### 信心最低点

#### 创建者：发布后的“是否真的可用”

创建者完成保存或还原后，管理端已经成功，但财富小助可能仍使用上一版本。最低信心点发生在“保存成功—运行就绪”之间。

- 蓝图落点：§3 创建与共享流程、§5 新版本未就绪、§6 Skill 详情页、§7 运行状态文案。

#### 分行用户：点击订阅前的影响判断

一次个人点击会为整个分行开通，用户如果只看到“订阅”二字，会误以为这是个人收藏。

- 蓝图落点：§3 分行订阅流程、§6 分行订阅确认弹窗、§7 分行开通状态。

#### 客户经理：联想列表为空

用户可能因为分行未开通、本人已停用、Skill 未准备完成或搜索词不匹配而看不到目标 Skill。只显示“无结果”无法帮助恢复。

- 蓝图落点：§3 智能联想流程、§5 联想无结果、§6 财富小助联想面板、§7 空状态文案。

### 关键转折

#### 从个人资产转为全行可见

创建者开启共享后，Skill 从个人范围进入广场，并自动对所属分行可用。共享前需要明确影响范围和发布者责任。

- 蓝图落点：§4 共享与取消共享、§6 我的 Skill、§6 共享确认区。

#### 从可见转为分行可用

外部分行用户在广场能看到 Skill，但只有建立分行订阅后才可调用。订阅确认必须说明组织级影响，成功后给出“去财富小助使用”的下一步。

- 蓝图落点：§3 分行订阅、§6 Skill 详情和订阅确认弹窗。

#### 从历史版本转为新当前版本

还原历史内容不是回退指针，而是生成新的当前版本。用户需要在确认前看到目标版本、影响和评分重算说明。

- 蓝图落点：§4 历史版本还原、§6 版本详情区和还原确认弹窗。

### 流失风险

- 用户把“本分行已开通”误解为自己不可退出，放弃管理个人联想结果。
- 创建者担心共享后失去控制权，不愿把优秀 Skill 放入广场。
- 复制者以为会继承原评分或订阅，发现副本为空后放弃编辑。
- 新版本评分未生成或运行未就绪时缺少解释，用户反复保存或重复还原。
- 页面只给技术错误或无结果，用户无法判断应重试、等待、恢复使用还是联系管理者。

## §2 交互流程总览

本次包含 3 条主路径和 7 条次路径。

### 主路径 A：创建并共享 Skill

我的 Skill Page
→ 点击 [发布 Skill]
→ 打开 创建方式 Dialog
→ 选择 [手动创建] 或 [上传 Markdown]
→ 进入 Skill 编辑 Page
→ 输入或校正名称、描述、提示词
→ 点击 [保存并发布]
→ 字段校验通过
→ 保存首个版本
→ Toast：Skill 已创建
→ 详情 Page 显示“正在准备使用”
→ 创建者点击 [共享到广场]
→ 确认共享范围
→ 状态变为“已共享”
→ 所属分行自动可用

分支：

- 文件格式、大小或编码不符合要求 → 上传区显示 InlineError，保留创建任务。
- 必填项为空或超长 → 对应字段就地报错，不离开编辑页。
- 运行版本尚未准备完成 → 详情页保持状态提示，不阻断继续编辑或查看历史。

### 主路径 B：浏览并为分行订阅

Skill 广场 Page
→ 搜索或筛选 Skill
→ 点击 Skill 卡片
→ 进入 Skill 详情 Page
→ 查看来源、描述、分行开通状态
→ 点击 [为本分行开通]
→ 打开 分行订阅确认 Dialog
→ 确认影响范围
→ 点击 [确认开通]
→ 建立分行订阅关系
→ Dialog 关闭
→ Toast：已为本分行开通
→ 页面状态变为“本分行已开通 · 我正在使用”

分支：

- 本分行已订阅 → 不重复提交，页面直接显示当前分行和个人状态。
- 当前用户曾个人停用 → 显示 [恢复使用]，不再显示“为本分行开通”。
- Skill 已取消共享或删除 → 阻止提交并刷新详情状态。

### 主路径 C：财富小助联想并调用

财富小助对话 Page
→ 用户在输入框开头或空格后输入 [/]
→ 显示 Skill 联想面板 LoadingState
→ 返回当前用户可用 Skill
→ 用户继续输入关键词
→ 实时筛选并高亮名称
→ 键盘上下键或点击选中 Skill
→ 输入框填入 [/{Skill名称}]
→ 用户发送
→ 跳过普通意图识别并执行 Skill
→ 返回 AI 结果

分支：

- 没有可用 Skill → EmptyState 提供 [去 Skill 广场]。
- 个人已停用的 Skill → 不进入联想结果。
- 加载或执行超时 → 保留用户输入，提供 [重试]。

### 次路径

- 编辑 Skill并生成新版本。
- 复制可见 Skill。
- 查看历史版本及评分。
- 还原历史版本。
- 个人停用与恢复使用。
- 取消共享与删除。
- 总行管理者管理任意 Skill。

## §3 主交互流程

### 3.1 创建与发布

#### 节点 1：选择创建方式

- **用户动作：**在“我的 Skill”点击“发布 Skill”，选择手动创建或上传 Markdown。
- **系统反馈：**选择手动创建后进入带模板的编辑页；选择上传后先校验文件，再把解析结果带入编辑页。
- **前置解释：**上传只负责填充内容，用户仍需在编辑页核对并保存；创建后默认不共享。
- **建议文案：**“新 Skill 默认仅你可见，保存后可再共享到广场。”
- **下一步：**进入编辑页完成内容。

#### 节点 2：填写与校验

- **用户动作：**填写名称、描述、提示词内容，或调整上传解析结果。
- **系统反馈：**实时显示字符数；必填、长度和上传问题在原字段附近解释；存在未保存修改时离开页面触发离开确认。
- **前置解释：**保存会直接形成正式版本，无审核步骤；共享是后续独立动作。
- **建议文案：**“保存后生成 v{版本号}，不会自动共享。”
- **下一步：**点击“保存并发布”。

#### 节点 3：保存结果

- **用户动作：**点击“保存并发布”。
- **系统反馈：**保存成功后进入详情页，显示“已创建，正在准备使用”；评分区域显示“评分生成中”。
- **前置解释：**管理端保存成功不代表财富小助已经完成更新。
- **建议文案：**“Skill 已创建。正在准备财富小助使用，完成后将显示‘可使用’。”
- **下一步：**继续编辑、查看详情，或发起共享。

### 3.2 共享到广场

#### 节点 1：发起共享

- **用户动作：**创建者或总行管理者在详情页点击“共享到广场”。
- **系统反馈：**展示共享影响说明，明确全行可见、所属分行自动可用，但其他分行仍需订阅。
- **前置解释：**共享不转移所有权；同分行其他用户不能编辑。
- **建议文案：**“共享后，全行用户可以查看和复制；你的所属分行将自动可用。只有你和总行管理者可以修改。”
- **下一步：**确认共享或取消。

#### 节点 2：共享成功

- **用户动作：**确认共享。
- **系统反馈：**状态变为“已共享”，Skill 进入广场；所属分行用户获得使用资格。
- **前置解释：**运行副本可能仍在准备，不将共享成功等同于立即可调用。
- **建议文案：**“已共享到广场。所属分行已自动开通。”
- **下一步：**查看广场展示、复制链接或返回我的 Skill。

### 3.3 分行订阅

#### 节点 1：判断当前关系

- **用户动作：**用户打开共享 Skill 详情。
- **系统反馈：**在主操作区优先展示三种结果之一：“本分行未开通”“本分行已开通 · 我正在使用”“本分行已开通 · 我已停用”。
- **前置解释：**所属分行自动可用，不计为用户主动订阅动作；其他分行需要首次开通。
- **建议文案：**“当前状态由分行开通与个人使用两部分组成。”
- **下一步：**为分行开通、个人停用/恢复，或直接去财富小助使用。

#### 节点 2：确认组织级影响

- **用户动作：**点击“为本分行开通”。
- **系统反馈：**打开确认弹窗，显示当前分行、影响对象、订阅分行数变化和可撤销边界。
- **前置解释：**任意用户都可发起开通；个人后续可以停用自己，但不能撤销分行整体开通。
- **建议文案：**“确认后，{所属分行}全体用户都可在财富小助使用此 Skill。”
- **下一步：**点击“确认开通”或返回。

#### 节点 3：开通成功

- **用户动作：**确认开通。
- **系统反馈：**弹窗关闭，状态更新，订阅分行数增加一次；提供“去财富小助使用”。
- **前置解释：**如果运行副本尚未准备完成，需要展示等待状态而非失败。
- **建议文案：**“已为{所属分行}开通。分行用户均可使用，个人可按需停用。”
- **下一步：**去财富小助、继续浏览或复制 Skill。

### 3.4 智能联想与调用

#### 节点 1：触发联想

- **用户动作：**在财富小助输入框开头或空格后输入“/”。
- **系统反馈：**500 毫秒目标内显示最多 10 条可用 Skill；加载期间显示轻量 LoadingState，不阻塞输入。
- **前置解释：**只展示个人私有、所属分行共享、分行订阅且本人未停用、并已可运行的 Skill。
- **建议文案：**空查询提示“输入关键词查找可用 Skill”。
- **下一步：**继续输入、上下键选择或点击选择。

#### 节点 2：选择 Skill

- **用户动作：**点击或回车选中 Skill。
- **系统反馈：**输入框填入“/{Skill名称}”，联想面板收起；保留继续输入补充内容的能力。
- **前置解释：**列表展示来源和简短描述，帮助用户在同名或相近结果间判断。
- **建议文案：**来源使用“我的”“本分行共享”“本分行已开通”三种统一标签。
- **下一步：**补充输入或发送。

#### 节点 3：执行与结果

- **用户动作：**发送 Skill 调用请求。
- **系统反馈：**进入执行中状态，成功后返回 AI 结果；失败时保留原输入和目标 Skill。
- **前置解释：**执行超时不等于 Skill 被删除或失效。
- **建议文案：**“本次处理超时，已保留你的输入，可直接重试。”
- **下一步：**继续对话、重试或选择其他 Skill。

## §4 次交互流程

### 4.1 编辑并生成新版本

- **触发条件：**创建者或总行管理者在详情页点击“编辑”。
- **用户动作：**修改名称、描述或提示词并保存。
- **系统反馈：**生成新版本；当前版本标记“正在准备使用”，上一可用版本继续服务，直到新版本准备完成。本处理为推荐方案。
- **前置解释：**已订阅分行会自动使用新版本，不需要重新订阅。
- **建议文案：**“v{新版本号} 已保存。准备完成前，财富小助继续使用 v{当前可用版本号}。”
- **下一步：**查看版本记录、等待新版本可用或继续编辑。

### 4.2 复制 Skill

- **触发条件：**用户对当前可见 Skill 点击“复制”。
- **用户动作：**在确认弹窗核对来源与继承规则，点击“创建副本”。
- **系统反馈：**创建名称为“{Skill名称}-副本”的私有 Skill；如个人范围内重名，自动追加序号。本命名范围为推荐方案。
- **前置解释：**副本归复制者，不共享，不继承订阅、调用、历史版本和评分。
- **建议文案：**“副本将成为你的独立 Skill，原 Skill 后续更新不会同步到副本。”
- **下一步：**进入副本编辑页完善并保存。

### 4.3 查看历史版本与评分

- **触发条件：**所属分行用户或总行管理者进入 Skill 详情的版本记录。
- **用户动作：**选择目标版本，查看内容和对应评分。
- **系统反馈：**展示版本号、更新时间、操作者、生效状态、评分时间、综合得分、评估结论和建议；未生成时显示独立状态。
- **前置解释：**评分只属于当前所选版本，不代表其他版本。
- **下一步：**切换版本、查看内容差异；创建者或总行管理者可发起还原。

### 4.4 还原历史版本

- **触发条件：**创建者或总行管理者在历史版本中点击“还原为新版本”。
- **用户动作：**在确认弹窗核对来源版本和影响，确认还原。
- **系统反馈：**以历史内容生成新的最新版本，触发新评分和运行准备；历史记录全部保留。
- **前置解释：**不是直接把历史版本重新设为当前，也不会沿用历史评分。
- **建议文案：**“将基于 v{历史版本号} 生成 v{新版本号}。新版本会重新评分并在准备完成后生效。”
- **下一步：**查看新版本详情或返回版本列表。

### 4.5 个人停用与恢复使用

- **触发条件：**本分行已订阅，当前用户处于使用中或已停用状态。
- **用户动作：**点击“停用我的使用”或“恢复使用”。
- **系统反馈：**停用后从本人财富小助联想中移除；恢复后重新进入本人可用集合，不改变分行订阅数。
- **前置解释：**这不是全分行取消订阅。
- **建议文案：**停用：“仅对你生效，不影响{所属分行}其他用户。”恢复：“已恢复，将重新出现在你的财富小助联想中。”
- **下一步：**继续浏览或去财富小助验证。

### 4.6 取消共享

- **触发条件：**创建者或总行管理者对已共享 Skill 点击“取消共享”。
- **用户动作：**查看影响说明并确认。
- **系统反馈：**按推荐方案，从广场下架、阻止新增分行订阅，所属分行仍可用，既有订阅分行暂时继续可用。
- **前置解释：**规则尚待业务确认，界面必须明确当前不会终止既有分行。
- **建议文案：**“取消共享后，新分行无法再订阅；已开通分行暂不受影响。”
- **下一步：**返回我的 Skill；如需终止全部使用，进入删除流程。

### 4.7 删除 Skill

- **触发条件：**创建者或总行管理者点击“删除”。
- **用户动作：**在高风险确认弹窗查看订阅分行数和影响，输入 Skill 名称完成确认。
- **系统反馈：**删除正式资产、解除使用关系并触发运行副本清理；操作不可恢复。
- **前置解释：**历史版本也不能通过普通用户界面恢复，所有使用方都会失去调用入口。
- **建议文案：**“删除后，{订阅分行数}个订阅分行及所属分行将无法继续使用，历史版本不可恢复。”
- **下一步：**删除成功后返回我的 Skill 或总行管理列表。

### 4.8 总行管理者操作

- **触发条件：**总行管理者查看任意 Skill。
- **用户动作：**执行编辑、共享、取消共享、删除、复制或还原。
- **系统反馈：**操作入口标注“总行管理”，操作结果记录操作者和影响范围。
- **前置解释：**最高权限操作不改变原创建者和所属分行，不把管理者变成所有者。
- **建议文案：**“你正在以总行管理者身份操作，此变更将记录在 Skill 历史中。”
- **下一步：**完成操作后返回详情并查看变更记录。

## §5 异常与阻断流程

### 5.1 上传文件不符合要求

- **发生时机：**选择 Markdown 文件后、进入编辑页前。
- **触发条件：**格式不是 `.md`、文件超过 1MB 或编码无法解析。
- **判断依据：**文件扩展名、大小和解析结果。
- **反馈形式：**上传区域 InlineError。
- **系统反馈：**不创建 Skill，不清空已选择的创建方式。
- **用户下一步：**查看具体限制并重新选择文件。
- **恢复路径：**原路恢复，无已填信息丢失。

### 5.2 编辑内容校验失败

- **发生时机：**输入过程中或点击保存时。
- **触发条件：**必填为空、名称超过 50 字符、描述超过 200 字符、提示词超过 10,000 字符。
- **判断依据：**字段规则。
- **反馈形式：**字段附近 InlineError，页面顶部仅在多字段同时失败时提供错误摘要。
- **系统反馈：**不提交，聚焦第一个错误字段并保留全部输入。
- **用户下一步：**就地修改后重新保存。
- **恢复路径：**在当前页修正一步即可，无信息丢失。

### 5.3 Skill 名称冲突

- **发生时机：**创建、复制或编辑保存时。
- **触发条件：**名称违反唯一性规则。
- **判断依据：**本蓝图暂按“同一创建者范围内唯一”推进。
- **反馈形式：**名称字段 InlineError。
- **系统反馈：**不保存当前名称，其他内容保留。
- **用户下一步：**采用建议名称或自行修改。
- **恢复路径：**修改名称后重新保存，不需重做其他字段。

### 5.4 无管理权限

- **发生时机：**用户进入已失去权限的编辑、共享、还原或删除入口。
- **触发条件：**不是创建者或总行管理者，或权限在页面打开后发生变化。
- **判断依据：**实时身份与资产所有权。
- **反馈形式：**入口预先隐藏或禁用；并发变化时使用状态阻断 Dialog。
- **系统反馈：**不修改数据，说明可联系的角色。
- **用户下一步：**返回只读详情或联系创建者/总行管理者。
- **恢复路径：**返回详情一步完成，无已保存数据变化；编辑草稿允许复制后保留为个人副本。

### 5.5 分行重复订阅

- **发生时机：**并发用户同时发起订阅。
- **触发条件：**提交时已存在分行订阅关系。
- **判断依据：**分行唯一订阅记录。
- **反馈形式：**轻量 Toast，并刷新详情状态。
- **系统反馈：**不重复计数；若当前用户个人已停用，展示“恢复使用”。
- **用户下一步：**直接去财富小助或恢复个人使用。
- **恢复路径：**原路恢复，无信息丢失。

### 5.6 Skill 在订阅或复制前失效

- **发生时机：**详情已打开后点击订阅或复制。
- **触发条件：**源 Skill 已删除、取消共享或当前用户失去可见性。
- **判断依据：**提交时的最新资产状态。
- **反馈形式：**页面级状态区；关闭操作弹窗。
- **系统反馈：**不建立订阅、不创建副本，刷新页面为“当前 Skill 已不可用”。
- **用户下一步：**返回广场选择其他 Skill。
- **恢复路径：**一步返回广场；筛选条件保留。

### 5.7 新版本尚未准备或准备失败

- **发生时机：**创建、编辑或还原后。
- **触发条件：**运行副本仍在准备或多次重试失败。
- **判断依据：**当前正式版本与当前可运行版本不一致。
- **反馈形式：**详情页持续状态 Banner，不使用一次性 Toast 代替。
- **系统反馈：**按推荐方案继续提供上一可用版本；没有上一版本时暂不进入联想列表。技术原因只对运维可见。
- **用户下一步：**继续使用上一版本、稍后刷新或联系运维支持。
- **恢复路径：**准备成功后状态自动更新，无需用户重复保存。

### 5.8 评分未生成或生成失败

- **发生时机：**查看新版本评分。
- **触发条件：**评分处理中、失败或评分服务不可用。
- **判断依据：**版本评分状态。
- **反馈形式：**评分模块 EmptyState/状态区。
- **系统反馈：**不伪造分数，不阻断版本保存和使用；是否允许使用仍待业务最终确认。
- **用户下一步：**稍后重试、查看其他版本或联系总行管理者。
- **恢复路径：**留在当前版本详情，刷新评分模块即可，无内容丢失。

### 5.9 历史版本还原失败

- **发生时机：**确认还原后。
- **触发条件：**历史内容读取、新版本保存或运行准备失败。
- **判断依据：**是否成功创建新的正式版本。
- **反馈形式：**复杂结果 Dialog；若正式版本已创建但运行未就绪，转为持续状态 Banner。
- **系统反馈：**未创建新版本时保持当前版本不变；已创建时保留新版本并说明当前运行版本。
- **用户下一步：**重新还原、查看版本记录或联系总行管理者。
- **恢复路径：**返回版本列表一步完成，原历史版本和当前版本均不丢失。

### 5.10 财富小助联想为空或加载失败

- **发生时机：**输入“/”或继续筛选时。
- **触发条件：**无可用 Skill、关键词无匹配或查询超时。
- **判断依据：**可用集合和查询结果。
- **反馈形式：**联想面板 EmptyState 或局部失败状态。
- **系统反馈：**区分“暂无可用 Skill”“没有匹配结果”“暂时加载失败”，不清空输入。
- **用户下一步：**去广场、清空关键词或重试。
- **恢复路径：**在面板内一步恢复，输入内容保留。

### 5.11 Skill 执行超时

- **发生时机：**用户发送 Skill 调用后。
- **触发条件：**AI 执行超过限制。
- **判断依据：**本次调用状态。
- **反馈形式：**对话流中的失败消息与“重试”动作。
- **系统反馈：**终止本次执行，保留 Skill 和补充输入，不重复提交。
- **用户下一步：**重试、修改输入或选择其他 Skill。
- **恢复路径：**点击重试一步恢复，无需重新选择 Skill。

**失败反馈：**弹窗不关闭，说明未删除并提供重试。

**页面目标：**在不中断对话输入的情况下快速发现并选择当前可运行 Skill。

**失败反馈：**空结果和加载失败在面板内解释，保留输入和光标位置。

## §7 状态与反馈文案

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
| --- | --- | --- | --- | --- |
| 未共享 | 仅创建者本人可见可用 | 创建者、总行管理者 | 编辑、共享、复制、删除 | “仅你可见，未进入 Skill 广场” |
| 已共享 | 全行可见，所属分行自动可用 | 全行可见用户 | 查看、复制；其他分行可开通 | “已共享到广场，所属分行已自动开通” |
| 本分行未开通 | 可见但当前分行不可调用 | 外部分行用户 | 为本分行开通、复制 | “开通后，本分行全体用户均可使用” |
| 本分行已开通·我正在使用 | 分行已订阅且个人未退出 | 分行用户 | 去使用、停用我的使用 | “本分行已开通，你可以在财富小助使用” |
| 本分行已开通·我已停用 | 分行关系保留，个人退出 | 当前用户 | 恢复使用 | “仅你已停用，不影响本分行其他用户” |
| 正在准备使用 | 正式版本已保存，运行版本未就绪 | 创建者、管理者、可用用户 | 等待、查看详情 | “已保存，正在准备财富小助使用” |
| 上一版本仍可用 | 新版本未就绪，旧版本继续服务 | 可用用户 | 继续使用、查看版本 | “新版本准备中，当前继续使用 {可用版本号}” |
| 准备失败 | 运行版本多次处理失败 | 创建者、管理者 | 等待恢复、联系支持 | “新版本暂未可用，当前数据已保留” |
| 评分生成中 | 当前版本尚无评分结果 | 所属分行、总行管理者 | 查看其他版本、稍后刷新 | “正在生成 {版本号} 的评分” |
| 评分失败 | 当前版本未得到评分 | 所属分行、总行管理者 | 重试或联系管理者 | “暂未生成评分，版本内容不受影响” |
| 已取消共享 | 已从广场下架 | 创建者、总行管理者 | 重新共享、编辑、删除 | “已从广场下架，不再接受新分行订阅” |
| 已删除 | 正式资产不可用且不可恢复 | 原可见用户 | 返回列表 | “此 Skill 已删除，无法继续使用” |
| 暂无可用 Skill | 当前可用集合为空 | 财富小助用户 | 去广场 | “暂无可用 Skill，可前往 Skill 广场查看并开通” |
| 无匹配结果 | 可用集合存在但关键词无匹配 | 财富小助用户 | 清空关键词 | “未找到匹配的 Skill，试试其他关键词” |
| 加载失败 | 本次查询失败 | 财富小助用户 | 重试 | “暂时无法加载 Skill，已保留你的输入” |
| 执行超时 | 本次 AI 调用超时 | 财富小助用户 | 重试或换 Skill | “本次处理超时，已保留你的输入” |

### 关键文案约束

- “订阅”仅用于建立分行开通关系；个人动作统一使用“停用我的使用/恢复使用”。
- “共享”描述全行可见和所属分行自动可用，不写成“全行已开通”。
- “保存成功”与“可在财富小助使用”分开表达。
- 用户侧不出现“消息队列、缓存、同步服务、接口错误”等技术词。
- 删除确认按订阅分行数表达影响，不使用“订阅人数”。

## §8 待确认问题

### 8.1 取消共享对既有订阅的影响

- **影响：**决定取消共享确认内容、既有外部分行可用状态和运行副本清理。
- **建议确认方：**Skill 产品负责人、财富小助负责人、总行管理者代表。
- **本蓝图推进方式：**基于推荐方案推进——从广场下架并停止新增订阅，既有订阅分行继续可用，删除才终止全部关系。

### 8.2 新版本未就绪时的回退

- **影响：**决定版本连续性、财富小助实际执行版本和失败反馈。
- **建议确认方：**财富小助技术负责人、同步服务负责人、Skill 产品负责人。
- **本蓝图推进方式：**基于推荐方案推进——继续使用上一成功版本；首个版本未就绪时不进入联想。

### 8.3 个人恢复使用

- **影响：**决定个人退出状态能否闭环。
- **建议确认方：**Skill 产品负责人。
- **本蓝图推进方式：**基于推荐方案推进——在广场和详情提供“恢复使用”，恢复后重新进入个人联想结果。

### 8.4 订阅分行数口径

- **影响：**决定卡片数字、确认弹窗和价值指标。
- **建议确认方：**业务运营负责人、数据指标负责人。
- **本蓝图推进方式：**基于推荐方案推进——只统计主动订阅的外部分行，所属分行自动可用但不计入订阅数。

### 8.5 名称唯一性

- **影响：**决定创建、复制命名和冲突校验。
- **建议确认方：**Skill 产品负责人、技术负责人。
- **本蓝图推进方式：**基于推荐方案推进——同一创建者范围内唯一；复制默认追加“副本”和序号。

### 8.6 评分触发与失败边界

- **影响：**决定新版本状态、评分等待和是否阻断使用。
- **建议确认方：**评分服务负责人、Skill 产品负责人。
- **本蓝图推进方式：**基于推荐方案推进——创建、编辑、复制和还原形成新版本后自动评分；评分失败不阻断保存和使用。

### 8.7 上游深化缺口

- **影响：**当前主任务链和旅程风险来自 UXB 推导，尚未经过同项目用户故事验收标准与深度旅程分析验证。
- **建议确认方：**产品负责人、体验设计负责人。
