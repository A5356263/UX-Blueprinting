# 体验蓝图：员工自助权限申请

---

## §0 本次关键设计判断

**判断：** 自助申请的核心体验不是"做一个申请表单"，而是让三类角色各自在关键决策点上有清晰的信息支撑——管理员知道开了会发生什么、员工知道该申请什么、审批人知道批的是什么。

**主要影响：** 管理端配置页是使用率的第一道门槛，设计必须让管理员有信心开启；员工端角色列表必须有"角色→实际权限"的解释层；审批详情必须让审批人在不切换页面的情况下理解申请全貌。

**建议方案：** 管理端配置页采用单页表单+锚点导航，核心配置（开关、角色选择、审批流程）平铺可见，高级设置折叠收起。员工端申请路径收敛为：看权限→选角色→看详情→写原因→提交→追踪。审批人侧在审批中台内查看申请详情，所见即所得。

**不建议方案：** 管理端用步骤条分步配置——开启能力、选角色、绑流程是平行决策不是串行依赖，步骤条会增加往返修改成本。员工端把角色列表做成纯名称列表不加解释层。

**关键待确认：** 自助申请模式与现有治理模式的关系（UXB §9 层级一未闭合，本蓝图基于"自助申请作为独立可选能力，与现有治理模式叠加共存"推进）。审批中台回写链路假设已具备。

---

## §1 旅程图

### 角色一：超级管理员 / 权限管理员

**阶段一：了解能力**
- 用户目标：判断这个功能是否适合自己企业
- 关键触点：管理后台中看到"自助申请权限"入口
- 用户信心：中低——不确定开启后会发生什么
- 痛点：担心开了收不住

↓ *转折：看到配置说明和预览后，决定尝试*

**阶段二：首次配置**
- 用户目标：完成必要设置，安全开启
- 关键触点：自助申请配置页——开关、角色选择器、审批流程绑定
- 用户信心：中——配置项不多，但对"可申请范围"拿不准
- 痛点：不确定选哪些角色合适，担心选多了失控

↓ *转折：配置完成，看到"已开启"状态确认*

**阶段三：持续治理**
- 用户目标：查看运行情况，必要时调整配置
- 关键触点：配置页状态概览、申请记录列表
- 用户信心：高——系统按预期运转
- 痛点：如果有人申请了不该申请的角色被批准，需要能追溯

↓ *转折：遇到需要关闭能力的情况*

**阶段四：关闭或调整**
- 用户目标：安全关闭或缩小范围，不造成业务中断
- 关键触点：关闭确认弹窗（含在途申请提示）、配置变更确认
- 用户信心：中——需要确认关闭的影响
- 痛点：不确定在途申请怎么处理

---

### 角色二：员工

**阶段一：了解自己的权限现状**
- 用户目标：知道自己有什么权限
- 关键触点：个人中心或工作台中的"我的权限"入口
- 用户信心：低——之前从来不知道自己有什么权限
- 痛点：看到一堆权限但不知道每条是什么意思

↓ *转折：发现缺少需要的权限，看到"申请权限"入口*

**阶段二：选择要申请的权限**
- 用户目标：找到自己需要的角色并理解它
- 关键触点：可申请角色列表，每个角色可展开查看详情
- 用户信心：中——能看到角色包含哪些权限
- 痛点：担心申请了用不上的角色，或者申请错了

↓ *转折：选好角色，填写原因，提交*

**阶段三：等待审批**
- 用户目标：知道申请走到哪了
- 关键触点：申请记录列表、状态标签、消息通知
- 用户信心：中——能看到"待审批"
- 痛点：不知道审批人是谁、大概要等多久

↓ *转折：收到审批结果通知*

**阶段四：获得权限或重新申请**
- 用户目标：确认权限到账或理解被拒原因
- 关键触点：审批结果通知、我的权限页（更新后）
- 用户信心：通过时高，被拒时低
- 痛点：通过后不确定何时生效；被拒后不知道能不能再申请

---

### 角色三：审批人

**阶段一：收到审批任务**
- 用户目标：知道有人申请了权限、申请了什么
- 关键触点：审批中心待处理列表、消息通知
- 用户信心：中——能在列表中看到申请概要
- 痛点：单看列表信息不够，需要点进去才知道详情

↓ *转折：进入审批详情*

**阶段二：判断是否批准**
- 用户目标：充分了解申请人是谁、申请什么、为什么申请，然后做决定
- 关键触点：审批详情页——申请人、申请角色及权限详情、申请原因
- 用户信心：高——信息充分
- 痛点：如果不了解这个角色包含什么权限，可能需要额外查询

↓ *转折：做出审批决定*

**阶段三：完成审批**
- 用户目标：确认审批结果已生效
- 关键触点：审批完成反馈、列表状态更新
- 用户信心：高——操作完成
- 痛点：同意后不确定权限是否已自动生效

---

## §2 交互流程总览

### 分角色流程

**管理员线：**
- A1：进入自助申请配置页 → A2：配置可申请角色范围 → A3：绑定审批流程 → A4：开启能力 → A5：查看运行状态 → A6：调整配置或关闭能力

**员工线：**
- B1：查看我的权限 → B2：进入申请权限 → B3：浏览可申请角色 → B4：查看角色详情 → B5：填写原因提交 → B6：追踪申请状态 → B7：查看审批结果

**审批人线：**
- C1：收到审批待办 → C2：查看申请详情 → C3：做出审批决定 → C4：填写审批意见 → C5：提交审批结果

### 异常流程重点

- E1（无可申请角色）：B2 入口可见但角色列表为空
- E2（能力已关闭）：B1 中不展示申请入口，或直链访问提示未开放
- E3（角色被删除）：B3→B5 提交时角色失效
- E5（自动授权失败）：C3 通过后系统通知管理员
- E6（重复申请）：B5 提交时阻断
- E7（关闭时在途申请）：A6 关闭时弹窗确认

## §3 主交互流程

### 管理员线

#### 节点 A1：进入自助申请配置页

- 用户动作：超管在管理后台导航中找到"自助申请权限"入口并点击
- 系统反馈：进入配置页面，展示当前能力状态（已开启/已关闭）及配置项
- 前置信息：入口仅超管可见；若当前与互斥的治理模式冲突，入口展示异常状态说明
- 建议文案：
  - 页面标题："自助申请权限"
  - 状态标签：已开启（绿色）/ 已关闭（灰色）
- 下一步：若已关闭 → A2 配置；若已开启 → A5 查看运行状态

#### 节点 A2：配置可申请角色范围

- 用户动作：超管从已有角色列表中选择一个或多个角色，作为员工可申请的范围
- 系统反馈：角色选择器实时展示已选数量；每个角色旁可展开查看角色包含的权限详情；已选角色进入"已选角色"汇总区
- 前置信息：角色列表来源于现有角色管理体系；角色名称旁标注成员数量帮助管理员判断范围大小
- 建议文案：
  - 选择器标题："可申请的角色范围"
  - 辅助说明："员工只能看到和申请你在这里选中的角色"
  - 空状态提示："至少选择一个角色后才能开启"
  - 已选汇总："已选 N 个角色"
- 下一步：继续 A3 或直接 A4

#### 节点 A3：绑定审批流程

- 用户动作：超管从审批流程模板列表中选择一个已配置的流程
- 系统反馈：展示所选流程的简要预览（审批节点数、审批人类型）；支持跳转到审批管理页新建流程
- 前置信息：流程模板来源于审批中台；若无可选流程，引导超管先去审批管理中创建
- 建议文案：
  - 选择器标题："审批流程"
  - 辅助说明："员工提交申请后将按此流程进入审批"
  - 无流程时："暂无可用的审批流程，请先去审批管理中创建"
  - 跳转按钮："去创建审批流程"
- 下一步：继续 A4

#### 节点 A4：开启能力

- 用户动作：超管确认角色范围和审批流程已配置，点击开启开关
- 系统反馈：
  - 尝试开启：校验配置完整性（至少一个角色 + 审批流程已绑定）
  - 校验通过：开关切换为"已开启"；展示成功 toast："自助申请权限已开启，员工端已出现申请入口"
  - 校验不通过：开关不切换；在对应缺失的配置项旁边标红提示
- 建议文案：
  - 开启前确认："开启后，员工可以在个人中心查看和申请权限。确认开启？"
  - 校验失败时："请先完成以下配置：选择可申请角色、绑定审批流程"
- 下一步：能力开启后 → A5

#### 节点 A5：查看运行状态

- 用户动作：超管在配置页查看当前运行概况
- 系统反馈：展示能力状态、当前配置摘要、近期申请统计（今日申请数、在途申请数、本月通过数）
- 建议文案：
  - 状态摘要区："当前可申请角色：N 个 | 审批流程：XXX | 今日申请：M 条 | 在途：K 条"
- 下一步：可调整配置 → A2/A3 或 A6 关闭能力

#### 节点 A6：关闭能力

- 用户动作：超管点击关闭开关
- 系统反馈：弹出确认弹窗，展示当前在途申请数量和处理说明；超管确认后关闭
- 建议文案：
  - 弹窗标题："关闭自助申请权限"
  - 弹窗正文："当前有 N 条申请正在审批中。关闭后，在途申请将继续走完审批流程（基于推荐方案）。员工端将看不到申请入口。已通过申请授予的权限不受影响。"
  - 确认按钮："确认关闭"
  - 取消按钮："再想想"
- 下一步：关闭后回到 A1 状态

---

### 员工线

#### 节点 B1：查看我的权限

- 用户动作：员工在个人中心或工作台点击"我的权限"
- 系统反馈：展示按应用分组的权限列表，每项权限标注来源（"管理员授予"或"自助申请"）和角色名称。若自助申请能力已开启，页面顶部或底部引导"申请更多权限"入口
- 前置信息：仅展示已生效的权限
- 建议文案：
  - 页面标题："我的权限"
  - 来源标签："管理员授予""自助申请"
  - 引导入口："申请更多权限 →"
  - 空状态："暂无权限记录"
- 下一步：点击"申请更多权限" → B2

#### 节点 B2：进入申请权限

- 用户动作：员工点击申请入口
- 系统反馈：进入可申请角色列表页。若自助申请能力已关闭或无可申请角色，展示对应空状态
- 建议文案：
  - 页面标题："申请权限"
  - 辅助说明："请选择你需要的角色，提交后将由审批人审核"
- 下一步：浏览角色 → B3

#### 节点 B3：浏览可申请角色

- 用户动作：员工浏览角色列表，对感兴趣的角色展开查看详情
- 系统反馈：
  - 角色列表卡片式展示，每张卡片含：角色名、角色简要描述、权限概要（如"包含 3 个应用的 5 项功能"）
  - 已拥有的角色标注"已拥有"标签
  - 展开后展示：角色包含的应用列表和功能说明（通俗语言）
- 建议文案：
  - 卡片展开按钮："查看包含的权限"
  - 已拥有标签："已拥有"
  - 角色详情区："该角色包含以下权限：XX 应用——XX 功能……"
- 下一步：选定角色 → B4

#### 节点 B4：查看角色详情并确认申请

- 用户动作：员工在角色详情中确认这就是自己需要的，点击"申请此角色"
- 系统反馈：进入申请提交页，展示选定角色名称、角色权限摘要、申请原因输入框
- 建议文案：
  - 页面标题："申请角色"
  - 角色信息区："申请角色：{角色名}" + 权限摘要（只读）
  - 原因输入框 label："申请原因"
  - 原因输入框 placeholder："请简要说明为什么需要这个角色，帮助审批人更好地理解你的需求"
- 下一步：填写原因 → B5

#### 节点 B5：提交申请

- 用户动作：员工填写申请原因并点击提交
- 系统反馈：
  - 校验申请原因非空
  - 校验同一角色无在途申请（提示"该角色已有申请正在审批中"）
  - 提交成功：toast"申请已提交"，跳转至申请记录页
  - 进入审批流转
- 建议文案：
  - 提交按钮："提交申请"
  - 成功反馈："申请已提交，请等待审批"
  - 重复申请阻断："该角色已有申请正在审批中，请等待审批结果"
- 下一步：→ B6

#### 节点 B6：追踪申请状态

- 用户动作：员工进入申请记录列表
- 系统反馈：按时间倒序展示所有申请记录，每条含：角色名、提交时间、当前状态标签（待审批/已通过/已生效/已拒绝/已撤回）、审批意见（如有）。待审批的申请可操作"撤回"
- 建议文案：
  - 页面标题："我的申请"
  - 状态标签：待审批（黄色）/ 已通过（蓝色）/ 已生效（绿色）/ 已拒绝（灰色）/ 已撤回（灰色）
  - 撤回按钮："撤回申请"
  - 撤回确认："撤回后需重新提交，确认撤回？"
- 下一步：等待或 → B7

#### 节点 B7：查看审批结果

- 用户动作：员工点击已完成的申请记录查看详情
- 系统反馈：
  - 已通过→已生效：展示"该角色权限已生效，可在'我的权限'中查看" + 跳转链接
  - 已拒绝：展示审批意见 + "可重新提交申请" 按钮
- 建议文案：
  - 已生效："{角色名}权限已生效。查看我的权限 →"
  - 已拒绝："审批未通过。审批意见：{意见}。" + "重新申请" 按钮
- 下一步：已生效 → B1 验证；已拒绝 → B2 重新申请

---

### 审批人线

#### 节点 C1：收到审批待办

- 用户动作：审批人在审批中心待处理列表中看到权限申请
- 系统反馈：列表中展示申请概要——申请人姓名、申请角色、提交时间
- 建议文案：
  - 列表项标题："{员工姓名} 申请 {角色名}"
  - 列表项副标题：提交时间
- 下一步：点击进入 → C2

#### 节点 C2：查看申请详情

- 用户动作：审批人进入申请详情页
- 系统反馈：展示完整申请信息——
  - 申请人：姓名、部门
  - 申请角色：角色名 + 角色包含的权限详情（可展开）
  - 申请原因：员工填写的原文
  - 申请时间
  - 该员工当前已有权限摘要（供审批人参考判断）
- 建议文案：
  - 详情区标题："权限申请详情"
  - 权限详情展开："该角色包含的权限"
  - 当前权限区："申请人当前已有权限"（折叠，按需展开）
- 下一步：判断 → C3

#### 节点 C3：做出审批决定

- 用户动作：审批人点击"同意"或"拒绝"
- 系统反馈：
  - 同意：展开审批意见输入框（若流程配置为必填则强制填写），提交后toast"已同意"，系统自动触发授权
  - 拒绝：展开审批意见输入框（必填），提交后toast"已拒绝"，通知员工
- 建议文案：
  - 同意按钮："同意"
  - 拒绝按钮："拒绝"
  - 同意意见 label："审批意见（选填）"
  - 拒绝意见 label："拒绝原因（必填）"
  - 同意成功："已同意，系统正在自动授权"
  - 拒绝成功："已拒绝，已通知申请人"
- 下一步：完成 → C4

#### 节点 C4：完成审批

- 用户动作：审批完成，系统自动回到待处理列表
- 系统反馈：该条申请从待处理列表中移除；若自动授权失败，审批人会收到异常通知
- 建议文案：
  - 列表更新：已处理的申请不出现在待处理中
  - 异常通知："{员工姓名}的{角色名}授权失败，请联系管理员手动处理"
- 下一步：继续处理其他待办

## §4 次交互流程

### 管理端次流程

#### 节点 S-A1：调整可申请角色范围

- 触发：管理员在能力已开启状态下修改角色选择
- 步骤：
  1. 管理员在配置页的角色选择器中增删角色
  2. 系统实时更新已选角色汇总
  3. 保存时，若移除了某个角色，系统检查是否有该角色的在途申请
  4. 若有在途申请：弹窗提示"当前有 M 条{角色名}的申请正在审批中。移除后新申请将不可见此角色，在途申请不受影响。"
  5. 确认后保存，新范围即时生效
- 建议文案：变更成功 toast："可申请角色范围已更新"

#### 节点 S-A2：切换审批流程

- 触发：管理员在能力已开启状态下更换绑定的审批流程
- 步骤：
  1. 管理员重新选择审批流程模板
  2. 系统提示"切换审批流程后，新提交的申请将使用新流程，在途申请不受影响"
  3. 确认后保存
- 建议文案：切换成功 toast："审批流程已更新"

#### 节点 S-A3：查看申请明细

- 触发：管理员在配置页查看运行统计后，想深入了解具体申请记录
- 步骤：
  1. 点击"查看申请记录"进入申请记录列表
  2. 可按状态、角色、时间筛选
  3. 点击单条记录查看详情，包含完整审批链路
  4. 对异常状态的申请（如自动授权失败），可手动介入处理
- 建议文案：手动授权按钮："手动授权"；手动授权确认："确认手动为{员工}授予{角色}权限？"

### 员工端次流程

#### 节点 S-B1：撤回申请

- 触发：员工在申请记录中对"待审批"的申请点击"撤回"
- 步骤：
  1. 点击撤回按钮
  2. 弹窗确认："撤回后需重新提交，确认撤回？"
  3. 确认后申请状态变为"已撤回"（终态）
  4. Toast："申请已撤回"
- 互动限制：仅"待审批"状态可撤回

#### 节点 S-B2：重新申请

- 触发：员工对"已拒绝"的申请点击"重新申请"
- 步骤：
  1. 点击重新申请按钮
  2. 跳转到申请提交页（B4），预填上次的角色和原因
  3. 员工可修改原因后重新提交
- 建议文案：按钮："重新申请"

#### 节点 S-B3：权限变更通知

- 触发：自助申请获得的权限被管理员回收或自动规则撤销时
- 步骤：
  1. 系统发送通知给员工
  2. 员工在"我的权限"中看到该权限已不在了
  3. 若需要可重新申请
- 建议文案：通知内容："你的{角色名}权限已被调整。如仍有需要，可重新申请。"

## §5 异常与阻断流程

### E1：无可申请角色

- 发生时机：员工进入申请权限页（B2）
- 触发条件：管理员未配置任何可申请角色，或已配置的角色被全部移除
- 判断依据：可申请角色列表为空
- 反馈形式：页面空状态
- 系统反馈：空状态插画 + 说明文字
- 建议文案：
  - 空状态标题："暂无可以申请的角色"
  - 空状态说明："管理员暂未设置可申请的角色范围，如有需要请联系管理员"
- 用户下一步：联系管理员或返回"我的权限"

### E2：自助申请已关闭

- 发生时机：员工尝试访问申请入口
- 触发条件：管理员关闭了自助申请能力
- 判断依据：全局开关状态为关闭
- 反馈形式：入口隐藏（推荐）+ 直链访问时页面提示
- 系统反馈：
  - 主路径：员工端不展示"申请权限"入口
  - 兜底（直链访问）：页面提示"自助申请权限功能暂未开放"
- 建议文案："自助申请权限功能暂未开放，如有需要请联系管理员"
- 用户下一步：联系管理员

### E3：申请角色已被删除

- 发生时机：员工提交申请时（B5）
- 触发条件：员工在浏览角色到提交之间的时间窗口内，管理员删除了该角色
- 判断依据：提交时校验角色是否存在
- 反馈形式：阻断提示（toast）
- 系统反馈：Toast"该角色已被移除，请选择其他角色"，页面自动刷新角色列表
- 建议文案："该角色已被移除，请选择其他角色"
- 用户下一步：返回角色列表重新选择

### E4：审批人不存在或不可用

- 发生时机：申请进入审批流转时
- 触发条件：绑定的审批流程中审批人岗位已空（离职/调动）
- 判断依据：审批中台在流转时无法定位审批人
- 反馈形式：通知管理员 + 申请状态标记为异常
- 系统反馈：
  - 员工侧：申请状态显示"审批异常"，附说明"审批流程暂时无法继续，管理员正在处理"
  - 管理员侧：站内通知"员工{XX}的{角色名}申请审批人不存在，请手动处理"；在申请记录中可手动转派
- 建议文案：
  - 员工侧状态："审批异常——审批流程暂时无法继续，管理员正在处理"
  - 管理侧通知："{员工}的{角色}申请审批人不存在，请前往处理"
- 用户下一步：管理员手动转派或指定审批人

### E5：自动授权失败

- 发生时机：审批通过后（C3）
- 触发条件：权限系统写入失败（角色不存在、系统异常等）
- 判断依据：审批中台回写权限系统返回失败
- 反馈形式：
  - 审批人：toast 提示 + 审批仍是已完成状态
  - 管理员：站内通知
  - 员工：申请记录状态更新为"授权异常"
- 系统反馈：
  - 审批人端 toast："已同意，但自动授权暂未完成，系统已通知管理员处理"
  - 管理员通知："{员工}的{角色}授权失败（原因：{具体原因}），请手动授权"
  - 员工侧："授权处理中，如有疑问请联系管理员"
- 建议文案：同上
- 用户下一步：管理员手动授权后，状态恢复正常

### E6：重复申请

- 发生时机：员工提交申请时（B5）
- 触发条件：同一角色已有在途（待审批）申请
- 判断依据：提交前查询当前员工对该角色的在途申请
- 反馈形式：阻断提示（提交按钮上方）
- 系统反馈：阻断提示说明已有在途申请，提供"查看申请"链接
- 建议文案："该角色已有申请正在审批中。查看申请 →"
- 用户下一步：等待审批结果或先撤回旧申请

### E7：关闭能力时存在在途申请

- 发生时机：管理员关闭自助申请能力（A6）
- 触发条件：存在状态为"待审批"的申请单
- 判断依据：关闭前统计在途申请数量
- 反馈形式：确认弹窗（强阻断）
- 系统反馈：
  - 弹窗标题："关闭自助申请权限"
  - 弹窗正文展示在途申请数量和关闭后处理说明
- 建议文案：
  - "当前有 N 条申请正在审批中。关闭后："
  - "· 员工端将不再展示申请入口"
  - "· 在途申请将继续走完审批流程（基于推荐方案）"
  - "· 已通过申请授予的权限不受影响"
  - "确认关闭？"
- 用户下一步：确认关闭或取消

### E8：与现有治理模式冲突（基于推荐方案推进）

- 发生时机：管理员尝试开启自助申请能力
- 触发条件：当前已开启的治理模式与自助申请模式定义上存在互斥
- 判断依据：模式互斥规则（UXB §9 层级一未闭合，此处基于推荐方案）
- 反馈形式：阻断提示 + 模式冲突说明
- 系统反馈：开启开关时弹窗说明冲突情况
- 建议文案："当前已开启{模式名}。开启自助申请前，请确认两种模式共存时的生效规则。"
- 用户下一步：管理员确认后继续开启，或在配置中关闭冲突模式

### P7：关闭确认弹窗（管理端）

- 弹窗目标：让管理员在充分知情的前提下确认关闭
- 触发条件：管理员在能力已开启状态下点击关闭开关
- 弹窗结构：

```
┌─────────────────────────────────────────────────┐
│ 关闭自助申请权限                         [✕]    │
│                                                 │
│ ⚠ 当前有 5 条申请正在审批中                     │
│                                                 │
│ 关闭后：                                        │
│ · 员工端将不再展示申请入口                      │
│ · 在途申请将继续走完审批流程                    │
│ · 已通过申请授予的权限不受影响                  │
│                                                 │
│ [再想想]                           [确认关闭]   │
└─────────────────────────────────────────────────┘
```

- 在途申请为 0 时：省略"当前有 N 条申请"提示行
- 按钮：
  - 确认关闭：危险按钮"确认关闭"
  - 取消：次按钮"再想想"

## §8 待确认问题

### 基于推荐方案推进的问题（对应 UXB §9 层级一）

1. **自助申请模式与现有治理模式的关系**
   - 影响：管理端配置页的互斥逻辑和开启前的校验
   - 当前处理：蓝图基于"自助申请作为独立可选能力，与现有治理模式叠加共存"推进。若实际为互斥关系，需调整 P1 页面开关逻辑和 E8 异常处理
   - 建议确认方：产品+技术

2. **审批中台回写链路是否已具备**
   - 影响：整个自动授权流程能否跑通。若不支持回写，需改为"审批通过后通知管理员手动授权"
   - 当前处理：蓝图假设回写链路已具备，C3 审批通过后触发自动授权
   - 建议确认方：技术

3. **关闭自助申请时在途申请的处理策略**
   - 影响：关闭确认弹窗（P7）的提示文案和处理逻辑
   - 当前处理：蓝图按"在途申请继续走完审批流程"推进
   - 建议确认方：产品

### 体验阶段新识别的问题

4. **员工申请页是否需要展示审批流程预览**
   - 影响：B3/B4 页面信息结构——是否在提交前告诉员工申请将经过哪些审批节点
   - 当前处理：蓝图未展示。可后续在提交确认时加入"审批流程预览"
   - 建议确认方：产品+体验

5. **员工端"我的权限"入口位置**
   - 影响：员工发现路径——放在个人中心还是工作台侧边栏
   - 当前处理：蓝图不做硬指定，建议根据产品现有导航习惯放置
   - 建议确认方：产品+体验

6. **审批详情中"申请人当前已有权限"是否需要展示**
   - 影响：C2 审批详情页信息密度——展示有助于审批人判断申请是否合理，但增加页面复杂度
   - 当前处理：蓝图按折叠展示，审批人需要时展开
   - 建议确认方：产品
