# 体验蓝图：员工自助申请权限

---

## §0 本次关键设计判断

**判断：** 这次体验设计的核心挑战不是页面数量，而是三个角色各不相同的认知负担——管理员的配置路径依赖、员工的权限理解门槛、审批人的决策信息不足。设计重心应放在管理端的引导式配置、员工端的业务化转译、审批端的决策信息呈现。

**主要影响：** 三条角色主线（配置→申请→审批）在体验上需要各自独立但数据层统一。员工侧需要把"角色/功能权限"转译为可理解的业务语言；管理端需要把配置前置依赖（范围→审批→开关）转化为自然操作顺序；审批端需要在审批详情中嵌入权限业务信息而不只是通用表单数据。

**建议方案：** 管理端采用引导式配置（先范围→再审批→最后开启），员工端以"我的权限"为统一入口承载查看和申请，审批端在 OA 审批详情中扩展权限信息卡片。关闭态、审批中态、授权失败态作为一等场景设计，不在主流程完成后再补。

**不建议方案：** 管理端把所有配置项平铺在单页（不考虑前置依赖，管理员可能先点开开关再被错误拦截）；员工端直接暴露角色名和功能枚举（员工无法理解这些技术概念）；审批端只展示通用表单字段不做权限语义扩展（审批人无法做出合理判断）。

**关键待确认：** 可申请范围的业务粒度（按角色/按功能/组合）直接影响员工端申请页的信息架构——本次按"按角色申请"设计，若最终确认按功能权限则需重构员工端选项呈现方式。

### 承接映射表

| UXB 判断 | 对体验意味着什么 | 体验设计决策 | 落点章节 |
|---|---|---|---|
| H-01: 自助申请是权限来源新增通道，不替代管理员授权 | 员工侧入口和信息架构需与管理员侧在体验上区分，但数据层统一 | 员工端统一入口为"我的权限"，聚合查看已有权限 + 申请新权限；与管理后台权限管理页完全独立 | §3(员工主线), §6(P2/P3) |
| H-02: 可申请范围由管理员预设，员工无自主扩大能力 | 员工看到的申请项是有限集合，需按业务语义分组呈现 | 按角色分组展示可申请项，每个角色附带简要说明和已包含的功能权限预览 | §3(员工申请), §6(P3) |
| H-03: 审批链路复用 OA 审批中台 | 申请状态追踪、消息通知复用 OA 既有体验，但需嵌入权限业务信息 | 审批详情中增加"权限信息卡片"，展示申请的角色/功能权限详情、数据范围说明 | §3(审批主线), §6(P4) |
| H-04: 申请单独立状态机与审批/授权双向同步 | 员工感知的状态变化需连续可理解，不能出现空白期 | 五个申请单状态全部设计对应的页面态和通知文案；授权中过渡态明确告知"权限正在生效中" | §7(状态文案表) |
| H-05: 权限来源标记为"自助申请"，纳入查询解释链路 | 员工理解不同来源的区别和含义 | "我的权限"列表中每项标注来源标签（管理员授予/角色分配/自助申请），自助申请项可点击查看原始申请记录 | §6(P2), §7 |
| H-06: 能力关闭时员工侧体验需收口 | 关闭后申请入口消失但查看已有权限和记录保留 | 关闭态下"我的权限"页保留查看功能，隐藏申请入口，审批中申请继续走完并通知结果 | §5(E-05), §6(P2-关闭态) |
| H-07: 管理端配置有前置依赖 | 需引导管理员按顺序完成配置 | 采用步骤引导：第一步配置范围→第二步设置审批→第三步确认开启，每步完成前检查前置条件 | §3(管理员主线), §6(P1) |

## §1 旅程图

### 角色一：超级管理员 — 配置自助申请能力

**阶段一：发现与决策**

- 用户目标：了解自助申请能力是什么、是不是自己企业需要的
- 关键触点：权限管理模式页面中的新能力卡片/入口
- 用户信心：中低——不确定这项能力会带来什么变化
- 痛点：不清楚和已有的子管理员、双管理员互审、权限变更审批是什么关系

**→ 关键转折：管理员决定尝试配置**

**阶段二：配置可申请范围**

- 用户目标：选择哪些角色或权限允许员工自助申请
- 关键触点：可申请范围配置页
- 用户信心：中等——选角色比较直观，但如果按功能权限选则复杂度陡增
- 痛点：不确定选的范围会不会太宽或太窄，缺乏参考基准

**→ 关键转折：范围配置完成，进入审批设置**

**阶段三：设置审批流程**

- 用户目标：为自助申请指定审批人和审批方式
- 关键触点：跳转至 OA 审批中台完成流程设计，或引用已有流程模板
- 用户信心：波动——熟悉 OA 审批的管理员较有信心，不熟悉的可能卡住
- 痛点：需要在两个系统之间跳转，可能打断配置心流

**→ 关键转折：审批流程就绪，准备开启**

**阶段四：开启并观察**

- 用户目标：正式开启能力，确认员工端正常运作
- 关键触点：开启确认页（含配置摘要），开启后的状态页
- 用户信心：中高——配置完成后的确认摘要增强了信心
- 痛点：开启后不确定员工看到的是什么，可能需要切换视角验证

---

### 角色二：员工 — 查看权限并申请

**阶段一：发现入口**

- 用户目标：找到可以查看和申请权限的地方
- 关键触点：工作台或导航中的"我的权限"入口
- 用户信心：低——之前没有这个入口，员工需要被告知
- 痛点：入口不明显，或和其他功能混在一起

**→ 关键转折：首次进入"我的权限"**

**阶段二：理解已有权限**

- 用户目标：看清楚自己现在有什么权限
- 关键触点：我的权限页面，按应用分组展示权限列表和来源
- 用户信心：提升——知道自己有什么了
- 痛点：如果权限项很多，列表可能很长，难以快速定位

**→ 关键转折：发现自己缺少某项权限**

**阶段三：选择并申请**

- 用户目标：找到需要的权限并提交申请
- 关键触点：申请权限页，按角色/功能展示可申请项
- 用户信心：波动——看到选项但不确定选哪个对
- 痛点：角色名可能无法一眼看出包含什么，需要展开查看详情

**→ 关键转折：提交申请**

**阶段四：等待与查看结果**

- 用户目标：知道申请走到哪了、什么时候有结果
- 关键触点：申请记录列表、申请详情页、消息通知
- 用户信心：中——知道在审批中，但不确定要多久
- 痛点：审批中状态长时间不变，缺乏进度感

**→ 关键转折：收到审批结果通知**

**阶段五：确认权限生效**

- 用户目标：确认新权限已经可以用了
- 关键触点：申请结果页 + 我的权限列表更新
- 用户信心：高——权限已生效，可以正常使用
- 痛点：如果审批通过但权限未生效，会产生困惑

---

### 角色三：审批人 — 处理权限申请

**阶段一：收到审批通知**

- 用户目标：知道有新的权限申请需要处理
- 关键触点：OA 审批待办列表、消息通知
- 用户信心：中——知道有申请，但不确定内容
- 痛点：待办列表中权限申请和其他审批混在一起，可能不显眼

**→ 关键转折：进入审批详情**

**阶段二：理解申请内容**

- 用户目标：判断这个申请是否合理
- 关键触点：审批详情页（含权限信息卡片）
- 用户信心：取决于信息完整度——看到申请人信息+权限详情+申请原因时才足够
- 痛点：如果只展示角色名不展开功能详情，审批人难以判断风险

**→ 关键转折：做出审批决策**

**阶段三：完成审批**

- 用户目标：同意或拒绝，并确认结果已生效
- 关键触点：审批操作区 + 审批结果确认
- 用户信心：高——点击后立即看到结果反馈
- 痛点：同意后不确定授权是否真的生效了

## §2 交互流程总览

### 管理员侧：配置与开关

```
M-01 进入权限管理模式 → M-02 查看自助申请能力卡片 → M-03 配置可申请范围
→ M-04 设置审批流程 → M-05 确认开启 → M-06 查看运行状态 → M-07 调整配置/关闭
```

### 员工侧：查看与申请

```
E-01 发现"我的权限"入口 → E-02 查看已有权限列表 → E-03 进入申请权限
→ E-04 浏览可申请项并选择 → E-05 填写申请原因并提交 → E-06 查看申请记录
→ E-07 追踪申请状态 → E-08 收到结果通知 → E-09 确认权限生效
```

### 审批人侧：审核与决策

```
A-01 收到审批待办 → A-02 进入审批详情 → A-03 查看权限信息卡片
→ A-04 查看申请人信息 → A-05 做出审批决策 → A-06 确认审批结果
```

### 异常流程重点

- EX-01 管理员未完成前置配置就尝试开启
- EX-02 员工申请的权限超出可申请范围
- EX-03 审批人不存在或已离职
- EX-04 审批通过后自动授权失败
- EX-05 管理员关闭能力时存在审批中申请
- EX-06 审批中员工账号变更（离职/禁用）
- EX-07 员工已有相同权限时提交申请
- EX-08 开启时治理模式冲突

## §3 主交互流程

### 管理员主线：首次配置并开启自助申请

#### M-01 进入权限管理模式

- 用户动作：在管理后台导航中点击"权限管理"，进入权限管理模式页面
- 系统反馈：展示当前已开启的治理模式状态（子管理员/双管理员互审/权限变更审批），以及"自助申请权限"能力卡片
- 需要前置解释的信息：能力卡片上展示简要说明——"允许员工自助查看权限并申请新权限，审批通过后自动授权"
- 建议文案：卡片标题"员工自助申请权限"，状态标签"未开启"，简介"员工可自行查看已有权限，并在设定范围内申请新权限，经审批后自动生效"
- 下一步：点击卡片进入配置

#### M-02 查看自助申请能力卡片

- 用户动作：在权限管理模式页查看"员工自助申请权限"卡片
- 系统反馈：卡片展示当前状态（未配置/已开启/已关闭），以及快捷操作入口
- 需要前置解释的信息：如果当前已开启其他不兼容的治理模式，卡片上需要提前提示可能冲突。按推荐方案（自助申请与双管理员互审互斥，与子管理员和权限变更审批兼容），仅在已开启双管理员互审时显示冲突提示
- 建议文案：（未配置态）"尚未配置。开启前需要先设定员工可申请的权限范围，并指定审批流程。"
- 下一步：点击"开始配置"

#### M-03 配置可申请范围

- 用户动作：在可申请范围配置页，按角色勾选允许员工自助申请的权限项。按推荐方案，此处以角色为主要选择粒度，每个角色附带能力摘要
- 系统反馈：展示角色列表（含角色名称、角色下包含的功能权限数量、简要说明），支持勾选和搜索。已勾选的角色实时显示在右侧"已选范围"摘要区
- 需要前置解释的信息：页面顶部提示——"员工将可以申请以下角色对应的权限。建议先选择范围和风险较低的角色开始。"
- 建议文案：列表项示例——"考勤管理员"（含 8 项功能权限，可查看和管理考勤数据），右侧摘要"已选 3 个角色"
- 下一步：点击"下一步：设置审批流程"

#### M-04 设置审批流程

- 用户动作：选择审批流程设置方式——"使用已有流程模板"或"新建审批流程"。新建时跳转至 OA 审批中台
- 系统反馈：若选择已有模板，展示可选模板列表（已过滤出权限审批类模板）；若选择新建，提供跳转按钮并说明跳转后如何返回
- 需要前置解释的信息：提示管理员审批流程中建议包含哪些信息展示（如申请人当前权限列表、申请的权限详情）
- 建议文案：跳转提示"将在新页面中完成审批流程设计。设计完成后返回此页面继续。"
- 下一步：点击"下一步：确认并开启"

#### M-05 确认开启

- 用户动作：查看配置摘要（可申请范围 + 审批流程），确认无误后点击开启
- 系统反馈：展示配置摘要面板——已选范围（角色名列表）、审批流程名称/节点摘要。开启按钮下方标注"开启后员工即可在'我的权限'中查看和申请"
- 需要前置解释的信息：治理模式兼容检查结果（如无冲突则显示"当前配置与其他治理模式无冲突"）
- 建议文案：确认面板标题"确认开启自助申请"，按钮"确认开启"，成功后 toast "自助申请权限能力已开启"
- 下一步：跳转至运行状态页

#### M-06 查看运行状态

- 用户动作：查看自助申请运行概况
- 系统反馈：展示能力状态（已开启）、当前审批中的申请数量、已完成的申请数量；提供"调整配置"和"关闭能力"入口
- 建议文案：状态卡片"运行中"，统计数据"审批中 X 项，已完成 X 项"
- 下一步：可调整配置、查看申请记录、或关闭

#### M-07 关闭能力

- 用户动作：在运行状态页点击"关闭自助申请"
- 系统反馈：弹出确认框，展示影响说明——"关闭后员工无法提交新申请。当前有 X 项审批中的申请，关闭后这些申请将继续走完审批流程。"（按推荐方案：允许关闭但审批中的继续走完）
- 需要前置解释的信息：关闭后已完成授权不受影响，员工仍可查看已有权限
- 建议文案：确认标题"确认关闭自助申请"，说明"关闭后：员工无法提交新申请；已有权限不受影响；审批中的 X 项申请将继续完成审批"
- 下一步：确认关闭后返回能力卡片页，卡片状态更新为"已关闭"

### 员工主线：查看权限并申请

#### E-01 发现"我的权限"入口

- 用户动作：在工作台或导航中发现"我的权限"入口并点击
- 系统反馈：自助申请已开启时，入口正常显示；未开启时不显示申请相关入口但保留"我的权限"查看入口（取决于产品决策）
- 需要前置解释的信息：入口名称"我的权限"比"权限管理"更贴近员工视角，避免员工以为这是管理功能
- 建议文案：入口名称"我的权限"，可选副标题"查看和申请权限"
- 下一步：进入我的权限页面

#### E-02 查看已有权限列表

- 用户动作：在"我的权限"页浏览当前拥有的权限
- 系统反馈：按应用分组展示权限列表，每项显示权限名称、简要说明、来源标签。来源标签分为"管理员授予""角色分配""自助申请"，自助申请来源可点击查看原始申请记录
- 需要前置解释的信息：页面顶部简要说明权限来源的含义——"不同来源的权限在使用上没有区别，只是获取方式不同"
- 建议文案：空状态（无权限时）"暂无权限记录。如需使用某个功能但没有权限，可以在下方申请。"；来源标签样式：自助申请=蓝色标签
- 下一步：如需新权限，点击"申请权限"按钮

#### E-03 进入申请权限

- 用户动作：在"我的权限"页点击"申请权限"按钮
- 系统反馈：进入申请页，展示可申请的角色/权限列表。列表仅显示管理员预设范围内的项目，且过滤掉员工已有的权限（避免重复申请）
- 需要前置解释的信息：如果员工已有某权限（无论来源），该项在申请列表中不出现或标注"已拥有"
- 建议文案：页面标题"申请权限"，引导语"请选择你需要申请的角色。每个角色包含一组相关权限，审批通过后自动生效。"
- 下一步：点击某个角色查看详情

#### E-04 浏览可申请项并选择

- 用户动作：浏览可申请的角色列表，点击某个角色查看其包含的功能权限详情
- 系统反馈：角色列表每项展示角色名称、简要说明、包含功能数量。点击展开后显示具体功能权限列表（只读）。提供搜索和筛选
- 需要前置解释的信息：角色说明用业务语言——"考勤管理员：可以查看和管理公司考勤数据，包括排班、打卡记录、考勤统计等"
- 建议文案：角色卡片示例——标题"考勤管理员"，说明"查看和管理公司考勤数据"，展开后"包含功能：排班管理、打卡记录查看、考勤统计、异常考勤处理"，按钮"选择此角色"
- 下一步：选择一个角色后进入提交页

#### E-05 填写申请原因并提交

- 用户动作：确认申请的角色，填写申请原因（按推荐方案为必填），提交申请
- 系统反馈：提交页展示申请摘要（申请的角色名称、包含的功能数量），申请原因输入框（必填，提示"请说明你需要此权限的原因，这将帮助审批人做出判断"），提交按钮
- 需要前置解释的信息：提交前展示预计审批流程（审批人、预计时效），让员工有合理预期
- 建议文案：输入框 placeholder"例如：因工作需要查看部门考勤数据"，提交按钮"提交申请"，提交后 toast "申请已提交，请等待审批"
- 下一步：跳转至申请记录页

#### E-06 查看申请记录

- 用户动作：在"我的申请"tab 或页面查看申请记录列表
- 系统反馈：列表展示申请时间、申请角色、当前状态（审批中/已通过/已拒绝/已撤销）、审批进度。支持点击查看详情
- 建议文案：列表项示例——"2026-06-21 申请 考勤管理员 审批中（1/2 节点已完成）"
- 下一步：点击进入申请详情

#### E-07 追踪申请状态

- 用户动作：在申请详情页查看审批进度
- 系统反馈：展示审批流节点状态（已完成/当前节点/待处理）、每个节点的审批人和处理时间/结果。审批中状态展示预计剩余时间或当前节点
- 需要前置解释的信息：如果审批超时未处理，展示提示并提供催办入口
- 建议文案：状态文案——审批中"等待 张经理 审批"，已通过"审批已通过，权限已生效"，已拒绝"审批未通过"（附拒绝原因）
- 下一步：审批中可操作"撤销申请"；已拒绝可操作"重新申请"

#### E-08 收到结果通知

- 用户动作：通过消息通知、待办或直接查看申请记录获知审批结果
- 系统反馈：审批通过——通知"你的'考勤管理员'权限申请已通过，权限已生效"；审批拒绝——通知"你的'考勤管理员'权限申请未通过"并附带拒绝原因
- 建议文案：通过通知"申请通过：考勤管理员权限已生效，可在我的权限中查看"；拒绝通知"申请未通过：考勤管理员。原因：暂不需要此权限。可修改后重新申请"
- 下一步：通过→进入我的权限确认；拒绝→进入申请详情重新申请

#### E-09 确认权限生效

- 用户动作：在"我的权限"页确认新权限已出现
- 系统反馈：权限列表更新，新增的权限项高亮或标注"新获得"，来源标签为"自助申请"
- 建议文案：新权限标记"新"（7天内展示），来源标签"自助申请"
- 下一步：正常使用

### 审批人主线：处理权限申请

#### A-01 收到审批待办

- 用户动作：在 OA 审批待办列表或消息通知中看到权限申请待办
- 系统反馈：待办列表中权限申请与通用审批一致展示，标题含申请类型和申请人姓名
- 建议文案：待办标题"权限申请 - 张三申请'考勤管理员'"
- 下一步：点击进入审批详情

#### A-02 进入审批详情

- 用户动作：在审批详情页查看申请内容
- 系统反馈：审批详情复用 OA 审批的标准结构，但扩展了"权限信息卡片"。卡片内容包括：申请的角色名称、角色包含的具体功能权限列表、数据范围说明（如有）
- 需要前置解释的信息：权限信息卡片帮助审批人理解这个权限的实际含义
- 建议文案：卡片标题"申请的权限"，内容示例"考勤管理员：包含排班管理、打卡记录查看、考勤统计、异常考勤处理等 8 项功能"
- 下一步：审阅信息后做出决策

#### A-03 查看权限信息卡片

- 用户动作：阅读权限信息卡片，理解申请内容
- 系统反馈：卡片展示角色描述，可展开查看每项功能权限的名称和说明。如有数据范围设置，展示为"数据范围：由管理员预设"
- 建议文案：展开项示例"排班管理：创建和修改排班计划；打卡记录查看：查看员工打卡记录详情"

#### A-04 查看申请人信息

- 用户动作：查看申请人的基本信息和申请原因
- 系统反馈：展示申请人姓名、部门、职务、申请原因。按推荐方案不展示申请人已有权限列表（G-06），但后续可根据产品决策补充
- 建议文案：申请人信息区"申请人：张三 | 部门：技术部 | 申请原因：因工作需要查看部门考勤数据"

#### A-05 做出审批决策

- 用户动作：点击"同意"或"拒绝"。拒绝时可填写原因（建议必填）
- 系统反馈：同意——确认后展示"已同意，权限将自动授予申请人"；拒绝——展示"已拒绝"并发送通知
- 需要前置解释的信息：同意即触发自动授权，不可撤销（需在确认前告知）
- 建议文案：同意按钮"同意（将自动授权）"，拒绝按钮"拒绝"，拒绝原因 placeholder"请说明拒绝原因"
- 下一步：返回待办列表

#### A-06 确认审批结果

- 用户动作：查看审批结果确认
- 系统反馈：同意后展示"权限已自动授予申请人"；拒绝后展示"已通知申请人"
- 建议文案：同意结果"审批完成。张三已获得'考勤管理员'权限。"；拒绝结果"审批完成。已通知张三审批结果。"
- 下一步：返回待办列表或继续处理下一项

## §4 次交互流程

### S-01 管理员调整可申请范围

1. 管理员在运行状态页点击"调整配置"
2. 进入范围配置页，展示当前已选范围
3. 管理员增减角色勾选，右侧摘要实时更新
4. 点击"保存"，系统校验变更是否影响审批中的申请（新增范围不影响；移除范围时提示"有 X 项审批中的申请涉及被移除的范围，审批通过后将不再自动授权"或阻止移除）
5. 保存成功，返回运行状态页

### S-02 管理员调整审批流程

1. 管理员在运行状态页点击"审批流程设置"
2. 展示当前绑定的审批流程信息
3. 选择切换至其他已有流程或新建流程
4. 确认变更，系统提示"审批流程变更后仅对新提交的申请生效，审批中的申请不受影响"
5. 保存成功，返回运行状态页

### S-03 员工撤销申请

1. 员工在申请详情页（审批中状态）点击"撤销申请"
2. 弹出确认框："确认撤销此申请？撤销后如需权限需重新申请。"
3. 确认后，申请状态更新为"已撤销"
4. 系统通知已处理的审批人"申请已撤销，无需继续处理"
5. 返回申请记录页

### S-04 员工重新申请（被拒后）

1. 员工在已拒绝的申请详情页点击"重新申请"
2. 进入申请页，预填上次申请的角色和原因（员工可修改）
3. 按推荐方案无冷却期限制（G-08），员工可直接提交
4. 提交后生成新申请单，进入独立审批流程

### S-05 审批人转派

1. 审批人在审批详情页点击"转派"
2. 选择转派对象（按 OA 审批中转派机制）
3. 确认转派后，当前审批节点更新审批人
4. 通知原审批人"已转派"，新审批人收到待办

### S-06 管理员查看申请记录

1. 管理员在运行状态页点击"查看申请记录"
2. 进入申请记录列表页（可筛选按人、按状态、按时间）
3. 支持查看申请详情（与员工端申请详情一致，但可看到所有员工的申请）
4. 审批中的申请不可由管理员直接修改结果（管理员应通过 OA 审批管理员功能处理）

### S-07 员工通过 OA 审批入口处理

1. 员工从 OA 审批工作台待办/消息进入
2. （此路径不涉及员工侧的权限申请操作，仅涉及审批人侧）审批人从 OA 审批待办进入与 A-01 一致
3. 移动端审批体验由 OA 审批中台统一承载，权限信息卡片需在移动端适配展示

## §5 异常与阻断流程

### EX-01 未配置前置条件即尝试开启

- 发生时机：管理员在未完成范围或审批配置时点击开启
- 触发条件：可申请范围为空 或 审批流程未设置
- 判断依据：系统校验配置完整性
- 反馈形式：页面内提示 + 按钮置灰，不使用弹窗
- 系统反馈：在开启按钮附近显示缺失项提示——"请先完成可申请范围配置"或"请先设置审批流程"，并提供快捷跳转链接
- 用户下一步：点击提示中的链接跳转到缺失项配置页

### EX-02 申请权限不在可申请范围

- 发生时机：员工提交申请时（前端校验即可拦截）
- 触发条件：所选权限不在管理员预设范围内（正常情况下前端不应出现此情况，但做防御校验）
- 判断依据：对比申请内容与可申请范围配置
- 反馈形式：页面内 toast
- 系统反馈："该权限不在当前可申请范围内，请重新选择"
- 用户下一步：返回申请页重新选择

### EX-03 审批人不存在或已离职

- 发生时机：审批流转到某节点时，指定的审批人已不存在
- 触发条件：审批人账号已删除/禁用/离职
- 判断依据：系统检测审批人状态
- 反馈形式：对审批人无反馈（已离职）；对管理员——在运行状态页展示告警信息
- 系统反馈：将该审批节点的申请标记为"审批异常"，自动触发管理员通知："X 项申请的审批人已失效，请前往 OA 审批数据管理进行流程转派"。通用审批超时机制也可作为兜底
- 用户下一步：管理员在 OA 审批数据管理中进行转派

### EX-04 审批通过后自动授权失败

- 发生时机：审批通过后系统尝试自动授权时
- 触发条件：权限写入失败（如权限系统异常、数据校验不通过等）
- 判断依据：授权接口返回失败
- 反馈形式：对员工——申请详情页展示异常状态；对管理员——运行状态页告警 + 消息通知
- 系统反馈：申请详情页展示"授权处理中，请稍候"，如果超时仍未成功则展示"授权失败，管理员正在处理"。管理员侧展示"X 项授权失败，需手动处理"，并提供手动授权入口
- 用户下一步：员工等待或联系管理员；管理员在权限管理后台手动完成授权

### EX-05 关闭能力时存在审批中申请

- 发生时机：管理员在运行状态页点击关闭时，检测到有审批中的申请
- 触发条件：存在状态为"审批中"的申请单
- 判断依据：系统查询审批中申请数量
- 反馈形式：弹窗——因为涉及不可逆操作且需要明确确认
- 系统反馈：弹窗展示"当前有 X 项审批中的申请。关闭自助申请后：员工无法提交新申请；已完成的授权不受影响；审批中的 X 项申请将继续完成审批，结果正常通知员工。确认关闭？"
- 用户下一步：确认关闭或取消

### EX-06 审批中员工账号变更

- 发生时机：审批流转过程中，申请人员工账号被禁用或标记为离职
- 触发条件：员工账号状态变为"禁用"或"离职"
- 判断依据：账号状态变更事件
- 反馈形式：对审批人——审批详情页提示"该员工已离职/账号已禁用，此申请已自动作废"
- 系统反馈：申请单自动作废，状态更新为"已作废"；通知审批人无需继续处理
- 用户下一步：审批人关闭审批详情；无需其他操作

### EX-07 员工已有相同权限

- 发生时机：员工在申请页尝试提交时
- 触发条件：员工已通过其他来源（直授/角色/自助申请）获得了该权限
- 判断依据：对比申请内容与员工当前权限（含各来源）
- 反馈形式：字段级提示 + 提交按钮置灰，不弹窗
- 系统反馈：在权限选择区标记"已拥有"标签，hover 提示"你已通过xx来源获得此权限，无需重复申请"
- 用户下一步：返回列表选择其他权限

### EX-08 治理模式冲突

- 发生时机：管理员尝试开启自助申请时
- 触发条件：当前已开启的治理模式与自助申请不兼容
- 判断依据：按治理模式共存矩阵检查。推荐方案：自助申请与双管理员互审不兼容，与子管理员和权限变更审批兼容
- 反馈形式：页面内提示 + 开启按钮置灰，不弹窗
- 系统反馈：在开启按钮附近展示冲突提示——"当前已开启'双管理员互审'模式，与自助申请不兼容。如需开启自助申请，请先关闭双管理员互审模式。"
- 用户下一步：前往关闭冲突模式或放弃开启

## §8 待确认问题

以下问题来自 UXB §9，标注了体验蓝图阶段的处理方式和影响。

### 层级一：影响主方案成立

| # | UXB 问题 | 体验蓝图处理方式 | 如果答案相反的影响 |
|---|---|---|---|
| G-01 | 自助申请与权限变更审批模式关系 | **基于推荐方案推进：假定二者独立并行。** 自助申请有自己的审批通道（在 OA 审批中台创建独立的审批表单/流程），不依赖权限变更审批模式 | 若实际为"依赖"关系：管理端配置流程需要调整为"先确保权限变更审批模式已开启→再配置自助申请审批"。P1 页面需要增加前置检查逻辑 |
| G-02 | 可申请范围的业务粒度 | **基于推荐方案推进：按角色定义。** 管理员以角色为粒度勾选可申请范围，员工端以角色卡片形式浏览和选择。每个角色附带功能权限摘要 | 若实际为"按功能权限"：P3 申请页需要从角色卡片布局改为功能树或功能列表布局，信息密度和认知负担大幅增加 |
| G-03 | 四种治理模式共存矩阵 | **基于推荐方案推进：自助申请与双管理员互审互斥，与其余兼容。** 开启时如检测到双管理员互审已开启则阻止 | 若实际共存矩阵不同：P1 的冲突检测逻辑和提示文案需要调整 |

### 层级二：影响局部体验设计

| # | UXB 问题 | 体验蓝图处理方式 | 影响 |
|---|---|---|---|
| G-04 | 关闭时审批中申请策略 | **基于推荐方案推进：允许关闭，审批中的继续走完。** EX-05 和 P1 关闭确认弹窗按此设计 | 若需要阻止关闭或批量取消：EX-05 分支逻辑和关闭确认文案需重写 |
| G-05 | 自动授权失败处理 | **已设计：管理员告警 + 手动处理入口。** 见 EX-04 和 P5 授权失败态 | 若改为自动重试机制：EX-04 员工侧文案从"管理员正在处理"改为"系统正在重试" |
| G-06 | 审批人所需申请人信息 | **基于推荐方案：展示申请人基本信息+角色包含功能详情。** 暂不展示申请人已有权限列表（避免信息过载），后续可补充 | 若需展示已有权限：P4 权限信息卡片需增加"申请人已有权限"对比区 |

| G-08 | 被拒后重新申请冷却期 | **基于推荐方案：无冷却期。** S-04 员工可直接重新提交 | 若增加冷却期：S-04 流程需增加时间判断和倒计时展示 |
