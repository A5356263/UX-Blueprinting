# 体验蓝图：员工自助权限申请

> 生成时间：2026-07-07 / 链式模式 / 基于 UXB 定案 + 旅程分析

---

## §0 本次关键设计判断

**判断：** 管理端配置页采用单页长表单 + 锚点导航，不拆步骤条。员工申请采用 Drawer 内单页表单 + 提交前摘要预览。

**主要影响：** 管理端配置涉及"可申请范围 → 审批流程 → 开关"三项，不存在强步骤依赖——管理员可能先看审批流程再决定范围，或先开关再调整。员工申请是轻量选择 + 填写原因，不需要分步引导。

**建议方案：** 管理端用单页三分区（范围配置 / 审批绑定 / 开关与状态），顶部锚点导航 + 保存按钮固定底部。员工申请 Drawer 内平铺：选择权限区 + 原因填写区 + 底部提交区，提交前弹出摘要确认。

**不建议方案：** 不用步骤条把管理端拆成"下一步→下一步→完成"——这会让管理员在调整配置时必须线性重走全部步骤，违反灵活与效率原则。不在员工申请中加"申请引导页"——员工已经知道自己要申请什么，额外引导页是摩擦。

**关键待确认：** 可申请范围如果最终采用功能点粒度而非角色粒度，管理端配置区需要从"角色勾选"改为"功能树勾选"，信息密度和操作复杂度会显著上升。

## §1 旅程消费摘要

本节从 journey-analysis 产出中提取三类信息，驱动后续设计决策。

### 信心最低点 → 异常流程优先级

| 来源角色 | 阶段 | 信心度 | 蓝图落点 |
|---|---|---|---|
| 员工 | 等待审批结果 | 低 | §5 异常：审批超时、审批人异常、在途申请被关闭 |
| 员工 | 感知权限缺口 | 低 | §6 P1 我的权限页：空状态 + 引导入口 |
| 管理员 | 调整或关闭 | 低 | §5 异常：关闭前影响评估与在途处理 |
| 审批人 | 审查申请内容 | 中 | §6 P6 审批详情页：已有权限与申请权限并排展示 |

### 关键转折 → 前置说明

| 来源角色 | 转折 | 蓝图落点 |
|---|---|---|
| 员工 | 查看已有 → 提交申请 | §3 主流程：提交前展示"申请摘要预览" |
| 员工 | 提交申请 → 等待审批 | §3 主流程：提交成功后告知"预计处理时效 + 不需要做什么" |
| 管理员 | 配置 → 开启 | §3 主流程：开启前校验"范围+审批"是否已配置 |
| 管理员 | 评估 → 配置 | §6 P4：页面顶部展示"自助申请运转流程图 + 开启前检查清单" |

### 流失风险 → 引导策略

| 来源角色 | 阶段 | 风险 | 蓝图落点 |
|---|---|---|---|
| 员工 | 等待审批结果 | 等待超时→线下催办→链路断裂 | §6 P3：状态详情展示处理进度（已送达/已查看/处理中） |
| 员工 | 权限生效与确认 | 被拒后原因不明确→放弃通道 | §5 异常：拒绝原因结构化 + 下一步引导 |
| 审批人 | 审查申请内容 | 信息不足→保守拒绝 | §6 P6：审批页"批准前后差异对比" |
| 管理员 | 评估是否开启 | 风险不明→不开启 | §6 P4：开启前影响评估 + 灰度开启建议 |

## §2 交互流程总览

### 路径清单

- **主路径 MP1：** 员工提交权限申请（我的权限 → 申请权限 Drawer → 提交确认 → 申请记录）
- **主路径 MP2：** 审批人处理申请（待办列表 → 审批详情页 → 通过/拒绝）
- **主路径 MP3：** 管理员开启自助申请（配置页 → 三步配置 → 开启）
- **次路径 SP1：** 员工重新提交被拒申请
- **次路径 SP2：** 管理员调整配置（修改范围/更换审批流程）
- **次路径 SP3：** 管理员关闭自助申请能力
- **次路径 SP4：** 员工查看申请记录与状态详情
- **异常路径 EP1：** 提交时校验失败（未选权限/原因过短/已有权限/不在范围）
- **异常路径 EP2：** 审批超时
- **异常路径 EP3：** 审批人不存在或不可达
- **异常路径 EP4：** 管理员关闭能力时存在在途申请
- **异常路径 EP5：** 自动授权失败
- **异常路径 EP6：** 可申请范围变更影响在途申请

### 主路径 MP1：员工提交权限申请

```
我的权限 Page
→ 查看已有权限列表
→ 点击 [申请权限]
→ 打开 申请权限 Drawer
→ 展示可申请权限列表（按角色聚合）
→ 选择一项或多项权限
→ 输入申请原因
→ 点击 [提交申请]
→ 弹出 提交确认 Modal：申请摘要预览
→ 点击 [确认提交]
→ 校验：所选权限在可申请范围内且未重复
→ Drawer 关闭
→ Toast：申请已提交，预计 {X} 小时内处理
→ 申请记录列表新增一条"审批中"记录

分支：
- 未选择任何权限 → [提交申请] 置灰
- 申请原因不足（少于 {N} 字）→ 原因输入区下方 InlineError："请至少输入 {N} 字说明申请原因"
- 所选权限已有有效申请 → InlineError："你已有该权限的审批中或已生效申请"
- 审批流程未配置 → 提交失败 Toast："审批流程异常，请联系管理员"
```

### 主路径 MP2：审批人处理申请

```
待办列表 / 消息通知
→ 点击某条权限申请
→ 打开 审批详情 Page
→ 查看：申请人信息 + 已有权限全貌 + 本次申请权限 + 申请原因
→ 审查"批准前后差异对比"
→ 点击 [通过] 或 [拒绝]
  → 通过：弹出确认 Modal"通过后系统将自动授权，预计 {X} 内生效"
  → 拒绝：弹出拒绝原因 Modal，选择结构化原因 + 可选补充
→ 确认操作
→ Toast：操作成功，已通知申请人
→ 返回待办列表

分支：
- 拒绝时不选原因 → [确认拒绝] 置灰
- 审批人点击通过但自动授权接口异常 → Toast 提示异常但不阻断审批结果，后台记录待补偿
```

### 主路径 MP3：管理员开启自助申请

```
权限管理模式 Page
→ 在模式卡片中选择"员工自助申请权限"
→ 打开 自助申请配置 Page
→ 查看页面顶部流程说明 + 检查清单
→ 配置区1：选择可申请范围（按角色勾选）
→ 配置区2：绑定审批流程（从已有审批流程中选择）
→ 配置区3：查看配置摘要
→ 点击 [开启自助申请]
→ 校验：范围和审批流程均已配置
→ 能力生效
→ Toast：员工自助申请权限已开启
→ 页面状态区更新为"运行中"

分支：
- 未配置范围 → [开启] 置灰，范围区提示"请先配置可申请范围"
- 未配置审批流程 → [开启] 置灰，审批区提示"请先绑定审批流程"
- 与现有治理模式冲突 → 弹出冲突提示 Modal，列出互斥模式，需先关闭
```

## §3 主交互流程

### MP1：员工提交权限申请

#### 节点 1-1：进入我的权限页

**用户动作**
员工从工作台或导航进入"我的权限"页面。

**系统反馈**
- 加载态：骨架屏或加载指示器，展示权限列表占位
- 正常态：按应用分组的权限列表，每项标注权限来源和生效状态
- 空状态：如果员工无任何权限，展示空状态 + 引导文案

**需要前置解释的信息**
- 权限分为"管理员授予"和"自行申请获得"两种来源，来源标注帮助员工理解权限的来路
- 如果自助申请能力未开启，"申请权限"入口隐藏

**建议文案**
- 空状态标题："暂无权限记录"
- 空状态说明："你当前没有任何应用权限。如需获取权限，请联系管理员。"
- 有可申请范围时补充："或点击下方'申请权限'自行申请。"

**下一步**
- 点击 [申请权限] → 节点 1-2
- 点击某条已有权限 → 展开权限详情（来源、范围、生效时间）

#### 节点 1-2：选择权限并填写申请

**用户动作**
在申请权限 Drawer 中，浏览可申请权限列表，选择一项或多项，输入申请原因。

**系统反馈**
- 权限列表按角色聚合展示，每个角色附带"包含X项功能权限"的能力摘要
- 选中某项后，该行高亮并展示勾选标记
- 已拥有或已有在途申请的权限置灰 + 标签说明
- 申请原因输入框下方显示字数计数

**需要前置解释的信息**
- 每个可申请项展示的不是技术命名，而是"角色名 + 包含能力摘要"
- Drawer 顶部展示："以下为当前可申请的权限范围，申请提交后将进入审批流程"

**建议文案**
- 权限项格式："{角色名}：包含 {能力列举}，适用于 {使用场景}"
- 原因输入框 placeholder："请说明申请原因，如：因XX项目需要，需使用XX功能进行XX操作"
- 字数不足 InlineError："申请原因至少需要 {N} 字，帮助审批人了解你的使用场景"
- 已有权限标签："已拥有"
- 在途申请标签："审批中"

**下一步**
- 点击 [提交申请] → 节点 1-3
- 点击 [取消] 或 Drawer 外部区域 → Drawer 关闭，已填信息不保留

#### 节点 1-3：确认提交

**用户动作**
在提交确认 Modal 中查看申请摘要，确认无误后提交。

**系统反馈**
- Modal 展示：申请权限列表、审批人姓名、预计处理时效
- 点击 [确认提交] 后，校验通过则 Drawer 关闭，Toast 出现
- 校验失败则在 Drawer 内展示对应错误

**需要前置解释的信息**
- 预计处理时效基于管理端配置和历史数据推算
- 明确告知"提交后无需再联系管理员或审批人"

**建议文案**
- Modal 标题："确认提交申请"
- 摘要格式："你正在申请 {N} 项权限，将提交至 {审批人姓名} 审批，预计 {X} 小时内处理。"
- 提交成功 Toast："申请已提交，预计 {X} 小时内处理，请在'申请记录'中查看进度。"
- 补充说明："无需联系管理员或审批人，审批结果将通过消息通知你。"

**下一步**
- Toast 出现后 3 秒自动消失 → 回到我的权限页
- 点击 Toast 中的 [查看进度] → 进入申请记录页

### MP2：审批人处理申请

#### 节点 2-1：查看申请详情

**用户动作**
从待办列表或消息通知进入审批详情页。

**系统反馈**
- 页面分三个信息区：
  - 申请人信息区：姓名、部门、岗位
  - 权限差异对比区：左侧"当前已有权限"、右侧"本次申请新增权限"、中间标注差异
  - 申请原因区：员工填写的申请原因正文

**需要前置解释的信息**
- "本次申请新增权限"每项附带能力说明，避免审批人看到技术命名无法判断
- 如果申请人所在部门其他同事普遍拥有该权限，可展示参考信息

**建议文案**
- 权限差异标题："批准后，该员工将新增以下能力："
- 能力说明格式："{权限名}：可以使用 {功能列举}"
- 参考信息："该员工所在部门共 {N} 人，其中 {M} 人已拥有此权限。"

**下一步**
- 点击 [通过] → 节点 2-2
- 点击 [拒绝] → 节点 2-3

#### 节点 2-2：通过申请

**用户动作**
点击 [通过]，在确认 Modal 中确认操作。

**系统反馈**
- Modal 展示：操作后果说明 + 自动授权说明
- 确认后 Toast 出现，自动授权在后台执行

**建议文案**
- Modal 标题："确认通过申请"
- Modal 正文："通过后，系统将自动为 {员工姓名} 授予所选权限，预计 {X} 内生效。结果将通过消息通知申请人。"
- Toast："已通过 {员工姓名} 的权限申请，系统正在自动授权。"

**下一步**
- 返回待办列表或上一页

#### 节点 2-3：拒绝申请

**用户动作**
点击 [拒绝]，在拒绝原因 Modal 中选择原因。

**系统反馈**
- Modal 展示结构化原因选项 + 可选文字补充
- 至少选择一个原因后 [确认拒绝] 才可点击

**建议文案**
- Modal 标题："拒绝申请"
- 原因选项：
  - "权限申请超出必要范围"
  - "申请理由不充分，建议补充信息后重新提交"
  - "该权限不适合当前岗位"
  - "其他原因"
- Toast："已拒绝 {员工姓名} 的权限申请，结果已通知申请人。"

**下一步**
- 返回待办列表或上一页

### MP3：管理员开启自助申请

#### 节点 3-1：进入配置页

**用户动作**
从权限管理模式页选择"员工自助申请权限"卡片，进入配置页。

**系统反馈**
- 页面顶部展示自助申请运转流程图（简化的角色交互示意）
- 流程图下方展示"开启前检查清单"：范围已配置 / 审批流程已绑定 / 无治理模式冲突

**需要前置解释的信息**
- 开启后员工即可在工作台或权限相关入口看到"申请权限"入口
- 可在开启后随时调整配置或关闭

**建议文案**
- 检查清单标题："开启前请确认"
- 清单每一项："□ 已配置可申请范围 / □ 已绑定审批流程 / □ 当前无互斥的治理模式"

**下一步**
- 进入配置区域 → 节点 3-2

#### 节点 3-2：配置可申请范围与审批流程

**用户动作**
在配置页的三个分区中依次操作。

**系统反馈**
- 分区1"可申请范围"：按角色勾选列表，每项显示角色名 + 包含权限数
- 分区2"审批流程"：从已有审批流程下拉选择，或点击 [新建审批流程] 跳转审批管理
- 分区3"配置摘要"：实时汇总已选范围 + 已绑审批流程

**需要前置解释的信息**
- 选择某个角色后，该角色下所有员工均可申请此角色对应的权限
- 审批流程需提前在审批管理中创建

**建议文案**
- 范围分区标题："可申请范围" + 说明："员工将能够申请以下角色对应的权限"
- 范围空状态："尚未选择任何角色，请至少选择一个角色"
- 审批分区标题："审批流程" + 说明："员工提交申请后将按此流程审批"
- 审批未配置："尚未绑定审批流程，请选择已有审批流程或新建"

**下一步**
- 点击 [开启自助申请] → 节点 3-3

#### 节点 3-3：开启确认

**用户动作**
点击 [开启自助申请]，确认操作。

**系统反馈**
- 校验范围和审批均已配置
- 校验无互斥的治理模式
- 校验通过后，开关切换为"已开启"，页面状态更新

**建议文案**
- 开启确认："开启后，员工即可在工作台和权限页面看到申请入口。确定开启？"
- 校验失败提示（范围未配置）："请先配置可申请范围"
- 校验失败提示（审批未配置）："请先绑定审批流程"
- 冲突提示："当前已开启 {模式名}，与员工自助申请互斥。请先关闭 {模式名} 后再开启。"
- 开启成功 Toast："员工自助申请权限已开启"

**下一步**
- 页面保持配置页，状态区更新为"运行中"，展示运行数据入口

## §4 次交互流程

### SP1：员工重新提交被拒申请

**触发条件**
员工在申请记录中看到"已拒绝"状态的申请，点击 [重新提交]。

**用户动作**
- 点击 [重新提交] 后，打开申请权限 Drawer，自动填入上次选择的权限和原因
- 员工修改原因或调整权限选择后重新提交

**系统反馈**
- Drawer 顶部展示上次拒绝原因："上次拒绝原因：{原因}。修改后重新提交。"
- 提交流程同主路径 MP1

**建议文案**
- 拒绝原因展示："审批人意见：{结构化原因 + 补充说明}"
- 重新提交引导："建议根据审批人意见调整申请原因后重新提交"

**下一步**
同 MP1 节点 1-3

### SP2：管理员调整配置

**触发条件**
管理员在自助申请运行期间修改可申请范围或更换审批流程。

**用户动作**
- 在配置页修改范围勾选或更换审批流程
- 点击 [保存配置]

**系统反馈**
- 保存前展示影响评估：当前在途申请数、变更后的影响
- 根据在途申请处理策略（待产品确认）告知变化

**需要前置解释的信息**
- 范围变更对在途申请的影响取决于产品策略，目前按"在途申请按提交时的范围判断"推进

**建议文案**
- 变更前提示："当前有 {N} 项在途申请，配置变更不会影响已提交的申请。"
- 保存成功 Toast："配置已更新"

**下一步**
回到配置页，查看更新后的配置摘要

### SP3：管理员关闭自助申请能力

**触发条件**

- 确认后开关切换为"已关闭"，员工端入口隐藏

**建议文案**
- Modal 标题："确认关闭员工自助申请"
- 影响评估："当前有 {N} 项在途申请。关闭后，员工将无法提交新申请。已提交的申请将按预设策略处理：{策略说明}。"
- 关闭成功 Toast："员工自助申请权限已关闭。员工端申请入口已隐藏。"
- 补充说明："关闭后历史申请记录保留可查，可随时重新开启。"

**下一步**
回到配置页，状态区更新为"已关闭"

### SP4：员工查看申请记录与状态详情

## §5 异常与阻断流程

### EP1：提交时校验失败

**发生时机**
员工在申请权限 Drawer 中点击 [提交申请] 时。

**触发条件**
- 未选择任何权限
- 申请原因少于最低字数要求
- 所选权限已有审批中或已生效的申请
- 所选权限超出当前可申请范围（如管理员在员工填写期间缩小了范围）

**判断依据**
UXB §5 业务规则：申请范围校验、已有权限去重；旅程分析：员工"提交权限申请"阶段信心度为中

**反馈形式**
- 未选权限：[提交申请] 按钮置灰，hover 提示
- 原因不足：原因输入区下方 InlineError
- 已有权限：对应权限行 InlineError + Toast
- 范围变更：Drawer 内全局 Banner 提示

**系统反馈**
- InlineError 在修正后即时消失
- 范围变更提示保持可见直到员工关闭 Drawer

**建议文案**
- 未选权限 hover："请至少选择一项权限"
- 原因不足 InlineError："申请原因至少 {N} 字，帮助审批人理解你的使用场景"
- 已有权限："你已拥有该权限的有效申请，无需重复提交"
- 范围变更 Banner："可申请范围已更新，部分权限可能不再可申请。请重新选择。"

**用户下一步**
- 原因不足：补充原因后重新点击提交
- 已有权限：取消该权限的选择
- 范围变更：重新查看可选列表，重新选择

**恢复路径**
原路恢复，已填信息不丢失（除非范围变更导致已选权限被移除）

### EP2：审批超时

**发生时机**
申请提交后，超过预设审批时效仍未处理。

**触发条件**
申请状态为"审批中"且超过管理端配置的处理时限。

**判断依据**
UXB §6 异常：审批链路未配置/审批人异常；旅程分析：员工"等待审批结果"信心度为低，等待超时是最高流失风险

**反馈形式**
- 员工侧：申请记录中该条目标注"已超时"标签；可选 [催办]
- 审批人侧：待办列表中该条目高亮或置顶 + 超时标记
- 管理员侧：运行状态页展示超时积压告警

**系统反馈**
- 自动向审批人发送催办提醒
- 通知员工"系统已自动催办"

**建议文案**
- 员工侧状态："已超时 · 系统已于 {时间} 自动催办"
- 催办按钮："催办"
- 催办后 Toast："已向审批人发送催办提醒"
- 审批人侧提醒："{员工姓名} 的权限申请已等待 {X} 小时，请尽快处理"

**用户下一步**
- 员工：等待或点击催办
- 审批人：处理超时申请
- 管理员：关注积压趋势，必要时手动转交

**恢复路径**
审批人处理后恢复正常流转，员工无数据丢失

### EP3：审批人不存在或不可达

**发生时机**
申请进入审批流程时，审批人已离职、停用或被移除。

**触发条件**
审批人账号状态为离职/停用，或审批人角色被清空。

**判断依据**
UXB §6 异常：审批人账号异常；旅程分析：员工"等待审批结果"阶段痛点

**反馈形式**
- 员工侧：无需感知具体审批人异常，状态保持"审批中" + 提示"审批处理中"
- 管理员侧：运行状态页红色告警 + 消息通知

**系统反馈**
- 系统检测到审批人不可达后，自动标记申请为"待转交"
- 通知管理员"审批人 {姓名} 不可达，{N} 项申请需要重新分配审批人"

**建议文案**
- 管理员通知："审批人 {姓名} 已离职/停用，{N} 项权限申请无法继续流转。请进入审批管理重新分配审批人或调整审批流程。"
- 告警标记："审批人异常"

**用户下一步**
- 管理员进入审批管理重新分配审批人或调整审批流程
- 员工继续等待（无需额外操作）

**恢复路径**
管理员完成审批人重新分配后，在途申请自动恢复流转。员工侧无信息丢失。

### EP4：管理员关闭能力时存在在途申请

**发生时机**
管理员点击 [关闭自助申请] 时。

**触发条件**
当前存在状态为"审批中"的申请。

**判断依据**
UXB §6 异常：能力已关闭；UXB §9 层级一 GAP（当前按推荐方案推进）

**反馈形式**
关闭确认 Modal 中展示影响评估，不能跳过。

**系统反馈**
- Modal 中不可隐藏地展示在途申请数量和预设处理策略
- 确认关闭后，按预设策略执行（当前推荐方案：允许在途申请走完，但不接受新申请）

**建议文案**
- Modal 正文："当前有 {N} 项在途申请涉及 {M} 名员工。关闭后，已提交的申请将继续走完审批流程，但不再接受新的申请。"
- 关闭后员工端提示（如果有人尝试进入）："员工自助申请暂未开放，如需获取权限请联系管理员。"

**用户下一步**
- 管理员：确认关闭或取消
- 员工（在途）：继续等待审批结果，不受影响
- 员工（新申请）：入口隐藏，无法提交

**恢复路径**
管理员关闭后，在途申请继续自然流转完成。历史记录保留可查。

### EP5：自动授权失败

**发生时机**
审批人通过申请后，系统执行自动授权时。

**触发条件**
权限引擎接口异常、权限数据冲突、网络超时等。

**判断依据**
UXB §5 业务规则：自动授权失败补偿；旅程分析：审批人"做出审批决策"阶段痛点

**反馈形式**
- 审批人侧：通过操作成功但附带异常提示
- 管理员侧：运行状态页告警 + 消息通知
- 员工侧：申请状态显示"已通过（授权处理中）"

**系统反馈**
- 审批结果正常生效（通过），但授权动作标记为"待补偿"
- 通知管理员"自动授权失败，需人工介入"

**建议文案**
- 审批人 Toast："已通过申请。授权执行中遇到延迟，系统将自动重试。"
- 管理员通知："{员工姓名} 的权限申请已审批通过，但自动授权失败。请进入用户授权页手动完成授权。失败原因：{技术原因转译，如'权限服务暂时不可用'}。"
- 员工侧状态："已通过 · 授权处理中，请稍后验证"

**用户下一步**
- 管理员：进入用户授权页手动授权
- 员工：稍后刷新验证权限是否生效

**恢复路径**
管理员手动授权后权限生效，员工验证通过。如果系统自动重试成功，无需管理员介入。

### EP6：可申请范围变更影响在途申请

**发生时机**
管理员在员工提交申请后、审批完成前修改了可申请范围。

**触发条件**
管理员缩小了可申请范围，导致已在途的申请中的权限不再属于可申请范围。

**判断依据**
UXB §6 异常：范围变更导致在途申请越界；UXB §9 层级二 GAP

**反馈形式**
- 按推荐方案推进：在途申请按提交时的范围判断，不受影响
- 范围变更保存时提示管理员"当前有 N 项在途申请按旧范围执行"

**建议文案**
- 管理员保存时提示："配置已保存。当前 {N} 项在途申请将按提交时的范围继续执行。"
- 不影响员工和审批人侧体验

**用户下一步**
管理员：确认保存；员工和审批人：不受影响

**恢复路径**
在途申请自然流转，无需额外恢复

## §7 状态与反馈文案

### 统一状态口径

| 状态 | 含义 | 适用对象 | 用户可操作 | 统一反馈口径 |
|---|---|---|---|---|
| 待提交 | 员工已选择权限但未提交 | 员工 | 编辑、提交 | 申请尚未提交 |
| 审批中 | 申请已提交，等待审批人处理 | 员工 / 审批人 / 管理员 | 员工：催办、查看进度；审批人：处理；管理员：监控 | 等待审批人处理 |
| 已送达审批人 | 审批人已收到申请但尚未查看 | 员工 / 审批人 | 员工：等待；审批人：查看 | {审批人姓名} 已收到申请 |
| 审批人已查看 | 审批人已查看申请内容 | 员工 / 审批人 | 员工：等待；审批人：决策 | {审批人姓名} 已于 {时间} 查看 |
| 超时 | 申请超过预设处理时效 | 员工 / 审批人 / 管理员 | 员工：催办；审批人：优先处理；管理员：转交 | 处理超时，系统已自动催办 |
| 已通过 | 审批人已通过，权限待生效或已生效 | 员工 / 审批人 / 管理员 | 员工：验证生效 | 申请已通过，权限已生效 |
| 已拒绝 | 审批人已拒绝 | 员工 / 审批人 / 管理员 | 员工：查看原因、重新提交 | 申请已拒绝，查看原因后可重新提交 |
| 已生效 | 权限已自动授予并生效 | 员工 / 管理员 | 员工：使用；管理员：查看 | 权限已生效，可正常使用 |
| 已撤销 | 申请被管理员撤销或能力关闭导致作废 | 员工 / 管理员 | 员工：查看原因 | 申请已作废 |
| 待补偿 | 审批通过但自动授权失败 | 管理员 | 管理员：手动授权 | 授权执行异常，需人工介入 |
| 待转交 | 审批人不可达，需重新分配 | 管理员 | 管理员：重新分配审批人 | 审批人异常，需重新分配 |
