# 问题框定：子管理员权限复制能力

## §0 关键判断

- 问题对象明确：企业超管为子管理员配置权限的效率问题
- 目标用户明确：企业超管/主管理员
- 当前替代做法明确：逐一勾选菜单权限 + 数据权限
- 为什么重要明确：来自具体客户诉求，企业规模大时权限分发工作量显著
- 约束明确：不支持跨企业复制、权限模型含菜单权限和数据权限两层、涉及多个子应用

## §1 输入摘要

本产品采用"多个子应用 × 菜单权限 × 数据权限"的权限模型。企业超管需要为子管理员逐项配置权限，当企业规模扩大、子管理员角色增多时，配置工作量线性增长。客户反馈明确提出希望"把现有子管理员的权限直接复制给目标子管理员"，场景是从一个源复制到多个目标，复制后只需微调。

## §2 问题定义

当企业超管需要创建多个职责相似（但非完全相同）的子管理员时，缺乏批量复制权限的能力，只能在每个子应用的菜单权限和数据权限面板中逐一勾选。权限项越多、子应用越多、目标子管理员越多，重复操作成本越高，且逐项勾选容易出错。

核心矛盾：**权限配置的重复性与角色职责任务的相似性不匹配。**

## §3 目标用户与场景

| 角色 | 场景 | 频率 |
|------|------|------|
| 企业超管（主管理员） | 新设子管理员，职责与现有角色基本一致 | 中等，随企业规模增长 |
| 企业超管（主管理员） | 组织架构调整，需要批量变更子管理员权限 | 低，但单次操作量大 |

典型画像：大型企业 IT 管理员或安全管理员，管理 10+ 子管理员账号，覆盖多个子应用。

## §4 当前替代做法

现有做法是在系统后台依次进入每个子应用 → 找到权限配置页 → 找到菜单权限和数据权限 → 逐项勾选 → 保存 → 切换到下一个目标子管理员重复操作。

无其他变通方案。权限模型不支持导入、不支持模板、不支持克隆。

## §5 机会点

1. **配置效率提升**：将 O(n × m) 次勾选（n=权限项数, m=目标人数）降为 O(n) 次确认，这是客户直接诉求。
2. **配置准确性**：减少遗漏或误勾选。逐项勾选时易漏掉某个子应用的部分权限，复制 + 对比可显著降低人为失误。
3. **权限一致性维护**：当同一批角色（如各地分公司运营经理）权限结构相似但不完全相同时，"复制 → 微调"比"从零配"更容易保持结构一致。
4. **新管理员上手效率**：新设子管理员时不需要理解完整的权限结构，直接参考已有角色的配置即可。
5. **后续批量变更潜力**：如果复制能力与权限模板结合，未来可支持批量更新（改模板 → 同步所有关联子管理员）。

## §6 候选方向

### 方向 A：权限复制工具

从源子管理员复制完整权限（全部子应用的菜单权限 + 数据权限）到一或多个目标子管理员，复制后目标可逐项检查和修改。

- 解决的问题：重复配置问题，直接回应客户诉求
- 目标用户价值：一步完成 80% 权限配置，仅需微调差异部分
- 主要风险：复制后如果目标已有权限，合并逻辑需要明确（覆盖/追加/跳过）
- 成立前提：权限模型支持深度复制（包括数据权限的作用域）

### 方向 B：权限模板/角色预设

抽象出"权限模板"概念——将一套权限配置保存为命名模板，子管理员关联模板获得权限。模板变更时可选择是否同步更新关联的子管理员。

- 解决的问题：不仅解决复制问题，还解决权限一致性和批量维护问题
- 目标用户价值：一次定义模板，多次复用；组织变更时改模板即可批量同步
- 主要风险：产品设计复杂度更高（模板管理、版本、同步策略）；可能与现有"角色"概念重叠带来认知混淆
- 成立前提：需要额外的模板生命周期管理，团队对其投入意愿可行

### 方向 C：权限克隆 + 差异编辑流

在复制过程中引入"差异编辑"步骤——选择源 → 选择多个目标 → 系统展示差异对比界面 → 在复制前统一调整各项权限 → 批量应用。源与目标之间的差异部分高亮呈现。

- 解决的问题：不仅复制，还解决"微调"的操作效率
- 目标用户价值：在复制流程中一站完成调整，不需要复制后再逐人修改
- 主要风险：交互流程更复杂，批量编辑多人的差异在大屏上也不易呈现
- 成立前提：产品团队愿意为批量编辑差异投入交互设计资源

## §7 推荐方向与承接要求

### 推荐方向：方向 A（权限复制工具）

**理由：** 方向 A 直接回应客户诉求，实现路径短，风险可控，且不排除后续向方向 B 演进的可能。方向 B/C 的价值更大但前置成本和不确定性更高，建议先解决最痛的"配置效率"问题，用真实反馈验证后再迭代。

### 体验侧关注点

1. **复制范围的可视化**：用户需要清楚看到"将被复制"的完整权限清单，避免黑盒复制造成意料外的权限变更。
2. **合并策略**：目标子管理员已有权限时，是覆盖、追加还是提示选择？推荐默认"追加，冲突时提示"。
3. **复制后的可检查性**：复制完成后应有变更摘要，便于用户确认复制结果是否符合预期。
4. **操作可逆性**：复制操作是否可以回滚？至少应提供操作前后的权限对比。

### 下游必须承接的问题

1. 选择源和目标的方式：列表选择还是拖拽？单源多目标如何选择？
2. "微调"的交互形态：复制后是逐一编辑各目标，还是提供批量差异编辑入口？
3. 权限项太多时的搜索和筛选：复制界面上是否需要在源/目标中搜索特定权限项？
4. 数据权限的复制细节：数据权限的范围（如组织层级、数据可见范围）能否精确复制？
5. 操作记录与审计：复制操作是否需要进入操作日志，供审计追溯？

### 明确不做什么（本轮）

- 不做权限模板（方向 B 暂不进入本轮 scope）
- 不做批量差异编辑 UI（方向 C 暂不进入本轮 scope）
- 不做跨企业权限复制
- 不做权限冲突自动检测（仅提示，由用户决定）

## §8 约束与不做什么

- 权限模型不可变：不因复制功能改变底层权限模型结构
- 不跨企业：复制仅限同一企业内的子管理员
- 角色不变：不新增"角色""模板"等抽象层

## §9 待确认问题

1. **目标子管理员已有权限时，默认行为偏好（覆盖/追加/询问）？** 需要与客户确认。
2. **"微调"的操作预期：是复制后各目标独立编辑，还是期望一次性批量微调？** 当前假设是前者，需进一步验证。
3. **是否需要权限差异对比功能？** 复制前后能看到"哪些项变了"是基本要求，但"复制前先对比差异"的优先级需要确认。
4. **操作可见性：超管复制权限给子管理员后，子管理员是否知晓？** 这涉及通知设计。
