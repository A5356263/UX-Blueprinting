# 需求定案：子管理员支持复制

---

## §0 本次关键判断

这是一项边界清晰的效率型需求——批量配置子管理员时，从已有子管理员复制可授权范围，降低重复勾选成本。

**判断**：子管理员复制与用户授权页的权限复制是两套独立能力，入口不同、语义不同，不应合并。

**主要影响**：子管理员模式列表页的新增操作、复制弹窗交互、批量校验与结果反馈。

**建议方案**：在子管理员模式列表的操作列新增"复制"，弹窗内选择复制内容（可授权组织/可授权功能）和目标用户，按固定顺序校验后执行，支持叠加逻辑和操作记录。

**不建议方案**：将本能力与用户授权页的权限复制合并为统一入口——两者的对象语义（管理范围 vs 实际权限）不同，合并会引入认知混淆。

**关键待确认**：叠加逻辑中"不覆盖"在具体配置项冲突时的处理规则。

---

## §1 需求输入摘要

### 需求背景

集团型企业（如广西交投 200+ 子管理员）的子管理员"可授权功能"通常一致，"可授权组织"不同。当前逐个子管理员单独配置，实施工作量大。

### 目标用户

- 主操作者：权限管理员 / 超级管理员
- 被复制来源：已有子管理员
- 复制目标：普通用户或已有子管理员

### 业务目标

- 支持复制可授权组织和可授权功能
- 支持批量复制给多个用户（上限 200）
- 支持普通用户快速成为子管理员
- 支持对已有子管理员叠加授权范围
- 记录复制操作，支持审计追溯
- 开启双管理员互审时生成审批

### 功能范围

- 子管理员模式列表 → 操作列新增"复制"入口
- 复制弹窗：复制信息（可授权组织/可授权功能）→ 复制对象（员工选择器）→ 校验 → 执行
- toast 提示"复制成功"
- 生成操作记录
- 双管理员互审模式下生成审批

### 已明确的约束

[FACT] 复制入口仅出现在子管理员模式列表
[FACT] 来源必须是已有子管理员
[FACT] 复制信息至少选择一项
[FACT] 复制对象至少选择一名用户（上限 200）
[FACT] 复制对象必须已加入 + 已认证
[FACT] 已有子管理员接收复制采用叠加逻辑，不覆盖
[FACT] 普通用户接收复制后成为子管理员
[FACT] 复制成功必须生成操作记录
[FACT] 开启双管理员互审时需生成审批

### PRD 缺口

[GAP] 叠加逻辑中，源和目标对同一配置项冲突时的具体处理规则未定义
[GAP] 批量操作中部分目标校验不通过时，是否支持跳过不合规目标继续处理合规目标
[GAP] 普通用户→子管理员的身份转变是否需要二次确认
[GAP] 双管理员互审模式下，审批通过前复制是否暂不生效

## §2 业务场景判断

**业务定位**：子管理员模式下的一项效率型补充能力。不改变子管理员模式的业务模型、治理规则和生效机制，只在现有"子管理员"对象上新增复制操作。

**与现有能力的关系**：
- 子管理员模式列表已具有"添加子管理员"、"编辑"、"移除"等操作。复制操作天然补充在操作列中。
- 与用户授权页的"复制权限"是两套独立能力——前者复制管理范围（可授权组织/可授权功能），后者复制业务权限（菜单权限/数据权限）。

**最大业务不确定性**：
叠加逻辑中"不覆盖"的具体行为——当源和目标对同一功能配置不同时，"不覆盖"保留目标原有值，但源的值不写入，这可能与操作者的预期不一致。

**判断错误的影响**：
如果把子管理员复制错误地定位为用户授权复制的一部分，会导致：
1. 入口混淆，操作者走错入口
2. 两个不同语义的"复制"在同一个页面上造成认知冲突
3. 状态模型混用导致数据和权限异常

---

## §3 需求成立性判断

**收益**：
- 直接降低大客户实施阶段的人工成本
- 200+ 子管理员的场景下效率提升显著
- 叠加逻辑减少了误操作风险（不覆盖已有配置）
- 操作记录和互审机制保证了安全底线

**代价**：
- 需要处理批量场景下的校验和异常反馈
- 叠加逻辑需要明确定义冲突处理规则，否则可能引发预期偏差
- 互审模式下审批流与复制操作的衔接增加实现复杂度

**更低成本替代方案**：
已考虑过"可授权功能模板"方案——即预定义一套功能模板，批量应用到子管理员。但该方案需要新增"模板"概念和管理界面，实现成本更高。当前"从已有子管理员复制"的方案更轻量，且与子管理员模式的既有交互一致。

**结论**：建议进入正式体验设计。

## §4 推荐业务边界

### 推荐能力形态

1. 从已有子管理员复制"可授权组织"和/或"可授权功能"到多个目标
2. 目标上限 200 个
3. 对已有子管理员叠加（不覆盖）
4. 对普通用户自动晋升为子管理员
5. 按固定顺序校验：复制信息 → 复制对象 → 加入状态 → 认证状态
6. 操作记录按可授权组织和可授权功能分条记录
7. 互审模式下进入审批流

### 不推荐能力形态

1. 不深入到子管理员的实际业务权限（菜单权限/数据权限）——那是用户授权页的职责
2. 不新增"模板"抽象层——复制已足够满足当前场景
3. 不做跨管理员类型的权限转移——只复制，不转移

### 与现有能力的边界

- 子管理员模式列表的操作列新增"复制"（知识库中该能力已被预留）
- 员工选择器复用"添加子管理员"弹窗的选择器
- 操作记录复用现有操作记录能力
- 互审模式复用现有审批流

## §5 角色、功能、规则范围

### 角色职责

| 角色 | 职责 |
|------|------|
| 权限管理员 / 超级管理员 | 执行复制操作，选择复制内容和目标 |
| 已有子管理员（来源） | 作为复制来源，提供可授权组织/可授权功能的配置 |
| 普通用户（目标） | 接收复制的管理范围，成为子管理员 |
| 已有子管理员（目标） | 在其现有配置基础上叠加复制的管理范围 |

### 功能范围

| 功能 | 输入 | 处理 | 输出/结果 |
|------|------|------|-----------|
| 复制入口 | 子管理员模式列表的某行 | 点击"复制" | 打开复制弹窗 |
| 复制信息选择 | 可授权组织/可授权功能（默认全选） | 至少勾选一项 | 选定复制内容 |
| 复制对象选择 | 员工选择器中选择 1-200 名用户 | 确认选择 | 选定目标清单 |
| 校验 | 复制信息、复制对象、成员状态 | 按顺序校验 | 通过→执行；失败→报错提示 |
| 执行复制 | 选定的复制内容和目标 | 逐目标执行叠加/晋升 | 新增操作记录 + toast |
| 操作记录 | 复制成功事件 | 按可授权组织和功能的粒度记录 | 操作记录已生成 |
| 互审审批 | 开启互审模式下的复制操作 | 生成审批实例 | 审批流转 |

### 关键业务规则

| 规则 | 触发条件 | 处理结果 | 不满足时 |
|------|---------|---------|---------|
| 复制信息必选 | 点击确认时 | 正常执行 | 提示"请选择复制信息" |
| 复制对象必选 | 点击确认时 | 正常执行 | 提示"请选择至少一名复制对象" |
| 目标上限 | 选择目标时 | 正常选择 | 超过 200 名时阻止继续添加 |
| 加入状态校验 | 确认时 | 通过→下一步 | 提示具体哪些目标未加入 |
| 认证状态校验 | 确认时 | 通过→执行复制 | 提示具体哪些目标未认证 |
| 叠加逻辑 | 目标原是子管理员 | 叠加，不覆盖 | — |
| 身份晋升 | 目标原是普通用户 | 成为子管理员 | — |
| 操作记录 | 复制成功 | 生成记录 | — |
| 互审审批 | 互审模式开启 | 生成审批 | 复制不立即生效 |

## §6 状态、异常与边界

### 核心状态

| 状态 | 说明 | 用户下一步 |
|------|------|-----------|
| 待配置 | 已打开复制弹窗，未操作 | 选择复制信息和目标 |
| 已确认待校验 | 已点击确认，系统正在校验 | 等待校验结果 |
| 校验不通过 | 校验发现不合规项 | 查看失败原因，修正后重试 |
| 校验通过 | 校验全部通过（非互审模式） | 自动执行复制 |
| 待审批（互审模式） | 校验通过，等待互审审批 | 等待审批结果 |
| 复制执行中 | 批量复制正在处理 | 等待处理完成 |
| 复制完成 | 全部目标处理成功 | 查看结果 |
| 部分完成 | 部分目标处理失败 | 查看失败明细，可重试 |
| 复制失败 | 全部目标处理失败 | 查看原因，修正后重试 |

### 异常清单

| 异常 | 触发条件 | 系统处理结果 | 用户下一步 |
|------|---------|-------------|-----------|
| 复制信息未选择 | 点击确认时复制信息为空 | 阻断，提示"请选择复制信息" | 勾选后重新确认 |
| 复制对象未选择 | 点击确认时目标为空 | 阻断，提示"请选择至少一名复制对象" | 选择后重新确认 |
| 目标未加入 | 目标中有成员的加入状态不是已加入 | 阻断，提示具体哪些目标未加入 | 移除不合规目标或调整状态后重试 |
| 目标未认证 | 目标中有成员未完成实名认证 | 阻断，提示具体哪些目标未认证 | 移除不合规目标或完成认证后重试 |
| 部分目标处理失败 | 复制执行中部分目标异常 | 标记失败目标，继续处理剩余 | 查看失败明细，重试失败项 |
| 全部目标处理失败 | 复制执行中全部目标异常 | 返回失败结果 | 查看原因，修正后重试 |
| 互审审批被拒绝 | 审批人拒绝该复制操作 | 复制不生效，记录审批结果 | 查看拒绝原因，调整后重新发起 |
| 来源子管理员被删除 | 打开弹窗后来源被删除 | 校验失败，弹窗关闭 | 重新选择来源 |

## §7 体验蓝图承接要求

| 业务判断 | 对体验设计的影响 | 下游必须承接的问题 | 禁止下游重判 |
|---------|----------------|-------------------|-------------|
| 复制入口在子管理员模式列表操作列 | 操作列已有"功能权限""数据权限""编辑""移除"，"复制"作为新增项需考虑排序 | 复制按钮的展示位置和置灰条件 | 禁止改为其他入口 |
| 复制信息支持分开勾选 | 弹窗中需要两个独立选项，且至少选一项 | 默认全选的设计、必选校验的反馈 | 禁止改为单选或固定全选 |
| 叠加逻辑（不覆盖） | 叠加后用户需要知道最终结果 | 操作前是否需要展示叠加预览；操作后是否需要展示变更摘要 | 禁止改为"覆盖"逻辑 |
| 普通用户→子管理员 | 身份转变是一个重要跃迁，操作者需要感知 | 确认环节是否需要额外提示"该用户将获得管理权限" | 禁止不提示直接执行 |
| 批量处理（上限 200） | 批量操作需要进度反馈和结果汇总 | 大量目标时的产物反馈设计 | 禁止使用单条提示替代批量结果 |
| 校验顺序固定 | 用户可能先看到"复制对象未选择"之类的问题 | 如何在不打断用户心流的前提下展示多项校验错误 | 禁止乱序校验 |
| 操作记录按组织/功能分条 | 记录详情需要清晰展示源和目标 | 操作记录中"详情"字段的文案格式 | 禁止合并为一条记录 |
| 互审模式需生成审批 | 复制不立即生效，用户需要感知审批状态 | 确认后到审批完成前的状态反馈 | 禁止在互审模式下直接生效 |

## §8 约束与不做什么

### 硬约束

- 复制入口仅出现在子管理员模式列表，不进入用户授权页
- 复制来源必须是已有子管理员
- 复制对象上限 200 名
- 复制对象必须已加入 + 已认证
- 已有子管理员使用叠加逻辑，不覆盖
- 开启双管理员互审时生成审批

### 不做什么

- 不做可授权功能模板（本次不新增抽象层）
- 不做跨管理员类型的权限转移
- 不与用户授权页的权限复制合并
- 不改变子管理员现有的状态模型和规则模型
