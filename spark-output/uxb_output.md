# 体验需求定案：子管理员复制

---

## §0 本次关键判断

子管理员复制是在现有子管理员分权能力上新增的批量操作手段，不改变底层授权模型与治理规则。核心价值是让权限管理员能从已配置好的子管理员出发，将其授权范围作为模板快速投射到多个目标用户，解决大客户（如 200+ 子管理员）批量配置效率低的问题。

**判断：** 需求成立，建议进入正式体验设计。批量复制本身不复杂，复杂的是部分成功的反馈处理、双管理员互审下的状态分层、以及"叠加去重"的边界表达。

**主要影响：** 落地后将显著缩短大客户的子管理员配置周期，但也意味着操作记录和审计追溯需要同步增强。

**推荐方向：** 按"模板化分发"的思路设计复制流程——来源子管理员提供授权模板，目标用户按规则接收，接收结果按成功/失败分组展示。

**不建议方向：** 不要把复制做成"逐人逐项勾选"的自动化版——如果每次复制前都要重新指定所有配置项，效率提升就有限了。

**关键待确认：** 失败项的后续处理已确认为"重新开始"，叠加逻辑已确认为"去重"，双管理员互审下已确认为"审批通过后才生效"。

---

## §1 需求输入摘要

**需求背景：** 集团型企业使用子管理员模式下放权限管理能力，部分客户（如广西交投）拥有 200+ 子管理员。这些子管理员的"可授权功能"通常一致，但"可授权组织"不同。当前配置需逐个子管理员单独勾选相同的功能权限，实施效率低。

**目标用户：** 权限管理员 / 超级管理员，负责维护子管理员及其可授权范围。

**业务目标：** 提升授权配置效率，减少重复勾选权限的人工成本，降低大客户实施周期。

**功能范围：**
- 在子管理员列表"操作"列增加"复制"入口，放在操作项最左侧
- 复制弹窗包含"复制信息"（可授权组织、可授权功能）和"复制对象"两部分
- 支持选择一名或多名用户作为复制目标（上限 200 名）
- 员工选择弹窗样式与"添加子管理员"弹窗一致
- 点击确认时按顺序校验：复制信息已勾选 → 复制对象已选择 → 复制对象加入状态为已启用 → 复制对象认证状态为已认证
- 复制成功后 toast 提示"复制成功"
- 复制成功生成操作记录
- 如开启双管理员互审模式，复制完成时生成审批

**已确认的关键补充（用户确认）：**
- 批量校验部分失败时，成功项生效，失败项列出，失败项需重新开始完整复制流程
- 叠加逻辑采用去重策略（多次复制同一范围不重复叠加）
- 双管理员互审模式下，审批通过后才生效

**输入缺口：** 原始材料中"加入状态"的目标状态出现"已启用/已加入"两种表述，需产品统一口径。

---

## §2 业务场景判断

**业务定位：** 这项需求是子管理员分权管理能力的一次水平扩展，不是新增治理模式或改造底层授权模型。复制操作本质上是"将已配置的授权范围作为模板进行分发"，它与现有"添加子管理员"和"编辑子管理员"能力互补，形成"配置→复制→叠加"的完整链路。

**与现有能力的关系：**
- 依赖子管理员模式已开启（前提条件）
- 依赖已有子管理员作为复制来源
- 依赖员工加入状态、认证状态等前置条件
- 与双管理员互审模式可共存（互审模式下复制需审批后生效）
- 不改变 R-008（子管理员边界限制）和 R-009（子管理员与双管理员互审关系）等既有规则

**最大业务不确定性：** 叠加去重的具体实现边界——"去重"是按功能 ID 精确去重还是按同一授权来源去重，决定了复制叠加后的最终授权范围。这个边界需要产品侧在体验设计前明确。

**判断错误的影响：** 如果判断为"不改变治理模型"是错误的（例如实际需要修改生效机制），则后续的体验方案需要全盘重做。

---

## §3 需求成立性判断

**收益：**
- 大幅提升大客户场景下的子管理员配置效率
- 减少人工重复操作导致的配置错误风险
- 降低大客户实施交付周期，对签单有直接帮助
- 提供操作审计记录，满足合规追溯要求

**系统代价：**
- 新增复制操作的后端处理逻辑（含叠加去重）
- 新增操作记录模板，需扩展审计字段
- 双管理员互审模式下需与审批管理对接
- 批量部分成功的状态管理和结果展示需要前后端配合

**更低成本替代路径：**
- 角色模板化授权（已存在，但与子管理员分权是两条路径，无法替代）
- 批量导入子管理员配置（当前不存在，从零建设成本高于复制功能）
- 结论：复制是当前约束下性价比最高的方案

**结论：** 建议进入正式体验设计。

---

## §4 推荐业务边界

**推荐能力形态：**
- 以子管理员为单位的授权范围复制（含可授权组织和可授权功能）
- 支持批量选择目标用户（上限 200 名）
- 操作记录包含复制配置快照，满足审计追溯
- 双管理员互审模式下，复制操作进入审批链路，审批通过后生效

**不推荐能力形态：**
- 不支持跨子管理员合并复制（从多个来源各取一部分合并为一个目标配置）
- 不支持复制后的即时编辑（复制成功后如需调整，走编辑入口）
- 不支持定时复制或计划任务复制

**与现有能力的边界：**
- 复制 ≠ 新增子管理员。复制依赖已有子管理员作为来源，新增则不依赖
- 复制 ≠ 编辑。复制产生新的授权范围配置（对已有子管理员是叠加），编辑修改现有配置
- 复制入口仅在子管理员模式列表中展示，不扩展到其他管理页面

**能力复用：**
- 复用子管理员列表页现有框架、筛选和分页能力
- 复用员工选择弹窗（与"添加子管理员"一致）
- 复用操作记录能力，扩展模板字段
- 复用审批管理中已有的双管理员互审流程

## §5 角色、功能、规则范围

### 角色职责

| 角色 | 职责 | 说明 |
|------|------|------|
| 权限管理员 / 超级管理员 | 发起复制操作，选定来源、内容和目标 | 操作执行者 |
| 来源子管理员 | 作为复制来源，提供可授权组织和可授权功能配置 | 被动角色，不参与操作 |
| 复制对象用户 | 接收复制过来的授权范围 | 被动角色，不参与操作；可能原是普通用户或已有子管理员 |

### 功能范围

| 功能 | 输入 | 处理 | 输出/结果 |
|------|------|------|----------|
| 复制入口 | 子管理员列表行数据 | 在操作列最左侧渲染"复制"按钮 | 点击打开复制弹窗 |
| 复制信息选择 | 来源子管理员的授权配置 | 默认全选，支持多选，必选至少一项 | 选定复制范围（可授权组织/可授权功能） |
| 复制对象选择 | 员工选择器 | 选择一名或多名用户，上限 200 名 | 选定目标用户列表 |
| 复制校验 | 复制信息 + 复制对象 | 按顺序校验 4 项规则 | 校验通过进入复制执行；不通过按部分成功处理 |
| 复制执行 | 已校验的复制信息 + 复制对象 | 对每个目标用户执行授权授予/叠加 | 成功项生效 + 失败项列出 |
| 操作记录 | 复制执行结果 | 按模板生成操作记录 | 写入审计日志 |

**注意：** 双管理员互审模式下，复制执行的结果不是直接生效，而是生成一条审批；审批通过后才执行上述"复制执行"逻辑。

### 关键业务规则

| 规则 | 触发条件 | 处理结果 | 不满足时的处理 |
|------|---------|---------|--------------|
| 复制信息必选 | 点击确认时 | 继续下一项校验 | 提示"请选择复制信息"，阻止提交 |
| 复制对象必选 | 复制信息已勾选 | 继续下一项校验 | 提示"请选择至少一名复制对象"，阻止提交 |
| 复制对象加入状态校验 | 复制对象已选择 | 校验通过则继续 | 状态不通过项计入失败列表，成功项继续执行 |
| 复制对象认证状态校验 | 加入状态校验通过 | 校验通过则继续 | 状态不通过项计入失败列表，成功项继续执行 |
| 普通用户接收复制 | 复制对象原本不是子管理员 | 成为子管理员，按复制信息设置授权范围 | — |
| 已有子管理员接收复制 | 复制对象已是子管理员 | 在原有范围上叠加，重复内容去重 | — |
| 复制对象上限 | 选择复制对象时 | 正常选择 | 超过 200 名时限制选择 |
| 双管理员互审同步 | 系统已开启双管理员互审模式 | 生成一条审批，审批通过后生效 | 不开启互审时直接生效 |

## §6 状态、异常与边界

### 核心状态

| 状态 | 说明 | 用户下一步 |
|------|------|----------|
| 复制弹窗-初始态 | 打开弹窗，复制信息默认全选，复制对象为空 | 选择复制信息或复制对象 |
| 复制弹窗-已选择 | 已选复制信息和复制对象 | 点击确认或修改选择 |
| 校验中 | 点击确认后，系统按顺序校验 | 等待校验结果 |
| 校验部分失败 | 部分对象不满足加入状态或认证状态 | 查看失败列表，重新开始复制 |
| 复制执行中（直接生效模式） | 校验通过，系统执行授权授予/叠加 | 等待执行结果 |
| 复制执行中（互审模式） | 校验通过，系统生成审批 | 等待审批通过 |
| 复制成功（直接生效） | 授权已生效 | 查看操作记录 |
| 复制成功（互审模式） | 审批已提交，待审批通过后生效 | 在审批中心查看进度 |

### 关键异常

| 异常 | 触发条件 | 系统处理结果 | 用户下一步 |
|------|---------|------------|----------|
| 复制信息未勾选 | 点击确认时未选任何内容 | 提示"请选择复制信息"，阻止提交 | 勾选至少一项后重试 |
| 复制对象未选择 | 未选择目标用户 | 提示"请选择至少一名复制对象"，阻止提交 | 选择目标用户后重试 |
| 部分用户加入状态不通过 | 校验时发现部分用户未加入 | 成功项继续执行，失败项列出 | 查看失败列表，重新开始完整复制流程 |
| 部分用户认证状态不通过 | 校验时发现部分用户未认证 | 成功项继续执行，失败项列出 | 查看失败列表，重新开始完整复制流程 |
| 双管理员互审模式未配置 | 系统已开启互审但未完成搭档配置 | 复制成功但可能无法提交审批 | 联系系统管理员完成互审配置 |
| 全部用户校验不通过 | 所有选定对象均不满足条件 | 复制不执行，全部失败列表展示 | 修正条件后重新开始 |

## §7 体验蓝图承接要求

### 承接要求清单

**7.1 批量复制与部分成功**

业务判断：200 人批量操作中部分用户可能不满足加入或认证条件，系统按部分成功处理。

对体验设计的影响：用户需要在提交前了解目标用户的有效性状态，提交后需要清晰看到成功/失败的分组结果。

下游必须承接的问题：
- 员工选择弹窗是否提供前置条件标识（如标记未加入/未认证用户），帮助用户在提交前剔除无效对象
- 复制结果如何按"成功/失败"分组展示
- 失败列表如何展示失败原因（加入状态/认证状态）

禁止下游重判：不允许改变"部分成功"的处理原则，即不得改为"整体失败"。

**7.2 叠加去重**

业务判断：已有子管理员接收复制时，在原有范围上叠加，重复内容去重。

对体验设计的影响：用户复制后看到的最终权限范围可能不等于"来源范围+原有范围"的简单并集（因为去重逻辑的存在）。

下游必须承接的问题：
- 复制成功后的反馈文案是否提示"已去重"或保持一致
- 操作记录是否记录原始复制范围和去重后的最终结果

禁止下游重判：不允许改为"覆盖"或"多次叠加不设限"。

**7.3 双管理员互审下的状态分层**

业务判断：双管理员互审模式下，复制操作需要审批通过后才生效。

对体验设计的影响："复制成功"在互审模式下有双重含义——"提交审批成功"和"审批生效成功"，需要在反馈中明确区分。

下游必须承接的问题：
- 互审模式下的"复制成功"toast 是否需要调整为"已提交审批"
- 用户是否需要查看审批进度入口
- 用户是否需要知道审批通过/拒绝的结果通知

禁止下游重判：不允许在互审模式下将"提交审批"等同于"已生效"。

**7.4 审计完整性**

业务判断：操作记录需要满足审计可追溯要求。

对体验设计的影响：操作记录不能仅记录"谁复制了谁"，还应包含复制时的配置快照。

下游必须承接的问题：
- 操作记录的"详情"字段是否需要扩展（至少包含复制信息快照、目标用户列表）
- 界面是否需要提供操作记录的查看入口

禁止下游重判：不允许将"详情"字段留空或仅记录"无"。

## §8 约束与不做什么

**硬约束：**
- 复制入口仅出现在子管理员模式列表中
- 复制来源必须是已有子管理员
- 复制对象上限 200 名
- 复制信息至少选择一项
- 复制对象必须已加入且已认证（否则进入失败列表）
- 已有子管理员接收复制采用叠加去重逻辑
- 复制成功必须生成操作记录

**依赖项：**
- 双管理员互审模式下，复制操作依赖审批管理完成流程闭环

**不做什么：**
- 不做跨子管理员合并复制
- 不做复制后的即时编辑
- 不做定时复制或计划任务
- 不做失败项的原地重试（失败需重新开始完整流程）
- 不增加新的治理模式

**不可突破的安全或业务边界：**
- 不可让子管理员复制出超出其自身管辖范围的授权（R-008）
- 不可绕过双管理员互审的审批链路直接生效
- 不可在操作记录中省略审计关键字段
