# UXB 需求定案：子管理员配置复制

---

## §0 关键设计判断

这项需求的核心矛盾是：集团客户子管理员的功能权限高度一致，但配置链路要求逐人逐项勾选，缺乏复用机制。

主要影响：200+ 子管理员批量配置场景下效率极低，直接影响大客户实施体验和平台竞争力。

建议方案：在子管理配置页增加复制能力，超管可以从已有子管理员复制完整配置（可授权组织 + 可授权功能）给目标用户，已有子管理员接收后叠加，普通用户接收后成为子管理员。

不建议方案：引入功能权限模板化抽象（复杂度高、对现有数据模型改动大）；仅做批量创建向导（覆盖场景单一，不支持日常新增）。

关键待确认：叠加策略下的配置结果展示方式；双管理员互审模式下复制审批的状态提示粒度。

---

## §1 需求输入摘要

### 需求背景 [FACT]

集团型企业使用子管理员模式下放权限管理能力。部分客户子管理员数量大（如广西交投 200+），所有子管理员可授权功能一致但可授权组织不同。当前需逐个子管理员单独勾选相同功能权限，实施工作量大、配置效率低。

### 目标 [FACT]

新增复制能力，使权限管理员可以：
- 复制某个子管理员的可授权组织
- 复制某个子管理员的可授权功能
- 批量复制给多个用户
- 将普通用户快速设置为子管理员
- 对已有子管理员叠加授权范围
- 记录复制操作，满足审计和追溯要求

### 功能范围 [FACT]

| 功能点 | 说明 |
|--------|------|
| 复制入口 | 子管理配置页「操作」列新增「复制」，展示在最左侧 |
| 复制弹窗 | 包含「复制信息」和「复制对象」两部分 |
| 复制信息 | 可授权组织 + 可授权功能，默认全选，至少选一项 |
| 复制对象 | 支持选择一个或多个用户（最多 200 名） |
| 校验链 | 复制信息 → 复制对象 → 加入状态 → 认证状态（顺序校验） |
| 双管理员互审 | 开启时复制操作须生成审批 |
| 操作记录 | 复制成功时生成操作记录 |

### 关键约束 [FACT]

- 复制入口仅出现在子管理员模式列表
- 复制来源必须是已有子管理员
- 复制信息至少选择一项
- 复制对象至少选择一名，最多 200 名
- 目标用户需已加入且已认证
- 已有子管理员接收复制采用叠加逻辑
- 普通用户接收复制后成为子管理员
- 需生成操作记录
- 双管理员互审模式下需按规则生成审批

## §2 业务场景判断

### 业务定位

这是「权限管理域 → 全局治理子域 → 子管理配置页」的能力扩展，不是新增领域也不是底层重构。复制能力是子管理员配置链路的效率补充，不改变子管理员的业务对象定义和角色责任。

### 与现有能力的关系

- 继承现有的子管理员数据模型（不新增业务对象）
- 新增复制操作模式（在「新增」基础上扩展）
- 叠加逻辑是对现有配置写入策略的补充（从"设置"变为"叠加"）
- 双管理员互审模式、操作记录等是既有能力的复用

### 最大业务不确定性

叠加策略后续的可管理性。短期内叠加解决了"不覆盖原有配置"的安全诉求，但多次叠加后子管理员的能力来源会变得不透明——超管分不清当前配置是基准配置、第一次叠加还是第二次叠加的结果。当前需求文档未说明被叠加后的配置如何展示和解释。

### 判断错误的影响

如果子管理员配置的未来方向是模板化（权限模板 → 批量关联），那么当前复制能力可能只是过渡方案，后续面临叠加数据向模板化的迁移成本。但从当前需求来看，复制→叠加是合理的第一步，对后续演进不构成阻塞。

---

## §3 需求成立性判断

### 收益 [CONFIRMED]

- 消除功能权限重复勾选——200 次操作降为 1 次复制
- 批量操作支持（最多 200 目标）覆盖大客户首次创建场景
- 叠加策略保护已有配置，降低误操作风险
- 操作记录和双管理员互审覆盖审计和治理要求
- 与现有子管理员体系兼容，不改底层数据模型

### 代价 [CONFIRMED]

- 需要新增复制弹窗及相关交互流程
- 叠加逻辑需要额外的配置汇聚展示能力支撑
- 批量操作（200 目标）对后端存在一定性能压力
- 双管理员互审模式下的审批对接需要确认

### 更低成本替代路径

**已排除：功能权限模板化。** 将可授权功能抽离为独立模板，超管先定义模板再关联子管理员。优势是模板更新可联动所有子管理员，劣势是引入了新业务对象（模板），数据模型复杂度高，且不解决当前最急迫的"200+ 子管理员配置效率"问题。

**已排除：仅做批量创建向导。** 一次配置多人但覆盖场景单一（仅首次创建），不支持日常零星新增，且与现有配置页双轨并行增加维护成本。

### 结论 [CONFIRMED]

建议进入正式体验设计。复制方案是当前问题空间下风险最低、价值最直接的路径。叠加策略带来的配置结果展示问题是下游体验设计必须承接的重点。

## §4 推荐业务边界

### 在范围内 [CONFIRMED]

| 能力 | 说明 |
|------|------|
| 子管理员配置复制 | 从已有子管理员复制完整配置给目标用户 |
| 复制内容可选 | 可独立选择复制可授权组织、可授权功能 |
| 单目标复制 | 复制给 1 个目标用户 |
| 批量复制 | 复制给最多 200 个目标用户 |
| 叠加写入 | 已有子管理员接收时叠加，不覆盖 |
| 普通用户转子管理员 | 接收复制后成为子管理员 |
| 校验与反馈 | 4 步顺序校验 + 结果反馈 |
| 双管理员互审对接 | 开启时复制操作进入审批流程 |
| 操作记录 | 复制成功时记录 |

### 不在范围内 [CONFIRMED]

| 排除项 | 原因 |
|--------|------|
| 功能权限模板化 | 复杂度高、数据模型改动大，当前不需要 |
| 组织范围批量配置 | 各子管理员组织范围天然不同，不属于复用对象 |
| 子管理员配置审批流程改造 | 仅对接既有双管理员模式 |
| 权限查询和审计功能重构 | 操作记录已在现有能力范围内 |
| 子管理员产品能力增强 | 本需求不涉及子管理员自身功能变更 |

### 边界理由

- 复制是一次性快照，不是模板绑定：来源变更不影响已复制的目标
- 叠加不是合并：已有子管理员原有配置保留，新增部分累加
- 范围隔离不突破：复制后的目标子管理员仍受其组织范围管辖约束
- 双管理员互审是既有模式：复制操作触发审批，但不改变审批链路本身

## §5 角色、功能、规则范围

### 角色职责

| 角色 | 类型 | 职责 | 能力边界 |
|------|------|------|----------|
| 权限管理员/超管 | 执行者 | 执行子管理员配置复制操作 | 可以查看已有子管理员配置、选择来源和目标、执行复制 |
| 子管理员(来源) | 被操作对象 | 作为复制来源提供配置信息 | 不参与操作，复制不影响其自身配置 |
| 复制对象(目标) | 被操作对象 | 接收复制过来的配置 | 可以是普通用户或已有子管理员 |

### 功能闭环

| 功能 | 输入 | 处理 | 输出 | 结果 |
|------|------|------|------|------|
| 选择复制来源 | 超管从列表选中一个子管理员 | 加载该子管理员的可授权组织和可授权功能 | 复制信息预填（默认全选） | 来源信息就绪 |
| 配置复制内容 | 超管选择复制可授权组织和/或可授权功能 | 勾选要复制的选项 | 选定复制范围 | 复制内容就绪 |
| 选择复制目标 | 超管从组织成员中选择 1-200 名用户 | 通过员工选择弹窗选择目标 | 目标用户列表 | 复制目标就绪 |
| 执行复制 | 超管点击确认 | 顺序校验 → 执行复制写入 | 成功/失败结果反馈 | 配置复制完成 |
| 叠加写入 | 已有子管理员接收复制 | 在原有配置上追加新权限 | 配置更新完成 | 原有配置保留，新增权限追加 |
| 转子管理员 | 普通用户接收复制 | 用户状态变更为子管理员 | 用户成为子管理员 | 用户获得子管理员身份和配置 |
| 生成操作记录 | 复制成功触发 | 记录操作类型、对象、内容 | 操作记录入库 | 审计可追溯 |
| 生成审批(双管理员模式) | 复制完成触发 | 按双管理员规则生成审批 | 审批流转开始 | 复制结果待审批生效 |

### 关键业务规则

| 规则 | 触发条件 | 处理结果 | 不满足时处理 |
|------|----------|----------|-------------|
| 复制内容必选 | 点击确认 | 通过 | 提示"请选择复制信息" |
| 复制对象必选 | 点击确认 | 通过 | 提示"请选择至少一名复制对象" |
| 目标加入状态校验 | 点击确认 | 通过的继续，不通过的标记 | 提示"XXX 加入状态不是已加入" |
| 目标认证状态校验 | 点击确认 | 通过的继续，不通过的标记 | 提示"XXX 未完成实名认证" |
| 普通用户转子管理员 | 目标原非子管理员 | 写入时自动转为子管理员 | 无（普通用户也需通过加入和认证校验） |
| 已有子管理员叠加 | 目标已是子管理员 | 在原有配置上追加 | 目标原有配置缺失时走新增逻辑 |
| 最多 200 目标 | 选择复制对象时 | 允许选择不超过 200 人 | 选择器做上限限制 |
| 双管理员互审 | 系统已开启双管理员模式 | 复制写入后生成审批 | 审核通过后生效 |

## §6 状态、异常与边界

### 核心状态

| 状态 | 含义 | 系统处理结果 | 用户下一步 |
|------|------|-------------|-----------|
| 复制前（待操作） | 超管选中来源，待执行复制 | 弹窗就绪，等待确认 | 选择复制内容和目标，点击确认 |
| 复制中（执行中） | 批量复制正在处理 | 逐目标校验并写入，收集结果 | 等待处理完成 |
| 复制完成（全部成功） | 所有目标复制成功 | 提示"复制成功"，生成操作记录 | 可进入目标详情查看或关闭 |
| 复制完成（部分成功） | 部分目标成功，部分失败 | 提示复制结果，展示成功/失败明细 | 查看失败原因，对失败目标单独处理 |
| 复制完成（全部失败） | 所有目标复制失败 | 提示复制失败，展示失败原因 | 根据失败原因调整后重新提交 |
| 审批中（双管理员模式） | 复制完成但需审批后生效 | 进入审批流转，待另一位管理员审批 | 通知审批人处理，等待审批结果 |

### 异常清单

| 异常 | 触发条件 | 系统处理结果 | 用户下一步 |
|------|----------|-------------|-----------|
| 复制信息未选择 | 点击确认时复制内容为空 | 阻止提交，提示"请选择复制信息" | 勾选复制内容后重试 |
| 复制对象未选择 | 点击确认时目标为空 | 阻止提交，提示"请选择至少一名复制对象" | 选择目标后重试 |
| 目标加入状态异常 | 目标用户未加入企业或已离职 | 标记该目标失败，继续处理其他目标 | 筛选失败目标，确认加入状态后重试 |
| 目标认证状态异常 | 目标用户未完成实名认证 | 标记该目标失败，继续处理其他目标 | 通知目标完成认证后重试 |
| 全部目标状态异常 | 所有目标均未满足条件 | 提示全部失败，列出所有失败原因 | 检查条件后重新选择或调整目标 |
| 批量复制超限 | 选择超过 200 个目标 | 选择器限制不可继续添加 | 减少目标数量至 200 以内 |
| 来源子管理员异常 | 来源已被删除或状态异常 | 提示来源不可用 | 选择其他来源 |

### 边界说明

- 批量场景下部分失败不应阻塞整体流程——系统对每个目标独立处理
- 复制过程中来源子管理员不应被锁定或限制——复制为读操作
- 目标失败不影响已成功目标的复制结果——不提供事务回滚
- 注意：需求文档中的加入状态同时出现"已启用"和"已加入"两种表述，需产品统一口径 [GAP]

## §7 体验蓝图承接要求

| 业务判断 | 体验影响 | 下游必须承接的问题 | 禁止下游重判 |
|----------|----------|-------------------|-------------|
| 叠加策略：已有子管理员接收复制时在原配置上追加 | 超管需要了解叠加后的最终结果，而非只有原始来源 | 子管理员详情页/列表页展示叠加后的生效配置，支持查看配置来源构成 | 禁止改为覆盖逻辑；禁止因叠加复杂而建议改为覆盖 |
| 批量复制 200 目标必然涉及部分失败 | 超管需要知道失败数量、哪些失败、失败原因、如何重试 | 批量结果汇总视图：成功/失败分类展示，支持对失败目标的筛选和单独重试 | 禁止简化为仅提示"部分失败"无明细 |
| 4 步顺序校验 | 超管需要知道校验卡在哪一步、什么原因 | 校验失败的步骤级提示，失败原因对应用户可见 | 禁止把校验提示压缩成统一报错 |
| 双管理员互审模式：复制后需审批 | 复制不是即时生效，超管需要知道当前状态 | 复制操作后的状态提示：已提交审批/审批通过/审批驳回；审批流转状态可见 | 禁止忽略审批状态，显示为已生效 |
| 普通用户接收复制→成为子管理员 | 被操作用户不知道自己的身份变化 | （可选）通知被操作用户已成为子管理员 | 禁止擅自通知用户；禁止因技术成本高直接放弃该能力 |
| 复制为一次性快照，非模板绑定 | 来源变更不影响副本，叠加记录有时间线 | 需要支持查看某个子管理员的配置变更时间线 | 禁止把复制改为隐式模板绑定 |
| 允许独立选择复制可授权组织/可授权功能 | 超管可能需要只复制其中一个维度 | 复制弹窗内容选择区的交互设计 | 禁止强制要求同时复制两个维度 |

## §8 约束与不做什么

### 硬约束 [FACT]

- 复制入口仅出现在子管理员模式列表中 [FACT]
- 复制来源必须是已有子管理员 [FACT]
- 复制信息至少选择一项 [FACT]
- 复制对象至少选择一名，最多 200 名 [FACT]
- 目标用户须已加入且已认证 [FACT]
- 子管理员模式与双管理员模式不可同时开启——这是现有约束，不变 [CONFIRMED]
- 子管理员受组织范围和应用管辖范围约束，复制不突破该约束 [CONFIRMED]
- 复制为一次性快照，来源变更不影响已复制的目标 [CONFIRMED]

### 不做什么

- 不做功能权限模板化改造
- 不做子管理员配置审批流程的独立改造（仅对接既有双管理员模式）
- 不做组织范围批量配置
- 不做权限查询或审计能力重构
- 不做子管理员自身产品能力增强

## §9 待确认问题

### 层级一：影响主方案是否成立的问题

| 问题 | 影响 | 建议确认方 |
|------|------|-----------|
| 加入状态的校验口径：文档同时出现"已启用"和"已加入"两种表述 | 影响校验规则设计、报错文案和异常处理逻辑 | 产品经理 |
| 叠加后的配置在子管理员列表和详情页中如何展示 | 影响子管理员配置页的列表设计和详情布局，是体验蓝图的核心输入 | 产品经理 + 体验设计师 |
| 双管理员互审模式下，复制审批的流程边界（谁审批、审批什么内容、审批后怎么通知超管） | 影响复制操作后的状态提示和用户引导链路 | 产品经理 |

### 层级二：影响局部体验设计的问题

| 问题 | 影响 | 建议确认方 |
|------|------|-----------|
| 批量复制 200 目标的性能表现（后端是否支持同步/异步处理） | 影响批量操作的进度展示方式和等待设计 | 后端开发 |
| 员工选择弹窗是否复用现有组件 | 影响复制弹窗的开发成本和交互一致性 | 体验设计师 + 前端开发 |
| 普通用户成为子管理员后是否需要系统通知 | 影响是否增加通知触点 | 产品经理 |
| 操作记录详情中复制内容的展示粒度（仅提示复制了组织和功能，还是展示具体项目） | 影响操作记录详情页的设计 | 产品经理 |
