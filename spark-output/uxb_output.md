# 需求定案：子管理员权限复制

## §0 本次关键判断

**判断**：这是一项中等复杂度的既有能力扩展，不改底层权限模型，核心是在子管理员列表上新增"以人为模板"的权限复制操作。

**主要影响**：校验失败采用部分执行（跳过不合规者继续执行其余），这要求结果反馈从简单 toast 升级为执行结果摘要展示；叠加逻辑要求管理员在操作前能理解目标用户已有权限。

**建议方案**：在子管理员列表操作列增加复制入口，通过弹窗承载复制信息选择（可授权组织/可授权功能）和目标人员指定（1-200 人），校验失败时部分执行并汇总展示结果。

**不建议方案**：不采用全部阻断策略；不对已有子管理员做覆盖式替换；不建议跳过人员选择器用"全选"或"一键复制到所有"。

**关键待确认**：双管理员互审模式下，审批期间复制是否即时生效、审批被拒后是否回滚。

## §1 需求输入摘要

**需求来源**：用户提供的需求文档《子管理员支持复制》

**需求背景**：集团型企业使用子管理员模式下放权限管理能力，部分客户（如广西交投）存在 200+ 子管理员。这些子管理员的"可授权功能"通常一致，但"可授权组织"不同。当前需要逐人重复勾选相同的功能权限，配置效率低。

**目标用户**：权限管理员 / 超级管理员

**业务目标**：降低批量配置子管理员的人力成本，缩短大客户实施周期。

**产品目标**：支持将已有子管理员的权限信息（可授权组织、可授权功能）复制给一个或多个目标用户。

**功能范围**（[FACT] 来自需求文档）：

- 复制入口：子管理员列表操作列最左侧
- 复制弹窗：包含复制信息选择区和复制对象选择区
- 复制信息：可授权组织、可授权功能（默认全选、至少选一项）
- 复制对象：可选 1-200 名用户
- 4 步顺序校验：复制信息是否勾选 → 复制对象是否已选 → 加入状态是否均为已加入 → 认证状态是否均为已认证
- 校验失败采用部分执行（[CONFIRMED] 用户确认）
- 复制后：普通用户成为子管理员，已有子管理员叠加权限
- 操作记录：复制成功时生成
- 双管理员互审：开启时复制完成需生成审批

**PRD 缺口**：

- [GAP] 需求文档中"加入状态"的目标状态出现"已启用"和"已加入"两种表述，需产品统一口径
- [GAP] 复制对象除加入状态和认证状态外，是否还有其他隐含限制（如跨企业、已离职员工等）
- [GAP] 双管理员互审审批的生效时机和拒绝后的回滚机制

## §2 业务场景判断

### 业务定位

这是对现有"子管理员模式"的一项能力扩展。知识库中 [子管理员列表页](.claude/skills/knowledge-wiki/knowledge/raw/业务/权限管理/15_页面载体语义.md#L400) 已将"复制"列为关键操作之一，本次需求是把该操作的交互细节、校验规则、执行逻辑和审计闭环完整定义出来。

### 与现有能力的关系

- **复用**子管理员列表页的入口和操作列结构
- **复用**添加子管理员流程中的人员选择器
- **沿用**现有子管理员边界规则（R-008：子管理员只能在管辖范围内操作）
- **沿用**现有治理模式互斥规则（R-009：子管理员模式与双管理员模式不可同时开启）
- **不改变**子管理员的角色定义、组织范围和应用范围的权限模型
- **不改变**加入状态和认证状态的定义，仅将其作为前置校验条件

### 最大业务不确定性

双管理员互审模式下，复制操作需要生成审批——但审批期间权限是否即时生效、审批被拒后复制结果是否回滚，这两个问题在需求文档中未覆盖。如果答案是"审批通过后才生效"，那整个复制流程需要增加一个"审批中"的中间态和对应的状态展示。

### 如果这个判断错了

如果复制操作实际上会改变底层权限生效机制（例如引入了新的审批链路或改变了子管理员的权限边界），那需要从 §4 开始重做业务边界判断，§5 的角色和规则也需要重新梳理。

## §3 需求成立性判断

### 收益

- 直接解决 200+ 子管理员场景下重复配置的效率问题
- 降低批量授权的人为配置错误风险
- 缩短大客户实施周期，减少实施人员的手工操作时间
- [FACT] 需求文档预期价值：提升授权配置效率、减少重复勾选权限的人工成本

### 代价

- 新增复制弹窗和校验链路的前端开发工作量
- 操作记录需要支持"部分成功"语义，可能需要调整操作记录的字段结构
- [GAP] 如果双管理员互审引入"审批中"状态，后端需要在复制流程中嵌入审批节点

### 更低成本替代路径

- **角色模板化分发**：将常用的权限组合定义为角色模板，管理员通过关联角色来批量授权。但需求文档明确指出"可授权功能通常一致，但可授权组织不同"，角色模板无法覆盖"同功能不同组织范围"的场景，因此角色分发不完全替代此需求。
- **仅支持单人选复制**：去掉 200 人批量，仅支持逐人复制。这会降低实现复杂度，但无法解决 200+ 子管理员的批量配置效率问题，价值打折扣。

### 成立判断

该需求成立。用户问题真实，带来的效率价值明确，系统代价可控。建议进入正式体验设计。

## §4 推荐业务边界

### 推荐能力形态

- 复制操作以"已有子管理员"为模板，复制单位为该子管理员的可授权组织范围和可授权功能范围 [FACT]
- 复制内容可选择：仅复制组织范围、仅复制功能范围、或两者都复制 [FACT]
- 复制对象支持 1-200 人，满足规模化配置需求 [FACT]
- 校验失败采用部分执行策略：跳过不合规人员，其余继续执行 [CONFIRMED]
- 复制成功后必须同时产出操作记录和（如开启互审）审批记录 [FACT]

### 与现有能力的边界

- 复制操作是**在子管理员列表上执行**，不是用户授权列表中的"权限复制"——两者操作对象不同（子管理员的授权范围 vs 普通用户的功能/数据权限）
- 复制的产出是**子管理员的授权范围**，不是直接授予业务权限——知识库明确区分"权限的权限"和业务权限本身
- 复制不改变子管理员自身的管辖范围约束（R-008），复制后的子管理员仍需在其组织范围和应用范围内操作

### 不建议能力形态

- 不建议把复制做成"角色模板"——因为模板无法解决同功能不同组织范围的场景
- 不建议复制后自动覆盖目标用户已有权限——需求已明确采用叠加逻辑 [FACT]
- 不建议把复制扩展为"全选所有子管理员一键复制"——缺乏明确的源模板，操作风险高
- 不建议复制时允许修改来源权限（复制就是复制，不是"基于模板编辑"）

## §5 角色、功能、规则范围

### 角色清单

| 角色 | 职责 |
|------|------|
| 权限管理员 / 超管 [FACT] | 执行复制操作，选择复制来源、复制内容和复制目标 |
| 被复制子管理员（来源）[FACT] | 提供可授权组织范围和可授权功能范围作为复制模板 |
| 复制对象用户（目标）[FACT] | 接收复制内容，可能原本不是子管理员，也可能已经是子管理员 |

### 功能清单

| 功能 | 输入 | 输出 | 结果 |
|------|------|------|------|
| 复制入口 | 子管理员列表中某行的操作列 | 点击触发，打开复制弹窗 | 弹窗展示，自动填入该子管理员作为来源 |
| 复制信息选择 | 可授权组织、可授权功能的勾选状态 | 选定要复制的内容范围 | 至少一项被选中，默认全部选中 |
| 复制对象选择 | 通过人员选择器指定目标用户 | 选定 1-200 名目标用户 | 用户列表展示在弹窗中 |
| 复制执行 | 点击确认按钮 | 按顺序校验 → 执行复制 | 全部成功或部分成功（跳过不合规者） |
| 结果反馈 | 复制执行结果 | 展示成功数和跳过数及跳过原因 | 管理员了解执行结果并知道下一步 |
| 操作记录 | 复制执行完成 | 生成操作记录 | 记录中体现执行结果（全部成功/部分成功） |
| 互审审批 [FACT] | 开启双管理员互审时，复制完成 | 生成审批记录 | 审批链路按现有互审规则处理 |

### 关键业务规则

| 规则 | 触发条件 | 处理结果 | 不满足时处理 |
|------|----------|----------|--------------|
| 复制信息必选 | 点击确认时 | 校验通过，继续下一步 | 提示"请选择复制信息"，阻断 [FACT] |
| 复制对象必选 | 复制信息校验通过后 | 校验通过，继续下一步 | 提示"请选择至少一名复制对象"，阻断 [FACT] |
| 加入状态校验 | 复制对象已选择后 | 已加入的通过，继续下一步 | 未加入的被标记为不合规，后续跳过 [FACT] + [CONFIRMED 部分执行] |
| 认证状态校验 | 加入状态校验后 | 已认证的通过 | 未认证的被标记为不合规，后续跳过 [FACT] + [CONFIRMED 部分执行] |
| 目标为普通用户 | 复制执行时 | 成为子管理员，获得对应授权范围 | — [FACT] |
| 目标为已有子管理员 | 复制执行时 | 在原权限基础上叠加，不覆盖 | — [FACT] |
| 复制数量上限 | 选择复制对象时 | 可选 1-200 人 | 超过 200 人时选择器限制 [FACT] |
| 操作记录生成 | 复制执行完成时 | 生成操作记录（含成功/跳过明细）| — [FACT] + [CONFIRMED 部分成功需体现] |
| 互审审批生成 | 复制完成且开启双管理员互审时 | 生成审批 | 按现有互审规则处理 [FACT] |
| 复制来源必须是子管理员 | 点击复制入口时 | 只有已有子管理员才展示复制入口 | — [FACT] |

## §6 状态、异常与边界

### 核心状态

| 状态 | 说明 |
|------|------|
| 就绪 | 复制弹窗已打开，复制信息默认全选，等待管理员指定复制对象 |
| 校验中 | 管理员点击确认，系统按顺序校验 |
| 校验完成（全部通过）| 所有复制对象均满足条件，准备执行 |
| 校验完成（部分通过）| 部分复制对象不满足条件，展示不合规名单 |
| 执行中 | 正在执行复制操作 |
| 全部成功 | 所有合规的复制对象均已成功接收权限 |
| 部分成功 | 部分复制对象成功，部分被跳过（不合规），展示明细 |
| 复制失败 | 系统异常导致操作未能完成 |

### 关键状态流转

```text
就绪 → 校验中 → 校验完成（全部通过/部分通过）→ 执行中 → 全部成功/部分成功
                                                          ↘ 复制失败
```

### 异常清单

| 异常 | 触发条件 | 系统处理 | 用户下一步 |
|------|----------|----------|------------|
| 复制信息未勾选 | 点击确认时，复制信息无勾选项 | 在复制信息区域提示"请选择复制信息" | 勾选至少一项复制信息后重新确认 |
| 复制对象未选择 | 点击确认时，未选择任何目标用户 | 在复制对象区域提示"请选择至少一名复制对象" | 选择目标用户后重新确认 |
| 复制对象加入状态不符 | 校验时发现目标用户加入状态非"已加入" | 标记该用户为不合规，继续校验其余用户；执行时跳过 | 查看跳过名单和原因，联系相关人员处理加入状态 |
| 复制对象认证状态不符 | 校验时发现目标用户未完成实名认证 | 标记该用户为不合规，继续校验其余用户；执行时跳过 | 查看跳过名单和原因，联系相关人员完成认证 |
| 部分执行-部分跳过 | 校验发现部分目标不合规，确认执行后 | 合规者执行复制，不合规者跳过；结果反馈中展示成功/跳过明细 | 查看结果明细，对跳过人员单独处理 |
| 全部不合规 | 所有复制对象均不满足校验条件 | 不执行复制，展示不合规名单和原因 | 修正目标用户状态后重新执行复制 |
| 系统异常 | 复制执行过程中发生系统错误 | 停止执行，提示系统异常，已执行部分可能需要确认是否回滚 | 联系技术支持，确认已执行部分的处理方式 |
| 互审审批阻塞 [GAP] | 开启双管理员互审，复制完成生成审批后 | 审批链路处理中 | [GAP] 需确认：等待审批通过后生效 / 即时生效审批被拒后回滚 |

## §7 体验蓝图承接要求

| 业务判断 | 对体验设计的影响 | 下游必须承接的问题 | 禁止下游重判 |
|----------|------------------|-------------------|-------------|
| 复制是"以人为模板"而非"角色模板" | 弹窗需要展示来源子管理员的身份和授权范围摘要，帮助管理员确认"复制的模板正确" | 弹窗中如何展示来源子管理员的当前授权范围概览（组织 + 功能） | ❌ 不得将复制重新解释为角色模板分发 |
| 校验失败采用部分执行 | 结果反馈不能只是 toast，需要展示执行摘要（成功数/跳过数/跳过原因） | 结果反馈的展示层级：全部成功 / 部分成功 / 全部跳过，每种形态的展示内容 | ❌ 不得改回全部阻断策略 |
| 叠加不覆盖已有权限 | 管理员需要对"目标用户已有权限"有基本认知，否则叠加结果不可预期 | 人员选择器中是否需要展示目标用户的子管理员状态和当前授权摘要 | ❌ 不得改为覆盖式替换 |
| 4 步顺序校验，不合规则跳过 | 校验反馈需要区分"阻断性报错"（信息未填）和"跳过性提示"（人员不合规） | 校验结果展示顺序和形式：先阻断还是先展示不合规名单 | ❌ 不得合并校验步骤或改变校验顺序 |
| 复制对象 1-200 人 | 人员选择器、校验结果和操作记录需支持 200 人量级的信息展示 | 大量目标用户时校验结果和操作记录的展示策略（截断/分页/导出） | ❌ 不得修改 200 人上限 |
| 需兼容双管理员互审 | 复制流程需要预留"审批中"状态节点 | 如果互审审批不即时生效，复制完成后的状态展示和生效说明 | ❌ 不得在方案中忽略互审分支 |
| 操作记录需覆盖部分成功 | 操作记录的语义不能只记录"成功/失败"二元结果 | 操作记录中如何体现部分成功的明细（成功人/跳过人/原因） | ❌ 不得简化为仅记录"复制成功" |

## §8 约束与不做什么

### 硬约束

1. 复制入口仅在子管理员模式下可见 [FACT]
2. 复制来源必须是已有子管理员，普通用户行不展示复制入口 [FACT]
3. 复制信息至少选择一项（可授权组织 / 可授权功能）[FACT]
4. 复制对象 1-200 人 [FACT]
5. 加入状态和认证状态是子管理员准入的硬门槛，不可绕过 [FACT]
6. 已有子管理员接收复制时叠加权限，不覆盖 [FACT]
7. 复制成功必须生成操作记录 [FACT]
8. 开启双管理员互审时必须生成审批 [FACT]
9. 子管理员模式与双管理员模式不可同时开启（R-009），复制操作不改变此互斥关系 [CONFIRMED]
10. 复制后子管理员仍受 R-008 边界限制（只在管辖范围内操作），复制不扩大其管辖边界 [CONFIRMED]

### 不做什么

- 不改变子管理员列表页的整体布局和列表字段
- 不改变添加子管理员的现有流程
- 不改变双管理员互审的审批规则和流程
- 不新增"复制历史"独立页面（操作记录由现有日志体系承接）
- 不引入"撤销复制"操作（本次不做，如有需要后续单独评估）
- 不将复制扩展为"剪切/转移"（复制是新增，不是移动）

## §9 待确认问题

### 层级一：影响主方案是否成立

| 问题 | 影响 | 建议确认方 |
|------|------|-----------|
| 双管理员互审模式下，复制生成的审批是"先审批后生效"还是"先生效后审批"？审批被拒后，已复制的权限是否回滚？ | 决定复制流程是否需要"审批中"中间态，以及结果反馈是否需要区分"已生效"和"待审批" | 产品 + 安全/合规 |

### 层级二：影响局部体验设计

| 问题 | 影响 | 建议确认方 |
|------|------|-----------|
| 需求文档中"加入状态"的目标值在"已启用"和"已加入"之间不统一，最终统一为哪个表述？ | 影响校验提示文案的准确性和员工管理状态字段的引用一致性 | 产品 |
