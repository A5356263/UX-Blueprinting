# 需求定案：财富专区-资产配置面客版

---

## §0 关键设计判断

**判断**：本次将月度诊断报告改造为资产配置面客版，是一次从"被动查阅"到"可行动的决策支持"的功能升级。需求方向清晰，不改变底层业务骨架，但信息密度和任务路径发生了实质性变化。

**主要影响**：需要同时解决高信息密度下的层级组织、多资产类型的范围差异、以及外部数据精度受限时如何维持用户对配置建议的信任。

**建议方案**：按"概览→诊断→推荐"的决策主线组织页面层级；各数据模块在头部明确其资产覆盖范围，让用户始终清楚当前在看什么范围的数据；关键数据点就近标注时效和精度状态，不依赖底部统一说明传达此类信息。

**不建议方案**：所有信息和免责统一堆在一个页面，让用户自己推导各模块的范围边界和可信程度。

**关键待确认**：无——需求范围清晰，体验方向已收敛。

---

## §1 需求输入摘要

| 项目 | 内容 |
|------|------|
| 需求概述 | 将月度诊断报告改造为资产配置功能，提供客户资产配置建议书 |
| 背景 | 原月度诊断报告升级改造，源数据由企业财富+资产配置提供，部分诊断规则有优化 |
| 目标 | ① 理财月报改造为资产配置 ② 优化持仓展示和诊断规则 ③ 提供产品推荐和操作功能 |
| 用户角色 | 企业客户（高优先级）、客户经理（中优先级） |
| 影响范围 | 财富专区、持仓列表、企业财富+、收益中心 |
| 价值指标 | 建议书查看量、产品购买笔数（目标值和基准值待定） |

**核心能力范围：**
- 持仓表现、持仓诊断、产品推荐：**仅支持理财**
- 投资分布、期限分布：支持理财 + 公募基金 + 资管计划 + 信托计划
- 下载：支持 PDF / PNG 格式，分页和分 Tab 内容平铺展示

---

## §2 业务场景判断

**业务定位**：资产配置面客版是财富专区内面向企业客户的资产分析与建议工具。它将原来偏"记录型"的月度报告升级为偏"决策型"的配置建议书。

**与现有能力的关系**：
- 替代了原月度诊断报告（理财月报更名）
- 数据源切换为企业财富+资产配置（而非旧报告的数据源）
- 去掉白名单逻辑
- 页面增加持仓列表作为第二入口

**最大不确定性**：外部依赖（企业财富+）的数据时效性和精度直接影响建议书的可信度和用户体验。虽然免责声明是监管要求统一置于底部，但数据精度问题在体验层面需要更精细的处理。

**判断错误的影响**：如果低估了信息密度和范围差异对用户认知的负担，可能会导致用户难以找到核心配置建议，或者对"哪些有建议、哪些只展示"产生困惑。

---

## §3 需求成立性判断

**收益**：
- 将低频、静态的月度报告变为可按需查看的配置工具
- 一次覆盖多种资产类型的展示（理财、基金、资管、信托）
- 诊断+推荐的闭环帮助用户发现持仓问题并采取行动
- 支持下载，便于线下留存和汇报

**代价**：
- 核心数据依赖外部接口，接口异常直接影响功能可用性
- 净值精度有限，配置建议的精准度受上游数据约束
- 持仓表现/诊断/推荐仅限理财，与其他资产类型的展示范围不一致，可能带来认知成本

**更低成本替代路径**：
- 在现有月度报告基础上增量优化（如增加购买入口、改善展示）——但无法实现将多资产类型分布与诊断建议整合展示的目标。当前方案在完整性和可行动性上有本质提升。

## §4 推荐业务边界

| 范围 | 内容 |
|------|------|
| 范围内 | 资产配置建议书的生成、展示、下载；多银行账号选择；持仓概览与表现；投资分布与期限分布（多资产类型）；持仓诊断（仅理财）；产品推荐与购买跳转（仅理财） |
| 范围外 | 历史建议书保存与管理（本版本不做）；持仓概览模块（本版本不做）；非理财业务的持仓诊断和产品推荐；购买流程本身（跳转至已有购买页和购物车） |
| 边界依据 | 需求文档明确标注"本版本不做"的内容；产品推荐的业务范围限制 |

## §5 角色、功能、规则范围

### 角色职责

| 角色 | 职责 | 关键需求 |
|------|------|----------|
| 企业客户 | 查看并理解资产配置建议、根据建议执行购买、下载保存建议书 | 清晰的资产视图、可行动的诊断建议、便捷的购买入口 |
| 客户经理 | 了解客户的资产配置情况 | 查看客户配置报告的能力（文档未展开此角色具体需求） |

### 功能闭环

| 功能 | 输入 | 处理 | 输出 | 结果 |
|------|------|------|------|------|
| 银行账号选择 | 用户选择账号/全部 | 根据权限过滤账号列表 | 展示选中账号的数据 | 各模块数据切换为目标账号的数据 |
| 持仓表现查看 | 选中账号 + 时间区间 | 计算时点资产、区间收益、年化收益率等 | 数值+趋势图表展示 | 用户了解该时段资产表现 |
| 投资分布查看 | 选中账号 | 按资产类型汇总持仓金额和占比 | 饼图+列表 | 用户了解资产构成 |
| 期限分布查看 | 选中账号 | 按产品期限汇总持仓金额和占比 | 列表 | 用户了解资金占用情况 |
| 持仓诊断 | 选中账号 | 执行集中度/到期/持仓时长诊断规则 | 诊断结果卡片 | 用户发现持仓问题 |
| 产品推荐 | 选中账号 | 调用企业财富+产品推荐 | 推荐产品列表 | 用户获取配置建议 |
| 建议书下载 | 用户触发 | 生成 PDF/PNG 文件 | 文件流 | 用户获得可留存的建议书 |
| 产品购买 | 用户点击 | 新开页签跳转购买页/购物车 | 跳转 | 用户进入购买流程 |

### 关键规则

| 规则 | 触发条件 | 处理结果 | 不满足时处理 |
|------|----------|----------|-------------|
| 账号权限校验 | 用户进入资产配置 | 展示有权限的账号列表 | 无可访问账号时展示空状态 |
| 持仓集中度诊断 | 活钱管理持仓占比≥60% | 展示诊断卡片 | 占比<60%时不展示 |
| 产品到期诊断 | 存在近两周到期产品 | 展示到期产品列表 | 无到期产品时不展示 |
| 持仓时间过长诊断 | 产品超期限持仓 | 展示超时产品列表 | 无不合理持仓时不展示 |
| 金额单位换算 | 展示金额数据 | 按范围切换元/万元/亿元 | — |
| 接口异常降级 | 企业财富+接口异常 | 自动重试3次 → 降级处理 | 按异常类型展示对应提示 |

## §6 状态、异常与边界

### 核心状态

| 状态 | 说明 | 系统处理结果 | 用户下一步 |
|------|------|-------------|-----------|
| 数据加载中 | 正在请求企业财富+数据 | 页面/模块展示加载态 | 等待 |
| 数据加载完成 | 数据正常返回 | 展示完整数据 | 浏览与操作 |
| 部分数据缺失 | 接口返回部分字段为空 | 缺失字段展示"--" | 浏览可用数据 |
| 无持仓数据 | 账号下无持仓 | 展示空状态 + 引导操作 | 点击"去购买"跳转产品列表 |
| 无诊断问题 | 所有诊断规则未命中 | 诊断模块整体不展示 | 可继续查看其他模块 |
| 接口超时 | 接口响应>5秒 | 重试→展示缓存或空状态 | 稍后重试 |
| 接口无响应 | 接口完全不可用 | 展示"系统繁忙"提示 | 稍后再试 |
| 下载完成 | 文件生成成功 | 触发浏览器下载 | 打开或保存文件 |
| 下载失败 | 文件生成或传输失败 | 展示错误提示 | 按提示重试 |

### 关键异常

| 异常 | 触发条件 | 系统处理结果 | 用户下一步 |
|------|----------|-------------|-----------|
| 接口返回 401 | 登录过期 | 提示"登录已过期，请重新登录" | 重新登录 |
| 接口返回 403 | 无权限 | 提示"您暂无权限访问该功能" | 联系管理员 |
| 接口返回 500/503 | 服务器异常/维护中 | 提示"系统繁忙/维护中，请稍后再试" | 稍后重试 |
| 接口超时 | 超5秒无响应 | 自动重试3次→失败后降级 | 稍后重试 |
| 数据计算异常 | 资产配置计算失败 | 该模块展示空状态 | 稍后重试 |
| 网络中断 | 下载过程中断 | 终止下载，提示"网络异常" | 检查网络后重试 |
| 浏览器拦截下载 | 浏览器安全策略 | 提示"请允许浏览器下载文件" | 允许下载 |

## §7 体验蓝图承接要求

| 业务判断 | 体验影响 | 必须承接的问题 | 禁止下游重判 |
|----------|----------|---------------|-------------|
| 数据精度受上游净值约束，精度有限 | 用户可能对建议书的准确性存疑 | 关键数据点需就地标注时效和精度口径，不让用户到底部免责说明中自行关联 | 不得只靠底部统一免责说明覆盖所有精度告知 |
| 持仓表现/诊断/推荐仅支持理财，但分布覆盖全量资产 | 用户看到全量资产分布却只拿到理财的诊断建议，产生"我的基金呢"的困惑 | 各模块头部必须明确表达其资产覆盖范围，不让用户自己推导边界 | 不得仅依赖需求文档中统一说明"仅支持理财" |
| 产品购买通过新开页签跳转 | 用户在新页签中完成购买后，与建议书的上下文关联可能丢失 | 购买页签的定位需让用户明确"这是从建议书过来的"（如页面标题或上下文线索） | 不得假设用户能自行记住当前在哪个建议书的上下文中 |
| 时间区间筛选联动多个数据模块 | 用户调整区间后，持仓表现及各趋势图同步刷新 | 联动刷新的进度需对各模块分别可见，用户能感知"哪些模块正在更新" | 不得以全页面loading替代模块级刷新反馈 |
| 下载时所有分页和分Tab内容平铺展示 | 线上分Tab的结构在下载后变为线性长文档，用户可能找不到对应信息 | 下载产物需保留模块标题和层级组织，保证线下阅读的可扫读性 | 不得直接按数据流顺序拼凑内容 |
| "无诊断问题"时模块不展示 | 用户无法区分"没有诊断问题"和"模块出错了" | 无诊断问题时不展示模块，但页面应通过其他模块的正常展示暗示"数据已加载、无问题可报" | 不得用一个独立的"暂无诊断问题"空状态占用页面空间 |
| 浮动下载按钮 | 下载是全局操作，页面内容长时按钮需始终可达 | 浮动按钮需在长页面滚动中保持位置固定 | 不得把下载操作收入菜单或页尾 |

## §8 约束与不做什么

**约束：**
- 免责声明必须按监管要求统一置于页面底部（已确认）
- 所有源数据由企业财富+资产配置提供，渠道前端不做数据计算
- 持仓表现、持仓诊断、产品推荐仅支持理财类型（已确认）
- 产品推荐需使用实时产品数据，并过滤不可购买/额度不足的产品
- 性能要求：页面加载≤3秒，数据计算≤5秒

**本次不做什么：**
- 历史建议书的保存和管理
- 持仓概览模块
- 非理财业务的诊断和推荐
- 购买流程本身（仅提供跳转）
- 客户经理角色的专属视图（文档未详述）
