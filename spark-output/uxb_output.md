# 财富小助 Skill 广场｜需求定案

## §0 本次关键判断

**判断：**本需求应定为一套贯通 Skill 生产、共享、分行开通、个人退出、版本治理与运行调用的管理能力，而非单一广场页面。**主要影响：**新增个人所有权、组织级可用范围、个人使用偏好和跨端生效关系。**建议方案：**以创建者所有、共享后本分行自动可用、外部分行整体订阅、个人可退出为主线。**不建议方案：**恢复审核流程，或用单一“订阅”状态表达分行与个人两层关系。**关键待确认：**取消共享对既有外部分行订阅的影响。

## §1 需求输入摘要

### 1.1 背景

不同分行和业务场景各自维护提示词模板，优秀实践难以复用，客户经理也缺少统一、快捷的 Skill 发现与调用方式。需求希望在企业财富+中建立统一管理和共享能力，并通过财富小助完成实际调用。

### 1.2 目标用户

- Skill 创建者：总分行产品经理、开发人员及其他获得创建权限的用户，负责创建和维护自己的 Skill。
- 分行普通用户与客户经理：浏览共享 Skill、发起分行订阅，并在财富小助中调用本分行可用的 Skill。
- Skill 所属分行用户：自动使用本分行成员已共享的 Skill，并查看本分行 Skill 的各版本评分。
- 总行管理者：拥有全部 Skill 的最高管理权限。
- 运维人员：处理沙盒同步失败、消息异常和运行告警。

### 1.3 业务目标

- 形成统一的 Skill 创建、共享、复用和调用机制。
- 降低不同分行重复建设相似提示词的成本。
- 让优秀 Skill 能以分行为单位快速开通，并在财富小助中使用。
- 通过版本、评分、复制和还原能力支持 Skill 持续优化。
- 通过全量和增量同步保证管理数据最终进入财富小助运行环境。

### 1.4 价值指标

- Skill 月均调用次数目标不低于 5,000 次。
- 分行共享 Skill 数量目标不低于 50 个/季度。
- Skill 使用满意度目标不低于 4.2/5。
- 被多个分行订阅的 Skill 占比目标不低于 30%。
- 订阅规模统一按“订阅分行数”统计，不按个人数统计。

### 1.5 已明确的功能范围

- 创建、编辑、发布、删除和管理个人 Skill。
- 手动创建或上传 Markdown 文件创建 Skill。
- 共享或取消共享创建者自己的 Skill。
- 浏览、搜索、筛选和排序已发布且已共享的 Skill。
- 任意分行用户发起分行订阅，使该 Skill 对全分行开通。
- 分行开通后，个人可以取消使用；个人取消不影响同分行其他用户。
- 在财富小助中通过“/”联想和调用可用 Skill。
- 复制所有当前用户可见的 Skill。
- 查看版本记录、历史版本内容和历史版本评分。
- 创建者与总行管理者还原历史版本。
- 每周全量同步及创建、编辑、删除、订阅变化后的实时增量同步。

### 1.6 已确认的调整

- 删除原需求中的全部内容审核、发布审核、敏感词审核和安全检测流程；创建、编辑、发布均无需审核。
- 原“我发布的 Skill”调整为“我的 Skill”，只展示当前用户自己创建的 Skill。
- Skill 广场只展示已发布且已共享的 Skill。
- 未共享 Skill 仅创建者本人可见、可用。
- 创建者所属分行中，仅创建者本人可以共享或取消共享；同分行其他用户不可编辑或代为共享。
- 同分行成员创建的 Skill 一旦共享，本分行自动可用，无需再次订阅。
- 总行管理者拥有最高权限，可管理、编辑、共享、删除、复制和还原全部 Skill。

### 1.7 明确约束

- Skill 提示词支持 Markdown，内容上限为 10,000 字符；上传文件仅支持 UTF-8 编码的 `.md` 文件且不超过 1MB。
- Skill 列表加载目标不超过 2 秒，智能联想目标不超过 500 毫秒，文件上传处理目标不超过 3 秒。
- 沙盒数据以管理数据库为准，每周全量刷新，并通过增量同步维持准实时一致。
- 原始同步状态不对普通用户展示，失败由系统重试并向运维告警。
- 提示词内容可能包含业务规则，需要加密存储。

## §2 业务场景判断

### 2.1 业务定位

本需求是在企业财富+和财富小助之间新增一套 Skill 生命周期与分发能力。Skill 不只是提示词文本，也是一项具有创建者、所属分行、共享范围、订阅范围、个人使用状态、版本、评分和运行副本的业务资产。

### 2.2 与现有能力的关系

- 复用企业财富+的登录身份、组织归属和功能权限，不再建立第二套人员体系。
- 复用应用可见范围与功能权限分离的原则：看得见某个 Skill，不自动代表能够编辑或管理它。
- 复用财富小助作为运行入口，不在管理端重复建设对话执行能力。
- 新增 Skill 资产、分行订阅关系、个人退出状态、版本记录、版本评分、复制来源和同步日志。

### 2.3 治理模式变化

需求把原本分散的个人提示词变为可跨分行传播、按分行开通并由财富小助执行的正式资产。虽然发布不需要审核，但仍必须清楚记录内容所有权、共享动作、订阅动作、版本变化和管理者操作，避免组织级结果无法追溯。

### 2.4 最大业务不确定性

最大不确定性是共享关系变化后的既有订阅如何处理，尤其是创建者取消共享时，其他分行已经建立的订阅是否立即失效。如果这一判断错误，Skill 的可用范围计算、取消共享影响提示、财富小助联想结果和沙盒删除策略都需要重做。

## §3 需求成立性判断

### 3.1 价值判断

- [FACT] 各分行当前分散维护提示词，存在重复创建、难以共享和更新成本高的问题。
- [CONFIRMED] 建立统一 Skill 资产与广场，可以让优秀实践跨分行复用，并缩短客户经理寻找和调用提示词的路径。
- [CONFIRMED] 复制、版本评分和历史还原使 Skill 能在保留来源和历史的前提下持续改进。

### 3.2 系统代价

- [CONFIRMED] 订阅不再是单层关系：系统既要保存分行整体开通关系，也要保存个人退出状态。
- [CONFIRMED] Skill 是否可调用需要联合判断所有权、共享关系、所属分行、分行订阅和个人退出状态。
- [CONFIRMED] 管理端与沙盒异步解耦，必须处理保存成功但运行端暂未生效的时间差。
- [CONFIRMED] 复制、编辑、还原和评分都与版本关联，会增加版本一致性、评分归属和同步管理成本。

### 3.3 更低成本替代路径

可以只建设由总行统一维护的静态提示词库，并在财富小助提供固定调用入口。这一方案开发和治理成本更低，但无法满足分行自主创建、跨分行复用、个人复制改造和版本持续优化的目标，只适合作为短期过渡。

### 3.4 成立性结论

[CONFIRMED] 用户问题和复用价值成立，系统代价也与目标规模相匹配，建议进入正式体验设计。正式设计必须优先解决多层可用范围、组织级操作影响、版本对应关系和跨端生效反馈，不能只围绕广场卡片和编辑表单展开。

## §4 推荐业务边界

### 4.1 推荐能力形态

- [CONFIRMED] 以创建者个人所有权为基础，每个 Skill 只归一个创建者所有，并记录所属分行。
- [CONFIRMED] 未共享 Skill 是创建者的个人资产，仅创建者本人可见、可调用。
- [CONFIRMED] 创建者共享后，Skill 进入全行可见的共享范围，同时自动对创建者所属分行开放使用。
- [CONFIRMED] 其他分行通过一次分行订阅整体开通；分行内个人可退出使用，但不能通过个人取消撤销分行开通。
- [CONFIRMED] 所有可见用户可以复制 Skill，复制品成为复制者独立所有的新 Skill。
- [CONFIRMED] 版本评分与具体版本绑定，历史版本可以查看和还原。
- [CONFIRMED] 总行管理者作为最高权限角色，可以管理全部 Skill。

### 4.2 与现有能力的边界

- [CONFIRMED] 企业财富+负责 Skill 的资产管理、共享、分行订阅、版本和评分查询。
- [CONFIRMED] 财富小助负责展示当前用户可调用的 Skill，并执行被选择的 Skill。
- [CONFIRMED] 沙盒承担运行副本和查询，不作为 Skill 所有权、订阅或版本事实的最终来源。
- [FACT] 企业现有身份、组织和权限体系继续决定用户身份与管理入口权限。

### 4.3 不推荐的能力形态

- [CONFIRMED] 不恢复内容审核或发布审批状态。
- [CONFIRMED] 不允许同分行其他用户代替创建者编辑、共享或取消共享。
- [CONFIRMED] 不把个人取消解释为全分行取消订阅。
- [CONFIRMED] 不让复制品继承原 Skill 的订阅、调用、历史版本或评分。
- [CONFIRMED] 不以沙盒缓存状态反向覆盖管理数据库中的正式资产关系。

### 4.4 仍需收口的边界

- [GAP] 取消共享后，其他分行已经建立的订阅是否继续有效。
- [GAP] 创建者所属分行的自动可用是否计入“订阅分行数”。
- [GAP] 个人退出后恢复使用的业务动作与记录规则尚未明确。

## §5 角色、功能、规则范围

### 5.1 角色职责

#### Skill 创建者

- 创建、编辑、发布、删除自己的 Skill。
- 共享或取消共享自己的 Skill。
- 查看自己的全部版本、版本评分和优化结果。
- 还原自己的历史版本。
- 对自己可见的 Skill 发起复制。

#### 分行普通用户与客户经理

- 浏览已发布且已共享的 Skill。
- 对共享 Skill发起分行订阅，使本分行整体可用。
- 使用本分行成员已共享或本分行已订阅的 Skill。
- 个人取消使用已由分行订阅的 Skill；该操作不影响其他同分行用户。
- 复制自己当前可见的 Skill。

#### Skill 所属分行用户

- 自动使用本分行成员已经共享的 Skill。
- 查看本分行 Skill 的当前及历史版本评分。
- 不得编辑、共享、取消共享或还原其他创建者的 Skill。

#### 总行管理者

- 以最高权限查看和管理全部 Skill。
- 可代为编辑、共享、取消共享、删除、复制和还原历史版本。
- 处理跨分行治理和异常资产处置。

#### 运维人员

- 接收同步失败和运行异常告警。
- 查询同步日志并执行恢复动作。
- 不因运维职责自动获得提示词业务内容的编辑权。

### 5.2 功能闭环

| 功能 | 输入 | 系统处理 | 输出与结果 |
| --- | --- | --- | --- |
| 创建 Skill | 名称、描述、提示词，或 Markdown 文件 | 校验格式与长度，生成 Skill 和首个版本 | 创建者获得一个可独立管理的 Skill |
| 编辑 Skill | 当前 Skill 与修改内容 | 校验创建者或总行管理者权限，生成新版本并触发同步 | 新版本成为当前版本，历史版本保留 |
| 共享/取消共享 | 创建者或总行管理者操作、目标 Skill | 更新共享状态并触发可用范围变化与同步 | 共享时进入广场并对所属分行自动可用；取消共享影响待确认 |
| 分行订阅 | 共享 Skill、操作用户所属分行 | 若分行未订阅则建立一条分行开通关系 | 该分行用户获得使用资格，订阅分行数增加一次 |
| 个人取消 | 当前用户、分行已订阅 Skill | 记录个人退出，不删除分行订阅关系 | 该 Skill 不再出现在该用户的联想结果中，其他人不受影响 |
| 复制 Skill | 当前用户可见的源 Skill | 新建归复制者所有的独立 Skill，并记录来源 | 复制品默认不共享，不继承原资产的订阅、调用、版本和评分 |
| 查看版本与评分 | Skill、目标版本、查看人身份 | 校验所属分行或总行管理者权限并读取版本评分 | 展示目标版本的内容、得分、结论和建议 |
| 还原历史版本 | 目标历史版本、创建者或总行管理者操作 | 用历史内容生成新的最新版本并触发重新评分和同步 | 新版本成为当前版本，原历史记录不删除 |
| 删除 Skill | Skill、创建者或总行管理者操作 | 删除正式资产、解除相关使用关系并触发沙盒清理 | Skill 不再可见、可订阅或调用，操作不可恢复 |
| 智能联想与调用 | “/”及后续关键词、当前用户身份 | 计算用户可用 Skill，排除个人已取消项，匹配名称并执行 | 返回匹配 Skill 或 AI 执行结果 |

### 5.3 关键业务规则

#### 所有权规则

- [CONFIRMED] Skill 默认归创建者个人所有。
- 触发：用户创建或复制 Skill。
- 结果：创建者获得编辑、共享、取消共享、删除和历史还原权。
- 不满足时：非创建者不得修改，只有总行管理者可以越过个人所有权执行管理操作。

#### 可见与可用规则

- [CONFIRMED] 未共享 Skill 仅创建者本人可见、可用。
- [CONFIRMED] 已共享 Skill 对全行用户可见，并对所属分行自动可用。
- [CONFIRMED] 其他分行只有建立分行订阅关系后才获得使用资格。
- 不满足时：不进入用户的可用 Skill 集合，也不得通过财富小助直接调用。

#### 两层订阅规则

- [CONFIRMED] 分行首位用户订阅时，建立分行整体开通关系。
- [CONFIRMED] 分行订阅后，全分行用户默认可用。
- [CONFIRMED] 个人取消只记录个人退出，不删除分行订阅，不影响其他人，不减少订阅分行数。
- [GAP] 个人退出后如何恢复个人使用尚待确认。

#### 复制规则

- [CONFIRMED] 所有能够看到源 Skill 的用户均可复制。
- [CONFIRMED] 复制品归复制者所有、默认不共享，并保留来源关系。
- [CONFIRMED] 复制品不继承原 Skill 的订阅、调用记录、历史版本和评分。
- 不满足时：源 Skill 已删除或当前用户不可见时，不创建复制品，并告知用户返回可用 Skill 范围重新选择。

#### 版本与评分规则

- [FACT] 每次编辑保存形成一个新版本，历史版本保留。
- [CONFIRMED] 还原历史版本时生成新的最新版本，不覆盖或删除原记录。
- [CONFIRMED] 评分与具体版本绑定，历史评分可查看；还原形成的新版本需要重新评分。
- [CONFIRMED] 评分仅向 Skill 所属分行用户和总行管理者开放。

#### 同步与生效规则

- [FACT] 创建、编辑、删除、订阅变化触发异步增量同步，每周执行一次全量同步。
- [FACT] 管理端操作成功不等待沙盒同步结果。
- [CONFIRMED] 管理数据库是正式事实来源，沙盒只保存运行副本。
- 不满足时：系统自动重试并向运维告警；普通用户不得看到无法行动的技术日志。

## §6 状态、异常与边界

### 6.1 核心状态

| 状态 | 说明 | 用户下一步 |
| --- | --- | --- |
| 已发布未共享 | Skill 已创建并可由创建者使用，仅创建者和总行管理者可管理 | 创建者可编辑、共享、复制、还原或删除 |
| 已发布已共享 | Skill 进入广场，对所属分行自动可用，可被其他分行订阅 | 可浏览、复制或发起分行订阅 |
| 分行未订阅 | 共享 Skill 对该分行可见但尚未整体开通 | 分行任意用户可发起订阅 |
| 分行已订阅、个人可用 | 分行已整体开通，当前用户未退出 | 用户可在财富小助中联想和调用 |
| 分行已订阅、个人已取消 | 分行关系仍有效，但当前用户选择退出 | 不在该用户联想结果中展示；恢复方式待确认 |
| 新版本同步中 | 管理数据已保存，运行副本正在更新 | 用户等待生效或继续使用当前可用版本，具体回退规则待确认 |
| 同步失败 | 管理数据已保存，但运行副本未完成更新 | 系统自动重试；持续失败由运维处理 |
| 已删除 | 正式资产和使用关系进入不可用状态 | 用户返回可用 Skill 范围选择其他 Skill |

### 6.2 关键状态流转

- 创建：新建或上传 → 已发布未共享。
- 共享：已发布未共享 → 已发布已共享 → 进入广场并对所属分行自动可用。
- 外部分行开通：分行未订阅 → 任意用户发起订阅 → 分行已订阅、个人可用。
- 个人退出：分行已订阅、个人可用 → 当前用户取消 → 分行已订阅、个人已取消。
- 编辑：当前版本 → 保存修改 → 生成新版本 → 异步同步 → 新版本可调用。
- 历史还原：选择历史版本 → 生成新的最新版本 → 重新评分与同步。
- 删除：任一有效状态 → 创建者或总行管理者确认删除 → 已删除。

### 6.3 关键异常

| 异常 | 触发条件 | 系统处理结果 | 用户下一步 |
| --- | --- | --- | --- |
| 文件格式错误 | 上传文件不是 `.md` | 拒绝解析，不创建 Skill | 重新选择符合格式的文件 |
| 文件过大或编码不支持 | 文件超过 1MB 或非 UTF-8 | 保留当前任务，停止上传 | 调整文件后重新上传 |
| 必填内容缺失 | 名称、描述或提示词为空 | 不保存并指出具体缺失项 | 补齐后再次提交 |
| Skill 名称冲突 | 名称违反唯一性规则 | 不创建或不保存当前名称 | 修改名称后重试；唯一性范围待确认 |
| 无编辑权限 | 非创建者且非总行管理者尝试修改 | 不改变数据 | 返回只读范围或联系创建者/总行管理者 |
| 重复分行订阅 | 分行已存在订阅关系 | 不重复新增，不增加订阅分行数 | 直接使用或根据个人状态恢复使用 |
| 个人重复取消 | 当前用户已处于个人退出状态 | 保持原状态，不影响分行关系 | 无需重复操作，可返回广场或其他 Skill |
| 复制源不可用 | 源 Skill 已删除或当前用户已失去可见性 | 不创建复制品 | 返回当前可见 Skill 重新选择 |
| 版本评分暂未生成 | 新版本评分尚在处理或失败 | 保留版本内容，不伪造评分 | 稍后重试或查看其他已有评分版本 |
| 历史版本还原失败 | 版本读取、保存或同步失败 | 不改变当前正式版本，记录失败原因 | 重新发起还原或联系管理者 |
| 删除已被订阅的 Skill | 删除对象存在外部分行订阅 | 在执行前识别影响范围，删除后解除相关关系 | 创建者或总行管理者确认影响后继续或取消 |
| 增量同步失败 | 消息、同步服务或沙盒异常 | 自动按既定策略重试并告警，正式数据保留 | 普通用户等待恢复；运维查看日志处理 |
| Skill 加载超时 | 财富小助无法在目标时间取得 Skill | 终止本次加载并记录异常 | 重试或选择其他 Skill |
| Skill 执行超时 | AI 执行超过限制 | 终止本次请求并记录异常 | 稍后重试，不重复提交敏感信息 |

### 6.4 边界冲突处理

- [GAP] 取消共享与既有外部分行订阅的关系未定，不能在下游默认“继续有效”或“立即失效”。
- [GAP] 同步失败时是否继续执行上一可用版本未定，不能默认把未同步的新版本视为可调用版本。
- [GAP] Skill 名称唯一性是全行、分行还是创建者个人范围未定。

## §7 体验蓝图承接要求

### 7.1 Skill 归属与权限

- **业务判断：**Skill 归创建者个人所有，仅创建者和总行管理者可修改；共享不转移所有权。
- **体验影响：**同一 Skill 对不同角色可见，但可执行的管理动作不同。
- **必须承接的问题：**让用户能理解 Skill 的创建者、所属分行、自己的角色与可操作范围，并在动作前知道为何能做或不能做。
- **禁止下游重判：**不得赋予同分行其他用户编辑、共享、取消共享或还原权限。

### 7.2 共享、可见与可用

- **业务判断：**未共享 Skill 仅创建者可见可用；共享后全行可见、所属分行自动可用，其他分行需订阅后可用。
- **体验影响：**“看得见”与“能调用”不是同一状态，用户需要理解当前 Skill 的来源和可用原因。
- **必须承接的问题：**明确区分所有权、共享范围、分行开通和个人使用状态，保证相同概念跨管理端与财富小助一致。
- **禁止下游重判：**不得把共享直接等同于所有分行可调用，也不得把可见等同于可编辑。

### 7.3 分行订阅与个人退出

- **业务判断：**订阅是分行整体开通；个人取消只让当前用户退出，不撤销分行关系。
- **体验影响：**同一分行内不同用户可能看到不同的个人使用状态，但订阅分行数保持一致。
- **必须承接的问题：**让订阅发起人理解组织级影响，让个人取消者理解只影响自己，并说明个人退出后的恢复路径。
- **禁止下游重判：**不得用单一二态订阅开关同时代表分行订阅和个人退出，不得因个人取消减少订阅分行数。

### 7.4 复制与来源

- **业务判断：**所有可见用户可复制；复制品是归复制者所有的独立私有 Skill，不继承源 Skill 的运行和历史数据。
- **体验影响：**用户需要区分“修改原 Skill”和“基于原 Skill 创建副本”，并理解副本不会自动共享或沿用原效果证明。
- **必须承接的问题：**表达复制后的归属、默认范围、来源关系和与原 Skill 的独立性。
- **禁止下游重判：**不得让复制操作直接修改源 Skill，或继承原 Skill 的订阅、调用、版本和评分。

### 7.5 版本、评分与还原

- **业务判断：**评分与版本绑定；历史版本可查看，创建者和总行管理者可还原，还原会生成新版本并重新评分。
- **体验影响：**用户需要准确判断当前版本、历史版本、对应评分以及还原后的实际生效版本。
- **必须承接的问题：**维持版本内容、评分时间、评分结论和还原结果的一一对应，并解释新版本评分尚未完成的状态。
- **禁止下游重判：**不得覆盖或删除历史版本，不得把历史评分直接视为还原后新版本的当前评分。

### 7.6 异步生效与运行一致性

- **业务判断：**管理数据保存成功后异步同步到沙盒，管理数据库是事实来源，但财富小助只能执行已到达运行环境的版本。
- **体验影响：**用户可能遇到管理端已成功、财富小助暂未更新的时间差。
- **必须承接的问题：**在不暴露技术同步细节的前提下，让用户知道当前是否可调用、实际使用哪个版本、异常时应等待还是重试。
- **禁止下游重判：**不得把保存成功直接表达为财富小助已经完成生效，也不得向普通用户暴露消息队列、接口或缓存错误原文。

### 7.7 组织级影响与可追溯性

- **业务判断：**共享、分行订阅、取消共享、删除和总行管理操作会影响多人或多个分行。
- **体验影响：**用户需要在关键动作前理解影响范围，发生问题后也需要定位操作者和变化来源。
- **必须承接的问题：**覆盖关键动作的影响说明、结果解释和变更追踪，优先保证删除、取消共享和最高权限操作可追溯。
- **禁止下游重判：**不得将组织级变化包装成无影响的个人偏好操作。

## §8 约束与不做什么

### 8.1 硬约束

- [FACT] Skill 创建、编辑和发布均不需要审核。
- [CONFIRMED] 未共享 Skill 仅创建者本人可见、可用。
- [CONFIRMED] 创建者所属分行仅创建者本人可以共享或取消共享自己的 Skill。
- [CONFIRMED] 同分行成员共享的 Skill 对本分行自动可用。
- [CONFIRMED] 外部分行订阅后全分行开通，个人取消只影响本人。
- [CONFIRMED] Skill 评分只向所属分行用户和总行管理者展示。
- [CONFIRMED] 总行管理者拥有最高管理权限。
- [FACT] 订阅量按分行数统计。

### 8.2 系统依赖

- 企业身份、用户所属分行和总行管理者角色判断。
- 企业财富+的功能权限与可见范围。
- 财富小助的联想和执行能力。
- Skill 版本评分服务。
- 消息队列、同步服务、沙盒缓存及运维告警能力。

### 8.3 本期不做

- [CONFIRMED] 不做任何内容审核、发布审核或审批流。
- [CONFIRMED] 不允许普通分行用户编辑或治理他人 Skill。
- [CONFIRMED] 不允许个人取消撤销全分行订阅。
- [CONFIRMED] 不让复制品继承源 Skill 的订阅、调用、版本和评分。
- [CONFIRMED] 不公开展示底层同步日志和技术错误信息。
- [FACT] 不支持删除历史版本。

## §9 待确认问题

### 层级一：影响主策略的问题

#### 1. 取消共享如何影响既有外部分行订阅

- **问题：**创建者取消共享后，已经订阅的其他分行是继续可用、立即失效，还是只禁止新增订阅。
- **影响：**决定可用范围计算、取消共享前的影响说明、沙盒清理和客户经理联想结果。
- **建议确认方：**Skill 产品负责人、财富小助负责人、总行管理者代表。

#### 2. 新版本同步失败时是否保留上一可用版本

- **问题：**编辑或还原产生的新版本未同步成功时，财富小助是否继续执行上一个成功版本。
- **影响：**决定业务连续性、版本解释和失败恢复策略。
- **建议确认方：**财富小助技术负责人、同步服务负责人、Skill 产品负责人。

### 层级二：影响局部体验设计的问题

#### 1. 个人退出后的恢复规则

- **问题：**个人取消后，通过什么业务动作恢复在财富小助中的可见与使用。
- **影响：**决定个人状态闭环和重复订阅的解释。
- **建议确认方：**Skill 产品负责人。

#### 2. 所属分行是否计入订阅分行数

- **问题：**Skill 所属分行因共享而自动可用，是否同时计为一个订阅分行。
- **影响：**决定广场统计数字和价值指标口径。
- **建议确认方：**业务运营负责人、数据指标负责人。

#### 3. Skill 名称唯一性范围

- **问题：**名称需要在全行、分行还是创建者个人范围内唯一。
- **影响：**决定复制命名、搜索结果辨识和名称冲突处理。
- **建议确认方：**Skill 产品负责人、技术负责人。

#### 4. 评分生成规则

- **问题：**每次创建、编辑、复制和还原分别何时触发评分，评分失败是否允许版本继续使用。
- **影响：**决定版本评分状态、等待关系和异常恢复。
- **建议确认方：**评分服务负责人、Skill 产品负责人。

### C. 当前设计判断

- Skill 是带所有权、组织范围、版本和运行副本的业务资产，不是普通提示词文本。
- 分行整体订阅与个人退出必须建模为两层状态，不能只保存单一开关结果。
- 复制形成新的独立 Skill，来源关系只用于追溯，不形成内容联动。
- 历史还原应生成新版本，避免覆盖既有历史和评分关系。
- 普通用户不需要看到技术同步状态，但必须能够判断当前是否可调用及如何恢复。
