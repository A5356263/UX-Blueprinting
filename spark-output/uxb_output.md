# 需求定案：资产配置面客版

## §0 关键设计判断

**判断：** 本次将月度诊断报告改造为实时资产配置功能，底层业务骨架复用企业财富+现有能力，但信息组织方式从"静态报告"变为"交互式配置工具"，体验设计压力集中在信息分层和链路转化上。

**主要影响：** 六大模块同屏承载带来信息过载风险；账号和时间双维度筛选的联动范围需要明确；推荐到购买的链路流畅度直接影响业务 KPI。

**建议方案：** 优先确定信息浏览优先级再做页面承载设计；明确"全部账号"的数据语义后再展开模块设计；诊断结果与推荐方案之间应建立可感知的承接关系。

**不建议方案：** 不建议把六个模块平铺展示不加分层；不建议在账号"全部"语义未确定前开始页面设计；不建议让购买跳转路径超过两步。

**关键待确认：** 账号"全部"选项的数据汇总方式、下载建议书的数据快照范围、诊断与推荐的关联逻辑。

## §1 需求输入摘要

### 背景与目标

- **来源：** `input/【财富专区】资产配置面客版/【财富专区】资产配置面客版.md`
- **核心任务：** 将原"月度诊断报告"改造为"资产配置功能"，提供面向企业客户的资产配置建议书
- **业务目标：** 优化持仓展示和诊断规则，提供产品推荐和操作功能
- **价值指标：** 建议书查看量、产品购买笔数（目标值待定）

### 用户角色

| 角色 | 优先级 | 关注点 |
|------|--------|--------|
| 企业客户 | 高 | 查看资产配置建议、产品推荐 |
| 客户经理 | 中 | 了解客户资产配置情况 |

### 功能范围

本次覆盖：资产配置建议书的查看、账号切换、时间筛选、持仓表现查看、投资分布/期限分布浏览、持仓诊断、产品推荐、建议书下载（PDF/PNG）。

本版本不做：持仓概览模块、历史建议书保存、其他业务的期限分布细化分类、其他业务的投资分布细化分类、产品到期诊断中的开放期/可赎回产品。

### 数据来源

所有源数据由企业财富+资产配置提供。前端不自主计算，仅做展示和下载。

### 明确约束

- 持仓表现、持仓诊断、产品推荐：仅支持理财
- 投资分布、期限分布：支持理财 + 公募基金 + 资管计划 + 信托计划
- 去掉白名单逻辑，所有有权限用户可见
- 数据计算 ≤ 5 秒，页面加载 ≤ 3 秒

---

## §2 业务场景判断

**业务定位：** 本次是**既有模块的功能升级**。"月度诊断报告"更名为"资产配置"，从定期报告变为实时交互工具，不是新增业务域，也不是替代外部系统。

**与现有能力的关系：** 完全依赖企业财富+资产配置提供数据，前端承担展示和交互职责。持仓列表增加入口，与财富专区菜单形成双入口结构。

**最大业务不确定性：** 企业财富+资产配置的数据计算能力和响应速度直接决定了前端体验质量。文档虽然有降级策略，但"全部账号"和"自定义时间区间"的数据计算量比原来的单月报告大得多，后端能否在 5 秒内稳定返回是关键前提。

**如果这个判断错了：**
- 如果企业财富+资产配置无法按时稳定交付接口，整个资产配置页面的可用性将不成立
- 如果"仅支持理财"的业务范围在后续版本需要扩展到其他业务类型，页面结构和信息架构需要重新设计，当前建议方案不兼容未来扩展

---

## §3 需求成立性判断

### 收益

- 从"看报告"升级为"做配置"，提升客户投资决策效率
- 产品推荐带购买入口，缩短从建议到行动的路径
- 支持自定义时间区间，比原来固定月度查看更灵活
- 下载能力满足客户留存和分享需求

### 代价

- 六大模块同屏承载，信息复杂度高，开发成本不低
- 完全依赖企业财富+数据源，前端缺乏自主容错能力
- 业务范围（仅理财）与用户期望（全业务）可能存在差距

### 更低成本替代路径

如果仅做月度报告的轻量升级（优化展示 + 增加下载），而不是改造成实时交互工具，开发成本更低。但这样做无法解决"产品推荐不带购买入口"的核心业务问题，也达不到提升购买转化率的目标。

### 结论

**建议进入正式体验设计。** 业务价值清晰（从报告到配置的升级），收益大于代价，且没有更低成本的路径能达到同样的业务目标。

## §4 推荐业务边界

### 在范围内

- 资产配置建议书的查看和交互浏览
- 多银行账号的选择和切换
- 自定义时间区间的筛选
- 持仓表现（仅理财）、投资分布（多业务）、期限分布（多业务）的展示
- 持仓诊断（仅理财）及诊断详情查看
- 产品推荐（仅理财）及购买跳转
- 建议书下载（PDF/PNG）

### 不在范围内

- 资产配置建议书的编辑和自定义
- 历史建议书的保存、查看和删除（本版本不做）
- 持仓概览模块（本版本不做）
- 其他业务的期限分布和投资分布细分类（本版本不做）
- 产品到期诊断中的开放期/每日可赎回产品（本版本不做）
- 客户经理的独立视图或管理功能

### 边界说明

- 本次不改变账户、持仓、产品等业务对象的关系
- 本次不新增外部回写链路（购买跳转现有流程）
- 本次不改变数据口径（年化收益率等计算公式已有明确说明）

## §5 角色、功能、规则范围

### 角色与职责

| 角色 | 职责 | 关键任务 |
|------|------|----------|
| 企业客户 | 查看资产配置建议书，了解持仓情况和优化建议，执行产品购买 | 选择账号 → 查看全貌 → 分析诊断 → 获取推荐 → 执行购买 |
| 客户经理 | 了解客户资产配置情况（文档标注中优先级，具体使用场景待补充） | 查看指定客户的资产配置概况 |

### 功能单元

| 功能 | 输入 | 处理 | 输出 | 结果 |
|------|------|------|------|------|
| 账号选择 | 用户从有效账号列表中选择（默认全部） | 切换账号后所有模块联动刷新 | 各模块展示对应账号的数据 | 用户可查看不同账号的配置情况 |
| 时间区间筛选 | 用户选择自定义时间区间（默认近一个月） | 持仓表现各指标按区间重新计算 | 更新后的持仓表现数据 | 用户可查看不同时间维度的表现 |
| 持仓表现查看 | 选定的账号和时间区间 | 取区间结束时间点余额、区间收益、区间年化收益率、购买/赎回数据、走势图、收益排行 | 持仓金额、较期初、区间收益、年化收益率、笔数、金额、走势图、排行 | 用户了解选定区间内的持仓表现 |
| 投资分布查看 | 选定的账号 | 按业务类型汇总持仓金额和占比 | 理财（按产品特点汇总，含年化收益率及排名）+ 其他业务（按类型汇总金额和占比） | 用户了解资产在各类产品中的分布 |
| 期限分布查看 | 选定的账号 | 按产品期限汇总持仓金额和占比 | 理财（含年化收益率）+ 其他业务（按持有期汇总金额和占比） | 用户了解资产在不同期限的分布 |
| 持仓诊断 | 选定的账号 | 执行诊断规则，识别问题 | 集中度诊断、到期诊断、持仓时间诊断 | 用户了解持仓存在的问题 |
| 产品推荐 | 选定的账号 | 取企业财富+资产配置推荐数据，过滤不可购买和额度不足产品 | 建议持有类型、产品信息、收益率、最大回撤、推荐理由 | 用户获得可执行的优化建议 |
| 建议书下载 | 用户点击下载 | 生成 PDF 或 PNG 文件 | 下载文件 | 用户获得可保存或分享的建议书 |
| 产品详情查看 | 用户点击产品名称 | 跳转产品详情页 | 产品详情页 | 用户了解产品详细信息 |
| 产品购买 | 用户点击购买按钮 | 跳转购买页（单个）或购物车（批量） | 购买页或购物车 | 用户完成购买流程 |

### 关键业务规则

| 规则 | 触发条件 | 处理结果 | 不满足时处理 |
|------|----------|----------|-------------|
| 持仓集中度诊断 | 活钱管理持仓占比 ≥ 60% | 展示诊断结果和详情 | 不展示该诊断模块 |
| 产品到期诊断 | 产品在未来两周内到期 | 展示到期产品列表 | 不展示该诊断模块 |
| 持仓时间过长诊断 | 灵活产品持仓＞2个月，或短期产品持仓＞3个月 | 展示对应产品列表 | 不展示该诊断模块 |
| 产品推荐过滤 | 产品不可购买或额度不足 | 从推荐列表中移除 | 推荐列表仅显示可购买产品 |
| 金额单位换算 | 金额达到对应阈值 | 按元/万元/亿元换算展示 | 按当前金额范围选择合适单位 |
| 空值处理 | 数据为空或缺失 | 展示"--" | 文本类字段不展示 |
| 收益率正负号 | 收益率数据 | 正数显示"+"，负数显示"-" | 无 |

## §6 状态、异常与边界

### 核心状态

| 状态 | 说明 | 系统处理结果 | 用户下一步 |
|------|------|-------------|-----------|
| 页面初始加载 | 用户进入资产配置页面 | 加载账号列表和默认数据 | 等待数据加载完成 |
| 数据加载中 | 请求资产配置数据 | 展示加载指示器 | 等待 |
| 数据加载完成 | 所有模块数据就绪 | 展示完整体验蓝图 | 浏览各模块内容 |
| 账号切换中 | 用户切换选择的账号 | 各模块数据重新加载 | 等待新账号数据加载 |
| 时间区间变更中 | 用户选择新的时间区间 | 持仓表现模块数据更新 | 等待数据更新 |
| 下载进行中 | 用户点击下载 | 生成文件并触发下载 | 等待下载完成 |
| 无持仓数据 | 账号下没有持仓 | 展示空状态（图标 + "暂无持仓数据" + 引导文案） | 点击"去购买"跳转产品列表 |
| 模块无数据 | 某模块无可用数据 | 展示对应空状态提示 | 无引导操作 |
| 无诊断问题 | 诊断无异常 | 不展示诊断模块 | 无 |

### 关键异常

| 异常 | 触发条件 | 系统处理 | 用户下一步 |
|------|----------|----------|-----------|
| 接口超时 | 企业财富+接口响应 > 5秒 | 自动重试3次，失败后展示缓存或空状态 | 稍后重试 |
| 接口错误码 | 接口返回 500/503/401/403/404/999 | 展示对应错误提示 | 按提示处理（重新登录、联系管理员等） |
| 接口无响应 | 服务完全不可用 | 展示"系统繁忙"提示 | 稍后再试 |
| 部分数据缺失 | 某模块数据缺失 | 展示可用数据，缺失字段显示"--" | 无（后台异步补全） |
| 数据计算异常 | 数据计算失败 | 该模块展示"功能暂时不可用" | 无 |
| 下载失败 | 文件生成失败 | 提示"文件生成失败，请稍后重试" | 稍后重试 |
| 网络中断 | 下载过程中网络断开 | 终止下载，提示"网络异常" | 检查网络后重试 |
| 存储空间不足 | 设备空间不足 | 提示用户清理空间 | 清理后重试 |
| 浏览器拦截下载 | 浏览器拦截弹出下载 | 引导用户允许下载 | 允许浏览器下载 |

## §7 体验蓝图承接要求

| 业务判断 | 体验影响 | 必须承接的问题 | 禁止下游重判 |
|----------|----------|---------------|-------------|
| 六大模块同屏承载，信息密度高 | 用户可能不知道从哪看起，容易迷失 | 设计信息分层方案，区分"概览级摘要"和"详情级内容"的浏览节奏 | 禁止不区分层级直接平铺所有模块 |
| 账号"全部"选项语义未定 | "全部"的含义（汇总/逐个/对比）会完全改变各模块的展示方式 | 在确定"全部"的展示方式前，保持模块结构的灵活性 | 禁止假设"全部=汇总"直接固定设计 |
| 诊断结果和推荐方案缺乏关联表达 | 用户可能认为推荐与诊断无关，降低信任感 | 设计诊断发现到推荐方案之间的逻辑承接关系（如：诊断问题 → 对应推荐策略） | 禁止诊断和推荐独立展示不做关联 |
| 仅理财 vs 多业务的支持范围不一致 | 用户可能困惑为什么某些模块看不到其他业务类型 | 在每个模块层面清晰表达业务覆盖范围，让用户理解差异 | 禁止统一口径或隐藏差异 |
| 产品推荐到购买的链路长度影响转化率 | 跳转步骤越多，购买转化越低 | 最小化推荐到购买的路径，保持购买意图的连续性 | 禁止设计超过两步的跳转链路 |
| 下载需"全部平铺"但页面含交互筛选 | 下载时的数据快照范围不明确，影响下载功能的实现方案 | 明确下载是按当前筛选条件还是全量数据 | 禁止在未确定快照范围前设计下载交互 |
| 两个入口的账号上下文继承 | 从持仓列表进入时应自动选中当前账号，从菜单进入则默认全部 | 处理好两个入口的账号选中状态差异 | 禁止两个入口使用完全相同的初始状态 |

## §8 约束与不做什么

### 硬约束

- 所有源数据必须由企业财富+资产配置提供，前端不做自主计算
- 数据计算响应必须 ≤ 5 秒，页面加载 ≤ 3 秒
- 支持同时 1000 用户在线
- 历史建议书数据保留至少 6 个月（接口侧）
- 需要验证用户对银行账号的访问权限
- 收益率数据仅供测算参考，不影响客户实际收益

### 不做什么

- 不做持仓概览模块（本版本）
- 不做历史建议书的保存、查看、删除（本版本）
- 不做其他业务的投资分布细分类（本版本）
- 不做其他业务的期限分布细分类（本版本）
- 不做产品到期诊断中的开放期/可赎回产品（本版本）
- 不改变账户、持仓、产品等核心业务对象的关系
- 不新增外部回写链路
- 不新增购买流程（复用现有购买页和购物车）
- 不做客户经理独立视图或管理功能

### 知识支撑

本次分析未使用项目知识库的既有业务知识（项目知识库覆盖人事、企业设置等领域，与银行财富管理无交集）。

### AI 设计判断

| 判断 | 类型 | 依据 |
|------|------|------|
| 底层业务骨架未变，体验设计压力高 | 知识支持的推断 | 复杂度判断框架：不改对象、规则、状态、生效、口径、回写；但信息密度高 |
| 六大模块需要信息分层 | 设计判断 | 信息密度高 → 需要浏览优先级设计 |
| 诊断和推荐应建立关联 | 设计判断 | 从诊断到推荐是客户决策的自然路径，断开会降低信任感 |
| 建议进入正式体验设计 | 设计判断 | 收益大于代价，无更低成本替代方案 |
