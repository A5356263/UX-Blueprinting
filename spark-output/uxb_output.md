# UXB 需求定案：子管理员权限复制

---

## §0 本次关键判断

**判断：** 在子管理员现有权限模型上新增批量复制能力，底层权限骨架不变，但"叠加"逻辑引入的来源透明性问题是体验成败的关键。

**主要影响：** 复制操作改变了子管理员的创建路径——从逐个手动配置变为从来源一次性复制。批量 200 人的规模要求结果核对和异常处理必须有闭环，否则管理员的信任成本反而高于手动逐个配。

**建议方案：** 在复制弹窗和操作记录基础上，必须增加复制结果核对环节（成功/失败/审批中分列），以及叠加后权限来源的展示能力。

**不建议方案：** 只做复制弹窗和成功 toast，不加结果核对和权限来源解释——这会直接把批量操作的高风险暴露给管理员，出了错只能逐个手动排查。

**关键待确认：** 复制来源的子管理员权限范围扩散是否存在越权风险；校验规则中"加入状态"的目标值需产品统一为"已加入"或"已启用"。

---

## §1 需求输入摘要

### 背景

集团型企业使用「子管理员模式」下放权限管理能力。部分客户（如广西交投）存在 200+ 子管理员，其"可授权功能"通常一致，仅"可授权组织"不同。当前需逐个子管理员单独勾选相同功能权限，配置效率低。

### 目标用户

- 权限管理员 / 超级管理员：执行复制操作的人
- 子管理员：作为复制来源
- 复制对象用户：作为复制目标，可能是普通用户或已有子管理员

### 业务目标

- 将已配置子管理员的权限信息（可授权组织、可授权功能）复制给其他用户
- 降低批量配置子管理员的重复操作成本
- 支持将普通用户通过复制快速设为子管理员
- 对已有子管理员采用叠加方式扩展授权范围

### 功能范围

- 子管理员列表新增「复制」入口
- 复制弹窗：选择复制内容（可授权组织/可授权功能）+ 选择复制对象（支持多选，最多 200 人）
- 前置校验：复制信息勾选 → 复制对象选择 → 加入状态 → 认证状态
- 复制成功 toast + 操作记录生成
- 双管理员互审模式下触发审批

### 明确约束

- 复制入口仅出现在子管理员模式列表
- 复制来源必须是已有子管理员
- 复制信息至少选一项，复制对象至少选一名
- 复制对象最多 200 名
- 复制对象必须已加入企业且已实名认证
- 已有子管理员接收复制时叠加、不覆盖
- 普通用户接收复制后成为子管理员

### 输入缺口

- "加入状态"出现"已启用"和"已加入"两种表述，需产品统一口径
- 未明确复制失败或部分失败时的处理策略
- 未明确双管理员互审被拒后的状态处理
- 未明确复制操作是否提供撤回/回滚能力

## §2 业务场景判断

### 业务定位

本次需求是在现有「子管理员模式」能力上的**既有能力扩展**，不是新增独立的权限管理模块。它在现有子管理员配置链路中增加了一条"复制"快捷路径，介于"逐个手动配置"和"角色模板批量分发"之间。

### 与现有能力的关系

- **与逐个手动配置的关系：** 复制是手动配置的效率替代，目标是减少重复勾选。两者共享同一套子管理员权限模型（组织范围 × 应用范围）。
- **与角色模板的关系：** 角色模板解决的是"给一批人相同的业务权限"，子管理员复制解决的是"给一批人相同的管理权限上限"。两者服务于不同层级，但复制功能不应替代或绕过角色体系。
- **与双管理员互审的关系：** 当互审模式开启时，复制操作触发审批，这意味着复制不是"即时生效"——操作完成和权限生效之间存在时间差。 [FACT]

### 是否改变治理模式

不改变。子管理员的权限边界（组织范围 × 应用范围）、双管理员互审的生效机制、操作记录的审计要求均保持不变。复制只是新增了一种"配置来源"——子管理员的权限可以通过手动配置产生，也可以通过复制叠加产生。 [CONFIRMED]

### 最大业务不确定性

复制来源的子管理员权限范围扩散是否存在越权风险。如果来源子管理员只能管 A 部门，复制后目标用户也获得 A 部门的授权能力——这本质上是"权限的权限"在扩散。需要产品明确：复制操作由超级管理员执行时，是否默认超管承担全部授权责任，还是需要额外约束复制来源的权限边界。 [GAP]

### 判断错误影响

如果上述"权限扩散"判断错误——即实际上存在越权约束但本判断未识别——后续体验方案中关于复制来源选择、复制范围提示、操作记录的责任归属都需要重新设计。

## §3 需求成立性判断

### 用户问题是否真实

真实。200+ 子管理员的场景下，逐个手动勾选相同功能权限确实是显著的实施障碍。这不是"用户懒"，而是系统没有提供合理效率工具。 [CONFIRMED]

### 业务价值

- 直接减少大客户实施周期，尤其对子管理员数量多的集团客户 [CONFIRMED]
- 降低权限管理员日常维护成本——新增同类子管理员时不再需要重复劳动 [CONFIRMED]
- 为后续可能的管理员权限模板化提供实践经验 [CONFIRMED]

### 系统代价

- 新增复制操作链路，包括弹窗、校验、结果处理 [CONFIRMED]
- 在双管理员互审模式下新增一类审批触发场景 [FACT]
- 操作记录需新增"复制-可授权组织"和"复制-可授权功能"两种操作类型 [FACT]
- 叠加逻辑需要在权限查询/详情中增加来源展示能力——这是隐性但必要的代价 [CONFIRMED]

### 替代路径

如果只解决"功能权限重复勾选"的问题，一个更轻的方案是支持"子管理员功能权限模板"——管理员先保存一套功能权限组合，配置新子管理员时直接套用模板，不引入复制、叠加、来源混合等概念。代价是模板需要独立维护，且不解决"从已有子管理员快速复制"的即时性需求。 [CONFIRMED]

### 成立性结论

**建议进入正式体验设计。** 需求成立，核心用户问题真实，业务价值明确。但成立的前提是：产品确认复制来源权限扩散风险可控，且体验设计中必须覆盖结果核对和来源可解释两个底线要求。 [CONFIRMED]

## §4 推荐业务边界

### 推荐能力形态

- 在子管理员列表的操作列增加「复制」入口 [FACT]
- 复制弹窗包含两个独立选择区：复制内容（组织/功能，可多选，至少选一）+ 复制对象（人员选择器，至少选一，上限 200） [FACT]
- 前置校验按固定顺序执行：复制信息 → 复制对象 → 加入状态 → 认证状态 [FACT]
- 复制成功后区分处理：普通用户成为子管理员、已有子管理员叠加权限 [FACT]
- 操作记录区分"复制-可授权组织"和"复制-可授权功能" [FACT]
- 双管理员互审模式下生成审批 [FACT]

### 不推荐能力形态

- 不推荐在复制弹窗中允许修改权限内容——复制是"搬运"不是"编辑"，如需调整应在复制完成后单独操作 [CONFIRMED]
- 不推荐复制后允许目标用户拒绝——子管理员权限是管理授权，不是协作邀请 [CONFIRMED]
- 不推荐将复制能力扩展到角色、应用管理员等其他权限对象——当前范围聚焦子管理员 [CONFIRMED]

### 与现有能力的边界

- 复制操作复用现有子管理员权限模型，不新增权限类型或权限维度 [CONFIRMED]
- 复用现有人员选择器组件 [FACT]
- 复用现有操作记录框架 [FACT]
- 复用现有双管理员互审审批链路 [FACT]

### 不应新增

- 不应新增"复制历史"独立页面——操作记录已覆盖追溯需求 [CONFIRMED]
- 不应新增"批量撤回复制"专用入口——如后续需要撤回能力，应纳入现有权限变更回滚体系 [CONFIRMED]

## §5 角色、功能、规则范围

### 角色清单

| 角色 | 职责 |
| --- | --- |
| 权限管理员 / 超级管理员 | 执行复制操作，选择复制来源、复制内容和复制目标，确认提交 |
| 子管理员（复制来源） | 提供可授权组织和可授权功能配置作为复制模板 |
| 复制对象用户（普通用户） | 接收复制后成为子管理员，获得对应可授权范围 |
| 复制对象用户（已有子管理员） | 接收复制后在原有基础上叠加可授权范围 |

### 功能单元

| 功能 | 输入 | 输出 | 结果 |
| --- | --- | --- | --- |
| 复制入口 | 子管理员列表行 | 打开复制弹窗 | 弹窗展示，复制信息默认全选 |
| 复制信息选择 | 可授权组织勾选态、可授权功能勾选态 | 至少一项已勾选 | 确定本次复制哪些权限维度 |
| 复制对象选择 | 人员选择器操作 | 已选用户列表（1-200 人） | 确定本次复制的目标用户 |
| 复制校验 | 复制信息、复制对象、目标用户状态数据 | 校验通过/校验失败及原因 | 通过则允许提交，失败则阻断并提示具体原因 |
| 复制执行 | 复制来源 ID、复制内容、目标用户列表 | 复制结果 | 目标用户权限变更，操作记录生成 |
| 复制结果反馈 | 复制执行结果 | toast + 操作记录 | 管理员获知操作结果 |

### 关键业务规则

| 规则 | 触发条件 | 处理结果 | 不满足时处理 |
| --- | --- | --- | --- |
| 复制信息必选 | 点击确认按钮 | 校验通过进入下一步 | 阻断并提示"请选择复制信息" |
| 复制对象必选 | 点击确认按钮 | 校验通过进入下一步 | 阻断并提示"请选择至少一名复制对象" |
| 目标已加入 | 点击确认按钮 | 校验通过进入下一步 | 阻断并提示"XXX、XXX 加入状态不是已加入，不能成为子管理员" |
| 目标已认证 | 点击确认按钮 | 校验通过进入下一步 | 阻断并提示"XXX、XXX 未完成实名认证，不能成为子管理员" |
| 目标非子管理员 | 复制执行时 | 目标成为子管理员，按复制信息设置权限 | — |
| 目标已是子管理员 | 复制执行时 | 目标原有权限不变，复制内容叠加 | — |
| 目标上限 200 | 选择复制对象时 | 超过 200 人时选择器阻止继续添加 | 提示已达到上限 |
| 互审触发 | 复制执行完成时（系统开启双管理员互审） | 生成一条审批，权限变更待审批生效 | 审批未完成前权限不变 |
| 操作记录生成 | 复制执行完成时 | 按复制内容生成对应操作记录 | — |

## §6 状态、异常与边界

### 核心状态

| 状态 | 说明 | 用户下一步 |
| --- | --- | --- |
| 待配置 | 复制弹窗打开，复制信息默认全选，未选择复制对象 | 选择复制内容、选择复制对象 |
| 校验中 | 点击确认后，系统按序校验 | 等待校验结果 |
| 校验失败 | 校验不通过，展示具体阻断原因 | 根据提示修正后重新提交 |
| 已提交（直接生效） | 校验通过且非互审模式，复制已生效 | 查看 toast 确认，通过操作记录核对结果 |
| 已提交（审批中） | 校验通过且互审模式，复制已提交审批 | 等待审批完成，通过审批链路跟踪进度 |
| 审批通过 | 互审审批通过，复制生效 | 权限变更生效 |
| 审批被拒 | 互审审批被拒，复制未生效 | [GAP] 需定义管理员如何获知被拒及后续操作 |
| 部分成功 | [GAP] 系统处理过程中部分目标成功、部分失败 | [GAP] 需定义结果展示和后续处理方式 |

### 关键异常

| 异常 | 触发条件 | 系统处理 | 用户下一步 |
| --- | --- | --- | --- |
| 复制来源失效 | 复制执行时来源子管理员已被删除或禁用 | [GAP] 需定义：是阻断复制还是以最后有效配置为准 | [GAP] |
| 目标用户状态变更 | 校验通过后、执行前目标用户退出企业或取消认证 | [GAP] 需定义事务性保证策略 | [GAP] |
| 复制内容为空 | 用户取消所有勾选后点击确认 | 阻断，提示"请选择复制信息" | 重新勾选至少一项 |
| 目标列表为空 | 用户未选择或清空后点击确认 | 阻断，提示"请选择至少一名复制对象" | 重新选择目标用户 |
| 互审审批超时 | 审批长时间未处理 | [GAP] 需定义超时策略 | [GAP] |
| 并发复制冲突 | 同一来源子管理员同时被多个管理员复制 | [GAP] 不做并发锁，以实际执行为准 | [GAP] |

### 边界条件

- 复制对象中包含复制来源自身时：[GAP] 需定义是否允许及处理逻辑
- 复制对象中已存在完全相同的权限配置时：叠加逻辑下功能权限会重复但去重、组织范围取并集 [CONFIRMED]
- 单次复制后目标超过子管理员总数上限时：[GAP] 需确认是否存在子管理员总数上限

## §7 体验蓝图承接要求

| 业务判断 | 体验影响 | 必须承接的问题 | 禁止下游重判 |
| --- | --- | --- | --- |
| 复制是子管理员配置的快捷路径，不改底层权限模型 | 复制弹窗的信息层级需要让管理员快速理解"复制的是什么"和"复制给谁" | 如何在一个弹窗内清晰区分"复制内容"和"复制对象"两个独立决策 | 不得重新定义子管理员的权限维度 |
| 批量操作最多 200 人，叠加逻辑不覆盖 | 200 人的结果反馈不能只靠 toast，管理员需要知道谁成功谁失败 | 复制结果如何分层展示（成功/失败/审批中），如何让管理员快速定位失败原因 | 不得将"叠加"改为"覆盖" |
| 双管理员互审模式下复制触发审批 | 操作完成和权限生效之间存在时间差，管理员和目标用户都需要感知中间态 | 审批中目标用户在子管理员列表中展示什么状态，审批通过/被拒后如何通知 | 不得改变互审的审批链路和生效机制 |
| 操作记录需区分"复制-可授权组织"和"复制-可授权功能" | 同时复制两者时产生两条记录，需要在记录列表中保持可读性 | 两条记录是分开展示还是合并展示，如何让审计者一眼看出是同一次复制操作 | 不得省略操作记录中任一维度的记录 |
| 复制来源的子管理员权限范围决定了复制内容 | 管理员需要确认来源子管理员的当前权限范围，避免"复制错了" | 复制弹窗中是否展示来源子管理员的权限摘要，帮助管理员确认 | 不得假设管理员一定记得来源的权限配置 |
| 普通用户通过复制成为子管理员 | 用户视角下"突然变成子管理员"需要一个合理的感知路径 | 目标用户是否需要收到通知（如"你已被设为子管理员"），还是静默生效 | 不得将"成为子管理员"与"角色分配"合并通知 |

## §8 约束与不做什么

### 硬约束

- 复制入口仅限子管理员模式列表，不扩展到其他权限管理页面 [FACT]
- 复制信息至少选择一项（可授权组织或可授权功能）[FACT]
- 单次复制目标上限 200 人 [FACT]
- 复制目标必须已加入企业且已实名认证 [FACT]
- 复制操作必须生成操作记录 [FACT]
- 双管理员互审模式下必须触发审批 [FACT]

### 不做什么

- 不做复制内容的编辑修改——复制弹窗只做选择和确认，不承载权限编辑能力 [CONFIRMED]
- 不做复制后自动通知目标用户——是否通知、如何通知由后续产品策略决定 [GAP]
- 不做批量撤回复制的专用入口——如需撤回，纳入现有权限变更回滚体系 [CONFIRMED]
- 不扩展到子管理员以外的权限对象（如角色、应用管理员）[CONFIRMED]
- 不做复制模板的保存和复用——当前聚焦即时复制 [CONFIRMED]

### 依赖项

- 人员选择器组件（复用现有）[FACT]
- 操作记录框架（复用现有）[FACT]
- 双管理员互审审批链路（复用现有）[FACT]
- 子管理员权限模型（组织范围 × 应用范围，不改变）[CONFIRMED]

## §9 待确认问题

### 层级一：影响主策略

| 问题 | 影响 | 建议确认方 |
| --- | --- | --- |
| 复制来源的子管理员权限范围扩散是否存在越权风险？超管执行复制时是否默认承担全部授权责任？ | 决定复制操作是否需要额外约束来源权限边界，影响复制弹窗是否需展示来源权限摘要 | 产品 + 安全 |

### A.1 原始输入事实

- 需求来源：`input/子管理员权限复制/子管理员支持复制.md`
- 广西交投存在 200+ 子管理员的真实场景
- 复制内容：可授权组织、可授权功能，两项可多选
- 复制对象：支持多选，最多 200 人
- 校验顺序：复制信息 → 复制对象 → 加入状态 → 认证状态
- 已有子管理员叠加、不覆盖
- 普通用户复制后成为子管理员
- 双管理员互审模式下生成审批
- 操作记录分"复制-可授权组织"和"复制-可授权功能"两种

### A.3 AI 设计判断

- 本次复杂度为中等：底层权限骨架不变，但批量规模和叠加逻辑引入体验压力
- 复制结果核对环节是批量操作的体验底线，不能只靠 toast
- 叠加后权限来源展示是权限域可解释性的硬要求
- 复制操作的可逆路径需要在方案中讨论，但不一定在首期实现
- 操作记录同时复制两项时拆成两条记录，可能影响审计可读性
