# 需求定案：子管理员权限复制

> 生成时间：2026-06-26 | 项目名：子管理员权限复制

---

## §0 本次关键判断

**判断**：既有能力扩展，"复制"是以已有子管理员配置为快照、批量直授给目标用户的新权限授予路径。

**主要影响**：核心风险不在交互本身，而在操作结果的可验证性和审计可追溯性。只给 toast 不做结果确认出口，大批量配置后管理员无法确认"谁收到了什么"。

**建议方案**：单弹窗完成选内容→选对象→校验→确认，复制结果提供可验证出口（结果汇总弹窗），操作记录补齐权限快照。

**不建议方案**：做成动态关联（来源变更自动同步目标），会引入新的权限来源认知模型。

**关键待确认**：批量校验失败时全部阻断还是跳过不符合的继续，直接影响交互分支设计。

## §1 需求输入摘要

### 背景

集团型企业使用子管理员模式下放权限管理能力。部分客户（如广西交投 200+ 子管理员）中，子管理员的"可授权功能"通常一致，但"可授权组织"不同。当前需逐个子管理员单独勾选相同功能权限，实施工作量大、配置效率低。 [FACT]

### 目标用户

- 权限管理员 / 超级管理员：负责维护子管理员及其可授权范围 [FACT]

### 业务目标

- 提升子管理员批量配置效率 [FACT]
- 降低大客户实施周期和人工成本 [FACT]
- 提供可追溯的批量操作能力 [FACT]

### 功能范围

- 在子管理员模式列表操作列增加「复制」入口 [FACT]
- 支持选择复制内容（可授权组织、可授权功能） [FACT]
- 支持选择多个用户作为复制目标（最多 200 名） [FACT]
- 复制后：非子管理员成为子管理员，已有子管理员叠加权限 [FACT]
- 复制成功生成操作记录 [FACT]
- 若开启双管理员互审模式，生成审批 [FACT]

### 明确约束

- 复制入口仅出现在子管理员模式列表中 [FACT]
- 复制来源必须是已有子管理员 [FACT]
- 复制信息至少选择一项 [FACT]
- 复制对象至少选择一名 [FACT]
- 复制对象最多 200 名 [FACT]
- 复制对象须满足加入状态和认证状态要求 [FACT]
- 已有子管理员接收复制采用叠加逻辑，不覆盖原有权限 [FACT]

### PRD 缺口

- "加入状态"的最终口径未统一（文档自注"已启用/已加入"两种表述待确认） [GAP]
- 批量校验失败时的处理分支未明确（全部阻断 vs 剔除非法继续） [GAP]
- 复制来源的组织范围超出目标子管理员自身管辖范围时的冲突处理规则未定义 [GAP]

## §2 业务场景判断

### 业务定位

这项需求在现有业务体系中属于**既有能力扩展**。它不改变子管理员的业务对象定义、权限模型（ACL_DIRECT / RBAC_ROLE / APP_VISIBILITY）和治理状态模型，而是在现有"逐一授予子管理员权限"的路径旁，增加一条"从已有子管理员复制权限"的批量路径。 [CONFIRMED]

### 与现有能力的关系

- **复用**：子管理员模式列表、添加子管理员弹窗（员工选择器复用其样式）、操作记录体系、双管理员互审批制 [CONFIRMED]
- **新增**：复制操作入口、复制弹窗、复制校验逻辑、叠加写入逻辑 [CONFIRMED]
- **互斥**：知识库 R-009 明确子管理员模式与双管理员模式不可同时开启。需求文档 §10 提及"若开启双管理员互审模式则生成审批"的触发条件需要产品侧确认是否实际存在 [GAP]

### 是否改变治理模式

不改变。复制操作写入后，权限来源仍为 ACL_DIRECT（直接授予），治理修饰因子（GOVERNANCE_MODE）的生效规则不变。 [CONFIRMED]

### 最大业务不确定性

批量复制作为一次性快照写入，写入后没有溯源标记可区分"通过复制获得的权限"和"原来就有的权限"。如果管理员后续需要撤回某次复制的效果，当前设计无法支持按复制批次回滚。这不是本次必须解决的问题，但应作为已知限制写入约束。 [CONFIRMED]

### 如果这个判断错了

如果"复制"实际需要建立动态关联（模板引用），或需要支持按复制批次回滚，那么权限来源模型需要增加新的 source_enum 值，操作记录的字段结构需要重新设计，后续体验蓝图的任务链路也需要重做。

## §3 需求成立性判断

### 用户问题是否真实成立

成立。集团型企业的子管理员批量配置效率问题是真实痛点，200+ 子管理员的场景下重复勾选相同功能权限是纯体力劳动。 [CONFIRMED]

### 业务价值

- 减少重复配置的人力成本，缩短大客户实施周期 [CONFIRMED]
- 为权限配置提供批量操作能力，补齐现有逐一配置的效率短板 [CONFIRMED]
- "复制"操作天然比"逐一配置"减少人工出错概率 [CONFIRMED]

### 系统代价

- 新增复制弹窗和校验链路的开发成本 [CONFIRMED]
- 操作记录需要新增复制类型的字段结构 [CONFIRMED]
- 叠加写入逻辑需要处理范围冲突的边界情况 [CONFIRMED]
- 如果后续需要支持按复制批次回滚，将引入额外的数据结构和审计字段 [CONFIRMED]

### 更低成本替代路径

- **不做复制，做"默认模板"**：预设一套子管理员功能权限模板，新建子管理员时自动填充。优点是概念更简单、不需要来源子管理员、不需要处理叠加冲突。缺点是无法覆盖"不同组织范围"的差异化需求。
- **不做复制，做"批量编辑"**：在子管理员列表中支持多选后批量修改功能权限。优点是复用现有编辑能力、不引入新概念。缺点是编辑是覆盖式操作，无法叠加。

综合判断：**复制方案在当前场景下是合理的**。它比模板更灵活（可以选任意已有子管理员作为来源），比批量编辑更安全（叠加不覆盖）。建议进入正式体验设计。 [CONFIRMED]

## §4 推荐业务边界

### 推荐能力形态

- 复制是一次性快照写入操作：读取来源子管理员当前的可授权组织和可授权功能配置，写入目标用户的 ACL_DIRECT 授权记录 [CONFIRMED]
- 复制结果按目标用户独立生效：每个目标用户各自写入一条授权记录，写入成功或失败互不影响 [CONFIRMED]
- 复制操作生成独立操作记录，记录类型区别于手动逐一授权 [CONFIRMED]

### 不推荐能力形态

- 不建立来源与目标的动态关联：来源后续变更不会同步到目标 [CONFIRMED]
- 不作为子管理员"克隆"：不复制来源的管辖范围（可授权组织范围本身就是目标需要差异化的维度） [CONFIRMED]
- 不自动创建角色或角色组：复制结果是按人直授，不走角色授予路径 [CONFIRMED]

### 与现有能力的边界

- 复制操作的写入结果复用现有 ACL_DIRECT 授权体系，不走角色管理（RBAC_ROLE）路径 [CONFIRMED]
- 复制不影响应用可见性（APP_VISIBILITY），只操作可授权功能和可授权组织 [CONFIRMED]
- 复制后的权限变更仍受治理模式（GOVERNANCE_MODE）修饰，生效规则与手动授权一致 [CONFIRMED]

### 复用

- 员工选择器复用现有"添加子管理员"弹窗的组件 [CONFIRMED]
- 操作记录复用现有记录体系框架 [CONFIRMED]

### 不应新增

- 不应新增独立的"复制历史"页面（操作记录体系已覆盖） [CONFIRMED]
- 不应新增"复制模板"概念（与本次需求范围不符） [CONFIRMED]

## §5 角色、功能、规则范围

### 5.1 角色清单

| 角色 | 职责 |
| --- | --- |
| 权限管理员 / 超级管理员 | 发起复制操作：选择来源子管理员、选择复制内容、选择目标用户、确认执行、查看复制结果 [FACT] |
| 来源子管理员 | 提供可授权组织和可授权功能配置作为复制快照的数据来源 [FACT] |
| 目标用户（非子管理员） | 接收复制后成为子管理员，获得复制内容中的可授权组织和可授权功能 [FACT] |
| 目标用户（已有子管理员） | 接收复制后在原有配置基础上叠加复制内容，原有配置不被覆盖 [FACT] |

### 5.2 功能清单

| 功能 | 输入 | 输出 | 结果 |
| --- | --- | --- | --- |
| 复制入口 | 子管理员列表中的某一行（操作列） | 打开复制弹窗 | 弹窗展示复制信息和复制对象选择区 [FACT] |
| 选择复制内容 | 可授权组织勾选、可授权功能勾选 | 确认后将作为复制写入的数据源 | 默认全选，至少保留一项 [FACT] |
| 选择复制对象 | 员工选择器中选择一名或多名用户（最多 200 名） | 确认后作为目标写入列表 | 用户可以是普通用户或已有子管理员 [FACT] |
| 复制校验 | 复制信息勾选状态、复制对象列表、目标加入状态、目标认证状态 | 校验通过进入写入，校验失败展示具体阻断原因 | 按顺序逐项校验 [FACT] |
| 复制写入 | 校验通过的复制信息 + 目标用户列表 | 每个目标用户各自写入授权记录 | 非子管理员→成为子管理员；已有子管理员→叠加权限 [FACT] |
| 操作记录 | 复制成功的写入结果 | 生成操作记录 | 记录操作人、来源、目标、复制内容、时间 [FACT] |
| 双管理员审批 | 复制写入完成（如系统处于双管理员互审模式） | 生成审批 | 待另一位管理员审批后生效 [FACT]（与 R-009 冲突，待确认） [GAP] |

### 5.3 关键业务规则

| 规则 | 触发条件 | 处理结果 | 不满足时的处理 |
| --- | --- | --- | --- |
| 复制信息必选 | 点击确认按钮 | 检查是否至少勾选一项 | 阻断并提示"请选择复制信息" [FACT] |
| 复制对象必选 | 点击确认按钮 | 检查是否至少选择一名用户 | 阻断并提示"请选择至少一名复制对象" [FACT] |
| 目标加入状态校验 | 校验阶段 | 检查每个目标用户的加入状态是否为"已加入"（或"已启用"，口径待统一） | 阻断并提示"XXX、XXX 加入状态不是已加入，不能成为子管理员" [FACT] |
| 目标认证状态校验 | 校验阶段 | 检查每个目标用户是否已完成实名认证 | 阻断并提示"XXX、XXX 未完成实名认证，不能成为子管理员" [FACT] |
| 非子管理员→成为子管理员 | 复制写入时，目标用户原本不是子管理员 | 创建子管理员身份，设置对应可授权功能和组织 | — [FACT] |
| 已有子管理员→叠加 | 复制写入时，目标用户原本已是子管理员 | 在原有配置基础上叠加可授权功能和可授权组织，不覆盖 | — [FACT] |
| 复制对象上限 | 选择复制对象时 | 最多选择 200 名用户 | 超过 200 名时限制选择 [FACT] |
| 来源必须为子管理员 | 复制入口展示条件 | 列表中该行对应用户必须为子管理员 | 非子管理员行不展示复制入口 [FACT] |

## §6 状态、异常与边界

### 6.1 核心状态

| 状态 | 说明 | 来源 |
| --- | --- | --- |
| 复制操作-待提交 | 弹窗已打开，用户正在选择复制信息和复制对象 | [CONFIRMED] |
| 复制操作-校验中 | 点击确认后，系统正在逐项校验 | [CONFIRMED] |
| 复制操作-校验失败 | 某项校验不通过，展示阻断原因 | [FACT] |
| 复制操作-写入中 | 校验通过，正在写入各目标用户的授权记录 | [CONFIRMED] |
| 复制操作-全部成功 | 所有目标用户均写入成功 | [CONFIRMED] |
| 复制操作-部分成功 | 部分目标用户写入成功，部分失败（取决于批量策略） | [CONFIRMED] |
| 复制操作-全部失败 | 所有目标用户写入失败 | [CONFIRMED] |
| 审批待处理 | 写入完成但需双管理员互审（如该模式实际可用） | [FACT]（与 R-009 冲突） [GAP] |

### 6.2 异常清单

| 异常 | 触发条件 | 系统处理 | 用户下一步 |
| --- | --- | --- | --- |
| 复制信息未选择 | 未勾选任何复制信息就点击确认 | 阻断提交，在复制信息区域提示"请选择复制信息" | 勾选至少一项复制信息后重试 |
| 复制对象未选择 | 未选择任何用户就点击确认 | 阻断提交，在复制对象区域提示"请选择至少一名复制对象" | 选择至少一名用户后重试 |
| 目标用户加入状态不符 | 选中的目标用户中存在加入状态不是"已加入"的用户 | **待确认**：全部阻断并列出所有不符合的用户，或跳过不符合用户继续复制 [GAP] | 移除不符合的用户后重试，或确认跳过 |
| 目标用户认证状态不符 | 选中的目标用户中存在未完成实名认证的用户 | **待确认**：全部阻断并列出所有不符合的用户，或跳过不符合用户继续复制 [GAP] | 移除不符合的用户后重试，或确认跳过 |
| 复制对象超过上限 | 选择超过 200 名用户 | 限制选择，选择器不允许继续添加 | 减少选择至 200 名以内 |
| 写入阶段系统异常 | 提交写入请求后系统错误 | 展示失败提示，说明失败原因和受影响的目标用户 | 重试或联系技术支持 |
| 来源子管理员在复制过程中被修改或删除 | 管理员打开弹窗期间，来源子管理员权限被他人修改或删除 | **待确认**：弹窗内是否需要提示"来源已变更"或写入时读取最新快照 [GAP] | **待确认** |
| 目标用户在企业中被禁用或移除 | 写入时目标用户在企业中的状态已变更 | 写入失败，在结果中标注该用户失败原因 | 查看结果汇总，确认剩余用户的复制结果 |
| 审批中（如双管理员互审模式可用） | 复制写入完成，系统处于双管理员互审模式 | 权限暂不生效，等待另一位管理员审批 | 通知审批人处理审批 |

## §7 体验蓝图承接要求

| # | 业务判断 | 对体验设计的影响 | 必须承接的问题 | 禁止下游重判 |
| --- | --- | --- | --- | --- |
| 1 | 复制是一次性快照写入，不是动态关联 | 交互文案需显式传递"复制的是当前配置"的语义 | 如何在界面中让管理员理解"复制的是这一刻的状态"？ | 不得将复制设计为"建立模板关联" |
| 2 | 批量操作涉及最多 200 名用户，校验和结果均存在分支 | 需要在弹窗内完成校验反馈，在结果阶段提供可验证出口 | 校验失败时如何呈现受影响用户列表？复制完成后如何让管理员确认"谁收到了什么"？ | 不得仅用 toast 替代结果验证 |
| 3 | 已有子管理员叠加、非子管理员成为子管理员，两种结果的展示需求不同 | 结果阶段可能需要区分展示"新增的子管理员"和"权限已叠加的子管理员" | 如何在结果中区分新增和叠加两种结果？ | 不得将两种结果混为一谈 |
| 4 | 操作记录必须支持按变更追溯，当前设计缺少结果快照 | 操作记录的数据结构需补齐 snapshot 字段 | 操作记录中如何结构化存储复制时刻的权限快照，支持后续按变更查询闭环？ | 不得将操作记录降级为纯文案记录 |
| 5 | 复制操作引入了新的权限授予路径，但不改变权限来源真源 | 不需要新增权限来源类型，但管理员可能需要知道"哪些权限是通过复制获得的" | 是否需要在操作记录中标记本次变更为"复制"类型以区分手动授权？ | 不得新增 source_enum 值 |
| 6 | 叠加写入时，来源的组织范围可能超出目标子管理员自身管辖范围 | 如未定义冲突处理规则，则待确认 GAP | 是否需要在前置校验中检查"来源范围是否超出目标管辖范围"？ | 不得在未确认规则前自行设定冲突处理逻辑 |
| 7 | 弹窗包含两类不同选择逻辑：复制信息（checkbox）和复制对象（人员选择器） | 信息架构需要决定单弹窗内排布还是分步 | 两类选择器在单一弹窗中的信息层次和操作顺序如何安排？ | 不得默认使用步骤条（不满足步骤条门禁条件） |

## §8 约束与不做什么

### 硬约束

- 复制入口仅出现在子管理员模式列表操作列，不扩展到其他管理页面 [FACT]
- 复制来源必须是已有子管理员，普通用户不可作为复制来源 [FACT]
- 复制对象最多 200 名 [FACT]
- 复制信息至少选择一项 [FACT]
- 复制对象至少选择一名 [FACT]
- 目标用户必须满足加入状态和认证状态要求 [FACT]
- 已有子管理员叠加不覆盖原有配置 [FACT]
- 复制成功必须生成操作记录 [FACT]

### 依赖项

- 员工选择器依赖现有"添加子管理员"弹窗的组件实现 [CONFIRMED]
- 操作记录体系依赖现有审计基础设施 [CONFIRMED]
- 双管理员互审批制（如适用）依赖现有审批管理能力 [CONFIRMED]

### 不做什么

- 不建立来源与目标的动态关联 [CONFIRMED]
- 不新增独立的"复制历史"页面 [CONFIRMED]
- 不新增"复制模板"概念 [CONFIRMED]
- 不改变现有权限来源模型（不新增 source_enum） [CONFIRMED]
- 不为本次需求引入按复制批次回滚能力（可在后续迭代中评估） [CONFIRMED]

### 安全与业务边界

- 复制操作属于批量高危操作（RISK-007），必须与审计、防错策略联动 [CONFIRMED]
- 子管理员模式与双管理员模式互斥（R-009），如确认互斥成立则 §6 中审批状态不适用 [CONFIRMED]

### A.3 AI 设计判断 [CONFIRMED]

- 复杂度判断：中等——既有能力扩展，引入新权限授予路径但不改变底层权限模型
- 需求成立性：成立，复制方案比"默认模板"更灵活，比"批量编辑"更安全
- 体验核心风险：批量操作的可验证性不足（仅 toast）、审计快照缺失、叠加范围冲突未定义
- 复制语义：一次性快照写入，非动态关联，非模板
- 流程模式：单弹窗完成，不使用步骤条
