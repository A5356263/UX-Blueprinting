企业数字化产品权限自助申请 - User Journey Map

2026-07-13 / prd-standalone / problem-framing, stories

员
员工（业务人员/经办人员） 员工在业务场景中被权限拦住→发现自助申请入口→浏览权限目录确定需要什么→提交申请→等待上级审批→获得权限或被拒绝后处理结果。聚焦员工端自助申请全流程，从感知需求到获得结果。

员工在业务场景中被权限拦住，意识到需要某项功能权限或角色才能继续工作

1 感知需求与发现入口
2 浏览与评估
3 申请提交
4 等待审批
5 结果处理
用户目标
员工意识到需要某项权限才能完成工作，并知道可以通过自助方式申请
在可申请目录中找到自己需要的权限或角色，理解其含义和作用
选择所需权限/角色，填写申请理由，成功提交申请
了解申请进度，等待上级处理，在需要时跟进
获得权限开始工作 / 了解被拒绝原因并决定下一步
用户行动
  • 在工作中遇到权限不足提示或被功能入口挡住
  • 询问同事'这个功能怎么用不了'
  • 同事/文档告知可通过权限自助申请
  • 找到申请入口
  • 进入权限申请页面
  • 查看可申请的角色列表和功能权限列表
  • 浏览分类/搜索权限名称
  • 点击查看详情
  • 判断是不是自己需要的
  • 对比不同选项
  • 勾选需要申请的功能权限/角色
  • 查看已选项汇总
  • 填写申请理由
  • 确认提交
  • 收到提交成功反馈
  • 收到提交成功通知
  • （被动）等待审批
  • 间歇性查看'我的申请'页面了解进度
  • （主动）如果着急可能私聊上级提醒
  • （通过）收到审批通过通知
  • （通过）查看已生效权限
  • （通过）回到工作场景使用权限
  • （拒绝）收到拒绝通知
  • （拒绝）查看拒绝原因
  • （拒绝）决定是否重新申请、补充说明或放弃

信心与风险
中
基于问题框定中用户描述的场景推导——当前做法是私下找管理员，员工对自助申请的存在和入口无认知
高。员工如果不知道自助入口，会直接回到找管理员/老板的旧模式，自助申请的价值归零
高
上游直接提供了目录结构、分类方式和员工可看到全部角色的规则（confirmed_facts）
中。看不懂目录→随意选一个试试/放弃自助转而问人
高
上游 confirmed_facts 和故事 US-02 完成标准提供了完整的申请流程定义
低。流程明确、操作简单，但'不确定怎么写理由'可能在理由输入处卡住
中
等待行为和情绪反应基于体验设计常识推导，审批流基建成熟度仍为 open_gap
高。等待时间过长→员工绕过流程找管理员直接授权→自助流程被架空且产生不一致的授权记录
高
上游 confirmed_facts 明确了自动生效规则，stories 提供了通过和拒绝两个分支的验收标准
中。拒绝场景下如果没有明确的重新申请路径，员工会退回找管理员模式
痛点
  • 员工不知道平台有自助申请功能，回到找人的老路
  • 入口不明显或藏在深层菜单中，员工找不到
  • 权限被拦截时只看到'无权限'提示，没有引导去向
  • 权限名称为技术编码，员工看不懂是什么
  • 功能权限与角色的区别不清晰，不确定选哪种方式
  • 不知道申请某个权限后会有什么实际影响
  • 角色列表全量展示但只有部分可申请，区分不直观
  • 搜索结果为空时不知道是没权限还是没搜对关键词
  • 不确定申请理由要写多详细，写太简单怕被拒、写太复杂费时间
  • 一次性申请多个权限时，审批人可能只熟悉其中一部分，部分被拒的原因不明
  • 已拥有的权限没有前置提示，提交后才被告知重复
  • 不知道审批人什么时候处理，等待焦虑
  • 审批超时无人跟进，员工也不敢催上级
  • 只有'待审批'一个状态，没有更细的进度信息
  • 着急用权限但只能被动等待
  • （通过后）权限生效了但员工不知道去哪里用
  • （拒绝后）拒绝原因太笼统，不知道如何改进重新申请
  • （拒绝后）没有重新申请的入口或指引，又回到找人的老路
  • （自动授权失败）系统提示'授权失败'但员工不知道找谁处理
设计机会
权限拦截时直接给出自助申请入口（'去申请权限'按钮） (蓝图)
在工作台/首页提供显性化的自助申请入口 (蓝图)
新员工入职引导中加入权限自助申请的指引 (故事)
权限描述使用业务语言，说明'谁可以用''用来做什么''申请后能做什么' (蓝图)
角色与功能权限分栏展示，明确说明各自适用场景 (蓝图)
为每个权限/角色标注申请前提或推荐人群 (蓝图)
搜索结果为空时提供引导'试试其他关键词'或'联系管理员确认' (蓝图)
申请理由输入框提供示例模板（'我在XX业务中需要XX权限来做XX'） (蓝图)
提交前自动检测已拥有权限并提示移除 (蓝图)
提交成功后清晰告知下一步（'你的申请已提交给XX审批，预计处理时间为XX'） (蓝图)
提交时告知预计审批时间（'通常XX小时内处理'） (蓝图)
审批超时自动提醒审批人 (待确认)
我的申请页展示审批进度节点（已提交→审批人已查看→已通过/已拒绝） (蓝图)
审批超时后允许员工自助催办 (蓝图)
通过后引导到对应的功能入口（'去看看新权限'） (蓝图)
拒绝原因结构化（提供具体原因而非一句话带过） (蓝图)
提供'修改后重新申请'按钮，保留原申请内容供修改 (蓝图)
授权失败时明确引导：'请联系管理员处理'并附管理员联系方式 (蓝图)

阶段转折

感知需求与发现入口 -> 浏览与评估：员工找到自助申请入口并进入；浏览与评估 -> 申请提交：员工确定需要申请的权限或角色；申请提交 -> 等待审批：申请成功提交；等待审批 -> 结果处理：审批人做出审批决定（通过/拒绝）
