§0 本次关键设计判断

判断一：员工端 "我的权限" 页面使用业务语言展示权限，不暴露后台来源模型

员工看不懂"费用管理-报销单-新增"这类后台权限名，这是旅程分析确认的高置信度痛点。体验蓝图中，权限列表统一用业务场景描述代替后台权限名。

  • 主要影响：员工端"我的权限"页面、"可申请权限"选择区域的展示方式
  • 建议方案：每个权限项展示"权限名（业务场景说明）"的双行模式，如"报销提交权限（可提交报销申请）"；来源模型在员工端完全隐藏，用"已有/可申请"二分类替代
  • 不建议方案：直接展示后台权限树结构；让员工在权限森林里自行搜索
  • 关键待确认：权限名称与业务场景描述的映射关系需要业务侧确认

判断二：申请流程使用单页 Drawer 承载，不采用步骤条

权限申请的表单字段少（选择权限 + 填写原因），不存在强步骤依赖，用 Drawer 承载更轻量，员工可随时取消返回。

  • 主要影响：申请表单的承载形式
  • 建议方案：从"我的权限"页点击申请后，右侧滑出 Drawer，内嵌权限选择器 + 申请原因输入区 + 提交按钮
  • 不建议方案：跳转到独立申请页；使用步骤条（Step wizard）
  • 关键待确认：是否需要支持一次性申请多个权限（影响 Drawer 内的权限选择器设计）

判断三：审批界面在同意/拒绝按钮之外，必须展示权限影响范围的业务语义说明

审批人缺乏判断依据是旅程分析确认的高流失风险点。审批人需要知道"批准后申请人能做什么"，而不是只看到权限名称。

  • 主要影响：审批人处理申请的界面布局
  • 建议方案：审批详情中增加"批准后影响"区块，用一句话说明权限授予后的实际效果（如"批准后，申请人可以查看全公司报销数据"），风险等级用标签区分
  • 不建议方案：只展示权限后台名称 + 申请人 + 申请原因三个字段
  • 关键待确认：权限影响范围的描述需要业务侧提供模板或映射规则

判断四：申请通过后到生效的过程必须对员工可见，不默认为"通过即生效"

审批通过≠权限生效——治理模式（如双管理员审批、子管理员隔离）可能导致延迟。旅程分析确认员工会在"通过但未生效"阶段产生焦虑。

  • 主要影响：申请记录详情页的展示逻辑、通知内容
  • 建议方案：申请详情页按时间线展示完整状态流转（提交→审批通过→生效中→已生效/生效失败）；审批通过后 Toast 提示"审批已通过，正在自动授权"
  • 不建议方案：审批通过后直接跳到"已完成"，不展示中间状态
  • 关键待确认：授权生效的平均时间，用于"预计生效"的时间提示

§3 主交互流程

节点 3.1：进入"我的权限"页面

  • 用户动作：员工从工作台或导航进入"我的权限"页面
  • 系统反馈：加载并展示当前员工的权限概览
  • 需要前置解释的信息：说明这是"查看自己已有权限 + 申请新权限"的统一入口
  • 建议文案：页面标题"我的权限"；副标题说明"查看你已有的权限，或申请新的权限"
  • 下一步：员工浏览已有权限列表，或点击 [申请权限]

节点 3.2：浏览已有权限

  • 用户动作：员工查看权限列表，可按应用/模块筛选
  • 系统反馈：按应用分组展示权限项，每项展示权限名称 + 业务场景说明
  • 需要前置解释的信息：已有权限用"已有"标签标记，与可申请权限区分
  • 建议文案：分组标题如"费用管理"、"考勤管理"；权限项如"报销提交权限（可提交报销申请）"
  • 下一步：员工点击底部或页面的 [申请权限] 按钮

节点 3.3：打开申请 Drawer

  • 用户动作：点击 [申请权限] 按钮
  • 系统反馈：右侧滑出 Drawer，展示可申请权限列表 + 申请原因输入区 + 提交按钮
  • 需要前置解释的信息：Drawer 顶部说明"请选择需要申请的权限"
  • 建议文案：Drawer 标题"申请权限"
  • 下一步：员工浏览或搜索可申请权限

节点 3.4：选择权限

  • 用户动作：在可申请权限列表中搜索或浏览，点击选中一个权限项
  • 系统反馈：选中项高亮，底部显示已选中的权限名称
  • 需要前置解释的信息：每个权限项展示权限名 + 业务场景说明 + "申请"按钮
  • 建议文案：权限项展示格式同已有权限列表，保持一致性（U-04）
  • 下一步：如支持多选，可继续选择其他权限；如单选直接进入填写原因

节点 3.5：填写申请原因

  • 用户动作：在原因输入框中填写申请理由
  • 系统反馈：输入框显示占位符引导，字数实时统计（可选）
  • 需要前置解释的信息：告知申请人"充分的申请原因有助于审批人快速处理"（C-02 减少认知负担）
  • 建议文案：占位符"请说明为什么需要该权限，例如：因负责XX业务，需要查看XX数据"
  • 下一步：点击 [提交申请]

节点 3.6：提交前确认

  • 用户动作：点击 [提交申请]
  • 系统反馈：系统自动校验：①是否在可申请范围内 ②是否已有该权限 ③是否存在进行中的相同申请
  • 需要前置解释的信息：校验失败时在对应位置显示 InlineError
  • 建议文案：
  • 超出范围："该权限暂未开放自助申请，如需申请请联系管理员"
  • 已拥有："您已有该权限，无需重复申请"
  • 进行中："该权限已有一个进行中的申请，请等待处理结果"
  • 下一步：校验通过 → Drawer 关闭 → 显示成功 Toast

节点 3.7：提交成功反馈

  • 用户动作：提交后自动回到"我的权限"页或申请记录列表
  • 系统反馈：Toast "申请已提交"，申请记录列表新增一条状态为"审批中"的记录
  • 需要前置解释的信息：告知员工接下来会发生什么——"请等待审批人处理，审批通过后将自动授权"
  • 建议文案：Toast "申请已提交，请等待审批"；记录卡片显示当前进度为"审批中"
  • 下一步：员工可继续浏览权限、查看申请记录、等待通知

§4 次交互流程

4.1 管理员开启并配置自助申请

触发条件：管理员进入自助申请配置页，首次开启或关闭后重新开启。

  • 用户动作：切换 [启用] 开关 → 选择范围类型 → 勾选可申请权限 → 选择审批流程 → 点击 [保存]
  • 系统反馈：
  • 切换 [启用] 时检查是否与现有治理模式冲突
  • 保存时校验：至少勾选一个权限、审批流程已配置
  • 保存成功后 Toast "配置已保存，自助申请已启用"
  • 需要前置解释的信息：
  • 开启前：一句话说明"开启后，员工可以在指定范围内自助申请权限，申请需经过审批"
  • 选择范围时：按应用/模块分组展示，配合搜索（IA-02 分块）
  • 选择审批流程时：展示已有审批流程列表，或提供"去审批管理配置"的快捷入口
  • 建议文案：
  • 页面标题"自助申请配置"
  • 范围说明"选择允许员工自助申请的权限范围"
  • 审批流程说明"选择申请提交后需要经过的审批流程"
  • 下一步：管理员可点击"员工视角预览"查看员工端效果；或点击 [保存] 完成配置

4.2 员工撤销申请

触发条件：员工在申请记录列表中看到一个"审批中"状态的申请，决定撤回。

  • 用户动作：点击 [撤销申请] → 弹窗确认 → 确认撤销
  • 系统反馈：
  • 弹窗提示"撤销后申请将结束，审批人将不再处理"
  • 确认后状态变更为"已撤销"
  • Toast "申请已撤销"
  • 需要前置解释的信息：撤销不可逆，撤销后需重新提交（U-03 用户控制与自由）
  • 建议文案：弹窗标题"撤销申请"；弹窗正文"撤销后该申请将结束，审批人不再处理。如仍需该权限，需要重新提交申请。"
  • 下一步：员工可重新申请该权限

4.3 审批人审批处理

触发条件：审批人收到审批通知，进入审批详情页处理申请。

  • 用户动作：查看申请详情 → 点击 [同意] 或 [拒绝] → 如拒绝填写原因 → 确认
  • 系统反馈：
  • 同意 → 状态变更为"已通过" → 系统自动执行授权 → 状态变更为"已生效" 或 "生效失败"
  • 拒绝 → 状态变更为"已拒绝" → 申请结束
  • 操作成功 Toast "审批已完成"
  • 需要前置解释的信息：
  • 审批详情页展示：权限名称 + 业务场景说明、权限影响范围、风险等级标签、申请人部门/岗位、申请原因
  • 拒绝原因提供常用模板："权限过大，建议申请更小范围""与现有角色重复""请补充申请理由"
  • 建议文案：审批详情页标题"审批权限申请"；"批准后影响"区块文案"批准后，申请人可以{具体影响}"
  • 下一步：审批人返回待办列表；申请人收到结果通知

4.4 管理员日常监控

触发条件：管理员进入自助申请配置页或申请记录列表查看运行状态。

  • 用户动作：查看统计概览 → 浏览申请记录 → 标记异常
  • 系统反馈：
  • 统计卡片：今日申请数、通过率、平均审批时长、进行中数量
  • 申请列表：按提交时间排序，支持按状态筛选
  • 异常标记：高频申请相同权限、同一人被多次拒绝时自动标记
  • 需要前置解释的信息：统计卡片帮助管理员快速了解整体运行情况（U-06 识别优于回忆）
  • 建议文案：统计卡片标题"运行概况"
  • 下一步：管理员可调整配置或关闭功能

4.5 管理员调整配置（运行中）

触发条件：管理员在已启用状态下修改可申请范围或审批流程。

  • 用户动作：进入自助申请配置页 → 修改配置 → 点击 [保存]
  • 系统反馈：
  • 保存时提示"配置变更不影响已提交的申请，已审批通过的授权不受影响"
  • Toast "配置已更新"
  • 需要前置解释的信息：配置变更的生效范围——只影响变更后提交的申请（ISO-04 符合预期）
  • 建议文案：提示文案"已提交的申请按原配置继续流转，不受本次变更影响"
  • 下一步：管理员确认变更已生效

4.6 管理员关闭自助申请

触发条件：管理员不再需要自助申请功能，或需要临时关闭进行调整。

  • 用户动作：切换 [启用] 开关为关闭 → 系统校验 → 弹窗确认 → 确认关闭
  • 系统反馈：
  • 校验结果：显示当前进行中的申请数量
  • 弹窗提示：关闭后新申请不可提交，进行中的 X 个申请将继续流转
  • 确认后 Toast "自助申请已关闭"
  • 需要前置解释的信息：关闭的边界：不收回已授予的权限，不影响进行中的申请（UXB §8 硬约束）
  • 建议文案：弹窗标题"关闭自助申请"；弹窗正文"关闭后，员工将无法提交新的权限申请。正在进行中的 {N} 个申请将继续正常流转，不受影响。已授予的权限不会被收回。"
  • 下一步：管理员可重新开启，上次的配置保留

§5 异常与阻断流程

5.1 申请超出可申请范围

  • 发生时机：员工在选择权限后点击提交时
  • 触发条件：所选权限不在管理员配置的可申请范围列表中
  • 判断依据：系统对比所选权限与可申请范围列表
  • 反馈形式：Drawer 内 InlineError，不关闭 Drawer
  • 系统反馈：提交按钮下方显示错误提示，已填信息保留
  • 用户下一步：重新选择其他权限，或放弃申请联系管理员
  • 恢复路径：原路恢复，无信息丢失。员工可继续选择其他权限或关闭 Drawer 退出

5.2 员工已有该权限

  • 发生时机：员工选择权限后点击提交时
  • 触发条件：所选权限当前员工已拥有
  • 判断依据：系统对比所选权限与当前员工已授权权限
  • 反馈形式：权限选择区该权限项下方显示 InlineError
  • 系统反馈：错误提示"您已有该权限，无需重复申请"
  • 用户下一步：重新选择其他权限
  • 恢复路径：原路恢复，无信息丢失。员工可直接切换选择其他权限

5.3 存在进行中的相同申请

  • 发生时机：员工选择权限后点击提交时
  • 触发条件：该权限已有一份"审批中"状态的申请
  • 判断依据：系统查询该员工该权限的进行中申请
  • 反馈形式：Drawer 内该权限项下方显示 InlineError
  • 系统反馈：错误提示"该权限已有一个进行中的申请，请等待处理结果"
  • 用户下一步：去申请记录页面查看该申请的状态，或等待审批结果
  • 恢复路径：原路恢复，无信息丢失。员工可查看现有申请记录

5.4 审批人缺失

  • 发生时机：员工提交申请时，或提交后转审批时
  • 触发条件：管理员配置的审批流程中无有效审批人（如审批人已离职、角色为空）
  • 判断依据：系统在申请提交时实时检查审批流程的有效性
  • 反馈形式：提交时 Drawer 显示 Toast 错误，不关闭 Drawer
  • 系统反馈：Toast "审批流程未配置有效审批人，请联系管理员处理"
  • 用户下一步：联系管理员补充审批人配置；管理员收到异常通知
  • 恢复路径：原路恢复，无信息丢失。管理员配置审批人后员工可重新提交

5.5 审批通过但授权失败

  • 发生时机：审批人点击同意后，系统执行自动授权时
  • 触发条件：系统调用授权接口失败（接口超时、权限模型冲突、治理模式阻断等）
  • 判断依据：授权接口返回失败
  • 反馈形式：审批人端 Toast + 管理员端通知 + 员工端状态更新
  • 系统反馈：
  • 审批人："授权执行异常，已通知管理员处理"
  • 管理员：收到"自动授权失败"的通知
  • 员工端：状态变更为"已通过（授权异常）"
  • 用户下一步：管理员介入手动授权或排查原因
  • 恢复路径：非自动恢复。管理员手动处理后，在后台将申请状态更新为"已生效"

5.6 关闭期间有新申请

  • 发生时机：员工在自助申请已关闭后尝试提交申请
  • 触发条件：自助申请功能已关闭
  • 判断依据：系统检查功能开关状态
  • 反馈形式：Drawer 无法打开，或打开后提交按钮置灰并显示提示
  • 系统反馈：提示"当前未开放自助申请，如需申请权限请联系管理员"
  • 用户下一步：联系管理员线下申请
  • 恢复路径：无法自行恢复。管理员重新开启后员工可正常申请

5.7 审批超时未处理

  • 发生时机：申请已提交，但审批人在规定时间内未处理
  • 触发条件：超过管理员配置的超时阈值（参考审批管理知识库"超时处理"策略：提醒/转派/通过/拒绝）
  • 判断依据：系统超时计时器触发
  • 反馈形式：员工端催办按钮变为可用 + 审批人端超时提醒
  • 系统反馈：
  • 员工端：申请详情页显示"已超过预计处理时间"，[催办] 按钮亮起
  • 审批人端：收到超时提醒通知（可能的方式：系统内通知/短信/邮件）
  • 用户下一步：员工点击 [催办] 提醒审批人；审批人尽快处理
  • 恢复路径：催办后等待审批人处理；如审批人长期不处理，员工联系管理员转派

5.8 催办功能

  • 发生时机：员工在申请详情页点击 [催办] 按钮
  • 触发条件：申请超过预计处理时间，员工主动催办
  • 判断依据：员工点击催办操作
  • 反馈形式：按钮置灰 + Toast + 审批人收到催办通知
  • 系统反馈：
  • 员工端："已催办审批人，请耐心等待"；[催办] 按钮置灰 24 小时
  • 审批人端：收到催办通知（"XXX 催办了权限申请：{权限名}"）
  • 用户下一步：等待审批人处理
  • 恢复路径：无需恢复，催办后路径回到等待审批状态
