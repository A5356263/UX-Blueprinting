§0 本次关键设计判断

来源可用性检查

检查项结果说明
角色与目标是否明确通过主角色为员工，目标为自助查看→申请→审批通过→自动生效
业务边界与对象是否明确通过业务对象为权限管理模块，范围覆盖功能权限和角色授权，不覆盖数据权限和协作可见性
关键状态与阻断是否明确通过主流程关键状态：浏览→申请→待审批→已通过/已拒绝→自动授权→生效；阻断包括审批拒绝、授权失败、重复申请等
是否存在会改写主流程的未决问题通过open_gaps 集中在基建成熟度，不影响主流程结构

本轮展开限制

本轮采用 full 展开模式。以下部分以 confirmed_facts 为稳定基础完整展开，working_assumptions 在对应节点标注为假设前提。

已确认可展开部分：

  • 员工端全流程：入口 → 浏览 → 申请 → 追踪 → 接收结果
  • 审批人端流程：待办接收 → 详情查看 → 审批操作
  • 管理员端配置：标记可申请项 → 保存生效
  • 自动授权执行：审批通过后触发 → 成功/失败反馈

当前不足以完整展开部分：

  • 审批流引擎的工程实现细节（依赖基建就绪度）
  • 移动端审批交互（蓝图层展开面）

判断1：双入口策略应对入口不可见风险

  • 判断：权限自助申请功能应采用"权限拦截处直达 + 工作台固定入口"双入口策略。在用户被权限拦截时，错误提示中直接提供"去申请权限"按钮；同时在员工端工作台或导航中设置固定入口。
  • 主要影响：入口页面设计、权限拦截提示文案、引导路径
  • 建议方案：权限拦截提示使用 Banner 组件，文案包含"你当前没有{权限名}的权限，点击去申请"；工作台入口置于"我的权限"聚合区
  • 不建议方案：仅设导航入口，不在拦截点做引导——会遗漏"不知道自己需要什么权限"的用户
  • 关键待确认：员工端入口落在工作台还是全局导航（open_gap）

判断2：目录分栏结构降低认知负担

  • 判断：权限目录采用"标签分栏"结构，将"功能权限"和"角色"分为两个独立 Tab，各自有独立的搜索和筛选。角色列表全量展示，可申请角色用徽标标识。
  • 主要影响：权限申请页面结构
  • 建议方案：默认展示"可申请的全部内容"聚合视图（含功能权限和角色混排），顶部提供"功能权限"和"角色"两个筛选项；角色卡片上加"可申请"标记
  • 不建议方案：功能权限和角色放在同列表混合展示且不做区分——员工无法建立两种授权方式的区别
  • 关键待确认：无

判断3：申请表单采用 Drawer + 单页结构

  • 判断：权限申请表单使用 Drawer 承载，采用单页长表单+锚点导航（非步骤条）。理由：选择权限和填写理由是并行任务，无强依赖关系，符合"默认非步骤化"原则（BFM-01）。
  • 主要影响：申请提交流程的界面形式
  • 建议方案：从目录页点击"申请"或勾选后点击"去申请"→打开 Drawer，左侧为已选项列表，右侧为理由输入区，底部为提交按钮
  • 不建议方案：使用步骤条 wizard——员工需要反复对照目录和已选项，步骤条增加修改成本
  • 关键待确认：无

判断4：审批上下文"三层信息"策略

  • 判断：审批人看到的申请详情，应包含三层信息：①申请人的身份和申请内容（是什么）；②申请理由（为什么）；③权限/角色的用途说明和风险提示（有什么影响）。三层信息应该递进展示，首屏展示①+②，可展开查看③。
  • 主要影响：审批详情页面结构
  • 建议方案：审批卡片首屏展示申请人+申请内容+申请理由+提交时间，下方折叠区域展示权限详情和风险说明
  • 不建议方案：仅展示申请内容和理由——审批人可能不了解某个权限的具体含义
  • 关键待确认：审批流引擎基建是否提供审批详情自定义能力

判断5：全链路状态追踪——不可只有终态通知

  • 判断：员工在提交申请到收到结果的等待区间，需要有"中间态可见性"。至少展示：已提交→审批人已查看→已通过/已拒绝。
  • 主要影响：我的申请页面设计、消息通知设计
  • 建议方案：我的申请页以时间线方式展示申请状态流转节点，每个节点附带时间戳；审批人查看申请后更新状态为"审批人已查看"
  • 不建议方案：只有提交成功通知和最终结果通知，中间全黑盒——导致等待焦虑和催办行为
  • 关键待确认：审批流引擎是否提供"审批人已查看"事件回调

§2 交互流程总览

路径清单

本设计包含以下交互路径：

编号路径说明
P1员工自助申请权限主路径：发现入口→浏览目录→提交申请→追踪进度→接收结果
P2审批人处理申请主路径：接收待办→查看详情→审批操作
P3员工查看我的申请分支路径：查看申请历史/进度/结果
P4员工查看我的权限分支路径：查看已生效权限/角色
P5管理员配置可申请目录分支路径：标记角色/功能权限为可自助申请
P6申请被拒绝后重新申请分支路径：查看拒绝原因→修改或重新提交
P7申请自动授权失败处理异常路径：授权失败通知→人工介入

P1 主路径：员工自助申请权限

我的工作台 / 权限拦截点 → 点击 [申请权限] 入口 → 打开 权限申请 Page（目录列表页） → 浏览功能权限 Tab / 角色 Tab → 点击 权限/角色 查看详情（Modal） → 勾选所需项 → 点击 [去申请] 或浮动按钮 → 打开 权限申请 Drawer → 已选项汇总区展示选中的权限/角色 → 填写申请理由 → 点击 [提交申请] → 校验通过 → Drawer 关闭 → Toast：申请已提交，等待审批 → 自动跳转至 我的申请 Page 查看进度

分支：

  • 未选择任何权限 → [去申请] 按钮置灰
  • 申请理由为空 → [提交申请] 置灰，提示"请填写申请理由"
  • 选择项中存在已拥有的权限 → 提交前检测提示"以下权限你已拥有，是否移除"
  • 审批人不存在 → Toast 提示"暂未匹配到审批人，请联系管理员"

P2 主路径：审批人处理申请

审批人收到待办通知（消息中心/审批待办入口） → 进入 审批待办列表 Page → 点击某条申请记录 → 打开 审批详情 Drawer → 查看申请人、申请内容、申请理由、权限说明 → 点击 [通过] 或 [拒绝] → 若拒绝，填写拒绝原因 → 确认操作 → Drawer 关闭 → Toast：操作成功 → 自动触发授权流程（通过时）/ 通知申请人（拒绝时）

分支：

  • 待办列表为空 → 空状态展示
  • 审批详情中权限已变更 → Toast 提示"该权限状态已变更，请刷新后查看"

P3 分支路径：员工查看我的申请

我的申请 Page → 展示申请记录列表（按时间倒序） → 每条记录展示：申请内容、提交时间、当前状态 → 点击某条记录可查看详情 → 状态：待审批 / 已通过 / 已拒绝 → 待审批时可看到当前处理人 → 已通过时可引导查看已生效权限 → 已拒绝时展示拒绝原因和[重新申请]入口

P4 分支路径：员工查看我的权限

我的权限 Page → 展示已生效的功能权限列表和角色列表 → 功能权限展示来源（直接授予/通过角色获得）和生效状态 → 角色展示所属角色名和成员状态 → 提供 [去申请] 跳转至可申请目录

P5 分支路径：管理员配置可申请目录

管理员后台 → 角色管理 / 功能权限管理 → 编辑角色或权限点 → 设置 [可自助申请] 开关 → 批量选择多个角色/权限点 → 批量标记/取消标记 → 保存配置 → Toast：配置已保存 → 员工端目录实时更新

分支：

  • 尝试标记敏感权限为可自助申请 → 开关禁用，Tooltip 提示"敏感权限不可设为自助申请"
  • 保存时网络异常 → Toast 提示"保存失败，请重试"

P6 分支路径：申请被拒绝后重新申请

拒绝通知 → 查看拒绝原因 → 点击 [修改后重新申请] → 打开 权限申请 Drawer（回填上次申请内容） → 修改申请内容或补充申请理由 → 重新提交

P7 异常路径：申请自动授权失败

审批人通过申请 → 系统自动触发授权 → 授权执行失败 → 通知审批人和申请人 → 通知内容包含失败原因和指引 → 申请人：请联系管理员处理 → 审批人：可联系系统管理员或查看授权日志

§3 主交互流程

节点 1：发现入口

1.1 权限拦截点引导

  • 用户动作：在业务功能入口被拦截，看到"无权限"提示
  • 系统反馈：Banner 提示"你当前没有{权限名}的权限"，下方提供 [去申请权限] 按钮
  • 需要前置解释的信息：说明点击后进入自助申请流程
  • 建议文案："你暂时没有使用该功能的权限，点击下方按钮可向你的上级发起权限申请"
  • 下一步：点击按钮 → 进入权限申请 Page（节点 2），未点击 → 用户可继续其他操作

1.2 工作台固定入口

  • 用户动作：进入工作台或在导航中找到"权限申请"入口
  • 系统反馈：展示入口名称和副标题
  • 需要前置解释的信息：无
  • 建议文案：入口名"权限申请"，副标题"查看和申请你需要的功能权限"
  • 下一步：点击入口 → 进入权限申请 Page（节点 2）

节点 2：浏览权限目录与提交申请

2.1 权限申请 Page — 目录浏览

  • 用户动作：进入权限申请页面，查看可申请的权限目录
  • 系统反馈：
  • 展示全量角色列表（按名称/创建时间排序）
  • 展示可申请的功能权限列表（按应用分类）
  • 角色列表中使用标签区分"可申请角色"和"全部角色"
  • 支持按应用、按类型分类筛选
  • 支持搜索角色名/权限名
  • 需要前置解释的信息：角色是权限的集合，加入角色即可获得一组关联的功能权限；功能权限是单个操作点的权限
  • 建议文案：角色区引导"加入角色可批量获得一组权限"，功能权限区引导"按需选择单个功能权限"
  • 下一步：点击角色/权限项的 [申请] 按钮或勾选后点击浮动 [去申请] → 节点 2.2

2.2 权限/角色详情 Modal

  • 用户动作：点击某个角色或功能权限的名称
  • 系统反馈：Modal 展示详情
  • 角色详情：角色名称、描述、包含的功能权限列表、成员数、申请前提
  • 功能权限详情：权限名称、所属应用、作用描述、适用端、申请前提
  • 需要前置解释的信息：每个角色的功能权限清单，让员工了解加入后会获得什么
  • 下一步：关闭 Modal → 回到目录页继续浏览；点击 [申请此角色/权限] → 节点 2.3

2.3 权限申请 Drawer — 提交申请

  • 用户动作：
  • 查看已选权限/角色汇总列表
  • 填写申请理由（必填）
  • 确认后点击 [提交申请]
  • 系统反馈：
  • 已选汇总区展示选中的角色和功能权限，支持移除
  • 申请理由输入区提供示例模板
  • 提交前校验：是否已选权限、理由是否为空、是否有重复申请
  • 校验不通过时，对应区域显示 InlineError
  • 需要前置解释的信息：申请理由的作用——帮助审批人了解你的具体业务需求
  • 建议文案：理由输入框占位文本"请说明你需要在什么业务场景中使用该权限，例如：我在XX业务中需要XX权限来做XX"
  • 下一步：校验通过 → 节点 2.4；取消 → Drawer 关闭，回到目录页

2.4 提交成功反馈

  • 用户动作：无（系统自动处理）
  • 系统反馈：
  • Drawer 关闭
  • Toast："申请已提交，等待上级审批"
  • 我的申请页新增一条"待审批"记录
  • 需要前置解释的信息：预计处理时间、审批人信息
  • 建议文案：Toast "申请已提交，你的上级{审批人姓名}将在XX小时内处理"
  • 下一步：自动跳转至我的申请 Page 查看进度（节点 3）

节点 3：追踪审批进度

3.1 我的申请 Page

  • 用户动作：主动查看申请进度
  • 系统反馈：
  • 展示历史申请记录列表（按时间倒序）
  • 每条记录展示：申请内容摘要、提交时间、当前状态、当前处理人（待审批时）
  • 状态标签：待审批（蓝色）/ 已通过（绿色）/ 已拒绝（红色）
  • 支持查看申请详情（点击展开）
  • 需要前置解释的信息：当前状态的下一步预期
  • 下一步：等待状态更新；点击进入具体申请详情

3.2 申请详情查看

  • 用户动作：点击某条申请记录
  • 系统反馈：展开/进入详情，展示：
  • 申请编号、提交时间
  • 申请的功能权限/角色完整列表
  • 申请理由
  • 审批进度时间线（已提交 → 审批人已查看 → 已通过/已拒绝）
  • 当前处理人信息（待审批时）
  • 已通过时额外展示：已生效权限列表 + [去使用] 按钮
  • 已拒绝时额外展示：拒绝原因 + [重新申请] 按钮
  • 建议文案：时间线节点文案"已提交""审批人已查看""已通过""已拒绝"
  • 下一步：通过→去使用权限；拒绝→重新申请

3.3 审批超时提示

  • 用户动作：申请提交超过预设时间（如24小时）未处理
  • 系统反馈：申请记录上出现 [催办] 按钮，状态标签旁出现"等待超时"标记
  • 建议文案：催办按钮文案"提醒审批人"
  • 下一步：点击催办 → 系统发送催办通知给审批人

节点 4：审批人处理

4.1 审批待办列表

  • 用户动作：审批人进入审批待办列表
  • 系统反馈：展示待审批的权限申请列表，按提交时间倒序排列
  • 每条展示：申请人姓名、申请内容摘要、申请理由、提交时间
  • 支持搜索和筛选
  • 下一步：点击某条记录 → 节点 4.2

4.2 审批详情 Drawer

  • 用户动作：查看申请详情
  • 系统反馈：
  • 首屏展示：申请人信息、申请权限/角色列表、申请理由
  • 展开区：每个权限/角色的用途说明和风险提示
  • 底部操作栏：[通过] [拒绝]
  • 需要前置解释的信息：权限的风险等级、适用范围——帮助审批人判断
  • 建议文案：风险提示区"该权限允许用户{权限作用描述}，请确认申请人的工作职责需要此权限"
  • 下一步：点击 [通过] 或 [拒绝]

4.3 审批操作确认

  • 用户动作：
  • 点击 [通过] → 二次确认弹窗（可选）
  • 点击 [拒绝] → 需填写拒绝原因
  • 系统反馈：
  • 通过：Drawer 关闭 → Toast "已通过" → 系统自动触发授权流程
  • 拒绝：填写原因 → 提交 → Drawer 关闭 → Toast "已拒绝" → 通知申请人
  • 建议文案：二次确认"确认通过 {申请人} 的权限申请？权限将自动生效"; 拒绝原因输入占位"请说明拒绝原因，申请人将收到该说明"
  • 下一步：流程结束或继续处理下一条待办

节点 5：自动授权执行

5.1 审批通过后自动触发

  • 用户动作：无（系统自动）
  • 系统反馈：
  • 审批通过事件触发自动授权
  • 功能权限授权或角色加入按顺序执行
  • 执行中状态：申请状态变为"授权中"
  • 下一步：执行完成 → 节点 5.2 或 5.3

5.2 授权成功

  • 系统反馈：
  • 申请状态更新为"已通过"
  • 员工权限即时生效
  • 通知申请人："你申请的{权限/角色}已生效"
  • 通知审批人："{申请人}的权限已生效"
  • 需要前置解释的信息：通知中包含"去使用"引导
  • 下一步：员工点击通知 → 跳转至对应功能入口

5.3 授权失败

  • 系统反馈：
  • 申请状态更新为"授权失败"
  • 通知申请人："授权失败，请联系管理员处理（失败原因：{原因}）"
  • 通知审批人："{申请人}的权限授权失败（失败原因：{原因}），请确认后联系系统管理员"
  • 建议文案：失败原因包括"授权服务暂时不可用""权限数据异常""角色成员已达上限"等
  • 下一步：管理员介入排查

§4 次交互流程

4.1 员工查看我的已有权限

  • 触发条件：员工在申请前想了解自己当前有哪些权限
  • 用户动作：进入"我的权限"页面
  • 系统反馈：
  • 展示已生效的功能权限列表（按应用分组）
  • 展示所属角色列表
  • 每条权限展示来源："直接授予"或"通过{角色名}获得"
  • 每条权限展示生效状态
  • 需要前置解释的信息：权限来源用于理解"为什么我有/没有这个权限"
  • 建议文案：来源标签"来自角色：{角色名}"、状态标签"已生效/生效中/已过期"
  • 下一步：点击 [去申请] → 跳转至权限申请 Page

4.2 管理员配置可自助申请目录

  • 触发条件：初始化自助申请功能或调整可申请范围
  • 用户动作：
  • 管理员进入后台角色管理或功能权限管理
  • 在编辑页中找到"可自助申请"开关
  • 开启后，该角色/权限点出现在员工可申请目录中
  • 系统反馈：
  • 角色管理：角色详情中新增"可自助申请"开关
  • 功能权限管理：权限点列表中新增"可自助申请"列，支持单个和批量操作
  • 敏感权限默认禁用且不可操作
  • 保存后实时生效
  • 需要前置解释的信息：开启后员工可自助申请，不需要管理员介入
  • 建议文案：开关旁说明"开启后，员工可在权限申请页面查看并申请此{角色/权限}"
  • 下一步：保存配置 → 员工端目录更新

4.3 申请被拒绝后重新申请

  • 触发条件：员工的权限申请被审批人拒绝
  • 用户动作：
  • 查看拒绝通知或在我的申请页查看
  • 点击 [修改后重新申请]
  • 修改申请内容或补充申请理由
  • 重新提交
  • 系统反馈：
  • 重新申请 Drawer 保留上次的申请内容
  • 可移除部分权限、补充理由
  • 提交后生成新的申请记录
  • 下一步：重新进入审批流程

4.4 员工催办

  • 触发条件：申请超过预设时间未处理
  • 用户动作：在我的申请页点击 [提醒审批人]
  • 系统反馈：
  • 发送催办通知给审批人
  • 员工侧展示"已提醒审批人"
  • 限制催办频率（如每4小时一次）
  • 建议文案：催办通知"你的下属{申请人}的权限申请已等待超过{时间}，请尽快处理"
  • 下一步：等待审批人处理

§5 异常与阻断流程

5.1 入口不可见 / 员工不知道自助申请

  • 发生时机：员工需要权限但不知有自助申请功能
  • 触发条件：员工在业务功能入口被权限拦截
  • 判断依据：当前权限状态为"无权限"
  • 反馈形式：权限拦截页面/提示中嵌入 [去申请权限] 按钮
  • 系统反馈：Banner 提示 + 去向按钮
  • 用户下一步：点击按钮进入目录页申请
  • 恢复路径：原路恢复，无信息丢失。如果员工关掉提示，可通过工作台固定入口再次进入。

5.2 审批人不存在或已离职

  • 发生时机：员工提交申请后，系统匹配审批人阶段
  • 触发条件：组织架构中未找到申请人的上级负责人，或上级负责人已离职/禁用
  • 判断依据：根据组织域数据查询审批人失败
  • 反馈形式：Toast 提示 + 引导联系管理员
  • 系统反馈：
  • 申请状态更新为"审批人匹配失败"
  • 通知申请人："暂未匹配到你的上级审批人，请联系管理员设置"
  • 通知超级管理员/权限管理员："员工{姓名}的权限申请因缺少审批人无法处理"
  • 用户下一步：联系管理员确认组织负责人关系
  • 恢复路径：管理员修复组织负责人关系后，系统自动重新匹配审批人，恢复审批流程。无信息丢失。

5.3 审批超时

  • 发生时机：申请提交后，审批人长时间未处理
  • 触发条件：超过预设时限（如24小时/48小时）审批人未操作
  • 判断依据：系统计时器检测超过时限
  • 反馈形式：员工端可催办，审批端超时标记
  • 系统反馈：
  • 员工端：申请记录出现 [提醒审批人] 按钮，状态旁"等待超时"标记
  • 审批端：待办列表中超时申请置顶显示，带"超时"标记
  • 如超时超过更长时间（如72小时），系统通知审批人的上级
  • 用户下一步：员工可催办，审批人尽快处理
  • 恢复路径：审批人操作后恢复正常流程。催办不改变审批流程，仅发送通知。

5.4 自动授权失败（系统异常）

  • 发生时机：审批通过后，系统自动执行授权时
  • 触发条件：授权服务不可用、权限数据异常、目标角色成员已达上限
  • 判断依据：授权执行接口返回失败
  • 反馈形式：通知申请人 + 审批人，应用状态更新为"授权失败"
  • 系统反馈：
  • 申请状态更新为"授权失败"
  • 通知：申请人 + 审批人分别收到失败通知
  • 失败原因格式化展示
  • 用户下一步：申请人联系管理员；审批人可查看失败原因并协助排查
  • 恢复路径：
  • 管理员排查修复后，可在后台选择"重新执行授权"
  • 恢复后员工权限生效，申请状态更新为"已通过"
  • 原路恢复，无信息丢失。用户之前的申请内容和审批记录完整保留。

5.5 批量授权部分成功部分失败

  • 发生时机：员工一次性申请了多个权限/角色，审批通过后自动授权
  • 触发条件：部分权限授权成功，部分失败（如某个角色已满员）
  • 判断依据：逐项执行授权时，部分项返回失败
  • 反馈形式：通知中展示"成功/N项，失败/M项"
  • 系统反馈：
  • 申请状态：部分成功（非终态）
  • 成功项即时生效
  • 失败项逐条说明原因
  • 通知："{N}项权限已生效，{M}项授权失败（失败原因：...）"
  • 用户下一步：对失败项，可单独重新申请或联系管理员
  • 恢复路径：失败项可单独重新提交申请（不需重复申请已成功的项），重新进入审批流程。

5.6 重复申请已拥有权限

  • 发生时机：员工提交申请前或提交时
  • 触发条件：员工选择的权限/角色中，部分已拥有且仍在有效期内
  • 判断依据：系统检测到申请项与已有权限重叠
  • 反馈形式：InlineError 提示，不阻断提交
  • 系统反馈：
  • 提交前校验：检测到重复项
  • InlineError："以下权限/角色你已拥有，可移除后再提交"
  • 已选项汇总区中重复项旁标记"已拥有"
  • 支持一键移除所有重复项
  • 用户下一步：移除重复项后提交，或保留重复项（系统自动过滤）
  • 恢复路径：无阻断，用户可选择移除或不处理。

5.7 申请时敏感权限被错误展示

  • 发生时机：员工浏览可申请目录时
  • 触发条件：（异常情况）员工看到不可申请的敏感权限出现在目录中
  • 判断依据：敏感权限标记系统级保护
  • 反馈形式：不可见或展示为"不可申请"状态
  • 系统反馈：
  • 正常情况：敏感权限不展示在目录中
  • 异常情况（万一展示）：显示为灰色禁用态，Tooltip "该权限暂不支持自助申请"
  • 用户下一步：联系管理员线下处理
  • 恢复路径：不可操作，无需恢复。

  • 无搜索结果："没有找到'{关键词}'，试试其他关键词"
