# 用户旅程：企业数字化产品权限自助申请

- **运行模式**：`prd-standalone`
- **是否使用补问**：否
- **数据来源**：`problem-framing`（问题框定）+ `stories`（用户故事）
- **结果等级**：完整旅程
- **聚焦角色**：员工（业务人员/经办人员）

---

## 角色摘要

| 角色 | 类型 | 在旅程中的位置 |
|------|------|----------------|
| 员工（业务人员/经办人员） | 主行动角色 | 完整旅程，从感知需求到获得权限/收到结果 |
| 上级组织负责人（审批人） | 协作角色 | 审批阶段介入（审批待办 → 审批操作） |
| 权限管理员 | 后台角色 | 旅程外配置可申请目录（前提条件） |

---

## 阶段正文

---

### 阶段一：感知需求与发现入口

| 字段 | 内容 |
|------|------|
| **阶段目标** | 员工意识到需要某项权限才能完成工作，并知道可以通过自助方式申请 |
| **用户行动** | 在工作中遇到权限不足提示或被功能入口挡住 → 询问同事"这个功能怎么用不了" → 同事/文档告知可通过权限自助申请 → 找到申请入口 |
| **触点** | 系统权限拦截提示、同事（口头/IM）、帮助文档/FAQ、工作台首页/导航入口 |
| **用户心声** | "我根本不知道还能自己申请权限，以前都是找xx帮忙的" |
| **置信度** | 中 |
| **置信度依据** | 基于问题框定中用户描述的场景推导——当前做法是私下找管理员，员工对自助申请的存在和入口无认知 |
| **痛点** | • 员工不知道平台有自助申请功能，回到找人的老路<br>• 入口不明显或藏在深层菜单中，员工找不到<br>• 权限被拦截时只看到"无权限"提示，没有引导去向 |
| **流失风险** | 高。员工如果不知道自助入口，会直接回到"找管理员/老板"的旧模式，自助申请的价值归零 |
| **设计机会** | • 权限拦截时直接给出自助申请入口（"去申请权限"按钮）<br>• 在工作台/首页提供显性化的自助申请入口<br>• 新员工入职引导中加入权限自助申请的指引 |

**阶段转折**：员工找到入口并进入权限申请页面 → 进入阶段二

---

### 阶段二：浏览与评估

| 字段 | 内容 |
|------|------|
| **阶段目标** | 在可申请目录中找到自己需要的权限或角色，理解其含义和作用 |
| **用户行动** | 进入权限申请页面 → 查看可申请的角色列表和功能权限列表 → 浏览分类/搜索权限名称 → 点击查看详情 → 判断"这个是不是我需要的" → 对比不同选项 |
| **触点** | 权限申请页面、目录筛选/搜索、权限/角色详情弹窗、分类标签页 |
| **用户心声** | "这么多权限和角色，我到底该申请哪个？" |
| **置信度** | 高 |
| **置信度依据** | 上游直接提供了目录结构、分类方式和员工可看到全部角色的规则（confirmed_facts） |
| **痛点** | • 权限名称为技术编码，员工看不懂是什么<br>• 功能权限与角色的区别不清晰，不确定选哪种方式<br>• 不知道申请某个权限后会有什么实际影响（"会不会给了太多权限？"）<br>• 角色列表全量展示，但只有部分可申请，区分不直观<br>• 搜索结果为空时不知道是没权限还是没搜对关键词 |
| **流失风险** | 中。看不懂目录→随意选一个试试/放弃自助转而问人 |
| **设计机会** | • 权限描述使用业务语言，说明"谁可以用""用来做什么""申请后能做什么"<br>• 角色与功能权限分栏展示，明确说明各自适用场景<br>• 为每个权限/角色标注申请前提或推荐人群<br>• 搜索结果为空时提供引导"试试其他关键词"或"联系管理员确认" |

**阶段转折**：员工确定了需要申请的权限或角色 → 进入阶段三

---

### 阶段三：申请提交

| 字段 | 内容 |
|------|------|
| **阶段目标** | 选择所需权限/角色，填写申请理由，成功提交申请 |
| **用户行动** | 勾选需要申请的功能权限/角色 → 查看已选项汇总 → 填写申请理由 → 确认提交 → 收到提交成功反馈 |
| **触点** | 申请表单（权限选择区、理由输入区、汇总确认区）、提交成功提示 |
| **用户心声** | "希望理由写得够清楚，上级能理解我为什么需要这个权限" |
| **置信度** | 高 |
| **置信度依据** | 上游 confirmed_facts 和故事 US-02 完成标准提供了完整的申请流程定义 |
| **痛点** | • 不确定申请理由要写多详细，写太简单怕被拒、写太复杂费时间<br>• 一次性申请多个权限时，审批人可能只熟悉其中一部分，部分被拒的原因不明<br>• 已拥有的权限没有前置提示，提交后才被告知重复 |
| **流失风险** | 低。流程明确、操作简单，但"不确定怎么写理由"可能在理由输入处卡住 |
| **设计机会** | • 申请理由输入框提供示例模板（"我在XX业务中需要XX权限来做XX"）<br>• 提交前自动检测已拥有权限并提示移除<br>• 提交成功后清晰告知下一步（"你的申请已提交给XX审批，预计处理时间为XX"） |

**阶段转折**：提交成功 → 进入阶段四（等待审批）

---

### 阶段四：等待审批

| 字段 | 内容 |
|------|------|
| **阶段目标** | 了解申请进度，等待上级处理，在需要时跟进 |
| **用户行动** | 收到提交成功通知 → （被动）等待审批 → 间歇性查看"我的申请"页面了解进度 → （主动）如果着急可能私聊上级提醒 |
| **触点** | 提交成功通知、我的申请页面、审批状态标签、消息通知 |
| **用户心声** | "审批怎么还没好，我都等了一天了……" |
| **置信度** | 中 |
| **置信度依据** | 等待行为和情绪反应基于体验设计常识推导，审批流基建成熟度仍为 open_gap |
| **痛点** | • 不知道审批人什么时候处理，等待焦虑<br>• 审批超时无人跟进，员工也不敢催上级<br>• 只有"待审批"一个状态，没有更细的进度信息（如"审批人已查看但未操作"）<br>• 着急用权限但只能被动等待 |
| **流失风险** | 高。等待时间过长→员工绕过流程找管理员直接授权→自助流程被架空且产生不一致的授权记录 |
| **设计机会** | • 提交时告知预计审批时间（"通常XX小时内处理"）<br>• 审批超时自动提醒审批人<br>• 我的申请页展示审批进度节点（已提交→审批人已查看→已通过/已拒绝）<br>• 审批超时后允许员工自助催办 |

**阶段转折**：审批人处理申请 → 进入阶段五

---

### 阶段五：结果处理

| 字段 | 内容 |
|------|------|
| **阶段目标** | 获得权限开始工作 / 了解被拒绝原因并决定下一步 |
| **用户行动** | **通过场景：** 收到审批通过通知 → 查看已生效权限 → 回到工作场景使用权限<br>**拒绝场景：** 收到拒绝通知 → 查看拒绝原因 → 决定是否重新申请、补充说明或放弃 |
| **触点** | 审批结果通知（站内信/消息）、我的权限页面、已生效权限列表、权限功能入口 |
| **用户心声** | **通过时：** "终于有了，可以继续干活了"<br>**拒绝时：** "为什么拒绝我？那我怎么办？" |
| **置信度** | 高 |
| **置信度依据** | 上游 confirmed_facts 明确了自动生效规则，stories 提供了通过和拒绝两个分支的验收标准 |
| **痛点** | • **通过后：** 权限生效了但员工不知道去哪里用<br>• **拒绝后：** 拒绝原因太笼统，不知道如何改进重新申请<br>• **拒绝后：** 没有重新申请的入口或指引，又回到找人的老路<br>• **自动授权失败：** 系统提示"授权失败"但员工不知道找谁处理 |
| **流失风险** | 中。拒绝场景下如果没有明确的重新申请路径，员工会退回找管理员模式 |
| **设计机会** | • 通过后引导到对应的功能入口（"去看看新权限"）<br>• 拒绝原因结构化（提供具体原因而非一句话带过）<br>• 提供"修改后重新申请"按钮，保留原申请内容供修改<br>• 授权失败时明确引导："请联系管理员处理"并附管理员联系方式 |

**阶段转折**：旅程终点。员工获得权限并开始使用，或决定下一步行动。

---

## 阶段转折汇总

| 阶段 | 进入条件 | 退出条件 |
|------|----------|----------|
| 感知需求与发现入口 | 员工在业务场景中被权限拦住 | 员工找到自助申请入口 |
| 浏览与评估 | 员工进入权限申请页面 | 员工确定需要申请的权限/角色 |
| 申请提交 | 员工开始选择权限 | 申请成功提交 |
| 等待审批 | 提交成功通知 | 收到审批结果通知 |
| 结果处理 | 收到审批结果通知 | 员工开始使用权限 / 决定下一步行动 |

## 缺口说明

| 缺口 | 影响阶段 | 说明 |
|------|----------|------|
| 审批流引擎就绪度 | 阶段四 | 影响审批待办路由和超时处理机制 |
| 上级负责人关系链路 | 阶段四 | 影响审批人自动匹配准确性 |
| 自动授权执行接口 | 阶段五 | 影响自动生效的成败 |
| 敏感权限标记机制 | 阶段二 | 影响目录筛选逻辑（员工是否能看到排除了敏感权限的目录） |
| 员工端入口位置 | 阶段一 | 影响入口显性化策略（工作台/导航/全局） |
