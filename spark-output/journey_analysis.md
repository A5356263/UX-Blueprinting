# 用户旅程分析：财富专区-资产配置面客版

- **运行模式**：`uxb-chain`
- **是否使用补问**：否
- **数据来源**：`spark-output/context/uxb.json`、`spark-output/uxb_output.md`、`input/【财富专区】资产配置面客版.md`
- **结果等级**：完整旅程

---

## 角色摘要

**企业客户**是财富专区的终端用户，持有理财产品、公募基金、资管计划、信托计划等多种资产。原来每月查看一次诊断报告来了解持仓情况，受限于功能单一（仅按月查看）、不能保存、没有直接购买入口。本次升级后，可以随时按需查看资产配置建议书，获得诊断建议和产品推荐，并可直接跳转购买。

---

## 用户旅程：企业客户查看资产配置建议书并采取行动

---

### 阶段 1：进入与账号定位

| 字段 | 内容 |
|------|------|
| **阶段名称** | 进入与账号定位 |
| **用户目标** | 找到资产配置入口，定位到要查看的账号 |
| **用户动作** | • 从财富专区菜单点击"资产配置"（原理财月报更名）<br>• 或从持仓列表页面点击资产配置入口<br>• 在页面上选择要查看的银行账号（默认展示全部账号） |
| **触点** | 财富专区导航菜单、持仓列表页面、资产配置页面、账号选择器 |
| **用户心声** | "我先看看我的整体资产情况。" |
| **信心度** | **高** |
| **信心依据** | 需求文档明确了两个入口路径和入口规则 |
| **痛点** | • 从持仓列表进入时自动选中当前查看的账号，但从菜单进入时默认全部，入口差异可能导致用户困惑"为什么两次看到的数据不一样"<br>• 若用户没有可访问权限的账号，看到空状态时不确定如何获得权限 |
| **流失风险** | **低** — 入口路径明确，用户有明确查看目标，不太可能在此阶段放弃 |
| **设计机会** | • 账号选择器标注当前选中的账号范围和账号数量<br>• 无可访问账号时的权限申请路径引导 |

### 阶段 2：了解资产全貌

| 字段 | 内容 |
|------|------|
| **阶段名称** | 了解资产全貌 |
| **用户目标** | 了解自己当前的总资产规模、各类资产分布和资金占用情况 |
| **用户动作** | • 查看当前时点资产总额<br>• 查看持仓表现数据：时点资产、区间收益、年化收益率、购买/赎回记录<br>• 查看投资分布饼图，了解理财/基金/资管/信托各自的占比<br>• 查看期限分布，了解各期限产品的持仓情况<br>• 如需调整时间范围，使用时间区间筛选器 |
| **触点** | 持仓表现模块（含数据卡片和趋势图）、投资分布饼图、期限分布列表、时间区间筛选器 |
| **用户心声** | "原来我的钱是这样分布的。" |
| **信心度** | **高** |
| **信心依据** | 需求文档对各模块的展示内容、数据来源、单位换算规则都有详细说明 |
| **痛点** | • **信息密度高**：时点资产、收益、购买赎回、趋势图、分布饼图同时展示，用户不确定应该先看什么<br>• **模块联动模糊**：调整时间区间后，持仓表现和趋势图等多个模块需要同步刷新，若加载反馈不清晰，用户可能重复点击或误以为页面卡住<br>• **范围差异隐忧**：投资分布和期限分布覆盖多资产类型，但持仓表现仅支持理财，如果范围边界没有在模块头部表达清楚，用户可能误以为"基金数据没出来"<br>• **数值感知**：金额在元/万元/亿元之间自动切换，用户可能对大规模数字的实际量级感知不准确 |
| **流失风险** | **中** — 信息密度高，用户可能感到认知超载而快速扫过关键信息，甚至跳过部分模块直接去底部 |
| **设计机会** | • 按"核心指标→分布概览→明细数据"的阅读层级组织模块视觉权重<br>• 模块级别表达资产覆盖范围（如"持仓表现（仅理财）"）<br>• 时间区间筛选后各模块独立反馈加载进度 |

### 阶段 3：接收诊断与配置建议

| 字段 | 内容 |
|------|------|
| **阶段名称** | 接收诊断与配置建议 |
| **用户目标** | 了解自己的持仓是否存在问题，以及应该如何优化 |
| **用户动作** | • 查看持仓诊断结果——集中度过高/产品到期/持仓时间过长<br>• 如有诊断问题，点击查看对应的产品列表和详情<br>• 查看产品推荐列表，了解建议持有类型、收益率、最大回撤和推荐理由<br>• 对比不同推荐产品的差异 |
| **触点** | 持仓诊断卡片（集中度/到期/时长展开列表）、产品推荐列表、产品详情链接 |
| **用户心声** | "我现在这样配置有问题吗？应该怎么调整？" |
| **信心度** | **高** |
| **信心依据** | 诊断规则（集中度阈值≥60%、到期近两周、持仓时长判断）和产品推荐逻辑在需求文档中有明确说明 |
| **痛点** | • **"没问题"的不确定性**：无诊断问题时诊断模块整体不展示，用户不确定"是数据没加载出来"还是"确实没有问题"<br>• **覆盖范围落差**：诊断和推荐仅限理财，但用户可能在公募基金或信托计划中有更大持仓，看到这里发现"我的基金呢？"——这是旅程中最关键的认知落差<br>• **推荐决策成本高**：产品推荐列表展示收益率、最大回撤、推荐理由，但多个产品并列时用户需要自行对比判断，缺乏明确的"哪个更适合我"的指引<br>• **数据可信度隐忧**：净值精度有限（文档明确说明"仅供参考"），用户可能对诊断结论的准确性和推荐收益率的可实现性持保留态度 |
| **流失风险** | **中-高** — 这是整个旅程的核心价值环节。如果用户发现诊断不覆盖自己的主要资产类型（如基金占大头），或者对数据精度不信任，可能在此阶段放弃继续操作 |
| **设计机会** | • 诊断模块头部清晰标注范围，与分布模块建立视觉关联<br>• 产品推荐按用户的实际持仓结构做排序或标注匹配度<br>• 对可能引起信任疑虑的数据点，就近提供精度和时效的简短说明 |

### 阶段 4：决策与行动

| 字段 | 内容 |
|------|------|
| **阶段名称** | 决策与行动 |
| **用户目标** | 根据诊断和建议采取行动：购买推荐产品或保存/下载建议书 |
| **用户动作** | • **单独购买**：点击单个产品的购买按钮，新开页签跳转至购买页<br>• **批量购买**：勾选多个产品后点击批量购买，跳转购物车<br>• **下载建议书**：点击浮动下载按钮，选择PDF或PNG格式<br>• **不接受/暂不决策**：直接关闭页面 |
| **触点** | 购买按钮、产品详情页（新页签）、购物车、下载按钮、下载格式选择弹窗 |
| **用户心声** | "这个推荐看起来不错，先买这个试试。不过先下载下来，回头再研究研究。" |
| **信心度** | **中** |
| **信心依据** | 需求文档明确了购买和下载的操作方式，但用户的实际决策路径高度依赖个人投资偏好和风险判断 |
| **痛点** | • **购买跳转与上下文丢失**：购买跳转到新页签后，用户完成购买回到原页签，但页面状态（滚动位置、已选账号、筛选区间）可能已不是当时做决策时的上下文<br>• **批量选择的认知负担**：批量购买需要用户勾选多个产品，但各产品在收益率、风险、期限等维度上有差异，用户需要反复对比才能决定<br>• **下载结构差异**：分Tab浏览在下载后平铺为一份长文档，用户可能在PDF中找不到在页面上看到的对应信息<br>• **缺少保留途径**：本版本不支持保存建议书，用户如果想下次再决策，只能下载留底或让页面状态丢失 |
| **流失风险** | **中** — 购买决策本身有资金门槛和心理门槛，用户可能选择"先下载，下次再说"。如果没有足够的决策信心，可能在此阶段止步于行动前 |
| **设计机会** | • 购买跳转后在原页签维持用户离开时的页面状态<br>• 下载产物保留页面模块标题和层级结构，建立线上线下的对应关系<br>• 提供"暂存当前配置"的轻量路径 |

### 阶段 5：收尾与离场

| 字段 | 内容 |
|------|------|
| **阶段名称** | 收尾与离场 |
| **用户目标** | 带走本次查看结果，或记住下次再来的线索 |
| **用户动作** | • 保存已下载的PDF/PNG文件<br>• 记住要关注的产品名称<br>• 关闭浏览器页签 |
| **触点** | 下载文件（PDF/PNG）、浏览器下载管理、个人记忆或笔记 |
| **用户心声** | "先下载下来，回头再研究研究。"
| **信心度** | **中** |
| **信心依据** | 用户收尾行为依赖个人习惯，需求文档只提供了下载功能 |
| **痛点** | • **无保存机制**：本版本不支持保存建议书，用户如果需要再次查看同一份配置建议，需要重新进入页面、选择账号、加载数据，所有操作重新来一遍<br>• **离开即丢失**：没有历史记录，用户关闭页面后无法回到本次建议书的上下文<br>• **线下线上结构差异**：下载的平铺文档与线上分Tab结构不同，用户下载后离线阅读时，可能还需要回到线上对照 |
| **流失风险** | **中** — 收尾选择有限（只能下载，不能保存或收藏），部分用户可能空手离开，下次使用意愿降低 |
| **设计机会** | • 确认用户是否已下载建议书后再离开的轻量提醒<br>• 下载文档首页增加内容索引，对应线上模块结构 |

## 阶段转折汇总

| 从 | 到 | 触发条件 | 转折风险 |
|----|----|----------|---------|
| 进入与账号定位 | 了解资产全貌 | 用户选择账号后数据加载完成 | **阻断风险**：无持仓数据时展示空状态，用户在此转折处被阻断 |
| 了解资产全貌 | 接收诊断与建议 | 用户滚动浏览至诊断模块 | **流失风险**：信息密度过高，用户在分布图表处停留过久，未到达诊断和推荐模块 |
| 接收诊断与建议 | 决策与行动 | 用户对某推荐产品产生兴趣或接受诊断建议 | **放弃风险**：若诊断无问题且推荐不吸引人，用户可能跳过此阶段直接收尾 |
| 决策与行动 | 收尾与离场 | 用户完成购买或决定暂不操作 | **流失风险**：购买跳转到新页签后，用户可能在购买流程中分心，不再回到建议书页面 |
