# 旅程分析：子管理员权限复制能力

## 元信息

- **运行模式**：`prd-standalone`
- **是否使用补问**：否
- **数据来源**：`problem-framing`（问题框定）、`stories`（用户故事）
- **结果等级**：完整旅程

## 角色

| 角色 | 定位 | 旅程类型 |
|------|------|----------|
| 企业超管（主管理员） | 为子管理员配置权限的执行者 | 单段旅程（权限复制场景） |

## 旅程全景：企业超管批量复制子管理员权限

### 阶段概览

| # | 阶段 | 阶段目标 | 流失风险 |
|---|------|----------|----------|
| 1 | 锁定参照 | 确认合适的源子管理员作为权限模板 | 低 |
| 2 | 圈定目标 | 确定要复制的目标范围 | 中 |
| 3 | 定规则与执行 | 按预期策略完成权限复制操作 | 高 |
| 4 | 核验结果 | 确认复制结果准确无误 | 中 |
| 5 | 适配收尾 | 处理个别差异后完成配置 | 低 |

### 阶段 1：锁定参照

- **目标**：找到一个权限配置与需求最接近的现有子管理员作为复制源
- **来源说明**：`原文提取`

**用户行动**

| # | 动作 | 触点 | 用户心声 |
|---|------|------|----------|
| 1 | 收到新子管理员创建需求，评估其职责范围 | 系统外（人事流程/IT 工单） | "这次跟分公司运营经理差不多" |
| 2 | 进入子管理员管理列表，浏览现有成员 | 子管理员列表页 | "先看看谁跟新来的权限最像" |
| 3 | 根据名字/职责描述筛选候选源 | 列表搜索/筛选 |  |
| 4 | 选中候选源，查看其权限全景概览 | 权限全景预览面板 | "确认一下他到底开了哪些权限" |
| 5 | 确认该子管理员可作为复制源 | — | "就他了" |

**详细分析**

| 字段 | 内容 |
|------|------|
| 名称 | 锁定参照 |
| 目标 | 确认合适的源子管理员作为权限模板 |
| 动作 | 收到创建需求 → 进入管理员列表 → 浏览/筛选 → 选中并查看权限全景 → 确认为源 |
| 触点 | 人事/IT 工单（系统外）、子管理员列表页、搜索筛选、权限全景预览面板 |
| 用户心声 | "新来的跟分公司运营经理差不多，先看看他开了哪些权限" |
| 置信度 | 高 |
| 置信度依据 | 问题框定和用户故事 S1 均明确描述该步骤，客户诉求直接提及"现有子管理员直接复制" |
| 痛点 | 1. 如果子管理员列表较长（50+），靠名字和职责筛选不够直观；<br>2. 权限全景项过多时加载慢，影响确认效率；<br>3. 如果权限结构复杂（横跨 10+ 子应用），全景预览的可读性不足 |
| 流失风险 | 低——即使查看不方便，超管通常不会在此步骤放弃，但可能降低使用复制功能的意愿 |
| 设计机会 | 提供源推荐的"权限接近度"提示；全景预览支持展开/折叠分组，默认收起细节只显示概览 |

---

### 阶段 2：圈定目标

- **目标**：选择要复制权限的目标子管理员，确定批量范围
- **来源说明**：`原文提取`

**用户行动**

| # | 动作 | 触点 | 用户心声 |
|---|------|------|----------|
| 1 | 在复制流程中进入目标选择步骤 | 复制操作页 | "这次有好几个人的权限要配" |
| 2 | 按部门/角色/地区筛选潜在目标 | 搜索/筛选控件 | "先把华东区运营经理们都勾上" |
| 3 | 逐一确认目标清单，查看其现有权限状态 | 目标列表、权限状态指示 | "这几个已经有部分权限了，要注意一下" |
| 4 | 确认目标清单 | 已选项展示区 | "就这些，下一步" |

**详细分析**

| 字段 | 内容 |
|------|------|
| 名称 | 圈定目标 |
| 目标 | 确定要复制的目标范围 |
| 动作 | 进入复制操作页 → 搜索筛选目标 → 查看现有权限状态 → 确认目标清单 |
| 触点 | 复制操作页（目标选择区）、目标多选列表、搜索筛选、权限状态指示 |
| 用户心声 | "这次华东区三个运营经理都要配，先看看他们现在有没有配过" |
| 置信度 | 高 |
| 置信度依据 | 问题框定明确"单源复制到多目标"，用户故事 S2 完整描述该步骤 |
| 痛点 | 1. 目标数量多时（10+），逐一勾选 + 逐一查看现有权限状态的操作链条较长；<br>2. 目标列表缺少分组能力（如按部门/组织批量勾选）；<br>3. 看不清各目标与源的权限差距，可能选了不合适的目标 |
| 流失风险 | 中——目标过多时用户可能放弃批量复制，退回逐一配置 |
| 设计机会 | 支持批量勾选（全选/按组选）；在目标列表中嵌入权限差异标签（"与源有 N 项差异"）； |

---

### 阶段 3：定规则与执行

- **目标**：确定冲突处理策略后一键完成复制
- **来源说明**：`规则推导`（策略偏好待确认）

**用户行动**

| # | 动作 | 触点 | 用户心声 |
|---|------|------|----------|
| 1 | 查看哪些目标已有权限冲突 | 冲突列表/差异对比 | "这几个已经配了一些，别给覆盖了" |
| 2 | 选择冲突处理策略（追加/覆盖/逐项确认） | 策略选择控件 | "追加吧，有冲突的系统提示我" |
| 3 | 最终确认源、目标清单和策略 | 确认摘要面板 | "再检查一遍——源、目标、策略都对" |
| 4 | 点击执行，等待复制完成 | 确认按钮、进度指示器 | "一下子配好这么多人，爽" |
| 5 | 接收复制结果（成功/部分失败/失败） | 结果提示 | "嗯？华东运营经理 3 号复制失败了？" |

**详细分析**

| 字段 | 内容 |
|------|------|
| 名称 | 定规则与执行 |
| 目标 | 按预期策略完成权限复制操作 |
| 动作 | 查看冲突 → 选择策略 → 最终确认 → 执行复制 → 接收结果 |
| 触点 | 冲突列表、策略选择控件、确认摘要面板、执行按钮、进度指示器、结果提示 |
| 用户心声 | "这些人大部分权限差不多，先追加过去，有冲突的再单独看" |
| 置信度 | 中 |
| 置信度依据 | 用户故事 S3 已描述冲突处理，但默认策略偏好仍需与客户确认 |
| 痛点 | 1. 冲突策略选错可能导致权限意外变更（覆盖了不该改的）；<br>2. 执行过程中没有取消按钮，错误操作后无法中断；<br>3. 部分失败时信息不清晰，不知道哪些目标成功、哪些失败；<br>4. 执行时间受权限项数量和目标数量影响，缺少时间预估 |
| 流失风险 | 高——策略选择不确定时可能不敢执行；执行后部分失败但信息不全时可能导致后续手动修复成本更高 |
| 设计机会 | 执行前提供"变更预览"（模拟执行结果）；执行中允许中断；部分失败时提供"重新执行失败项"的快捷操作 |

### 阶段 4：核验结果

- **目标**：确认每个目标的权限变更符合预期
- **来源说明**：`原文提取`

**用户行动**

| # | 动作 | 触点 | 用户心声 |
|---|------|------|----------|
| 1 | 查看变更摘要，按目标分支浏览 | 变更摘要页 | "看看这次到底改了哪些" |
| 2 | 展开有疑问的目标，查看前后差异对比 | 差异对比视图 | "运营经理 2 号多了库存权限？不对啊" |
| 3 | 确认差异在预期范围内 | — | "哦，库存权限是从源带过来的，没问题" |
| 4 | 如需存档，确认操作已记入操作日志 | 操作日志 | "日志里有记录，后面审计能追溯到" |

**详细分析**

| 字段 | 内容 |
|------|------|
| 名称 | 核验结果 |
| 目标 | 确认复制结果准确无误 |
| 动作 | 查看变更摘要 → 展开差异对比 → 确认预期 → 核对日志 |
| 触点 | 变更摘要页、差异对比视图、操作日志列表 |
| 用户心声 | "运营经理 2 号的库存权限是哪儿来的？……哦，源带过来的，没问题" |
| 置信度 | 高 |
| 置信度依据 | 用户故事 S4 完整描述，体验侧关注点明确要求"复制后变更摘要" |
| 痛点 | 1. 变更项很多时差异对比视图的可读性差，难以快速定位意外变更；<br>2. 发现错误后缺少"一键回滚"入口，只能手动修复；<br>3. 操作日志中复制操作的颗粒度不够细（只记了"批量复制"，没记每项变更） |
| 流失风险 | 中——变更太多核对不过来时可能直接关闭，遗留配置错误风险 |
| 设计机会 | 差异对比按子应用分组，支持筛选"只看变更项"；发现错误后可直接在差异视图中逐个撤销（单项回滚） |

---

### 阶段 5：适配收尾

- **目标**：对职责有差异的目标做局部调整，完成全部配置
- **来源说明**：`原文提取`

**用户行动**

| # | 动作 | 触点 | 用户心声 |
|---|------|------|----------|
| 1 | 从结果摘要直接进入需要微调的目标编辑页 | 权限编辑页 | "运营经理 3 号不用管库存，去关掉" |
| 2 | 在搜索/筛选中快速定位目标权限项 | 搜索/筛选 | "找找库存管理在哪个子应用下" |
| 3 | 关闭/调整不需要的权限项 | 权限树/列表编辑控件 | "这个关掉，那个只读就行" |
| 4 | 保存并验证修改生效 | 保存按钮 | "好了，这个搞定了" |
| 5 | 重复 1-4 步完成其他目标微调后退出 | — | "全部搞定，比一个一个配快多了" |

**详细分析**

| 字段 | 内容 |
|------|------|
| 名称 | 适配收尾 |
| 目标 | 处理个别差异后完成配置 |
| 动作 | 进入目标编辑 → 搜索定位差异项 → 调整权限 → 保存验证 → 重复至全部目标完成 |
| 触点 | 权限编辑页、搜索/筛选、权限树/列表控件、保存按钮 |
| 用户心声 | "运营经理 3 号跟源不一样，不用库存权限，关掉就好" |
| 置信度 | 中 |
| 置信度依据 | 客户明确要求"复制后微调"，但微调的交互形态（逐目标独立编辑 vs 批量差异编辑）待确认 |
| 痛点 | 1. 如果有 5 个目标要微调，每个都要独立进入编辑页操作，仍有一定重复感；<br>2. 需要清楚记得源权限的配置才能知道差异在哪里，缺少"与源的差异项高亮"；<br>3. 微调后需逐一保存，目标较多时容易遗漏 |
| 流失风险 | 低——已经完成了大部分工作，微调是收尾步骤，放弃意愿低 |
| 设计机会 | 编辑页中高亮"与源的差异项"；支持"从复制结果摘要中标记哪些目标需要微调"的批量跳转 |
