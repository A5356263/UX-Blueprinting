# 旅程分析：子管理员权限复制

> 生成时间：2026-07-09 / 运行模式：链式 / 数据来源：spark-output/uxb_output.md + spark-output/context/uxb.json

## 权限管理员 / 超级管理员

角色概述：负责维护企业子管理员配置，在面临大量子管理员需要相同权限配置时，通过复制能力批量完成权限复用。本次是其首次使用「复制」来完成原本逐人手动配置的工作。

### 1. 识别需求与定位来源

**用户目标**

在子管理员列表中找到那个「权限配置刚好合适」的已有子管理员，作为本次批量复制的参照。

**用户行动**

浏览或搜索子管理员列表，根据组织范围或功能配置判断哪个子管理员的权限设置是理想参照。

**关键触点**

- 子管理员列表页
- 列表的搜索和筛选功能
- 列表中每个子管理员的组织范围和功能配置信息

**用户心声**

「这两百多号人要配一样的权限，我总不能一个一个点过去。我先看看哪个人的配置是对的，照着他的来。」

**用户信心度**

高。判断依据：列表浏览和搜索是已有成熟能力，定位参照来源不涉及复杂判断。但列表只展示摘要信息时，管理员可能需要点进详情才能确认某个子管理员的具体权限范围。

**痛点**

- 当子管理员数量多（如 200+）且列表仅靠翻页浏览时，定位一个合适的参照来源本身也费时
- 列表摘要信息不足以判断「这个人的权限是不是我要的」，需逐人点进详情查看

**流失风险**

在列表中找不到明确参照时，管理员可能放弃使用复制，回到逐人手动配置的老路。

**设计机会**

- 列表支持按可授权组织范围、可授权功能维度进行筛选，帮助快速缩小参照范围（下游：蓝图）
- 列表卡片或行内直接展示关键权限摘要，减少点进详情的必要（下游：蓝图）

### 阶段转折

识别需求与定位来源 → 配置复制参数：管理员在列表中找到合适参照子管理员，点击该行操作列的「复制」按钮，弹窗打开。

---

### 2. 配置复制参数

**用户目标**

准确选择要复制的权限内容，并尽可能高效地选出所有需要接收权限的目标用户。

**用户行动**

在复制弹窗中确认复制信息（可授权组织、可授权功能默认全选，可按需取消勾选），然后通过员工选择器搜索并勾选目标用户（支持多选，最多 200 人）。

**关键触点**

- 复制弹窗
- 复制信息勾选区域（可授权组织 / 可授权功能）
- 员工选择器弹窗（复用「添加子管理员」的现有选择器）
- 已选目标用户列表

**用户心声**

「组织也要复制过去，功能也要。这些人我一个个搜出来勾上——等等，他们都在企业里吧？都是已认证的吧？我怎么看不出来？」

**用户信心度**

中。判断依据：复制信息选择简单明了（两项勾选），但选人环节存在不确定性——管理员在选择器中看不到目标用户的加入状态和认证状态，无法预判哪些人会校验失败。选了 200 人提交后才发现其中 20 人不合格，体验断裂。

**痛点**

- 选人器中不展示用户的加入状态和认证状态，管理员只能「盲选」
- 选完 200 人提交后才被告知其中有不合格者，所有选择可能需要重来（取决于产品对部分失败的策略）
- 员工选择器为通用组件，未必针对「复制为子管理员」场景做了状态提示优化

**流失风险**

- 选择过程中发现搜索体验不佳（如不支持批量粘贴名单），放弃批量复制
- 提交后被大量校验失败打击信心，退回逐人手动配置

**设计机会**

- 选人器中前置标识不符合加入/认证状态要求的用户（如下游：蓝图）
- 支持批量粘贴用户名单或按组织批量选择，减少逐人搜索操作（下游：蓝图）
- 弹窗中实时显示已选用户数量和上限（如「已选 120/200 人」）（下游：蓝图）

### 阶段转折

配置复制参数 → 确认并提交：管理员完成复制信息和目标用户的选择，点击弹窗「确认」按钮，系统开始校验。

---

### 3. 确认并提交

**用户目标**

在提交前理解操作的具体后果，确认无误后执行。

**用户行动**

（如有后果预览）查看确认前摘要，确认新增子管理员数、叠加权限数和具体复制内容 → 点击确认 → 等待系统按序校验（复制信息 → 复制对象 → 加入状态 → 认证状态）。

**关键触点**

- 确认前后果摘要（UXB 建议实现，当前需求文档未包含）
- 「确认」按钮
- 校验过程中的错误提示

**用户心声**

「我点确认之后到底会发生什么？哪些人会变成子管理员？哪些人只是多几个权限？我会不会不小心把谁的权限覆盖了？」

**用户信心度**

低。判断依据：UXB 判断当前需求方案缺少确认前后果预览，管理员属于高风险盲操作——不知道点了确认后哪些人会新增为子管理员、哪些人会被叠加权限、会不会覆盖已有配置。如果实现了后果预览，信心度可提升至中。

**痛点**

- 确认前看不到操作后果摘要，批量 200 人操作无预览直接执行
- 「叠加不覆盖」的规则虽然正确，但管理员在没有预览的情况下容易担心「会不会覆盖」
- 校验按顺序执行，可能在前几步拦截后让管理员反复修正

**流失风险**

- 不确定后果时放弃操作——「算了，我还是一个个配吧，至少我知道每一步在干什么」
- 提交时校验失败回退，反复修正消耗耐心

**设计机会**

- 确认前展示后果摘要：本次复制将新增 N 名子管理员、更新 M 名已有子管理员的权限范围，复制内容为可授权组织+可授权功能（下游：蓝图）
- 摘要中明确区分「将新增为子管理员」和「将在现有基础上叠加」两类目标（下游：蓝图）
- 摘要中标注「叠加不覆盖，原有权限不受影响」以消除顾虑（下游：蓝图）

### 阶段转折

确认并提交 → 处理操作结果：系统完成校验。校验通过 → 进入结果处理。校验失败 → 回到配置阶段修正。

---

### 4. 处理操作结果

**用户目标**

快速理解操作结果，知道当前权限是否已生效，以及下一步该做什么。

**用户行动**

查看 toast 提示 → 如果校验失败（部分或全部），根据错误信息判断是修正后重试还是放弃 → 如果启用双管理员互审，了解当前处于待审批状态 → 关闭弹窗。

**关键触点**

- toast 提示
- 校验失败的错误信息（具体列出不符合条件的用户名和原因）
- 审批状态信息（双管理员互审模式下）

**用户心声**

「到底成功了没有？弹窗告诉我『复制成功』，但我看权限好像没变——哦对了，开了双管理员审批，得等另一个人批完才生效。那为什么不直接告诉我『已提交审批』？」

**用户信心度**

低。判断依据：UXB 明确指出需求文档用「复制成功」覆盖了所有情况，但双管理员互审模式下复制实际不即时生效。toast 说成功而权限未变，管理者产生认知混乱。如果反馈区分了直接生效和待审批两种结果，信心度可提升至中。

**痛点**

- 双管理员互审模式下 toast「复制成功」与实际权限未生效脱节——用户以为成功了但权限没变
- 部分用户校验失败时，不知道哪些人通过了、哪些人被拦下（取决于产品的部分失败策略）
- 校验失败的错误信息以纯文本列出用户名，管理员需要逐个记住并回到选人器排查

**流失风险**

- 收到模糊反馈（「复制成功」但权限未生效）后重复操作，造成数据重复
- 校验失败后无法快速定位和修正问题，放弃批量操作
- 审批被拒绝后无人通知，以为「已经搞定了」

**设计机会**

- 区分直接生效和待审批两种结果，toast 和弹窗关闭后的反馈分别设计（下游：蓝图）
- 部分校验失败时，明确展示成功/失败名单，支持一键移除失败用户后继续（下游：蓝图）
- 审批被拒绝时主动通知发起人（下游：故事）

### 阶段转折

处理操作结果 → 验证与追溯：管理员关闭弹窗，回到列表页，进入验证和记录查看阶段。若双管理员互审待审批，此阶段延长至审批完成后。

---

### 5. 验证与追溯

**用户目标**

确认复制操作已经生效，并在需要时能够回溯完整的操作历史。

**用户行动**

在子管理员列表中检查目标用户是否已出现在列表中（对新增者）或权限范围是否已更新（对叠加者） → 如有疑问，打开操作记录查看复制操作的详细记录。

**关键触点**

- 子管理员列表
- 目标用户的权限详情页
- 操作记录列表与详情

**用户心声**

「我怎么能确定刚才的复制确实生效了？如果半年后有人问起来这批权限是谁配的、什么时候配的、照着谁配的，我能查得到吗？」

**用户信心度**

中。判断依据：列表可以验证当前权限状态，操作记录可以回溯历史。但两条分散的记录（复制-可授权组织 + 复制-可授权功能）难以还原为「一次复制操作」，追溯体验碎片化。双管理员互审下审批被拒绝后无主动通知，管理员可能遗漏。

**痛点**

- 复制生成两条独立操作记录，管理员难以在记录列表中还原「这一次复制操作的完整面貌」
- 操作记录中目标用户以纯文本列表展示（「XXX/手机号、XXX/手机号…」），人数多时难以阅读
- 双管理员互审审批被拒绝后，管理员可能不知道操作未生效

**流失风险**

- 追溯困难时降低对系统审计能力的信任——「记录是有了，但根本没法查」
- 审批被拒不知情，后续配置基于错误假设（以为那批人已经是子管理员了）

**设计机会**

- 操作记录支持按批次 ID 聚合展示，将「复制-可授权组织」和「复制-可授权功能」关联为同一次操作（下游：蓝图）
- 操作记录详情中目标用户列表支持展开/折叠和逐个查看（下游：蓝图）
- 复制操作记录中关联审批状态，展示「已生效」或「待审批」标记（下游：蓝图）

### 阶段转折

验证与追溯 → 结束：管理员确认权限生效且记录可查，本次复制任务完成。若发现异常（如权限未生效），进入排障链路。
