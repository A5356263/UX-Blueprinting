# 用户旅程分析：子管理员复制

---

**运行模式：** uxb-chain
**是否使用补问：** 否
**数据来源：** UXB 需求定案（`spark-output/uxb_output.md`）
**结果等级：** 完整旅程

---

## 主角色：权限管理员 / 超级管理员

权限管理员负责维护子管理员及其可授权范围。在批量配置场景中，需要将已配置好的子管理员授权范围快速复制给多个目标用户。操作目标是降低批量子管理员的配置工作量，同时确保复制结果的准确性和可追溯性。

---

## 阶段正文

### 阶段一：定位来源与发起复制

| 字段 | 内容 |
|------|------|
| **目标** | 在子管理员列表中找到已配置好的来源子管理员，进入复制流程 |
| **动作** | 进入"子管理员模式"列表页；在列表中浏览或通过搜索定位目标子管理员；点击该行操作列的"复制"按钮 |
| **触点** | 子管理员模式列表页（筛选查询区、数据表格区） |
| **用户心声** | "那么多子管理员，先找到那个已经配好的" |
| **信心** | 高 |
| **信心依据** | UXB 已明确复制入口位置和列表页结构，操作路径清晰 |
| **痛点** | • 子管理员数量多（200+）时，在长列表中定位特定子管理员需要多次翻页或精确筛选<br>• 操作列新增"复制"按钮后，操作项增多可能增加视觉查找成本 |
| **流失风险** | 低。即使查找稍慢，也不会在此阶段放弃操作 |
| **机会点** | 提供从列表行直接进入复制的快捷入口，减少"从来源到操作"的查找时间 |

---

### 阶段二：确定复制范围

| 字段 | 内容 |
|------|------|
| **目标** | 确定本次要复制哪些授权内容 |
| **动作** | 在复制弹窗的"复制信息"区查看默认选项；确认或调整勾选"可授权组织"和/或"可授权功能" |
| **触点** | 复制弹窗（复制信息选择区） |
| **用户心声** | "默认都选上，反正本来就是要一样的权限" |
| **信心** | 高 |
| **信心依据** | UXB 已确认复制信息默认为全选、至少选一项、支持多选 |
| **痛点** | • 如果用户只需要复制"可授权组织"但默认全选了"可授权功能"，需要手动取消，增加一步操作<br>• 用户可能不理解"可授权组织"和"可授权功能"的差异，不确定是否都需要勾选 |
| **流失风险** | 低。此阶段操作简单，几乎没有放弃的可能 |
| **机会点** | 在选项旁提供简短的解释说明，帮助用户理解"可授权组织"和"可授权功能"的区别 |

---

### 阶段三：圈选复制目标

| 字段 | 内容 |
|------|------|
| **目标** | 从企业员工中选择本次要复制授权的目标用户 |
| **动作** | 点击选择器打开"选择员工"弹窗；通过搜索或组织树浏览目标用户；勾选目标用户（可多选，上限200名）；确认选择回到复制弹窗 |
| **触点** | 员工选择弹窗、复制弹窗（复制对象展示区） |
| **用户心声** | "200个人，别选漏了，也别选了不能用的" |
| **信心** | 中 |
| **信心依据** | UXB 确认了员工选择弹窗样式、多选能力和200名上限；但"是否前置标识无效用户"仍为待确认 |
| **痛点** | • **关键痛点：** 选择阶段无法预知目标用户的加入状态和认证状态，可能在提交后才发现部分人不行，被迫重新选择<br>• 200人上限在大客户场景中可能需要分多次操作<br>• 多选200人的场景下，难以核对是否选全、有无误选 |
| **流失风险** | 中。如果用户在选人时无法预判哪些人可用，可能导致选了大量无效对象后在执行阶段挫败 |
| **机会点** | 在选择阶段对被选用户做前置条件标识（如标记"未加入""未认证"状态），帮助用户在提交前剔除无效对象 |

---

### 阶段四：提交与等待处理

| 字段 | 内容 |
|------|------|
| **目标** | 提交复制操作并获得处理结果 |
| **动作** | 点击确认；等待系统顺序校验（复制信息→复制对象→加入状态→认证状态）；校验通过后等待复制执行或审批提交 |
| **触点** | 确认按钮、校验反馈提示、失败列表展示区、审批提交通知 |
| **用户心声** | "赶紧确认，看看哪些成了哪些没成" |
| **信心** | 中 |
| **信心依据** | UXB 已明确校验顺序、部分成功处理原则、双管理员互审生效机制；但批量校验的等待时间和反馈节奏不确定 |
| **痛点** | • **关键痛点：** 4步顺序校验全集中在点击确认后执行，200人场景下校验时间较长，用户只能被动等待<br>• **关键痛点：** 部分失败时，失败项需重新开始完整流程（用户确认），意味着用户得从头选人重来，中断操作流<br>• **关键痛点（互审模式）：** "复制成功"在互审模式下是"已提交审批"而不是"已生效"，用户可能误解为操作已完成<br>• 全部校验不通过时，所有选择作废，挫败感最强 |
| **流失风险** | 高。部分失败且需重试时，用户可能放弃批量配置，退回逐人配置的旧方式；审批等待期可能产生二次确认需求 |
| **机会点** | • 提供校验进度的实时反馈（如分步逐项显示校验状态），降低不确定感<br>• 部分失败时展示清晰的失败原因和失败用户列表，虽需重试但至少让用户明确问题在哪<br>• 互审模式下明确区分"已提交审批"和"审批通过已生效"两种状态反馈 |

---

### 阶段五：核对结果与操作追溯

| 字段 | 内容 |
|------|------|
| **目标** | 确认复制最终结果，了解操作是否被记录 |
| **动作** | 查看复制结果（成功项/失败项分组展示）；查看失败原因；查看操作记录确认审计信息 |
| **触点** | 复制结果展示区、操作记录列表 |
| **用户心声** | "看一下哪些成了哪些没成，没成的还得从头来" |
| **信心** | 中 |
| **信心依据** | UXB 确认了操作记录必须生成、审计字段要求；但"详情"字段格式和结果展示方式未定 |
| **痛点** | • 失败项需重新开始完整流程，在操作流上产生断裂感<br>• 操作记录的"详情"字段目前留空，审计追溯能力不足<br>• 如果多次复制同一批用户，去重逻辑可能导致实际生效范围和预期不一致，用户可能困惑 |
| **流失风险** | 中。大量失败需反复重试时可能放弃批量方式；审计信息不全时可能影响合规信心 |
| **机会点** | • 操作记录应包含复制配置快照（复制信息、目标用户列表、时间、结果），满足审计追溯<br>• 复制结果展示区分成功/失败，失败项显示具体原因代码 |

## 阶段转折

| 从 | 到 | 转折事件 | 成功条件 | 失败/停留条件 |
|----|----|---------|---------|-------------|
| 阶段一 | 阶段二 | 点击复制按钮打开弹窗 | 复制弹窗正常打开 | — |
| 阶段二 | 阶段三 | 确认复制信息，进入选人 | 复制信息至少勾选一项 | 未勾选时弹窗阻止提交 |
| 阶段三 | 阶段四 | 确认复制对象，开始校验 | 复制对象至少选择1人，最多200人 | 未选择时弹窗阻止提交 |
| 阶段四 | 阶段五 | 校验与复制执行结束 | 复制执行完成（直接生效或审批提交） | 全部失败时停留在失败结果页 |
| 阶段五 | — | 查看结果并结束操作 | 确认结果后关闭弹窗或页面 | 存在失败项时需重新进入阶段一 |
