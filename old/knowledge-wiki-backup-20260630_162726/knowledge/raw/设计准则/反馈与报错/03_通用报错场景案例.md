# 通用报错场景案例

## 2. 报错类型与推荐体验处理

### 2.1 操作权限不足

原始分类：

- 大类：权限类
- 小类：操作权限不足
- 当前形式：弹窗阻断

任务场景：

- 用户执行查看、编辑、删除、发起流程等功能操作。

问题原因：

- 用户未被授予该功能权限。
- 权限配置缺失。

现状体验问题：

- 用户已经点击操作后才知道无权限。
- 文案常出现敬语堆叠和系统配置语言。
- “分配权限”等表达偏后台管理视角。

推荐反馈形式：

- 首选：入口或操作态上提前说明不可用原因。
- 兜底：用户仍然触发阻断时，用轻量弹窗或提示说明无权限。

推荐文案：

```text
暂无此功能权限，请联系管理员开通。
暂无【{功能名称}】的操作权限，请联系管理员开通。
```

原文案问题示例：

```text
您没有【查询员工的档案信息】的操作权限，请联系超级管理员分配权限。
```

建议处理：

- 去掉“您”等敬语堆叠。
- 将“分配权限”统一为“开通”。
- 说明缺少哪个功能权限。
- 如果能明确管理员角色，写具体角色。

需确认信息：

- 当前需求是否已经说明该功能由哪个角色开通或管理。
- 用户无权限时是否有可执行的下一步。

体验影响方向：

- 减少无效点击。
- 减少用户因不知道找谁开通权限而产生的询问。
- 降低弹窗阻断感。

### 2.2 数据权限不足

原始分类：

- 大类：权限类
- 小类：数据权限不足
- 当前形式：弹窗提示

任务场景：

- 用户查看或操作特定数据范围，例如部门、组织、账套、区域数据。

问题原因：

- 用户没有该数据范围的查看或操作权限。

现状体验问题：

- 文案只说没有权限，但不告诉用户找谁。
- “请检查”含义模糊。
- 弹窗会打断当前页面阅读。

推荐反馈形式：

- 在列表、详情或数据区域内展示空状态/占位提示。
- 如果用户仍触发具体操作，再用轻量提示兜底。

推荐文案：

```text
暂无此{数据范围}的查看权限。
如需获取权限，请联系{管理员角色/负责人}。
```

可选操作文案：

```text
联系管理员
返回列表
```

原文案问题示例：

```text
没有该账套的数据权限，请检查。
```

建议处理：

- 删除“请检查”。
- 明确说明是哪个数据范围不可见。
- 给出联系对象或处理路径。

需确认信息：

- 是否能明确该数据范围由哪个角色管理。
- 当前页面是否需要展示联系入口。

体验影响方向：

- 减少弹窗打断。
- 让用户知道找谁处理。
- 降低因权限说明不清产生的咨询。

### 2.3 登录或会话失效

原始分类：

- 大类：权限类
- 小类：登录/会话失效
- 当前形式：弹窗提示后跳转登录页

任务场景：

- 任何需要登录态的操作。

问题原因：

- 未登录。
- 登录状态过期。
- 认证信息失效。

现状体验问题：

- 暴露 token、签名、session 等技术词。
- 提示和跳转动作之间关系不清。
- 弹窗过重。

推荐反馈形式：

- 轻量 toast 或页面状态提示。
- 告知登录已失效，并引导重新登录。

推荐文案：

```text
登录已失效，请重新登录。
```

如需说明跳转：

```text
登录已失效，正在为你跳转到登录页。
```

原文案问题示例：

```text
签名已过期，请刷新列表后重新请求。
参数token不能为空！
```

建议处理：

- “签名/token”统一转成“登录状态”。
- 不让用户刷新列表解决认证问题。

需确认信息：

- 登录失效后是否直接回到登录页。
- 是否需要保留用户当前任务上下文。

体验影响方向：

- 减少技术术语暴露。
- 减少无效手动操作。
- 让用户明确下一步是重新登录。

### 2.4 网络、超时、服务繁忙

原始分类：

- 大类：系统异常类
- 小类：网络/超时错误、服务端通用异常
- 当前形式：弹窗或英文错误透传

任务场景：

- 页面数据加载。
- 操作提交。
- 需要请求服务的任意任务。

问题原因：

- 网络断开。
- 请求超时。
- 服务繁忙。
- 服务器异常。

现状体验问题：

- 直接展示英文裸错误。
- 页面级失败和操作级失败不区分。
- 弹窗频繁打断。
- 提示过长，toast 放不下。

推荐反馈形式：

- 页面内容加载失败：页面区域内展示失败占位和重试按钮。
- 操作提交失败：toast 或轻量提示。
- 服务繁忙：短提示，必要时再提供客服或重试路径。

推荐文案：

```text
数据加载失败，请稍后重试。
网络异常，操作未成功，请稍后重试。
服务繁忙，请稍后重试。
处理时间较长，请稍后刷新查看结果。
```

可选操作：

```text
重新加载
重试
```

原文案问题示例：

```text
Network Error
timeout of 120000ms exceeded
Request failed with status code 500/502/504
服务异常，可尝试重试解决，若无法解决可联系在线客服，或电话客服400-0695-555。
```

建议处理：

- 英文错误统一转成中文状态。
- 页面加载失败和操作提交失败分开表达。
- 长客服话术不要默认塞进轻量提示。

需确认信息：

- 当前失败是否影响整页内容，还是只影响某个操作。
- 是否允许用户立即重试。

体验影响方向：

- 降低技术裸错误造成的困惑。
- 减少弹窗打断。
- 提供清晰重试路径。

### 2.5 外部系统或第三方服务失败

原始分类：

- 大类：系统异常类
- 小类：远程调用/接口异常
- 当前形式：弹窗提示，常携带技术细节

任务场景：

- 调用第三方、外部系统或微服务能力。
- 典型场景包括税局登录、外部服务响应、智能记账等。

问题原因：

- 外部系统超时。
- 外部系统不可用。
- 外部系统返回失败。

现状体验问题：

- 暴露“接口”“远程服务”等技术词。
- 用户不知道是当前系统失败，还是外部系统暂不可用。
- 后台无感知失败也可能打扰用户。

推荐反馈形式：

- 用户主动触发的外部操作失败：toast 或弹窗，保留必要原因。
- 用户无感知的后台失败：不默认打断当前任务。

推荐文案：

```text
{外部系统}响应超时，请稍后重试。
{业务操作}暂时无法完成，请稍后重试。
```

如果外部系统返回的信息对用户有帮助：

```text
{外部系统}处理失败：{用户可理解的具体原因}。请核对后重试。
```

原文案问题示例：

```text
调用远程服务异常。
智能记账接口调用异常。
```

建议处理：

- 将“接口/远程服务”改成具体业务能力或外部系统。
- 区分用户主动触发和后台自动发生。

需确认信息：

- 该失败是否发生在用户主动操作中。
- 外部系统返回的具体原因是否适合展示给用户。

体验影响方向：

- 减少技术术语暴露。
- 避免后台失败过度打扰。
- 帮助用户理解外部依赖问题。

### 2.6 必填字段为空

原始分类：

- 大类：数据校验类
- 小类：参数为空校验
- 当前形式：弹窗提示

任务场景：

- 表单提交。
- 数据保存。

问题原因：

- 必填字段未填写。

现状体验问题：

- 提交后才弹窗。
- 关闭弹窗后用户不知道哪个字段要改。
- 文案里常出现内部字段名。

推荐反馈形式：

- 输入框附近红字提示。
- 提交时可在按钮附近汇总提示，并定位到第一个错误字段。

推荐文案：

```text
请填写{字段名}。
存在未填写项，请检查标红字段。
```

原文案问题示例：

```text
提交数据有误，请检查：成员id不能为空。
```

建议处理：

- “成员id”改为用户可见字段名。
- 不用弹窗承载字段级错误。
- 让用户能直接看到要修改的位置。

需确认信息：

- 需求中是否已经明确字段 label。
- 是否存在跨区域表单，需额外定位错误字段。

体验影响方向：

- 减少提交后返工。
- 缩短用户定位错误字段的时间。
- 提升表单一次性完成体验。

### 2.7 格式、长度、编码规则错误

原始分类：

- 大类：数据校验类
- 小类：参数格式/内容错误
- 当前形式：弹窗提示

任务场景：

- 表单提交。
- 数据导入。
- 日期、编码、证件类型、长度等字段填写。

问题原因：

- 格式不正确。
- 编码规则不符。
- 字段超长。

现状体验问题：

- 暴露技术字段名。
- 未给正确示例。
- 弹窗不方便用户就地修正。

推荐反馈形式：

- 字段附近红字。
- 对长度限制可配合实时计数。

推荐文案：

```text
请输入正确的{格式说明}，如 {示例}。
最多可输入{max}个字符，当前已输入{current}个。
{编码名}需为{规则说明}。
```

原文案问题示例：

```text
字段[CERTYP:证件类型]的值的长度[3]不能大于定义的最大长度[1]。
```

建议处理：

- 技术字段名改为用户可见字段名。
- 给出正确格式或限制。
- 不把校验规则写成系统异常。

需确认信息：

- 字段的用户可见名称。
- 格式规则和示例。

体验影响方向：

- 用户输入时更容易修正。
- 减少提交后返工。
- 提升字段理解度。

### 2.8 唯一性、重复、命名冲突

原始分类：

- 大类：数据校验类
- 小类：唯一性/重复校验
- 当前形式：弹窗提示

任务场景：

- 新增或创建数据。
- 填写名称、编码、编号。

问题原因：

- 名称、编码或编号与已有数据重复。

现状体验问题：

- 用户填完整个表单后才知道冲突。
- 弹窗只说“已存在”，没有回到具体字段。

推荐反馈形式：

- 字段附近红字。
- 如冲突对象可展示且不涉及权限，可补充已被哪个记录使用。
- 提交后的并发冲突可用兜底弹窗或提示。

推荐文案：

```text
{名称/编码}已被使用，请更换。
「{名称/编码}」已被使用，请更换。
```

可选补充：

```text
已被「{已有记录名称}」使用。
```

原文案问题示例：

```text
账套名称已存在，请重新输入！
```

建议处理：

- 语义可保留，但形式应贴近字段。
- 去掉感叹号。

需确认信息：

- 是否允许展示已存在记录名称。
- 当前冲突是否只影响单字段，还是影响整条数据。

体验影响方向：

- 减少重复提交。
- 降低创建流程返工。
- 提升名称/编码输入成功体验。

### 2.9 文件上传和导入校验

原始分类：

- 大类：数据校验类
- 小类：文件上传校验
- 当前形式：弹窗提示

任务场景：

- 文件上传。
- 数据导入。

问题原因：

- 文件格式不支持。
- 文件过大。
- 文件名含非法字符。
- 文件内容解析失败。

现状体验问题：

- 文案过长。
- 错误不贴近上传区域。
- 用户不知道应该换什么文件或怎么修复。

推荐反馈形式：

- 上传区域下方红字。
- 文件属性类问题在选择文件后提示。
- 内容解析失败在解析结果区域或上传区域提示。

推荐文案：

```text
不支持此文件类型，请上传 {支持的格式} 格式文件。
文件大小超过 {max}MB 限制，请压缩后上传。
文件名含不支持字符，请修改后重新上传。
文件内容解析失败，请检查文件是否完整或使用标准模板。
```

原文案问题示例：

```text
文件校验不通过，请检查后重新上传，具体说明：文件【XX】的名称不合法。
```

建议处理：

- 按格式、大小、名称、解析失败分开写。
- 不在一条提示中堆叠所有解释。

需确认信息：

- 支持哪些文件格式。
- 文件大小上限。
- 文件命名规则。
- 是否有标准模板。

体验影响方向：

- 减少无效上传。
- 帮助用户快速替换或修正文件。
- 降低批量导入失败成本。

### 2.10 金额、数值和跨字段关系

原始分类：

- 大类：数据校验类
- 小类：金额/数值校验
- 当前形式：弹窗提示

任务场景：

- 财务开票。
- 薪资计算。
- 凭证录入。
- 金额勾稽关系校验。

问题原因：

- 金额为 0。
- 输入非数值。
- 不含税金额、税额、含税金额之间不一致。

现状体验问题：

- 只说金额错误，不给具体差异。
- 单字段错误和多字段关系错误使用同一种提示。

推荐反馈形式：

- 单字段错误：字段附近红字。
- 跨字段关系错误：弹窗或集中校验区域，展示具体数值和差异。

推荐文案：

```text
金额不能为0。
请输入有效的数字。
不含税金额（{A}）+ 税额（{B}）与含税金额（{C}）不一致，差额为 {D}。
```

原文案问题示例：

```text
发票金额错误:不含税金额+税额≠ 含税金额。
```

建议处理：

- 保留业务关系，但补充具体数值。
- 区分单字段问题和跨字段问题。

需确认信息：

- 相关字段名称和计算关系。
- 差额是否需要展示精度规则。

体验影响方向：

- 减少用户排查金额错误的时间。
- 提升财务场景的可核对性。

### 2.11 数据或记录不存在

原始分类：

- 大类：业务状态类
- 小类：数据/记录不存在
- 当前形式：弹窗提示

任务场景：

- 查看或操作某条具体数据记录。

问题原因：

- 数据已删除。
- 数据已作废。
- 数据从未创建或 ID 无效。

现状体验问题：

- “请检查”含义模糊。
- 建议刷新，但刷新并不能解决已删除问题。
- 用户不知道返回哪里。

推荐反馈形式：

- 从列表进入：页面占位，提供返回列表。
- 从外部链接或直链进入：弹窗或空状态，提供返回上一页/首页。

推荐文案：

```text
该{业务对象}已被删除或不存在。
返回列表
返回上一页
回到首页
```

原文案问题示例：

```text
账套不存在，请检查。
公告不存在，请刷新后重试。
```

建议处理：

- 不建议用户刷新解决不存在问题。
- 给出明确返回去向。

需确认信息：

- 用户从哪里进入当前记录。
- 是否有合适的列表页或首页承接。

体验影响方向：

- 减少用户对“数据去哪了”的困惑。
- 提供清晰退路。

### 2.12 重复操作或已处理

原始分类：

- 大类：业务状态类
- 小类：重复操作/已处理
- 当前形式：弹窗提示

任务场景：

- 审批。
- 任务处理。
- 确认操作。

问题原因：

- 任务已被他人处理。
- 流程已结束。
- 用户重复提交。

现状体验问题：

- “请勿重复处理”有责备语气。
- 用户被要求手动刷新。
- 终态提醒被做成阻断。

推荐反馈形式：

- Toast 或轻量状态提示。
- 同时更新列表或当前页面状态。

推荐文案：

```text
该任务已被处理，页面已更新。
审批已完成，列表已更新。
```

原文案问题示例：

```text
此任务已处理，请勿重复处理。
没有需要处理的任务，可能已被处理，请刷新后重试！
```

建议处理：

- 去掉责备语气。
- 不要求用户手动刷新。
- 告诉用户页面已经更新或需要返回列表。

需确认信息：

- 是否需要自动刷新列表或更新当前状态。
- 是否需要说明由谁处理。

体验影响方向：

- 减少不必要阻断。
- 降低重复处理造成的焦虑。

### 2.13 状态不允许操作

原始分类：

- 大类：业务状态类
- 小类：状态不允许操作
- 当前形式：弹窗阻断

任务场景：

- 对某条记录执行状态变更或撤销、提交、删除等操作。

问题原因：

- 当前状态不在允许操作的状态范围内。

现状体验问题：

- 文案只说不可操作，不说明当前状态。
- 反向表达多，例如“非审批中状态不能撤销”。
- 缺少允许条件。

推荐反馈形式：

- 若状态限制是当前页面已知规则：操作入口说明或置灰。
- 若状态变化发生在用户操作过程中：保留弹窗兜底，明确当前状态和允许条件。

推荐文案：

```text
暂无法{目标操作}。
{业务对象}当前状态为{当前状态}，需在{允许状态}下才能{目标操作}。
```

原文案问题示例：

```text
非审批中状态的流程不能撤销!
当前批次状态不可进行操作。
```

建议处理：

- 改成正向条件表达。
- 明确当前状态和允许状态。
- 去掉感叹号。

需确认信息：

- 当前状态名称。
- 哪些状态允许目标操作。
- 用户是否有其他可执行路径。

体验影响方向：

- 减少无效操作。
- 帮助用户理解状态机规则。

### 2.14 流程中或处理中

原始分类：

- 大类：业务状态类
- 小类：流程中/处理中
- 当前形式：弹窗提示

任务场景：

- 对已在流程中的数据发起新操作。
- 审批中、计算中、处理中。

问题原因：

- 数据已有进行中的流程或任务。
- 当前任务需要等待处理完成。

现状体验问题：

- 用户不知道正在等哪个流程。
- 文案缺少等待建议。
- 每次点击才弹窗，打断感强。

推荐反馈形式：

- 操作入口置灰并说明原因。
- 兜底弹窗说明正在进行的流程。
- 对计算/处理中状态可用 toast 告知等待。

推荐文案：

```text
该记录正在{流程名}中，暂不可操作。
该{业务对象}正在{流程名}中，请等待流程完成后再试。
算税正在进行中，请稍后查看结果。
```

原文案问题示例：

```text
已在转正流程中，无法申请转正。
当前正在算税中，不能进行算税。
```

建议处理：

- 告知具体流程名。
- 给出等待或查看结果的建议。
- 避免重复强调“不能”。

需确认信息：

- 进行中的流程名称。
- 用户是否需要等待、返回列表或查看处理结果。

体验影响方向：

- 减少重复点击。
- 帮助用户理解等待状态。

### 2.15 已锁定、已冻结、已结账

原始分类：

- 大类：业务状态类
- 小类：已锁定/已冻结/已结账
- 当前形式：弹窗提示

任务场景：

- 修改或编辑已锁定数据。
- 财务期间、薪资组、账套等持续状态限制。

问题原因：

- 数据处于锁定、冻结、结账等不可编辑状态。

现状体验问题：

- 持续状态每次操作才弹窗。
- 用户不知道如何解锁或找谁处理。

推荐反馈形式：

- 页面顶部或操作区 banner。
- 编辑入口置灰。
- 文案说明状态、影响和处理对象。

推荐文案：

```text
当前{期间}已结账，数据不可编辑。如需修改，请联系{角色}。
薪资组已锁定，无法修改薪酬数据。如需解锁，请联系薪酬管理员。
```

原文案问题示例：

```text
当前期间已结账，公式不允许修改。
薪资组已锁定，无法计算薪资。
```

建议处理：

- 从弹窗改为持续状态说明。
- 补充解锁路径或负责角色。

需确认信息：

- 哪个角色可解锁或处理。
- 当前状态影响哪些操作。

体验影响方向：

- 减少反复弹窗。
- 提前解释持续限制。
