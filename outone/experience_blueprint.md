# 体验蓝图：企业财富+商机中心

## §0 本次关键设计判断

### D-001 · 商机中心用三个平级页签承载，客户营销为默认页签

**体验判断**

商机中心以客户营销、策略管理、数据回检三个平级页签承载，进入后默认落在客户营销页签。影响范围：商机中心入口与全部角色。

**具体做法**

进入商机中心时按权限决定默认页签：拥有客户营销权限的用户默认展示客户营销页签；无客户营销权限时默认展示其第一个有权页签。三个页签保持平级切换，互不隐藏。

避免出现：无客户营销权限的用户落在客户营销页签导致空白或权限报错。

### D-002 · 客户营销页把稳定统计与任务列表分离

**体验判断**

顶部五项统计作为稳定信息常驻展示，不与列表筛选联动。影响范围：客户营销页信息层级。

**具体做法**

统计区固定置于筛选区上方，只随用户权限和业务数据变化；筛选区与客户列表承担定位、排序与批量任务入口；用户改变筛选时统计保持不变。

避免出现：统计数字随筛选变化，导致用户误判权限范围内的整体客户规模。

### D-003 · 批量去营销采用确认后异步传输与结果分层反馈

**体验判断**

去营销不是即时完成的表单提交，而是确认后异步分批传输名单、再跳转CRM的跨系统流程。影响范围：去营销流程与CRM交接。

**具体做法**

首次使用时在确认弹窗内前置说明营销渠道选择与数据留存意义；确认后系统校验并异步分批传输（每批最多1000名）；全部批次成功才返回可跳转结果并打开CRM新建活动页；任一批失败就地展示失败并允许重新提交；名单传输成功后到活动创建前，商机营销状态保持不变。

避免出现：把"确认"或"名单传输成功"视为营销已完成的反馈，误导用户。

### D-004 · 暂不处理与已线下处理用强阻断确认覆盖不可逆性

**体验判断**

暂不处理、已线下处理不可撤销，必须用强阻断弹窗确认对象范围与结果。影响范围：批量人工处理与客户详情顶部操作区。

**具体做法**

确认弹窗明确展示受影响客户数与执行结果（该批客户将不再在待营销下展示、不可恢复为待营销）；确认前系统复核所选客户营销状态，部分状态已变时提示实际处理数量、只处理仍为待营销的客户；全部状态已变时提示"没有客户有待营销商机，默认不做处理"并置灰确认按钮。

避免出现：轻量二次确认后用户误以为可撤销，或确认时仍按旧状态处理已变化客户。

### D-005 · 批量选择客户采用对象选择与回填，不做常驻选择视图

**体验判断**

客户营销列表是批量操作的候选集合，选中结果回填到批量操作区后继续任务。影响范围：客户营销列表与批量操作区。

**具体做法**

列表行勾选、选择本页全部、选择全部筛选结果三个选择入口只选中待营销状态客户；已选数量与去营销、暂不处理、已线下处理入口联动；修改筛选或重置后清空选择；未选择客户时点击批量操作统一提示"请选择至少一名客户"。

避免出现：把客户候选集合做成常驻选择页签，混淆浏览与办理。

### D-006 · 商机记录操作列按商机营销状态只展示一个动作

**体验判断**

商机记录操作列按商机营销状态分型，每行只展示一个可执行动作。影响范围：策略详情与客户详情的商机记录。

**具体做法**

营销中、营销成功、营销失败、无经营价值时展示"查看关联活动"；已线下处理、暂不处理时展示"查看人工处理记录"；待营销、已过期未营销时操作列显示"-"。策略详情与客户详情共用同一规则。

避免出现：同一行堆叠多个动作，或状态与动作不匹配。

### D-007 · 客户详情的活动与任务在页面内就地承接

**体验判断**

查看关联活动在客户详情内就地展开，不跳离原页面。影响范围：客户详情的商机记录与活动任务展示。

**具体做法**

点击商机记录操作列的"查看关联活动"后，在客户详情右侧就地展示该商机的活动与任务：活动按发起时间倒序，每个活动下展示当前客户对应的全部任务；活动与任务不受商机是否过期限制。

避免出现：跳转独立页面导致丢失客户详情上下文，或完成查看后无法回到商机记录。

### D-008 · 异常阻断就地反馈并给出恢复路径

**体验判断**

无权限、名单传输失败、数据回检失败等异常采用就地阻断，并给出明确的恢复或等待路径。影响范围：全部角色对异常的感知与下一步。

**具体做法**

无权限时页面展示"暂无权限"且不返回业务数据；名单传输任一批失败就地展示失败并允许重新提交；数据回检跳转失败就地提示"暂时无法打开数据回检，请稍后重试"并允许重试；批量确认前状态变化就地提示实际处理数量。

避免出现：只给错误码或"失败"二字，无后续动作。

## §3 交互流程总览

### 主路径 1 · 产品经理发起批量去营销（FN-004）

→ 商机中心 ＞ 客户营销页签
→ 查看顶部统计
→ 按字段筛选客户（名称/编号、策略、营销状态、星级、机构、客户经理、时间、余额）
→ 勾选待营销状态客户，或选择本页全部 / 选择全部筛选结果
→ 点击 [去营销]
→ 首次使用时：打开去营销说明弹窗，可勾选"不再提示"
→ 点击 [确认并继续]
→ 系统校验权限、客户去重、1—10000名上限及待营销商机
→ 系统为每名客户固定当前全部待营销商机快照
→ 系统分批传输客户名单（每批最多1000名）
→ 全部批次成功：返回可跳转结果，打开CRM新建活动页
→ CRM创建营销活动并回流活动创建证据，企业财富+将活动与快照中的商机关联
→ CRM审批活动并生成营销任务，通过Kafka回流状态
→ 系统更新商机营销状态，再聚合客户营销状态

**分支**
- 未选择客户 → 点击 [去营销] → 提示"请选择至少一名客户"，不打开确认弹窗
- 所选客户超过10000名 → 提示"单次最多选择10000名客户"，不上传
- 任一批名单传输失败 → 不跳转，就地展示失败，允许重新提交（幂等）
- 确认前部分客户状态已变化 → 弹窗提示实际处理数量，只处理仍为待营销客户
- 确认前全部客户状态已变化 → 提示"没有客户有待营销商机，默认不做处理"，确认按钮置灰

### 主路径 2 · 产品经理批量暂不处理或已线下处理（FN-005 / FN-006）

→ 商机中心 ＞ 客户营销页签
→ 筛选并勾选待营销状态客户
→ 点击 [暂不处理] 或 [已线下处理]
→ 打开确认弹窗，展示受影响客户数与处理结果说明
→ 点击 [确认]
→ 系统校验并逐条保存人工处理记录（操作类型、操作人、操作时间、客户号、商机编号）
→ 系统重算商机及客户营销状态
→ 列表更新，处理客户不再在待营销下展示

**分支**
- 未选择客户 → 提示"请选择至少一名客户"
- 确认前部分客户状态已变化 → 只处理仍为待营销客户并提示数量
- 确认前全部客户状态已变化 → 确认按钮置灰

### 主路径 3 · 产品经理查看客户详情及商机记录（FN-007）

→ 客户营销列表点击客户名称/客户号，或策略详情商机记录点击客户名称/客户号
→ 新窗口打开客户详情
→ 查看客户信息（星级、余额、机构、客户经理等）与客户营销状态
→ 查看商机记录列表（每页10条，默认按生效时间倒序）
→ 点击商机记录操作列的 [查看关联活动] 或 [查看人工处理记录]
→ 就地展示活动与任务，或弹窗展示人工处理记录
→ 客户营销状态为待营销时，顶部操作区 [去营销] / [暂不处理] / [已线下处理] 可用

**分支**
- 客户营销状态非待营销 → 顶部操作按钮置灰，提示"只有待营销客户可以操作"
- 客户权限已变化 → 客户详情接口重新校验，提示"暂无权限"且不返回客户数据
- 商机状态为待营销或已过期未营销 → 操作列显示"-"

### 主路径 4 · 产品经理查看商机策略与策略详情（FN-001 / FN-002）

→ 商机中心 ＞ 策略管理页签
→ 查看策略列表（3条，默认按优先级从高到低、相同优先级按预置顺序）
→ 点击策略名称/编号 → 打开策略详情
→ 查看基本信息、标签组合规则、规则说明与聚合统计
→ 在商机记录筛选区按客户/机构/优先级/有效性/营销状态/时间筛选（不支持商机编号筛选）
→ 查看该策略权限范围内的全部当前及历史商机记录
→ 点击商机记录中的客户名称/客户号 → 新窗口打开客户详情

**分支**
- 策略尚无用户有权查看的商机 → 商机记录展示空状态，不提供批量操作
- 无查看商机策略权限 → 不展示菜单，访问页面提示"暂无权限"

### 分支路径 · 查看有效商机弹窗（FN-003）

→ 客户营销列表点击有效商机列
→ 打开有效商机弹窗，展示该客户当前全部有效商机（每页10条，默认按生效时间倒序）
→ 点击策略名称/编号 → 新窗口打开对应策略详情
→ 关闭弹窗 → 保留客户列表原有筛选、排序和分页状态

- 承载说明：有效商机属于候选集合，用弹窗承载，不做常驻Tab。

### 分支路径 · 数据回检（FN-008）

→ 商机中心 ＞ 数据回检页签
→ 点击 [数据回检]
→ 系统校验功能权限
→ 系统获取可信跳转地址和必要参数
→ 打开CRM营销回检中心（CRM再次校验用户权限）
→ 查看营销数据后返回商机中心

- 承载说明：数据回检为复用引用，直接打开CRM营销回检中心，企业财富+不承载回检页面。

## §4 主路径详细流程

### 主路径 1 · 产品经理发起批量去营销

**节点 1 · 定位待营销客户**

- 【用户动作】：进入客户营销页签，查看顶部统计，按字段筛选客户。
- 【系统响应】：按权限范围返回客户列表，顶部统计不随筛选变化。
- 【用户需要知道】：列表默认把待营销客户排在前面；临近过期信息通过商机最晚过期时间列表达。
- 【下一步】：勾选待营销状态客户。

**节点 2 · 选择客户并触发去营销**

- 【用户动作】：勾选客户（单行 / 本页全部 / 全部筛选结果），点击 [去营销]。
- 【系统响应】：未选择客户时提示"请选择至少一名客户"；选择客户后按权限与状态校验可操作客户。
- 【用户需要知道】：只有待营销状态客户可被勾选和操作。
- 【下一步】：进入去营销确认。

**节点 3 · 去营销说明与确认**

- 【用户动作】：首次使用时查看操作说明弹窗，可勾选"不再提示"；点击 [确认并继续]。
- 【系统响应】：说明弹窗承载营销渠道选择提示与数据留存说明；确认后提交客户选择。
- 【用户需要知道】：确认前系统重新计算所选客户营销状态；部分客户已变化时提示实际处理数量。
- 【建议文案】：确认弹窗文案"CRM营销平台支持客户经理、企微、企银栏位等营销渠道，可同时选择多个；通过系统开展营销，可留存营销数据，用于追踪营销过程及后续回检优化。"
- 【下一步】：系统异步处理名单传输。

**节点 4 · 名单传输与CRM交接**

- 【用户动作】：等待名单传输结果；传输期间停留在当前页面。
- 【系统响应】：校验权限、去重、上限及待营销商机；固定商机快照；分批传输名单（每批最多1000名）；全部成功返回可跳转结果，打开CRM新建活动页。
- 【用户需要知道】：任一批失败时不跳转并展示失败，允许重新提交（重复提交由接口幂等处理）；名单传输成功但活动尚未创建时不改变商机营销状态。
- 【下一步】：在CRM新建活动页完成活动创建与审批。

**节点 5 · 营销状态回流**

- 【用户动作】：CRM创建活动、审批并生成营销任务。
- 【系统响应】：收到活动创建证据且活动为待审批、审批中或审批通过后，覆盖商机进入营销中；CRM任务结果经Kafka回流后，更新商机营销状态，再聚合客户营销状态。
- 【用户需要知道】：活动组建失败、审批不通过或审批已撤回时，有效商机恢复待营销。
- 【下一步】：在客户营销列表或客户详情回看营销状态与活动任务。

### 主路径 2 · 产品经理批量暂不处理或已线下处理

**节点 1 · 选择客户并触发批量处理**

- 【用户动作】：筛选并勾选待营销客户，点击 [暂不处理] 或 [已线下处理]。
- 【系统响应】：未选择客户时提示"请选择至少一名客户"。
- 【下一步】：进入批量处理确认。

**节点 2 · 批量处理确认**

- 【用户动作】：查看确认弹窗中的受影响客户数与结果说明，点击 [确认]。
- 【系统响应】：确认前复核所选客户营销状态；部分客户状态已变时提示实际处理数量，只处理仍为待营销的客户；全部状态已变时提示"没有客户有待营销商机，默认不做处理"并置灰确认按钮。
- 【用户需要知道】：暂不处理、已线下处理不可撤销，处理后客户不再在待营销下展示，商机不恢复为待营销状态。
- 【建议文案】：暂不处理弹窗"本次将对已选{数量}位待营销客户执行暂不处理操作，执行后该批客户将不在待营销状态下展示，确认继续吗？"；已线下处理弹窗"本次将对已选{数量}位待营销客户执行已线下处理操作，执行后该批客户将不在待营销状态下展示，确认继续吗？"
- 【下一步】：系统保存人工处理记录并重算状态。

**节点 3 · 处理结果与列表更新**

- 【用户动作】：查看处理结果。
- 【系统响应】：逐条保存操作类型、操作人、操作时间、客户号、商机编号；重算商机及客户营销状态；处理客户不再在待营销下展示。
- 【用户需要知道】：处理记录可在客户详情商机记录中通过"查看人工处理记录"回看。
- 【下一步】：继续处理其他待营销客户或回看处理结果。

### 主路径 3 · 产品经理查看客户详情及商机记录

**节点 1 · 进入客户详情**

- 【用户动作】：在客户营销列表或策略详情商机记录点击客户名称/客户号。
- 【系统响应】：新窗口打开企业财富+客户详情；客户详情接口再次校验当前客户数据权限。
- 【用户需要知道】：权限变化时提示"暂无权限"且不返回客户数据。
- 【下一步】：查看客户信息与商机记录。

**节点 2 · 查看商机记录**

- 【用户动作】：查看客户全部当前及历史商机记录，设置筛选。
- 【系统响应】：商机记录默认按生效时间倒序，每页10条；支持按策略名称/编号、优先级、商机有效性、商机营销状态、生效时间、过期时间筛选（不支持商机编号筛选）。
- 【下一步】：按商机营销状态查看关联活动或人工处理记录。

**节点 3 · 查看关联活动或人工处理记录**

- 【用户动作】：点击商机操作列的 [查看关联活动] 或 [查看人工处理记录]。
- 【系统响应】：营销中/营销成功/营销失败/无经营价值时右侧就地展示活动与任务；已线下处理/暂不处理时弹窗展示人工处理记录；待营销/已过期未营销时操作列显示"-"。
- 【用户需要知道】：活动与任务不受商机是否过期限制。
- 【下一步】：对待营销客户执行去营销、暂不处理或已线下处理。

### 主路径 4 · 产品经理查看商机策略与策略详情

**节点 1 · 查看策略列表**

- 【用户动作】：切换至策略管理页签，查看3条策略。
- 【系统响应】：策略列表默认按优先级从高到低、相同优先级按预置顺序排列；展示聚合客户数据与更新频率。
- 【下一步】：进入策略详情。

**节点 2 · 查看策略详情与商机记录**

- 【用户动作】：点击策略名称/编号，查看基本信息、标签组合规则、规则说明与聚合统计；在商机记录筛选区筛选并查看商机。
- 【系统响应】：展示策略详情与该策略权限范围内的全部当前及历史商机；后端按客户数据权限校验。
- 【用户需要知道】：无商机时展示空状态，不提供批量操作。
- 【下一步】：点击商机记录中的客户名称/客户号进入客户详情。

## §5 次交互流程

### 次流程 1 · 查看有效商机弹窗

- 【触发条件】：客户营销列表中存在有效商机列。
- 【用户动作】：点击有效商机列（如"上市公司发布...|共2项"）。
- 【系统反馈】：弹窗展示该客户当前全部有效商机，默认按生效时间倒序，每页10条；展示商机编号、策略名称/编号、优先级、生效时间、过期时间；点击策略名称/编号在新窗口打开策略详情。
- 【需要前置解释的信息】：有效商机指当前仍在跟进期限内的商机，一个客户可有多条。
- 【下一步】：关闭弹窗后保留客户列表原有筛选、排序和分页状态。

### 次流程 2 · 查看关联活动与任务

- 【触发条件】：商机营销状态为营销中、营销成功、营销失败或无经营价值。
- 【用户动作】：点击商机记录操作列的 [查看关联活动]。
- 【系统反馈】：在客户详情右侧就地展示该商机的活动与任务：活动按发起时间倒序，每个活动下展示当前客户对应的全部任务（含任务渠道与任务状态）；活动与任务不受商机是否过期限制。
- 【需要前置解释的信息】：无经营价值旁提示"一般为客户经理反馈"。
- 【下一步】：关闭就地展示后回到商机记录。

### 次流程 3 · 查看人工处理记录

- 【触发条件】：商机营销状态为已线下处理或暂不处理。
- 【用户动作】：点击商机记录操作列的 [查看人工处理记录]。
- 【系统反馈】：弹窗展示该商机的人工处理记录（操作类型、操作人、操作时间）。
- 【下一步】：关闭弹窗后回到商机记录；处理操作不可撤销。

### 次流程 4 · 数据回检

- 【触发条件】：用户拥有"商机中心-查看商机数据回检"权限。
- 【用户动作】：点击数据回检页签。
- 【系统反馈】：后端校验功能权限，获取可信跳转地址和必要参数，打开CRM营销回检中心；企业财富+不改变客户及营销状态。
- 【需要前置解释的信息】：数据回检承载在CRM营销回检中心，企业财富+仅提供入口跳转。
- 【建议文案】：跳转失败时提示"暂时无法打开数据回检，请稍后重试"。
- 【下一步】：在CRM回检中心查看营销数据后返回商机中心。

## §6 异常与阻断流程

### 异常 1 · 无权限访问商机中心

- **发生时机**：普通用户或未授权用户访问商机中心任一页面。
- **触发条件**：无对应功能权限（查看客户营销、查看商机策略、查看商机数据回检）。
- **判断依据**：后端校验功能权限。
- **反馈形式**：不展示菜单；直接访问页面地址时页面级提示。
- **系统反馈**：提示"暂无权限"，接口不返回业务数据。
- **如何处理**：用户无处理路径，按权限申请或联系管理员由现有权限体系承接。

### 异常 2 · 去营销名单传输任一批失败

- **发生时机**：批量去营销名单分批传输过程中。
- **触发条件**：任一批次传输失败。
- **判断依据**：批次结果失败。
- **反馈形式**：就地页面反馈。
- **系统反馈**：不跳转CRM新建活动页并展示失败；名单交接成功但活动尚未创建时不改变商机营销状态。
- **如何处理**：允许重新提交，重复提交由接口幂等机制处理。

### 异常 3 · 去营销超过人数上限

- **发生时机**：点击去营销并确认前。
- **触发条件**：所选去重客户超过10000名。
- **判断依据**：数量校验。
- **反馈形式**：就地提示。
- **系统反馈**：不上传并提示"单次最多选择10000名客户"。
- **如何处理**：调整选择后重新发起。

### 异常 4 · 批量操作确认前客户状态变化

- **发生时机**：确认弹窗打开后、确认前。
- **触发条件**：已选客户部分或全部不再为待营销状态。
- **判断依据**：提交前重新计算客户营销状态。
- **反馈形式**：确认弹窗内提示。
- **系统反馈**：部分变化时提示实际处理数量，只处理仍为待营销的客户；全部变化时提示"没有客户有待营销商机，默认不做处理"并置灰确认按钮。
- **如何处理**：用户确认后只处理仍为待营销的客户；无需其他动作。

### 异常 5 · CRM活动组建失败、审批不通过或审批已撤回

- **发生时机**：去营销跳转CRM后活动处理阶段。
- **触发条件**：活动组建失败、审批不通过或审批已撤回，且无其他进行中证据。
- **判断依据**：CRM活动状态回流。
- **反馈形式**：状态回流后列表与详情状态更新。
- **系统反馈**：有效商机恢复待营销，按商机营销状态计算顺序重算。
- **如何处理**：用户可重新发起去营销。

### 异常 6 · 数据回检跳转失败

- **发生时机**：点击数据回检后。
- **触发条件**：跳转地址或参数获取失败、CRM不可访问。
- **判断依据**：后端跳转处理失败。
- **反馈形式**：就地页面反馈。
- **系统反馈**：终止跳转并记录失败日志，提示"暂时无法打开数据回检，请稍后重试"。
- **如何处理**：允许重试；用户留在当前页面。

### 异常 7 · 客户无有效商机

- **发生时机**：查看客户营销列表或客户详情。
- **触发条件**：客户没有新增匹配或持续有效商机。
- **判断依据**：有效商机为空。
- **反馈形式**：列表字段与详情展示。
- **系统反馈**：有效商机列显示"-"，点击区域不可用；客户营销状态仍按最近30日商机聚合。
- **如何处理**：用户可查看商机历史记录了解状态依据。

### 异常 8 · 客户权限发生变化

- **发生时机**：用户打开客户详情后失去该客户数据权限。
- **触发条件**：客户数据权限变化。
- **判断依据**：客户详情接口重新校验数据权限。
- **反馈形式**：页面级提示。
- **系统反馈**：提示"暂无权限"且不返回客户数据。
- **如何处理**：用户无处理路径，由现有权限体系承接。

### 异常 9 · 上游商机同步异常（系统处理）

- **发生时机**：三室产品系统同步商机。
- **触发条件**：延迟、补发、重复同步或缺少商机生成时间。
- **判断依据**：技术方案幂等识别与字段校验。
- **反馈形式**：后台告警，用户无直接感知。
- **系统反馈**：重复同步不生成新商机、不重置生效时间；缺少商机生成时间时同步失败并告警，不生成不完整商机。
- **如何处理**：由双方技术方案保证幂等与告警处理。

## §7 页面 / 弹窗 / 抽屉设计

### 页面 1 · 商机中心（父级承载页）

- **页面目标**：作为企业财富+内商机统一经营入口，承载客户营销、策略管理、数据回检三个平级页签。
- **进入条件**：拥有任一商机中心功能权限的用户进入商机中心。
- **适用角色**：总分行产品经理及领导、系统管理员、客户经理（按各自权限）；普通用户不展示菜单。
- **结构草图**：

```text
企业财富+ ＞ 商机中心
┌─────────────────────────────────────────────────────┐
│ [客户营销]  [策略管理]  [数据回检]                     │
├─────────────────────────────────────────────────────┤
│ {当前页签内容区域}                                    │
│                                                     │
│                                                     │
└─────────────────────────────────────────────────────┘
```

- **成功反馈**：进入商机中心后默认落在客户营销页签（拥有客户营销权限时）；无客户营销权限时落在第一个有权页签。
- **异常状态下的结构变化**：无对应权限的用户不展示商机中心菜单；直接访问页面地址时展示"暂无权限"提示且不返回业务数据。

### 页面 2 · 客户营销页（Tab）

- **页面目标**：从客户维度统一查看商机与营销状态，筛选客户并批量处理其待营销商机。
- **进入条件**：拥有"商机中心-查看客户营销"权限的用户进入客户营销页签。
- **适用角色**：总分行产品经理及领导、系统管理员、客户经理（客户经理仅自己数据权限内客户）。
- **结构草图**：

```text
客户营销
┌─────────────────────────────────────────────────────┐
│ 顶部统计：新增匹配{数} 待营销{数} 已过期未营销{数}     │
│          公金五星{数} 企业财富重点客户{数}             │
├─────────────────────────────────────────────────────┤
│ 筛选：客户名称/编号 策略 营销状态 星级 机构 客户经理    │
│       商机最新触发时间 商机最晚过期时间                │
│       年日均余额 时点余额 历史最高时点余额              │
├─────────────────────────────────────────────────────┤
│ 已选择 {数量} 人  [选择本页全部] [选择全部筛选结果]      │
│ [已线下处理] [暂不处理] [去营销]                       │
├─────────────────────────────────────────────────────┤
│ 客户列表（每行一名客户）：                            │
│ □ 客户名称/客户号 有效商机 最新触发 最晚过期            │
│   营销状态 公金星级 财富星级 年日均 时点 历史最高       │
│   所属机构 客户经理 [详情]                            │
└─────────────────────────────────────────────────────┘
```

- **成功反馈**：展示权限范围内自本系统上线以来至少产生过一条商机的全部客户，按客户号去重，每名客户一行；默认按营销状态分组（待营销、营销中、其他状态）、公金星级降序、企业财富星级降序、商机最新触发时间降序；顶部统计不随筛选变化。
- **失败反馈**：无查看权限时不展示菜单，直接访问页面提示"暂无权限"，接口不返回客户数据。
- **异常状态下的结构变化**：未选择客户时点击批量操作统一提示"请选择至少一名客户"；非待营销状态客户选择框置灰并提示"仅待营销状态客户可批量处理"。
- **具体文案**：有效商机列拼接规则"策略名称（最多前10字符）...|共X项"，无有效商机显示"-"；顶部统计提示文案"新增匹配客户数：最近1天内有新商机且当前待营销的客户数"。

### 弹窗 3 · 去营销说明与确认弹窗

- **弹窗目标**：首次使用时前置说明营销渠道与数据留存，并确认批量去营销。
- **触发条件**：点击 [去营销]；首次使用展示说明，后续可按"不再提示"跳过说明。
- **适用角色**：拥有"去做营销"权限的总分行产品经理及领导、系统管理员、客户经理。
- **结构草图**：

```text
前往CRM营销平台创建活动
┌─────────────────────────────────────────────────────┐
│ CRM营销平台支持客户经理、企微、企银栏位等营销渠道，    │
│ 可同时选择多个。                                      │
│ 如需选择客户经理渠道，请先选择其他渠道；从第二个渠道   │
│ 开始可选择客户经理。                                 │
│ 通过系统开展营销，可留存营销数据，用于追踪营销过程及   │
│ 后续回检优化。                                       │
│ □ 不再提示                                          │
│                    [取消] [确认并继续]                │
└─────────────────────────────────────────────────────┘
```

- **成功反馈**：确认后系统提交客户选择并进入异步名单传输；全部批次成功返回可跳转结果并打开CRM新建活动页。
- **失败反馈**：确认前系统复核所选客户营销状态，全部状态已变时提示"没有客户有待营销商机，默认不做处理"并置灰确认按钮；超过10000名时提示"单次最多选择10000名客户"。
- **异常状态下的结构变化**：任一批名单传输失败时不跳转，就地展示失败并允许重新提交。

### 弹窗 4 · 暂不处理确认弹窗

- **弹窗目标**：确认对所选待营销客户批量暂不处理，明确不可逆结果。
- **触发条件**：点击 [暂不处理] 并已选择待营销状态客户。
- **适用角色**：拥有"暂不处理"权限的总分行产品经理及领导、系统管理员。
- **结构草图**：

```text
确定暂不处理？
┌─────────────────────────────────────────────────────┐
│ 本次将对已选{数量}位待营销客户执行暂不处理操作，执行后  │
│ 该批客户将不在待营销状态下展示，确认继续吗？           │
│                    [取消] [确认]                      │
└─────────────────────────────────────────────────────┘
```

- **成功反馈**：确认后对客户全部待营销商机保存人工处理记录并重算状态，客户不再在待营销下展示；无需填写理由。
- **失败反馈**：确认前客户状态已变化时提示实际处理数量，只处理仍为待营销的客户；全部状态已变时置灰确认按钮。
- **异常状态下的结构变化**：操作不可撤销，确认后无恢复入口。

### 弹窗 5 · 已线下处理确认弹窗

- **弹窗目标**：确认对所选待营销客户批量记录已线下处理，明确不可逆结果。
- **触发条件**：点击 [已线下处理] 并已选择待营销状态客户。
- **适用角色**：拥有"已线下处理"权限的总分行产品经理及领导、系统管理员。
- **结构草图**：

```text
记录已线下处理
┌─────────────────────────────────────────────────────┐
│ 本次将对已选{数量}位待营销客户执行已线下处理操作，执行  │
│ 后该批客户将不在待营销状态下展示，确认继续吗？          │
│                    [取消] [确认]                      │
└─────────────────────────────────────────────────────┘
```

- **成功反馈**：确认后对客户全部待营销商机保存人工处理记录并重算状态，客户不再在待营销下展示；无需填写方式和结果。
- **失败反馈**：确认前客户状态已变化时提示实际处理数量，只处理仍为待营销的客户。
- **异常状态下的结构变化**：操作不可撤销，确认后无恢复入口。
