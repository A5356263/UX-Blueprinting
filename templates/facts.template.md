# Facts

> 本模板用于约束 `facts.md` 的最终输出结构，不代表内部生成方式。
> 生成阶段应先完成事实推理与结构化抽取，再由 renderer 输出本结构。

## 任务意图

- 任务目标：先明确本轮任务要解决什么问题。
- 任务边界：明确本次只覆盖什么，不覆盖什么。
- 输出用途：说明这些事实将如何支撑 business judgment 与 experience translation。

## 事实来源说明

- 主输入：
  - `projects/{{TASK_ID}}/source/requirement.md`
  - `projects/{{TASK_ID}}/source/background.md`
- 显式引用：
  - 仅列出 task card 中实际命中的 wiki / knowledge / guideline
- 使用边界：
  - 引用知识只用于术语校准、边界校准、冲突识别与缺口识别，不替代当前任务事实

## 术语与对象边界

- 先统一术语，再进入角色、对象、规则、状态与异常提取。

## 角色与对象清单

- 角色要区分配置方、申请方、审批方、协作方、系统反馈方。
- 对象要区分核心对象、配置对象、结果对象。

## 原子事实清单

- facts 必须按 Actor / Object / State / Action / Rule / Exception / Dependency / Scope 分组。
- 每条事实只表达一个明确业务结论，不能把多层信息压成一句摘要。

## 规则矩阵

- 规则必须拆成触发条件、作用对象、前置条件、结果、失败 / 拦截。

## 状态模型

- 状态必须区分进入条件、退出条件、阻断条件与状态解释。

## 动作与流程事实

- 流程链路不能替代规则表达，规则表达也不能替代流程链路。

## 异常与拦截清单

- 所有失败、阻断、冲突、不可执行条件都必须单独列出。

## 依赖清单

- 外部流程、帮助文档、组织配置、角色库、应用库等依赖必须显式列出。

## 范围与非范围

- 必须区分本次明确范围、非范围与暂不展开范围。

## 开放问题与缺口

- 输入不足时保留 open question 与 gap，不得伪造事实。

## 追踪映射

- 所有关键事实、规则、异常都必须能回链到 source 输入或显式引用。
