# 设计指南合并文件（guidelines.md）

> 说明：为降低维护复杂度，将原 `principles/*.md` 合并为单文件，按标题分段维护。
> 使用建议：先看 `trigger_index.md` 定位原则 ID，再在本文件中按标题/ID 搜索对应条目。

## 总览说明（来自 index.md）

1. 定位

本目录用于存放跨业务、跨产品复用的通用设计原则（方法论/认知/可用性/无障碍等）。
用于支持 S3 在产出设计文档时进行体验推导与自检。

本库只包含：

原则与方法论（可用性、认知负担、信息架构、可读性、视觉层级、无障碍、治理与信任等）

原则如何转译为“体验要求/风险点/检查问句”（原则层表达）

本库不包含：

任何业务逻辑、业务流程、产品功能规则（这些属于 Business Knowledge / 产品规范）

UI 组件方案、页面布局、视觉规范、工程实现细节

2. 目录结构

index.md：本说明文件（定位、结构、使用方式、维护规则）

trigger_index.md：触发索引（场景/风险 → 推荐原则 ID）

guidelines.md：原则正文合并文件（按标题分段维护）

3. 使用方式（原则库怎么被用）

S3 根据当前任务识别“场景/风险类型”

在 trigger_index.md 中找到对应场景，获取推荐原则 ID

到 guidelines.md 中按标题/原则 ID 查对应原则内容，用于推导设计要求与自检

注意：S3 输出时“如何标记引用了哪些原则/如何在模板里呈现引用”，属于 S3 Agent Prompt 的职责，不在本知识库里定义。

4. ID 命名约定（用于索引与引用）

建议使用统一前缀，便于检索与裁剪：

U- 可用性原则（如 Nielsen）

ISO- ISO 9241-110 交互原则

C- 认知/决策/负担

IA- 信息架构/可发现性

V- 视觉层级/格式塔

R- 可读性/文案/术语一致

G- 治理/信任/可解释性/可追溯/安全

A11Y- 无障碍/包容性

Q- 质量评估框架

L- 交互定律与偏差（可选扩展）

5. 裁剪原则（避免注入过多）

按场景裁剪：只使用与当前场景匹配的原则（以 trigger_index.md 为入口）

按风险优先：高风险/不可逆/权限与安全相关场景优先使用治理与可解释性原则

按任务类型裁剪：表单/列表/搜索/配置/批量/流程/多角色等只拿对应原则

6. 维护规则

新增/调整原则：需同步更新 trigger_index.md 的映射与 guidelines.md 对应条目

保持“原则层”纯净：发现混入业务规则/产品特例/实现细节应移出本库

避免重复：相近原则合并，保留一个主条目，其他用补充说明即可

## 原则卡片：包容性与可访问性（原则层）
> 来源：原 principles 分文件（已合并）

**包容性与可访问性（原则层）**
# A11Y-01 POUR 四原则

来源：WCAG 原则

定义：可感知、可操作、可理解、健壮。

触发：任何广泛用户群系统。

推导输出：信息不只靠颜色；操作可达；内容可理解；结构语义清晰。

文档落点：无障碍要求

自检问句：键盘/辅助技术用户是否可完成关键任务？

反模式：只靠颜色、只靠 hover、缺替代文本。

取舍提示：无障碍不是“加功能”，是“保证可达”。

# A11Y-02 通用设计 7 原则（提纲化）

来源：Universal Design

定义：公平、灵活、简单直观、信息可感知、容错、低体力、空间适配。

触发：多设备、多环境、多能力差异。

推导输出：为边缘用户校验主方案；减少隐性门槛。

文档落点：体验要求（包容性）

自检问句：是否存在“只有高手会用”的路径？

反模式：把弱势人群当作例外处理。

取舍提示：优先覆盖高频关键任务的可达性。

## 原则卡片：认知与决策（复杂系统常用）
> 来源：原 principles 分文件（已合并）

**认知与决策（复杂系统常用）**
# C-01 选择越多越慢（Hick）

来源：交互定律

定义：选项越多，决策时间越长。

触发：菜单/筛选/配置项过多、同层并列过多。

推导输出：分组、默认、渐进披露；减少同层并列选项。

文档落点：信息结构｜流程

自检问句：用户是否在一屏面对大量同权重选项？

反模式：把所有选项平铺。

取舍提示：减少选项可能牺牲灵活性，用“高级展开”平衡。

# C-02 工作记忆有限（分块，不机械 7±2）

来源：认知心理

定义：避免要求用户同时记很多信息。

触发：多条件组合、跨页配置、规则编辑。

推导输出：分步呈现；当前选择/结果摘要外显；可回看。

文档落点：信息结构｜流程

自检问句：用户是否必须记住多个条件才能继续？

反模式：无摘要、无回看、跨页丢上下文。

取舍提示：分步会增加步骤数，需用默认值减少负担。

# C-03 减少无关认知负荷（Cognitive Load）

来源：认知负荷理论

定义：减少“外在负荷”，把认知资源留给任务。

触发：信息密度高、术语多、规则复杂。

推导输出：删无关信息；用示例/模板；分层解释。

文档落点：可读性｜信息结构

自检问句：用户是否在做“解题”而不是做任务？

反模式：大量解释一次性倾倒。

取舍提示：必要规则必须保留，但要分层。

# C-04 渐进披露（Progressive Disclosure）

来源：信息呈现策略

定义：先主任务，后高级/低频能力。

触发：配置项多、专家功能多。

推导输出：主路径不被高级项打断；高级能力延后出现。

文档落点：信息结构｜流程

自检问句：新手是否被迫面对全部复杂度？

反模式：高级参数默认展开。

取舍提示：高级入口要可发现但不打扰。

# C-05 默认效应（Default Effect）

来源：行为经济学/心理学

定义：默认值会被大量接受，影响面大。

触发：开关、范围、审批、生效策略。

推导输出：默认必须安全、可解释、可逆；默认匹配最常见场景。

文档落点：默认策略｜风险与防护

自检问句：默认是否可能导致越权/误配置？

反模式：默认放大权限、默认不可逆。

取舍提示：默认越保守，可能增加操作成本，需提供效率通道。

# C-06 损失厌恶（Loss Aversion）

来源：行为经济学

定义：用户对损失更敏感。

触发：删除/禁用/收回权限/覆盖。

推导输出：强调影响范围与恢复方式；提供预览与回滚说明。

文档落点：风险与防护｜反馈

自检问句：用户是否在“不确定后果”下被迫确认？

反模式：确认弹窗只问“确定吗”。

取舍提示：解释越充分，越能减少误操作，但需简洁分层。

# C-07 峰终定律（Peak-End）

来源：体验记忆偏差

定义：记忆受峰值与结尾影响大。

触发：长流程、审批闭环、保存/发布。

推导输出：峰值处给清晰解释与可逆；结尾给明确结果与下一步。

文档落点：流程结束态｜反馈

自检问句：结束时是否让用户不确定“是否生效/下一步”？

反模式：完成后无总结、无下一步。

取舍提示：结尾总结可做为“可复制的结果摘要”。

## 原则卡片：治理、信任与可解释性（对复杂业务特别关键）
> 来源：原 principles 分文件（已合并）

**治理、信任与可解释性（对复杂业务特别关键）**
# G-01 最小惊讶（Least Surprise）

来源：通用软件原则

定义：系统行为符合承诺与直觉，不暗改结果。

触发：覆盖规则、默认值、自动生效。

推导输出：任何覆盖/自动行为必须可解释、可追溯。

文档落点：规则｜可解释性｜审计

自检问句：用户是否常说“我明明配置了但没生效”？

反模式：覆盖规则隐藏、结果与预期不一致且无解释。

取舍提示：透明会增加信息量，用分层表达。

# G-02 可解释性（Explainability）

来源：复杂系统通用要求

定义：用户能理解“为什么是这个结果”。

触发：多来源叠加、优先级覆盖、审批生效。

推导输出：必须提供来源、优先级、冲突原因、判定链路（可读文本）。

文档落点：规则｜可见信息清单

自检问句：能否回答“为什么有/没有、为何不生效”？

反模式：只展示结果不展示原因。

取舍提示：解释内容可折叠，但关键原因必须可达。

# G-03 可追溯（Traceability）

来源：治理/合规模型

定义：关键变更可被追踪与复盘。

触发：权限、策略、批量、导出。

推导输出：记录谁/何时/对谁/做了什么/影响范围/原因；支持查询。

文档落点：审计与查询｜依赖与缺口

自检问句：出了问题能否定位责任与影响？

反模式：只记录“发生过变更”，没有细节。

取舍提示：追溯成本高，优先覆盖高风险动作。

# G-04 最小授权（Least Privilege）

来源：安全原则

定义：默认更安全，授权范围可控。

触发：授权/共享/可见性/导出。

推导输出：默认收敛；扩大范围需要更强解释与确认；可撤销。

文档落点：默认策略｜风险与防护

自检问句：默认是否可能导致越权？

反模式：默认全开、缺回收路径。

取舍提示：安全与效率冲突时，提供可审计的效率通道。

## 原则卡片：信息架构与可发现性
> 来源：原 principles 分文件（已合并）

**信息架构与可发现性**
# IA-01 信息气味（Information Scent）

来源：信息觅食理论

定义：用户用线索判断入口是否值得点、内容是否匹配预期。

触发：导航命名、列表摘要、搜索结果、配置入口。

推导输出：入口命名可预测；结果提供范围/来源/状态等线索。

文档落点：IA｜命名｜列表信息要求

自检问句：用户能否在点击前判断点进去会得到什么？

反模式：入口名含糊、点进去才发现不相关。

取舍提示：线索太多会噪音，优先关键线索。

# IA-02 分块（Chunking）

来源：认知策略

定义：按任务与语义分组信息。

触发：长表单、规则说明、配置页。

推导输出：同组强相关；组与组边界清晰；标题表达组意图。

文档落点：信息结构

自检问句：用户是否需要来回对照才能理解字段关系？

反模式：字段散落、说明与字段分离过远。

取舍提示：分块要服务任务顺序，不要只按数据结构分。

# IA-03 单一语义源（Single Source of Meaning）

来源：一致性原则延伸

定义：同一概念的定义与解释应一致可复用。

触发：跨模块复用、多人协作、长期演进。

推导输出：术语表与规则表可引用；避免不同处不同解释。

文档落点：术语表｜规则库

自检问句：同一概念是否出现两套定义？

反模式：各模块自行解释，产生漂移。

取舍提示：需要治理机制维护“定义源”。

## 原则卡片：交互效率与操作学
> 来源：原 principles 分文件（已合并）

**交互效率与操作学**
# I-01 指向效率（Fitts）

来源：交互定律

定义：目标越大/越近，操作越快越不易错。

触发：主操作、高频操作、移动端触控。

推导输出：高频目标更易触达；危险操作避免“太易触达”。

文档落点：操作原则｜风险与防护

自检问句：高频操作是否需要精细点击？

反模式：高频按钮很小、危险按钮离主操作太近。

取舍提示：易触达与防误触需平衡（隔离危险操作）。

# I-02 约束与防呆（Constraints）

来源：交互原则

定义：用约束减少错误路径与不确定性。

触发：输入、范围选择、条件组合。

推导输出：不可选即不可操作且原因可解释；避免先错后罚。

文档落点：校验规则｜可解释性

自检问句：用户是否经常走到“不可用”的死路？

反模式：把错误留到最后一次性爆发。

取舍提示：约束要配说明，避免“系统莫名其妙不让选”。

# I-03 新手/专家双通道

来源：可用性原则组合

定义：新手保底，专家提速。

触发：管理员高频配置、重复任务。

推导输出：保留安全主路径；提供批量/快捷但可审计可回滚。

文档落点：流程｜效率策略

自检问句：专家是否只能重复低效步骤？

反模式：只有一种路径，且对一类用户极其低效。

取舍提示：快捷能力必须有边界与风险控制。

## 原则卡片：B端表单流程模式选择（步骤条 vs 单页锚点）
> 来源：B端表单流程模式实践总结（已结构化为设计原则）

**B端表单流程模式选择（步骤条 vs 单页锚点）**
# BFM-01 默认非步骤化（B端专家场景）

来源：B端专家用户特征 + 流程效率原则

定义：对 B 端高频录入/编辑型任务，默认优先单页表单，不因“字段多/表单长/看起来复杂”直接使用步骤条。

触发：长表单、复杂配置页、二次编辑频繁、资料分批补录。

推导输出：先评估 `single_page_form` 是否可完成；优先从任务依赖而非字段数量决定流程模式。

文档落点：流程模式决策｜信息结构

自检问句：如果取消步骤条，用户是否更容易全局查看、补录与修改？

反模式：把 Steps 当成“复杂表单默认答案”。

取舍提示：字段多不等于流程多；先判断依赖关系，再决定是否分步。

# BFM-02 步骤条使用门禁（强依赖/不可逆/高风险）

来源：流程控制与风险管理

定义：步骤条用于“真实分步流程”，而不是视觉分组。

触发：后续内容强依赖前一步结果、分阶段校验/阶段提交、一次性不可逆任务、低频高风险任务。

推导输出：仅在上述门禁满足时使用 `wizard + Steps`；并显式说明触发依据。

文档落点：流程模式决策｜风险控制

自检问句：后续步骤是否会因前一步选择而改变字段集合、规则或校验？

反模式：步骤条仅作装饰，无真实切换与阶段状态。

取舍提示：步骤条能降低阶段内认知负担，但会增加跨步骤往返与修改成本。

# BFM-03 单页长表单 + 锚点导航（步骤条替代模式）

来源：信息架构与可控性原则

定义：在无强步骤依赖的 B 端长表单场景，用单页长表单配合锚点导航提供全局视角与随机存取能力。

触发：日常高频录入、商品/资料编辑、可分批收集资料、二次修改频繁。

推导输出：同屏展示主要模块；提供锚点定位；允许按资料可得性跳填；可配暂存/草稿策略。

文档落点：信息结构｜流程｜可控性

自检问句：用户是否需要频繁往返不同区块修改内容？是否需要按手头资料跳填？

反模式：线性“下一步”强打断录入心流，导致反复切换和高修改成本。

取舍提示：单页模式提升全局掌控感，但必须控制信息密度并保证分块清晰、定位便捷。

## 原则卡片：ISO-01 适合任务
> 来源：原 principles 分文件（已合并）

# ISO-01 适合任务

来源：ISO 9241-110

定义：交互应高效支持任务完成。

触发：流程冗长、重复输入、频繁切换。

推导输出：减少非必要步骤；结构顺序匹配任务顺序。

文档落点：流程｜信息结构

自检问句：是否存在“为系统而做”的步骤？

反模式：为了配置而配置、必须走完全部字段。

取舍提示：一致性与效率可能冲突，优先保任务完成。

# ISO-02 自描述

来源：ISO 9241-110

定义：用户在任意点都能理解“这里是什么/能做什么/下一步”。

触发：复杂配置页、规则编辑、空状态。

推导输出：关键对象/范围/状态语义清晰；结果可解释。

文档落点：信息结构｜状态与反馈

自检问句：是否需要培训才能理解当前页面？

反模式：只有内部术语、缺上下文。

取舍提示：自描述依赖一致术语与可读性。

# ISO-03 可控性

来源：ISO 9241-110

定义：用户能控制节奏与顺序。

触发：自动跳转、强制流程、批量执行。

推导输出：支持暂停/返回/调整；避免不可预期的自动行为。

文档落点：流程｜风险与防护

自检问句：系统是否“替用户做决定”且不可改？

反模式：强制提交、不可返回。

取舍提示：对高风险动作可提高控制成本以换安全。

# ISO-04 符合预期

来源：ISO 9241-110

定义：与用户既有经验一致（平台/行业/产品内部一致）。

触发：多端一致、迁移旧系统、管理员工具。

推导输出：不随意发明新概念/新入口；例外需解释。

文档落点：命名规范｜信息结构

自检问句：是否出现“只有老用户才懂”的私有规则？

反模式：同类功能在不同端逻辑不同。

取舍提示：创新要有强收益且可渐进引入。

# ISO-05 容错

来源：ISO 9241-110

定义：允许犯错且不造成严重后果。

触发：权限/配置/批量/高影响变更。

推导输出：预览影响、可回滚、失败可恢复。

文档落点：风险与防护｜审计

自检问句：误操作是否会造成不可逆后果？

反模式：一次点击永久生效。

取舍提示：容错会增加系统复杂度，需分风险等级。

# ISO-06 适合学习

来源：ISO 9241-110

定义：系统帮助用户逐步掌握。

触发：首次使用、复杂模块、角色交接。

推导输出：渐进披露、示例、就地解释、可逆操作。

文档落点：帮助与指引｜流程

自检问句：新手能否在无培训下完成核心任务？

反模式：上来就要求理解全部概念。

取舍提示：学习性与效率需双通道策略。

# ISO-07 可个性化

来源：ISO 9241-110

定义：允许不同用户以不同方式完成任务。

触发：岗位差异大、新手/专家差异大。

推导输出：偏好/视图可配置，但不破坏一致性与审计。

文档落点：效率策略｜可配置项

自检问句：是否只有一种路径，且对某类角色很不友好？

反模式：强制统一流程忽略岗位差异。

取舍提示：个性化需要边界与回退机制。

## 原则卡片：U-01 系统状态可见
> 来源：原 principles 分文件（已合并）

# U-01 系统状态可见

来源：Nielsen 启发式

定义：系统应持续告知用户当前状态与进展。

触发：异步、审批/延迟生效、加载、后台任务、冲突覆盖。

推导输出：状态/进度/结果必须可见；用户能判断“现在/下一步/何时生效”。

文档落点：状态与反馈｜流程｜可解释性

自检问句：用户是否需要刷新/猜测系统在做什么？

反模式：操作后无反馈、只给“成功/失败”不解释。

取舍提示：信息可见≠信息堆叠，需分层呈现。

# U-02 贴近现实世界

来源：Nielsen

定义：用用户熟悉的概念与语言解释系统。

触发：领域术语多、规则抽象、管理员配置。

推导输出：用业务语义表达规则与对象；避免内部字段直出。

文档落点：术语与概念｜规则

自检问句：用户是否必须理解系统内部结构才能操作？

反模式：术语混用、名词不可理解。

取舍提示：必要专业术语要给出定义与示例。

# U-03 用户控制与自由

来源：Nielsen

定义：支持撤销、回退、退出，避免“被困住”。

触发：长流程、批量、高风险配置、误操作成本高。

推导输出：关键动作可撤销/可回滚；提供退出与恢复入口。

文档落点：流程｜风险与防护

自检问句：做错一步是否只能重来？

反模式：强制不可退、不可撤销。

取舍提示：不可撤销时必须加强确认与审计。

# U-04 一致性与标准

来源：Nielsen

定义：同概念同命名同规则；遵循平台与行业惯例。

触发：多模块、多端、多入口。

推导输出：术语/状态/反馈/规则表达统一；避免同义不同名。

文档落点：命名规范｜状态与反馈｜规则

自检问句：同一概念是否在不同位置叫不同名字？

反模式：状态名、按钮文案、概念模型漂移。

取舍提示：少数例外必须显式标注“为什么不同”。

# U-05 错误预防

来源：Nielsen

定义：优先通过约束与提示降低错误发生。

触发：高风险操作、权限/资金/删除、复杂配置。

推导输出：执行前暴露影响范围与冲突原因；阻止明显错误路径。

文档落点：校验规则｜风险与防护

自检问句：是否把用户推向错误再报错？

反模式：先允许执行、事后再泛化报错。

取舍提示：过度约束会降低效率，需匹配角色与风险等级。

# U-06 识别优于回忆

来源：Nielsen

定义：让用户“看见就能用”，减少记忆负担。

触发：跨页配置、多条件、多来源叠加。

推导输出：关键选择/来源/结果外显；提供摘要与上下文线索。

文档落点：信息结构｜可解释性

自检问句：用户是否要记住上一步做了什么？

反模式：隐藏关键信息、依赖用户记忆。

取舍提示：外显信息需可扫读，避免长段解释。

# U-07 灵活与效率

来源：Nielsen / Shneiderman

定义：兼顾新手保底与熟练用户提速。

触发：管理员高频任务、重复配置、批量处理。

推导输出：默认值/批量/快捷入口；但不破坏可控与安全。

文档落点：流程｜效率策略

自检问句：熟练用户是否被迫走新手路径？

反模式：只能逐条处理、重复劳动。

取舍提示：效率提升要配套审计与回滚。

# U-08 极简与聚焦

来源：Nielsen

定义：减少无关信息，突出任务与决策点。

触发：信息密度高、配置页/表格页。

推导输出：主次分层；低频/高级内容延后呈现。

文档落点：信息结构｜可读性

自检问句：是否“全是重点”导致没有重点？

反模式：一屏堆满规则与字段。

取舍提示：极简不等于缺信息，关键是分层。

# U-09 可行动的错误恢复

来源：Nielsen

定义：错误要可理解、可定位、可行动。

触发：校验失败、冲突覆盖、权限不足。

推导输出：原因+影响+修复路径；提供下一步建议。

文档落点：错误与恢复｜规则

自检问句：用户看完错误是否仍不知道怎么办？

反模式：只给错误码/“未知错误”。

取舍提示：避免暴露敏感内部信息，但要给可行动指引。

# U-10 就地帮助与文档

来源：Nielsen

定义：复杂系统需要可就地获取的解释。

触发：首次使用、规则系统、管理员工具。

推导输出：关键决策点提供解释入口；帮助可检索、可复制。

文档落点：帮助与指引｜术语

自检问句：用户是否只能找人问？

反模式：把帮助全放到外部大文档。

取舍提示：帮助应短、贴近当前决策点。

## 原则卡片：视觉层级与感知组织（原则层）
> 来源：原 principles 分文件（已合并）

**视觉层级与感知组织（原则层）**
# V-01 视觉层级（Visual Hierarchy）

来源：视觉认知

定义：用层级引导注意力与决策顺序。

触发：信息密度高、关键路径不清。

推导输出：主任务/主风险最突出；次要信息弱化并可展开。

文档落点：信息结构（层级要求）

自检问句：用户是否能一眼找到“该做什么”？

反模式：所有信息同权重、无主次。

取舍提示：突出越多越稀释，慎用强调。

# V-02 接近性（Proximity）

来源：格式塔

定义：相近即相关。

触发：字段+说明、按钮组、条件组。

推导输出：强相关元素靠近；避免产生错误配对。

文档落点：信息结构（分组规则）

自检问句：说明是否跟错对象？

反模式：说明集中在页尾、用户来回找。

取舍提示：靠近不等于拥挤，需留出层级间距。

# V-03 相似性（Similarity）

来源：格式塔

定义：相似即同类/同状态。

触发：状态标签、按钮、可点击元素。

推导输出：同语义一致；不同语义必须可区分。

文档落点：状态与反馈（表达一致性）

自检问句：不同状态是否看起来一样？

反模式：相同样式表达不同语义。

取舍提示：差异表达要有规则，避免随意改色改形。
