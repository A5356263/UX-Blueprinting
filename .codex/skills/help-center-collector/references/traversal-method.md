# 遍历方法

使用"清单制 + 广度优先 + 完整性核对"。

## 1. 核心规则

先列清单，再采正文，最后逐项核对。

在拿到某个模块的完整子目录和文章列表前，不要开始该模块的正文采集。

对每个模块都按这个顺序做：

1. 打开模块目录页。
2. 列出所有可见子目录和文章链接。
3. 把完整列表写进模块 `README.md` 或采集清单。
4. 以这份列表作为采集任务清单。
5. 每采完一篇文章就立刻写入文件。
6. 同步把该项标成已完成。
7. 在宣布模块完成前，对比磁盘文件数和清单项数。
8. 如果数量不一致，就逐项回查并补采缺失页面。

## 2. 清单格式

```md
## 采集清单

| 序号 | 文章标题 | 文件路径 | 状态 |
|------|---------|----------|------|
| 1 | xxx | modules/xxx/xxx.md | 已完成 / 进行中 / 未开始 |
```

## 3. 广度优先流程

1. 打开帮助中心首页。
2. 等到导航和文章列表稳定。
3. 识别一级模块和可点击入口。
4. 展开第一个一级模块，记录完整子项列表。
5. 递归检查每个子目录，并继续记录完整子项列表。
6. 只有进入真正有正文的文章页时，才开始采集内容。
7. 按清单顺序逐篇采集。
8. 每完成一个子目录，就做一次文件数核对。
9. 返回上一级，继续下一个子目录。

## 4. 叶子节点判定

下面这些类型要区分清楚：

- 文章列表页：继续往下遍历。
- 文章详情页：有标题、段落、步骤时，采正文。
- FAQ 列表页：如果每项都能点开独立答案页，就不是叶子节点。
- 版本动态列表页：如果每项都能点开独立详情页，就不是叶子节点。
- 手册列表页：如果每项都能点开独立详情页，就不是叶子节点。

### 硬规则

只要列表项能进入独立详情页，它就是内容节点，必须采正文，不能只留标题壳。

## 5. 完整性检查

完成一个目录层级后，要核对清单和磁盘输出是否一致。

用本地文件列表命令对比预期 Markdown 文件和实际 Markdown 文件。

在数量和文件名都对上前，不要把该目录标成完成。

## 6. 去重依据

去重时综合看这些信号：

- URL 或 hash route
- 页面标题
- 面包屑路径
- 主内容标题
- 模块路径
- 主体内容相似度
