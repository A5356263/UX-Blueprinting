# 采集范围与原则

## 1. 工具能力预期

### 1.1 环境检查

开始采集前，先确认当前 Codex 环境里有可用的浏览器导航和页面检查能力。

优先使用 Browser Use 插件或等价浏览器工具。如果当前环境没有浏览器自动化能力，就停止采集并明确报告限制，不要伪造采集结果。

最低需要的能力包括：

- 打开 URL
- 检查页面结构
- 点击展开目录和文章链接
- 在需要视觉识别时截图
- 在需要定位媒体资源时查看网络请求

如果某些能力缺失，要把限制写进采集日志，只在现有能力支持的范围内继续。

### 1.2 媒体识别

使用模型的视觉能力识别：

- 截图
- 帮助文档中的产品图片
- 视频关键帧

如果视觉识别不可用，就保留媒体资源、上下文和失败说明，不要猜界面细节。

## 2. 采集边界

### 2.1 需要采集

只采与产品使用相关的信息：

- 产品模块
- 功能入口
- 操作流程
- 配置步骤
- 字段说明
- 明确规则
- 权限、审批、数据或状态限制
- 前置条件
- 依赖关系
- 异常处理
- 注意事项
- 图片里的可识别产品信息
- 视频里的可识别产品信息
- 相关帮助内容链接

### 2.2 不需要采集

排除这些与产品使用无关的信息：

- 页脚内容
- 电话号码
- 二维码
- 法律备案信息
- IPv6 标识
- 法律与合规页面
- 服务协议
- 隐私政策
- 关于我们
- 新闻资讯
- 通用客服入口
- 营销或品牌介绍

判断标准：

```text
这条信息是否有助于理解产品能力、流程、配置规则或使用限制？
```

如果有，就采。

如果没有，就排除。

## 3. 采集原则

### 3.1 尽量贴近原帮助结构

输出结构要尽量贴近帮助中心原始结构：

- 一级模块
- 二级模块
- 文章
- 小节
- 步骤
- 图片或视频
- 规则或注意事项

不要把无关模块混进同一个输出文件。

### 3.2 保留原始粒度

不要把页面压成摘要。

尽量保留：

- 原始标题
- 原始段落
- 原始步骤
- 原始提示文案
- 原始注意事项
- 原始规则说明
- 字段说明
- 操作限制
- 异常提示

### 3.3 只记录明确规则

只记录页面明确写出的规则。

不要写：

- 可能
- 大概
- 按经验看
- 推测

如果页面没说清，就写：

```md
当前页面未明确说明。
```

### 3.4 媒体信息回填上下文

图片和视频解析结果必须写回原来的文章位置：

- 对应模块
- 对应文章
- 对应步骤或小节

可以另建媒体索引做导航，但不能替代正文里的上下文内容。

### 3.5 过程残留不进正文

正文里只放产品知识。

下面这些内容要单独记到采集日志里：

- 采集失败
- 浏览器能力缺失
- 页面加载失败
- 视频解析失败
- 图片解析失败
- 覆盖率统计
- visited 记录
- 过程说明

统一放在：

```text
help/_collection/
```
