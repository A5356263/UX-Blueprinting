# 条件确认说明

这份说明只负责：

**分析总结收敛之后，怎么用用户可读的“分析结论收敛”进入条件确认。**

## 顺序

当前固定顺序是：

```text
Step 2
→ 分析总结收敛
→ 分析结论收敛
→ 条件确认
```

条件确认前，必须先有分析总结收敛。

## 什么时候进入条件确认前收敛

满足下面条件后，才整理“分析结论收敛”：

1. `Step 1` 已完成
2. `Step 2` 已完成
3. `Step 2` 后已经停下来交流
4. 已完成分析总结收敛

如果还没到这里，不要提前进入条件确认。

## 分析结论收敛结构

默认使用四段：

1. 已明确
2. 必须解决
3. 未定项
4. 下一步

不要再生成“一句话总结”类模块。

## 用户侧表达

分析结论收敛必须用用户看得懂的话。

不要说：

- `facts`
- `route_decision`
- `run-routed-main`
- `gate / validate / coverage`

可以说：

- 当前已经比较明确的是
- 现在真正必须解决的是
- 现在还没完全定死的是
- 你可以直接选下一步

## 条件确认

分析结论收敛后，必须进入条件确认节点。

默认 3 条路径是：

1. 进入正式蓝图任务
2. 先补充需要确认的
3. 探索更多的业务方案

这里默认使用编号选项。

## 启动门槛

只有用户明确选择：

- `1. 进入正式蓝图任务`

才表示正式进入主链路。

确认之前：

1. 不创建正式任务目录
2. 不写正式输入
3. 不写判断单
4. 不运行主链路

## 正式产物与知识库边界

正式任务产物进入：

- `projects/<project-id>/`

不要把正式任务产物自动写进 `knowledge/`。
