# 判断不准时的询问规则

## 何时算判断不准

只要 UXB 无法确认以下任一项，就不能输出确定复杂度：

- 是否改变业务对象关系
- 是否改变业务规则
- 是否改变状态机
- 是否改变生效机制
- 是否改变数据口径
- 是否涉及外部回写链路
- 是否只是复用现有逻辑
- 是否只是前端展示、布局、反馈或文案

## 必须怎么做

1. 说明当前不能直接判断为低 / 中 / 高复杂度。
2. 说明卡点是什么。
3. 只问阻碍判断的关键问题。
4. 问题不超过 3 个。
5. 用户补充前，不输出确定结论。
6. 不自行假设业务规则。

## 提问类型

优先从下面六类里选问题：

- 对象：是否新增或改变核心业务对象关系？
- 规则：是否改变业务规则、计算规则、审批规则、可见规则？
- 状态：是否新增状态、状态流转或失败分支？
- 生效：结果何时生效，是否需要审批、定时或回写？
- 口径：是否改变统计、汇总、保密、归属或范围口径？
- 回写：是否联动银行、税局、ERP、总账、电子档案等外部系统？

## 推荐表达

```md
判断：现在还不能直接判断为低 / 中 / 高复杂度。
卡点：当前不清楚它是否影响 <对象 / 规则 / 状态 / 生效 / 口径 / 回写>。
建议：先确认关键边界，再决定处理方式。
需要确认：
1. ...
2. ...
3. ...
```

## 示例

现在还不能判断它是局部体验优化还是既有能力扩展。

卡点在于：这个改动是否只是复用现有审批逻辑，还是改变审批后的生效规则。

请确认：
1. 是否复用现有审批流程？
2. 审批通过前结果是否生效？
3. 审批拒绝后是否需要回滚？

## 容易复用的问题方向

以下不是固定场景模板，而是在相似边界类型下可优先参考的问题方向。

### 非标准人员身份边界

当需求涉及外部人员、外包人员、顾问、供应商人员等非标准员工身份时，可优先确认：

1. 这类人员是否进入员工主数据、组织架构或汇报关系？
2. 是否与正式员工共用同一套账号、字段和状态？
3. 是否需要参与权限、门户、协作或审批流程？

### 角色化首页 / 入口分发边界

当需求涉及不同角色看到不同首页、入口或工作台时，可优先确认：

1. 首页差异是否只影响展示，还是会改变应用可见范围？
2. 多角色用户是自动命中一个首页，还是允许切换 / 合并？
3. PC 和移动端是否必须共享同一套入口分发规则？
