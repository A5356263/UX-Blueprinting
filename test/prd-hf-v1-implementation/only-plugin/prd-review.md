# 正式需求基线

- 项目：剧场场务设备转交
- 基线状态：`formal`
- 原始 PRD：`requirements.md`
- 辅助输入：`prototype-reference.md`，仅作形态参考。

## §1 背景与目标

### 为什么现在做

场务主管需要在剧场场次内转交设备。原始 PRD 说明了现有设备台账的进入方式，未说明此前如何处理转交及其直接影响。依据为 PRD「范围与角色」。

### 本期目标

支持在设备台账完成本场次设备的保管人转交。依据为 PRD「范围与角色」。

### 本期范围

- 包含本场次单件设备转交，具体变更见 §2。
- 本期排除项见 §9。

## §2 功能与变更清单

### 新增

#### 本场次设备转交

- 本期变化：设备台账增加转交能力。
- 对象关系：一次转交关联一件设备和一名接收人，见 BR-001。
- 来源：PRD「范围与角色」。

### 复用能力

- 复用「设备台账」菜单及其现有工具页。来源为 PRD「范围与角色」。

## §3 谁能做什么

- 场务主管负责发起转交，将当前场次设备转交给该场次的在岗接收人，范围见 BR-001。
- 只有场务主管能看到并使用本期转交操作。其他角色看不到该操作。
- 来源：PRD「范围与角色」。

## §4 每件事怎么完成

### FN-001 · 场务主管 · 转交本场次设备

#### 什么时候开始

- 需求发生事件：本场次需要转交设备。
- 业务触发条件：场务主管办理本场次设备转交。
- 前置条件：设备须属于当前场次，见 BR-001。
- 来源：PRD「范围与角色」。

#### 从哪里进入

- 本期支持的进入渠道：「设备台账」菜单进入现有工具页。
- 现有任务位置：工具页的设备列表行。
- 现有页面或载体：「设备台账」工具页。
- 来源：PRD「范围与角色」「已确认的操作与文本」。

#### 怎么完成

1. 点击设备行的「发起转交」，打开「设备转交」弹窗。
2. 弹窗只读显示「设备编号」「当前保管人」，并提供「接收人」字段和三个独立选项「携带说明」「通知接收人」「保留交接备注」。接收人和选项规则见 BR-001、BR-002。
3. 选择接收人并按需调整选项。点击「确认转交」，系统按 BR-003 校验，通过后执行 §8 的记录保存及条件通知。
4. 如点击「取消」，关闭弹窗并保留原设备行，记录结果见 §8。

来源为 PRD「已确认的操作与文本」。

#### 完成后发生什么

- 成功结果：关闭弹窗，返回设备列表原行并更新「当前保管人」，提示「设备已转交」。
- 失败或拒绝结果：拦截转交并留在弹窗内，触发和处理见 EX-001、EX-002。
- 下一步：成功后在原行查看更新结果。取消后转交结束，返回未变化的原行。
- 来源：PRD「已确认的操作与文本」。

## §5 要遵守什么规则

### BR-001 · 转交范围与接收人

- 适用对象：一次设备转交。
- 触发条件：场务主管选择和提交转交对象。
- 判断条件：仅限一件当前场次设备，且必须选择一名本场次在岗人员作为接收人。
- 业务结果：跨场次设备及离岗接收人不可提交。
- 来源：PRD「范围与角色」「已确认的操作与文本」。

### BR-002 · 转交选项

- 适用对象：「设备转交」的三个独立选项。
- 触发条件：打开弹窗或调整选项。
- 业务结果：允许多选、允许全不选。初始仅勾选「通知接收人」。按以下勾选结果处理：
  - 携带说明 → 连同设备使用说明交接。
  - 通知接收人 → 保存后按 §8 发送站内通知。
  - 保留交接备注 → 一同保留当前记录中的交接备注。
  - 未勾选 → 对应内容不随本次转交。
- 来源：PRD「已确认的操作与文本」。

### BR-003 · 提交校验顺序

- 适用对象：「确认转交」提交。
- 触发条件：点击「确认转交」。
- 判断条件：必须已选接收人。资格校验先判断设备是否仍属于当前场次，再判断接收人是否仍为本场次在岗人员。
- 业务结果：必填与资格校验均通过才可保存，拦截处理见 §7。
- 优先级或互斥关系：资格校验依设备、接收人的顺序执行。
- 来源：PRD「已确认的操作与文本」。

## §6 会出现哪些状态

本期无新增业务状态枚举。用于提交判断的场次和在岗资格见 BR-001、BR-003。

## §7 遇到特殊情况怎么办

### EX-001 · 未选接收人

- 触发场景：未选择接收人就点击「确认转交」。
- 业务判定：接收人必填校验未通过。
- 对用户任务的结果：拦截提交，在「接收人」字段下显示「请选择接收人」。
- 对对象状态的结果：见 §8 的失败处理。
- 是否允许重试或恢复：场务主管可选择接收人后再次发起提交。
- 来源：PRD「已确认的操作与文本」。

### EX-002 · 提交时设备或接收人资格变化

- 触发场景：点击「确认转交」时设备已不属于当前场次，或者接收人已不符合本场次在岗资格。
- 业务判定：BR-003 的资格校验未通过。
- 对用户任务的结果：不保存，弹窗保持打开并保留其他输入，提示「设备或接收人状态已变化」。
- 对对象状态的结果：见 §8 的失败处理。
- 是否允许重试或恢复：场务主管可刷新候选后重新选择，也可取消。
- 来源：PRD「范围与角色」「已确认的操作与文本」。

## §8 会影响哪些记录和系统

- 成功提交时保存新的保管人，以及 BR-002 三项各自的勾选状态。只读显示字段见 FN-001。
- 系统在保存成功且勾选「通知接收人」时，向所选接收人发送一次站内通知。未勾选时不发送。
- 失败或取消不改变保管人、选项记录或通知结果。
- 来源：PRD「已确认的操作与文本」。

## §9 这次明确不做什么

- 不支持批量转交、跨场次转交或短信通知。
- 无需审批或二次人工确认。
- 来源：PRD「范围与角色」「范围排除」。

## §11 做成后应该看到什么结果

- **AC-001（FN-001、BR-002）** 场务主管通过「设备台账」进入设备列表并点击设备行的「发起转交」后，打开「设备转交」弹窗。可查看两个只读字段和接收人字段，且初始只选「通知接收人」。
- **AC-002（FN-001、BR-002、BR-003）** 选择一名合格接收人、保留通知选项并点击「确认转交」后，关闭弹窗，返回原行看到更新后的「当前保管人」及「设备已转交」，并产生一次站内通知。
- **AC-003（BR-002）** 在设备和接收人均合格时取消三个勾选并提交，转交成功，三项均保存为未勾选，无站内通知，说明和备注均不随本次转交。
- **AC-004（EX-001）** 未选接收人点击「确认转交」，提交被拦截，接收人字段下出现「请选择接收人」。
- **AC-005（EX-002、BR-003）** 提交时设备已不属于当前场次或接收人已不符合本场次在岗资格，提交不保存，弹窗保留其他输入并显示「设备或接收人状态已变化」，可刷新候选后重新选择或取消。
- **AC-006（FN-001）** 在弹窗点击「取消」，关闭弹窗并返回未变化的设备原行，保管人、选项记录和通知结果均保持原状。
- **AC-007（§3）** 其他角色进入设备列表时看不到「发起转交」。
