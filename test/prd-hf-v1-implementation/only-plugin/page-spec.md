# 页面生成规格：剧场场务设备转交

## 1. 页面摘要

- **产品领域**：剧场场务设备台账。
- **页面类型**：现有设备台账工具页、设备转交弹窗。
- **用户角色**：场务主管负责发起和提交转交。在岗接收人接受保管人变更，按选项接收站内通知。
- **核心任务**：从设备原行发起转交，为本场次的一件设备选择一名在岗接收人，配置转交选项，确认后回到原行核对结果。

---

## 2. 生成范围

### 生成

- E1 · 设备台账工具页（修改）。落地「设备台账」菜单进入、设备列表、行内转交入口和返回原行的结果。按下文覆盖本期所需结构，沿用现网未涉及本期的台账区域和字段。
- E2 · 设备转交弹窗（新增）。源自 E1 设备行，承接默认表单、候选展开、未选接收人校验、资格变化与恢复。

### 只引用不生成

- 站内通知的接收侧仅承接系统发送结果，转交任务在台账原行结束。

### 不生成

- 转交保存与资格校验后台处理属于非界面逻辑。
- 批量转交、跨场次转交、审批、二次人工确认及短信通知超出范围。

---

## 3. 跨实体任务流程

### 转交当前场次设备

- 「设备台账」菜单 —点击→ E1 设备台账工具页。
- E1 设备列表原行 —场务主管点击「发起转交」→ E2 设备转交弹窗。
- E2 —点击「确认转交」且保存成功→ 返回 E1 设备列表原行（弹窗关闭，保管人更新并显示成功反馈）。
- E2 —点击「取消」→ 返回 E1 设备列表原行（弹窗关闭，原行和记录保持原状）。
- E2 —点击「确认转交」遭校验拦截→ 停留 E2（在原弹窗修正或取消）。

---

## 4. E1 · 设备台账工具页

### 页面目标

通过设备行启动转交，并在返回时核对同一设备当前的保管人。

### 页面结构

```text
「设备台账」菜单
└─ 设备台账工具页
   └─ 设备列表
      └─ 设备原行
         ├─ 当前保管人  {保管人}
         └─ 发起转交    （仅场务主管可见）
```

### 区域说明

- 设备列表承载现有设备行。当前保管人随对应设备行展示，转交入口置于该行的操作位置。
- 其他角色进入相同列表时，行内隐藏「发起转交」，保留设备列表和该行已授权的现有内容。

### 信息与字段

- 当前保管人：设备原行展示的保管人。成功回流时显示本次所选接收人对应的新保管人。

### 关键操作

- 通过「设备台账」菜单打开本页。
- 场务主管点击本场次设备行的「发起转交」，打开 E2 并保留触发行的位置。跨场次设备不得提交转交。

### 状态与异常恢复

- E2 保存成功并关闭后，定位到发起转交的同一行，更新「当前保管人」，在 E1 显示即时成功 Toast，使用 `ledger.transfer_success`。
- E2 取消并关闭后，定位到同一行，保持原行的保管人及其业务记录。

### 文案与变量

| key | 文案 | 适用位置／状态 | 变量及含义、取值 |
|---|---|---|---|
| ledger.menu | 设备台账 | 进入工具页的菜单 | 无 |
| ledger.list | 设备列表 | 工具页列表区域 | 无 |
| ledger.transfer | 发起转交 | 场务主管的设备行操作 | 无 |
| ledger.transfer_success | 设备已转交 | 保存成功返回原行时的 Toast | 无 |
| shared.custodian | 见跨实体共用文案与变量 | 设备行的保管人标签 | 无 |

## 5. E2 · 设备转交弹窗

### 弹窗目标

核对转交设备的身份和当前保管人，选择一名接收人及可选内容，在当前弹窗内提交或修正拦截问题。

### 区域结构

```text
设备转交
├─ 设备信息
│  ├─ 设备编号    {设备编号}       只读
│  └─ 当前保管人  {当前保管人}     只读
├─ 接收人 *      [请选择接收人 ▾]
├─ 转交选项
│  ☐ 携带说明
│  ☑ 通知接收人
│  ☐ 保留交接备注
└─ [取消]                       [确认转交]
```

### 条件结构（展开接收人）

```text
接收人 *  [{已选接收人或空值} ▴]
           └─ 候选菜单
              └─ {接收人姓名} （单选，选择后回填）
```

### 条件结构（未选接收人提交）

```text
接收人 *  [请选择接收人 ▾]
           └─ 请选择接收人
```

### 条件结构（设备或接收人资格变化）

```text
接收人 *  [{已选接收人} ▾]
           └─ 设备或接收人状态已变化    [刷新候选]
```

### 区域说明

- 设备信息在表单顶部只读呈现。
- 接收人以弹窗内单选下拉承载。展开时在字段下方显示本场次的在岗候选。选中一人后收起菜单并将该人回填到字段，用户可在提交前重新选择。
- 转交选项垂直排列为一组复选框，每项可独立勾选。
- 底部提供取消和确认转交操作。点击确认直接执行校验和保存，无审批或二次人工确认。

### 信息与字段

- 设备编号、当前保管人：只读，显示触发该弹窗的设备信息。
- 接收人：必填单选，一次选择一名当前场次的在岗人员。初始未选择。
- 携带说明：默认未勾选。勾选时连同设备使用说明交接。
- 通知接收人：默认勾选。勾选时在保存成功后向所选接收人发送一次站内通知。
- 保留交接备注：默认未勾选。勾选时一同保留当前记录中的交接备注。
- 三项允许任意多选，包括全不选。未勾选项的对应内容不随本次转交。

### 关键操作

- 点击「接收人」展开候选，选择一名接收人并回填当前表单。点击复选框独立调整对应选项。
- 点击「确认转交」执行本弹窗的提交校验。校验通过后，系统保存新保管人和三项各自的勾选状态，按通知选项处理站内通知，关闭弹窗并返回 E1 原行。
- 点击「取消」关闭弹窗并返回 E1 原行。失败或取消均不改变保管人、选项记录或通知结果。
- 资格变化后点击「刷新候选」，按本场次在岗资格更新候选，展开候选供重新选择，保留其他输入。选定接收人后仍须由用户点击「确认转交」重新校验。

### 校验与反馈

- 点击确认时，若未选接收人，拦截提交，使用 `transfer.receiver_required` 在接收人字段下提示。选择合格接收人后即可重新点击确认。
- 提交时先校验设备是否仍属于当前场次，再校验接收人是否仍为本场次在岗人员。任一条件不满足即拦截且不保存，使用 `transfer.scope_changed` 在弹窗内显示资格变化。
- 保存成功的即时反馈在 E1 的「状态与异常恢复」承载。

### 状态与异常恢复

- 默认显示表单，按「信息与字段」初始化复选框。
- 未选接收人导致拦截时，按对应条件结构显示字段错误，停留当前弹窗并允许直接选择。
- 提交时资格变化导致拦截时，保持弹窗打开并保留其他输入，按对应条件结构显示提示和刷新动作。刷新后可重新选择，或点击「取消」回到原行。重新提交时仍按同一顺序校验两项资格。

### 文案与变量

| key | 文案 | 适用位置／状态 | 变量及含义、取值 |
|---|---|---|---|
| transfer.title | 设备转交 | 弹窗标题 | 无 |
| transfer.device_group | 设备信息 | 只读信息区域 | 无 |
| transfer.device_id | 设备编号 | 只读字段标签 | 无 |
| shared.custodian | 见跨实体共用文案与变量 | 只读字段标签 | 无 |
| transfer.receiver | 接收人 | 单选字段标签 | 无 |
| transfer.receiver_required | 请选择接收人 | 字段未选时的占位文字，未选且提交时另在字段下显示必填错误 | 无 |
| transfer.options | 转交选项 | 复选框组标题 | 无 |
| transfer.include_instruction | 携带说明 | 复选框标签 | 无 |
| transfer.notify | 通知接收人 | 复选框标签 | 无 |
| transfer.retain_note | 保留交接备注 | 复选框标签 | 无 |
| transfer.cancel | 取消 | 弹窗底部按钮 | 无 |
| transfer.submit | 确认转交 | 弹窗底部按钮 | 无 |
| transfer.scope_changed | 设备或接收人状态已变化 | 提交遭资格校验拦截时的弹窗内提示 | 无 |
| transfer.refresh | 刷新候选 | 资格变化提示旁的恢复操作 | 无 |
| transfer.device_value | {设备编号} | 只读设备编号值 | 本次转交设备的编号 |
| transfer.receiver_value | {接收人姓名} | 候选标签与选中后的字段值 | 本场次在岗接收人的姓名 |

## 7. 不参与本次生成的待确认项

| 待确认项 | 影响 |
|---|---|
| 现有设备台账的其他区域、列表列及其排列未由基线提供 | 本轮规格覆盖已确认的菜单、设备行、转交入口及回流。合并到现网页面时，以实际工具页为准放置新增行操作，并保留现有其余结构。 |
