# 任务详情页与产物编辑 Spec

- 日期：2026-11-20
- 状态：待确认
- 范围：只改左侧；右侧任务动态、对话、下一步保持现状
- 依赖：任务 ID、`prd-review-record.md` / `prd-review.md` 双文件、现有任务会话绑定

## 1. 目标

任务正式启动后，左侧从 Skill 画布进入任务详情页：

- 标题是任务 ID；
- 标题旁提供任务操作；
- 当前任务的产物用分段控件切换，产物内容上下排列；
- 只有明确可编辑的产物才允许编辑；
- 底部提供一个简单输入框，把消息发送到原始任务会话。

## 2. 非目标

- 不改右侧任务面板的结构和逻辑；
- 不新增「进入会话」按钮；
- 不做产物版本历史；
- 不做多人协作；
- 不做按文档片段自动引用；
- 不做正式基线的直接编辑；
- 不做新的任务类型或 Skill 流程。

## 3. 入口与返回

### 自动进入

以下场景自动进入任务详情页：

- 点击「执行任务」并成功创建任务；
- 从沉淀列表打开已有任务；
- 刷新页面后存在 activeTaskId，且上次视图为详情页。

### 返回

- 详情页左上角提供「返回任务画布」；
- 返回后任务仍保持 active；
- 再次点击任务头或从沉淀打开任务，回到详情页；
- 当前选中的产物、编辑状态不跨返回保留；未保存编辑必须确认。

### 任务状态

- `active`：可编辑审核记录、可发送底部消息；
- `paused`：所有产物只读，底部输入禁用；
- `completed`：所有产物只读，底部输入禁用。

## 4. 左侧页面布局

```text
[← 返回任务画布]
T-20261120-01
权限需求分析
[暂停/继续] [结束] [重命名]

[需求审核记录] [正式需求基线] [页面规格] ...

┌ 产物内容 ─────────────────────────────┐
│ 预览 / 编辑                            │
│                                        │
│ Markdown 内容                          │
└────────────────────────────────────────┘

[ 输入消息，发送到当前任务会话…… ] [发送]
```

- 标题：任务 ID 为主标题，任务标题为副标题；
- 操作：暂停/继续、结束、重命名；
- 不出现「进入会话」；
- 右侧面板不移动、不重构，允许与左侧操作暂时重复。

## 5. 产物分段控件

### 展示

- 只展示当前任务真实存在的产物；
- 不展示空 Tab；
- 分段控件横向排列，超出时横向滚动，不换行；
- 选中项有明确状态；
- 无产物时显示空闲状态，不显示表单。

### 标签

- `prd-review-record`：需求审核记录；
- `prd-review`：正式需求基线；
- 其他产物：Skill 名称。

### 排序

固定顺序：

1. 需求审核记录（如果存在）；
2. 正式需求基线（如果存在）；
3. 其他产物按 Skill 图谱顺序，再按更新时间倒序。

### 状态

每个产物可以提供轻量状态：

- `waiting_response`
- `no_confirmation_required`
- `formal`
- `stale`
- `已手动编辑`

状态只做信息展示，不改变右侧逻辑。

## 6. 产物预览

- 默认展示预览，不直接进入编辑；
- 渲染 Markdown：标题、列表、表格、代码块；
- 禁止原始 HTML；
- 内容为空或文件不存在时显示错误状态；
- 展示产物名称、更新时间、来源（模型/用户）、状态；
- 只有 `editable=true` 才显示「编辑」。

## 7. 可编辑规则

### 第一版只允许

- `prd-review-record.md`；
- 任务状态为 `active`；
- 当前不存在正式需求基线 `prd-review.md`。

### 不允许

- 正式需求基线；
- 其他 Skill 产物；
- 已完成/已暂停任务；
- 已存在正式基线后的审核记录。

### 正式基线生成后

- 审核记录自动变为只读；
- 隐藏编辑按钮；
- 如果用户正在编辑，保存前重新检查；已失效时提示「审核记录已归档为历史」。

## 8. 编辑与保存

### 交互

- 点击「编辑」进入 Markdown 源码编辑；
- 提供「保存」「取消」；
- 保存成功后回到预览；
- 取消恢复原内容；
- 未保存时切换产物或返回画布，必须确认。

### 保存校验

Host 侧校验：

- 产物存在且属于当前任务；
- 任务 active；
- 产物当前 editable；
- `baseSha` 与当前文件一致，否则返回 409 冲突；
- 内容符合该产物的 Markdown 结构；
- 审核记录必须仍是 `PRD 审核记录`，状态为 `waiting_response` 或 `no_confirmation_required`；
- 写入使用原子替换。

### 保存结果

保存成功后更新：

- 文件内容；
- `sha256`；
- `updatedAt`；
- `origin: "user"`；
- `editedAt`；
- 审核记录状态重新解析。

页面重新加载该产物，显示「已手动编辑」。

### 人工编辑与模型覆盖

人工保存后，产物进入用户控制状态：

- `manualLock: true`；
- 模型后续 `submit_design_artifact` 写同一产物时，如果 `manualLock` 仍为 true，拒绝覆盖；
- 用户通过底部输入框发送下一条消息时，Host 解除该产物的 `manualLock`，把控制权交回模型；
- 解除后模型才可以正常提交新版本；
- 不实现版本历史，但人工内容在被模型覆盖前不会静默丢失。

## 9. 底部输入框

### 行为

- 只存在于任务详情页；
- 纯文本输入；
- 不绑定当前产物；
- 不拼接产物全文；
- 不选择 Skill；
- 不选择会话；
- 不创建新任务；
- 发送到当前任务绑定的原始会话。

### 状态

- 任务 `active` 时可输入、发送；
- `paused` / `completed` 时禁用，并显示原因；
- 输入为空时禁用；
- Enter 发送，Shift+Enter 换行；
- 发送中禁用，避免重复发送。

### 发送流程

1. 用户输入文本；
2. 客户端调用 Host 的 handoff/message 接口，解除当前可编辑产物的 manualLock（若有）；
3. 客户端将原始文本发送到任务会话；
4. 清空输入框；
5. 右侧对话/动态自然刷新；
6. 不改变任务状态、不创建新任务。

### 明确不做

- 不自动附带当前产物路径；
- 不自动引用选中文本；
- 不自动把消息转成结构化 PRD 回复；
- 不出现「进入会话」按钮。

## 10. Host 接口

### `GET ?workspace&task=`

在原有 `task`、`manifest`、`next` 之外增加：

```json
{
  "artifacts": [
    {
      "key": "prd-review-record",
      "skill": "prd-review",
      "label": "需求审核记录",
      "artifactKind": "review-record",
      "reviewStatus": "waiting_response",
      "editable": true,
      "manualLock": true,
      "origin": "user",
      "stale": false,
      "updatedAt": "..."
    }
  ]
}
```

- `editable` 由 Host 计算，前端不得自行推断；
- 只返回 manifest 中存在且文件可读的产物；
- `artifacts` 排序按本 Spec 第 5 节。

### `GET ?workspace&task=&artifact=`

读取指定产物内容：

- `artifact` 支持 `prd-review-record`、`prd-review`、其他 Skill 名；
- 兼容旧的 `skill=` 参数；
- 返回 `{ artifact, content }`。

### `POST {action:"update-artifact"}`

请求：

```json
{
  "workspaceId": "...",
  "taskId": "...",
  "artifactKey": "prd-review-record",
  "markdown": "...",
  "baseSha": "..."
}
```

校验：

- 任务 active；
- 产物存在；
- `editable` 为 true；
- `baseSha` 匹配；
- Markdown 结构合法；
- 路径在任务目录内。

成功：

- 原子写入；
- 更新 manifest；
- `origin: "user"`、`editedAt`、`manualLock: true`；
- 返回最新 `artifact` 和 `next`。

失败：

- 409：`baseSha` 冲突；
- 400：不可编辑、结构非法、任务非 active；
- 保留用户编辑内容，不覆盖。

### `POST {action:"message"}`

请求：

```json
{
  "workspaceId": "...",
  "taskId": "...",
  "artifactKey": "prd-review-record",
  "text": "..."
}
```

行为：

- 校验任务 active；
- 若传入 artifactKey 且该产物 `manualLock=true`，解除锁；
- 返回原始文本，由客户端发送到任务会话；
- 不修改任务状态、不创建任务、不注入产物上下文。

## 11. 状态与边界

- 任务切换：清空当前产物选择和编辑状态；
- 产物被模型更新：如果当前未编辑，刷新预览；如果正在编辑，提示冲突，不覆盖编辑框；
- 审核记录被手动保存后，右侧历史不会被修改；
- 正式基线出现后，审核记录只读；
- Host 重启后任务、产物、manualLock 均从 manifest 恢复；
- 页面刷新后恢复任务详情视图和最近选中的产物（如果仍存在）。

## 12. 验收标准

### 入口

- [ ] 执行任务成功后自动进入详情页；
- [ ] 详情页标题为任务 ID，副标题为任务标题；
- [ ] 从沉淀打开任务进入详情页；
- [ ] 返回画布后任务仍 active；
- [ ] 刷新后恢复详情页和当前产物（若仍存在）。

### 产物

- [ ] 分段控件只显示真实存在的产物；
- [ ] 默认选中最近使用的产物；不存在时选第一个；
- [ ] 产物内容在 Tab 下方上下排列；
- [ ] 无产物时显示空状态，不显示编辑按钮；
- [ ] 审核记录显示 `waiting_response` / `no_confirmation_required`；
- [ ] 正式基线出现后审核记录只读。

### 编辑

- [ ] 只有审核记录在 active 且无正式基线时显示「编辑」；
- [ ] 正式基线和其他产物没有编辑入口；
- [ ] 编辑保存后刷新仍保留内容；
- [ ] 非法审核记录被拒绝，编辑内容不丢失；
- [ ] `baseSha` 不一致返回冲突，不覆盖文件；
- [ ] 未保存切换 Tab/返回会提示；
- [ ] 手动保存后显示「已手动编辑」；
- [ ] 手动编辑后模型提交被拒绝，直到用户通过底部输入发送消息；
- [ ] 正式基线出现后，正在编辑的审核记录保存会被拒绝并转为只读。

### 底部输入

- [ ] active 任务可输入并发送纯文本；
- [ ] paused/completed 时禁用并显示原因；
- [ ] 消息发送到任务原始会话；
- [ ] 不创建新任务、不切会话、不注入产物上下文；
- [ ] 发送后右侧对话/动态更新；
- [ ] 左侧没有「进入会话」按钮。

### 右侧

- [ ] 右侧组件、布局、推荐逻辑保持不变；
- [ ] 左侧新增操作不导致右侧状态错乱；
- [ ] 左侧返回/切换不影响右侧当前任务。

## 13. 实施阶段

- P1：任务详情页骨架、返回、任务头、分段控件、产物只读预览；
- P2：Host 产物元数据、`update-artifact`、`baseSha`、manualLock；
- P3：审核记录编辑、保存/取消、未保存提示；
- P4：底部输入、handoff/message、active/paused/completed 状态；
- P5：验收、回归、打包。

## 14. 风险

- 产物预览使用 Markdown 渲染，必须防止原始 HTML 注入；
- 人工编辑与模型提交必须有锁，否则会静默覆盖；
- 审核记录只读条件必须由 Host 计算，不能只靠前端隐藏按钮；
- 任务页与右侧操作暂时重复，需避免两处状态不同步；
- 底部输入只发原始文本，模型可能缺少产物上下文；第一版接受该限制，后续再加引用。
