# AGENTS.md · only-plugin

适用于本工作树中的 AI 编程助手。安装和使用说明见 [README.md](README.md)。

## 判断与执行

- 开始前明确任务范围、关键歧义和可验证的完成条件。事实以本轮授权材料和可定位的正式来源为准，区分事实、推断和待确认事项。
- 先找最小可行改法，只修改与任务直接相关的内容，匹配现有风格。能用测试复现问题时先复现，完成后运行相关构建和测试，说明实际验证结果及限制。
- 涉及路径、编码、脚本或权限行为的改动，应考虑 Windows、macOS、Linux。只在实际验证过的环境上报告通过。

## 沟通

- 使用简体中文说明命令目的、文件改动、原因和影响范围。代码、路径、字段、日志和专有名词可保留原文。
- 回复先给结果和依据，写清尚未确认或无法验证的事项。

## Git 操作

- 先核对当前分支及其工作树，在本分支目录完成任务。提交只纳入当前任务范围内已核对的文件，检查暂存区，避免带入遗留改动。
- 用户要求「提交 GitHub」时，提交并推送当前分支。涉及危险的删除或回退操作时，先说明影响并获得确认。

## 插件维护边界

- 变更任务、产物或工作台界面时，核对 `index.js`、`runtime/` 与 `client.js` 的现有依赖关系，保留调用方依赖的行为。
- 在宿主任务执行中，使用本轮明确材料和任务上下文。正式产物通过 `submit_design_artifact` 按有效 `taskId` 登记，任务须为进行中。保留审核记录和正式基线的不同产物身份。禁止直接往 `spark-output/` 根目录写正式产物。
- 修改随包 Skill 时核对插件提供的任务上下文、产物路径和发布清单。不能把其他分支的产物路径直接套入插件。
- 只检查发布范围时使用打包预演。需要生成验收包且无需调整版本时使用 `--no-bump`。涉及宿主任务或保存行为的改动，应验证实际 Harness 路径并报告未覆盖的场景。
