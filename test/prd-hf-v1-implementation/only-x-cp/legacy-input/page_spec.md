# 页面生成规格：农产市集批次追踪

## 1. 页面摘要

- **产品领域**：市集管理 · 进货批次追踪
- **页面类型**：顶级只读列表工作台
- **用户角色**：市集质检员
- **核心任务**：按类别查看当前批次并核对流向。

## 2. 生成范围

### 生成

- E1 · 「批次追踪」顶级工作台。三类批次使用页内视图，读取反馈与重试保留在所属视图。

### 只引用不生成

无。

### 不生成

- 批次新增、验收人修改、退回处置、导出、转交和新增审批均在工作台范围之外。
- 批次数据读取属于后台处理。

## 3. 跨实体任务流程

### 核对进货批次流向

- 市集管理导航 —市集质检员点击「批次追踪」顶级入口→ E1 初始视图（在同一工作台查看、切换和核对批次）。

## 4. E1 · 批次追踪工作台

### 页面目标

让市集质检员查看当前三类批次的流向，并在同一工作台处理读取失败。

### 页面结构

初始布局：

```text
批次追踪 Page
├─ 批次追踪
├─ Tabs：在途批次（选中） | 已到场 | 退回批次
└─ 在途批次内容区
   └─ Table：批次号 | 来源农场 | 预计到场时间
```

选择「已到场」且读取成功：

```text
已到场内容区
└─ Table：批次号 | 验收人 | 到场时间
```

选择「退回批次」且读取成功：

```text
退回批次内容区
└─ Table：批次号 | 退回原因
```

「在途批次」读取成功、无数据：

```text
在途批次内容区
└─ EmptyState：暂无在途批次
```

所选 Tab 读取失败：

```text
当前 Tab 内容区
└─ InlineError：批次读取失败
   └─ Button：重试
```

### 区域说明

- 顶级入口属于现有「市集管理」。只有市集质检员可以打开工作台。
- 标题和 Tab 条保持在内容区上方。三个 Tab 从左到右为「在途批次」「已到场」「退回批次」。
- 首次打开时选中「在途批次」，与 Tab 条的浏览起点一致。
- 切换 Tab 只替换内容区，标题、Tab 条和当前工作台保持。

### 信息与字段

- 「在途批次」按列展示「批次号」「来源农场」「预计到场时间」。「预计到场时间」使用 24 小时制。
- 「已到场」按列展示「批次号」「验收人」「到场时间」。
- 「退回批次」按列展示「批次号」「退回原因」。

### 关键操作

- 点击任一 Tab，工作台保留，内容区切换为该 Tab 的表格或相应读取反馈。
- 当前 Tab 显示失败反馈时点击「重试」，系统仅重新加载该 Tab。
- 工作台只提供批次查看操作。查看时读取当前批次数据，业务记录无写入。

### 状态与异常恢复

- **无访问权限**。市集质检员可见工作台入口。对其他角色隐藏入口，直接访问时拒绝打开工作台和展示批次数据。
- **读取中**。LoadingState 显示在当前 Tab 内容区，Tab 条仍可操作。
- **读取成功**。当前 Tab 显示对应表格。核对完成后留在当前工作台。
- **在途空态**。只有「在途批次」成功读取且无数据时，该 Tab 显示 `in_transit_empty`。另外两个 Tab 仍可访问。
- **读取失败**。任一 Tab 加载失败时，仅对应内容区显示 `tab_load_error` 和 `tab_retry`。系统保持工作台和当前选中项。重试成功后展示属于该 Tab 的表格或适用的在途空态，重试仍失败时保留该 Tab 的失败状态和重试入口。
