# 页面生成规格：农产市集批次追踪

## 1. 页面摘要

- **产品领域**：市集管理 · 批次追踪
- **页面类型**：顶级只读列表工作台
- **用户角色**：市集质检员
- **核心任务**：按类别查看当前进货批次并核对流向。

来源为本轮指定的原始需求 [requirements.md](../requirements.md)。

## 2. 生成范围

### 生成

- E1 · 「批次追踪」工作台，包含三个页内 Tab 及其读取反馈。

### 只引用不生成

无。

### 不生成

- 批次新增、验收人修改、退回处置、导出、跨角色转交和审批均不属于本期工作台。
- 当前批次数据读取为后台处理。

## 3. 跨实体任务流程

### 核对进货批次流向

- 市集管理导航 —市集质检员点击「批次追踪」顶级入口→ E1（进入「在途批次」，查看或切换批次，完成核对后留在工作台）。

## 4. E1 · 批次追踪工作台

### 页面目标

市集质检员在同一工作台中查看三类批次，读取异常时就地恢复。

### 页面结构

```text
批次追踪 Page
├─ 标题：批次追踪
├─ Tabs：在途批次（初始） | 已到场 | 退回批次
└─ 当前 Tab 内容区
   └─ Table：批次号 | 来源农场 | 预计到场时间
```

「已到场」读取成功时：

```text
当前 Tab 内容区
└─ Table：批次号 | 验收人 | 到场时间
```

「退回批次」读取成功时：

```text
当前 Tab 内容区
└─ Table：批次号 | 退回原因
```

「在途批次」读取成功且无数据时：

```text
在途批次内容区
└─ EmptyState：暂无在途批次
```

任一个 Tab 读取失败时：

```text
当前 Tab 内容区
└─ InlineError：批次读取失败
   └─ Button：重试
```

### 区域说明

- 标题和 Tab 条在切换时保持不变。Tab 依次为「在途批次」「已到场」「退回批次」。
- 首次打开时选择顺序中的第一项「在途批次」。从左到右的查看顺序与初始位置一致。
- 仅在内容区呈现选中 Tab 的表格或当前反馈。

### 信息与字段

- 「在途批次」依次包含「批次号」「来源农场」「预计到场时间」。「预计到场时间」使用 24 小时制。
- 「已到场」依次包含「批次号」「验收人」「到场时间」。
- 「退回批次」依次包含「批次号」「退回原因」。

### 关键操作

- 点击任一 Tab，工作台选中该项并替换内容区，展示该项对应的列或反馈。
- 点击「重试」只重新读取发生失败的 Tab，工作台和选中项保持。
- 工作台只读，查看过程无业务记录写入。

### 状态与异常恢复

- **访问控制**。只有获得市集质检员权限的用户可看到入口并打开工作台。其他角色看不到入口，直接访问也无法打开工作台或查看批次。
- **读取中**。LoadingState 位于正在读取的 Tab 内容区，Tab 条保持可用。
- **读取成功**。展示当前 Tab 的表格，用户可继续切换或留在工作台完成核对。
- **在途空态**。当「在途批次」没有数据时，仅该 Tab 内容区显示 `transit_empty`，其他两个 Tab 仍可点击。
- **读取失败**。失败的 Tab 内容区显示 `read_error` 与 `retry`，用户留在同一工作台。点击重试只重新读取该 Tab。成功后显示对应表格或适用的在途空态，再次失败时显示该 Tab 的失败反馈。
