# 看起来像功能扩展，实际影响状态机

## 需求背景
用户希望新增一个状态标签，让审批进度看起来更清楚。

## 需求描述
新增“待补件”状态标签，但未明确这是不是一个真正的新状态，还是对现有状态的解释。

## 已知边界
表面像既有能力扩展。
实际可能改变状态机。

## 预期需求类型
不确定，需要补充判断

## 预期处理方式
先补关键确认，不应直接按中等需求落地。

## 预期重点维度
状态异常
业务规则

## 预期用户侧引导
现在还不能直接把它当成普通功能扩展，因为它可能改变状态含义或状态机。我建议先确认“待补件”是新的业务状态，还是现有状态的解释，再决定后续处理方式。这里最需要确认的是：它是否会影响审批流转和结果回写？

## 不应出现的判断
不应直接当成多一个展示标签。
不应跳过状态边界确认。
