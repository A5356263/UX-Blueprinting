# 页面生成规格：样品复检派单

## 1. 页面摘要

- **产品领域**：样品检验与复检派单
- **页面类型**：登记与跟踪页、待办列表页、弹窗
- **用户角色**：登记员、检验员
- **核心任务**：登记员提交并跟踪复检单，检验员认领复检单并提交检验结果。

---

## 2. 生成范围

### 生成

- E0 复检登记（Page），包含登记区和“我提交的复检”列表。
- E1 复检待办（Page），承载检验员的待办查看、认领和结果提交入口。
- E2 填写结果（Modal），承载本人认领的复检单的结果录入。

### 只引用不生成

无。

### 不生成

- 已完成复检单的结果修改界面，业务范围仅包括首次提交结果。
- 登记、认领与结果回写的系统处理，用户在登记、待办和结果弹窗接收其结果。

---

## 3. 跨实体任务流程

### 提交复检与跟踪结果

- 登记员顶级菜单 —点击“复检登记”→ E0（登记新复检或查看本人提交记录）。
- E0 —登记成功后系统交接记录→ E1 待认领行（检验员在待办页认领，登记员留在 E0）。

### 认领与提交结果

- 检验员顶级菜单 —点击“复检待办”→ E1（查看其可见的待办）。
- E1 —点击本人认领行的“填写结果”→ E2（带入该复检单的样品编号）。
- E2 —点击“取消”→ E1（返回原待办列表，丢弃弹窗中未提交的内容）。
- E2 —点击“提交结果”且成功→ E1（关闭弹窗，已完成行移出待办）及 E0（同一复检单原行显示更新的状态和结果摘要）。

---

## 4. 复检登记（E0）

### 页面目标

登记员从“复检登记”菜单进入，在本页提交新复检并查看本人提交的复检单。登记员无认领或完成复检的权限，页面不提供这些操作。

### 页面结构

```text
+-----------------------------------------------------------------------+
| 复检登记                                                              |
|-----------------------------------------------------------------------|
| 样品编号 [Input: {样品编号}]                                          |
| 复检原因 [Textarea: {复检原因}]                                       |
| [提交复检]                                                            |
|-----------------------------------------------------------------------|
| 我提交的复检                                                          |
| 复检单号         样品编号         状态            结果摘要            |
| {复检单号}       {样品编号}       {状态}          {结果摘要}          |
+-----------------------------------------------------------------------+
```

### 条件结构（提交复检时有必填项为空）

在缺失字段下追加对应的反馈。两行提示各按其字段条件出现。

```text
| 样品编号 [Input: {样品编号}]                                          |
| {InlineError: registration.sample_required}                           |
| 复检原因 [Textarea: {复检原因}]                                       |
| {InlineError: registration.reason_required}                           |
```

### 区域说明

- 登记区依次放置样品编号 Input、复检原因 Textarea 和提交 Button。两字段标记为必填。
- “我提交的复检”区域使用 Table，只显示当前登记员本人提交的记录。

### 信息与字段

- 登记区“样品编号”为必填样品标识，“复检原因”为必填文本。
- 列表“复检单号”为复检单标识，“样品编号”为此单关联样品的标识。“状态”为同一复检单的业务状态，“结果摘要”为已提交结果的摘要文本。

### 关键操作

- 点击“提交复检”校验必填信息。成功时清空登记区，在“我提交的复检”列表中新增一行并展示 Toast `registration.submitted`。

### 校验与反馈

- 点击“提交复检”时，样品编号为空则在该字段下显示 `registration.sample_required`，复检原因为空则在该字段下显示 `registration.reason_required`。有缺失时保留当前输入并阻止提交，可补填后再次提交。

### 状态与异常恢复

- 复检登记成功时，新行显示“待认领”。检验员认领该单后，状态显示“检验中”。结果提交成功后，原行显示“已完成”和回写的结果摘要。
- 结果提交前，该单“结果摘要”列显示 `registration.no_result`。提交后该列读取同一复检单的实际结果摘要。

### 文案与变量

| key | 文案 | 适用位置／状态 | 变量及含义、取值 |
| --- | --- | --- | --- |
| `registration.title` | 复检登记 | 顶级菜单、页标题 | 无 |
| `registration.submit` | 提交复检 | 登记区 Button | 无 |
| `registration.mine` | 我提交的复检 | 列表区标题 | 无 |
| `registration.submitted` | 复检已提交 | 登记成功后的 Toast | 无 |
| `registration.no_result` | — | 尚无已提交结果时的结果摘要列 | 无 |
| `registration.sample_required` | 请输入样品编号 | 提交时样品编号为空，字段下 InlineError | 无 |
| `registration.reason_required` | 请输入复检原因 | 提交时复检原因为空，字段下 InlineError | 无 |
| `registration.completed` | 已完成 | 已提交结果的复检单状态列 | 无 |

登记字段及列表列名使用 `common.sample_id`、`common.reason`、`common.order_id`、`common.status`、`common.result`。列表的另外两个状态使用 `common.pending`、`common.in_progress`。

## 5. 复检待办（E1）

### 页面目标

检验员从同名顶级菜单进入，认领可见的待认领复检单，并对本人认领的复检单提交结果。

### 页面结构

```text
+---------------------------------------------------------------------------------------+
| 复检待办                                                                              |
|---------------------------------------------------------------------------------------|
| 复检单号       样品编号      复检原因         状态          操作                       |
| {复检单号}     {样品编号}    {复检原因}       待认领        [认领]                     |
+---------------------------------------------------------------------------------------+
```

### 条件结构（本人认领的复检单）

本人认领且尚未提交结果时，本行显示“检验中”和“填写结果”。

```text
| {复检单号}     {样品编号}    {复检原因}       检验中        [填写结果]                 |
```

### 条件结构（无可见待办）

替换表头下方的列表内容区。

```text
| 暂无复检任务                                                                          |
```

### 区域说明

- 页面标题为“复检待办”。待办 Table 同时承载待认领单和本人已认领单，每行的操作与状态对应。

### 信息与字段

- “复检单号”显示复检单标识，“样品编号”显示该单关联样品的标识，“复检原因”显示登记员提交的原因。
- “状态”显示“待认领”或“检验中”。“操作”承载与当前行对应的入口。

### 关键操作

- “认领”仅在待认领行显示。点击后认领成功时，原行状态更新为“检验中”，操作替换为“填写结果”。
- “填写结果”仅在当前检验员本人认领的行显示，以该复检单为结果录入对象。

### 状态与异常恢复

- 他人已认领的复检单及已完成的复检单不在待办列表展示。当前检验员无可见待办时，列表内容区显示 EmptyState `worklist.empty`。
- 点击认领时若该单已被他人认领，在本页显示 Toast `worklist.claim_conflict`，刷新列表并移除该行，留在待办页。不打开结果弹窗。刷新后若无可见待办，进入列表空态。
- 本人成功提交结果后，已完成行从待办移出。页面留在待办列表，仍可继续处理其他可见任务。

### 文案与变量

| key | 文案 | 适用位置／状态 | 变量及含义、取值 |
| --- | --- | --- | --- |
| `worklist.title` | 复检待办 | 顶级菜单、页标题 | 无 |
| `worklist.actions` | 操作 | 待办表头 | 无 |
| `worklist.claim` | 认领 | 待认领行 Button | 无 |
| `worklist.empty` | 暂无复检任务 | 当前检验员无可见待办 | 无 |
| `worklist.claim_conflict` | 该复检单已被其他人认领 | 认领冲突时，待办页 Toast | 无 |

表头使用 `common.order_id`、`common.sample_id`、`common.reason`、`common.status`，状态列使用 `common.pending`、`common.in_progress`，本人认领行的操作使用 `common.fill_result`。

## 6. 填写结果（E2）

### 弹窗目标

检验员为本人认领的复检单填写并提交结果，或取消此次录入。

### 区域结构

```text
+--------------------------------------------------+
| 填写结果                                         |
|--------------------------------------------------|
| 样品编号  {样品编号}                             |
| 结果摘要  [Textarea: {结果摘要}]                 |
|--------------------------------------------------|
|                           [取消] [提交结果]      |
+--------------------------------------------------+
```

### 条件结构（提交结果时结果摘要为空）

在结果摘要字段下追加提示。

```text
| 结果摘要  [Textarea: {结果摘要}]                 |
| {InlineError: result.summary_required}           |
```

### 区域说明

- Modal 从 E1 待办行打开。弹窗标题为“填写结果”，内容区上方显示只读样品编号，下方为标记必填的结果摘要 Textarea。底部放置“取消”和“提交结果”。

### 信息与字段

- “样品编号”为当前复检单所关联的样品标识，不可编辑。
- “结果摘要”为必填多行文本，保存到触发该弹窗的同一张复检单。

### 关键操作

- “提交结果”触发必填校验。提交成功后，该复检单状态为“已完成”，结果摘要写回该单，供登记员的原记录行读取。
- “取消”关闭弹窗并放弃本次未提交内容。

### 校验与反馈

- 点击“提交结果”时结果摘要为空，显示 `result.summary_required`，阻止提交且保持弹窗打开，用户可补填后重新提交。

### 文案与变量

| key | 文案 | 适用位置／状态 | 变量及含义、取值 |
| --- | --- | --- | --- |
| `result.cancel` | 取消 | 弹窗底部 Button | 无 |
| `result.submit` | 提交结果 | 弹窗底部 Button | 无 |
| `result.summary_required` | 请输入结果摘要 | 提交时结果摘要为空，字段下 InlineError | 无 |

标题使用 `common.fill_result`，两个字段标签使用 `common.sample_id`、`common.result`。

---

## 7. 跨实体共用文案与变量

| key | 文案 | 适用位置／状态 | 变量及含义、取值 |
| --- | --- | --- | --- |

| `common.reason` | 复检原因 | E0 登记字段、E1 表头 | 无 |
| `common.status` | 状态 | E0、E1 表头 | 无 |
| `common.result` | 结果摘要 | E0 表头、E2 编辑字段 | 无 |
| `common.pending` | 待认领 | E0、E1 状态列，登记成功且尚未认领 | 无 |
| `common.in_progress` | 检验中 | E0、E1 状态列，已认领且未完成 | 无 |
| `common.fill_result` | 填写结果 | E1 本人认领行的 Button、E2 弹窗标题 | 无 |
