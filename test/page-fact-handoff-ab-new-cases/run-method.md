# 页面事实交接 A/B 测试方法

本次只使用新编的四个业务用例。温室监测、展馆设备绑定和样品复检覆盖不同类型的事实，社团预约用冻结的候选规则另开上下文运行。样本采用正式基线格式，业务为测试虚构；没有用实际 PRD、产品审核记录或业务结论冒充验证证据。

- A 使用原 Page Spec Skill 和基线的页面事实交接。交接文件按现行规则从该案例基线编制，用来评估 Page Spec 消费端的现行路径；本轮没有另外计量上游 PRD Review 实际生成交接的耗时。
- B 使用同版 Page Spec Skill、同一份基线和独立运行上下文；仅以候选规则替换页面事实交接部分。后置的体验约束消费与写盘完整性检查继续适用。
- A、B 对应案例的两个基线副本已逐份对照 SHA-256，均相同。B 的案例目录不存在外部交接文件。
- 正式 Page Spec 合同应用到隔离目录。测试未调用仓库级进度预览，未写入工作区的正式业务产物。
- 按独立的评分清单查看 Page Spec 正文证据，比较完整、遗漏、不一致。复合项要求全部条件成立。该检查覆盖有意选取的关键细节，不能代替所有交付合同或对任意未来业务的验证。
- 成本只报告实际保存的独立交接体量及能取得的运行计量。文件字节和运行时 token 是不同指标。
