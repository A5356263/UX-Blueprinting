# 页面生成规格：样品复检派单

## 1. 页面摘要

- **产品领域**：样品检验 — 复检派单与结果追踪
- **页面类型**：登记页、待办列表页、结果填写弹窗
- **用户角色**：登记员、检验员
- **核心任务**：登记员提交复检并追踪状态，检验员认领复检单并提交结果。

---

## 2. 生成范围

### 生成

- E0A 复检登记（Page）。登记员从同名顶级菜单进入，提交复检并查看自己提交的记录。
- E0B 复检待办（Page）。检验员从同名顶级菜单进入，查看可见复检单并处理。其中本人认领的行提供 E1 入口。
- E1 填写结果（Modal）。在 E0B 上打开，提交或取消后关闭。

### 只引用不生成

- 无。

### 不生成

- 已完成复检单的结果修改，本期明确排除。
- 创建单据、认领冲突检查、同单回写，为系统处理。

---

## 3. 跨实体任务流程

### 登记并追踪复检

- 登记员 —点击顶级菜单“复检登记”→ E0A。
- E0A —点击“提交复检”且提交成功→ E0A 显示新单据，进入 E0B 的待认领范围；登记员停留 E0A。

### 认领并提交结果

- 检验员 —点击顶级菜单“复检待办”→ E0B。
- E0B —点击当前行“填写结果”／本人已认领→ E1。
- E1 —点击“取消”→ 关闭 E1 并丢弃本次输入，回 E0B 该行仍可填写；提交校验未通过→ 停留 E1。
- E1 —点击“提交结果”且成功→ 关闭 E1，回 E0B 且该行移出待办；E0A 同一复检单显示“已完成”和本次结果摘要。

---

## 4. 复检登记（E0A）

### 页面目标

登记员发起复检，并在“我提交的复检”查看本人提交单据的当前状态和结果。

### 页面结构

```text
+---------------------------------------------------------+
| 复检登记                                                |
+---------------------------------------------------------+
| 登记区                                                  |
| 样品编号 [Input]                                        |
| 复检原因 [Textarea]                                     |
| [提交复检]                                              |
+---------------------------------------------------------+
| 我提交的复检                                            |
| Table 复检单号 | 样品编号 | 状态 | 结果摘要             |
+---------------------------------------------------------+
```

### 条件结构（登记必填字段未填写）

```text
登记区
├─ 样品编号 [Input]
│  └─ InlineError reg.sampleRequired（该项缺失时）
├─ 复检原因 [Textarea]
│  └─ InlineError reg.reasonRequired（该项缺失时）
└─ [提交复检]
```

### 区域说明

- “复检登记”为登记员的顶级菜单入口。页面上方为登记区，两个字段在提交按钮上方。
- 登记区下方是独立的“我提交的复检”列表。列表仅显示本人提交的单据，提供查看，不提供认领、填写结果或完成操作。

### 信息与字段

- 登记区的“样品编号”为必填文本输入，“复检原因”为必填多行文本输入。
- “我提交的复检”列表中的复检单号、样品编号、状态、结果摘要均来自对应复检单。状态为“待认领”“检验中”或“已完成”。结果未提交时，结果摘要展示 `reg.noResult`，成功提交后展示该单保存的摘要。

### 关键操作

- 输入样品编号、复检原因后点击“提交复检”。提交成功后清空登记区，在“我提交的复检”新增一行并显示 Toast `reg.submitted`。新单可由检验员在“复检待办”认领。
- 查看本人提交列表的状态和摘要。检验员认领后可看到同一单据状态更新，提交结果后可在同一行看到结果。

### 校验与反馈

- 点击“提交复检”时检查两个必填字段。任一缺失时不提交，按“条件结构（登记必填字段未填写）”就地显示对应 `reg.sampleRequired` 或 `reg.reasonRequired`，保留已填项。补齐后再次点击“提交复检”。

### 状态与异常恢复

- 待认领。登记成功生成单据后在新行展示 `common.unclaimed`，登记员可追踪。
- 检验中。检验员认领该单后原行展示 `common.inProgress`，登记员继续查看该单。
- 已完成。检验员成功提交结果后原行展示 `reg.completed` 和该单的结果摘要，登记员可查看结果，已完成结果无修改入口。

### 文案与变量

| key | 文案 | 适用位置／状态 | 变量及含义、取值 |
| --- | --- | --- | --- |
| reg.title | 复检登记 | 顶级菜单、页面标题 | 无 |
| reg.form | 登记区 | 页面内登记表单标题 | 无 |
| reg.submit | 提交复检 | 登记区提交按钮 | 无 |
| reg.mine | 我提交的复检 | 本人复检列表标题 | 无 |
| reg.noResult | — | 未提交结果的摘要单元格 | 无 |
| reg.submitted | 复检已提交 | 登记成功 Toast | 无 |
| reg.completed | 已完成 | 结果已提交的单据状态单元格 | 无 |
| reg.sampleRequired | 请输入样品编号 | 提交时样品编号缺失 | 无 |
| reg.reasonRequired | 请输入复检原因 | 提交时复检原因缺失 | 无 |

共用文案 `common.sample` 用于样品编号表单标签和列头，`common.reason` 用于复检原因表单标签，`common.order`、`common.status`、`common.summary` 用于列表列头，`common.unclaimed`、`common.inProgress` 用于状态值。

## 5. 复检待办（E0B）

### 页面目标

检验员查看待认领的复检单和本人认领的复检单，认领任务或为本人任务填写结果。

### 页面结构

```text
+-----------------------------------------------------------------------+
| 复检待办                                                              |
+-----------------------------------------------------------------------+
| Table 复检单号 | 样品编号 | 复检原因 | 状态   | 操作                    |
|       {复检单号} | {样品编号} | {复检原因} | 待认领 | [认领]            |
+-----------------------------------------------------------------------+
```

### 条件结构（本人认领的行）

```text
Table > 本人认领的复检单行
{复检单号} | {样品编号} | {复检原因} | 检验中 | [填写结果]
```

### 条件结构（无可见待办）

```text
待办列表内
└─ EmptyState 暂无复检任务
```

### 区域说明

- “复检待办”为检验员的顶级菜单入口。登记员无此任务的认领或完成入口。页面的待办 Table 只显示待认领和本人已认领的未完成单据。其他检验员已认领的单据和所有已完成的单据不显示。
- 操作列的可见操作随当前行状态变化。待认领行提供“认领”，本人认领行提供“填写结果”。

### 信息与字段

- 表格依次列出复检单号、样品编号、复检原因、状态、操作。复检原因取登记员在该单填写的原因。状态为“待认领”或“检验中”。
- 认领动作绑定当前复检单；打开 E1 时以当前行的复检单与样品编号为上下文。

### 关键操作

- 点击待认领行的“认领”。认领成功后，原行状态变为“检验中”，操作更新为“填写结果”，仍停在 E0B。若发生认领冲突，按本页“状态与异常恢复”处理。
- 点击本人认领行的“填写结果”，在 E0B 上打开 E1。E1 取消后继续操作原行；E1 成功提交后该行从待办移出。

### 状态与异常恢复

- 待认领。登记成功创建的单据在可见待办中用 `common.unclaimed` 表示，检验员可点击“认领”。
- 本人认领。认领成功后按“条件结构（本人认领的行）”在原行展示 `common.inProgress` 和“填写结果”，可继续处理该单。
- 认领冲突。点击“认领”时该单已被他人认领，显示 Toast `inbox.claimConflict`，刷新待办并移除该行，保持在 E0B，不打开 E1。检验员可处理剩余待办。
- 无待办。当前用户没有任何可见待办时，在列表内按“条件结构（无可见待办）”展示 `inbox.empty`。认领冲突或提交结果移除最后一行时同样进入该状态，留在 E0B。

### 文案与变量

| key | 文案 | 适用位置／状态 | 变量及含义、取值 |
| --- | --- | --- | --- |
| inbox.title | 复检待办 | 顶级菜单、页面标题 | 无 |
| inbox.action | 操作 | 待办列表列头 | 无 |
| inbox.claim | 认领 | 待认领行按钮 | 无 |
| inbox.empty | 暂无复检任务 | 列表内无可见待办 | 无 |
| inbox.claimConflict | 该复检单已被其他人认领 | 认领冲突 Toast | 无 |

共用文案 `common.order`、`common.sample`、`common.reason`、`common.status` 用于待办列头，`common.unclaimed`、`common.inProgress` 用于状态值，`common.enterResult` 用于本人认领行按钮。

## 6. 填写结果（E1）

### 弹窗目标

检验员为本人认领的复检单填写并提交结果摘要。

### 区域结构

```text
+------------------------------------------+
| 填写结果                                 |
+------------------------------------------+
| 样品编号 {样品编号}                      |
| 结果摘要 [Textarea]                     |
+------------------------------------------+
|                       [取消] [提交结果] |
+------------------------------------------+
```

### 条件结构（结果摘要未填写）

```text
填写区
├─ 样品编号 {样品编号}
├─ 结果摘要 [Textarea]
│  └─ InlineError result.required
└─ 底部 [取消] [提交结果]
```

### 区域说明

- 弹窗覆盖在 E0B 之上。标题下为填写区，先显示只读样品编号，再显示结果摘要输入。底部为“取消”和“提交结果”。

### 信息与字段

- “样品编号”来自触发所在的复检单，只读。
- “结果摘要”为必填多行文本，只回写该复检单。

### 关键操作

- 输入结果摘要后点击“提交结果”。校验通过且提交成功时关闭 E1，当前单据进入“已完成”。E0B 移出该行，E0A 对应记录可见结果摘要。
- 点击“取消”关闭 E1，放弃本次未提交内容，回 E0B 原行。再次点击该行“填写结果”可重新录入。

### 校验与反馈

- 点击“提交结果”时检查结果摘要。未填写则阻止提交，按“条件结构（结果摘要未填写）”在输入区显示 `result.required`，保留弹窗和当前复检单上下文。用户可补录并再次提交，或取消。

### 文案与变量

| key | 文案 | 适用位置／状态 | 变量及含义、取值 |
| --- | --- | --- | --- |
| result.submit | 提交结果 | 弹窗底部提交按钮 | 无 |
| result.cancel | 取消 | 弹窗底部取消按钮 | 无 |
| result.required | 请输入结果摘要 | 提交时结果摘要缺失 | 无 |

共用文案 `common.enterResult` 用于弹窗标题，`common.sample`、`common.summary` 用于字段标签。
