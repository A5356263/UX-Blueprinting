# 轻量业务蓝图

## 0. 路线说明

- 需求类型：局部布局交互优化。
- 执行路线：standard。
- 本次采用轻量业务蓝图的原因：route 判断存在展示宽度和边界处理压力，但不涉及完整业务能力重构。
- 如需升级，升级条件：发现组织可见范围、权限模型、审批模式或业务对象关系变化。

## 1. 一句话结论

需求成立，建议作为组织架构页面的局部展示能力优化处理，边界限定在本浏览器内宽度记忆和组织树可读性。

## 2. 关键业务规则

- 不新增组织、成员、角色或权限能力。
- 不改变用户可见组织数据范围。
- 宽度记忆只影响当前浏览器展示，不跨设备同步。

## 3. 边界与风险

- 权限边界：不改变权限。
- 数据边界：不改变组织数据范围。
- 状态边界：不新增业务状态，只保存展示偏好。
- 异常风险：本地记忆失败不能阻断组织架构页面使用。

## 4. 体验承接要求

- 角色：组织架构页面使用者。
- 流程：进入页面、拖动分隔线、释放后保存宽度、刷新后恢复。
- 状态：可拖动、拖动中、达到最小宽度、达到最大宽度、恢复默认宽度。
- 异常：本地记忆失败、窗口缩小、长名称仍被截断。
- 反馈：拖动时实时反馈宽度变化，达到边界时停止变化。
- 文案：提供恢复默认宽度或说明当前达到边界的轻提示。

## 5. 升级信号

- 如果宽度配置需要团队共享、跨设备同步或影响组织可见范围，应升级 full。

## 6. 待确认问题

- 无阻断问题。
