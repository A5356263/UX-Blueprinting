Experience Blueprint｜模拟优化版
1. 交互流程总览

本次体验围绕两类用户展开：

管理员 / 超管：开启并配置“自助申请权限模式”，决定员工能申请什么、由谁审批。
员工：在个人中心查看自己的权限，并在需要时提交权限申请。
审批人：收到审批待办后，同意或拒绝员工的申请。

主流程分为两条：

管理员配置流程：
进入权限管理模式 → 点击立即启用 → 配置申请方式 → 配置可申请范围 → 配置审批流程 → 开启成功

员工申请流程：
进入个人中心 → 我的权限 → 申请权限 → 填写申请内容 → 提交申请 → 等待审批 → 查看结果

异常流程重点关注：

互斥模式已开启，不能启用自助申请权限模式
员工申请了不可申请的角色 / 功能权限
关闭模式时仍有申请流程未完成
审批拒绝、审批中、撤销申请等状态反馈
2. 主交互流程
流程 A：管理员开启自助申请权限模式
节点 A1：进入权限管理模式页

用户动作：
管理员进入权限管理模式设置页，查看是否可以开启“自助申请权限模式”。

系统反馈：
页面展示该模式的作用：员工可以自助查询和申请权限，审批通过后系统自动分配权限。

本节点需要前置解释：

开启后，员工会看到“我的权限”和“申请权限”入口。
权限申请通过后，系统会自动分配权限。
该模式不能和“双管理员互审模式”“权限变更审批模式”同时开启。

建议页面文案：

员工可自助申请权限，审批通过后系统将自动分配权限。

下一步：
管理员点击“立即启用”。

节点 A2：点击“立即启用”

用户动作：
管理员点击“立即启用”。

系统反馈：
系统先校验是否已开启互斥模式。

正常结果：
未开启互斥模式时，进入“自助申请权限模式设置页”。

异常结果：
如果企业已开启“双管理员互审模式”或“权限变更审批模式”，阻断启用。

异常提示文案：

企业已开启「双管理员互审模式」，不能同时开启此模式。
节点 A3：选择员工申请权限的方式

用户动作：
管理员选择员工后续可以申请什么类型的权限。

页面提供两个选项：

申请角色
申请功能权限

本节点需要前置解释：

选择“申请角色”后，员工申请通过会自动关联角色。
选择“申请功能权限”后，员工申请通过会自动获得对应功能权限。
这里决定后续员工申请页面展示哪类申请内容。

页面文案：

请选择员工可以申请的权限类型。

选项说明：

申请角色：申请通过后，员工将自动关联上申请角色。适合企业主要通过角色授权的场景。

申请功能权限：申请通过后，员工将自动获得对应功能权限。适合企业主要按应用和功能直接授权的场景。
节点 A4：配置可申请范围

用户动作：
管理员配置员工可以申请的角色范围或应用范围。

如果选择“申请角色”：
进入“设置角色范围”。

需要展示：

全部角色
部分角色
后续新增角色是否自动加入可申请范围

如果选择“申请功能权限”：
进入“设置应用范围”。

需要展示：

全部应用
部分应用
后续新增应用是否自动加入可申请范围

本节点需要前置解释：

员工只能申请这里配置过的角色或应用。
敏感角色、敏感组织不应进入可申请范围。
“部分角色 / 部分应用”需要提供选择弹窗，并支持搜索、分页、状态展示。

页面文案：

请选择允许员工自助申请的范围。未包含在范围内的角色或应用，员工无法提交申请。
节点 A5：配置审批流程

用户动作：
管理员查看或修改员工申请权限时的审批流程。

系统反馈：
系统默认预设审批人为员工所在组织的组织负责人。

本节点需要前置解释：

员工提交申请后，会进入审批流程。
审批通过后，系统才会分配权限。
如需调整审批人，可以点击“修改审批流程”。

页面文案：

系统已预设「员工申请权限」时的审批流程，默认审批人为员工所在组织的组织负责人。如需调整，可点击修改审批流程。

主要操作：

修改审批流程
节点 A6：点击“开启”

用户动作：
管理员完成配置后，点击“开启”。

系统反馈：
系统再次校验互斥模式。

成功结果：

toast 提示开启成功
页面刷新为“已开启”状态
个人中心增加“我的权限”入口
员工可以开始提交权限申请

成功文案：

自助申请权限模式已开启。

已开启状态说明：

此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。
流程 B：员工申请权限
节点 B1：进入个人中心

用户动作：
员工进入个人中心。

系统反馈：
如果企业已开启自助申请权限模式，个人中心展示“我的权限”。

展示规则：

已开启模式：展示“我的权限”
未开启模式：不展示
服务人员：不展示
节点 B2：进入“我的权限”

用户动作：
员工点击“我的权限”。

系统反馈：
进入“我的权限”页面，页面包含三个 tab：

功能权限
数据权限
角色

页面需要让员工知道：

自己当前拥有哪些功能权限
自己拥有哪些数据权限
自己关联了哪些角色
如果没有权限，需要看到空状态说明

空状态文案：

您没有功能权限。
您没有数据权限。
您没有关联的角色。
节点 B3：点击“申请权限”

用户动作：
员工点击“申请权限”。

系统反馈：
打开“申请权限”抽屉。

抽屉需要展示：

申请人：默认当前用户，不可编辑
申请原因：必填，最多 500 字
申请功能权限
申请角色
提交按钮
节点 B4：填写申请内容

用户动作：
员工选择要申请的功能权限或角色，并填写申请原因。

本节点需要前置解释：

员工只能选择管理员配置范围内的应用、功能或角色。
申请功能权限时，默认申请该功能的所有数据权限。
如果只需要部分数据权限，需要联系管理员单独授权。

申请功能权限提示文案：

提交申请后，默认申请功能的所有数据权限。如需申请部分数据权限，请联系企业管理员授权。

申请原因提示文案：

请填写申请原因。
节点 B5：提交申请

用户动作：
员工点击“提交”。

系统反馈：
系统发起审批流程。

成功反馈：

申请已提交，请等待审批。

下一步：
员工可以回到申请记录查看审批状态。

节点 B6：查看申请记录

用户动作：
员工进入申请记录。

系统反馈：
列表展示每条申请的状态。

申请记录字段：

申请时间
申请原因
申请内容
审批状态
操作

审批状态包括：

审批中
已通过
已拒绝
已撤销

操作规则：

审批中：可以撤销
已通过 / 已拒绝 / 已撤销：不可撤销

4. 异常与阻断流程
异常 1：互斥模式已开启，不能启用

发生时机：
管理员点击“立即启用”或“开启”时。

触发条件：
企业已开启“双管理员互审模式”或“权限变更审批模式”。

系统反馈：

企业已开启「双管理员互审模式」，不能同时开启此模式。

用户下一步：
管理员需要先关闭互斥模式，再重新开启自助申请权限模式。

异常 2：关闭模式时仍有在途审批

发生时机：
管理员点击“关闭模式”并确认关闭。

触发条件：
当前还有申请流程未完成审批。

弹窗文案：

标题：关闭失败

正文：当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。

按钮：知道了

用户下一步：
等待审批人处理完在途流程后，再次关闭模式。

异常 3：员工申请了不可授予的权限

发生时机：
员工提交权限申请后，系统校验申请内容。

可能原因：

为非资金用户申请“代发付款”
子管理员申请子管理员模式权限
申请内容涉及实名要求
申请内容涉及特殊身份默认权限

页面反馈策略：

不要只提示“提交失败”
要说明失败原因
要告诉员工是否可以修改后重新提交
对无法自行处理的问题，要提示联系管理员

建议文案：

当前申请内容不满足授权条件，请调整申请内容后重新提交。

6. 状态与反馈文案
状态：未开启

含义：
企业还没有开启自助申请权限模式。

用户可做：
管理员可以点击“立即启用”。

页面反馈：

员工暂时无法自助查询和申请权限。
状态：设置中

含义：
管理员已进入设置页，但还没有真正开启模式。

用户可做：
继续配置申请方式、申请范围和审批流程。

页面反馈：

完成设置并点击“开启”后，员工才能自助申请权限。
状态：已开启

含义：
自助申请权限模式已生效。

用户可做：
管理员可以编辑配置或关闭模式；员工可以在个人中心查看和申请权限。

页面反馈：

此模式已开启，员工可以自助查询和申请个人权限。申请通过后，系统自动分配权限。
状态：审批中

含义：
员工已提交申请，审批人还未处理。

用户可做：
员工可以查看申请记录；如允许，可以撤销申请。

页面反馈：

申请已提交，请等待审批。
状态：已通过

含义：
审批人已同意申请，系统已分配权限。

页面反馈：

申请已通过，权限已生效。
状态：已拒绝

含义：
审批人拒绝了申请。

页面反馈：

申请已拒绝。你可以查看拒绝原因后重新提交申请。
状态：关闭失败

含义：
管理员关闭模式时，还有申请流程未完成审批。

页面反馈：

当前有申请流程未完成审批，请联系审批人审批完成，再关闭模式。
