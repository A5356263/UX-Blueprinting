# 正式需求基线

- 项目：农产市集批次追踪
- 基线状态：`formal`
- 原始 PRD：[requirements.md](../requirements.md)
- 辅助输入：[prototype-reference.md](../prototype-reference.md)，用途为形态参考。

## §1 背景与目标

### 为什么现在做

市集质检员每天要核对进货批次的流向。现有「市集管理」承载本期新增的批次追踪工作台入口。来源为 PRD「范围与角色」。

### 本期目标

让质检员在同一工作台查看进货批次流向。来源为 PRD「范围与角色」「验收」。

### 本期范围

本期包含：

- 通过只读工作台查看三类批次。来源为 PRD「范围与角色」「已确认的页面事实」。

本期不包含（非目标）：

- 批次维护、退回处置或导出。详见 §9。

## §2 功能与变更清单

### 新增

#### 批次追踪

- 本期变化：新增「批次追踪」顶级工作台入口。
- 对象关系：「批次追踪」属于现有「市集管理」，展示当前进货批次数据。
- 来源：PRD「范围与角色」「范围排除」。

## §3 谁能做什么

### 市集质检员

- 责任：核对进货批次流向。
- 权限前提：仅质检员可打开并查看「批次追踪」工作台。
- 可执行动作：查看当前批次数据。
- 权限边界：工作台只读。
- 来源：PRD「范围与角色」「范围排除」。

## §4 每件事怎么完成

### FN-001 · 市集质检员 · 核对进货批次流向

#### 什么时候开始

- 需求发生事件：质检员进行每日进货批次流向核对。
- 业务触发条件：需要查看当前进货批次的流向。
- 前置条件：符合 §3 的工作台查看权限。

#### 从哪里进入

- 本期支持的进入渠道：从现有「市集管理」进入本期新增的「批次追踪」顶级工作台。
- 现有任务位置：「市集管理」。

#### 怎么完成

1. 打开「批次追踪」工作台。
2. 工作台内的三个 Tab 依次为「在途批次」「已到场」「退回批次」。三个 Tab 都可用作初始视图。默认 Tab 见 E-001。
3. 按核对需要切换 Tab，切换只替换同一页的内容区。
4. 查看当前 Tab 对应的批次和列，列定义见 §8。

#### 完成后发生什么

- 成功结果：质检员在同一工作台查看所选类别及其对应的列。
- 失败或拒绝结果：单个 Tab 读取失败时，适用 EX-002。
- 下一步：质检员可继续查看其他类别。完成所需类别查看后，本期核对任务结束。

本任务来源为 PRD「范围与角色」「已确认的页面事实」「验收」。

## §5 要遵守什么规则

### BR-001 · 批次数据只读

- 适用对象：「批次追踪」工作台。
- 触发条件：质检员查看当前批次。
- 业务结果：读取当前批次数据。
- 来源：PRD「范围与角色」「范围排除」。

## §6 会出现哪些状态

本期不涉及工作台内的批次生命周期流转。三个类别的查看行为见 FN-001，无在途数据和读取失败时的显示结果见 §7。来源为 PRD「已确认的页面事实」「范围排除」。

## §7 遇到特殊情况怎么办

### EX-001 · 无在途批次

- 触发场景：查看「在途批次」时没有在途数据。
- 业务判定：当前没有在途批次。
- 对用户任务的结果：只在「在途批次」Tab 内显示「暂无在途批次」。另外两个 Tab 仍可访问。
- 来源：PRD「已确认的页面事实」。

### EX-002 · 单个 Tab 读取失败

- 触发场景：加载任意一个 Tab 失败。
- 业务判定：该 Tab 的批次数据读取失败。
- 对用户任务的结果：质检员仍留在同一工作台，失败 Tab 内显示「批次读取失败」和「重试」。
- 是否允许重试或恢复：质检员可在失败 Tab 内使用「重试」，仅重新加载该 Tab。
- 后续处理责任方：质检员发起重试。
- 来源：PRD「已确认的页面事实」「验收」。

## §8 会影响哪些记录和系统

| Tab | 展示的列 |
| --- | --- |
| 在途批次 | 批次号、来源农场、预计到场时间 |
| 已到场 | 批次号、验收人、到场时间 |
| 退回批次 | 批次号、退回原因 |

- 「预计到场时间」使用 24 小时制。以上列与格式来源为 PRD「已确认的页面事实」。
- 工作台查看操作不写入业务记录。来源为 PRD「范围排除」。

## §9 这次明确不做什么

- 新增批次。
- 修改验收人。
- 处置退回。
- 导出。

来源为 PRD「范围排除」。

## §11 做成后应该看到什么结果

- **AC-001（FN-001）** 质检员从「市集管理」进入「批次追踪」，同一工作台按「在途批次」「已到场」「退回批次」排列三个 Tab。
- **AC-002（FN-001、§8）** 有在途数据时，质检员切换到「在途批次」，只有内容区切换，显示「批次号」「来源农场」「预计到场时间」，其中「预计到场时间」使用 24 小时制。
- **AC-003（FN-001、§8）** 有已到场数据时，质检员切换到「已到场」，只有内容区切换，显示「批次号」「验收人」「到场时间」。
- **AC-004（FN-001、§8）** 有退回数据时，质检员切换到「退回批次」，只有内容区切换，显示「批次号」「退回原因」。
- **AC-005（§3）** 非质检员尝试打开「批次追踪」，无法打开或查看工作台。
- **AC-006（EX-001）** 没有在途数据时，质检员查看「在途批次」，只在该 Tab 内看到「暂无在途批次」，另外两个 Tab 仍可访问。
- **AC-007（EX-002）** 任意一个 Tab 加载失败时，质检员仍留在同一工作台，在该 Tab 内看到「批次读取失败」和「重试」。
- **AC-008（EX-002）** 质检员在失败的 Tab 内触发「重试」，系统仅重新加载该 Tab。
- **AC-009（BR-001、§8）** 质检员在工作台查看批次，系统读取当前数据，业务记录没有写入。
