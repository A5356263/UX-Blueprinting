# 正式需求基线

- 项目：剧场场务设备转交
- 基线状态：`formal`
- 原始 PRD：[requirements.md](../requirements.md)
- 辅助输入：[prototype-reference.md](../prototype-reference.md)，用途为形态参考。

## §1 背景与目标

### 为什么现在做

场务主管从「设备台账」菜单进入现有工具页。本期在该工具页处理场次内的设备转交。来源为 PRD「范围与角色」。

### 本期目标

让场务主管把当前场次的一件设备转交给该场次的一名在岗接收人，完成保管人交接。来源为 PRD「范围与角色」「已确认的操作与文本」。

### 本期范围

本期包含：

- 单件设备转交。
- 按转交选项执行交接和站内通知。

本期不包含（非目标）：

- 批量转交、跨场次转交和短信通知。详见 §9。

本节范围来源为 PRD「范围与角色」「已确认的操作与文本」「范围排除」。

## §2 功能与变更清单

### 新增

#### 场次内设备转交

- 本期变化：在现有「设备台账」工具页新增本场次设备转交。
- 对象关系：设备关联当前场次，转交更新该设备和当前保管人的关系。
- 来源：PRD「范围与角色」「已确认的操作与文本」。

## §3 谁能做什么

### 场务主管

- 责任：发起本场次设备转交，选择接收人和交接选项。
- 权限前提：只有场务主管可见「发起转交」操作。
- 可执行动作：为当前场次的设备发起转交。
- 来源：PRD「范围与角色」「已确认的操作与文本」。

### 接收人

- 责任：接收本次转交的设备。
- 资格前提：为本场次在岗人员。
- 来源：PRD「范围与角色」。

## §4 每件事怎么完成

### FN-001 · 场务主管 · 转交本场次设备

#### 什么时候开始

- 需求发生事件：场务主管需将一件设备交给本场次的接收人。
- 业务触发条件：对当前场次的一件设备发起转交。
- 前置条件：执行人是场务主管，设备属于当前场次。

#### 从哪里进入

- 本期支持的进入渠道：从「设备台账」菜单进入现有工具页，在目标设备行使用「发起转交」。
- 现有页面或载体：「设备台账」菜单下的工具页。
- 现有入口：「设备台账」菜单。

#### 怎么完成

1. 使用设备行的「发起转交」，打开「设备转交」弹窗。
2. 弹窗只读显示「设备编号」和「当前保管人」。场务主管通过必填的「接收人」字段选择一人，并可按 BR-002 设置三个独立选项。
3. 使用「确认转交」时，系统按 BR-001 检查提交资格。提交通过后执行 §8 已确认的记录更新及通知。
4. 如使用「取消」，弹窗关闭，设备列表保留原行，业务记录和通知结果按 §8 保持原状。

#### 完成后发生什么

- 成功结果：关闭弹窗，回到设备列表原行，更新显示「当前保管人」，提示「设备已转交」。
- 失败或拒绝结果：未选择接收人时拦截，见 EX-001。提交时资格变化则不保存，见 EX-002。
- 下一步：成功或取消时结束本次转交。资格变化导致提交被拒后可按 EX-002 恢复或结束。

本任务各字段来源为 PRD「范围与角色」「已确认的操作与文本」。

## §5 要遵守什么规则

### BR-001 · 单件设备转交资格

- 适用对象：本次设备及其接收人。
- 触发条件：场务主管使用「确认转交」。
- 判断条件：
  - 每次转交一件设备给一名接收人。
  - 设备在提交时仍属于当前场次。
  - 接收人在提交时仍是本场次在岗人员。
- 业务结果：缺少接收人时拦截。设备或接收人资格不成立时拒绝提交。
- 优先级或互斥关系：先校验设备仍属于当前场次，再校验接收人仍为本场次在岗人员。
- 来源：PRD「范围与角色」「已确认的操作与文本」。

### BR-002 · 转交选项及结果

- 适用对象：「设备转交」弹窗的三个独立选项。
- 触发条件：打开弹窗并设置本次转交选项。
- 判断条件：支持多选，允许全不选。默认仅选中「通知接收人」。
- 业务结果：
  - 勾选「携带说明」时，将设备使用说明随设备交接。
  - 勾选「通知接收人」时，保存后向所选接收人发送一次站内通知。
  - 勾选「保留交接备注」时，一同保留当前记录中的交接备注。
  - 未勾选的内容不随本次转交。
- 来源：PRD「已确认的操作与文本」。

### BR-003 · 转交无需审批

- 适用对象：本场次设备转交。
- 触发条件：场务主管确认转交。
- 业务结果：无需审批或二次人工确认。
- 来源：PRD「范围与角色」。

## §6 会出现哪些状态

本期涉及设备的当前保管人关系更新。成功、失败和取消分别对应的记录结果见 §8。来源为 PRD「已确认的操作与文本」。

## §7 遇到特殊情况怎么办

### EX-001 · 未选择接收人

- 触发场景：场务主管使用「确认转交」时「接收人」为空。
- 业务判定：缺少必须选择的一名接收人。
- 对用户任务的结果：拦截提交，在「接收人」字段下显示「请选择接收人」。
- 对对象状态的结果：按 §8 的失败结果处理。
- 来源：PRD「已确认的操作与文本」。

### EX-002 · 提交时设备或接收人资格变化

- 触发场景：场务主管提交时，设备已不属于当前场次，或已选接收人已不符合本场次在岗资格。
- 业务判定：按 BR-001 判定不满足转交资格。
- 对用户任务的结果：保持「设备转交」弹窗打开，保留其他输入，提示「设备或接收人状态已变化」。
- 对对象状态的结果：不保存，按 §8 的失败结果处理。
- 是否允许重试或恢复：刷新候选后可重新选择，也可取消。
- 后续处理责任方：场务主管。
- 来源：PRD「范围与角色」「已确认的操作与文本」。

## §8 会影响哪些记录和系统

- 成功时，系统保存新保管人。
- 成功时，系统保存三项勾选状态。
- 成功且选中「通知接收人」时，按 BR-002 执行站内通知。
- 失败或取消时，保管人、选项记录和通知结果保持原状。

来源为 PRD「已确认的操作与文本」。

## §9 这次明确不做什么

- 批量转交。
- 跨场次转交。
- 短信通知。

来源为 PRD「范围排除」。

## §11 做成后应该看到什么结果

- **AC-001（FN-001、BR-002）** 场务主管在「设备台账」工具页使用设备行的「发起转交」，打开「设备转交」弹窗，看到只读的「设备编号」「当前保管人」和必选一人的「接收人」字段。弹窗提供「携带说明」「通知接收人」「保留交接备注」三个独立选项，默认仅选中「通知接收人」。
- **AC-002（§3）** 非场务主管查看设备行时，看不到「发起转交」操作。
- **AC-003（FN-001、BR-001、BR-002、BR-003、§8）** 当前场次设备和所选的本场次在岗接收人资格均有效，场务主管保持仅勾选「通知接收人」并确认。系统保存新保管人和三项勾选状态，并在保存后向该接收人发送一次站内通知。弹窗关闭，设备列表原行的「当前保管人」更新，出现「设备已转交」提示，无需审批或二次人工确认。
- **AC-004（FN-001、BR-002、§8）** 设备和接收人资格均有效，场务主管勾选「携带说明」和「保留交接备注」后确认。设备使用说明随设备交接，当前记录中的交接备注一同保留，两项勾选状态均已保存。
- **AC-005（FN-001、BR-002、§8）** 设备和接收人资格均有效，场务主管取消勾选全部选项后确认。转交成功，系统保存三项未勾选状态，说明及交接备注不随本次转交，系统不发送站内通知。
- **AC-006（FN-001、EX-001、§8）** 未选接收人时，场务主管使用「确认转交」，系统拦截并在「接收人」字段下显示「请选择接收人」。保管人、选项记录和通知结果保持原状。
- **AC-007（FN-001、BR-001、EX-002、§8）** 设备在提交前变为非当前场次设备，场务主管确认转交时系统不保存，弹窗保持打开并保留其他输入，提示「设备或接收人状态已变化」。保管人、选项记录和通知结果保持原状。
- **AC-008（FN-001、BR-001、EX-002、§8）** 设备仍属于当前场次，但已选接收人在提交前失去本场次在岗资格，场务主管确认转交时系统不保存，弹窗保持打开并保留其他输入，提示「设备或接收人状态已变化」。保管人、选项记录和通知结果保持原状。
- **AC-009（EX-002）** 提交时资格变化且弹窗保持打开，场务主管刷新候选后可重新选择。
- **AC-010（FN-001、§8）** 弹窗打开时，场务主管使用「取消」，弹窗关闭，设备列表保留原行。保管人、选项记录和通知结果保持原状。
